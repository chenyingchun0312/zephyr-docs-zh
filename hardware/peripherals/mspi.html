多位 SPI 总线

MSPI（多位 SPI，multi-bit SPI）是一套通用 API，用于支持高级 SPI 外设和设备。这类设备通常需要命令、地址和数据阶段，并在这些阶段使用多根信号线。该 API 支持 XIP 和加扰等高级功能，同时也兼容通用 SPI。

MSPI 控制器 API

当系统中存在多位 SPI 控制器（例如 Ambiq MSPI、QSPI、OSPI、Flexspi 等）时，可以使用 Zephyr 的 MSPI 控制器 API。该 API 支持从单线到十六线的 SDR/DDR IO，支持可变延迟，以及 XIP 和加扰等高级功能。适用的设备包括但不限于高速、高密度的 Flash/PSRAM 存储器设备、显示器和传感器。

MSPI 接口包含两类驱动：SoC 平台特定、实现 MSPI API 的控制器驱动，以及引用这些 API 的设备驱动。控制器驱动与设备驱动之间是多对多关系，便于在不同平台之间切换。

下面是在设备驱动初始化函数中初始化 MSPI 控制器和 MSPI 总线的通用步骤：

  1. 初始化 MSPI 控制器驱动实例的数据结构。可以使用 DEVICE_DT_INST_DEFINE 等常用的设备定义宏，并将初始化函数、配置和数据作为参数传给该宏。

  2. 初始化硬件，包括但不限于：

    • 根据硬件自身的能力检查 mspi_cfg，防止错误使用。

    • 设置默认的引脚复用。

    • 为控制器设置时钟。

    • 为硬件上电。

    • 使用 mspi_cfg 以及可能的其他平台特定设置配置硬件。

    • 通常，mspi_cfg 由设备树填充，包含静态的启动时参数。不过如有需要，也可以在运行时使用 mspi_config() 以新参数重新初始化硬件。

    • 如适用，释放所有锁。

  3. 执行设备驱动初始化。与往常一样，可以使用 DEVICE_DT_INST_DEFINE。在设备驱动初始化函数中执行以下必要步骤。

    1. 使用从设备数据手册获得的设备特定硬件设置调用 mspi_dev_config()。

      • mspi_dev_cfg 应由设备树填充，可以使用辅助宏 MSPI_DEVICE_CONFIG_DT。

      • 随后，控制器驱动应验证 mspi_dev_cfg 的各成员，防止错误使用。

      • 控制器驱动应实现互斥量，防止意外访问。

      • 控制器驱动也可以根据 mspi_dev_id 在不同设备之间切换。

    2. 如果硬件支持，调用 API 进行额外设置：

      • mspi_memmap_config() 用于存储器映射访问（例如 XIP）

      • mspi_scramble_config() 用于加扰功能

      • mspi_timing_config() 用于平台特定的时序设置。

    3. 如有需要，使用 mspi_register_callback() 注册回调。

    4. 释放控制器的互斥锁。

收发

收发请求的类型为 mspi_xfer。在工作模式由 mspi_dev_config() 确定并配置之后，可以通过它动态修改与传输相关的设置。

该 API 还通过 mspi_xfer_packet 支持具有不同起始地址和大小的批量传输。不过，是否支持分散 IO 和回调管理取决于控制器实现。如果回调已通过 mspi_register_callback() 注册，控制器可以在每次异步/同步传输完成时，根据 mspi_bus_event_cb_mask 决定触发哪个用户回调；也可以使用 MSPI_BUS_NO_CB，即使已注册回调也不触发任何回调。如果所实现的驱动支持，该 API 支持用 MSPI_BUS_XFER_COMPLETE_CB 通知传输完成，用 MSPI_BUS_TIMEOUT_CB 通知传输或请求超时。如果控制器支持硬件命令队列，并且驱动实现支持分散 IO 和回调管理，用户就可以充分发挥硬件性能。

设备树

下面是在设备树中定义 MSPI 控制器的示例。mspi 控制器的绑定应将 mspi-controller.yaml 作为其基础绑定之一。

mspi0: mspi@400 {
         status = "okay";
         compatible = "zephyr,mspi-emul-controller";

         reg = <0x400 0x4>;
         #address-cells = <0x1>;
         #size-cells = <0x0>;

         clock-frequency = <0x17d7840>;
         op-mode = "MSPI_CONTROLLER";
         duplex = "MSPI_HALF_DUPLEX";
         ce-gpios = <&gpio0 0x5 0x1>, <&gpio0 0x12 0x1>;
         dqs-support;

         pinctrl-0 = <&pinmux-mspi0>;
         pinctrl-names = "default";
};

下面是在设备树中定义 MSPI 设备的示例。mspi 设备的绑定应将 mspi-device.yaml 作为其基础绑定之一。

&mspi0 {

         mspi_dev0: mspi_dev0@0 {
                  status = "okay";
                  compatible = "zephyr,mspi-emul-device";

                  reg = <0x0>;
                  size = <0x10000>;

                  mspi-max-frequency = <0x2dc6c00>;
                  mspi-io-mode = "MSPI_IO_MODE_QUAD";
                  mspi-data-rate = "MSPI_DATA_RATE_SINGLE";
                  mspi-hardware-ce-num = <0x0>;
                  read-instruction = <0xb>;
                  write-instruction = <0x2>;
                  instruction-length = "INSTR_1_BYTE";
                  address-length = "ADDR_4_BYTE";
                  rx-dummy = <0x8>;
                  tx-dummy = <0x0>;
                  memmap-config = <0x0 0x0 0x0 0x0>;
                  ce-break-config = <0x0 0x0>;
         };

};

用户应在 DTS 中指定目标工作参数，例如 mspi-max-frequency、mspi-io-mode 和 mspi-data-rate，即使这些参数在运行时可能改变。它们应代表设备在正常工作期间的典型配置。

多外设

由于 mspi_dev_id 定义为来自设备树的设备索引和 CE GPIO 的组合，该 API 支持在同一控制器实例上连接多个设备。控制器驱动实现可以支持也可以不支持设备切换，切换可以由软件或硬件完成。如果由软件处理切换，应在 mspi_dev_config() 调用中完成。

为支持由软件控制的设备切换，设备驱动应通过保存和更新 mspi_dev_cfg 及其他相关 mspi 结构体或私有数据结构，记录设备当前的工作状态。特别是，包含设备身份的 mspi_dev_id 在每次 API 调用中都需要使用。
