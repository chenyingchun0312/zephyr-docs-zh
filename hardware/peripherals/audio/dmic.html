数字麦克风（DMIC）

概述

音频 DMIC 接口用于访问数字麦克风。

数字麦克风通常输出 PDM（脉冲密度调制，Pulse Density Modulation）比特流，而不是模拟音频。PDM 使用 1 位的高速率信号，以一段时间内 1 和 0 的密度来表示音频幅度。

由于应用程序通常使用的是 PCM（脉冲编码调制，Pulse Code Modulation）采样而不是原始 PDM 数据，DMIC 控制器会把麦克风数据流转换为 PCM 音频。这一转换包括滤波和抽取：滤波去除被整形到 PDM 数据流中的高频噪声，抽取则把比特流速率降低到所需的 PCM 采样率。

从 Zephyr 的角度看，DMIC 设备是一种音频采集外设。应用程序配置麦克风和控制器，启动采集，然后从驱动读取 PCM 缓冲区。

关键概念

DMIC API 把配置分为三部分，与采集路径一一对应：

  1. 在 PDM 侧如何驱动麦克风；

  2. 如何排列输入的 PDM 通道；

  3. 如何把转换后的 PCM 采样交付给应用程序。

这三部分组合在 dmic_cfg 中，并传递给 dmic_configure()。

PDM I/O 配置（dmic_cfg.io）

描述麦克风接口的电气和时序要求，例如支持的 PDM 时钟频率范围、占空比，以及控制器特定的信号极性设置。

通道配置（dmic_cfg.channel）

告诉驱动在 PCM 输出中，每个逻辑音频通道对应哪个物理 PDM 控制器以及左或右麦克风通路。它还声明了应用程序要使用的通道数和数据流数。

PCM 数据流配置（dmic_cfg.streams）

定义驱动交付的 PCM 数据，包括采样率、采样位宽、块大小，以及为每个已启用数据流分配接收缓冲区所用的 k_mem_slab。

典型的应用程序流程

DMIC API 的典型用法如下：

  1. 获取 DMIC 设备，通常从设备树获取。

  2. 在 dmic_cfg 结构体中填入 I/O、通道和数据流设置。关于如何定义 DMIC 用来存放接收到的 PCM 数据的内存缓冲区，详见下文 缓冲 一节。

  3. 调用 dmic_configure()，传入该配置结构体。

  4. 使用 DMIC_TRIGGER_START 调用 dmic_trigger() 启动采集。

  5. 使用 dmic_read() 获取 PCM 数据。

  6. 根据需要使用其他触发命令停止、暂停或复位采集。

缓冲

接收到的 PCM 数据通过驱动所拥有的缓冲区返回。应用程序通过每个已配置 PCM 数据流所引用的 k_mem_slab 提供底层内存。

常见做法是静态声明该内存块（slab）：

为 PCM 接收缓冲区静态声明内存块（slab）
 K_MEM_SLAB_DEFINE_STATIC(mem_slab,
                          SAMPLES_PER_BUFFER * sizeof(int16_t),
                          BUFFER_COUNT,
                          sizeof(void *));

在此示例中，每个 slab 块存放一个 PCM 缓冲区，BUFFER_COUNT 设置在应用程序使用 dmic_read() 读取之前，内部最多可排队多少个缓冲区。

Shell 命令

启用 CONFIG_AUDIO_DMIC_SHELL 后，可以使用一组 dmic 命令。借助这些命令，无需编写专门的应用程序即可交互式地从 DMIC 设备采集音频。

每个子命令的第一个参数是 DMIC 设备名称，其后可选地跟随音频采集参数（采样率、通道数和 PCM 采样位宽）。

可用的子命令如下：

dmic read <device> [<count> [<rate_hz> [<channels> [<pcm_width>]]]]

采集 count 个音频块，并打印每个通道的峰值电平。count 默认为 5；每个块为 50 ms 的音频。

dmic vu <device> [<rate_hz> [<channels> [<pcm_width>]]]

显示实时的彩色电平表，带峰值保持和削波指示，每个通道一个条形。按任意键前持续运行。

dmic dump <device> [<seconds> [<rate_hz> [<channels> [<pcm_width>]]]]

采集 seconds 秒的音频，并以 base64 编码的原始 PCM 形式打印出来，同时给出在主机上解码和回放所需的命令。默认时长为 2 秒。

内置帮助（例如 dmic read --help）会列出各参数及其默认值。

相关配置选项：
