Inter-Integrated Circuit（I2C）总线

概述

备注

Zephyr I2C API 所用的术语遵循 NXP I2C 总线规范第 7.0 版。该版本于 2021 年 10 月 1 日发布，术语与之前的版本有所不同。

I2C（Inter-Integrated Circuit，读作 “eye squared see”）是一种常用的双信号线共享外设接口总线。许多片上系统方案都提供在 I2C 总线上通信的控制器。总线上的设备可以担任两种角色：发起事务并控制时钟的“控制器”（controller），或响应事务命令的“目标”（target）。SoC 上的 I2C 控制器一般支持控制器角色，有些还支持目标模式。Zephyr 为这两种角色都提供了 API。

I2C 控制器 API

当 I2C 外设控制总线（尤其是起始条件、停止条件和时钟）时，使用 Zephyr 的 I2C 控制器 API。这是最常见的模式，用于与传感器、串行存储器等 I2C 设备交互。

树内所有 I2C 外设驱动都支持该 API，它被视为稳定 API。

I2C 目标 API

当 I2C 外设响应总线上其他控制器发起的事务时，使用 Zephyr 的 I2C 目标 API。例如，当 Zephyr 应用程序担任换能器角色、由主处理器等其他设备控制时，就可以使用它。

树内只有极少数 I2C 外设驱动支持该 API。该 API 被视为实验性的，因为它与所有支持控制器模式的 I2C 外设的能力并不完全兼容。

配置选项

相关配置选项：

  • CONFIG_I2C

  • CONFIG_I2C_TRANSFER_TIMEOUT_MS

传输超时

I2C 子系统提供两种互补的机制，用于控制驱动在返回 -ETIMEDOUT 之前等待传输完成的时长。

应用程序级默认值（Kconfig）

CONFIG_I2C_TRANSFER_TIMEOUT_MS 为所有通过选择 I2C_TRANSFER_TIMEOUT_SUPPORTED 加入此机制的 I2C 控制器驱动设置默认超时（以毫秒为单位）。值为 0 表示永久等待（K_FOREVER）。不允许无限超时的驱动（例如直接把该值写入硬件寄存器的驱动）使用 BUILD_ASSERT_INVALID_I2C_TRANSFER_TIMEOUT 在构建时强制要求非零值。

按控制器的设备树覆盖

各控制器可以通过 dts/bindings/i2c/i2c-controller.yaml 中定义的 zephyr,transfer-timeout-ms 设备树属性覆盖应用程序级默认值。未设置该属性时，驱动回退到 CONFIG_I2C_TRANSFER_TIMEOUT_MS。

开发板覆盖文件示例:

&i2c1 {
    /* Fast sensor bus - fail quickly on a hung device */
    zephyr,transfer-timeout-ms = <50>;
};

&i2c2 {
    /* EEPROM bus - allow for long internal write cycles */
    zephyr,transfer-timeout-ms = <2000>;
};

支持按实例设置超时的驱动使用 I2C_DT_INST_TRANSFER_TIMEOUT（需要原始整数时使用 I2C_DT_INST_TRANSFER_TIMEOUT_MS），这两个宏按以下优先级确定超时：

  1. 控制器节点上的 zephyr,transfer-timeout-ms 设备树属性

  2. CONFIG_I2C_TRANSFER_TIMEOUT_MS

  3. 当确定的值为 0 时使用 K_FOREVER
