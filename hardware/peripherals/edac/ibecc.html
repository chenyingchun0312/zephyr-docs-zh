带内纠错码（IBECC）

概述

该机制最初出现在 Intel Elkhart Lake SoC 及后续开发板中，是一种集成了 IBECC 的内存控制器。

带内纠错码（IBECC，In-Band Error Correction Code）通过提供错误检测和纠正来提高可靠性。IBECC 可以作用于整个物理内存空间，也可以只作用于其中的特定区域。对于不支持带外 ECC 的内存技术，IBECC 十分有用。

IBECC 会占用 1/32 的内存作为额外开销。这部分内存不可访问，用于存储 ECC 校验子数据。IBECC 将读/写事务转换为两个独立的事务：一个用于实际数据，另一个用于包含 ECC 值的缓存行。

IBECC 提供一项调试功能，即 IBECC 错误注入，用于调试和验证 IBECC 功能。ECC 错误在写路径上注入，并在读路径上引发 ECC 错误。

IBECC 配置

IBECC 有三种工作模式，可由引导加载程序选择，如下所列：

  • OPERATION_MODE = 0x0：将功能模式设置为根据地址范围保护请求

  • OPERATION_MODE = 0x1：将功能模式设置为不保护任何请求并忽略范围检查

  • OPERATION_MODE = 0x2：将功能模式设置为保护所有请求并忽略范围检查

IBECC 工作模式通过 BIOS 或引导加载程序配置。对于工作模式 0，BIOS 还有更多配置选项，例如内存区域。

由于安全风险较高，量产产品不应启用错误注入功能。错误注入仅在测试时启用。

IBECC 日志

IBECC 记录以下字段：

  • 错误地址

  • 错误校验子

  • 错误类型

    • 可纠正错误（CE）：错误被 IBECC 模块检测到并已纠正。

    • 不可纠正错误（UE）：错误被 IBECC 模块检测到，但未被自动纠正。

IBECC 驱动向上层应用程序提供错误类型，以便其针对这些内存错误实现所需的处理策略。IBECC 驱动本身不使用错误校验子，而是将其提供给上层应用程序。

使用说明

对不可屏蔽中断（NMI）需要格外小心。NMI 可能在任何时刻到来，即使本地 CPU 已禁用中断。这意味着没有任何锁机制能保护代码不受 NMI 打断。Zephyr 的 IPC 机制普遍以本地 IRQ 锁作为所有上层同步原语的基础。因此，不能与 NMI 共享任何由锁“保护”的数据，因为这种保护不起作用。在 Zephyr API 中，唯一能对 NMI 起作用的同步工具是原子操作层。这同样适用于由 NMI 处理程序调用的回调函数。

相关配置选项：
