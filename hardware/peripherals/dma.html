直接存储器访问（DMA）

概述

直接存储器访问（控制器）是一种常见的协处理器，通常可以分担外设与存储器之间的数据传输工作。

DMA API 不是可移植的 API，事实上也无法做到可移植，因为每种 DMA 都有其独特的存储器要求、外设交互方式和功能。实际上，该 API 提供的是树内各驱动所需的全部有用 DMA 功能的并集。对于 DMA IP 非常相似但略有差异的厂商外设，只要谨慎使用，它仍然是不错的抽象。

DMA 驱动通常不处理缓存一致性；由于需求因应用程序而差异极大，这部分工作留给开发者。关于 Zephyr 中缓存管理的概述，请参阅 缓存基础。

对驱动实现的要求

同步与所有权

从 API 的角度看，DMA 通道是单一所有者对象，这意味着驱动不应尝试用互斥量或信号量等内核同步原语来包装通道。如果 DMA 通道需要修改共享寄存器，这些寄存器更新应使用自旋锁保护。

这样，整个 API 的开销很低，并且可以在任何调用上下文中调用，包括 ISR。在 ISR 中启动/停止/挂起/恢复/重新加载通道传输可能非常有用。

传输描述符的内存管理

驱动不应使用任何形式的堆分配。如果传输描述符需要对象池，其设置方式不应破坏“可在 ISR 中调用”的承诺。许多驱动选择为每个通道创建一个简单的静态描述符数组，数组大小可通过 Kconfig 调整。

对通道状态机的要求

DMA 通道应被视为状态机，DMA API 以 API 调用的形式为其提供状态转换事件。每个驱动都应自行维护通道状态跟踪。任何时候都应能通过 dma_get_status() 查询通道的忙碌状态。
