时钟监视器

概述

时钟监视器 API 用于访问这样一类硬件外设：它们在运行时观察时钟信号，并在其频率偏离预期范围或完全停止时进行报告。该 API 面向功能安全和诊断用例，用于检测关键时钟树上的振荡器失效、参考时钟丢失或频率漂移超出规格等问题。

工作模式

两种模式共用同一个生命周期：使用 clock_monitor_configure() 配置，使用 clock_monitor_start() 开始运行，使用 clock_monitor_stop() 结束运行。

该 API 提供两种工作模式：

CLOCK_MONITOR_MODE_WINDOW

连续阈值检查。硬件将被监视时钟的频率与可编程的上、下限进行比较，这两个界限由 clock_monitor_window_cfg.expected_hz 和 clock_monitor_window_cfg.tolerance_ppm 推导得出。越过阈值的事件通过配置时安装的用户回调异步交付。

CLOCK_MONITOR_MODE_MEASURE

每次调用 clock_monitor_start() 进行一次频率测量，结果通过配置时设置的回调交付（CLOCK_MONITOR_EVT_MEASURE_DONE 加上以 Hz 为单位的测量值）。回调运行之前，设备会自动回到已配置（停止）状态，因此在正常路径上无需调用 clock_monitor_stop()。如需重复测量，可在回调中再次调用 clock_monitor_start()。clock_monitor_start() 和 clock_monitor_stop() 都可以在 ISR 中安全调用（与在计数器闹钟回调中重新设置闹钟的惯用法相同）。

在 MEASURE 模式下，API 不提供阻塞等待，超时由应用程序负责。常见做法是等待一个由回调释放的信号量，超时时间由应用程序选定，并在超时路径上调用 clock_monitor_stop() 中止进行中的测量。另外，也可以用 clock_monitor_get_rate() 轮询最近一次的结果；对于可能无法安装回调的用户模式线程，这也是获取结果的途径。

事件

事件以位掩码形式通过 clock_monitor_event_data.events 交付：

  • CLOCK_MONITOR_EVT_FREQ_HIGH：被监视的频率超过上阈值（WINDOW 模式）。

  • CLOCK_MONITOR_EVT_FREQ_LOW：被监视的频率低于下阈值（WINDOW 模式）。

  • CLOCK_MONITOR_EVT_CLOCK_LOST：被监视的时钟在测量窗口内不再产生边沿（MEASURE 模式下的硬件故障）。

  • CLOCK_MONITOR_EVT_MEASURE_DONE：测量成功完成（MEASURE 模式）；结果保存在 clock_monitor_event_data.measured_hz 中。

配置时设置的回调是唯一的事件交付途径。在 MEASURE 模式下，最近一次完成的结果还可以通过轮询 clock_monitor_get_rate() 获取。对于可能无法安装回调的 WINDOW 模式用户模式观察者，事件需经由管理态一侧的中转来接收（例如由回调填充的 k_msgq）。

配置

时钟监视器在启动之前必须通过 clock_monitor_configure() 进行配置。配置包括工作模式、模式相关的参数（预期频率、容差、测量窗口）以及可选的异步回调。只有在监视器停止时才能进行配置；重新配置的方法是用新的模式/参数组合再次调用 clock_monitor_configure()，没有单独的拆除操作。返回码的完整列表请参阅 API Reference 中的 clock_monitor_configure()。

相关配置选项：

  • CONFIG_CLOCK_MONITOR
