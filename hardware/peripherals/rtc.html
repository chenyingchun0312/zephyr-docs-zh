实时时钟（RTC）

概述

术语表

术语

定义

实时时钟

使用分解时间（broken-down time）计时的低功耗设备

实时计数器

可用于计时的低功耗计数器

RTC

实时时钟（real-time clock）的缩写

RTC 是使用分解时间计时的低功耗设备。不要将它与低功耗计数器混淆，后者有时会使用相同的名称、缩写，或二者皆同。

RTC 通常针对低能耗进行了优化，即使系统处于低功耗状态，通常也保持运行。

RTC 通常包含一个或多个闹钟，可配置为在指定时间触发。这些闹钟常用于将系统从低功耗状态唤醒。

设备树绑定

RTC 绑定必须包含 rtc-device.yaml 绑定，后者包含 base.yaml 绑定和必需的 alarms-count 属性。

include: rtc-device.yaml

设备驱动设计

驱动初始化

系统从不关闭 RTC 的电源。初始化时，驱动应预期 RTC 处于以下两种状态之一：

  • 已供电、已配置并正在运行。

  • 已供电、未配置且已停止。

初始化时，驱动必须确保 RTC 配置正确，同时保留时间、闹钟和运行状态。

通过调用 rtc_set_time() 设置时间，此时 RTC 开始运行。闹钟的挂起状态由 rtc_alarm_is_pending() 清除，或者由通过 rtc_alarm_set_callback() 设置的闹钟回调清除。

经 GPIO 路由的中断

连接了中断输出引脚的 RTC 必须在初始化时配置并使能这些引脚。主机可以使能和禁止其 GPIO 的中断，但 RTC 的中断输出引脚必须保持使能。

这确保了内部连接和外部连接的 RTC 行为一致，并允许在任何已使能的 RTC 事件（如闹钟或更新）发生时通过 GPIO 唤醒系统。

备注

对于中断输出引脚未连接的 RTC，不允许通过定期轮询 RTC 来模拟已连接的情况。在这种情况下，rtc_alarm_set_callback() 和 rtc_update_set_callback() 必须返回 -ENOTSUP。

时钟输出

如果支持时钟输出，其配置在设备树中定义。驱动在初始化时配置该输出。

配置选项

相关配置选项：

  • CONFIG_RTC

  • CONFIG_RTC_ALARM

  • CONFIG_RTC_UPDATE

  • CONFIG_RTC_CALIBRATION

RTC 设备驱动测试套件

该测试套件验证 RTC 设备驱动的行为，设计为可在不同开发板之间移植。它使用设备树别名 rtc 指定要测试的 RTC 设备。

该测试套件测试以下内容：

  • 设置和获取时间。

  • RTC 时间正确递增。

  • 闹钟（如果硬件支持），分别在启用和不启用回调的情况下测试

  • 校准（如果硬件支持）。

校准测试会测试一系列值，并将其打印到控制台以供人工比对。用户必须检查设置值与读回值，确认它们有效。

默认情况下，只启用必需的时间设置与获取测试。要测试可选的闹钟、更新事件回调和时钟校准，必须通过选择 CONFIG_RTC_ALARM、CONFIG_RTC_UPDATE 和 CONFIG_RTC_CALIBRATION 启用它们。

以下示例为 native_sim 开发板构建测试套件。要为其他开发板构建测试套件，请将 native_sim 替换为你的开发板。

要以默认配置构建测试应用程序（只测试必需功能），可参考以下命令：

# From the root of the zephyr repository
west build -b native_sim tests/drivers/rtc/rtc_api

要在启用更多 RTC 功能的情况下构建测试，请使用 menuconfig 更新配置以启用这些功能。可参考以下命令：

# From the root of the zephyr repository
west build -b native_sim tests/drivers/rtc/rtc_api
west build -t menuconfig

然后使用以下命令构建测试应用程序：

# From the root of the zephyr repository
west build -b native_sim tests/drivers/rtc/rtc_api

要运行测试套件，请将应用程序烧录到开发板上并运行，输出会打印到控制台。

备注

在真实硬件上测试时，每项测试最多需要 30 秒。

RTC 仿真设备

RTC 仿真设备完整实现了 RTC API，其行为与真实 RTC 设备相同，但有以下限制：

  • RTC 时间在应用程序重新初始化后不会保留。

  • RTC 闹钟在应用程序重新初始化后不会保留。

  • RTC 时间会随着时间推移而漂移。

每次应用程序初始化时，RTC 的时间和闹钟都会被复位。在使用 rtc_set_time() 设置时间之前，使用 rtc_get_time() 读取时间会返回 -ENODATA。此后，在应用程序复位之前，RTC 的行为与真实 RTC 相同。

RTC 仿真设备驱动针对 compatible zephyr,rtc-emul 构建，选择 CONFIG_RTC 时会被包含进来。

Zephyr 中 RTC 的历史

在此 API 出现之前，RTC 是通过 计数器 API 支持的。RTC 驱动内部使用分解时间表示，并借助 Unix 时间戳在分解时间与 Unix 时间戳之间进行转换。

这种方式的缺点是：硬件计数器无法设置为特定计数值，导致所有 RTC 都要使用设备特定的 API 来设置时间；某些情况下需要进行不必要的 Unix 时间到分解时间的转换；并且缺少一些常见功能，例如输入时钟校准和更新回调。
