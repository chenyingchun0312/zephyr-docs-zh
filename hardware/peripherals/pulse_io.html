脉冲 IO

概述

脉冲 IO（Pulse IO）子系统为在单根 GPIO 线上产生和捕获定时数字边沿的硬件提供与厂商无关的 API。多个 MCU 系列都为此提供了专用外设，只是名称各不相同。脉冲 IO 对这类硬件进行了抽象，使可寻址 LED 灯带、红外发送与接收、步进脉冲生成、频率与占空比测量以及单总线类协议等客户端驱动只需绑定一次，即可在任何提供了后端的 SoC 上运行。

相关配置选项：

  • CONFIG_PULSE_IO

提交模式

通道在配置时被锁定为一种提交模式，可从后端通过其能力信息公布的模式中选择。

PULSE_IO_MODE_SYMBOL

应用程序提交一个 pulse_symbol 数组，每个元素携带明确的电平以及以所配置分辨率的节拍数表示的持续时间。相邻符号的持续时间可以任意且互不相关。适用于同一数据流中边沿长度会变化的协议，例如红外遥控、单总线以及步进电机加速斜坡。

PULSE_IO_MODE_CELL

应用程序提交一个 pulse_cell 数组。所有单元的周期相同，在通道配置中一次性设置；每个单元在该周期内携带一个电平或一个占空比值。适用于天然具有周期性、只有每周期电平或占空比会变化的数据流，例如可寻址 LED 的位整形或占空比可变的 PWM。在这些情况下，单元比符号更节省内存。

后端在 pulse_io_caps 中公布其支持的模式。请求不支持的模式会导致 pulse_io_channel_configure() 返回 -ENOTSUP。

配置

客户端在探测时调用 pulse_io_get_capabilities() 查询能力，以决定使用哪种模式和功能集；使用 pulse_io_channel_get() 预留通道；并在任何传输之前使用 pulse_io_channel_configure() 进行配置。阻塞式传输使用 pulse_io_transmit_sync() 和 pulse_io_receive_sync()；异步和流式传输使用 RTIO 路径。

字节到符号的辅助函数 pulse_io_encode_bytes() 及其逆函数 pulse_io_decode_bytes() 使用按位模板，在协议字节流与脉冲符号之间进行转换。

RTIO

后端可以选择与 实时 I/O（RTIO） 集成，提供一条 iodev 提交路径，以及可通过 pulse_io_get_encoder() 和 pulse_io_get_decoder() 获取的编码器和解码器虚函数表。使用 RTIO 时，客户端将有效载荷编码到符号缓冲区，通过 RTIO 队列提交，并解码捕获到的应答，从而获得 RTIO 框架提供的排队传输和链式传输、流式接收以及用户空间路径。RTIO 操作是可选的；未实现这些操作的后端将相应的驱动 API 成员保留为 NULL，此时访问函数返回 -ENOSYS。
