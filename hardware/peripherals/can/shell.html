CAN Shell

  • 概述

  • 查看

  • 配置

  • 接收

  • 发送

  • 总线恢复

概述

CAN shell 为 shell 模块提供一个带有一组子命令的 can 命令。借助它，无需编写专门的应用程序，即可通过交互式界面测试和探索 CAN 控制器 驱动 API。也可以在现有应用程序中启用 CAN shell，以便交互式地调试 CAN 问题。

CAN shell 可以使用大部分 CAN 控制器功能，包括查看、配置、发送和接收 CAN 帧以及总线恢复。

要启用 CAN shell，必须启用以下 Kconfig 选项：

  • CONFIG_SHELL

  • CONFIG_CAN

  • CONFIG_CAN_SHELL

以下 Kconfig 选项为 can 命令启用额外的子命令和功能：

  • CONFIG_CAN_FD_MODE 启用 CAN FD 特有的子命令（例如用于设置 CAN FD 数据阶段的时序）。

  • CONFIG_CAN_RX_TIMESTAMP 启用接收 CAN 帧时间戳的打印。

  • CONFIG_CAN_STATS 启用在 can show 子命令中打印 CAN 控制器的各项统计信息。这还要求启用 CONFIG_STATS。

  • CONFIG_CAN_MANUAL_RECOVERY_MODE 启用 can recover 子命令。

例如，为 FRDM-K64F 构建启用了 CAN shell 和 CAN 统计信息的 Hello World 示例：

# From the root of the zephyr repository
west build -b frdm_k64f samples/hello_world -- -DCONFIG_SHELL=y -DCONFIG_CAN=y -DCONFIG_CAN_SHELL=y -DCONFIG_STATS=y -DCONFIG_CAN_STATS=y

关于如何连接 shell 并与之交互的一般说明，请参阅 shell 文档。CAN shell 自带内置帮助（除非禁用了 CONFIG_SHELL_HELP）。向 can 命令或其任一子命令传入 -h 或 --help 即可打印内置帮助信息。所有子命令的参数都支持 Tab 补全。

小技巧

所有 CAN shell 子命令的第一个参数都是 CAN 控制器的名称，该参数同样支持 Tab 补全。启用 CONFIG_DEVICE_SHELL 后，可以使用 device list shell 命令获取所有可用设备的列表。下面的示例均使用设备名 can@0。

查看

可以使用 can show 子命令查看指定 CAN 控制器的属性，如下所示。这些属性包括 CAN 核心时钟频率、支持的最大位速率、支持的 RX 过滤器数量、能力、当前模式、当前状态、错误计数器、时序限制等：

uart:~$ can show can@0
core clock:      144000000 Hz
max bitrate:     5000000 bps
max std filters: 15
max ext filters: 15
capabilities:    normal loopback listen-only fd
mode:            normal
state:           stopped
rx errors:       0
tx errors:       0
timing:          sjw 1..128, prop_seg 0..0, phase_seg1 2..256, phase_seg2 2..128, prescaler 1..512
timing data:     sjw 1..16, prop_seg 0..0, phase_seg1 1..32, phase_seg2 1..16, prescaler 1..32
transceiver:     passive/none
statistics:
  bit errors:    0
    bit0 errors: 0
    bit1 errors: 0
  stuff errors:  0
  crc errors:    0
  form errors:   0
  ack errors:    0
  rx overruns:   0

备注

只有启用 CONFIG_CAN_STATS 时才会打印统计信息。

配置

CAN shell 可以配置 CAN 控制器的模式和时序，并启动和停止 CAN 帧的处理。

备注

只有在 CAN 控制器停止时才能修改其模式和时序，而停止正是启动后的初始状态。CAN 控制器的初始模式为 normal，初始时序根据 bitrate、sample-point、bitrate-data 和 sample-point-data 这几个 设备树 属性设置。

时序

可以使用 can bitrate 子命令配置经典 CAN 位速率或 CAN FD 仲裁阶段位速率，如下所示。位速率以比特每秒为单位指定。

uart:~$ can bitrate can@0 125000
setting bitrate to 125000 bps

如果启用了 CONFIG_CAN_FD_MODE，可以使用 can dbitrate 子命令配置数据阶段位速率，如下所示。位速率以比特每秒为单位指定。

uart:~$ can dbitrate can@0 1000000
setting data bitrate to 1000000 bps

这两个子命令都允许通过位置参数指定可选的采样点（以千分比表示）和（再）同步跳转宽度（SJW，以时间量子为单位）。更多细节请参阅这些子命令的交互式帮助。

也可以使用 can timing 和 can dtiming 子命令配置原始位时序。所需参数的详细说明请参阅这些子命令的交互式帮助输出。

模式

CAN shell 可以使用 can mode 子命令设置 CAN 控制器的模式。下面是启用回环模式的示例。

uart:~$ can mode can@0 loopback
setting mode 0x00000001

该子命令可以在同一命令行中接受多个模式（例如 can mode can@0 fd loopback 同时设置 CAN FD 模式和回环模式）。厂商特定的模式可以用十六进制指定。

启动和停止

根据需要配置好时序和模式后，可以使用 can start 子命令启动 CAN 控制器，如下所示。这将使能 CAN 帧的接收和发送。

uart:~$ can start can@0
starting can@0

在重新配置时序或模式之前，需要使用 can stop 子命令停止 CAN 控制器，如下所示：

uart:~$ can stop can@0
stopping can@0

接收

要接收 CAN 帧，需要配置一个或多个 CAN RX 过滤器。使用 can filter add 子命令添加 CAN RX 过滤器，如下所示。该子命令接受十六进制格式的 CAN ID，以及可选的十六进制格式 CAN ID 掩码，用于设置需要匹配 CAN ID 中的哪些位。所支持参数的更多细节请参阅该子命令的交互式帮助输出。

uart:~$ can filter add can@0 010
adding filter with standard (11-bit) CAN ID 0x010, CAN ID mask 0x7ff, data frames 1, RTR frames 0, CAN FD frames 0
filter ID: 0

移除该 CAN RX 过滤器时需要使用返回的过滤器 ID（上例中为 0）。

与已添加过滤器匹配的已接收 CAN 帧会打印到 shell 中。下面是几个示例：

# Dev Flags    ID   Size  Data bytes
can0  --       010   [8]  01 02 03 04 05 06 07 08
can0  B-       010  [08]  01 02 03 04 05 06 07 08
can0  BP       010  [03]  01 aa bb
can0  --  00000010   [0]
can0  --       010   [1]  20
can0  --       010   [8]  remote transmission request

各列含义如下：

  • Dev

    • 接收该帧的设备名称。

  • 标志

    • B：该帧设置了 CAN FD 波特率切换（BRS）标志。

    • P：该帧设置了 CAN FD 错误状态指示（ESI）标志，表示发送节点处于被动错误状态。

    • -：标志未设置。

  • ID

    • 010：该帧的标准（11 位）CAN ID，十六进制格式，此处为 10h。

    • 00000010：该帧的扩展（29 位）CAN ID，十六进制格式，此处为 10h。

  • 大小

    • [8]：帧数据字节数，十进制格式，此处为带 8 个数据字节的经典 CAN 帧。

    • [08]：帧数据字节数，十进制格式，此处为带 8 个数据字节的 CAN FD 帧。

  • 数据字节

    • 01 02 03 04 05 06 07 08：帧数据字节，十六进制格式，此处为数字 1 到 8。

    • remote transmission request：该帧是远程传输请求（RTR）帧，因此不携带数据字节。

小技巧

如果启用了 CONFIG_CAN_RX_TIMESTAMP，每一行前面都会加上一个时间戳，该时间戳来自 CAN 控制器中自由运行的时间戳计数器。

可以使用 can filter remove 子命令移除已配置的 CAN RX 过滤器，如下所示。过滤器 ID 是 can filter add 子命令返回的 ID（下例中为 0）。

uart:~$ can filter remove can@0 0
removing filter with ID 0

另一种方法是使用 can dump 子命令。它会添加可匹配任意 RX 帧的标准（11 位）和扩展（29 位）CAN 过滤器，启动 CAN 控制器，并将所有接收到的 CAN 帧打印到 shell：

uart:~$ can dump can@0
dumping CAN RX frames on device can@0, press Ctrl+C to exit

按 Ctrl+C 退出 can dump 子命令后，所添加的过滤器会被自动移除，CAN 控制器也会重新停止。

发送

可以使用 can send 子命令将 CAN 帧加入发送队列，如下所示。该子命令接受十六进制格式的 CAN ID，以及可选的若干数据字节（同样以十六进制指定）。所支持参数的更多细节请参阅该子命令的交互式帮助输出。

uart:~$ can send can@0 010 1 2 3 4 5 6 7 8
enqueuing CAN frame #2 with standard (11-bit) CAN ID 0x010, RTR 0, CAN FD 0, BRS 0, DLC 8
CAN frame #2 successfully sent

总线恢复

可以使用 can recover 子命令从 CAN 总线关闭事件中发起手动恢复，如下所示：

uart:~$ can recover can@0
recovering, no timeout

该子命令接受一个可选的总线恢复超时（以毫秒为单位）。如果未指定超时，命令将无限期等待总线恢复成功。

备注

只有启用 CONFIG_CAN_MANUAL_RECOVERY_MODE 时，recover 子命令才可用。
