传感器

传感器驱动 API 以统一的方式读取和配置那些以有意义的单位测量真实世界物理量的设备，并为其设置事件处理。

传感器的范围很广：从必须以固定量程轮询、非常简单的温度读取设备，到从大量传感器获取读数并自行生成新的推断数据（如步数、存在检测、方向等）的复杂设备。

支持如此多样的设备是一项艰巨的任务，传感器 API 试图为它们提供统一的接口。

使用传感器

在应用程序中使用传感器时，了解一些 API 和术语会有所帮助。Zephyr 中的传感器由 传感器通道、传感器属性 和 传感器触发器 组成。属性和触发器可以是设备特定的，也可以是通道特定的。

备注

目前使用传感器 API 从传感器获取采样有两种方式：一种是稳定且长期存在的 API 获取与读取（Fetch and Get），另一种是较新但正在快速稳定的 API 读取与解码（Read and Decode）。预计在不久的将来，获取与读取（Fetch and Get） 将被弃用，转而使用 读取与解码（Read and Decode）。获取与读取（Fetch and Get） 和 读取与解码（Read and Decode） 对触发器的处理方式完全不同，其差异在各自的章节中有说明。

实现传感器驱动

备注

实现传感器 API 的驱动侧，需要了解传感器 API 的使用方式。请先通读 使用传感器！

实现属性

  • 应当（SHOULD）以阻塞方式实现属性设置。

  • 如果设备支持，应当（SHOULD）提供获取和设置通道量程的能力。

  • 如果设备支持，应当（SHOULD）提供获取和设置通道采样率的能力。

实现获取与读取（Fetch and Get）

  • 应当（SHOULD）将 sensor_sample_fetch_t 实现为阻塞调用，把指定通道（或所有传感器通道）的数据暂存为驱动实例数据。

  • 应当（SHOULD）将 sensor_channel_get_t 实现为无副作用、不改变驱动状态的调用，返回暂存的传感器读数。

  • 实现 sensor_trigger_set_t 时，应当（SHOULD）保存 sensor_trigger 的地址，而不是复制其内容。这样就可以使用 CONTAINER_OF 获取触发器回调的上下文。

实现读取与解码（Read and Decode）

  • 必须（MUST）将 sensor_submit_t 实现为非阻塞调用。

  • 实现 sensor_submit_t 时，如有可能，应当（SHOULD）使用 实时 I/O（RTIO） 进行非阻塞总线传输。

  • 如果总线不支持 实时 I/O（RTIO），可以（MAY）使用工作队列实现 sensor_submit_t。

  • 实现 sensor_submit_t 时，应当（SHOULD）检查 rtio_sqe 的类型是否为 RTIO_SQE_RX（读请求）。

  • 实现 sensor_submit_t 时，应当（SHOULD）检查所有请求的通道是否都受支持，否则返回错误。

  • 实现 sensor_submit_t 时，应当（SHOULD）检查所提供的缓冲区是否足以容纳所请求的通道。

  • 实现 sensor_submit_t 时，应当（SHOULD）直接读入所提供的缓冲区，避免任何形式的复制，少数例外情况除外。

  • 必须（MUST）使用纯粹的无状态函数实现 sensor_decoder_api。将原始传感器读数转换为以 SI 单位表示的定点数值所需的全部状态，都必须包含在所提供的缓冲区中。

  • 必须（MUST）实现 sensor_get_decoder_t，返回该设备类型的 sensor_decoder_api。
