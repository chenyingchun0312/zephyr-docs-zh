虚拟 I/O（VIRTIO）

概述

虚拟 I/O（VIRTIO）是一种用于与各种设备通信的协议，通常用于虚拟化环境。它的主要目标是提供一种高效、标准化的机制，用于在虚拟机内部与虚拟设备交互。通信依赖于 virtqueue 以及 PCI 或 MMIO 等标准传输方式。

概念

Virtio 定义了通信和初始化过程中使用的各种组件。它同时规定了主机端（规范中称为“device”）和客户机端（规范中称为“driver”）。目前 Zephyr 只能作为客户机运行。在 Virtio 驱动提供的功能之上，可以实现特定设备（例如网卡）的驱动。

配置空间

每个设备都提供配置空间，用于初始化和配置。通过配置空间可以选择设备和驱动特性、启用特定的 virtqueue 并设置其地址。设备配置完成后，大部分配置在不复位设备的情况下无法更改。配置空间的具体布局取决于传输方式。

驱动特性与设备特性

配置空间提供了一种协商特性位的方式，用于确定设备的一些非强制性能力。具体可用的特性位取决于设备和平台。

设备特定配置

部分设备提供设备特定的配置空间，用于提供额外的配置选项。

Virtqueue

在主机和客户机之间传输数据的主要机制是 virtqueue。不同设备的 virtqueue 数量不同，例如支持双向传输的设备通常有一对或多对 tx/rx virtqueue。Virtio 规定了两种 virtqueue：拆分式（split）virtqueue 和紧凑式（packed）virtqueue。Zephyr 目前只支持拆分式 virtqueue。

拆分式 virtqueue

拆分式 virtqueue 由三部分组成：描述符表、可用环（available ring）和已用环（used ring）。

描述符表保存缓冲区的描述符，即缓冲区的物理地址、长度和标志。每个描述符要么可由设备写入，要么可由驱动写入。描述符可以链接起来，形成描述符链。通常，一条描述符链以包含供设备读取的数据的描述符开头，以设备可写的部分结尾，设备会把响应放在该部分中。

可用环的主体是一个环形缓冲区，其中保存指向描述符表中描述符的引用（以索引形式）。当客户机决定向主机发送数据时，会把描述符链头部的索引添加到可用环的顶部。

已用环与可用环类似，但由主机用来将描述符归还给客户机。除了存储描述符索引外，它还提供写入这些描述符的数据量信息。

通用 Virtio 库

Zephyr 提供了用于与 Virtio 设备和 virtqueue 交互的 API，可在 Virtio 设备的整个生命周期内执行必要的操作。

设备初始化

Virtio 驱动完成使用给定传输方式的所有设备共有的底层初始化（例如在总线上查找设备、映射 Virtio 结构）后，由设备特定驱动接手，借助 Virtio API 执行后续阶段的初始化。

设备特定驱动首先进行特性位协商。它使用 virtio_read_device_feature_bit() 确定设备提供哪些特性，然后使用 virtio_write_driver_feature_bit() 选择所需的特性。选择完所有需要的特性后，设备特定驱动调用 virtio_commit_feature_bits()。接着使用 virtio_init_virtqueues() 初始化 virtqueue。该函数会枚举各个 virtqueue，并调用所提供的回调 virtio_enumerate_queues 来确定每个 virtqueue 所需的大小。最后调用 virtio_finalize_init() 完成初始化过程。此后，如果上述函数均未返回错误，virtqueue 即可投入使用。如果具体设备提供了设备特定配置，可以通过调用 virtio_get_device_specific_config() 获取。

Virtqueue 操作

virtqueue 可用后，即可用来发送和接收数据。为此，需要先使用 virtio_get_virtqueue() 获取指向第 n 个 virtqueue 的指针。要发送由描述符链组成的数据，需要使用 virtq_add_buffer_chain()。除描述符链外，该函数还接收一个回调指针，设备归还该描述符链时会调用此回调。之后，需要使用 Virtio API 中的 virtio_notify_virtqueue() 通知该 virtqueue。

客户机端 Virtio 驱动

目前 Zephyr 提供了基于 PCI 的 Virtio 驱动和基于 MMIO 的 Virtio 驱动，以及三个使用 virtio 的设备驱动：virtiofs，用于访问主机的文件系统；virtio-entropy，用作熵源；virtio-blk，用于访问块设备。

Virtiofs

此驱动提供对 virtiofs 的支持，这是一种允许虚拟机客户机访问主机上某个目录的文件系统。它使用 FUSE 消息在主机和客户机之间通信，以执行打开、读取文件等文件系统操作。每当客户机要执行某个文件系统操作时，它会在 virtqueue 中放入一条描述符链：链的开头是设备可读部分，包含 FUSE 输入头和输入数据；结尾是设备可写部分，为 FUSE 输出头和输出数据预留空间。

Virtio-entropy

此驱动允许在 Zephyr 中将 virtio-entropy 用作熵源。该设备的工作方式很简单：驱动在 virtqueue 中放入一个缓冲区，然后收回填满随机数据的缓冲区。

Virtio-blk

此驱动将 virtio-blk 块设备提供给 Zephyr 的磁盘访问层，因此可以通过 磁盘访问 API 使用它，并可在其上挂载文件系统。它同一时间只处理一个请求，提交的描述符链由请求头、作为一个或多个分散-聚集（scatter-gather）段的调用者数据缓冲区以及一个状态字节组成。详情见 VirtIO 块设备。

Virtio 示例

virtiofs filesystem 中提供了一个示例，展示如何使用依赖 Virtio 的驱动。如果想查看直接与 Virtio 驱动交互的代码，可以参考 virtiofs 驱动，尤其是用于初始化的 virtiofs_init()，以及用于与 Virtio 设备收发数据的 virtiofs_send_receive() 和 virtiofs_recv_cb()。
