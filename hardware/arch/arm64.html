ARM64 开发者指南

带超时的等待（WFxT）

Arm WFxT 扩展提供 WFET 和 WFIT 指令，它们以一个绝对的虚拟计数器值作为超时。Zephyr 在运行时根据 ID_AA64ISAR2_EL1 中的 WFxT 字段检测该扩展。Arm64 架构代码可以使用 include/zephyr/arch/arm64/lib_helpers.h 中声明的 is_wfxt_implemented() 查询是否支持该扩展。

当 Arm 架构定时器实现了 arch_busy_wait() 时，如果实现了 WFxT，Arm64 路径会使用 WFET 来实现 k_busy_wait()。它根据 CNTVCT_EL0 计算出截止时间，并重复执行 WFET，直到计数器到达该截止时间。之所以需要循环，是因为 WFET 允许在超时之前返回。不支持 WFxT 的 CPU 则改用计数器轮询。实现见 drivers/timer/arm_arch_timer.c。

默认的 Arm64 arch_cpu_idle() 实现仍使用 WFI。使用 Arm 架构定时器时，内核的下一个超时会编程到系统定时器中，由其中断唤醒 CPU。如果在保留该中断的同时用 WFIT 替代 WFI，并不能省去定时器编程或中断处理。若要避免该中断，就需要对内核的超时计算、重新调度以及 SMP 截止时间协调进行复杂的修改，这会带来相当大的风险和维护成本，却没有已证实的收益。

基于设备树的 MMU 区域映射

在 ARM64 平台上，可以在编译时根据设备树自动填充 MMU 页表。任何 compatible = "zephyr,memory-region" 且带有 zephyr,memory-attr 属性的节点，都会被架构启动代码转换为一个静态的 arm_mmu_region 条目，无需修改各 SoC 的 mmu_regions.c。

支持的内存属性

只接受 Normal 内存类型。设备内存（外设 MMIO）必须通过 DEVICE_MMIO API 映射（见 设备驱动模型）。

这些属性宏定义在 include/zephyr/dt-bindings/memory-attr/memory-attr-arm64.h 中，是通用的 DT_MEM_CACHEABLE 标志与架构特定子属性的可组合组合：

DT 宏

说明

DT_MEM_ARM64_MMU_NORMAL

Normal 回写（write-back）可缓存（DT_MEM_CACHEABLE | ATTR_ARM64_CACHE_WB）

DT_MEM_ARM64_MMU_NORMAL_NC

Normal 不可缓存（0）

DT_MEM_ARM64_MMU_NORMAL_WT

Normal 写直通（write-through）可缓存（DT_MEM_CACHEABLE）

设备树覆盖文件（overlay）示例

#include <zephyr/dt-bindings/memory-attr/memory-attr.h>
#include <zephyr/dt-bindings/memory-attr/memory-attr-arm64.h>

/ {
    soc {
        /* Cacheable shared memory pool */
        shm0: memory@42000000 {
            compatible = "zephyr,memory-region";
            reg = <0x0 0x42000000 0x0 0x1000>;
            zephyr,memory-region = "SHM0";
            zephyr,memory-attr = <DT_MEM_ARM64_MMU_NORMAL>;
        };

        /* Non-cacheable DMA buffer */
        dma_buf: memory@43000000 {
            compatible = "zephyr,memory-region";
            reg = <0x0 0x43000000 0x0 0x1000>;
            zephyr,memory-region = "DMA_BUF";
            zephyr,memory-attr = <DT_MEM_ARM64_MMU_NORMAL_NC>;
        };
    };
};

每个区域都以 MT_P_RW_U_NA | MT_DEFAULT_SECURE_STATE 与从 zephyr,memory-attr 推导出的内存类型组合后进行映射。

转换表大小

每个位于不同 2 MB 边界上的已映射区域都需要额外的一个 Level 3 页表。如果添加新区域后启动过程无声地挂起，请在开发板或测试配置中增大 CONFIG_MAX_XLAT_TABLES：

CONFIG_MAX_XLAT_TABLES=16

支持的属性组合

所有非设备属性组合都是有效的：通用位 DT_MEM_CACHEABLE 选择可缓存或不可缓存；可缓存时，架构特定子位 ATTR_ARM64_CACHE_WB 选择回写或写直通。
