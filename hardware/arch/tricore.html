TriCore AURIX 开发者指南

概述

本页介绍 Zephyr 中 Infineon TriCore AURIX 架构移植的状态，以及为 AURIX 平台开发 Zephyr 应用程序时需要注意的方面。

TriCore 架构是一种面向实时嵌入式系统的统一 32 位微控制器-DSP 架构。它在单个核心中集成了微控制器的实时能力、DSP 的运算能力以及 RISC 加载/存储架构的性能。

该移植涵盖两个 AURIX SoC 家族：

  • 使用 TC1.6.2P ISA 的 AURIX TC3xx

  • 使用 TC1.8P ISA 的 AURIX TC4x

目前两者都只通过 QEMU 开发板提供支持，见 支持的开发板。

架构

寄存器

TriCore 架构提供 32 个通用寄存器（GPR），分为 16 个 32 位数据寄存器（D[0] 到 D[15]）和 16 个 32 位地址寄存器（A[0] 到 A[15]）。此外，程序计数器（PC）、程序状态字（PSW）和前一上下文信息寄存器（PCXI）构成核心系统状态。

有几个地址寄存器和数据寄存器具有专门用途：

  • A[10]：栈指针（SP）

  • A[11]：返回地址（RA）

  • A[0]、A[1]、A[8]、A[9]：全局地址寄存器

  • D[15]：隐式数据寄存器

  • A[15]：隐式基地址寄存器

TC4x 的 TC1.8P 核心实现了虚拟机管理程序（hypervisor）扩展，并以虚拟化模式启动。当 SoC select CONFIG_CPU_HAS_TRICORE_VIRTUALIZATION 时，启动代码会降级到默认虚拟机中运行。

上下文保存区（CSA）

TriCore 架构使用上下文保存区（CSA）在硬件中保存和恢复上下文。每个 CSA 是一个 64 字节的内存块，按 64 字节边界对齐。CSA 链接在一起，形成两个链表：

  • 空闲上下文链表（FCX）：可用 CSA 池

  • 前一上下文链表（PCX）：当前执行路径上已保存上下文的链

寄存器组分为上部上下文和下部上下文：

  • 上部上下文（在中断、陷阱和调用时自动保存）：A[10]-A[15]、D[8]-D[15]、PSW 和 PCXI。

  • 下部上下文（通过 SVLCX 或 BISR 指令显式保存）：A[2]-A[7]、D[0]-D[7]、A[11] 和 PCXI。

因此，在上下文切换、中断进入或函数调用时，软件无需压栈和出栈寄存器。

在 Zephyr 中，CSA 池是一个包含 CONFIG_TRICORE_CSA_COUNT 个条目的静态数组。arch/tricore/core/reset.S 中的启动代码将所有 CSA 链接到空闲链表中，并设置 FCX 和 LCX 寄存器。LCX 被设置在距链表末尾 CONFIG_TRICORE_CSA_FCD_RESERVE 个条目的位置，这样空闲上下文链表耗尽（FCD）陷阱处理程序仍有剩余的 CSA 可用于报告故障并中止线程。

操作系统特性

线程

线程栈对齐

TriCore 上的 Zephyr 线程使用 8 字节栈对齐（ARCH_STACK_PTR_ALIGN = 8），与 EABI 对栈指针的要求一致。

栈指针

TriCore 架构使用单个栈指针寄存器 A[10]。PSW.IS 位表示处理器是运行在线程栈上还是中断栈上。在 PSW.IS == 0 的情况下进入中断或陷阱时，硬件会从中断栈指针（ISP）寄存器加载 A[10]，并设置 PSW.IS = 1。

在 Zephyr 中，所有异常和中断共享同一个中断栈。其大小由 CONFIG_ISR_STACK_SIZE 控制。

线程上下文切换

上下文切换使用 SYSCALL 指令。arch_switch() 执行 syscall 1，以监管者模式进入系统调用陷阱处理程序。该处理程序保存下部上下文并调用 z_tricore_switch()，后者会：

  • 将当前的 PCXI（即换出线程 CSA 链的头部）保存到换出线程中，

  • 加载换入线程的 PCXI 并返回。

随后，处理程序通过 RSLCX 恢复换入线程的下部上下文，并通过 RFE 返回，RFE 会恢复其上部上下文。

当线程中止自身时，内核通过 to_reclaim 将其交出，处理程序会在切换之后将其 CSA 链归还到空闲链表中。

上下文切换也可以从中断上下文中触发。在最外层中断返回（nested == 0）且没有更高优先级的中断挂起（ICR.PIPN == 0）时，_isr_wrapper 会向调度器请求下一个线程。

实现位于 arch/tricore/core/switch.S、arch/tricore/core/syscall_wrapper.S 和 arch/tricore/core/isr_wrapper.S 中。

中断处理

中断优先级

TriCore 架构最多支持 255 个中断优先级。每个中断源都在中断路由器（IR）中其服务请求控制（SRC）寄存器内被分配一个服务请求优先级号（SRPN）。ICR（中断控制寄存器）保存当前 CPU 优先级号（CCPN）和挂起中断优先级号（PIPN）。

当 ICR.IE == 1 且 PIPN > CCPN 时，中断被响应。

进入中断时，硬件会：

  • 将上部上下文保存到一个 CSA 中，

  • 设置 PCXI.PIE = ICR.IE 和 PCXI.PCPN = ICR.CCPN，

  • 设置 ICR.CCPN = ICR.PIPN 和 ICR.IE = 0，

  • 如果尚未处于中断栈上，则从 ISP 加载 A[10]，

  • 跳转到位于 BIV + 32 * PIPN 的向量入口。

Zephyr 提供 256 个间隔为 32 字节的向量入口。每个入口保存下部上下文并跳转到 _isr_wrapper，后者从中断路由器读取当前活动的中断号，并通过软件 ISR 表进行分派。_isr_wrapper 在调用处理程序之前会重新启用中断，因此更高优先级的中断可以嵌套。

从中断返回（RFE）时，硬件会从 PCXI 恢复上部上下文和之前的 ICR 状态。

向量位于 arch/tricore/core/vectors.c 中。

锁定和解锁 IRQ

arch_irq_lock() 将当前的 ICR 值作为 key 返回，并执行 DISABLE 指令清除 ICR.IE。如果 key 中设置了 ICR.IE，arch_irq_unlock() 会执行 ENABLE。

动态中断

启用 CONFIG_DYNAMIC_INTERRUPTS 后，可以在运行时通过软件 ISR 表连接中断。

CPU 空闲

arch_cpu_idle() 启用中断，arch_cpu_atomic_idle() 则根据其 key 恢复中断状态；随后两者都执行 WAIT，核心在下一个中断到来时被唤醒。

实现位于 arch/tricore/core/cpu_idle.c 中。

陷阱处理

TriCore 架构定义了 8 类陷阱，向量间隔为 32 字节，通过 BTV（基陷阱向量）寄存器寻址：

  • 第 0 类：MMU 陷阱

  • 第 1 类：内部保护陷阱（特权指令、内存保护、全局寄存器写保护）

  • 第 2 类：指令错误（非法或未实现的操作码、无效操作数、对齐、无效的本地内存地址）

  • 第 3 类：上下文管理（空闲上下文耗尽、调用深度溢出）

  • 第 4 类：系统总线和外设错误

  • 第 5 类：断言陷阱

  • 第 6 类：系统调用（SYSCALL 指令）

  • 第 7 类：不可屏蔽中断（NMI）

Zephyr 将第 0 到 5 类以及第 7 类陷阱路由到 z_tricore_fault()，它会记录陷阱类别、陷阱标识号（TIN）和寄存器转储，然后调用 z_fatal_error()。空闲上下文链表下溢（FCU，第 3 类 TIN 4）时没有剩余的 CSA 可用于处理该陷阱，核心会停机。

系统调用陷阱（第 6 类）用于上下文切换（syscall 1）、引发异常（syscall 2）和 IRQ 卸载（syscall 3）。

实现位于 arch/tricore/core/fatal.c 和 arch/tricore/core/vectors.c 中。

浮点

TriCore 的 FPU 集成在数据通路中，对 D[0]-D[15] 数据寄存器进行运算。没有单独的 FPU 数据寄存器。FPU 的舍入模式和异常标志保存在 PSW 中，而 PSW 在中断、陷阱和调用时作为上部上下文的一部分被保存和恢复。

FPU 陷阱控制和捕获寄存器（FPU_TRAP_CON 及其后的 FPU_TRAP_* 寄存器）不属于上下文。Zephyr 不启用 FPU 陷阱，因此对线程有意义的 FPU 状态都在已保存的上下文中，在多线程应用程序中无需额外处理。

  • TC3xx（TC1.6.2P）：单精度 FPU（IEEE 754）

  • TC4x（TC1.8P）：单精度和双精度 FPU（IEEE 754）

工具链

TriCore 移植使用 Infineon 提供的 11.3.1 版 AURIX GCC 工具链构建：Infineon AURIX GCC

export ZEPHYR_TOOLCHAIN_VARIANT=tricore
export TRICORE_TOOLCHAIN_PATH=/path/to/tricore-gcc

TRICORE_TOOLCHAIN_PATH 默认为 /opt/toolchains/tricore-elf。

备注

Zephyr SDK 不包含 TriCore 工具链。
