内核对象

内核对象可以是以下三类数据之一：

  • 核心内核对象，例如信号量、线程、管道等。

  • 线程栈，即 z_thread_stack_element 数组，使用 K_THREAD_STACK_DEFINE() 声明

  • 属于某个已定义子系统集合的设备驱动实例（const struct device）

已知的内核对象和驱动子系统集合在 include/zephyr/sys/kobject.h 中定义为 k_objects。

内核对象对用户线程完全不透明。用户线程在进行 API 调用时使用内核对象的地址，但绝不能解引用这些地址，否则会引发内存保护故障。所有内核对象都必须放在用户线程无法访问的内存中。

由于用户线程不能直接操作内核对象，对内核对象的所有使用都必须通过系统调用进行。对内核对象执行系统调用时，系统调用处理函数会检查该内核对象地址是否有效，以及调用线程是否有足够的权限使用它。

对对象拥有权限还具有对该对象持有引用的语义。这对于某些会进行临时分配的对象 API，或者本身是从运行时内存池中分配的对象来说很重要。

如果一个对象失去了所有引用，可能会发生两件事：

  • 如果该对象有关联的清理函数，可能会调用该清理函数来释放该对象正在使用的所有运行时分配的缓冲区。

  • 如果该对象本身是动态分配的，则会释放该对象的内存。

对象的放置

仅由管理态线程使用的内核对象没有任何限制，可以位于二进制文件中的任何位置，甚至可以在栈上声明。但为了防止用户线程意外或故意破坏它们，这些对象不得位于用户线程可以直接访问的任何内存中。

要让用户线程能够通过系统调用 API 使用静态内核对象，该内核对象的声明方式必须满足以下几个条件：

  • 该对象必须在构建时声明为顶层全局对象，使其出现在 ELF 符号表中。允许以 static 作用域声明内核对象。构建后脚本 scripts/build/gen_kobject_list.py 会扫描生成的 ELF 文件以查找内核对象，并将其内存地址放入一张特殊的内核对象元数据表中。内核对象可以是数组的成员，也可以嵌入在其他数据结构中。

  • 内核对象必须位于为内核保留的内存中，不得位于任何用户可访问的内存分区中。

  • 为内核对象保留的任何内存都必须专供该对象使用。内核对象不能是联合体（union）类型的成员。

被找到但不满足上述条件的内核对象，不会被纳入生成的表中，而该表用于校验从用户模式传入的内核对象指针。

在调试某个对象为何意外地未被跟踪时，scripts/build/gen_kobject_list.py 脚本的调试输出可能会有帮助。如果运行脚本时带有 --verbose 标志，或者以详细输出模式调用构建系统，就会打印这些信息。

动态对象

如果启用了 CONFIG_DYNAMIC_OBJECTS，还可以在运行时分配内核对象。此时可以使用 k_object_alloc() API 从调用线程的资源池中实例化对象。这类分配可以通过两种方式释放：

  • 管理态线程可以调用 k_object_free() 强制释放动态对象。

  • 如果对象的引用计数降为零（即没有任何线程对其拥有权限），该对象会被自动释放。用户线程可以用 k_object_release() 放弃自己对某个对象的权限，线程终止时其权限也会被自动清除。此外，管理态线程还可以使用 k_object_access_revoke() 撤销另一个线程的引用。

由于权限也用于引用计数，即使权限系统的访问控制部分对管理态线程不起作用，管理态线程也应获取其所用对象的权限，这一点很重要。

实现细节

scripts/build/gen_kobject_list.py 脚本是一个构建后步骤，用于找出二进制文件中所有有效的内核对象实例。它通过解析为内核生成的 ELF 文件中的 DWARF 调试信息来实现这一点。

对于与内核对象对应、且满足对象放置条件的所有结构体或数组实例，其内存地址都会被放入一张由“gperf”工具生成的特殊内核对象完美哈希表中。当进行系统调用、内核拿到一个可能是也可能不是有效内核对象的内存地址时，可以通过在该表中进行常数时间查找来校验该地址。

驱动是一种特殊情况。所有驱动都是 device 的实例，但必须知道驱动属于哪个子系统，才能阻止错误的操作，例如在传感器驱动对象上调用 UART API。找到 device 结构体后，会检查其 API 指针，以确定该驱动属于哪个子系统。

该表本身把内核对象的内存地址映射到 z_object 实例，后者包含该对象的所有元数据，包括：

  • 一个表示该对象权限的位域。所有线程在构建时都会被分配一个数字 ID，用于索引对象的权限位域，以判断该线程是否对其拥有权限。该位域的大小由 CONFIG_MAX_THREAD_BYTES 选项控制，如果该值过小，构建系统会报错。

  • 一个表示对象种类的类型字段，其值为 k_objects 的某个成员。

  • 该对象的一组标志，目前用于跟踪初始化状态以及对象是否为公开对象。

  • 一个额外数据字段。该字段的语义因对象类型而异，参见 z_object_data 的定义。

运行时分配的动态对象在一棵运行时红黑树中跟踪，校验对象指针时会同时查询这棵树和 gperf 表。

管理态线程的访问权限

管理态线程可以访问任何内核对象。但出于以下两个原因，仍然会跟踪管理态线程的权限：

  • 如果管理态线程调用 k_thread_user_mode_enter()，该线程随后将以用户模式运行，并拥有它作为管理态线程时被授予（在很多情况下是由它自己授予）的所有权限。

  • 如果管理态线程使用 K_INHERIT_PERMS 选项创建用户线程，子线程将被授予与父线程相同的权限，但父线程对象本身除外。

用户线程的访问权限

默认情况下，用户线程创建时只对其自身的线程对象拥有访问权限，其他内核对象默认都不可用。对它们的访问需要显式或隐式地授予，有以下几种方式。

  • 如果线程以 K_INHERIT_PERMS 创建，该线程将继承父线程的所有权限，但父线程对象本身除外。

  • 对某个对象拥有权限或运行在管理态模式下的线程，可以通过 k_object_access_grant() API 把该对象的权限授予另一个线程。也可以使用便捷的伪函数 k_thread_access_grant()，它接受任意数量的内核对象指针，并对每个指针调用 k_object_access_grant()。被授予权限的线程以及被授予访问权限的对象都不必处于已初始化状态。如果调用者来自用户模式，则调用者必须同时对该内核对象和目标线程对象拥有权限。

  • 管理态线程可以使用 k_object_access_all_grant() API 将某个内核对象声明为公开对象，供当前和将来的所有线程使用。此时必须假定任何不可信或被攻破的代码都能访问该对象。请谨慎使用此 API！

  • 如果线程是用 K_THREAD_DEFINE() 静态声明的，则可以使用 K_THREAD_ACCESS_GRANT() 在启动时授予该线程对一组内核对象的访问权限。

线程被授予对某个对象的访问权限后，可以用 k_object_access_revoke() API 移除该权限。用户线程不能使用此 API，但可以使用 k_object_release() 放弃自己对某个对象的权限。

管理态线程可以使用 k_object_access_revoke_others() 撤销除调用者以外所有线程的访问权限。如果之前曾把访问权限授予某个不可信的用户线程，而该线程可能又把权限转授给了其他线程，此 API 可用于重置该对象的权限。此 API 还会撤销先前可能通过 k_object_access_all_grant() 设置的公开访问状态。

从管理态模式调用 API 为未被内核跟踪的内核对象设置权限，不会有任何效果。从用户模式这样做则会导致调用线程发生致命错误。

用 k_object_alloc() 分配的对象会隐式地把该对象的权限授予调用线程。

初始化状态

如果对象被认为处于未初始化状态，对内核对象的大多数操作都会失败。必须先执行该对象相应的初始化函数。

有些对象会在启动时被隐式初始化：

  • 用静态初始化宏（例如信号量的 K_SEM_DEFINE）声明的内核对象在构建时就处于已初始化状态。

  • 设备驱动对象在内核于启动过程早期运行其初始化函数之后，即被视为已初始化。

如果内核对象是用私有的静态初始化器初始化的，则必须由管理态线程在某个时刻对该对象调用 k_object_init()，否则当用户线程访问该对象时，内核会认为它未初始化。这种情况很少见，通常只出现在嵌入某个更大的结构体中并被静态初始化的内核对象上。

struct foo {
    struct k_sem sem;
    ...
};

struct foo my_foo = {
    .sem = Z_SEM_INITIALIZER(my_foo.sem, 0, 1),
    ...
};

...
k_object_init(&my_foo.sem);
...

创建新的内核对象类型

在实现新的内核特性或驱动子系统时，可能需要定义一些新的内核对象类型。创建核心内核对象和新的驱动子系统所需的步骤有所不同。

创建新的核心内核对象

  • 在 scripts/build/gen_kobject_list.py 中，把该结构体的名称加入 kobjects 列表。

此后新结构体的实例就会被跟踪。

创建新的驱动子系统内核对象

所有驱动实例都是 device，它们通过所设置的 API 结构体加以区分。

  • 在 scripts/build/gen_kobject_list.py 中，把新子系统的 API 结构体名称加入 subsystems 列表。

此后新子系统的驱动实例就会被跟踪。
