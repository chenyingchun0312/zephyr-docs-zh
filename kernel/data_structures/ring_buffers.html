环形缓冲区

ring buffer（环形缓冲区）是一种循环缓冲区，其内容按先进先出的顺序存储。

当应用程序需要实现异步的“流式”数据复制时，Zephyr 提供了 struct ring_buf 抽象，用于管理此类数据复制进出共享内存缓冲区的过程。

概念

可以定义任意数量的环形缓冲区（仅受可用 RAM 限制）。每个环形缓冲区通过其内存地址引用。

环形缓冲区具有以下关键属性：

  • 一个字节 数据缓冲区。数据缓冲区包含已添加到环形缓冲区但尚未取出的原始字节。

  • 数据缓冲区大小，以字节为单位。它决定了环形缓冲区可以容纳的最大数据量。

环形缓冲区在使用前必须初始化。初始化会将其数据缓冲区置为空。

struct ring_buf 可以放在用户可访问内存中的任意位置，并且必须在使用前通过 ring_buf_init() 初始化。初始化时必须提供一块由用户控制的内存区域，用作缓冲区本身。请特别注意，传入的缓冲区大小的单位（字节或字）会因环形缓冲区之后的使用方式而不同。为方便起见，还提供了一些宏，可以将这些步骤合并到一个静态声明中。RING_BUF_DECLARE 会声明并静态初始化一个具有指定字节数的环形缓冲区，其中

可以使用 ring_buf_put() 将“字节”数据复制到环形缓冲区中，需要传入数据指针和字节数。这些字节会按顺序复制到缓冲区，复制的数量以已分配缓冲区能容纳的为限。函数返回实际复制的总字节数（可能少于提供的字节数）。同样，ring_buf_get() 会按写入顺序将字节从环形缓冲区复制到用户提供的缓冲区中，并返回传输的字节数。

为避免数据被多次复制，还提供了一套零拷贝的“指针” API。ring_buf_put_ptr() 返回一个指向环形缓冲区内部内存的指针，可用于接收字节，同时返回可供写入的连续内部区域的大小（如果区域发生回绕，该大小可能小于总空闲空间）。然后，用户可以直接将数据写入该区域（例如通过 DMA），而无需先将所有字节汇集到一个区域中。完成后，使用 ring_buf_commit() 通知缓冲区传输已完成，并传入实际传输的字节数。此时即可发起新的传输。类似地，ring_buf_get_ptr() 返回一个指向环形缓冲区内部数据的指针，用户可以直接从中读取而无需逐字复制；ring_buf_consume() 则告知缓冲区已消费了多少字节，并允许开始新的传输。

旧版的 ring_buf_put_claim() / ring_buf_put_finish() 和 ring_buf_get_claim() / ring_buf_get_finish() API 提供了类似的功能，但会在完成之前一直保留所申请的区域，这会带来额外的代码体积和运行时开销。这些 API 已被弃用，并将在未来的版本中移除；新代码应使用上文介绍的 _ptr / _commit / _consume 变体。

用户可以在不修改环形缓冲区的情况下管理其容量：使用 ring_buf_space_get() 获取空闲字节数，或者检测 ring_buf_is_empty() 谓词。

最后，调用 ring_buf_reset() 可以立即清空环形缓冲区，丢弃对已写入缓冲区的所有字节的跟踪。不过，它不会修改缓冲区本身的内存内容。

实例化与使用

环形缓冲区实例使用 RING_BUF_DECLARE() 声明，并通过以下函数访问：ring_buf_put_ptr()、ring_buf_commit()、ring_buf_get_ptr()、ring_buf_consume()、ring_buf_put() 和 ring_buf_get()。

可以将数据复制到环形缓冲区中（参见 ring_buf_put()），也可以由用户直接使用环形缓冲区的内存。在后一种情况下，操作分为三个阶段：

  1. 访问环形缓冲区的内部缓冲区（ring_buf_put_ptr()），获取指向下一个可写入数据位置的指针，以及该位置可用的连续空间大小。

  2. 由用户写入数据（例如由 DMA 写入缓冲区）。

  3. 指明写入所提供缓冲区的数据量（ring_buf_commit()）。提交的数据量可以小于或等于 ring_buf_put_ptr() 所提供的数据量。

可以通过复制从环形缓冲区中取出数据（参见 ring_buf_get()），也可以按地址直接访问数据。在后一种情况下，操作分为三个阶段：

  1. 访问环形缓冲区的内部缓冲区（参见 ring_buf_get_ptr()），获取指向下一个可读取数据位置的指针，以及该位置可用的连续数据量。

  2. 处理数据

  3. 通知环形缓冲区数据已被消费（参见 ring_buf_consume()）。消费的数据量可以小于或等于 ring_buf_get_ptr() 所提供的数据量。

并发

环形缓冲区 API 内部不提供任何并发控制。根据使用方式（尤其是并发读取者/写入者的数量），应用程序可能需要使用互斥量保护环形缓冲区，和/或使用信号量通知消费者有数据可读。

运行在不同执行上下文中（例如两个线程，或一个线程和一个 ISR）的单个生产者和单个消费者，可以在不额外加锁的情况下并发使用同一个环形缓冲区。生产者一方只更新 put 索引，消费者一方只更新 get 索引，因此双方永远不会写入相同的字段。这一点对复制 API（ring_buf_put() / ring_buf_get()）和零拷贝 “claim” API（ring_buf_put_claim() / ring_buf_put_finish() 以及 ring_buf_get_claim() / ring_buf_get_finish()）都成立。

当生产者和消费者运行在不同的 CPU 上（SMP）时，应用程序仍必须确保数据写入在发布这些数据的索引更新之前可见。实际上，当生产者和消费者使用内核同步原语进行协调时（例如由生产者发出信号、由消费者等待的 k_sem），这一点会自然得到满足，因为这些原语包含了必要的内存屏障。

任何存在多个并发生产者或多个并发消费者的使用场景，都必须在外部对这些访问进行串行化（例如使用互斥量或禁用抢占）。

内部操作

流经环形缓冲区的数据总是写入缓冲区中的下一个字节，到达末尾后回绕到第一个元素，“环形”结构由此得名。在内部，struct ring_buf 包含它自己的缓冲区指针及其大小，还包含一组 “head” 和 “tail” 索引，表示下一次读取和写入操作可以进行的位置。

对于使用常规 put/get API 的用户来说，这个边界是不可见的，但它会成为 “claim” API 的障碍，因为显然无法返回一个跨越缓冲区末尾的连续区域。这可能会让应用程序代码感到意外，并且当传输需要在缓冲区末尾附近进行时会带来性能上的影响，因为此类传输所需的 claim/finish 调用次数会翻倍。

实现

定义环形缓冲区

环形缓冲区使用 ring_buf 类型的变量定义，然后必须调用 ring_buf_init() 进行初始化。

可以在文件作用域使用宏在编译时定义并初始化环形缓冲区。该宏会定义环形缓冲区本身及其数据缓冲区。

以下代码定义了一个环形缓冲区：

#define MY_RING_BUF_BYTES 93
RING_BUF_DECLARE(my_ring_buf, MY_RING_BUF_BYTES);

数据入队

通过调用 ring_buf_put() 将字节复制到环形缓冲区。

uint8_t my_data[MY_RING_BUF_BYTES];
uint32_t ret;

ret = ring_buf_put(&ring_buf, my_data, MY_RING_BUF_BYTES);
if (ret != MY_RING_BUF_BYTES) {
    /* not enough room, partial copy. */
    ...
}

也可以通过直接访问环形缓冲区的内存向其中添加数据。例如：

uint32_t size;
uint32_t rx_size;
uint8_t *data;

/* Get pointer to writable area within the ring buffer memory. */
size = ring_buf_put_ptr(&ring_buf, &data, 0);

/* Work directly on a ring buffer memory. */
rx_size = uart_rx(data, size);

/* Indicate amount of valid data. rx_size must be equal or less than size. */
ring_buf_commit(&ring_buf, rx_size);

取出数据

通过调用 ring_buf_get() 将数据字节从环形缓冲区中复制出来。例如：

uint8_t my_data[MY_DATA_BYTES];
size_t  ret;

ret = ring_buf_get(&ring_buf, my_data, sizeof(my_data));
if (ret != sizeof(my_data)) {
    /* Fewer bytes copied. */
} else {
    /* Requested amount of bytes retrieved. */
    ...
}

也可以通过直接操作环形缓冲区的内存从中取出数据。例如：

uint32_t size;
uint32_t proc_size;
uint8_t *data;

/* Get pointer to readable data within the ring buffer memory. */
size = ring_buf_get_ptr(&ring_buf, &data, 0);

/* Work directly on a ring buffer memory. */
proc_size = process(data, size);

/* Indicate amount of data that has been consumed. proc_size must be equal
 * or less than size.
 */
ring_buf_consume(&ring_buf, proc_size);

配置选项

相关配置选项：

  • CONFIG_RING_BUFFER：恢复已弃用的旧版环形缓冲区 API（claim/finish 以及固定大小数据项 API）。环形缓冲区本身仅由头文件实现且始终可用，因此正常使用时不需要此选项。

  • CONFIG_RING_BUFFER_LARGE：将最大缓冲区大小从 32KB 增加到 1GB。
