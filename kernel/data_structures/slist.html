单向链表

Zephyr 提供了 sys_slist_t 类型，用于存储简单的单向链表数据（即每个链表元素保存指向下一个元素的指针，但不保存指向上一个元素的指针）。它支持以常数时间访问链表的第一个（头部）和最后一个（尾部）元素、在头部之前和尾部之后插入，以及以常数时间删除头部。删除后续节点需要访问“前一个”指针，因此只能通过搜索链表以线性时间完成。

用户可以在任何可访问的内存中实例化 sys_slist_t 结构体。使用前应通过 sys_slist_init() 或用 SYS_SLIST_STATIC_INIT 静态赋值进行初始化。其内部字段是不透明的，用户代码不应访问。

可以使用 sys_slist_peek_head() 和 sys_slist_peek_tail() 获取链表的端点节点。如果链表为空，这两个函数返回 NULL，否则返回指向 sys_snode_t 结构体的指针。

sys_snode_t 结构体表示要插入的数据。一般来说，它应由用户分配和控制，通常嵌入在要添加到链表中的结构体内。可以使用 SYS_SLIST_CONTAINER 从链表节点获取外层结构体的指针，需要向其传入外层结构体的结构体名称和节点的字段名。在内部，sys_snode_t 结构体只包含一个 next 指针，可以通过 sys_slist_peek_next() 访问。

可以使用 sys_slist_prepend() 和 sys_slist_append() 在头部或尾部添加单个节点来修改链表。也可以使用 sys_slist_insert() 在内部位置添加节点，它会在现有节点之后插入新节点。同样，给定指向前驱节点的指针，sys_slist_remove() 会删除该节点。这些操作都是常数时间的。

对于更复杂的链表修改，还提供了一些便捷例程。sys_slist_merge_slist() 会将整个链表追加到现有链表上。sys_slist_append_list() 会以常数时间追加现有链表中一段有界的子集。sys_slist_find_and_remove() 会（以线性时间）在链表中搜索给定节点，如果存在则将其删除。

最后，slist 实现提供了一组 “for each” 宏，可以用自然的方式遍历链表，而无需手动沿 next 指针遍历。SYS_SLIST_FOR_EACH_NODE 会枚举链表中的每个节点，需要提供一个用于保存节点指针的局部变量。SYS_SLIST_FOR_EACH_NODE_SAFE 的行为类似，但实现更复杂，需要一个额外的临时变量用于存储，并允许用户在迭代过程中删除当前迭代的节点。这些宏都还有一个 “container” 变体（SYS_SLIST_FOR_EACH_CONTAINER 和 SYS_SLIST_FOR_EACH_CONTAINER_SAFE），它们会对一个类型与用户外层结构体（而非节点结构体）相匹配的局部变量赋值，并在内部完成所需的偏移计算。此外，SYS_SLIST_ITERATE_FROM_NODE 允许只枚举某个节点及其所有后继节点，而不检查链表的前面部分。

单向链表内部实现

slist 代码的设计力求精简和常规。在内部，sys_slist_t 结构体只不过是一对 “head” 和 “tail” 指针字段，而 sys_snode_t 只保存一个 “next” 指针。

不过，链表代码的具体实现是通过一个内部的 “Z_GENLIST” 模板 API 完成的，它可以从任意结构体中提取这些字段，并生成一组任意命名的函数。这样就可以使用相同的基本原语实现更复杂的单向链表变体。genlist 的实现者只需负责基本操作的自定义实现：每个结构体的 “init” 步骤，以及相关结构体上 head、tail 和 next 指针各自的 “get” 和 “set” 原语。这些内联函数作为参数传给 genlist 宏展开。

目前 Zephyr 中只有一个这样的变体，即 sflist。

带标志链表

sys_sflist_t 使用上述 genlist 模板 API 实现。除了符号命名（“sflist” 而非 “slist”）和下面介绍的额外 API 之外，它在各方面的行为都与 slist API 完全相同。

它增加了为每个链表节点关联恰好两位用户自定义“标志”的能力。可以通过 sys_sfnode_flags_get() 和 sys_sfnode_flags_set() 访问和修改这些标志。在内部，这些标志与 next 指针的最低几位以联合方式存储，与更简单的 slist 代码相比，不会产生额外的 SRAM 存储开销。
