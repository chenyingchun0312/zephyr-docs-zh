最小堆数据结构

  • 堆结构

  • 使用场景

  • 值变体与引用变体

  • 示例

  • API 参考

    • 值堆

    • 引用堆

最小堆实现提供了一种高效的数据结构，用于管理动态变化的元素列表，同时能够快速取出最小值。它是一种满足堆性质的树形数据结构，支持插入、删除以及从最小堆中弹出最小元素等常用操作

本节介绍该实现的设计动机、内部结构、API 用法，以及在嵌入式系统和实时环境中的示例场景。

堆结构

堆以存储在数组中的完全二叉树形式维护。每个节点都满足 最小堆 性质：

  • 每个节点的值都小于或等于其子节点的值。

这一性质确保 最小元素始终位于根部（索引 0）。

Index:      0   1   2   3   4   5   6
Values:    [1,  3,  5,  8,  9, 10, 12]

               1
             /   \
           3       5
          / \     / \
         8   9  10  12

对于索引为 i 的任意节点，其子节点的索引为：

  • 左子节点：\(2*i + 1\)

  • 右子节点：\(2*i + 2\)

其父节点的索引为：

  • 父节点：\((i - 1) / 2\)

使用场景

最小堆非常适合以下用途：

  • 实现优先级队列

  • 增量排序数据

  • 资源仲裁（例如选择成本最低的资源）

  • 协作式多任务系统中的调度

  • 管理超时和延迟队列

  • 基于优先级的传感器或数据采样

在 Zephyr 这样的 RTOS 环境中，该堆可用于内核级或应用级模块，满足以最小延迟获取最高优先级资源的需求。

值变体与引用变体

提供了两种变体，它们的区别仅在于元素的存储方式：

  • min_heap（如上所述）在连续缓冲区中 按值 存储元素。可以按内容（搜索）或按索引删除任意元素。它适合按内容查找小数据值的优先级队列。

  • min_heap_ref 存储指向调用者所拥有节点的 引用，每个节点中嵌入一个 min_heap_handle。插入操作是零拷贝的，并且可以利用调用者已持有的句柄在 \(O(\log n)\) 时间内删除特定节点，无需搜索。它适合按标识而非按内容删除的长期存在的对象，例如内核超时。

这两种变体互为补充：值堆按标识删除的复杂度无法优于 \(O(n)\)，而引用堆则不适合“按值存储并搜索”的用法。min_heap_ref 仅由头文件实现，不需要任何 Kconfig 配置。
