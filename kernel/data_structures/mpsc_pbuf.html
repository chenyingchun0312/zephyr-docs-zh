多生产者单消费者数据包缓冲区

Multi Producer Single Consumer Packet Buffer (MPSC_PBUF)（多生产者单消费者数据包缓冲区）是一种循环缓冲区，其内容按先进先出的顺序存储。缓冲区中存储的是可变大小的数据包。数据包缓冲区基于只有一个上下文消费数据的假设工作。不过，也可能有另一个上下文介入以刷出数据，并且再也不会返回（panic 的情况）。数据包的生产分两步进行：首先分配所请求数量的数据空间，生产者填入数据并提交。数据包的消费同样分两步进行：消费者申请（claim）数据包，获取指向它的指针及其长度，之后再释放该数据包。这种方式减少了内存复制。

MPSC Packet Buffer（MPSC 数据包缓冲区）具有以下关键特性：

  • 数据包生产采用“分配、提交”方案。

  • 数据包消费采用“申请、释放”方案。

  • 分配器确保分配所请求长度的连续内存。

  • 当无法分配所请求的空间时，可以采用以下策略：

    • 覆盖：丢弃最旧的条目，直到能够分配所请求数量的内存为止。每丢弃一个数据包都会调用用户回调。

    • 不覆盖：当无法分配所请求数量的空间时，分配失败。

  • 专门针对存储短数据包优化的 API。

  • 支持带超时的分配。

内部实现

缓冲区中的每个数据包都包含一个 MPSC_PBUF 专用头部，用于内部管理。头部由 2 个标志位组成。为了优化内存使用，可以使用 MPSC_PBUF_HDR 将该头部叠加在用户头部之上，第一个字中的其余位可以由应用程序自行定义。头部包含以下标志：

  • valid：当数据包包含有效的用户数据包时，该位置 1

  • busy：当数据包正在被消费（已申请但尚未释放）时，该位置位

内部跳过数据包

数据包缓冲区空间中包含空闲空间、有效的用户数据包和内部跳过数据包。内部跳过数据包表示填充，例如位于缓冲区末尾的填充。

分配

通过成对的读写索引确定可用空间。如果可以分配空间，则移动临时写索引，并返回指向缓冲区内该空间的指针，同时重置数据包头部。如果分配需要让写索引回绕，则在缓冲区末尾添加一个跳过数据包。如果无法分配空间且禁用了覆盖，则返回 NULL 指针；如果是带超时的分配，则上下文会阻塞。

带覆盖的分配

如果启用了覆盖，则会丢弃最旧的数据包，直到能够分配所请求数量的空间为止。丢弃数据包时会检查头部中的 busy 标志，以确保当前正在被消费的数据包不会被覆盖。在这种情况下，会在忙数据包之前添加一个跳过数据包，并丢弃忙数据包之后的数据包。当释放忙数据包时，会检测到这种情况，并将该数据包转换为跳过数据包，以避免重复处理。

用法

数据包头部定义

数据包头部的详细信息参见 include/zephyr/sys/mpsc_packet.h。API 函数参见 include/zephyr/sys/mpsc_pbuf.h。将头文件拆分开是为了避免在声明数据包时引入过多头文件。

用户头部结构体必须以内部头部开头：

#include <zephyr/sys/mpsc_packet.h>

struct foo_header {
        MPSC_PBUF_HDR;
        uint32_t length: 32 - MPSC_PBUF_HDR_BITS;
};

数据包缓冲区配置

配置结构体包含缓冲区详细信息、配置标志和回调。数据包缓冲区使用以下回调：

  • 丢弃通知：每当有数据包因覆盖而被丢弃时调用的回调。

  • 获取数据包长度：用于确定数据包长度的回调

生产数据包

标准的两步方法：

foo_packet *packet = mpsc_pbuf_alloc(buffer, len, K_NO_WAIT);

fill_data(packet);

mpsc_pbuf_commit(buffer, packet);

针对性能优化的小数据包存储：

  • 32 位字数据包

  • 带指针的 32 位字数据包

注意，由于数据包是按值写入的，它们的头部中应已设置 valid 位。

mpsc_pbuf_put_word(buffer, data);
mpsc_pbuf_put_word_ext(buffer, data, ptr);

消费数据包

两步方法：

foo_packet *packet = mpsc_pbuf_claim(buffer);

process(packet);

mpsc_pbuf_free(buffer, packet);
