代码和数据重定位

概述

该功能可以将指定文件中的 .text、.rodata、.data 和 .bss 段重定位，并放置到指定的内存区域中。内存区域和文件以字符串形式提供给 scripts/build/gen_relocate_app.py 脚本。该脚本总是从 cmake 内部调用。

该脚本提供了一种可靠的方式来重新排列内存内容，而无需实际修改代码。简单来说，该脚本相当于同时对一批文件完成 __attribute__((section("name"))) 的工作。

可以使用正则表达式过滤器，只选择需要重定位的段。

详细说明

内存区域和文件通过一个文件提供给 scripts/build/gen_relocate_app.py 脚本，该文件的每一行指定要放置到给定区域中的文件列表。

此类文件的示例如下：

SRAM2:/home/xyz/zephyr/samples/hello_world/src/main.c,
SRAM1:/home/xyz/zephyr/samples/hello_world/src/main2.c,

调用该脚本时使用以下参数：python3 gen_relocate_app.py -i input_file -o generated_linker -c generated_code

在 prj.conf 中启用 Kconfig 选项 CONFIG_CODE_DATA_RELOCATION 后，将会调用该脚本并完成所需的重定位。

该脚本还会触发生成 linker_relocate.ld 和 code_relocation.c 文件。linker_relocate.ld 文件会创建相应的段，并链接所有选定文件中所需的函数或变量。

备注

在主链接脚本中，text 段被拆分为 2 部分。第一部分包含与向量表相关的信息以及其他调试相关信息，第二部分包含完整的 text 段。这样做是为了将所需的函数和数据变量强制放到正确的位置，这是由链接器的行为决定的。链接器只会链接一次，因此必须拆分这个 text 段，为生成的链接脚本腾出位置。

code_relocation.c 文件包含初始化数据段所需的代码，以及 text 段的副本（如果是 XIP）。此外，它还包含 bss 清零所需的代码，以及将数据从 ROM 复制到所需内存类型的代码。

使用该功能的步骤如下：

  • 在 prj.conf 文件中启用 CONFIG_CODE_DATA_RELOCATION

  • 在项目的 CMakeLists.txt 文件中，列出所有需要重定位的文件。

    zephyr_code_relocate(FILES src/main.c LOCATION SRAM2)

    其中第一个参数是一个或多个文件，第二个参数是这些文件必须放置到的内存。

    备注

    zephyr_code_relocate() 函数可以根据需要调用任意多次。

其他配置

本节介绍可以在 CMakeLists.txt 中设置的其他配置选项。

  • 如果内存是 SRAM1、SRAM2、CCD 或 AON，则将整个目标文件放入这些段中。例如：

    zephyr_code_relocate(FILES src/file1.c LOCATION SRAM2)
zephyr_code_relocate(FILES src/file2.c LOCATION SRAM1)

  • 如果内存类型后面附加了 _DATA、_TEXT、_RODATA、_BSS 或 _NOINIT，则只有所选的部分会被放置到指定的内存区域中。例如：

    zephyr_code_relocate(FILES src/file1.c LOCATION SRAM2_DATA)
zephyr_code_relocate(FILES src/file2.c LOCATION SRAM2_TEXT)

  • 也可以将多个区域附加在一起，例如 SRAM2_DATA_BSS_NOINIT。这会将所有数据（值初始化、零初始化和未初始化的数据）都放入 SRAM2 中。

  • 可以向 FILES 参数传入多个文件，也可以使用 CMake 生成器表达式来重定位以逗号分隔的文件列表。

    file(GLOB sources "file*.c")
zephyr_code_relocate(FILES ${sources} LOCATION SRAM2)
zephyr_code_relocate(FILES $<TARGET_PROPERTY:my_tgt,SOURCES> LOCATION SRAM2)

段过滤

默认情况下，指定文件的所有段都会被重定位。如果使用 FILTER，则需提供一个正则表达式，只选择要重定位的段。

正则表达式作用于段名称。当文件使用 -ffunction-sections 和 -fdata-sections 构建时（默认即是如此），可以借此选择该文件中的符号。

zephyr_code_relocate(FILES src/file1.c FILTER ".*\\.func1|.*\\.func2" LOCATION SRAM2_TEXT)

上面的示例只会重定位文件 src/file1.c 中的 func1() 和 func2()

NOKEEP 标志

默认情况下，生成 linker_relocate.ld 时，所有被重定位的函数和变量都会用 KEEP() 标记。因此，如果某个输入文件恰好包含未使用的符号，即使在调用链接器时使用了 --gc-sections，这些符号也不会被丢弃。如果要改变这一行为，可以向 zephyr_code_relocate() 调用传入 NOKEEP。

zephyr_code_relocate(FILES src/file1.c LOCATION SRAM2_TEXT NOKEEP)

上面的示例有助于确保 file1.c 的 .text 段中任何未使用的代码不会被保留在 SRAM2 中。

NOCOPY 标志

当向 zephyr_code_relocate() 函数传入 NOCOPY 选项时，不会在 code_relocation.c 中生成重定位代码。当需要将特定文件（或一组文件）的内容移到 XIP 区域时，可以使用此标志。

该示例会将 xip_external_flash.c 文件的 .text 段放置到 EXTFLASH 内存区域，并从该区域执行（XIP）。.data 段则照常重定位到 SRAM 中。

zephyr_code_relocate(FILES src/xip_external_flash.c LOCATION EXTFLASH_TEXT NOCOPY)
zephyr_code_relocate(FILES src/xip_external_flash.c LOCATION SRAM_DATA)

重定位库

可以向 zephyr_code_relocation() 传入 LIBRARY 参数和库名称来重定位库。例如，以下代码片段会将串口驱动重定位到 SRAM2：

zephyr_code_relocate(LIBRARY drivers__serial LOCATION SRAM2)

提示

重定位 kernel/arch 文件时要小心，其中一些文件包含在代码重定位之前执行的早期初始化代码。

可能需要额外的 MPU/MMU 配置，以确保目标内存区域被配置为允许执行代码。
