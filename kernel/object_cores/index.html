对象核心

对象核心（object core）是一种内核调试工具，可用于识别已注册的对象并对其执行操作。

对象核心概念

每个对象实例都嵌入一个名为 obj_core 的对象核心字段。对象核心将对象与其对象类型关联起来，而每个对象类型都让调试工具能够枚举该类型的对象。对象类型之间通过一个单向链表连接在一起。综合起来，调试工具就可以遍历系统中的所有对象。

对象类型从两个地方枚举其对象：

  • 它的永久对象，即静态定义的实例，例如使用 K_SEM_DEFINE 创建的实例。这些对象直接在其可迭代段中原地遍历，从不在运行时注册。

  • 一个容量有限的注册表，记录在运行时初始化的对象，例如驱动数据结构中通过 k_sem_init() 初始化的信号量。注册表只引用这些对象，从不在对象内部存储任何内容。

因此，对象可以在任何存储中初始化、原地再次初始化，或者在不调用任何对象核心函数的情况下被丢弃：已不存在的对象不会破坏注册表。由这一模型可以得出以下规则：

  • 位于当前运行线程的栈或中断栈中的对象不会被注册：它的生命周期随栈帧结束而结束。对象类型会在其 skipped 字段中统计此类对象。其他栈不会被识别，例如用户线程执行系统调用时所用的特权栈，或某个架构特有的异常栈；位于这些栈中的对象会被注册，并一直被报告，直到其存储被重用。

  • 当注册表已满时，后续对象不会被注册，对象类型会在其 dropped 字段中统计这些对象。注册表大小通过 CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS 设置。

  • 未注销就被丢弃的对象会一直被报告，直到其存储被重用：遍历时会根据缺失的类型标签识别出被重用的存储，并删除该条目。内核在释放对象时会自行将其注销：在线程中止时，在 k_object_free()、k_timer_cleanup()、k_msgq_cleanup() 和 k_stack_cleanup() 中，以及在启用 CONFIG_OBJ_CORE_EVICT_ON_FREE 时将内存归还给堆、内存块（slab）或内存块分配器（Memory Blocks）时。以其他方式结束对象生命周期的代码可以调用 k_obj_core_unlink()，使该对象立即不再被报告；类型标签检查只是一道兜底措施，而且它会读取对象原先的存储，该存储必须仍处于映射状态。

  • 一旦某个类型的 dropped 计数不为零，就存在任何遍历都不会报告的对象，因此只有在该计数为零时，对象清单才是完整的。

以下内核对象已集成对象核心：

  • 条件变量

  • 事件

  • FIFO 和 LIFO

  • 邮箱

  • 内存块（slab）

  • 消息队列

  • 互斥量

  • 管道

  • 队列

  • 信号量

  • 线程

  • 定时器

  • 系统内存块（Memory Blocks）

开发者可以根据需要自由地将对象核心集成到其项目中的其他对象中。Object cores 示例逐步展示了这一机制，Object monitor 示例则使用它来监视正在运行的应用程序中的对象。

对象核心统计概念

许多内核对象支持收集和报告统计信息。对象核心通过对象核心统计提供了一种获取这些信息的统一方式。启用后，对象类型包含一个指向统计描述符的指针，该描述符定义了为对接对象统计信息而启用的各种操作。此外，对象核心还包含一个指针，指向与该对象关联的“原始”统计信息。原始数据是与统计信息相关的、未经处理的原始数据。查询得到的数据可能是“原始”数据，也可能经过某种计算处理（例如求平均值）。

实现

定义新的对象类型

对象类型是一个 k_obj_type 类型的全局变量。当对象结构体在可迭代段中有静态定义的实例时，该类型在构建时通过 K_OBJ_TYPE_DEFINE 定义，这些实例就成为它的永久对象。以下代码展示了如何定义一个新的对象类型，以便与对象核心和对象核心统计一起使用。

/* Unique object type ID */

#define K_OBJ_TYPE_MY_NEW_TYPE  K_OBJ_TYPE_ID_GEN("UNIQ")

struct my_obj_type_raw_info {
    ...
};

struct my_obj_type_query_stats {
    ...
};

struct my_new_obj {
    ...
    struct k_obj_core obj_core;
    struct my_obj_type_raw_info  info;
};

struct k_obj_core_stats_desc my_obj_type_stats_desc = {
    .raw_size = sizeof(struct my_obj_type_raw_stats),
    .query_size = sizeof(struct my_obj_type_query_stats),
    .raw = my_obj_type_stats_raw,
    .query = my_obj_type_stats_query,
    .reset = my_obj_type_stats_reset,
    .disable = NULL,    /* Stats gathering is always on */
    .enable = NULL,     /* Stats gathering is always on */
};

K_OBJ_TYPE_DEFINE_STATS(my_obj_type, my_new_obj, K_OBJ_TYPE_MY_NEW_TYPE,
                        &my_obj_type_stats_desc, info);

如果某个类型的对象不在可迭代段中，则改为在运行时、在其任何对象之前初始化该类型。可以将一个永久的对象数组注册为该类型的范围，这样其中的对象就不需要注册表条目。

struct k_obj_type  my_obj_type;
struct my_new_obj  my_objects[8];

void my_obj_type_init(void)
{
    z_obj_type_init(&my_obj_type, K_OBJ_TYPE_MY_NEW_TYPE,
                    offsetof(struct my_new_obj, obj_core));
    k_obj_type_init_range(&my_obj_type, my_objects,
                          &my_objects[ARRAY_SIZE(my_objects)],
                          sizeof(struct my_new_obj), false);
    k_obj_type_stats_init(&my_obj_type, &my_obj_type_stats_desc);
}

初始化新的对象核心

已集成到对象核心框架中的内核对象，会在对象初始化时自动初始化其对象核心。但是，希望将自己的对象加入该框架的开发者，需要既初始化对象核心，又对其进行注册。注册属于该类型永久范围内的对象不会产生任何效果，因为该对象会从该范围中被报告。以下代码在上面示例的基础上初始化对象核心。

void my_new_obj_init(struct my_new_obj *new_obj)
{
    ...
    k_obj_core_init(K_OBJ_CORE(new_obj), &my_obj_type);
    k_obj_core_link(K_OBJ_CORE(new_obj));
    k_obj_core_stats_register(K_OBJ_CORE(new_obj), &new_obj->raw_stats,
                              sizeof(struct my_obj_type_raw_info));
}

遍历对象核心列表

有两个例程可用于遍历某个对象类型的对象核心：k_obj_type_walk_locked() 和 k_obj_type_walk_unlocked()。两者都会先访问该类型的永久对象，然后访问已注册的对象。以下代码在上面示例的基础上，打印该新对象类型所有对象的地址。

int walk_op(struct k_obj_core *obj_core, void *data)
{
    uint8_t *ptr;

    ptr = obj_core;
    ptr -= obj_core->type->obj_core_offset;

    printk("%p\n", ptr);

    return 0;
}

void print_object_addresses(void)
{
    struct k_obj_type *obj_type;

    /* Find the object type */

    obj_type = k_obj_type_find(K_OBJ_TYPE_MY_NEW_TYPE);

    /* Walk the list of objects */

    k_obj_type_walk_unlocked(obj_type, walk_op, NULL);
}
