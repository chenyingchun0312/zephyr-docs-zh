时间工具

概述

Zephyr 中的 运行时间 基于一个节拍计数器。在默认启用 CONFIG_TICKLESS_KERNEL 的情况下，该计数器从系统启动那一刻的零开始，以名义上恒定的速率递增。在 POSIX 中与该计数器相当的是 CLOCK_MONOTONIC，或 Linux 中的 CLOCK_MONOTONIC_RAW 之类的时钟。k_uptime_get() 以毫秒为单位提供该时间。

应用程序经常需要将 Zephyr 内部时间与日常生活中使用的外部时间尺度（例如本地时间或协调世界时）关联起来。这些系统对时间的解释方式各不相同，并且可能由于 闰秒 以及夏令时等本地时间偏移而存在不连续。

由于这些不连续，再加上周期计数器底层时钟存在明显的误差，根据 Zephyr 时钟估算出的时间与“真实”民用时间尺度中的实际时间之间的偏移量并不是恒定的，在 Zephyr 应用程序运行期间可能会有很大变化。

时间工具 API 支持：

  • 在不同时间表示形式之间转换

  • 同步和对齐时间尺度

  • 比较、相加和相减时间表示

有关支撑这些功能的术语和概念，请参阅 Zephyr 时间支持的基础概念。

时间工具 API

表示形式转换

时间尺度中的瞬时可以用多种方式表示，包括：

  • 自某个纪元起的秒数。POSIX 中这种形式的时间表示包括 time_t 和 struct timespec，它们通常被解释为“UNIX 时间”的表示（参见 RFC 8536 Section 2）。

  • 日历时间，即相对于某个纪元的年、月、日、时、分、秒。POSIX 中这种形式的时间表示包括 struct tm。

请记住，这些只是时间的表示形式，必须相对于某个时间尺度来解释，该时间尺度可以是本地时间、UTC，或其他某种连续或不连续的尺度。

标准 C 库例程中提供了一些必要的转换。例如，可以使用 gmtime() 将表示自 POSIX 纪元以来秒数的 time_t 转换为表示日历时间的 struct tm。struct timespec 等亚秒级时间戳也可以借此生成日历时间表示，并单独处理亚秒级的偏移。

反向转换没有标准化：mktime() 之类的 API 需要时区信息。Zephyr 通过 timeutil_timegm() 和 timeutil_timegm64() 提供这种转换。

要在 struct timespec 与 k_timeout_t 时长之间转换，请使用 timespec_to_timeout() 和 timespec_from_timeout()。

k_timeout_t to;
struct timespec ts;

timespec_from_timeout(K_FOREVER, &ts);
to = timespec_to_timeout(&ts); /* to == K_FOREVER */

timespec_from_timeout(K_MSEC(100), &ts);
to = timespec_to_timeout(&ts); /* to == K_MSEC(100) */
timeutil_repr_apis

时间尺度同步

影响时间尺度同步的因素有以下几个：

  • 离散瞬时表示的变化速率。例如，Zephyr 运行时间以节拍跟踪，节拍随名义上以 CONFIG_SYS_CLOCK_TICKS_PER_SEC 赫兹发生的事件递增，而外部时间源提供的数据可能以整秒或秒的分数（例如微秒）为单位。

  • 在某一瞬时对齐两种尺度所需的绝对偏移量。

  • 两种尺度中可观测瞬时之间的相对误差，这是一致地对齐多个瞬时所必需的。例如，经过每秒 1 个脉冲的 GPS 信号校准的参考时钟，要比由误差为 +/- 250 ppm 的 RC 振荡器驱动的 Zephyr 系统时钟精确得多。

时间尺度之间的同步或对齐通过一个多步骤的过程完成：

  • 时间尺度中的一个瞬时由一个（无符号）64 位整数表示，并假定它以固定的名义速率递增。

  • timeutil_sync_config 记录参考时间尺度/时间源（例如 TAI）和本地时间源（例如 k_uptime_ticks()）的名义速率。

  • timeutil_sync_instant 记录单个瞬时在参考时间尺度和本地时间尺度中的表示。

  • timeutil_sync_state 用于存储一个初始瞬时、最近收到的第二个观测值，以及一个可以校正各时间尺度实际速率相对误差的偏斜系数（skew）。

  • timeutil_sync_ref_from_local() 和 timeutil_sync_local_from_ref() 将一种时间尺度中的瞬时转换到另一种时间尺度，转换时会考虑偏斜系数，该系数可以由 timeutil_sync_estimate_skew() 根据状态结构体中存储的两个瞬时估算得出。

timespec 操作

可以使用 timespec_is_valid() 检查 timespec 的有效性。

struct timespec ts = {
    .tv_sec = 0,
    .tv_nsec = -1, /* out of range! */
};

if (!timespec_is_valid(&ts)) {
    /* error-handing code */
}

在某些情况下，可以使用 timespec_normalize() 将无效的 timespec 对象重新规范化。

if (!timespec_normalize(&ts)) {
    /* error-handling code */
}

/* ts should be normalized */
__ASSERT(timespec_is_valid(&ts) == true, "expected normalized timespec");

可以使用 timespec_equal() 比较两个 timespec 对象是否相等。

if (timespec_equal(then, now)) {
    /* time is up! */
}

可以使用 timespec_compare() 对（有效的）timespec 对象进行比较和全排序。

int cmp = timespec_compare(a, b);

switch (cmp) {
case 0:
    /* a == b */
    break;
case -1:
    /* a < b */
    break;
case +1:
    /* a > b */
    break;
}

可以分别使用 timespec_add()、timespec_sub() 和 timespec_negate() 对 timespec 对象进行加法、减法和取反运算。与 timespec_normalize() 一样，当不会导致溢出时，这些函数会输出规范化的 timespec。成功时，这些函数返回 true；如果会发生溢出，则返回 false。

/* a += b */
if (!timespec_add(&a, &b)) {
    /* overflow */
}

/* a -= b */
if (!timespec_sub(&a, &b)) {
    /* overflow */
}

/* a = -a */
if (!timespec_negate(&a)) {
    /* overflow */
}

Zephyr 时间支持的基础概念

以下术语来自 ISO/TC 154/WG 5 N0038（ISO/WD 8601-1）及其他来源：

  • 时间轴 是将时间表示为有序瞬时序列的一种方式。

  • 时间尺度 是相对于作为纪元的原点来表示瞬时的一种方式。

  • 如果连续时间瞬时的表示值从不减小，则该时间尺度是 单调的（递增的）。

  • 如果表示值没有突变（例如在连续瞬时之间向前或向后跳变），则该时间尺度是 连续的。

  • 民用时间 一般指由地方政府等民政机构依法定义的时间尺度，通常用于将本地午夜与太阳时对齐。

相关时间尺度

国际原子时（TAI）是一种基于以 SI 秒计数的多个时钟取平均值的时间尺度。TAI 是单调且连续的时间尺度。

世界时（UT）是一种基于地球自转的时间尺度。UT 是不连续的时间尺度，因为它需要偶尔进行调整（闰秒）以跟上地球自转的变化。因此，TAI 与 UT 之间的差值随时间变化。UT 有多个变体，其中最常用的是 UTC。

UT 时间与地点无关。UT 是标准时间（或“本地时间”）的基础，标准时间是特定地点的时间。在任一给定瞬时，标准时间与 UT 之间有固定的偏移量，主要受经度影响，但该偏移量可能会被调整（“夏令时”），以使标准时间与当地太阳时对齐。从某种意义上说，本地时间比 UT “更不连续”。

POSIX 时间（参见 RFC 8536 Section 2）是一种时间尺度，它计算自 1970-01-01T00:00:00Z（即 UTC 1970 年开始时）这一“POSIX 纪元”以来的秒数。UNIX 时间是 POSIX 时间的扩展，使用负值表示 POSIX 纪元之前的时间。这两种尺度都假定每天恰好有 86400 秒。在正常使用中，这些尺度中的瞬时对应于 UTC 尺度中的时间，因此它们继承了 UTC 的不连续性。

与之对应的连续时间尺度是 UNIX 闰秒时间（UNIX Leap Time），即 UNIX 时间加上 POSIX 纪元（当时 TAI-UTC 为 8 秒）之后添加的所有闰秒修正。

功能需求

Zephyr 节拍计数器没有闰秒或标准时间偏移的概念，是一种连续的时间尺度。不过它可能相对不准确，漂移可达每小时三分钟（假设使用容差为 5% 的 RC 定时器）。

要支持 Zephyr 时间与常用人类时间尺度之间的转换，需要两个阶段：

  • 在连续但不准确的 Zephyr 时间尺度与准确且稳定的外部时间尺度之间进行转换；

  • 在稳定的时间尺度与（可能不连续的）民用时间尺度之间进行转换。

围绕 timeutil_sync_state_update() 的 API 支持第一步，即在连续时间尺度之间进行转换。

第二步需要外部信息，包括闰秒和本地时间偏移变化的时间表。这些信息最好由外部库提供，目前不属于时间工具 API 的一部分。

选择外部时间源和时间尺度

如果应用程序要求民用时间的精度在几秒以内，则可以使用 UTC 作为稳定的时间源。但是，如果外部时间源因闰秒而进行调整，就会出现不连续：以 1 Hz 采集的两次观测之间经过的时间，并不等于它们时间戳的数值差。

对于精确的活动，使用不受本地和太阳时调整影响的连续尺度会使问题大大简化。合适的连续尺度包括：

  • GPS 时间：纪元为 1980-01-06T00:00:00Z，连续并跟随 TAI，偏移量为 TAI-GPS=19 秒。

  • Bluetooth Mesh 时间：纪元为 2000-01-01T00:00:00Z，连续并跟随 TAI，偏移量为 -32。

  • UNIX 闰秒时间：纪元为 1970-01-01T00:00:00Z，连续并跟随 TAI，偏移量为 -8。

由于 C 和 Zephyr 库函数支持使用 UNIX 纪元在整数时间表示和日历时间表示之间转换，UNIX 闰秒时间是外部时间尺度的理想选择。

用于填充同步点的机制无关紧要：可以从本地高精度 RTC 外设读取，可以使用 NTP 或 PTP 等协议通过网络交换数据包，也可以处理从 GPS 接收的 NMEA 消息（带或不带 1pps 信号）。

timespec 概念

struct timespec 最初来自 POSIX，自 C11 起已成为 C 标准的一部分。struct timespec 的定义如下所示。

struct timespec {
    time_t tv_sec;  /* seconds */
    long   tv_nsec; /* nanoseconds */
};

tv_nsec 字段仅在取值范围 [0, 999999999] 内有效。tv_sec 字段是自纪元以来的秒数。如果用 struct timespec 表示时间差，则 tv_sec 字段可能为负值。
