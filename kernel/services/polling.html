轮询 API

轮询 API 用于同时等待多个条件中的任意一个得到满足。

概念

轮询 API 的主函数是 k_poll()，它在概念上与 POSIX 的 poll() 函数非常相似，区别在于它操作的是内核对象而不是文件描述符。

轮询 API 允许单个线程同时等待一个或多个条件得到满足，而无需逐个主动检查每个条件。

这类条件的种类有限：

  • 信号量变为可用

  • 内核 FIFO 中有可取出的数据

  • 内核 LIFO 中有可取出的数据

  • 内核消息队列中有可取出的数据

  • 内核管道中有可取出的数据，或管道已关闭

  • 轮询信号被触发

需要等待多个条件的线程必须定义一个 轮询事件 数组，每个条件对应一个事件。

在对数组进行轮询之前，必须初始化数组中的所有事件。

每个事件必须指定需要满足的条件 类型，条件满足时事件状态随之改变，以表明所请求的条件已经满足。

每个事件必须指定条件所针对的 内核对象。

每个事件必须指定条件满足时所使用的操作 模式。

每个事件可以选择指定一个 标签，由用户自行决定用它把多个事件归为一组。

除内核对象之外，还有一种可以被直接发出信号的 轮询信号 伪对象类型。

只要所等待的条件中有一个得到满足，k_poll() 函数就会返回。如果某些条件在调用 k_poll() 之前就已满足，或者由于内核的抢占式多线程特性，k_poll() 返回时可能有不止一个条件得到满足。调用者必须检查数组中所有轮询事件的状态，以确定哪些条件已满足以及要采取什么操作。

目前只有一种操作模式可用：不获取对象。例如，这意味着当 k_poll() 返回且轮询事件表明信号量可用时，k_poll() 的调用者还必须调用 k_sem_take() 来获取该信号量的所有权。如果该信号量存在竞争，则无法保证在调用 k_sem_take() 时它仍然可用。

实现

使用 k_poll()

主 API 是 k_poll()，它操作一个 k_poll_event 类型的轮询事件数组。数组中的每一项表示一个带有条件的事件，调用 k_poll() 会等待该条件得到满足。

轮询事件可以使用运行时初始化器 K_POLL_EVENT_INITIALIZER() 或 k_poll_event_init() 初始化，也可以使用静态初始化器 K_POLL_EVENT_STATIC_INITIALIZER() 初始化。必须向初始化器传入与所指定 类型 相匹配的对象。模式 必须 设置为 K_POLL_MODE_NOTIFY_ONLY。状态 必须 设置为 K_POLL_STATE_NOT_READY（初始化器会处理这一点）。用户 标签 是可选的，对 API 完全不透明：它的作用是帮助用户将类似的事件归为一组。由于它是可选的，出于性能考虑，只有静态初始化器接受该参数，运行时初始化器不接受。如果使用运行时初始化器，用户必须在 k_poll_event 数据结构中单独设置它。如果要忽略数组中的某个事件（通常是暂时忽略），可以将其类型设置为 K_POLL_TYPE_IGNORE。

struct k_poll_event events[4] = {
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_SEM_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_sem, 0),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_FIFO_DATA_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_fifo, 0),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_MSGQ_DATA_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_msgq, 0),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_PIPE_DATA_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_pipe, 0),
};

或者在运行时初始化

struct k_poll_event events[4];
void some_init(void)
{
    k_poll_event_init(&events[0],
                      K_POLL_TYPE_SEM_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_sem);

    k_poll_event_init(&events[1],
                      K_POLL_TYPE_FIFO_DATA_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_fifo);

    k_poll_event_init(&events[2],
                      K_POLL_TYPE_MSGQ_DATA_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_msgq);

    k_poll_event_init(&events[3],
                      K_POLL_TYPE_PIPE_DATA_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_pipe);

    // tags are left uninitialized if unused
}

事件初始化后，就可以将数组传给 k_poll()。可以指定一个超时，只等待指定的时长；也可以使用特殊值 K_NO_WAIT 和 K_FOREVER，分别表示不等待，或者一直等到某个事件条件满足为止。

每个信号量或 FIFO 上都提供一个轮询者列表，应用程序需要多少事件在其中等待都可以。注意，等待者按先到先服务的顺序得到服务，而不是按优先级顺序。

成功时，k_poll() 返回 0。如果超时，则返回 -EAGAIN。

// assume there is no contention on this semaphore and FIFO
// -EADDRINUSE will not occur; the semaphore and/or data will be available

void do_stuff(void)
{
    rc = k_poll(events, ARRAY_SIZE(events), K_MSEC(1000));
    if (rc == 0) {
        if (events[0].state == K_POLL_STATE_SEM_AVAILABLE) {
            k_sem_take(events[0].sem, 0);
        } else if (events[1].state == K_POLL_STATE_FIFO_DATA_AVAILABLE) {
            data = k_fifo_get(events[1].fifo, 0);
            // handle data
        } else if (events[2].state == K_POLL_STATE_MSGQ_DATA_AVAILABLE) {
            ret = k_msgq_get(events[2].msgq, buf, K_NO_WAIT);
            // handle data
        } else if (events[3].state == K_POLL_STATE_PIPE_DATA_AVAILABLE) {
            bytes_read = k_pipe_read(events[3].pipe, buf, bytes_to_read, K_NO_WAIT);
            if (bytes_read == -EPIPE) {
                // pipe is closed
            } else {
                // handle data
            }
        }
    } else {
        // handle timeout
    }
}

在循环中调用 k_poll() 时，用户必须将事件状态重置为 K_POLL_STATE_NOT_READY。

void do_stuff(void)
{
    for(;;) {
        rc = k_poll(events, ARRAY_SIZE(events), K_FOREVER);
        if (events[0].state == K_POLL_STATE_SEM_AVAILABLE) {
            k_sem_take(events[0].sem, 0);
        }
        if (events[1].state == K_POLL_STATE_FIFO_DATA_AVAILABLE) {
            data = k_fifo_get(events[1].fifo, 0);
            // handle data
        }
        if (events[2].state == K_POLL_STATE_MSGQ_DATA_AVAILABLE) {
            ret = k_msgq_get(events[2].msgq, buf, K_NO_WAIT);
            // handle data
        }
        if (events[3].state == K_POLL_STATE_PIPE_DATA_AVAILABLE) {
            bytes_read = k_pipe_read(events[3].pipe, buf, bytes_to_read, K_NO_WAIT);
            if (bytes_read == -EPIPE) {
                // closed pipe stays ready; stop polling it
                events[3].type = K_POLL_TYPE_IGNORE;
            } else {
                // handle data
            }
        }
        events[0].state = K_POLL_STATE_NOT_READY;
        events[1].state = K_POLL_STATE_NOT_READY;
        events[2].state = K_POLL_STATE_NOT_READY;
        events[3].state = K_POLL_STATE_NOT_READY;
    }
}

使用 k_poll_signal_raise()

事件类型之一是 K_POLL_TYPE_SIGNAL：它是发给轮询事件的“直接”信号，可以看作只能由一个线程等待的轻量级二值信号量。

轮询信号是一个类型为 k_poll_signal 的独立对象，与信号量或 FIFO 类似，必须关联到一个 k_poll_event 上。它必须先通过 K_POLL_SIGNAL_INITIALIZER() 或 k_poll_signal_init() 初始化。

struct k_poll_signal signal;
void do_stuff(void)
{
    k_poll_signal_init(&signal);
}

通过 k_poll_signal_raise() 函数发出信号。该函数接受一个用户 结果 参数，该参数对 API 不透明，可用于向等待该事件的线程传递额外信息。

struct k_poll_signal signal;

// thread A
void do_stuff(void)
{
    k_poll_signal_init(&signal);

    struct k_poll_event events[1] = {
        K_POLL_EVENT_INITIALIZER(K_POLL_TYPE_SIGNAL,
                                 K_POLL_MODE_NOTIFY_ONLY,
                                 &signal),
    };

    k_poll(events, 1, K_FOREVER);

    int signaled, result;

    k_poll_signal_check(&signal, &signaled, &result);

    if (signaled && (result == 0x1337)) {
        // A-OK!
    } else {
        // weird error
    }
}

// thread B
void signal_do_stuff(void)
{
    k_poll_signal_raise(&signal, 0x1337);
}

如果要在循环中轮询该信号，则在每次迭代中，如果信号已被触发，既要 将其事件状态重置为 K_POLL_STATE_NOT_READY，也要 使用 k_poll_signal_reset() 重置其 result。

struct k_poll_signal signal;
void do_stuff(void)
{
    k_poll_signal_init(&signal);

    struct k_poll_event events[1] = {
        K_POLL_EVENT_INITIALIZER(K_POLL_TYPE_SIGNAL,
                                 K_POLL_MODE_NOTIFY_ONLY,
                                 &signal),
    };

    for (;;) {
        k_poll(events, 1, K_FOREVER);

        int signaled, result;

        k_poll_signal_check(&signal, &signaled, &result);

        if (signaled && (result == 0x1337)) {
            // A-OK!
        } else {
            // weird error
        }

        k_poll_signal_reset(&signal);
        events[0].state = K_POLL_STATE_NOT_READY;
    }
}

注意，轮询信号内部不做同步。传入信号的 k_poll() 调用会在系统中任何代码调用 k_poll_signal_raise() 之后返回。但如果信号在外部管理并通过 k_poll_signal_init() 重置，那么在应用程序检查时，事件状态可能已不再等于 K_POLL_STATE_SIGNALED，（考虑不周的）应用程序就会漏掉事件。最佳做法是始终只在调用 k_poll() 循环的线程内重置信号，否则就使用其他能记录事件计数的事件类型：从这个意义上说，信号量和 FIFO 更不容易出错，因为从架构上讲它们不会“漏掉”事件。

建议用法

使用 k_poll() 合并多个各自挂起在一个对象上的线程，从而可能节省大量栈空间。

如果只有一个线程挂起在轮询信号上，可将其用作轻量级二值信号量。

备注

由于只有在没有其他线程等待对象变为可用时，对象才会发出信号，并且只能有一个线程轮询某个特定对象，因此轮询最适合对象不会被多个线程争用的场景，基本上就是单个线程作为多个对象的主“服务器”或“分发器”，并且是唯一尝试获取这些对象的线程。
