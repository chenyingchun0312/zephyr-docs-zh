自旋锁

  • 用法

    • 不自旋地获取锁

    • 规则

  • 单处理器系统上的自旋锁

  • 自旋锁校验

  • 公平自旋锁

  • 建议用法

  • API 参考

自旋锁是 Zephyr 中最底层的互斥原语。它保护一段简短的临界区，使同一时刻只有一个执行上下文能够访问共享资源。发现锁已被持有的上下文会“自旋”，即忙等待直到锁变为可用，而不是阻塞并让出 CPU。因此，自旋锁只适用于很短的临界区。

获取自旋锁还会在持锁期间屏蔽本地 CPU 上的中断。正因如此，自旋锁可以安全地在线程和中断处理程序之间共享：当某个上下文持有锁时，同一 CPU 上的任何 ISR 都无法抢占它，其他 CPU 也无法获取同一把锁，因此它们都无法在更新过程中观察到或破坏受保护的数据。基于这些原因，k_spinlock 是 Zephyr 内核自身使用的主要同步原语，用于保护对其核心数据结构的访问。

应用程序代码也可以直接使用自旋锁，但通常建议改用更高层的同步原语，例如 k_mutex 或 k_sem。

用法

为每个需要保护的独立资源声明一个 k_spinlock。使用 k_spin_lock() 获取锁，该函数返回一个 k_spinlock_key_t，释放锁时必须将其传回 k_spin_unlock()：

static struct k_spinlock lock;

void update_shared_state(void)
{
        k_spinlock_key_t key = k_spin_lock(&lock);

        /* critical section: exclusive access */

        k_spin_unlock(&lock, key);
}

辅助宏 K_SPINLOCK 在其包含的代码块执行期间持有锁，并在退出代码块时自动释放锁。

K_SPINLOCK(&lock) {
        /* critical section: exclusive access */
}

该代码块必须执行到末尾，或者使用 K_SPINLOCK_BREAK 退出。使用普通的 break、goto 或 return 退出会跳过释放操作，导致锁泄漏：

K_SPINLOCK(&lock) {
        if (nothing_to_do) {
                K_SPINLOCK_BREAK;
        }

        /* critical section: exclusive access */
}

不自旋地获取锁

k_spin_trylock() 只尝试获取一次锁，失败时直接报告而不是等待。当调用者还有其他工作要做或不能停顿时，这很有用。成功时它会保存键值，释放方式与 k_spin_lock() 完全相同：

k_spinlock_key_t key;

if (k_spin_trylock(&lock, &key) == 0) {
        /* critical section: exclusive access */
        k_spin_unlock(&lock, key);
} else {
        /* lock is held elsewhere, do something else */
}

规则

使用自旋锁时请遵循以下规则：

  • 尽量缩短临界区。持锁期间本地 CPU 上的中断被屏蔽，而其他 CPU 可能正在该锁上自旋。

  • 持有自旋锁时，切勿执行任何阻塞或睡眠操作。

  • 不要递归获取自旋锁。已经持有某把锁的上下文不得再次尝试获取它，否则会发生死锁。允许嵌套获取 不同的 自旋锁，但必须遵循一致的加锁顺序以避免死锁。

单处理器系统上的自旋锁

在禁用 CONFIG_SMP 构建的内核中，自旋锁实际上并不自旋。由于只有一个 CPU，不存在竞争，因此 k_spin_lock() 退化为屏蔽本地 CPU 上的中断。这可以防止 ISR 和上下文切换在更新过程中观察到受保护的数据，而这正是单处理器上实现互斥所需的全部条件。

自旋锁校验

可以通过 CONFIG_SPIN_VALIDATE 启用一个校验层，用于检测自旋锁的各种误用。它可以检测以下情况：

  • 递归获取自旋锁

  • 释放并非由当前上下文持有的自旋锁

  • 未按顺序释放自旋锁（在内层锁仍被持有时释放了外层锁）

  • 在持有自旋锁期间，或在中断被嵌套的 irq_lock() 屏蔽期间发生上下文切换

在单处理器系统上，只有递归获取检查有意义。其他误用不可能发生，因为不存在竞争，并且持锁期间中断已被屏蔽。

公平自旋锁

默认的自旋锁实现基于单个 atomic_t 变量，不保证竞争的 CPU 之间的公平性：某个 CPU 可能反复赢得竞争，从而使其他 CPU 陷入饥饿。如果这一点很重要，可以启用 CONFIG_TICKET_SPINLOCKS，切换为基于票号（ticket）的实现，按 FIFO 顺序将被争用的锁授予请求的 CPU，代价是锁对象略大。

建议用法

使用自旋锁保护在线程与中断处理程序之间，或在 SMP 系统的多个 CPU 之间共享的短临界区。

如果其他原语更合适，应优先使用：

  • k_mutex 适用于可能较长、可能阻塞或可能睡眠的临界区。只有线程才能获取互斥量。

  • k_sem 适用于上下文之间的信号通知，以及对资源池的访问计数。

  • 当共享状态是可以用一次原子操作更新的单个字时，使用 原子服务，此时无需加锁。
