互斥量

mutex （互斥量）是实现传统可重入互斥量的内核对象。互斥量通过确保对资源的互斥访问，使多个线程能够安全地共享与之关联的硬件或软件资源。

概念

可以定义任意数量的互斥量（仅受可用 RAM 限制）。每个互斥量通过其内存地址引用。

互斥量具有以下关键属性：

  • 锁计数，表示持有该互斥量的线程对其加锁的次数。计数为零表示互斥量未被锁定。

  • 持有线程，在互斥量被锁定时标识锁定它的线程。

互斥量必须先初始化才能使用，初始化会将其锁计数置零。

需要使用共享资源的线程必须先通过 锁定 关联的互斥量来获得对该资源的独占访问权。如果互斥量已被其他线程锁定，请求线程可以选择等待互斥量解锁。

锁定互斥量后，线程可以在需要的时间内安全地使用关联资源；不过，良好的做法是尽量缩短持锁时间，以免影响其他想要使用该资源的线程。当线程不再需要该资源时，必须 解锁 互斥量，以便其他线程使用该资源。

互斥量在被锁定期间或有线程在其上等待期间，不得被释放，其内存也不得被重用。嵌入在动态分配对象中的互斥量必须在该对象被释放之前解锁；否则，持有线程将继续跟踪一个位于已不属于它的内存中的互斥量。

任意数量的线程可以同时在一个已锁定的互斥量上等待。互斥量解锁后，将由等待时间最长的最高优先级线程锁定。

备注

互斥量对象 不 适合在 ISR 中使用。

可重入锁定

线程可以锁定自己已经锁定的互斥量。这使线程可以在执行过程中的某一处访问关联资源，而无需关心此时互斥量是否已被锁定。

被同一线程重复锁定的互斥量必须解锁相同的次数，才能完全解锁，从而被其他线程获取。

优先级继承

锁定互斥量的线程可以获得 priority inheritance （优先级继承）。也就是说，如果有更高优先级的线程开始在该互斥量上等待，内核会 临时 提升该线程的优先级。这样，持有线程以与等待线程相同的优先级执行，从而更快地完成工作并释放互斥量。互斥量解锁后，解锁线程会将其优先级恢复到锁定该互斥量之前的水平。

备注

配置选项 CONFIG_PRIORITY_CEILING 限制了内核因优先级继承而能将线程优先级提升到的最高程度。默认值 -128 表示不限制。将其设置为等于或低于空闲线程优先级的级别则会禁用优先级继承。

线程在任何与互斥量相关的提升之前的优先级，会在第一次被提升时保存在线程自身中，线程持有的每个互斥量都记录在一个线程私有的链表中。每当有更高优先级的线程在互斥量上等待时，内核都会调整持有线程的优先级。当持有线程释放一个锁（或者高优先级的等待线程超时）时，内核会重新扫描该线程仍持有的互斥量，并根据其中任意一个互斥量上仍在等待的最高优先级等待者重新计算其优先级；如果已没有等待者，则恢复为线程的原始优先级。因此，无论以何种顺序解锁所持有的互斥量，结果都是正确的。

如果互斥量的持有者本身也在阻塞等待另一个互斥量，优先级提升会沿着这条持有链传播，使阻碍等待者推进的每个线程依次得到提升，但每次加锁尝试遍历的链节点数有一个由实现定义的上限。超出该上限的持有者会保持提升前的优先级，直到之后的某次加锁尝试再次遍历该链。

实现

定义互斥量

互斥量使用 k_mutex 类型的变量定义，然后必须调用 k_mutex_init() 进行初始化。

以下代码定义并初始化了一个互斥量。

struct k_mutex my_mutex;

k_mutex_init(&my_mutex);

也可以调用 K_MUTEX_DEFINE 在编译时定义并初始化互斥量。

以下代码与上面的代码段效果相同。

K_MUTEX_DEFINE(my_mutex);

锁定互斥量

调用 k_mutex_lock() 锁定互斥量。

以下代码基于上面的示例，如果互斥量已被其他线程锁定，则无限期等待其变为可用。

k_mutex_lock(&my_mutex, K_FOREVER);

以下代码最多等待 100 毫秒，直到互斥量变为可用；如果互斥量未变为可用，则发出警告。

if (k_mutex_lock(&my_mutex, K_MSEC(100)) == 0) {
    /* mutex successfully locked */
} else {
    printf("Cannot lock XYZ display\n");
}

解锁互斥量

调用 k_mutex_unlock() 解锁互斥量。

以下代码基于上面的示例，解锁该线程之前锁定的互斥量。

k_mutex_unlock(&my_mutex);

建议用法

使用互斥量提供对资源（例如物理设备）的独占访问。

Futex API 参考

k_futex 是一种轻量级互斥原语，旨在尽量减少内核的参与。无竞争时的操作只依赖对共享内存的原子访问。k_futex 不是内核对象，也不使用内核对象权限管理。它们位于用户内存中，任何对该内存具有读写权限的线程都可以使用。

用户模式互斥量 API 参考

sys_mutex 的行为与 k_mutex 几乎完全相同，额外的优点是 sys_mutex 实例可以位于用户内存中。未启用用户模式时，sys_mutex 的行为与 k_mutex 相同。
