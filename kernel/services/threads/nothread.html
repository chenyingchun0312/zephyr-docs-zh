无线程运行

有些应用程序不需要线程支持：

  • 引导加载程序

  • 简单的事件驱动应用程序

  • 用于演示核心功能的示例

将 CONFIG_MULTITHREADING 设置为 n 即可禁用线程支持。由于该配置对 Zephyr 的功能影响很大，并且针对它的测试有限，因此在该配置下哪些功能可以正常工作是有条件的。

可以正常工作的功能

禁用 CONFIG_MULTITHREADING 时，以下核心功能应当正常工作：

  • 构建系统

  • 将应用程序启动到 main() 的能力

  • 中断管理

  • 系统时钟，包括 k_uptime_get()

  • 定时器，即 k_timer()

  • 非睡眠延时，例如 k_busy_wait()。

  • 睡眠函数 k_cpu_idle()。

  • main() 之前的驱动和子系统初始化，例如 SYS_INIT。

  • 内存管理

  • 某些子系统中特别指明的驱动，见下文列表。

上述要求会影响其他功能的选择，例如 CONFIG_SYS_CLOCK_EXISTS 不能设置为 n。

无法正常工作的功能

禁用 CONFIG_MULTITHREADING 时无法工作的功能包括大部分内核 API：

  • 线程

  • 调度

  • 工作队列线程

  • 轮询 API

  • 信号量

  • 互斥量

  • 条件变量

  • 数据传递

无线程支持时的子系统行为

以下各节列出了在禁用 CONFIG_MULTITHREADING 时预期能在一定程度上工作的驱动和功能子系统。未在此列出的子系统不应指望能够工作。

所列子系统中的部分现有驱动在禁用线程时无法工作，但按其所属子系统属于支持范围；或者它们足够独立，在特定平台上支持它们的影响很小。对于最初未按禁用线程情况实现的现有功能，欢迎提交增加支持的改进。

Flash

Flash 预期适用于所有 SoC Flash 外设驱动。通过总线访问的设备（如串行存储器）可能不受支持。

此处待补充受支持驱动的列表/表格

GPIO

通用输入/输出（GPIO） 预期适用于所有 SoC GPIO 外设驱动。通过总线访问的设备（如 GPIO 扩展器）可能不受支持。

此处待补充受支持驱动的列表/表格

UART

通用异步收发器（UART） 的一个子集预期适用于所有 SoC UART 外设驱动。

  • 选择了 CONFIG_UART_INTERRUPT_DRIVEN 的应用程序可能可以工作，具体取决于驱动实现。

  • 选择了 CONFIG_UART_ASYNC_API 的应用程序可能可以工作，具体取决于驱动实现。

  • 既未选择 CONFIG_UART_ASYNC_API 也未选择 CONFIG_UART_INTERRUPT_DRIVEN 的应用程序预期可以工作。

此处待补充受支持驱动的列表/表格，包括支持哪些 API 选项
