断言

Zephyr 提供了多种用于捕获编程错误的断言机制：

  • 运行时断言 在代码运行时检查条件，如果条件不成立，则引发 致命错误。推荐使用的 API 是支持模块的 ZASSERT() 宏；旧的 __ASSERT() 宏现在只是构建在其之上的一层薄兼容层，并且已被弃用。

  • 构建断言 （BUILD_ASSERT()）完全在编译时求值，并且始终会被检查。

备注

本文介绍的运行时 ZASSERT() 宏与 Ztest 框架提供的小写 zassert_* 宏（zassert_true()、zassert_equal() 等）无关。zassert_* 宏用于报告测试失败，而 ZASSERT() 宏在检测到编程错误时引发致命错误。

运行时断言

ZASSERT()

支持模块的断言 API 声明在 include/zephyr/sys/zassert.h 中。每个源文件选择加入一个断言 模块，该模块的级别是编译时常量。由于级别在编译时已知，编译器可以根据断言所属模块的断言级别来优化断言代码的空间占用。

断言级别

每个模块都会解析为以下四个级别之一：

  • ZASSERT_LEVEL_OFF —— 断言被完全编译掉。

  • ZASSERT_LEVEL_TERSE —— 检查断言；失败时只报告固定的 ASSERTION FAIL 提示。位置、条件、消息和参数都不会被编译进来。

  • ZASSERT_LEVEL_NORMAL —— 检查断言；失败时只报告位置（ASSERTION FAIL @ file:line）。条件、消息和参数都不会被编译进来。

  • ZASSERT_LEVEL_VERBOSE —— 检查断言；失败时报告字符串化的条件、位置以及可选的消息。

CONFIG_ASSERT 是总开关。禁用它时，无论各模块配置的级别如何，所有模块都会被强制设为 ZASSERT_LEVEL_OFF，所有 ZASSERT() / ZASSERT_MODULE() 的使用都不会生成任何代码。

注意:

ZASSERTS 减少空间占用依赖编译器优化在编译时删除未使用的条件、参数和字符串字面量。较低的优化级别可能妨碍死代码消除，导致即使模块断言级别设置得很低，二进制文件中仍残留断言相关内容。

选择模块

在翻译单元中首次使用 ZASSERT 之前，在文件作用域中放置一次 ZASSERT_MODULE：

#include <zephyr/sys/zassert.h>

ZASSERT_MODULE(MYMODULE);

模块名是一个全大写的标识符。其默认级别取自 Kconfig 符号 CONFIG_ASSERT_MODULE_<module>_LEVEL （此处为 CONFIG_ASSERT_MODULE_MYMODULE_LEVEL）。文件可以通过第二个参数显式传入级别来覆盖模块默认值，例如 ZASSERT_MODULE(MYMODULE, ZASSERT_LEVEL_VERBOSE)。

选择模块后，可以像条件检查一样使用 ZASSERT，并可附带类似 printf() 的可选消息：

ZASSERT(x == 3, "x was %d, expected 3", x);

如果条件为假，且模块级别至少为 ZASSERT_LEVEL_TERSE，就会引发致命错误。只有在 ZASSERT_LEVEL_NORMAL 或更高级别下，位置信息才会被编译进来并打印；只有在 ZASSERT_LEVEL_VERBOSE 级别下，条件、消息及其参数才会被编译进来并打印。

对于头文件和内联函数，应避免在文件作用域中使用 ZASSERT_MODULE()，因为该选择会泄漏到每个包含该头文件的文件中。请改用以下方式之一。

将 ZASSERT_MODULE 放在函数体内。这样选择的作用域仅限于该代码块，不会泄漏到包含者中，并且在该函数内可以直接使用 ZASSERT：

static inline void f(void *ptr)
{
        ZASSERT_MODULE(MYMODULE);

        ZASSERT(ptr != NULL, "ptr must not be NULL");
}

对于固定级别的断言，使用 ZASSERT_TERSE、ZASSERT_NORMAL 或 ZASSERT_VERBOSE。这些形式在调用处选择级别，不会在作用域中声明任何内容：

ZASSERT_TERSE(ptr != NULL);
ZASSERT_NORMAL(ptr != NULL);
ZASSERT_VERBOSE(ptr != NULL, "ptr must not be NULL");

ZASSERT_LEVEL_TERSE、ZASSERT_LEVEL_NORMAL 和 ZASSERT_LEVEL_VERBOSE 这些定义用于配置模块断言级别，而 ZASSERT_TERSE()、ZASSERT_NORMAL() 和 ZASSERT_VERBOSE() 用于执行固定级别的断言。

备注

ZASSERT() 及其文件作用域模块需遵循以下规则：

  • ZASSERT_MODULE() 必须出现在翻译单元中第一个 ZASSERT() 之前，并且每个文件只能选择一个模块。

  • 在作用域中没有模块时使用 ZASSERT() 会导致编译错误。请先选择一个模块，或者使用固定级别的 ZASSERT_TERSE()、ZASSERT_NORMAL() 或 ZASSERT_VERBOSE() 形式。

  • CONFIG_ASSERT 仍然是总开关：禁用它时，无论配置的级别如何，模块级别都会被强制设为 ZASSERT_LEVEL_OFF。

定义模块的 Kconfig 级别

CONFIG_ASSERT_MODULE_<module>_LEVEL 符号由模板 subsys/debug/zassert/Kconfig.template.assert 生成。在某个 Kconfig 文件中先设置模块名和一段易读的描述，然后引入（source）该模板：

module = MYMODULE
module-str = the MYMODULE assert module
source "subsys/debug/zassert/Kconfig.template.assert"

这会生成一个面向用户的 Off / Terse / Normal / Verbose 选项组，以及由其派生、不可赋值的整数符号 CONFIG_ASSERT_MODULE_MYMODULE_LEVEL，供 ZASSERT_MODULE(MYMODULE) 使用。该选项组默认为 Verbose，并且仍可在 prj.conf 中覆盖。

示例

Assertions 示例演示了在启用断言总开关的情况下，为单个文件启用详细断言。精简版如下：

#include <zephyr/kernel.h>
#include <zephyr/sys/zassert.h>

ZASSERT_MODULE(MYMODULE);

int main(void)
{
        int x = 2;

        ZASSERT(x == 3, "x was %d, expected 3", x);

        return 0;
}

设置 CONFIG_ASSERT_MODULE_MYMODULE_LEVEL_VERBOSE=y 时，失败的检查会输出：

ASSERTION FAIL [x == 3] @ .../src/main.c:...
x was 2, expected 3

自定义失败行为

整个断言冷路径都集中在少数几个可覆盖的弱函数中，它们声明在 include/zephyr/sys/zassert.h 中，实现在 subsys/debug/zassert/zassert.c 中：

  • zassert_fail() 报告失败的断言（位置，以及存在消息时的消息及其参数），然后调用 zassert_post_action()。要捕获或重定向全部断言输出，只需覆盖这一个函数。

  • zassert_post_action() 执行最终操作。默认实现在失败线程运行于用户模式时调用 k_oops()，否则调用 k_panic()。

  • zassert_vprint() 是所有断言文本输出所经过的唯一原语。覆盖它即可在一处捕获或重定向所有断言消息。zassert_print() 是对它的可变参数便捷封装，供旧的 __ASSERT_PRINT() 兼容垫片使用。

启用 CONFIG_ASSERT_TEST 时，后置操作处理函数允许返回（而不是中止），以便测试通过安装自定义钩子来验证断言行为。

构建断言

Zephyr 提供了一个用于执行构建时断言检查的宏。它完全在编译时求值，并且始终会被检查。

BUILD_ASSERT()

它的语义与 C 语言的 _Static_assert 或 C++ 的 static_assert 相同。如果求值失败，编译器会产生构建错误。如果编译器支持，还会打印所提供的消息，以提供更多上下文。

与 __ASSERT() 不同，消息必须是静态字符串或由静态字符串拼接而成的字符串。该宏不支持格式化或可变参数。

例如，假设以下检查失败：

BUILD_ASSERT(FOO == 2000, "Invalid value of FOO, expected 2000, got " STRINGIFY(FOO));

使用 GCC 时，输出类似于：

     tests/kernel/fatal/src/main.c: In function 'test_main':
     include/zephyr/toolchain/gcc.h:28:37: error: static assertion failed:
"Invalid value of FOO, expected 2000, got 1000"
      #define BUILD_ASSERT(EXPR, MSG) _Static_assert(EXPR, "" MSG)
                                      ^~~~~~~~~~~~~~
     tests/kernel/fatal/src/main.c:370:2: note: in expansion of macro 'BUILD_ASSERT'
       BUILD_ASSERT(FOO == 2000,
       ^~~~~~~~~~~~~~~~

旧式 __ASSERT()

__ASSERT() 系列声明在 include/zephyr/sys/__assert.h 中，早于 ZASSERT() 出现，现在是使用内置 DEFAULT 断言模块的兼容垫片。新代码应优先使用带有专用模块的 ZASSERT()。

备注

__ASSERT() 和 CONFIG_ASSERT* Kconfig 选项已被弃用。它们仍然可以通过 DEFAULT 模块工作，但底层的断言 API 在未来版本中可能会发生变化。

DEFAULT 模块由 CONFIG_ASSERT 启用。其级别由 CONFIG_ASSERT_MODULE_DEFAULT_LEVEL 控制，通过 Off / Terse / Normal / Verbose 选项组进行配置（CONFIG_ASSERT_MODULE_DEFAULT_LEVEL_OFF / CONFIG_ASSERT_MODULE_DEFAULT_LEVEL_TERSE / CONFIG_ASSERT_MODULE_DEFAULT_LEVEL_NORMAL / CONFIG_ASSERT_MODULE_DEFAULT_LEVEL_VERBOSE）。运行 Zephyr 测试用例时，断言默认启用，这由 CONFIG_TEST 选项配置。

已弃用的旧符号仍然有效，并会推导出 DEFAULT 模块的级别：CONFIG_ASSERT_VERBOSE 映射为 Verbose，CONFIG_ASSERT_NO_COND_INFO、CONFIG_ASSERT_NO_MSG_INFO 和 CONFIG_ASSERT_NO_FILE_INFO 映射为 Terse，而 CONFIG_ASSERT_LEVEL == 0 则使其保持 Off。如果这些符号都未设置，DEFAULT 模块的选项组会采用其自身的默认值 CONFIG_ASSERT_MODULE_DEFAULT_LEVEL_VERBOSE，从而保留默认使用详细断言的旧行为。如果要禁用所有断言（无论级别如何配置），请设置 CONFIG_ASSERT=n。
