浮点服务

在支持浮点寄存器的开发板配置上，内核允许线程使用这些寄存器。

备注

浮点服务目前仅适用于以下平台：基于支持浮点扩展的 ARM Cortex-M SoC 的开发板、Intel x86 架构、SPARC 架构，以及支持浮点扩展的 ARCv2 SoC。所提供的服务与架构相关。

内核不支持 ISR 使用浮点寄存器。

概念

可以对内核进行配置，使其只提供应用程序所需的浮点服务。内核支持三种运行模式，下文将分别介绍。此外，还可以根据需要包含或省略内核对 SSE 寄存器的支持。

线程是否参与浮点上下文保存也可以在运行时管理。k_float_enable() 为线程启用上下文保存，并接受用于选择保存哪些寄存器组的选项（例如 K_FP_REGS 和 K_SSE_REGS）；k_float_disable() 则再次关闭上下文保存。在未实现浮点上下文管理的目标上，这些例程返回 -ENOTSUP；如果请求因其他原因无效而无法执行，则返回 -EINVAL。

无 FP 寄存器模式

当应用程序中没有任何线程使用浮点寄存器时使用此模式。这是内核默认的浮点服务模式。

如果某个线程使用了任何浮点寄存器，内核会产生致命错误并中止该线程。

非共享 FP 寄存器模式

当应用程序中只有一个线程使用浮点寄存器时使用此模式。

在 x86 平台上，内核会初始化浮点寄存器，使任何线程都可以使用它们（在 ARM Cortex-M 平台和 ARCv2 平台上跳过初始化）。发生上下文切换时，浮点寄存器保持不变。

备注

如果有两个或更多线程尝试使用浮点寄存器，行为是未定义的，因为内核不会尝试检测（或阻止）多个线程使用这些寄存器。

共享 FP 寄存器模式

当应用程序中有两个或更多线程使用浮点寄存器时使用此模式。根据底层 CPU 架构的不同，内核支持以下一种或多种线程子类：

  • 非使用者：不能使用任何浮点寄存器的线程

  • FPU 使用者：可以使用标准浮点寄存器的线程

  • SSE 使用者：既可以使用标准浮点寄存器又可以使用 SSE 寄存器的线程

内核会初始化并启用对浮点寄存器的访问，使任何线程都可以使用它们，然后在上下文切换期间保存和恢复这些寄存器，以确保每个 FPU 使用者或 SSE 使用者执行的计算不受其他使用者计算的影响。

ARM Cortex-M 架构（带浮点扩展）

备注

在 ARM Cortex-M 中，共享 FP 寄存器模式是默认的浮点服务模式。

在带浮点扩展的 ARM Cortex-M 架构上，启用共享 FP 寄存器模式时，内核将 所有 线程都视为 FPU 使用者。这意味着任何线程都可以访问浮点寄存器。ARM 内核会在线程首次访问浮点寄存器时自动检测到该线程正在使用它们。

对于打算使用 FP 寄存器的线程，可以使用以下方法之一预先标记。

  • 静态创建的 ARM 线程可以通过向 K_THREAD_DEFINE 传入 K_FP_REGS 选项来预先标记。

  • 动态创建的 ARM 线程可以通过向 k_thread_create() 传入 K_FP_REGS 选项来预先标记。

使用 K_FP_REGS 选项预先标记线程，会指示基于 MPU 的栈保护机制正确配置该线程保护区域的大小，以始终保证能够检测到栈溢出，并在创建线程时为其启用惰性压栈（lazy stacking）。

在线程上下文切换期间，如果被换出的线程一直在使用浮点寄存器，ARM 内核会保存其 被调用者保存（callee-saved） 的浮点寄存器。此外，调用者保存（caller-saved） 的浮点寄存器会被保存在线程的栈上。如果被换入的线程一直在使用浮点寄存器，内核会恢复被换入线程的 被调用者保存 的 FP 寄存器，并从线程栈中恢复 调用者保存 的 FP 上下文。因此，内核不会保存或恢复未使用 FP 寄存器的线程的 FP 上下文。

每个打算使用浮点寄存器的线程都必须额外提供 72 字节的栈空间，用于保存被调用者保存的 FP 上下文。

目前，在 ARM Cortex-M 架构上的 Zephyr 应用程序中，当浮点上下文处于活动状态时，会启用 惰性压栈，以尽量减少中断延迟。

未启用基于 MPU 的栈保护机制时，Zephyr 应用程序中的惰性压栈始终处于激活状态。启用基于 MPU 的栈保护时，惰性压栈遵循以下规则：

  • 对使用 K_FP_REGS 预先标记的线程，默认激活惰性压栈

  • 对未使用 K_FP_REGS 预先标记的线程，一旦内核检测到它们正在使用浮点寄存器，就会动态激活惰性压栈。

如果 ARM 线程不再需要使用浮点寄存器，可以调用 k_float_disable()。这会指示内核在线程上下文切换期间不再保存或恢复其 FP 上下文。

ARM64 架构

备注

在 ARM64 上，共享 FP 寄存器模式是默认的浮点服务模式。编译器可以自由地使用 FP/SIMD 寄存器优化代码，并且已知 memcpy 等库函数会使用这些寄存器。

在 ARM64（Aarch64）架构上，内核根据具体情况逐个将线程视为 FPU 使用者。上下文切换期间使用“惰性保存”算法，只在绝对必要时才更新浮点寄存器。例如，从一个 FPU 使用者切换到非使用者线程，然后再切换回原来的 FPU 使用者时，不会 保存这些寄存器。

支持 ISR 使用 FPU 寄存器，但不推荐这样做。当 ISR 使用浮点或 SIMD 寄存器时，该访问会被捕获（trap），当前 FPU 使用者的上下文会被保存到线程对象中，然后 ISR 在禁用中断的状态下继续执行，以防止其他 IRQ 中断该 ISR 并可能请求使用 FPU。由于 ISR 没有持久的寄存器上下文，也就无法保存 ISR 的 FPU 上下文，因此需要禁用 IRQ。

启用共享 FP 寄存器模式后，每个线程对象会增大 512 字节。

ARCv2 架构

在 ARCv2 架构上，内核将每个线程视为非使用者或 FPU 使用者，并且必须使用以下方法之一标记线程。

  • 静态创建的 ARC 线程可以通过向 K_THREAD_DEFINE 传入 K_FP_REGS 选项来标记。

  • 动态创建的 ARC 线程可以通过向 k_thread_create() 传入 K_FP_REGS 来标记。

如果 ARC 线程不再需要使用浮点寄存器，可以调用 k_float_disable()。这会指示内核在线程上下文切换期间不再保存或恢复其 FP 上下文。

在线程上下文切换期间，如果被换出的线程一直在使用浮点寄存器，ARC 内核会保存其 被调用者保存（callee-saved） 的浮点寄存器。此外，调用者保存（caller-saved） 的浮点寄存器会被保存在线程的栈上。如果被换入的线程一直在使用浮点寄存器，内核会恢复被换入线程的 被调用者保存 的 FP 寄存器，并从线程栈中恢复 调用者保存 的 FP 上下文。因此，内核不会保存或恢复未使用 FP 寄存器的线程的 FP 上下文。加载和存储浮点寄存器需要额外 16 字节（单精度浮点硬件）或 32 字节（双精度浮点硬件）的栈空间。

RISC-V 架构

在 RISC-V 架构上，内核根据具体情况逐个将线程视为 FPU 使用者，并按需分配 FPU 访问权。上下文切换期间使用“惰性保存”算法，只在绝对必要时才更新浮点寄存器。例如，从一个 FPU 使用者切换到非使用者线程（或在其调度时间片内没有访问 FPU 的 FPU 使用者），然后再切换回原来的 FPU 使用者时，不会 保存 FPU 寄存器。

支持 ISR 使用 FPU 寄存器，但不推荐这样做。当 ISR 使用浮点或 SIMD 寄存器时，该访问会被捕获（trap），当前 FPU 使用者的上下文会被保存到线程对象中，然后 ISR 在禁用中断的状态下继续执行，以防止其他 IRQ 中断该 ISR 并可能请求使用 FPU。由于 ISR 没有持久的寄存器上下文，也就无法保存 ISR 的 FPU 上下文，因此需要禁用 IRQ。

作为一种优化，如果某个“活跃 FPU 使用者”线程的 FPU 上下文因其他线程使用 FPU 而被保存，那么当它被重新调度时，其 FPU 上下文会被预先恢复。线程如果在被换出之前的最近一个调度时间片内使 FPU 状态变“脏”，就被认定为活跃 FPU 使用者。因此，如果某个线程在其调度时间片内没有修改 FPU 状态，而之后另一个线程占用了 FPU，那么第一个线程将采用按需机制，直到它再次尝试访问 FPU 时才会恢复其 FPU 上下文。但如果该线程在被换出之前修改了 FPU，那么它在被重新调度后很可能会继续使用 FPU，此时预先恢复其 FPU 上下文可以省去原本会发生的异常陷入开销。

启用共享 FP 寄存器模式后，每个线程对象会增大 136 字节（单精度浮点硬件）或 264 字节（双精度浮点硬件）。

SPARC 架构

在 SPARC 架构上，内核将每个线程视为非使用者或 FPU 使用者，并且必须使用以下方法之一标记线程：

  • 静态创建的线程可以通过向 K_THREAD_DEFINE 传入 K_FP_REGS 选项来标记。

  • 动态创建的线程可以通过向 k_thread_create() 传入 K_FP_REGS 来标记。

在从中断处理程序退出时发生线程上下文切换期间，如果被换出的线程启用了 FPU，SPARC 内核会保存 所有 浮点寄存器。浮点寄存器保存在线程的栈上。当且仅当保存上下文时保存了浮点寄存器，恢复线程上下文时才会恢复它们。浮点寄存器的保存和恢复是同步进行的，因此不是惰性的。调用 ISR 时，FPU 总是处于禁用状态（与 CONFIG_FPU_SHARING 无关）。

未实现使用 k_float_disable() 禁用浮点。

使用 CONFIG_FPU_SHARING 时，每个 FPU 使用者线程需要 136 字节的栈空间用于加载和存储浮点寄存器。如果不使用 CONFIG_FPU_SHARING，则不需要额外的栈空间。

x86 架构

在 x86 架构上，内核根据具体情况逐个将线程视为非使用者、FPU 使用者或 SSE 使用者。上下文切换期间使用“惰性保存”算法，只在绝对必要时才更新浮点寄存器。例如，从一个 FPU 使用者切换到非使用者线程，然后再切换回原来的 FPU 使用者时，不会 保存这些寄存器。下表列出了线程为正确保存寄存器而必须额外提供的栈空间大小。

x86 内核会在线程首次访问浮点寄存器时自动检测到该线程正在使用它们。如果内核已配置为支持 SSE 寄存器，该线程会被标记为 SSE 使用者；如果不支持 SSE 寄存器，则被标记为 FPU 使用者。如果这会导致原本是 FPU 使用者的线程被标记为 SSE 使用者，或者应用程序希望避免自动标记线程所涉及的异常处理开销，可以使用以下方法之一预先标记线程。

  • 静态创建的 x86 线程可以通过向 K_THREAD_DEFINE 传入 K_FP_REGS 或 K_SSE_REGS 选项来预先标记。

  • 动态创建的 x86 线程可以通过向 k_thread_create() 传入 K_FP_REGS 或 K_SSE_REGS 选项来预先标记。

  • 已经创建的 x86 线程可以在启动后通过向 k_float_enable() 传入 K_FP_REGS 或 K_SSE_REGS 选项来预先标记自身。

如果 x86 线程很少使用浮点寄存器，可以调用 k_float_disable() 取消其 FPU 使用者或 SSE 使用者标记。这样，在不需要时，内核就不必在上下文切换期间采取措施保留浮点寄存器的内容。当线程再次需要使用浮点寄存器时，可以调用 k_float_enable() 将自身重新标记为 FPU 使用者或 SSE 使用者。

实现

执行浮点运算

如果内核配置正确，线程使用浮点运算不需要任何特殊的编码。

以下代码展示了在计算一系列整数值的平均值时，例程如何使用浮点运算来避免溢出问题。

int average(int *values, int num_values)
{
    double sum;
    int i;

    sum = 0.0;

    for (i = 0; i < num_values; i++) {
        sum += *values;
        values++;
    }

    return (int)((sum / num_values) + 0.5);
}

建议用法

当应用程序需要执行浮点运算时，使用内核浮点服务。

配置选项

要配置非共享 FP 寄存器模式，请启用 CONFIG_FPU 配置选项，并保持 CONFIG_FPU_SHARING 配置选项为禁用状态。

要配置共享 FP 寄存器模式，请同时启用 CONFIG_FPU 和 CONFIG_FPU_SHARING 配置选项。此外，如上文所述，请确保每个使用浮点寄存器的线程都有足够的额外栈空间，用于在上下文切换期间保存浮点寄存器的值。

对于 x86，使用 CONFIG_X86_SSE 配置选项启用对 SSEx 指令的支持。
