邮箱

mailbox （邮箱）是一种内核对象，提供超出消息队列对象能力的增强型消息队列功能。邮箱允许线程同步或异步地发送和接收任意大小的消息。

概念

可以定义任意数量的邮箱（仅受可用 RAM 限制）。每个邮箱通过其内存地址引用。

邮箱具有以下关键属性：

  • 发送队列，包含已发送但尚未被接收的消息。

  • 接收队列，包含正在等待接收消息的线程。

邮箱必须先初始化才能使用，初始化会将它的两个队列都置为空。

邮箱允许线程（而非 ISR）交换消息。发送消息的线程称为 发送线程，接收消息的线程称为 接收线程。每条消息只能被一个线程接收（即不支持点对多点消息和广播消息）。

通过邮箱交换的消息以非匿名方式处理，参与交换的双方线程都能知道（甚至指定）对方线程的身份。

消息格式

消息描述符 是一种数据结构，用于指定消息数据所在的位置，以及邮箱处理该消息的方式。发送线程和接收线程在访问邮箱时都要提供消息描述符。邮箱使用这些消息描述符在相互兼容的发送线程和接收线程之间执行消息交换。在交换过程中，邮箱还会更新消息描述符的某些字段，使双方线程都能了解发生了什么。

邮箱消息包含零个或多个字节的 消息数据。消息数据的大小和格式由应用程序定义，并且每条消息可以不同。

消息缓冲区 是由发送或接收消息数据的线程提供的一块内存区域。通常可以使用数组或结构体变量来实现。

不包含任何形式消息数据的消息称为 空消息。

备注

消息缓冲区存在但实际数据为零字节的消息 不是 空消息。

消息生命周期

消息的生命周期很简单。发送线程将消息交给邮箱时，消息即被创建。之后消息归邮箱所有，直到被交给接收线程。接收线程可以在从邮箱接收消息时取回消息数据，也可以在随后的第二次邮箱操作中取回数据。只有在数据被取回之后，邮箱才会删除该消息。

线程兼容性

发送线程可以指定消息要发往的线程地址，也可以指定 K_ANY 将消息发给任意线程。同样，接收线程可以指定希望从哪个线程接收消息，也可以指定 K_ANY 从任意线程接收消息。只有当发送线程和接收线程双方的要求都得到满足时，才会交换消息；这样的线程称为 兼容的 线程。

例如，如果线程 A 向线程 B（且仅向线程 B）发送一条消息，那么当线程 B 尝试从线程 A 接收消息，或者尝试从任意线程接收消息时，线程 B 都会收到该消息。如果线程 B 尝试从线程 C 接收消息，则不会发生交换。线程 C 永远无法收到这条消息，即使它尝试从线程 A（或从任意线程）接收消息。

消息流控制

邮箱消息可以 同步 或 异步 交换。在同步交换中，发送线程会阻塞，直到接收线程完全处理完该消息。在异步交换中，发送线程不必等到消息被其他线程接收就可以继续执行；这样，发送线程可以在消息被交给接收线程并完全处理 之前 做其他工作（例如收集下一条消息要使用的数据）。某次消息交换使用哪种方式由发送线程决定。

同步交换方式提供了一种隐式的流控制，防止发送线程生成消息的速度超过接收线程的消费速度。异步交换方式提供了一种显式的流控制，使发送线程能够在发送下一条消息之前判断之前发送的消息是否仍然存在。

实现

定义邮箱

邮箱使用 k_mbox 类型的变量定义，然后必须调用 k_mbox_init() 进行初始化。

以下代码定义并初始化了一个空邮箱。

struct k_mbox my_mailbox;

k_mbox_init(&my_mailbox);

也可以调用 K_MBOX_DEFINE 在编译时定义并初始化邮箱。

以下代码与上面的代码段效果相同。

K_MBOX_DEFINE(my_mailbox);

消息描述符

消息描述符是 k_mbox_msg 类型的结构体。只应使用下面列出的字段；其他字段仅供邮箱内部使用。

info

由消息发送方和接收方交换的 32 位值，其含义由应用程序定义。这种交换是双向的：在任何消息交换中，发送方都可以向接收方传递一个值；在同步消息交换中，接收方也可以向发送方传递一个值。

size

消息数据的大小，以字节为单位。发送空消息，或发送不含实际数据的消息缓冲区时，将其设为零。接收消息时，将其设为期望接收的最大数据量；如果不需要消息数据，则设为零。消息被接收后，邮箱会用实际交换的数据字节数更新该字段。

tx_data

指向发送线程消息缓冲区的指针。发送空消息时将其设为 NULL。接收消息时不要初始化该字段。

tx_target_thread

目标接收线程的地址。将其设为 K_ANY 表示允许任意线程接收该消息。接收消息时不要初始化该字段。消息被接收后，邮箱会用实际接收者的地址更新该字段。

rx_source_thread

期望的发送线程的地址。将其设为 K_ANY 表示接收任意线程发送的消息。发送消息时不要初始化该字段。消息被放入邮箱时，邮箱会用实际发送者的地址更新该字段。

发送消息

线程发送消息时，首先创建消息数据（如果有）。

接着，发送线程按上一节所述创建一个描述待发送消息的消息描述符。

最后，发送线程调用邮箱发送 API 发起消息交换。如果当前有兼容的接收线程正在等待，消息会立即交给该线程；否则，消息会被加入邮箱的发送队列。

发送队列中可以同时存在任意数量的消息。发送队列中的消息按发送线程的优先级排序。优先级相同的消息按时间排序，使最早的消息最先被接收。

对于同步发送操作，通常要等到接收线程既接收了消息又取回了消息数据，操作才完成。如果在发送线程指定的等待时间到达之前消息未被接收，该消息会从邮箱的发送队列中移除，发送操作失败。发送操作成功完成后，发送线程可以检查消息描述符，以确定哪个线程接收了消息、交换了多少数据，以及接收线程提供的应用程序自定义 info 值。

备注

同步发送操作可能会无限期阻塞发送线程，即使该线程指定了最大等待时间。等待时间只限制邮箱在消息被其他线程接收之前等待的时长。消息一旦被接收，接收线程取回消息数据并解除发送线程阻塞所用的时间就 没有 任何限制。

对于异步发送操作，操作总是立即完成。这样，无论消息是立即交给接收线程，还是被加入发送队列，发送线程都可以继续处理。发送线程可以选择指定一个信号量，当邮箱删除该消息时（例如消息已被接收线程接收并取回数据时），邮箱会释放该信号量。借助信号量，发送线程可以很容易地实现一种流控制机制，确保邮箱在任何时刻持有的、来自某个发送线程（或一组发送线程）的消息数量不超过应用程序指定的数目。

备注

异步发送消息的线程无法确定哪个线程接收了消息、交换了多少数据，也无法得知接收线程提供的应用程序自定义 info 值。

发送空消息

这段代码使用邮箱，以同步方式向任何需要的消费者线程传递 4 字节随机值。消息的 "info" 字段足以承载要交换的信息，因此不使用消息的数据部分。

void producer_thread(void)
{
    struct k_mbox_msg send_msg;

    while (1) {

        /* generate random value to send */
        uint32_t random_value = sys_rand32_get();

        /* prepare to send empty message */
        send_msg.info = random_value;
        send_msg.size = 0;
        send_msg.tx_data = NULL;
        send_msg.tx_target_thread = K_ANY;

        /* send message and wait until a consumer receives it */
        k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);
    }
}

使用消息缓冲区发送数据

这段代码使用邮箱，以同步方式将大小可变的请求从生产者线程传递给任何需要的消费者线程。消息的 "info" 字段用于交换每个线程能够处理的最大消息缓冲区大小的信息。

void producer_thread(void)
{
    char buffer[100];
    int buffer_bytes_used;

    struct k_mbox_msg send_msg;

    while (1) {

        /* generate data to send */
        ...
        buffer_bytes_used = ... ;
        memcpy(buffer, source, buffer_bytes_used);

        /* prepare to send message */
        send_msg.info = buffer_bytes_used;
        send_msg.size = buffer_bytes_used;
        send_msg.tx_data = buffer;
        send_msg.tx_target_thread = K_ANY;

        /* send message and wait until a consumer receives it */
        k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);

        /* info, size, and tx_target_thread fields have been updated */

        /* verify that message data was fully received */
        if (send_msg.size < buffer_bytes_used) {
            printf("some message data dropped during transfer!");
            printf("receiver only had room for %d bytes", send_msg.info);
        }
    }
}

接收消息

线程接收消息时，首先创建一个描述期望接收的消息的消息描述符，然后调用某个邮箱接收 API。邮箱会搜索其发送队列，并从找到的第一个兼容线程处取出消息。如果不存在兼容的线程，接收线程可以选择等待。如果在接收线程指定的等待时间到达之前没有出现兼容的线程，接收操作失败。接收操作成功完成后，接收线程可以检查消息描述符，以确定哪个线程发送了消息、交换了多少数据，以及发送线程提供的应用程序自定义 info 值。

任意数量的接收线程可以同时在邮箱的接收队列上等待。这些线程按优先级排序；优先级相同的线程按开始等待的先后排序，最先开始等待的线程最先收到消息。

备注

由于消息描述符指定了线程兼容性约束，接收线程并不总是按先进先出（FIFO）的顺序收到消息。例如，如果线程 A 等待只接收来自线程 X 的消息，随后线程 B 等待接收来自线程 Y 的消息，那么线程 Y 发往任意线程的消息将交给线程 B，而线程 A 会继续等待。

接收线程既可以控制从收到的消息中取回多少数据，也可以控制数据存放的位置。线程可以选择取走消息中的全部数据、只取开头一部分数据，或者完全不取数据。同样，线程也可以选择将数据复制到自己指定的消息缓冲区中。

以下各节概述了接收线程取回消息数据时可以采用的几种方法。

在接收时取回数据

线程取回消息数据最直接的方式，是在接收消息时指定一个消息缓冲区。线程需要同时指明消息缓冲区的位置（不得为 NULL）及其大小。

作为接收操作的一部分，邮箱会将消息数据复制到消息缓冲区中。如果消息缓冲区不足以容纳消息的全部数据，未被复制的数据将丢失。如果消息数据不足以填满缓冲区，消息缓冲区中未使用的部分保持不变。无论哪种情况，邮箱都会更新接收线程的消息描述符，指明复制了多少字节的数据（如果有）。

立即取回数据的方式最适合预先知道最大消息大小的小消息。

以下代码使用邮箱和立即取回数据的方式，处理来自任意生产者线程的大小可变的请求。消息的 "info" 字段用于交换每个线程能够处理的最大消息缓冲区大小的信息。

void consumer_thread(void)
{
    struct k_mbox_msg recv_msg;
    char buffer[100];

    int i;
    int total;

    while (1) {
        /* prepare to receive message */
        recv_msg.info = 100;
        recv_msg.size = 100;
        recv_msg.rx_source_thread = K_ANY;

        /* get a data item, waiting as long as needed */
        k_mbox_get(&my_mailbox, &recv_msg, buffer, K_FOREVER);

        /* info, size, and rx_source_thread fields have been updated */

        /* verify that message data was fully received */
        if (recv_msg.info != recv_msg.size) {
            printf("some message data dropped during transfer!");
            printf("sender tried to send %d bytes", recv_msg.info);
        }

        /* compute sum of all message bytes (from 0 to 100 of them) */
        total = 0;
        for (i = 0; i < recv_msg.size; i++) {
            total += buffer[i];
        }
    }
}

稍后使用消息缓冲区取回数据

接收线程可以选择在接收消息时推迟取回消息数据，以便稍后再将数据取回到消息缓冲区中。为此，线程将消息缓冲区的位置指定为 NULL，并用大小指明稍后愿意取回的最大数据量。

作为接收操作的一部分，邮箱不会复制任何消息数据，但仍会更新接收线程的消息描述符，指明有多少字节的数据可供取回。

接收线程随后必须按如下方式处理：

  • 如果消息描述符中的大小为零，说明发送方的消息不含数据，或者接收线程不想接收任何数据。接收线程无需进一步操作，因为邮箱已经完成数据取回并删除了该消息。

  • 如果消息描述符中的大小不为零，且接收线程仍想取回数据，则线程必须调用 k_mbox_data_get()，并提供一个足以容纳这些数据的消息缓冲区。邮箱会将数据复制到该消息缓冲区并删除消息。

  • 如果消息描述符中的大小不为零，而接收线程 不 想取回数据，则线程必须调用 k_mbox_data_get()，并将消息缓冲区指定为 NULL。邮箱会删除该消息而不复制数据。

后续取回数据的方式适用于不希望立即取回消息数据的应用程序。例如，当内存受限，接收线程无法总是提供一个能容纳最大可能消息的消息缓冲区时，就可以使用这种方式。

以下代码使用邮箱的延迟取回数据机制，仅当消息满足特定条件时才从生产者线程获取消息数据，从而避免不必要的数据复制。发送方提供的消息 "info" 字段用于对消息进行分类。

void consumer_thread(void)
{
    struct k_mbox_msg recv_msg;
    char buffer[10000];

    while (1) {
        /* prepare to receive message */
        recv_msg.size = 10000;
        recv_msg.rx_source_thread = K_ANY;

        /* get message, but not its data */
        k_mbox_get(&my_mailbox, &recv_msg, NULL, K_FOREVER);

        /* get message data for only certain types of messages */
        if (is_message_type_ok(recv_msg.info)) {
            /* retrieve message data and delete the message */
            k_mbox_data_get(&recv_msg, buffer);

            /* process data in "buffer" */
            ...
        } else {
            /* ignore message data and delete the message */
            k_mbox_data_get(&recv_msg, NULL);
        }
    }
}

建议用法

当消息队列的能力不足时，使用邮箱在线程之间传递数据项。
