消息队列

message queue （消息队列）是实现简单消息队列的内核对象，允许线程和 ISR 异步发送和接收固定大小的数据项。

概念

可以定义任意数量的消息队列（仅受可用 RAM 限制）。每个消息队列通过其内存地址引用。

消息队列具有以下关键属性：

  • 环形缓冲区，存放已发送但尚未被接收的数据项。

  • 数据项大小，以字节为单位。

  • 最大数量，即环形缓冲区中可排队的数据项的最大个数。

消息队列必须先初始化才能使用，初始化会将其环形缓冲区置为空。

线程或 ISR 都可以向消息队列 发送 数据项。如果有线程正在等待，发送线程所指向的数据项会被复制给该等待线程；否则，在有空间的情况下，数据项会被复制到消息队列的环形缓冲区中。无论哪种情况，所发送数据区的大小 必须 等于消息队列的数据项大小。

如果线程在环形缓冲区已满时尝试发送数据项，发送线程可以选择等待空间变为可用。环形缓冲区已满时，任意数量的发送线程可以同时等待；当有空间可用时，空间会交给等待时间最长的最高优先级发送线程。

线程可以从消息队列 接收 数据项。数据项会被复制到接收线程指定的区域；接收区域的大小 必须 等于消息队列的数据项大小。

如果线程在环形缓冲区为空时尝试接收数据项，接收线程可以选择等待有数据项被发送。环形缓冲区为空时，任意数量的接收线程可以同时等待；当有数据项可用时，它会交给等待时间最长的最高优先级接收线程。

线程还可以 窥视 （peek）消息队列队首的消息，而不将其从队列中移除。数据项会被复制到接收线程指定的区域；接收区域的大小 必须 等于消息队列的数据项大小。

备注

内核允许 ISR 从消息队列接收数据项，但如果消息队列为空，ISR 不得尝试等待。

备注

消息队列的环形缓冲区无需对齐。底层实现使用 memcpy() （与对齐无关），并且不暴露任何内部指针。

实现

定义消息队列

消息队列使用 k_msgq 类型的变量定义，然后必须调用 k_msgq_init() 进行初始化。

以下代码定义并初始化了一个空消息队列，它最多可容纳 10 个数据项，每个数据项长 12 字节。

struct data_item_type {
    uint32_t field1;
    uint32_t field2;
    uint32_t field3;
};

char my_msgq_buffer[10 * sizeof(struct data_item_type)];
struct k_msgq my_msgq;

k_msgq_init(&my_msgq, my_msgq_buffer, sizeof(struct data_item_type), 10);

也可以调用以下宏之一，在编译时定义并初始化消息队列：

  • K_MSGQ_DEFINE —— 定义一个公共消息队列。

  • K_MSGQ_DEFINE_STATIC —— 定义一个私有（静态作用域）消息队列。

  • K_MSGQ_DEFINE_TYPE —— 为给定的数据项类型定义一个公共消息队列。

  • K_MSGQ_DEFINE_STATIC_TYPE —— 为给定的数据项类型定义一个私有消息队列。

以下代码与上面的代码段效果相同。注意，该宏同时定义了消息队列及其缓冲区。

K_MSGQ_DEFINE(my_msgq, sizeof(struct data_item_type), 10, 1);

如果在编译时已知队列数据项的类型，可以使用简写宏 K_MSGQ_DEFINE_TYPE。该宏会自动配置队列数据项的大小和对齐方式：

K_MSGQ_DEFINE_TYPE(my_msgq, struct data_item_type, 10);

写入消息队列

调用 k_msgq_put() 向消息队列添加数据项。

以下代码基于上面的示例，使用消息队列将数据项从生产者线程传递给一个或多个消费者线程。如果由于消费者处理不及而导致消息队列已满，生产者线程会丢弃所有现有数据，以便保存较新的数据。注意，此 API 会触发重新调度。

void producer_thread(void)
{
    struct data_item_type data;

    while (1) {
        /* create data item to send (e.g. measurement, timestamp, ...) */
        data = ...

        /* send data to consumers */
        while (k_msgq_put(&my_msgq, &data, K_NO_WAIT) != 0) {
            /* message queue is full: purge old data & try again */
            k_msgq_purge(&my_msgq);
        }

        /* data item was successfully added to message queue */
    }
}

从消息队列读取

调用 k_msgq_get() 从消息队列中取出数据项。

以下代码基于上面的示例，使用消息队列处理由一个或多个生产者线程生成的数据项。注意，应检查 k_msgq_get() 的返回值，因为 k_msgq_purge() 可能导致其返回 -ENOMSG。

void consumer_thread(void)
{
    struct data_item_type data;

    while (1) {
        /* get a data item */
        k_msgq_get(&my_msgq, &data, K_FOREVER);

        /* process data item */
        ...
    }
}

窥视消息队列

调用 k_msgq_peek() 从消息队列中读取数据项。

以下代码窥视消息队列，读取位于队首、由一个或多个生产者线程生成的数据项。

void consumer_thread(void)
{
    struct data_item_type data;

    while (1) {
        /* read a data item by peeking into the queue */
        k_msgq_peek(&my_msgq, &data);

        /* process data item */
        ...
    }
}

建议用法

使用消息队列在线程之间以异步方式传递小数据项。

备注

如有需要，消息队列也可以用于传递大数据项。但这可能会增加中断延迟，因为写入或读取数据项期间中断是被锁定的。由于数据项要整体复制到内存缓冲区或从中复制出来，写入或读取数据项的时间随其大小线性增长。因此，传递大数据项时，通常更好的做法是交换指向数据项的指针，而不是数据项本身。

可以使用内核的邮箱对象类型实现同步传输。
