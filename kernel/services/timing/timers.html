定时器

timer （定时器）是使用内核系统时钟度量时间流逝的内核对象。当定时器达到指定的时限时，它可以执行应用程序定义的操作，也可以只记录到期事件，等待应用程序读取其状态。

概念

可以定义任意数量的定时器（仅受可用 RAM 限制）。每个定时器通过其内存地址引用。

定时器具有以下关键属性：

  • 持续时间，指定定时器首次到期之前的时间间隔。它是一个 k_timeout_t 值，可以用不同的单位初始化。

  • 周期，指定首次到期之后各次到期之间的时间间隔，同样是 k_timeout_t 值，且必须是非负数。周期为 K_NO_WAIT （即零）或 K_FOREVER 表示该定时器是单次定时器，到期一次后即停止。（例如，如果以持续时间 200、周期 75 启动定时器，它会在 200 ms 后首次到期，之后每 75 ms 到期一次。）

  • 到期函数，每次定时器到期时执行。该函数由系统时钟中断处理程序执行。如果不需要到期函数，可以指定 NULL。

  • 停止函数，在定时器运行期间被提前停止时执行。该函数由停止定时器的线程执行。如果不需要停止函数，可以指定 NULL。

  • 状态 值，表示自上次读取状态值以来定时器到期的次数。

定时器必须先初始化才能使用。初始化会指定其到期函数和停止函数，将定时器的状态置零，并使定时器进入 停止 状态。

通过指定持续时间和周期来 启动 定时器。定时器的状态被重置为零，然后定时器进入 运行 状态，开始倒计时直至到期。

备注

定时器的持续时间是相对于定时器启动时刻的 最小 延迟。定时器的周期是相对于定时器上一次“本应”到期时刻的 最小 延迟。这意味着周期定时器相对于系统定时器不会产生漂移，其周期性延迟可能比指定的周期更短或更长。

要确保定时器到期前至少经过最小延迟，请在 到期函数 中或在定时器到期之后重新启动定时器。

延迟的变化源于系统中的可变因素，例如中断处理延迟和之前的定时器处理函数的执行时间。

运行中的定时器到期时，其状态加一，并执行到期函数（如果有）；如果有线程正在等待该定时器，该线程会被解除阻塞。如果定时器的周期为零，定时器进入停止状态；否则，定时器以新的持续时间重新启动，该持续时间等于其周期与定时器“本应”到期时刻之间的差值。

如有需要，可以在倒计时过程中停止运行中的定时器。定时器的状态保持不变，然后定时器进入停止状态，并执行停止函数（如果有）。如果有线程正在等待该定时器，该线程会被解除阻塞。允许尝试停止未运行的定时器，但由于定时器已经停止，这不会产生任何效果。

如有需要，可以在倒计时过程中重新启动运行中的定时器。定时器的状态被重置为零，然后定时器使用调用者指定的新持续时间和周期开始倒计时。如果有线程正在等待该定时器，该线程会继续等待。

可以随时直接读取定时器的状态，以确定自上次读取状态以来定时器到期的次数。读取定时器状态会将其值重置为零。还可以读取定时器到期前的剩余时间；值为零表示定时器已停止。

线程可以通过与定时器 同步 来间接读取定时器的状态。这会阻塞线程，直到定时器状态不为零（表示它至少到期过一次）或定时器被停止；如果定时器状态已经不为零或定时器已经停止，线程会继续执行而不等待。同步操作返回定时器的状态，并将其重置为零。

备注

对于任何给定的定时器，只应由一个使用者检查其状态，因为（直接或间接）读取状态会改变其值。同样，同一时刻只应有一个线程与给定的定时器同步。ISR 不允许与定时器同步，因为 ISR 不允许阻塞。

定时器观察者

启用 CONFIG_TIMER_OBSERVER 后，代码可以注册 timer observers （定时器观察者），以便接收系统中所有定时器的生命周期事件通知。观察者是一组可选回调，在定时器被初始化、启动、停止或到期时调用。这使外部模块（例如跟踪、性能分析或电源管理代码）无需修改内核内部实现或各个定时器，就能对定时器活动作出响应。

观察者通过 K_TIMER_OBSERVER_DEFINE 静态定义，该宏接受指向 on_init、on_start、on_stop 和 on_expiry 回调的指针；不需要的回调可以传入 NULL。由于到期回调在中断上下文中运行，它必须保持简短且不阻塞。

实现

定义定时器

定时器使用 k_timer 类型的变量定义，然后必须调用 k_timer_init() 进行初始化。

以下代码定义并初始化了一个定时器。

struct k_timer my_timer;
extern void my_expiry_function(struct k_timer *timer_id);

k_timer_init(&my_timer, my_expiry_function, NULL);

也可以调用 K_TIMER_DEFINE 在编译时定义并初始化定时器。

以下代码与上面的代码段效果相同。

K_TIMER_DEFINE(my_timer, my_expiry_function, NULL);

使用定时器到期函数

以下代码使用定时器周期性地执行一项较复杂的操作。由于所需的工作不能在中断级别完成，定时器的到期函数会将一个工作项提交到 系统工作队列，由其线程执行该工作。

void my_work_handler(struct k_work *work)
{
    /* do the processing that needs to be done periodically */
    ...
}

K_WORK_DEFINE(my_work, my_work_handler);

void my_timer_handler(struct k_timer *dummy)
{
    k_work_submit(&my_work);
}

K_TIMER_DEFINE(my_timer, my_timer_handler, NULL);

...

/* start a periodic timer that expires once every second */
k_timer_start(&my_timer, K_SECONDS(1), K_SECONDS(1));

读取定时器状态

以下代码直接读取定时器的状态，以确定定时器是否已到期。

K_TIMER_DEFINE(my_status_timer, NULL, NULL);

...

/* start a one-shot timer that expires after 200 ms */
k_timer_start(&my_status_timer, K_MSEC(200), K_NO_WAIT);

/* do work */
...

/* check timer status */
if (k_timer_status_get(&my_status_timer) > 0) {
    /* timer has expired */
} else if (k_timer_remaining_get(&my_status_timer) == 0) {
    /* timer was stopped (by someone else) before expiring */
} else {
    /* timer is still running */
}

使用定时器状态同步

以下代码执行定时器状态同步，使线程在确保两个协议操作之间相隔指定时间间隔的同时，还能完成其他有用的工作。

K_TIMER_DEFINE(my_sync_timer, NULL, NULL);

...

/* do first protocol operation */
...

/* start a one-shot timer that expires after 500 ms */
k_timer_start(&my_sync_timer, K_MSEC(500), K_NO_WAIT);

/* do other work */
...

/* ensure timer has expired (waiting for expiry, if necessary) */
k_timer_status_sync(&my_sync_timer);

/* do second protocol operation */
...

备注

如果线程没有其他工作要做，可以直接在两个协议操作之间睡眠，而无需使用定时器。

建议用法

使用定时器在指定时间之后启动异步操作。

使用定时器判断是否已经过了指定的时间。特别是，当需要比更简单的 k_sleep() 和 k_usleep() 调用更高的精度和/或单位控制时，应使用定时器。

在执行有时限的操作时，使用定时器以便同时完成其他工作。

备注

如果线程需要测量执行某个操作所需的时间，可以直接读取 系统时钟或硬件时钟，而不必使用定时器。
