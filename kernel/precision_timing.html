精密计时

精密计时子系统为 PTP、gPTP 以及其他控制高分辨率时钟的使用者提供了一小组可复用的机制。通过 CONFIG_PRECISION_TIMING 启用。

备注

该 API 处于 实验性 成熟度，仍可能发生变化。协议不会因为使用了该子系统而改变其成熟度。

该子系统有意不实现同步策略。PTP 和 gPTP 仍各自负责其协议状态机、时钟选择、步进阈值、样本接受、锁定检测、源丢失处理以及诊断。

精密时间

precision_time_t 是一个有符号 64 位纳秒值。带检查的加法和减法辅助函数会报告溢出。该类型不标识时间域或时间尺度；对 TAI、UTC、PHC、单调时间及协议关系的建模不在此 API 范围之内。

精密时钟

precision_clock 分派四种必需的时钟操作：

  • 读取当前时间；

  • 设置绝对时间；

  • 施加相位调整；以及

  • 设置相对于标称频率的速率偏移，以百万分率（ppm）表示，带 16 位二进制小数部分。

所有操作都必须由时钟适配器实现。调整范围及其他硬件约束仍由底层时钟实现负责。

precision_clock_ptp_adapter 通过该接口暴露现有的 Zephyr PTP 时钟设备。它在 net_ptp_time 与 precision_time_t 之间进行所需的转换；它不增加能力发现或同步状态。

PI 控制器

precision_pi 是一个基于实例的比例积分控制器。每个实例保存各自的增益和积分项。对于每个误差样本，其更新等价于：

integral += ki * error;
output = kp * error + integral;

该控制器不决定某个误差应被步进、拒绝还是用于速率调整。它也不跟踪同步、捕获、锁定、保持（holdover）、源超时或时钟故障。这些决策由调用者负责，并在其策略需要时重置累积的积分项。

PTP 和 gPTP 集成通过 CONFIG_PRECISION_TIMING_PI_KP 和 CONFIG_PRECISION_TIMING_PI_KI 初始化其控制器。这些整数值以千分之一为单位表示增益。直接使用 precision_pi_init() 的用户可以为每个控制器实例提供不同的增益。

协议集成

PTP 和 gPTP 的默认时钟更新路径各自保留其现有策略，并使用 precision_pi 完成共用的计算。它们会初始化一次 PTP 时钟适配器，并使用 precision_clock 操作访问 PHC。
