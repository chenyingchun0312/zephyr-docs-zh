内存堆

Zephyr 提供了一组工具，允许线程动态分配内存。

同步堆分配器

创建堆

定义堆最简单的方式是使用 K_HEAP_DEFINE 宏静态定义。它会创建一个具有给定名称的静态 k_heap 变量，用于管理指定大小的内存区域。

还可以使用 k_heap_init() 创建堆，来管理由应用程序控制的任意内存区域。

分配内存

可以使用 k_heap_alloc() 从堆中分配内存，向其传入堆对象的地址和所需的字节数。它的功能类似于标准 C 的 malloc()，分配失败时返回 NULL 指针。

堆支持阻塞操作，允许线程休眠直到有可用内存。最后一个参数是一个 k_timeout_t 超时值，表示线程在返回之前最多可以休眠多久，也可以是常量超时值 K_NO_WAIT 或 K_FOREVER 之一。

当需要特定对齐的内存块时，k_heap_aligned_alloc() 会分配一个起始地址为调用者指定的 2 的幂对齐值整数倍的内存块。k_heap_calloc() 分配一个数组并将其初始化为零。

已分配内存的大小可以用 k_heap_realloc() 修改，它返回一个所请求大小的内存块，并保留原有内容（保留长度为新旧大小中较小者）。与标准 C 的 realloc() 一样，返回的指针可能与原指针不同。

释放内存

用 k_heap_alloc() 分配的内存必须用 k_heap_free() 释放。与标准 C 的 free() 类似，所提供的指针必须是 NULL 值，或者是之前由 k_heap_alloc() 针对同一个堆返回的指针。释放 NULL 值被定义为不产生任何效果。

枚举堆

所有用 K_HEAP_DEFINE 静态定义的堆都放在一个专用的链接器段中，因此可以在运行时枚举它们。k_heap_array_get() 返回静态定义堆的数组地址及其包含的条目数。这主要用于需要检查系统中每个堆的插桩和诊断工具。

底层堆分配器

k_heap 抽象的底层实现由一个名为 sys_heap 的数据结构提供。它实现了完全相同的分配语义，但不提供内核同步工具。它适用于希望在无法使用同步或同步更复杂的上下文（例如用户空间）中自行管理内存块的应用程序。与 k_heap 不同，对同一个堆的所有 sys_heap 函数调用都必须由调用者串行化，不允许不同线程同时使用。

实现

在内部，sys_heap 内存块被划分为 8 字节的“块单元（chunk）”。所有分配都来自一段连续的块单元区域。每个已分配或未使用内存块的第一个块单元前面都有一个块单元头，其中存储该块单元的长度、物理内存中相邻的下一个较低地址（“左侧”）块单元的长度、一个表示该块单元是否在使用中的位，以及以块单元为索引、指向“空闲链表”中前一个和后一个块单元的链接指针，未使用的块单元会被加入该空闲链表。

堆代码会适当注意避免碎片。空闲块链表按大小存放在各个“桶”中，每个桶存放大小在一个 2 的幂范围内的块（即一个桶存放 3-4 个块单元的块，另一个存放 5-8 个，然后是 9-16 个，依此类推），这使得新的分配可以从可用的最小/最碎片化的块中进行。此外，当分配的内存被释放并归还给堆时，它们会自动与相邻的空闲块合并，以防止碎片。

所有元数据都存储在连续堆内存块的开头，包括可变长度的桶链表头列表（其长度取决于堆大小）。唯一需要的外部内存就是 sys_heap 结构体本身。

sys_heap 函数不做同步。所有使用者都必须注意防止并发访问。同一时刻只能有一个上下文处于某个 API 函数内部。

堆代码注重提供高性能和可靠的延迟。所有 sys_heap API 函数都保证在常数时间内完成。在典型架构上，它们都会在 1 到 200 个周期内完成。其中一个复杂之处在于，为一次分配查找最小桶大小（即“可能放得下”的空闲块集合）时，迭代次数有一个编译时上限，以防止无界的链表搜索，代价是牺牲一些抗碎片能力。该值 CONFIG_SYS_HEAP_ALLOC_LOOPS 可由用户在构建时选择，默认为 3。

多堆包装工具

sys_heap 工具要求所有被管理的内存都位于一个连续的块中。而复杂的微控制器应用程序常常有更复杂的内存布局，但仍希望把它们作为“堆”进行动态管理。例如，内存可能是若干彼此不连续的区域，不同区域可能有不同的缓存、性能或功耗特性，外设可能只能对某些区域进行 DMA，等等。

针对这些情况，Zephyr 提供了 sys_multi_heap 工具。它实际上是对一个或多个 sys_heap 对象集合的简单包装。应在其子堆之后通过 sys_multi_heap_init() 初始化，之后可以通过 sys_multi_heap_add_heap() 把每个堆加入被管理的集合。它不提供销毁工具；与 sys_heap 一样，想要销毁多堆的应用程序只需确保所有已分配的块都已释放（或至少永远不会再被使用），然后把底层内存挪作他用即可。

它只有一对分配入口：sys_multi_heap_alloc() 和 sys_multi_heap_aligned_alloc()。它们的行为与名称相似的 sys_heap 函数完全相同，只是还接受一个不透明的“配置”参数。多堆代码本身不检查这个指针，而是把它传给初始化时提供的回调函数。这个由应用程序提供的回调负责从某个被管理的堆中完成实际分配，并可以按任意方式使用该配置参数来做出决定。

要修改已分配缓冲区的大小（无论是缩小还是扩大），可以使用 sys_multi_heap_realloc() 和 sys_multi_heap_aligned_realloc() API。如果缓冲区无法在其当前所在的堆上扩大，则可以使用配置参数所指定的任何符合条件的堆。

不再使用时，可以通过 sys_multi_heap_free() 释放多堆中的内存。应用程序不需要传入配置参数。从任何被管理的 sys_heap 对象中分配的内存都可以用同样的方式释放。

系统堆

system heap 是一个预定义的内存分配器，允许线程以类似 malloc() 的方式从一块公共内存区域中动态分配内存。

只定义了一个系统堆。与其他堆或内存池不同，系统堆不能通过其内存地址直接引用。

系统堆的大小可以配置为任意值，只受可用空间的限制。

线程可以调用 k_malloc() 动态分配一块堆内存。所分配内存块的地址保证按指针大小的整数倍对齐。如果找不到合适的堆内存块，则返回 NULL。

线程用完一块堆内存后，可以调用 k_free() 将其归还给系统堆。

定义堆内存池

堆内存池的大小使用 CONFIG_HEAP_MEM_POOL_SIZE 配置选项指定。

默认情况下，堆内存池大小为零字节。该值指示内核不定义堆内存池对象。最大大小受系统中可用内存量的限制。如果无法支持所指定的大小，项目构建将在链接阶段失败。

此外，每个子系统（开发板、驱动、库等）都可以通过定义一个以 HEAP_MEM_POOL_ADD_SIZE_ 为前缀的 Kconfig 选项（值以字节为单位）来设置自定义的需求。如果多个子系统指定了自定义值，则以它们的总和作为最低需求。如果应用程序试图设置一个小于最低值的值，该值将被忽略，转而使用最低值。

要强制使用小于最低值的值，应用程序可以启用 CONFIG_HEAP_MEM_POOL_IGNORE_MIN 选项。在优化堆大小、并且可以针对特定应用程序更准确地确定最低需求时，这会很有用。

分配内存

调用 k_malloc() 分配一块堆内存。

以下代码分配一块 200 字节的堆内存，然后将其填充为零。如果没有获得合适的内存块，则发出警告。

char *mem_ptr;

mem_ptr = k_malloc(200);
if (mem_ptr != NULL)) {
    memset(mem_ptr, 0, 200);
    ...
} else {
    printf("Memory not allocated");
}

释放内存

调用 k_free() 释放一块堆内存。

以下代码分配一块 75 字节的内存，然后在不再需要时将其释放。

char *mem_ptr;

mem_ptr = k_malloc(75);
... /* use memory block */
k_free(mem_ptr);

建议用法

使用堆内存池以类似 malloc() 的方式动态分配内存。
