按需分页

按需分页提供了一种机制：只有当前执行上下文需要时，才把数据调入物理内存。从概念上讲，物理内存被划分为页大小的页框，作为存放数据的区域。

Zephyr 内核镜像本身始终驻留在物理内存中，永远不会成为换出的候选对象。按需分页仅适用于：

  • 在运行时通过 k_mem_map() 创建的匿名内存映射，以及

  • 启用 CONFIG_LINKER_USE_ONDEMAND_SECTION 时，通过 __ondemand_func / __ondemand_rodata 属性放入显式按需链接器段中的内存。

这与所有主流操作系统使用的模型相同：异常或中断的分派路径永远不会位于可分页的页上，因此从结构上就不可能在处理缺页时再发生缺页。把代码或数据加入 __ondemand_* 段，意味着贡献者明确选择让该区域可分页，并且有责任确保缺页处理函数自身的执行路径不会访问到该区域。

备注

早期版本的 Zephyr 还支持一种基于 __pinned_* 链接器属性的选择性锁定方案，只让内核镜像中被标记的子集常驻内存，其余部分按需分页。后来发现该模型既不安全，又侵入性很强：CPU 异常分派的目标可能是位于可换出页上的线程特权栈，如果该页已被换出，在 x86 上会升级为双重故障，在 ARM64 上会导致嵌套中止；而要求缺页处理函数可达范围内（调度器、驱动、libc、锁原语）的每一个字节都被完整标记，这一约定既难以一次性建立，之后也无法维护。__pinned_* 属性系列、相应的 Kconfig 选项（LINKER_USE_PINNED_SECTION / LINKER_GENERIC_SECTIONS_PRESENT_AT_BOOT）以及 K_*_PINNED_STACK_* 栈宏已在 Zephyr 4.4 中移除。完整分析参见 GitHub #108773。

  • 当处理器尝试访问数据，而该数据页位于某个页框中时，执行会继续进行，不会被打断。

  • 当处理器尝试访问不在任何页框中的数据页时，就会发生缺页。如果有空闲页框，分页代码会把对应的数据页从后备存储调入物理内存。如果没有空闲页框，则调用换出算法选择一个要调出的数据页，从而腾出一个页框供新数据调入。如果该数据页在首次调入后被修改过，其数据会被写回后备存储。如果没有修改，或者已经写回后备存储，该数据页即被视为已调出，对应的页框也随之空闲。然后分页代码调用后备存储，调入与所请求数据位置相对应的数据页。后备存储把该数据页复制到空闲页框中。此时数据页已位于物理内存中，执行可以继续。

可以通过 k_mem_page_in() 和 k_mem_page_out() 函数手动调入和调出。k_mem_page_in() 可用于预先调入预计近期需要的数据页。由于这些数据页已在物理内存中，可以减少缺页次数，从而降低延迟。k_mem_page_out() 可用于调出相当长一段时间内不会被访问的数据页。这样可以腾出页框，使下一次调入执行得更快，因为分页代码无需调用换出算法。

还可以使用 k_mem_pin() 把一个数据区域 锁定 在物理内存中。它会在必要时调入该区域，并标记其页框，使换出算法永远不会选中它们，从而保证该区域常驻内存，对它的访问永远不会产生缺页。这是比 k_mem_page_in() 更强的形式，适用于必须始终可用的、对延迟或安全要求严格的数据。被锁定的区域之后可以用 k_mem_unpin() 释放，该函数把页框重新标记为可换出；解除锁定本身不会换出该区域，因此如果希望立即换出，可以随后调用 k_mem_page_out()。

术语

数据页

数据页是页大小的一块数据区域。它可能位于某个页框中，也可能已被调出到某个后备存储。总是可以通过虚拟地址在 CPU 的页表（或等价结构）中查到它的位置。其数据类型总是 void *，在做指针运算时某些情况下为 uint8_t *。

页框

页框是 RAM 中页大小的一块物理内存区域。它是可以放置数据页的容器，总是通过物理地址引用。Zephyr 的约定是使用 uintptr_t 表示物理地址。每个页框都会实例化一个 struct k_mem_page_frame 来存储元数据。每个页框的标志如下：

  • K_MEM_PAGE_FRAME_FREE 表示页框未被使用，位于空闲页框链表中。设置该标志时，其他标志都没有意义，并且不得修改。

  • K_MEM_PAGE_FRAME_PINNED 表示页框被锁定在内存中，永远不应被调出。

  • K_MEM_PAGE_FRAME_RESERVED 表示由硬件保留的物理页，完全不应使用。

  • 物理页被映射到虚拟内存地址时，会设置 K_MEM_PAGE_FRAME_MAPPED。

  • K_MEM_PAGE_FRAME_BUSY 表示页框当前正处于调入/调出操作中。

  • K_MEM_PAGE_FRAME_BACKED 表示页框在后备存储中有一份干净的副本。

K_MEM_SCRATCH_PAGE

提供给后备存储的一个特殊页的虚拟地址，用于：* 把数据页从 k_MEM_SCRATCH_PAGE 复制到指定位置；或者 * 把数据页从所提供的位置复制到 K_MEM_SCRATCH_PAGE。它用作调入/调出操作的中间页。该暂存页需要映射为可读写，以便后备存储代码访问。但数据页本身在虚拟地址空间中可能只映射为只读。如果把该数据页原样提供给后备存储，就必须把它重新映射为可读写，这会带来安全隐患，因为该数据页对应用程序的其他部分不再是只读的。

分页统计

启用 CONFIG_DEMAND_PAGING_TIMING_HISTOGRAM_NUM_BINS 后，可以通过以下各个函数调用获取分页统计信息：

  • 通过 k_mem_paging_stats_get() 获取总体统计信息

  • 如果启用了 CONFIG_DEMAND_PAGING_THREAD_STATS，可通过 k_mem_paging_thread_stats_get() 获取每个线程的统计信息

  • 启用 CONFIG_DEMAND_PAGING_TIMING_HISTOGRAM 并定义了 CONFIG_DEMAND_PAGING_TIMING_HISTOGRAM_NUM_BINS 后，可以获取执行时间直方图。注意，计时结果在很大程度上取决于架构、SoC 或开发板。强烈建议针对特定应用程序定义 k_mem_paging_eviction_histogram_bounds[] 和 k_mem_paging_backing_store_histogram_bounds[]。

    • 通过 k_mem_paging_histogram_eviction_get() 获取换出算法的执行时间直方图

    • 通过 k_mem_paging_histogram_backing_store_page_in_get() 获取后备存储执行调入的时间直方图

    • 通过 k_mem_paging_histogram_backing_store_page_out_get() 获取后备存储执行调出的时间直方图

换出算法

换出算法用于确定可以调出哪个数据页及其对应的页框，从而为下一次调入操作腾出页框。内核分页代码会调用以下四个函数：

  • 调用 k_mem_paging_eviction_init() 初始化换出算法。它在 POST_KERNEL 阶段被调用。

  • 每当某个数据页可以在将来被换出时，都会调用 k_mem_paging_eviction_add()。

  • 当某个数据页不再可以被换出时，会调用 k_mem_paging_eviction_remove()。这可能发生在该数据页被锁定、被取消映射或即将被换出时。

  • 调用 k_mem_paging_eviction_select() 选择一个要换出的数据页。函数参数 dirty 会被写入，用于告知调用者所选数据页在首次调入后是否被修改过。如果返回的 dirty 位被置位，分页代码会通知后备存储把该数据页写回存储（从而更新其内容）。该函数返回指向所选数据页对应页框的指针。

此外还有一个函数 k_mem_paging_eviction_accessed()，由架构的内存管理代码在数据页触发访问故障时调用，用于标记这些数据页。LRU 算法用它把“已使用”的页重新排队。

目前有两种可用的换出算法：

  • 作为示例实现了一个 NRU（最近未使用，Not-Recently-Used）换出算法。这是一个非常简单的算法，根据数据页是否被访问和修改过对其进行排名，并基于该排名进行选择。

  • 还提供了一个 LRU（最近最少使用，Least-Recently-Used）换出算法。它基于一个已排序的数据页队列。LRU 代码比 NRU 代码复杂，但效率也高得多，推荐在生产环境中使用。

要实现新的换出算法，必须实现 k_mem_paging_eviction_init() 和 k_mem_paging_eviction_select()。如果为某个算法启用了 CONFIG_EVICTION_TRACKING，还必须实现以下函数：k_mem_paging_eviction_add()、k_mem_paging_eviction_remove()、k_mem_paging_eviction_accessed()。

后备存储

后备存储负责在数据页对应的页框与存储之间调入/调出数据页。必须实现以下函数：

  • 调用 k_mem_paging_backing_store_init() 在 POST_KERNEL 阶段初始化后备存储。

  • 调用 k_mem_paging_backing_store_location_get() 预留一个后备存储位置，以便调出数据页。该 location 令牌会传给 k_mem_paging_backing_store_page_out()，以执行实际的调出操作。

  • 调用 k_mem_paging_backing_store_location_free() 释放一个后备存储位置（即 location 令牌），之后该位置可用于后续的调出操作。

  • 调用 k_mem_paging_backing_store_location_query() 获取与要进行虚拟映射并按需调入的存储内容相对应的 location 令牌。与 CONFIG_DEMAND_MAPPING 搭配使用时最有用。

  • k_mem_paging_backing_store_page_in() 把数据页从与所提供的 location 令牌关联的后备存储位置复制到 K_MEM_SCRATCH_PAGE 所指向的页。

  • k_mem_paging_backing_store_page_out() 把数据页从 K_MEM_SCRATCH_PAGE 复制到与所提供的 location 令牌关联的后备存储位置。

  • k_mem_paging_backing_store_page_finalize() 在 k_mem_paging_backing_store_page_in() 之后调用，以便更新页框结构体，用于内部记账。它可以不执行任何操作。

要实现新的后备存储，必须实现上述函数。如有需要，k_mem_paging_backing_store_page_finalize() 可以是空函数。
