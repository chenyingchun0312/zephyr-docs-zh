虚拟内存

Zephyr 中的虚拟内存（VM）让开发者能够精细地调整对内存的访问。要使用虚拟内存，平台必须支持内存管理单元（MMU），并且必须在构建中启用。由于 Zephyr 主要面向嵌入式系统，其虚拟内存支持与传统操作系统有所不同：

内核镜像的映射

如果未启用按需分页，默认对内核镜像（包括代码和数据）在物理和虚拟内存地址空间之间进行 1:1 映射。偏离这一做法需要谨慎修改链接器脚本。

二级存储

基本的虚拟内存支持不使用二级存储来扩展可用内存。最大可用内存与物理内存相同。

  • 按需分页 允许将二级存储用作虚拟内存的后备存储，从而使可用内存大于可用的物理内存。注意，按需分页需要显式启用。

  • 虽然虚拟内存空间可以大于物理内存空间，但如果不启用按需分页，所有虚拟映射的内存都必须由物理内存支撑。

Kconfig 选项

必需

以下是内核支持虚拟内存所需启用或定义的 Kconfig 选项。

  • CONFIG_MMU：内核支持虚拟内存时必须启用。

  • CONFIG_MMU_PAGE_SIZE：内存页的大小，默认为 4KB。

  • CONFIG_KERNEL_VM_BASE：虚拟地址空间的基地址。

  • CONFIG_KERNEL_VM_SIZE：虚拟地址空间的大小，默认为 8MB。

  • CONFIG_KERNEL_VM_OFFSET：内核镜像从相对于 CONFIG_KERNEL_VM_BASE 的这一偏移处开始。

可选

  • CONFIG_KERNEL_DIRECT_MAP：允许虚拟地址与物理地址之间的 1:1 映射，而不是由内核在虚拟地址空间内选择地址。这对于映射设备 MMIO 区域以实现更精确的访问控制很有用。

内存映射概览

以下是虚拟内存地址空间的内存映射概览。注意，代码中使用的 Z_* 宏可能因架构和 Kconfig 选项不同而含义不同，下文将加以解释。

+--------------+ <- K_MEM_VIRT_RAM_START
| Undefined VM | <- architecture specific reserved area
+--------------+ <- K_MEM_KERNEL_VIRT_START
| Mapping for  |
| main kernel  |
| image        |
|              |
|              |
+--------------+ <- K_MEM_VM_FREE_START
|              |
| Unused,      |
| Available VM |
|              |
|..............| <- grows downward as more mappings are made
| Mapping      |
+--------------+
| Mapping      |
+--------------+
| ...          |
+--------------+
| Mapping      |
+--------------+ <- memory mappings start here
| Reserved     | <- special purpose virtual page(s) of size K_MEM_VM_RESERVED
+--------------+ <- K_MEM_VIRT_RAM_END

  • K_MEM_VIRT_RAM_START 是虚拟内存地址空间的起始地址，需要按页对齐。目前它与 CONFIG_KERNEL_VM_BASE 相同。

  • K_MEM_VIRT_RAM_SIZE 是虚拟内存地址空间的大小，需要按页对齐。目前它与 CONFIG_KERNEL_VM_SIZE 相同。

  • K_MEM_VIRT_RAM_END 就是（K_MEM_VIRT_RAM_START + K_MEM_VIRT_RAM_SIZE）。

  • K_MEM_KERNEL_VIRT_START 与链接器脚本中指定的 z_mapped_start 相同。它是启动时内核镜像起始处的虚拟地址。

  • K_MEM_KERNEL_VIRT_END 与链接器脚本中指定的 z_mapped_end 相同。它是启动时内核镜像结束处的虚拟地址。

  • K_MEM_VM_FREE_START 是虚拟地址空间中可分配给内存映射的地址的起始处。它取决于是否启用了 CONFIG_ARCH_MAPS_ALL_RAM。

    • 如果启用了该选项，即所有物理内存都映射在虚拟内存地址空间中，则它等于（DT_CHOSEN_SRAM_ADDR + DT_CHOSEN_SRAM_SIZE）。

    • 如果禁用了该选项，K_MEM_VM_FREE_START 与 K_MEM_KERNEL_VIRT_END 相同，即内核镜像的结束处。

  • K_MEM_VM_RESERVED 是为支持内核功能而保留的区域。例如，有些地址被保留用于支持按需分页。

虚拟内存映射

启动时建立映射

一般来说，大多数受支持的架构在启动时按如下方式建立内存映射：

  • .text 段为只读、可执行，在内核模式和用户模式下均可访问。

  • .rodata 段为只读、不可执行，在内核模式和用户模式下均可访问。

  • 其他内核段（例如 .data、.bss 和 .noinit）为可读写、不可执行，只能在内核模式下访问。

    • 在创建线程时，用户模式线程的栈会自动授予对应用户模式线程读写权限。

    • 默认情况下，用户模式线程无法访问全局变量。关于如何在用户模式线程中使用全局变量以及如何在用户模式线程之间共享数据，请参阅 内存域和分区。

这些映射的缓存模式与架构相关，可以是不缓存、回写或写直通。

注意，SoC 还有其自身启动所需的额外映射，这些映射在各自的 SoC 配置中定义，通常包括设置硬件所需的设备 MMIO 区域。

映射匿名内存

未使用的物理内存可以按需映射到虚拟地址空间中。这在概念上类似于从堆中分配内存，但这些映射必须按页大小对齐，并且具有更精细的访问控制。

  • k_mem_map() 可用于映射未使用的物理内存：

    • 所请求的大小必须是页大小的整数倍。

    • 返回的地址位于虚拟地址空间中 K_MEM_VM_FREE_START 与 K_MEM_VIRT_RAM_END 之间。

    • 不保证映射区域在内存中物理连续。

    • 会在映射的虚拟区域前后自动分配保护页，以捕获由缓冲区下溢或上溢引起的访问问题。

  • 可以通过 k_mem_unmap() 取消映射（即释放）映射区域：

    • 必须注意向 k_mem_map() 和 k_mem_unmap() 传入相同的区域大小。取消映射函数在取消映射之前不会检查它是否是有效的已映射区域。
