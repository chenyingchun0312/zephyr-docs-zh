其他交叉编译器

这一工具链变体借鉴了 Linux 内核构建系统的机制，即使用 CROSS_COMPILE 环境变量来设置基于 GNU 的交叉工具链。

这类“其他交叉编译器”的例子包括：你的 Linux 发行版打包的交叉工具链、你自己编译的交叉工具链，或从网上下载的交叉工具链。与 工具链 中明确列出的工具链不同，Zephyr 构建系统可能未使用它们测试过，也不提供官方支持。（不过，工具链设置机制本身是受支持的。）

按照以下步骤使用这类工具链。

  1. 安装适合你的主机和目标系统的交叉编译器。

    例如，在基于 Debian 的 Linux 系统上可以安装 gcc-arm-none-eabi 软件包，在 Fedora 或 Red Hat 上可以安装 arm-none-eabi-newlib：

    # On Debian or Ubuntu
sudo apt-get install gcc-arm-none-eabi
# On Fedora or Red Hat
sudo dnf install arm-none-eabi-newlib

  2. 设置以下环境变量：

    • 将 ZEPHYR_TOOLCHAIN_VARIANT 设置为 cross-compile。

    • 将 CROSS_COMPILE 设置为工具链二进制文件共有的路径前缀，例如包含编译器二进制文件的目录路径，再加上目标三元组和末尾的短横线。

  3. 要检查当前环境中这些变量是否设置正确，请参照以下 shell 会话示例（你系统上的 CROSS_COMPILE 值可能不同）：

    # Linux, macOS:
$ echo $ZEPHYR_TOOLCHAIN_VARIANT
cross-compile
$ echo $CROSS_COMPILE
/usr/bin/arm-none-eabi-

    也可以将 CROSS_COMPILE 设置为 CMake 变量。

使用此选项时，所有工具链二进制文件必须位于同一目录中，并具有共同的文件名前缀。CROSS_COMPILE 变量的值是该目录与文件名前缀拼接而成的。在上面的 Debian 示例中，gcc-arm-none-eabi 软件包会将 arm-none-eabi-gcc 和 arm-none-eabi-ld 等二进制文件安装到 /usr/bin/ 目录，因此共同前缀为 /usr/bin/arm-none-eabi-（包括末尾的短横线 -）。如果你的工具链安装在 /opt/mytoolchain/bin，且二进制文件名基于目标三元组 myarch-none-elf，则 CROSS_COMPILE 应设置为 /opt/mytoolchain/bin/myarch-none-elf-。
