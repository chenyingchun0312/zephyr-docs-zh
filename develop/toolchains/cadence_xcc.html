Cadence Tensilica Xtensa C/C++ 编译器（XCC）

  1. 获取面向目标 SoC 的 Tensilica 软件开发工具包。它通常包含两部分：

    • Xtensa Xplorer，其中包含所需的可执行文件和库。

    • 一个特定于 SoC 的附加组件，需安装在 Xtensa Xplorer 之上。

      • 该附加组件使编译器能够为目标 SoC 生成代码。

  2. 先安装 Xtensa Xplorer，然后安装 SoC 附加组件。

    • 按照 Cadence 提供的说明安装 SDK。

    • 根据 SDK 的不同，有两套编译器：

      • 基于 GCC 的编译器：xt-xcc 及其配套工具。

      • 基于 Clang 的编译器：xt-clang 及其配套工具。

  3. 确保你已获得使用该 SDK 的许可证，或可以访问远程许可证服务器。

  4. 设置以下环境变量：

    • 将 ZEPHYR_TOOLCHAIN_VARIANT 设置为 xcc 或 xt-clang。

    • 将 XTENSA_TOOLCHAIN_PATH 设置为工具链的安装目录。

    • 有两种方式指定要使用的 SoC ID 和 SDK 版本。两者互斥，不能同时使用。

      1. 为单个 SoC 构建时：

        • 将 XTENSA_CORE 设置为应用程序所面向的 SoC ID。

        • 将 TOOLCHAIN_VER 设置为 Xtensa SDK 版本。

      2. 为多个 SoC 构建时，针对每个 SoC 与开发板的组合：

        • 将 XTENSA_CORE_{normalized_board_target} 设置为应用程序所面向的 SoC ID。

        • 将 TOOLCHAIN_VAR_{normalized_board_target} 设置为 Xtensa SDK 版本。

  5. 例如，假设 SDK 安装在 /opt/xtensa，并使用该 SDK 在 intel_adsp/ace15_mtpm 上开发应用程序，可以用上述两种方式设置环境：

    1. 单个 SoC：

      # Linux
export ZEPHYR_TOOLCHAIN_VARIANT=xt-clang
export XTENSA_TOOLCHAIN_PATH=/opt/xtensa/XtDevTools/install/tools/
export XTENSA_CORE=ace10_LX7HiFi4_2022_10
export TOOLCHAIN_VER=RI-2022.10-linux

    2. 多个 SoC：

      # Linux
export ZEPHYR_TOOLCHAIN_VARIANT=xt-clang
export XTENSA_TOOLCHAIN_PATH=/opt/xtensa/XtDevTools/install/tools/
export TOOLCHAIN_VER_intel_adsp_ace15_mtpm=RI-2022.10-linux
export XTENSA_CORE_intel_adsp_ace15_mtpm=ace10_LX7HiFi4_2022_10

  6. 要使用基于 Clang 的编译器：

    • 将 ZEPHYR_TOOLCHAIN_VARIANT 设置为 xt-clang。

    • 注意，基于 Clang 的编译器可能包含一个旧的 LLVM 缺陷，会导致以下错误：

      /tmp/file.s: Assembler messages:
/tmp/file.s:20: Error: file number 1 already allocated
clang-3.9: error: Xtensa-as command failed with exit code 1

      如果出现这种情况，请将 XCC_NO_G_FLAG 设置为 1。

      • 例如：

        # Linux
export XCC_NO_G_FLAG=1
