内置命令

本页更详细地介绍 west 的内置命令，其中一些已在 基础知识 中介绍过。

有些命令与同名的 Git 命令相关，但作用于整个工作区。例如，west diff 会显示工作区中多个 Git 仓库的本地更改。

有些命令以项目作为参数。这些参数可以是清单文件中指定的项目名称，或者（作为后备）它们在本地文件系统中的路径。对于接受项目参数的命令（例如 west list、west forall 等），省略项目参数时，通常默认使用清单文件中的所有项目以及清单仓库本身。

如需更多帮助，请运行 west <command> -h （例如 west init -h）。

west init

此命令创建一个 west 工作区。它有两种用法：

  1. 从远程 URL 克隆一个新的清单仓库

  2. 围绕一个已有的本地清单仓库创建工作区

方式 1：要从远程 URL 克隆一个新的清单仓库，请使用：

west init [-m URL] [--mr REVISION] [--mf FILE] [directory]

新工作区创建在给定的 directory 中，并在该目录内创建一个新的 .west。可以使用 -m 开关指定清单 URL，使用 --mr 指定要检出的初始修订版本，使用 --mf 指定清单文件在仓库中的位置。

例如，运行：

west init -m https://github.com/zephyrproject-rtos/zephyr --mr v1.14.0 zp

会将上游官方 zephyr 仓库克隆到 zp/zephyr 中，并检出 v1.14.0 版本。此命令会创建 zp/.west，并将 manifest.path 配置选项 设置为 zephyr，以记录清单仓库在工作区中的位置。清单文件使用默认位置。

-m 选项的默认值为 https://github.com/zephyrproject-rtos/zephyr。--mf 选项的默认值为 west.yml。从 west v0.10.1 起，除非使用 --mr 选项覆盖，否则 west 将使用清单仓库的默认分支。（在之前的版本中，--mr 默认为 master。）

如果没有给出 directory，则使用当前工作目录。

方式 2：要围绕一个已有的本地清单仓库创建工作区，请使用：

west init -l [--mf FILE] directory

这会在文件系统中 directory 的 旁边 创建 .west，并将 manifest.path 设置为 directory。

与上面一样，--mf 默认为 west.yml。

重新配置工作区：

如果之后改变了主意，可以在运行 west init 后使用 west config 随意更改 manifest.path 和 manifest.file。只是之后一定要运行 west update，使工作区与新的清单文件相匹配。

west update

west update [-f {always,smart}] [-k] [-r]
            [--group-filter FILTER] [--stats] [PROJECT ...]

会更新哪些项目：

默认情况下，此命令会解析清单文件（通常是 west.yml），并更新其中指定的每个项目。如果清单使用了 项目组，则只更新活动项目。

如果只想对部分项目进行操作，请给出 PROJECT 参数。每个 PROJECT 可以是清单文件中给出的项目名称，也可以是指向工作区中该项目的路径。如果显式指定了项目，则无论它们是否处于活动状态都会被更新。

项目更新过程：

对于每个要更新的项目，此命令会：

  1. 如果工作区中还没有该项目的本地 Git 仓库，则初始化一个

  2. 检查清单中该项目的 revision 字段，如果本地尚无该修订版本，则从远程获取

  3. 将该项目的 manifest-rev 分支设置为上一步中修订版本所指定的提交

  4. 在本地工作副本中以 分离 HEAD（detached HEAD） 的方式检出 manifest-rev （关于这一选择的详细信息，请参阅 west update 的分离 HEAD）

  5. 如果清单文件为该项目指定了 submodules 键，则按下文所述递归更新该项目的子模块。

为避免不必要的获取，如果项目的 revision 值是本地已有的 Git SHA 或标签，west update 不会去获取它们。这是 -f （--fetch）选项取默认值 smart 时的行为。要强制此命令从项目的远程仓库获取（即使修订版本看起来在本地已经存在），可以使用 -f always，或者将 update.fetch 配置选项 设置为 always。只要 Git 能够接受，SHA 可以以唯一前缀的形式给出 [1]。

如果项目的 revision 是一个既不是标签也不是 SHA 的 Git 引用（即项目跟踪的是一个分支），那么无论 -f 和 update.fetch 如何设置，west update 都会执行获取。

有些分支名称可能看起来像短 SHA，例如 deadbeef。West 会把它们当作 SHA 处理。可以在 revision 值前加上 refs/heads/ 前缀来消除歧义，例如 revision: refs/heads/deadbeef。

出于安全考虑，west update 使用 git checkout --detach 在每个被更新项目的清单修订版本上检出一个分离的 HEAD，原先已检出的分支则保持不动。这通常是一个安全的操作，不会修改你的任何本地分支。

但是，如果你在 west 之前检出的分离 HEAD 上添加了一些本地提交，git 会警告你遗留了一些不再被任何分支引用的提交。这些提交将来某个时候可能会被垃圾回收而丢失。如果项目中有本地提交，为避免这种情况，请确保在运行 west update 之前检出一个本地分支。

如果你更希望对本地已检出的分支执行变基（rebase），请使用 -r （--rebase）选项。

如果希望 west update 在本地分支指向的提交是新 manifest-rev 的后代时保持这些分支的检出状态，请使用 -k （--keep-descendants）选项。

备注

如果你的分支与清单带来的新提交之间存在 git 冲突，west update --rebase 会在这些项目中失败。你应当像平时使用 git 那样立即解决这些冲突，或者使用 git -C <project_path> rebase --abort 暂时忽略传入的更改。

在干净的工作树中，普通的 west update 永远不会失败，因为它不会试图保留你的提交，而只是把它们放在一边。

west update --keep-descendants 提供了一个折中选项，它同样永远不会失败，但不会对所有项目一视同仁：

  • 在你的分支与传入提交出现分叉的项目中，它甚至不会尝试变基，而是像普通的 west update 一样把你的分支留在原处；

  • 在其他所有不需要变基或合并的项目中，它会保持你的分支不变。

一次性调整项目组：

--group-filter 选项可用于在单条 west update 命令执行期间更改启用或禁用哪些项目组。有关项目组功能的详细信息，请参阅 项目组。

west update 命令的行为就如同把 --group-filter 选项的值追加到了 manifest.group-filter 配置选项 之后。

例如，运行 west update --group-filter=+foo,-bar 的效果，等同于临时把字符串 "+foo,-bar" 追加到 manifest.group-filter 的值之后，运行 west update，然后再把 manifest.group-filter 恢复为原值。

注意，如果只想禁用单个组，例如 --group-filter=-bar，使用 --group-filter=VALUE 语法而不是 --group-filter VALUE，可以避免命令行选项解析问题。

子模块更新过程：

如果清单中的某个项目带有 submodules 键，则根据 submodules 键的值，按如下方式更新子模块。

如果项目设置了 submodules: true，west 首先使用以下命令同步该项目的子模块：

git submodule sync --recursive

然后，根据运行 west update 时是否带有 --rebase 选项，west 会在项目仓库中运行以下命令之一：

# without --rebase, e.g. "west update":
git submodule update --init --checkout --recursive

# with --rebase, e.g. "west update --rebase":
git submodule update --init --rebase --recursive

否则，项目设置的是 submodules: <list-of-submodules>。在这种情况下，west 使用以下命令同步该项目的子模块：

git submodule sync --recursive -- <submodule-path>

然后，根据运行 west update 时是否带有 --rebase 选项，按如下方式更新列表中的每个子模块：

# without --rebase, e.g. "west update":
git submodule update --init --checkout --recursive <submodule-path>

# with --rebase, e.g. "west update --rebase":
git submodule update --init --rebase --recursive <submodule-path>

如果 配置 选项 update.sync-submodules 为 false，则跳过 git submodule sync 命令。

其他项目命令

West 还有一些用于管理工作区中项目的命令，在此做简要说明。运行 west <command> -h 可获得详细帮助。

  • west compare：将工作区的状态与清单进行比较

  • west diff：在本地项目仓库中运行 git diff

  • west forall：在本地项目仓库中运行任意命令

  • west grep：在本地项目仓库中搜索模式

  • west list：根据格式字符串，为清单中的每个项目打印一行信息

  • west manifest：管理清单文件。请参阅 清单命令。

  • west status：在本地项目仓库中运行 git status

其他内置命令

最后，下面是其他内置命令的简要说明。

  • west config：获取或设置 配置选项

  • west topdir：打印 west 工作区的顶层目录

  • west help：获取某个命令的帮助，或打印工作区中所有命令（包括 扩展）的信息

脚注

[1]

当以 SHA 作为修订版本时，west 可能会从 Git 服务器获取所有引用。这是因为一些 Git 服务器过去不允许直接获取 SHA。
