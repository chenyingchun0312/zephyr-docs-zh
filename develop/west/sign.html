签名二进制文件

west sign 扩展 命令可以借助外部工具对 Zephyr 应用程序二进制文件进行签名，以供引导加载程序使用。在某些配置中，west sign 还用于调用一个外部后处理工具，将镜像的最终各组成部分“拼接”在一起。运行 west sign -h 可获取命令行帮助。

rimage

rimage 的配置方式不依赖 Kconfig 或 CMake，而是依赖 west config，与 永久 CMake 参数 类似。

签名涉及多个层层叠加的“包装”脚本：west flash 调用 west build，后者调用 cmake 和 ninja，它们再调用 west sign，最后由它调用 imgtool 或 rimage。只要所需的签名参数是默认参数且相当固定，这些间接调用就不成问题。但另一方面，当这些层次并没有抽象出任何东西时，把 imgtool 或 rimage 的选项穿过所有这些层传递下去，就会引发典型的问题。首先，这通常需要在每一层编写样板代码。要让空白或其他特殊字符的引号转义穿过所有包装层可能很困难。为了调试某个构建期问题而复现底层的 west sign 命令可能非常耗时：至少需要启用并搜索详细构建日志，才能找出到底使用了哪些选项。从构建日志中复制这些选项也不一定可靠：由于环境的细微差异，可能产生不同的结果。最后也是最糟糕的一点：在每一层都添加更多样板代码之前，新的签名功能和选项根本无法使用。

为避免这些问题，可以在 west config 中设置 rimage 参数。下面是一个 workspace/.west/config 示例：

[sign]
# Not needed when invoked from CMake
tool = rimage

[rimage]
# Quoting is optional and works like in Unix shells
# Not needed when rimage can be found in the default PATH
path = "/home/me/zworkspace/build-rimage/rimage"

# Not needed when using the default development key
extra-args = -i 4 -k 'keys/key argument with space.pem'

为了支持引号，这些值会像 一次性 CMake 参数 中那样由 Python 的 shlex.split() 解析。

extra-args 会直接传递给 rimage 命令。上面的示例与像这样在命令行的 -- 之后追加这些参数的效果相同：west sign --tool rimage -- -i 4 -k 'keys/key argument with space.pem'。如果两者同时使用，命令行参数排在最后。

silabs_commander

silabs_commander 工具用于对 Silicon Labs 设备的二进制文件进行签名、添加 MIC 或加密。当 sign.tool 配置设置为 silabs_commander 时，可以由 west sign 调用它；当设置了 CONFIG_SIWX91X_SIGN_KEY 或 CONFIG_SIWX91X_MIC_KEY 时，也可以由 west build 调用它。

如果设置了 CONFIG_SIWX91X_SIGN_KEY 或 CONFIG_SIWX91X_MIC_KEY 之一，west flash 会自动烧录二进制文件的签名版本。

silabs_commander 要求主机上安装 Simplicity Commander。在设备上配置（provisioning）密钥的方法请参阅 UG574 SiWx917 SoC Manufacturing Utility User Guide。
