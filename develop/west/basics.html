基础知识

本页介绍 west 的基本概念，并提供进一步阅读的参考资料。

West 的内置命令可以让你在一个公共的 工作区 目录下处理多个 项目 （Git 仓库）。

West 的工作方式如下：west init 命令创建 west workspace，并克隆 清单仓库；而 west update 命令首次会克隆工作区中清单所列出的 项目，之后则负责更新它们。

工作区示例

如果你已按照 入门指南 操作，你的本地 west workspace （在本例中是名为 zephyrproject 的文件夹及其所有子文件夹）如下所示：

zephyrproject/                 # west topdir
├── .west/                     # marks the location of the topdir
│   └── config                 # per-workspace local configuration file
│
│   # The manifest repository, never modified by west after creation:
├── zephyr/                    # .git/ repo
│   ├── west.yml               # manifest file
│   └── [... other files ...]
│
│   # Projects managed by west:
├── modules/
│   └── lib/
│       └── zcbor/             # .git/ project
├── tools/
│   └── net-tools/             # .git/ project
└── [ ... other projects ...]

工作区概念

以下是关于此结构你应当了解的基本概念。更多细节请参阅 工作区。

topdir

上例中，zephyrproject 是工作区顶层目录（即 topdir）的名称。（名称 zephyrproject 只是一个示例，它可以是任何名称，例如 z、my-zephyr-workspace 等。）

通常你会使用 west init 创建 topdir 以及其他一些文件和目录。

.west 目录

topdir 中包含 .west 目录。当 west 需要查找 topdir 时，它会搜索 .west，并使用其父目录。搜索从当前工作目录开始（如果失败，则作为后备，再从 ZEPHYR_BASE 环境变量所指的位置重新开始搜索）。

配置文件

文件 .west/config 是工作区的 本地配置文件。

清单仓库

每个 west 工作区都恰好包含一个 清单仓库，它是一个包含 清单文件 的 Git 仓库。清单仓库的位置由本地配置文件中的 manifest.path 配置选项 指定。

对于上游 Zephyr，zephyr 就是清单仓库，但你可以将 west 配置为使用工作区中的任何 Git 仓库作为清单仓库。唯一的要求是它包含一个有效的清单文件。其他选项的信息请参阅 支持的拓扑结构，清单文件格式的详细信息请参阅 West 清单。

清单文件

清单文件是一个 YAML 文件，用于定义 项目，即工作区中由 west 管理的其他 Git 仓库。清单文件默认名为 west.yml；可以使用本地配置选项 manifest.file 覆盖该名称。

使用 west update 命令，可以根据清单文件的内容更新工作区中的项目。

项目

项目是由 west 管理的 Git 仓库。项目在清单文件中定义，可以位于工作区内的任何位置。在上面的工作区示例中，zcbor 和 net-tools 都是项目。

默认情况下，Zephyr 构建系统 使用 west 获取工作区中所有项目的位置，因此项目中包含的任何代码都可以作为 模块（外部项目） 使用。但请注意，模块和项目 在概念上是不同的。

扩展

west 已知的任何仓库（清单仓库或任何项目仓库）都可以定义 扩展。扩展是使用该工作区时可以运行的额外 west 命令。

zephyr 仓库利用这一特性提供 west build 等 Zephyr 专用命令。将这些命令定义为扩展，可以使 west 的核心不依赖于任何工作区的 Zephyr 版本等具体细节。

被忽略的文件

工作区中可以包含不由 west 管理的其他 Git 仓库或其他文件和目录。除了 .west、清单仓库以及清单文件中指定的项目之外，west 基本上会忽略工作区中的其他所有内容。

west init 和 west update

与工作区相关的两个最重要的命令是 west init 和 west update。

west init 基础

此命令创建一个 west 工作区。

重要

运行 west init 之后，west 不会再更改清单仓库的内容。请使用普通的 Git 命令拉取新版本等。

通常只需运行一次，例如：

west init -m https://github.com/zephyrproject-rtos/zephyr --mr v2.5.0 zephyrproject

这将：

  1. 创建 topdir zephyrproject，并在其中创建 .west 和 .west/config

  2. 从 https://github.com/zephyrproject-rtos/zephyr 克隆清单仓库，并将其放到 zephyrproject/zephyr 中

  3. 在本地 zephyr 克隆中检出 git 标签 v2.5.0

  4. 在 .west/config 中将 manifest.path 设置为 zephyr

  5. 将 manifest.file 设置为 west.yml

现在你的工作区几乎可以使用了；只需再运行 west update，将其余项目克隆到工作区中即可完成。

更多细节请参阅 west init。

west update 基础

此命令确保你的工作区中包含与清单文件中的项目相匹配的 Git 仓库。

重要

每当你在清单仓库中检出不同的修订版本时，都应运行 west update，以确保工作区中包含新修订版本所需的项目仓库。

west update 命令通过以下步骤读取清单文件的内容：

  1. 查找 topdir。在上面的 west init 示例中，即找到 zephyrproject。

  2. 加载 topdir 中的 .west/config，读取 manifest.path （例如 zephyr）和 manifest.file （例如 west.yml）选项。

  3. 加载这些选项所指定的清单文件（例如 zephyrproject/zephyr/west.yml）。

然后，它根据清单文件决定缺失的项目应放在工作区中的什么位置、从哪些 URL 克隆，以及在本地检出哪些 Git 修订版本。对于已存在的项目仓库，则就地更新：获取并检出清单文件中各自指定的 Git 修订版本。

更多细节请参阅 west update。
