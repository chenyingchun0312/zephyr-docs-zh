west.commands

所有内置命令和扩展命令都实现为此处定义的 WestCommand 类的子类。此外还提供了一些异常类型。

WestCommand

class west.commands.WestCommand(name: str, help: str, description: str, accepts_unknown_args: bool = False, requires_workspace: bool = True, verbosity: Verbosity = Verbosity.INF)

west 命令的抽象超类。

实例属性：

name

即传递给构造函数的值。

help

即传递给构造函数的值。内置命令需要它，扩展会忽略它，请参阅 https://github.com/zephyrproject-rtos/west/issues/927

description

即传递给构造函数的值。

accepts_unknown_args

即传递给构造函数的值。

requires_workspace

即传递给构造函数的值。

在 0.7.0 版本加入.

parser

通过调用 WestCommand.add_parser() 创建的参数解析器。

实例特性（property）：

manifest

一个特性，返回当前清单文件对应的 west.manifest.Manifest 实例；如果未提供，则中止程序。只有在 do_run() 方法中使用才是安全的。

在 0.6.1 版本加入.

在 0.7.0 版本发生变更: 现在可以设置。

has_manifest

如果读取 manifest 特性会成功而不是报错，则为 True。

config

一个可设置的特性，返回 west.configuration.Configuration 实例；如果未提供，则中止程序。只有在 do_run() 方法中使用才是安全的。

在 0.13.0 版本加入.

has_config

如果读取 config 特性会成功而不是报错，则为 True。

在 0.13.0 版本加入.

git_version_info

Git 版本信息的元组。

在 0.11.0 版本加入.

color_ui

如果 west 配置允许彩色输出，则为 True，否则为 False。

在 1.0.0 版本加入.

构造函数：

__init__(name: str, help: str, description: str, accepts_unknown_args: bool = False, requires_workspace: bool = True, verbosity: Verbosity = Verbosity.INF)

west 命令的抽象超类。

某些字段（例如 name、help 和 description）与应传递给 WestCommand.add_parser 所添加的 argparse.ArgumentParser 的关键字参数重叠。这种不够优雅之处是有意为之：argparse 没有提供多少 API 稳定性保证，因此为了面向未来，这些信息必须在这里重复一份。

参数:

  • name -- 命令的名称，即用户输入的名称

  • help -- 单行命令帮助文本

  • description -- 多行命令描述

  • accepts_unknown_args -- 如果为 true，则命令可以在 WestCommand.run 中处理任意未知的命令行参数。否则，传递未知参数属于致命错误。

  • requires_workspace -- 如果为 true，则命令需要在 west 工作区中运行，在工作区之外运行属于致命错误。

  • verbosity -- 命令输出详细级别；之后可以更改

在 0.6.0 版本加入: requires_installation 参数（已在 v0.13.0 中移除）。

在 0.7.0 版本加入: requires_workspace 参数。

在 0.8.0 版本发生变更: topdir 参数现在可以是任何 os.PathLike。

在 0.13.0 版本发生变更: 移除了已弃用的 requires_installation 参数。

在 1.0.0 版本加入: verbosity 参数。

方法：

run(args: Namespace, unknown: list[str], topdir: str | PathLike, manifest: Manifest | None = None, config: Configuration | None = None) → None

运行该命令。

如果由于上下文不匹配而无法运行该命令，则引发 west.commands.CommandContextError。也可能引发其他异常。

参数:

  • args -- 通过 WestCommand.add_parser 解析出的已知参数

  • unknown -- 命令行中出现的未知参数；除非 accepts_unknown_args 为 true，否则必须为空

  • topdir -- west 工作区 topdir，在 WestCommand.do_run 中可以通过 self.topdir 以 str 形式访问

  • manifest -- west.manifest.Manifest 或 None，在 WestCommand.do_run 中可以通过 self.manifest 访问

  • config -- west.configuration.Configuration 或 None，在 WestCommand.do_run 中可以通过 self.config 访问

在 0.6.0 版本发生变更: 添加了 topdir 参数。

add_parser(parser_adder) → ArgumentParser

为此命令注册一个解析器并返回它。

解析器对象存储在 parser 属性中。

参数:

parser_adder -- 调用 argparse.ArgumentParser.add_subparsers() 的返回值

add_pre_run_hook(hook: Callable[[WestCommand], None]) → None

添加一个钩子，它将在 do_run() 之前被调用。

这可用于推迟那些需要完全设置好的命令才能进行的工作。

参数:

hook -- 要添加的钩子

在 1.0.0 版本加入.

check_call(args, **kwargs)

以 Verbosity.DBG_MORE 级别记录调用之后，运行 subprocess.check_call(args, **kwargs)。

在 1.2.0 版本发生变更: cwd 关键字参数被替换为通用的 **kwargs。

在 0.11.0 版本发生变更.

check_output(args, **kwargs)

以 Verbosity.DBG_MORE 级别记录调用之后，运行 subprocess.check_output(args, **kwargs)。

在 1.2.0 版本发生变更: cwd 关键字参数被替换为通用的 **kwargs。

在 0.11.0 版本发生变更.

run_subprocess(args, **kwargs)

以 Verbosity.DBG_MORE 级别记录调用之后，运行 subprocess.run(args, **kwargs)。

在 1.2.0 版本加入.

所有子类都必须提供以下抽象方法，它们用于实现上述功能：

abstractmethod do_add_parser(parser_adder) → ArgumentParser

用于注册命令行参数的子类方法。

WestCommand.add_parser 会调用此方法来注册命令的选项和参数。

子类应调用 parser_adder.add_parser() 为该子命令添加一个 ArgumentParser，然后添加所需的参数。必须返回最终的解析器。

参数:

parser_adder -- 调用 argparse.ArgumentParser.add_subparsers() 的返回值

abstractmethod do_run(args: Namespace, unknown: list[str])

子类必须实现；调用它来运行命令。

参数:

  • args -- 已解析参数的 argparse.Namespace

  • unknown -- 如果 accepts_unknown_args 为 true，则为未解析参数字符串的序列。

当命令需要打印输出时，应使用以下方法。引入这些方法是为了从已弃用的 west.log 模块过渡到按命令划分的接口，以便在将来的版本中为 west 命令提供全局“安静”模式：

dbg(*args, level: Verbosity = Verbosity.DBG, end: str = '\n')

打印详细的调试消息。

只有当 self.verbosity 至少为 level 时才会打印消息。

参数:

  • args -- 要打印的参数序列

  • level -- 消息的详细级别

在 1.2.0 版本发生变更: end 参数。

在 1.0.0 版本加入.

inf(*args, colorize: bool = False, end: str = '\n')

打印一条信息性消息。

只有当 self.verbosity 至少为 INF 时才会打印消息。

参数:

  • args -- 要打印的参数序列。

  • colorize -- 如果此参数为 True，配置选项 color.ui 未定义或为 true，并且 stdout 是终端，则消息以绿色打印。

在 1.2.0 版本发生变更: end 参数。

在 1.0.0 版本加入.

wrn(*args, end: str = '\n')

打印一条警告。

只有当 self.verbosity 至少为 WRN 时才会打印消息。

消息以字符串 "WARNING: " 为前缀。

如果配置选项 color.ui 未定义或为 true，并且 stdout 是终端，则消息以黄色打印。

参数:

args -- 要打印的参数序列。

在 1.2.0 版本发生变更: end 参数。

在 1.0.0 版本加入.

err(*args, fatal: bool = False, end: str = '\n')

打印一条错误。

只有当 self.verbosity 至少为 ERR 时才会打印消息。

此函数不会中止程序。如需中止，请使用 die()。

如果配置选项 color.ui 未定义或为 true，并且 stdout 是终端，则消息以红色打印。

参数:

  • args -- 要打印的参数序列。

  • fatal -- 如果为 True，消息以“FATAL ERROR: ”为前缀；否则使用“ERROR: ”。

在 1.2.0 版本发生变更: end 参数。

在 1.0.0 版本加入.

die(*args, exit_code: int = 1) → NoReturn

使用 err() 打印一条致命错误，并中止程序。

参数:

  • args -- 要打印的参数序列。

  • exit_code -- 中止时程序应使用的返回码。

等价于 die(*args, fatal=True)，随后尝试以给定的 exit_code 中止。

在 1.0.0 版本加入.

banner(*args)

使用 inf() 将 args 打印为“横幅”。

args 默认以 '=== ' 为前缀并带颜色。

在 1.0.0 版本加入.

small_banner(*args)

将 args 打印为较小的 banner()，即以 '-- ' 为前缀且不带颜色。

在 1.0.0 版本加入.

详细程度（Verbosity）

从 west v1.0 起，west 命令应使用 west.commands.WestCommand.dbg()、west.commands.WestCommand.inf() 等方法（见上文）打印输出。本节介绍用于声明详细级别的相关枚举。

class west.commands.Verbosity(*values)

WestCommand 实例的详细级别。

QUIET = 0

调用 WestCommand.dbg()、.inf() 等时不打印任何输出。

ERR = 1

只打印错误消息。

WRN = 2

只打印错误和警告。

INF = 3

打印错误、警告和信息性消息。

DBG = 4

与 INFO 类似，但还会打印 WestCommand.dbg(..., level=Verbosity.DBG) 的输出。

DBG_MORE = 5

与 DEBUG 类似，但还会打印 WestCommand.dbg(..., level=Verbosity.DBG_MORE) 的输出。

DBG_EXTREME = 6

与 DEBUG_MORE 类似，但还会打印 WestCommand.dbg(..., level=Verbosity.DBG_EXTREME) 的输出。

在 1.0.0 版本加入.

west.configuration

West 配置文件处理。

West 在配置文件位置方面遵循类似 Git 的约定。配置文件有三种类型：系统范围的文件适用于当前计算机上的所有用户，全局文件适用于当前用户，本地文件适用于当前 west 工作区。

系统文件：

  • Linux：/etc/westconfig

  • macOS：/usr/local/etc/westconfig

  • Windows：%PROGRAMDATA%\west\config

全局文件：

  • Linux：~/.westconfig，或者（如果设置了 $XDG_CONFIG_HOME）$XDG_CONFIG_HOME/west/config

  • macOS：~/.westconfig

  • Windows：用户主目录（由 os.path.expanduser 确定）下的 .westconfig。

本地文件：

  • Linux、macOS、Windows：<workspace-topdir>/.west/config

可以使用 WEST_CONFIG_SYSTEM、WEST_CONFIG_GLOBAL 和 WEST_CONFIG_LOCAL 环境变量覆盖这些文件的位置。

后面的配置文件中的配置值会覆盖前面的配置。本地值的优先级最高，系统值的优先级最低。

从 west v0.13 起，推荐使用 west.configuration.Configuration 类读取配置。

注意，如果你在编写 west 扩展，可以通过 self.config 访问当前的 Configuration 对象。请参阅 west.commands.WestCommand。

配置 API

这是从 west v0.13 起推荐使用的 API。

class west.configuration.ConfigFile(*values)

west 配置文件的类型。

枚举成员：

  • SYSTEM：所有用户共享的系统级配置

  • GLOBAL：全局（用户范围）配置

  • LOCAL：按工作区的配置

  • ALL：上述三者全部（在适用的情况下）

class west.configuration.Configuration(topdir: str | PathLike | None = None)

表示可用的配置选项及其值。

允许获取、设置和删除系统、全局和本地文件中的配置选项。

设置值会立即影响文件，且不针对并发读取提供保护。调用者负责进行任何必要的互斥。

WEST_CONFIG_* 环境变量当且仅当创建 Configuration 对象时生效。这可用于让不同的对象指向不同的文件。

如果没有向构造函数传递 topdir 参数，且未定义 WEST_CONFIG_LOCAL，则该对象不指向任何本地文件。

在 0.13.0 版本加入.

delete(option: str, configfile: ConfigFile | None = None) → None

从给定的一个或多个文件中删除某个选项。

如果给定的 configfile 中未设置 option，则引发 KeyError。

参数:

  • option -- 要删除的选项，形式为 'foo.bar'

  • configfile -- 如果为 ConfigFile.ALL，则在设置了 option 的所有文件中删除它。如果为 None，则只在设置了 option 的优先级最高的文件中删除它。否则，从给定的 ConfigFile 中删除。

get(option: str, default: str | None = None, configfile: ConfigFile = ConfigFile.ALL) → str | None

以字符串形式获取配置选项的值。

参数:

  • option -- 要获取的选项，形式为 'foo.bar'

  • default -- 选项缺失时返回的默认值

  • configfile -- 在哪种类型的配置文件中查找该值

getboolean(option: str, default: bool = False, configfile: ConfigFile = ConfigFile.ALL) → bool

以布尔值形式获取配置选项的值。

对找到的任何值都会应用 configparser 模块的布尔值转换。无效值会引发 ValueError。

参数:

  • option -- 要获取的选项，形式为 'foo.bar'

  • default -- 选项缺失时返回的默认值

  • configfile -- 在哪种类型的配置文件中查找该值

getfloat(option: str, default: float | None = None, configfile: ConfigFile = ConfigFile.ALL) → float | None

以浮点数形式获取配置选项的值。

参数:

  • option -- 要获取的选项，形式为 'foo.bar'

  • default -- 选项缺失时返回的默认值

  • configfile -- 在哪种类型的配置文件中查找该值

getint(option: str, default: int | None = None, configfile: ConfigFile = ConfigFile.ALL) → int | None

以整数形式获取配置选项的值。

参数:

  • option -- 要获取的选项，形式为 'foo.bar'

  • default -- 选项缺失时返回的默认值

  • configfile -- 在哪种类型的配置文件中查找该值

items(configfile: ConfigFile = ConfigFile.ALL) → Iterable[tuple[str, Any]]

（选项，值）对的迭代器。

set(option: str, value: Any, configfile: ConfigFile = ConfigFile.LOCAL) → None

设置配置选项的值。

对配置文件的写入会立即生效。从创建此 Configuration 对象开始，不会针对并发访问执行任何并发保护。如果该文件在此期间可能已被修改，请在使用此方法之前创建一个新的 Configuration 对象，否则这期间的修改将会丢失。

参数:

  • option -- 要设置的选项，形式为 'foo.bar'

  • value -- 要为选项设置的值

  • configfile -- 在哪种类型的配置文件中设置该值

已弃用的 API

以下 API 同样使用 west.configuration.ConfigFile，但默认对一个存储当前工作区配置的全局对象进行操作。事实证明这是一个糟糕的设计决策，因为 west 的 API 可能被多个工作区使用。它们已在 west v0.13.0 中弃用。

保留这些 API 是为了与较旧的扩展兼容。在可以假定使用 west v0.13.0 或更高版本的新代码中，不应使用它们。

west.configuration.read_config(configfile: ConfigFile | None = None, config: ConfigParser = <configparser.ConfigParser object>, topdir: str | PathLike | None = None) → None

将配置文件读入 config。

读取 configfile 所指定的文件，并将值存储到 configparser.ConfigParser 对象 config 中。如果未给出 config，则使用全局的 west.configuration.config 对象。

如果给出了 configfile，则只读取其值所指定的文件。如果未给出，则使用 ConfigFile.ALL。

如果 configfile 请求本地配置选项（即其值为 ConfigFile.LOCAL 或 ConfigFile.ALL）：

  • 如果给出了 topdir，则读取 topdir/.west/config

  • 接着，如果环境中设置了 WEST_CONFIG_LOCAL，则使用其内容（一个文件）。

  • 否则，在文件系统中搜索本地配置文件，如果找不到则忽略。

参数:

  • configfile -- 一个 west.configuration.ConfigFile

  • config -- 要读入的配置对象

  • topdir -- 从中读取本地选项的 west 工作区根目录

在 0.8.0 版本发生变更: 移除了已弃用的 read_config 参数。

在 0.6.0 版本发生变更: 因找不到本地配置文件而导致的错误会被忽略。

west.configuration.update_config(section: str, key: str, value: Any, configfile: ConfigFile = ConfigFile.LOCAL, topdir: str | PathLike | None = None) → None

在给定的配置文件中将 section.key 设置为 value。

参数:

  • section -- 配置节；如果不存在则会被创建

  • key -- 要在给定节中设置的键

  • value -- 要为该键设置的值

  • configfile -- west.configuration.ConfigFile，不能为 ALL

  • topdir -- 要写入本地配置选项的 west 工作区根目录

要写入的目标文件由 configfile 给出。默认值（ConfigFile.LOCAL）会写入按以下方式确定的本地配置文件：

  • 如果给出了 topdir，则为 topdir/.west/config；否则

  • 如果环境中设置了 'WEST_CONFIG_LOCAL'，则为其值；否则

  • 通过搜索文件系统找到的 west 工作区中的本地配置文件（如果找不到，则引发 WestNotFound）。

west.configuration.config

当前配置对应的模块级全局 ConfigParser 实例。在读取之前，应使用 west.configuration.read_config() 对其进行初始化。

west.log（已弃用）

由于使用了全局状态，使 west 更难进行单元测试，该模块已被弃用。请参阅：

https://github.com/zephyrproject-rtos/west/issues/149

在 west v2.0 之前不会移除。

今后，命令应改用等价的 WestCommand 方法。例如，使用 WestCommand.dbg() 代替 west.log.dbg()，依此类推。

提供用于打印要向用户显示的消息的通用方法，这些方法遵循 color.ui 配置选项和详细级别。以前鼓励 WestCommand 实例使用这些方法。

详细程度控制

要设置全局详细级别，请使用 set_verbosity()。

west.log.set_verbosity(value)

设置日志详细级别。

参数:

value -- 要设置的详细级别，例如 VERBOSE_VERY。

定义了以下详细级别。

west.log.VERBOSE_NONE = 0

默认详细级别，不打印 dbg() 消息。

west.log.VERBOSE_NORMAL = 1

打印部分详细消息。

west.log.VERBOSE_VERY = 2

将打印非常详细的输出消息。

west.log.VERBOSE_EXTREME = 3

将打印极其详细的输出消息。

输出函数

主要函数有 dbg()、inf()、wrn()、err() 和 die()。此外还提供 inf() 的两种特殊形式 banner() 和 small_banner()，用于将输出分组为若干“节”。

west.log.dbg(*args, level=1)

打印一条详细的调试日志消息。

参数:

  • args -- 要打印的参数序列。

  • level -- 要设置的详细级别，例如 VERBOSE_VERY。

只有当 level 参数不大于当前详细级别时才会打印消息。

west.log.inf(*args, colorize=False)

打印一条信息性消息。

参数:

  • args -- 要打印的参数序列。

  • colorize -- 如果此参数为 True，配置选项 color.ui 未定义或为 true，并且 stdout 是终端，则消息以绿色打印。

west.log.wrn(*args)

打印一条警告。

参数:

args -- 要打印的参数序列。

消息以字符串 "WARNING: " 为前缀。

如果配置选项 color.ui 未定义或为 true，并且 stdout 是终端，则消息以黄色打印。

必须给出 topdir 和 source_data 关键字参数中的恰好一个：

  • 使用 topdir 从工作区加载清单

  • 使用 source_data 在没有任何工作区的情况下加载数据

如果给出了 topdir：

  • 如果已经加载了所需的工作区配置，可以传入 config。它用于根据 manifest.path 和 manifest.file 选项查找清单文件的位置。在这种情况下，你需要负责确保 config 是从 topdir 正确加载的。

    如果不传入 config，构造函数会自行实例化正确的 Configuration 对象。

  • 返回值中的绝对路径将相对于 topdir。如果 topdir 不是绝对路径，会先对其进行解析（这也会解析符号链接）。如果它是绝对路径，则不会被解析。

如果给出了 source_data：

  • 不能传入 config。

  • 除非传入 importer 或使用 import_flags 忽略清单导入，否则清单导入将会失败。

  • 结果中的所有绝对路径（例如 projects[i].abspath）都将为 None。

如果给出了 importer 关键字参数，它是一个可调用对象。当构造函数必须导入在本地文件系统中找不到的清单数据时，会将其用作回调。

importer 回调将以如下方式调用：

importer(project, file)

其中 project 是一个 west.manifest.Project，file 是缺失的清单文件。回调通常应返回该文件在 refs/heads/manifest-rev 处的内容，必要时可能需要先从项目的远程 URL 获取其修订版本并更新该引用。

importer 回调的返回值应为包含清单数据的字符串；如果 file 是包含 YAML 文件的目录，则应为字符串列表。返回 None 会使该导入被忽略。

引发的异常：

  • MalformedManifest：如果清单数据无效

  • ManifestImportFailed：如果导入失败

  • ManifestVersionError：如果此版本的 west 太旧，无法解析该清单（根据其模式版本判断）

  • OSError：或其子类，当无法打开文件时

  • ValueError：用于其他无效参数

参数:

  • source_data -- 以 Python 对象形式表示的已解析 YAML 数据，或包含未解析 YAML 数据的字符串

  • topdir -- west 工作区顶层目录

  • config -- 可选的、从 topdir 预先加载的配置

  • importer -- 提供缺失的清单导入数据

  • import_flags -- 位掩码，控制导入解析

  • internal_import_ctx -- 仅供内部使用；请勿使用

在 0.13.0 版本发生变更: 所有参数都改为仅限关键字参数。移除了 source_file 参数（请改用 topdir）。该函数不再引发 WestNotFound。

is_active(project: Project, extra_filter: Iterable[str] | None = None) → bool

项目是否处于活动状态？

如果设置了 manifest.project-filter 配置选项，则返回值由该选项的值决定：

  • manifest.project-filter 值的各个元素会与项目名称进行比对。如果元素中的正则表达式与项目名称匹配，则根据该元素以 + 还是 - 开头，项目分别为活动或非活动状态。

  • 如果多个元素的正则表达式都与项目名称匹配，则由最后一个匹配的元素决定结果。

  • 根据这些规则，如果项目为活动状态，此函数返回 True；如果为非活动状态，返回 False。

使用的是构造此 Manifest 对象时所设置的 manifest.project-filter 值。

否则，返回值取决于项目是否有任何组，以及如果有，这些组是否已启用：

  • 'project.groups' 列表为空的项目始终处于活动状态，对于此类项目，此函数返回 True。

  • 如果 'project.groups' 不为空，且其中有任何组被此清单的 'group-filter:' 列表（以及 'manifest.group-filter' 本地配置选项，如果存在工作区的话）启用，则返回 True。

  • 否则，即项目的所有组都被禁用时，返回 False。

在更新、列出、解析导入等操作中，“非活动”项目通常应被视为不存在于工作区中。

参数:

  • project -- 要检查的项目

  • extra_filter -- 可选的附加组过滤器

在 0.9.0 版本加入.

在 1.1.0 版本发生变更: 此方法遵循 manifest.project-filter 配置选项。请参阅 内置配置选项。

class west.manifest.ImportFlag(*values)

解析清单时用于处理导入的位标志。

注意，即使给出了 IGNORE 或 IGNORE_PROJECTS，“import:”中设置的任何“path-prefix:”值仍然对项目本身生效。例如，在以下清单中：

manifest:
  projects:
  - name: foo
    import:
      path-prefix: bar

无论是否给出 IGNORE 或 IGNORE_PROJECTS，项目 'foo' 的路径都是 'bar/foo'。这确保了该 Project 的 path 属性与不忽略被导入项目时通常所具有的值相同。

DEFAULT = 0

默认值 0 会读取文件系统来解析“self: import:”，并运行 git 来解析“projects:”中的导入。

IGNORE = 1

忽略通过“self:”和“projects:”中的“import:”添加的项目

FORCE_PROJECTS = 2

对于“projects:”中的导入，始终调用 importer 回调

IGNORE_PROJECTS = 4

仅忽略通过“projects:”中的“import:”添加的项目；通过“self:”中的“import:”添加的项目仍包括在内

class west.manifest.ManifestProject(path: str | PathLike | None = None, west_commands: str | list[str] | None = None, topdir: str | PathLike | None = None, userdata: Any | None = None)

将清单仓库表示为一个 Project。

有意义的属性：

  • name：字符串 "manifest"

  • topdir：该清单项目所控制的 west 工作区的顶层目录，或 None

  • path：清单仓库在工作区内的相对路径，或 None （即如果设置了 topdir，则相对于它）

  • abspath：清单仓库的绝对路径，采用本机路径名格式（如果 topdir 为空，则为 None）

  • posixpath：与 abspath 类似，但以斜杠（/）作为路径分隔符

  • west_commands：清单 self: 映射中的 west_commands: 键。如果 self 节导入了多个包含 west 命令的附加文件，这可能是此类值的列表。

  • userdata：清单文件中 self 下已解析的 'userdata' 字段

为了与 Project 兼容而包含的其他可读属性：

  • url：空字符串；west 清单本身不受 west 的版本控制，即使 'west init' 可以从 Git 远程仓库获取清单仓库

  • revision："HEAD"

  • clone_depth：None，因为没有 URL

  • groups：空列表

只支持 Project 方法的一个有限子集。调用其他方法的结果未作规定。

在 0.8.0 版本发生变更: url 属性现在是空字符串，而不是 None。abspath 属性改用 os.path.abspath() 而不是 os.path.realpath() 创建，从而改进了对符号链接的支持。
