扩展

West 是“可插拔”的：无需编辑其源代码，就可以向 west 添加自己的命令。这些命令称为 west 扩展命令，简称“扩展”。扩展会显示在 west --help 输出中定义它们的项目所对应的专门一节里。本页提供有关 west 扩展命令的一般信息，并包含一个编写自定义扩展的教程。

将 west 与 Zephyr 一起使用时可以运行的一些命令，例如用于 构建、烧录和调试 的命令以及 此处介绍的命令，都是扩展。这就是它们的帮助信息在 west --help 中如下显示的原因：

extension commands from project manifest (path: zephyr):
  completion:           display shell completion scripts
  boards:               display information about supported boards
  shields:              display list of supported shields
  build:                compile a Zephyr application
  twister:              west twister wrapper
  sign:                 sign a Zephyr binary for bootloader chain-loading
  flash:                flash and run a binary on a board
  debug:                flash and interactively debug a Zephyr application
  debugserver:          connect to board and launch a debug server
  attach:               interactively debug a board
  ...

实现细节请参阅 zephyr/scripts/west-commands.yml 和 zephyr/scripts/west_commands 目录。

禁用扩展命令

要禁用对扩展命令的支持，请将 commands.allow_extensions 配置 选项设置为 false。要使此设置对你每次运行 west 都全局生效，请使用：

west config --global commands.allow_extensions false

如果需要，之后可以在某个特定的 west workspace 中使用以下命令重新启用它们：

west config --local commands.allow_extensions true

注意，除非显式运行扩展命令，否则 west 不会导入包含这些命令的文件。详情见下文。

添加 West 扩展

添加自己的扩展分为三步：

  1. 编写实现该命令的代码。

  2. 将有关它的信息添加到 west-commands.yml 文件中。

  3. 确保 west manifest 引用了该 west-commands.yml 文件。

注意，west 会忽略与内置命令同名的扩展命令。

第 1 步：实现命令

创建一个 Python 文件来存放命令的实现（当前支持的 Python 版本请参阅 west PyPI page 上的 west 项目元数据）。你可以把它放在 west manifest 所跟踪的任何项目中的任何位置，或者放在清单仓库本身中。该文件必须包含 west.commands.WestCommand 类的一个子类。运行扩展时，会实例化并使用这个类。

下面是一个可以作为起点的基本框架。它包含 WestCommand 的一个子类，并实现了所有抽象方法。有关可用的 west API 的更多细节，请参阅 West 的 API。

'''my_west_extension.py

Basic example of a west extension.'''

from textwrap import dedent            # just for nicer code indentation

from west.commands import WestCommand  # your extension must subclass this

class MyCommand(WestCommand):

    def __init__(self):
        super().__init__(
            'my-command-name',  # gets stored as self.name
            '', # ignored self.help, will not be required by future west versions
            # self.description:
            description=dedent('''
            A multi-line description of my-command.

            You can split this up into multiple paragraphs and they'll get
            reflowed for you. You can also pass
            formatter_class=argparse.RawDescriptionHelpFormatter when calling
            parser_adder.add_parser() below if you want to keep your line
            endings.'''))

    def do_add_parser(self, parser_adder):
        # This is a bit of boilerplate, which allows you full control over the
        # type of argparse handling you want. The "parser_adder" argument is
        # the return value of an argparse.ArgumentParser.add_subparsers() call.
        parser = parser_adder.add_parser(self.name,
                                         description=self.description)

        # Add some example options using the standard argparse module API.
        parser.add_argument('-o', '--optional', help='an optional argument')
        parser.add_argument('required', help='a required argument')

        return parser           # gets stored as self.parser

    def do_run(self, args, unknown):
        # This gets called when the user runs the command, e.g.:
        #
        #   $ west my-command-name -o FOO BAR
        #   --optional is FOO
        #   required is BAR
        self.inf('--optional is', args.optional)
        self.inf('required is', args.required)

可以忽略 do_run() 的第二个参数（上例中的 unknown），因为 WestCommand 默认会拒绝未知参数。如果希望改为接收未知参数的列表，请在 super().__init__() 的参数中添加 accepts_unknown_args=True。

第 2 步：添加或更新 west-commands.yml

现在需要向项目添加一个 west-commands.yml 文件，用来向 west 描述你的扩展。

下面是对应上述类定义的示例，假设该类位于项目根目录下的 my_west_extension.py 中：

west-commands:
  - file: my_west_extension.py
    commands:
      - name: my-command-name
        class: MyCommand
        help: one-line help for what my-command-name does

该 YAML 文件的顶层是一个带有 west-commands 键的映射。该键的值是一个“命令描述符”序列。每个命令描述符给出实现 west 扩展的文件位置、这些扩展的名称，以及可选的定义它们的类名（如果未给出，class 值默认与 name 相同）。

此文件中的部分信息与 Python 代码中的定义是重复的。这是因为在用户运行 west my-command-name 之前，west 不会导入 my_west_extension.py，原因如下：

  • 这样用户可以使用来自不受信任来源的清单运行 west update，然后再使用其他 west 命令，而不会在此过程中导入你的代码。由于导入 Python 模块等同于执行 shell 命令，这样可以让人更放心。

  • 这是一个小优化，因为只有在需要时才会导入你的代码。

因此，除非显式运行你的命令，否则 west 只会加载 west-commands.yml 文件，以获取在 west --help 输出等处向用户显示扩展信息所需的基本信息。

如果有多个扩展，或者想把扩展拆分到多个文件中，west-commands.yml 大致如下所示：

west-commands:
  - file: my_west_extension.py
    commands:
      - name: my-command-name
        class: MyCommand
        help: one-line help for what my-command-name does
  - file: another_file.py
    commands:
      - name: command2
        help: another cool west extension
      - name: a-third-command
        class: ThirdCommand
        help: a third command in the same file as command2

上例中：

  • my_west_extension.py 定义了扩展 my-command-name，其类为 MyCommand

  • another_file.py 定义了两个扩展：

    1. command2，其类为 command2

    2. a-third-command，其类为 ThirdCommand

描述 west-commands.yml 内容的模式（schema），请参阅 west repository 中的 west-commands-schema.yml 文件。

第 3 步：更新清单

最后，需要在 west 清单中指定刚刚编辑的 west-commands.yml 的位置。如果扩展位于某个项目中，请这样添加：

manifest:
   # [... other contents ...]

   projects:
     - name: your-project
       west-commands: path/to/west-commands.yml
     # [... other projects ...]

其中 path/to/west-commands.yml 是相对于项目根目录的路径。注意，west-commands.yml 这个名称虽然是推荐的，但只是一种约定；如有需要，可以给文件取其他名称。

或者，如果扩展位于清单仓库中，只需在清单的 self 节中做同样的事情，例如：

manifest:
  # [... other contents ...]

  self:
    west-commands: path/to/west-commands.yml

这样就完成了；现在可以运行 west my-command-name。命令的名称、帮助信息以及包含其代码的项目现在也会显示在 west --help 输出中。如果与他人共享更新后的仓库，他们也能使用该命令。
