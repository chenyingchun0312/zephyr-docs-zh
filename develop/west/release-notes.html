West 发布说明

v1.5.0

主要变更：

  • 添加对自动缓存的支持。向 west update 传递 --auto-cache <directory> 参数即可。

其他变更：

  • 允许在 west update 中同时使用 --name-cache 和 --path-cache。

  • 在清单模式中记录默认修订版本值。

缺陷修复：

  • 允许清单中的项目列表为空或缺失。

  • 冻结或解析清单文件时，使 manifest.group-filter 列表的顺序具有确定性。

v1.4.0

变更：

  • 允许向配置字符串追加数据。要向 <name> 的值追加内容，请输入：west config -a <name> <value>。

  • 为 west manifest 添加 --untracked 参数选项。在工作区中运行 west manifest --untracked，可以打印所有不被 west 跟踪或管理的文件和目录。

  • 为 west list 添加 --inactive 参数选项，以支持打印非活动项目。

  • west manifest --resolve 和 west manifest --freeze 命令支持 --active-only 参数选项。这样就可以冻结使用了活动项目过滤器或组过滤器的工作区。

API 变更：

  • west.manifest.Manifest 的方法 as_dict()、as_frozen_dict()、as_yaml() 和 as_frozen_yaml() 现在有一个可选的 active_only 参数（默认为 False），用于返回包含所有项目或仅包含活动项目的对象。

v1.3.0

主要变更：

  • 添加对 West 别名 命令的支持。

  • 打包采用 pyproject TOML specification。

其他变更：

  • 为子模块添加缓存支持。

  • 默认以 UTF-8 解码清单文件。

  • 将 west diff 和 west status 的未知参数传递给底层的 git 命令。

  • 为 west diff 添加 --manifest 参数，以便将当前工作区与清单修订版本进行比较。

  • west forall 中可以使用环境变量。定义了以下变量：

    • WEST_PROJECT_NAME

    • WEST_PROJECT_PATH

    • WEST_PROJECT_ABSPATH

    • WEST_PROJECT_REVISION

    • WEST_PROJECT_URL

    • WEST_PROJECT_REMOTE

  • 添加对前置参数 -q/--quiet 的支持，用于降低详细程度。

  • 为 west init 添加 -o/--clone-opt 参数，用于传递给 git clone。

  • 支持 Python 3.13，并放弃对 Python 3.8 的支持。

  • 禁止清单在 .west 目录中包含项目。

  • 为 west init 添加 NTFS 变通措施和 --rename-delay。

  • 在调试模式 -vvv 下调用 die 时打印栈回溯。

缺陷修复：

  • 使用 'backslashreplace'，避免因子进程输出格式错误的 UTF 而崩溃。

  • 修复 west diff 对存在合并冲突的仓库的处理。此外改进错误输出，并处理 git diff 的返回码。

  • 修复使用 git 子模块时 west manifest 命令的 --freeze 和 --resolve。

v1.2.0

主要变更：

  • 新增 west grep 命令，用于在 west 工作区的各仓库中运行“grep 工具”。目前支持的 grep 工具有 git grep、ripgrep 和标准 grep。

    要运行此命令，从所有已克隆的活动仓库中获取 git grep foo 的结果，请运行：

    west grep foo

    下面是使用 west grep 运行不同 grep 命令的其他示例：

    git grep --untracked

    west grep --untracked foo

    ripgrep

    west grep --tool ripgrep foo

    grep --recursive

    west grep --tool grep foo

    要切换工作区中的默认 grep 工具，请运行下表中相应的命令：

    ripgrep

    west config grep.tool ripgrep

    grep

    west config grep.tool grep

    更多细节请运行 west help grep。

其他变更：

  • 清单文件格式现在支持在每个 projects: 元素中使用 description 字段。示例请参阅 项目。

  • west list --format 现在接受格式字符串中的 {description}，它会打印项目的 description: 值。

  • west compare 现在总会打印有关 manifest-rev 分支 的信息。

缺陷修复：

  • 如果目标目录已存在，west init 会中止。

API 变更：

  • west.commands.WestCommand 的方法 check_call() 和 check_output() 现在接受任何可传递给底层 subprocess 函数的关键字参数。

  • west.commands.WestCommand.run_subprocess()：新增的 subprocess.run() 包装器。它不能命名为 run()，因为 WestCommand 已经有一个同名方法。

  • west.commands.WestCommand 的方法 dbg()、inf()、wrn() 和 err() 现在都接受一个 end 关键字参数，该参数会传递给对 print() 的调用。

  • west.manifest.Project 现在有一个 description 属性，其中包含清单数据中 description: 字段的解析值。

v1.1.0

主要变更：

  • west compare：新命令，用于将工作区的状态与清单进行比较。

  • 支持新的 manifest.project-filter 配置选项。详情请参阅 内置配置选项。设置此选项时，目前无法使用 west manifest --freeze 和 west manifest --resolve 命令。此限制可能会在以后的版本中移除。

  • 包含逗号（,）或空白的项目名称现在会产生警告。如果设置了新的 manifest.project-filter 配置选项，这些警告将成为错误。在 west 未来的主版本中，这些警告可能会升级为错误。

其他变更：

  • west forall 现在接受 --group 参数，可用于将命令限制为只在一个或多个组中运行。详情请运行 west help forall。

  • 现在所有 west 命令都会输出来自 west API 模块的警告级别或更高级别的日志消息。此外，可以向 west 传递一次 --verbose 参数以包含所有命令的信息性消息，传递两次以包含调试消息。

缺陷修复：

  • 对错误消息、调试日志和错误处理进行了各种改进。

API 变更：

  • west.manifest.Manifest.is_active() 现在会遵循 manifest.project-filter 配置选项的值。

v1.0.1

主要变更：

  • 此版本开始可以使用清单模式版本“1.0”。就功能而言，它与模式版本“0.13”相同，但可供不希望使用“0.x”清单“version:”字段的应用程序使用。有关此功能的详细信息，请参阅 版本（version）。

缺陷修复：

  • West 在收到中断信号时不再以表示成功的错误码退出。而是以平台特定的错误码退出，并向调用环境表明该进程被中断。

v1.0.0

此版本的主要变更：

  • West 的 API 现在被声明为稳定。任何破坏性变更都将通过从 v1.x.y 到 v2.x.y 的主版本升级来告知。

  • West v1.0 不再支持 Zephyr v1.14 LTS 版本。该 LTS 早已被 Zephyr v2.7 LTS 取代。如果需要使用 Zephyr v1.14，必须使用 west v0.14 或更早版本。

  • 与 Zephyr 的其他部分一样，west 现在需要 Python v3.8 或更高版本

  • West 命令不再接受缩写的命令行参数。例如，现在必须指定 west update --keep-descendants，而不能使用 west update --keep-d 之类的缩写。这是对 Zephyr 所有 Python 脚本命令行接口所做变更的一部分。在实践中，当命令更新并添加了与现有选项名称相近但行为不同的新选项时，这些缩写会引发问题。

其他变更：

  • 所有内置 west 函数都已停止使用 west.log

  • west update：新增 --submodule-init-config 选项。详情请参阅提交 9ba92b05。

缺陷修复：

  • 未能正确加载的 West 扩展命令有时会转储栈信息。此问题已修复，现在 west 在这种情况下会打印合理的错误消息。

  • 如果配置选项参数格式错误（选项名中缺少 .），west config 现在会失败

API 变更：

  • west 包现在包含一些静态分析器（例如 mypy）自动检测其类型注解所需的元数据文件。详情请参阅提交 d9f00e24。

  • 移除了为兼容 Zephyr v1.14 LTS 而使用的已弃用 west.build 模块

  • 移除了为兼容 Zephyr v1.14 LTS 而使用的已弃用 west.cmake 模块

  • west.log 模块现已弃用。该模块使用全局状态，因此作为可能被多个不同 python 模块依赖的 API 使用时会不太方便。

  • west.commands 模块增加了一些新 API，为将来给命令输出添加全局详细程度控制的变更打下基础，并致力于从 west 包的 API 中移除全局状态：

    • 新的 west.commands.WestCommand.__init__() 关键字参数：verbosity

    • 新的 west.commands.WestCommand 属性：color_ui

    • 新的 west.commands.WestCommand 方法，扩展命令应使用这些方法打印输出，而不是直接写入 sys.stdout 或 sys.stderr：inf()、wrn()、err()、die()、banner()、small_banner()

    • 新的 west.commands.VERBOSITY 枚举

v0.14.0

缺陷修复：

  • 使用有问题的本地配置文件运行 West 命令时，会以令人困惑的方式转储栈信息。此问题已修复，现在 west 在这种情况下会打印合理的错误消息。

  • 修复了 west 查找 zephyr 仓库的方式中存在的一个缺陷。该缺陷通常出现在新工作区中首次运行 west build 之类的扩展命令时；除非在工作区顶层目录中运行该命令，否则会失败（只是第一次失败，后续调用不会失败）。

  • 当用户没有打开清单文件的权限时，West 现在会打印合理的错误消息，而不是转储栈回溯。

API 变更：

  • west.manifest.MalformedConfig 异常类型已移至 west.configuration 模块

  • west.manifest.MalformedConfig 异常类型已移至 west.configuration 模块

  • west.configuration.Configuration 类现在在某些情况下会引发 MalformedConfig 而不是 RuntimeError

v0.13.1

缺陷修复：

  • 在工作区之外调用 west.manifest.Manifest.from_file() 时，west 再次回退到使用 ZEPHYR_BASE 环境变量来定位工作区。

v0.13.0

新功能：

  • 现在可以在 manifest: self: userdata: 值中将任意用户数据与清单仓库本身关联，如下所示：

    manifest:
  self:
    userdata: <any YAML value can go here>

缺陷修复：

  • 在 [issue #572](https://github.com/zephyrproject-rtos/west/issues/572) 中详述的某些情况下，west 报告的清单仓库路径可能不正确。作为对 west.manifest API 模块中路径处理支持的一次较大规模重构的一部分，此问题已修复。

  • 修复了 west.Manifest.ManifestProject.__repr__ 的返回值

API 变更：

  • west.configuration.Configuration：访问当前配置的新面向对象接口。它反映系统、全局和工作区本地的配置值，并允许从其中任意一个或所有位置读取、写入和删除配置选项。

  • west.commands.WestCommand：

    • config：新属性，返回一个 Configuration 对象；如果未设置，则中止程序。在扩展命令的 do_run() 实现中始终可以使用它。

    • has_config：新的布尔属性，当且仅当读取 self.config 会中止程序时为 True。

  • west.manifest 包中的路径处理以不向后兼容的方式进行了重构。更多细节请参阅提交 [56cfe8d1d1](https://github.com/zephyrproject-rtos/west/commit/56cfe8d1d1f3c9b45de3e793c738acd62db52aca)。

  • west.manifest.Manifest.validate()：现在以 Python dict 的形式返回经过验证的数据。如果传给此函数的值是 str，而你需要的是 dict，这会很有用。

  • west.manifest.Manifest：新增：

    • 路径属性 abspath、posixpath、relative_path、yaml_path、repo_path、repo_posixpath

    • userdata 属性，其中包含 manifest: self: userdata: 的解析值，或者为 None

    • from_topdir() 工厂方法

  • west.manifest.ManifestProject：新增 userdata 属性，其中同样包含 manifest: self: userdata: 的解析值，或者为 None

  • west.manifest.ManifestImportFailed：构造函数现在可以接受任意值；这可用于表示来自 映射 或其他复合值的导入失败。

  • 已弃用的配置 API：

    以下 API 现已弃用，建议改用 Configuration 对象。通常通过 WestCommand 实例中的 self.config 来使用它，但在其他用途中也可以直接实例化一个 Configuration 对象。

    • west.configuration.config

    • west.configuration.read_config

    • west.configuration.update_config

    • west.configuration.delete_config

v0.12.0

新功能：

  • West 现在可以在 MSYS2 平台上运行。

  • West 清单文件现在可以包含与每个项目关联的任意用户数据。详情请参阅 仓库用户数据。

缺陷修复：

  • 修复了 west list 命令的 {sha} 格式键对清单仓库的处理；它现在会按预期打印 N/A （“不适用”）。

API 变更：

  • 添加了 west.manifest.Project.userdata 属性，以支持项目用户数据。

v0.11.1

新功能：

  • west status 现在只为状态非空的项目打印输出。

缺陷修复：

  • 清单文件解析器之前错误地允许项目名称包含路径分隔符 / 和 \。现在会拒绝这些无效字符。

    注意：如果需要将项目放在工作区 topdir 的某个子目录中，请使用 path: 键。如果需要相对于远程仓库的 url-base: 自定义项目的获取 URL，请使用 repo-path:。示例请参阅 项目。

  • west v0.10.1 中对用于选择默认分支名称的 west init --manifest-rev 选项所做的更改，会使清单仓库处于分离 HEAD 状态。现在通过在内部使用 git clone 代替 git init 和 git fetch 修复了此问题。详情请参阅 issue #522。

  • WEST_CONFIG_LOCAL 环境变量现在能够正确覆盖默认位置 <workspace topdir>/.west/config。

  • west update --fetch=smart （smart 是默认值）现在能够正确跳过对 lightweight tags 项目修订版本的获取（对附注标签本来就工作正常；只有轻量标签会被不必要地获取）。

其他变更：

  • 上述对 issue #522 的修复引入了一项新限制。如果给出了 west init --manifest-rev 选项的值，它现在必须是分支或标签。特别是，以前可以用来获取 PR（拉取请求）的“伪分支”（例如 GitHub 的 pull/1234/head 引用）不能再传给 --manifest-rev。用户现在必须在运行 west init 之后手动获取并检出这类修订版本。

API 变更：

  • west.manifest.Manifest.get_projects() 避免了在 issue #523 中所述的某些边界情况下返回错误结果。

  • west.manifest.Project.sha() 现在可以正确处理标签修订版本。（这同时适用于轻量标签和附注标签。）

v0.11.0

新功能：

  • west update 现在支持 --narrow、--name-cache 和 --path-cache 选项。它们可以受 update.narrow、update.name-cache 和 update.path-cache 配置 选项的影响。这些选项可用于提高更新速度。

  • west update 现在支持 --fetch-opt 选项，该选项会被传递给更新每个项目时用于获取远程修订版本的 git fetch 命令。

缺陷修复：

  • west update 现在默认会同步项目中的 Git 子模块。如果清单文件中的 URL 与子模块首次初始化时不同，这样可以避免出现问题。将 update.sync-submodules 配置选项设置为 false 即可禁用此行为。

其他变更：

  • west.manifest 模块修正了 Project 类的文档字符串

v0.10.1

新功能：

  • west init 命令的 --manifest-rev （--mr）选项不再默认为 master。该命令会查询仓库的默认分支名称并改用它。这样用户就可以从 master 迁移到 main，而不会破坏未提供此选项的脚本。

v0.10.0

新功能：

  • 项目 子模块列表 中的 name 键现在是可选的。

缺陷修复：

  • West 现在会检查清单模式版本是否为 版本（version） 中记录的明确允许的值之一。旧的行为只是检查模式版本是否比引入 manifest: version: 键的 west 版本更新。这会错误地允许无效的模式版本，例如 0.8.2。

其他变更：

  • 清单文件的 group-filter 现在会通过 import 传播。这与 west v0.9.x 的处理方式不同。在 west v0.9.x 中，只有顶层清单文件的 group-filter 有效；任何被导入清单中的组过滤器列表都会被忽略。

    从 west v0.10.0 开始，被导入清单中的组过滤器列表也会被导入。详情请参阅 组过滤器与导入。

    如果未给出 manifest: version:，或者其值至少为 0.10，则新行为生效。只有在顶层清单文件中显式指定 manifest: version: 0.9 时，旧行为才仍然可用。有关模式版本的更多信息，请参阅 版本（version）。

    此变更的动机和更多背景信息请参阅 west pull request #482。

v0.9.1

缺陷修复：

  • west manifest --resolve 等命令现在会正确包含组和组过滤器信息。

其他变更：

  • 如果将 import 与 group-filter 结合使用，West 现在会发出警告。从 v0.10.x 开始，这种组合的语义发生了变化。更多信息请参阅上面的 v0.10.0 发布说明。

v0.9.0

警告

下文所述的 west config 修复是有代价的：通过该命令或 west.configuration API 设置配置选项时，配置文件中的所有注释或其他手动编辑内容都会被删除。

警告

不建议将此版本引入的 group-filter 功能与清单导入结合使用。其最终行为在 west v0.10 中已发生变化。

新功能：

  • West 清单现在支持 项目中的 Git 子模块。这样除了项目仓库本身之外，还可以将 Git submodules 克隆到 west 项目仓库中。

  • West 清单现在支持 项目组。可以启用和禁用项目组，以确定哪些项目是“活动的”，从而被以下命令处理：west update、west list、west diff、west status、west forall。

  • west update 默认不再更新非活动项目。它现在支持 --group-filter 选项，允许对启用和禁用的项目组集合进行一次性修改。

  • 不带参数运行 west list、west diff、west status 或 west forall 时，默认不会打印非活动项目的信息。如果用户在命令行中显式指定了项目列表，无论这些项目是否活动，都会包含它们的输出。

    这些命令现在还支持 --all 参数，用于包含所有项目，包括非活动项目。

  • west list 现在在其 --format 参数中支持 {groups} 格式字符串键。

缺陷修复：

  • west config 命令和 west.configuration API 之前无法正确存储某些配置值，例如包含逗号的字符串。此问题已修复；详情请参阅 commit 36f3f91e。

  • manifest: self: path: 值为空的清单文件是无效的，但 west 以前会默默放行。现在 West 会拒绝此类清单。

  • 修复了一个影响 west init -l . 命令行为的缺陷；请参阅 issue #435。

API 变更：

  • 添加了 west.manifest.Manifest.is_active()

  • 添加了 west.manifest.Manifest.group_filter

  • 为 west.manifest.Project 添加了 submodules 属性，其类型为新增的 west.manifest.Submodule

其他变更：

  • 清单导入 功能现在支持术语 allowlist 和 blocklist，分别替代 whitelist 和 blacklist。

    为了兼容，旧术语仍然受支持，但文档已更新为只使用新术语。

v0.8.0

这是一个功能版本，通过在 import: 映射中添加对 path-prefix: 键的支持来更改清单模式，同时还包含其他一些功能和修复。

  • 清单导入映射现在支持 path-prefix: 键，它会将项目及其导入的仓库放到工作区的一个子目录中。示例请参阅 示例 3.4：导入到子目录中。

  • west manifest --path 打印 west.yml 的绝对路径

  • west init 现在支持 --mf foo.yml 选项，该选项使用 foo.yml 而不是 west.yml 初始化工作区。

  • west list 现在使用 manifest.path 配置选项 打印清单仓库的路径，该路径可能与清单数据中的 self: path: 值不同。旧行为仍然可用，但需要传递新的 --manifest-path-from-yaml 选项。

  • 多项 Python API 变更；详情请参阅 West 的 API。

v0.6.1

警告

请勿使用此补丁版本，务必改用 v0.6.2。

此补丁版本中用户可见的功能有：

  • west update 命令新增了 --fetch 命令行标志和 update.fetch 配置选项。默认值“smart”会跳过获取本地已有的 SHA 和标签。

  • west diff、west status、west forall 和 west update 命令的错误处理更好、更一致。这些命令都可以对多个项目进行操作；如果与某个项目相关的子进程失败，这些命令现在会继续处理其余项目。此外，只要其中任何子进程失败，它们现在都会让 west 进程返回非零错误码（以前，特别是 west forall，并非如此）。

  • west manifest 命令的错误处理也有所改进。

  • west list 命令现在即使在项目尚未克隆时也能工作，只要其格式字符串只需要能从清单文件中读取的信息即可。如果格式字符串需要存储在项目仓库中的数据（例如包含 {sha} 格式字符串键），它仍然会失败。

  • 对 git 修订版本进行操作的命令和选项现在接受缩写的 SHA。例如，west init --mr SHA_PREFIX 现在可以正常工作。以前，如果 --mr 参数不是分支或标签，就必须是完整的 40 字符 SHA。

对 West 的 API 的开发者可见变更如下：

  • west.log.banner()：新增

  • west.log.small_banner()：新增

  • west.manifest.Manifest.get_projects()：新增

  • west.manifest.Project.is_cloned()：新增

  • west.commands.WestCommand 实例现在可以在 do_run() 调用期间通过新的 self.manifest 属性访问已解析的 Manifest 对象。读取该属性时，它会返回 Manifest 对象；如果无法解析清单，则中止命令。

  • west.manifest.Project.git() 现在有一个 capture_stderr 关键字参数

v0.6.0

  • 不再有单独的引导程序

    在 west v0.5.x 中，程序分为两个组件：一个引导程序和每次安装各自的一份克隆。更多细节请参阅 Multiple Repository Management in the v1.14 documentation。

    这与 Google 的 Repo 工具的工作方式类似，使 west 在早期能够快速迭代。但这种方式引起了困惑，而 west 现在已经足够稳定，可以作为一个整体通过 PyPI 分发。

    从 v0.6.x 开始，所有核心 west 命令和辅助类都属于通过 PyPI 分发的 west 包。这消除了复杂性，并使得可以在系统中的任何地方导入 west 模块，而不仅限于扩展命令。

  • 为了向后兼容，selfupdate 命令仍然存在，但现在只会打印一条错误消息然后退出。

  • 清单语法变更

    • West 清单文件的 projects 元素现在可以直接指定其获取 URL，如下所示：

      manifest:
  projects:
    - name: example-project-name
      url: https://github.com/example/example-project

      以这种方式设置了 url 属性的项目元素不能同时具有 remote 属性。

    • 项目名称必须唯一：这项限制是支持后续工作所必需的，但在 west v0.5.x 中无法实现，因为不同的项目可能具有最后一个路径名组成部分相同的 URL，如下所示：

      manifest:
  remotes:
    - name: remote-1
      url-base: https://github.com/remote-1
    - name: remote-2
      url-base: https://github.com/remote-2
  projects:
    - name: project
      remote: remote-1
      path: remote-1-project
    - name: project
      remote: remote-2
      path: remote-2-project

      这些清单现在可以改用 url 而不是 remote 来编写项目，如下所示：

      manifest:
  projects:
    - name: remote-1-project
      url: https://github.com/remote-1/project
    - name: remote-2-project
      url: https://github.com/remote-2/project

  • west list 命令现在支持 {sha} 格式字符串键

  • west list 的默认格式字符串已更改为 "{name:12} {path:28} {revision:40} {url}"。

  • 现在可以运行 west manifest --validate 命令来加载并验证当前清单文件；此外还有其他一些与清单解析相关的错误处理修复。

  • 对 west 的 API 进行了不兼容的更改。在 west v1.0 宣布 API 稳定之前，预计还会有进一步的更改。

    • west.manifest.Project 构造函数的 remote 和 defaults 位置参数现在改为关键字参数。还新增了 url 关键字参数；如果给出，则 Project 的 URL 设置为该值，并忽略 remote 关键字参数。

    • 移除了 west.manifest.MANIFEST_SECTIONS。现在只有一个节，即 manifest。west.manifest.Manifest 工厂方法和构造函数中的 sections 关键字参数也已移除。

    • 移除了 west.manifest.SpecialProject 类。请改用 west.manifest.ManifestProject。
