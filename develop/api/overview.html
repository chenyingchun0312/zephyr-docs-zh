API 概览

下表列出了 Zephyr 的各个 API 及其相关信息，包括当前的 稳定性级别。关于主要版本之间 API 变更的更多详情，请参阅 版本发布。

版本列采用 语义化版本，并遵循以下约定：

  • 主版本号为零（0.y.z）表示处于初始开发阶段。任何内容都可能随时更改。公共 API 不应被视为稳定。

    • 如果次版本号不超过一（0.1.z），则该 API 被视为 实验性。

    • 如果次版本号大于一（0.y.z | y > 1），则该 API 被视为 不稳定。

  • 1.0.0 版本定义了公共 API。此版本之后版本号如何递增，取决于该公共 API 及其变更方式。

    • 主版本号大于或等于一（x.y.z | x >= 1）的 API 被视为 稳定。

    • Zephyr 中所有现有的稳定 API 都将从 1.0.0 版本开始。

  • 如果只引入了向后兼容的缺陷修复，则必须递增修订号 Z（x.y.Z | x > 0）。缺陷修复是指修正错误行为的内部变更。

  • 如果向公共 API 引入了向后兼容的新功能，则必须递增次版本号 Y（x.Y.z | x > 0）。如果有任何公共 API 功能被标记为弃用，也必须递增次版本号。如果在私有代码中引入了大量新功能或改进，可以递增次版本号。次版本号的递增可以包含修订级别的变更。递增次版本号时，修订号必须重置为 0。

  • 如果对 API 做了破坏兼容性的变更，则必须递增主版本号 X（x.Y.z | x > 0）。

备注

现有 API 的版本最初根据 API 的当前状态设置：

  • 0.1.0 表示 实验性 API

  • 0.8.0 表示 不稳定 API，

  • 最后，1.0.0 表示 稳定 API。

今后对 API 的变更需要按照上述准则调整版本。
