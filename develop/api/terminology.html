API 术语

以下术语可用作简写的 API 标签，用于说明允许的调用上下文（线程、ISR、内核启动前）、调用对当前线程状态的影响以及其他行为特征。

reschedule

执行该函数会到达重新调度点

sleep

执行该函数可能导致调用线程休眠

no-wait

该函数的某个参数可以阻止调用线程尝试休眠

isr-ok

无论从中断上下文还是线程上下文调用，该函数都可以安全调用，并产生其规定的效果

pre-kernel-ok

在内核完全初始化之前即可安全调用该函数，并且在该上下文中调用时会产生其规定的效果。

async

该函数可能在其发起的操作完成之前返回（即函数返回与操作完成是异步的）

supervisor

调用线程必须具有特权（supervisor）权限才能执行该函数

以下各节详细说明各个属性对行为的影响。

reschedule

reschedule 属性用于在执行过程中可能到达 重新调度点 的函数。

详情

该属性的意义在于：当线程调用一个会重新调度的函数时，该线程可能因为某个更高优先级的线程变为就绪而被挂起。挂起是否实际发生，取决于与重新调度点相关的操作，以及调用线程与就绪队列队首线程的相对优先级。

注意，在时间片轮转的情况下，或者在中断中执行重新调度点时，任何线程都可能在任何函数中被挂起。

不具有 reschedule 属性的函数可以从线程上下文或中断上下文调用。

具有 reschedule 属性的函数可以从线程上下文调用。

具有 reschedule 但不具有 sleep 属性的函数可以从中断上下文调用。

sleep

sleep 属性用于可能导致调用线程 休眠 的函数。

说明

对于只使用不可抢占线程的应用程序，该属性尤为重要，因为内核不会在重新调度点替换正在运行的纯协作式线程，除非该线程显式调用了会使其休眠的操作。

该属性并不意味着函数会无条件休眠，而是表示该操作可能要求调用线程挂起、等待或调用 k_yield()，然后才能完成其操作。这一行为可以通过 no-wait 加以调节。

具有 sleep 属性的函数隐含具有 reschedule 属性。

具有 sleep 属性的函数可以从线程上下文调用。

当且仅当以 no-wait 模式调用时，具有 sleep 属性的函数才可以从中断上下文和内核启动前上下文调用。

no-wait

no-wait 属性用于同时具有 sleep 属性的函数，表示该函数的某个参数可以强制走一条不会导致调用线程休眠的执行路径。

说明

no-wait 函数的典型例子是接受超时参数、并且可以传入 K_NO_WAIT 的函数。这一特殊超时值的语义是：只要函数的操作能够立即完成就执行它；如果不能，则返回错误码而不是休眠。

正是借助 no-wait 特性，k_sem_take() 等函数才能从 ISR 中调用，因为在中断上下文中不允许休眠。

函数具有 no-wait 路径，并不意味着走该路径就能保证函数是同步的。

具有该属性的函数，只有在参数选择了 no-wait 路径时，才可以从中断上下文和内核启动前上下文调用。

isr-ok

isr-ok 属性用于表示函数无论从中断上下文还是线程上下文调用都能正常工作。

说明

任何不具有 sleep 属性的函数本身就是 isr-ok 的。具有 sleep 属性的函数，如果其实现能确保即使从中断上下文调用也能实现文档所述的行为，则也是 isr-ok 的。实现方式可以是让实现检测调用上下文，并将会休眠的操作转交给某个线程；也可以在文档中说明从非线程上下文调用时函数将返回特定错误（通常为 -EWOULDBLOCK）。

注意，no-wait 函数只有在选择了 no-wait 路径时才能安全地从中断上下文调用。isr-ok 函数不必提供 no-wait 路径。

pre-kernel-ok

pre-kernel-ok 属性用于表示函数即使在内核主线程启动之前调用，也能按文档所述工作。

说明

该属性在功能上与 isr-ok 类似，但适用于预期会在 DEVICE_DEFINE() 或 SYS_INIT() 调用中使用的任何 API，这些调用可能以 PRE_KERNEL_1 或 PRE_KERNEL_2 初始化级别执行。

通常，pre-kernel-ok 函数会检查 k_is_pre_kernel()，以确定能否完成其要求的行为。在许多情况下，它还会检查 k_is_in_isr()，从而同时成为 isr-ok 函数。

async

如果函数可能在其发起的操作完成之前返回，则该函数是 async（即异步）的。异步函数通常会提供某种报告操作完成的机制，例如回调或事件。

不是异步的函数就是同步的，即函数返回时操作总是已经完成。由于大多数函数都是同步的，这种行为没有专门的属性来标识。

说明

注意，async 与上下文切换是正交的。某些 API 可能通过回调提供完成信息，但在等待发起操作所需的资源时可能会挂起；spi_transceive_signal() 就是一个例子。

如果函数同时具有 no-wait 和 async 属性，那么选择 no-wait 路径只能保证函数不会休眠，并不影响操作是否会在函数返回之前完成。

supervisor

supervisor 属性只与用户模式应用程序相关，表示该函数不能从用户模式调用。
