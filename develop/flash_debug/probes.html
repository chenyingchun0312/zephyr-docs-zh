调试探针

调试探针 是一种特殊硬件，可用于控制在另一块开发板上运行的 Zephyr 应用程序的执行。调试探针通常可以读写寄存器和内存，并支持在主机工作站上使用 GDB 等工具对 Zephyr 应用程序进行断点调试。它们还可能支持其他调试软件以及更高级的功能，例如 跟踪程序执行。关于 Zephyr 支持的相关主机软件，详见 烧录与调试主机工具。

调试探针通常通过 USB 连接到主机工作站，有时也可以通过 IP 网络或其他方式访问。它们通常使用 JTAG 或 SWD 协议连接到运行 Zephyr 的器件。调试探针可以是独立的硬件设备，也可以是集成在运行 Zephyr 的同一块开发板上的电路。

Zephyr 支持的许多开发板都带有第二颗微控制器，用作板载调试探针、USB 转串口适配器，有时还用作拖放式 Flash 编程器。这样就无需另外购买外部调试探针，并提供多种调试主机工具选择。

一些硬件厂商有自己品牌的板载调试探针实现：NXP 开发板根据调试探针固件所运行的微控制器，可能使用 OpenSDA、LPC-Link2 或 MCU-Link 探针。ST 开发板配备 ST-LINK 探针。每种板载调试探针微控制器都可以支持一种或多种固件，用于与各自的调试主机工具通信。例如，OpenSDA 微控制器可以烧录 DAPLink 固件以便与 pyOCD 或 OpenOCD 调试主机工具通信，也可以烧录 J-Link 固件以便与 J-Link 调试主机工具通信。

Zephyr 支持的某些开发板不带板载调试探针，因此需要外部调试探针。此外，带板载调试探针的开发板通常也有 SWD 或 JTAG 接头，以便改用外部调试探针。这样做的一个原因是板载调试探针可能存在局限，例如不支持高级调试器或高速跟踪。你可能需要调整跳线，防止板载调试探针干扰外部调试探针。

NXP 板载调试探针

NXP 开发板可能带有几种板载调试探针之一。这些探针包括 MCU-Link 板载调试探针、LPC-LINK2 板载调试探针 和 OpenSDA 板载调试探针。每种探针都实现为评估板上的一颗辅助微控制器。某块开发板上具体是哪种调试探针，可以根据调试微控制器的 SoC 来判断：

  • LPC55S69：MCU-Link 板载调试探针

  • LPC4322：LPC-LINK2 板载调试探针

  • MK20：OpenSDA 板载调试探针

例如，FRDM-K64F 开发板带有一颗 MK20 调试微控制器，因此该开发板使用 OpenSDA 板载调试探针。

MCU-Link 板载调试探针

MCU-Link 板载调试探针使用 LPC55S69 SoC。该探针支持以下固件：

  • MCU-Link CMSIS-DAP 板载调试探针（默认固件）

  • MCU-Link JLink 板载调试探针

该探针使用 MCU-Link 主机工具进行编程，这些工具随 LinkServer 调试主机工具 一起安装。NXP 建议使用 NXP 的 MCUXpresso Installer 安装 Linkserver 工具。

MCU-Link CMSIS-DAP 板载调试探针

这是 MCU-Link 调试探针上默认安装的固件。CMSIS-DAP 调试探针支持从任何兼容的工具链进行调试，包括 IAR EWARM、Keil MDK、NXP 的 MCUXpresso IDE 以及 VS Code 的 MCUXpresso 扩展。除调试探针功能外，MCU-Link 探针还可能提供：

  1. SWO 跟踪端点：MCUXpresso 使用此虚拟设备获取 SWO 跟踪数据。更多信息请参阅 MCUXpresso IDE 文档。

  2. 连接到目标处理器的虚拟 COM（VCOM）端口 / UART 桥

  3. USB 转 UART、SPI 和/或 I2C 接口（取决于 MCU-Link 的类型/实现）

  4. 目标 MCU 的能耗测量

该调试探针兼容以下调试主机工具：

  • LinkServer 调试主机工具

安装 MCU-Link 主机工具后，需要按以下步骤烧录 CMSIS-DAP 固件：

  1. 确保主机上有 MCU-Link 实用程序。可以通过安装 LinkServer 调试主机工具 获得。

  2. 装上 DFU 跳线，然后连接开发板上的 USB 调试端口，使 MCU-Link 微控制器进入 DFU 启动模式。该跳线也可能被称为 ISP 跳线，连接到 LPC55S69 的 PIO0_5。

  3. 运行已安装的 MCU-Link scripts 文件夹中的 program_CMSIS 脚本。

  4. 取下 DFU 跳线，并给开发板重新上电。

MCU-Link JLink 板载调试探针

该调试探针固件提供与 JLink 兼容的调试接口以及 USB 转串口适配器。它兼容以下调试主机工具：

  • J-Link 调试主机工具

这些探针默认未安装 JLink 固件，必须进行更新。安装 MCU-Link 主机工具后，需要按以下步骤烧录 JLink 固件：

  1. 确保主机上有 MCU-Link 实用程序。可以通过安装 LinkServer 调试主机工具 获得。

  2. 装上 DFU 跳线，然后连接开发板上的 USB 调试端口，使 MCU-Link 微控制器进入 DFU 启动模式。该跳线也可能被称为 ISP 跳线，连接到 LPC55S69 的 PIO0_5。

  3. 运行已安装的 MCU-Link scripts 文件夹中的 program_JLINK 脚本。

  4. 取下 DFU 跳线，并给开发板重新上电。

LPC-LINK2 板载调试探针

LPC-LINK2 板载调试探针使用 LPC4322 SoC。该探针支持以下固件：

  • LPC-LINK2 CMSIS DAP 板载调试探针

  • LPC-Link2 J-Link 板载调试探针

  • LPC-Link2 DAPLink 板载调试探针（默认固件）

该探针使用 LPCScrypt 主机工具进行编程，这些工具随 LinkServer 调试主机工具 一起安装。NXP 建议使用 NXP 的 MCUXpresso Installer 安装 Linkserver 工具。

LPC-LINK2 CMSIS DAP 板载调试探针

CMSIS-DAP 调试探针支持从任何兼容的工具链进行调试，包括 IAR EWARM、Keil MDK，以及 NXP 的 MCUXpresso IDE 和 VS Code 的 MCUXpresso 扩展。除调试探针功能外，LPC-Link2 探针还提供：

  1. SWO 跟踪端点：MCUXpresso 使用此虚拟设备获取 SWO 跟踪数据。更多信息请参阅 MCUXpresso IDE 文档。

  2. 连接到目标处理器的虚拟 COM（VCOM）端口 / UART 桥

  3. LPCSIO 桥，用于与 I2C 和 SPI 外设通信

该调试探针固件兼容以下调试主机工具：

  • LinkServer 调试主机工具

可以按以下步骤将探针更新为使用 CMSIS-DAP 固件：

  1. 确保主机上有 LPCScrypt 实用程序。可以通过安装 LinkServer 调试主机工具 获得。

  2. 装上 DFU 跳线，然后连接开发板上的 USB 调试端口，使 LPC-Link2 微控制器进入 DFU 启动模式。该跳线连接到 LPC4322 SoC 的 P2_6。

  3. 运行已安装的 LPCScrypt scripts 文件夹中的 program_CMSIS 脚本。

  4. 取下 DFU 跳线，并给开发板重新上电。

LPC-Link2 J-Link 板载调试探针

该调试探针固件提供与 JLink 兼容的调试接口以及 USB 转串口适配器。它兼容以下调试主机工具：

  • J-Link 调试主机工具

  2. 装上 DFU 跳线，然后连接开发板上的 USB 调试端口，使 LPC-Link2 微控制器进入 DFU 启动模式。该跳线连接到 LPC4322 SoC 的 P2_6。

LPC-Link2 DAPLink 板载调试探针

LPC-Link2 DAPLink 固件是基于 LPC-Link2 的开发板出厂时默认附带的固件，但并不是推荐的固件。用户应按照上文的说明更新为 LPC-LINK2 CMSIS DAP 板载调试探针 固件。关于烧录 DAPLink 固件的详细信息，请参阅 NXP AN13206。

OpenSDA 板载调试探针

OpenSDA 板载调试探针基于 NXP MK20 SoC。它支持拖放式编程，并支持以下调试固件：

  • OpenSDA DAPLink 板载调试探针（默认固件）

  • OpenSDA J-Link 板载调试探针

OpenSDA DAPLink 板载调试探针

该调试探针固件兼容以下调试主机工具：

  • pyOCD 调试主机工具

  • OpenOCD 调试主机工具

  • LinkServer 调试主机工具

该探针通过在 OpenSDA 微控制器上烧录 DAPLink OpenSDA 固件实现。NXP 提供了 OpenSDA DAPLink Board-Specific Firmwares。

烧录固件之前，请先安装调试主机工具。

与所有 OpenSDA 调试探针一样，烧录固件的步骤如下：

  1. 按住复位按钮的同时给开发板上电，使 OpenSDA 微控制器进入引导加载程序模式。注意，此处的“引导加载程序模式”指的是 OpenSDA 微控制器本身，而不是 Zephyr 应用程序的目标微控制器。

  2. 开发板上电后，松开复位按钮。系统会枚举出一个名为 BOOTLOADER 或 MAINTENANCE 的 USB 大容量存储设备。如果枚举出的设备名为 BOOTLOADER，请先按照 DAPLink Bootloader Update 的说明将引导加载程序更新到最新版本。

  3. 将 OpenSDA 固件二进制文件复制到该 USB 大容量存储设备。

  4. 给开发板重新上电，这次不要按住复位按钮。此时应枚举出三个 USB 设备：一个 CDC 设备（串口）、一个 HID 设备（调试端口）和一个大容量存储设备（拖放式 Flash 编程）。

OpenSDA J-Link 板载调试探针

该调试探针兼容以下调试主机工具：

  • J-Link 调试主机工具

该探针通过在 OpenSDA 微控制器上烧录 J-Link OpenSDA 固件实现。Segger 提供 OpenSDA J-Link Generic Firmwares 和 OpenSDA J-Link Board-Specific Firmwares，如有后者，一般推荐使用后者。i.MX RT 开发板需要使用开发板专用固件以支持其外部 Flash 存储器，而通用固件兼容所有 Kinetis 开发板。

烧录固件之前，请先安装调试主机工具。

与所有 OpenSDA 调试探针一样，烧录固件的步骤如下：

  1. 按住复位按钮的同时将 USB 线插入开发板的 USB 调试端口，使 OpenSDA 微控制器进入引导加载程序模式。注意，此处的“引导加载程序模式”指的是 OpenSDA 微控制器本身，而不是 Zephyr 应用程序的目标微控制器。

  2. 开发板上电后，松开复位按钮。系统会枚举出一个名为 BOOTLOADER 或 MAINTENANCE 的 USB 大容量存储设备。如果枚举出的设备名为 BOOTLOADER，请先按照 DAPLink Bootloader Update 的说明将引导加载程序更新到最新版本。

  3. 将 OpenSDA 固件二进制文件复制到该 USB 大容量存储设备。

  4. 给开发板重新上电，这次不要按住复位按钮。此时应枚举出两个 USB 设备：一个 CDC 设备（串口）和一个厂商专用设备（调试端口）。

J-Link 外部调试探针

Segger J-Link 是一系列外部调试探针，包括 J-Link EDU、J-Link PLUS、J-Link ULTRA+ 和 J-Link PRO，支持来自不同硬件架构和厂商的大量器件。

该调试探针兼容以下调试主机工具：

  • J-Link 调试主机工具

  • OpenOCD 调试主机工具

烧录固件之前，请先安装调试主机工具。

ST-LINK/V2-1 板载调试探针

ST-LINK/V2-1 是内置于所有 Nucleo 和 Discovery 开发板中的串口与调试适配器。它在你的计算机（或其他 USB 主机）与嵌入式目标处理器之间架起桥梁，只需一根普通 USB 线即可进行调试、Flash 编程和串口通信。

它兼容以下主机调试工具：

  • OpenOCD 调试主机工具

  • J-Link 调试主机工具

  • STM32CubeCLT 烧录与调试主机工具

对于某些基于 STM32 的开发板，它还兼容：

  • pyOCD 调试主机工具

它可以直接配合 OpenOCD 使用，但要配合 J-Link 使用则需要烧录一些固件。为此，SEGGER 提供了一款固件，用于升级 Nucleo 和 Discovery 开发板上的板载 ST-LINK/V2-1。该固件使 ST-LINK/V2-1 与 J-LinkOB 兼容，让用户可以利用 J-Link 的大多数特性，例如超高速的 Flash 下载和调试速度，或可免费使用的 GDBServer。

关于将 ST-LINK/V2-1 升级为 JLink 或恢复 ST-Link/V2-1 固件的更多信息，请访问：Segger over ST-Link

使用 ST-Link 烧录和调试

ST-Link 默认支持 OpenOCD，并将其配置为默认的烧录和调试工具。烧录和调试可以按如下方式进行：

# From the root of the zephyr repository
west build -b None samples/hello_world
west flash

# From the root of the zephyr repository
west build -b None samples/hello_world
west debug

为 STLink 烧录 SEGGER 固件并在主机上安装 J-Link GDB 服务器后，可以按如下方式烧录和调试：

在 CMake 中使用 -DBOARD_FLASH_RUNNER=jlink，将默认的 OpenOCD 运行器改为 J-Link。也可以在应用程序的 CMakeList.txt 文件中添加以下一行。

set(BOARD_FLASH_RUNNER jlink)

如果使用 West（Zephyr 的元工具），可以通过 --runner（或 -r）选项修改默认运行器。

west flash --runner jlink

使用 jlink 将调试器连接到开发板并打开调试控制台。

west debug --runner jlink

关于 West 及其可用选项的更多信息，请参阅 West（Zephyr 的元工具）。

如果你将 Zephyr 应用程序配置为改用 Segger RTT 控制台，请打开 telnet：

$ telnet localhost 19021

如果没有 RTT 输出，并且你运行的示例或应用程序默认启用了与 RTT 冲突的其他控制台，则可能需要禁用这些控制台，例如在 menuconfig 中禁用 UART_CONSOLE

更新或恢复 ST-Link 固件

可以使用 STM32CubeProgrammer Tool 更新 ST-Link 固件。遇到烧录问题时（例如使用 twister 的设备测试选项时），这通常很有用。

安装后，可以用以下命令更新所连接开发板的 ST-Link 固件

s java -jar ~/STMicroelectronics/STM32Cube/STM32CubeProgrammer/Drivers/FirmwareUpgrade/STLinkUpgrade.jar -sn <board_uid>

其中 board_uid 可以通过 twister 的 generate-hardware-map 选项获取。关于 twister 及其可用选项的更多信息，请参阅 测试运行器（Twister）。

OpenOCD 弃用 HLA ST-Link 接口

2024 年 1 月，OpenOCD 弃用了 ST-Link 固件所使用的旧版 HLA 接口，转而采用通用 DAP 接口（参见 OpenOCD deprecates ST-Link HLA Interface）。ST-Link 固件自 2015 年（从 v2j24 版本起）就已支持 DAP 接口。

OpenOCD 弃用该接口后，如果使用较新的 OpenOCD 工具（v0.12.0 发布标签之后），而 ST-Link 适配器内置的固件早于 v2j24 版本，则可能遇到通信问题。这种情况下，建议更新 ST-Link 固件（参见 ST-LINK 固件更新）。如果无法更新固件，仍然可以使用旧的 HLA 接口，方法是修改 OpenOCD 配置脚本，将下面两行（如果存在）：

source [find interface/stlink-dap.cfg]
transport select dapdirect_swd

替换为以下两行：

source [find interface/stlink-hla.cfg]
transport select hla_swd

NXP S32 调试探针

NXP S32 Debug Probe 通过 USB 或以太网远程连接到开发者工作站，并通过标准调试端口调试 NXP S32 目标系统。

NXP S32 调试探针设计为与 NXP S32 Design Studio（S32DS）以及 NXP 汽车级微控制器和处理器配合使用。烧录固件之前，请按照 NXP S32 调试探针主机工具 中的说明安装调试主机工具。

Black Magic Probe

Black Magic Probe 是一款开源调试硬件，设计为与 Black Magic Debug 固件配合使用。该固件集成了 GDB 服务器，因此可以直接从 gdb 连接到目标器件。

部分基于 STM32F103 的开发板可以运行 Black Magic Debug 固件。参见 Black Magic Debug supported hardware。
