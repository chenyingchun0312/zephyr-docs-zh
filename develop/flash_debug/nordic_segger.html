Nordic nRF5x Segger J-Link

概述

所有 Nordic nRF5x 开发套件、预览版开发套件和 Dongle 都配备了一颗调试 IC（Atmel ATSAM3U2C），它提供以下功能：

  • Segger J-Link 固件和桌面工具

  • nRF5x IC 的 SWD 调试

  • 用于拖放式镜像烧录的大容量存储设备

  • 桥接到 nRF5x UART 外设的 USB CDC ACM 串口

  • Segger RTT 控制台

  • Segger Ozone 调试器

安装 Segger J-Link 软件

按以下步骤安装 J-Link 软件和文档包：

  1. 从 J-Link Software and documentation pack [9] 网站下载相应的软件包

  2. 根据你的平台，安装该软件包或运行安装程序

  3. 连接支持 J-Link 的开发板（如 nRF5x DK、PDK 或 Dongle）时，应当会出现一个对应 USB 大容量存储设备的驱动器以及一个串口

安装 nRF5x 命令行工具

nRF5x 命令行工具可以让你从命令行控制 nRF5x 器件，包括复位器件、擦除或编程 Flash 存储器等。

要安装这些工具，请访问 nRF5x Command-Line Tools [1] 并选择你的操作系统。

安装后，确保 nrfjprog 位于可执行文件路径中，以便在任何位置调用它。

烧录

按照说明安装 Segger J-Link 软件和 nRF5x 命令行工具后，按以下步骤将编译好的 Zephyr 镜像烧录到 Flash：

  • 将 micro-USB 线连接到 nRF5x 开发板和你的计算机

  • 擦除 nRF5x IC 中的 Flash 存储器：

nrfjprog --eraseall -f nrf5<x>

其中 <x> 对于基于 nRF51 的开发板为 1，对于基于 nRF52 的开发板为 2

  • 从你选择的示例文件夹烧录 Zephyr 镜像：

nrfjprog --program outdir/<board>/zephyr.hex -f nrf5<x>

其中：<board> 是构建时在 BOARD 指令中使用的开发板名称（例如 nrf52dk/nrf52832），<x> 对于基于 nRF51 的开发板为 1，对于基于 nRF52 的开发板为 2

  • 复位并启动 Zephyr：

nrfjprog --reset -f nrf5<x>

其中 <x> 对于基于 nRF51 的开发板为 1，对于基于 nRF52 的开发板为 2

USB CDC ACM 串口设置

重要提示：nRF5x 开发板上 Segger J-Link 固件的一个问题，可能导致某些机器上 USB CDC ACM 串口出现数据丢失和/或损坏。要规避此问题，请按照 禁用大容量存储设备功能 中的说明禁用开发板上的大容量存储设备。

Windows

串口会显示为 COMxx。只需在设备管理器中查看“端口 (COM 和 LPT)”部分即可。

GNU/Linux

串口会显示为 /dev/ttyACMx。默认情况下，并非所有用户都能访问该端口。输入以下命令将你的用户添加到 dialout 组，使其可以访问串口。注意需要重新登录才能生效。

sudo usermod -a -G dialout `whoami`

新版本的 ModemManager send AT commands to TTY-like devices [7]，其中也包括 Nordic 开发套件。这会使你在几秒钟内无法使用串口，并且如果应用程序从 UART 读取数据，可能导致其行为异常。运行应用程序之前，可以运行以下命令临时禁用 ModemManager：

systemctl stop ModemManager.service
systemctl disable ModemManager.service

也可以运行以下命令 blocklist Segger devices by editing udev rules [8]，让 ModemManager 忽略它们：

sudo sh -c 'echo "ATTRS{idVendor}==\"1366\", ENV{ID_MM_DEVICE_IGNORE}=\"1\" " \
  >> /etc/udev/rules.d/99-segger-modemmanager-blocklist.rules'
sudo service udev restart

预计 ModemManager 1.8 和新版 Segger IMCU 固件会修复此问题。

Apple macOS (OS X)

串口会显示为 /dev/tty.usbmodemXXXX。

禁用大容量存储设备功能

由于 Segger J-Link 固件中的一个已知问题，取决于你的操作系统及其版本，如果通过 USB CDC ACM 串口传输大于 64 字节的数据包，可能会遇到数据损坏或丢失。在 GNU/Linux 和 macOS（OS X）上都观察到了这种情况。

为避免此问题，只需打开以下程序禁用大容量存储设备：

  • 在 GNU/Linux 或 macOS（OS X）上，从终端打开 JLinkExe

  • 在 Microsoft Windows 上，打开“JLink Commander”应用程序

然后输入以下内容：

MSDDisable

最后拔下开发板再重新插上。大容量存储设备应当不会再出现，此时应该可以通过虚拟串口发送长数据包了。更多信息请参阅 Segger 的 Segger SAM3U Wiki [2]。

RTT 控制台

Segger 的 J-Link 支持 Real-Time Tracing (RTT) [3]，这项技术可以在目标（nRF5x 开发板）与开发计算机之间建立终端连接（包括输入和输出），用于日志记录和输入。Zephyr 在 nRF5x 目标上支持 RTT；如果 UART（通过 USB CDC ACM）已被用于日志之外的用途（例如 hci_uart 应用程序中的 HCI 通信），RTT 会非常有用。要使用 RTT，首先需要在 .conf 文件中添加以下几行来启用它：

CONFIG_USE_SEGGER_RTT=y
CONFIG_RTT_CONSOLE=y

警告

还有一个 HAS_SEGGER_RTT 符号，表示平台支持 SEGGER J-Link RTT。该符号由 SoC 的 Kconfig 文件自动设置。不要将它与 USE_SEGGER_RTT 混淆。

USE_SEGGER_RTT 依赖于 HAS_SEGGER_RTT。

如果没有 RTT 输出，并且你运行的示例或应用程序默认启用了与 RTT 冲突的其他控制台，则可能需要禁用这些控制台。例如，要禁用 UART 控制台，请在 .conf 文件中添加：

CONFIG_UART_CONSOLE=n

启用 RTT 并完成编译和烧录后，可以按以下方式显示 RTT 控制台消息：

Windows

  • 打开“J-Link RTT Viewer”应用程序

  • 选择以下选项：

    • Connection：USB

    • Target Device：从列表中选择你的 IC

    • Target Interface and Speed（目标接口与速度）：SWD，4000 KHz

    • RTT Control Block（RTT 控制块）：Auto Detection（自动检测）

GNU/Linux 和 macOS（OS X）

  • 从终端打开 JLinkRTTLogger

  • 选择以下选项：

    • Device Name：使用你的 IC 的完整器件名称

    • Target Interface（目标接口）：SWD

    • Interface Speed（接口速度）：4000 KHz

    • RTT Control Block address：自动检测

    • RTT Channel name or index（RTT 通道名称或索引）：0

    • Output file：文件名，或 /dev/stdout 以直接在终端上显示

Python 查看器

Python 版 RTT 查看器工具可在 GitHub 仓库 pyrtt-viewer [4] 中找到。

Segger Ozone

Segger J-Link 兼容可视化调试器 Segger Ozone [5]，可从这里获取：

  • Segger Ozone Download [6]

下载后，可以按如下方式安装和配置：

  • Target Device：从列表中选择你的 IC

  • Target Interface（目标接口）：SWD

  • Target Interface Speed（目标接口速度）：4 MHz

  • Host Interface（主机接口）：USB

配置完成后，可以通过 File->Open 菜单打开构建文件夹中的 zephyr.elf 文件。
