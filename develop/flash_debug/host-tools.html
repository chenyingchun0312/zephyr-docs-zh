烧录与调试主机工具

本指南介绍可以在主机工作站上运行、用于烧录和调试 Zephyr 应用程序的软件工具。

Zephyr 的 west 工具在其 flash、debug、debugserver 和 attach 命令中内置了对所有这些工具的支持，前提是你的开发板硬件支持它们，并且 Zephyr 开发板目录中的 board.cmake 文件正确声明了这些支持。关于这些命令的更多信息，请参阅 构建、烧录和调试。

Black Magic Probe

Black Magic Probe（BMP）是一款开源调试硬件，其固件中集成了 GDB 调试服务器功能。它不需要 GDB 服务器程序，因此也没有对应的主机工具程序。

更多详细信息，包括使用说明和支持的目标，请参阅 Black Magic Probe。

SAM 引导助手（SAM Boot Assistant，SAM-BA）

Atmel SAM Boot Assistant（Atmel SAM-BA）支持通过 USB 或 UART 主机进行在系统编程（ISP），无需任何外部编程接口。Zephyr 允许用户使用 west 开发和烧录支持 SAM-BA 的开发板。Zephyr 支持带或不带 ROM 引导加载程序的器件，并同时支持 Arduino 和 Adafruit 的扩展。完整支持自 Zephyr SDK 0.12.0 起引入。

烧录开发板的典型命令如下：

west flash [ -r bossac ] [ -p /dev/ttyX ] [ --erase ]

备注

默认情况下，使用 bossac 烧录时只会擦除包含所烧录应用程序的 Flash 页，其他页保持不变。如果希望在烧录时擦除目标的整个 Flash，请在烧录时传入 --erase 参数。

各类器件的 Flash 配置：

这类器件不需要任何特殊配置。构建应用程序后，只需运行 west flash 即可烧录开发板。

对于这类器件，用户应当：

  1. 定义容纳引导加载程序和应用程序镜像所需的 Flash 分区；详见 Flash 映射（Flash map）。

  2. 在开发板的 .defconfig 文件中将 Kconfig 选项 CONFIG_USE_DT_CODE_PARTITION 设置为 y，指示构建系统使用这些分区进行代码重定位。该选项也可以在 prj.conf 或任何其他 Kconfig 片段中设置。

  3. 构建 SAM-BA 引导加载程序并将其烧录到器件上。

对于这类器件，用户应当：

  1. 定义容纳引导加载程序和应用程序镜像所需的 Flash 分区；详见 Flash 映射（Flash map）。

  2. 在开发板的 .defconfig 文件中将 Kconfig 选项 CONFIG_BOOTLOADER_BOSSA 设置为 y。这会自动选中 Kconfig 选项 CONFIG_USE_DT_CODE_PARTITION，指示构建系统使用这些分区进行代码重定位。开发板的 .defconfig 文件应将 Kconfig 选项 CONFIG_BOOTLOADER_BOSSA_ARDUINO、CONFIG_BOOTLOADER_BOSSA_ADAFRUIT_UF2 或 CONFIG_BOOTLOADER_BOSSA_LEGACY 设置为 y，以选择正确的兼容 SAM-BA 引导加载程序模式。这些选项也可以在 prj.conf 或任何其他 Kconfig 片段中设置。

  3. 构建 SAM-BA 引导加载程序并将其烧录到器件上。

备注

Kconfig 选项 CONFIG_BOOTLOADER_BOSSA_LEGACY 应作为最后手段使用。请先尝试按“不带 ROM 引导加载程序的器件”进行配置。

典型的 Flash 布局与配置

对于驻留在 Flash 上的引导加载程序，设备树分区布局是必需的。对于带 ROM 引导加载程序的器件，当应用程序使用存储分区或其他非应用程序分区时，分区布局也是必需的。在这种特殊情况下，应省略 boot 分区，并且 code_partition 应从偏移量 0 开始。无论何种情况，都必须定义大小互不重叠的分区。

不带 ROM 引导加载程序的器件，其典型 Flash 布局如下：

/ {
        chosen {
                zephyr,code-partition = &code_partition;
        };
};

&flash0 {
        partitions {
                #address-cells = <1>;
                #size-cells = <1>;
                ranges;

                boot_partition: partition@0 {
                        compatible = "zephyr,mapped-partition";
                        label = "sam-ba";
                        reg = <0x00000000 0x2000>;
                        read-only;
                };

                code_partition: partition@2000 {
                        compatible = "zephyr,mapped-partition";
                        label = "code";
                        reg = <0x2000 0x3a000>;
                        read-only;
                };

                /*
                * The final 16 KiB is reserved for the application.
                * Storage partition will be used by FCB/LittleFS/NVS
                * if enabled.
                */
                storage_partition: partition@3c000 {
                        compatible = "zephyr,mapped-partition";
                        label = "storage";
                        reg = <0x0003c000 0x00004000>;
                };
        };
};

带 ROM 引导加载程序和存储分区的器件，其典型 Flash 布局如下：

/ {
        chosen {
                zephyr,code-partition = &code_partition;
        };
};

&flash0 {
        partitions {
                #address-cells = <1>;
                #size-cells = <1>;
                ranges;

                code_partition: partition@0 {
                        compatible = "zephyr,mapped-partition";
                        label = "code";
                        reg = <0x0 0xF0000>;
                        read-only;
                };

                /*
                * The final 64 KiB is reserved for the application.
                * Storage partition will be used by FCB/LittleFS/NVS
                * if enabled.
                */
                storage_partition: partition@F0000 {
                        compatible = "zephyr,mapped-partition";
                        label = "storage";
                        reg = <0x000F0000 0x00100000>;
                };
        };
};

启用 SAM-BA 运行器（runner）

要让 Zephyr west 工具使用 SAM-BA 引导加载程序，board.cmake 文件中必须包含 include(${ZEPHYR_BASE}/boards/common/bossac.board.cmake) 条目。注意，Zephyr 工具接受更多条目以定义多个运行器。默认情况下，使用 west flash 命令时会选择第一个。其余运行器可以通过传入 runner 选项使用，例如 west flash -r bossac。

更多实现细节请参阅 支持的开发板和扩展板 文档。作为快速参考，可以查看以下三个开发板文档页面：

  • SAM4E Xplained Pro（ROM 引导加载程序）

  • Feather M0 Basic Proto（Adafruit UF2 引导加载程序）

  • Arduino Nano 33 IOT（Arduino 引导加载程序）

  • Arduino Nano 33 BLE (Sense)（Arduino 旧版引导加载程序）

在 Windows 原生环境中启用 BOSSAC [实验性]

Zephyr SDK 中的 bossac 目前仅支持 Linux 和 macOS。可以使用 BOSSA official releases 中的 bossac 版本获得 Windows 支持。使用默认选项安装后，必须将 bossac.exe 添加到 Windows 的 PATH 中。也可以通过传入 --bossac 选项使用特定的 bossac 可执行文件，如下所示：

west flash -r bossac --bossac="C:\Program Files (x86)\BOSSA\bossac.exe" --bossac-port="COMx"

备注

目前不支持 WSL。

LinkServer 调试主机工具

Linkserver 是一个用于启动和管理 NXP 调试探针 GDB 服务器的实用程序，同时提供命令行目标 Flash 编程功能。Linkserver 可以与 NXP MCUXpresso for Visual Studio Code 实现配合使用，也可以用于基于 GNU 工具的自定义调试配置，或作为持续集成和测试的无头（headless）方案的一部分。LinkServer 可以与 NXP 的 MCU-Link、LPC-Link2、基于 LPC11U35 和基于 OpenSDA 的独立或板载调试探针配合使用。

NXP 建议使用 NXP 的 MCUXpresso Installer 安装 LinkServer。这种方式还会安装支持下列调试探针的工具，包括 NXP 的 MCU-Link 和 LPCScrypt 工具。

LinkServer 兼容以下调试探针：

  • LPC-LINK2 CMSIS DAP 板载调试探针

  • MCU-Link CMSIS-DAP 板载调试探针

  • OpenSDA DAPLink 板载调试探针

要在 west 命令中使用 LinkServer，应将其安装文件夹添加到 PATH 环境变量 中。需要添加的默认安装路径为：

/usr/local/LinkServer

/Applications/LinkServer_<version>

c:\nxp\LinkServer_<version>

支持的 west 命令：

  1. flash

  2. debug

  3. debugserver

  4. attach

注意：

  1. 可以用 LinkServer 列出探针：

LinkServer probes

2. With multiple debug probes attached to the host, use the LinkServer west runner --probe option to pass the probe index.

west flash --runner=linkserver --probe=3

  1. 可以通过 LinkServer west 运行器的 '--override' 选项覆盖器件专用设置。该选项可以多次使用。格式由 LinkServer 规定，例如：

west flash --runner=linkserver --override /device/memory/5/flash-driver=MIMXRT500_SFDP_MXIC_OSPI_S.cfx

  1. LinkServer 不会在复位处理函数处设置隐式断点。如果希望从应用程序开头单步执行，需要手动在 main 或复位处理函数处添加断点。

  2. 该断点以及任何其他 GDB 命令都可以通过 --gdb-init 自动设置，该运行器会在 west debug 和 west attach 中将其追加给 GDB 客户端，例如：

    west debug --runner=linkserver --gdb-init 'b main'

    参见 传递额外的 GDB 命令。

J-Link 调试主机工具

Segger 为 Linux、macOS 和 Windows 操作系统提供了一套调试主机工具：

  • J-Link GDB Server：GDB 远程调试

  • J-Link Commander：命令行控制与 Flash 编程

  • RTT Viewer：RTT 终端输入与输出

  • SystemView：实时事件可视化与记录

这些调试主机工具兼容以下调试探针：

  • LPC-Link2 J-Link 板载调试探针

  • OpenSDA J-Link 板载调试探针

  • MCU-Link JLink 板载调试探针

  • J-Link 外部调试探针

  • ST-LINK/V2-1 板载调试探针

检查你的 SoC 是否列在 J-Link Supported Devices 中。

下载并安装 J-Link Software and Documentation Pack，以获取 J-Link GDB Server 和 Commander，并安装相关的 USB 设备驱动。RTT Viewer 和 SystemView 可以单独下载，但并非必需。

注意，J-Link GDB 服务器尚不支持 Zephyr RTOS 感知。

传递额外的 GDB 命令

jlink 运行器接受 --gdb-init 选项，用于向 west debug 和 west attach 启动的 GDB 客户端追加命令。该选项可以多次给出，命令按给出的顺序执行，排在运行器发送给 GDB 的所有内容之后、目标恢复运行之前。由于这些命令只是被追加，它们无法改变运行器自身的连接、加载和复位流程。west flash、west reset、west rtt 和 west debugserver 不受影响。

例如，要在调试会话期间启用 J-Link 半主机（semihosting）：

west debug -r jlink --gdb-init 'monitor semihosting enable' \
  --gdb-init 'monitor semihosting basedir .'

将这些命令添加到开发板的 board.cmake 中，即可使其成为该开发板的默认设置：

board_runner_args(jlink "--gdb-init=monitor semihosting enable")

注意，--gdb-init 只作用于 GDB 客户端。J-Link GDB 服务器本身的选项通过 --tool-opt 传递，烧录时运行的 J-Link Commander 命令通过 --pre-script-cmd 传递。

linkserver、openocd 和 intel_cyclonev 运行器也接受同一选项。该选项作用于哪些命令、命令插入在何处，由各运行器自行决定。

OpenOCD 调试主机工具

OpenOCD 是一个社区开源项目，为众多 SoC 提供 GDB 远程调试和 Flash 编程支持。Zephyr SDK 中包含一个增加了 Zephyr RTOS 感知功能的分支版本；此外，也可以参阅 Getting OpenOCD，了解从官方仓库下载 OpenOCD 的方式。

这些调试主机工具兼容以下调试探针：

  • OpenSDA DAPLink 板载调试探针

  • J-Link 外部调试探针

  • ST-LINK/V2-1 板载调试探针

检查你的 SoC 是否列在 OpenOCD Supported Devices 中。

备注

在 Linux 上，可以通过 Zephyr SDK 获取 openocd。Windows 用户应按以下步骤安装 openocd：

  • 从这里下载 Windows 版 openocd：OpenOCD Windows

  • 将 bin 和 share 目录复制到 C:\Program Files\OpenOCD\

  • 将 C:\Program Files\OpenOCD\bin 添加到 'PATH' 环境变量中

pyOCD 调试主机工具

pyOCD 是 Arm 推出的开源项目，为 Arm Cortex-M SoC 提供 GDB 远程调试和 Flash 编程支持。它通过 PyPi 分发，在完成入门指南中的 获取 Zephyr 并安装 Python 依赖项 步骤时就会安装。pyOCD 支持 Zephyr RTOS 感知。

这些调试主机工具兼容以下调试探针：

  • LPC-LINK2 CMSIS DAP 板载调试探针

  • MCU-Link CMSIS-DAP 板载调试探针

  • OpenSDA DAPLink 板载调试探针

  • ST-LINK/V2-1 板载调试探针

检查你的 SoC 是否列在 pyOCD Supported Devices 中。

Lauterbach TRACE32 调试主机工具

Lauterbach TRACE32 是一条微处理器开发工具、调试器和实时跟踪器产品线，支持在多种内核架构（包括 Arm Cortex-A/-R/-M、RISC-V、Xtensa 等）上通过 JTAG、SWD、NEXUS 或 ETM 进行调试和跟踪。Zephyr 允许用户使用 west 开发和烧录支持 Lauterbach TRACE32 的开发板。

该运行器是对 TRACE32 软件的封装，允许 Zephyr 开发板针对所支持的各个命令执行自定义启动脚本（Practice Script），并可从 CMake 传入额外参数。每个命令执行哪些操作，由使用该运行器的开发板自行定义。

安装 Lauterbach TRACE32 软件

从 Lauterbach TRACE32 download website 下载 Lauterbach TRACE32 软件（需要注册），并按照 Lauterbach TRACE32 Installation Guide 中描述的步骤进行安装。

烧录与调试

将 环境变量 T32_DIR 设置为 TRACE32 系统目录。然后按照 构建、烧录和调试 中的说明，执行 west flash 或 west debug 命令来烧录或调试 Zephyr 应用程序。debug 命令会启动 TRACE32 图形界面以调试 Zephyr 应用程序，而 flash 命令会隐藏图形界面，在后台执行所有操作。

默认情况下，t32 运行器会使用位于 TRACE32 系统目录中名为 config.t32 的默认配置文件启动 TRACE32。要使用其他配置文件，请向运行器传入参数 --config CONFIG，例如：

west flash --config myconfig.t32

更多选项请运行 west flash --context -r t32 查看用法。

Zephyr RTOS 感知

要启用 Zephyr RTOS 感知，请按照 Lauterbach TRACE32 Zephyr OS Awareness Manual 中描述的步骤操作。

NXP S32 调试探针主机工具

NXP S32 调试探针 设计为与 NXP S32 Design Studio for S32 Platform 配合使用。

下载 NXP S32 Design Studio for S32 Platform（需要注册），并按照 S32 Design Studio for S32 Platform Installation User Guide 获取所需的调试主机工具和相关的 USB 设备驱动。

注意，NXP S32 GDB 服务器对 Zephyr RTOS 感知的支持取决于目标器件。更多信息请查阅产品发布说明。

支持的 west 命令：

  1. debug

  2. debugserver

  3. attach

基本用法

开始之前，将 NXP S32 Design Studio 的安装目录添加到系统的 PATH 环境变量 中。也可以在每次调用运行器时通过 --s32ds-path 传入该路径，如下所示：

west debug --s32ds-path=/opt/NXP/S32DS.3.6

west debug --s32ds-path=C:\NXP\S32DS.3.6

如果主机通过 USB 连接了多个 S32 调试探针，运行器会在继续之前通过命令行提示让用户选择其中一个。也可以在调用运行器时通过 --dev-id=<connection-string> 指定探针的连接字符串。关于如何构造连接字符串，请查阅 NXP S32 调试探针用户手册。例如，使用序列号为 00:04:9f:00:ca:fe 的探针时：

west debug --dev-id='s32dbg:00:04:9f:00:ca:fe'

可以通过 --tool-opt 向调试主机工具传递额外选项。执行 debug 或 attach 命令时，这些工具选项只会传给 GDB 客户端。执行 debugserver 时，这些工具选项会传给 GDB 服务器。例如，将 Zephyr 应用程序加载到 SRAM，然后分离调试会话：

west debug --tool-opt='--batch'

要求

  • S32 Design Studio 版本：3.6.0 或更高版本。

  • S32DebugProbe OS（固件）：1.1.0 或更高版本。

S32 调试探针 OS 升级步骤

要升级 S32DebugProbe 的 OS，请参阅 S32 Debug Probe User Guide 中的“Reprogramming S32 Debug Probe Firmware Images”一章。

probe-rs 调试主机工具

probe-rs 是一个用 Rust 编写的开源嵌入式工具包。它开箱即用地支持多种调试探针，包括 CMSIS-DAP、ST-Link、SEGGER J-Link、FTDI 以及 ESP32 器件上内置的 USB-JTAG 接口。

更多设置细节请查看 probe-rs Installation。

检查你的 SoC 是否列在 probe-rs Supported Devices 中。

Renesas Flash Programmer（RFP）主机工具

Renesas 提供 Renesas Flash Programmer，作为使用 Renesas 标准启动固件的 Renesas 开发板的官方编程工具。它提供图形界面和命令行两种形式。

对于配置了 rfp west 运行器的开发板，可以方便地使用 RFP 命令行工具烧录 Zephyr。

支持的 west 命令：

  1. flash

下载后，如果 rfp-cli 不在系统 PATH 中，可以在烧录时传入 rfp-cli 的位置：

west flash --rfp-cli ~/Downloads/RFP_CLI_Linux_V31800_x64/linux-x64/rfp-cli

STM32CubeCLT 烧录与调试主机工具

STMicroelectronics 提供 STM32CubeCLT 作为官方的一体化工具集，兼容 Linux®、macOS® 和 Windows®，允许在第三方开发环境中使用 STMicroelectronics 的专有工具。

它尤其提供了一个 GDB 调试服务器（ST-LINK GDB Server），借助板载或外部 ST-LINK 调试探针，可用于在 STM32 开发板上调试应用程序。

它兼容以下调试探针：

  • ST-LINK/V2-1 板载调试探针

  • 独立的 ST-LINK-V2、ST-LINK-V3 和 STLINK-V3PWR 探针

安装 STM32CubeCLT

获取 ST-LINK GDB Server 最简单的方法是从 STMicroelectronics 网站安装 STM32CubeCLT。需要提供有效的电子邮件地址以接收下载链接。

基本用法

ST-Link GDB Server 可以通过 west attach、west debug 或 west debugserver 命令用于调试 Zephyr 应用程序。

west debug --runner stlink_gdbserver

备注

STM32CubeCLT 安装中包含的 STM32CubeProgrammer 版本也可用于烧录应用程序。为此，应使用专门的 STM32CubeProgrammer 运行器，而不是 stlink_gdbserver，如下例所示：

west flash --runner stm32cubeprogrammer

STM32CubeProgrammer 烧录主机工具

STMicroelectronics 提供 STM32CubeProgrammer（STM32CubeProg）作为 STM32 开发板的官方编程工具，支持 Linux®、macOS® 和 Windows® 操作系统。

它提供了一个易用且高效的环境，可通过调试接口（JTAG 和 SWD）和引导加载程序接口（UART 和 USB DFU、I2C、SPI 以及 CAN）读取、写入和校验器件存储器。

它提供丰富的功能，用于编程 STM32 内部存储器（如 Flash、RAM 和 OTP）以及外部存储器。

它还支持选项字节的编程和上传、编程内容校验，以及通过脚本实现编程自动化。

它提供 GUI（图形用户界面）和 CLI（命令行界面）两个版本。

它兼容以下调试探针：

  • ST-LINK/V2-1 板载调试探针

  • J-Link 外部调试探针

  • 独立的 ST-LINK-V2、ST-LINK-V3 和 STLINK-V3PWR 探针

安装 STM32CubeProgrammer

获取 STM32CubeProgrammer 最简单的方法是从 STMicroelectronics 网站下载。需要提供有效的电子邮件地址以接收下载链接。

此外，它也可以作为 STM32CubeCLT 的一部分安装，后者是一个支持多操作系统的一体化命令行工具集，还包含 GDB 调试器客户端和服务器。

如果系统上已安装 STM32CubeIDE，则 STM32CubeProg 已经存在。

基本用法

STM32CubeProgrammer 被设置为 Zephyr 支持的所有在维 STM32 开发板的默认 west 运行器。可以通过 west flash 命令使用它烧录 Zephyr 应用程序。

west flash --runner stm32cubeprogrammer

关于通过 GUI 或 CLI 的高级用法，请查阅 STM32CubeProgrammer User Manual。

XSDB 烧录与调试主机工具

AMD XSDB 实用程序（Xilinx Software Command-line Tool for Debug）是用于编程和调试众多 AMD 自适应 SoC 及 FPGA 平台的命令行工具。它 不 包含在 Zephyr SDK 中：请安装 AMD Vitis（或适用于你平台的同等 AMD 工具链发行版），并确保 xsdb 可执行文件位于系统 PATH 中。

选择 xsdb west 运行器的开发板通常会在开发板定义旁附带一个开发板专用的 support/xsdb.cfg。所需的启动产物（PDI、比特流、FSBL 等）请参阅开发板的文档。

支持的 west 命令包括 flash、debug 和 debugserver。

对于该运行器，west debug 和 west debugserver 都会启动同一个原生 XSDB 交互式会话。与基于 GDB 的运行器（其 debugserver 会为 IDE 启动远程桩程序）不同，xsdb 运行器总是直接启动 XSDB，通过开发板的 xsdb.cfg 加载应用程序，然后停留在 XSDB 提示符下。

west flash --runner xsdb

west debug --runner xsdb

west debugserver --runner xsdb

备注

这与本章中其他专有主机工具（例如 J-Link 或 STM32CubeCLT）属于同一类依赖：Zephyr 通过 west 运行器与该工具集成；获取工具链及其许可证由用户自行负责。

UF2 上传工具

uf2 运行器支持使用 UF2（USB Flashing Format）烧录部分开发板。UF2 是一种用户友好的文件格式，专为通过 USB 大容量存储设备进行拖放式编程而设计。

它要求目标器件进入一种特殊的引导加载程序模式，在该模式下，器件在主机上显示为 USB 大容量存储设备。进入该模式后，将 .uf2 文件复制到挂载的卷即可上传应用程序镜像。

west flash --runner uf2

Realtek 替代烧录工具（rtkprog）

rtkprog 是一个开源实现，实现了通过 UART 烧录 Realtek Bee 系列 SoC 所需的协议。

west flash --runner rtkprog

Realtek Bee 烧录工具（MPCli）主机工具

Realtek 提供 Realtek Flash Programmer (MPCli) 作为 Bee 系列的官方编程工具，支持 Linux、macOS 和 Windows 操作系统。MPCli 支持通过 UART 接口进行在系统编程（ISP），无需外部编程硬件。大多数官方 Bee 系列评估板都内置了 UART 转 USB 转换器，开箱即可用于编程和日志输出。

下载 MPCli 压缩包后，将其解压并选择与你的操作系统兼容的版本。然后，将包含 mpcli 可执行文件的目录添加到系统的 PATH 环境变量 中。

开始之前，请确保开发板处于下载模式。请参阅开发板文档：Realtek Supported Boards

west flash [--runner mpcli] --port /dev/ttyX

IAR EW 与 C-Spy 主机工具

IAR 提供 Embedded Workbench 和 CSpyBat 用于调试和烧录。iar 运行器适用于 EWARM 10.10 或更新版本。
