Coccinelle

Coccinelle 是一款用于模式匹配和文本转换的工具，在内核开发中有许多用途，包括应用复杂的、遍及整个源码树的补丁，以及检测有问题的编程模式。

备注

支持 Linux 和 macOS 开发环境，不支持 Windows。

获取 Coccinelle

内核中包含的语义补丁使用了 Coccinelle 1.0.0-rc11 及以上版本提供的特性和选项。使用更早的版本会失败，因为 Coccinelle 文件和 coccicheck 所用的选项名称已经更新。

许多发行版的软件包管理器都提供 Coccinelle，例如：

  • Debian

  • Fedora

  • Ubuntu

  • OpenSUSE

  • Arch Linux

  • NetBSD

  • FreeBSD

某些发行版的软件包已经过时，建议使用 Coccinelle 主页 https://coccinelle.lip6.fr/ 上发布的最新版本

或者从 GitHub 获取：

https://github.com/coccinelle/coccinelle

获取后，运行以下命令：

./autogen
./configure
make

以普通用户身份运行，然后使用以下命令安装：

sudo make install

从源码构建的更详细安装说明见：

https://github.com/coccinelle/coccinelle/blob/master/install.txt

补充文档

关于语义补丁语言（SmPL）的语法文档，请参阅：

https://coccinelle.gitlabpages.inria.fr/website/documentation.html

在 Zephyr 上使用 Coccinelle

coccicheck 检查器是 Coccinelle 基础设施的前端，有多种模式：

定义了四种基本模式：patch、report、context 和 org。通过设置 --mode=<mode> 或 -m=<mode> 指定要使用的模式。

  • patch 在可能的情况下给出修复建议。

  • report 生成如下格式的列表：file:line:column-column: message

  • context 以类似 diff 的样式高亮显示相关行及其上下文。相关行以 - 标示。

  • org 以 Emacs 的 Org mode 格式生成报告。

注意，并非所有语义补丁都实现了所有模式。为了便于使用 Coccinelle，默认模式为 report。

另外两种模式提供了上述模式的一些常用组合。

  • chain 按上述顺序依次尝试各模式，直到有一种成功为止。

  • rep+ctxt 依次运行 report 模式和 context 模式。它应与按文件检查代码的 C 选项（稍后介绍）一起使用。

示例

要为每个语义补丁生成报告，请运行以下命令：

./scripts/coccicheck --mode=report

要生成补丁，请运行：

./scripts/coccicheck --mode=patch

coccicheck 目标会将 scripts/coccinelle 各子目录中所有可用的语义补丁应用到整个源码树。

对于每个语义补丁，都会给出一条建议的提交消息。它描述了该语义补丁所检查的问题，并包含对 Coccinelle 的引用。

与任何静态代码分析器一样，Coccinelle 也会产生误报。因此，必须仔细检查报告，并评审补丁。

要启用详细消息，请设置 --verbose=1 选项，例如：

./scripts/coccicheck --mode=report --verbose=1

Coccinelle 并行化

默认情况下，coccicheck 会尽可能并行运行。要更改并行度，请设置 --jobs=<number> 选项。例如，要在 4 个 CPU 上运行：

./scripts/coccicheck --mode=report --jobs=4

从 Coccinelle 1.0.2 开始，Coccinelle 使用 Ocaml parmap 实现并行化；如果检测到支持该功能，你将受益于 parmap 并行化。

启用 parmap 时，coccicheck 会使用 --chunksize 1 参数启用动态负载均衡，确保逐个向线程分派工作，从而避免大部分工作只由少数几个线程完成的情况。借助动态负载均衡，如果某个线程提前完成，就会继续给它分派更多工作。

启用 parmap 时，如果 Coccinelle 中发生错误，该错误值会被传回，coccicheck 命令的返回值会捕获这个返回值。

使用单个语义补丁运行 Coccinelle

可以使用 --cocci 选项检查单个语义补丁。此时，该变量必须初始化为要应用的语义补丁的名称。

例如：

./scripts/coccicheck --mode=report --cocci=<example.cocci>

或者：

./scripts/coccicheck --mode=report --cocci=./path/to/<example.cocci>

控制 Coccinelle 处理哪些文件

默认情况下会检查整个源码树。

要将 Coccinelle 应用到特定目录，请将该目录的路径作为参数传入。

例如，要检查 drivers/usb/，可以这样写：

./scripts/coccicheck --mode=patch drivers/usb/

report 模式为默认模式。可以使用上文介绍的 --mode=<mode> 选项选择其他模式。

调试 Coccinelle SmPL 补丁

最好使用 coccicheck，因为它会在 spatch 命令行中提供与编译内核时所用选项相匹配的包含选项。可以通过 verbose 选项了解这些选项是什么，然后手动运行添加了调试选项的 Coccinelle。

另外，也可以通过让 stderr 重定向到 stderr 来调试针对 SmPL 补丁运行的 Coccinelle。默认情况下 stderr 被重定向到 /dev/null；如果想捕获 stderr，可以为 coccicheck 指定 --debug=file.err 选项。例如：

rm -f cocci.err
./scripts/coccicheck --mode=patch --debug=cocci.err
cat cocci.err

只有使用 Coccinelle >= 1.0.2 时才支持调试。

附加标志

可以通过 SPFLAGS 变量向 spatch 传递附加标志。之所以可行，是因为当选项冲突时，Coccinelle 会以最后给出的标志为准。

./scripts/coccicheck --sp-flag="--use-glimpse"

Coccinelle 也支持 idutils，但要求 coccinelle >= 1.0.6。如果未指定 ID 文件，coccinelle 会假定你的 ID 数据库文件是内核顶层目录下的 .id-utils.index 文件；coccinelle 附带一个脚本 scripts/idutils_index.sh，可以用以下命令创建该数据库：

mkid -i C --output .id-utils.index

如果你的数据库文件名不同，也可以直接用这个名称创建符号链接。

./scripts/coccicheck --sp-flag="--use-idutils"

也可以显式指定数据库文件名，例如：

./scripts/coccicheck --sp-flag="--use-idutils /full-path/to/ID"

有时 coccinelle 会因定义不充分而无法识别或解析复杂的宏变量。因此，为了使其可解析，我们使用 ---macro-file-builtins <headerfile.h> 标志显式提供该复杂宏的原型。

<headerfile.h> 应包含该复杂宏的完整原型，以便 spatch 引擎从中提取转换过程中所需的类型信息。

例如：

coccinelle 无法识别 Z_SYSCALL_HANDLER。因此，我们将它的原型放到一个头文件中，例如 mymacros.h。

$ cat mymacros.h
#define Z_SYSCALL_HANDLER int xxx

然后在转换时传入头文件 mymacros.h：

./scripts/coccicheck --sp-flag="---macro-file-builtins mymacros.h"

更多 spatch 选项请参阅 spatch --help。

注意，--use-glimpse 和 --use-idutils 选项需要借助外部工具为代码建立索引，因此它们默认都不启用。不过，如果用其中某个工具为代码建立索引，并视所用的 cocci 文件而定，spatch 处理整个代码库的速度可以更快。

SmPL 补丁专用选项

SmPL 补丁可以对传给 Coccinelle 的选项有自己的要求。可以在 SmPL 补丁的开头提供 SmPL 补丁专用选项，例如：

// Options: --no-includes --include-headers

提议新的语义补丁

内核开发者可以提议并提交新的语义补丁。为清晰起见，它们应组织在 scripts/coccinelle/ 的各子目录中。

cocci 脚本应具有以下特性：

  • 该脚本 必须 具有 report 模式。

  • 开头几行应使用 /// 注释说明脚本的用途。通常，在基于该脚本提议补丁时，这段消息会被用作提交日志。

示例

/// Use ARRAY_SIZE instead of dividing sizeof array with sizeof an element

  • 关于该脚本的更详细信息，例如特殊情况或误报（如有），可以使用 //# 注释列出。

示例

//# This makes an effort to find cases where ARRAY_SIZE can be used such as
//# where there is a division of sizeof the array by the sizeof its first
//# element or by any indexed element or the element type. It replaces the
//# division of the two sizeofs by ARRAY_SIZE.

  • Confidence：用于说明脚本准确程度的属性。根据观察到的误报数量，它可以是 High、Moderate 或 Low。

示例

// Confidence: High

  • 虚拟规则（Virtual rules）：用于支持脚本中设计的各种模式。脚本中指定的虚拟规则应有对应的模式处理规则。

示例

virtual context

@depends on context@
type T;
T[] E;
@@
(
* (sizeof(E)/sizeof(*E))
|
* (sizeof(E)/sizeof(E[...]))
|
* (sizeof(E)/sizeof(T))
)

report 模式详解

report 生成如下格式的列表：

file:line:column-column: message

示例

运行：

./scripts/coccicheck --mode=report --cocci=scripts/coccinelle/array_size.cocci

会执行 SmPL 脚本中的以下部分：

<smpl>

@r depends on (org || report)@
type T;
T[] E;
position p;
@@
(
(sizeof(E)@p /sizeof(*E))
|
(sizeof(E)@p /sizeof(E[...]))
|
(sizeof(E)@p /sizeof(T))
)

@script:python depends on report@
p << r.p;
@@

msg="WARNING: Use ARRAY_SIZE"
coccilib.report.print_report(p[0], msg)

</smpl>

这段 SmPL 摘录会在标准输出上生成如下所示的条目：

ext/hal/nxp/mcux/drivers/lpc/fsl_wwdt.c:66:49-50: WARNING: Use ARRAY_SIZE
ext/hal/nxp/mcux/drivers/lpc/fsl_ctimer.c:74:53-54: WARNING: Use ARRAY_SIZE
ext/hal/nxp/mcux/drivers/imx/fsl_dcp.c:944:45-46: WARNING: Use ARRAY_SIZE

patch 模式详解

如果 patch 模式可用，它会为发现的每个问题给出修复建议。

示例

运行：

./scripts/coccicheck --mode=patch --cocci=scripts/coccinelle/misc/array_size.cocci

会执行 SmPL 脚本中的以下部分：

<smpl>

@depends on patch@
type T;
T[] E;
@@
(
- (sizeof(E)/sizeof(*E))
+ ARRAY_SIZE(E)
|
- (sizeof(E)/sizeof(E[...]))
+ ARRAY_SIZE(E)
|
- (sizeof(E)/sizeof(T))
+ ARRAY_SIZE(E)
)

</smpl>

这段 SmPL 摘录会在标准输出上生成如下所示的补丁块（hunk）：

diff -u -p a/ext/lib/encoding/tinycbor/src/cborvalidation.c b/ext/lib/encoding/tinycbor/src/cborvalidation.c
--- a/ext/lib/encoding/tinycbor/src/cborvalidation.c
+++ b/ext/lib/encoding/tinycbor/src/cborvalidation.c
@@ -325,7 +325,7 @@ static inline CborError validate_number(
static inline CborError validate_tag(CborValue *it, CborTag tag, int flags, int recursionLeft)
{
  CborType type = cbor_value_get_type(it);
-    const size_t knownTagCount = sizeof(knownTagData) / sizeof(knownTagData[0]);
+    const size_t knownTagCount = ARRAY_SIZE(knownTagData);
   const struct KnownTagData *tagData = knownTagData;
   const struct KnownTagData * const knownTagDataEnd = knownTagData + knownTagCount;

context 模式详解

context 以类似 diff 的样式高亮显示相关行及其上下文。

备注

生成的类似 diff 的输出 不是 可应用的补丁。context 模式的目的是高亮显示重要的行（以减号 - 标注），并给出其周围的若干上下文行。该输出可以配合 Emacs 的 diff 模式来审查代码。

示例

运行：

./scripts/coccicheck --mode=context --cocci=scripts/coccinelle/array_size.cocci

会执行 SmPL 脚本中的以下部分：

<smpl>

@depends on context@
type T;
T[] E;
@@
(
* (sizeof(E)/sizeof(*E))
|
* (sizeof(E)/sizeof(E[...]))
|
* (sizeof(E)/sizeof(T))
)

</smpl>

这段 SmPL 摘录会在标准输出上生成如下所示的 diff 块：

diff -u -p ext/lib/encoding/tinycbor/src/cborvalidation.c /tmp/nothing/ext/lib/encoding/tinycbor/src/cborvalidation.c
--- ext/lib/encoding/tinycbor/src/cborvalidation.c
+++ /tmp/nothing/ext/lib/encoding/tinycbor/src/cborvalidation.c
@@ -325,7 +325,6 @@ static inline CborError validate_number(
static inline CborError validate_tag(CborValue *it, CborTag tag, int flags, int recursionLeft)
{
  CborType type = cbor_value_get_type(it);
-    const size_t knownTagCount = sizeof(knownTagData) / sizeof(knownTagData[0]);
   const struct KnownTagData *tagData = knownTagData;
   const struct KnownTagData * const knownTagDataEnd = knownTagData + knownTagCount;

org 模式详解

org 以 Emacs 的 Org mode 格式生成报告。

示例

运行：

./scripts/coccicheck --mode=org --cocci=scripts/coccinelle/misc/array_size.cocci

会执行 SmPL 脚本中的以下部分：

<smpl>

@r depends on (org || report)@
type T;
T[] E;
position p;
@@
(
(sizeof(E)@p /sizeof(*E))
|
(sizeof(E)@p /sizeof(E[...]))
|
(sizeof(E)@p /sizeof(T))
)

@script:python depends on org@
p << r.p;
@@
coccilib.org.print_todo(p[0], "WARNING should use ARRAY_SIZE")

</smpl>

这段 SmPL 摘录会在标准输出上生成如下所示的 Org 条目：

* TODO [[view:ext/lib/encoding/tinycbor/src/cborvalidation.c::face=ovl-face1::linb=328::colb=52::cole=53][WARNING should use ARRAY_SIZE]]
