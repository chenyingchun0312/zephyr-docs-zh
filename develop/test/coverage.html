生成覆盖率报告

在 Zephyr 中，可以生成代码覆盖率报告，分析给定的测试或应用程序覆盖了代码的哪些部分。

有两种方式可以做到：

  • 在真实的嵌入式目标或 QEMU 中，使用 Zephyr 的 gcov 集成

  • 直接在主机上，将应用程序编译为面向 POSIX 架构的程序

嵌入式设备或 QEMU 中的测试覆盖率报告

概述

GCC GCOV 是一个与 GCC 编译器配合使用的测试覆盖率程序，用于分析程序并生成测试覆盖率报告，帮助你编写更高效、运行更快的代码，并发现未经测试的代码路径

在 Zephyr 中，gcov 会在应用程序运行期间将覆盖率剖析数据收集到 RAM 中（而不是文件系统中）。gcov 的收集和报告支持受到可用 RAM 大小的限制，因此目前只在嵌入式目标的 QEMU 仿真中启用。

详细说明

启用此功能分为两部分：一是为设备启用覆盖率，二是在测试应用程序中启用覆盖率。如前所述，使用 gcov 进行代码覆盖率统计取决于可用的 RAM。因此，为设备启用覆盖率时，要确保设备有足够的 RAM。例如，frdm_k64f 这样的小型设备可以运行简单的测试应用程序，但启用覆盖率后，消耗更多 RAM 的复杂测试用例会崩溃。

要为设备启用覆盖率，请在 Kconfig.board 文件中 select CONFIG_HAS_COVERAGE_SUPPORT。

要报告特定测试应用程序的覆盖率，请设置 CONFIG_COVERAGE。

生成代码覆盖率报告的步骤

以下步骤会为单个应用程序生成 HTML 覆盖率报告。

  1. 使用 CONFIG_COVERAGE=y 构建代码。

    west build -b mps2/an385 -- -DCONFIG_COVERAGE=y -DCONFIG_COVERAGE_DUMP=y

  2. 将模拟器的输出捕获到日志文件中。在覆盖率转储打印完成后，可能需要按 Ctrl-A X 终止模拟器，才能完成这一步：

    $ ninja -Cbuild run | tee log.log

  3. 从保存的日志文件生成 gcov 的 .gcda 和 .gcno 文件：

    $ python3 scripts/gen_gcov_files.py -i log.log

  4. 找到 SDK 中的 gcov 二进制文件。之后调用 gcovr 时，需要传入相应架构的 gcov 二进制文件路径：

    $ find $ZEPHYR_SDK_INSTALL_DIR -iregex ".*gcov"

  5. 为报告创建输出目录：

    $ mkdir -p coverage-report

  6. 运行 gcovr 获取报告：

    $ gcovr -r $ZEPHYR_BASE . --html -o coverage-report/coverage.html --html-details --gcov-executable <gcov_path_in_SDK>

使用 POSIX 架构生成覆盖率报告

为 POSIX 架构编译时，会使用主机的原生工具构建一个原生可执行文件，其中包含你的应用程序、Zephyr OS 以及一些基本的硬件仿真。

这意味着你可以使用开发其他桌面应用程序时所用的相同工具。

要使用 gcc 的 gcov 构建应用程序，只需在编译前设置 CONFIG_COVERAGE。运行应用程序时，gcov 覆盖率数据会被转储到相应的 gcda 和 gcno 文件中。你可以使用自己喜欢的工具对其进行后处理。例如：

west build -b native_sim samples/hello_world -- -DCONFIG_COVERAGE=y

$ ./build/zephyr/zephyr.exe
# Press Ctrl+C to exit
$ lcov --capture --directory ./ --output-file lcov.info -q --rc lcov_branch_coverage=1
$ genhtml lcov.info --output-directory lcov_html -q --ignore-errors source --branch-coverage --highlight --legend

备注

需要支持中间文本格式的较新版本 lcov（至少 1.14）。较新的 Linux 发行版中提供了这样的软件包。

也可以使用 gcovr（至少 4.2 版本）。

使用 Twister 生成覆盖率报告

Zephyr 的 twister 脚本 可以根据已执行的测试自动生成覆盖率报告，只需使用 --coverage 命令行选项调用它即可。

例如，可以调用：

$ west twister --coverage -p qemu_x86 -T tests/kernel

或者：

$ west twister --coverage -p native_sim -T tests/bluetooth

这会生成 twister-out/coverage/index.html 报告，以及由 gcovr 工具收集到 twister-out/coverage.json 中的覆盖率数据。

可以通过 --coverage-tool 和 --coverage-formats 命令行选项选择其他报告。

要生成同时包含 Zephyr 源码和位于 Zephyr 仓库之外的应用程序代码（参见 应用程序类型）的代码覆盖率报告，请在项目目录中使用 --coverage-basedir $ZEPHYR_BASE 命令行选项调用 Twister，例如：

$ west twister --coverage -p native_sim --coverage-basedir $ZEPHYR_BASE -T your_project_dir

备注

默认情况下，Twister 调用 gcovr 工具，该工具在过滤源文件时假定所有路径都是 已解析所有符号链接 的真实路径。因此，如果开发环境中有包含符号链接的目录，为了避免 gcovr 报告不完整，要么让 ZEPHYR_BASE 包含真实路径，要么添加 Twister 命令行选项 --coverage-tool lcov，改用 lcov 工具代替 gcovr。

对于单元测试，流程有所不同，因为单元测试使用主机工具链构建，并且需要使用不同的开发板：

$ west twister --coverage -p unit_testing -T tests/unit

生成的报告与非单元测试位于相同的位置。

按测试统计的覆盖率矩阵

默认情况下，覆盖率按测试场景汇总。要将覆盖率细化到单个 Ztest 测试用例（例如回答“哪些测试执行了 foo.c 的第 X 行”这样的问题），请传入 --coverage-per-test：

$ west twister -p mps2/an385 -T tests/kernel --coverage --coverage-tool lcov \
    --coverage-per-test

这会启用 CONFIG_ZTEST_COVERAGE_PER_TEST，它会在每个测试用例之前重置 gcov 计数器，并在测试用例之后转储一份独立的、带有测试标记的覆盖率产物。在支持半主机（semihosting）的平台上（QEMU 下的 ARM、RISC-V 和 Xtensa 目标，例如 mps2/an385），每个测试的数据会直接写入主机文件系统，从而避免按测试转储时原本会产生的大量串口控制台流量；其他平台则回退到串口控制台传输。

除了常规的汇总覆盖率报告外，这还会生成：

  • 在每个构建的 coverage/tests/ 目录下，为每个测试生成一个 <scenario>.<test>.info 跟踪文件；以及

  • twister-out/coverage/test_matrix.json，一个机器可读的矩阵，包含 by_line 视图（{file: {line: [tests]}}）和 by_test 视图（{test: {file: [lines]}}）。

按测试的归属信息由该矩阵（及其仪表盘）承载，而不在汇总的 lcov 报告中体现：每个实例的覆盖率在汇总前会被合并为单个跟踪文件，因此运行结束时的报告开销与实例数量成正比，而不是与测试用例总数成正比。

备注

--coverage-per-test 需要使用 lcov 覆盖率工具，因为该矩阵依赖于 lcov 按测试记录的 TN 跟踪文件记录，而 gcovr 没有对应的功能。该选项还隐含启用 --coverage。

可视化矩阵

可以使用独立脚本 scripts/gen_test_matrix_dashboard.py 将 test_matrix.json 转换为一个自包含的交互式 HTML 仪表盘（该脚本不依赖于 Twister，可以对任何以前生成的矩阵运行）：

$ scripts/gen_test_matrix_dashboard.py -i twister-out/coverage/test_matrix.json

这会生成 twister-out/coverage/test_matrix.html，其中按测试列出了它覆盖的文件数和行数，以及它 独有 覆盖的行数（即其他测试都未覆盖到的行，可用于找出冗余的或起关键作用的测试），并且可以深入查看某个测试覆盖的文件，或者查询哪些测试覆盖了给定文件的给定行。

使用不同的工具链

Twister 会查看环境变量 ZEPHYR_TOOLCHAIN_VARIANT，以确定默认使用哪个 gcov 工具。Twister --gcov-tool 参数的默认值如下：

工具链

--gcov-tool 的值

host

gcov

llvm

llvm-cov gcov

zephyr
