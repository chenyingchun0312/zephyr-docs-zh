CI 测试计划选择器（test_plan_v2）

CI 测试计划选择器是一个模块化的 Python 脚本，位于 scripts/ci/test_plan_v2.py。它的作用是分析 PR（拉取请求）中修改的文件集合，并输出一份有针对性的 twister 测试计划：只运行可能受该修改影响的测试，避免每次提交都在整个代码树范围内运行全部测试。

该脚本会写出两个产物：

  • testplan.json：通过 twister --load-tests 传给 twister。

  • .testplan：一个纯 KEY=value 格式的环境文件，供 CI 编排脚本使用，其中包含 TWISTER_TESTS、TWISTER_NODES 和 TWISTER_FULL。

架构

该选择器围绕 策略流水线 构建。每个策略都是一个独立的分析器，它会：

  1. 接收修改文件列表（或其中尚未被前面策略认领的子集）。

  2. 按照自身逻辑检查这些文件。

  3. 返回一个 TwisterCall 描述符列表，以及它已 处理 的文件集合。

Orchestrator 驱动该流水线，将所有结果合并到 PlanAccumulator 中，对测试套件去重，并写出输出文件。

策略顺序

各策略按固定顺序运行，该顺序体现了两条原则：

具体优先于通用。 最精确的策略最先运行。位于 tests/kernel/sched/ 中的文件会由 DirectTestStrategy 确定性地处理（只运行这些测试），而不会等到兜底的 MaintainerAreaStrategy 添加整个 Kernel 区域的全面测试。

认领型优先于叠加型。 认领型策略先于叠加型策略运行。一旦某个认领型策略认领了某个文件，下游策略就不会再看到它。这样可以避免对开发板文件的修改，同时又针对同一路径触发驱动 compat 扫描和 Kconfig 全面测试。

当前顺序为：

#

策略

认领

理由

0

ComplexityStrategy

否

使用 pydriller 和 lizard 对补丁集评分。必须最先运行，以便 RiskClassifierStrategy 可以使用该评分。不产生任何 twister 调用。

1

IgnoreStrategy

是

静默丢弃永远不会影响测试的文件（文档、CI 工作流、工具）。尽早运行，使后续策略不会在被忽略的路径上浪费精力。

1b

BoilerplateFilter

是

认领整个 diff 只包含空白调整、空行改动、SPDX 许可证标识符、版权声明或单纯注释分隔符的文件。这类修改不会影响运行时行为，因此尽早移除它们，可以让文件池只留给处理实质性修改的策略。需要 git 提交范围，否则不执行任何操作。

2

DirectTestStrategy

是

修改的测试或示例文件必须 只 触发该测试，而不是整个区域范围的全面测试。认领该文件可以避免在修改 tests/kernel/sched/main.c 时，MaintainerAreaStrategy 又添加 Kernel 区域中的每个测试。

3

SnippetStrategy

是

代码片段（snippet）的修改是自包含的：只有在 required_snippets 中声明了该代码片段的测试才需要运行。认领可以避免下游策略将代码片段 YAML 当作未知的配置文件处理。

4

BoardStrategy

是

开发板特定的修改需要在每个开发板变体上运行有针对性的集成测试。认领可以避免开发板 .yaml 文件同时匹配 Kconfig 和 Header 策略。

5

SoCStrategy

是

SoC 级别的修改会影响基于该 SoC 系列构建的所有开发板。认领可以避免同一 soc/ 路径进入 Kconfig 全面测试。

6

ManifestStrategy

是

修改 west.yml 需要运行带有模块标签的集成测试，而不是通用的维护者区域测试。认领清单（manifest）文件可以避免兜底策略添加无关的测试。

7

DriverCompatStrategy

否

叠加型：驱动文件也可能被区域模式覆盖，因此不认领该文件，KconfigImpactStrategy 和 MaintainerAreaStrategy 可以进一步增加覆盖。

8

DtsBindingStrategy

否

叠加型：绑定的修改会将基于覆盖文件的测试选择与针对开发板的区域调用结合起来。

9

KconfigImpactStrategy

否

叠加型：Kconfig 修改可能影响许多无关的文件；只有在发现非广泛使用的符号时才认领，涉及广泛使用符号的文件留给兜底策略处理。

10

HeaderImpactStrategy

否

叠加型：对于头文件的修改，会将包含该头文件的使用者追溯回维护者区域。广泛使用的头文件（被包含次数超过配置阈值）会被跳过。

11

MaintainerAreaStrategy

否

兜底策略：将剩余的所有文件与 MAINTAINERS.yml 的区域模式进行匹配，并为每个 tests: 列表非空的匹配区域发出 --test-pattern 调用。

样板修改过滤器

BoilerplateFilter 紧接在 IgnoreStrategy 之后、任何测试选择策略之前运行。它会（通过 git diff）检查每个修改文件的实际 diff，并认领那些全部内容变化都是非实质性修改的文件：

  • 空白和空行修改：通过 git diff -w --ignore-blank-lines 检测，如果该命令对某个文件没有任何输出，则所有修改的行都是空白或空行。

  • SPDX 和版权头的编辑：以 SPDX-License-Identifier:、SPDX-FileCopyrightText: 或单词 Copyright 开头的行。

  • 只含注释分隔符的行：非空白内容完全由 /*、*/、//、# 或 * 字符组成的行（例如重新排版的块注释边框）。

只有当某个文件 diff 中 每一 行新增或删除的内容都属于上述类别之一时，该文件才会被认领。只要有一行实质性修改（修改了语句、宏或声明），该文件就会原样传给下游策略。

如果未提供 --commits（例如使用 --modified-files 时），该过滤器不执行任何操作，因为没有提交范围就无法计算 diff。此时所有文件都会保留在文件池中。

认领型与叠加型行为

每个策略子类都带有一个类属性 consumes: bool。

当 consumes = True 时：

handled 集合中返回的文件会在下一个策略运行之前从 remaining 文件池中移除。当该策略对其文件类型具有 权威性 时使用，即后续策略再看到该文件会产生冗余或错误的结果时。

当 consumes = False（默认）时：

无论策略返回什么，文件都会保留在文件池中。所有下游策略都会收到相同的文件列表。适用于只贡献 额外 测试覆盖、而不声明独占所有权的叠加型策略。

备注

当 remaining 文件池为空时，Orchestrator 会完全跳过该策略。由于非认领型策略能看到所有文件，"remaining" 只会通过认领型策略缩减。文件池一旦为空，编排器就会停止调用策略。

完整运行与回退条件

当满足以下任一条件时，编排器会在 .testplan 中发出 TWISTER_FULL=True 信号：

  1. 存在未解析的文件。 所有策略运行完毕后，至少有一个修改的文件未被任何策略 处理。脚本不会对未知路径静默跳过覆盖，而是回退为请求完整运行，确保不会漏掉任何回归。

  2. 显式的完整运行信号。 某个策略返回了 full_run=True 的 TwisterCall。编排器遇到这样的调用时，会立即设置 TWISTER_FULL=True，清空剩余文件池，并停止执行后续调用。这一机制允许策略放弃有针对性的选择（例如修改了整个代码树都在使用的核心子系统头文件时）。

当 TWISTER_FULL=True 时，CI 脚本应丢弃 testplan.json，并在不带 --load-tests 的情况下运行 twister。

节点数计算

.testplan 中的 TWISTER_NODES 按以下方式计算：

  • 0：未选中任何测试。

  • 1：选中的测试少于 --tests-per-builder 个（一个构建器即可容纳）。

  • ceil(total / tests_per_builder)：其他情况。向上取整可确保在不能整除时，没有任何构建器超出容量。

--tests-per-builder 的默认值为 900。

添加新策略

  1. 继承 SelectionStrategy 并实现两个抽象成员：

    class MyStrategy(SelectionStrategy):

    consumes: bool = False  # or True if authoritative

    @property
    def name(self):
        return "MyStrategy"

    def analyze(self, changed_files):
        # inspect changed_files
        calls = [...]       # list of TwisterCall
        handled = {...}     # subset of changed_files this strategy owns
        return calls, handled

  2. 确定是认领型还是叠加型。 问自己：“如果下游策略也看到这个文件，它会产生有用的额外覆盖，还是冗余/错误的结果？”如果是冗余/错误的结果，则设置 consumes = True。

  3. 在 build_strategies() 中 插入到正确的位置。经验法则如下：

    • 认领型策略应位于所有叠加型策略之前。

    • 更具体的策略应位于不那么具体的策略之前。

    • 对文件池没有副作用的策略（叠加型）可以按开销排序，开销最小的在前。

  4. 在 analyze 内部使用延迟导入来 保护可选依赖，并在缺少依赖时平稳地返回 [], set()。使用 # noqa: PLC0415 注释屏蔽延迟导入警告。

  5. 在 scripts/tests/ci/test_test_plan_v2.py 中 编写单元测试，覆盖：

    • 正常路径（文件被正确识别和分派）。

    • 空操作路径（无关文件不产生任何调用，handled 集合为空）。

    • 边界情况（磁盘上缺少文件、YAML 格式错误、输入为空）。

共享的流水线上下文

PipelineContext 是一个数据类，通过 build_strategies() 在所有策略之间传递。它目前包含：

  • complexity_score：补丁集的总评分，由 ComplexityStrategy 写入，由 RiskClassifierStrategy 读取。

  • file_metrics：每个文件的 ComplexityMetrics 映射，用于详细日志记录和下游决策。

新的跨策略状态应作为带类型的字段添加到 PipelineContext 中，而不是作为策略级别的实例变量。

验证选择行为的测试策略

测试套件位于 scripts/tests/ci/test_test_plan_v2.py，使用 pytest 运行：

pytest scripts/tests/ci/test_test_plan_v2.py -v

测试按策略或共享组件组织，每个策略或组件一个类。每个新策略都应具备以下几类测试：

单元测试（不需要 Zephyr 代码树）

使用 tmp_path fixture 创建执行每条代码路径所需的最少文件系统结构（board.yml、snippet.yml、testcase.yaml 等）。这些测试应当快速且与外部环境隔离。

辅助方法测试

单独测试内部方法（路径遍历、YAML 解析、正则提取）。传入合成的内容，而不是依赖仓库中的真实文件。

编排器集成测试

使用模拟策略和模拟的 TwisterExecutor，在不调用 twister 的情况下测试编排器的认领/叠加逻辑、完整运行信号以及 .testplan 输出。

真实代码树集成测试（可选，@pytest.mark.integration）

可以添加此类测试并用 @pytest.mark.integration 标记，使其不包含在默认运行中。这些测试只有在完整的 Zephyr 检出中才有意义。

新策略的最低测试清单

  • 当输入列表中没有相关文件时，该策略不返回任何调用，也不返回任何已处理文件。

  • 对于已知正确的输入，该策略能正确识别并返回预期的 TwisterCall。

  • 当文件系统中缺少所需文件时，该策略不会崩溃。

  • 对于认领型策略：handled 集合恰好等于匹配到的文件，不多也不少。

  • 对于叠加型策略：handled 集合为空，或者只包含该策略具有权威性的文件。

命令行参考

usage: test_plan_v2.py [-c A..B] [-m FILE] [-f PATH]
                       [-o FILE] [-p PLATFORM] [--maintainers-file FILE]
                       [-T DIR] [--quarantine-list FILE]
                       [--tests-per-builder N] [--disable-strategy NAME]
                       [--detailed-test-id]

-c A..B              Git commit range (e.g. ``main..HEAD``).  Changed files
                     are derived from ``git diff --name-only A..B``.
-m FILE              JSON file containing a list of changed file paths.
-f PATH              Treat PATH as a changed file (repeatable).
-o FILE              Output JSON file (default: ``testplan.json``).
-p PLATFORM          Restrict all selections to this platform (repeatable).
--maintainers-file   Path to ``MAINTAINERS.yml``.
-T DIR               Extra testsuite root forwarded to every twister call.
--quarantine-list    Quarantine YAML forwarded to twister.
--tests-per-builder  Tests per CI builder node (default: 900).
--disable-strategy   Skip a strategy by name (repeatable).
--detailed-test-id   Pass ``--detailed-test-id`` to twister.
