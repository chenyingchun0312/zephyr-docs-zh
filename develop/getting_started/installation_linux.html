安装 Linux 主机依赖项

以下 Linux 发行版提供了相应文档：

  • Ubuntu

  • Fedora

  • Clear Linux

  • Arch Linux

对于非滚动发布的发行版，包管理器可能无法满足部分需求和依赖项。这种情况下，请按照所提供的补充说明，从包管理器以外的来源获取软件。

备注

如果在企业防火墙后工作，并且尚未配置代理，可能需要配置代理才能访问互联网。有些工具通过环境变量 http_proxy 和 https_proxy 获取代理设置，而有些工具使用各自的配置文件，其中最典型的是 apt 和 git。

更新操作系统

确保主机系统是最新的。

sudo apt-get update
sudo apt-get upgrade

sudo dnf upgrade

sudo swupd update

sudo pacman -Syu

安装必需软件和依赖项

注意，按照这些说明会同时安装 Ninja 和 Make；实际上只需要其中一个。

sudo apt-get install --no-install-recommends git cmake ninja-build gperf \
  ccache dfu-util device-tree-compiler wget \
  python3-dev python3-pip python3-setuptools python3-tk python3-wheel xz-utils file \
  make gcc gcc-multilib g++-multilib libsdl2-dev libmagic1

sudo dnf group install development-tools c-development
sudo dnf install cmake ninja-build gperf dfu-util dtc wget which \
  python3-pip python3-tkinter xz file python3-devel SDL2-devel \
  libusb1-devel

sudo swupd bundle-add c-basic dev-utils dfu-util dtc \
  os-core-dev python-basic python3-basic python3-tcl

Clear Linux 侧重于 原生 性能和安全性，而不是交叉编译。因此，它独特地默认向所有用户的 环境 导出一组编译器和链接器标志。Zephyr 的 CMake 构建系统会因此发出警告或构建失败。要清除其中的 C/C++ 标志并修复 Zephyr 构建，请以 root 身份运行以下命令，然后注销并重新登录：

echo 'unset CFLAGS CXXFLAGS' >> /etc/profile.d/unset_cflags.sh

注意，此命令会为 系统上的所有用户 取消设置 C/C++ 标志。每个 Linux 发行版都有各自独特、相对复杂且可能不断变化的 bash 初始化文件相互引用（source）的顺序，Clear Linux 也不例外。如果需要更灵活的解决方案，可以先查看 /usr/share/defaults/etc/profile 中的逻辑。

sudo pacman -S git cmake ninja gperf ccache dfu-util dtc wget \
    python-pip python-setuptools python-wheel tk xz file make which

CMake

需要 较新版本的 CMake。使用 cmake --version 检查当前版本。如果版本较旧，可以通过以下几种方式获取较新版本：

  • 在 Ubuntu 上，可以按照说明添加 kitware 第三方 apt 软件源，然后通过 apt 获取更新版本的 cmake。

  • 从 CMake 项目网站下载并安装打包好的 cmake。（注意，这不会卸载之前版本的 cmake。）

    cd ~
wget https://github.com/Kitware/CMake/releases/download/v3.21.1/cmake-3.21.1-Linux-x86_64.sh
chmod +x cmake-3.21.1-Linux-x86_64.sh
sudo ./cmake-3.21.1-Linux-x86_64.sh --skip-license --prefix=/usr/local
hash -r

    如果安装脚本把 cmake 放到了 PATH 中的新位置，可能需要执行 hash -r 命令。

  • 从 CMake 项目自己在 CMake Downloads 页面提供的预构建二进制文件下载并安装。例如，将 3.21.1 版本安装到 ~/bin/cmake：

    mkdir $HOME/bin/cmake && cd $HOME/bin/cmake
wget https://github.com/Kitware/CMake/releases/download/v3.21.1/cmake-3.21.1-Linux-x86_64.sh
yes | sh cmake-3.21.1-Linux-x86_64.sh | cat
echo "export PATH=$PWD/cmake-3.21.1-Linux-x86_64/bin:\$PATH" >> $HOME/.zephyrrc

  • 使用 pip3：

    pip3 install --user cmake

    注意，这不会卸载之前版本的 cmake，并且会把新的 cmake 安装到 ~/.local/bin 文件夹中，因此需要将 ~/.local/bin 添加到 PATH 中。（详见 Python 和 pip。）

  • 在发行版的 beta 或 unstable 软件包库中查找更新。

  • 在 Ubuntu 上，也可以使用 snap 获取可用的最新版本：

    sudo snap install cmake

更新 cmake 后，使用 cmake --version 确认能找到新安装的 cmake。为避免冲突，也可以卸载包管理器提供的 CMake。（使用 whereis cmake 查找其他已安装的版本。）

DTC（设备树编译器）

需要 较新版本的 DTC。使用 dtc --version 检查当前版本。如果版本较旧，可以从源代码构建安装较新版本，或者安装 Zephyr SDK 并使用其中附带的版本。

Python

需要 较新的 Python 3 版本。使用 python3 --version 检查当前版本。

如果版本较旧，需要安装较新的 Python 3。可以从源代码构建，或者使用发行版包管理器渠道提供的向后移植（backport）版本（如果有）。建议将该 Python 隔离在虚拟环境中，以免干扰系统自带的 Python。

安装 Zephyr 软件开发工具包（SDK）

Zephyr 软件开发工具包（SDK）包含 Zephyr 支持的每种架构的工具链。它还包括其他主机工具，例如定制的 QEMU 和 OpenOCD。

强烈建议使用 Zephyr SDK，在某些情况下甚至必须使用（例如，为某些架构在 QEMU 中运行测试）。

要安装 SDK，请按照 Zephyr SDK 安装指南 中的 Linux 步骤操作。

在 Linux 上不使用 Zephyr SDK 进行构建

提供 Zephyr SDK 是为了方便易用。它为所有 Zephyr 目标架构提供工具链，构建应用程序或运行测试时不需要任何额外的标志。除交叉编译器外，Zephyr SDK 还提供预构建的主机工具。不过，也可以按照 工具链 一节所述，使用其他工具链而不使用 SDK 的工具链进行构建。

如上所述，SDK 还包含预构建的主机工具。要将 SDK 的预构建主机工具与其他来源的工具链一起使用，必须将环境变量 ZEPHYR_SDK_INSTALL_DIR 设置为 Zephyr SDK 的安装目录。要在不使用 Zephyr SDK 预构建主机工具的情况下构建，必须取消设置环境变量 ZEPHYR_SDK_INSTALL_DIR。

要确保取消设置该变量，请运行：

unset ZEPHYR_SDK_INSTALL_DIR
