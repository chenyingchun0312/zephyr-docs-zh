Console

console harness 让 Twister 使用测试 YAML 文件中定义的正则表达式来解析测试的文本输出。

目前支持以下选项：

type: <one_line|multi_line>（必需）

取决于要匹配的正则表达式字符串

regex: <正则表达式列表>（必需）

包含正则表达式的字符串，用于与测试输出进行匹配，以确认测试按预期运行。

ordered: <True|False>（默认 False）

按顺序或以任意顺序检查各正则表达式字符串

record: <记录选项>（可选）
regex: <正则表达式列表>（必需）

带命名子组的正则表达式，用于匹配测试实例输出行中的数据字段，这些输出行提供了供进一步分析的自定义数据。这些记录会写入构建目录中的 recording.csv 文件，以及 twister.json 中测试套件对象的 recording 属性。

如果给出了多个正则表达式，每个表达式都会应用到每一行输出上，结果可能是从同一输出行生成多条不同的记录，从不同输出行生成不同的记录，或者从不同输出行生成相似的记录。

.CSV 文件的列数等于所有记录中检测到的字段数；缺失的值用空字符串填充。

例如，要提取 metric、cycles、nanoseconds 三个数据字段：

record:
  regex:
    - "(?P<metric>.*):(?P<cycles>.*) cycles, (?P<nanoseconds>.*) ns"
merge: <True|False>（默认 False）

使一个测试实例只保留一条记录，其中包含由正则表达式提取的所有数据字段。同名字段会放入列表中，按它们在记录中出现的顺序排列。根据正则规则和测试输出的不同，这类多值字段可能含有不同数量的值。

as_json: <正则子组名称列表>（可选）

由正则表达式提取到命名子组中的数据字段，会额外按 JSON 编码字符串进行解析，并作为嵌套的 recording 对象属性写入 twister.json。recording.csv 中对应的列会原样包含这些 JSON 字符串。

借助该选项，测试日志可以传递从测试镜像输出的分层数据结构，用于结合汇总结果、跟踪信息、统计数据等进行进一步分析。

例如，以下配置：

record:
  regex: "RECORD:(?P<type>.*):DATA:(?P<metrics>.*)"
  as_json: [metrics]

与如下测试日志字符串匹配时：

RECORD:jitter_drift:DATA:{"rollovers":0, "mean_us":1000.0}

将在 twister.json 中报告为：

"recording":[
    {
          "type":"jitter_drift",
          "metrics":{
              "rollovers":0,
              "mean_us":1000.0
          }
    }
]
