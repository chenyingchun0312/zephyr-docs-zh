Twister 状态

什么是 Twister 状态？

Twister 状态以全面且易于理解的方式描述以下对象的当前状态：

  • Harness

  • TestCase

  • TestSuite

  • TestInstance

实际上，大多数用户在 Twister 运行结束后，关心的是实例（Instance）和用例（Case）的状态。

小技巧

术语回顾：

Harness 是 Twister 内部的一个 Python 类，用于捕获和分析 Twister 外部程序的输出。由于它不会出现在最终报告中，为清晰起见，本页不再讨论它。

TestCase，也称为用例（Case），是旨在验证某个断言的一段代码，是 Zephyr 中最小的测试单位。

TestSuite，也称为套件（Suite），是一组用例。可以通过 testcase.yaml 文件按套件修改 Twister 的行为。归为一组的用例应有足够多的共同点，使 Twister 对它们一视同仁是合理的。

TestInstance，也称为实例（Instance），是某个平台上的一个套件。Twister 通常按实例报告结果，尽管在报告中它们被称为 "Suites"。如果某个状态标注为适用于套件，那么它同样适用于实例。由于在本节中区分二者没有意义，凡是读到“套件”时，均可认为同样适用于实例。

更详细的说明请参阅 此处。

按套件状态的详细说明

FILTER：

该状态表示整个套件已在某次 Twister 运行中被静态过滤掉。因此，其中的所有用例也应处于该状态。

ERROR：

套件在运行测试时遇到了问题。它要求至少有一个用例处于 ERROR 或 BLOCK 状态。由于该状态的优先级高于所有其他用例状态，这样的套件中可以包含所有有效的终止用例状态。

FAIL：

套件中至少有一个用例未满足其断言。在不满足 ERROR 状态条件的前提下，该状态的优先级高于所有其他用例状态。

PASS：

套件已正常通过。它不能包含任何处于 BLOCK、ERROR 或 FAIL 状态的用例，因为这些状态表示运行套件时出现了问题。

NOTRUN：

整个套件未运行，只进行了构建。这要求其中的所有用例都未运行。由于是否可运行是按套件决定的，其用例只能处于 NOTRUN 状态。

SKIP：

整个套件在运行时被跳过。所有用例也必须处于 SKIP 状态。
