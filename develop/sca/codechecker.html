CodeChecker 支持

CodeChecker 是一套静态分析基础设施。它会执行构建系统上可用的分析工具，例如 Clang-Tidy、Clang Static Analyzer 和 Cppcheck。安装说明请参阅各分析器的网站。

安装 CodeChecker

CodeChecker 本身是一个 Python 软件包，发布在 pypi 上。

pip install codechecker

使用 CodeChecker 构建

要运行 CodeChecker，应在调用 west build 时传入 -DZEPHYR_SCA_VARIANT=codechecker 参数，例如：

west build -b mimxrt1064_evk samples/basic/blinky -- -DZEPHYR_SCA_VARIANT=codechecker

配置 CodeChecker

CodeChecker 使用不同的命令步骤，每个步骤都有各自的配置参数。下表列出了所有这些选项。

参数

说明

CODECHECKER_ANALYZE_JOBS

分析时使用的线程数。（默认值：<CPU 数量>）

CODECHECKER_ANALYZE_OPTS

直接传递给 analyze 命令的参数。（例如 --timeout;360）

CODECHECKER_CLEANUP

在解析/存储之后执行清理。这会删除所有 plist 文件。

CODECHECKER_CONFIG_FILE

一个包含配置选项的 JSON 或 YAML 文件，会传递给所有命令。

CODECHECKER_EXPORT

以逗号分隔的报告类型列表。允许的类型有：html,json,codeclimate,gerrit,baseline。

CODECHECKER_NAME

CodeChecker 运行的元数据名称。（默认值：zephyr）

CODECHECKER_PARSE_EXIT_STATUS

默认情况下，CodeChecker 发现的问题不会导致构建失败；设置此选项可使其在分析时失败。

CODECHECKER_PARSE_OPTS

直接传递给 parse 命令的参数。（例如 --verbose;debug）

CODECHECKER_PARSE_SKIP

跳过对分析结果的解析，在只想存储结果时很有用。

CODECHECKER_STORE

在分析之后运行 store 命令。

CODECHECKER_STORE_OPTS

直接传递给 store 命令的参数。隐含启用 CODECHECKER_STORE。（例如 --url;localhost:8001/Default）

CODECHECKER_STORE_TAG

向 store 命令传递一个标识符 --tag。

CODECHECKER_TRIM_PATH_PREFIX

从分析结果中去掉所定义的路径，例如 /home/user/zephyrproject。默认会添加 west topdir 的值。

这些参数可以在命令行中传入，也可以设置为环境变量。

在 twister 中运行 CodeChecker

在 twister 中运行 CodeChecker 时，会设置以下默认选项：

参数

值

CODECHECKER_ANALYZE_JOBS

1

CODECHECKER_NAME

<board target>:<testsuite name>

CODECHECKER_STORE_TAG

应用程序源码目录中 git describe 的值。

要覆盖这些值，请设置环境变量或将其作为额外参数传入。
