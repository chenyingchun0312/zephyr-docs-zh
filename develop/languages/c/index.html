C 语言支持

C 是一种通用的低级编程语言，广泛用于为嵌入式系统编写代码。

Zephyr 主要使用 C 编写，原生支持用 C 语言编写的应用程序。所有 Zephyr API 函数和宏都用 C 实现，并通过 include 目录下的 C 头文件提供，因此用 C 编写 Zephyr 应用程序可以让开发者使用最多的特性。

main() 函数的返回类型必须为 int，因为 Zephyr 应用程序运行在 C 标准所定义的“宿主（hosted）”环境中。应用程序必须从 main 返回零（0）。所有非零返回值均为保留值。

语言标准

Zephyr 并不以某个特定版本的 C 标准为目标；不过，Zephyr 代码库大量使用了 1999 年发布的 ISO C 标准（ISO/IEC 9899:1999，下文简称 C99）中新引入的特性，例如下列特性，因此实际上要求使用支持 C99 及以上标准的编译器工具链：

  • 内联函数

  • 标准布尔类型（<stdbool.h> 中的 bool）

  • 固定宽度整数类型（<stdint.h> 中的 [u]intN_t）

  • 指定初始化器（designated initializer）

  • 可变参数宏

  • restrict 限定符

此外，一些组件或其中的部分代码使用了 C11 和 C17 版本标准（分别为 ISO/IEC 9899:2011 和 9899:2018）中引入的特性：

  • _Generic 关键字

  • _Static_assert 关键字

总之，建议使用至少支持 C17 标准的编译器工具链进行 Zephyr 开发。但需要注意，某些可选的 Zephyr 组件和外部模块可能使用了更新版本标准中引入的 C 语言特性，此时需要使用支持这些标准的更新的编译器工具链。

格式化输出

C 定义了 printf 和 sprintf 等标准格式化输出函数，这些函数由 C 标准库实现。

每种 C 标准库在选择格式化输出模式和功能方面都有各自的要求和配置。详情请参阅各 C 标准库的文档。

动态内存管理

C 定义了标准的动态内存管理接口（例如 malloc() 和 free()），这些函数由 C 标准库实现。

虽然不同 C 标准库的动态内存管理实现细节各不相同，但所有受支持的库都必须遵循以下约定。每个受支持的 C 标准库都应当：

  • 在内部管理自己的内存堆，或通过调用 libc-hooks.c 中实现的钩子函数（例如 sbrk()）来管理。

  • 对于标准动态内存分配接口（例如 malloc()）所分配的内存块，满足特定于架构和内存区域的对齐要求。

  • 启用用户空间时，在 z_malloc_partition 内存分区中分配内存块。参见 预定义的内存分区。

关于特定 C 标准库的内存管理实现的更多详情，请参阅各 C 标准库的文档。

备注

原生 Zephyr 应用程序应使用 Zephyr 内核支持的 内存管理 API，例如 k_malloc()，以利用它们提供的高级特性。

只有面向多个操作系统的可移植应用程序和库，才应使用 malloc() 等 C 标准动态内存管理接口函数。
