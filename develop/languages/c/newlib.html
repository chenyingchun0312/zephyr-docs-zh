Newlib

Newlib 是为嵌入式系统编写的完整 C 库实现。它是一个独立的开源项目，并未以源代码形式包含在 Zephyr 中。Zephyr SDK 为每种支持的架构提供了预编译的库（libc.a 和 libm.a）。

备注

其他第三方工具链（例如 GNU Arm Embedded）也以预编译库的形式捆绑了 Newlib。

Zephyr 实现了 Newlib 中 C 标准库函数所调用的“API 钩子”函数。这些钩子函数实现于 lib/libc/newlib/libc-hooks.c，负责将库内部的系统调用转换为等效的 Zephyr API 调用。

Newlib 的类型

Zephyr SDK 中包含的 Newlib 有两个版本：'full' 变体和 'nano' 变体。

Full Newlib

Newlib full 变体（libc.a 和 libm.a）是 Zephyr SDK 中功能最全的 Newlib 变体，几乎支持所有标准 C 库特性。它针对性能进行了优化（性能优先于代码大小），其资源占用比 nano 变体大得多。

在应用程序配置文件中选中 CONFIG_NEWLIB_LIBC 并取消选中 CONFIG_NEWLIB_LIBC_NANO，即可启用该变体。

Nano Newlib

Newlib nano 变体（libc_nano.a 和 libm_nano.a）是 Newlib 针对大小优化的版本，支持 full 变体支持的所有特性，但不支持 C99 中引入的新格式说明符，例如 char、long long 类型的格式说明符（即 %hhX 和 %llX）。

在应用程序配置文件中选中 CONFIG_NEWLIB_LIBC 和 CONFIG_NEWLIB_LIBC_NANO，即可启用该变体。

注意，Newlib nano 变体并非适用于所有架构。nano 变体是否可用由 CONFIG_HAS_NEWLIB_LIBC_NANO 指定。

格式化输出

Newlib 支持所有标准 C 格式化输入和输出函数，包括 printf、fprintf、sprintf 和 sscanf。

Newlib 的格式化输入输出函数实现支持 C 标准定义的所有格式说明符，但有以下例外：

  • 浮点格式说明符（例如 %f）需要启用 CONFIG_NEWLIB_LIBC_FLOAT_PRINTF 和 CONFIG_NEWLIB_LIBC_FLOAT_SCANF。

  • Newlib nano 变体不支持 C99 格式说明符（即用于 char 的 %hhX、用于 long long 的 %llX、用于 intmax_t 的 %jX、用于 size_t 的 %zX、用于 ptrdiff_t 的 %tX）。

动态内存管理

Newlib 实现了一个内部堆分配器，用于管理标准动态内存管理接口函数（例如 malloc() 和 free()）所使用的内存块。

Newlib 实现的内部堆分配器可能因所用 Newlib 类型的不同而不同。例如，Zephyr SDK 中 Full Newlib（libc.a 和 libm.a）实现的堆分配器会向操作系统申请更大的内存块，其最低内存需求也比 Nano Newlib（libc_nano.a 和 libm_nano.a）高得多。

Newlib 动态内存管理函数与 Zephyr 侧 libc 钩子之间唯一的接口是 sbrk() 函数，Newlib 用它来管理为其内部堆分配器预留的内存池大小。

libc-hooks.c 中实现的 _sbrk() 钩子函数处理来自 Newlib 的内存池大小变更请求，并在系统内存不足时返回错误，从而确保 Newlib 内部堆分配器的内存池大小不会超过可用内存空间。

启用用户空间时，Newlib 内部堆分配器的内存池会被放在一个名为 z_malloc_partition 的专用内存分区中，用户模式线程可以访问该分区。

Newlib 堆可用的内存空间大小取决于系统配置：

  • 启用 MMU（选中 CONFIG_MMU）时，为 Newlib 堆预留的内存空间大小取 k_mem_free_get() 函数返回的空闲内存空间大小与 CONFIG_NEWLIB_LIBC_MAX_MAPPED_REGION_SIZE 中的较小者。

  • 启用 MPU 且 MPU 要求分区大小和地址按 2 的幂对齐（CONFIG_NEWLIB_LIBC_ALIGNED_HEAP_SIZE 设置为非零值）时，为 Newlib 堆预留的内存空间大小由 CONFIG_NEWLIB_LIBC_ALIGNED_HEAP_SIZE 设定。

  • 否则，为 Newlib 堆预留的内存空间大小等于 SRAM 区域中空闲（未分配）内存的大小。

Newlib 实现的标准动态内存管理接口函数是线程安全的，可以被多个线程同时调用。
