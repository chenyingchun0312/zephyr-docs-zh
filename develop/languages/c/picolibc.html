Picolibc

Picolibc 是为嵌入式系统编写的完整 C 库实现，面向 C17 (ISO/IEC 9899:2018) 和 POSIX 2018 (IEEE Std 1003.1-2017) 标准。Picolibc 是一个外部开源项目，以模块形式提供给 Zephyr，并以预编译形式（libc.a）为每种支持的架构包含在 Zephyr SDK 中。

备注

Picolibc 也可用于其他第三方工具链，例如 GNU Arm Embedded。

Zephyr 实现了 Picolibc 中 C 标准库函数所调用的“API 钩子”函数。这些钩子函数实现于 lib/libc/picolibc/，负责将库内部的系统调用转换为等效的 Zephyr API 调用。

Picolibc 模块

作为 Zephyr 模块构建时，有多个配置项可用于调整库的特性集，在库所支持的功能与生成函数的代码大小之间取得平衡。由于标准 C++ 库必须针对目标 C 库进行编译，Picolibc 模块不能用于使用标准 C++ 库的应用程序。构建 Picolibc 模块会增加应用程序的编译时间。

在应用程序配置文件中选中 CONFIG_PICOLIBC_USE_MODULE，即可启用 Picolibc 模块。

将 Picolibc 模块更新到新版本时，Zephyr SDK 中随工具链捆绑的 Picolibc 也必须更新到相同版本。

工具链 Picolibc

从 0.16 版本开始，Zephyr SDK 为每种目标架构都包含预编译的 Picolibc，以及预编译的 libstdc++。

在应用程序配置文件中取消选中 CONFIG_PICOLIBC_USE_MODULE，即可启用工具链版本的 Picolibc。

对于 Zephyr 的每个版本，在使用 推荐版本的 Zephyr SDK 时，随工具链捆绑的 Picolibc 与 Picolibc 模块 保证保持同步。

在没有工具链捆绑 Picolibc 的情况下构建

对于没有捆绑 Picolibc 的工具链，仍然可以从源码构建 Picolibc 来使用它。注意，Picolibc 模块 中提到的所有限制仍然适用。

要在没有工具链捆绑 Picolibc 的情况下构建，工具链必须启用 CONFIG_PICOLIBC_SUPPORTED。例如，需要在工具链的 Kconfig 文件中添加以下内容：

config TOOLCHAIN_<name>_PICOLIBC_SUPPORTED
   def_bool y
   select PICOLIBC_SUPPORTED

启用 CONFIG_PICOLIBC_SUPPORTED 后，如果没有工具链捆绑的 Picolibc，构建系统会自动通过其模块从源码构建 Picolibc。

格式化输出

Picolibc 支持所有标准 C 格式化输入和输出函数，包括 printf()、fprintf()、sprintf() 和 sscanf()。

Picolibc 的格式化输入输出函数实现支持 C17 和 POSIX 2018 标准定义的所有格式说明符，但有以下例外：

  • 浮点格式说明符（例如 %f）需要启用 CONFIG_PICOLIBC_IO_FLOAT。

  • long long 格式说明符（例如 %lld）需要启用 CONFIG_PICOLIBC_IO_LONG_LONG。启用 CONFIG_PICOLIBC_IO_FLOAT 时会自动启用该选项。

printk、cbprintf 及相关函数

使用 Picolibc 时，Zephyr 的格式化输出函数基于 stdio 调用实现。包括：

  • printk、snprintk 和 vsnprintk

  • cbprintf 和 cbvprintf

  • fprintfcb、vfprintfcb、printfcb、vprintfcb、snprintfcb 和 vsnprintfcb

使用带标签的参数（CONFIG_CBPRINTF_PACKAGE_SUPPORT_TAGGED_ARGUMENTS 和 CBPRINTF_PACKAGE_ARGS_ARE_TAGGED）时，对 cbpprintf 的调用不会使用 Picolibc，因此这些代码的输出格式会与 Picolibc 的结果不同，因为 cbprintf 系列函数并不完全符合 C/POSIX 标准。

数学函数

Picolibc 为 float、double 和 long double 数学运算提供完整的 C17/IEEE STD 754-2019 支持，但 Bessel 函数的 long double 版本除外。

线程本地存储

Picolibc 对应当局限于各个线程的数据（例如 errno）使用线程本地存储（TLS）（在支持的情况下）。这意味着使用 Picolibc 时会启用 TLS 支持。由于所有 TLS 变量都从线程栈区域中分配，这可能会使栈大小需求增加几个字节。

C 库本地变量

Picolibc 使用少量内部变量来处理堆管理等事务。这些变量集中放在一个名为 z_libc_partition 的专用内存分区中。使用 CONFIG_USERSPACE 和内存域的应用程序必须确保，在调用 Picolibc 期间处于活动状态的任何内存域都包含该分区。

动态内存管理

Picolibc 使用 通用 C 库 提供的 malloc 系列 API 实现，而后者本身构建在 内核内存堆 API 之上。
