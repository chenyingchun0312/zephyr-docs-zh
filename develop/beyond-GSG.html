入门指南之外

入门指南 提供了一条直接的路径，用于在 Linux、macOS 或 Windows 上搭建 Zephyr 开发环境。本文将进一步探讨 Zephyr 开发环境搭建中的问题和替代方案。

Python 和 pip

Zephyr 大量使用 Python 3 及其包管理器 pip[1]，用于安装和运行编译、运行 Zephyr 应用程序所需的脚本，搭建和维护 Zephyr 开发环境，以及构建项目文档。

根据所用的操作系统，安装新软件包时可能需要为 pip3 命令提供 --user 标志。各处说明中都注明了这一点。关于 pip[1] 的更多信息（包括 information on -\-user），请参见 Python 打包用户指南中的 Installing Packages。

  • 在 Linux 上，请确保 ~/.local/bin 位于 PATH 环境变量 的最前面，否则将找不到使用 --user 安装的程序。使用 --user 安装可以避免 pip 与系统包管理器之间的冲突，这也是基于 Debian 的发行版的默认行为。

  • 在 macOS 上，Homebrew disables -\-user。

  • 在 Windows 上，如果需要使用 --user 选项，请参见 Installing Packages 中关于该选项的信息。

在所有操作系统上，如果软件包已在本地安装但有更新的版本可用，pip 的 -U 标志会安装或更新该软件包。如果需要软件包的最新版本，使用此标志是一种好习惯。（查看 scripts/requirements.txt 文件，了解是否要求特定版本的 Python 软件包。）

安装工具链

Zephyr 二进制文件由 工具链 编译和链接。工具链由交叉编译器及相关工具组成，与用于开发在主机操作系统上原生运行的软件的编译器和工具不同。

可以安装 Zephyr SDK 来获取所有受支持架构的工具链，也可以安装 SoC 厂商或特定开发板推荐的 其他工具链 （请查看具体的 开发板文档）。

可以通过设置 环境变量 来配置 Zephyr 构建系统使用特定的工具链，例如将 ZEPHYR_TOOLCHAIN_VARIANT 设置为受支持的值，并设置该工具链变体特有的其他变量。

更新 Zephyr SDK 工具链

更新 Zephyr SDK 时，请检查环境变量 ZEPHYR_TOOLCHAIN_VARIANT 或 ZEPHYR_SDK_INSTALL_DIR 是否已设置。

  • 如果这些变量未设置，默认会选择最新的兼容版本 Zephyr SDK。无需做任何更改，直接进行下一步。

  • 如果设置了 ZEPHYR_TOOLCHAIN_VARIANT，构建时会选择相应的工具链。Zephyr SDK 由值 zephyr 标识。如果环境变量 ZEPHYR_TOOLCHAIN_VARIANT 的值不是 zephyr，请取消设置该变量或将其值改为 zephyr，以确保选择 Zephyr SDK。

  • 如果设置了环境变量 ZEPHYR_SDK_INSTALL_DIR，它将覆盖 Zephyr SDK 的默认查找位置。如果将 Zephyr SDK 安装到某个 推荐位置，可以取消设置此变量；否则，请将其设置为所选的安装位置。

关于 Zephyr 中这些环境变量的更多信息，请参见 重要的环境变量。

克隆 Zephyr 仓库

Zephyr 项目源代码维护在 GitHub zephyr 仓库 中。Zephyr 使用的外部模块位于上级的 GitHub Zephyr 项目 中。由于存在这些依赖关系，使用 Zephyr 开发的 west 工具来获取和管理 Zephyr 及外部模块的源代码会很方便。详见 基础知识。

安装好开发工具后，使用 West（Zephyr 的元工具） 创建、初始化工作区，并从 zephyr 及外部模块仓库下载源代码。这里使用名称 zephyrproject，但可以选择任意名称，只要整个路径中不包含空格即可。

west init zephyrproject
cd zephyrproject
west update

west update 命令获取 zephyrproject 文件夹中的 模块（外部项目），并使其与本地 zephyr 仓库中的代码保持同步。

警告

每当 zephyr/west.yml 发生变化时，都必须运行 west update。例如，拉取 zephyr 仓库、在其中切换分支或执行 git bisect 时，都会导致该文件变化。

保持 Zephyr 为最新

要更新 Zephyr 项目源代码，需要通过 git 获取最新更改。之后按照上一段所述运行 west update。此外，还要检查是否有更新或新增的 Python 依赖项。

# replace zephyrproject with the path you gave west init
cd zephyrproject/zephyr
git pull
west update
west packages pip --install

:: replace zephyrproject with the path you gave west init
cd zephyrproject\zephyr
git pull
west update
cmd /c scripts\utils\west-packages-pip-install.cmd

# replace zephyrproject with the path you gave west init
cd zephyrproject\zephyr
git pull
west update
python -m pip install @((west packages pip) -split ' ')

导出 Zephyr CMake 包

如果在 入门指南 过程中尚未导出 Zephyr CMake 包，可以将其导出到 CMake 的用户包注册表。

开发板别名

使用多块开发板的开发者可能觉得明确写出开发板名称很繁琐，希望为常用目标使用别名。这可以通过一个内容类似如下的 CMake 文件来实现：

# Variable foo_BOARD_ALIAS=bar replaces BOARD=foo with BOARD=bar and
# sets BOARD_ALIAS=foo in the CMake cache.
set(pca10028_BOARD_ALIAS nrf51dk/nrf51822)
set(pca10056_BOARD_ALIAS nrf52840dk/nrf52840)
set(k64f_BOARD_ALIAS frdm_k64f)
set(sltb004a_BOARD_ALIAS efr32mg_sltb004a)

然后在 ZEPHYR_BOARD_ALIASES 中指定该文件的位置。这样就可以在 cmake -DBOARD=pca10028 和 west -b pca10028 等场景中使用别名 pca10028。

构建并运行应用程序

可以使用受支持的主机系统，在真实硬件上构建、烧录和运行 Zephyr 应用程序。根据所用的操作系统，还可以在 QEMU 中仿真运行，或者使用 native_sim 作为原生应用程序运行。关于构建应用程序的更多信息，请参见 构建应用程序 一节。

构建 Blinky

下面构建 Blinky 示例应用程序。

Zephyr 应用程序针对特定硬件构建，这种硬件称为“开发板”[2]。这里使用 Phytec reel_board，如果使用其他开发板，可以把构建目标 reel_board 改为其他值。要获取受支持开发板的列表，请参见 支持的开发板和扩展板，或在 zephyrproject 目录内的任意位置运行 west boards。

  1. 进入 zephyr 仓库：

    cd zephyrproject/zephyr

  2. 为 reel_board 构建 blinky 示例：

    # From the root of the zephyr repository
west build -b reel_board samples/basic/blinky

主要构建产物位于 build/zephyr 中；build/zephyr/zephyr.elf 是 ELF 格式的 blinky 应用程序二进制文件。根据开发板的不同，还可能生成其他格式的二进制文件、反汇编文件和映射（map）文件。

samples 文件夹中的其他示例应用程序在 Samples and Demos 中有文档说明。

备注

如果要为其他开发板或应用程序重用现有的构建目录，需要为 west build 添加参数 -p=auto，以清除上一次构建留下的设置和产物。

通过烧录到开发板运行应用程序

Zephyr 支持的大多数硬件开发板都可以通过运行 west flash 进行烧录。这可能需要安装和配置开发板特定的工具才能正常工作。

更多详细信息，请参见 运行应用程序 以及 支持的开发板和扩展板 中具体开发板的文档。

设置 udev 规则

烧录开发板需要直接访问开发板硬件的权限，这通常在安装烧录工具时进行配置。在 Linux 系统上，如果 west flash 命令失败，很可能需要定义 udev 规则来授予所需的访问权限。

udev 是 Linux 内核的设备管理器，udev 守护进程处理向系统添加（或从系统移除）硬件设备时产生的所有用户空间事件。可以添加一个规则文件，授予非 root 用户访问某些 USB 连接设备的权限。

OpenOCD（片上调试器）项目提供了一个方便的规则文件，为 Zephyr 支持的大多数基于 Arm 的开发板定义了开发板特定的规则。因此建议安装此规则文件：可以从其 sourceforge 仓库下载；如果已安装 Zephyr SDK，SDK 文件夹中也有该规则文件的副本：

  • 可以下载 OpenOCD 规则文件并将其复制到正确的位置:

    wget -O 60-openocd.rules https://sf.net/p/openocd/code/ci/master/tree/contrib/60-openocd.rules?format=raw
sudo cp 60-openocd.rules /etc/udev/rules.d

  • 也可以从 Zephyr SDK 文件夹中复制规则文件:

    sudo cp ${ZEPHYR_SDK_INSTALL_DIR}/sysroots/x86_64-pokysdk-linux/usr/share/openocd/contrib/60-openocd.rules /etc/udev/rules.d

然后，无论采用哪种方式，都要让 udev 守护进程重新加载这些规则:

sudo udevadm control --reload

拔下并重新插入开发板的 USB 连接后，应该就有权限访问开发板硬件进行烧录了。如有需要，请查看开发板特定的文档（支持的开发板和扩展板）以获取更多信息。

在 QEMU 中运行应用程序

以 x86 或 ARM Cortex-M3 架构为目标时，可以使用 QEMU 在主机系统上通过仿真运行 Zephyr 应用程序。Zephyr SDK 中包含 QEMU。

如果使用手动安装的 QEMU，请确保它在系统环境变量 PATH 中可用。

QEMU_BIN_PATH 是一个可选的覆盖设置，用于指定 Twister 所用 QEMU 二进制文件的位置。如果提供了该设置，Twister 会验证指定的路径是否存在；否则，Twister 依靠 SDK 或其他 QEMU 查找机制。

例如，可以使用 x86 仿真开发板配置（qemu_x86）构建并运行 Hello World 示例，命令如下：

# From the root of the zephyr repository
west build -b qemu_x86 samples/hello_world
west build -t run

要退出 QEMU，请按 Ctrl-a，然后按 x。

使用 qemu_cortex_m3 以仿真的 Arm Cortex-M3 为目标运行示例。

以原生方式运行示例应用程序（Linux）

可以将某些示例编译为在 Linux 上作为主机程序运行。更多信息请参见 Native simulator - native_sim。在 64 位主机操作系统上，需要安装 32 位 C 库，或者以 native_sim/native/64 为目标进行构建。

首先，为 native_sim 构建 Hello World。

# From the root of the zephyr repository
west build -b native_sim samples/hello_world

接着，运行该应用程序。

west build -t run
# or just run zephyr.exe directly:
./build/zephyr/zephyr.exe

按 Ctrl-C 退出。

可以运行 ./build/zephyr/zephyr.exe --help 获取可用选项列表。

可以使用 gdb 或 valgrind 等标准工具对该可执行文件进行插桩分析。

脚注

[1] (1,2)

pip 是 Python 的软件包安装程序。它的 install 命令首先尝试重用计算机上已安装的软件包及其依赖项。如果无法重用，pip install 会从互联网上的 Python 软件包索引（PyPI）下载它们。

Zephyr 的 requirements.txt 所要求的软件包版本可能与系统上的其他需求冲突，这种情况下可以为 Zephyr 开发搭建一个 virtualenv。

[2]

随着时间推移，这个名称已经有些名不副实。虽然目标可以是（而且通常是）运行在专用硬件开发板上的微处理器，但 Zephyr 还支持：使用 QEMU 仿真运行为其他架构构建的目标；生成原生主机系统二进制文件、并用 POSIX API 实现 Zephyr 驱动接口的目标；甚至在同一块物理芯片上不同架构的 CPU 核上运行不同的基于 Zephyr 的二进制文件。所有这些硬件配置都称为“开发板”，尽管在具体语境中这个叫法并不总是十分贴切。
