ARM V2M Musca B1

概述

v2m_musca_b1 开发板配置用于在 V2M Musca B1 开发板上运行的 Zephyr 应用程序。它支持 Musca B1 ARM Cortex-M33 CPU 以及以下设备：

  • 嵌套向量中断控制器（NVIC）

  • 系统节拍时钟（SYSTICK）

  • Cortex-M System Design Kit GPIO

  • Cortex-M System Design Kit UART

有关此开发板的更多信息，请访问 V2M Musca B1 Website。

硬件

ARM V2M MUSCA B1 提供以下硬件组件：

  • ARM Cortex-M33

  • 适用于 Cortex-M33 的 ARM IoT 子系统

  • 内存

    • 512KB 片上系统存储器 SRAM。

    • 8MB 外部 QSPI Flash。

    • 4MB 片上启动 eFlash。

  • 调试

    • JTAG、SWD 和 4 位 TRACE。

    • 带虚拟 UART 端口的 DAPLink。

  • Arduino 接口

    • 16 3V3 GPIO.

    • UART.

    • SPI.

    • I2C.

    • I2S.

    • 3 通道 PWM。

    • 6 通道模拟接口。

  • 板载外设

    • 用户 RGB LED。

    • 陀螺仪传感器。

    • ADC/DAC/温度传感器组合器件。

    • 安全数字 I/O（SDIO）microSD 卡。

用户按键

v2m_musca_b1 开发板提供以下用户按键：

  • PBON：电源开/关。

  • nSRST：Cortex-M33 系统复位和 CoreSight 调试复位。

  • ISP：更新 DAPLink 固件。

引脚映射

ARM V2M Musca B1 开发板有 4 个 GPIO 控制器。这些控制器负责引脚复用、输入/输出、上拉等功能。

所有 GPIO 控制器引脚按以下引脚编号顺序引出：

  • 引脚 0 - 15 属于 GPIO

ARM V2M Musca B1 开发板引脚到 GPIO 控制器的映射：

  • D0 : P0_0

  • D1 : P0_1

  • D2 : P0_2

  • D3 : P0_3

  • D4 : P0_4

  • D5 : P0_5

  • D6 : P0_6

  • D7 : P0_7

  • D8 : P0_8

  • D9 : P0_9

  • D10 : P0_10

  • D11 : P0_11

  • D12 : P0_12

  • D13 : P0_13

  • D14 : P0_14

  • D15 : P0_15

外设映射：

  • UART_0_RX : D0

  • UART_0_TX : D1

  • SPI_0_CS : D10

  • SPI_0_MOSI : D11

  • SPI_0_MISO : D12

  • SPI_0_SCLK : D13

  • I2C_0_SDA : D14

  • I2C_0_SCL : D15

更多细节请参阅 Musca B1 Technical Reference Manual (TRM)。

RGB LED

Musca B1 有一个内置 RGB LED，连接到 GPIO[4:2] 引脚。

  • 红色 LED 连接到 GPIO[2] 引脚，可选 PWM0。

  • 绿色 LED 连接到 GPIO[3] 引脚，可选 PWM1。

  • 蓝色 LED 连接到 GPIO[4] 引脚，可选 PWM2。

备注

SCC 寄存器选择 GPIO[4:2] 引脚的功能。

系统时钟

V2M Musca B1 有一个 32.768kHz 晶体时钟。该时钟送入 PLL 倍频后驱动 Cortex-M33 处理器和 SSE-200 子系统。默认频率为 40MHz，但对于副处理器（CPU1），可通过软件配置提高到最高 160MHz。主处理器（CPU0）的最高时钟频率为 40MHz。

串口

ARM Musca B1 处理器有两个 UART。两个 UART 都只有 RX/TX 两根线，没有流控（CTS/RTS），也没有 FIFO。Zephyr 控制台输出默认使用 UART1。

安全组件

  • 实现定义属性单元（IDAU）。IDAU 用于定义安全和非安全内存映射。默认情况下，所有内存空间都定义为仅可安全访问。

  • 通过外设保护控制器（PPC）区分安全和非安全外设。外设可以分配为可安全访问或可非安全访问。

  • 安全启动。

  • 安全 AMBA® 互连。

串行配置控制器（SCC）

ARM Musca B1 测试芯片实现了串行配置控制（SCC）寄存器。该寄存器用于单独控制外设的时钟、复位信号和中断，以及引脚复用。

启动存储器

Musca-B1 测试芯片默认从 4MB eFlash 正常启动，这是最快的启动方式。Musca-B1 测试芯片也支持从 8MB QSPI 启动。可以更新 DAPLink 固件，选择从 QSPI 或 eFlash 启动。

编程与调试

Musca B1 支持 v8m 安全扩展，默认启动进入安全状态。

构建安全/非安全应用程序时，安全应用程序必须在跳转之前设置 idau/sau 和 mpc 配置，允许非安全应用程序进行访问。

安全固件运行期间需要正确配置以下系统组件：

  • AHB5 TrustZone 内存保护控制器（MPC）。

  • AHB5 TrustZone 外设保护控制器（PPC）。

  • 实现定义属性单元（IDAU）。

详情参见 Corelink SSE-200 Subsystem。

烧录

DAPLink

V2M Musca B1 提供：

  • 一条连接主机的 USB 连接，提供一个大容量存储设备和一个 USB 串口。

  • 一个串行 Flash 设备，用于实现 USB 闪存盘文件存储。

  • 一条物理 UART 连接，通过 USB 串口接口进行转发。

这些接口通过 DAPLink 提供，DAPLink 提供：

  • 串行线调试（SWD）。

  • USB 大容量存储设备（USBMSD）。

  • UART.

  • 远程复位。

详情参见 DAPLink Website。

构建纯安全应用程序

可以按常规方式构建应用程序。以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b v2m_musca_b1 samples/hello_world

使用以下设置打开串口终端（minicom、putty 等）：

  • 波特率：115200

  • 数据位：8 位

  • 校验位：无

  • 停止位：1

复位开发板，应能在对应串口上看到以下消息：

Hello World! musca_b1
使用可信固件构建安全/非安全应用程序

该过程需要五个步骤：

  1. 构建可信固件（tfm）。

  2. 将其作为库导入 Zephyr 源代码目录。

  3. 使用非安全配置构建 Zephyr。

  4. 将两个二进制文件合并并签名。

  5. 将引导加载程序与已签名的镜像数据拼接在一起。

构建 tfm 请参阅 Trusted Firmware M Guide。按照 AN521 目标的构建步骤操作，但将平台替换为 -DTARGET_PLATFORM=MUSCA_B1，并（如有需要）将编译器替换为 -DCOMPILER=GNUARM

将 tfm 作为库复制到 Zephyr 项目源代码中，并为安全 veneer 和所需的头文件创建快捷方式。TF-M 构建完成后，所有文件都位于 install 目录中。

将应用程序上传到 V2M Musca B1

应用程序在烧录到 V2M Musca B1 之前必须转换为 Intel hex 格式。可以选择在镜像前添加引导加载程序。QSPI Flash 基地址别名为 0x0，eFlash 基地址别名为 0xA000000。镜像偏移等于 Flash 偏移加上引导加载程序分区大小。

使用第三方工具（srecord）生成 Intel 格式的 hex 镜像。更多信息请参阅 Srecord Manual。

srec_cat $BIN_BOOTLOADER -Binary -offset $FLASH_OFFSET $BIN_SNS -Binary -offset $IMAGE_OFFSET -o $HEX_FLASHABLE -Intel

# For a 128K bootloader IMAGE_OFFSET = $FLASH_OFFSET + 0x20000
srec_cat $BIN_BOOTLOADER -Binary -offset 0xA000000 $BIN_SNS -Binary -offset 0xA020000 -o $HEX_FLASHABLE -Intel

使用 USB 端口将 V2M Musca B1 连接到主机。应能看到一个呈现为大容量存储设备（MUSCA_B）和 USB 串口的 USB 连接。将生成的 zephyr.hex 复制到 MUSCA_B 驱动器中。

复位开发板，应能在对应串口上看到以下消息：

Hello World! musca_b1
