Arm Corstone-1000-A320 固定虚拟平台

概述

此开发板配置使用 Arm Corstone-1000-A320 固定虚拟平台（FVP）仿真以 Cortex-A320 为主处理器的 Arm Corstone-1000 参考设计。

Corstone-1000 是 Arm 面向安全物联网系统的参考设计，具有以下特性：

  • 带 Cortex-A320（ARMv9.2-A）的主机处理器子系统

  • 运行 TF-M 的安全飞地（Secure Enclave，Cortex-M0+）

  • Ethos-U85 NPU（神经网络处理单元）

  • CryptoCell-312 硬件加速器

  • 基于 MCUboot 验证启动的系统级安全

此配置支持：

  • Cortex-A320 CPU（ARMv9.2-A 架构）

  • GICv3 中断控制器（GIC-600）

  • ARM 架构（通用）定时器

  • PL011 UART 控制器

  • SVE2（可伸缩向量扩展 2）

备注

FVP 模型中包含 Ethos-U85 NPU，但此开发板配置目前不支持它。

启动架构

Corstone-1000 采用涉及两个处理器的多级启动流程：

Secure Enclave (M0+):  BL1_1 -> BL1_2 -> BL2/MCUboot -> TF-M SPE -.
                                                                     |
Host CPU (A320):                                TF-A BL2 -> BL31 -> Zephyr (BL33)

Secure Enclave (Cortex-M0+):

  1. BL1_1（ROM）— 硬件初始化、密钥配置

  2. BL1_2（OTP）— 由 BL1_1 验证

  3. BL2（MCUboot）— 解析 GPT，加载 TF-M 和 TF-A 镜像并进行 ECDSA 验证

  4. TF-M 运行时 — 初始化 ITS/PS/Crypto 分区，通过 DSU-120T PPU 为主机 CPU 上电

Host CPU (Cortex-A320):

  1. TF-A BL2 — 由 MCUboot 加载，解析 FIP，加载 BL31 和 BL33

  2. TF-A BL31 — EL3 运行时（PSCI、GIC 初始化），通过 ERET 进入 NS-EL1

  3. BL33（Zephyr）— 运行在 EL1 的非安全应用程序

备注

FVP 的配置（provisioning）周期需要在真正启动之前完成两次完整的 SE 启动。这是正常现象：第一次启动会配置虚拟密钥，然后重新启动。

编程与调试

前提条件

  1. Zephyr SDK（推荐）— 同时提供用于 TF-M 的 arm-zephyr-eabi 和用于 Zephyr/TF-A 构建的 aarch64-zephyr-elf，以及用于编译 TF-A 设备树的 dtc。

  2. Corstone-1000-A320 FVP — 从 Arm Ecosystem FVPs 下载。

    将 ARMFVP_BIN_PATH 环境变量设置为包含 FVP 二进制文件的目录（默认安装路径如下所示）：

    export ARMFVP_BIN_PATH=~/FVP_Corstone_1000-A320/models/Linux64_GCC-9.3

  3. sgdisk — 用于创建 GPT 分区表。从 gdisk 软件包安装：

    # Fedora / RHEL
sudo dnf install gdisk

# Ubuntu / Debian
sudo apt install gdisk

构建

此开发板需要支持 Corstone-1000-A320 的 TF-M 和 TF-A 模块。检出此分支后，更新模块：

west update

此开发板需要使用 Sysbuild（系统构建），以便与 Zephyr 一起自动构建 TF-M（安全飞地）和 TF-A（主机固件）：

west build -b fvp_corstone1000/a320 samples/hello_world --sysbuild

小技巧

如果不想每次都传入 --sysbuild，可以将其设为默认值：

west config build.sysbuild true

这会在 build/firmware/ 中生成：

  • bl1.bin — 安全飞地 ROM（BL1_1 + 配置数据包）

  • cs1000.bin — 32 MB GPT Flash 镜像，包含已签名的 TF-M、已签名的 TF-A BL2、BL31，以及位于 FIP 中的 Zephyr

运行

west build -t run

要设置仿真时间限制或其他 FVP 选项，请在配置阶段设置 ARMFVP_EXTRA_FLAGS：

ARMFVP_EXTRA_FLAGS="--simlimit 120" west build -b fvp_corstone1000/a320 \
    samples/hello_world --sysbuild
west build -t run

预期输出（配置周期结束后）：

*** Booting Zephyr OS build v4.3.0-... ***
Hello World! fvp_corstone1000/a320

调试

请参阅 应用程序调试 的详细概述。

FVP 支持通过 Arm Development Studio 或其他使用 Iris 调试接口的调试器进行连接。

小技巧

若要在 UART 可用之前调试早期启动过程，可以启用 CONFIG_SEMIHOST 和 CONFIG_SEMIHOST_CONSOLE 并禁用 CONFIG_UART_CONSOLE，以使用半主机（semihosting）。FVP 默认启用半主机。

已知限制

  • 仅限 Linux/Unix 主机 — sysbuild 集成使用 POSIX shell 工具（sh、dd、sgdisk）组装安全飞地 Flash 镜像，目前不支持 Windows 主机。

  • Ethos-U85 NPU — FVP 模型中包含该 NPU，但 Zephyr 目前不支持它。

  • mmap 重叠警告 — TF-A BL2/BL31 中会出现 mmap_add_region_check() failed. error -22。这是 release 模式下 Ethos-U85 内存映射重叠导致的非致命问题，在 Yocto 参考构建中同样存在。
