ARM MPS2+ AN521

概述

mps2/an521 开发板配置用于在 MPS2+ AN521 开发板上运行的 Zephyr 应用程序。它支持 MPS2+ AN521 ARM Cortex-M33 CPU 以及以下设备：

  • 嵌套向量中断控制器（NVIC）

  • 系统节拍时钟（SYSTICK）

  • Cortex-M System Design Kit GPIO

  • Cortex-M System Design Kit UART

除了支持在实际硬件上使用之外，此开发板配置还可以使用 QEMU 仿真运行在 MPS2+ 上的 AN521 平台。

有关此开发板的更多信息，请访问 MPS2 FPGA Website。

备注

此开发板配置不保证适用于使用 AN521 的实际 MPS2 硬件系统或任何其他硬件系统。它已在实际硬件上测试过，但主要用途是配合 QEMU 和 ARM Cortex-M33 的单元测试使用。

Zephyr 开发板选项

MPS2+ AN521 是一款双核 SoC，两个内核（CPU0 和 CPU1）均采用 Cortex-M33 架构。Zephyr 支持为 CPU0 和 CPU1 构建固件镜像。CPU0 支持 ARM 安全扩展，可以为其构建安全和非安全固件镜像。

内存分区

AN521 为代码空间分配了 4MB，为 SRAM 分配了 4MB。这些存储区域由两个内核共享，并在安全区域和非安全区域中都有别名，其中安全内存别名相对于非安全内存的偏移为 0x10000000。

默认使用以下内存映射和分区方案，其中偏移值是相对于 4MB 代码块或 SRAM 块基址的偏移，不考虑 S/NS 别名的差异。

NS

mps2/an521/cpu0/ns 开发板目标用于配合 TF-M 使用，其 Zephyr 内存映射与上游 TF-M 中定义的 AN521 内存映射一致。TF-M 先启动安全处理环境，然后在非安全处理环境中初始化 Zephyr。非安全 Zephyr 镜像做了偏移，为安全引导加载程序和安全固件（TF-M）留出空间，因此起始地址为 0x00100000。SRAM 以 1MB 偏移从 0x28100000 开始。

mps2/an521/cpu1 开发板目标针对 AN521 上的第二个内核，使用 4MB 代码块中最后的 468KB 代码存储器。选择这个值是为了与 TF-M 保持兼容，TF-M 将最后这 468KB 代码区域标记为 Unused。因此代码存储器从 3628KB 偏移处（地址 0x0038B000）开始，SRAM 从 1.5MB 偏移处（地址 0x28180000）开始。

这种内存映射使两个备选开发板目标可以在需要时一起使用，代价是第二个内核上可用的代码存储器按 TF-M 的最坏情况减少。

使用其中一个备选开发板目标（mps2/an521/cpu0/ns 或 mps2/an521/cpu1）时，由于内存映射存在部分重叠，需要注意主开发板目标（mps2/an521）所使用的代码存储器或 SRAM 的大小。

硬件

ARM MPS2+ AN521 提供以下硬件组件：

  • 双核 ARM Cortex-M33

  • SSE-200 子系统的软宏模型（SMM）实现

  • 内存

    • 4MB 代码存储器（SSRAM1）

    • 4MB SRAM（SSRAM2 和 SSRAM3）

    • 16MB 并行 SRAM（PSRAM，仅非安全）

    • 8KB NVM 代码存储器

  • 调试

    • P-JTAG、SWD 和 16 位 TRACE

    • UART 端口

  • 接口

    • 连接到 EXP 端口的 AHB GPIO

    • UART

    • SPI

    • I2C

    • I2S

    • 彩色 LCD 串行接口

    • 以太网

    • VGA

  • 板载外设

    • 彩色 LCD

    • 8 LEDs

    • 8 个开关

    • 外部 SSRAM1、SSRAM2 和 SSRAM3

    • SMSC9220

    • CS42L52

用户按键

mps2/an521 开发板提供以下用户按键：

  • ON：上电

  • nSRST：Cortex-M33 系统复位和 CoreSight 调试复位

  • USERPB0 和 USERPB1：用户自定义按键

支持的功能

  • 详情参见 V2M MPS2。

LED

MPS2+ 有 8 个内置 LED，连接到串行配置控制器（SCC）。

备注

SCC 寄存器 CFG_REG1 的位 [7:0] 对应 LEDa，0 = 灭，1 = 亮。

系统时钟

MPS2+ AN521 连接了以下几个时钟：

  • MAINCLK : 20MHz

  • SYSCLK : 20MHz

  • S32KCLK : 32kHz

  • TRACECLK : 20MHz

  • SWCLKTCK : 20MHz

  • TRACECLKIN : 20MHz

串口

MPS2+ AN521 有五个 UART。Zephyr 控制台输出默认使用 UART0，即开发板上的 J10。

UART2 为保留。UART 1、3 和 4 是 EXP 端口上的复用功能。

安全组件

  • 实现定义的属性单元（IDAU）。IDAU 用于定义安全和非安全内存映射。默认情况下，整个内存空间都定义为仅可安全访问

  • 通过外设保护控制器（PPC）提供安全和非安全外设。外设可以分配为可安全访问或可非安全访问

  • 安全启动

  • 安全 AMBA® 互连

串行配置控制器（SCC）

MPS2+ AN521 实现了串行配置控制（SCC）寄存器。该寄存器用于单独控制外设的时钟、复位信号和中断，以及引脚复用、LED 和开关。

编程与调试

MPS2+ AN521（CPU0）支持 Armv8m 安全扩展。为 mps2/an521 开发板构建的应用程序默认在安全状态下启动。

MPS2+ AN521（CPU1）不支持 Armv8m 安全扩展。

使用 Arm® TrustZone® 构建安全/非安全 Zephyr 应用程序

MPS2+ AN521（CPU0）上的应用程序可以包含一个安全固件镜像和一个非安全固件镜像。安全镜像可以使用 Zephyr 或 Trusted Firmware M（TF-M）构建。非安全固件镜像始终使用 Zephyr 构建。下面介绍这两种方式。

备注

默认情况下，MPS2+ AN521（CPU0）的安全镜像使用 TF-M 构建。

使用 TF-M 构建安全固件

使用 TF-M 构建安全固件镜像、使用 Zephyr 构建非安全固件镜像的过程需要以下步骤：

  1. 使用 -DBOARD=mps2/an521/cpu0/ns 为 MPS2+ AN521（CPU0）构建非安全 Zephyr 应用程序。要触发 TF-M 的构建，Zephyr 构建系统要求启用 Kconfig 选项 BUILD_WITH_TFM，将 Zephyr 构建为非安全应用程序时默认会启用该选项。Zephyr 构建系统会自动执行以下步骤：

    • 将非安全固件镜像作为普通 Zephyr 应用程序构建

    • 构建 TF-M（安全）固件镜像

    • 将输出的镜像二进制文件合并在一起

    • 可选：构建引导加载程序镜像（MCUboot）

备注

根据 TF-M 配置的不同，可能需要为应用程序提供 DTS 覆盖文件，以调整非安全镜像的 Flash 和 SRAM 起始地址及大小。

使用 Zephyr 构建安全固件

使用 Zephyr 构建安全和非安全固件镜像的过程需要以下步骤：

  1. 使用 -DBOARD=mps2/an521，并在应用程序项目配置文件中设置 CONFIG_TRUSTED_EXECUTION_SECURE=y 和 CONFIG_BUILD_WITH_TFM=n，为 MPS2+ AN521（CPU0）构建安全 Zephyr 应用程序。

  2. 使用 -DBOARD=mps2/an521/cpu0/ns 为 MPS2+ AN521（CPU0）构建非安全 Zephyr 应用程序。

  3. 将两个二进制文件合并在一起。

在 MPS2+ AN521（CPU0）上构建仅安全应用程序

按常规方式构建 Zephyr 应用程序（参见 构建应用程序 和 运行应用程序），为运行在 MPS2+ AN521（CPU0）上的固件使用 -DBOARD=mps2/an521。

为 MPS2+ AN521（CPU0）构建安全/非安全应用程序时，安全应用程序必须设置 SAU/IDAU 配置，允许非安全访问非安全应用程序固件所用的全部 CPU 资源。SAU/IDAU 配置应在跳转到非安全应用程序之前完成。

安全固件运行期间需要正确配置以下系统组件：

  • AHB5 TrustZone 内存保护控制器（MPC）

  • AHB5 TrustZone 外设保护控制器（PPC）

  • 实现定义的属性单元（IDAU）

更多细节请参阅 Corelink SSE-200 Subsystem。

在 MPS2+ AN521 CPU1 上构建独立应用程序

可以为 MPS2+ AN521 的第二个 Cortex-M33（远程）内核构建应用程序。该内核称为 CPU1。

按常规方式构建 Zephyr 应用程序（参见 构建应用程序 和 运行应用程序），为运行在 MPS2+ AN521（CPU1）上的固件使用 -DBOARD=mps2/an521/cpu1。

Zephyr 构建会自动为 CPU0 构建一个最小的（空的）仅安全固件，用于启动远程内核（CPU1）。

烧录

MPS2+ AN521 提供：

  • 一个连接到主机的 USB 接口，呈现为大容量存储设备

  • 一个串口，即 MPS2+ 开发板上的 J10

按上述方式构建应用程序。以下是将 Hello World 应用程序构建为 CPU0 仅安全应用程序的示例。

# From the root of the zephyr repository
west build -b mps2/an521 samples/hello_world

使用以下设置打开串口终端（minicom、putty 等）：

  • 波特率：115200

  • 数据位：8 位

  • 校验位：无

  • 停止位：1

复位开发板，应能在对应串口上看到以下消息：

Hello World! mps2_an521

将应用程序上传到 MPS2+ AN521

应用程序可以是 elf、hex 或 bin 格式。开发板启动时，使用存储在板载 Micro SD 卡上的文件烧录二进制文件。主板配置控制器（MCC）负责加载 FPGA 镜像和二进制文件。

使用 USB 端口将 MPS2+ 连接到主机。应能看到一个呈现为大容量存储设备的 USB 连接（默认为 V2M_MPS2）。

更新需要 3 个步骤：

  1. 将应用程序文件复制到 <MPS2 device name>/SOFTWARE/。

  2. 打开 <MPS2 device name>/MB/HBI0263C/AN521/images.txt。
