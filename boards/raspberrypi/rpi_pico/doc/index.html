Raspberry Pi Pico

Board Overview

Name:
rpi_pico
Vendor:

Raspberry Pi Foundation

Status:

Not actively maintained

Architecture:

arm

SoC:

rp2040

Browse board sources

概述

Raspberry Pi Pico [1] 和 Pico W 是 Raspberry Pi 推出的小巧、低成本、用途广泛的开发板。它们配备 RP2040 [2] SoC、一个板载 LED、一个 USB 连接器和一个 SWD 接口。

Pico W 还另外带有一个 Infineon CYW43439 [3] 2.4 GHz Wi-Fi/Bluetooth 模块。

RP2040 有两个 Cortex-M0+ 内核。Zephyr 目前只在一个内核上运行，不支持在第二个内核上运行代码。

借助 USB 引导加载程序，无需任何适配器，通过拖放即可完成烧录。也可以使用外部适配器，通过开发板的 SWD 接口进行烧录和调试。

硬件

  • 双核 Arm Cortex-M0+ 处理器，主频最高 133MHz

  • 264KB 片上 SRAM

  • 2MB 板载 QSPI Flash，支持 XIP

  • 26 个 GPIO 引脚

  • 3 个模拟输入

  • 2 个 UART 外设

  • 2 个 SPI 控制器

  • 2 个 I2C 控制器

  • 16 个 PWM 通道

  • USB 1.1 控制器（主机/设备）

  • 8 个可编程 I/O（PIO），用于实现自定义外设

  • 板载 LED

  • 1 个看门狗定时器外设

  • Infineon CYW43439 2.4 GHz Wi-Fi 芯片（仅限 Pico W）

引脚映射

RP2040 SoC 的外设可以路由到开发板上的不同引脚。这些路由配置可以通过 DTS 修改。各外设可用的路由方式请参阅数据手册。

Pico W 的外部引脚映射与 Pico 相同，但要注意，在 W 上 RP2040 内部的 GPIO 23、24、25 和 29 连接到了 Infineon 模块。由于 GPIO 25 在 Pico 上连接板载 LED，而在 Pico W 上连接 Infineon 模块，"blinky" 示例程序无法在 W 上运行（可以改用 hello_world 作为简单的测试程序）。

Zephyr 默认外设映射：

  • UART0_TX : P0

  • UART0_RX : P1

  • I2C0_SDA : P4

  • I2C0_SCL : P5

  • I2C1_SDA : P6

  • I2C1_SCL : P7

  • SPI0_RX : P16

  • SPI0_CSN : P17

  • SPI0_SCK : P18

  • SPI0_TX : P19

  • ADC_CH0 : P26

  • ADC_CH1 : P27

  • ADC_CH2 : P28

  • ADC_CH3 : P29

可编程 I/O（PIO）

RP2040 SoC 带有两个 PIO 外设。它们是两个专为 I/O 操作设计的简单协处理器。PIO 运行一套自定义指令集，由一种自定义汇编语言生成。PIO 程序使用 Raspberry Pi 提供的工具 pioasm 汇编。

Zephyr（目前）不会汇编 PIO 程序，而应手动汇编后嵌入源代码中。具体做法可参考 drivers/serial/uart_rpi_pico_pio.c。

示例：通过 PIO 实现 SPI

samples/sensor/bme280/README.rst 示例演示了如何使用 PIO SPI 驱动与环境传感器通信。PIO SPI 驱动支持用任意 GPIO 引脚组合构成 SPI 总线，并且单块开发板上最多可以有四条独立的 SPI 总线（使用两个 SPI 设备和两个 PIO 设备）。

系统要求

Pico W 的前提条件

为 Raspberry Pi Pico W 构建需要 Infineon 提供的 AIROC 二进制 blob。运行以下命令获取这些文件：

west blobs fetch hal_infineon

备注

建议在执行 west update 之后运行上述命令。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

rpi_pico 开发板配置的应用程序可以按常规方式构建和烧录（详见 构建应用程序 和 运行应用程序）。

有多种调试工具支持 Raspberry Pi Pico。Raspberry Pi Debug Probe [6] 是 Raspberry Pi 基金会官方提供的 CMSIS-DAP 适配器，容易购买，是调试 rpi_pico 的便捷选择。它可以配合 openocd 或 pyocd 使用。

烧录

rpi_pico 可以使用 Zephyr 的标准方法烧录。另请参见 构建、烧录与调试。

使用 OpenOCD

要使用 Raspberry Pi Debug Probe 等调试适配器，必须配置 udev。详见 设置 udev 规则。

Raspberry Pi Pico 有一个 SWD 接口，可用于编程和调试板载 SoC。该接口可以配合 OpenOCD 使用，需要 OpenOCD 0.12.0 或更高版本。

如果使用基于 Debian 的系统（包括 Raspberry Pi OS、Ubuntu 等），使用 pico_setup.sh [4] 脚本可以方便地安装 OpenOCD 的分支版本。

下面是构建并烧录 Blinky 应用程序的示例。

# From the root of the zephyr repository
west build -b rpi_pico samples/basic/blinky -- -DRPI_PICO_DEBUG_ADAPTER=cmsis-dap
west flash --openocd /usr/local/bin/openocd

将烧录运行器选项 --openocd 设为 /usr/local/bin/openocd。这适用于按默认配置安装的 OpenOCD，也适用于由 pico_setup.sh [4] 脚本搭建的环境。

在这个示例中，RPI_PICO_DEBUG_ADAPTER 指定调试所用的调试适配器。

如果未设置 RPI_PICO_DEBUG_ADAPTER，默认使用 cmsis-dap。已验证 raspberrypi-swd 和 jlink 可以正常工作。cmsis-dap 和 raspberrypi-swd 的连接方法见 Getting Started with Raspberry Pi Pico [5]。其他 SWD 调试适配器可能也适用于此配置。

RPI_PICO_DEBUG_ADAPTER 的值会被缓存，因此如果之前运行 west build 时已设置，west flash 和 west debug 中可以省略。

RPI_PICO_DEBUG_ADAPTER 用在传给 OpenOCD 的参数 "source [find interface/${RPI_PICO_DEBUG_ADAPTER}.cfg]" 中。因此 RPI_PICO_DEBUG_ADAPTER 需要设为调试适配器配置文件的名称。

使用 JLink 或其他受支持的工具

可以按照 构建、烧录与调试 中的说明，使用 SEGGER J-Link [7] 调试探针烧录。

下面是构建并烧录 Blinky 应用程序的示例。

# From the root of the zephyr repository
west build -b rpi_pico samples/basic/blinky
west flash --runner jlink

也可以通过修改 -- runner 选项使用其他受支持的工具，例如 Black Magic Probe [8]。

使用 UF2

如果没有 SWD 适配器，可以使用 UF2 文件烧录 Raspberry Pi Pico。默认情况下，为该开发板构建应用程序会生成 build/zephyr/zephyr.uf2 文件。如果在按住 BOOTSEL 按键的同时给 Pico 上电，它会在主机上显示为大容量存储设备。运行以下命令，或将 uf2 文件拖放到该设备中，即可烧录 Pico。

# From the root of the zephyr repository
west build -b rpi_pico samples/basic/blinky
west flash --runner uf2

调试

与烧录一样，调试也可以使用 Zephyr 的标准方法进行（参见 运行应用程序）。以下示例演示如何使用 OpenOCD 和 Raspberry Pi Debug Probe [6] 进行调试。

# From the root of the zephyr repository
west build -b rpi_pico samples/basic/blinky
west debug --openocd /usr/local/bin/openocd

默认调试工具是 openocd。如果使用其他工具，请用 --runner 指定，例如 jlink。
