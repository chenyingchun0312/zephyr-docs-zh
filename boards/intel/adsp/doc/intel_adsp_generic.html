Intel ADSP cAVS 和 ACE

Intel 的音频与数字信号处理（ADSP）硬件产品包括 Converged Audio Voice Speech（cAVS）系列及其后继产品 Audio and Context Engine（ACE）。这些基于 Xtensa 的 ADSP 可以集成到多种 Intel 产品中。下表列出了各版本 Intel ADSP 所兼容的（部分）Intel 微处理器。

ADSP

微处理器

cAVS 1.5

Apollo Lake

cAVS 1.8

Whiskey Lake

cAVS 2.5

Tiger Lake

ACE 1.5

Meteor Lake

Intel 在 Sound Open Firmware（SOF）项目下开源了其 ADSP 硬件的固件。SOF 既可以基于 Zephyr 构建，也可以基于 Cadence 专有的 Xtensa OS（XTOS）构建，并可在多种 Intel 和非 Intel 平台上运行。

Intel UP Xtreme 产品线提供了公开可用的参考开发板，用于 Zephyr 的 Intel ADSP 支持。本指南以 UP Xtreme i11-0001 series （Intel ADSP CAVS 2.5）开发板为例。不过，除非另有说明，这些说明是通用的，同样适用于其他开发板。遇到特殊情况时，会引导你参阅具体开发板的文档。

系统要求

设置目标开发板

只能在开发板主 CPU 上运行的 Linux 主机中使用 Zephyr 的 Python 工具将 Zephyr 烧录到 ADSP。用户可以（也推荐）在本地开发机上构建二进制文件，再进行远程烧录，但开发板本身必须能够运行 Python 脚本，由该脚本接收 West 通过网络发送的二进制文件并完成烧录。应安装支持或自带 Zephyr 所需的当前 Python 版本的 Linux。可以考虑使用自带 Python 3.8 的 Ubuntu 20.04。

注意，如果打算在开发板上使用 SOF，则需要构建并安装修改过的 Linux SOF 内核，而不是默认内核。建议按照 SOF instructions 在 Zephyr 上构建并运行 SOF。

UP Xtreme 用户可以参阅 UP Community wiki，获取在开发板上安装 Linux 操作系统的帮助。

签名工具

由于从 Skylake 开始的 Intel 产品强制要求对固件二进制文件签名，你还需要设置 SOF rimage 签名工具和密钥。

git clone https://github.com/thesofproject/rimage
git submodule update --init
cd tools/rimage/

按照 rimage README.md 中的说明在你的系统上构建该工具。可以将可执行文件复制到 PATH 中的某个目录，也可以使用 west config rimage.path /path/to/rimage-build/rimage；详见 west sign -h 的输出。直接从构建目录运行可以降低误用过时 rimage 版本的可能性。

平台专用的配置文件位于 rimage/config/ 子目录中。如需使用其他配置目录，可以使用：west config build.cmake-args -- -DRIMAGE_CONFIG_PATH=/path/to/my/rimage/config。

Xtensa 工具链（可选）

Zephyr SDK 提供了为 cAVS 和 ACE 开发板构建 Zephyr 所需的基于 GCC 的工具链。不过，追求更高优化水平的用户可能希望改用 Cadence 发布的专有 Xtensa 工具链进行构建。以下说明假定你已按照其说明购买并安装了适用于你的开发板的工具链和内核（core）。

首先，按照 Cadence 的说明设置 $HOME/.flexlmrc 文件或 XTENSAD_LICENSE_FILE 变量。然后设置以下环境变量：

export XTENSA_TOOLCHAIN_PATH=$HOME/xtensa/XtDevTools/install/tools
export XTENSA_BUILDS_DIR=$XTENSA_TOOLCHAIN_PATH/../builds
export ZEPHYR_TOOLCHAIN_VARIANT=xcc
export TOOLCHAIN_VER=RG-2017.8-linux
export XTENSA_CORE=cavs2x_LX6HiFi3_2017_8

最后三个变量因 cAVS / ACE 版本而异；其取值请参阅你的开发板文档。

编程与调试

构建

按常规方式构建。

# From the root of the zephyr repository
west build -b intel_adsp/cavs25 samples/hello_world

签名

west build 会在构建结束时尝试对二进制文件签名。如果需要自行签名，可以直接调用 west sign。阅读 west 日志可以找到 west sign 的调用命令；你可以复制日志中记录的命令并按需修改。更多详情请运行 west sign -h。

构建过程会尽可能提供默认的 rimage 参数。如有需要，可以根据具体情况和用例，通过多种方式覆盖这些参数。这些方式通常并不互斥，但为了避免未记录的 rimage 优先级规则带来的问题，最好一次只使用一种方式。

  • 对于本地交互式使用，推荐在 west 配置中使用 rimage.extra-args，参见 west sign -h。如有需要，可以用 WEST_CONFIG_LOCAL 环境变量指向另一个 west 配置文件。

  • 可以在 rimage/config/ 目录中添加或覆盖 $platform.toml 文件

  • 对于开发板专用的需求，可以在 boards/my/board/board.cmake 中定义 WEST_SIGN_OPTS，示例参见 soc/intel/adsp/common/CMakeLists.txt

从 Zephyr 3.6.0 开始，west flash 不再调用 west sign，也不能再向 west flash 传递 rimage 参数。要查看 Intel ADSP 运行器所有参数的最新列表，请在构建二进制文件后运行以下命令：

west flash --context

远程烧录基于 cAVS 的 ADSP

如前所述，在 cAVS 开发板上运行 Zephyr 并监视其输出的推荐方式是远程操作。如果 ADSP 上发生烧录或运行时错误，主 CPU 上的 Linux 主机可能会卡死而需要重启。从这里开始，我们将开发板称为“远程主机”，将你的开发机称为“本地主机”。

将以下脚本复制到 cAVS 开发板。soc/intel/intel_adsp/tools/remote-fw-service.py 会接收 West 通过网络发送的二进制文件，并调用 soc/intel/intel_adsp/tools/cavstool.py （称为“cAVS 工具”）执行烧录并捕获日志。启动 remote-fw-service.py。

scp -r $ZEPHYR_BASE/soc/intel/intel_adsp/tools/cavstool.py username@remotehostname
scp -r $ZEPHYR_BASE/soc/intel/intel_adsp/tools/remote-fw-service.py username@remotehostname
ssh username@remotehostname
sudo ./remote-fw-service.py

remote-fw-service.py 使用远程主机上的 9999 和 10000 端口进行通信。它在 9999 端口（称为“日志端口”）上转发 cavstool.py 收集的日志，并在 10000 端口（“请求端口”）上处理请求。在本地主机上运行 West 或 Twister 时，它们会使用 soc/intel/intel_adsp/tools/cavstool_client.py 脚本（称为“cAVS 工具客户端”）发送请求。该脚本同样使用本地主机上的 9999 和 10000 端口，因此请确保这两个端口未被占用。

使用 West 烧录很简单。

west flash --remote-host remotehostname --pty remotehostname

使用 Twister 运行测试稍微复杂一些。

twister -p intel_adsp/cavs25 --device-testing --device-serial-pty="$ZEPHYR_BASE/soc/intel/intel_adsp/tools/cavstool_client.py,-s,remotehostname,-l" --west-flash="--remote-host=remotehostname" -T samples/hello_world

如果你的网络配置使得从 cavstool_client.py 到 remote-fw-service.py 的 TCP 连接需经过中间主机转发，则可能需要让 cavstool_client.py 连接到不同的端口和主机名。为此，可以在中间主机名后附加端口号。

west flash --remote-host intermediatehost:reqport --pty remotehostname:logport
twister -p intel_adsp/cavs25 --device-testing --device-serial-pty="$ZEPHYR_BASE/soc/intel/intel_adsp/tools/cavstool_client.py,-s,remotehostname:logport,-l" --west-flash="--remote-host=remotehostname:reqport" -T samples/hello_world

也可以将这些信息保存到硬件映射文件中，再传给 Twister。

twister -p intel_adsp/cavs25 --hardware-map cavs.map --device-testing -T samples/hello_world

以下是一个 cavs.map 示例：

- connected: true
  id: None
  platform: intel_adsp/cavs25
  product: None
  runner: intel_adsp
  serial_pty: "/home/zephyrus/zephyrproject/zephyr/soc/intel/intel_adsp/tools/cavstool_client.py,-s,remotehostname:logport,-l"
  runner_params:
  - --remote-host=remotehostname:reqport

凡是可以传给 Twister 或 West 的参数，都可以通过硬件映射传入。如前所述，使用 West 烧录时传入 --context 选项即可查看 Intel ADSP 运行器的参数。

有关硬件映射的更多信息，请参阅 测试运行器（Twister）。

本地烧录基于 cAVS 的 ADSP

也可以在开发板上使用 cAVS 工具直接烧录签名后的二进制文件。这在调试时可能很有用。

sudo ./cavstool.py zephyr.ri

如果成功，日志末尾应显示以下内容：

***** Booting Zephyr OS vx.x.x-xxx-gxxxxxxxxxxxx *****
Hello World! intel_adsp

烧录基于 ACE 的 ADSP

目前尚不支持烧录采用基于 ACE 的 ADSP 的平台，因为这些平台还没有公开发布。

调试

由于 Zephyr （目前）不支持在 Intel ADSP 平台上使用 GDB，建议用户使用 Zephyr 内置的 核心转储 和 日志 功能。

故障排除

可以直接向 Intel ADSP 脚本传递详细输出选项：

sudo ./remote-fw-service.py -v
sudo ./cavstool.py zephyr.ri -v

要查看它们的参数列表：

sudo ./remote-fw-service.py --help
sudo ./cavstool.py --help

如果烧录在 west sign 阶段失败，并报出与未解析密钥相关的错误，请尝试重新安装最新版本的签名工具。例如：

error: 1 unparsed keys left in 'adsp'
error: 1 unparsed arrays left in 'adsp'

如果在开发板上启动 remote-fw-service.py 时出现 "Address already in use" 错误，可能是该脚本已有另一个实例在运行。请终止它。

$ sudo netstat -peanut | grep 9999
tcp   0   0 0.0.0.0:9999   0.0.0.0:*   LISTEN   0   289788   14795/python3
$ sudo kill 14795

如果 West 或 Twister 成功完成签名并与 remote-fw-service.py 建立了 TCP 连接，但随后卡住且没有任何输出，则有两种可能：要么 remote-fw-service.py 通信失败，要么 cavstool.py 烧录失败。请登录远程主机并检查 remote-fw-service.py 的输出。

如果出现有关 "incorrect communication" 的消息，说明你在命令或硬件映射中把日志端口和请求端口的端口号弄反了。请对调后重试。

ERROR:remote-fw:incorrect monitor communication!

如果出现 "load failed" 消息，说明烧录失败。请检查 west flash 的日志，并仔细确认传给 west sign 的参数是否正确。

WARNING:cavs-fw:Load failed?  FW_STATUS = 0x81000012
INFO:cavs-fw:cAVS firmware load complete
--

有时烧录失败或网络通信错误会破坏 ADSP 或 remote-fw-service.py 的状态。如果反复失败又找不到原因，请尝试重启这些脚本和/或给开发板重新上电，以重置状态。

用户（尤其是 Xtensa 工具链用户）还应考虑清除 Zephyr 缓存，因为缓存问题时有发生。删除缓存以及所有相关的构建目录，然后从头开始。如果愿意，也可以先尝试使用 West 的 "pristine" 选项。

rm -rf build twister-out*
rm -rf ~/.ccache ~/.cache/zephyr

Xtensa 工具链用户可以通过导出 FLEXLM_DIAGNOSTICS=3 从许可证服务器获取更详细的日志。
