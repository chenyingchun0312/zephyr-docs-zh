在 Chromebook 上进行 Zephyr 音频 DSP 开发

Intel Chromebook 上的音频 DSP 配置为使用 SOF "Community" 密钥进行固件签名，因此可以接受用户任意开发的固件，例如 Zephyr 应用程序（SOF 就是其中之一），包括 Zephyr 示例和测试套件。

TGL Chromebook 初始设置

（这些说明是专门针对代号为 "delbin" 的 Asus Flip CX5 设备编写的，但应该也基本适用于任何较新的 Intel 设备。）

打开设备电源并连接到无线网络。设备很可能会要求下载固件更新（我的设备就是这样）。请先等更新完成，以确保有两个可用的操作系统镜像。

启用开发者模式

关闭设备电源（通过右下角菜单，或按住侧面的电源键）

按住 Esc + Refresh（"3" 上方带圆圈箭头的 "reload" 键），再按电源键进入恢复模式。注意：在恢复模式下触摸屏和触控板都不能使用，请用方向键导航。

选择 "Advanced Options"，然后选择 "Enable Developer Mode" 并确认。在引导加载程序界面中选择 "Boot from Internal Storage"。从此以后，每次开机都会看到这个界面，提示启动未经验证。

等待设备完成必要的数据擦除。我的设备大约需要 15 分钟才能完整写入有状态分区。重启后，再次选择 "Boot from Internal Storage"，并（重新）使用 Google 账号完成设置。

制作恢复盘

你迟早会把设备弄坏，届时就需要一个恢复 U 盘。请从 Google Web Store 安装 Chromebook Recovery Utility 并制作一个。

实际上，在任何装有 Chrome 的机器（和任何操作系统）上都可以制作恢复盘，但在 Chromebook 上最方便，因为它知道自己的设备 ID（例如 Asus Tiger Lake 开发板为 "DELBIN-XHVI D4B-H4D-G4G-Q9A-A9P"）。注意，执行恢复时不会影响开发者模式或固件设置，但 会清除根文件系统以及你在 /usr/local 中所做的自定义修改。因此，对于你正在折腾的设备，请规划一种能容忍数据丢失的策略！

使根文件系统可写

出于安全考虑，ChromeOS 会对只读根文件系统的所有访问进行签名和加密验证（使用 Linux 的 dm-verity 功能）。改动 rootfs（例如为自定义内核安装模块）需要关闭 dm-verity 层：

首先按 Ctrl-Alt-T 打开终端。然后在 "crosh> " 提示符下执行 "shell" 命令，获得以 "chronos" 用户身份运行的 shell。最后（在开发者模式下）只需执行 "sudo su -" 即可获得 root 提示符。

crosh> shell
chronos@localhost / $ sudo su -
localhost ~ #

现在需要关闭引导加载程序中的签名验证（因为显然我们会破坏现有的签名）。注意，签名验证由 ROM 引导加载程序而不是操作系统完成，此设置是给该代码的一条指令（仅在开发者模式下有效）：

cros# crossystem dev_boot_signed_only=0

(Note: for clarity, commands in this document entered at the ChromeOS core shell will be prefixed with a hostname of cros.)

接下来禁用验证步骤：

cros# /usr/share/vboot/bin/make_dev_ssd.sh --remove_rootfs_verification

此命令会失败，并报错提示你正在更改整个运行系统的设置，同时建议改用 "--partitions X" 参数，只修改当前使用的分区。运行修改后的命令，然后重启。

重启后你会发现，Chromebook 启动时挂载为根的是原始存储设备（例如 /dev/nvme0n1p5），而不是 verity 设备 "dm-0"，并且 rootfs 可读写。

注意：该命令实际所做的是修改已安装内核镜像的命令行（它会在 /mnt/stateful_partition/cros_sign_backups 中保存备份），使其指定 "root=<guid>" 而不是 "root=dm-0"。不过它似乎保留了其他 verity 配置，只是不再尝试挂载由此产生的（现已无效的！）分区。

补充说明：细心的读者会注意到，我们很可能会丢弃这个内核，其实也可以直接编辑新内核的命令行，而不必先烧录并重启到这个修改过的内核。但对我来说，同时处理这么多事情太复杂了。

启用 ChromeOS SSH

以可写分区启动后，可以用以下命令开启内置的 ssh 服务器：

cros# /usr/libexec/debugd/helpers/dev_features_ssh

默认情况下，"chronos" 用户和 root 账户都没有密码，因此除非你想手动输入 ssh 密钥，否则最好为首次登录设置一个密码（当然要在运行 ssh-copy-id 之前）：

cros# passwd

现在通过 ssh 登录 Chromebook，并像在任何 Linux 系统上一样，将你的密钥添加到 .ssh/authorized_keys。

安装 Crouton

Zephyr 集成工具需要完整的 Linux 环境，无法在 ChromeOS 的精简发行版上运行，因此需要安装一个 Linux 环境（personality）。不要 费心从 ChromeOS 开发者设置中安装 "Linux Development Environment"（Crostini）。该环境运行在虚拟机中，而我们的工具需要访问在真实硬件上运行的真实内核。请改为安装 Crouton（https://github.com/dnschneid/crouton），这是一个由社区维护、基于 chroot 的环境，保留了对真实硬件 sysfs 和 /dev 文件系统的访问。这些说明安装的是 "cli-extra" 软件包列表；如果你希望直接在设备屏幕上工作，也有支持 X11 的列表可用。详见项目页面等。

在 root shell 中下载安装程序并运行（注意：/usr/local 是唯一一个没有 noexec 的可写文件系统，必须将二进制文件放在那里才能运行！）：

cros# mkdir -p /usr/local/bin
cros# curl -L https://github.com/dnschneid/crouton/raw/master/installer/crouton \
              > /usr/local/bin/crouton
cros# chmod 755 /usr/local/bin/crouton
cros# crouton -r focal -t cli-extra

启动 Crouton chroot 环境：

cros# startcli

现在你输入的命令都在 Ubuntu 环境中执行。在 Crouton 上启用入站 ssh，但要使用 22 以外的端口（22 已被 ChromeOS 原生 ssh 服务器占用）。这里使用 222（容易记，而且不是 /etc/services 中的已注册端口）：

crouton# apt install iptables openssh-server
crouton# echo "Port 222" >> /etc/ssh/sshd_config
crouton# mkdir /run/sshd
crouton# iptables -I INPUT -p tcp --dport 222 -j ACCEPT
crouton# /usr/sbin/sshd

(As above: note that we have introduced a hostname of "crouton" to refer to the separate Linux personality.)

注意：每次重新启动 chroot 时都需要运行 mkdir、iptables 和 sshd 命令。为方便起见，可以将它们放在 /etc/rc.local 中。Crouton 不运行 systemd（因为它无法运行，它并不掌管整个系统！），所以 openssh-server 等 Ubuntu 服务不知道如何自行启动。

构建并安装自定义内核

在构建主机上获取一份 ChromeOS 内核源码树。出厂设备使用的是 5.4 内核，但 5.10 源码树在我这里也能用，而且它似乎一直在向后移植上游驱动，因此其主要硬件支持都相当新（大约落后主线 5-6 周）。为简单起见，这里将其放在主目录中：

dev$ cd $HOME
dev$ git clone https://chromium.googlesource.com/chromiumos/third_party/kernel
dev$ cd kernel
dev$ git switch chromeos-5.10

(Once again, we are typing into a different shell. We introduce the hostname "dev" here to represent the development machine on which you are building kernels and Zephyr apps. It is possible to do this on the chromebook directly, but not advisable. Remember the discussion above about requiring a drive wipe on system recovery!)

注意：你可能已经在某处有一个 Linux 源码树。如果有，将其添加为远程仓库并只获取增量会快得多，因为 ChromeOS 紧密跟踪上游。

现在需要一个 .config 文件。Chromebook 内核附带已编译的 "configs" 模块，可以在运行中的内核里提供该文件。只需加载该模块并读取文件即可。

dev$ cd /path/to/kernel
dev$ ssh root@cros modprobe configs
dev$ ssh root@cros zcat /proc/config.gz > .config

你需要将一些自定义配置变量设置为与 ChromeOS 默认值不同的值（可以直接编辑 .config，也可以使用 menuconfig 等）：

  • CONFIG_HUGETLBFS=y - Zephyr 加载工具需要此选项

  • CONFIG_EXTRA_FIRMWARE_DIR=n - 该选项指向 Google 构建环境中的

    一个构建目录，而我们并没有这个环境。

  • CONFIG_SECURITY_LOADPIN=n - 该选项会锁定模块，使其

    只能从一个文件系统加载。对自定义内核来说，这是个恼人的限制。

  • CONFIG_MODVERSIONS=n - 允许从修改过的

    "dirty" 构建树中构建并安装模块。

现在像构建其他内核一样构建你的内核：

dev$ make olddefconfig     # Or otherwise update .config
dev$ make bzImage modules  # Probably want -j<whatever> for parallel build

模块可以直接复制到设备上（现已可写的）rootfs 中。注意，该文件系统空间非常有限（它本来就是只读的），因此必须使用 INSTALL_MOD_STRIP=1，而且你可能需要定期删除旧内核的模块以腾出空间：

dev$ make INSTALL_MOD_PATH=mods INSTALL_MOD_STRIP=1 modules_install
dev$ (cd mods/lib/modules; tar cf - .) | ssh root@cros '(cd /lib/modules; tar xfv -)'

打包并安装 ChromeOS 内核镜像

内核 bzImage 文件本身需要签名并打包成 ChromeOS vboot 包，然后直接写入内核分区。好在 Debian/Ubuntu 软件仓库中已经提供了完成这些工作的工具：

$ sudo apt install vboot-utils vboot-kernel-utils

找到设备上当前的内核分区。可以将（引导加载程序传入的）"kernel_guid" 命令行参数与启动盘的分区表进行比较来确定，例如：

dev$ KPART=`ssh root@cros 'fdisk -l -o UUID,Device /dev/nvme0n1 | \
                           grep -i $(sed "s/.*kern_guid=//" /proc/cmdline \
                                     | sed "s/ .*//") \
                           | sed "s/.* //"'`
dev$ echo $KPART
/dev/nvme0n1p4

将该镜像中的命令行提取到本地文件中：

dev$ ssh root@cros vbutil_kernel --verify /dev/$KPART | tail -1 > cmdline.txt

现在可以使用 vboot 工具打包新的内核镜像。这些参数大多是固定的样板内容。之所以需要密钥，是因为启动需要有效的签名，尽管按当前配置并不会用到它。注意作为 "bootloader" 传入的那个不能为空的虚拟文件，它是早期需要 EFI 桩（stub）的 ROM 版本遗留下来的。

dev$ echo dummy > dummy.efi
dev$ vbutil_kernel --pack kernel.img --config cmdline.txt \
       --vmlinuz arch/x86_64/boot/bzImage \
       --keyblock /usr/share/vboot/devkeys/kernel.keyblock \
       --signprivate /usr/share/vboot/devkeys/kernel_data_key.vbprivk \
       --version 1 --bootloader dummy.efi --arch x86_64

如有需要，可以用 "vbutil_kernel --verify" 验证该镜像。

现在只需将文件复制到设备上并写入分区：

$ scp kernel.img root@cros:/tmp
$ ssh root@cros dd if=/tmp/kernel.img of=/dev/nvme0n1p4

然后重启，如果一切顺利，你就会运行在新内核上。

修复 Wifi 固件

在 Tiger Lake Chromebook 上，/lib/firmware 目录相对于当前的 5.10 内核有些过时。iwlwifi 驱动会请求一个不存在的固件文件，导致设备没有网络。问题很简单，但如果不解决，后果很严重。看来只需将旧版本链接到新名称就足够了。（更好的做法可能是从最新的 kernel.org 检出中的 /lib/firmware 复制正确的版本。）：

cros# cd /lib/firmware
cros# ln -s iwlwifi-QuZ-a0-hr-b0-62.ucode iwlwifi-QuZ-a0-hr-b0-64.ucode

构建并运行 Zephyr 应用程序

最后，新内核启动后，就可以运行 Zephyr 代码了。

构建 rimage 签名工具

首先下载并构建一份 Sound Open Firmware 的 "rimage" 工具（为清晰起见，这些说明将其放在主目录中，但放在任何位置都可以）：

dev$ cd $HOME
dev$ git clone https://github.com/thesofproject/rimage
dev$ git submodule init
dev$ git submodule update
dev$ cd tools/rimage/
dev$ cmake .
dev$ make

将集成脚本复制到 Chromebook

设备上需要一个 python 脚本，在上文安装的 Crouton 环境中运行。复制这些脚本：

dev$ scp soc/intel/intel_adsp/tools/cavstool.py user@crouton:

然后在 Crouton 环境中启动该服务：

crouton$ sudo ./cavstool.py user@crouton:

构建 Zephyr 应用程序并签名

在该平台上，Zephyr 应用程序按常规方式构建，并通过 "west flash" 加上几个额外参数进行签名。注意，Tiger Lake DSP 使用的密钥是 SOF 的 "3k" 密钥，而不是旧硬件使用的原始密钥。输出产物是一个 "zephyr.ri" 文件，需要复制到设备上。

dev$ west build -b intel_adsp/cavs25 samples/hello_world
dev$ west sign --tool-data=~/rimage/config -t ~/rimage/rimage -- \
            -k $ZEPHYR_BASE/boards/intel/adsp/support/otc_private_key_3k.pem

运行！

加载脚本以签名后的 rimage 文件作为参数。脚本报告成功后，应用程序会立即开始运行，其控制台输出（位于 SOF 共享内存跟踪缓冲区中）可以由日志脚本读取。

dev$ west flash --remote-host crouton
Hello World! intel_adsp
