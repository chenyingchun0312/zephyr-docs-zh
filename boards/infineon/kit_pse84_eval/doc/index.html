PSOC™ Edge E84 Evaluation Kit

Board Overview

Name:
kit_pse84_eval
Vendor:

Infineon Technologies

Status:

Not actively maintained

Architecture:

arm

SoC:

pse846gps2dbzc4a

Browse board sources

概述

KIT_PSE84_EVAL 是基于 PSOC™ Edge E84 系列的评估套件，搭载一颗 PSE846GPS2DBZC4A 微控制器，包含一个 200 MHz 的 Arm® Cortex®-M33 内核、一个 400 MHz 的 Arm® Cortex®-M55 内核和一个 Arm® Ethos™-U55 NPU。该套件面向机器学习、可穿戴设备和物联网应用。

该评估套件采用基于 SODIMM 的可拆卸 SOM，连接到功能丰富的底板上。SOM 上集成了 MCU 以及 128 Mb QSPI Flash、1 Gb Octal Flash、128 Mb Octal HYPERRAM™、一个 PSOC™ 4000T CAPSENSE™ 协处理器和一个板载 AIROC™ CYW55513IUBG Wi-Fi + Bluetooth® 二合一模块。

底板提供丰富的连接能力，包括 USB Host Type-A、USB Device Type-C、RJ45 以太网、M.2 B-key 和 E-key 插槽、Arduino、mikroBUS 和 Shield2Go 排针、MIPI-DSI 显示接口、模拟和 PDM 麦克风、耳机和扬声器输出、microSD 卡槽、CAPSENSE 按键和滑条，以及完整的调试排针（ETM/JTAG/SWD）。

该开发板带有一个通过 USB Type-C 连接的板载 KitProg3 编程器/调试器。

启动流程

Cortex®-M33 是启动内核。Cortex®-M55 保持复位状态，直到运行在 M33 上的应用程序将其释放。

Reset
  -> Extended boot (Infineon, stored in RRAM), reads BOOT SW
       BOOT SW ON:  CM33 Secure image in external flash (XIP)
       BOOT SW OFF: MCUBoot in RRAM, which validates and starts the CM33 Secure image
  -> CM33 Secure image (Zephyr, or TF-M when using the /ns target)
       -> CM33 application
       -> optional: releases the CM55
            -> CM55 application

扩展引导（extended boot）运行的第一个镜像必须采用 MCUboot 镜像格式。构建过程会自动生成该格式；详见 Secure Boot。MCUBoot 引导加载程序是可选的；参见 MCUBoot Bootloader Support。

串口

所有目标都使用 SCB2 （uart2）作为控制台和 shell，它通过 KitProg3 USB-UART 桥引出。默认设置为 115200 8N1。两个内核都运行 Zephyr 时，它们的输出共用该 UART。

Bluetooth HCI UART 为 SCB4 （uart4），带硬件流控（RTS/CTS），连接到 SOM 上的 CYW55513 模块。

系统时钟

PSOC™ Edge E84 有 14 个高频时钟（CLK_HF0 到 CLK_HF13），由 CM33 镜像配置。与应用程序最相关的是：

  • CLK_HF0： 200 MHz，CM33 内核和系统时钟

  • CLK_HF1： 400 MHz，CM55 内核

KIT_PSE84_EVAL 带有一个板载编程器/调试器（KitProg3），可用于对 PSOC™ Edge E84 的两个内核进行编程和调试。

Board Setup

备注

SW6 （BOOT SW）拨码开关用于选择扩展引导的跳转目标（参见 Secure Boot）：

  • ON （默认）：直接跳转到外部 Flash 中的应用程序。所有不使用 MCUBoot 的构建（包括下面的示例）都应使用此设置。

  • OFF：跳转到 RRAM 中的 MCUBoot 引导加载程序（0x22011000）。启用 MCUBoot 时使用此设置。

在某些开发板上，该开关位于所装的 LCD 屏幕下方。

用 USB 线将 PC 连接到 KitProg3 USB Type-C 接口（J8）。使用任意终端（minicom、PuTTY 等）以 115200 8N1 打开 KitProg3 串口。

安装 Infineon OpenOCD

ModusToolbox™ Programming Tools 软件包中包含 Infineon OpenOCD。也可以下载适用于你的系统的 Infineon OpenOCD 发布版，并解压到任意位置。

备注

在 Linux 上，KitProg3 需要设备访问权限。ModusToolbox™ Programming Tools 安装程序会设置这些权限。对于独立安装的 OpenOCD，请运行 openocd/udev_rules/install_rules.sh。

告诉 west Infineon OpenOCD 的安装位置。在 Windows 上，可执行文件为 openocd.exe。

west config build.cmake-args -- "-DOPENOCD=path/to/infineon/openocd/bin/openocd"

备注

这会替换现有的 build.cmake-args 值。如果只想为单条命令设置路径，请使用 west flash --openocd <path>。

调试

CM33:

# From the root of the zephyr repository
west build -b kit_pse84_eval/pse846gps2dbzc4a/m33 samples/hello_world

对于 CM55，west debug 通过 GDB 端口 3334 连接到 CM55。CM55 由 CM33 启动，而不是由芯片复位启动，因此 GDB 的 run 命令无法重新启动它。请改用开发板提供的 restart GDB 命令。

安全启动

PSOC™ Edge E84 MCU 包含一个英飞凌扩展引导（extended boot）阶段，存放在保留的 RRAM 区域中，复位后跳转到第一个应用程序镜像。跳转目标由板载 BOOT SW 选择：

  • BOOT SW 为 OFF：扩展引导跳转到位于内部 RRAM 中的第一个应用程序，例如 MCUBoot 引导加载程序。

  • BOOT SW 为 ON：扩展引导跳转到位于外部 Flash 中的第一个应用程序。该开发板的 Zephyr 应用程序就放在这里。

在这两种情况下，第一个应用程序镜像都必须采用 MCUboot 镜像格式，即镜像前面必须有 MCUboot 镜像头（魔数、头大小、向量表地址、镜像大小），后面必须有包含哈希/签名 TLV 的尾部（trailer）。出厂时器件 没有 针对安全启动进行预置，因此扩展引导只检查镜像格式和哈希，不会使用已预置的密钥进行加密签名验证。

MCUboot 镜像格式由 soc/infineon/edge/pse84/pse84_metadata.cmake 中的辅助函数 pse84_add_extboot_metadata() 自动生成，它使用从设备树内存映射推导出的头地址、头大小和槽大小调用 imgtool sign。默认情况下该辅助函数不传入签名密钥，这对于未配置（non-provisioned）的设备已经足够。

启用安全启动

要让扩展启动程序进行真正的签名验证，必须重新配置设备。按照 PSOC™ Edge Security Getting Started Application Note 的 2.2.1、2.2.2 和 2.2.3 节完成以下操作：

  1. 生成（或导入）OEM 签名密钥对。

  2. 使用对应的公钥配置设备并进行生命周期转换。

  3. 编程所需的安全计数器/防回滚值。

重新配置设备后，必须更新 soc/infineon/edge/pse84/pse84_metadata.cmake 中的 pse84_add_extboot_metadata() 函数，使 imgtool sign 也接收签名密钥和安全计数器。需要添加的内容如下：

${PYTHON_EXECUTABLE} ${IMGTOOL} sign --version "0.0.0+0"
  --header-size ${header_size} --erased-val 0xff ${pad_header_arg}
  --slot-size ${slot_size} --hex-addr ${hex_addr}
  --key <oem-private-key-file>
  --security-counter <value>
  ${INPUT_FILE} ${OUTPUT_FILE}

其中 <oem-private-key-file> 是与配置到设备中的公钥相匹配的 OEM 私钥文件路径（例如 .pem 文件），<value> 是配置时分配的安全计数器。如果没有这些额外参数，为已配置设备构建的镜像会被扩展启动程序拒绝。

MCUBoot Bootloader Support

kit_pse84_eval 开发板支持使用 MCUBoot 作为引导加载程序并进行空中（OTA）固件更新。PSOC™ Edge E84 扩展引导（位于 RRAM 中）先验证 RRAM 中 MCUBoot 引导加载程序位置处的 MCUBoot 兼容镜像头，再将控制权交给 MCUBoot，随后由 MCUBoot 验证并启动应用程序。

重要

使用 MCUBoot 时，SW6 （BOOT SW）拨码开关 必须 拨到 OFF 位置。这样扩展引导会跳转到 RRAM 中 0x22011000 处的 MCUBoot 引导加载程序。如果开关仍处于 ON，扩展引导会尝试直接跳转到外部 Flash 的 XIP 地址，完全绕过 MCUBoot。

基础内存映射（kit_pse84_eval_memory_map.dtsi）为每个 Flash 区域定义了一个角色标签，用于描述该区域 是什么 （例如 m33s_xip、m33_xip、m55_xip）。MCUBoot 镜像编号标签（slotN_partition）叠加在这些角色标签之上。绝对的共享槽 slot2_partition .. slot5_partition 只由 MCUBoot 引导加载程序使用，因此它们在引导加载程序覆盖文件（MCUBoot 仓库中的 boot/zephyr/boards/kit_pse84_eval_pse846gps2dbzc4a_m33.overlay）中附加到这些角色节点上，该覆盖文件还会选择 boot_partition，并将 RRAM 选为引导加载程序的 Flash 设备。slot0_partition / slot1_partition 标签相对于正在构建的镜像，由各内核的开发板文件（kit_pse84_eval_m33.dts / kit_pse84_eval_m33_ns.dts）绑定。因此，应用程序镜像不需要额外的 DTS 覆盖文件。

独立构建各镜像（Standalone）

每个镜像都可以单独构建和烧录。应用程序镜像通过各内核的开发板设备树绑定 slot0_partition，因此应用程序镜像不需要额外的 DTS 覆盖文件。

下文引用的应用程序级 kit_pse84_eval_slot.conf 位于相对 $ZEPHYR_BASE 的 boards/infineon/kit_pse84_eval/ 目录中。

步骤 1 — MCUBoot 引导加载程序

引导加载程序必须链接到 RRAM 中的 boot_partition。所需的覆盖文件和配置文件位于 MCUBoot 仓库中：boot/zephyr/boards/kit_pse84_eval_pse846gps2dbzc4a_m33.overlay 和 boot/zephyr/boards/kit_pse84_eval_pse846gps2dbzc4a_m33.conf。每当为该开发板构建 MCUBoot 时，Zephyr 的开发板专用 overlay/conf 机制都会自动应用它们，无需 EXTRA_DTC_OVERLAY_FILE / EXTRA_CONF_FILE 参数。

该 kit_pse84_eval_pse846gps2dbzc4a_m33.conf 默认设置 CONFIG_UPDATEABLE_IMAGE_NUMBER=2，使 MCUBoot 开箱即可验证两个独立镜像（镜像 0 使用 slot0/slot1，镜像 1 使用 slot2/slot3）。这与 TF-M 流程（slot0 中的已签名 SPE + slot2 中的已签名 NSPE）相符。

对于 双镜像 构建（TF-M SPE + NSPE）：

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33 \
    bootloader/mcuboot/boot/zephyr -d build_mcuboot

对于 单镜像 配置（仅 CM33S），将镜像数量覆盖为 1：

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33 \
    bootloader/mcuboot/boot/zephyr -d build_mcuboot \
    -- -DCONFIG_UPDATEABLE_IMAGE_NUMBER=1

步骤 2 — CM33S 应用程序（slot0）

不需要额外的 DTS 覆盖文件。该 conf 文件会设置 CONFIG_BOOTLOADER_MCUBOOT=y、对应的 MCUBoot 模式，以及生成未签名镜像：

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33 \
    <path/to/cm33s/app> -d build_cm33s \
    -- -DEXTRA_CONF_FILE="$ZEPHYR_BASE/boards/infineon/kit_pse84_eval/kit_pse84_eval_slot.conf"

步骤 3 — 烧录

每个镜像都从各自的构建目录单独烧录。west flash 会自动选择正确的 hex 文件。

先烧录 MCUBoot（只需烧录一次；仅在更新引导加载程序时才需重新烧录）：

west flash -d build_mcuboot

烧录 CM33S 应用程序：

west flash -d build_cm33s

升级模式：Swap-Using-Move

开发板配置文件默认使用 MCUBoot swap-using-move 升级模式：

  • kit_pse84_eval_pse846gps2dbzc4a_m33.conf （位于 MCUBoot 仓库中）为引导加载程序设置 CONFIG_BOOT_SWAP_USING_MOVE=y 和 CONFIG_MCUBOOT_BOOT_MAX_ALIGN=16。

  • kit_pse84_eval_slot.conf 为应用程序设置 CONFIG_MCUBOOT_BOOTLOADER_MODE_SWAP_USING_MOVE=y。

这两个文件的模式必须一致：应用程序编译时会内置自身的尾部（trailer）布局（BOOT_MAX_ALIGN）和 imgtool 对齐方式，它们必须与引导加载程序一致，否则镜像确认（image-confirm）偏移量会对不上。

该开发板之所以能使用 swap，是因为外部 QSPI Flash（s25fs128s）的 write-block-size 为 16 字节，即器件自动 ECC 块的大小，在 MCUBoot 的 BOOT_MAX_ALIGN 限制之内。每个尾部字段和 swap 状态条目都按每个 16 字节 ECC 块写入一次，因此 ECC 得以保持。swap-using-move 不需要 scratch 分区，但要求主槽和次级槽大小相同且扇区大小一致。

在 swap 模式下，imgtool 使用 --align 16 对每个镜像签名并写入尾部，如下所述。

签名并暂存次级（升级）镜像

应用程序构建会将其签名镜像（zephyr.signed.hex）放在 主 槽（例如 slot0 / m33s_xip）。要测试升级，必须在 次级 槽（沿用上例即 slot1 / m33s_upgrade）中暂存第二个镜像，并带有有效的尾部，以便 MCUBoot 检测到待处理的更新。对同一个构建执行 west flash 只会重新烧写主槽，因此必须为次级镜像重新签名并加上尾部，再将其重定位到次级槽地址。

用 imgtool 对升级应用程序的原始二进制文件签名，添加填充的尾部，并将其放到次级槽的编程地址。--slot-size （0x240000）和 --align 16 的取值与槽布局和 write-block-size 相符；--header-size 与 CONFIG_ROM_START_OFFSET 相符：

python bootloader/mcuboot/scripts/imgtool.py sign \
    --version 0.0.0+0 --header-size 0x400 --slot-size 0x240000 --align 16 \
    --pad --hex-addr 0x70700000 \
    build_cm33s_upgrade/zephyr/zephyr.bin \
    build_cm33s_upgrade/zephyr/upgrade_slot1.hex

然后无需重新构建，直接将重定位后的 hex 烧录到次级槽，主槽保持不变：

west flash -d build_cm33s_upgrade --no-rebuild \
    --hex-file build_cm33s_upgrade/zephyr/upgrade_slot1.hex

下次复位时，MCUBoot 会将次级镜像交换到主槽并启动它。

备注

仅使用 --pad 会请求一次 测试 交换：升级只运行一次，除非应用程序确认该升级（调用 boot_write_img_confirmed()，或烧录用 --pad --confirm 签名的镜像），否则 MCUBoot 会在下一次复位时 回退 到之前的镜像。使用 --pad --confirm 可使升级立即永久生效。

TF-M 与 MCUBoot 配合使用（多镜像）

TF-M 与 MCUBoot 一起使用时，TF-M 安全处理环境（SPE）放在 slot0_partition （镜像 0）中，非安全应用程序（NSPE）放在 slot2_partition （镜像 1）中。MCUBoot 以多镜像模式运行（CONFIG_UPDATEABLE_IMAGE_NUMBER=2，开发板默认值），分别验证 SPE 和 NSPE。运行时从安全状态到非安全状态的切换仍由 TF-M 自身处理。

签名由 soc/infineon/edge/pse84/pse84_tfm_signing.cmake 中的辅助脚本完成，它是对默认 cmake/mcuboot.cmake 流程的简单封装。它会：

  • 包含原有的 cmake/mcuboot.cmake 来为 NSPE 签名。由于非安全开发板设备树将 slot0_partition 绑定到 NS 槽，原有流程已经会使用 imgtool sign --overwrite-only --align 1 按正确的槽（slot2 的 NS 视图）确定镜像大小。

  • 将已签名的 SPE（由 TF-M 自身构建生成）与刚签名的 NSPE 合并为 tfm_merged.hex，并让 west flash 使用该文件。

启动流程:

Extended Boot (RRAM) → MCUBoot (RRAM, 0x22011000)
    → validates image 0 (TF-M SPE  @ slot0 / 0x18100000)
    → validates image 1 (NSPE     @ slot2 / 0x08340000)
    → jumps to TF-M SPE
        → TF-M configures TrustZone / MPC / SAU
        → TF-M launches NSPE (@ 0x08340000)

步骤 1 — MCUBoot 引导加载程序

与上文独立构建的双镜像情况相同：开发板默认配置已经会验证 slot0 和 slot2，引导加载程序的 overlay/conf 会从 MCUBoot 仓库自动应用：

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33 \
    bootloader/mcuboot/boot/zephyr -d build_mcuboot

步骤 2 — TF-M NS 应用程序（SPE + NSPE）

在启用 CONFIG_BUILD_WITH_TFM=y （/ns 变体默认启用）的情况下构建 m33/ns 目标时，会自动将 TF-M 构建为 SPE，分别为它和 NSPE 签名，并生成包含这两个已签名镜像的 tfm_merged.hex，可直接交由 MCUBoot 验证：

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33/ns \
    <path/to/ns/app> -d build_tfm_ns \
    -- -DEXTRA_CONF_FILE="$ZEPHYR_BASE/boards/infineon/kit_pse84_eval/kit_pse84_eval_slot.conf"

步骤 3 — 烧录

烧录 MCUBoot（只需一次）：

west flash -d build_mcuboot

烧录 TF-M + NS 应用程序。west flash 会自动使用 tfm_merged.hex，其中包含已签名的 SPE（slot0）和已签名的 NSPE（slot2）：

west flash -d build_tfm_ns

备注

由于 SPE 和 NSPE 作为两个独立的 MCUBoot 镜像进行签名和验证，OTA 更新可以只针对其中一个，而无需重新签名另一个：新的 SPE 暂存在 slot1 中，新的 NSPE 暂存在 slot3 中。

TF-M Multicore Support

在此配置中，TF-M 运行在 CM33 安全侧，同时为 CM33 非安全应用程序和 CM55 应用程序提供 PSA 请求服务。CM55 通过基于邮箱的中继访问 TF-M。该功能通过 CONFIG_PSOC_EDGE_M55_SRF_SUPPORT 启用，必须在 两个 镜像中都设置。

备注

与独立 CM55 目标不同，此配置 不 使用 sysbuild。两个镜像作为独立的 Zephyr 应用程序分别构建、分别烧录。

构建

CM55 构建使用 CM33 非安全（TF-M）构建生成的 PSA 清单头文件，因此 必须先构建 CM33 镜像。通过 CMake 变量 PSE84_CM33_BUILD_DIR 让 CM55 构建指向它，该变量必须是 CM33 的构建目录（即传给 west build -d 的目录）。请使用绝对路径。

  1. 构建 CM33 非安全镜像：

    west build -b kit_pse84_eval/pse846gps2dbzc4a/m33/ns \
           -d build_multicore_33 samples/hello_world \
           -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y

  2. 构建 CM55 镜像：

    west build -b kit_pse84_eval/pse846gps2dbzc4a/m55 \
           -d build_multicore_55 samples/basic/blinky \
           -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y \
              -DPSE84_CM33_BUILD_DIR=<absolute-path-to>/build_multicore_33

如果未指定 PSE84_CM33_BUILD_DIR，默认为 ${ZEPHYR_BASE}/build。如果该目录中不包含 tfm/generated/interface/include，CM55 构建会以 FATAL_ERROR 停止。

烧录

先烧录 CM55 镜像。复位时 CM33 非安全镜像会启动 CM55，如果没有有效的 CM55 镜像，就会发生故障。

west flash -d build_multicore_55
west flash -d build_multicore_33

多核与 MCUBoot（三个镜像）

TF-M 多核配置也可以在 MCUBoot 之后运行。在此配置中，MCUBoot 在交出控制权之前会验证三个独立的镜像：

  • 镜像 0 — 位于 slot0_partition （0x100000）的 TF-M SPE

  • 镜像 1 — 位于 slot2_partition （0x340000）的 CM33 非安全镜像

  • 镜像 2 — 位于 slot4_partition （0x580000）的 CM55 应用程序

与上文的独立多核构建相比，只需增加两点：使用 CONFIG_UPDATEABLE_IMAGE_NUMBER=3 构建 MCUBoot，并将 kit_pse84_eval_slot.conf （它会启用 CONFIG_BOOTLOADER_MCUBOOT）传给两个应用程序构建。CONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y 仍用于启用 CM55 内核，必须在两个镜像中都设置。

备注

SW6 （BOOT SW）必须处于 OFF 位置，使扩展引导跳转到 RRAM 中的 MCUBoot。

步骤 1 — MCUBoot 引导加载程序（三个镜像）

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33 \
    bootloader/mcuboot/boot/zephyr -d build_mcuboot3 \
    -- -DCONFIG_UPDATEABLE_IMAGE_NUMBER=3

步骤 2 — CM33-NS 镜像（SPE + NSPE）

先构建 CM33-NS 镜像；CM55 构建会使用它生成的 PSA 清单头文件。

west build -b kit_pse84_eval/pse846gps2dbzc4a/m33/ns \
    -d build_multicore_33 samples/hello_world \
    -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y \
       -DEXTRA_CONF_FILE="$ZEPHYR_BASE/boards/infineon/kit_pse84_eval/kit_pse84_eval_slot.conf"

步骤 3 — CM55 镜像

通过 PSE84_CM33_BUILD_DIR 让 CM55 构建指向 CM33-NS 的构建目录。

west build -b kit_pse84_eval/pse846gps2dbzc4a/m55 \
    -d build_multicore_55 samples/basic/blinky \
    -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y \
       -DPSE84_CM33_BUILD_DIR=<absolute-path-to>/build_multicore_33 \
       -DEXTRA_CONF_FILE="$ZEPHYR_BASE/boards/infineon/kit_pse84_eval/kit_pse84_eval_slot.conf"

步骤 4 — 烧录

先烧录一次 MCUBoot，然后先烧录 CM55 镜像，再烧录 CM33-NS 镜像（CM33-NS 镜像在复位时启动 CM55）：

west flash -d build_mcuboot3
west flash -d build_multicore_55
west flash -d build_multicore_33
