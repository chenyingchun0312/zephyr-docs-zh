PSOC™ Edge E84 AI Evaluation Kit

Board Overview

Name:
kit_pse84_ai
Vendor:

Infineon Technologies

Status:

Not actively maintained

Architecture:

arm

SoC:

pse846gps2dbzc4a

Browse board sources

概述

KIT_PSE84_AI 是基于 PSOC™ Edge E84 系列的评估套件，搭载一颗 PSE846GPS2DBZC4A 微控制器，包含一个 200 MHz 的 Arm® Cortex®-M33 内核、一个 400 MHz 的 Arm® Cortex®-M55 内核和一个 Arm® Ethos™-U55 NPU。该套件面向机器学习、可穿戴设备和物联网应用。

主要特性包括 512 Mb QSPI NOR Flash、128 Mb Octal HYPERRAM™、基于 AIROC™ CYW55513 的 Wi-Fi + Bluetooth® 连接（LBEE5HY2FY 模块）、丰富的传感器（6 轴 IMU、磁力计、气压计、湿度传感器、雷达）、MIPI-DSI 显示接口、模拟和数字麦克风，以及一个 OV7675 DVP 摄像头模块。

该开发板带有一个通过 USB Type-C 连接的板载 KitProg3 编程器/调试器、扩展 IO 排针，并支持与树莓派兼容的 MIPI-DSI 显示屏。

启动流程

Cortex®-M33 是启动内核。Cortex®-M55 保持复位状态，直到运行在 M33 上的应用程序将其释放。

Reset
  -> Extended boot (Infineon, stored in RRAM), reads the boot pin
       (HIGH by default: first image in external flash)
  -> CM33 Secure image (Zephyr, or TF-M when using the /ns target)
       -> CM33 application
       -> optional: releases the CM55
            -> CM55 application

扩展引导（extended boot）运行的第一个镜像必须采用 MCUboot 镜像格式。构建过程会自动生成该格式；详见 Secure Boot。

两个镜像

在 CM55 上运行应用程序有两种方式：

  • 独立 CM55 （m55 目标加 --sysbuild）：CM55 运行应用程序，CM33 只负责启动它。这是通常的选择。

硬件

  • SoC： PSOC™ Edge E84（PSE846GPS2DBZC4A）

  • CPU： 200 MHz Arm® Cortex®-M33（启动内核）、400 MHz Arm® Cortex®-M55

  • NPU： Arm® Ethos™-U55

  • Flash： 512 Mb QSPI NOR Flash 存储器

  • RAM： 128 Mb Octal HYPERRAM 存储器

  • 无线： LBEE5HY2FY 模块 — Wi-Fi + Bluetooth®（AIROC CYW55513）

  • 传感器： 6 轴 IMU、3 轴磁力计、气压计、湿度传感器、雷达

  • 显示： MIPI-DSI（兼容树莓派）

  • 音频： 模拟和数字麦克风

  • USB： Type-C（设备）

  • 扩展： 扩展 IO 排针

  • 用户 I/O： 用户 LED 和用户按键

  • 安全： Arm® TrustZone®-M，带加密加速器的安全飞地（secure enclave）

  • 调试： 板载 KitProg3（SWD + UART 桥接）

串口

所有目标都使用 SCB2 （uart2）作为控制台和 shell，它通过 KitProg3 USB-UART 桥引出。默认设置为 115200 8N1。两个内核都运行 Zephyr 时，它们的输出共用该 UART。

Bluetooth HCI UART 为 SCB4 （uart4），带硬件流控（RTS/CTS），连接到 LBEE5HY2FY 模块。

系统时钟

PSOC™ Edge E84 有 14 个高频时钟（CLK_HF0 到 CLK_HF13），由 CM33 镜像配置。与应用程序最相关的是：

  • CLK_HF0： 200 MHz，CM33 内核和系统时钟

  • CLK_HF1： 400 MHz，CM55 内核

编程与调试

KIT_PSE84_AI 带有一个板载编程器/调试器（KitProg3），可用于对 PSOC™ Edge E84 的两个内核进行编程和调试。

Board Setup

用 USB 线将 PC 连接到 KitProg3 USB Type-C 接口（J1）。使用任意终端（minicom、PuTTY 等）以 115200 8N1 打开 KitProg3 串口。

以下示例假定使用默认的启动引脚设置，即从外部 Flash 启动（参见 Secure Boot）。

安装 Infineon OpenOCD

ModusToolbox™ Programming Tools 软件包中包含 Infineon OpenOCD。也可以下载适用于你的系统的 Infineon OpenOCD 发布版，并解压到任意位置。

备注

在 Linux 上，KitProg3 需要设备访问权限。ModusToolbox™ Programming Tools 安装程序会设置这些权限。对于独立安装的 OpenOCD，请运行 openocd/udev_rules/install_rules.sh。

告诉 west Infineon OpenOCD 的安装位置。在 Windows 上，可执行文件为 openocd.exe。

west config build.cmake-args -- "-DOPENOCD=path/to/infineon/openocd/bin/openocd"

备注

这会替换现有的 build.cmake-args 值。如果只想为单条命令设置路径，请使用 west flash --openocd <path>。

CM33:

# From the root of the zephyr repository

使用 west flash --erase 在编程前擦除设备。这会擦除用户可编程的 RRAM 区域以及 全部 外部 Flash，包括所有已存储的设置。扩展启动程序、OEM 策略和已配置的密钥不会被擦除。

安全启动

PSOC™ Edge E84 MCU 包含一个英飞凌扩展引导（extended boot）阶段，存放在保留的 RRAM 区域中，复位后跳转到第一个应用程序镜像。在 KIT_PSE84_AI 上，跳转目标由启动引脚的电平决定。该引脚默认被上拉为高电平，使扩展引导跳转到位于 外部 Flash 中的第一个应用程序。

要让扩展引导跳转到位于内部 RRAM 中的第一个应用程序，必须执行以下操作之一：

  • 硬件改装：拆除电阻 R188 并焊上电阻 R187，将启动引脚下拉为低电平。

  • 重新预置（无需改装硬件）：按照下文 Enabling Secure Boot 中描述的相同流程重新预置器件，但要修改生成的 OEM 策略 JSON，使其忽略启动引脚的状态。执行预置步骤时，在生成 OEM 密钥对之后、预置套件之前，将项目中 policy/policy_oem_provisioning.json 里的 oem_alt_boot 设为 false。

无论采用哪种方式，之后启动行为都会固定为从 RRAM 启动；要重新启用从外部 Flash 启动，必须恢复原状（重新焊上 R188 并拆除 R187，或将 oem_alt_boot 改回 true 后再次重新预置）。

在所有情况下，第一个应用程序镜像都必须采用 MCUboot 镜像格式，即镜像前面必须有 MCUboot 镜像头（魔数、头大小、向量表地址、镜像大小），后面必须有包含哈希/签名 TLV 的尾部（trailer）。出厂时器件 没有 针对安全启动进行预置，因此扩展引导只检查镜像格式和哈希，不会使用已预置的密钥进行加密签名验证。

MCUboot 镜像格式由 soc/infineon/edge/pse84/pse84_metadata.cmake 中的辅助函数 pse84_add_extboot_metadata() 自动生成，它使用从设备树内存映射推导出的头地址、头大小和槽大小调用 imgtool sign。默认情况下该辅助函数不传入签名密钥，这对于未配置（non-provisioned）的设备已经足够。

启用安全启动

要让扩展启动程序进行真正的签名验证，必须重新配置设备。按照 PSOC™ Edge Security Getting Started Application Note 的 2.2.1、2.2.2 和 2.2.3 节完成以下操作：

  1. 生成（或导入）OEM 签名密钥对。

  2. 使用对应的公钥配置设备并进行生命周期转换。

  3. 编程所需的安全计数器/防回滚值。

重新配置设备后，必须更新 soc/infineon/edge/pse84/pse84_metadata.cmake 中的 pse84_add_extboot_metadata() 函数，使 imgtool sign 也接收签名密钥和安全计数器。需要添加的内容如下：

${PYTHON_EXECUTABLE} ${IMGTOOL} sign --version "0.0.0+0"
  --header-size ${header_size} --erased-val 0xff
  --slot-size ${slot_size} --hex-addr ${hex_addr}
  --key <oem-private-key-file>
  --security-counter <value>
  ${INPUT_FILE} ${OUTPUT_FILE}

其中 <oem-private-key-file> 是与配置到设备中的公钥相匹配的 OEM 私钥文件路径（例如 .pem 文件），<value> 是配置时分配的安全计数器。如果没有这些额外参数，为已配置设备构建的镜像会被扩展启动程序拒绝。

TF-M Multicore Support

在此配置中，TF-M 运行在 CM33 安全侧，同时为 CM33 非安全应用程序和 CM55 应用程序提供 PSA 请求服务。CM55 通过基于邮箱的中继访问 TF-M。该功能通过 CONFIG_PSOC_EDGE_M55_SRF_SUPPORT 启用，必须在 两个 镜像中都设置。

备注

与独立 CM55 目标不同，此配置 不 使用 sysbuild。两个镜像作为独立的 Zephyr 应用程序分别构建、分别烧录。

构建

CM55 构建使用 CM33 非安全（TF-M）构建生成的 PSA 清单头文件，因此 必须先构建 CM33 镜像。通过 CMake 变量 PSE84_CM33_BUILD_DIR 让 CM55 构建指向它，该变量必须是 CM33 的构建目录（即传给 west build -d 的目录）。请使用绝对路径。

  1. 构建 CM33 非安全镜像：

    west build -b kit_pse84_ai/pse846gps2dbzc4a/m33/ns \
           -d build_multicore_33 samples/hello_world \
           -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y

  2. 构建 CM55 镜像：

    west build -b kit_pse84_ai/pse846gps2dbzc4a/m55 \
           -d build_multicore_55 samples/basic/blinky \
           -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y \
              -DPSE84_CM33_BUILD_DIR=<absolute-path-to>/build_multicore_33

如果未指定 PSE84_CM33_BUILD_DIR，默认为 ${ZEPHYR_BASE}/build。如果该目录中不包含 tfm/generated/interface/include，CM55 构建会以 FATAL_ERROR 停止。

烧录

先烧录 CM55 镜像。复位时 CM33 非安全镜像会启动 CM55，如果没有有效的 CM55 镜像，就会发生故障。

west flash -d build_multicore_55
west flash -d build_multicore_33
