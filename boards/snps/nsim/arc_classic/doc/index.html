ARC nSIM and HAPS FPGA boards

Board Overview

Name:
nsim
Vendor:

Synopsys, Inc.

Status:

Not actively maintained

Architecture:

arc

SoC:

nsim_hs_smp, nsim_hs6x, nsim_em7d_v22, nsim_hs5x_smp, nsim_vpx5, nsim_hs6x_smp, nsim_sem, nsim_hs, nsim_em11d, nsim_em, nsim_hs5x

Browse board sources

概述

该平台可用于在 Designware ARC nSIM [1] 仿真中，在尽可能多种类的 ARC 处理器上运行 Zephyr RTOS，也可以在 FPGA 原型验证平台 HAPS [3] 上运行相同的镜像。该平台具有以下特性：

  • 实现 ARCv2 或 ARCv3 ISA 的 ARC 处理器内核，当前支持的 ARC 处理器系列完整列表请参阅 此处

  • 虚拟串口控制台（标准 ns16550 UART 模型）

ARC 处理器以高度可定制著称，Zephyr RTOS 的 ARC 移植目前只支持其中部分配置，支持的功能完整列表同样请参阅 此处。

该平台支持多种子配置。下面列出了当前可用配置中的一部分：

  • nsim/nsim_em - ARC EM 内核 v4.0，带两个寄存器组、FastIRQ、MPUv2、DSP 选项和 XY 存储器

  • nsim/nsim_em7d_v22 - ARC EM 内核 v3.0，带一个寄存器组和 FastIRQ

  • nsim/nsim_em11d - ARC EM 内核 v4.0，带一个寄存器组，无 FastIRQ，带 MPUv2、DSP 选项和 XY 存储器

  • nsim/nsim_sem - ARC EM 内核 v4.0，带安全特性（因此称为“SEM”，即 Secure EM）和 MPUv4

  • nsim/nsim_hs - ARCv2 HS 内核 v2.1，带两个寄存器组、FastIRQ 和 MPUv3

  • nsim/nsim_hs_smp - 双核 ARCv2 HS 内核 v2.1，带两个寄存器组、FastIRQ 和 MPUv3

  • nsim/nsim_vpx5 - ARCv2 VPX5 内核，接近 vpx5_integer_full 模板

  • nsim/nsim_hs5x - 32 位 ARCv3 HS 内核，带丰富的选项

  • nsim/nsim_hs6x - 64 位 ARCv3 HS 内核，带丰富的选项

  • nsim/nsim_hs5x_smp/12cores - 12 核 SMP 32 位 ARCv3 HS 平台

  • nsim/nsim_hs6x_smp/12cores - 12 核 SMP 64 位 ARCv3 HS 平台

建议查看 boards/snps/nsim/arc_classic/support/ 目录中 .props 或 .args 文件对具体子配置的准确描述，以了解配置了哪些选项，从而了解调用仿真器时会使用哪些选项。

对于单核配置，.props 文件包含 nSIM 仿真器的配置，.args 文件包含 MetaWare 调试器（MDB）的配置。注意这两个文件包含相同的硬件配置，分别供对应的工具使用：.props 文件用于 nSIM 仿真器，.args 文件用于 MDB（MDB 内部同样使用 nSIM 进行仿真）。

提示

如果在执行或调试某个应用程序时观察到不同的行为（尤其是在新建开发板或修改现有开发板之后），请确保 .props 和 .args 中定义的特性在语义上完全一致（遗憾的是 nSIM 和 MDB 的选项并不完全对应，因此需要格外小心）。

例如，对于单核 nsim/nsim_hs5x 平台，有 boards/snps/nsim/arc_classic/support/nsim_hs5x.props 和 boards/snps/nsim/arc_classic/support/mdb_hs5x.args 两个文件。

对于多核配置，只有 .args 文件，因为多核配置只能借助 MDB 实例化。

例如，对于多核 nsim/nsim_hs5x_smp 平台，只有 boards/snps/nsim/arc_classic/support/mdb_hs5x_smp.args。

警告

所有 nSIM/MDB 配置都仅用于演示和测试，并不代表任何实际系统，因此随时可能被重命名、删除或修改。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

所需硬件和软件

要在本开发板上以仿真方式运行单核 Zephyr RTOS 应用程序，需要 DesignWare ARC nSIM [1] 或 DesignWare ARC Free nSIM [2]。

要在该开发板上以仿真方式运行多核 Zephyr RTOS 应用程序，需要 DesignWare ARC nSIM [1] 以及 ARC MWDT [4] 中的 MetaWare 调试器。

要在基于 FPGA 的 HAPS [3] 平台上运行 Zephyr RTOS 应用程序，除 HAPS 平台本身外，还需要 ARC MWDT [4] 中的 MetaWare 调试器。

构建和运行示例应用程序

大多数开发板子配置都支持使用 GNU 和 ARC MWDT 两种工具链构建，但也可能有例外，尤其是新添加的目标。可以在相应的 .yaml 文件中查看子配置支持的工具链。

例如，对于 nsim/nsim_hs5x 开发板，可以查看 boards/snps/nsim/arc_classic/nsim_nsim_hs5x.yaml

支持的工具链列在 .yaml 文件的 toolchain: 数组中，其中包括：

  • zephyr - 指 Zephyr SDK 中的 ARC GNU 工具链。关于 Zephyr SDK 的更多信息请参见 此处。

  • cross-compile - 指不属于 Zephyr SDK 的 ARC GNU 交叉工具链。注意，部分子配置（尤其是新的子配置）可能只声明支持 cross-compile 工具链而不支持 zephyr 工具链，因为相应目标 CPU 的支持尚未加入 Zephyr SDK。关于其用法的更多信息请参见 此处。

  • arcmwdt：表示专有的 ARC MWDT 工具链。有关其用法的更多信息，请参阅 此处。

备注

注意，即使目标声明同时支持 GNU 和 MWDT 工具链，由于某些功能仅限于特定工具链，部分测试或示例也可能只能用 GNU 或 MWDT 工具链之一构建。

使用此配置在 nSIM 中运行基本 Zephyr 应用程序和内核测试，例如使用 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b nsim_em samples/synchronization
west flash

这将构建一个包含 synchronization 示例应用的镜像，使用 nSIM 启动该镜像，并显示以下控制台输出：

*** Booting Zephyr OS build zephyr-v3.2.0-3948-gd351a024dc87 ***
thread_a: Hello World from cpu 0 on nsim!
thread_b: Hello World from cpu 0 on nsim!
thread_a: Hello World from cpu 0 on nsim!
thread_b: Hello World from cpu 0 on nsim!
thread_a: Hello World from cpu 0 on nsim!

备注

要退出仿真器，请按 Ctrl+]，然后按 Ctrl+c

小技巧

以详细模式运行构建可以获取构建过程的更多细节。方法是向 west 传入 -v 标志：west -v build -b nsim_hs samples/synchronization

为 nsim 开发板构建的应用程序不仅可以在 nSIM 仿真中运行，还可以在基于 FPGA 的硬件平台 HAPS [3] 上运行。要在 HAPS 上运行已构建的应用程序，执行：

west flash --runner mdb-hw

备注

要在 HAPS 上运行，除了正确构建和烧录 Zephyr 镜像外，还需要设置 HAPS 本身，并烧录正确构建的 FPGA 镜像（即 .bit 文件）。本说明不涉及这些步骤，请按照 HAPS 手册操作。

调试

使用 MDB 调试

备注

我们强烈建议使用 MetaWare 调试器（MDB）进行调试，因为它：

  • 支持更多的 ARC 硬件特性

  • 可以调试单核和多核 nsim 目标。

  • 可以在 HAPS [3] 平台上调试。

在 nSIM 仿真器上运行应用程序时（无论使用单核还是多核配置），可以使用以下命令启动图形界面调试：

west debug --runner mdb-nsim

在 HAPS [3] 平台上运行应用程序时，可以使用以下命令启动图形界面调试：

west debug --runner mdb-hw

小技巧

west debug（以及 west flash）只是一个包装脚本，因此可以通过以详细模式运行它来提取其中实际调用的命令。为此需要向包装脚本传入 -v 参数。例如，运行以下命令：

west -v debug --runner mdb-nsim

会产生以下输出（该示例使用的是 nsim/nsim_hs5x_smp 配置）：

 < *snip* >
-- west debug: using runner mdb-nsim
runners.mdb-nsim: mdb -pset=1 -psetname=core0 -nooptions -nogoifmain -toggle=include_local_symbols=1 -nsim @/path/zephyr/boards/snps/nsim/support/mdb_hs5x_smp.args /path/zephyr/build/zephyr/zephyr.elf
runners.mdb-nsim: mdb -pset=2 -psetname=core1 -prop=download=2 -nooptions -nogoifmain -toggle=include_local_symbols=1 -nsim @/path/zephyr/boards/snps/nsim/support/mdb_hs5x_smp.args /path/zephyr/build/zephyr/zephyr.elf
runners.mdb-nsim: mdb -multifiles=core1,core0 -OKN

从该输出中可以提取出用于建立图形界面调试会话的 MDB 命令：

mdb -pset=1 -psetname=core0 -nooptions -nogoifmain -toggle=include_local_symbols=1 -nsim @/path/zephyr/boards/snps/nsim/support/mdb_hs5x_smp.args /path/zephyr/build/zephyr/zephyr.elf
mdb -pset=2 -psetname=core1 -prop=download=2 -nooptions -nogoifmain -toggle=include_local_symbols=1 -nsim @/path/zephyr/boards/snps/nsim/support/mdb_hs5x_smp.args /path/zephyr/build/zephyr/zephyr.elf
mdb -multifiles=core1,core0 -OKN

然后可以直接使用这些命令，或在需要时将其用于其他自动化流程中。

警告

强烈建议不要依赖上面列出的 mdb 命令行选项，而是针对自己的配置自行提取。

备注

如果不通过 west flash 和 west debug 包装脚本，而是直接在 nSIM 仿真器的多核配置上使用 MDB 执行或调试，则需要将环境变量 NSIM_MULTICORE 设置为 1。如果使用 west flash 或 west debug，包装脚本会自动完成此设置。

如果未将环境变量 NSIM_MULTICORE 设置为 1，MDB 将仿真 2 个彼此不共享任何内存区域的独立 ARC 内核，因此启用 SMP 的代码将无法按预期工作。

使用 GDB 调试

备注

在 nSIM 上通过 GDB 调试仅支持单核配置（使用独立的 nSIM）。不过，如果可以在多核 nsim 目标上启动应用程序，就可以直接 使用 MDB 调试器调试。这是 nSIM 配合 ARC GDB 使用时的限制，真实的多核 ARC 硬件目标可以使用 ARC GDB 调试。

备注

目前不支持在 HAPS [3] 平台上使用 GDB 调试。

备注

普通的 west debug 命令无法用于调试使用 nsim 开发板的应用程序，因为 nSIM 仿真器和调试器（GDB 或 MDB）使用同一个控制台进行输入/输出。对于 GDB 调试器，可以为 GDB 和 nSIM 分别使用单独的终端窗口，以避免二者的输出混在一起。对于 MDB 调试器，直接使用图形界面模式即可。

构建应用程序后，打开两个终端窗口。在第一个终端中，使用以下命令让 nSIM 启动 GDB 服务器并等待远程连接：

west debugserver --runner arc-nsim

在第二个终端中，使用 ARC GDB 连接到 GDB 服务器。ARC GDB 可以在 Zephyr SDK 中找到：

  • 对于 ARCv2 目标，应使用 arc-zephyr-elf-gdb

  • 对于 ARCv3 目标，应使用 arc64-zephyr-elf-gdb

该命令从 elf 二进制文件（例如 build/zephyr/zephyr.elf 文件）加载符号表：

arc-zephyr-elf-gdb  -ex 'target remote localhost:3333' -ex load build/zephyr/zephyr.elf

调试环境现已设置完成，可以使用 gdb 命令调试应用程序。

修改配置

如果需要修改现有的 nsim 配置，甚至需要创建新配置，则必须保持以下各项之间的一致

  • Zephyr OS 配置

  • nSIM 与 MDB 配置

  • GNU 和 MWDT 工具链编译器选项

备注

Zephyr 不直接支持 .tcf 配置文件，原因有多个。.tcf 非常适合构建裸机单线程应用程序：此时 .tcf 中的所有编译器选项都会传给编译器，应用程序因而使用全部硬件功能，并生成最优代码。而对于功能丰富的多线程操作系统，情况则完全不同。当然，仍然可以使用 .tcf 中的全部选项构建所有代码，但这可能远非最优方案。例如，这种做法需要为所有任务（有时甚至为中断）保存和恢复完整的寄存器上下文。对于启用了 DSP 或 FPU 的系统，即使大多数用户和内核任务实际上并不使用 DSP 或 FPU，也会导致额外保存和恢复数十个寄存器。因此，我们更倾向于精细调整硬件功能的使用，这样做（尽管有诸多好处）需要我们在 .tcf 配置之外单独维护这些设置。

Zephyr OS 配置

Zephyr OS 的配置通过 Kconfig 和设备树定义。这些并非 ARC 特有的机制，在 开发板移植指南 中有说明。

建议以 <board_name>_defconfig、<board_name>.dts 和 <board_name>.yaml 作为了解开发板配置的入口。

nSIM 配置

nSIM 配置定义在 props 和 args 文件 中。通常它们与相应 .tcf 配置中的值相同，只有少数例外：

  • 添加了 UART 模型（同时加入 .props 和 .args 文件）。

  • 添加了用于微调 MDB 行为的选项（仅加入 .args 文件），用于禁用 MDB 性能分析并微调 MDB 在多核系统上的行为。

GNU 和 MWDT 工具链编译器选项

硬件相关的编译器选项在相应的 SoC cmake 文件中设置。对于 nsim 开发板，该文件是 soc/snps/nsim/arc_classic/CMakeLists.txt。

对于 GNU 工具链，基本配置通过 -mcpu 设置，该选项在通用代码中定义，并根据通过 Kconfig 选择的 CPU 型号确定。仍然可以在 SoC 层面将其强制设置为所需的值。

对于 MWDT 工具链，所有硬件相关的编译器选项都直接在 SoC 的 CMakeLists.txt 中设置。

备注

与硬件无关的编译器选项，例如优化、库选择、C/C++ 语言选项，仍在 Zephyr 通用代码中设置。可以通过 以详细模式运行构建 查看这些选项。
