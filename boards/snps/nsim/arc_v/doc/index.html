RISC-V nSIM and HAPS FPGA boards

Board Overview

Name:
nsim_arc_v
Vendor:

Synopsys, Inc.

Status:

Not actively maintained

Architecture:

riscv

SoC:

rhx100, rmx100

Browse board sources

概述

该平台可用于在 Designware ARC nSIM [1] 仿真中，在尽可能多种类的 Synopsys RISC-V 处理器上运行 Zephyr RTOS，也可以在 FPGA 原型验证平台 HAPS [3] 上运行相同的镜像。该平台具有以下特性：

  • 实现 riscv32 ISA 的 RISC-V 处理器内核

  • 虚拟串口控制台（标准 ns16550 UART 模型）

该平台支持的开发板目标如下：

  • nsim_arc_v/rmx100 - Synopsys RISC-V RMX100 内核

  • nsim_arc_v/rhx100 - Synopsys RISC-V RHX100 内核

建议查看 boards/snps/nsim/arc_v/support/ 目录中 .props 文件对具体开发板目标的准确描述，以了解配置了哪些选项，从而了解调用仿真器时会使用哪些选项。

警告

所有 nSIM 目标都仅用于演示和测试，并不代表任何实际系统，因此随时可能被重命名、删除或修改。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

所需硬件和软件

要在本开发板上以仿真方式运行单核 Zephyr RTOS 应用程序，需要 DesignWare ARC nSIM [1] 或 DesignWare ARC Free nSIM [2]。

构建和运行示例应用程序

大多数开发板目标都支持使用 GNU 和 ARC MWDT 两种工具链构建，但也可能有例外，尤其是新添加的目标。可以在相应的 .yaml 文件中查看开发板目标支持的工具链。

例如，对于 nsim_arc_v/rmx100 开发板，可以查看 boards/snps/nsim/arc_v/nsim_arc_v_rmx100.yaml；对于 nsim_arc_v/rhx100 开发板，可以查看 boards/snps/nsim/arc_v/nsim_arc_v_rhx100.yaml

支持的工具链列在 .yaml 文件的 toolchain: 数组中，其中包括：

  • zephyr - 指 Zephyr SDK 中的 RISC-V GNU 工具链。关于 Zephyr SDK 的更多信息请参见 此处。

  • cross-compile - 指不属于 Zephyr SDK 的 RISC-V GNU 交叉工具链。注意，部分开发板目标（尤其是新的目标）可能只声明支持 cross-compile 工具链而不支持 zephyr 工具链，因为相应目标 CPU 的支持尚未加入 Zephyr SDK。关于其用法的更多信息请参见 此处。

  • arcmwdt：表示专有的 ARC MWDT 工具链。有关其用法的更多信息，请参阅 此处。

备注

注意，即使目标声明同时支持 GNU 和 MWDT 工具链，由于某些功能仅限于特定工具链，部分测试或示例也可能只能用 GNU 或 MWDT 工具链之一构建。

使用此配置在 nSIM 中运行基本 Zephyr 应用程序和内核测试，例如使用 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b nsim_arc_v/rmx100 samples/synchronization
west flash

这将构建一个包含 synchronization 示例应用的镜像，使用 nSIM 启动该镜像，并显示以下控制台输出：

*** Booting Zephyr OS build zephyr-v3.2.0-3948-gd351a024dc87 ***
thread_a: Hello World from cpu 0 on nsim_arc_v!
thread_b: Hello World from cpu 0 on nsim_arc_v!
thread_a: Hello World from cpu 0 on nsim_arc_v!
thread_b: Hello World from cpu 0 on nsim_arc_v!
thread_a: Hello World from cpu 0 on nsim_arc_v!

备注

要退出仿真器，请按 Ctrl+]，然后按 Ctrl+c

小技巧

以详细模式运行构建可以获取构建过程的更多细节。方法是向 west 传入 -v 标志：west -v build -b nsim_hs samples/synchronization

调试

使用 GDB 调试

备注

在 nSIM 上通过 GDB 调试仅支持单核目标（使用独立的 nSIM）。

备注

普通的 west debug 命令无法用于调试使用 nsim 开发板的应用程序，因为 nSIM 仿真器和调试器使用同一个控制台进行输入/输出。对于 GDB 调试器，可以为 GDB 和 nSIM 分别使用单独的终端窗口，以避免二者的输出混在一起。

构建应用程序后，打开两个终端窗口。在第一个终端中，使用以下命令让 nSIM 启动 GDB 服务器并等待远程连接：

west debugserver --runner arc-nsim

在第二个终端中，使用 RISC-V GDB 连接到 GDB 服务器。RISC-V GDB 可以在 Zephyr SDK 中找到：

  • 应使用 riscv64-zephyr-elf-gdb

该命令从 elf 二进制文件（例如 build/zephyr/zephyr.elf 文件）加载符号表：

riscv64-zephyr-elf-gdb  -ex 'target remote localhost:3333' -ex load build/zephyr/zephyr.elf

调试环境现已设置完成，可以使用 gdb 命令调试应用程序。

使用 lldbac 调试

lldbac 运行器随 Synopsys ARC MWDT 工具链提供，使用 run-lldbac 对仿真器和硬件目标进行集成调试。

备注

确保已安装 run-lldbac（来自 ARC MWDT [4]），并且可以在 PATH 中找到。

lldbac 运行器支持以下命令：

  1. debug：带集成服务器管理的交互式调试

  2. flash：在物理硬件上烧录并运行

使用仿真器（nSIM）调试

要在 nSIM 仿真器上进行交互式调试，请使用带 --simulator 参数的 debug 命令：

west debug --runner lldbac --simulator

运行器使用开发板 board.cmake 文件中配置的 nSIM 属性。可以通过 --nsim-props 覆盖，或通过 --tcf 使用 TCF 文件：

west debug --runner lldbac --simulator --nsim-props=rmx100.props
west debug --runner lldbac --simulator --tcf=rmx100

备注

lldbac 运行器专为交互式调试流程设计。如需在仿真器上执行而不调试（flash），请使用 arc-nsim 运行器，它可以高效地以非交互方式执行：

west flash --runner arc-nsim

这样分工后，lldbac 可以专注于调试功能，而 arc-nsim 负责高效完成常规执行。

使用硬件调试

要在物理硬件上调试，请通过命令行参数提供 JTAG 配置：

west debug --runner lldbac
west flash --runner lldbac

可用的硬件选项：

  • --jtag：JTAG 适配器类型（默认：jtag-digilent）

  • --jtag-device：JTAG 设备名称（可选，未指定时自动检测，例如 JtagHs2）

  • --jtag-frequency：JTAG 时钟频率（默认：500KHz）

  • --postconnect-cmd：连接后执行的命令（可多次使用）

  • --postconnect-file：包含硬件初始化后要执行的命令的文件

  • --board-json：用于复杂开发板配置的 board.json 文件路径

使用 postconnect 命令进行硬件初始化的示例：

west flash --runner lldbac --postconnect-cmd "reg write sp 0x1000"
west flash --runner lldbac --postconnect-file postconnect.cmd
west debug --runner lldbac --board-json board.json

图形界面模式

要启动带 VS Code 图形界面支持的调试，请添加 --gui 参数：

west debug --runner lldbac --simulator --gui
west debug --runner lldbac --gui

修改配置

如果需要修改现有的 nsim 配置，甚至需要创建新配置，则必须保持以下各项之间的一致

  • Zephyr OS 配置

  • nSIM 配置

  • GNU 和 MWDT 工具链编译器选项

备注

Zephyr 不直接支持 .tcf 配置文件，原因有多个。.tcf 非常适合构建裸机单线程应用程序：此时 .tcf 中的所有编译器选项都会传给编译器，应用程序因而使用全部硬件功能，并生成最优代码。而对于功能丰富的多线程操作系统，情况则完全不同。当然，仍然可以使用 .tcf 中的全部选项构建所有代码，但这可能远非最优方案。例如，这种做法需要为所有任务（有时甚至为中断）保存和恢复完整的寄存器上下文。对于启用了 DSP 或 FPU 的系统，即使大多数用户和内核任务实际上并不使用 DSP 或 FPU，也会导致额外保存和恢复数十个寄存器。因此，我们更倾向于精细调整硬件功能的使用，这样做（尽管有诸多好处）需要我们在 .tcf 配置之外单独维护这些设置。

Zephyr OS 配置

Zephyr OS 的配置通过 Kconfig 和设备树定义。这些并非 RISC-V 特有的机制，在 开发板移植指南 中有说明。

建议以 <board_name>_defconfig、<board_name>.dts 和 <board_name>.yaml 作为了解开发板目标的入口。

nSIM 配置

nSIM 配置定义在 props 文件 中。通常它们与相应 .tcf 配置中的值相同，只有少数例外：

  • 添加了 UART 模型

  • 添加了 CLINT 模型

GNU 和 MWDT 工具链编译器选项

硬件相关的编译器选项在相应的 SoC cmake 文件中设置。对于 nsim_arc_v 开发板，该文件是 soc/snps/nsim/arc_v/CMakeLists.txt。

对于 GNU 工具链，基本配置通过 -march 设置，该选项在通用代码中定义，并根据通过 Kconfig 选择的 CPU 型号确定。仍然可以在 SoC 层面将其强制设置为所需的值。

备注

与硬件无关的编译器选项，例如优化、库选择、C/C++ 语言选项，仍在 Zephyr 通用代码中设置。可以通过 以详细模式运行构建 查看这些选项。
