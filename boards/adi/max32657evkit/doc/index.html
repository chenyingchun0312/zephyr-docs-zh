Board Overview

max32657evkit

Analog Devices, Inc.

Status:

Not actively maintained

Architecture:

arm

SoC:

max32657

Browse board sources

概述

MAX32657 微控制器（MCU）是一款先进的片上系统（SoC），搭载带单精度浮点单元（FPU）和数字信号处理（DSP）指令的 Arm® Cortex®-M33 内核、大容量 Flash 和 SRAM 存储器，以及最新一代 Bluetooth® 5.4 低功耗（LE）无线电。纳瓦级功耗模式可大幅延长电池寿命。

MAX32657 的工作温度范围为 -20 °C 至 +85 °C。Bluetooth 5.4 LE 无线电支持 Mesh、远距离（编码）和高吞吐量模式。加密工具箱（CTB）提供先进的信任根安全功能，包括高级加密标准（AES）引擎、TRNG 和安全启动。M33 内核还包含 TrustZone。该器件支持多种高速接口，包括多个 SPI、UART 和 I3C/I2C 串行接口。所有接口都支持在外设与存储器之间进行高效的 DMA 传输。

Zephyr 移植运行在 MAX32657 MCU 上。

硬件

  • MAX32657 MCU:

    • 带 TrustZone® 和 FPU 的 Arm Cortex-M33 CPU

    • 集成升压 DC-DC 转换器，输入范围 1.2V 至 1.6V

    • 50MHz 低功耗振荡器

    • 支持外部晶体

      • BLE 需要 32MHz

    • 1MB 带 ECC 的内部 Flash

    • 256kB 内部 SRAM

    • 8kB 缓存

    • 32.768kHz RTC 外部晶体

    • 典型电气特性

      • 工作模式：运行 Coremark（50MHz）时 Arm Cortex-M33 功耗 50μA/MHz

    • Bluetooth 5.4 LE 射频

      • 接收灵敏度：-96dBm；发射功率：+4.5dBm

      • 1.5V 输入、0dBm 时发射功耗 15mW

      • 1.5V 输入时接收功耗 14mW

      • 单端天线连接（50Ω）

      • 支持 802.15.4 和 LE Audio

      • 高吞吐量（2Mbps）模式

      • 远距离（125kbps 和 500kbps）模式

    • 优化的外设组合，提供平台可扩展性

      • 2 个 DMA 控制器（安全和非安全）

      • One SPI Controller/Peripheral

      • One I2C/I3C

      • 1 个低功耗 UART（LPUART）

      • 六个带 PWM 的 32 位低功耗定时器

      • 14 个可配置 GPIO，带内部上拉/下拉电阻

    • 用于 IP/数据安全的加密工具箱（CTB）

      • 真随机数发生器（TRNG）

      • AES-128/192/256

      • 唯一 ID

    • 安全启动 ROM

Zephyr 开发板选项

MAX32657 微控制器（MCU）是一款先进的片上系统（SoC），采用 ARM Cortex-M33 架构，提供 TrustZone 技术，可以分别定义安全和非安全应用程序。Zephyr 支持构建安全（S）和非安全（NS）固件。

BOARD 选项汇总如下：

max32657evkit/max32657

max32657evkit/max32657/ns

BOARD: max32657evkit/max32657

为 max32657evkit/max32657 开发板目标构建 Zephyr 应用程序会生成 Zephyr 安全固件。在此配置中，960KB Flash 用于存储代码，64KB 用作存储分区。在此模式下，TF-M 关闭，安全模式标志开启（CONFIG_TRUSTED_EXECUTION_SECURE 设为 y，CONFIG_BUILD_WITH_TFM 设为 n）

以下是使用 Blinky 示例以安全配置构建 Zephyr 的说明：

# From the root of the zephyr repository
west build -b max32657evkit/max32657 samples/basic/blinky/

BOARD: max32657evkit/max32657/ns

max32657evkit/max32657/ns 开发板目标用于使用 TF-M 构建安全固件镜像（CONFIG_BUILD_WITH_TFM 设为 y），并使用 Zephyr 构建非安全固件镜像（CONFIG_TRUSTED_EXECUTION_NONSECURE 设为 y）。

以下是使用 Blinky 示例以非安全配置构建 Zephyr 的说明：

# From the root of the zephyr repository
west build -b max32657evkit/max32657/ns samples/basic/blinky/

上述命令将：

  • 构建引导加载程序镜像（MCUboot）

  • 构建 TF-M（安全）固件镜像

  • 将 Zephyr 应用程序构建为非安全固件镜像

  • 将它们合并为包含所有镜像的 tfm_merged.hex。

注：

Zephyr 以 CONFIG_TFM_PROFILE_TYPE_NOT_SET 模式构建 TF-M，该模式满足大多数用例配置，尤其是与 BLE 相关的应用程序。如果 TF-M small 配置文件满足应用程序的需求，可以将 CONFIG_TFM_PROFILE_TYPE_SMALL 设置为 y，以减少 TF-M 的 RAM 和 Flash 占用。

Flash 存储器布局同时在 Zephyr 开发板文件和 Trusted Firmware M（TF-M）项目中定义，这两处定义必须一致。Zephyr 在 boards/adi/max32657evkit/max32657evkit_max32657_common.dtsi 文件的 flash 部分中定义布局。TF-M 项目在 <zephyr_path>../modules/tee/tf-m/trusted-firmware-m/platform/ext/target/adi/max32657/partition/flash_layout.h 文件中定义布局。` 如果要为应用程序修改 Flash 区域，需要更新这些文件中的相关部分。

此外，如果需要固件更新功能，还需要定义 slot1 和 slot1_ns 分区。默认情况下不需要固件更新，因此这些分区大小设置为 0。

外设与内存归属

ARM 安全扩展模型允许系统开发者对设备的硬件和软件资源进行划分，使其要么位于供安全子系统使用的安全世界，要么位于供其他一切使用的普通世界。正确的系统设计可以确保无法从普通世界访问任何安全世界的资产。安全的设计会将所有敏感资源放在安全世界中，并且最好运行可靠的软件，能够保护资产免受各种可能的软件攻击（1）。

MPC（内存保护控制器）和 PPC（外设保护控制器）可以保护内存和外设。如有需要，可以在 <zephyr_path>../modules/tee/tf-m/trusted-firmware-m/platform/ext/target/adi/max32657/s_ns_access.cmake` 文件中将 cmake 标志改为 ON/OFF，以更新外设和 Flash 的归属。

set(ADI_NS_PRPH_TIMER1      ON         CACHE BOOL "")
set(ADI_NS_PRPH_TIMER2      ON         CACHE BOOL "")
set(ADI_NS_PRPH_TIMER3      ON         CACHE BOOL "")
set(ADI_NS_PRPH_TIMER4      ON         CACHE BOOL "")
set(ADI_NS_PRPH_TIMER5      ON         CACHE BOOL "")
set(ADI_NS_PRPH_I3C         ON         CACHE BOOL "")
set(ADI_NS_PRPH_UART        ON         CACHE BOOL "")
set(ADI_NS_PRPH_SPI         ON         CACHE BOOL "")
set(ADI_NS_PRPH_TRNG        OFF        CACHE BOOL "")

# SRAMs
set(ADI_NS_SRAM_0           OFF        CACHE BOOL "Size: 32KB")
set(ADI_NS_SRAM_1           OFF        CACHE BOOL "Size: 32KB")
set(ADI_NS_SRAM_2           ON         CACHE BOOL "Size: 64KB")
set(ADI_NS_SRAM_3           ON         CACHE BOOL "Size: 64KB")
set(ADI_NS_SRAM_4           ON         CACHE BOOL "Size: 64KB")

# Ramfuncs section size
set(ADI_S_RAM_CODE_SIZE     "0x800"    CACHE STRING "Default: 2KB")

# Flash: BL2, TFM and Zephyr are contiguous sections.
set(ADI_FLASH_AREA_BL2_SIZE        "0x10000"  CACHE STRING "Default: 64KB")
set(ADI_FLASH_S_PARTITION_SIZE     "0x50000"  CACHE STRING "Default: 320KB")
set(ADI_FLASH_NS_PARTITION_SIZE    "0x90000"  CACHE STRING "Default: 576KB")
set(ADI_FLASH_PS_AREA_SIZE         "0x4000"   CACHE STRING "Default: 16KB")
set(ADI_FLASH_ITS_AREA_SIZE        "0x4000"   CACHE STRING "Default: 16KB")

#
# Allow user set S-NS resources ownership by overlay file
#
if(EXISTS "${CMAKE_BINARY_DIR}/../../s_ns_access_overlay.cmake")
  include(${CMAKE_BINARY_DIR}/../../s_ns_access_overlay.cmake)
endif()

另一种方法（推荐）是通过 cmake 覆盖文件配置外设归属，而无需修改 TF-M 源文件。为此，在项目根目录下创建 s_ns_access_overlay.cmake 文件，并在其中写入希望由安全世界访问的外设/内存。

例如，如果将以下配置放入 s_ns_access_overlay.cmake 文件，TRNG、SRAM_0 和 SRAM_1 将只能被安全世界访问。

set(ADI_NS_PRPH_TRNG        OFF        CACHE BOOL "")
set(ADI_NS_SRAM_0           OFF        CACHE BOOL "Size: 32KB")
set(ADI_NS_SRAM_1           OFF        CACHE BOOL "Size: 32KB")
