NRF52 模拟开发板（BabbleSim）

  • 概述

  • 构建与运行

  • C 库的选择

  • 调试、覆盖率和地址消毒器

  • 关于 BabbleSim 中的时间

概述

为了能够模拟 nRF52833 SOC，提供了一个 Zephyr 目标开发板：nrf52_bsim。

这里使用 BabbleSim 模拟射频活动，并使用 POSIX 架构 和 native simulator 在开发系统上原生运行应用程序。这样可以获得原生代码的执行性能，并能方便地使用原生工具调试，但也继承了 它的局限性。

该开发板包含部分 nRF52 SOC 外设的模型：

  • 无线电

  • 定时器

  • AAR（加速地址解析器）

  • AES CCM 和 AES ECB 加密硬件

  • CLOCK（时钟控制）

  • EGU（事件发生器单元）

  • FICR（工厂信息配置寄存器）

  • GPIO & GPIOTE

  • NVMC（非易失性存储器控制器 / Flash）

  • PPI（可编程外设互连）

  • RNG（随机数发生器）

  • RTC（实时计数器）

  • TEMP（温度传感器）

  • UART 和 UARTE（带 Easy DMA 的 UART）

  • UICR（用户信息配置寄存器）

并且这些外设使用与 nrf52 dk 目标相同的驱动。有关哪些部分被建模以及建模的详细程度，请查看 HW models implementation status。

注意，与真实的 nrf52 设备不同，nrf52_bsim 的 RAM 和代码 Flash 不受限制。

构建与运行

该开发板需要主机的 32 位 C 库。参见 POSIX 架构依赖项。

要以该开发板为目标，还需要在系统中编译 BabbleSim。如果尚未安装，最简单的获取方式是在本地 west 配置中启用 babblesim 组，运行 west update，然后构建模拟器：

west config manifest.group-filter -- +babblesim
west update
cd ${ZEPHYR_BASE}/../tools/bsim
make everything -j 8

备注

如果需要更多 BabbleSim 组件或更新的版本，可以查看 BabbleSim 网页，了解如何 获取 和 构建 它。

现在需要定义两个指向 BabbleSim 安装位置的环境变量：BSIM_OUT_PATH 和 BSIM_COMPONENTS_PATH。如果按照前面的步骤操作，只需执行：

export BSIM_OUT_PATH=${ZEPHYR_BASE}/../tools/bsim
export BSIM_COMPONENTS_PATH=${BSIM_OUT_PATH}/components/

备注

可以将这两行添加到 ~/.zephyrrc 文件或 shell 初始化脚本（~/.bashrc）中，这样就不必在每个新 shell 中手动重新运行它们。

现在可以构建以该开发板为目标的应用程序了，例如：

west build -b nrf52_bsim samples/hello_world

然后可以使用以下命令运行应用程序：

$ ./build/zephyr/zephyr.exe -nosim
# Press Ctrl+C to exit

注意，该可执行文件是一个 BabbleSim 可执行文件。-nosim 命令行选项表示要脱离 BabbleSim 模拟运行它。这只有在没有射频活动时才可行，但对大多数 Zephyr 示例和测试来说完全没有问题。

如果要运行带有射频活动的模拟，还需要运行 BableSim 2G4（2.4GHz）物理层模拟（phy）。

例如，如果要运行一个简单的场景，让 BLE Heart-rate Monitor (Central) 示例应用程序连接到 BLE Heart-rate Monitor (Peripheral) 示例应用程序：以该开发板为目标构建 Heart-rate Monitor (Central) 应用程序，并将生成的可执行文件以合适的名称复制到模拟器的 bin 文件夹中：

west build -b nrf52_bsim samples/bluetooth/central_hr

$ cp build/zephyr/zephyr.exe \
  ${BSIM_OUT_PATH}/bin/bs_nrf52_bsim_samples_bluetooth_central_hr

对 Heart-rate Monitor (Peripheral) 示例应用程序执行同样的操作：

west build -b nrf52_bsim samples/bluetooth/peripheral_hr

$ cp build/zephyr/zephyr.exe \
  ${BSIM_OUT_PATH}/bin/bs_nrf52_bsim_samples_bluetooth_peripheral_hr

然后将它们与 BabbleSim 的 2G4 物理层模拟一起运行：

cd ${BSIM_OUT_PATH}/bin/
./bs_nrf52_bsim_samples_bluetooth_peripheral_hr -s=trial_sim -d=0 &
./bs_nrf52_bsim_samples_bluetooth_central_hr -s=trial_sim -d=1 &
./bs_2G4_phy_v1 -s=trial_sim -D=2 -sim_length=10e6 &

其中，-s 命令行选项提供一个唯一标识此次模拟的字符串；-D 选项告诉 Phy 此次模拟中将运行多少个设备；-d 选项告诉每个设备它在模拟中的设备编号；-sim_length 选项以微秒为单位指定模拟时长。BabbleSim 设备和 Phy 支持许多命令行开关，使用 -help 运行它们可获取更多信息。

有关如何运行 BabbleSim 模拟的更多信息，请参阅 这个 BabbleSim 示例。

运行使用控制台的应用程序

有些应用程序需要使用控制台与用户交互。这些应用程序通常会启用 CONFIG_CONSOLE_SUBSYS 和 CONFIG_CONSOLE_GETCHAR。BabbleSim 开发板默认禁用 UART 控制台，要启用它，只需添加代码片段 UART 控制台代码片段（uart-console）。

west build -S serial-console [...]

要查看输出并与应用程序交互，用户需要将终端连接到该伪终端。

# Automatically attach to the terminal
./build/zephyr/zephyr.exe --uart<uart_id>_pty_attach
# Use a custom command to attach to the terminal, for example 'xterm -e screen %s &'
./build/zephyr/zephyr.exe --uart<uart_id>_attach_cmd=<cmd>
# Use a custom way to connect to the pseudoterminal
./build/zephyr/zephyr.exe --uart<uart_id>_pty --uart_pty_wait
minicom -D /dev/pts/<pts_id>

命令行选项 --uart_list 会打印 uart_id 与 UART 外设之间的映射。覆盖文件描述了哪个 UART 外设被用作控制台输出。

有关连接到 UART 输出的更多详细信息，请参阅可执行文件 -help 选项的输出。

C 库的选择

这些 nRF bsim 开发板以 native simulator 为核心，因此可以选择使用哪个 C 库来构建嵌入式代码。更多信息请查看 原生模拟器的 C 库选择一节。

调试、覆盖率和地址消毒器

与 native_sim 一样，生成的可执行文件是 Linux 原生应用程序。因此可以使用与其他原生应用程序相同的工具（例如 gdb 或 valgrind）对其进行调试或插桩。

该开发板继承了 POSIX 架构的代码覆盖率分析手段。同样，也可以 像在 native_sim 中一样使用地址消毒器和未定义行为消毒器。

注意，即使 BabbleSim 的一个或多个组件在调试器中运行或被插桩，BabbleSim 仍能正常运行。例如，在断点处暂停一个设备会暂停整个模拟。

BabbleSim 在设计上是完全确定性的，结果不受主机计算速度的影响。所有随机性都由随机种子控制，随机种子可以通过命令行选项提供。

关于 BabbleSim 中的时间

注意，BabbleSim 中的时间是模拟的，与实际时间解耦。通常，模拟时间的流逝比实际时间快几个数量级，仅受工作站算力的限制。如果出于某种原因希望将模拟速度限制为实时或其某个比例，可以将 handbrake device 连接到 BabbleSim Phy。
