NRF54L15 模拟开发板（BabbleSim）

  • 概述

  • 构建和使用本开发板

  • TrustZone、TF-M 及其他安全注意事项

概述

为了能够模拟 nRF54L15 SOC，提供了一个 Zephyr 目标开发板：nrf54l15bsim/nrf54l15/cpuapp。

这里使用 BabbleSim 模拟射频活动，并使用 POSIX 架构 和 native simulator 在开发系统上原生运行应用程序。这样可以获得原生代码的执行性能，并能方便地使用原生工具调试，但也继承了 它的局限性。

与 nrf54l15dk 目标一样，nrf54l15bsim/nrf54l15/cpuapp 构建目标为模拟的 nRF54L15 SOC 的应用核提供支持。

备注

与真实的 nRF54L15 设备不同，nrf54l15bsim 目标的 RAM 不受限制，代码也不占用其 RRAM。因此，由于 nRF54L15、nRF54L10 和 nRF54L05 SOC 仅在可用 RAM 和 RRAM 的容量上有所不同，它们都可以使用 nrf54l15bsim 进行模拟。

备注

该仿真目标 尚不 支持以 cpuflpr 核为目标。

该开发板包含部分 nRF54L15 SOC 外设的模型：

  • AAR（加速地址解析器）

  • CCM（AES CCM 模式加密）

  • CLOCK（时钟控制）

  • CRACEN（加密加速引擎）

  • DPPI（分布式可编程外设互连）

  • ECB（AES 电子密码本模式加密）

  • EGU（事件发生器单元）

  • FICR（工厂信息配置寄存器）

  • GPIO & GPIOTE

  • GRTC（全局实时计数器）

  • PPIB（PPI 桥）

  • RADIO

  • RRAMC（阻变 RAM 控制器）

  • TEMP（温度传感器）

  • TIMER

  • UARTE（带 Easy DMA 的 UART）

  • UICR（用户信息配置寄存器）

并且这些外设使用与 nrf54l15dk 目标相同的驱动。有关哪些部分被建模以及建模的详细程度，请查看 HW models implementation status。

构建和使用本开发板

可以按照 nrf52_bsim 开发板 中的说明操作，只需在构建时相应地更改开发板/目标即可。

TrustZone、TF-M 及其他安全注意事项

该开发板没有对 ARM 的 TrustZone 建模。这意味着：

  • 不区分安全与非安全执行状态或总线访问。

  • 原则上，所有软件都可以访问全部 RAM、Flash 和外设。拥有自己互连主端口的外设原则上可以访问任何其他外设或 RAM 区域。

  • 没有 nrf54l15bsim/nrf54l15/cpuapp/ns 开发板/构建目标，也无法混合使用安全镜像和非安全镜像。

  • 目前没有 SPU 的模型，因此无法将 RRAM、RAM 区域或外设标记为仅限安全访问或非安全访问。

  • 无法使用 TF-M。

加密库方面，可以使用带软件加密后端的 Mbed TLS。
