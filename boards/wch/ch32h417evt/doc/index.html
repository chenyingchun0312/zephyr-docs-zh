概述

WCH [1] CH32H417EVT 是面向 CH32H417 SoC 的评估板。该 SoC 包含两个非对称 RISC-V 内核：

  • QingKe V3F 启动内核，hart 0

  • QingKe V5F 应用内核，hart 1

CH32H417 以 AMP 系统的形式获得支持，使用 Zephyr 硬件模型 v2 的 CPU 集群目标。它不是 SMP 系统，不得启用 CONFIG_SMP。V3F 和 V5F 内核的 Zephyr 镜像分别单独构建。

冷复位时只有 V3F 内核开始执行。V5F 内核不会自行启动，必须由 V3F 固件通过 CH32H417 PFIC 唤醒机制唤醒。推荐的 Zephyr 应用程序目标是 V5F 目标：ch32h417evt/ch32h417/v5f。

硬件

当前的开发板支持将 V5F 内核配置为运行在 480 MHz，HCLK 和 USART 时钟域配置为 120 MHz。经过验证的控制台为 PB4 上的 USART8 TX，复用功能 11，波特率 115200。

V5F 的 Zephyr 镜像链接到 Flash 地址 0x08010000，并使用位于 0x200c0400 的 V5F DTCM RAM 区域。V3F 唤醒镜像链接到 Flash 地址 0x00000000。CH32H417 将主 Flash bank 映射到低端的 0x00000000 窗口，因此位于 0x08010000 的 V5F 镜像与下文 OpenOCD 编程命令所用的偏移 0x10000 是同一块物理 Flash。

V3F 镜像在 soc_early_init_hook() 中唤醒 V5F 镜像，然后进入空闲。在这一初始开发板支持中，V3F 目标不负责管理应用程序外设。

编程与调试

该开发板目前尚未提供一步完成的 west flash 运行器。可启动的配置需要将 V3F 和 V5F 镜像合并，并通过一次 OpenOCD 操作完成编程。

构建

构建 V5F hello_world 应用程序：

$ west build -p always -b ch32h417evt/ch32h417/v5f samples/hello_world

构建 V5F blinky 应用程序：

$ west build -p always -b ch32h417evt/ch32h417/v5f samples/basic/blinky

构建 V3F 唤醒镜像。V3F 目标会在 soc_early_init_hook() 中唤醒 V5F 内核（由 CONFIG_SOC_CH32H417_BOOT_V5F 控制，默认启用），因此使用标准的 minimal 示例即可：

$ west build -p always -b ch32h417evt/ch32h417/v3f samples/basic/minimal

烧录

完整的可启动配置需要将两个镜像都写入 Flash，地址按 OpenOCD 流程编程时使用的低端映射 Flash 窗口计算：

  • V3F 唤醒镜像位于 Flash 偏移 0x00000000

  • V5F 应用程序镜像位于 Flash 偏移 0x00010000（V5F 镜像链接在映射地址 0x08010000，对应同一块物理 Flash）

不要以为执行两次独立的 OpenOCD 编程操作后两个镜像都会保持有效。在当前测试过的 WCH OpenOCD 流程中，编程一个镜像可能会擦除另一个镜像。可靠的方法是将生成的 V3F 二进制文件填充到 0x10000，再追加生成的 V5F 二进制文件，然后一次性编程合并后的二进制文件。

例如，在 build-v3f 中构建 V3F 唤醒镜像、在 build-v5f 中构建 V5F 应用程序之后：

$ python3 - <<'PY'
from pathlib import Path

waker = Path('build-v3f/zephyr/zephyr.bin').read_bytes()
app = Path('build-v5f/zephyr/zephyr.bin').read_bytes()
merged = bytearray([0xff]) * 0x10000
merged[:len(waker)] = waker
Path('ch32h417_dual.bin').write_bytes(merged + app)
PY
$ openocd -f boards/wch/ch32h417evt/support/openocd.cfg -c init -c halt -c "program ch32h417_dual.bin 0x00000000 verify" -c reset -c shutdown

编程时请启用校验。某些 WCH OpenOCD 版本可能会在校验成功后、恢复 Flash 算法工作区时异常终止；如果日志显示校验已成功完成，说明镜像已经写入。

运行

在 V5F 控制台端口上以 115200 波特率打开串口终端，然后复位开发板：

$ screen /dev/ttyACM0 115200

V5F 目标上的 hello_world 示例应输出：

Hello World! ch32h417evt/ch32h417/v5f

V5F 目标上的 blinky 示例应按示例的正常时序翻转 PB1。

调试

可以使用兼容 WCH-LinkE 的 OpenOCD 配置调试该开发板。调试 V5F 目标时请注意，冷复位后 V5F 不会立即运行，必须先运行 V3F 唤醒镜像，在 0x08010000 处唤醒 V5F。
