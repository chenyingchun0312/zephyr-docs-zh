mimx8mm6

Browse board sources

概述

Verdin iMX8M Mini 是一款系统模块，基于 NXP® i.MX 8M Mini 系列嵌入式片上系统（SoC）。i.MX 8M Mini 系列包括 i.MX 8M Mini Quad、i.MX 8M Mini QuadLite、i.MX 8M Mini Dual、i.MX 8M Mini DualLite、i.MX 8M Mini Solo 和 i.MX 8M Mini SoloLite。顶级型号 i.MX 8M Mini Quad 以四个 Cortex-A53 内核作为主处理器集群。这些内核完整支持 64 位 Armv8-A，同时与 32 位 Armv7-A 软件保持无缝向后兼容。商业级产品的主内核运行频率最高 1.8 GHz，工业级温度范围产品最高 1.6 GHz。

除主 CPU 复合体外，i.MX 8M Mini 还带有一个最高 400 MHz 的 Cortex-M4F 处理器。该处理器独立于主复合体，拥有自己的专用接口，同时仍可访问常规接口。借助这种异构多核系统，可以在 M4 内核上运行额外的实时操作系统，处理对时间和安全要求严格的任务。

连接与 IO

UART:

Zephyr 默认配置为使用 UART4，在大多数 Toradex 载板上，它连接到 FTDI USB 转换器。

在带有 WiFi/BT 芯片的模组中，该 UART 也连接到 WiFi/BT 芯片。因此，如果使用 UART4，WiFI/BT 将无法正常工作。

如果需要使用 WiFi/BT，则 Zephyr 应使用另一个 UART（例如 UART2）。可以修改 boards/toradex/verdin_imx8mm/verdin_imx8mm_mimx8mm6_m4.dts 文件中的 zephyr,console 和 zephyr,shell-uart 来更换 UART。

模块本身没有 LED，这取决于与模块配套使用的载板。设备树配置为使用 GPIO3_IO1，它可以连接到 Verdin Development Board 的 LED；如有需要，也可以在 boards/toradex/verdin_imx8mm/verdin_imx8mm_mimx8mm6_m4.dts 中修改。

系统时钟

i.MX8MM 没有供 M4 使用的 QSPI Flash，需要由 A53 内核启动 M4。A53 内核负责将 M4 二进制应用程序加载到 RAM 中，使 M4 进入复位状态，设置 M4 的程序计数器和栈指针，然后使 M4 退出复位。A53 可以在引导加载程序阶段执行这些步骤，也可以在 Linux 系统启动后通过 RemoteProc 执行。

编译时需要选择使用哪块 RAM。该配置在文件 boards/toradex/verdin_imx8mm/verdin_imx8mm_mimx8mm6_m4.dts 中通过 "zephyr,flash"（当 CONFIG_XIP=y 时）和 "zephyr,sram" 属性完成。可用的配置有：

"zephyr,flash"
- &tcml_code
- &ocram_code
- &ocram_s_code

"zephyr,sram"
- &tcmu_sys
- &ocram_sys
- &ocram_s_sys

通过 U-Boot 启动 Cortex-M4

将编译好的 zephyr.bin 复制到 eMMC（可以是 FAT 或 EXT4 分区），然后在 A53 上使用 u-boot 将 Zephyr 加载到 M4 并运行。例如，可以通过 U 盘复制，或通过以太网使用 scp 命令传输。上电并停在 u-boot 提示符处。

将 M4 二进制文件加载到所需的存储器中，并使用以下命令开始执行：

fatload mmc 0:1 ${loadaddr} zephyr.bin
cp.b ${loadaddr} 0x7e0000 <size_of_binary_in_bytes>
bootaux 0x7e0000

如果二进制文件位于 ext4 分区上：

ext4load mmc 0:2 ${loadaddr} /path/to/zephyr.bin
cp.b ${loadaddr} 0x7e0000 <size_of_binary_in_bytes>
bootaux 0x7e0000

如果使用的是 TorizonCore 操作系统，则应使用分区 1：

ext4load mmc 0:1 ${loadaddr} /path/to/zephyr.bin
cp.b ${loadaddr} 0x7e0000 <size_of_binary_in_bytes>
bootaux 0x7e0000

通过 RemoteProc 启动 Cortex-M4

将 zepyhr.elf 复制到目标设备的 /lib/firmware。

备注

要使用 remoteproc，需要在 /boot/overlays.txt 中该行的末尾添加 imx8mm-verdin_hmp_overlay.dtbo，然后重启目标设备。如果使用的是 TorizonCore，该文件位于 /boot/ostree/torizon-<hash>/dtb/overlays.txt。

使用以下命令加载并启动固件：

verdin-imx8mm:~# echo zepyhr.elf > /sys/class/remoteproc/remoteproc0/firmware
verdin-imx8mm:~# echo start > /sys/class/remoteproc/remoteproc0/state
[   94.714498] remoteproc remoteproc0: powering up imx-rproc
[   94.720481] remoteproc remoteproc0: Booting fw image zephyr.elf, size 473172
[   94.727713] remoteproc remoteproc0: No resource table in elf
[   94.733615] remoteproc remoteproc0: remote processor imx-rproc is now up

M4 核现已启动并运行。可以在 UART4 上看到 Zephyr 的输出。

调试

可以将外部 JLink JTAG 调试器连接到 J902 调试连接器和 PC 来调试 MIMX8MM EVK 开发板，然后照常调试应用程序。

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b verdin_imx8mm/mimx8mm6/m4 samples/hello_world
west debug

打开串口终端，在调试器中单步执行应用程序，终端中应显示以下信息：

*** Booting Zephyr OS build zephyr-v3.4.0-1251-g43c549305bdb ***
Hello World! verdin_imx8mm_m4
