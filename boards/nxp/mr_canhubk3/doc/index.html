MR-CANHUBK3

Board Overview

Name:
mr_canhubk3
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm

SoC:

s32k344

Browse board sources

概述

NXP MR-CANHUBK3 [8] 是一款面向移动机器人应用的评估板，例如自主移动机器人（AMR）和自动导引车（AGV）。它采用基于 Arm Cortex-M7 内核（锁步）的 NXP S32K344 [9] 通用汽车微控制器。

硬件

  • NXP S32K344

    • Arm Cortex-M7（锁步），最高 160 MHz

    • 4 MB 程序 Flash，带 ECC

    • 320 KB RAM，带 ECC

    • 100 Mbps 以太网、CAN FD、FlexIO、QSPI

    • 12 位 1 Msps ADC，16 位 eMIOS 定时器

  • NXP FS26 Safety System Basis Chip [10]

  • 接口

    • 控制台 UART

    • 6x CAN FD

    • 100Base-T1 以太网

    • 用于 I2C、SPI、GPIO、PWM 等的 JST-GH 连接器和 I/O 排针

有关硬件和设计资源的更多信息，请访问 NXP MR-CANHUBK3 [8] 网站。

连接与 IO

每个 GPIO 端口分为两个 bank：低 bank（引脚 0 到 15）和高 bank（引脚 16 到 31）。例如，PTA2 是 gpioa_l（低 bank）的引脚 2，PTA20 是 gpioa_h（高 bank）的引脚 4。

GPIO 控制器可以将外部输入焊盘中断路由到 SIUL2 EIRQ 或 WKPU 中断控制器，具体取决于 SoC 的支持情况。默认情况下，GPIO 中断路由到 SIUL2 EIRQ 中断控制器，除非按照 dts/bindings/gpio/nxp,siul2-gpio.yaml 中的说明显式配置为路由到 WKPU 中断控制器。

要了解哪些 GPIO 与各个中断控制器兼容，请参阅器件参考手册。

备注

需要特别指出，当前的开发板配置不支持唤醒事件和电源管理功能。WKPU 仅用作中断控制器。

ADC 通过 ADC SAR 控制器提供，共 3 个实例。ADC 通道分为 3 组（精密、标准和外部）。

备注

同一实例的所有通道在同一时间只能运行在 1 个组通道上。

FS26 SBC 看门狗

正常工作时，开发板上电后有一个 256 ms 的窗口，必须在此窗口内用正确的令牌刷新来喂 FS26 看门狗，否则看门狗将向 MCU 发出复位信号。该开发板配置启用了处理这一初始化过程的 FS26 看门狗驱动。

备注

也可以按照以下步骤以调试模式（看门狗禁用）启动 FS26：

  1. 关闭开发板电源。

  2. 拔下默认连接的跳线 JP1（引脚 1-2 断开）。

  3. 给开发板上电。

  4. 重新连接跳线 JP1（引脚 1-2 短接）。

外部 Flash

板载 MX25L6433F 64M 位多 I/O 串行 NOR Flash 存储器连接到 QSPI 控制器端口 A1。该开发板配置将其选为默认的 Flash 控制器。

以太网

该开发板有一个以太网媒体访问控制器（EMAC）实例，与 NXP TJA1103 [11] 100Base-T1 以太网 PHY 连接。目前该 PHY 的驱动功能有限，只能将 PHY 默认的引脚配置（RMII、主模式、启用自主模式、启用极性校正）覆盖为从模式。

100Base-T1 信号引出到连接器 P9，可以使用 RDDRONE-T1ADAPT [12] 等以太网媒体转换器转换为 100Base-T。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

mr_canhubk3 开发板的应用程序可以按照 构建应用程序 中所述的常规方式构建。

该开发板配置支持使用 Lauterbach TRACE32 [13]、SEGGER J-Link [14] 和 pyOCD [15] West 运行器进行烧录和调试。请按照 Lauterbach TRACE32 调试主机工具、J-Link 调试主机工具 和 pyOCD 调试主机工具 中的步骤设置所需的主机工具。默认运行器是 J-Link。

如果使用 TRACE32，请确保安装的版本 >= 2024.09。

烧录

运行 west flash 命令，使用 SEGGER J-Link 烧录应用程序。也可以运行 west flash -r trace32 使用 Lauterbach TRACE32，或运行 west flash -r pyocd` 使用 pyOCD。

Lauterbach TRACE32 运行器（runner）支持通过命令行传入以下附加选项：

west flash -r trace32 --startup-args elfFile=<elf_path> loadTo=<flash/sram>
   eraseFlash=<yes/no> verifyFlash=<yes/no>

其中：

  • <elf_path> 是输出目录中 Zephyr 应用程序 ELF 文件的路径

  • loadTo=flash 将应用程序加载到 SoC 内部程序 Flash（必须设置 CONFIG_XIP），loadTo=sram 将应用程序加载到 SRAM。默认为 flash。

  • eraseFlash=yes 在将应用程序下载到 Flash 或 SRAM 之前擦除 SoC 内部 Flash 的全部内容。该过程需要一定时间。默认为 no。

  • verifyFlash=yes 在编程后校验 SoC 内部 Flash 的内容（与 loadTo=flash 一起使用）。默认为 no。

例如，擦除并校验 Flash 内容：

west flash -r trace32 --startup-args elfFile=build/zephyr/zephyr.elf loadTo=flash eraseFlash=yes verifyFlash=yes

MCUboot

该开发板支持使用 MCUboot 链式加载应用程序。

构建与烧录

要同时构建 MCUboot 和 flash_shell 示例应用程序，并生成适合烧录的 HEX 文件，请运行：

west build -p -b mr_canhubk3/s32k344/mcuboot samples/drivers/flash_shell --sysbuild
west flash

生成的产物如下：

  • MCUboot: build/mcuboot/zephyr/zephyr.hex

  • 应用程序（未签名）：build/flash_shell/zephyr/zephyr.hex

故障排除

如果 MCUboot 打印“Image in the primary slot is not valid”，或在“Jumping to the first image slot”之后停止响应，很可能是应用程序签名时使用了 512 字节的头。请使用 --header-size 0x400 重新签名并重新烧录。

不要为由 MCUboot 链式加载的应用程序添加 IVT；IVT 只会为独立/XIP 镜像或 MCUboot 本身生成。

调试

运行 west debug 命令，使用 SEGGER J-Link 启动 GDB 会话。也可以运行 west debug -r trace32 或 west debug -r pyocd，分别启动 Lauterbach TRACE32 或 pyOCD 软件调试接口。
