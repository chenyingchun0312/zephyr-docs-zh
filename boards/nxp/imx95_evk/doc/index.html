i.MX95 EVK

Board Overview

Name:
imx95_evk
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm, arm64

SoC:

mimx9596

Browse board sources

概述

i.MX95 EVK（IMX95LPD5EVK-19）开发板是一个旨在展示 i.MX 95 汽车应用处理器最常用功能的平台。它是一款入门级开发板，可帮助开发者在为更具体的设计投入大量资源之前熟悉该处理器。开发板上的 i.MX95 器件采用紧凑的 19 x 19 mm 封装。

硬件

  • i.MX 95 汽车应用处理器

    • 该处理器集成最多六个 Arm Cortex-A55 核，并通过内置的 Arm Cortex-M33 和 -M7 核支持功能安全

  • DRAM 存储器：128-Gbit LPDDR5 DRAM

  • eMMC: 64 GB Micron eMMC

  • SPI NOR Flash 存储器：1 Gbit 八线（octal）Flash 存储器

  • USB 接口：两个 USB 端口，Type-A 和 Type-C

  • 音频编解码器接口

    • 一个音频编解码器 WM8962BECSN/R，带一条 TX 和 RX 通道

    • 一个 3.5 mm 四极 CTIA 标准音频插孔

    • 一个用于连接扬声器的 4 针连接器

  • 以太网接口

    • ENET2 控制器

      • 连接到一个 60 针以太网连接器

      • 支持可配置为 100 Mbit/s 或 1000 Mbit/s 工作的以太网 PHY 子卡

    • ENET1 控制器

      • 支持 100 Mbit/s 或 1000 Mbit/s RGMII 以太网，一个 RJ45 连接器连接外部 PHY RTL8211

    • 10 Gbit 以太网控制器

      • 支持 XFI 和 USXGMII 接口，带一个连接外部 PHY Marvell AQR113C 的 10 Gbit RJ45 ICM

  • M.2 接口：一个基于 NXP AW693 芯片的 Wi-Fi/蓝牙 Murata Type-2EL 模组，支持 2x2 Wi-Fi 6 和蓝牙 5.2

  • MIPI CSI 接口：以 x4 通道配置连接到一个 36 针 miniSAS 连接器

  • MIPI CSIDSI 接口：以 4 通道配置连接到一个 36 针 miniSAS 连接器

  • LVDS 接口：两个 mini-SAS 连接器，均为 4 通道配置

  • CAN 接口：两个用于外部连接的 4 针 CAN 排针

  • SD 卡接口：一个 4 位 SD3.0 microSD 卡槽

  • I2C 接口：I2C1 到 I2C7 控制器

  • FT4232H I2C 接口：PCT2075 温度传感器和电流监测器件

  • DMIC 接口：两个提供单比特 PDM 输出的数字麦克风（DMIC）

  • ADC 接口：两个 4 通道 ADC 排针

  • 音频板接口

    • 支持用于连接 Quantum 板的 PCIe x4 插槽

    • 支持用于连接 Audio I/O 板的 PCIe x8 插槽

  • 调试接口

    • 一个 USB 转 UART/MPSSE 器件 FT4232H

    • 一个用于 FT4232H 的 USB 2.0 Type-C 连接器（J31），提供四个串口

支持的功能

imx95_evk 开发板支持下列硬件功能。

说明

The list of supported hardware features was not generated. Run a full documentation build for the required metadata to be available.

系统时钟

该开发板配置为 Cortex-A55 使用 24 MHz 的系统时钟频率。Cortex-A55 内核最高运行在 1.8 GHz。Cortex-M7 内核最高运行在 800MHz，SYSTICK 以相同频率运行。

串口

该开发板配置使用单一串行通信通道：Cortex-A55 使用 CPU 的 UART1，Cortex-M7 使用 UART3。

TPM

M7 在 TPM2 上启用了两个 PWM 通道。可以用示波器观察信号。通道 2 信号路由到电阻 R881，通道 3 信号路由到电阻 R882。

SPI

EVK 开发板需要改装，在 R1217/R1218/R1219/R1220 处焊接 0R 电阻。M7 启用了 J35 上的 SPI1。

以太网

NETC 驱动支持管理物理站接口（PSI）。可以在 M7 DDR 和 A55 平台上启用第一个 ENET1 端口。

对于 A55 内核，NETC 依赖 GIC ITS，因此需要确保分配的堆内存大于 851968 字节。启用 GIC ITS 会将系统堆的最小值提高到该值，因此无需手动设置 CONFIG_HEAP_MEM_POOL_SIZE。

编程与调试（A55）

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

在 A55 内核上烧写和运行 Zephyr 有多种方法：

选项 1：使用 SPSDK 运行器启动 Zephyr

SPSDK 运行器借助 SPSDK 工具（https://spsdk.readthedocs.io）构建一个可引导的 Flash 镜像 flash.bin，其中包含所有必需的固件组件，例如 ELE+V2X 固件、System Manager、TCM OEI、TF-A 镜像等。使用 west flash 命令会将启动镜像 flash.bin 下载到 DDR 存储器、SD 卡或 eMMC Flash。使用 flash.bin 时没有 U-Boot 镜像，因此 TF-A 会直接在第一个 Cortex-A55 内核上启动 Zephyr。

使用 SPSDK 运行器需要获取二进制 blob，可运行以下命令完成：

west blobs fetch hal_nxp

备注

建议在执行 west update 之后运行上述命令。

SPSDK 运行器通过配置项 CONFIG_BOARD_NXP_SPSDK_IMAGE 启用，目前 i.MX95 EVK 开发板默认未启用，因此需使用该配置启用它，例如对于 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b imx95_evk/mimx9596/a55 samples/synchronization -- -DCONFIG_BOARD_NXP_SPSDK_IMAGE=y

如果 CONFIG_BOARD_NXP_SPSDK_IMAGE 可用并已为该开发板变体启用，则会自动构建 flash.bin。可以通过以下命令进行烧写。在此之前，应将开关 SW7[1:4] 配置为 0b1001，以 USB 下载模式启动，并将 USB1 和 DBG 端口连接到 PC。系统会枚举出 4 个串口（115200 8n1），第一个串口用于 M7，第四个用于 M33 System Manager。（烧写工具为 spsdk，已通过 scripts/requirements.txt 安装。在 Linux 主机上，应按照 https://spsdk.readthedocs.io 的安装指南配置 USB 设备权限。）

# load and run without programming. for next flashing, execute 'reset' in the
# fourth serail port
$ west flash -r spsdk

# program to SD card, then set SW7[1:4]=0b1011 to reboot
$ west flash -r spsdk --bootdevice sd

# program to emmc card, then set SW7[1:4]=0b1010 to reboot
$ west flash -r spsdk --bootdevice=emmc

选项 2：使用 U-Boot 命令引导 Zephyr

U-Boot "go" 命令可用于在 A55 core0 上启动 Zephyr，U-Boot "cpu" 命令用于将 Zephyr 加载到其他 A55 从核并启动。目前 Real-Time Edge U-Boot 支持 "cpu" 命令（使用 "uboot_vxxxx.xx-y.y.y" 分支，其中 xxxx.xx 是 U-Boot 版本，y.y.y 是 Real-Time Edge Software 版本，例如 "uboot_v2023.04-2.9.0" 分支是 Real-Time Edge Software v2.9.0 版本所用的 U-Boot v2023.04），预编译镜像和用户指南可在 Real-Time Edge Software 获取。

步骤 1：将 Zephyr 镜像下载到 DDR 内存

首先需要将 Zephyr 二进制镜像下载到 DDR 内存中，可以使用 tftp：

tftp 0xd0000000 zephyr.bin

也可以将 Zephyr 镜像 zephyr.bin 复制到 SD 卡，再将卡插入开发板。例如，如果复制到 SD 卡的 FAT 分区，可使用以下 U-Boot 命令将镜像加载到 DDR 内存中（假设 SD 卡为 dev 1，FAT 分区 ID 为 1，可根据实际情况修改）：

fatload mmc 1:1 0xd0000000 zephyr.bin;

步骤 2：引导 Zephyr

使用此配置运行基本的 Zephyr 应用程序和内核测试，例如 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b imx95_evk/mimx9596/a55 samples/synchronization

这将构建一个包含 synchronization 示例应用程序的镜像（zephyr.bin）。

然后使用以下命令在 core0 上引导 Zephyr：

dcache off; icache flush; go 0xd0000000;

也可以使用 "cpu" 命令从副核引导，例如 Core1：

dcache flush; icache flush; cpu 1 release 0xd0000000

将显示以下控制台输出：

*** Booting Zephyr OS build v3.6.0-4569-g483c01ca11a7 ***
thread_a: Hello World from cpu 0 on imx95_evk!
thread_b: Hello World from cpu 0 on imx95_evk!
thread_a: Hello World from cpu 0 on imx95_evk!
thread_b: Hello World from cpu 0 on imx95_evk!
thread_a: Hello World from cpu 0 on imx95_evk!

选项 3：在 Linux 下使用 Remoteproc 引导 Zephyr

在 A55 核上运行 Linux 时，可以使用 remoteproc 框架加载并启动 Zephyr，详情请参阅 Real-Time Edge 用户指南。预构建镜像和用户指南可在 Real-Time Edge Software 获取。

选项 4：使用 JLink 运行器启动 Zephyr

该开发板支持使用 JLink 运行器烧录和调试 Zephyr。使用 J-Link 调试器将 EVK 开发板的 JTAG 连接器连接到主机。

如果在 Core0 上运行和调试 Zephyr，只需给开发板上电并使其停在 U-Boot 命令行。

然后使用 "west flash -r jlink" 命令从主机加载 zephyr.bin 镜像并启动 Zephyr，或使用 "west debug -r jlink" 调试 Zephyr。

烧录并运行

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b imx95_evk/mimx9596/a55 samples/hello_world
west flash -r jlink

调试

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b imx95_evk/mimx9596/a55 samples/hello_world
west debug -r jlink

备注

如果在 Core0 以外的其他 Cortex-A 内核（例如 Core2）上运行和调试 Zephyr，需要在 U-Boot 命令行下执行以下命令，使指定的 CPU 内核进入死循环状态（U-Boot 需要支持 "cpu" 命令，具体的 U-Boot 版本请参考“选项 2：使用 U-Boot 命令启动 Zephyr”）。

mw.l 0xD0000000 14000000; dcache flush; icache flush; cpu 2 release 0xD0000000

还需要按以下修改更新 jlink 设备，将设备 ID MIMX9556_A55_0 改为指定的 ID，例如 CPU Core2 对应 MIMX9556_A55_2：

diff --git a/boards/nxp/imx95_evk/board.cmake b/boards/nxp/imx95_evk/board.cmake
index daca6ade79f..c58de8c2431 100644
--- a/boards/nxp/imx95_evk/board.cmake
+++ b/boards/nxp/imx95_evk/board.cmake
@@ -21,6 +21,6 @@ if(CONFIG_BOARD_NXP_SPSDK_IMAGE OR (DEFINED ENV{USE_NXP_SPSDK_IMAGE}
endif()

if(CONFIG_SOC_MIMX9596_A55)
-  board_runner_args(jlink "--device=MIMX9556_A55_0" "--no-reset" "--flash-sram")

然后使用 "west flash -r jlink" 命令从主机加载 zephyr.bin 镜像并启动 Zephyr，或使用 "west debug -r jlink" 调试 Zephyr。

编程与调试（M7）

i.MX95 上使用 i.MX System Manager（SM），它是一个运行在 Cortex-M33 处理器上的应用程序。Cortex-M33 是启动内核，运行引导 ROM，由引导 ROM 加载 SM（及其他启动代码），然后跳转到 SM。SM 随后配置硬件的某些方面（例如隔离机制），再启动系统中的其他内核。启动这些内核后，SM 进入服务模式，通过基于 ARM System Control and Management Interface (SCMI) 的客户端 RPC API 提供对时钟、电源、传感器和引脚控制的访问。

要编程 M7，必须制作 i.MX 容器镜像 flash.bin，其中包含所需的多个组件，如 ELE+V2X 固件、System Manager、TCM OEI、Cortex-M7 镜像等。

flash.bin 使用 SPSDK 运行器（runner）构建，需要获取二进制 blob，可通过运行以下命令完成：

west blobs fetch hal_nxp

备注

建议在执行 west update 之后运行上述命令。

构建和编程 flash.bin 有两种方法。

1. If CONFIG_BOARD_NXP_SPSDK_IMAGE is not available for the board variant, the steps making flash.bin and programming should refer to Getting Started with MCUXpresso SDK for IMX95LPD5EVK-19.pdf in i.MX95 MCUX SDK release. Note that for the DDR variant, one should use the Makefile targets containing the ddr keyword. See 4.2 Run an example application, just rename zephyr.bin to m7_image.bin to make flash.bin and program to SD/eMMC.

2. If CONFIG_BOARD_NXP_SPSDK_IMAGE is available and enabled for the board variant, flash.bin will be built automatically. The programming could be through below commands. Before that, switch SW7[1:4] should be configured to 0b1001 for usb download mode to boot, and USB1 and DBG ports should be connected to PC. There are 4 serial ports enumerated (115200 8n1), and we use the first for M7 and the fourth for M33 System Manager. (The flasher is spsdk which already installed via scripts/requirements.txt. On linux host, usb device permission should be configured per Installation Guide of https://spsdk.readthedocs.io)

# load and run without programming. for next flashing, execute 'reset' in the
# fourth serail port
$ west flash

# program to SD card, then set SW7[1:4]=0b1011 to reboot
$ west flash --bootdevice sd

# program to emmc card, then set SW7[1:4]=0b1010 to reboot
$ west flash --bootdevice=emmc

Zephyr 支持两款基于 M7 的 i.MX95 开发板：imx95_evk/mimx9596/m7 和 imx95_evk/mimx9596/m7/ddr。两者的主要区别在于所用的存储器。imx95_evk/mimx9596/m7 使用 TCM（ITCM 用于代码和一般的只读数据，DTCM 用于读写数据），而 imx95_evk/mimx9596/m7/ddr 使用 DDR。

  1. 为基于 TCM 的开发板构建 Hello World 应用程序

# From the root of the zephyr repository
west build -b imx95_evk/mimx9596/m7 samples/hello_world

  1. 为基于 DDR 的开发板构建 Hello World 应用程序

# From the root of the zephyr repository
west build -b imx95_evk/mimx9596/m7/ddr samples/hello_world

制作 flash.bin 并烧写到 SD/eMMC 后，打开串口终端并复位开发板。对于 imx95_evk/mimx9596/m7 开发板，应看到类似以下的输出：

*** Booting Zephyr OS build v3.6.0-4569-g483c01ca11a7 ***
Hello World! imx95_evk/mimx9596/m7

而对于 imx95_evk/mimx9596/m7/ddr 开发板，应得到以下输出：

*** Booting Zephyr OS build v3.6.0-4569-g483c01ca11a7 ***
Hello World! imx95_evk/mimx9596/m7/ddr
