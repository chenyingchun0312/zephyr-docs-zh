MCX-N9XX-EVK

Board Overview

Name:
mcx_n9xx_evk
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm

SoC:

mcxn947

Browse board sources

概述

MCX-N9XX-EVK 是一款功能齐全的评估套件，用于 MCX N94 / N54 MCU 的原型开发。它提供用于访问 MCU I/O 的行业标准排针、集成的开放标准串行接口，以及具备功耗测量能力的板载 MCU-Link 调试器。MCX N 系列是高性能、低功耗的微控制器，配有智能外设和加速器，具备多任务处理能力和高性能效率。

硬件

  • MCX-N947 双核 Arm Cortex-M33 微控制器，运行频率 150 MHz

  • 2MB 双 bank 片上 Flash

  • 512 KB RAM

  • 通过 FlexSPI 连接的外部 Quad SPI Flash

  • 高速 USB（主机/设备），带片上 HS PHY。

  • 全速 USB（主机/设备），带片上 FS PHY。

  • 10 个 LP Flexcomm，每个都支持 SPI、I2C、UART

  • 支持 FD 的 FlexCAN、I3C、SAI

  • 1 个支持 QoS 的以太网

  • 板载 MCU-Link 调试器，支持 CMSIS-DAP

  • Arduino 排针、FlexIO/LCD 排针、mikroBUS、M.2

可用目标

默认配置文件 boards/nxp/mcx_nx4x_evk/mcx_n9xx_evk_mcxn947_cpu0_defconfig 只启用第一个内核。CPU0 是唯一可以独立运行的目标。

CPU1 必须由 CPU0 启用后才能工作。

要启用 CPU1，请创建 System Build 应用程序项目，并通过配置项 CONFIG_SECOND_CORE_MCUX 启用第二个核。

请参考一些已启用的示例：

系统时钟

MCX-N947 SoC 配置为使用运行在 150MHz 的 PLL0 作为系统时钟源。

串口

MCX-N9XX-EVK SoC 有 10 个用于串行通信的 FLEXCOMM 接口。Flexcomm 4 配置为 UART，用作控制台。

以太网

要通过以太网接口使用网络示例，请将跳线 JP13 改接到引脚 2-3。

编程与调试

按常规方式构建并烧录应用程序（详见 构建应用程序 和 运行应用程序）。

配置调试探针

调试探针既用于烧录也用于调试开发板。本开发板默认配置为使用 MCU-Link CMSIS-DAP 板载调试探针。

使用 LinkServer

LinkServer 是该开发板的默认运行器（runner），支持出厂默认的 MCU-Link 固件。按照 MCU-Link CMSIS-DAP 板载调试探针 中的说明重新烧写默认的 MCU-Link 固件。只有在板载调试电路的默认固件被更改过时才需要这样做。要让开发板进入 ISP mode 以烧写固件，请短接跳线 JP24。

使用 J-Link

有两种方式。第一种是按照 MCU-Link JLink 板载调试探针 中的说明，将板载调试电路更新为 Segger J-Link 固件。为了烧写固件，需要短接跳线 JP24，使开发板进入 ISP mode。第二种是将 J-Link 外部调试探针 连接到开发板的 20 针 SWD 连接器（J11）。此外，必须短接跳线 JP6。两种方式都需要在 west 中使用 -r jlink 选项来使用 jlink 运行器。

west flash -r jlink

配置控制台

用 USB 线将 PC 连接到 J5，并使用任意串口终端（minicom、putty 等），设置如下：

  • 波特率：115200

  • 数据位：8 位

  • 校验位：无

  • 停止位：1

以下以 Hello World 应用程序为例。

调试双核镜像

对于双核构建，应先让从核进入循环，然后再连接调试器。更多信息请参考（AN13264，第 4.2.3 节）。该参考资料针对 RT1170，但类似的方法也适用于此处。

使用 QSPI 开发板变体

MCX-N9XX-EVK 开发板带有一个外部 QSPI Flash。MCXN947 可以通过 FlexSPI 接口直接从该 Flash 启动并就地执行（XIP）。QSPI 变体支持构建在 QSPI 中执行的应用程序和代码。

为外部 QSPI 编程 ROM 引导加载程序

默认情况下，MCXN947 ROM 中的引导加载程序从内部 Flash 启动。但可以对 MCU 进行编程，使其从 FlexSPI 接口上的外部存储器启动。在使用 QSPI 开发板变体之前，应按以下步骤将开发板编程为从 QSPI 启动。

要配置 ROM 引导加载程序，必须对受保护 Flash 区域（PFR）进行编程。PFR 的编程使用 NXP 的 ROM 引导加载程序工具完成。NXP 的 MCUXpresso SDK example hello_world_qspi_xip readme 中提供了一些简单步骤。用 blhost 烧写的二进制文件位于 bootfromflexspi.bin。更详细的说明请参阅文章 Running code from external memory with MCX N94x。以下步骤用于烧写 MCX-N9XX-EVK 开发板。注意，这些步骤通过 UART 串口与 ROM 引导加载程序通信，也可以改用 USB。

  1. 断开 UART 串口上连接的所有终端，因为以下步骤需要使用该串口。

  2. 用 micro USB 线将主机连接到开发板左上角的 J5。这样会为开发板供电、连接调试探针，并连接 blhost 命令所用的 UART 串口。

  3. 让 MCU 进入 ISP 模式。在 MCX-N9XX-EVK 开发板上，可以使用 ISP 按键实现。按住开发板右下角的 ISP 按键 SW3，然后按下并松开开发板左下角的复位按键 SW1。此时 MCU 已启动进入 ISP 模式，松开 ISP 按键。

  4. 运行 blhost 命令：

此步骤假设 MCU 串口连接到 /dev/ttyACM0

blhost -t 2000 -p /dev/ttyACM0,115200 -j -- write-memory 0x01004000 bootfromflexspi.bin

将 COMxx 改为 MCU 串口所连接的 COM 端口号。

blhost -t 2000 -p COMxx -j -- write-memory 0x01004000 bootfromflexspi.bin

编程成功时的输出类似如下：

$ blhost -t 2000 -p /dev/ttyACM0,115200 -j -- write-memory 0x01004000 bootfromflexspi.bin
{
   "command": "write-memory",
   "response": [
      256
   ],
   "status": {
      "description": "0 (0x0) Success.",
      "value": 0
   }
}

  1. 按 SW1 复位开发板以退出 ISP 模式。此时 MCU 已可从 QSPI 启动。

也可以将 ROM 引导加载程序重新配置为从内部 Flash 启动。重复上述步骤编程 PFR，并编程文件 bootfromflash.bin。

使用 QSPI 变体构建、烧录和调试

将 PFR 编程为从 QSPI 启动后，即可对 QSPI 开发板变体使用常规的 Zephyr 构建、烧录和调试步骤。以下是一些示例。

以下以 Hello World 应用程序为例：

west build -b mcx_n9xx_evk//cpu0/qspi zephyr/samples/hello_world
west flash

QSPI 变体也可以使用 MCUboot。默认情况下，MCUboot 引导加载程序与应用程序镜像一起放在 QSPI Flash 的 boot-partition 中。ROM 引导加载程序先启动，加载 QSPI 中的 MCUboot，再由 MCUboot 加载应用程序。以下示例使用 Sysbuild 构建并加载带 MCUboot 的 Blinky 示例：

west build -b mcx_n9xx_evk//cpu0/qspi --sysbuild zephyr/samples/basic/blinky -- -DSB_CONFIG_BOOTLOADER_MCUBOOT=y
west flash

打开串口终端，按 SW1 按键复位开发板，控制台将打印：

*** Booting MCUboot vX.Y.Z ***
*** Using Zephyr OS build vX.Y.Z ***
I: Starting bootloader
I: Image index: 0, Swap type: none
I: Bootloader chainload address offset: 0x14000
I: Image version: v0.0.0
I: Jumping to the first image slot
*** Booting Zephyr OS build vX.Y.Z ***
LED state: OFF
LED state: ON

故障排除

使用 Segger SystemView 和 RTT

注意，在此 SoC 上使用 SEGGER SystemView 或 RTT 时，必须在 SystemView 或 RTT Viewer 中手动设置 RTT 控制块地址。提供给工具的地址应为 _SEGGER_RTT 符号所在的位置，可以通过调试器或查看链接器输出的 zephyr.map 文件找到。

之所以必须手动提供 RTT 控制块地址，是因为此 SoC 支持 ECC RAM。如果启用了 ECC，且 SEGGER 工具在 ECC RAM 空间中搜索控制块时所搜索的 RAM 段尚未初始化为已知值，就会发生故障。
