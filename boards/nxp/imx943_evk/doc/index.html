i.MX943 EVK

Board Overview

Name:
imx943_evk
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm, arm64

SoC:

mimx94398

Browse board sources

概述

IMX943LP5EVK-19 开发板是基于 NXP i.MX 943 处理器的设计和评估平台。i.MX 943 处理器集成了最多四个 Arm Cortex-A55 内核，以及用于功能安全的两个 Arm Cortex-M33 内核和两个 Arm Cortex-M7 内核。凭借 PLC、I/O 控制器、V2X 加速器、ML 加速、能源管理和高级安全功能，i.MX 943 处理器为工业、物联网和汽车设备提供了优化的性能和能效。开发板上的 i.MX943 器件采用紧凑的 19 x 19 mm/15 x 15 mm 封装。

硬件

  • i.MX 943 汽车应用处理器

    • 该处理器集成最多四个 Arm Cortex-A55 核，并通过内置的 Arm Cortex-M33 和 -M7 核支持功能安全

  • DRAM 存储器：8-Gbit LPDDR5 DRAM

  • XSPI 接口：64 MB octal SPI NOR Flash 存储器

  • eMMC：32 GB eMMC NAND Flash 存储器

  • uSDHC 接口：一个 SD 卡槽

  • USB 接口：两个 USB Type-C 端口

  • 以太网接口：七个以太网端口

  • PCIe 接口：一个 M.2 插槽和一个 PCIe x4 插槽。

  • FlexCAN 接口：四个 CAN 控制器，配有四个 CAN 连接器。

  • LPUART 接口

  • LPSPI 接口

  • LPI2C 接口

  • SAI 接口

  • MQS 接口

  • MICFIL 接口

  • LVDS 接口

  • ADC 接口

  • SINC 接口

  • 调试接口

    • 一个 USB 转 UART/MPSSE 器件 FT4232H

    • 一个用于 FT4232H 的 USB 3.2 Type-C 连接器（J15），提供四路串口

    • JTAG 排针 J16

支持的功能

imx943_evk 开发板支持下列硬件功能。

系统时钟

该开发板配置为 Cortex-A55 使用 24 MHz 的系统时钟频率。Cortex-A55 内核最高运行在 1.7 GHz。Cortex-M33 内核最高运行在 333MHz，SYSTICK 以相同频率运行。

串口

该开发板配置使用单个串行通信通道：Cortex-A55 使用 CPU 的 UART1，Cortex-M33 使用 UART8。

以太网

NETC 驱动支持管理物理站接口（PSI）和 TSN 交换机。可以通过 west 构建选项 -DEXTRA_DTC_OVERLAY_FILE=enetc.overlay 为 M33 启用 ENET0、ENETC1、ENETC2 端口。

对于 A55 内核，ENET0、ENETC1、ENETC2 端口默认启用，因此不需要覆盖文件；但 NETC 依赖 GIC ITS，因此需要确保分配的堆内存大于 851968 字节。启用 GIC ITS 会将系统堆的最小值提高到该值，因此无需手动设置 CONFIG_HEAP_MEM_POOL_SIZE。

在 EVK 开发板上，交换机 port0 和 port2 同时连接到 SGMII 端口（SGMII-swp0 和 SGMII-swp1）和 100M 端口（swp0 和 swp1）。目前只启用了 100M 端口（swp0 和 swp1），因此可以连接到 100M 端口来验证两个交换机端口。

可以在 M33 内核或 A55 内核上通过 DSA (Distributed Switch Architecture) 验证这两个交换机端口，例如对于 A55 内核：

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/a55 samples/net/ethernet/dsa
west flash

或者对于 M33 内核：

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/m33/ddr samples/net/ethernet/dsa

编程与调试（A55）

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

在 A55 核上编程和调试 Zephyr 有多种方法：

选项 1：使用 JLink 运行器引导 Zephyr

依赖项

需要在 U-Boot 中禁用所有看门狗，否则 Zephyr 从同一个 A55 内核启动后，看门狗会复位开发板。

设置

本开发板的默认运行器为 JLink。使用 J-Link 调试器将 EVK 开发板的 JTAG 连接器连接到主机，给开发板上电，并让开发板停在 U-Boot 命令行。

然后使用 "west flash" 或 "west debug" 命令从主机加载 zephyr.bin 镜像，并在 A55 core0 上启动 Zephyr 应用程序。

烧录并运行

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/a55 samples/hello_world
west flash

然后可以在 UART1 控制台上看到以下日志：

*** Booting Zephyr OS build v4.1.0-3650-gdb71736adb68 ***
Hello World! imx943_evk/mimx94398/a55

调试

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/a55 samples/hello_world
west debug

选项 2：使用 U-Boot 命令引导 Zephyr

可以使用 U-Boot "go" 命令在 A55 Core0 上启动 Zephyr。

依赖项

需要在 U-Boot 中禁用所有看门狗，否则 Zephyr 从同一个 A55 内核启动后，看门狗会复位开发板。

第 1 步：构建 Zephyr 应用程序

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/a55 samples/hello_world

第 2 步：将 Zephyr 镜像下载到 DDR 存储器

首先需要将 Zephyr 二进制镜像下载到 DDR 内存中，可以使用 tftp：

tftp 0xd0000000 zephyr.bin

也可以将 Zephyr 镜像 zephyr.bin 复制到 SD 卡，再将卡插入开发板。例如，如果复制到 SD 卡的 FAT 分区，可使用以下 U-Boot 命令将镜像加载到 DDR 内存中（假设 SD 卡为 dev 1，FAT 分区 ID 为 1，可根据实际情况修改）：

fatload mmc 1:1 0xd0000000 zephyr.bin;

第 3 步：启动 Zephyr

使用以下命令在 core0 上启动 Zephyr：

dcache flush; icache flush; go 0xd0000000;

然后可以在 UART1 控制台上看到以下日志：

*** Booting Zephyr OS build v4.1.0-3650-gdb71736adb68 ***
Hello World! imx943_evk/mimx94398/a55

Cortex-A55 SMP 模式

默认的 SMP 变体在全部四个 Cortex-A 内核上运行。可以通过在 dts 中禁用部分 A55 内核节点，并将 CONFIG_MP_MAX_NUM_CPUS 改为 dts 中启用的 A55 内核数量来更改。

构建 SMP 内核，例如使用 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/a55/smp samples/synchronization

无论使用哪种启动方式，都需要确保 SMP Zephyr 从 "cpus" dts 节点中列出的第一个 CPU 内核启动。默认 SMP 变体 dts 中的第一个 A55 内核是 Core0，可以通过 U-Boot "go" 命令、J-Link 运行器或 SPSDK 运行器启动。

选项 3：使用 SPSDK 运行器引导 Zephyr

SPSDK 运行器借助 SPSDK 工具（https://spsdk.readthedocs.io）构建一个可引导的 Flash 镜像 flash.bin，其中包含所有必需的固件组件，例如 ELE+V2X 固件、System Manager、DDR OEI、TF-A 镜像等。使用 west flash 命令会将启动镜像 flash.bin 下载到 DDR 存储器，或将启动镜像烧写到 SD 卡或 eMMC Flash。使用 flash.bin 时没有 U-Boot 镜像，因此 TF-A 会直接在第一个 Cortex-A55 内核上启动 Zephyr。

使用 SPSDK 运行器需要获取二进制 blob，可运行以下命令完成：

west blobs fetch hal_nxp

备注

建议在执行 west update 之后运行上述命令。

SPSDK 运行器通过配置项 CONFIG_BOARD_NXP_SPSDK_IMAGE 启用，目前 i.MX943 EVK 开发板默认未启用，因此需使用该配置启用它，例如对于 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/a55 samples/synchronization -- -DCONFIG_BOARD_NXP_SPSDK_IMAGE=y

如果 CONFIG_BOARD_NXP_SPSDK_IMAGE 可用并已为该开发板变体启用，则会自动构建 flash.bin。可以通过以下命令进行烧写。在此之前，应将开关 SW4[3:0] 配置为 0b1001，以 USB 下载模式启动，并将 USB1 和 DBG 端口连接到 PC。系统会枚举出 4 个串口（115200 8n1），第三个串口用于 A55 Zephyr，第四个用于 M33 System Manager。（烧写工具为 spsdk，已通过 scripts/requirements.txt 安装。在 Linux 主机上，应按照 https://spsdk.readthedocs.io 的安装指南配置 USB 设备权限。）

# load and run without programming. for next flashing, execute 'reset' in the
# fourth serail port
$ west flash -r spsdk

# program to SD card, then set SW4[3:0]=0b1011 and reboot the board from SD
$ west flash -r spsdk --bootdevice sd

# program to emmc card, then set SW4[3:0]=0b1010 and reboot the board from eMMC
$ west flash -r spsdk --bootdevice=emmc

然后可以在第三个串口的控制台中看到 Zephyr 日志。

注意：默认启动镜像适用于 LPDDR5 EVK 开发板，启用配置项 CONFIG_BOARD_NXP_LPDDR4 可为 LPDDR4 EVK 开发板构建启动镜像。

编程与调试（NETC MIX 中的 M33、M7MIX0 中的 M7_0、M7MIX1 中的 M7_1）

第 1 步：构建 Zephyr 应用程序

以下是构建 Hello World 应用程序的示例。

对于 TCM 目标

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/m33 samples/hello_world

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/m7_0 samples/hello_world

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/m7_1 samples/hello_world

对于 DDR 目标

# From the root of the zephyr repository
west build -b imx943_evk/mimx94398/m33/ddr samples/hello_world

第 2 步：构建可引导固件

要制作烧写到 SD/eMMC 的可引导固件，需要使用 i.MX Linux BSP release 中的 imx-mkimage 工具和其他一些固件文件。

以下是在 Linux 主机上的操作示例。（更多详细信息请参阅 i.MX Linux BSP release 6.12.3_1.0.0）

# download

git clone https://github.com/nxp-imx/imx-mkimage.git -b lf-6.12.3_1.0.0
git clone https://github.com/nxp-imx/imx-sm.git      -b lf-6.12.3-imx943-er1
git clone https://github.com/nxp-imx/imx-oei.git     -b lf-6.12.3-imx943-er1

wget https://www.nxp.com/lgfiles/NMG/MAD/YOCTO/firmware-imx-8.27-5af0ceb.bin
wget https://www.nxp.com/lgfiles/NMG/MAD/YOCTO/firmware-ele-imx-2.0.1-0a66c34.bin

# some firmware files need to be unpacked

chmod 777 firmware-imx-8.27-5af0ceb.bin
chmod 777 firmware-ele-imx-2.0.1-0a66c34.bin
./firmware-imx-8.27-5af0ceb.bin --auto-accept
./firmware-ele-imx-2.0.1-0a66c34.bin --auto-accept

# some firmware files need to be built from source

export TOOLS=$ARMGCC_DIR
export SM_CROSS_COMPILE=${TOOLS}/bin/arm-none-eabi-
export OEI_CROSS_COMPILE=${TOOLS}/bin/arm-none-eabi-

make -C imx-oei board=mx943lp5-19 oei=ddr d=1 all
make -C imx-sm config=mx94alt cfg
make -C imx-sm config=mx94alt all

# make bootable firmware flash.bin

cp firmware-imx-8.27-5af0ceb/firmware/ddr/synopsys/lpddr5*v202409.bin imx-mkimage/iMX94/
cp firmware-ele-imx-2.0.1-0a66c34/mx943a0-ahab-container.img          imx-mkimage/iMX94/
cp imx-sm/build/mx94alt/m33_image.bin                                 imx-mkimage/iMX94/
cp imx-oei/build/mx943lp5-19/ddr/oei-m33-ddr.bin                      imx-mkimage/iMX94/
cp zephyr/build/zephyr/zephyr.bin                                     imx-mkimage/iMX94/m33s_image.bin (m70_image.bin or m71_image.bin)

cd imx-mkimage
make SOC=iMX94 OEI=YES flash_m33s     # for TCM target
make SOC=iMX94 OEI=YES flash_m33s_ddr # for DDR target
or
make SOC=iMX94 OEI=YES flash_m33s_m70_m71  # for TCM target


# Program to SD card

dd if=iMX94/flash.bin of=/dev/sdb bs=1k seek=32 && sync
