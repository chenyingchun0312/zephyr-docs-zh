FRDM-MCXW71

Board Overview

Name:
frdm_mcxw71
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm

SoC:

mcxw716c

Browse board sources

概述

FRDM-MCXW71 是一款紧凑、可扩展的开发板，用于 MCX W71 无线 MCU 的快速原型设计。它便于评估 MCX W71 对低功耗蓝牙、Zigbee、Thread 和 Matter 的多协议无线支持。该开发板包含板载 MCU-Link 调试器、便于访问 MCU I/O 的业界标准排针、加速度计、光传感器和外部 SPI Flash 存储器。

MCX W71x 系列搭载 96 MHz Arm® Cortex®-M33 内核，并配有支持 Matter、Thread、Zigbee 和低功耗蓝牙的多协议射频子系统。独立的射频子系统具有专用内核和存储器，可以减轻主 CPU 的负担，使其专注于主应用程序，并允许通过固件更新支持未来的无线标准。

硬件

  • MCXW71 Arm Cortex-M33 微控制器，运行频率最高 96 MHz

  • 1MB 片上 Flash 存储单元

  • 128 KB TCM RAM

  • 板载 MCU-Link 调试器，支持 CMSIS-DAP

有关 MCXW71 SoC 和 FRDM-MCXW71 开发板的更多信息，请参阅：

  • MCXW71 SoC Website [8]

  • FRDM-MCXW71 Website [9]

获取二进制 blob

要支持蓝牙，frdm_mcxw71 需要获取二进制 blob，可以运行以下命令完成：

west blobs fetch hal_nxp -l "mcxw71"

备注

-l 选项接受一个 Python 正则表达式，用于匹配每个 blob 的路径。传入 "mcxw71" 会将下载限制为该开发板所需的 blob，而不是获取所有 NXP blob。省略该选项（west blobs fetch hal_nxp）则会获取所有 NXP blob。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

按常规方式构建并烧录应用程序（详见 构建应用程序 和 运行应用程序）。

配置调试探针

调试探针既用于烧录也用于调试开发板。本开发板默认配置为使用 MCU-Link CMSIS-DAP 板载调试探针。

使用 LinkServer

Linkserver 是该开发板的默认运行器，支持出厂默认的 MCU-Link 固件。按照 MCU-Link CMSIS-DAP 板载调试探针 中的说明重新烧写默认的 MCU-Link 固件。只有在板载调试电路的默认固件被更改过时才需要这样做。要使开发板进入 DFU mode 以烧写固件，请短接跳线 J5。

使用 J-Link

有两种方案。第一种是按照 MCU-Link JLink 板载调试探针 中的说明，将板载调试电路更新为 Segger J-Link 固件。为了能够烧写固件，需要短接跳线 JP5，使开发板进入 DFU mode。第二种是将 J-Link 外部调试探针 连接到开发板的 10 针 SWD 连接器（J12）。两种方案都需要在 west 中使用 -r jlink 选项来使用 jlink 运行器。

west flash -r jlink

配置控制台

使用 USB 线将 PC 连接到 J10，并在你选用的串口终端（minicom、putty 等）中使用以下设置：

  • 波特率：115200

  • 数据位：8 位

  • 校验位：无

  • 停止位：1

构建应用程序

OpenThread 应用程序

# From the root of the zephyr repository
west build -b frdm_mcxw71 samples/net/sockets/echo_server -- -DEXTRA_CONF_FILE=overlay-ot.conf

# From the root of the zephyr repository
west build -b frdm_mcxw71 samples/net/sockets/echo_client -- -DEXTRA_CONF_FILE=overlay-ot.conf

烧录应用程序

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b frdm_mcxw71/mcxw716c samples/hello_world
west flash

打开串口终端，复位开发板（按下 RESET 按键），终端中应显示以下信息：

*** Booting Zephyr OS build v3.7.0-xxx-xxxx ***
Hello World! frdm_mcxw71/mcxw716c

调试

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b frdm_mcxw71/mcxw716c samples/hello_world
west debug

打开串口终端，在调试器中单步执行应用程序，终端中应显示以下信息：

*** Booting Zephyr OS build v3.7.0-xxx-xxxx ***
Hello World! frdm_mcxw71/mcxw716c

进入 ISP 模式

要让 MCU 以 ISP 模式启动，请按以下步骤操作：

  • 断开 FRDM-MCXW71 开发板的所有电源。

  • 按住开发板上的 SW3 按键，同时将开发板连接到主机的 USB 端口。

  • 松开 SW3 按键。MCXW72 MCU 将以 ISP 模式启动。

  • 如有需要，重新连接外部电源。

低功耗模式下的烧录

运行启用了低功耗模式（CONFIG_PM=y）的应用程序时，通过标准调试探针（MCU-Link 或 J-Link）烧录可能会失败。这是因为 MCU 会进入低功耗状态，此时 SWD 调试接口无法响应。

要烧录运行低功耗镜像的开发板，请进入 ISP 模式（参见 Entering ISP Mode）。

烧录 NBU

BLE 功能需要获取二进制 blob，因此请先按照 Fetch Binary Blobs 一节操作。

需要向开发板写入两个镜像：一个用于主机（CM33），一个用于 NBU（CM3）。

  • 烧录应用程序（CM33）请参阅上文 Application Flashing 一节。

  • 要烧录 NBU，请按以下说明操作：

    • 从 NXP 网站安装 blhost。该工具用于烧录 NBU。

    • 进入 ISP 模式（参见 Entering ISP Mode）。

    • 从开发板的 blobs 文件夹（<zephyr workspace>/modules/hal/nxp/zephyr/blobs/mcxw71/）中选择所需协议对应的 NBU 镜像，例如仅 BLE 镜像或动态 BLE + 802.15.4 镜像，然后烧写：

blhost.exe -p COMxx -- receive-sb-file <nbu-image>

./blhost -p /dev/ttyxx -- receive-sb-file <nbu-image>

将 COMxx/ttyxx 替换为开发板所用的串口，将 <nbu-image> 替换为从 blobs/mcxw71/ 文件夹中选择的文件。

故障排除

使用 Segger SystemView 和 RTT

注意，在此 SoC 上使用 SEGGER SystemView 或 RTT 时，必须在 SystemView 或 RTT Viewer 中手动设置 RTT 控制块地址。提供给工具的地址应为 _SEGGER_RTT 符号所在的位置，可以通过调试器或查看链接器输出的 zephyr.map 文件找到。

之所以必须手动提供 RTT 控制块地址，是因为此 SoC 支持 ECC RAM。如果启用了 ECC，且 SEGGER 工具在 ECC RAM 空间中搜索控制块时所搜索的 RAM 段尚未初始化为已知值，就会发生故障。
