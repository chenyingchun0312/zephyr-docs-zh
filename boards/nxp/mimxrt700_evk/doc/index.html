MIMXRT700-EVK

Board Overview

Name:
mimxrt700_evk
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

xtensa, arm

SoC:

mimxrt798s

Browse board sources

概述

全新的 i.MX RT700 CPU 架构由高性能主计算子系统、辅助的“常开”感知计算子系统和专用协处理器组成。

主计算子系统有一个运行在 325 MHz 的主 Arm® Cortex®-M33，并集成 Cadence® Tensilica® HiFi 4 DSP，用于要求更高的 DSP 和音频处理任务。感知计算子系统有第二个 Arm® Cortex®-M33，并集成 Cadence® Tensilica® HiFi 1 DSP。这样就不再需要外部传感器集线器，从而降低系统设计复杂度、占板面积和 BOM 成本。

HiFi4 是基于超长指令字（VLIW）架构的高性能 DSP 内核，每个指令周期最多可处理八次 32x16 MAC 运算。它可用于卸载音频和图像处理等高性能数值计算任务，同时支持定点和浮点运算。

i.MX RT700 还配有 NXP 的 eIQ Neutron NPU，可使用 eIQ 机器学习软件开发环境。

硬件

  • 主计算子系统：

    • Arm Cortex-M33，最高 325 MHz

    • HiFi 4 DSP，最高 325 MHz

    • eIQ Neutron NPU，最高 325 MHz

  • 感知计算子系统

    • Arm Cortex-M33，最高 250 MHz

    • HiFi 1 DSP，最高 250 MHz

  • 7.5 MB 片上 SRAM

  • 三个用于片外存储器扩展的 xSPI 接口，支持最宽 16 位、最高 250 MHz DDR 的外部存储器

  • 支持 eUSB，集成 PHY

  • 两个 SD/eMMC 存储卡接口，其中一个支持 eMMC 5.0 及 HS400/DDR 模式

  • 高速 USB 主机/设备控制器，带片上 PHY

  • 数字麦克风接口，最多支持 8 个通道

  • 串行外设（UART/I²C/I3C/SPI/HSPI/SAI）

  • 2.5D GPU，支持矢量图形加速和帧缓冲压缩

  • EZH-V，使用带额外 SIMD/DSP 指令的 RISC-V 内核

  • 完整支持 openVG 1.1

  • 从片上 SRAM 最高支持 720p 60 FPS

  • LCD 接口 + MIPI DSI

  • 集成 JPEG 和 PNG 支持

  • CSI 8/10/16 位并行接口（通过 FlexIO）

有关 MIMXRT798 SoC 和 MIMXRT700-EVK 开发板的更多信息，请参阅以下参考资料：

  • i.MX RT700 Website

系统时钟

MIMXRT700 EVK 配置为使用 Systick 作为系统时钟源。

HiFi1 DSP 内核

可以以 HiFi 1 SoC 为目标，为 i.MX RT700 HiFi 1 DSP 内核构建 Zephyr 应用程序。Zephyr SDK 中包含支持 RT700 DSP 内核的 Xtensa 工具链。

为 i.MX RT700 HiFi 1 DSP 内核构建 hello_world 示例：

# From the root of the zephyr repository
west build -b mimxrt700_evk/mimxrt798s/hifi1 samples/hello_world

HiFi4 DSP 内核

可以以 HiFi 4 SoC 为目标，为 i.MX RT700 HiFi 4 DSP 内核构建 Zephyr 应用程序。Zephyr SDK 中包含支持 RT700 DSP 内核的 Xtensa 工具链。

为 i.MX RT700 HiFi 4 DSP 内核构建 hello_world 示例：

# From the root of the zephyr repository
west build -b mimxrt700_evk/mimxrt798s/hifi4 samples/hello_world

多核运行

MIMXRT700-EVK 支持所有内核的多核运行，包括 Cortex-M33 CPU0、Cortex-M33 CPU1、HiFi1 DSP 和 HiFi4 DSP。默认情况下，CM33 CPU0 内核是启动内核，负责初始化系统并启动 CM33 CPU1 内核和/或 HiFi4 DSP。CM33 CPU1 负责启动 HiFi1 DSP。

通常的启动过程是：负责启动从内核的内核将其固件/镜像复制到指定的内存位置，然后让从内核退出复位。

配置调试探针

调试探针既用于烧录也用于调试开发板。本开发板默认配置为使用 MCU-Link CMSIS-DAP 板载调试探针。

  1. 安装 LinkServer 调试主机工具，并确保其位于搜索路径中。

  2. 要让开发板进入 DFU mode 以烧写固件，请短接跳线 J20。

  3. 要更新调试固件，请按照 MIMXRT700-EVK Debug Firmware 中的说明操作

  1. 安装 J-Link 调试主机工具，并确保它们位于搜索路径中。

  2. 要断开 SWD 信号与板载调试电路的连接，请 短接 跳线 JP18。

  3. 将 J-Link 探针连接到 J18 20 针排针。

更多信息参见 J-Link 外部调试探针。

配置控制台

用 USB 线将 PC 连接到 J54，并使用任意串口终端（minicom、putty 等），设置如下：

  • 波特率：115200

  • 数据位：8 位

  • 校验位：无

  • 停止位：1

烧录

拨码开关 SW10 用于选择启动选项。将 SW10 设置为 Off-On（01），从 XSPI0 上默认的外部 Flash 启动。

以下以 Hello World 应用程序为例。本例默认使用 J-Link 调试主机工具。

# From the root of the zephyr repository
west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 samples/hello_world
west flash

打开串口终端，复位开发板（按下 RESET 按键），终端中应显示以下信息：

*** Booting Zephyr OS v3.7.0 ***
Hello World! mimxrt700_evk/mimxrt798s/cm33_cpu0

调试

以下以 Hello World 应用程序为例。本例默认使用 J-Link 调试主机工具。

# From the root of the zephyr repository
west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 samples/hello_world
west debug

打开串口终端，在调试器中单步执行应用程序，终端中应显示以下信息：

*** Booting Zephyr OS v3.7.0 ***
Hello World! mimxrt700_evk/mimxrt798s/cm33_cpu0

SEGGER RTT 日志

CM33 CPU0 内核默认在 SRAM 上启用了 D-cache，这意味着如果简单地把 RTT 缓冲区放在普通的 .bss 中，调试器将看不到它（CPU 的写入停留在 D-cache 中，永远不会到达 J-Link 读取的物理 SRAM）。只要启用 CONFIG_USE_SEGGER_RTT，SoC 层就会自动将 SEGGER RTT 控制块和缓冲区放入 Zephyr 的 nocache 区域，因此不需要任何用于放置缓冲区的 Kconfig 或 DTS 覆盖文件。

要通过 RTT 输出日志，只需启用日志后端：

CONFIG_USE_SEGGER_RTT=y
CONFIG_LOG_BACKEND_RTT=y

使用 JLinkRTTViewer 或 JLinkRTTLogger 连接时，将 RTT Control Block 选项设置为 Address（而不是 Auto Detection），并输入构建生成的链接器映射文件中 _SEGGER_RTT 的地址：

$ grep " _SEGGER_RTT$" build/zephyr/zephyr.map
                0x30180260                _SEGGER_RTT

由于开发板 defconfig 中启用了 CONFIG_TRUSTED_EXECUTION_SECURE，该地址位于安全 SRAM 别名范围（0x30xxxxxx）内。J-Link 默认的 RTT 自动搜索范围只覆盖非安全别名（0x20xxxxxx），否则将无法找到控制块。

SD 卡支持

MIMXRT700-EVK 上的 USDHC1 接口通过电子开关（TMUX136）在 SD 卡座（J47）和 M.2 连接器（J44）之间共享。跳线 JP65 用于选择哪个接口有效：

  • JP65 1-2：将 SDIO 信号连接到 SD 卡座（J47）。使用 SD 卡时请设置为此位置。

  • JP65 2-3（默认）：将 SDIO 信号连接到 M.2 连接器（J44）。

要使用 SD 卡，请确保 JP65 设置在 1-2 位置。

显示支持

mimxrt700_evk 开发板支持以下树内显示模块。各模块的设置说明如下。注意，开发板上的显示控制器在启用数据缓存时无法工作。

NXP G1120B0MIPI MIPI 显示屏

NXP G1120B0MIPI MIPI 显示屏 直接连接到开发板的 MIPI 连接器 J52，但需要进行一些修改（修改列表见 boards/shields/g1120b0mipi/boards/mimxrt700_evk_mimxrt798s_cm33_cpu0.overlay）。可以按如下方式为该模块构建显示示例：

west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 --shield g1120b0mipi samples/drivers/display

NXP RK055HDMIPI4MA0 720p MIPI 显示屏

NXP RK055HDMIPI4MA0 MIPI 显示屏 直接连接到开发板的 MIPI 连接器 J52，但需要进行一些修改（修改列表见 boards/shields/rk055hdmipi4ma0/boards/mimxrt700_evk_mimxrt798s_cm33_cpu0.overlay）。该面板分辨率为 720p，需要较大的帧缓冲区，因此必须使用 PSRAM 内存区域，这需要连接 JP45 1-2。可以按如下方式为该模块构建显示示例：

west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 --shield rk055hdmipi4ma0 samples/drivers/display

NXP ZC143AC72MIPI MIPI 显示屏

NXP ZC143AC72MIPI MIPI 显示屏 直接连接到开发板的 MIPI 连接器 J26，但需要进行一些修改（修改列表见 boards/shields/zc143ac72mipi/boards/mimxrt700_evk_mimxrt798s_cm33_cpu0.overlay）。可以按如下方式为该模块构建显示示例：

west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 --shield zc143ac72mipi samples/drivers/display

NXP LCD_PAR_S035

NXP LCD_PAR_S035 TFT LCD Module 直接连接到开发板 LCD 插座 J4 的引脚 1 至引脚 28，但需要进行一些修改（修改列表见 boards/shields/lcd_par_s035/boards/mimxrt700_evk_mimxrt798s_cm33_cpu0.overlay）。连接 JP7 的 2 和 3 以使用 3.3v 接口，并拆除电阻 R60 以使用触摸功能。可以按如下方式为该模块构建显示示例：

west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 --shield lcd_par_s035_8080 samples/drivers/display

Flash 存储器配置

默认情况下，开发板从 XSPI0 上的板载八线 SPI NOR（MX25UM51345G）启动并就地执行（XIP）。

经过改装、在 XSPI0 上改为焊接板载 Winbond W25Q512NW 四线 SPI NOR 的开发板，可通过 w25q512nw 开发板版本获得支持。该版本会选择四线 Flash 器件、启动 ROM 进行 XIP 所用的对应启动 Flash 配置块（FCB），以及相应的 XSPI0 时钟设置。可以按如下方式为该版本构建 spi flash 示例：

west build -b mimxrt700_evk@w25q512nw/mimxrt798s/cm33_cpu0 -p always samples/drivers/spi_flash

该硬件改装通过更改以下电阻，将 XSPI0 连接到 W25Q512NW 四线 SPI NOR：

  • 拆除：R396、R397、R400、R402

  • 焊接：R386、R694、R695、R701、R707、R708

构建时不指定版本限定符，将选择默认的 mx25um51345g 版本，对应出厂时的八线 Flash。

备注

w25q512nw 版本使用 LinkServer 烧录（west flash --runner linkserver），默认的 J-Link 运行器不支持该器件。LinkServer 通过 MIMXRT700_XSPI0_Quad_S.cfx Flash 算法操作安全的 XSPI0 区域，该算法由 NXP 单独提供。请将其复制到 <LinkServer>/binaries/Flash/。

west flash --runner linkserver -- \
  --override=/board/memory/1/flash-driver=MIMXRT700_XSPI0_Quad_S.cfx
# west flash --runner linkserver -- \
#   --override=/device/memory/5/flash-driver=MIMXRT700_XSPI0_Quad_S.cfx
