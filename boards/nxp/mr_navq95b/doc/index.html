MR-NavQ95B

Board Overview

Name:
mr_navq95b
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm

SoC:

mimx9596

Browse board sources

概述

NXP MR-NAVQ95 [8] 是一款为移动机器人应用设计的开源开发板。它基于 NXP i.MX95 应用处理器，提供异构多核处理能力，适合将实时任务与高性能应用处理结合起来。

该平台集成了 Cortex-A55 应用内核以及 Cortex-M7 和 Cortex-M33 实时内核。在 Zephyr 中，目前的支持主要针对 Cortex-M7 内核，它通常是实时固件的目标内核。

硬件

处理器

  • NXP i.MX95 SoC

    • 6 个 Arm Cortex-A55 内核

    • 1 个 Arm Cortex-M7 内核

    • 1 个 Arm Cortex-M33 内核

内存

  • 片上 SRAM：1376 KiB（ECC）

  • 外部 LPDDR5：16 GiB（带内联 ECC 和加密）

  • 外部 Flash：64 MiB 八线 SPI NOR

连接

NXP MR-NAVQ95 [8] 由一块底板组成，可通过可选的附加模块扩展更多接口和功能。这张 block diagram [10] 概述了各扩展板以及可用的外设。

这些接口是复用的，取决于 i.MX95 平台的开发板配置和 pinmux 设置。

串口控制台

默认串口控制台连接到 UART2 接口。可以通过 I/O 扩展板 USB-C 连接器（J10）上的 USB 转 UART 桥接器访问。此外，主板上专用的 JST-GH 板载连接器（J2）也引出了 UART2。

构建并运行 Hello World

建议在 SD 卡上安装 NavQ95 镜像。该镜像会初始化 M33 和 A55 内核，并在启动时于 M7 上运行 MCUBoot，从而可以从外部 Flash 运行 zephyr 固件。该 SD 卡镜像的构建和下载说明见 NXP IMX-MANIFEST-NAVQ95 [9]

为 MR-NAVQ95B 构建在 ITCM 上运行的 Zephyr 应用程序：

west build -b mr_navq95b/mimx9596/m7 samples/hello_world/

构建从 MX25UM51345G 外部 Flash 运行的应用程序：

west build -b mr_navq95b/mimx9596/m7/flash samples/hello_world/

可以使用连接到 J7 端口的 Segger/J-Link 探针上传二进制文件：

west flash

备注

要将二进制文件烧录到外部 Flash，PyOCD 需要支持 mimx95_cm7_mx25um 目标。在撰写本文时，该支持尚未合入。

按照以下步骤获取支持 mimx95_cm7_mx25um 的 PyOCD：

  • 安装 pyocd，以便通过板载 JTAG 设备烧录镜像。

  • 将 pyocd 克隆到你选择的目录，并检出 pr-imx95 分支：

    git clone https://github.com/NXP-Robotics/pyOCD -b pr-imx95

  • 构建 pyocd：

    cd pyocd-private
python3 -m pip install .

从外部 Flash 运行固件时，标准启动流程包括：

  1. System Manager（Cortex-M33）初始化系统

  2. MCUBoot 被加载到 TCM

  3. MCUBoot 校验外部 Flash 中的固件

  4. 固件在 Flash 中执行（XIP）

以太网：与 Linux 并行运行 NETC VSI

i.MX95 NETC（ENETC）以太网控制器由 Cortex-A55 内核上的 Linux 和 Cortex-M7 上的 Zephyr 共享。Linux 通过物理站接口（PSI）拥有物理端口和 PHY，该接口显示为 end0 网络接口。M7 上的 Zephyr 使用虚拟站接口（VSI），即同一控制器的一个虚拟功能（VF）（enetc0_vsi1，ENETC0 VF1），并通过该共享端口收发数据。

VF 隶属于 PF，因此 Linux 必须先创建并移交 VF，M7 才能使用它。M7 驱动从不访问 PHY 或 PF，只启动自己的站接口，并通过 NETC VSI 到 PSI 的消息通道请求 PSI 设置其 MAC 过滤器。

Linux 设备树

Linux 设备树无需针对 M7 做任何修改。默认的 NavQ95 Linux 镜像（见 NXP IMX-MANIFEST-NAVQ95 [9]）已将 ENETC0 PF 启用为支持 SR-IOV 的 end0，这就是所需的全部配置。VF 本身在运行时创建（见下文），而不是在设备树中静态描述。

在 Linux 中启动 VF

Linux 启动后，在 A55 上（以 root 身份）运行一次以下命令，其中 end0 是以 VF1 形式移交给 M7 的 ENETC0 PF：

# Keep Linux's VF driver off the VF so the M7 can own it, then create VF0+VF1.
echo 0 > /sys/class/net/end0/device/sriov_drivers_autoprobe
echo 2 > /sys/class/net/end0/device/sriov_numvfs

# Resolve the VF1 PCI address and let it DMA and raise MSI-X interrupts.
vf=$(basename "$(readlink -f /sys/class/net/end0/device/virtfn1)")
setpci -s "$vf" COMMAND=0x0006          # Bus Master Enable
setpci -s "$vf" CAP_MSIX+2.w=0x8000:0x8000

# Trust the VF so the PSI honours the M7 driver's MAC-filter requests.
ip link set end0 vf 1 trust on

此后，M7 VSI 驱动会检测到 VF 已启用，并通过 end0 接入网络。

备注

NavQ95 BSP（见 NXP IMX-MANIFEST-NAVQ95 [9]）附带一个 enetc-vsi-handoff-mcore 服务，会在启动时执行这些步骤，因此通常无需手动运行。这里列出这些步骤是为了便于自定义配置。
