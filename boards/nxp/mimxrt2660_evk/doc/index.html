MIMXRT2660-EVK

概述

MIMXRT2660-EVK 是 NXP i.MX RT266x 系列的评估板，基于 MIMXRT2663 跨界 MCU。i.MX RT266x 采用按子系统划分的设计：单个 Arm Cortex-M85 计算内核与 HSP、MAIN、WAKE、AUDIO、MEDIA、COMM、SYSCON 和 VBAT 域并存，每个域都有各自的时钟和电源控制。

硬件

  • MIMXRT2663 跨界 MCU：

    • Arm Cortex-M85，最高 1 GHz，带 Helium、TrustZone、MPU 和 L1 缓存

    • 256 KB ITCM、256 KB DTCM，以及三个 256 KB 片上 RAM 存储体

    • Neutron N256 神经网络处理单元，以及显示/图形子系统

    • 两个 xSPI 接口（一个 8 位、一个 16 位），8 个 UART、4 个 I2C、2 个 I3C、6 个 SPI

    • 两个支持 TSN 的千兆以太网、两个 10BASE-T1S、三个 CAN-FD

    • 安全隔区（EdgeLock）和末级缓存

  • 开发板：

    • MIMXRT2663CVVAA，工业级，289BGA 0.8 mm，1 GHz

    • XSPI0 上的 64 MB Winbond W25H512NWEAM 串行 NOR Flash

    • XSPI1 上的 32 MB Winbond W958D6NMYA Xccela PSRAM

    • eMMC、SD 卡槽、以太网、USB

    • 板载 MCU-Link 调试探针

有关 i.MX RT266x SoC 和本开发板的更多信息，请参阅 i.MX RT2660 Reference Manual [1] 和 i.MX RT2660 Data Sheet [1]。

内存布局

该开发板从外部 Flash 就地执行，并使用外部 RAM：

  • zephyr,flash 是 64 MB 的 XSPI0 NOR Flash，代码直接在其中就地运行。

  • zephyr,sram 是 32 MB 的 XSPI1 PSRAM，.data、.bss 以及内核栈和堆都位于其中。

  • ITCM 存放时钟启动窗口的代码，DTCM 中的临时栈供该窗口本身使用：重新配置 PLL 需要让两个 XSPI 控制器都停止工作，因此在窗口打开期间，代码及其运行所用的栈都不能位于外部存储器中。其他内容都不需要移动，因此应用程序可以将整个 PSRAM 用于自己的栈和堆，TCM 也保持空闲供其使用。

在本镜像运行之前，启动 ROM 会根据启动头初始化这两种存储器：NOR 使用 Flash 配置块，PSRAM 使用外部存储器配置数据。

备注

该 SoC 的启动 ROM 使用基于容器的（AHAB）镜像格式，不读取镜像向量表。构建会生成 ROM 读取的全部三个块：偏移 0x400 处的 Flash 配置块、0xA00 处的外部存储器配置数据和 0x1000 处的 AHAB 容器，并将镜像本身放在 0xC000 处，因此写入启动 Flash 的 zephyr.bin 可以在冷复位后直接运行，无需任何构建后步骤。评估板上不需要签名：出厂（out-of-fab）生命周期会忽略认证错误，因此容器中只带有一个空的签名块。

备注

Flash 仅用于执行代码：该目标不包含 Flash 驱动，也没有分区，因此无法使用 Flash API、MCUboot 和基于 Flash 的 settings。要启用 Flash 驱动，需要对 Zephyr 共享的 XSPI 驱动进行移植工作，这些驱动使用了该 SoC 未实现的 xspi_config_t 字段。

系统时钟

开发板的启动时钟配置通过电源控制器进入 Over Drive Run 工作点，使 Cortex-M85 运行在 1 GHz。由于这一切换还需要把 PLL 参考时钟从片上振荡器切换到板载晶振，其中一部分必须在关闭缓存、禁用两个 xSPI 控制器的情况下从 RAM 执行，因此这部分代码及其运行所用的栈位于 ITCM 和 DTCM，而不是任何外部存储器中。

系统定时器的计数时钟是由板载晶振派生的外部 24 MHz 参考时钟（计算子系统的 SysTick 时钟根），而不是内核时钟，因此节拍定时的精度取决于晶振，与内核频率无关。

外设时钟根在设备树中描述为 nxp,imx-ccm-rev3-root 节点。根据时钟根在时钟树中的位置，有两种配置方式。

上游时钟根和共享时钟根（CGU 分配时钟根，以及没有单一使用者的时钟根，例如 main_rootclk，或为所有以 PERI3 为源的外设供时钟的 peri3_rootclk）将其选择器和分频器作为属性写在时钟根节点本身上。应用程序的覆盖文件可以重新配置这类时钟根，无需修改开发板 C 代码，并会同时改变所有从它取时钟的叶子节点。例如，要更改共享 PERI3 时钟根的源：

&peri3_rootclk {
        clock-mux = <IMX_CCM_MUX_PERI3_SYSPLL_DIVOUT2>;
        clock-div = <1>;
};

叶子外设时钟根（由单个设备独占的逐实例功能时钟根，例如每个 LPUART 的时钟根）则把默认选择器和分频器直接写在使用它的外设节点上，作为门控之外的第二个 clocks 条目。这样每个此类设备都有开发板默认值，无需单独的覆盖文件。控制台 LPUART0 使用 PERI3 五分频（80 MHz）：

&lpuart0 {
        clock-names = "gate", "source";
        clocks = <&ccm IMX_CCM_CLK(IMX_CCM_LPCG_MAIN_HSP_LPUART0,
                                   IMX_CCM_ROOT_MAIN_LPUART0_FCLK)>,
                 <&ccm IMX_CCM_ROOT_CFG(IMX_CCM_ROOT_MAIN_LPUART0_FCLK,
                                        IMX_CCM_MUX_LPUART0_PERI3, 5, 1)>;
};

目前只有 LPUART 驱动会读取这第二个条目。驱动尚未应用该条目的外设，其时钟根保持复位值，因此仅添加该条目不会对 LPSPI、LPI2C 等外设产生任何影响。

备注

只有叶子外设时钟根可以安全地用这种方式重新配置。模拟时钟源、CPU 和总线时钟根以及 PLL 分配时钟根也是设备树节点（SoC 时钟启动时会读取它们，而不是硬编码数值），但在上文所述的参考时钟切换过程中，它们会被停止、断电并重新切换，因此仅修改属性并不能让其他设置生效。两个 xSPI 功能时钟根声明在 xspi0/xspi1 上，而不是作为控制器的子节点，并且还会在该窗口内被手动写入。

编程与调试

说明

按常规方式构建并烧录应用程序（详见 构建应用程序 和 运行应用程序）。

配置调试探针

该开发板默认配置为使用板载的 MCU-Link CMSIS-DAP 板载调试探针。

使用 LinkServer

LinkServer 是该开发板的默认运行器（runner）。需要 LinkServer v26.09 或更高版本，旧版本不包含 MIMXRT2663 器件。安装 LinkServer 调试主机工具 并确保其位于搜索路径中，然后使用以下命令构建并烧录：

# From the root of the zephyr repository
west build -b mimxrt2660_evk/mimxrt2663/cm85 samples/hello_world
west flash
使用 J-Link

可以按照 MCU-Link JLink 板载调试探针 中的说明将板载调试电路更新为 Segger J-Link 固件，也可以将外部 J-Link 外部调试探针 连接到 SWD 排针。

# From the root of the zephyr repository
west build -b mimxrt2660_evk/mimxrt2663/cm85 samples/hello_world
west flash -r jlink

在 MCU-Link 虚拟 COM 端口上以 115200 8N1 打开串口终端，复位开发板，示例会输出：

*** Booting Zephyr OS build v4.5.0 ***
Hello World! mimxrt2660_evk/mimxrt2663/cm85
