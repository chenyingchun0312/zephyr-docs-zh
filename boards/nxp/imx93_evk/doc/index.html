i.MX93 EVK

Board Overview

Name:
imx93_evk
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm, arm64

SoC:

mimx9352

Browse board sources

概述

i.MX93 评估套件（MCIMX93-EVK 开发板）是一个旨在以小巧、低成本的形式展示 i.MX 93 应用处理器最常用功能的平台。MCIMX93-EVK 开发板是一款入门级开发板，可帮助开发者在为更具体的设计投入大量资源之前熟悉该处理器。

i.MX93 MPU 由一个包含 2 个 Cortex®-A55 内核的集群和一个 Cortex®-M33 内核组成。Zephyr OS 已移植到 Cortex®-A55 内核和 Cortex®-M33 内核上。

  • 开发板特性：

    • RAM: 2GB LPDDR4

    • 存储：

      • SanDisk 16GB eMMC5.1

      • microSD 卡座

    • 无线：

      • Murata Type-2EL（SDIO+UART+SPI）模组。它基于 NXP IW612 SoC，支持双频（2.4 GHz / 5 GHz）1x1 Wi-Fi 6、蓝牙 5.2 和 802.15.4

    • USB:

      • 两个 USB 2.0 Type C 连接器

    • 以太网

    • PCI-E M.2

    • 连接器：

      • 40 针双排排针

    • LEDs:

      • 1 个电源状态 LED

      • 2x UART LED

    • 调试

      • 20 针 JTAG 连接器

      • 用于 UART 调试的 MicroUSB，为 A55 和 M33 提供两个 COM 端口

支持的功能

imx93_evk 开发板支持下列硬件功能。

说明

The list of supported hardware features was not generated. Run a full documentation build for the required metadata to be available.

PWM(TPM)

对于 M33 内核，启用了 TPM2。可以用示波器或逻辑分析仪观察信号：将 J1005-3 和 J1005-7（GND）连接到示波器或逻辑分析仪

对于 A55 内核，为 PWM Blinky 应用程序启用了 TPM3，开发板上 RGB LED D1001 中的绿色 LED 会以不同频率闪烁。

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/basic/blinky_pwm

ADC

为 M33 内核启用了 sar_adc1。引脚 ADC_IN0/1/2/3 连接到 J1003-1/3/5/7

设备

系统时钟

本开发板配置使用 24 MHz 的系统时钟频率。Cortex-A55 内核最高运行在 1.7 GHz。Cortex-M33 内核最高运行在 200MHz，SYSTICK 运行在相同频率。

串口

该开发板配置为 A55 核和 M33 核共用 CPU 的 UART2 这一个串行通信通道。

uSDHC（A55 上的 SD 或 eMMC 接口）

i.MX 93 处理器有三个超安全数字主机控制器（uSDHC）模块，用于支持 SD/eMMC 接口。在 MCIMX93-EVK 开发板上，处理器的 uSDHC2 接口连接到 MicroSD 卡槽（J1002），uSDHC1 接口连接到 eMMC 存储器（位于 SOM 板上）。提供了 DTS 覆盖文件 "usdhc1.overlay" 和 "usdhc2.overlay"，用于启用指定的 uSDHC 控制器。

目前依赖 U-boot 或 Linux 在 Cortex-A 内核上引导 Zephyr，因此 Zephyr 需要使用与 U-boot 或 Linux 不同的 uSDHC 控制器，以避免资源冲突。例如，如果 EVK 开发板从使用 uSDHC2 的 SD 卡启动，Zephyr 可以使用 uSDHC1 所连接的 MMC 进行测试：

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 tests/subsys/sd/mmc -- -DEXTRA_DTC_OVERLAY_FILE=usdhc1.overlay

如果 EVK 开发板从使用 uSDHC1 的 MMC 启动，Zephyr 可以使用 uSDHC2 所连接的 SD 卡进行测试：

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 tests/subsys/sd/sdmmc -- -DEXTRA_DTC_OVERLAY_FILE=usdhc2.overlay

开发板 MUX 控制

该开发板配置使用一系列数字多路复用器在不同的开发板功能之间切换。这些多路复用器由板载 GPIO 扩展器 ADP5585 发出的名为 EXP_SEL 的 GPIO 信号控制。如果启用了开发板控制模块，可以通过 dts 配置选择功能集 "A" 或 "B"。定义了以下 dts 节点：

board_exp_sel: board-exp-sel {
    compatible = "imx93evk-exp-sel";
    mux-gpios = <&gpio_exp0 4 GPIO_ACTIVE_HIGH>;
    mux = "A";
};

配置 EXP_SEL 信号需要以下步骤：

  1. 启用 Kconfig 选项 CONFIG_BOARD_MIMX93_EVK_EXP_SEL_INIT。

  2. 在 &board_exp_sel 设备树节点中选择 mux="A"; 或 mux="B";。

如果启用了需要配置多路复用器的开发板功能，就会启用 Kconfig 选项 CONFIG_BOARD_MIMX93_EVK_EXP_SEL_INIT。启用某些开发板功能时会自动选择相应的 MUX 选项，并且其优先级高于 dts 配置。例如，如果启用了 CONFIG_CAN，即使 dts 中配置了 mux="B";，也会选择 MUX A，并在日志中报告一条警告。

用户按键 GPIO 选项

用户按键 RFU_BTN1 和 RFU_BTN2 默认连接到 i.MX 93 GPIO，但可以通过板载拨码开关改为连接到板载 GPIO 扩展器 PCAL6524。为此，请将 SW1006 拨到 0000，然后将 SW1005 拨到 0101。为此提供了一个设备树覆盖文件。

运行以下命令测试 PCAL6524 上的用户按键：

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/basic/button -- -DEXTRA_DTC_OVERLAY_FILE=imx93_evk_mimx9352_exp_btn.overlay

运行应用程序，按下 RFU_BTN1，红色 LED 就会相应点亮。

注意：该覆盖文件仅支持 mimx9352/a55，但如果启用了 I2C 和 PCAL6524，可以扩展为支持 mimx9352/m33。

编程与调试（A55）

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

在 A55 核上编程和调试 Zephyr 有多种方法：

选项 1：使用 JLink 运行器引导 Zephyr

该开发板的默认运行器是 JLink。使用 J-Link 调试器将 EVK 开发板的 JTAG 连接器连接到主机，给开发板上电并使其停在 U-Boot 命令行，然后执行以下 U-boot 命令禁用 D-Cache：

dcache off

然后使用 "west flash" 或 "west debug" 命令从主机加载 zephyr.bin 镜像，并在 A55 core0 上启动 Zephyr 应用程序。

烧录并运行

以下是 Basic Synchronization 应用程序的示例。

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/synchronization
west flash

然后可以在 UART2 控制台上看到以下日志：

*** Booting Zephyr OS build Booting Zephyr OS build v3.7.0-2055-g630f27a5a867  ***
thread_a: Hello World from cpu 0 on imx93_evk!
thread_b: Hello World from cpu 0 on imx93_evk!
thread_a: Hello World from cpu 0 on imx93_evk!
thread_b: Hello World from cpu 0 on imx93_evk!

调试

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/hello_world
west debug

选项 2：使用 U-Boot 命令引导 Zephyr

U-Boot "go" 命令可用于在 A55 core0 上启动 Zephyr，U-Boot "cpu" 命令用于将 Zephyr 加载到其他 A55 从核并启动。目前 Real-Time Edge U-Boot 支持 "cpu" 命令（使用 "uboot_vxxxx.xx-y.y.y" 分支，其中 xxxx.xx 是 U-Boot 版本，y.y.y 是 Real-Time Edge Software 版本，例如 "uboot_v2023.04-2.9.0" 分支是 Real-Time Edge Software v2.9.0 版本所用的 U-Boot v2023.04），预编译镜像和用户指南可在 Real-Time Edge Software 获取。

步骤 1：将 Zephyr 镜像下载到 DDR 内存

首先需要将 Zephyr 二进制镜像下载到 DDR 内存中，可以使用 tftp：

tftp 0xd0000000 zephyr.bin

也可以将 Zephyr 镜像 zephyr.bin 复制到 SD 卡，再将卡插入开发板。例如，如果复制到 SD 卡的 FAT 分区，可使用以下 U-Boot 命令将镜像加载到 DDR 内存中（假设 SD 卡为 dev 1，FAT 分区 ID 为 1，可根据实际情况修改）：

fatload mmc 1:1 0xd0000000 zephyr.bin;

步骤 2：引导 Zephyr

然后使用以下命令在 core0 上引导 Zephyr：

dcache off; icache flush; go 0xd0000000;

也可以使用 "cpu" 命令从副核引导，例如 Core1：

dcache flush; icache flush; cpu 1 release 0xd0000000

备注

以 imx93_evk/mimx9352/a55/smp 为目标构建时，使用 U-Boot "go" 命令启动 Zephyr，因为 i.MX 93 只有 2 个 Cortex-A55 内核。

选项 3：在 Linux 下使用 Remoteproc 引导 Zephyr

在 A55 核上运行 Linux 时，可以使用 remoteproc 框架加载并启动 Zephyr，详情请参阅 Real-Time Edge 用户指南。预构建镜像和用户指南可在 Real-Time Edge Software 获取。

使用此配置运行基本的 Zephyr 应用程序和内核测试，例如 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/synchronization

这将构建一个包含 synchronization 示例应用程序的镜像，启动该镜像，并显示以下控制台输出：

*** Booting Zephyr OS build Booting Zephyr OS build v3.7.0-2055-g630f27a5a867  ***
thread_a: Hello World from cpu 0 on imx93_evk!
thread_b: Hello World from cpu 0 on imx93_evk!
thread_a: Hello World from cpu 0 on imx93_evk!
thread_b: Hello World from cpu 0 on imx93_evk!

选项 4：使用 SPSDK 运行器启动 Zephyr

SPSDK 运行器基于 SPSDK 工具（https://spsdk.readthedocs.io），它会构建一个包含所有必要固件组件的可启动 Flash 镜像 flash.bin。使用 west flash 命令会将启动镜像 flash.bin 下载到 DDR 内存、SD 卡或 eMMC Flash 中。使用 flash.bin 时没有 U-Boot 镜像，因此 TF-A 会直接在第一个 Cortex-A55 核上启动 Zephyr。

使用 SPSDK 运行器需要获取二进制 blob，可运行以下命令完成：

west blobs fetch hal_nxp

备注

建议在执行 west update 之后运行上述命令。

SPSDK 运行器通过配置项 CONFIG_BOARD_NXP_SPSDK_IMAGE 启用，目前 i.MX93 EVK 开发板默认未启用，因此需使用该配置启用它，例如对于 Basic Synchronization 示例：

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/synchronization -- -DCONFIG_BOARD_NXP_SPSDK_IMAGE=y

如果 CONFIG_BOARD_NXP_SPSDK_IMAGE 可用并已为该开发板变体启用，则会自动构建 flash.bin。可以通过以下命令进行烧写。在此之前，应将板载开关 SW1301[3:0] 配置为 0b0011，以 USB 下载模式启动，并将 USB1 和 DBG 端口连接到 Linux 主机 PC。系统会枚举出 4 个串口（115200 8n1），第四个串口用作 Cortex-A55 Zephyr 的控制台。（烧写工具为 spsdk，已通过 scripts/requirements.txt 安装。在 Linux 主机上，应按照 https://spsdk.readthedocs.io 的安装指南配置 USB 设备权限。）

# load and run without programming. for next flashing, need to reset the board firstly
$ west flash -r spsdk

# program to SD card, then set SW1301[3:0]=0b0010 to reboot from SD
$ west flash -r spsdk --bootdevice sd

# program to emmc card, then set SW1301[3:0]=0b0000 to reboot from EMMC
$ west flash -r spsdk --bootdevice=emmc

然后 Zephyr 日志会显示在第四个串口的控制台中。

系统重启（A55）

目前 i.MX93 仅支持冷重启，不支持热重启。使用此配置通过 Custom Shell module 示例验证冷重启：

# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/subsys/shell/shell_module

这将构建一个包含 shell 示例应用的镜像，启动该镜像，并在 shell 命令行中执行 kernel reboot 命令：

uart:~$ kernel reboot cold

编程与调试（M33）

使用 SOF 专用变体

用途

由于该开发板没有 DSP，需要为有意在此开发板上运行 SOF 的人找到替代方案。该方案是使用 Jailhouse 从 Linux 中“拿走”一个 A55 内核并将其分配给 Zephyr，从而在 A55 内核上运行 SOF。

什么是 Jailhouse？

Jailhouse 是一个轻量级虚拟机管理程序（hypervisor），用于对硬件资源进行分区。有关其实现方式以及 Jailhouse 的总体介绍，请参阅：1、2 和 3。GitHub 仓库见 here。

它是如何工作的？

首先，需要解释后文会提到的几个 Jailhouse 概念：

  • Cell：指一组硬件资源，分配给该 cell 的操作系统可以使用这些资源。

  • Root cell：指运行 Linux 的 cell。这是主 cell，包含 Linux 将使用的所有硬件资源，并用于向 inmate 分配资源。inmate 不能 使用尚未分配给 root cell 的资源，例如 CPU。

  • Inmate：指与 Linux 并行运行的任何其他操作系统。inmate 使用的资源取自 root cell（运行 Linux 的 cell）。

SOF+Zephyr 将作为 inmate 与 Linux 并行运行在开发板的 core 1 上。这意味着该内核会从 Linux 中拿走，仅供 Zephyr 使用。

虚拟机管理程序使用基于配置文件中所描述内存区域的第二阶段转换表，限制 inmate/root 对某些硬件资源的访问。请考虑以下场景：

Root cell 要使用 UART，假设其寄存器映射在 [0x0 - 0x42000000] 区域。如果 inmate 出于某种原因也要使用同一个 UART，就需要将该区域也添加到 inmate 的配置文件中，并添加 JAILHOUSE_MEM_ROOTSHARED 标志。该标志表示允许 inmate 与 root 共享该区域。如果 inmate 的配置文件中没有设置该区域，而 Zephyr（此处作为 inmate 运行）尝试访问该区域，就会导致第二阶段转换错误。

注意：

  • Linux 和 Zephyr 并不知道它们彼此并行运行，它们只知道通过配置文件分配给自己的内核（root 有一个配置文件，每个 inmate 各有一个配置文件）。
