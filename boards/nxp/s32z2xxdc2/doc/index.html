X-S32Z27X-DC (DC2)

Board Overview

Name:
s32z2xxdc2
Vendor:

NXP Semiconductors

Status:

Not actively maintained

Architecture:

arm

SoC:

s32z270

Browse board sources

概述

X-S32Z27X-DC（DC2）开发板基于 NXP S32Z2 实时处理器，该处理器包含两个实时单元（RTU），每个由四个 ARM Cortex-R52 内核组成，支持灵活的分离/锁步配置。

每个 SoC/RTU 对应一个 Zephyr 开发板：

  • s32z2xxdc2/s32z270/rtu0：用于 S32Z270/RTU0

  • s32z2xxdc2/s32z270/rtu1：用于 S32Z270/RTU1。

硬件

有关硬件和设计资源的信息，请访问 NXP S32Z2 Real-Time Processors website [8]。

支持的功能

s32z2xxdc2 开发板支持下列硬件功能。

该开发板没有用户 LED 或开关，而 Blinky 或 Button 等部分示例需要用到它们。请按照示例说明中的步骤为该开发板启用支持。

系统时钟

Cortex-R52 内核配置为运行在 1 GHz。

串口

该 SoC 有 12 个可用于 UART 模式的 LINFlexD 实例。默认可通过 USB micro-B 连接器 J119 访问控制台。

看门狗

看门狗驱动仅支持在定时器到期时触发中断。目前在该开发板上 Zephyr 从 SRAM 运行，因此不支持系统复位。

以太网

NETC 驱动支持管理物理站接口（PSI0）和/或单个虚拟 SI（VSI）。其余 VSI 应分配给系统中的其他内核。要了解如何配置以太网网络控制器，请参阅 S32 Network Controller (NETC)。

控制器局域网

CANEXCEL

CANEXCEL 支持经典 CAN（CAN 2.0）和 CAN FD 模式，不支持远程传输请求。

注意，该开发板目前没有为 CANEXCEL 端口安装 CAN 收发器。要与外部通信，需要添加 CAN 收发器。可以使用任何与 CAN 2.0 和 CAN FD 协议引脚兼容的收发器。

FlexCAN

FlexCAN 支持经典 CAN（CAN 2.0）和 CAN FD 模式。

ADC

ADC 通过 ADC SAR 控制器提供，共 2 个实例。每个 ADC SAR 实例的分辨率为 12 位。ADC 通道分为 2 组（精密和内部/标准）。

备注

同一实例的所有通道在同一时间只能运行在 1 个组通道上。

EDMA

EDMA 模块包含四个 EDMA3 实例：实例 0 有 32 个通道，实例 1、4 和 5 各有 16 个通道。

外部 Flash

板载 S26HS512T 512M 位 HyperFlash 存储器连接到 QSPI 控制器端口 A1。该开发板配置将其选为默认的 Flash 控制器。

CRYPTO

硬件安全引擎（HSE）支持哈希和对称加密等密码运算，可使用基于 RAM 的密钥目录、以 128 位或 256 位密钥长度执行 ECB、CBC 和 CTR 模式。

备注

该驱动假定 HSE 固件已安装并配置完毕（即密钥目录已格式化、所用的 MU 实例已激活等）。HSE 固件的安装和配置过程记录在 HSE 固件用户手册中。如需获取该文档，请联系 NXP 销售人员或 NXP 分销商。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

s32z2xxdc2 开发板的应用程序可以按照 构建应用程序 中所述的常规方式构建。

目前在该开发板上，只能从内核的内部 SRAM 加载并执行 Zephyr 应用程序二进制文件。

本开发板支持以下调试工具的 West 运行器（runner）：

  • NXP S32 调试探针（默认）

  • Lauterbach TRACE32

加载固件前，请先按照所用调试工具的安装步骤进行安装。

设置开发板

将外部调试探针连接到开发板的 JTAG 连接器（J134），并根据探针支持的方式通过 USB 或以太网连接到主机。

要查看串口输出，请将开发板的 USB/UART 端口（J119）连接到主机，并运行你常用的终端程序监听输出。例如，使用跨平台的 pySerial miniterm [9] 终端：

python -m serial.tools.miniterm <port> 115200

将 <port> 替换为开发板所在的端口。例如，在 Linux 下为 /dev/ttyUSB0。

调试

可以使用以下命令为开发板 s32z2xxdc2/s32z270/rtu0 构建并调试 Hello World 示例：

# From the root of the zephyr repository
west build -b s32z2xxdc2/s32z270/rtu0 samples/hello_world
west debug

如果使用的是较新的 PCB 版本，由于默认 PCB 版本为 B，必须使用相应调整过的开发板定义。例如，使用版本 D 时：

west build -b s32z2xxdc2@D/s32z270/rtu0 samples/hello_world
west debug

此时即可进行正常的调试会话。设置断点，然后输入 c 继续运行程序。终端中应显示以下信息：

Hello World! s32z2xxdc2

要改用 Lauterbach TRACE32 软件调试，请运行：

west debug -r trace32

烧录

如果只想将应用程序下载到开发板 SRAM 并运行，请按照以下步骤操作。

只有 Lauterbach TRACE32 运行器支持 flash 命令：

west build -b s32z2xxdc2/s32z270/rtu0 samples/hello_world
west flash -r trace32

备注

目前，flash 和 debug 命令所执行的 Lauterbach 启动脚本会执行相同的步骤来初始化 SoC 并将应用程序加载到 SRAM。区别在于 flash 会隐藏 Lauterbach TRACE32 界面，执行应用程序后退出。

要使用 NXP S32 Debug Probe 运行器模拟类似的行为，可以在批处理模式下用 GDB 运行 debug 命令：

west debug --tool-opt='--batch'

RTU 与内核配置

本 Zephyr 移植只能在任意一个 Cortex-R52 内核上以单核方式运行，可以是锁步模式，也可以是分离锁步模式。默认情况下，Zephyr 运行在所选 RTU 的第一个内核上，并采用锁步模式（即复位后的配置）。

要构建分离锁步模式，必须在应用程序的 Kconfig 文件中禁用 CONFIG_DCLS。

默认情况下，开发板配置会根据构建配置设置运行器参数。要调试默认内核以外的其他内核，请使用：

west debug --core-name='R52_<rtu_id>_<core_id>_LS'

west debug --core-name='R52_<rtu_id>_<core_id>'

其中：

  • <rtu_id> 是从零开始的 RTU 索引

  • <core_id> 是运行 Zephyr 应用程序的内核在该 RTU 内从零开始的索引（0、1、2 或 3）

例如，要以分离锁步内核配置为开发板 s32z2xxdc2/s32z270/rtu0 构建 Hello World 示例：

west build -b s32z2xxdc2/s32z270/rtu0 samples/hello_world -- -DCONFIG_DCLS=n

要在分离锁步模式下于 RTU0 的第二个内核上执行该示例：

west debug --core-name='R52_0_1'

如果使用 Lauterbach TRACE32，必须在命令行中覆盖所有运行器参数：

west debug -r trace32 --startup-args elfFile=<elf_path> rtu=<rtu_id> core=<core_id> lockstep=<yes/no>

其中 <elf_path> 是输出目录中 Zephyr 应用程序 ELF 文件的路径。
