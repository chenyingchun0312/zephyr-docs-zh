QEMU Emulation for Hexagon

Board Overview

Name:
qemu_hexagon
Vendor:

QEMU, a generic and open source machine emulator and virtualizer

Status:

Not actively maintained

Architecture:

hexagon

SoC:

qemu_hexagon_virt

Browse board sources

概述

此开发板配置使用 QEMU 模拟 Qualcomm Hexagon DSP 虚拟平台。

Hexagon DSP 是 Qualcomm 设计的 VLIW 数字信号处理器，用于 Snapdragon SoC。此开发板配置提供一个基于 QEMU 的环境，用于开发和测试面向 Hexagon 架构的 Zephyr 应用程序。

Hexagon 上的 Zephyr 作为客户机运行在 Hexagon VM 虚拟机管理程序（hypervisor）之下。zephyr.elf 二进制文件不能直接启动，必须通过 HVM loadlinux 引导加载程序加载。

此配置支持以下设备：

  • HVM PIC 中断控制器

  • HVM 定时器

  • PL011 UART（控制台）

入门

本节介绍如何安装在 QEMU Hexagon 开发板上构建和运行 Zephyr 所需的工具和依赖项。

前提条件

需要以下工具：

  • west 构建工具和 Zephyr Python 依赖项（见第 5 步）

  • 面向 Hexagon 的 LLVM/Clang 交叉编译器（见下文）

  • 支持 Hexagon 的 QEMU（见下文）

  • Hexagon hypervisor loadlinux 引导加载程序（见下文）

第 1 步：安装 Hexagon LLVM 工具链

从 toolchain_for_hexagon 发布页面 下载预编译的 Hexagon LLVM 交叉编译器。

对于 Ubuntu 22.04 及更高版本的 x86_64 主机，推荐使用以下文件：

clang+llvm-22.1.4-cross-hexagon-unknown-linux-musl.tar.zst

下载并解压到你选择的目录，例如 /opt/hexagon-toolchain：

$ wget https://artifacts.codelinaro.org/artifactory/codelinaro-toolchain-for-hexagon/22.1.4_/clang+llvm-22.1.4-cross-hexagon-unknown-linux-musl.tar.zst
$ mkdir -p /opt/hexagon-toolchain
$ tar -xf clang+llvm-22.1.4-cross-hexagon-unknown-linux-musl.tar.zst \
      -C /opt/hexagon-toolchain --strip-components=2

备注

该压缩包顶层包含一个 x86_64-linux-gnu/ 子目录。--strip-components=2 会同时去掉压缩包名称前缀和该子目录，使 bin/clang 直接位于安装目录下。

选择 hexagon 工具链变体，并将 HEXAGON_TOOLCHAIN_PATH 指向解压后的目录：

$ export ZEPHYR_TOOLCHAIN_VARIANT=hexagon
$ export HEXAGON_TOOLCHAIN_PATH=/opt/hexagon-toolchain

有关 hexagon 工具链变体的详细信息，参见 Qualcomm Hexagon LLVM 工具链。

第 2 步：支持 Hexagon 的 QEMU

标准 QEMU 发行版不包含 Hexagon 系统模拟。第 1 步安装的工具链在其 bin 目录中自带 qemu-system-hexagon，构建系统会优先在该目录查找，因此运行 west build -t run 或 Twister 无需额外设置。

如需使用其他 QEMU，请从 Qualcomm 的分支构建：

$ git clone https://github.com/qualcomm/qemu.git -b hexagon-sysemu-22-may-2026 qemu-hexagon
$ cd qemu-hexagon
$ mkdir build && cd build
$ ../configure --target-list=hexagon-softmmu --disable-werror
$ make -j$(nproc)

生成的二进制文件是当前所在 build 目录中的 qemu-system-hexagon。将 QEMU_BIN_PATH 指向该目录，即可选用它而不是自带的版本：

$ export QEMU_BIN_PATH="$PWD"

第 3 步：安装 Hexagon SDK

loadlinux 引导加载程序需要 Hexagon SDK，它提供 hexagon-clang 及相关工具。下载并解压 SDK 压缩包：

$ curl -LO https://github.com/snapdragon-toolchain/hexagon-sdk/releases/download/v6.4.0.2/hexagon-sdk-v6.4.0.2-amd64-lnx.tar.xz
$ tar -xf hexagon-sdk-v6.4.0.2-amd64-lnx.tar.xz -C /opt/hexagon-sdk
$ export HEXAGON_SDK_ROOT=/opt/hexagon-sdk/6.4.0.2
$ export HEXAGON_TOOLS_ROOT=$HEXAGON_SDK_ROOT/tools/HEXAGON_Tools/19.0.04
$ export PATH=$HEXAGON_TOOLS_ROOT/Tools/bin:$PATH

确认可以访问 SDK 工具链：

$ hexagon-clang --version

第 4 步：构建 Hexagon Hypervisor 引导加载程序

Zephyr 必须作为客户机运行在 Hexagon VM（H2）hypervisor 之下。hypervisor 仓库中的 loadlinux 二进制文件用作 QEMU 的 -bios 参数，由它加载并启动 Zephyr ELF。

克隆 hypervisor 仓库并检出所需的标签。直接克隆到 $ZEPHYR_BASE 下，Zephyr 构建系统就能自动找到 loadlinux：

$ git clone https://github.com/androm3da/hexagon-hypervisor.git \
      $ZEPHYR_BASE/hexagon-hypervisor
$ cd $ZEPHYR_BASE/hexagon-hypervisor
$ git checkout h2-bcain-1-june-2026

先构建 H2 hypervisor 库。NULL_ANGEL_TRAP=1 会禁用 angel 半主机（semihosting）处理程序，否则它会导致 QEMU virt 机器无提示地挂起：

$ ARCHV=73
$ make USE_PKW=0 ARCHV=$ARCHV TARGET=opt NULL_ANGEL_TRAP=1 -j$(nproc)

然后在 linux/ 子目录中构建 loadlinux。makefile 的默认构建路径是 ../install 和 ../kernel，但上一步的产物位于 artifacts/v${ARCHV}/opt/。在调用 make 之前导出正确的路径：

$ export INSTALLPATH=$(pwd)/artifacts/v${ARCHV}/opt/install
$ export KERNELPATH=$(pwd)/artifacts/v${ARCHV}/opt/build/kernel
$ make -C linux USE_PKW=0 ARCHV=$ARCHV NO_LOAD=1 \
      NULL_ANGEL_TRAP=1 LINUX_LINK_ADDR=0xa0000000 loadlinux

生成的 linux/loadlinux 通过 -bios 参数传给 QEMU。Zephyr 构建系统默认在 $ZEPHYR_BASE/hexagon-hypervisor/linux/loadlinux 查找它。可以通过设置 HEXAGON_H2_LOADLINUX 环境变量，或向 CMake 传递 -DHEXAGON_H2_LOADLINUX=<path> 来覆盖该路径。

第 5 步：设置 Zephyr 环境

按照标准的 入门指南 指南安装 Zephyr 依赖项并初始化工作区。

创建 Python 3.12 虚拟环境，在其中安装 west 和 Zephyr Python 依赖，然后激活该环境：

$ python3.12 -m venv ~/zephyr-venv
$ ~/zephyr-venv/bin/pip install west
$ ~/zephyr-venv/bin/pip install -r $ZEPHYR_BASE/scripts/requirements.txt
$ source ~/zephyr-venv/bin/activate

加载（source）Zephyr 环境脚本：

$ source $ZEPHYR_BASE/zephyr-env.sh

构建

为此开发板构建 Zephyr 应用程序。由于 Hexagon 使用 LLVM 交叉编译器而不是 Zephyr SDK 构建，必须显式指定工具链：

# From the root of the zephyr repository
west build -b qemu_hexagon/qemu_hexagon_virt samples/hello_world -- -DZEPHYR_TOOLCHAIN_VARIANT=hexagon -DHEXAGON_TOOLCHAIN_PATH=/opt/hexagon-toolchain

备注

将 /opt/hexagon-toolchain 替换为第 1 步中设置的 $HEXAGON_TOOLCHAIN_PATH 的实际值。如果已导出第 1 步中的环境变量，这两个参数都可以省略。

构建会生成 zephyr.elf，它既用于调试，也由 hypervisor 在运行时加载。

运行

如果 loadlinux 位于默认路径，可以这样运行：

$ west build -t run

如需手动运行，请显式传入 QEMU 二进制文件和 loadlinux 引导加载程序的路径：

$ qemu-system-hexagon \
    -machine virt -nographic -m 4G \
    -bios path/to/hexagon-hypervisor/linux/loadlinux \
    -device loader,file=build/zephyr/zephyr.elf

将 path/to/hexagon-hypervisor/linux/loadlinux 替换为第 3 步中得到的 loadlinux 二进制文件的实际路径。

按 CTRL+A x 退出 QEMU。

samples/hello_world 的预期输出：

*** Booting Zephyr OS build v4.x.x ***
Hello World! qemu_hexagon/qemu_hexagon_virt

调试

请参阅 应用程序调试 的详细概述。

QEMU 支持通过 GDB 远程串行协议进行远程调试。使用 -s -S 参数启动 QEMU，可以暂停执行并在 1234 端口等待调试器连接：

$ qemu-system-hexagon \
    -machine virt -nographic -m 4G \
    -bios path/to/hexagon-hypervisor/linux/loadlinux \
    -device loader,file=build/zephyr/zephyr.elf \
    -s -S

使用 LLDB 连接目标。GDB 不支持 Hexagon ISA：

$ lldb build/zephyr/zephyr.elf
(lldb) gdb-remote 1234
(lldb) b main
(lldb) continue
