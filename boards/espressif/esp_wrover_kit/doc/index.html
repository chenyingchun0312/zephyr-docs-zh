ESP-WROVER-KIT

Board Overview

Name:
esp_wrover_kit
Vendor:

Espressif Systems

Status:

Not actively maintained

Architecture:

xtensa

SoC:

esp32

Browse board sources

概述

ESP-WROVER-KIT 集成了以下组件：

  • ESP32-WROVER-E 模块

  • LCD 屏幕

  • MicroSD 卡槽

它的另一个显著特点是内嵌 FTDI FT2232HL 芯片，这是一款先进的多接口 USB 桥接芯片。借助该芯片，可以通过 USB 接口使用 JTAG 直接调试 ESP32，而无需单独的 JTAG 调试器。ESP-WROVER-KIT 让开发变得方便、简单且经济。

ESP32 的大部分 I/O 引脚都引出到开发板的排针上，便于使用。

备注

ESP32 的 GPIO16 和 GPIO17 用作 PSRAM 的片选和时钟信号。为确保性能可靠，默认情况下这两个 GPIO 没有引出到开发板的排针上。

更多信息请参阅 ESP32-WROVER-E Datasheet [6] 和 ESP32 Datasheet [1]。

硬件

ESP32 特性

  • 双核 Xtensa 微处理器（LX6），主频 160 或 240MHz

  • 520KB of SRAM

  • 802.11b/g/n/e/i

  • Bluetooth v4.2 BR/EDR 和 BLE

  • 其他外设：

    • 12 位 ADC，最多 18 个通道

    • 2 个 8 位 DAC

    • 10 个触摸传感器

    • 4x SPI

    • 2x I2S

    • 2x I2C

    • 3x UART

    • SD/SDIO/MMC 主机

    • 从机（SDIO/SPI）

    • 以太网 MAC

    • CAN 总线 2.0

    • IR (RX/TX)

    • 电机 PWM

    • LED PWM，最多 16 个通道

    • 霍尔效应传感器

    • 温度传感器

  • 加密硬件加速（RNG、ECC、RSA、SHA-2、AES）

  • 5uA 深度睡眠电流

非对称多处理（AMP）

搭载 ESP32 和 ESP32-S3 SoC 的开发板可以运行两个不同的应用程序。得益于双核架构，每个核都可以独立运行定制任务，和/或通过 OpenAMP 框架交换数据。代码参考见 Inter-Processor Communication (IPC) 目录。

备注

** AMP 与串口输出支持 **

在当前的 Zephyr ESP32 实现中，运行在 APPCPU 上的应用程序尚不能使用由 Zephyr 管理的串口驱动（例如 printk()、日志或控制台 UART）。因此，Zephyr 提供的串口输出 API 只能在 PROCPU 上使用。

作为变通方法，运行在 APPCPU 上的应用程序可以使用 ets_printf() 等 ESP32 ROM 函数输出诊断或调试信息。

更多信息请参阅 ESP32 Datasheet [1] 或 ESP32 Technical Reference Manual [2]。

关键组件

说明

FT2232

FT2232 芯片用作多协议 USB 转串口桥接器，可通过 USB 编程和控制，以便与 ESP32 通信。FT2232 还提供 USB 转 JTAG 接口，位于芯片的通道 A，而 USB 转串口位于通道 B。FT2232 芯片让应用程序的开发和调试更加方便。参见 ESP-WROVER-KIT V4.1 原理图。

32.768 kHz

外部高精度 32.768 kHz 晶体振荡器在芯片处于 Deep-sleep 模式时用作低功耗时钟。

0R

零欧姆电阻，作为电流分流电阻的占位元件，可以拆焊或替换为分流电阻，以便测量 ESP32 在不同模式下的电流消耗。

ESP32-WROVER-E 模块

该 ESP32 模组带有 64-Mbit PSRAM，提供灵活的扩展存储和数据处理能力。

诊断 LED

四个连接到 FT2232 GPIO 引脚的红色 LED，留作将来使用。

UART

串口。FT2232 和 ESP32 的串行 TX/RX 信号分别引出到 JP2 的内侧和外侧。默认情况下，这些引脚对通过跳线帽连接。要使用 ESP32 的串行接口，请取下跳线帽，并将其他外部串行设备连接到相应的引脚。

SPI

默认情况下，ESP32 使用其 SPI 接口访问模块内的 Flash 和 PSRAM 存储器。可以使用这些引脚将 ESP32 连接到其他 SPI 设备，这种情况下需要额外的片选（CS）信号。请注意，该接口的电压为 3.3 V。

CTS/RTS

串口流控信号：默认情况下这些引脚未连接到电路。要启用它们，请用跳线帽短接 JP14 的相应引脚。

JTAG

JTAG 接口。FT2232 和 ESP32 的 JTAG 信号分别引出到 JP2 的内侧和外侧。默认情况下，这些引脚对是断开的。要启用 JTAG，请按照 设置选项 一节所示，用跳线帽短接相应的引脚

USB 端口

USB 接口。既为开发板供电，也是计算机与开发板之间的通信接口。

EN 按键

复位按键。

BOOT 按键

下载按键。按住 Boot 再按下 EN，即可进入固件下载模式，通过

电源开关

电源开关。朝 Boot 按键方向拨动为开发板上电，背离 Boot 方向拨动则断电。

电源选择器

电源选择接口。开发板可以通过 USB 或 5V 输入接口供电，用跳线帽选择电源。详见“设置选项”一节中的跳线排针 JP7。

5V 输入

5V 电源接口，适用于 5.5 x 2.1 mm、中心为正极的标准同轴电源连接器。当开发板独立运行（未连接计算机）时，使用该接口会更加方便。

5V 电源指示 LED

当开发板通过 USB 或 5V 输入供电时，该红色 LED 点亮。

LDO

NCP1117(1A)。5V 转 3.3V 的 LDO。NCP1117 最大可提供 1A 电流。板上 LDO 的输出电压是固定的，但用户也可以换装输出电压可调的 LDO。详情请参阅 ESP-WROVER-KIT V4.1 原理图。

摄像头连接器

摄像头接口，适用于标准 OV7670 摄像头模块。

RGB LED

红、绿、蓝（RGB）发光二极管（LED），可通过脉冲宽度调制（PWM）控制。

I/O 连接器

ESP32 模块的所有引脚都引出到排针上。可以对 ESP32 编程以启用多种功能，例如 PWM、ADC、DAC、I2C、I2S、SPI 等。

MicroSD 卡槽

便于开发访问 MicroSD 卡以存储和读取数据的应用程序。

LCD

支持安装并连接 3.2” SPI（标准 4 线串行外设接口）LCD，如图 ESP-WROVER-KIT 开发板布局 - 背面 所示

ESP32 引脚分配

ESP32 的部分引脚/端子分配给板载或外部硬件使用。如果未使用这些硬件，例如摄像头（JP4）排针上没有插入任何设备，则这些 GPIO 可用于其他用途。

部分引脚（例如 GPIO0 或 GPIO2）具有多种功能，其中一些由板载和外部外设共用。某些外设组合无法同时工作。例如，无法对使用 SD 卡的应用程序进行 JTAG 调试，因为 JTAG 和 SD 卡槽共用了多个引脚。

在其他情况下，外设可以在一定条件下共存。例如 LCD 屏幕和 SD 卡只共用一个引脚 GPIO21。该引脚既为 LCD 提供 D/C（数据/控制）信号，又用于读取 SD 卡槽的卡检测信号。如果卡检测功能不是必需的，可以拆除 R167 将其禁用，这样 LCD 和 SD 卡就可以同时工作。

有关哪些引脚由哪些外设共用的更多详细信息，请参阅下一节中的表格。

简单引导

开发板可以直接加载单个二进制镜像，无需二级引导加载程序。在不做额外配置的情况下构建应用程序时，这是默认选项。

备注

简单引导不提供任何安全功能，也不支持 OTA 更新。

MCUboot 引导加载程序

用户也可以改用 MCUboot 引导加载程序。这种情况下，必须至少构建（并烧录）一次引导加载程序。

构建应用程序时有两种方式可选：

  1. Sysbuild

  2. 手动构建

备注

用户可以在开发板默认配置文件中添加以下一行来选用 MCUboot 引导加载程序。

CONFIG_BOOTLOADER_MCUBOOT=y

Sysbuild

借助 sysbuild，可以构建并烧录在搭载 ESP32 SoC 的开发板上完成引导所需的全部镜像。

要使用 sysbuild 构建示例应用程序，请使用以下命令：

west build -b <board> --sysbuild samples/hello_world

默认情况下，ESP32 sysbuild 会生成引导加载程序（MCUboot）镜像和应用程序镜像，但也可以配置为生成其他类型的镜像。

sysbuild 创建的构建目录结构与传统 Zephyr 构建不同。输出按域（domain）子目录组织：

build/
├── hello_world
│   └── zephyr
│       ├── zephyr.elf
│       └── zephyr.bin
├── mcuboot
│    └── zephyr
│       ├── zephyr.elf
│       └── zephyr.bin
└── domains.yaml

备注

使用 --sysbuild 选项时，每次进行全新（pristine）构建都会重新构建并重新烧录引导加载程序。

有关系统构建的更多信息，请阅读 Sysbuild（系统构建） 文档。

手动构建

在开发过程中，通常希望尽可能快地完成构建和烧录。为此，可以使用传统构建方式逐个构建镜像。

以下说明同时适用于手动构建和 sysbuild，唯一的区别在于构建目录的结构。

备注

请记住，引导加载程序（MCUboot）至少需要烧录一次。

按常规方式构建并烧录应用程序（详见 构建应用程序 和 运行应用程序）。

# From the root of the zephyr repository
west build -b <board> samples/hello_world

常规的 flash 目标可直接用于该开发板配置。以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b <board> samples/hello_world
west flash

备注

在提供内置 USB Serial/JTAG 控制器的目标上，执行 west flash 后芯片可能停留在下载模式，在重新上电之前不会启动新镜像。如果出现这种情况，请使用看门狗复位进行烧录，使芯片自行重启：

west flash --reset-type watchdog-reset

更快的烧录

为了加快开发周期，--esp-skip-flashed 会在 Flash 中已有的二进制文件与待烧录的文件一致时跳过写入，一致性通过在设备上进行 MD5 校验来确认：

west flash --esp-skip-flashed

如需更快地重新烧录，--esp-diff 只写入与上次烧录的镜像不同的区域。它与本地缓存的副本进行比较，而不是读取设备，因此仅当自上次 west flash 以来 Flash 未被其他工具、开发板或手动写入修改过时才可使用：

west flash --esp-diff

可以关闭进度输出以使日志更简洁，这在 CI 中很有用：

west flash --esp-no-progress

使用以下命令打开串口监视器：

west espressif monitor

开发板自动复位并启动后，监视器中应显示以下信息：

***** Booting Zephyr OS vx.x.x-xxx-gxxxxxxxxxxxx *****
Hello World! <board>

使用代码片段（snippet）的开发板变体

ESP32 开发板可以搭配不同的模组，组合出多种 SPI Flash 容量、PSRAM 容量和 PSRAM 模式。snippets/espressif 下的代码片段提供了一种模块化方式，可在构建时应用这些变体，而无需重复编写开发板定义。

支持以下基于代码片段的变体：

代码片段名称

说明

Flash memory size

espressif-flash-4M

配备 4MB Flash 的开发板

espressif-flash-8M

配备 8MB Flash 的开发板

espressif-flash-16M

配备 16MB Flash 的开发板

espressif-flash-32M

配备 32MB Flash 的开发板

espressif-flash-64M

配备 64MB Flash 的开发板

espressif-flash-128M

配备 128MB Flash 的开发板

PSRAM memory size

espressif-psram-2M

配备 2MB PSRAM 的开发板

espressif-psram-4M

配备 4MB PSRAM 的开发板

espressif-psram-8M

配备 8MB PSRAM 的开发板

PSRAM utilization

espressif-psram-reloc

将 Flash 内容重定位到 PSRAM

espressif-psram-wifi

将 Wi-Fi 缓冲区放在 PSRAM 中

要应用某个开发板变体，请在 west build 中使用 -S 参数：

west build -b <board> -S espressif-flash-32M -S espressif-psram-4M samples/hello_world

备注

这些代码片段仅适用于硬件支持所选 Flash/PSRAM 配置的开发板。

  • 如果未使用 FLASH 代码片段，则使用开发板默认的 Flash 容量。

  • 如果未使用 PSRAM 代码片段，则使用开发板默认的 PSRAM 容量。

调试

OpenOCD 调试

Espressif 芯片需要使用带有 ESP32 专用补丁的定制版 OpenOCD。请从 OpenOCD for ESP32 [3] 下载最新版本。

详细的 JTAG 设置说明请参阅 JTAG debugging for ESP32 [5]。

Zephyr 线程感知

OpenOCD 支持 Zephyr RTOS 线程感知，使 GDB 能够：

  • 使用 info threads 列出所有线程

  • 显示线程名称、优先级和状态

  • 在不同线程上下文之间切换

  • 显示任意线程的回溯（backtrace）

Requirements:

  • OpenOCD ESP32 v0.12.0-esp32-20251215 [4] 或更高版本

  • 构建时启用 CONFIG_DEBUG_THREAD_INFO=y

Example:

# From the root of the zephyr repository
west build -b <board> samples/hello_world -- -DCONFIG_DEBUG_THREAD_INFO=y -DOPENOCD=<path/to/bin/openocd> -DOPENOCD_DEFAULT_PATH=<path/to/openocd/share/openocd/scripts>
west debug

使用自定义 OpenOCD

Zephyr SDK 自带 OpenOCD，但可能不支持 ESP32。要使用 Espressif OpenOCD，请在构建时指定其路径：

# From the root of the zephyr repository
west build -b <board> samples/hello_world -- -DOPENOCD=/path/to/openocd -DOPENOCD_DEFAULT_PATH=/path/to/openocd/scripts
west debug

在 ESP-WROVER-KIT 开发板上，JTAG 引脚在内部连接到与控制台位于同一设备上的 USB 串口。这些开发板无需外部硬件即可直接调试。不过，必须用跳线帽短接 JTAG 信号才能连接内部控制器（默认是断开的）。从电源开关一侧看，这些跳线排针位于开发板右侧，旁边是 SPI 和 UART 的类似排针。详见 ESP-WROVER-32 V3 Getting Started Guide [7]。
