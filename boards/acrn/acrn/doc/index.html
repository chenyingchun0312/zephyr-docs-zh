ACRN 虚拟机监控程序

Zephyr 能够作为客户机运行在 x86 ACRN 虚拟机监控程序（hypervisor）之上（参见 https://projectacrn.org/）。不过，实现这一点的过程相对复杂。

ACRN 虚拟机监控程序支持一种混合场景，其中 Zephyr 以所谓的“预启动”（pre-launched）模式运行。这意味着 Zephyr 将直接访问 ACRN 虚拟机监控程序，而不经过 SOS VM。这是现实中最实用的用户场景，因为 Zephyr 的实时性和安全能力可以得到保证，不受其他 VM 的影响。下图摘自 ACRN 官方文档，展示了混合场景的工作方式：

本教程将演示如何构建一个最小的 Zephyr 与 ACRN 虚拟机监控程序运行实例，以证明其可以正常工作。要了解 ACRN 的其他功能，例如构建和使用 SOS VM 或其他客户机 VM，请参阅 ACRN 入门指南：https://projectacrn.github.io/latest/tutorials/using_hybrid_mode_on_nuc.html

构建 Zephyr 应用程序

首先，像平常一样构建要在 ACRN 中运行的 Zephyr 应用程序，并选择合适的开发板：

west build -b acrn_ehl_crb samples/hello_world

本教程使用 Intel Elkhart Lake 参考板（EHL CRB），因为它是此类场景的推荐平台之一。使用 acrn_ehl_crb 作为目标开发板参数。

注意 build/zephyr/.config 中的 Kconfig 输出，稍后配置 ACRN 时需要参考它。

需要的 Zephyr 构建产物是 build/zephyr/zephyr.bin，它是一个原始内存镜像。与其他 x86 目标不同，这里不应使用 zephyr.elf！

配置并构建 ACRN

首先需要获取源代码，从以下地址克隆：

git clone https://github.com/projectacrn/acrn-hypervisor

建议使用 v2.5.1 或更高版本的 ACRN 虚拟机监控程序，因为这些版本对 Zephyr 中 SMP 的支持更好。

与 Zephyr 一样，ACRN 倾向于在构建时进行配置管理，而不是在运行时探测或控制。与 Zephyr 不同的是，ACRN 使用单个大型配置文件，而不是像 Kconfig defconfig 文件或设备树 include 那样易于合并的小型配置单元。需要编辑一个很大的 XML 文件来匹配 Zephyr 配置。选择与硬件匹配的 ACRN 主机配置（本例中为 "ehl-crb-b"），然后找到对应的文件 misc/config_tools/data/<platform>/hybrid.xml。

首先，找到 <vm> 声明列表。每个声明都有一个 id= 属性。测试 Zephyr 时，应确保 Zephyr 镜像的 ID 为零。这样只需一个 VM 镜像即可启动 ACRN，避免将大型 Linux 二进制文件无谓地复制到引导文件系统中。在当前测试过的配置下，Zephyr 的 "vm_type" 标签始终为 "SAFETY_VM"。

配置 Zephyr 内存布局

接下来，确定 Zephyr 镜像的加载地址及其入口点地址。这些地址必须在 ACRN 中手动配置。Zephyr 传统上以 ELF 镜像形式发布，可以从中自动提取这些地址，但 ACRN 不支持这样做，它只能将单个连续的数据区域加载到内存中并跳转到指定地址。

找到 "<vm id="0">...<os_config>" 标签，其内容类似如下：

<os_config>
    <name>Zephyr</name>
    <kern_type>KERNEL_ZEPHYR</kern_type>
    <kern_mod>Zephyr_RawImage</kern_mod>
    <ramdisk_mod/>
    <bootargs></bootargs>
    <kern_load_addr>0x1000</kern_load_addr>
    <kern_entry_addr>0x1000</kern_entry_addr>
</os_config>

kern_load_addr 标签必须与 include/arch/x86/memory.ld 中的 Zephyr LOCORE_BASE 符号一致。该值目前为 0x1000，与 ACRN 默认配置相符。

kern_entry_addr 标签必须与构建出的 zephyr.elf 文件中的入口点一致。可以使用 binutils 查找，例如：

$ objdump -f build/zephyr/zephyr.elf

build/zephyr/zephyr.elf:     file format elf64-x86-64
architecture: i386:x86-64, flags 0x00000012:
EXEC_P, HAS_SYMS
start address 0x0000000000001000

默认情况下，该入口地址同样为 0x1000。但并非所有配置都一直如此，将来也可能会改变。

配置 Zephyr CPU

现在需要配置 ACRN 提供给客户机的 CPU 环境。Zephyr 默认以 SMP 模式构建，但 ACRN 的默认配置只为其分配一个 CPU。在 Zephyr 的 .config 文件中找到 CONFIG_MP_MAX_NUM_CPUS 的值，并在 <cpu_affinity> 标签中为客户机分配相同数量的 CPU。例如：

<vm id="0">
    <vm_type>SAFETY_VM</vm_type>
    <name>ACRN PRE-LAUNCHED VM0</name>
    <guest_flags>
        <guest_flag>0</guest_flag>
    </guest_flags>
    <cpu_affinity>
        <pcpu_id>0</pcpu_id>
        <pcpu_id>1</pcpu_id>
    </cpu_affinity>
    ...
    <clos>
        <vcpu_clos>0</vcpu_clos>
        <vcpu_clos>0</vcpu_clos>
    </clos>
    ...
</vm>

要使用 SMP，必须将 VM0 的 pcpu_id 改为 0 和 1，从而让 ACRN 在 CPU0 和 CPU1 上运行 Zephyr。不做此修改，ACRN 虚拟机监控程序和 Zephyr 应用程序将无法成功启动。如果计划只用一个 CPU 运行 Zephyr，可以跳过此步骤。

由于 Zephyr 使用 CPU0 和 CPU1，还必须修改 VM1 的配置，使其运行在 CPU2 和 CPU3 上。如果 ACRN 环境中还有其他 VM，也应相应修改它们的配置。

<vm id="1">
    <vm_type>SOS_VM</vm_type>
    <name>ACRN SOS VM</name>
    <guest_flags>
        <guest_flag>0</guest_flag>
    </guest_flags>
    <cpu_affinity>
        <pcpu_id>2</pcpu_id>
        <pcpu_id>3</pcpu_id>
    </cpu_affinity>
    <clos>
        <vcpu_clos>0</vcpu_clos>
        <vcpu_clos>0</vcpu_clos>
    </clos>
    ...
</vm>

注意，这些序号是主机上的物理 CPU。配置多个客户机时，通常不希望这些分配与其他客户机重叠。但测试 Zephyr 时，只使用 CPU 0 和 1 即可正常工作。（注意 ehl-crb-b 有四个物理 CPU，因此配置全部 0-3 也能正常工作，但这样就没有空余 CPU 可专门分配给其他客户机了。）

构建 ACRN

配置完成后，ACRN 的构建过程相当顺利：

$ make -j BOARD=ehl-crb-b SCENARIO=hybrid

唯一需要的构建产物是 build/hypervisor/acrn.bin 中的 ACRN multiboot 镜像

制作 EFI 启动介质

ACRN 通过 GNU GRUB 引导加载程序在硬件上启动，而 GRUB 本身由 EFI 固件启动。两者都需要正确配置。

获取 GRUB

首先，需要一个与硬件相匹配的 GRUB EFI 二进制文件。很多情况下，直接从上游源码构建，或从合适的 Linux 发行版中复制一份即可。但有些情况下不行，需要针对特定硬件给 GRUB 打补丁。请联系硬件支持团队（此处应有笑声），获取构建可用 GRUB 的明确说明。实际上，可能只需四处问问，从别人上次测试成功的环境中复制一个二进制文件即可。

创建 EFI 启动文件系统

现在将启动介质（例如位于 /dev/sdb 的 U 盘，具体硬件可能不同！）连接到 Linux 系统，并创建一个足以存放启动文件的 EFI 启动分区（类型代码 0xEF）。下面的命令直接将相关命令传给 fdisk，也可以手动输入这些命令：

# for i in n p 1 "" "" t ef w; do echo $i; done | fdisk /dev/sdb
...
<lots of fdisk output>

现在在新分区中创建 FAT 文件系统并挂载：

# mkfs.vfat -n ACRN_ZEPHYR /dev/sdb1
# mkdir -p /mnt/acrn
# mount /dev/sdb1 /mnt/acrn

复制镜像并配置 GRUB

ACRN 自身无法访问运行时文件系统。它以 GRUB "multiboot" 模块的形式接收客户机 VM（即 zephyr.bin），因此必须依赖 GRUB 的文件系统驱动。三个文件（GRUB、ACRN 和 Zephyr）都需要复制到启动介质的 "/efi/boot" 目录中。注意，GRUB 必须命名为 "bootx64.efi"，固件才能将其识别为引导加载程序：

# mkdir -p /mnt/acrn/efi/boot
# cp $PATH_TO_GRUB_BINARY /mnt/acrn/efi/boot/bootx64.efi
# cp $ZEPHYR_BASE/build/zephyr/zephyr.bin /mnt/acrn/efi/boot/
# cp $PATH_TO_ACRN/build/hypervisor/acrn.bin /mnt/acrn/efi/boot/

启动时，GRUB 会加载 "efi/boot/grub.cfg" 文件以获取运行时配置指令（讽刺的是，ACRN 和 Zephyr 都没有这项功能！）。该文件需要将 acrn.bin 作为启动目标加载，并将 zephyr.bin 文件作为其第一个模块传入（因为上面将 Zephyr 配置为 <vm id="0">）。除极个别特殊硬件外，这个最小配置都能正常工作（"hd0" 几乎总是 GRUB 被加载时所在的启动文件系统），无需折腾 GRUB 插件、菜单或超时设置：

# cat > /mnt/acrn/efi/boot/grub.cfg<<EOF
set root='hd0,msdos1'
multiboot2 /efi/boot/acrn.bin
module2 /efi/boot/zephyr.bin Zephyr_RawImage
boot
EOF

至此文件系统已准备完毕

# umount /dev/sdb1
# sync

启动 ACRN

如果一切顺利，在硬件上从 EFI 介质启动后，ACRN 和 Zephyr 都会运行起来（因为 Zephyr 默认配置为“预启动”VM），控制台上会出现可用的 ACRN 命令行。

可以使用 "vm_console" 命令查看 Zephyr（vm 0）的控制台输出：

ACRN:\>vm_console 0

----- Entering VM 0 Shell -----
*** Booting Zephyr OS build v2.6.0-rc1-324-g1a03783861ad  ***
Hello World! acrn
