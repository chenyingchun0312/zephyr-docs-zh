NEORV32

Board Overview

Name:
neorv32
Vendor:

Other/Unknown

Status:

Not actively maintained

Architecture:

riscv

SoC:

neorv32

Browse board sources

概述

NEORV32 是一个开源的 RISC-V 兼容处理器系统，可作为较大 SoC 设计中即用型的辅助处理器，也可作为独立的可定制微控制器。

有关 NEORV32 的更多信息，请访问以下网站：

  • The NEORV32 RISC-V Processor GitHub

  • The NEORV32 RISC-V Processor Datasheet

  • The NEORV32 RISC-V Processor User Guide

当前支持的版本为 NEORV32 v1.11.6。

支持的开发板目标

Zephyr 支持以下 NEORV32 开发板目标：

  • neorv32/neorv32/minimalboot

  • neorv32/neorv32/up5kdemo

每个目标都对应 NEORV32 RTL 附带的一个 NEORV32 处理器模板。可以使用 开发板扩展 或 设备树覆盖文件 在树外定制这些开发板目标，以匹配自定义的 NEORV32 实现。

支持的功能

Zephyr 支持以下 NEORV32 功能。这些功能已为受支持的开发板目标预先配置，但也可以定制以匹配自定义的 NEORV32 实现。

系统时钟

默认开发板配置从 NEORV32 SYSINFO 模块读取系统时钟频率，这会带来少量运行时开销。如果在构建时已知时钟频率，可以通过设置 cpu0 设备树节点的 clock-frequency 属性来覆盖此行为。

CPU

SoC 配置假定 NEORV32 CPU 实现启用了以下 RISC-V ISA 扩展：

  • Zicntr（基础计数器和定时器扩展）

  • Zicsr（控制和状态寄存器（CSR）指令，始终启用）

  • Zifencei（取指屏障，始终启用）

可以通过相应修改 cpu0 节点的 riscv,isa-extensions 设备树属性来启用其他受支持的 RISC-V ISA 扩展。

内核本地中断器

NEORV32 内核本地中断器（CLINT）及其机器定时器（MTIMER）已获支持，但默认禁用。对于支持它们的 NEORV32 SoC 实现，可以将 clint 和 mtimer 设备树节点的 status 属性设置为 okay 来启用支持。

内部指令存储器

用于执行代码的内部指令存储器（IMEM）已获支持，但默认禁用。对于支持 IMEM 的 NEORV32 SoC 实现，可以通过 imem 设备树节点的 reg 属性设置其大小，并将其 status 属性设置为 okay 来启用支持。

内部数据存储器

内部数据存储器（DMEM）已获支持，但默认禁用。对于支持 DMEM 的 NEORV32 SoC 实现，可以通过 dmem 设备树节点的 reg 属性设置其大小，并将其 status 属性设置为 okay 来启用支持。

串口

NEORV32 串口（UART0 和 UART1）已获支持，但默认禁用。对于支持其中任一 UART 的 NEORV32 SoC 实现，可以将 uart0 和/或 uart1 设备树节点的 status 属性设置为 okay 来启用支持。

备注

开发板目标在 UART0 上提供控制台，波特率为 19200，与标准 NEORV32 引导加载程序一致。可以通过修改 uart0 设备树节点的 current-speed 属性来更改波特率。

通用输入/输出

NEORV32 GPIO 端口已获支持，但默认禁用。对于支持 GPIO 的 NEORV32 SoC 实现，可以将 gpio 设备树节点的 status 属性设置为 okay 来启用支持。可以通过 ngpios 设备树属性设置支持的 GPIO 数量。

脉宽调制

NEORV32 PWM 控制器已获支持，但默认禁用。对于支持 PWM 的 NEORV32 SoC 实现，可以将 pwm 设备树节点的 status 属性设置为 okay 来启用支持。

真随机数发生器

NEORV32 的真随机数发生器（TRNG）已获支持，但默认禁用。对于支持 TRNG 的 NEORV32 SoC 实现，可以将 trng 设备树节点的 status 属性设置为 okay 来启用支持。

通用定时器

NEORV32 的通用定时器（GPTMR）已获支持，但默认禁用。对于支持 GPTMR 的 NEORV32 SoC 实现，可以将 gptmr 设备树节点的 status 属性设置为 okay，并通过该节点的 prescaler 属性选择所需的 GPTMR 时钟预分频值来启用支持。

编程与调试

首先，按照 NEORV32 用户指南中的说明，用 NEORV32 比特流配置 FPGA。

然后按常规方式构建和烧录应用程序（详情参见 构建应用程序 和 运行应用程序）。

配置控制台

在你选用的串口终端（minicom、putty 等）中使用以下设置：

  • 速率：19200

  • 数据位：8 位

  • 校验位：无

  • 停止位：1

通过 JTAG 烧录

以下示例演示如何为 NEORV32 构建 Hello World 应用程序并通过 JTAG 烧录。通过 JTAG 烧录要求 NEORV32 SoC 实现启用片上调试器（OCD）和引导加载程序。

备注

如果未启用引导加载程序，内部指令存储器（IMEM）会被配置为 ROM，无法通过 JTAG 修改。

# From the root of the zephyr repository
west build -b neorv32/neorv32/<variant> samples/hello_world
west flash

默认开发板配置使用的 OpenOCD 调试主机工具 配置与 NEORV32 项目提供的示例类似。烧录时提供额外参数即可使用其他 JTAG。以下是使用 2 kHz Flyswatter JTAG 的示例：

# From the root of the zephyr repository
west build -b neorv32/neorv32/<variant> samples/hello_world
west flash --config interface/ftdi/flyswatter.cfg --config neorv32.cfg --cmd-pre-init 'adapter speed 2000'

烧录后，终端中应显示类似以下的信息：

*** Booting Zephyr OS build zephyr-vn.n.nn  ***
Hello World! neorv32/neorv32/<variant>

但请注意，上述步骤并未将应用程序持久保存到 Flash 中，只是将其写入了 FPGA 的内部块 RAM。下次配置 FPGA 时，它将恢复为 FPGA 比特流中块 RAM 存储的应用程序。

将应用程序固化到 FPGA 比特流中的步骤请参阅 NEORV32 用户指南。如果启用了 CONFIG_BUILD_OUTPUT_BIN，并且 NEORV32 image_gen 二进制程序可用，构建系统会自动生成适合初始化 NEORV32 内部指令存储器的 zephyr.vhd 文件。

为了让构建系统自动找到 image_gen 二进制程序，它必须位于 PATH 环境变量中。否则，可以在构建时传入其路径：

# From the root of the zephyr repository
west build -b neorv32/neorv32/<variant> samples/hello_world -- -DCMAKE_PROGRAM_PATH=<path/to/neorv32/sw/image_gen/>

通过 UART 上传

如果启用了 CONFIG_BUILD_OUTPUT_BIN，并且 NEORV32 image_gen 二进制程序可用，构建系统会自动生成 zephyr_exe.bin 文件，可按照 NEORV32 用户指南中的说明，通过内置引导加载程序上传到 NEORV32。

通过 JTAG 调试

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b neorv32/neorv32/<variant> samples/hello_world
west debug

在调试器中单步执行应用程序，终端中应显示类似以下的消息：

*** Booting Zephyr OS build zephyr-vn.n.nn  ***
Hello World! neorv32/neorv32/<variant>
