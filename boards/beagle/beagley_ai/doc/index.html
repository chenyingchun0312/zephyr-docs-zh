BeagleY-AI

Board Overview

Name:
beagley_ai
Vendor:

BeagleBoard.org Foundation

Status:

Not actively maintained

Architecture:

arm

SoC:

j722s

Browse board sources

概述

BeagleY-AI 是一个由 TI AM67A（J722S）SoC 驱动的计算平台，面向汽车应用。

硬件

BeagleY-AI 由 TI AM67A（J722S）SoC 驱动，该 SoC 有两个域（Main、MCU）。本文档概述在两个 Cortex R5 上运行的 Zephyr。

L1 存储系统

BeagleY-AI 的 R5 子系统默认采用单核模式。更改此模式会影响 L1 存储系统的配置。

  • 32KB 指令缓存

  • 32KB 数据缓存

  • 64KB 紧耦合存储器（TCM） * 32KB TCMA * 32KB TCMB

区域地址转换

RAT 模块执行基于区域的地址转换，将 32 位输入地址转换为 36 位输出地址。如果区域已启用，任何起始地址落在已编程区域内的输入事务都会进行地址转换。

VIM 中断控制器

VIM 汇集设备中断并将其发送给 R5F CPU。VIM 模块为每个 R5F 内核支持 512 个中断输入。每个中断可以是电平或脉冲（均为高电平有效）。VIM 为每个内核提供两个中断输出：IRQ 和 FIQ。

支持的功能

此开发板配置支持通过 HAT 排针引脚输出控制台 UART。未来的版本还将支持基于 RPmsg 的控制台。

运行 Zephyr

AM67A 没有为 R5 内核提供单独的 Flash。因此必须由 A53 内核将 R5 内核的程序加载到正确的内存地址，设置 PC 并启动处理器。这可以在 A53 内核上的 Linux 中通过 remoteproc 完成。

以下是从 A53 到 R5 可用内存的映射。注意，R5 内核看到的本地 TCMA 始终位于地址 0x00000000，TCMB0 位于地址 0x41010000。

A53 上的 Linux 配置在 DDR 中分配了一块与 R5 共享的区域。分配的大小可以在 Linux 设备树中修改。注意 BeagleY-AI 有 4GB DDR。

运行镜像的步骤

以下是针对 BeagleY-AI 上 MAIN 域 Cortex R5F 构建 Hello World 应用程序的示例：

# From the root of the zephyr repository
west build -b beagley_ai/j722s/main_r5f0_0 samples/hello_world

针对 BeagleY-AI 上的 MCU 域 Cortex R5F：

# From the root of the zephyr repository
west build -b beagley_ai/j722s/mcu_r5f0_0 samples/hello_world

加载镜像：

将 Zephyr 镜像复制到 /lib/firmware/ 目录。
cp build/zephyr/zephyr.elf /lib/firmware/

确保该内核未在运行。
echo stop > /dev/remoteproc/am67a-{main,mcu}-r5f0_0/state

为 remoteproc 模块配置镜像名称。
echo zephyr.elf > /dev/remoteproc/am67a-{main,mcu}-r5f0_0/firmware

配置好镜像名称后，发送 start 命令。
echo start > /dev/remoteproc/am67a-{main,mcu}-r5f0_0/state

Console

BeagleY-AI Cortex-R5F 上的 Zephyr 使用 UART 1（HAT 引脚 8-TX、10-RX）作为控制台。
