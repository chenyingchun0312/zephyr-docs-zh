BeagleBone AI-64

Board Overview

Name:
beaglebone_ai64
Vendor:

BeagleBoard.org Foundation

Status:

Not actively maintained

Architecture:

arm

SoC:

j721e

Browse board sources

概述

BeagleBone AI-64 是一个由 TI J721E SoC 驱动的计算平台，面向汽车应用。

硬件

BeagleBone AI-64 由 TI J721E SoC 驱动，该 SoC 有三个域（MAIN、MCU、WKUP）。本文档介绍 MAIN 域和 MCU 域 Cortex-R5F 内核上的 Zephyr。

L1 存储系统

  • 16 KB 指令缓存。

  • 16 KB 数据缓存。

  • 64 KB TCM.

区域地址转换

RAT 模块执行基于区域的地址转换，将 32 位输入地址转换为 48 位输出地址。如果区域已启用，任何起始于已编程区域内的输入事务，其地址都会被转换。

VIM 中断控制器

VIM 汇集设备中断并将其发送给 R5F CPU。VIM 模块为每个 R5F 内核支持 512 个中断输入。每个中断可以是电平或脉冲（均为高电平有效）。VIM 为每个内核提供两个中断输出：IRQ 和 FIQ。

运行 Zephyr

J721E 没有为 R5 内核提供单独的 Flash。因此，A72 内核必须将 R5 内核的程序加载到正确的内存地址，设置 PC 并启动处理器。这可以在 A72 内核上的 Linux 中通过 remoteproc 完成。

默认情况下，R5 的内存保护单元（MPU）只允许执行 ATCM/BTCM 中的指令。Linux 还为每个 R5 划出了几块 DRAM 内存区域，可用于 IPC（DDR0）和数据（DDR1）。对 MPU 编程后，DDR1 也可用作可执行区域。

下面是从 A72 到 R5 可用内存的内存映射。注意，R5 内核始终在地址 0x00000000 处看到本地 ATCM，在地址 0x41010000 处看到 BTCM（TRM 表 2-5）。remoteproc 使用的 ATCM/BTCM 从端口列于下表（Linux k3-j721e-main.dtsi）。当 正在运行的 Linux 设备树包含 k3-j721e-ti-ipc-firmware.dtsi 时，DDR 区域遵循该文件的定义；可在开发板上用 ls /proc/device-tree/reserved-memory/ 进行验证。

U-Boot 通常会在 Linux 之前启动 MCU R5FSS0 Core0，因此该内核在 remoteproc 中显示为 IPC-only / attached。要从 Linux 替换其固件，该内核必须处于 remoteproc 模式（而非后期附加），或者由引导加载程序将 Zephyr 作为 j7-mcu-r5f0_0-fw 加载。在默认的 BeagleBone AI-64 Linux 设备树中，两个 MCU 内核处于锁步模式（ti,cluster-mode = 1），因此在将集群切换到拆分模式之前，Core1 不是独立的 remoteproc 设备。

构建并运行镜像的步骤

以下是针对 BeagleBone AI-64 上某个 Cortex R5F 构建 Hello World 应用程序的示例：

# From the root of the zephyr repository
west build -b beaglebone_ai64/j721e/main_r5f0_0 samples/hello_world

加载镜像（以 R5FSS0 Core0 为例）：

将 Zephyr 镜像复制到 /lib/firmware/ 目录。
cp build/zephyr/zephyr.elf /lib/firmware/

确保该内核未在运行。
echo stop > /dev/remoteproc/j7-main-r5f0_0/state

为 remoteproc 模块配置镜像名称。
echo zephyr.elf > /dev/remoteproc/j7-main-r5f0_0/firmware

配置好镜像名称后，发送 start 命令。
echo start > /dev/remoteproc/j7-main-r5f0_0/state

对于 main_r5f0_1、main_r5f1_0、main_r5f1_1 以及 MCU 目标，请使用上表中对应的 remoteproc 路径。MCU Core0 通常已处于附加状态；只有当该内核处于 offline 状态后，echo start 才有效。

Console

main_r5f0_0 使用 UART2（Rx P8.22，Tx P8.34）作为 zephyr,console（TRM 表 2-1 中 UART2 位于 0x02820000，TRM 表 9-47 中为 VIM 160）。

其他 MAIN R5 目标和两个 MCU R5 目标可以通过覆盖文件配置 RPMsg UART 控制台。在 Linux 上，启用 RPMsg TTY 驱动（rpmsg_tty）并查找 /dev/ttyRPMSG*（绑定顺序取决于哪些内核正在运行）。
