Browse board sources

概述

UDOO Neo Full 是一款兼容 Arduino Uno 的开源单板计算机。它搭载 NXP® i.MX 6SoloX 混合多核处理器，该处理器由一个最高 1 GHz 的 ARM® Cortex-A9 内核和一个最高 227 MHz 的 Cortex-M4 内核组成，兼顾高 CPU 性能与实时响应。Zephyr 仅移植到了 Cortex-M4 内核上运行。在未来的版本中，它还将通过 OpenAMP 与（运行 Linux 的）Cortex-A9 内核通信。

硬件

  • MCIMX6X MCU，带一个 Cortex-A9（1 GHz）内核和一个 Cortex-M4（227 MHz）内核

  • 内存

    • 1 GB RAM

  • A9 启动设备

    • LVDS 显示屏连接器

    • 触摸（I2C 信号）

  • 多媒体

    • 集成 2D/3D 图形控制器

    • HDMI 音频发送器

  • 连接

    • 32x GPIO (A9)

系统时钟

MCIMX6X SoC 配置为使用开发板上的 24 MHz 外部振荡器，并通过片上 PLL 生成内核时钟。M4 内核的 PLL 设置由运行在 A9 内核上的代码完成。

串口

MCIMX6X SoC 有六个 UART。UART5 配置给 M4 内核使用，其余由 A9 内核使用或未使用。

M4 内核没有 Flash 存储器，并且上电复位时不会获得时钟，因此需要由 A9 内核启动。A9 内核负责将 M4 二进制应用程序加载到 RAM 中，使 M4 进入复位状态，设置 M4 的程序计数器和栈指针，然后使 M4 退出复位。A9 可以在引导加载程序阶段或 Linux 系统启动后执行这些步骤。

M4 内核最多可以使用 5 种不同的 RAM（安全 RAM 等其他类型的存储器目前尚未在 Zephyr 中实现）。以下是 A9 和 M4 的内存映射：

需要在编译时选择使用哪块 RAM。该配置在文件 boards/udoo/udoo_neo_full/udoo_neo_full_mcimx6x_m4.dts 中完成。

如果希望将代码放在某块存储器的子区域中（使用 DDR 时通常如此），请选择 "zephyr,flash=&flash"，并设置 DT_FLASH_SIZE 宏以确定区域大小，设置 DT_FLASH_ADDR 以确定区域的起始地址。

如果希望将数据放在某块存储器的子区域中（使用 DDR 时通常如此），请选择 "zephyr,sram = &sram"。

否则，请将 "zephyr,flash" 和/或 "zephyr,sram" 设置为以下预定义区域之一：

"zephyr,flash"
- &tcml
- &ocram_s
- &ocram
- &ddr

"zephyr,sram"
- &tcmu
- &ocram_s
- &ocram
- &ddr

下面介绍如何使用运行在 A9 内核上的 Linux 用户空间应用程序，在 M4 内核上加载并运行 Zephyr 应用程序。

UDOOBuntu Linux 发行版包含一个 udooneo-m4uploader [6] 工具，但其用途是加载 UDOO Neo 的“类 Arduino”程序（sketch），因此大多数情况下无法用于 Zephyr 应用程序。原因在于该工具与运行在 M4 内核上的程序之间会通过硬编码的共享内存位置交换信息。该工具写入一个标志，由运行在 M4 内核上的程序读取。随后该程序应安全结束，并将状态写入共享内存位置供主内核读取。接着该工具加载新的应用程序，并从共享内存位置读取其状态，以判断是否已成功启动。由于该功能是 UDOO Neo“类 Arduino”程序特有的，Zephyr 中并未实现。不过，如果计划与运行在 A9 内核上的 UDOOBuntu Linux 配合使用，Zephyr 应用程序可以自行支持该功能。udooneo-uploader 工具会调用另一个名为 mqx_upload_on_m4SoloX 的可执行文件，可以直接调用它来加载 Zephyr 应用程序。将 Zephyr 二进制镜像复制到 Linux 文件系统中，然后以 root 用户身份调用该工具：

mqx_upload_on_m4SoloX zephyr.bin

如果输出如下所示，说明 mqx_upload_on_m4SoloX 无法读取已停止应用程序的状态。如果之前加载的应用程序不是 UDOO Neo“类 Arduino”程序，并且忽略了共享内存通信，这是预期的情况：

UDOONeo - mqx_upload_on_m4SoloX 1.1.0
UDOONeo - Waiting M4 Stop, m4TraceFlags: 00000000
UDOONeo - Waiting M4 Stop, m4TraceFlags: 00000000
UDOONeo - Waiting M4 Stop, m4TraceFlags: 00000000
UDOONeo - Waiting M4 Stop, m4TraceFlags: 00000000
UDOONeo - Failed to Stop M4 sketch: reboot system !

在这种情况下，mqx_upload_on_m4SoloX 工具已重置跟踪标志，因此再次调用时会成功。此时可能会得到以下输出：

UDOONeo - mqx_upload_on_m4SoloX 1.1.0
UDOONeo - FILENAME = zephyr.bin; loadaddr = 0x84000000
UDOONeo - start - end (0x84000000 - 0x84080000)
UDOONeo - Waiting M4 Run, m4TraceFlags: 000001E0
UDOONeo - M4 sketch is running

如果该工具无法读取表示 M4 内核应用程序已启动的状态标志，则可能得到以下输出。这可以忽略，因为应用程序应该已经在运行，只是该工具不知道而已：

UDOONeo - mqx_upload_on_m4SoloX 1.1.0
UDOONeo - FILENAME = zephyr.bin; loadaddr = 0x84000000
UDOONeo - start - end (0x84000000 - 0x84080000)
UDOONeo - Waiting M4 Run, m4TraceFlags: 00000000
UDOONeo - Waiting M4 Run, m4TraceFlags: 00000000
UDOONeo - Waiting M4 Run, m4TraceFlags: 00000000
UDOONeo - Waiting M4 Run, m4TraceFlags: 00000000
UDOONeo - Failed to Start M4 sketch: reboot system !

栈指针和程序计数器的值从二进制文件中读取。二进制文件的放置地址由程序计数器的值向下按 64 KB 对齐计算得出，也可以作为第二个命令行参数提供：

mqx_upload_on_m4SoloX zephyr.bin 0x84000000

如果将二进制文件复制到在 A9 和 M4 内核上映射不同的存储区域，则必须提供该地址，因为根据二进制文件中栈指针值计算出的地址将是错误的。

可以修改 mqx_upload_on_m4SoloX 工具的源代码，使其不通过共享内存与 M4 内核应用程序交换信息。

也可以使用 imx-m4fwloader [7] 工具加载 M4 内核应用程序。

在 UDOOBuntu Linux 中适用的一种方法是将二进制文件复制到 Linux 文件系统中的 /var/opt/m4/m4last.fw 文件。下次系统启动时，Das U-Boot 会从该位置加载它。

另一种方法是直接使用 Das U-Boot 加载代码。

调试

UDOO Neo Full 开发板带有用于焊接 14 针 JTAG 连接器的焊盘。运行在 M4 内核上的 Zephyr 应用程序目前仅通过观察 UART 控制台输出进行过测试。
