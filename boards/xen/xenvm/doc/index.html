ARMv8 Xen 虚拟机示例

概述

此开发板可以在任何支持 ARM 虚拟化扩展的 ARMv8 开发板上将 Zephyr 作为 Xen 客户机运行。由于几乎每种虚拟机配置在许多方面都各不相同，这只是一个示例配置。

它提供了一组最基本的设备：

  • ARM 通用定时器

  • GICv2/GICv3

硬件

支持的功能

xenvm 开发板支持下列硬件功能。

说明

The list of supported hardware features was not generated. Run a full documentation build for the required metadata to be available.

设备

系统时钟

此开发板配置使用 8.32 MHz 的系统时钟频率。这是默认值，应根据用户的实际硬件进行修正。

可以通过查看 Xen 启动日志来确定 ARM 通用定时器的时钟频率：

(XEN) [    0.147541] Generic Timer IRQ: phys=30 hyp=26 virt=27 Freq: 8320 KHz
中断控制器

根据硬件上 GIC 的版本，可以选择以下开发板配置变体之一：

  • xenvm 选择 GICv2

  • xenvm//gicv3 选择 GICv3

CPU 内核类型

此配置中的默认内核为 Cortex A72。根据实际硬件，可能需要按照与中断控制器配置相同的方式修改此选项。

已知问题或限制

Xen 在运行时通过提供描述客户机环境的设备树来配置客户机。而 Zephyr 使用的是构建时就应确定的静态配置。因此，使用默认配置生成的 Zephyr 镜像有可能无法在你的硬件上启动。这种情况下，需要通过修改设备树和 Kconfig 选项来更新配置。下一节将对此进行详细介绍。

目前大部分 Xen 特有功能尚不支持，包括：

  • XenBus（开发中）

  • Xen PV 驱动

目前仅支持以下功能：

  • Xen Enlighten 内存页

  • Xen 事件通道

  • Xen PV 控制台（2 个版本：用于 DomU 的基于常规环形缓冲区的版本，以及用于 Dom0 的 consoleio 版本）

  • Xen 早期 console_io 接口（主要用于调试，需要调试版本的 Xen）

  • Xen 授权表（为自身授权提供访问，并映射/取消映射外部授权）

  • Xen 域看门狗

看门狗

开发板设备树将 Xen 域看门狗描述为 Zephyr 看门狗设备。该看门狗定时器归 Xen 所有，超时后会按照该域的 Xen on_watchdog 策略使整个客户机域失效。Zephyr 应用程序可以使用标准的看门狗 API 安装、设置和喂狗看门狗通道。

构建与运行

使用此配置可以将基本的 Zephyr 应用程序和内核测试作为 Xen 客户机运行，例如运行 Basic Synchronization 示例：

  • 如果硬件基于 GICv2：

$ west build -b xenvm samples/synchronization

  • 如果硬件基于 GICv3：

$ west build -b xenvm//gicv3 samples/synchronization

这会构建一个包含 synchronization 示例应用程序的镜像。接下来，需要创建客户机配置文件 zephyr.conf。示例如下：

kernel="zephyr.bin"
name="zephyr"
vcpus=1
memory=16
gic_version="v2"
on_crash="preserve"

使用 xenvm//gicv3 配置时，需要删除 gic_version 参数，或将其设置为 "v3"。

需要将 zephyr.bin 和 zephyr.conf 都上传到 Dom0，然后执行以下命令运行 Zephyr

$ xl create zephyr.conf

接下来需要连接到 PV 控制台：

$ xl console zephyr

也可以通过一条命令完成：

$ xl create -c zephyr.conf

将看到 Zephyr 输出：

*** Booting Zephyr OS build zephyr-v2.4.0-1137-g5803ee1e8183  ***
thread_a: Hello World from cpu 0 on xenvm!
thread_b: Hello World from cpu 0 on xenvm!
thread_a: Hello World from cpu 0 on xenvm!
thread_b: Hello World from cpu 0 on xenvm!
thread_a: Hello World from cpu 0 on xenvm!

按 CTRL+] 退出 Xen 虚拟控制台

更新配置

如前所述，Xen 使用设备树描述硬件，并期望客户机在运行时解析设备树。而 Zephyr 只支持静态的构建时配置。虽然所提供的配置应能在几乎所有以 aarch64 模式运行的 ARMv8 主机上工作，但无法保证 Xen 将来不会更改某些值（例如 RAM 基地址）。

此外，系统定时器的频率因开发板而异，在新硬件上运行 Zephyr xenvm 镜像时应更新该值。

可以通过 LIBXL_DEBUG_DUMP_DTB 环境变量让 Xen 导出生成的 DTB，例如：

$ LIBXL_DEBUG_DUMP_DTB=domu-libxl.dtb xl create zephyr.conf

然后可以使用“dtc”工具反编译生成的“domu-libxl.dtb”文件。

根据反编译得到的 DTB 文件中的信息，更新所提供的“xenvm.dts”文件中的所有相关条目。如果内存布局也发生了变化，可能还需要更新 CONFIG_SRAM_BASE_ADDRESS。
