概述

STM32N6570_DK Discovery 套件是面向基于 Arm® Cortex®‑M55 内核的 STM32N657X0H3Q 微控制器的完整演示和开发平台。

STM32N6570_DK Discovery 套件具有丰富的硬件功能，可帮助用户评估多种外设，例如 USB Type-C®、Octo‑SPI Flash 和 Hexadeca‑SPI PSRAM 器件、以太网、摄像头模块、LCD、microSD™、音频编解码器、数字麦克风、ADC、灵活的扩展连接器和用户按键。4 个灵活的扩展连接器可为无线连接、模拟应用和传感器等特定应用提供简便且不受限的扩展能力。

STM32N657X0H3Q 微控制器具有 1 个 USB 2.0 高速/全速设备/主机/OTG 控制器、1 个带 UCPD（USB Type-C® Power Delivery）的 USB 2.0 高速/全速设备/主机/OTG 控制器、1 个支持 TSN（时间敏感网络）的以太网、4 个 I2C、2 个 I3C、6 个 SPI（其中 4 个支持 I2S）、2 个 SAI（支持 4 路 DMIC）、5 个 USART、5 个 UART（ISO78916 接口、LIN、IrDA，最高 12.5 Mbit/s）、1 个 LPUART、2 个 SDMMC（MMC 版本 4.0、CE-ATA 版本 1.0 和 SD 版本 1.0.1）、3 个支持 TTCAN 的 CAN FD，支持 JTAG 和 SWD 调试，以及嵌入式跟踪宏单元（Embedded Trace Macrocell™，ETM）。

STM32N6570_DK Discovery 套件集成了 STLINK-V3EC，作为 STM32 MCU 的嵌入式在线调试器和编程器，带 USB 虚拟串口桥，并附带完整的 MCU 软件包。

硬件

  • 基于 Arm® Cortex®‑M55 的 STM32N657X0H3Q 微控制器，配备 ST Neural-ART Accelerator™、H264 编码器、NeoChrom 2.5D GPU 和 4.2 MB 连续 SRAM，VFBGA264 封装

  • 5 英寸 LCD 模块，带电容式触摸面板

  • USB Type-C®，USB 2.0 HS 接口，双角色电源（DRP）

  • USB Type-A，USB 2.0 HS 接口，主机模式，最大 0.5 A

  • 支持 TSN（时间敏感网络）的千兆以太网，符合 IEEE‑802.3‑2002

  • SAI 音频编解码器

  • 1 个 MEMS 数字麦克风

  • 1 Gbit 容量的 Octo‑SPI Flash

  • 256 Mbit 容量的 Hexadeca‑SPI PSRAM

  • 两个用户 LED

  • 用户按键、防篡改按键和复位按键

  • 开发板连接器：

    • USB Type-C®

    • USB Type-A 接口

    • 以太网 RJ45

    • 摄像头模块

    • microSD™ 卡

    • LCD

    • 立体声耳机插孔，含模拟麦克风输入

    • 音频 MEMS 子板扩展连接器

    • ARDUINO® Uno R3 扩展连接器

    • STMod+ 扩展连接器

  • 板载 STLINK-V3EC 调试器/编程器，支持 USB 重枚举功能：虚拟串口和调试端口

支持的功能

stm32n6570_dk 开发板支持下列硬件功能。

说明

The list of supported hardware features was not generated. Run a full documentation build for the required metadata to be available.

视频

STM32N6570-DK 配有一个 CSI 摄像头模块，带高分辨率 500 万像素 CMOS RGB 图像传感器。该摄像头以 RAW Bayer 格式输出图像，需要经过信号处理才能以真实色彩显示。这种图像信号处理可以通过专用的 STM32 ISP module 完成。

NPU

STM32N6570-DK 还内置 ST Neural-ART Accelerator™ 作为 NPU，专为高能效边缘 AI 应用设计，例如作为独立 Zephyr 应用程序提供的 Zephyr computer vision application。

以太网

STM32N6570-DK 配有一个千兆以太网接口，通过 RGMII 连接到外部 PHY。

片上 OTP（一次性可编程）存储器中有一个区域专门用于保存以太网 MAC 地址。该区域在生产时未编程，读出值全为零；必须在现场使用 STM32CubeProgrammer 编程。

要在应用程序中使用 OTP MAC 地址 MAC_ADDR1，请添加以下覆盖文件：

&mac {
    nvmem-cells = <&mac_address0>;
    nvmem-cell-names = "mac-address";
};

警告

如果片上 OTP 尚未编程，使用此覆盖文件时以太网将无法工作，因为此时会读到未编程的 OTP 值（全为零）并将其用作 MAC 地址，而 00:00:00:00:00:00 不是有效的 MAC 地址。

不过，为了能在不对设备进行不可逆编程的情况下运行 Zephyr 网络相关示例，STM32 以太网驱动默认会根据设备唯一 ID 生成一个本地管理的 MAC 地址。

STM32 OEMuROT 集成

STM32CubeN6 提供了一个名为 STM32 OEMuROT 的外部安全引导加载程序，它利用了 STM32N657X0H3Q 微控制器的安全特性。有关该引导加载程序的详细信息，请参阅 OEMuRoT for STM32N6 wiki article。

该引导加载程序在 Zephyr 构建环境中的集成由外部的 STM32 OEMxROT module 提供。

USB

STM32N657XX 微控制器上的 USB 引脚分配是固定的。也就是说，指定用于 USB 功能的引脚不能更改，也不能重新分配给其他功能，从而确保 USB 通信一致可靠。

系统时钟

STM32N6570_DK 的系统时钟可以由内部或外部振荡器驱动，也可以由主 PLL 时钟驱动。默认情况下，系统时钟由 400MHz 的 PLL 时钟驱动，PLL 由 64MHz 高速内部振荡器驱动。

串口

STM32N6570_DK 开发板有 10 个 U(S)ART。Zephyr 控制台输出分配到 USART1。默认设置为 115200 8N1。

开发板变体

STM32N6570_DK 有 3 种变体：

  • 主应用程序（默认变体）。以链式加载应用程序的形式提供，应由引导加载程序加载，可访问整个 AXISRAM1 和 AXISRAM2 区域。应只使用 --sysbuild 选项构建。

  • fsbl：第一阶段引导加载程序（FSBL），以由 Boot ROM 加载、通过 ST-Link 烧录的应用程序形式提供，通常是引导加载程序镜像。它以 RAM LOAD 模式运行在 AXISRAM2 的后半部分，整个镜像可用 511K 空间。

  • sb：第一阶段引导加载程序 - 串行启动。等同于 FSBL 镜像，但可以通过 USB 加载，无需切换启动引脚。这是开发阶段最方便的方式。

编程与调试

说明

The list of supported runners was not generated. Run a full documentation build for the required metadata to be available.

STM32N6570_DK 开发板集成了 ST-LINK/V3 嵌入式调试工具接口。借助该探针，可以使用多种工具烧录和调试开发板。

烧录或加载

本开发板配置为使用 west STM32CubeProgrammer 运行器（runner）进行编程，因此需要 安装 该工具。要求 STM32CubeProgrammer 版本为 2.18.0 或更高。

备注

固件以安全执行模式运行，因此需要签名。构建完成后，构建系统会自动使用 STM32CubeProgrammer 的工具 STM32_SigningTool_CLI 生成二进制文件的签名版本。该工具随 STM32CubeProgrammer 一同安装，但请确保它位于 PATH 变量中。

编程开发板有两种方式：

  • 将固件编程到外部 Flash 中。启动时，固件会被加载到 RAM 并在 RAM 中执行。

  • 也可以选择利用启动 ROM 提供的串行启动接口。此时固件直接加载到 RAM 并在 RAM 中执行，不会保留在持久性存储器中。

将应用程序编程到 STM32N6570_DK

以下是构建并运行 Hello World 应用程序的示例。

首先，使用 ST-Link USB 端口将 STM32N6570_DK 连接到主机。

构建并烧录由 MCUBoot 加载的应用程序。

# From the root of the zephyr repository
west build -b stm32n6570_dk --sysbuild samples/hello_world
west flash

备注

默认情况下，应用程序以 XIP 模式运行。要使用 RAMLOAD 模式，请改用以下命令构建：

# From the root of the zephyr repository
west build -b stm32n6570_dk --sysbuild -- -DCONFIG_XIP=n -DSB_CONFIG_MCUBOOT_MODE_RAM_LOAD=y samples/hello_world
west flash

备注

烧录时，在给开发板上电之前，按以下配置设置启动引脚：

  • BOOT0：0（开关 SW2 拨到 L 位置）

  • BOOT1：1（开关 SW1 拨到 H 位置）

烧录完成后，要运行应用程序，请按以下配置设置启动引脚：

  • BOOT0：0（开关 SW2 拨到 L 位置）

  • BOOT1：0（开关 SW1 拨到 L 位置）

将开发板断电后重新上电。

使用 stm32n6570_dk/stm32n657xx/fsbl 目标构建并烧录应用程序。

# From the root of the zephyr repository
west build -b stm32n6570_dk//fsbl samples/hello_world
west flash

备注

烧录时，在给开发板上电之前，按以下配置设置启动引脚：

  • BOOT0：0（开关 SW2 拨到 L 位置）

  • BOOT1：1（开关 SW1 拨到 H 位置）

烧录完成后，要运行应用程序，请按以下配置设置启动引脚：

  • BOOT0：0（开关 SW2 拨到 L 位置）

  • BOOT1：0（开关 SW1 拨到 L 位置）

将开发板断电后重新上电。

除 USB/ST-Link 外，还需使用 USB1 端口（CN18）将 STM32N6570_DK 连接到主机。

在这种配置下，ST-Link（USB/CN6）用于为开发板供电并通过虚拟串口进行串行通信，而 USB1/CN18 用于将 Zephyr 镜像发送给 Boot ROM，以便将其加载到 RAM 中执行。

备注

在给开发板上电之前，按以下配置设置启动引脚：

  • BOOT0：1（开关 SW2 拨到 H 位置）

  • BOOT1：0（开关 SW1 拨到 L 位置）

使用 stm32n6570_dk/stm32n657xx/sb 目标构建并加载应用程序（也可以使用简写形式 stm32n6570_dk//sb）

# From the root of the zephyr repository
west build -b stm32n6570_dk//sb samples/hello_world
west flash

运行串口终端程序连接 Disco 开发板：

$ minicom -D /dev/ttyACM0

控制台上应显示以下信息：

Hello World! stm32n6570_dk/stm32n657xx

调试

可以按常规方式使用 west 和 ST-LINK GDB 服务器 调试应用程序。

备注

要启用调试，请在给开发板上电之前，按以下配置设置启动引脚：

  • BOOT0：0（开关 SW2 拨到 L 位置）

  • BOOT1：1（开关 SW1 拨到 H 位置）

要调试多阶段应用程序（由 MCUboot 等引导加载程序加载的应用程序），请按以下步骤操作：

首先烧录应用程序，这样 MCUboot 才能在外部存储器中找到它（参见上文说明）。

然后使用引导加载程序域启动调试会话：

west debug --domain mcuboot

此时即可调试引导加载程序。要调试被链式加载的应用程序，请运行以下 gdb 命令：

(gdb) b do_boot
(gdb) c
# Once stopped in do_boot, add chainloaded application symbols
(gdb) add-symbol-file ./build/hello_world/zephyr/zephyr.elf
# Place breakpoint on 'main' in chainloaded application
(gdb) b main
(gdb) c

每次调试会话之前，务必先对开发板进行断电复位。可以使用 the following script: 完成

./boards/st/common/scripts/board_power_reset.sh

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b stm32n6570_dk/stm32n657xx/fsbl samples/hello_world
west debug

以下以 Hello World 应用程序为例。

# From the root of the zephyr repository
west build -b stm32n6570_dk/stm32n657xx/sb samples/hello_world
west debug

另一种调试方法是使用 STM32CubeIDE：

  • 依次选择 File ‣ Import，然后选择 C/C++ ‣ STM32 Cortex-M Executable。

  • 在 Executable 字段中，浏览选择 <ZEPHYR_PATH>/build/zephyr/zephyr.elf。

  • 在 MCU 字段中，选择 STM32N657X0HxQ。

  • 点击 Finish。

  • 最后，点击 Debug 开始调试会话。

使用 twister 运行测试

由于使用 stm32n6570_dk 开发板目标烧录时需要拨动 BOOT 开关，只能在 stm32n6570_dk/stm32n657xx/sb 开发板目标上运行 twister 测试，因为该目标加载和执行二进制文件时无需更改 BOOT 引脚。为此，建议使用 Twister 的硬件映射功能，并采用以下设置：

- platform: stm32n6570_dk/stm32n657xx/sb
  product: BOOT-SERIAL
  pre_script: <path_to_zephyr>/boards/st/common/scripts/board_power_reset.sh
  runner: stm32cubeprogrammer
