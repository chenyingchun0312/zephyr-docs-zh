通用

  • 现在要求的 Zephyr SDK 最低版本为 1.0.0。

  • 现在要求的 Python 最低版本为 3.12（原为 3.10）。

构建系统

  • Zephyr 现在正式默认以 C17（ISO/IEC 9899:2018）作为最低要求的 C 标准版本。如果你的工具链不支持该标准，则需要使用现有且现已弃用的选项之一：CONFIG_STD_C99 或 CONFIG_STD_C11。

  • board.yml 文件中，新开发板对应的 board/boards 条目现在必须提供 full_name 属性。

  • CMake 变量 BOARD_QUALIFIERS 已与对应的 CONFIG_BOARD_QUALIFIERS 保持一致，不再以 / 作为前缀。这意味着所有使用 ${BOARD}${BOARD_QUALIFIERS} 的地方都必须更新为包含 /，例如：${BOARD}/${BOARD_QUALIFIERS}。

  • SNIPPET_ROOT 已与 Zephyr 的其他 <type>_ROOT 设置保持一致，默认不再包含应用程序源码目录。需要将应用程序源码目录加入 SNIPPET_ROOT 的示例，必须改为在 zephyr/module.yml 中使用 snippet_root = <dir> 条目添加该目录，或手动将该目录追加到 CMake 变量 SNIPPET_ROOT 中。

  • 由于开发板目标的自动补全现在支持开发板版本（revision），应重新生成 Shell 自动补全脚本（west completion）。

内核

  • 堆加固支持的实现方式是新增一个构建时生成的 zephyr/heap_constants.h 文件，该文件现在由 kernel.h 包含。对于以 cmake 库形式构建的下游应用程序，这可能导致构建竞争条件：cmake 可能在该头文件生成之前就尝试构建这些库，此时可能需要在 cmake 中额外添加 add_dependencies(${lib} zephyr_generated_headers) 条目，详见 GitHub #106439。

  • __pinned_* 属性系列以及 CONFIG_LINKER_USE_PINNED_SECTION / CONFIG_LINKER_GENERIC_SECTIONS_PRESENT_AT_BOOT Kconfig 选项已被移除（GitHub #108773）。现在内核镜像始终驻留在物理内存中；按需分页仅适用于通过 k_mem_map() 创建的匿名映射，以及通过 CONFIG_LINKER_USE_ONDEMAND_SECTION 放入 __ondemand_* 链接器段的符号。

    之前的“默认可换出”模型（任何未显式标记 __pinned_* 的内核页面都可能被换出）从设计上就不安全：某个构建能否正常运行，取决于代码和数据相对于缺页异常分派路径的偶然布局，而没有任何保证。如果你的应用程序依赖旧模型，并且在某个现有版本上运行正常，建议继续停留在该版本（最好是 长期支持 版本），而不要升级。迁移到更新的版本很可能使布局发生足够的变化（新增代码、函数重新排序、更换编译器），导致某个未标记的页面落在异常分派路径上，以难以诊断的方式破坏系统。正是由于这种潜在的脆弱性，该模型被移除而不是继续保留。确实要升级的应用程序需要进行以下修改：

    • 从开发板 defconfig 和 prj.conf 覆盖文件中删除所有 CONFIG_LINKER_USE_PINNED_SECTION=y 或 CONFIG_LINKER_GENERIC_SECTIONS_PRESENT_AT_BOOT=n 行。

    • 从源代码中删除 __pinned_func、__pinned_data、__pinned_rodata、__pinned_bss 和 __pinned_noinit 属性。需要支持按需分页的代码必须改用 __ondemand_func / __ondemand_rodata；贡献者有责任确保缺页处理程序的执行路径不会访问这些符号。

    • 将汇编中所有使用 PINNED_TEXT、PINNED_RODATA、PINNED_DATA、PINNED_BSS 和 PINNED_NOINIT（作为 SECTION_FUNC() / SECTION_VAR() 的段名参数）的地方，替换为普通的 TEXT、RODATA、DATA、BSS 和 NOINIT 别名。

    • 将所有使用 K_KERNEL_PINNED_STACK_DEFINE、K_KERNEL_PINNED_STACK_ARRAY_DEFINE、K_KERNEL_PINNED_STACK_ARRAY_DECLARE、K_THREAD_PINNED_STACK_DEFINE 和 K_THREAD_PINNED_STACK_ARRAY_DEFINE 的地方，重命名为对应的非固定版本（K_KERNEL_STACK_DEFINE、K_KERNEL_STACK_ARRAY_DEFINE、K_KERNEL_STACK_ARRAY_DECLARE、K_THREAD_STACK_DEFINE、K_THREAD_STACK_ARRAY_DEFINE）。

    • 提供了包含固定段（pinned_text / pinned_rodata / pinned_data / pinned_bss / pinned_noinit）的自定义链接器脚本的树外开发板，应将这些输入段的匹配规则并回常规的 text / rodata / data / bss / noinit 输出段。

    • 依赖 lnkr_pinned_* 链接器符号或 lnkr_is_pinned() / lnkr_is_region_pinned() 的树外代码必须移除这些引用。对应的 app_smem_pinned*.ld 包含文件以及 scripts/build/gen_app_partitions.py 的 --pinoutput / --pinpartitions 选项也已移除。

开发板

  • OpenOCD 运行器现在使用标准的 --file 和 --file-type 接口来指定烧录文件，与 JLink 等其他运行器保持一致。具体变更如下：

    • 弃用了 --use-hex、--use-elf 和 --use-bin 标志，请改用 --file-type：

      • --use-elf → --file-type=elf

      • --use-bin → --file-type=bin

      • --use-hex → --file-type=hex（也可以省略，因为 hex 是默认值）

    • 现在支持使用 --file 选项指定自定义文件路径，与 JLink 运行器类似。

    • 使用已弃用标志的开发板 cmake 文件仍可继续工作，但会发出弃用警告。

    • 现在可以在不使用 --file 的情况下使用 --file-type 选项，在构建产物（hex、elf、bin）之间进行选择。

  • native_sim：主机 FUSE 访问：现在默认使用 libfusev3 而不是 v2，但可以通过 CONFIG_FUSE_LIBRARY_VERSION 进行选择（GitHub #104965）。

  • m5stack_fire：移除了 UART2 未使用的 pinctrl 条目，并将 UART1 的引脚映射从 GPIO32/GPIO33 更新为 GPIO16/GPIO17，以符合文档中 Grove PORT.C 的接线。

  • Ai-Thinker 的 ai_m62_12f 和 ai_wb2_12f 开发板已分别重命名为 ai_m62_12f_kit 和 ai_wb2_12f_kit。

  • 编译定义 'XIP_EXTERNAL_FLASH'、'USE_HYPERRAM' 和 'XIP_BOOT_HEADER_XMCD_ENABLE' 仅在 boards/nxp/mimxrt1180_evk/xip/evkmimxrt1180_flexspi_nor_config.c 和 boards/nxp/mimxrt1170_evk/xmcd/xmcd.c 中使用，因此已在各自开发板的 CMakeLists.txt 文件中将其改为局部作用域。依赖这些定义全局可见的应用程序可能需要相应更新。（GitHub #101322）

  • Renesas ek_ra8t2/r7ka8t2lfecac/cm85 已重命名为 ek_ra8t2/r7ka8t2lflcac/cm85。

  • NXP 调整了部分树内编译标志的作用域，将其可见范围限制在真正需要的地方。依赖这些标志全局可见的树外应用程序或开发板，可能需要将它们添加到自己的 CMakeLists.txt 文件中，以确保仍能正确构建。（GitHub #100252）受影响的标志如下：

    • 对于 RT10xx 和 RT11xx 系列，编译标志 BOARD_FLASH_SIZE 原本定义在 boards/nxp/mimxrt10xx_evk/CMakeLists.txt 和 boards/nxp/mimxrt11xx_evk/CMakeLists.txt 中，仅被 HAL 头文件 fsl_flexspi_nor_boot.h 使用，而该头文件由 soc/nxp/imxrt/imxrt10xx/soc.c 和 soc/nxp/imxrt/imxrt11xx/soc.c 包含。为避免与其他全局标志发生冲突，该宏现在在 SoC 层通过 soc/nxp/imxrt/imxrt10xx/CMakeLists.txt 和 soc/nxp/imxrt/imxrt11xx/CMakeLists.txt 中的 zephyr_library_compile_definitions() 定义。此变更已应用于所有 RTxxxx 开发板。

    • 对于 RTxxx 系列，编译标志 BOARD_FLASH_SIZE 原本定义在 boards/nxp/mimxrtxxx_evk/CMakeLists.txt 中，但 Zephyr 树中并未使用，因此已从所有 RTxxx 开发板的 CMakeLists.txt 文件中移除。

    • 对于 RTxxx 系列，编译标志 BOOT_HEADER_ENABLE 之前定义在 boards/nxp/mimxrtxxx_evk/CMakeLists.txt 中，并在 boards/nxp/rtxxx/<boot_header>.c 中使用，现已由一个 Kconfig 选项取代。因此，已从 RTxxx 开发板的 CMakeLists.txt 文件中删除 zephyr_compile_definitions(BOOT_HEADER_ENABLE=1) 这一行。

    • 从 boards/nxp/rd_rw612_bga/CMakeLists.txt 中移除了编译标志 BOOT_HEADER_ENABLE 的定义，因为 Zephyr 树中并未使用它。

    • 编译标志 XIP_BOOT_HEADER_ENABLE 和 XIP_BOOT_HEADER_DCD_ENABLE 原本在 boards/nxp/rt1xxx/<boot_header>.c 中使用。现在这些标志在所有 NXP RTxxxx 评估板上都已转换为 Kconfig 选项，可以通过 Kconfig 构建系统而不是编译时宏定义来配置启动头。因此，已从 RTxxxx 开发板级的 CMakeLists.txt 文件中移除 zephyr_compile_definitions(XIP_BOOT_HEADER_ENABLE=1) 和 zephyr_compile_definitions(XIP_BOOT_HEADER_DCD_ENABLE=1)。由于 hal_nxp/rt10xx/fsl_flexspi_nor_boot.h 和 hal_nxp/rt11xx/fsl_flexspi_nor_boot.h 也需要这些宏，它们已通过 zephyr_library_compile_definitions() 添加到对应的 SoC 层 CMakeLists.txt 文件中，以限制其作用域。

  • 以下 Nordic SoC Kconfig 选项已弃用并被取代，如果 Kconfig/CMake/代码中引用了这些已弃用的选项，需要相应更新：

    • CONFIG_SOC_SERIES_NRF51X 由 CONFIG_SOC_SERIES_NRF51 取代

    • CONFIG_SOC_SERIES_NRF52X 由 CONFIG_SOC_SERIES_NRF52 取代

    • CONFIG_SOC_SERIES_NRF53X 由 CONFIG_SOC_SERIES_NRF53 取代

    • CONFIG_SOC_SERIES_NRF54HX 由 CONFIG_SOC_SERIES_NRF54H 取代

    • CONFIG_SOC_SERIES_NRF54LX 由 CONFIG_SOC_SERIES_NRF54L 取代

    • CONFIG_SOC_SERIES_NRF91X 由 CONFIG_SOC_SERIES_NRF91 取代

    • CONFIG_SOC_SERIES_NRF92X 由 CONFIG_SOC_SERIES_NRF92 取代

  • 以下 SiFive Freedom SoC Kconfig 选项已弃用并被取代，如果 Kconfig/CMake/代码中引用了这些已弃用的选项，需要相应更新：

    • CONFIG_SOC_SERIES_SIFIVE_FREEDOM_FE300 由 CONFIG_SOC_SERIES_FE300 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FE310_G000 由 CONFIG_SOC_FE310_G000 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FE310_G002 由 CONFIG_SOC_FE310_G002 取代

    • CONFIG_SOC_SERIES_SIFIVE_FREEDOM_FU500 由 CONFIG_SOC_SERIES_FU500 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FU540 由 CONFIG_SOC_FU540 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FU540_E51 由 CONFIG_SOC_FU540_E51 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FU540_U54 由 CONFIG_SOC_FU540_U54 取代

    • CONFIG_SOC_SERIES_SIFIVE_FREEDOM_FU700 由 CONFIG_SOC_SERIES_FU700 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FU740 由 CONFIG_SOC_FU740 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FU740_S7 由 CONFIG_SOC_FU740_S7 取代

    • CONFIG_SOC_SIFIVE_FREEDOM_FU740_U74 由 CONFIG_SOC_FU740_U74 取代

  • ITE it515xx_evb 已重命名为 it51xxx_evb。

  • 使用 CONFIG_USE_DT_CODE_PARTITION 或设置了 zephyr,code-partition chosen 节点的开发板，现在应使用新的 zephyr,mapped-partition 兼容属性。该绑定利用设备树单元地址获取分区的内存映射地址，而不必为了计算地址手动逐级向上查找子节点，直到找到具有特定名称的节点。此外，在使用 zephyr,mapped-partition 时，不再允许使用 CONFIG_FLASH_LOAD_OFFSET 和 CONFIG_FLASH_LOAD_SIZE，因为链接器文件现在可以自行算出 NVM 偏移和大小，无需 Kconfig 作为中间步骤进行数学运算。另外，在内存映射设备上切换到 zephyr,mapped-partition 后，不再需要 fixed-subpartitions，因为这些分区本身就可以相互嵌套，并且（配合设备树 ranges 属性使用时）会得到正确的地址和偏移。对于尚未将 zephyr,code-partition chosen 设备更新为使用 zephyr,mapped-partition 绑定的开发板目标，将设置 CONFIG_FLASH_CODE_PARTITION_USING_FIXED_PARTITIONS。将来会弃用以 fixed-partitions 作为 chosen zephyr,code-partition 节点的支持。

  • 基于 STM32N6x SoC（CONFIG_SOC_SERIES_STM32N6X）的开发板或项目，如果 Zephyr 应用程序需要在处理器的安全状态下执行，现在需要显式启用 CONFIG_TRUSTED_EXECUTION_SECURE。反之，如果 Zephyr 应用程序需要在处理器的非安全状态下执行，开发板或项目必须显式启用 CONFIG_TRUSTED_EXECUTION_NON_SECURE。

  • 以下 WCH SoC Kconfig 选项已重命名。如果 Kconfig/CMake/代码中引用了旧的选项，需要相应更新：

    • CONFIG_SOC_SERIES_CH32V00X 由 CONFIG_SOC_SERIES_QINGKE_V2C 取代

设备驱动与设备树

ADC

  • renesas,ra-adc 兼容属性已被 renesas,ra-adc12 取代。使用旧兼容属性的应用程序必须更新其设备树节点。

  • 新增了 renesas,ra-adc16 兼容属性。使用提供 16 位 ADC 分辨率的 EK-RA2A1 开发板时必须使用该兼容属性。

  • CONFIG_ADC_MCUX_SAR_ADC 已重命名为 CONFIG_ADC_NXP_SAR_ADC。

  • 驱动文件 adc_mcux_sar_adc.c 已重命名为 drivers/adc/adc_nxp_sar_adc.c。

  • 使用 SAR ADC 驱动的应用程序需要更新设备树中的节点，加入 zephyr,input-positive 以指定硬件通道。对于目前支持 SAR ADC 的 SoC，参考电压应使用 ADC_REF_VDD_1，而不是 ADC_REF_INTERNAL。此次驱动更新也修正了该问题，因此用户还需要相应地更新设备树中该属性的值。（GitHub #100978）

  • st,stm32-adc 不再有 resolutions 属性，由 st,adc-resolutions 属性取代。对于 Y 版本的 STM32H7 器件，不再需要替换 14 位和 12 位的分辨率值。如果使用 14 位或 12 位分辨率，此变更可能影响功耗：之前使用的是功耗优化值，现在使用标准值（未做功耗优化，但精度更高）。对其他系列没有影响。

时钟控制

  • bflb,bl60x-pll、bflb,bl61x-root-clk、bflb,bl60x-root-clk、bflb,bl61x-wifipll、bflb,bl70x-root-clk 和 bflb,bl61x-flash-clk 已分别被 bflb,flash-clk、bflb,pll 和 bflb,root-clk 取代。

  • infineon,peri-div 时钟控制绑定移除了 resource-type、resource-instance 和 resource-channel 属性。驱动不再使用这些属性，驱动内部数据结构中的对应字段也已移除。使用该兼容属性的树外开发板必须从其设备树节点中删除这些属性。（GitHub #105393）

控制器局域网（CAN）

  • 移除了 CONFIG_CAN_MAX_FILTER、CONFIG_CAN_MAX_STD_ID_FILTER、CONFIG_CAN_MAX_EXT_ID_FILTER（GitHub #100596）。它们由以下驱动专用的 Kconfig 符号取代，其中部分符号的默认值已提高，以满足常见的软件需求：

    • CONFIG_CAN_LOOPBACK_MAX_FILTERS，用于 zephyr,can-loopback

    • CONFIG_CAN_MAX32_MAX_FILTERS，用于 adi,max32-can

    • CONFIG_CAN_MCP2515_MAX_FILTERS，用于 microchip,mcp2515

    • CONFIG_CAN_MCP251XFD_MAX_FILTERS，用于 microchip,mcp251xfd

    • CONFIG_CAN_MCUX_FLEXCAN_MAX_FILTERS，用于 nxp,flexcan

    • CONFIG_CAN_NATIVE_LINUX_MAX_FILTERS，用于 zephyr,native-linux-can

    • CONFIG_CAN_RCAR_MAX_FILTERS，用于 renesas,rcar-can

    • CONFIG_CAN_SJA1000_MAX_FILTERS，用于 kvaser,pcican 和 espressif,esp32-twai

    • CONFIG_CAN_STM32_BXCAN_MAX_EXT_ID_FILTERS，用于 st,stm32-bxcan

    • CONFIG_CAN_STM32_BXCAN_MAX_STD_ID_FILTERS，用于 st,stm32-bxcan

    • CONFIG_CAN_STM32_FDCAN_MAX_EXT_ID_FILTERS，用于 st,stm32-fdcan

    • CONFIG_CAN_STM32_FDCAN_MAX_STD_ID_FILTERS，用于 st,stm32-fdcan

    /* Old (deprecated) */
lptmr0: counter@40040000 {
    compatible = "nxp,lptmr";
    /* Implicitly bypassed */
    prescale-glitch-filter = <0>;
};

/* New (correct) */
lptmr0: counter@40040000 {
    compatible = "nxp,lptmr";
    /* Explicitly bypassed */
    prescale-glitch-filter-bypass;
};

    prescale-glitch-filter 的使用示例

    备注

    prescale-glitch-filter-bypass 是布尔属性。存在时启用旁路；不存在时禁用旁路，并应用 prescale-glitch-filter。

    在脉冲计数模式下，prescale-glitch-filter = <0> 不是受支持的毛刺滤波器配置。如果不需要滤波，请使用 prescale-glitch-filter-bypass;。

    • 时间计数模式：对计数器时钟分频

      在时间计数模式下，预分频器按 2^(N + 1) 分频。

      /* Divide by 2^(0+1) = 2 */
lptmr0: counter@40040000 {
    compatible = "nxp,lptmr";
    /* Time Counter mode */
    timer-mode-sel = <0>;
    clk-source = <1>;
    clock-frequency = <32768>;
    /* /2 */
    prescale-glitch-filter = <0>;
    resolution = <16>;
};

/* Divide by 2^(3+1) = 16 */
lptmr1: counter@40041000 {
    compatible = "nxp,lptmr";
    /* Time Counter mode */
    timer-mode-sel = <0>;
    clk-source = <1>;
    clock-frequency = <32768>;
    /* /16 */
    prescale-glitch-filter = <3>;
    resolution = <16>;
};

    • 时间计数模式：显式旁路（不分频）

      lptmr0: counter@40040000 {
    compatible = "nxp,lptmr";
    /* Time Counter mode */
    timer-mode-sel = <0>;
    clk-source = <1>;
    clock-frequency = <32768>;
    /* no prescaler */
    prescale-glitch-filter-bypass;
    resolution = <16>;
};

    • 脉冲计数模式：毛刺滤波

      在脉冲计数模式下，毛刺滤波器在 2^N 个上升沿之后才识别变化。毛刺滤波不支持值 0；如果不需要滤波，请使用旁路。

      /* Recognize change after 2^2 = 4 rising edges */
lptmr0: counter@40040000 {
    compatible = "nxp,lptmr";
    /* Pulse Counter mode */
    timer-mode-sel = <1>;
    clk-source = <1>;
    input-pin = <0>;
    prescale-glitch-filter = <2>;
    resolution = <16>;
};

/* No filtering (explicit bypass) */
lptmr1: counter@40041000 {
    compatible = "nxp,lptmr";
    /* Pulse Counter mode */
    timer-mode-sel = <1>;
    clk-source = <1>;
    input-pin = <0>;
    prescale-glitch-filter-bypass;
    resolution = <16>;
};

    • 之前的行为（Zephyr ≤ 4.3）：GPT 计数器始终以自由运行模式运行（enableFreeRun = true）。发生比较事件时，计数器不会复位，而是继续计数。

    • 新的行为（Zephyr ≥ 4.4）：除非显式配置，GPT 计数器默认使用重启模式。新的 run-mode 设备树属性控制该行为：

      • "restart"（默认）：计数器达到比较通道 1 的值时复位为 0

      • "free-run"：计数器继续计数，不复位（之前的行为）

    需要迁移：使用 GPT 计数器的树外开发板和应用程序必须在其设备树节点中添加 run-mode = "free-run";，以保持之前的行为。

    compatible = "nxp,imx-gpt";
    /* Explicitly restore Zephyr ≤4.3 behavior */
    run-mode = "free-run";
    /* ... other properties ... */
};

    警告

    该驱动使用比较通道 1 实现 Zephyr 计数器的告警功能。使用 run-mode = "restart" 时，设置告警会使计数器在告警比较点复位。如果你的应用程序既依赖告警又需要连续计数，必须使用 run-mode = "free-run"。

    备注

    此变更统一了 NXP 计数器驱动的运行模式配置。GPT 现在使用显式的设备树属性而不是硬编码值，可以按实例进行定制。
