构建系统

  • 彻底重构了 SoC 和开发板的定义方式。所有树外（out-of-tree）SoC 和开发板都需要移植到新模型。详细信息请参阅 过渡到当前硬件模型。(GitHub #69607)

  • 以下构建时生成的头文件：

    受影响的头文件

    app_version.h

    autoconf.h

    cmake_intdef.h

    core-isa-dM.h

    devicetree_generated.h

    driver-validation.h

    kobj-types-enum.h

    linker-kobject-prebuilt-data.h

    linker-kobject-prebuilt-priv-stacks.h

    linker-kobject-prebuilt-rodata.h

    mcuboot_version.h

    offsets.h

    otype-to-size.h

    otype-to-str.h

    strerror_table.h

    strsignal_table.h

    syscall_list.h

    version.h

    zsr.h

    以及系统调用的头文件和源文件，现在都放入了 zephyr/ 目录命名空间下。此更改基本可以自动完成，相应脚本见 GitHub #63973。目前，兼容性 Kconfig 选项（CONFIG_LEGACY_GENERATED_INCLUDE_PATH）默认启用，以便下游应用程序可以继续编译，此时 CMake 配置阶段会产生一条警告信息。该 Kconfig 选项将来会被弃用并最终移除，建议开发者尽快更新这些受影响头文件的包含路径。

内核

  • 现在所有架构都必须定义新的 struct arch_esf，用于描述栈帧的成员。这个新结构体取代了命名结构体 z_arch_esf_t。(GitHub #73593)

  • 命名结构体 z_arch_esf_t 现已弃用，请改用 struct arch_esf。(GitHub #73593)

  • 头文件 include/zephyr/arch/arch_interface.h 已从 include/zephyr/sys/ 移动到 include/zephyr/arch/。树外源文件需要更新包含路径。(GitHub #64987)

开发板

  • 调整了 SparkFun Pro Micro RP2040 的 pro_micro 连接器 gpio-map 中 D1 和 D0 的顺序，使其与原始 Pro Micro 定义一致。树外扩展板（shield）必须相应更新。(GitHub #69994)

  • ITE：重命名了所有 SoC 型号的 Kconfig 选项，例如 CONFIG_SOC_IT82202_AX 重命名为 CONFIG_SOC_IT82202AX。所有符号重命名如下：SOC_IT81202BX、SOC_IT81202CX、SOC_IT81302BX、SOC_IT81302CX、SOC_IT82002AW、SOC_IT82202AX、SOC_IT82302AX。此外，SOC_SERIES_ITE_IT8XXX2 重命名为 SOC_SERIES_IT8XXX2。(GitHub #71680)

  • 对于 native_sim/posix：设置 CONFIG_I2C 时不再默认启用 CONFIG_EMUL。需要启用该设置的用户应在其项目配置文件中设置。(GitHub #73067)

  • LiteX：LiteX VexRiscV 中断控制器节点的 compatible 已从 vexriscv-intc0 重命名为 litex,vexriscv-intc0。(GitHub #73211)

  • lairdconnect 开发板现在改为 ezurio 开发板。Laird Connectivity 已更名为 Ezurio。

模块

Mbed TLS

  • TLS 1.2、RSA、AES、DES 以及除 SHA-256 以外的所有哈希算法（SHA-224、SHA-384、SHA-512、MD5 和 SHA-1）不再默认启用。现在需要显式启用各自的 Kconfig 选项才能使用它们。(GitHub #72078)

  • 原名为 CONFIG_MBEDTLS_MAC_*_ENABLED 的 Kconfig 选项已重命名，名称中的 _MAC 和 _ENABLED 部分已被去掉。(GitHub #73267)

  • 修复了 CONFIG_MBEDTLS_HASH_ALL_ENABLED Kconfig 选项，使其真正启用所有可用的哈希算法。此前它只启用 SHA-2 系列算法。(GitHub #73267)

  • 移除了 CONFIG_MBEDTLS_HASH_SHA*_ENABLED Kconfig 选项。它们与其他 Kconfig 选项重复，后者现在命名为 CONFIG_MBEDTLS_SHA*。(GitHub #73267)

  • 移除了 CONFIG_MBEDTLS_MAC_ALL_ENABLED Kconfig 选项。与之等效的是 CONFIG_MBEDTLS_HASH_ALL_ENABLED 和 CONFIG_MBEDTLS_CMAC 的组合。(GitHub #73267)

  • 移除了 Kconfig 选项 CONFIG_MBEDTLS_MAC_MD4_ENABLED、CONFIG_MBEDTLS_CIPHER_ARC4_ENABLED 和 CONFIG_MBEDTLS_CIPHER_BLOWFISH_ENABLED，因为 Mbed TLS 已不再支持它们。(GitHub #73222)

  • 当系统中存在任何 PSA 加密提供者（即设置了 CONFIG_MBEDTLS_PSA_CRYPTO_CLIENT）时，必须使用相应的 CONFIG_PSA_WANT_* 显式启用所需的 PSA 加密功能。(GitHub #72243)

  • 只要系统中存在任何 PSA 加密提供者（即设置了 CONFIG_MBEDTLS_PSA_CRYPTO_CLIENT），TLS/X509/PK/MD 模块就会使用 PSA 加密 API，而不是旧版 API。(GitHub #72243)

Trusted Firmware-M

  • 默认的 MCUboot 签名类型已从 RSA-3072 改为 EC-P256。这会影响在 TF-M 中启用了 MCUboot（CONFIG_TFM_BL2）的构建。如果希望继续使用 RSA-3072，需要将 CONFIG_TFM_MCUBOOT_SIGNATURE_TYPE 设置为 "RSA-3072"。否则，请确保拥有所用签名类型的自有签名密钥。

LVGL

  • 移除了 CONFIG_LV_Z_POINTER_KSCAN，需要将基于 kscan 的驱动转换到输入子系统，并改为在设备树中使用 zephyr,lvgl-pointer-input。(GitHub #73800)

设备驱动与设备树

  • nxp,kinetis-pit PIT 驱动的 compatible 已改为 nxp,pit，并已更新为支持多个通道。要配置各个通道，必须添加 compatible 为 nxp,pit-channel 的子节点，并按如下方式配置。随着 PIT 绑定的重命名，CONFIG_COUNTER_MCUX_PIT 也已重命名为 CONFIG_COUNTER_NXP_PIT。(GitHub #66336) 示例：

    / {
    pit0: pit@40037000 {
        /* Other Pit DT Attributes */
        compatible = "nxp,pit";
        status = "disabled";
        num-channels = <1>;
        #address-cells = <1>;
        #size-cells = <0>;

        pit0_channel0: pit0_channel@0 {
            compatible = "nxp,pit-channel";
            reg = <0>;
            status = "disabled";
        };
};

  • nxp,kinetis-ethernet 已弃用，改用 nxp,enet。树内所有 SoC 都已转换为使用这一新模式。因此，所有使用 NXP ENET 外设的开发板都需要在设备树中改用此绑定，它还对应另一个版本的驱动。或者，也可以删除以太网节点并按旧绑定重新定义，以使用已弃用的旧版驱动。新绑定的主要优点是能够通过 MDIO API 抽象任意 PHY。(GitHub #70400) 开发板级 ENET 设备树基本定义示例：

    &enet_mac {
    status = "okay";
    pinctrl-0 = <&pinmux_enet>;
    pinctrl-names = "default";
    phy-handle = <&phy>;
    zephyr,random-mac-address;
    phy-connection-type = "rmii";
};

&enet_mdio {
    status = "okay";
    pinctrl-0 = <&pinmux_enet_mdio>;
    pinctrl-names = "default";
    phy: phy@3 {
        compatible = "ethernet-phy";
        reg = <3>;
        status = "okay";
    };
};

  • nxp,kinetis-lptmr compatible 字符串已改为 nxp,lptmr。旧字符串在短期内仍可使用，但应尽快替换，因为它将来会被移除。

  • 部分驱动 API 结构体已重命名，以带上必需的 _driver_api 后缀。(GitHub #72182) 以下类型已重命名：

    • emul_sensor_backend_api 改为 emul_sensor_driver_api

    • emul_bbram_backend_api 改为 emul_bbram_driver_api

    • usbc_ppc_drv 改为 usbc_ppc_driver_api

  • maxim,max31790 的驱动被拆分为一个 MFD 驱动和一个真正的 PWM 驱动。(GitHub #68433) 此前，该设备的实例可以这样定义：

    max31790_max31790: max31790@20 {
    compatible = "maxim,max31790";
    status = "okay";
    reg = <0x20>;
    pwm-controller;
    #pwm-cells = <2>;
};

    可以转换为：

    max31790_max31790: max31790@20 {
    compatible = "maxim,max31790";
    status = "okay";
    reg = <0x20>;

    max31790_max31790_pwm: max31790_max31790_pwm {
        compatible = "maxim,max31790-pwm";
        status = "okay";
        pwm-controller;
        #pwm-cells = <2>;
    };
};

  • invensense,icm42688 的驱动现在能正确支持设备树配置（GitHub #74267）。以前的设备树可能尝试使用绑定来设置加速度计/陀螺仪的采样率和量程，但没有任何效果。现在设备树应使用所提供的宏定义和包含文件，以及接受这些值的新绑定。

    例如：

    #include <zephyr/dt-bindings/sensor/icm42688.h>

icm42688: icm42688@0 {
    accel-pwr-mode = <ICM42688_ACCEL_LN>;
    accel-fs = <ICM42688_ACCEL_FS_16G>;
    accel-odr = <ICM42688_ACCEL_ODR_2000>;
    gyro-pwr-mode= <ICM42688_GYRO_LN>;
    gyro-fs = <ICM42688_GYRO_FS_2000>;
    gyro-odr = <ICM42688_GYRO_ODR_2000>;
};

  • st,lis2mdl 的属性 spi-full-duplex 改为 duplex = SPI_FULL_DUPLEX。现在默认为全双工。

  • 移除了 nxp,lpc-lpadc 驱动的设备树属性 nxp,reference-supply，如果设备树中有该属性，用户应将其删除。新增了 phandle-array 类型的设备树属性 nxp,references，用户可以用它指定 LPADC 使用的参考电压及参考电压值。(GitHub #75005)

  • microchip,ksz8081 PHY 绑定的设备树属性 mc,interface-type、mc,reset-gpio 和 mc,interrupt-gpio 已分别改为 microchip,interface-type、reset-gpios 和 int-gpios（GitHub #73725）

充电器

  • 删除了 charger_max20335 驱动中的 constant-charge-current-max-microamp 属性，因为它并不反映芯片的实际功能。(GitHub #69910)

  • 为 maxim,max20335-charger 绑定中的 constant-charge-voltage-max-microvolt 属性添加了 enum 键，以便在构建时指出无效的设备树值。(GitHub #69910)

控制器局域网（CAN）

  • 移除了以下已弃用的 CAN 控制器设备树属性。使用这些属性的树外开发板可以改用 bitrate、sample-point、bitrate-data 和 sample-point-data 设备树属性（或依靠 CONFIG_CAN_DEFAULT_BITRATE 和 CONFIG_CAN_DEFAULT_BITRATE_DATA）来指定初始 CAN 比特率：

    • sjw

    • prop-seg

    • phase-seg1

    • phase-seg2

    • sjw-data

    • prop-seg-data

    • phase-seg1-data

    • phase-seg2-data

    bus-speed 和 bus-speed-data CAN 控制器设备树属性已弃用。

    (GitHub #68714)

  • 重新设计了对手动总线关闭（bus-off）恢复的支持（GitHub #69460）：

    • 无论 Kconfig 选项如何设置，驱动初始化时都会始终启用自动总线恢复。由于 CAN 控制器初始化后处于“停止”状态，此时不会启动不必要的总线关闭恢复。

    • Kconfig 选项 CONFIG_CAN_AUTO_BUS_OFF_RECOVERY 已重命名（并且含义反转）为 CONFIG_CAN_MANUAL_RECOVERY_MODE，默认禁用。该 Kconfig 选项启用对 can_recover() API 函数以及新的手动恢复模式（见下一条）的支持。

    • 新增了 CAN 控制器工作模式 CAN_MODE_MANUAL_RECOVERY。只有启用 CONFIG_CAN_MANUAL_RECOVERY_MODE 时才支持该模式。将其设计为一种模式后，应用程序可以通过 can_get_capabilities() API 函数查询 CAN 控制器是否支持手动恢复模式，然后选择让初始化失败，或者依靠自动总线关闭恢复。此外，这样设计还使不支持手动恢复模式的 CAN 控制器驱动能够在应用程序启动阶段调用 can_set_mode() 时就尽早失败，而不是等到之后调用 can_recover() 时才失败。

加密

  • 弃用了 NXP lpc55s36 上的 CSS 驱动（GitHub #71173）。

显示

  • 基于 GC9X01 的显示屏现在使用 MIPI DBI 驱动类。现在必须在 MIPI DBI 驱动封装设备中声明这些显示屏，由该设备负责与显示屏的接口通信。(GitHub #73686) 示例如下：

    /* Legacy GC9X01 display definition */
&spi0 {
    gc9a01: gc9a01@0 {
        status = "okay";
        compatible = "galaxycore,gc9x01x";
        reg = <0>;
        spi-max-frequency = <100000000>;
        cmd-data-gpios = <&gpio0 8 GPIO_ACTIVE_HIGH>;
        reset-gpios = <&gpio0 14 GPIO_ACTIVE_LOW>;
        ...
    };
};

/* New display definition with MIPI DBI device */

#include <zephyr/dt-bindings/mipi_dbi/mipi_dbi.h>

...

mipi_dbi {
    compatible = "zephyr,mipi-dbi-spi";
    dc-gpios = <&gpio0 8 GPIO_ACTIVE_HIGH>;
    reset-gpios = <&gpio0 14 GPIO_ACTIVE_LOW>;
    spi-dev = <&spi0>;
    #address-cells = <1>;
    #size-cells = <0>;

    gc9a01: gc9a01@0 {
        status = "okay";
        compatible = "galaxycore,gc9x01x";
        reg = <0>;
        mipi-max-frequency = <100000000>;
        ...
    };
};

蓝牙

蓝牙 HCI

  • 引入了新的 HCI 驱动 API（GitHub #72323），并弃用了旧 API。新 API 遵循 Zephyr 常规的驱动模型，使用设备树节点等。主机现在通过查找 zephyr,bt-hci chosen 属性来选择用作控制器的驱动实例。所有 HCI 驱动的设备树绑定都派生自通用的 bt-hci.yaml 基础绑定。

  • 作为新 HCI 驱动 API 的一部分，不再使用 zephyr,bt-uart chosen 属性，UART HCI 驱动改为通过查找 HCI 驱动实例节点的父设备树节点来选择所用的 UART。

  • 作为新 HCI 驱动 API 的一部分，zephyr,bt-hci-ipc chosen 属性只用于控制器端，而 HCI 驱动现在依赖 compatible 字符串为 zephyr,bt-hci-ipc 的节点。

  • 移除了 BT_NO_DRIVER Kconfig 选项。HCI 驱动不再位于 Kconfig choice 之下，而是可以各自独立启用和禁用，这主要取决于其对应的设备树节点是否启用。

  • 删除了 BT_HCI_VS_EXT Kconfig 选项，该功能现在包含在 CONFIG_BT_HCI_VS Kconfig 选项中。

  • 移除了 BT_HCI_VS_EVT Kconfig 选项，因为只要启用 CONFIG_BT_HCI_VS 选项，就隐含支持厂商事件。

  • 移除了 bt_read_static_addr() API。它其实并不是完全公开的 API，但由于它通过公共头文件 hci_driver.h 对外暴露，因此在此说明其移除。请改为启用 CONFIG_BT_HCI_VS Kconfig 选项，并在可用时使用厂商特定 HCI 命令 API 获取控制器的蓝牙静态地址。

蓝牙 Mesh

  • bt_mesh_model 的模型元数据指针声明已改为添加 const 限定符。bt_mesh_models_metadata_entry 的数据指针也加上了 const 限定符。模型的元数据结构和元数据原始值可以声明为非易失性存储器中的永久常量。(GitHub #69679)

  • bt_mesh_model 的模型元数据指针声明已改为单个 const *，并移除了 bt_mesh_health_srv 中冗余的元数据指针。因此，BT_MESH_MODEL_HEALTH_SRV 定义改为使用可变参数形式。现在，当实现支持 CONFIG_BT_MESH_LARGE_COMP_DATA_SRV 且需要为 Health Server 模型指定元数据时，只需将元数据作为最后一个参数传给 BT_MESH_MODEL_HEALTH_SRV 宏，否则省略最后一个参数即可。(GitHub #71281)

    • bt_audio_codec_cfg_meta_get_lang()

蓝牙主机

蓝牙加密

  • 新增了 CONFIG_BT_USE_PSA_API，用于显式要求在加密操作中使用 PSA API 而不是 TinyCrypt。当然，这只有在系统中存在 PSA 加密提供者（即设置了 CONFIG_PSA_CRYPTO_CLIENT）时才可行。(GitHub #73378)

网络

  • 弃用了 CONFIG_NET_SOCKETS_POSIX_NAMES 选项。这是一个遗留选项，用于让用户在不启用 POSIX API 的情况下调用 BSD 套接字 API。在构建希望启用 CONFIG_POSIX_API 选项的应用程序时，它可能导致问题。这意味着，如果应用程序要使用常规的 BSD 套接字接口，就需要启用 CONFIG_POSIX_API。如果应用程序不想或无法启用该选项，则套接字 API 调用需要加上 zsock_ 前缀。所有使用 BSD 套接字接口的示例应用程序都已改为启用 CONFIG_POSIX_API。网络协议栈内部不会启用 POSIX API 选项，因此各个使用套接字的网络库都已改为调用 zsock_* API。(GitHub #69950)

  • zperf 的 zperf_results 结构体已修改，传输字节数（total_len）和测试时长（time_in_us 和 client_time_in_us）改为 64 位而非 32 位，使长时间的 zperf 测试能显示正确的吞吐量结果。(GitHub #69500)

  • 分配给网络接口的每个 IPv4 地址都绑定了各自的 IPv4 子网掩码，而不是为整个接口设置一个掩码。如果网络接口只指定了一个 IPv4 地址，从用户角度看没有任何变化。但如果一个网络接口有多个 IPv4 地址，则必须为每个 IPv4 地址分别指定子网掩码。(GitHub #68419)

  • 虚拟网络接口 API 不再提供 input 回调。该回调用于读取 IP 隧道中内层的 IPv4/IPv6 数据包。隧道入站读取现在在 recv 回调中实现。(GitHub #70549)

  • 虚拟局域网（VLAN）的实现已改为使用虚拟网络接口。API 没有变化，但 VLAN 网络接口的类型从 ETHERNET 改为 VIRTUAL。这可能需要修改为网络接口设置 VLAN 标签的代码。例如，在 net_eth_is_vlan_enabled() API 中，第 2 个参数（接口）必须指向主以太网接口，而不是 VLAN 接口。(GitHub #70345)

  • 修改了 wifi connect 命令，参数改用键值格式。在之前的实现中，选项是根据其在参数字符串中的位置来识别的，这使得处理可选参数或扩展对其他选项的支持都很困难。采用键值格式后，更容易扩展可传给 connect 命令的选项。wifi -h 会给出 connect 命令用法的更多信息。(GitHub #70024)

  • 弃用了 Kconfig 选项 CONFIG_NET_TCP_ACK_TIMEOUT。它仅用于 TCP 握手，而在这种情况下，总超时应（与其他情况一样）取决于总重传超时，因此该配置既多余又容易引起混淆。请改用 CONFIG_NET_TCP_INIT_RETRANSMISSION_TIMEOUT 和 CONFIG_NET_TCP_RETRY_COUNT 在 TCP 层控制总超时。(GitHub #70731)

  • 在 LwM2M API 中，回调类型 lwm2m_engine_set_data_cb_t 新增了参数 offset，用于指示 CoAP 分块传输期间数据的偏移量。所有写后（post write）、校验以及部分固件回调都应更新以包含该参数。(GitHub #72590)

  • DNS 解析器和 mDNS/LLMNR 响应器已改为使用套接字服务 API。这意味着可能需要增加系统中可轮询套接字的数量。请检查 CONFIG_NET_SOCKETS_POLL_MAX 和 CONFIG_POSIX_MAX_FDS 的值是否足够大。遗憾的是，无法给出确切的数值，因为这取决于应用程序的需求和使用方式。(GitHub #72834)

  • socket API 调用中数据包套接字（类型 AF_PACKET）的协议字段已更改。协议字段应采用网络字节序，以便与 Linux 套接字调用兼容。如果希望接收所有网络数据包，Linux 要求协议字段为 htons(ETH_P_ALL)。详见 https://www.man7.org/linux/man-pages/man7/packet.7.html 文档。(GitHub #73338)

  • TCP 现在使用 SHA-256 而不是 MD5 生成 ISN。这一哈希计算的加密支持也从 Mbed TLS 改为 PSA API。具体做法是让 CONFIG_NET_TCP_ISN_RFC6528 依赖 PSA_WANT_ALG_SHA_256，而不是旧版 CONFIG_MBEDTLS_* 功能。(GitHub #71827)

其他子系统

Flash 映射

  • Flash 校验函数的加密后端（CONFIG_FLASH_AREA_CHECK_INTEGRITY_BACKEND）以前由 TinyCrypt 或 Mbed TLS 提供，现在改由 PSA 或 Mbed TLS 提供。更新后的 Mbed TLS 实现比之前的 TinyCrypt 实现占用空间略小，而对于使用 TF-M 构建的设备，PSA 实现还能进一步减少占用空间。PSA 是今后受支持的方式，但目前如果无法承担启用 PSA API（对于不带 TF-M 的设备为 CONFIG_MBEDTLS_PSA_CRYPTO_C）的一次性开销，仍可使用 Mbed TLS。GitHub #73511

hawkBit

  • CONFIG_HAWKBIT_PORT 现在是整数而不是字符串。使用 hawkBit 需要启用 CONFIG_SETTINGS，因为它现在使用设置子系统来保存 hawkBit 配置。(GitHub #68806)

MCUmgr

  • 对 SHA-256 的支持（使用校验和/哈希函数时）以前由 TinyCrypt 或 Mbed TLS 提供，现在改由 PSA 或 Mbed TLS 提供。今后推荐使用 PSA API，但如果尚未启用它（CONFIG_MBEDTLS_PSA_CRYPTO_CLIENT）且代码大小受到严格限制，改用 Mbed TLS 可能节省 1.3 KB。

调制解调器

  • Kconfig 选项 CONFIG_MODEM_CHAT_LOG_BUFFER 已重命名为 CONFIG_MODEM_CHAT_LOG_BUFFER_SIZE。(GitHub #70405)

POSIX API

状态机框架

  • SMF_CREATE_STATE 宏现在始终接受 5 个参数。参数个数不再取决于 CONFIG_SMF_ANCESTOR_SUPPORT 和 CONFIG_SMF_INITIAL_TRANSITION 的值。如果不使用额外的参数，必须将其设置为 NULL。(GitHub #71250)

  • 当转换源是 smf_run_state() 所调用状态的父状态时，SMF 现在遵循更接近 UML 的转换流程：执行从转换源到转换源与目标状态的最近公共祖先（LCA，不含）为止的退出动作，并执行从 LCA（不含）向下到目标状态的进入动作。(GitHub #71675)

  • 以前，调用 smf_set_state() 并将 new_state 设为 NULL 时，会执行从当前状态到最顶层父状态的所有退出动作，并期望最顶层的退出动作终止状态机。现在不允许传入 NULL。请改为在顶层创建一个“终止”状态，并在其进入动作中调用 smf_set_terminate()。
