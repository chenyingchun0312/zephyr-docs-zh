迁移到 Zephyr v4.2.0 的指南

本文档介绍将应用程序从 Zephyr v4.1.0 迁移到 Zephyr v4.2.0 时所需的更改。

构建系统

  • 对 HWMv1 的支持已被移除，任何 HWMv1 格式的树外开发板或 SoC 都必须迁移到 HWMv2，才能在 Zephyr v4.2 及以后的版本中使用。

内核

开发板

  • 所有基于 Nordic IC、默认使用 Nordic 命令行工具 nrfjprog 进行烧录的开发板，现已改为默认使用新的 nRF Util（nrfutil）工具。这意味着你可能需要 安装 nRF Util；如果你希望继续使用 nrfjprog，可以在调用 west 时指定运行器：west flash -r nrfjprog。nRF Util 的完整文档请参阅 此处。

  • 所有基于 nRF54L 系列 Nordic IC 的开发板，现在默认在烧录时不擦除内部存储的任何部分。如果你想恢复以前的默认行为，即擦除待烧录固件将要写入的页，可以在调用 west flash 时将新的命令行开关 --erase-mode 设置为 ranges。请注意，nRF54L 器件上的 RRAM 在物理上并不分页，分页只是人为提供的，页大小为 4096 字节，目的是让 nRF52 软件更容易过渡到 nRF54L 器件。

  • 配置选项 CONFIG_NATIVE_POSIX_SLOWDOWN_TO_REAL_TIME 已被弃用，改用 CONFIG_NATIVE_SIM_SLOWDOWN_TO_REAL_TIME。

  • 设备树绑定 zephyr,native-posix-cpu 已被弃用，改用 zephyr,native-sim-cpu。

  • Zephyr 现在支持 NEORV32 的 1.11.6 版本。NEORV32 处理器（SoC）的实现需要更新到该版本，才能与 Zephyr v4.2.0 兼容。

  • NEORV32 现在通过开发板变体来对应 NEORV32 处理器（SoC）模板。原来的 neorv32 开发板目标现在名为 neorv32/neorv32/up5kdemo。

  • arduino_uno_r4_minima、arduino_uno_r4_wifi 和 mikroe_clicker_ra4m1 已迁移到新的基于 FSP 的配置。虽然功能上没有重大变化，但设备树结构做了大幅修改。以下设备树绑定现已被移除：renesas,ra-gpio、renesas,ra-uart-sci、renesas,ra-pinctrl、renesas,ra-clock-generation-circuit 和 renesas,ra-interrupt-controller-unit。请改用以下替代项： - renesas,ra-gpio-ioport - renesas,ra-sci-uart - renesas,ra-pinctrl-pfs - renesas,ra-cgc-pclk-block

  • Nucleo WBA52CG 开发板（nucleo_wba52cg）已不再受支持，因为它处于 NRND（Not Recommended for New Design，不推荐用于新设计）状态，且 STM32CubeWBA 从 1.1.0 版本（2023 年 7 月）起也不再支持它。建议迁移到 Nucleo WBA55CG（nucleo_wba55cg），迁移无需任何改动。

  • Espressif 开发板 esp32_devkitc_wroom 和 esp32_devkitc_wrover 的功能几乎完全相同。两者的差异已由 Kconfig 选项覆盖，因此这两个开发板已合并为 esp32_devkitc。

  • STM32 开发板现在应通过包含 openocd-stm32.board.cmake（而不是 openocd.board.cmake）来添加 OpenOCD 编程支持。openocd-stm32.board.cmake 文件在默认 OpenOCD 运行器的基础上扩展了厂商特定的配置，例如 STM32 整片擦除命令。

  • STM32N6570-DK 开发板的默认变体（stm32n6570_dk/stm32n657xx）现在应作为链式加载的应用程序，并且应使用 --sysbuild 构建。原来的默认变体会将应用程序构建为第一阶段引导加载程序（First Stage BootLoader）运行，现在作为一个专用变体（stm32n6570_dk/stm32n657xx/fsbl）提供，必须显式选择。有关这些变体的更多信息，请参阅开发板文档。

  • 内嵌 TF-M BL2 引导阶段的 STM32 开发板（b_u585i_iot02a//ns、nucleo_l552ze_q//ns 和 stm32l562e_dk//ns）不再像以前那样在 BL2 中内嵌硬件加密加速器驱动，而是改为依赖 Mbed TLS 的软件实现。这与升级到 TF-M v2.2 有关。TF-M 仍然支持硬件加密加速器，但仅限于运行时安全固件。

设备驱动与设备树

Audio

  • cirrus,cs43l22 的绑定文件已重命名，使其名称与 compatible 字符串一致。

Counter

  • counter_native_posix 已重命名为 counter_native_sim，其 Kconfig 选项和设备树绑定也随之重命名。zephyr,native-posix-counter 已被弃用，改用 zephyr,native-sim-counter；CONFIG_COUNTER_NATIVE_POSIX 及其相关选项已被弃用，改用 CONFIG_COUNTER_NATIVE_SIM（GitHub #86616）。

DAI

  • 设备树属性 dai_id 已重命名为 dai-id。

  • 设备树属性 afe_name 已重命名为 afe-name。

  • 设备树属性 agent_disable 已重命名为 agent-disable。

  • 设备树属性 ch_num 已重命名为 ch-num。

  • 设备树属性 mono_invert 已重命名为 mono-invert。

  • 设备树属性 quad_ch 已重命名为 quad-ch。

  • 设备树属性 int_odd 已重命名为 int-odd。

DMA

  • 设备树属性 nxp,a_on 已重命名为 nxp,a-on。

  • 设备树属性 dma_channels 已重命名为 dma-channels。

  • Xilinx DMA 控制器的绑定文件已重命名，改用正确的厂商前缀（xlnx 而不是 xilinx），并与其 compatible 字符串保持一致。

设备树

  • 原先位于 dts/common 中的许多厂商特定和架构特定文件已移动到更具体的位置。因此，任何通过 #include <common/some_file.dtsi> 包含 Zephyr 树中文件的 dts 文件，都需要改为直接 #include <some_file.dtsi>。

  • Silicon Labs Series 2 的 SoC 级 dts 文件已按器件超家族（superfamily）重新组织到各个子目录中。因此，使用 Series 2 SoC 的开发板的 dts 文件需要将包含语句从 #include <silabs/some_soc.dtsi> 改为 #include <silabs/xg2[1-9]/some_soc.dtsi>。

  • 当 DT_ENUM_HAS_VALUE 和 DT_INST_ENUM_HAS_VALUE 宏用于数组时，现在会检查所有值，而不仅仅是第一个值。

  • 设备树和绑定中的属性名称使用连字符（-）作为分隔符，取代此前使用的所有下划线（_）。对于本地代码，可以运行 scripts/utils/migrate_bindings_style.py 脚本，将绑定中的属性名称迁移为使用连字符。

显示

  • 在 STM32 器件上，LTDC 驱动（st,stm32-ltdc）的 RGB565 格式 PIXEL_FORMAT_RGB565 已替换为 PIXEL_FORMAT_BGR565，以匹配 Zephyr 期望的格式。此变更确保显示和视频采集示例都能正常工作。

EEPROM

  • ti,tmp116-eeprom 已重命名为 ti,tmp11x-eeprom，因为它同时支持 tmp117 和 tmp119。

增强型串行外设接口（eSPI）

  • 设备树属性 io_girq 已重命名为 io-girq。

  • 设备树属性 vw_girqs 已重命名为 vw-girqs。

  • 设备树属性 pc_girq 已重命名为 pc-girq。

  • 设备树属性 poll_timeout 已重命名为 poll-timeout。

  • 设备树属性 poll_interval 已重命名为 poll-interval。

  • 设备树属性 consec_rd_timeout 已重命名为 consec-rd-timeout。

  • 设备树属性 sus_chk_delay 已重命名为 sus-chk-delay。

  • 设备树属性 sus_rsm_interval 已重命名为 sus-rsm-interval。

熵源

  • fake_entropy_native_posix 已重命名为 fake_entropy_native_sim，其 Kconfig 选项和设备树绑定也随之重命名。zephyr,native-posix-rng 已被弃用，改用 zephyr,native-sim-rng；CONFIG_FAKE_ENTROPY_NATIVE_POSIX 及其相关选项已被弃用，改用 CONFIG_FAKE_ENTROPY_NATIVE_SIM（GitHub #86615）。

以太网

  • Kconfig 选项 ETH_STM32_HAL_MII 已被移除（GitHub #86074）。PHY 接口类型现在通过设备树中的 phy-connection-type 属性选择。

  • st,stm32-ethernet 驱动现在要求在设备树中将 phy-handle phandle 设置为对应的 PHY 节点（GitHub #87593）。

  • Kconfig 选项 ETH_STM32_HAL_PHY_ADDRESS、ETH_STM32_CARRIER_CHECK、ETH_STM32_CARRIER_CHECK_RX_IDLE_TIMEOUT_MS、ETH_STM32_AUTO_NEGOTIATION_ENABLE、ETH_STM32_SPEED_10M、ETH_STM32_MODE_HALFDUPLEX 已被移除，因为已不再需要；驱动现在使用以太网 PHY API 与 PHY 驱动通信，由 PHY 驱动负责配置 PHY 设置（GitHub #87593）。

  • ethernet_native_posix 已重命名为 ethernet_native_tap，其 Kconfig 选项也随之重命名：CONFIG_ETH_NATIVE_POSIX 及其相关选项已被弃用，改用 CONFIG_ETH_NATIVE_TAP（GitHub #86578）。

  • NuMaker 以太网驱动 eth_numaker.c 现在支持 gen_random_mac，EMAC 数据 Flash 功能已被移除（GitHub #87953）。

  • include/zephyr/net/ethernet.h 中的枚举 ETHERNET_DSA_MASTER_PORT 和 ETHERNET_DSA_SLAVE_PORT 已分别重命名为 ETHERNET_DSA_CONDUIT_PORT 和 ETHERNET_DSA_USER_PORT。

  • 表示以太网速率的枚举已重命名，使其更加独立于所用的介质。LINK_HALF_10BASE_T、LINK_FULL_10BASE_T、LINK_HALF_100BASE_T、LINK_FULL_100BASE_T、LINK_HALF_1000BASE_T、LINK_FULL_1000BASE_T、LINK_FULL_2500BASE_T 和 LINK_FULL_5000BASE_T 已分别重命名为 LINK_HALF_10BASE、LINK_FULL_10BASE、LINK_HALF_100BASE、LINK_FULL_100BASE、LINK_HALF_1000BASE、LINK_FULL_1000BASE、LINK_FULL_2500BASE 和 LINK_FULL_5000BASE。ETHERNET_LINK_10BASE_T、ETHERNET_LINK_100BASE_T、ETHERNET_LINK_1000BASE_T、ETHERNET_LINK_2500BASE_T 和 ETHERNET_LINK_5000BASE_T 已分别重命名为 ETHERNET_LINK_10BASE、ETHERNET_LINK_100BASE、ETHERNET_LINK_1000BASE、ETHERNET_LINK_2500BASE 和 ETHERNET_LINK_5000BASE（GitHub #87194）。

  • ETHERNET_CONFIG_TYPE_LINK、ETHERNET_CONFIG_TYPE_DUPLEX、ETHERNET_CONFIG_TYPE_AUTO_NEG 以及相关的 NET_REQUEST_ETHERNET_SET_LINK、NET_REQUEST_ETHERNET_SET_DUPLEX、NET_REQUEST_ETHERNET_SET_AUTO_NEGOTIATION 已被移除。应改为结合使用 phy_configure_link() 和 net_eth_get_phy() 来配置链路（GitHub #90652）。

  • phy_configure_link() 新增了 flags 参数。将其设置为 0 可保持原有行为（GitHub #91354）。

Flash

  • 文件 flash_hp_ra.h 已重命名为 soc_flash_renesas_ra_hp.h。

  • 文件 flash_hp_ra.c 已重命名为 soc_flash_renesas_ra_hp.c。

  • 文件 flash_hp_ra_ex_op.c 已重命名为 soc_flash_renesas_ra_hp_ex_op.c。

  • Flash HP Renesas RA 双 bank 模式 Kconfig 符号 CONFIG_DUAL_BANK_MODE 已被移除。

  • Flash HP Renesas RA Kconfig 符号 CONFIG_RA_FLASH_HP 已重命名为 CONFIG_SOC_FLASH_RENESAS_RA_HP。

  • Flash HP Renesas RA 写保护 Kconfig 符号 CONFIG_FLASH_RA_WRITE_PROTECT 已重命名为 CONFIG_FLASH_RENESAS_RA_HP_WRITE_PROTECT。

  • 文件 renesas,ra-nv-flash.yaml 已拆分为 renesas,ra-nv-code-flash.yaml 和 renesas,ra-nv-data-flash.yaml 两个文件。

  • compatible 已从 renesas,ra-nv-flash 拆分为 renesas,ra-nv-code-flash.yaml 和 renesas,ra-nv-data-flash.yaml。

GPIO

  • 为了支持引脚数量较多的 RP2350B，Raspberry Pi GPIO 的配置方式已经更改。raspberrypi,rpi-gpio 原有的功能已迁移到 raspberrypi,rpi-gpio-port，raspberrypi,rpi-gpio 现在仅作为占位和映射节点保留。相关标签也已一并更改，因此常规使用无需任何改动。

  • arduino-nano-header-r3 已重命名为 arduino-nano-header。原因是 R3 源自 Arduino UNO R3，该版本相对之前的版本更改了连接器，与 Arduino Nano 无关。

  • 文件 include/zephyr/dt-bindings/gpio/nordic-npm1300-gpio.h 已移动到 include/zephyr/dt-bindings/gpio/nordic-npm13xx-gpio.h，并且宏定义中所有的 NPM1300 都已重命名为 NPM13XX

  • CONFIG_GPIO_NPM1300 已重命名为 CONFIG_GPIO_NPM13XX，CONFIG_GPIO_NPM1300_INIT_PRIORITY 已重命名为 CONFIG_GPIO_NPM13XX_INIT_PRIORITY

I2S

  • nxp,mcux-i2s 驱动新增了属性 mclk-output。设置此属性可以

  • 将 MCLK 信号配置为输出。旧版本驱动使用宏

  • I2S_OPT_BIT_CLK_SLAVE 来配置 MCLK 信号方向。（GitHub #88554）

LED

  • CONFIG_LED_NPM1300 已重命名为 CONFIG_LED_NPM13XX

MFD

  • 文件 include/zephyr/drivers/mfd/npm1300.h 已移动到 include/zephyr/drivers/mfd/npm13xx.h，并且枚举和函数名中所有的 npm1300/NPM1300 都已重命名为 npm13xx/NPM13XX

  • CONFIG_MFD_NPM1300 已重命名为 CONFIG_MFD_NPM13XX，CONFIG_MFD_NPM1300_INIT_PRIORITY 已重命名为 CONFIG_MFD_NPM13XX_INIT_PRIORITY

杂项

  • 文件 drivers/memc/memc_nxp_flexram.h 已移动到 include/zephyr/drivers/misc/flexram/nxp_flexram.h，以便可以通过 <zephyr/drivers/misc/flexram/nxp_flexram.h> 包含该文件。使用此驱动时不再需要修改 CMakeList.txt 来添加包含路径。

  • 所有以 memc_flexram_* 为命名空间的内容（包括 Kconfig 选项和 C API）都已改为仅以 flexram_* 命名。

  • 要启用 Ethos-U NPU 驱动，请选择 CONFIG_ETHOS_U，而不是 CONFIG_ARM_ETHOS_U。

  • 所有前缀为 CONFIG_ARM_ETHOS_U_ 的配置都应重命名为以 CONFIG_ETHOS_U_ 为前缀。

调制解调器

  • Kconfig 选项 CONFIG_MODEM_CELLULAR_CMUX_MAX_FRAME_SIZE 已被移除，改用 CONFIG_MODEM_CMUX_WORK_BUFFER_SIZE 和 CONFIG_MODEM_CMUX_MTU。

稳压器

  • 文件 include/zephyr/dt-bindings/regulator/npm1300.h 已移动到 include/zephyr/dt-bindings/regulator/npm13xx.h，并且宏定义中所有的 NPM1300 都已重命名为 NPM13XX

  • CONFIG_REGULATOR_NPM1300 已重命名为 CONFIG_REGULATOR_NPM13XX，CONFIG_REGULATOR_NPM1300_COMMON_INIT_PRIORITY 已重命名为 REGULATOR_NPM13XX_COMMON_INIT_PRIORITY，CONFIG_REGULATOR_NPM1300_INIT_PRIORITY 已重命名为 CONFIG_REGULATOR_NPM13XX_INIT_PRIORITY

  • nordic,npm1300-regulator 的 BUCK 和 LDO 节点 GPIO 属性现在以不带 GPIO 控制器的整数数组形式指定，因此不再要求必须存在并启用 nordic,npm1300-gpio 节点才能通过 GPIO 控制输出电源轨。例如，enable-gpios = <&pmic_gpios 3 GPIO_ACTIVE_LOW>; 现在应写为 enable-gpio-config = <3 GPIO_ACTIVE_LOW>;。

SPI

  • CONFIG_SPI_MCUX_LPSPI 已重命名为 CONFIG_SPI_NXP_LPSPI，该驱动的所有子配置也做了类似的重命名，包括 CONFIG_SPI_NXP_LPSPI_DMA 和 CONFIG_SPI_NXP_LPSPI_CPU。

  • 设备树属性 port_sel 已重命名为 port-sel。

  • 设备树属性 chip_select 已重命名为 chip-select。

  • andestech,atcspi200 的绑定文件已重命名，使其名称与 compatible 字符串一致。

传感器

  • 厂商前缀 ltr 已重命名为 liteon，相应地，ltr,f216a 已替换为 liteon,ltrf216a。选项 DT_HAS_LTR_F216A_ENABLED 已替换为 DT_HAS_LITEON_LTRF216A_ENABLED（GitHub #85453）

  • ti,tmp116 已重命名为 ti,tmp11x，因为它同时支持 tmp116、tmp117 和 tmp119。

  • meas,ms5837 已替换为 meas,ms5837-30ba 和 meas,ms5837-02ba。要使用这两个变体之一，还需要同时使用 status 属性。

  • we,wsen-itds 驱动已重命名为 we,wsen-itds-2533020201601。设备树可按如下方式配置：

    &i2c0 {
  itds:itds-2533020201601@19 {
    compatible = "we,wsen-itds-2533020201601";
    reg = <0x19>;
    odr = "400";
    op-mode = "high-perf";
    power-mode = "normal";
    events-interrupt-gpios = <&gpio1 1 GPIO_ACTIVE_HIGH>;
    drdy-interrupt-gpios = <&gpio1 2 GPIO_ACTIVE_HIGH>;
  };
};

  • raspberrypi,pico-temp.yaml 的绑定文件已重命名，使其名称与 compatible 字符串一致。

  • 文件 include/zephyr/drivers/sensor/npm1300_charger.h 已移动到 include/zephyr/drivers/sensor/npm13xx_charger.h，并且枚举中所有的 NPM1300 都已重命名为 NPM13XX

  • CONFIG_NPM1300_CHARGER 已重命名为 CONFIG_NPM13XX_CHARGER

串口

  • uart_native_posix 已重命名为 uart_native_pty，其 Kconfig 选项和设备树绑定也随之重命名。zephyr,native-posix-uart 已被弃用，改用 zephyr,native-pty-uart；CONFIG_UART_NATIVE_POSIX 及其相关选项已被弃用，改用 CONFIG_UART_NATIVE_PTY。选项 CONFIG_NATIVE_UART_0 已替换为 CONFIG_UART_NATIVE_PTY_0，不过现在也可以在运行时通过命令行选项 --<uart_name>_stdinout 选择让 UART 连接到进程的 stdin/stdout，而不是连接到 PTY。CONFIG_NATIVE_UART_AUTOATTACH_DEFAULT_CMD 已替换为 CONFIG_UART_NATIVE_PTY_AUTOATTACH_DEFAULT_CMD。CONFIG_UART_NATIVE_WAIT_PTS_READY_ENABLE 已被弃用，它所启用的功能现在始终启用，因为该功能没有任何副作用。CONFIG_UART_NATIVE_POSIX_PORT_1_ENABLE 已被弃用，该选项现在不起任何作用。用户应当按需要的原生 PTY UART 实例数量，实例化相应数量的 zephyr,native-pty-uart 节点。（GitHub #86739）

步进电机

  • 函数 stepper_enable(const struct device * dev, bool enable) 已重构为 stepper_enable() 和 stepper_disable()。

定时器

  • native_posix_timer 已重命名为 native_sim_timer，因此其 Kconfig 选项 CONFIG_NATIVE_POSIX_TIMER 已被弃用，改用 CONFIG_NATIVE_SIM_TIMER（GitHub #86612）。

  • andestech,machine-timer、neorv32-machine-timer、telink,machine-timer、lowrisc,machine-timer、niosv-machine-timer 和 scr,machine-timer 已统一为 riscv,machine-timer。

    现在必须使用 reg 和 reg-names 属性显式指定 MTIME 和 MTIMECMP 两个寄存器的地址。reg-names 属性现在是 必需的，其中列出的名称必须与 reg 中的各个条目一一对应。（GitHub #84175 和 GitHub #89847）

    示例：

    mtimer: timer@d1000000 {
    compatible = "riscv,machine-timer";
    interrupts-extended = <&cpu0_intc 7>;
    reg = <0xd1000000 0x8
           0xd1000008 0x8>;
    reg-names = "mtime", "mtimecmp";
};

  • 现在可以在 cpus DTS 组中使用 timebase-frequency 属性来提供 CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC 的值，而不必直接设置该值：GitHub #91296

视频

  • 8 位 RAW Bayer 格式 BGGR8 / GBRG8 / GRBG8 / RGGB8 已重命名，在前面加上了 S 前缀：

    VIDEO_PIX_FMT_BGGR8 变为 VIDEO_PIX_FMT_SBGGR8 VIDEO_PIX_FMT_GBRG8 变为 VIDEO_PIX_FMT_SGBRG8 VIDEO_PIX_FMT_GRBG8 变为 VIDEO_PIX_FMT_SGRBG8 VIDEO_PIX_FMT_RGGB8 变为 VIDEO_PIX_FMT_SRGGB8

  • 在 STM32 器件上，DCMI 驱动（st,stm32-dcmi）现在依赖基于端点（endpoint）的 video-interfaces.yaml 绑定来获取传感器接口属性（例如总线宽度和同步信号）。此外，capture-rate 属性已被帧间隔 API video_set_frmival() 取代。参见（GitHub #89627）。

  • video_endpoint_id 已被移除，它不再是任何视频 API 的参数。

  • 新增了 video_buf_type。它是以下视频 API 的必需参数：set_stream()、video_stream_start()、video_stream_stop()

  • video_format.pitch 现在改为由驱动显式设置，此前这项工作需要由应用程序完成。这一更新使应用程序能够针对各个驱动正确分配缓冲区大小。现有应用程序不会因此变更而出错，但可以按照提交 33dcbe37cfd3593e8c6e9cfd218dd31fdd533598 中对示例所做的修改进行简化。

  • 使用 原生模拟器 的示例和项目现在需要指定 --snippet video-sw-generator 才能正确构建。

  • video_query_ctrl() 现在只接受一个 video_ctrl_query 参数，该结构体现在包含一个 video_ctrl_query.dev 字段，用于指定并回读被查询的设备（GitHub #91265）。

看门狗

  • CONFIG_WDT_NPM1300 已重命名为 CONFIG_WDT_NPM13XX，CONFIG_WDT_NPM1300_INIT_PRIORITY 已重命名为 CONFIG_WDT_NPM13XX_INIT_PRIORITY

qSPI/oSPI/xSPI

  • 在 STM32 器件上，外部存储器在设备树中的大小和地址描述现已拆分为两个独立的属性，以符合规范建议。

    例如，以下外部 Flash 描述 reg = <0x70000000 DT_SIZE_M(64)>; /* 512 Mbits / 改为 reg = <0>; size = <DT_SIZE_M(512)>; / 512 Mbits */。

    请注意，该属性给出的是存储器件的实际大小，单位为位（bit）。以前的映射地址信息现在在 SoC dtsi 层级的 xspi、ospi 或 qspi 节点中描述。

Bluetooth

Bluetooth 音频

  • CONFIG_BT_CSIP_SET_MEMBER_NOTIFIABLE 已重命名为 CONFIG_BT_CSIP_SET_MEMBER_SIRK_NOTIFIABLE。（GitHub #86763）

  • bt_csip_set_member_get_sirk 已被移除。请使用 bt_csip_set_member_get_info() 获取 SIRK（以及其他信息）。（GitHub #86996）

  • BT_AUDIO_CONTEXT_TYPE_PROHIBITED 已重命名为 BT_AUDIO_CONTEXT_TYPE_NONE。（GitHub #89506）

经典 Bluetooth

  • 结构体 bt_hfp_ag_cb 中 HFP AG 回调 sco_disconnected 的参数已改为 SCO 连接对象 struct bt_conn *sco_conn 和 SCO 连接的断开原因 uint8_t reason。

Bluetooth HCI

  • 通过 HCI 驱动接口传递的缓冲区类型，现在以 H:4 编码的前缀字节形式作为缓冲区负载本身的一部分来表示。bt_buf_set_type() 和 bt_buf_get_type() 函数已被弃用，但仍可使用，只是每个缓冲区只能调用一次。

  • bt_hci_cmd_create() 函数已被弃用，应改用新的 bt_hci_cmd_alloc() 函数。新函数不接受任何参数，因为命令发送函数已更新为自行完成命令头编码。

Bluetooth 主机（Host）

  • include/zephyr/bluetooth/conn.h 中的符号 BT_LE_CS_TONE_ANTENNA_CONFIGURATION_INDEX_<NUMBER> 已重命名为 BT_LE_CS_TONE_ANTENNA_CONFIGURATION_A<NUMBER>_B<NUMBER>。

  • ISO 数据路径不再自动建立，应用程序必须分别调用 bt_iso_setup_data_path() 和 bt_iso_remove_data_path() 来显式建立和移除数据路径。（GitHub #75549）

  • BT_ISO_CHAN_TYPE_CONNECTED 已拆分为 BT_ISO_CHAN_TYPE_CENTRAL 和 BT_ISO_CHAN_TYPE_PERIPHERAL，以更好地描述 ISO 通道的类型，因为不同角色的行为可能不同。现有对 BT_ISO_CHAN_TYPE_CONNECTED 的使用或检查，都可以替换为这两者的 ||。（GitHub #75549）

  • include/zephyr/bluetooth/gatt.h 中的 struct _bt_gatt_ccc 已重命名为结构体 bt_gatt_ccc_managed_user_data。（GitHub #88652）

  • include/zephyr/bluetooth/gatt.h 中的宏 BT_GATT_CCC_INITIALIZER 已重命名为 BT_GATT_CCC_MANAGED_USER_DATA_INIT。（GitHub #88652）

  • Kconfig 选项 CONFIG_BT_ISO_TX_FRAG_COUNT 已被移除，因为它完全未被使用。对它的任何使用都可以直接删除。（GitHub #89836）

网络

  • 结构体 net_linkaddr_storage 已重命名为结构体 net_linkaddr，原来的结构体 net_linkaddr 已被移除。结构体 net_linkaddr 现在包含用于存储链路地址的空间，而不是一个指向链路地址的指针。这样可以避免在克隆结构体 net_pkt 时可能出现的悬空指针。对于 IEEE 802.15.4，这会使结构体 net_pkt 的大小增加 4 个字节，而对于以太网等其他网络技术则不会增加大小。请注意，任何直接使用结构体 net_linkaddr 并包含诸如 if (lladdr->addr == NULL) 之类检查的代码将无法再按预期工作（因为 addr 不再是指针）；如果代码要检查链路地址是否未设置，必须改为 if (lladdr->len == 0)。

  • TLS 凭据类型 TLS_CREDENTIAL_SERVER_CERTIFICATE 已重命名为更通用的 TLS_CREDENTIAL_PUBLIC_CERTIFICATE，以更好地反映该凭据类型的用途。

  • MQTT 公共 API 函数 mqtt_disconnect() 已更改。该函数现在额外接受一个 param 参数以支持 MQTT 5.0。该参数是可选的，在旧版本 MQTT 中不使用，MQTT 3.1.1 用户应传入 NULL 作为参数。

  • 不再支持 AF_PACKET/SOCK_RAW/IPPROTO_RAW 套接字组合，因为 AF_PACKET 套接字只应接受 IEEE 802.3 协议号。作为替代，可以根据实际用例使用 AF_PACKET/SOCK_DGRAM/ETH_P_ALL 或 AF_INET(6)/SOCK_RAW/IPPROTO_IP 套接字。

  • HTTP 服务器现在会遵循所配置的 _concurrent 和 _backlog 值。请检查是否为 HTTP_SERVICE_DEFINE_EMPTY、HTTPS_SERVICE_DEFINE_EMPTY、HTTP_SERVICE_DEFINE 和 HTTPS_SERVICE_DEFINE 提供了合适的值。

  • CONFIG_NET_ZPERF 默认不再包含服务器支持。要使用服务器命令，请启用 CONFIG_NET_ZPERF_SERVER。如果不需要服务器支持，可以考虑减小 CONFIG_ZVFS_POLL_MAX。

  • L2 Wi-Fi shell 现在为大多数命令提供了接口选项，为适应这一变化，部分现有选项已重命名。下表汇总了这些变化：

    命令

    旧选项

    新选项

    wifi connect wifi ap enable

    -i

    -g

    wifi twt setup

    -i

    -p

    wifi ap config

    -i

    -t

    wifi mode wifi channel wifi packet_filter

    --if-index

    --iface

  • HTTP 客户端响应回调 http_response_cb_t 的签名已更改。回调函数现在返回 int 而不是 void，这使应用程序可以中止 HTTP 连接。现有应用程序需要更新其响应回调的实现。要保持当前行为，只需在回调中返回 0。

  • net_mgmt 事件处理函数 net_mgmt_event_handler_t 和请求处理函数 net_mgmt_request_handler_t 的 API 签名已更改。管理事件类型从 uint32_t 改为 uint64_t。这一变更使事件编号值可以是位掩码而不是枚举值，层代码仍然是枚举值。如有需要，可以在请求或事件处理函数中使用 NET_MGMT_LAYER_CODE 和 NET_MGMT_GET_COMMAND 从实际事件值中获取层代码和管理事件命令。

  • net_mgmt 类型套接字的套接字选项不能再直接使用网络管理事件类型，因为这些类型现在是 uint64_t，而套接字选项期望的是普通的 32 位整数值。因此新增了 SO_NET_MGMT_ETHERNET_SET_QAV_PARAM 和 SO_NET_MGMT_ETHERNET_GET_QAV_PARAM 套接字选项，用于取代之前使用的 NET_REQUEST_ETHERNET_SET_QAV_PARAM 和 NET_REQUEST_ETHERNET_GET_QAV_PARAM 选项。

  • DNS 服务器解析器配置函数 dns_resolve_reconfigure() 和 dns_resolve_reconfigure_with_interfaces() 现在要求用户提供 DNS 服务器信息的来源。例如，当 DNS 服务器信息通过 DHCPv4 获得时，需要指定 DNS_SOURCE_DHCPV4。

LwM2M

  • 加速度计对象：按照加速度计对象规范，可选资源 Y 值、Z 值、最小量程值、最大量程值现在可以按需使用。使用这些资源的用户现在需要提供读取缓冲区。

OpenThread

  • Zephyr 中的 OpenThread 协议栈集成经过了一次大规模重构。其实现已从 Zephyr 网络层（subsys/net/l2/openthread/）移到了一个专用模块（modules/openthread/）中。

  • OpenThread 现在是 Zephyr 中的一个独立模块，可以独立于 Zephyr 网络协议栈（L2 和 IEEE802.15.4 适配层）使用。这带来了新的用例，例如应用程序直接将 OpenThread 与自己的 IEEE802.15.4 驱动一起使用，或者不需要完整的 Zephyr 网络协议栈。

  • include/zephyr/net/openthread.h 文件中的大多数函数已被弃用。这些已弃用的 API 仍可使用以保持向后兼容，但新应用程序应使用 OpenThread 模块提供的新 API。以下列表汇总了这些变化：

    • 互斥量处理：

      • 以前：

        • openthread_api_mutex_lock

        • openthread_api_mutex_try_lock

        • openthread_api_mutex_unlock

      • 现在使用：

        • openthread_mutex_lock()

        • openthread_mutex_try_lock()

        • openthread_mutex_unlock()

    • 启动 OpenThread：

      • 以前：openthread_start

      • 现在使用：openthread_run()

    • 回调注册：

      • 以前：

        • openthread_state_changed_cb_register

        • openthread_state_changed_cb_unregister

      • 现在使用：

        • openthread_state_changed_callback_register()

        • openthread_state_changed_callback_unregister()

    • 回调结构体：

      • 以前：openthread_state_changed_cb

      • 现在使用：openthread_state_changed_callback

    • 以下 openthread_context 结构体字段已被弃用，新代码中不得再使用：

      • instance

      • api_lock

      • work_q

      • api_work

      • state_change_cbs

    • 以前没有的新函数：

      • openthread_init()：初始化 OpenThread 协议栈。

      • openthread_stop()：停止并禁用 OpenThread 协议栈。

      • openthread_set_receive_cb()：设置 OpenThread 协议栈的接收回调。

  • subsys/net/l2/openthread/Kconfig 中与 OpenThread 相关的 Kconfig 选项已移动到 modules/openthread/Kconfig。所有 Kconfig 选项保持不变，你仍然可以像以前一样使用它们，但如需修改，请在 menuconfig 或 guiconfig 中使用新的路径。

  • 如果启用了 Kconfig 选项 CONFIG_NET_L2_OPENTHREAD，Zephyr 的 L2 层将使用新的 OpenThread 模块 API 作为后端。L2 层不再自行实现 OpenThread，而是将实现委托给该模块。

  • 对于通过 Zephyr 网络协议栈使用 OpenThread 的现有应用程序：

    • 你的应用程序应当可以继续工作，因为旧 API 为保持兼容仍然可用。不过，建议迁移到新 API 并使用新的模块化结构，以适应未来的变化。

    • 在配置工具中，将所有对 OpenThread Kconfig 选项的引用更新为使用新路径（modules/openthread/Kconfig）。

  • 对于使用 openthread_context 或其他已弃用 API 的应用程序：

    • 开始迁移到新 API。已弃用的 API 将在未来的版本中移除。

    • 避免直接使用 openthread_context 及其相关字段，请改用新的初始化和回调注册函数。

  • 对于新应用程序，或不通过 Zephyr L2 使用 OpenThread 的应用程序：

    • 使用新的初始化（openthread_init()）、运行（openthread_run()）和回调注册 API（openthread_state_change_callback_register()）。

    • 如果你的用例允许，现在可以直接使用 OpenThread，而无需启用 Zephyr 的 L2 层或 IEEE802.15.4 层。

其他子系统

Modbus

  • modbus_serial_param 中的 client_stop_bits 字段已重命名为 stop_bits。该设置在客户端和服务器模式下均有效。

  • 自定义停止位设置默认处于禁用状态，应通过 CONFIG_MODBUS_NONCOMPLIANT_SERIAL_MODE 启用。

状态机框架

  • smf_set_handled() 已被移除。

  • 状态运行动作现在返回 smf_state_result 值而不是 void，返回码决定事件是传递给父状态的运行动作，还是已被处理。完全处理了事件的运行动作应返回 SMF_EVENT_HANDLED，将处理传递给父状态的运行动作应返回 SMF_EVENT_PROPAGATE。

  • 扁平状态机会忽略返回值；从技术上讲，返回 SMF_EVENT_HANDLED 最为准确。

hawkBit

  • 启用 CONFIG_HAWKBIT_CUSTOM_DEVICE_ID 时，device_id 前面将不再自动加上 CONFIG_BOARD。如有需要，用户应当自行编写回调，在前面加上开发板名称。

模块

CMSIS

  • Cortex-M 开发板/SoC 现在需要 CMSIS_6 模块才能正确构建（取代原来的 CMSIS 5.9.0 模块 cmsis）。如果要构建 Cortex-M 开发板，请先执行 west update，确保在运行 west build 或其他命令之前 CMSIS_6 模块可用。

    通过本地副本或通过 CONFIG_ZEPHYR_CMSIS_MODULE_DIR 使用旧 cmsis 模块的开发板、SoC 或模块，需要迁移到 CMSIS_6 模块，该模块可通过 CONFIG_ZEPHYR_CMSIS_6_MODULE_DIR 配置访问。

    注意：对于 Cortex-A 和 Cortex-R 目标，Zephyr 将继续使用旧的 cmsis 模块。

架构

  • CONFIG_SRAM_VECTOR_TABLE 已从 zephyr/Kconfig.zephyr 移动到 zephyr/arch/Kconfig，并添加了对 CONFIG_XIP、CONFIG_ARCH_HAS_VECTOR_TABLE_RELOCATION 和 CONFIG_ROMSTART_RELOCATION_ROM 的依赖，以支持将向量表重定位到 RAM 中。

  • CONFIG_DEBUG_INFO 已重命名为 CONFIG_X86_DEBUG_INFO，以更好地反映其用途。该选项现在仅适用于 x86 架构。
