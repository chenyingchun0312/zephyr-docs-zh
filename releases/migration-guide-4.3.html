构建系统

内核

  • device_init()：由于一个缺陷，早期版本在设备初始化失败时会返回正的 +errno 值。该问题现已修复，会返回正确的负 -errno 值。曾针对此问题实现变通处理的应用程序现在应相应地更新代码。

基础库

  • UTF-8 工具函数的声明（utf8_trunc()、utf8_lcpy()）已从 util.h 移动到单独的 include/zephyr/sys/util_utf8.h 文件中。

  • Z_MIN、Z_MAX 和 Z_CLAMP 宏已分别重命名为 min、max 和 clamp。

  • 不应再使用头文件 <zephyr/posix/time.h> 和 <zephyr/posix/signal.h>。请通过标准路径以 <time.h> 和 <signal.h> 的形式包含它们，这些头文件由 C 库提供。非 POSIX C 库的维护者可以包含 include/zephyr/posix/posix_time.h 和 include/zephyr/posix/posix_signal.h，以可移植的方式提供 POSIX 定义。

  • POSIX 限制值不再在 <zephyr/posix/posix_features.h> 中定义。同样，请通过标准路径经由 C 库提供的 <limits.h> 包含它们。非 POSIX C 库的维护者可以包含 include/zephyr/posix/posix_limits.h 来获取 Zephyr 的定义。某些运行时不变的值可能需要通过 sysconf() 查询。

  • 文件描述符表的大小及其可用性现在由 ZVFS_OPEN_SIZE 宏定义决定，而不再由 Kconfig 选项 CONFIG_ZVFS_OPEN_MAX 决定。子系统可以通过定义前缀为 CONFIG_ZVFS_OPEN_ADD_SIZE_ 的 Kconfig 选项来指定自己对文件描述符表大小的定制需求。旧的 Kconfig 选项仍然存在，但如果定制需求更大，它将被覆盖。为了在旧 Kconfig 选项的值小于所指定的定制需求时仍强制使用该值，新增了 CONFIG_ZVFS_OPEN_IGNORE_MIN 选项（默认禁用）。

开发板

  • b_u585i_iot02a/ns：Flash 布局已更改，以与上游 TF-M 2.2.1 的开发板配置保持同步。新布局扩大了 Flash 分区，并将次分区移到外部 NOR Flash 上。此变更目前导致无法从旧版 Zephyr 镜像升级到 Zephyr 4.3 版本的镜像。更多细节请参阅 TF-M 迁移说明和发布说明。

  • nucleo_h753zi：Flash 布局已更新，由于与之前的布局不兼容，固件升级可能会失败。新布局将 storage 分区扩大到 2 个扇区，移除了 scratch 分区，并重新排列了所有 Flash 分区以使结构更合理。

  • mimxrt11x0：lpadc1 已重命名为 lpadc2，lpadc0 已重命名为 lpadc1。

  • NXP frdm_mcxa166 已重命名为 frdm_mcxa346。

  • NXP frdm_mcxa276 已重命名为 frdm_mcxa266。

  • Panasonic panb511evb 已重命名为 panb611evb。

  • STM32 开发板的 OpenOCD 配置文件已更改，以支持最新的 OpenOCD 版本（> v0.12.0），这些版本已弃用 HLA/SWD 传输方式（参见 https://review.openocd.org/c/openocd/+/8523 和提交 https://sourceforge.net/p/openocd/code/ci/34ec5536c0ba3315bc5a841244bbf70141ccfbb4/）。连接运行 v2j24 之前固件的 ST-Link 适配器时可能会遇到问题，因为这些固件不支持新的传输方式。这种情况下应升级 ST-Link 固件；如果无法升级，则应修改 OpenOCD 配置脚本，使其引用（source）"interface/stlink-hla.cfg" 并显式选择 "hla_swd" 接口。仍保持与 OpenOCD v0.12.0 及更早版本的向后兼容。

设备驱动与设备树

ADC

  • iadc_gecko.c 驱动已被 adc_silabs_iadc.c 取代。silabs,gecko-iadc 已被 silabs,iadc 取代。

  • st,stm32-adc 及其衍生绑定现在要求定义 clock-names 属性，且其数量必须与 clocks 属性中的时钟数量一致。期望的时钟名称为：寄存器时钟 adcx、内核源时钟 adc-ker，以及用于设置 ADC 预分频器的 adc-pre（适用于预分频器位于 RCC 寄存器中的系列）。

时钟控制

  • CONFIG_CLOCK_STM32_HSE_CLOCK 不再由用户配置。它的值现在总是取自 &clk_hse 设备树节点的 clock-frequency 属性，但仅在该节点启用时有效（否则不定义该符号）。此变更应只影响基于 STM32 MPU 的平台，使其与 STM32 MCU 平台的现有做法保持一致。

  • st,stm32f1-rcc 和 st,stm32f3-rcc 已不复存在，因此 adc-prescaler、adc12-prescaler 和 adc34-prescaler 属性也不再定义。取而代之的是，将预分频器作为一个额外的时钟添加到 ADC 的 clocks 属性中。

比较器

  • nordic,nrf-comp 和 nordic,nrf-lpcomp 的 psel 和 extrefsel 属性类型已改为整数。这些属性的取值范围为 NRF_COMP_AIN0 到 NRF_COMP_AIN_VDDH_DIV5，其中 NRF_COMP_AIN0 到 NRF_COMP_AIN7 表示外部输入 AIN0 到 AIN7，NRF_COMP_AIN_VDD_DIV2 表示内部参考 VDD/2，NRF_COMP_AIN_VDDH_DIV5 表示 VDDH/5。原来的 string 属性类型已被弃用。

DMA

  • DMA 的 API 不再实现用户模式系统调用。经评估，这些系统调用的访问范围定义过宽，无法以安全的方式实现系统调用参数校验步骤。

以太网

  • 当复位信号为低电平有效时，microchip,vsc8541 PHY 驱动现在要求 reset-gpios 条目指定 GPIO_ACTIVE_LOW 标志。此前，低电平有效的特性是硬编码在驱动中的。（GitHub #91726）。

  • 在 Xilinx GEM 以太网驱动（xlnx,gem）中，将 CRC 校验和生成卸载到硬件的功能现在需要显式禁用，而不再需要显式启用。为了提高性能，卸载功能现在默认启用；不过对于 QEMU 目标，卸载功能始终禁用，因为无论是否通过设备树显式禁用，QEMU 都不模拟硬件中的校验和生成。（GitHub #95435）

    • 用于启用 RX 校验和卸载的设备树属性 rx-checksum-offload 已替换为 disable-rx-checksum-offload，后者用于主动禁用该功能。

    • 用于启用 TX 校验和卸载的设备树属性 tx-checksum-offload 已替换为 disable-tx-checksum-offload，后者用于主动禁用该功能。

  • Xilinx GEM 以太网驱动（xlnx,gem）现在在运行时从设计配置寄存器中获取与当前目标 SoC（Zynq-7000 或 ZynqMP）相匹配的 AMBA AHB 数据总线宽度，因此设备树属性 amba-ahb-dbus-width 已经过时，并已被移除。

  • nxp,enet-mac 和 xlnx,gem 驱动在初始化期间不再通过 phy_configure_link() 配置 PHY 的链路速率和双工模式。当 MAC 只支持 PHY 所支持速率的一个子集时，如果用户希望限制自动协商时通告的速率，必须使用 PHY 的 default-speeds 设备树属性。（GitHub #91572）

MFD

  • AXP2101 的驱动支持已从 AXP192 中分离出来，因此 Kconfig 符号 MFD_AXP192_AXP2101 已被移除。现在 AXP192 器件应使用 MFD_AXP192，AXP2101 器件应使用 MFD_AXP2101。

杂项

  • nrf_etr 驱动已迁移到 drivers/debug。因此，相关的 Kconfig 符号 NRF_ETR 已重命名为 DEBUG_NRF_ETR，其余 NRF_ETR 符号也一并重命名。此外，该驱动不再默认构建，需要通过 DEBUG_DRIVER 显式启用。

PWM

  • nxp,pca9685 的 invert 属性已被移除，现在可以使用 PWM_POLARITY_INVERTED 或 PWM_POLARITY_NORMAL 标志，因为 "pwm" 空间的说明符单元现在命名为 ['channel', 'period', 'flags']（旧值：['channel', 'period']），并且 #pwm-cells 的常量值已从 2 改为 3。

PHY

  • compatible 属性为 st,stm32u5-otghs-phy 的节点，现在需要使用新属性 clock-reference 来选择 SYSCFG_OTGHSPHYCR 寄存器中的 CLKSEL（PHY 参考时钟）。该选择直接取决于 RCC_CCIPR2 寄存器中 OTGHSSEL（OTG_HS PHY 内核时钟源选择）的值。

SPI

  • 宏 SPI_CS_CONTROL_INIT、SPI_CS_CONTROL_INIT_INST、SPI_CONFIG_DT、SPI_CONFIG_DT_INST、SPI_DT_SPEC_GET 和 SPI_DT_SPEC_INST_GET 已更改，不再需要传入延时参数。这是因为 SPI 外设片选的时序参数现在应在设备树中通过 spi-cs-setup-delay-ns 和 spi-cs-hold-delay-ns 属性指定。（GitHub #87427）。

传感器

  • compatible 属性为 invensense,icm42688 的节点，现在还需要额外包含 invensense,icm4268x 才能正常工作。

步进电机

  • zephyr,gpio-stepper 已被 zephyr,h-bridge-stepper 取代。

USB

  • USB 视频类（Video Class）以前会配置源视频设备的帧率和格式。现在这项工作改为在主机选定格式后由应用程序完成（GitHub #93192）。

Bluetooth

  • bt_le_cs_test_param 和 bt_le_cs_create_config_params 现在要求将主模式和子模式作为单个参数一起提供。

  • bt_conn_le_cs_config 现在将主模式和子模式作为单个参数一起报告。

  • bt_conn_le_cs_main_mode 和 bt_conn_le_cs_sub_mode 已被 bt_conn_le_cs_mode 取代。

Bluetooth 控制器

  • 以下内容已重命名：

    • CONFIG_BT_CTRL_ADV_ADI_IN_SCAN_RSP 重命名为 CONFIG_BT_CTLR_ADV_ADI_IN_SCAN_RSP

    • bt_hci_vs_fata_error_cpu_data_cortex_m 重命名为 bt_hci_vs_fatal_error_cpu_data_cortex_m，并且现在包含程序计数器的值。

Bluetooth 音频

  • bt_audio_codec_cfg 现在要求显式设置目标延迟和目标 PHY，而不再总是将目标延迟设为 "Balanced"、将目标 PHY 设为 LE 2M。要保持现有功能，请将 target_latency 设置为 BT_AUDIO_CODEC_CFG_TARGET_LATENCY_BALANCED，将 target_phy 设置为 BT_AUDIO_CODEC_CFG_TARGET_PHY_2M。BT_AUDIO_CODEC_CFG 宏默认使用这些值。（GitHub #93825）

  • 为 GMAP 设置 BGS 角色时，现在还需要支持并实现 CONFIG_BT_BAP_BROADCAST_ASSISTANT。可参考 Basic Audio Profile (BAP) Broadcast Audio Assistant 示例。

  • BAP Scan Delegator 不再自动更新 PA 同步状态，必须使用 bt_bap_scan_delegator_set_pa_state() 来更新该状态。如果 BAP Scan Delegator 与 BAP Broadcast Sink 一起使用，那么当 PA 状态改变时，bt_bap_broadcast_sink 接收状态中的 PA 状态仍会自动更新。（GitHub #95453）

Bluetooth HCI

  • 已弃用的 ipm 值已从设备树属性 bt-hci-bus 中移除，应改用 ipc。

Bluetooth Mesh

  • Kconfig 选项 CONFIG_BT_MESH_USES_MBEDTLS_PSA 和 CONFIG_BT_MESH_USES_TFM_PSA 已被移除。PSA Crypto 提供者的选择现在由 Kconfig 选项 CONFIG_PSA_CRYPTO 自动控制。

Bluetooth 主机（Host）

  • CONFIG_BT_FIXED_PASSKEY 已被弃用。作为替代，应用程序可以使用 bt_conn_auth_cb.app_passkey 回调为配对提供配对码（passkey），该回调在启用 CONFIG_BT_APP_PASSKEY 时可用。应用程序可以返回用于配对的配对码，也可以返回 BT_PASSKEY_RAND，由主机生成随机配对码。

电源管理

  • CONFIG_PM_S2RAM 和 PM_S2RAM_CUSTOM_MARKING 已重构为由 SoC 和设备树自动管理。应用程序不应再直接启用它们，而应在设备树中启用或禁用 "suspend-to-ram" 电源状态。

  • 对于 NXP RW61x，设备树属性 exit-latency-us 已更新，以反映更准确的实测唤醒时间。对于使用待机模式（PM3）的应用程序，这一更新以及设备树属性 min-residency-us 的增大，可能会影响系统在电源模式之间的切换方式。在某些情况下，这可能导致功耗发生变化。

网络

  • HTTP 服务器现在会遵循所配置的 _config 值。请检查是否为 HTTP_SERVICE_DEFINE_EMPTY、HTTPS_SERVICE_DEFINE_EMPTY、HTTP_SERVICE_DEFINE 和 HTTPS_SERVICE_DEFINE 提供了合适的值。

  • 套接字地址长度类型 socklen_t 的大小已更改。为了与 Linux 保持一致，它现在始终定义为 32 位的 uint32_t。此前它被定义为 size_t，这意味着其大小可能是 32 位或 64 位，取决于系统配置。

  • net_icmp_init_ctx() API 已更改，现在额外接受一个 family 参数，用于指示该上下文应处理哪种协议族的数据包。ICMPv4 上下文使用 AF_INET，ICMPv6 上下文使用 AF_INET6。

CoAP

  • coap_client_response_cb_t 的签名已更改。参数列表改为以 coap_client_response_data 指针的形式传递。

  • coap_client_request 已更改，以提高该库对错误配置（即在结构体中使用临时指针）的容错能力：

    • coap_client_request.path 现在是一个 char 数组而不是指针。数组大小可通过 CONFIG_COAP_CLIENT_MAX_PATH_LENGTH 配置。

    • coap_client_request.options 现在是一个 coap_client_option 数组而不是指针。数组大小可通过 CONFIG_COAP_CLIENT_MAX_EXTRA_OPTIONS 配置。

调制解调器

  • CONFIG_MODEM_AT_SHELL_USER_PIPE 已重命名为 CONFIG_MODEM_AT_USER_PIPE。

  • CONFIG_MODEM_CMUX_WORK_BUFFER_SIZE 已更新为 CONFIG_MODEM_CMUX_WORK_BUFFER_SIZE_EXTRA，该选项只接受在默认值（CONFIG_MODEM_CMUX_MTU + 7）之外额外需要的字节数。

显示

  • 显示示例中混用了 RGB565 和 BGR565 像素格式，该问题现已修复。基于旧示例进行测试或开发的开发板和应用程序可能会受此变更影响（更多信息参见 GitHub #79996）。

  • SSD1363 中使用 'greyscale' 的属性现在改用 'grayscale'。

PTP 时钟

  • ptp_clock_rate_adjust() API 的文档此前没有提供恰当、清晰的函数说明，驱动将其实现为相对于当前频率调整速率比。现在 PTP 和 gPTP 中都引入了 PI 伺服，该 API 函数改为基于标称频率调整速率比。实现了 ptp_clock_rate_adjust() 的驱动应进行相应调整，以适应新的行为。

视频

  • min_line_count 和 max_line_count 字段已从 video_caps 中移除。应用程序应根据新的 video_format.size 来分配缓冲区。

其他子系统

蜂窝网络

  • cellular_access_technology 的取值已重新定义，以与 3GPP TS 27.007 保持一致。

  • cellular_registration_status 的取值已扩展，以与 3GPP TS 27.007 保持一致。

加密

  • 哈希操作现在要求 hash_pkt 中的输入为常量。这应该不会影响任何现有代码，除非某个树外哈希后端确实以原地（in-place）方式执行该操作（参见 GitHub #94218）

Flash 映射

  • 出于让 PSA Crypto API 成为 Zephyr 中唯一加密支持的长期目标，FLASH_AREA_CHECK_INTEGRITY_MBEDTLS 已被弃用。FLASH_AREA_CHECK_INTEGRITY_PSA 现在是默认选项：如果未启用 TF-M 或平台不支持 TF-M，将使用 Mbed TLS 作为 PSA Crypto API 的提供者。

日志

  • UART 字典日志解析脚本 scripts/logging/dictionary/log_parser_uart.py 已被弃用，应改用更通用的脚本 scripts/logging/dictionary/live_log_parser.py。新脚本支持相同（以及更多）的功能，但调用时所需的命令行参数不同。

MCUmgr

  • OS 管理 的 操作系统/应用程序信息 命令在响应中输出的硬件平台信息已更新为开发板目标，而不再是开发板及其版本，因此现在还包含 SoC 和开发板变体。旧行为已被弃用，但仍可通过启用 CONFIG_MCUMGR_GRP_OS_INFO_HARDWARE_INFO_SHORT_HARDWARE_PLATFORM 来使用。

  • 对旧版 Mbed TLS 哈希加密的支持已被移除，现在只使用 PSA Crypto API。如果构建中未启用 TF-M，CONFIG_MCUMGR_GRP_FS_HASH_SHA256 会自动启用 Mbed TLS 及其 PSA Crypto 实现。

Mbed TLS

  • 为了让 Zephyr Kconfig 符号与 Mbed TLS 构建符号更好地一一对应，以下 Kconfig 选项已重命名：

    • CONFIG_MBEDTLS_MD -> CONFIG_MBEDTLS_MD_C

    • CONFIG_MBEDTLS_LMS -> CONFIG_MBEDTLS_LMS_C

    • CONFIG_MBEDTLS_TLS_VERSION_1_2 -> CONFIG_MBEDTLS_SSL_PROTO_TLS1_2

    • CONFIG_MBEDTLS_DTLS -> CONFIG_MBEDTLS_SSL_PROTO_DTLS

    • CONFIG_MBEDTLS_TLS_VERSION_1_3 -> CONFIG_MBEDTLS_SSL_PROTO_TLS1_3

    • CONFIG_MBEDTLS_TLS_SESSION_TICKETS -> CONFIG_MBEDTLS_SSL_SESSION_TICKETS

    • CONFIG_MBEDTLS_CTR_DRBG_ENABLED -> CONFIG_MBEDTLS_CTR_DRBG_C

    • CONFIG_MBEDTLS_HMAC_DRBG_ENABLED -> CONFIG_MBEDTLS_HMAC_DRBG_C

RTIO

  • 回调操作现在额外接受一个参数，对应链中第一个错误的结果码。

  • 无论链中之前提交的操作成功还是出错，回调操作都总会被调用。

安全存储

  • 用于标识存储条目的 psa_storage_uid_t 的大小已从 64 位改为 30 位。此变更破坏了与先前已存储条目的向后兼容性，这些条目的认证将开始失败。如果你要从早期版本的 Zephyr 升级现有安装，并希望保留原有条目，请启用 CONFIG_SECURE_STORAGE_64_BIT_UID。（GitHub #94171）

Shell

  • 与 SHELL_BACKEND_MQTT 相关的 MQTT 主题已重命名：<device_id>_rx 已重命名为 <device_id>/sh/rx，<device_id>_tx 已重命名为 <device_id>/sh/tx。<device_id> 之后的部分现在可以通过 SHELL_MQTT_TOPIC_RX_ID 和 SHELL_MQTT_TOPIC_TX_ID 配置，因此可以保留之前的主题以实现向后兼容。（GitHub #92677）。

UpdateHub

  • 作为加密支持选项的旧版 Mbed TLS 已被移除，现在所有情况下都使用 PSA Crypto。如果构建中未启用 TF-M，CONFIG_UPDATEHUB 会自动启用 PSA Crypto 的 Mbed TLS 实现。

模块

  • 由于上游版本已不再维护，TinyCrypt 库已被移除。PSA Crypto API 现在是 Zephyr 推荐使用的加密库。

MCUboot

  • MCUboot 的默认工作模式已改为 swap using offset，该模式交换更新更快、开销更小，并减少执行更新所需的 Flash 擦写次数；之前的默认模式是 swap using move。如果某个开发板为 swap using move 做过优化，即主槽比次槽多一个扇区，那么需要改为次槽比主槽多一个扇区（这是优化用法，两个槽扇区数相同的配置仍然受支持）。或者，也可以在 sysbuild 中通过 SB_CONFIG_MCUBOOT_MODE_SWAP_USING_MOVE 选择之前的 swap using move 模式。

Silabs

  • Rail 选项的名称已与其他 SiSDK 相关选项保持一致：

    • CONFIG_RAIL_PA_CURVE_HEADER 重命名为 CONFIG_SILABS_SISDK_RAIL_PA_CURVE_HEADER

    • CONFIG_RAIL_PA_CURVE_TYPES_HEADER 重命名为 CONFIG_SILABS_SISDK_RAIL_PA_CURVE_TYPES_HEADER

    • CONFIG_RAIL_PA_ENABLE_CALIBRATION 重命名为 CONFIG_SILABS_SISDK_RAIL_PA_ENABLE_CALIBRATION

  • 修正了 CONFIG_SOC_* 选项的名称。这些选项的名称中原本包含 PART_NUMBER，而实际上不应包含。

  • Series 2 SoC 中单独的 em3 电源状态已被移除。系统会根据硬件外设对振荡器的请求，自动切换到 EM2 或 EM3。

LVGL

  • modules/lvgl/lvgl_display_mono.c 中的 PIXEL_FORMAT_MONO10 和 PIXEL_FORMAT_MONO01 格式被弄反了，导致在单色显示屏上使用 LVGL 时黑白颠倒。该问题现已修复。之前为实现预期效果而采用的任何变通处理都应移除，否则黑白会再次颠倒。

LED 灯带

  • arduino,modulino-smartleds 已重命名为 arduino,modulino-pixels

Trusted Firmware-M

  • BL2（MCUboot）的签名流程已更新。运行 TF-M NS 且需要 BL2 的开发板，其 Flash 布局中必须包含 Flash 控制器信息。这样可以确保在对 hex/bin 文件签名时，S 和 NS 镜像中包含所有细节。镜像现在包含了必要的细节，使 FWU 状态机能够正确运行并支持 FOTA。（GitHub #94470）

    • --align 参数以前固定为 1。现在它被设置为 Flash 设备树属性 write_block_size 的值，但对于特定厂商仍以 1 作为后备值。

    • --max-sectors 的值现在根据镜像数量计算，并考虑最大镜像的大小。

    • --confirm 选项现在会同时确认 S 和 NS 的 HEX 镜像，确保运行的任何镜像对于生产和开发都是有效的。

    • 现在提供 S 和 NS 的 BIN 镜像，它们是用于 FOTA 的正确镜像。请注意，S 和 NS 镜像默认处于未确认状态，应用程序负责通过 psa_fwu_accept() 确认它们，否则镜像将在下次重启时回滚。

  • 在 TF-M v2.1.0 发布之后引入的 TF-M 证明（attestation）流程中发现了一个兼容性问题。因此，使用 TF-M v2.1 的系统无法升级到任何更高版本的 TF-M，否则会出现故障。此限制影响使用 TF-M v2.1.0 至 v2.1.2 的 Zephyr 版本，具体为 Zephyr v3.7 至 v4.2，导致这些版本之间无法顺利升级。该问题已于 10 月 25 日在 TF-M 主线中解决，修复已包含在 Zephyr v4.3.0 中。建议用户从任何更早的 Zephyr 版本直接迁移到 Zephyr v4.3.0 或更高版本，以确保完整的 TF-M 证明功能和升级兼容性。（GitHub #94859）对于最初基于 Zephyr v4.0 至 v4.2 构建的应用程序，必须设置 CONFIG_TFM_ZEPHYR_4_0_TO_4_2_COMPATIBILITY 才能成功升级到 v4.2 之后的任何版本，并且在之后的所有升级中都要保持设置。（GitHub #103793）

  • 构建时由 CMake 自动下载 MCUboot 和 ethos 的支持已被移除，现在将使用这些模块的树内版本。如需使用自定义版本，请创建一个 west 清单（manifest），改为从中拉取这些仓库的所需版本。
