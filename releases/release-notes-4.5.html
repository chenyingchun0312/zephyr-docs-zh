Zephyr 4.5.0

我们很高兴地宣布 Zephyr 4.5.0 版本发布。

本版本的主要改进包括：

新架构：Infineon TriCore 与 Qualcomm Hexagon

Zephyr 现已支持 AURIX 车规级微控制器所使用的 Infineon TriCore architecture，以及 Qualcomm Hexagon DSP architecture。

多媒体管道（mpipe）

新增实验性的 多媒体管道（mpipe） 子系统。它借鉴了 GStreamer 的设计，提供了一套框架，用于将源（source）、变换（transform）和汇（sink）元素连接成零拷贝管道，从而构建媒体应用程序。

网络增强

IP 协议栈的多项优化使 zperf 回环基准测试 中的 TCP 吞吐量最多提升 21%。

网络协议栈还新增了以下功能：

  • 支持 QUIC 和 HTTP/3。

  • RTP（RFC 3550）协议栈，用于通过 UDP 收发媒体流。

  • SSH 服务器与客户端，包括一个 shell 后端。

  • 模型上下文协议（MCP）服务器，使 AI 代理能够使用设备提供的工具。

  • 网关功能：IPv4 转发、NAT、IPv6 路由器角色以及 DHCPv6 前缀委派。

新驱动类别

Zephyr 4.5 新增了以下驱动 API：

  • 蜂鸣器（Buzzer），用于由 PWM 或 GPIO 驱动的无源和有源蜂鸣器；

  • 时钟监视器（Clock Monitor），用于在运行时观测时钟频率；

  • DALI，用于数字可寻址照明接口（Digital Addressable Lighting Interface）；

  • LIN，用于汽车串行总线 LIN（Local Interconnect Network，局部互联网络）；

  • MUX，用于硬件信号多路复用器；以及

  • Pulse IO，用于生成和捕获定时数字边沿的硬件，可满足可寻址 LED 灯带和红外收发器等的需求。

安全与 SBOM 改进

本版本改进了 SBOM 生成、加固检查和密码学加速：

  • SPDX 3 SBOM，记录镜像的构建方式（构建配置（Build profile））、所链接的 预编译库，以及用于漏洞匹配的 软件包标识符。

  • 全面改进的 加固工具，提供 CWE 参考并集成到 CI 中。

  • 在部分 Silicon Labs、NXP 和 STM32 器件上提供硬件加速的 PSA Crypto。

仿真与测试改进

本版本扩展了仿真目标和测试工具：

  • 新增基于主机实现的 native_sim 外设，包括 Wi-Fi、音频、视频、LED 以及主机目录挂载。

  • 为 QEMU 目标新增 VirtIO 驱动（块设备、输入、GPIO、I2C 和 SPI）。

  • Twister 支持 多设备测试 和 多工具链构建。

  • 面向网络协议栈的 TTCN-3 一致性测试套件。

调试与诊断

本版本新增了多项调试和诊断工具：

  • ZASSERT()，支持按模块和按文件设置断言级别。

  • 堆内存错误检测：CONFIG_SYS_HEAP_SANITIZER_ASAN（native_sim）和 CONFIG_SYS_HEAP_KASAN（真实目标）。

  • 新的 跟踪（tracing） 功能：终端查看器、Perfetto 导出、shell 以及 ITM 后端。

扩展的开发板支持

本版本新增了对 178 款 新开发板 和 29 款 新扩展板（shield） 的支持。

将应用程序从 Zephyr v4.4.0 迁移到 Zephyr v4.5.0 时所需或建议的更改概述，请参阅单独的 迁移指南。

  • 密码学（Crypto）

    • 新增 AES CFB 和 OFB 密码模式支持。

  • Mbed TLS

    • Mbed TLS 已更新至 4.1.1 版本。发布说明请见 此处。

    • TF-PSA-Crypto 已更新至 1.1.1 版本。发布说明请见 此处。

    • 新增 CONFIG_TF_PSA_CRYPTO_DISPATCH_DIR，使 TF-PSA-Crypto 能够使用自定义的密码操作分派实现。借助感知加速器的分派实现，即可对密码操作进行硬件加速。

  • TF-M

    • TF-M 已从 2.2.2 版本更新至 2.3.1 版本。发布说明请见：

      • https://trustedfirmware-m.readthedocs.io/en/latest/releases/2.3.0.html

      • https://trustedfirmware-m.readthedocs.io/en/tf-mv2.3.1/releases/2.3.1.html

    • 现在可以通过将 ZEPHYR_TOOLCHAIN_VARIANT 设置为 zephyr/llvm，使用 LLVM 编译 TF-M。

  • DFU

    • 新增 CONFIG_IMG_CUSTOM_SECTOR_SIZE，允许 MCUboot 使用不同的扇区大小，以减小 swap-using-offset 状态区的大小。

  • 管理

    • 新增 基于 HTTP 的固件空中升级 库。这是一个固件空中升级（FOTA）客户端，可通过 HTTP 或 HTTPS 将 MCUboot 镜像直接下载到副槽（secondary slot），并可选支持断点续传、跟随重定向、SHA-256 校验以及 fota shell 命令。

  • LoRa / LoRaWAN

    • 新增原生 LoRaWAN 后端（CONFIG_LORA_MODULE_BACKEND_NATIVE），它直接在 LoRa 射频驱动之上实现 LoRaWAN 1.0.x Class A，不再依赖 Semtech LoRaMac-node。目前支持 EU868 区域。

    • lora_modem_config.sync_word

  • 网络

    • 新增对通过卸载（offloaded）套接字绑定的本地端口的跟踪（CONFIG_NET_SOCKETS_OFFLOAD_PORT_TRACKING）。卸载套接字在卸载引擎中完成绑定，位于 net_context 层之外，因此 net_context_port_in_use() 无法看到它们。套接字层现在会跟踪这些绑定，并提供 net_socket_port_in_use() 同时检查原生端口和卸载端口。mDNS 探测端口的选择以及 DNS-SD 服务检查均使用这个新函数。

    • PTP 新增 IEEE 802.3 传输支持、数据包套接字接收时间戳以及 PTP shell 诊断功能（GitHub #106464）。

  • 管理

    • MCUmgr

      • 镜像管理客户端现在支持 SHA-512 镜像摘要。在使用 CONFIG_MCUBOOT_BOOTLOADER_USES_SHA512 构建的目标上，它可以列出镜像并选择镜像进行测试或确认。

  • 多媒体管道

    • 引入 多媒体流水线（mpipe），这是一个实验性子系统，用于将可复用的元素（源、变换和汇）连接成管道来构建多媒体应用程序。应用程序只需描述所需的媒体流，而无需自行驱动每个音频、视频或显示设备。

    • 基础插件提供与媒体类型无关的元素：caps 过滤器、tee、队列，以及应用程序源和应用程序汇。

    • 拓扑转储功能可以将管道渲染为 Graphviz 图；播放器则可以从工作线程和 shell 驱动管道。

  • 网络

    • CoAP

      • CoAP 服务器接受携带空令牌（token）的观察注册（RFC 7641 允许这种做法），并以端点和该空令牌作为观察者的键。

    • IGMP

      • 按照 RFC 2236 和 RFC 3376 的要求，主机现在会应答特定组查询（Group-Specific Query），在最大响应时间（Max Resp Time）内随机延迟查询响应，重传加入组时的主动报告，并在存在 IGMPv1 或 IGMPv2 查询器时切换到相应版本。报告的发送次数遵循新的 CONFIG_NET_IPV4_IGMP_ROBUSTNESS。启用 CONFIG_NET_IPV4_IGMP_REQUIRE_ROUTER_ALERT 时，会忽略不带 IP Router Alert 选项的查询。

    • MLD

      • 按照 RFC 2710 和 RFC 3810 的要求，节点现在会应答特定组播地址查询（Multicast Address Specific Query），在最大响应延迟（Maximum Response Delay）内随机延迟查询响应，重传加入组时的主动报告，在存在 MLDv1 查询器时切换到 MLDv1，并丢弃源地址不是链路本地地址或不带 Router Alert 选项的查询。不再为全节点组发送报告；当接口的链路本地地址生效后，会重新报告所有组。报告的发送次数遵循新的 CONFIG_NET_IPV6_MLD_ROBUSTNESS；禁用新的 CONFIG_NET_IPV6_MLD_V1_COMPAT 会使节点忽略 MLDv1 消息。

  • 安全存储

    • 对于认证失败或格式错误的条目，psa_its_get*() 函数现在返回 PSA_ERROR_INVALID_SIGNATURE 或 PSA_ERROR_DATA_CORRUPT，而不是 PSA_ERROR_GENERIC_ERROR。

    • 修改条目的 ITS 操作现在会被串行化；丢弃无法读回的条目时会记录一条警告日志。

    • 以 0 作为 data_size 调用 psa_its_get() 时，现在会报告条目是否存在且有效，而不是总是返回 PSA_SUCCESS。

    • psa_its_set() 和 psa_its_remove() 现在只在无法读回的条目确实已损坏时才替换或删除它，否则会以底层错误失败。

    • 现在在返回之前，会从子系统自身的缓冲区中擦除条目的解密数据。

    • ZMS 存储现在通过 64 位 ZMS ID 支持 64 位 UID，并会拒绝无法映射的 UID，而不是为其设置别名。更多信息请参阅 迁移指南。

  • 精确定时

    • 引入 精密计时，为 PTP、gPTP 及其他使用高分辨率时钟的场景提供实验性的可复用机制：带检查的时间运算、时钟操作以及 PI 控制。

  • 视频

    • 引入视频子系统，它继承了先前位于视频驱动中的所有函数名。

  • Zbus

    • CONFIG_ZBUS_MSG_SUBSCRIBER_NET_BUF_POOL_ISOLATION 现在无需为每个通道都配置专用池即可工作（在调用 zbus_chan_set_msg_sub_pool() 之前，通道会回退使用共享池）

  • __assert

    • 移除了 __ASSERT_ON 宏定义。

  • ADC shell 现在通过 adc 设备类别枚举 ADC 控制器，而不再使用硬编码的 compatible 列表，因此也能覆盖树外 ADC 驱动。

  • I3C shell 现在通过 i3c 设备类别枚举 I3C 控制器，而不再使用硬编码的 compatible 列表，因此也能覆盖树外 I3C 驱动。

其他值得注意的变更

  • ADC

    • STM32 ADC 驱动（st,stm32-adc）：启用 CONFIG_ADC_STM32_VREFINT_CALIBRATE 时，adc_ref_internal() 可能返回实测的刻度，而不是设备树中的 vref-mv。任何由 st,stm32-vref 的 io-channels 属性指定的 ADC 都可以进行该测量；测量结果在整个 SoC 范围内缓存。请参阅 迁移指南 中的 ADC 一节。

    • STM32G4 SoC 的 dtsi 文件现在描述了芯片中实际存在的额外 VREFINT 输入：st,stm32-vref 的 vref3（ADC3，G491 及更高型号）、vref4 和 vref5（ADC4/ADC5，G473 及更高型号）。这些节点默认保持禁用；开发板需启用自己使用的实例。ADC2 没有 VREFINT 多路选择。

  • 蓝牙

    • CONFIG_SYSTEM_WORKQUEUE_PRIORITY 不再仅因启用 CONFIG_BT 就被强制设为协作式优先级。现在只有向系统工作队列提交工作的组件才有此要求，因此不包含这些组件的构建（例如驱动外部控制器的 HCI raw 镜像）可以重新选择可抢占的优先级（GitHub #119123）。

  • 构建系统

    • 最低 CMake 版本要求已提高到 3.28.0，Ubuntu 24.04 LTS 软件包仓库中的 CMake 软件包即可满足该要求。如果您的发行版提供的版本较旧，可选方案请参阅 迁移指南。

    • 加固工具（west build -t hardenconfig）现在从一个经过模式（schema）校验的 YAML 数据库获取建议，而不再使用 CSV 文件：配置文件（profile）位于 scripts/kconfig/hardening.yaml，各子系统的 hardening.yaml 片段则与其相关的 Kconfig 文件放在一起。现在每条建议都附有理由（显示在报告中），并可引用 CWE/CVE 条目；建议按配置文件分组（base 和 strict，可通过 -DHARDENCONFIG_PROFILE= 选择）；整数类建议可以表达最小值/最大值约束；提供 JSON 输出和失败退出码以便在 CI 中使用；还可以通过 -DHARDENCONFIG_EXTRA_SOURCES= 叠加树外数据库。CI 会根据实际的 Kconfig 树校验该数据库，因此其中的条目不会再过时。

  • 软件物料清单（west spdx）

    • 除默认的 SPDX 2.3 外，还支持通过 --spdx-version 3.0 选择 SPDX 3.0 JSON-LD 文档；SPDX 3.1 输出为实验性功能。元素 ID 在每次构建中唯一，因此 Sysbuild（系统构建） 构建中各镜像的 SBOM 可以合并为一个图。参见 选择 SPDX 版本。

    • SPDX 3 文档包含 构建配置（Build profile）：工具链及其版本、开发板和架构，以及每个库的子构建及其源文件和编译选项。

    • Zephyr 及其模块在记录时附带供应商信息和固定到所构建修订版的 purl；Zephyr 还附带根据 VERSION 生成的 CPE（包括候选发布版本）。每个模块的源文件都会关联到其 modules-deps 条目。参见 包标识。

    • 现在会列出链接到镜像中的预编译库（例如厂商二进制文件），并附上其所属模块声明的版本和下载 URL。参见 预构建库。

    • 许可证和版权信息通过 reuse 工具解析，因此会遵循 REUSE.toml 和 .license 文件，二进制文件也不例外。

    • 文件还会计算 SHA512 哈希值，并且每个文档都会记录其作者以及生成它的工具所对应的 Zephyr 版本。

  • CRC

    • 软件 CRC 子系统、CRC 驱动 API 和 NXP CRC 驱动新增 CRC-32/MPEG-2 支持（crc32_mpeg2() / crc32_mpeg2_update）。

  • 内核

    • 对象核心框架 不再在其跟踪的对象内部保存注册表状态。静态定义的对象被就地枚举，运行时初始化的对象则由一个有容量上限的注册表引用，因此内核对象可以声明在栈上、嵌入在已释放的内存中或被重新初始化，而不会破坏注册表。位于栈存储中的对象不会被跟踪。

    • CONFIG_SCHED_CPU_MASK 不再依赖 CONFIG_SCHED_SIMPLE。现在三种调度器后端都支持 CPU 亲和性掩码：SCHED_SIMPLE（O(N) 链表扫描）、SCHED_SCALABLE（O(N) 红黑树遍历）和 SCHED_MULTIQ（O(P·N) 按优先级的桶扫描）。各后端的性能说明请参阅更新后的 SMP 文档。

    • CONFIG_SCHED_CPU_MASK_PIN_ONLY 现在会在 API 边界（cpu_mask_mod()）和入队时（thread_runq()）同时强制执行“只能设置一个 CPU 位”的不变式。在 PIN_ONLY 模式下调用 k_thread_cpu_mask_clear()、k_thread_cpu_mask_enable_all() 或 k_thread_cpu_mask_disable() 会触发断言失败。请使用 k_thread_cpu_pin() 将线程重新分配到其他 CPU。

  • 定时器

    • 启用 CONFIG_SYSTEM_CLOCK_SLOPPY_IDLE 时，如果停止时基会破坏 sys_clock_cycle_get_32() / sys_clock_cycle_get_64()，驱动就不能再在没有待处理超时时立即停止其时基。只要 CPU 在运行，这两个函数就必须持续计数。只允许在 sys_clock_idle_enter() 中停止时基，因为此后必定会调用 sys_clock_idle_exit()。

    • 无节拍（tickless）系统定时器驱动现在可以基于共享的实现头文件 drivers/timer/system_timer_generic.h 构建。该头文件接管了以往各驱动自行实现的节拍计算：周期到节拍的转换、通告基准、节拍对齐的截止时间，以及计数器回绕和范围处理。驱动只需提供少量周期域的基本操作，即读取周期计数器和设置绝对比较值。用法请参阅 迁移指南（GitHub #115844）。

  • 网络

    • DHCPv4 客户端现在在每一条放弃租约的路径上，都会从接口上移除租用的地址、租约提供的 DNS 服务器以及它所设置的网关；在请求被拒绝或地址被谢绝（decline）之后，会等待约十秒再重新启动。

  • Wi-Fi

    • 移除了 samples/net/wifi/test_certs/rsa2k 企业级测试证书（其私钥采用 DES 加密）。请改用 rsa2k_no_des。

    • 连接结果事件现在可以通过新的 WIFI_STATUS_CONN_AUTH_REJECT 和 WIFI_STATUS_CONN_ASSOC_REJECT 值，表明接入点拒绝了认证或关联；wifi_status 还会携带导致失败的原始 IEEE 802.11 状态码和原因码。supplicant 会填写这些信息，Wi-Fi shell 会在显示连接和断开结果时打印它们。（GitHub #116704）

    • ESP32 Wi-Fi 驱动新增 802.11k/v/r 和 MBO 支持，默认全部关闭。CONFIG_ESP32_WIFI_11KV_SUPPORT 启用 802.11k 和 802.11v，CONFIG_ESP32_WIFI_MBO_SUPPORT 在此基础上启用 MBO，CONFIG_ESP32_WIFI_11R_SUPPORT 启用 802.11r。现在当 station 已关联时，wifi 11k 和 wifi 11v_btm_query shell 命令可以在 ESP32 上使用；CONFIG_ESP32_WIFI_SIGNAL_CHANGE_EVENT 会在所连接接入点的信号减弱时产生 NET_EVENT_WIFI_SIGNAL_CHANGE，供自行决定何时漫游的应用程序使用。

    • wifi-tx-power-2g.yaml 和 wifi-tx-power-5g.yaml 中的发射功率上限属性不再是 required，现在带有保守的默认值，因此未经特性测定的开发板宁可发射功率偏低，也不会超出法规限值。已测定自身限值的开发板会继续显式声明这些值，因此任何开发板的行为都不会改变。

    • P2P 新增了用于设置本地设备名和查询当前 P2P 状态的 shell 命令，其底层是新的 wifi_p2p_op 操作 WIFI_P2P_SET_DEV_NAME 和 WIFI_P2P_STATUS。wifi_p2p_params 中新增了对应的 device_name 和 status 成员，同时还新增了缓冲区大小宏 WIFI_P2P_STATUS_BUF_SIZE。

    • NET_REQUEST_WIFI_CONN_PARAMS 不再返回调用者在上一次连接请求中传入的缓冲区。psk、sae_password 和 EAP 字段现在为 NULL，SSID 在下一次连接请求之前保持有效。

  • MCUboot

    • SB_CONFIG_BOOT_SIGNATURE_KEY_FILE 现在接受以逗号分隔的密钥文件列表，并将每个密钥的公钥部分嵌入 MCUboot 引导加载程序。当给出多个密钥时，MCUboot 接受由其中任意一个签名的镜像。典型用法是让开发用引导加载程序既能引导开发签名的镜像，也能引导生产签名的镜像，而生产用引导加载程序只嵌入生产密钥。第一项是用于签名应用程序的密钥，其余各项是仅用于验证的公钥。参见 对二进制文件签名。

    • Espressif 开发板在 sysbuild 下不再强制使用仅覆盖（overwrite-only）模式和未签名镜像。现在它们会构建支持回滚的 swap-using-offset 模式 MCUboot，以及使用 RSA-2048 签名的应用程序；Espressif 共享分区表也不再预留 scratch 分区。请参阅 迁移指南。

  • Microchip

    • 采用 PIC32C 系列器件的 Microchip 开发板的默认 west flash 运行器已从 jlink 改为 mplab_ipe（MPLAB IPE 编程器，调用 ipecmd）。如需继续使用 J-Link，请传入 --runner jlink。

  • NXP

    • NXP LPC 的 DTSI 文件已从扁平的 dts/arm/nxp/lpc/ 目录重新组织到按系列划分的子目录中（lpc11u6x/、lpc51u68/、lpc54xxx/、lpc55xxx/、lpc84x/）。如何更新树外开发板的包含路径，请参阅 迁移指南。

    • NXP Kinetis 的 DTSI 文件已从扁平的 dts/arm/nxp/kinetis/ 目录重新组织到按系列划分的子目录中（k2x/、k32lx/、k6x/、k8x/、ke1xf/、ke1xz/、kl2x/、kv5x/、kwx/）。如何更新树外开发板的包含路径，请参阅 迁移指南。

    • NXP MCX 的 DTSI 文件已从扁平的 dts/arm/nxp/mcx/ 目录重新组织到按系列划分的子目录中（mcxa/、mcxc/、mcxe/、mcxl/、mcxn/、mcxw/）。如何更新树外开发板的包含路径，请参阅 迁移指南。

    • NXP i.MX RT 的 DTSI 文件已从扁平的 dts/arm/nxp/imxrt/ 目录重新组织到按系列划分的子目录中（imxrt10xx/、imxrt11xx/、imxrt5xx/、imxrt6xx/、imxrt7xx/、imxrt118x/）。如何更新树外开发板的包含路径，请参阅 迁移指南。

    • NXP MCUX CTimer、GPT 和 LPTimer 驱动新增计数器复位 API 支持。

    • 新增适用于 NXP LPC55xx 电源管理控制器（PMC）的 HWInfo 复位原因驱动。

  • Arm

    • 以下开发板的非安全变体：

      Arm Musca-S1（v2m_musca_s1/musca_s1/ns）已被移除，原因是 TF-M 移除了对该开发板的平台支持。

    • 因此，Arm Musca-S1 的安全变体（v2m_musca_s1）也已被弃用，以避免出现仅部分支持这种令人困惑的状态。

Trusted Firmware-A

  • 引入 CONFIG_TFA_BUILD_FIP，用于配置 FIP（固件镜像包，Firmware Image Package）的生成。FIP 生成默认禁用，可以通过在 prj.conf 中设置 CONFIG_TFA_BUILD_FIP=y 来启用；对于自定义开发板，也可以在开发板的 <board>_defconfig 文件中设置。
