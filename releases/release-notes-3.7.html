Zephyr 3.7.0

我们很高兴地宣布 Zephyr 3.7.0 版本发布。

本版本是最后一个非维护性的 3.x 版本，因此将成为下一个 长期支持（LTS）版本。

本版本的主要改进包括：

  • 引入了一个全新的、彻底 重构的硬件模型。它改变了 Zephyr 中 SoC 和开发板的命名、定义和构建方式。更多信息请参阅 开发板移植指南。

  • 期待已久的 HTTP 服务器 库及相关服务 API，使得在 Zephyr 中可以轻松实现 HTTP/1.1 和 HTTP/2 服务器。资源可以静态或动态注册，并且包含 WebSocket 支持。

  • 扩展了 POSIX 支持，IEEE 1003-2017 系统接口 的大部分选项（Option）都已得到支持，PSE51、PSE52 和 PSE53 所要求的大部分选项和选项组也已得到支持。

  • 蓝牙主机新增了对 Nordic UART 服务（NUS）、免提音频网关（AG）、高级音频分发配置文件（A2DP）和音频/视频分发传输协议（AVDTP）的支持。

  • 重构了传感器抽象模型，采用 先读取后解码的方式，与之前的 fetch/get API 相比，可以支持更多类型的传感器和数据流。

  • 新的 LLEXT 扩展开发者套件（EDK） 让开发自定义扩展并将其集成到 Zephyr 中变得更加容易，包括在 Zephyr 树之外开发。

  • 原生模拟器 现在支持直接利用主机原生网络协议栈，而无需对主机环境进行复杂的设置。

  • Zephyr 集成了 Trusted Firmware-M（TF-M）2.1.0 和 Mbed TLS 3.6.0，这两个版本都是 LTS 版本。此外，采用了 PSA Crypto 来取代 TinyCrypt，提供了更好的安全性和性能。

  • 新的 精确时间协议（PTP，IEEE 1588）实验性实现可以在设备之间以亚微秒级精度同步时间。

  • 新增了文档页面，帮助开发者为 Visual Studio Code 和 CLion 搭建本地开发环境。

将应用程序从 Zephyr v3.6.0 迁移到 Zephyr v3.7.0 时需要或建议进行的更改概述，请参阅单独的 迁移指南。

完整的变更日志可以参考之前各 3.x 版本的发布说明。自上一个 LTS 版本 Zephyr 2.7.0 以来，其他主要改进和变更包括：

  • 新增了对 Picolibc 的支持，并将其作为新的默认 C 库。

  • 新增了对以下类型硬件外设的支持：

    • 1-Wire

    • 电池充电器

    • 蜂窝调制解调器

    • 电量计

    • GNSS

    • 硬件自旋锁

    • I3C

    • RTC（实时时钟）

    • SMBus

  • 新增了对代码片段（snippet）的支持。代码片段是可以跨平台使用的通用配置设置。

  • 新增了对可链接可加载扩展（LLEXT）的支持。

  • 不兼容变更摘要（详情请参阅以往版本的发布说明和迁移指南）：

    • 所有 Zephyr 公共头文件都已移动到 include/zephyr，因此包含它们时需要加上 <zephyr/...> 前缀。

    • 移除了 Pinmux API，需要改用引脚控制（pin control），详情请参阅 引脚控制。

    • 移除了以下已弃用或实验性功能：

      • 6LoCAN

      • civetweb 模块。可改用 Zephyr 3.7 新增的 HTTP 服务器。

      • tinycbor 模块。可改用 zcbor。

API 变更

本版本移除的 API

  • 移除了蓝牙子系统专用的调试符号，已由 Zephyr 日志符号取代。

  • 从 PCIe API 中移除了已弃用的 pcie_probe 和 pcie_bdf_lookup 函数。

  • 移除了已弃用的 CONFIG_EMUL_EEPROM_AT2X Kconfig 选项。

  • 从设备电源管理 API 中移除了 pm_device_state_lock、pm_device_state_is_locked 和 pm_device_state_unlock 函数。

  • 移除了已弃用的 MCUmgr 传输 API 函数：zephyr_smp_rx_req、zephyr_smp_alloc_rsp 和 zephyr_smp_free_buf。

本版本弃用的内容

  • 蓝牙广播选项 BT_LE_ADV_OPT_USE_NAME 和 BT_LE_ADV_OPT_FORCE_NAME_IN_AD 现已弃用。这意味着以下宏已弃用：

    • BT_LE_ADV_CONN_NAME

    • BT_LE_ADV_CONN_NAME_AD

    • BT_LE_ADV_NCONN_NAME

    • BT_LE_EXT_ADV_CONN_NAME

    • BT_LE_EXT_ADV_SCAN_NAME

    • BT_LE_EXT_ADV_NCONN_NAME

    • BT_LE_EXT_ADV_CODED_NCONN_NAME

    应用程序开发者现在需要通过更新广播数据或扫描响应数据，自行设置广播名称。

  • CAN

    • 弃用了 can_calc_prescaler() API 函数，因为它允许存在比特率误差。同一网络中节点之间的比特率误差会导致它们在帧起始（SOF）同步之后逐渐失步，从而引发总线错误。

    • 弃用了 can_get_min_bitrate() 和 can_get_max_bitrate() API 函数，改用 can_get_bitrate_min() 和 can_get_bitrate_max()。

    • 弃用了 CAN_MAX_STD_ID 和 CAN_MAX_EXT_ID 宏，改用 CAN_STD_ID_MASK 和 CAN_EXT_ID_MASK。

  • 电源管理

    • 弃用了 CONFIG_PM_DEVICE_RUNTIME_EXCLUSIVE。使用 CONFIG_PM_DEVICE_SYSTEM_MANAGED 可以实现类似的行为。

  • POSIX API

    • 移除了已弃用的 PTHREAD_BARRIER_DEFINE。

    • 移除了已弃用的 EFD_IN_USE 和 EFD_FLAGS_SET。

    • 为了使用与 IEEE 1003.1-2017 中的选项（Option）和选项组（Option Group）直接对应的 Kconfig 选项，以下 Kconfig 选项已弃用（括号内为替代选项）：

      • CONFIG_EVENTFD_MAX (CONFIG_ZVFS_EVENTFD_MAX)

      • CONFIG_FNMATCH (CONFIG_POSIX_C_LIB_EXT)

      • CONFIG_GETOPT (CONFIG_POSIX_C_LIB_EXT)

      • CONFIG_MAX_PTHREAD_COUNT (CONFIG_POSIX_THREAD_THREADS_MAX)

      • CONFIG_MAX_PTHREAD_KEY_COUNT (CONFIG_POSIX_THREAD_KEYS_MAX)

      • CONFIG_MAX_TIMER_COUNT (CONFIG_POSIX_TIMER_MAX)

      • CONFIG_POSIX_LIMITS_RTSIG_MAX (CONFIG_POSIX_RTSIG_MAX)

      • CONFIG_POSIX_CLOCK (CONFIG_POSIX_CLOCK_SELECTION、CONFIG_POSIX_CPUTIME、CONFIG_POSIX_MONOTONIC_CLOCK、CONFIG_POSIX_TIMERS 和 CONFIG_POSIX_TIMEOUTS)

      • CONFIG_POSIX_FS (CONFIG_POSIX_FILE_SYSTEM)

      • CONFIG_POSIX_MAX_FDS (CONFIG_POSIX_OPEN_MAX 和 CONFIG_ZVFS_OPEN_MAX)

      • CONFIG_POSIX_MAX_OPEN_FILES (CONFIG_POSIX_OPEN_MAX 和 CONFIG_ZVFS_OPEN_MAX)

      • CONFIG_POSIX_MQUEUE (CONFIG_POSIX_MESSAGE_PASSING)

      • CONFIG_POSIX_PUTMSG (CONFIG_XOPEN_STREAMS)

      • CONFIG_POSIX_SIGNAL (CONFIG_POSIX_SIGNALS)

      • CONFIG_POSIX_SYSCONF (CONFIG_POSIX_SINGLE_PROCESS)

      • CONFIG_POSIX_UNAME (CONFIG_POSIX_SINGLE_PROCESS)

      • CONFIG_PTHREAD (CONFIG_POSIX_THREADS)

      • CONFIG_PTHREAD_BARRIER (CONFIG_POSIX_BARRIERS)

      • CONFIG_PTHREAD_COND (CONFIG_POSIX_THREADS)

      • CONFIG_PTHREAD_IPC (CONFIG_POSIX_THREADS)

      • CONFIG_PTHREAD_KEY (CONFIG_POSIX_THREADS)

      • CONFIG_PTHREAD_MUTEX (CONFIG_POSIX_THREADS)

      • CONFIG_PTHREAD_RWLOCK (CONFIG_POSIX_READER_WRITER_LOCKS)

      • CONFIG_PTHREAD_SPINLOCK (CONFIG_POSIX_SPIN_LOCKS)

      • CONFIG_SEM_NAMELEN_MAX (CONFIG_POSIX_SEM_NAMELEN_MAX)

      • CONFIG_SEM_VALUE_MAX (CONFIG_POSIX_SEM_VALUE_MAX)

      • CONFIG_TIMER (CONFIG_POSIX_TIMERS)

      • CONFIG_TIMER_DELAYTIMER_MAX (CONFIG_POSIX_DELAYTIMER_MAX)

      请参阅 POSIX API 迁移指南。

  • SPI

  • 移除了已弃用的 spi_is_ready() API 函数。

  • 移除了已弃用的 spi_transceive_async() API 函数。

  • 移除了已弃用的 spi_read_async() API 函数。

  • 移除了已弃用的 spi_write_async() API 函数。

架构

  • ARC

    • 新增了针对 ARC-V 目标的 ARC MWDT 工具链支持

    • 新增了针对多核目标的硬件内存屏障 API 支持

    • 使用 ARC MWDT 工具链时，如果使用 C++，则默认启用 TLS

    • 修复了使用 ARC MWDT 工具链和最小 LibC 时，由于标记边界检查接口 C 库扩展支持的宏定义不正确而导致 mbedtls 构建失败的问题

    • 修复了使用 ARC MWDT 工具链时的设备延迟初始化问题

  • ARM

    • 新增了对 Cortex-M85 内核的初步支持

  • ARM64

    • 实现了回溯（backtrace）中的符号名称显示，可通过选择 CONFIG_SYMTAB 启用

    • 新增了针对 Cortex-R82 的编译器调优

  • RISC-V

    • 由故障触发的致命错误信息现在包含被调用者保存寄存器（callee-saved registers）的状态。

    • 实现了栈回溯（stack unwinding）

      • 可以选择使用帧指针来获得精确的栈跟踪，代价是代码体积略有增加、速度略有降低。

      • 可通过选择 CONFIG_EXCEPTION_STACK_TRACE_SYMTAB 启用符号名称显示

  • Xtensa

    • 新增了对保存/恢复 HiFi AudioEngine 寄存器的支持。

    • 新增了对使用 MPU 的支持。

    • 新增了对自动生成中断处理程序的支持。

    • 新增了对在构建时生成向量表并将其包含到链接脚本中的支持。

    • 新增了 Kconfig 选项 CONFIG_XTENSA_BREAK_ON_UNRECOVERABLE_EXCEPTIONS，用于控制是否对不可恢复的异常使用 break 指令。通过该选项启用 break 指令可能导致无限的中断风暴，从而妨碍调试。

    • 修复了通过系统调用传递第 7 个参数时处理不正确的问题。

    • 修复了 arch_user_string_nlen() 访问未映射内存时导致不可恢复异常的问题。

内核

  • 新增了 k_uptime_seconds() 函数，以简化 k_uptime_get() / 1000 的用法。

  • 新增了 k_realloc()，它使用内核堆实现传统的 realloc() 语义。

  • 现在开启 CONFIG_DEVICE_DT_METADATA 后，设备可以保存节点标签（nodelabel）等设备树元数据。该选项在 shell 等场景中可能很有用，因为借助 device_get_by_dt_nodelabel() 等 API，可以使用便于人阅读的名称获取设备。

  • 如果设备关联的设备树节点设置了特殊属性 zephyr,deferred-init，则该设备的初始化可以推迟，之后可使用 device_init() 初始化该设备。

  • 静态分配线程栈的声明已更新，单个线程栈声明和线程栈数组声明都使用 K_THREAD_STACK_LEN，以确保所有线程栈正确对齐。对于用户线程，根据架构的对齐要求，这可能会增大静态分配的栈对象的大小。

  • 修复了 k_thread_abort()（以及 join）中的一个边界情况死锁：在 SMP 系统上，相互竞争的 ISR 可能会在互相通知对方被中断的线程时陷入自旋而卡住。

  • 修复了同时使用 CONFIG_SCHED_SCALABLE 和 CONFIG_SCHED_DEADLINE 时会破坏调度队列的缺陷。

蓝牙

  • 音频

    • 从 bt_bap_broadcast_assistant_cb.recv_state_removed 中移除了 err，因为它是多余的。

    • broadcast_audio_assistant 示例已重命名为 bap_broadcast_assistant。broadcast_audio_sink 示例已重命名为 bap_broadcast_sink。broadcast_audio_source 示例已重命名为 bap_broadcast_source。unicast_audio_client 示例已重命名为 bap_unicast_client。unicast_audio_server 示例已重命名为 bap_unicast_server。public_broadcast_sink 示例已重命名为 pbp_public_broadcast_sink。public_broadcast_source 示例已重命名为 pbp_public_broadcast_source。

    • 对于 BT_CAP_SET_TYPE_AD_HOC 集合，CAP Commander 和 CAP Initiator 现在不再要求先发现 CAS。这样，应用程序就可以在未实现 CAP Acceptor 角色的 BAP Unicast Server 等设备上使用这些 API。

  • 主机

    • 新增了 Nordic UART 服务（NUS），通过 CONFIG_BT_ZEPHYR_NUS 启用。该服务支持声明多个 GATT 服务实例，从而可以将多个串行端点用于不同用途。

    • 实现了免提音频网关（AG），通过 CONFIG_BT_HFP_AG 启用。它作为音频网关设备工作，典型的音频网关设备是手机。它控制作为远端音频输入输出装置的设备（免提单元）。

    • 实现了高级音频分发配置文件（A2DP）和音频/视频分发传输协议（AVDTP），A2DP 通过 CONFIG_BT_A2DP 启用，AVDTP 通过 CONFIG_BT_AVDTP 启用。它们实现了以单声道、立体声或多声道模式分发高质量音频内容的协议和流程。典型用例是将音乐内容从立体声音乐播放器流式传输到耳机或扬声器。音频数据会压缩为合适的格式，以便高效利用有限的带宽。

    • 重构了数据和命令的发送路径。移除了“BT TX”线程以及用于 HCI 分片和 L2CAP 分段的缓冲池。与控制器的所有通信现在都只在系统工作队列上下文中进行。

    • CONFIG_BT_PER_ADV_SYNC_TRANSFER_RECEIVER 和 CONFIG_BT_PER_ADV_SYNC_TRANSFER_SENDER 现在依赖 CONFIG_BT_CONN，因为它们在没有连接的情况下无法工作。

    • 改进了 bt_foreach_bond()，使其支持遍历经典蓝牙密钥。

  • HCI 驱动

    • 彻底重新设计了 HCI 驱动接口。更多信息请参阅 迁移到 Zephyr v3.7.0 的指南 中的蓝牙 HCI 一节。

    • 新增对 Ambiq Apollo3 Blue 系列的支持。

    • 新增对 NXP RW61x 的支持。

    • 新增对 Infineon CYW208XX 的支持。

    • 新增对 Renesas SmartBond DA1469x 的支持。

    • 移除了无人维护的 B91 驱动。

    • 在开发板 mimxrt1170_evkb 和 mimxrt1040_evk 上新增对 NXP IW612 的支持。可通过 CONFIG_BT_NXP_NW612 启用。

开发板与 SoC 支持

  • 新增对以下 SoC 系列的支持：

    • 新增对 Ambiq Apollo3 Blue 和 Apollo3 Blue Plus SoC 系列的支持。

    • 新增对 Synopsys ARC-V RMX1xx 仿真平台的支持。

    • 新增对 STM32H7R/S SoC 系列的支持。

    • 新增对 NXP mke15z7、mke17z7、mke17z9、MCXNx4x、RW61x 的支持

    • 新增对 Analog Devices MAX32 SoC 系列的支持。

    • 新增对 Infineon Technologies AIROC™ CYW20829 Bluetooth LE SoC 系列的支持。

    • 新增对 MediaTek MT8195 音频 DSP 的支持

    • 新增对 Nuvoton Numaker M2L31X SoC 系列的支持。

    • 新增对 Microchip PolarFire ICICLE Kit SMP 变体的支持。

    • 新增对 Renesas RA8 系列 SoC 的支持。

  • 对其他 SoC 系列进行了以下更改：

    • Intel ACE 音频 DSP：使用专用寄存器而不是任意内存来报告启动状态。

    • ITE：重命名了所有 ITE SoC 型号的 Kconfig 符号。

    • STM32：在兼容的系列上启用了 ART 加速器、I-cache、D-cache 和预取。

    • STM32H5：新增对 Stop 模式和 CONFIG_PM 的支持。

    • STM32WL：将 Sub-GHz SPI 频率从 12 MHz 降至 8 MHz。

    • STM32C0：新增对 CONFIG_POWEROFF 的支持。

    • STM32U5：新增对 Stop3 模式的支持。

    • Synopsys：

      • nsim：将 nsim 平台拆分为 arc_classic（基于 ARCv2 和 ARCv3 ISA）和 arc_v（基于 RISC-V ISA）

      • nsim/nsim_hs5x/smp：使系统时钟频率与其他 SMP nSIM 配置保持一致

    • NXP IMX8M：新增资源域控制器支持

    • NXP s32k146：将 RTC 时钟源设置为内部振荡器

    • GD32F4XX：修复了 uart4 中断号错误的问题。

    • Nordic nRF54L：新增对 FLPR（快速轻量处理器）RISC-V CPU 的支持。

    • Espressif：移除了所有 ESP32 SoC 型号对 idf-bootloader 的依赖。

    • Espressif：为 ESP32 SoC 型号新增简单启动（Simple boot）支持，可以使用单个二进制镜像加载应用程序，无需二级引导加载程序。

    • Espressif：重新设计并优化了所有 SoC 的内存映射。

    • LiteX：

      • 新增对 sys_arch_reboot() 的支持。

      • 不再错误地以 y-select 方式选中 CONFIG_RISCV_ISA_EXT_A。

    • rp2040：停用了专有 UART 驱动，改用 PL011。

    • Renesas RZ/T2M：为系统时钟控制寄存器添加了默认值。

  • 新增对以下开发板的支持：

    • 新增对 Ambiq Apollo3 Blue 开发板（apollo3_evb）的支持。

    • 新增对 Ambiq Apollo3 Blue Plus 开发板（apollo3p_evb）的支持。

    • 新增对 Raspberry Pi 5 开发板（rpi_5）的支持。

    • 新增对 Seeed Studio XIAO RP2040 开发板（xiao_rp2040）的支持。

    • 新增对 Mikroe RA4M1 Clicker 开发板（mikroe_clicker_ra4m1）的支持。

    • 新增对 Arduino UNO R4 WiFi 开发板（arduino_uno_r4_wifi）的支持。

    • 新增对 Renesas EK-RA8M1 开发板（ek_ra8m1）的支持。
