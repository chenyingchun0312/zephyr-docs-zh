Zephyr 4.3.0

我们很高兴地宣布 Zephyr 4.3.0 版本正式发布。

本版本的主要改进包括：

USB 设备“Next”协议栈现已成为默认协议栈

基于现代 UDC（USB 设备控制器）API 构建的新 USB 设备协议栈 取代了旧版协议栈，带来了对多个控制器同时工作、运行时配置的支持，整体架构也更加完善。旧版协议栈现已弃用，并将在 Zephyr 4.5 中移除。

CPU 负载与动态调频子系统

新的实验性 CPU 调频 子系统支持动态的、由策略驱动的时钟调整，以平衡功耗与性能。与此同时，新的 CPU 负载 子系统使用户能够基于调度器统计信息获取 CPU 使用率指标，这些指标可用于驱动调频策略。

插桩（Instrumentation）子系统

新的 插桩子系统 借助编译器管理的函数插桩，简化了 Zephyr 应用程序的跟踪和性能分析，可在运行时记录调用图跟踪和统计分析数据。

OCPP 1.6 库

新的 OCPP（开放充电点协议） 库使得可以使用 Zephyr 开发电动汽车充电站。该库通过 WebSocket 实现了 OCPP 1.6 充电点功能，支持核心规范中的各项操作，包括授权、交易管理和电表读数上报，用于与中央系统服务器通信。

Twister 显示测试框架（harness）

Twister 现在可以通过 USB 视频摄像头捕获画面，并与预先录制的视觉“指纹”进行匹配，从而 验证目标设备上的显示输出。

开发者体验改进

新引入了若干工具，用于协助完成常见的开发和故障排查任务：

  • 设备树诊断（dtdoctor），用于帮助诊断设备树构建错误。

  • traceconfig 构建目标，用于帮助了解 Kconfig 符号的来源及其最终取值。

  • 交互式占用空间图表，用于可视化应用程序的 RAM/ROM 使用情况。

扩展的开发板支持

本版本新增了对 105 款 新开发板 和 39 款 新扩展板 的支持。

将应用程序从 Zephyr v4.2.0 迁移到 Zephyr v4.3.0 时需要或建议进行的更改概述，请参阅单独的 迁移指南。

以下各节按组件详细列出了各项更改。

安全漏洞相关

本版本解决了以下 CVE：

  • CVE 2025-9408 Zephyr 项目缺陷跟踪 GHSA-3r6j-5mp3-75wr

  • CVE 2025-9557：禁止披露至 2025-11-24

  • CVE 2025-9558：禁止披露至 2025-11-24

  • CVE 2025-12035：禁止披露至 2025-12-13

  • CVE 2025-12899：禁止披露至 2026-01-28

  • CVE 2025-59438 通过密码错误报告时序实现的填充预言攻击

  • CVE 2025-54764 RSA 密钥生成及运算中的侧信道（SSBleed、M-Step）

更多详细信息请参阅：https://docs.zephyrproject.org/latest/security/vulnerabilities.html

API 变更

  • 加密

    • hash_pkt 中的输入缓冲区现在是常量

已移除的 API 和选项

  • 移除了 TinyCrypt 库，因为其上游版本已不再维护。现在推荐使用 PSA Crypto API 作为 Zephyr 的加密库。

  • 移除了旧版管道对象 API。请改用新的管道 API。

  • bt_le_set_auto_conn

  • CONFIG_BT_BUF_ACL_RX_COUNT

  • 设备树中 base.yaml 绑定的 status 属性已彻底移除枚举值 ok。

  • 移除了通过 Kconfig 选择 STM32 LPTIM 时钟源的方式，现在必须改用设备树。受影响的 Kconfig 符号：CONFIG_STM32_LPTIM_CLOCK_LSI / CONFIG_STM32_LPTIM_CLOCK_LSE

已弃用的 API 和选项

  • 弃用了 maxim,ds3231，改用 maxim,ds3231-rtc。

  • 弃用了向 SPI_CONFIG_DT、SPI_CONFIG_DT_INST、SPI_DT_SPEC_GET、SPI_DT_SPEC_INST_GET 传入第三个参数的用法，也弃用了向 SPI_CS_CONTROL_INIT 传入第二个参数的用法。请改用新的设备树属性 spi-cs-setup-delay-ns 和 spi-cs-hold-delay-ns 来指定延迟。

  • 弃用了 bt_hci_bus，因为它未被使用。应改用 BT_DT_HCI_BUS_GET。

  • 弃用了 CONFIG_BT_AUTO_PHY_UPDATE，它已被按角色（中心设备与外围设备）区分的选项取代，这些选项可以精确指定自动更新时首选的 PHY。

  • 弃用了 CONFIG_POSIX_READER_WRITER_LOCKS。请改用 CONFIG_POSIX_RW_LOCKS。

  • 弃用了 CONFIG_JWT_SIGN_RSA_LEGACY。请改用基于 PSA Crypto API 的替代方案（即 CONFIG_JWT_SIGN_RSA_PSA）。

  • 弃用了 RISCV 的 CONFIG_EXTRA_EXCEPTION_INFO。请改用 CONFIG_EXCEPTION_DEBUG。

库/子系统

  • 固件

    • SCMI

      • 新增了 ARM_SCMI_CHAN_SEM_TIMEOUT_USEC，用于配置通道信号量的超时时间。

      • 直接使用 scmi_status_to_errno() 检查返回的命令状态码。

      • 为 scmi_send_message() 新增了一个参数，允许用户指定是否使用轮询。

      • [NXP] 新增了与 NXP 专用 CPU 协议相关的多项内容。

  • 日志：

    • 新增了混合式限速日志宏，以防止在频繁生成消息时日志泛滥。系统同时提供便捷宏（使用 CONFIG_LOG_RATELIMIT_INTERVAL_MS 中的默认速率）和显式速率宏（带有自定义速率参数）。该设计沿用了 Linux 的 printk_ratelimited 模式，同时提供了更大的灵活性。限速按宏调用点进行，即每个限速宏的不同调用处都拥有各自独立的速率限制。可以通过 CONFIG_LOG_RATELIMIT 全局启用或禁用限速日志。禁用限速时，可以通过 CONFIG_LOG_RATELIMIT_FALLBACK 控制其行为：记录所有消息，或将其全部丢弃。更多详细信息请参阅 限速日志。

  • Mbed TLS

    • 新增了 Kconfig 选项 CONFIG_PSA_CRYPTO，以简化 PSA Crypto API 提供者的启用。如果启用了 CONFIG_BUILD_WITH_TFM，提供者为 TF-M，否则为 Mbed TLS。前一种情况下会设置 CONFIG_PSA_CRYPTO_PROVIDER_TFM，后一种情况下会设置 CONFIG_PSA_CRYPTO_PROVIDER_MBEDTLS。此外还新增了 CONFIG_PSA_CRYPTO_PROVIDER_CUSTOM，允许最终用户提供自定义方案。

    • 从 3.6.4 版本更新至 3.6.5 版本。该版本的发布说明见以下链接：

      • https://github.com/Mbed-TLS/mbedtls/releases/tag/mbedtls-3.6.5

  • 安全存储

    • 移除了实验性状态。（GitHub #96483）

其他值得注意的变更

  • Nordic Semiconductor nRF54L09 PDK（nrf54l09pdk）仅面向模拟器，现已从代码树中移除。一旦有正式的开发板定义可用，将会以其取代。

  • 移除了对 Nordic Semiconductor nRF54L20 PDK（nrf54l20pdk）的支持，因为它已被 nRF54LM20 DK（nrf54lm20dk）取代。
