通用

  • 头文件 include/zephyr/sys_clock.h 已弃用，并将在未来的版本中移除。应改为包含 include/zephyr/sys/clock.h。

构建系统

  • CMake 的最低版本要求现在是 3.28.0。Ubuntu 24.04 LTS 的软件包仓库提供 CMake 3.28.3。使用自带较旧 CMake 的发行版（例如 Ubuntu 22.04 LTS）的用户，可以从 Kitware APT 仓库 或通过 pip install cmake 获取较新的版本。

  • 对早于 C17 的 C 标准版本的支持在弃用之后已被移除。Kconfig 选项 CONFIG_STD_C11、CONFIG_STD_C99 和 CONFIG_STD_C90 已被移除。编译 Zephyr 时请使用 C17 或更高版本。

  • CONFIG_LEGACY_GENERATED_INCLUDE_PATH 已弃用，并且默认禁用，现在包含 Zephyr 文件时必须加上 zephyr/ 前缀。

  • CMake 变量 SOC_NAME、SOC_SERIES、SOC_FAMILY 和 SOC_V2_DIR 已弃用，因为它们与已有的变量重复，对应的替代变量如下：CONFIG_SOC、CONFIG_SOC_SERIES、CONFIG_SOC_FAMILY 和 SOC_FULL_DIR。

  • CONFIG_BUILD_NO_GAP_FILL 已被移除。间隙填充需要通过 CONFIG_BUILD_OUTPUT_HEX_GAP_FILL 和 CONFIG_BUILD_OUTPUT_S19_GAP_FILL 主动启用，因此直接删除该选项即可。

  • cmake/app/boilerplate.cmake 已被移除。仍直接包含该文件的应用程序，必须改为在其 CMakeLists.txt 开头使用 find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})。

  • 名为 <board>_<revision>.conf 的开发板版本 Kconfig 片段不再被读取。请将它们重命名为 <board>_<revision>_defconfig。

  • zephyr_code_relocate(FILES ...) 不再展开通配符模式，遇到通配符模式时现在会报错。请使用 file(GLOB ...) 展开该模式，然后传入得到的文件名。

  • 自 Zephyr 3.1 起弃用的 ZephyrUnittest CMake 包已被移除，west zephyr-export 也不再注册它。请使用 find_package(Zephyr COMPONENTS unittest) 代替 find_package(ZephyrUnittest)。

  • west spdx --init 已弃用，并将在 Zephyr 5.0 中移除。启用 CONFIG_BUILD_OUTPUT_META 的构建现在会向 CMake 请求 west spdx 所读取的基于文件的 API 对象模型，因此生成 SBOM 不再需要事先准备构建目录：照常构建，然后运行 west spdx 即可。

  • CMake 的 flash、debug、debugserver、attach 和 rtt 目标已被移除。请改用 west flash、west debug、west debugserver、west attach 和 west rtt。用于仿真的 run 和 debugserver 目标不受影响。

  • 构建系统不再使用 WEST_DIR 变量。

  • CONFIG_DEPRECATION_TEST 已弃用，因为可以改用 CONFIG_WARN_DEPRECATED，只需将 CONFIG_DEPRECATION_TEST=y 这样的行替换为 CONFIG_WARN_DEPRECATED=n。

  • 加固工具的数据文件 scripts/kconfig/hardened.csv 已被 YAML 数据库取代：配置方案位于 scripts/kconfig/hardening.yaml，各子系统的 hardening.yaml 片段则放在与其相关的 Kconfig 文件旁边。修改过该 CSV 的下游分支应将其条目迁移到新格式（参见 加固工具）；树外的建议项完全不再需要修改树内文件，可以改为通过 -DHARDENCONFIG_EXTRA_SOURCES= 提供。注意，CONFIG_DEBUG_COREDUMP 在 CSV 中的条目存在语法错误，此前被静默跳过；现在会真正对它进行检查，因此 hardenconfig 可能会将其报告为新的发现。有三个 CSV 条目被直接删除而没有迁移：CONFIG_STACK_USAGE，它只在构建时生成 .su 文件，不影响镜像；以及 CONFIG_MPU_STACK_GUARD 和 CONFIG_BUILTIN_STACK_GUARD，它们是互斥的机制，由 CONFIG_HW_STACK_PROTECTION 决定选用哪一个——同时推荐两者会在带有栈指针限制寄存器的内核上标记出错误的那一个。仍然推荐启用 CONFIG_HW_STACK_PROTECTION，由架构自行选择。

内核

  • 由于 errno 已从内核移到 lib/libc/common，_k_neg_eagain 已重命名为 _errno_neg_egain。

  • k_sem_reset() 不再唤醒在该信号量上等待的轮询等待者。轮询等待者会一直等待，直到信号量变为可用或轮询操作超时。依赖重置操作来唤醒轮询等待者的应用程序必须改用显式的同步机制。

  • Kconfig 选项 CONFIG_SMP_BOOT_DELAY 已被移除。将从 CPU 的启动推迟到运行时，现在改为在设备树中按 CPU 指定：在 /cpus 下对应的 cpu 节点上添加 zephyr,deferred-start 标志（通常在开发板覆盖文件中添加），之后与以前一样，使用 k_smp_cpu_start() 或 k_smp_cpu_resume() 启动该 CPU。被移除的选项会跳过所有从 CPU，而现在可以为每个 CPU 单独选择是否推迟启动。注意，该标志只对设备树绑定包含 cpu.yaml 的 cpu 节点生效；没有此类绑定的节点无法推迟启动。

  • 启用 CONFIG_SCHED_CPU_MASK_PIN_ONLY 时，调用 k_thread_cpu_mask_clear()、k_thread_cpu_mask_enable_all() 或 k_thread_cpu_mask_disable() 现在会触发断言，而不是静默地产生无效状态。在 PIN_ONLY 模式下使用这些函数的应用程序必须改为使用 k_thread_cpu_pin()。

  • CONFIG_SCHED_CPU_MASK 不再仅限于 CONFIG_SCHED_SIMPLE。以前选择了 SCHED_SCALABLE 或 SCHED_MULTIQ、并为了 CPU 亲和性而保留 SCHED_SIMPLE 来绕过该限制的项目，现在可以直接使用自己偏好的后端。

  • k_sleep() 和 k_usleep() 不再是独立的系统调用。它们现在是新系统调用 k_sleep_ticks() 的内联封装，使编译器可以折叠或消除其中的单位换算。它们的原型、语义和返回值不变，并已从 include/zephyr/kernel.h 移到新的 include/zephyr/sleep.h，后者由 kernel.h 包含。调用它们的代码无需修改。获取它们地址的树外代码，或依赖 K_SYSCALL_K_SLEEP 或 K_SYSCALL_K_USLEEP 的树外代码，必须改为使用 k_sleep_ticks()。注意，从 K_FOREVER 提前唤醒时，它报告的是 K_TICKS_FOREVER，而 k_sleep() 返回的是 -1。

  • sys_port_trace_k_thread_sleep_*()、sys_port_trace_k_thread_msleep_*() 和 sys_port_trace_k_thread_usleep_*() 钩子已被 sys_port_trace_k_thread_sleep_ticks_enter() 和 sys_port_trace_k_thread_sleep_ticks_exit() 取代，因为 k_sleep_ticks() 现在是这四个函数中唯一不是内联的函数。退出钩子以节拍为单位报告剩余的睡眠时间，因此以毫秒形式呈现该值的后端应进行换算，例如使用 k_ticks_to_ms_ceil64()。定义了任何已停用钩子的树外跟踪后端都必须更新。

  • k_futex 不再是内核对象，对应的类型 K_OBJ_FUTEX 已被移除。任何用户可访问的内存都可以用作 futex 地址。futex 操作不会再返回 -EINVAL 错误。

  • 对象核心框架 不再通过对象中的节点将对象链接到按类型划分的链表中。静态定义的对象在原位枚举，运行时初始化的对象则由一个有界的注册表引用，其大小由 CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS 决定。k_obj_core 的 node 成员和 k_obj_type 的 list 成员已被移除；遍历这些链表的工具必须改用 k_obj_type_walk_locked() 或 k_obj_type_walk_unlocked()。K_OBJ_TYPE_DEFINE 现在会自行定义 k_obj_type 变量，因此必须删除该变量的单独声明。位于线程栈或中断栈中的对象不再被注册，并且 CONFIG_OBJ_CORE 会选择 CONFIG_THREAD_STACK_INFO，从而为每个 k_thread 添加栈信息字段。新增的 CONFIG_OBJ_CORE_QUEUE 默认启用，它为每个 k_queue 添加一个对象核心；由于 FIFO 和 LIFO 内嵌了一个队列，它们会同时以自身的对象类型和队列类型被报告。

  • 对象跟踪（CONFIG_TRACING_OBJECT_TRACKING）现在由对象核心框架提供，并会选择该框架。_track_list_k_* 链表头、SYS_PORT_TRACK_NEXT() 宏、sys_track_*_init() 钩子以及 include/zephyr/tracing/tracking.h 头文件已被移除。遍历跟踪链表的代码必须改用 k_obj_type_walk_locked() 或 k_obj_type_walk_unlocked()，并配合 k_obj_type_find() 找到的对象类型。

开发板

  • 在 NXP LPC54xxx 上，CONFIG_LPC54XXX_SRAM2_CLOCK 已被 CONFIG_SOC_SERIES_LPC54XXX_SRAM_CLOCKS 取代。在 LPC54114 还是该系列唯一一款 SoC 时，旧名称是合适的，因为在它上面 CMSIS SystemInit() 只启用 SRAM2。而在 LPC546xx 上，它会启用 SRAM2 和 SRAM3，因此该选项现在涵盖的不止其名称所指的那一个存储体。两者的默认值都是 y。对旧符号赋值的配置必须更新，否则将无法构建。

  • 在 RP2040 和 RP2350 上，vreg 节点（raspberrypi,core-supply-regulator）现在默认为 disabled，而不是 okay。需要该稳压器的树外开发板必须在 &vreg 节点上设置 status = "okay"。

    在 RP2040 上，SoC dtsi 现在默认设置了 regulator-always-on 和 regulator-allowed-modes = <REGULATOR_RPI_PICO_MODE_NORMAL> 属性。以前显式设置这些属性的开发板可以删除相应的行。（GitHub #114751）

  • 在 RP2040 上，mbox 节点已拆分为 mbox0 和 mbox1，以提供每个核心各自的邮箱实例。ipm_mbox 节点相应地重命名为 ipm_mbox0 和 ipm_mbox1。

  • 在 RP2350（rpi_pico 系列）上，hazard3 和 m33 cpucluster 限定符已弃用，改用 hazard3_0 和 m33_0，它们明确将该簇标识为 CPU0，为双核支持做好准备。所有树内 RP2350 开发板都已迁移到新的限定符（例如从 rpi_pico2/rp2350a/m33 改为 rpi_pico2/rp2350a/m33_0）。使用不带编号的 hazard3/m33 限定符的树外开发板，应重命名其开发板文件、board.yml 中的 cpucluster: 条目，并将 Kconfig select 行改为使用 SOC_RP2350[AB]_HAZARD3_0/SOC_RP2350[AB]_M33_0。soc.yml 中不带编号的 hazard3/m33 条目以及对应的 SOC_RP2350[AB]_HAZARD3/_M33 Kconfig 符号已弃用，两者都将在未来的版本中移除。

  • RAK4631 WisBlock Core Module 现在支持 WisBlock 生态系统。需要一块 WisBlock 底板扩展板（例如 RAK19007 WisBlock 第二代底板）来引出传感器和 IO 插槽：

    west build -b rak4631/nrf52840 --shield rakwireless_rak19007

  • Kconfig 选项 CONFIG_SRAM_SIZE 和 CONFIG_SRAM_BASE_ADDRESS 已弃用，开发板应改为使用设备树的 zephyr.sram chosen 节点来指定所使用的 RAM 节点（这些 Kconfig 值原本就是由该节点的值填充的）。如果手动调整了其中任一选项，就会设置 CONFIG_SRAM_DEPRECATED_KCONFIG_SET，以表明使用了已弃用的配置。

  • Nordic SoC 平台内部的 Kconfig 符号 CONFIG_NRF_PLATFORM_HALTIUM 和 CONFIG_NRF_PLATFORM_LUMOS 不再被树内代码使用，树内代码现在改为显式检查 CONFIG_SOC_SERIES_NRF54H、CONFIG_SOC_SERIES_NRF92、CONFIG_SOC_SERIES_NRF54L 和 CONFIG_SOC_SERIES_NRF71。这两个符号作为已弃用的存根保留：当选择了对应的 SoC 系列并启用 CONFIG_NRF_PLATFORM_DEPRECATED_SYMBOLS 时，它们默认为 y，因此现有的 CONFIG_NRF_PLATFORM_*=y 行和 depends on NRF_PLATFORM_* 子句仍能构建，但会产生 Kconfig 弃用警告。使用这些符号的树外 Kconfig、CMake 和代码应进行更新：

    • 将 CONFIG_NRF_PLATFORM_HALTIUM 替换为 CONFIG_SOC_SERIES_NRF54H 或 CONFIG_SOC_SERIES_NRF92。

    • 将 CONFIG_NRF_PLATFORM_LUMOS 替换为 CONFIG_SOC_SERIES_NRF54L 或 CONFIG_SOC_SERIES_NRF71。

  • Aesc Silicon 的 elemrv 开发板已重命名为 elemrv_flask_n。

  • STMicroelectronics 的 stm32mp157c_dk2 开发板已重命名为 stm32mp157x_dk2，现在同时涵盖两种 SoC 型号。为 STM32MP157C-DK2 构建时使用 -b stm32mp157x_dk2/stm32mp157cxx，为 STM32MP157F-DK2 构建时使用 -b stm32mp157x_dk2/stm32mp157fxx。原来的 -b stm32mp157c_dk2 已弃用，现在映射到 stm32mp157x_dk2/stm32mp157cxx。

  • Infineon 的 kit_psc3m6_evk 开发板已重命名为 kit_psc3m6_eval。原来的 -b kit_psc3m6_evk 和 -b kit_psc3m6_evk/psc3m6ges3ahq1 已弃用，现在分别映射到 kit_psc3m6_eval 和 kit_psc3m6_eval/psc3m6ges3ahq1。

  • Nordic 的 sysbuild Kconfig 选项 SB_CONFIG_NRF_HALTIUM_GENERATE_UICR 已重命名为 SB_CONFIG_NRF_GENERATE_UICR。请更新 sysbuild 配置以使用新名称。

  • Nordic SoC 头文件 <haltium_power.h> 和 <haltium_pm_s2ram.h> 已分别重命名为 <soc_power.h> 和 <soc_pm_s2ram.h>。旧名称下仍保留转发头文件，它们会发出一条 #warning，指向新的包含路径。包含旧路径的树外代码应进行更新：

    • 将 #include <haltium_power.h> 替换为 #include <soc_power.h>。

    • 将 #include <haltium_pm_s2ram.h> 替换为 #include <soc_pm_s2ram.h>。

  • 基于 STM32H7RS 的开发板（stm32h7s78_dk 和 nucleo_h7s3l8）的系统时钟已提高到 600 MHz。这是通过将 PLL1 频率提高到 300 MHz 实现的，这也会影响总线时钟和内核时钟，使它们的频率略有升高。

  • 在大多数 STM32 开发板上，CONFIG_GPIO 不再默认启用（带有 GPIO hog 的开发板仍保持启用，因为 hog 需要 GPIO 才能工作）。依赖 CONFIG_GPIO=y 为默认值的应用程序需要显式启用该选项。（GitHub #109468）

  • 使用 UF2 镜像并迁移到 zephyr,mapped-partition 的开发板，应在其 defconfig 中启用 HEX 输出（CONFIG_BUILD_OUTPUT_HEX），因为生成 UF2 镜像时不能再依赖 CONFIG_FLASH_LOAD_OFFSET 从 BIN 输出中确定代码地址。现在默认由 HEX 转换为 UF2（而不是 BIN）。（GitHub #107944）

  • Ezurio bl54l15u_dvk 已被移除。bl54l15_dvk 仍然可用，它支持该模块的 bl54l15 和 bl54l15u 两种型号，功能相同。使用 bl54l15u_dvk 的开发板应根据情况迁移到 bl54l15_dvk/nrf54l15/cpuapp 或 bl54l15_dvk/nrf54l15/cpuflpr。

  • stm32h573i_dk 和 b_u585i_iot02a 开发板的默认 MCUboot 签名类型已从 RSA-3072 改为 EC-P256。这会影响在 TF-M 中启用了 MCUboot 的构建（CONFIG_TFM_BL2）。如果希望继续使用 RSA-3072，需要将 CONFIG_TFM_MCUBOOT_SIGNATURE_TYPE 设置为 "RSA-3072"。否则，请确保拥有所用签名类型的自有签名密钥。

  • Kconfig 选项 CONFIG_LPADC_CHANNEL_COUNT 已被移除。NXP LPADC 驱动现在将硬件命令槽视为逻辑 ADC 通道，并根据设备树中为每个实例声明的 channel 子节点推导出该实例的逻辑通道数，因此未使用的命令槽不再占用 RAM。以前为了节省 RAM 而调低该 Kconfig 选项的应用程序，只需删除该选项即可。未声明任何 channel 节点的实例会保留全部硬件容量可用，因此只在运行时通过 adc_channel_setup() 配置通道的应用程序不受影响；两种方式混用的应用程序，必须在设备树中声明其在运行时配置的最大通道标识符。声明的通道标识符超出 SoC 实现的 CMD 寄存器数量时，现在会产生构建错误，而不是运行时的 HAL 断言；并且 adc_read() 现在会以 -EINVAL 拒绝空的通道掩码或选择了超出该限制的通道的掩码，而不是静默忽略（GitHub #116995）。

Analog Devices

  • 现在，所有 MAX32 SoC 的 CONFIG_NUM_IRQS 都会使用 Kconfig 预处理器函数 dt_highest_controller_irq_number，根据设备树中处于活动状态（status = "okay";）的设备自动计算。按 SoC 硬编码的值已被移除，得到的 IRQ 表通常比以前小得多。由于 CONFIG_NUM_IRQS 的值变小，注册自定义 ISR（使用 IRQ_CONNECT()）的应用程序可能会遇到如下构建失败：

    gen_isr_tables.py: error: IRQ 88 (offset=0) exceeds the maximum of 54

    显式将 CONFIG_NUM_IRQS 设置为合适的值即可解决这些问题。（此文档页面 介绍了具体做法）

    在运行时使用 irq_connect_dynamic() 安装 ISR 的应用程序不在此构建时检查的覆盖范围内，必须手动检查。

&hfclk {
    status = "okay";

/* if nRF52, nRF53, nRF91 or nRF54L LFCLK is to be controlled */
&lfclk {
    status = "okay";
};

/* if HFCLK192M is to be controlled */
&hfclk192m {
    status = "okay";
};

/* if XO24M is to be controlled */
&xo24m {
    status = "okay";
};

/* if HFCLKAUDIO is to be controlled */
&hfclkaudio {
    status = "okay";
};

    • 将 CONFIG_NRFX_CLOCK_LF_CAL_ENABLED 替换为 CONFIG_CLOCK_CONTROL_NRF_K32SRC_RC_CALIBRATION。

    • 将 CONFIG_CLOCK_CONTROL_NRF_K32SRC_FREQUENCY 替换为 k32src-frequency 属性。

    • 将 CONFIG_CLOCK_CONTROL_NRF_SOURCE 选择项替换为 k32src 枚举属性。

    • 将 CONFIG_CLOCK_CONTROL_NRF_K32SRC_XTAL 和 CONFIG_NRFX_CLOCK_LF_SRC_XTAL 替换为 k32src = "xtal"。

    • 将 CONFIG_CLOCK_CONTROL_NRF_K32SRC_SYNTH 和 CONFIG_NRFX_CLOCK_LF_SRC_SYNTH 替换为 k32src = "synth"。

    • 将 CONFIG_CLOCK_CONTROL_NRF_K32SRC_EXT_LOW_SWING 和 CONFIG_NRFX_CLOCK_LF_SRC_LOW_SWING 替换为 k32src = "ext_low_swing"。

    • 将 CONFIG_CLOCK_CONTROL_NRF_K32SRC_EXT_FULL_SWING 和 CONFIG_NRFX_CLOCK_LF_SRC_FULL_SWING 替换为 k32src = "ext_full_swing"。

    • 将 CONFIG_CLOCK_CONTROL_NRF_ACCURACY_PPM 选择项替换为 k32src-accuracy-ppm 枚举属性。

    • 将 CONFIG_CLOCK_CONTROL_NRF_K32SRC_500PPM 替换为 k32src-accuracy-ppm = <500>。

    更新 API 调用时，请使用以下对应关系：

    • mgr 是为 nordic,nrf-clock 创建、并通过 z_nrf_clock_control_get_onoff 获取的开关（on-off）管理器。

    • dev 是与 nordic,nrf-clock 兼容的设备。

    • sys 是 nordic,nrf-clock 的子系统。

      新的时钟实现不使用它。

    • new_dev 是与之前所用 sys 值对应的设备。它必须与以下节点之一兼容：

      • nordic,nrf-clock-lfclk

      • nordic,nrf-clock-hfclk

      • nordic,nrf-clock-xo

      • nordic,nrf-clock-hfclk192m

      • nordic,nrf-clock-xo24m

      • nordic,nrf-clock-hfclkaudio

onoff_cancel_or_release(mgr, &cli);     //4

clock_control_off(dev,sys)              //6
clock_control_async_on(dev,sys)         //7
clock_control_get_status(dev,sys)       //8
z_nrf_clock_control_get_onoff(sys)      //9

// New API usage
z_nrf_clock_calibration_init();                             //1
nrf_clock_control_release(new_dev, NULL);                   //2
nrf_clock_control_request(new_dev, NULL, &cli);             //3
nrf_clock_control_cancel_or_release(new_dev, NULL, &cli);   //4
clock_control_on(new_dev, NULL)                             //5
clock_control_off(new_dev, NULL)                            //6
clock_control_async_on(new_dev, NULL)                       //7
clock_control_get_status(new_dev, NULL)                     //8
// Remove all uses of z_nrf_clock_control_get_onoff         //9

  • CAN 控制器驱动操作中不再包含 can_set_state_change_callback_t 函数指针，因为回调的添加和移除现在由通用 API 函数 can_add_state_change_callback() 和 can_remove_state_change_callback() 处理。树外驱动可以根据需要完全删除该驱动操作，或将其替换为 can_state_change_callbacks_enabled_t。驱动现在必须使用 can_fire_state_change_callbacks() 来触发 CAN 控制器状态变化回调（GitHub #117889）。

  • CAN 总线网络驱动（CONFIG_NET_CANBUS）现在为每个使用 CAN_DEVICE_DT_DEFINE 或 CAN_DEVICE_DT_INST_DEFINE 定义的 CAN 控制器设备定义一个网络接口，而不是只为 zephyr,canbus chosen 节点定义一个。

计数器

  • nxp,lpc-ctimer 现在通过通用的 mux 子系统路由其输入捕获信号。inputmux-connections 属性已被移除；请改为使用 INPUTMUX 控制器节点（nxp,inputmux）描述路由，并在定时器节点的 mux-states 属性中引用它。单元格布局不变，因此现有的 inputmux-connections = <&inputmux0 0 0x06000024>; 改为 mux-states = <&inputmux0 0 0x06000024>; 即可（GitHub #112088）

  • nxp,lptmr 的 prescaler 属性已被移除。请改用 prescale-glitch-filter 和 prescale-glitch-filter-bypass。新属性是指数而不是除数：预分频器的分频系数为 2^(prescale-glitch-filter + 1)。

  • adi,max32-rtc-counter 和 adi,max32-wut 现在使用共享的 clk_32k 节点选择 32 kHz 时钟源。时钟源现在通过 clk_32k 节点的 clocks 属性配置，而不再通过各外设节点中的 clock-source 属性配置（GitHub #117709）。

  • NXP RTC 计数器驱动（nxp,rtc、nxp,lpc-rtc 和 nxp,imx-snvs-rtc）在设置的绝对闹钟为时已晚时，counter_set_channel_alarm() 现在返回 -ETIME 而不是 -EINVAL，与计数器 API 的约定一致。在绝对闹钟过晚的处理路径上检查 -EINVAL 的应用程序，必须改为检查 -ETIME。绝对目标值等于当前计数值时，现在也会报告为过晚（-ETIME），并且过晚检查不再适用于相对闹钟。

  • CONFIG_NVME_REQUEST_TIMEOUT 的文档说明和取值范围都以秒为单位。NVMe 请求超时路径以前未经换算就将该值与 k_uptime_get_32() 的毫秒值比较，因此默认值 5 大约在 5 ms 后就会超时，而不是 5 秒。驱动现在会在调度和超时检查之前用 MSEC_PER_SEC 进行换算。如果应用程序依赖以前的短超时行为，请检查所有非默认设置。（GitHub #117809）

显示

  • 用于选择 SDL 显示像素格式的 Kconfig 选项 CONFIG_SDL_DISPLAY_DEFAULT_PIXEL_FORMAT_* 已被移除，改为使用 include/zephyr/dt-bindings/display/panel.h 中的 PANEL_PIXEL_FORMAT_* 宏，直接在设备树中的 SDL 伪设备节点上设置 pixel-format 属性。（GitHub #104099）

  • LVGL 的 Kconfig 选项 CONFIG_LV_Z_COLOR_24_BGR_TO_RGB 已被移除。LVGL 的 RGB888 颜色格式在内存中按蓝、绿、红的顺序存储字节，与 PIXEL_FORMAT_RGB_888 的内存布局一致，因此对于报告该格式的显示器不会进行通道交换。帧缓冲区要求红、绿、蓝字节顺序的显示器，现在必须报告 PIXEL_FORMAT_BGR_888，LVGL 适配层会针对该格式自动交换红、蓝通道。

  • 对于报告 PIXEL_FORMAT_RGB_565X 的显示器，LVGL 现在直接以其 RGB565_SWAPPED 颜色格式渲染，因此这些显示器不再需要 CONFIG_LV_COLOR_16_SWAP，并且不得在使用该像素格式的同时启用它，否则缓冲区最终会被字节交换两次。t_deck、m5stack_core2 和 wio_terminal 开发板不再默认启用该选项。

  • 用于 ST7305 和 ST7306 显示器的 Kconfig 选项 CONFIG_ST730X_POWERMODE_LOW 已被移除，改为在设备节点上切换 low-power-mode 属性。

  • ST7567 显示驱动的 set_contrast 函数现在接受 0-255 范围内的对比度值，而不是 0-63。驱动现在会将该值缩放到控制器所需的 6 位范围。Kconfig 选项 CONFIG_ST7567_DEFAULT_CONTRAST 已更新以反映新的范围。（GitHub #112528）

  • raspberrypi,bcm2711-framebuffer 现在要求提供 pixel-format 属性，并新增可选的布尔属性 red-blue-swap，用于表示面板要求 BGR 通道顺序。依赖固件协商像素顺序来纠正通道交换的开发板，也必须设置 red-blue-swap。（GitHub #115633）

  • chipone,co5300 MIPI DSI 显示驱动不再维护内部影子帧缓冲区，并且 pitch-align、addr-align 和 ext-ram 设备树属性已从 chipone,co5300 绑定中移除。以前依赖这些属性来满足显示控制器对齐要求的开发板，应改为启用 CONFIG_LV_Z_AREA_X_ALIGNMENT_WIDTH 和 CONFIG_LV_Z_AREA_Y_ALIGNMENT_WIDTH（LVGL），使失效区域在到达驱动之前就按所需边界取整。（GitHub #117765）

  • ssd16xx 显示驱动现在报告 PIXEL_FORMAT_MONO01，而不是 PIXEL_FORMAT_MONO10，这与控制器 RAM 一致：在其中，置位的比特表示白色像素。LVGL 和字符帧缓冲区无需任何修改即可以预期的颜色绘制。向 display_write() 传入自有缓冲区、并为补偿旧像素格式而对其取反的应用程序，必须去掉该取反操作。

ESPI

  • ECUSTOM_HOST_SUBS_INTERRUPT_EN 已弃用，改用新的 API，该 API 可以对各个 eSPI 硬件中断进行细粒度的启用和禁用控制。它取代了当前“全有或全无”的方式，后者在所有 eSPI 驱动中都与 CONFIG_ESPI_PERIPHERAL_CUSTOM_OPCODE 以及单个 eSPI ACPI 硬件模块实例紧密耦合。为了留出过渡时间，它将在下一个 Zephyr 版本中被彻底移除。

  • Microchip XEC eSPI v2 驱动（microchip,xec-espi-v2）已从 MEC172x 移植扩展，现在还支持 MEC174x、MEC175x 和 MEC165xB。这需要进行若干设备树修改，会影响使用此绑定的树外开发板（GitHub #109519）：

    • pcrs 属性已被 pcr-scr 取代，后者现在是一个用辅助宏 MCHP_XEC_SCR_ENCODE(reg, bit) 编码的单个整数，而不是 <reg bit> 单元格对。请将现有覆盖文件中的 pcrs = <2 19>; 更新为 pcr-scr = <MCHP_XEC_SCR_ENCODE(2, 19)>;。

    • 仅在 MEC174x/5x/165xB 上，girqs 单元格现在每个条目是一个由 MCHP_XEC_ECIA_GIRQ_ENC(reg, bit) 生成的单个整数，而不是 <reg bit> 对。MEC172x 继续使用现有的 MCHP_XEC_ECIA(...) 形式。

    • 对于地址空间超过 32 位的主机，eSPI 控制器节点新增了两个可选属性：host-memmap-addr-high（内存映射逻辑设备的主机地址位 [47:32]）和 sram-bar-addr-high（两个 SRAM BAR 的主机地址位 [47:32]）。

    • 为保持一致，eSPI 控制器及其主机设备子节点的 interrupt-names 已重命名。请相应地更新覆盖文件：

      • 控制器：rst → erst；vwct_0_6 / vwct_7_10 → ht_vw_bank0 / ht_vw_bank1。必须在 interrupts 数组中添加两个对应的中断（ht_vw_bank0 / ht_vw_bank1）。

      • KBC 子节点：kbc_obe / kbc_ibf → obe / ibf。

      • ACPI EC 子节点：acpi_ibf / acpi_obe → ibf / obe。

    • 在 MEC5 SoC DTSI（MEC174x/5x/165xB）中，eSPI 控制器的每个主机设备子节点（邮箱、KBC、ACPI EC、ACPI PM1、port92、glue、EMI、BIOS 调试端口等）现在都声明了 microchip,xec-espi-host-dev 所要求的 ldn（逻辑设备号）属性。为这些 SoC 覆盖或添加主机设备子节点的树外开发板，必须为每个子节点设置 ldn。

  • Enhanced Serial Peripheral Interface (eSPI) 示例中开发板电源节点的 compatible 已从 intel-rvp,board-power 重命名为 intel,rvp-board-power。用于该示例的树外开发板覆盖文件必须使用新的 compatible。

HWSPINLOCK

  • num-locks 设备树属性现在是 hwspinlock 控制器绑定中的标准必需属性。每个 hwspinlock 控制器节点都必须设置该属性，树外绑定必须删除其自身对 num-locks 的 type/required 声明。

  • hw_spin_lock()、hw_spin_trylock() 和 hw_spin_unlock() 不再接受 hwspinlock_ctx_t * 参数；每个锁对应的 Zephyr 自旋锁现在位于驱动的配置中。struct hwspinlock_context、hwspinlock_ctx_t、hwspinlock_dt_spec 的 ctx 成员以及 HWSPINLOCK_CTX_INITIALIZER 已被移除。辅助函数 hw_spin_lock_dt()、hw_spin_trylock_dt() 和 hw_spin_unlock_dt() 保持不变。因此，所有引用同一个硬件自旋锁的 HWSPINLOCK_DT_SPEC_GET 实例现在共享同一个 Zephyr 自旋锁，而不再各自拥有一个。

  • 硬件自旋锁驱动现在必须将 hwspinlock_driver_config 作为其配置结构体的第一个成员嵌入，使用 HWSPINLOCK_COMMON_CONFIG_FROM_DT_INST（或 HWSPINLOCK_COMMON_CONFIG_FROM_DT_NODE）初始化它，并使用 HWSPINLOCK_SPINLOCK_ARRAY_DT_INST_DEFINE（或 HWSPINLOCK_SPINLOCK_ARRAY_DT_DEFINE）声明底层的自旋锁数组。get_max_id 驱动操作现在是可选的：未实现时，hw_spinlock_get_max_id() 的默认实现返回 num-locks 设备树属性的值减 1。

I2C

  • 在基于 CONFIG_I2C_DW 的控制器上，CONFIG_I2C_DW_RW_TIMEOUT_MS 选项已被 CONFIG_I2C_TRANSFER_TIMEOUT_MS 取代，默认值为 500ms。

  • ITE I2C 控制器 ite,enhance-i2c、ite,it51xxx-i2c、ite,it8xxx2-i2c 的传输超时现在使用通用的 zephyr,transfer-timeout-ms 属性，而不是 transfer-timeout-ms，默认值为 500ms。

  • nxp,sc18im704-i2c 桥接器不再将未移位的目标地址发送给 SC18IM704。Zephyr I2C API 会向控制器的 transfer() 回调传递 7 位地址，驱动现在会将其左移一位，以构造桥接器所需的地址字节。位于 nxp,sc18im704-i2c 总线上、并通过声明预先移位的 reg 来弥补缺失移位的设备树节点（例如为地址 0x50 的设备声明 reg = <0xa0>），现在必须声明真实的 7 位地址（reg = <0x50>）。

I2S

  • i2s_buf_write() 现在在分配发送块时会遵循流配置中的 timeout。以前它会无限等待，因此文档中所述的 -EAGAIN 返回值永远不会出现，在多线程构建中 -ENOMEM 同样不会出现。依赖无限等待的调用者可以将 timeout 设置为 SYS_FOREVER_MS，但同一字段也限制驱动的入队等待时间，因此没有任何单一取值能重现以前“分配无限等待、入队有限等待”的组合。

IEEE 802.15.4

  • 自 Zephyr 3.6 起弃用的无线电能力 IEEE802154_HW_SLEEP_TO_TX 已被移除，位于其后的能力位已重新编号。所有树内驱动都支持直接从低功耗状态发送，因此该能力不传达任何信息；OpenThread 平台现在总是声明 OT_RADIO_CAPS_SLEEP_TO_TX，并允许从睡眠状态发送。声明该能力的树外驱动只需将其删除即可。

输入

  • gpio-keys 的 no-disconnect 属性已被枚举属性 zephyr,suspend-action 取代。新属性目前有三个取值，其中两个直接对应原来的两种情况：

    • zephyr,suspend-action = "none"; 用于替代存在 no-disconnect 时的行为。使用 no-disconnect 属性的用户应将其替换为 zephyr,suspend-action = "none";。

    • zephyr,suspend-action = "disconnect-with-pupd"; 用于替代不存在 no-disconnect 时的行为。为与以前的行为保持向后兼容，默认选择该值。

    • zephyr,suspend-action = "full-disconnect"; 是新增的取值。（详情请参阅 the binding）

    建议使用默认配置的用户重新考虑该配置是否真正合适；推荐迁移到 zephyr,suspend-action = "full-disconnect";。（GitHub #108294）

  • ft6146、ft5336 和 cst8xx 输入驱动的 Kconfig 选项已重命名，以与其他输入驱动保持一致。使用以下 Kconfig 选项的应用程序必须相应地更新其配置：

    • CONFIG_INPUT_FT5336_PERIOD → CONFIG_INPUT_FT5336_PERIOD_MS

    • CONFIG_INPUT_CST8XX_PERIOD → CONFIG_INPUT_CST8XX_PERIOD_MS

    • CONFIG_INPUT_FT6146_PERIOD → CONFIG_INPUT_FT6146_PERIOD_MS

    • Nunchuk 驱动以前在按键事件中错误地分别报告 INPUT_KEY_Z 和 INPUT_KEY_C。此问题已修复，现在分别使用 INPUT_BTN_Z 和 INPUT_BTN_C。

中断控制器

  • 所有中断控制器绑定现在都使用 flags 而不是 sense 作为中断单元格名称。以下中断控制器绑定已更新：

    • intel,ioapic

    • intel,loapic

    • cdns,xtensa-core-intc

    • intel,ace-intc

    • intel,cavs-intc

    • snps,designware-intc

    • mediatek,adsp_intc

    使用这些中断控制器的驱动已更新为使用 flags 作为单元格名称。但是，任何使用 DT_INST_IRQ(n, sense) 或 DT_IRQ(node, sense) 直接访问中断属性的树外驱动，都应更新为使用 flags 而不是 sense。

  • GIC 头文件 gic.h 中的 GIC_NUM_CPU_IF 已弃用。应改用:kconfig:option:CONFIG_MP_MAX_NUM_CPUS。

MBOX

  • renesas,rz-mhu-mbox 驱动已重新设计，使单个 MHU 单元在一个 MBOX 通道上同时处理发送和接收，而不再将每个通道专用于一个方向。单个驱动实例现在可以拥有多个通道。使用此 compatible 的设备树节点必须更新：

    • channel 已重命名为 unit，因为它索引的是底层 MHU 硬件单元，而不是 MBOX 通道。这两种编号方式相互独立。

    • tx-mask 和 rx-mask 已被单个 channel-mask 取代，它是有效 MBOX 通道的位掩码，其中第 n 位启用通道 n。

    • channels-count 必须与节点上 interrupt-names 条目的数量一致。现在会在构建时强制检查这一点。

    • shared-memory 现在是可选的，在大多数情况下应保持不设置。共享内存改为由一个名为 mhu_shmem 的 zephyr,memory-region 节点提供，该节点取代了每个单元各自的 mmio-sram 节点，并使链接器为 FSP MHU 驱动生成 __mhu_shmem_start。缺少此内存区域的开发板会因对该符号的未定义引用而链接失败。

    例如：

    /* Before */
mhu3_shm: memory@62f01018 {
        compatible = "mmio-sram";
        reg = <0x62f01018 0x8>;
};

mbox3: mhu@40400060 {
        channel = <3>;
        tx-mask = <0x00000002>;
        rx-mask = <0x00000001>;
        shared-memory = <&mhu3_shm>;
};

/* After */
mhu_shmem: memory-region@62f01000 {
        compatible = "zephyr,memory-region";
        reg = <0x62f01000 0x1000>;
        zephyr,memory-region = "mhu_shmem";
};

mbox3: mhu@40400060 {
        unit = <3>;
        channel-mask = <0x1>;
};

MSPI

  • STM32 外部串行存储器支持正在从旧的 QSPI、OSPI 和 XSPI Flash 及 RAM 驱动迁移到相互独立的 MSPI 控制器驱动和存储设备驱动。新驱动提供了更灵活的模型，支持在单个控制器上挂接多个存储设备，并为所有外部串行存储器（包括 NOR Flash 和外部 RAM）提供分层清晰的统一接口。

    该迁移在 Zephyr 4.5 中仍在进行，计划在下一个版本中完成。在该版本中，旧的、STM32 控制器专用的外部 Flash 和 RAM 驱动模型将被正式弃用，改用 MSPI。

    面向应用程序的 API 保持不变。该迁移只在受影响的开发板上将设备树绑定和 Kconfig 选项改为使用 MSPI 模型。SoC 设备树描述在 Zephyr 4.5 中保持不变，将在下一个版本中更新。旧驱动对尚未迁移的开发板仍然可用。

    这不仅仅是 Kconfig 的修改。树外开发板和覆盖文件可以在下一个版本之前提前迁移，方法是同时更新控制器节点及其存储设备子节点：

    • 根据情况，将 st,stm32-xspi 替换为 st,stm32-xspi-controller，将 st,stm32-ospi 替换为 st,stm32-ospi-controller，或将 st,stm32-qspi 替换为 st,stm32-qspi-controller。将 op-mode 设置为 "MSPI_OP_MODE_CONTROLLER"，并在控制器上提供 clock-frequency。保留所需的时钟、引脚控制、DMA 和端口路由配置。

    • 将旧的 NOR 子节点 compatible 替换为 jedec,nor 以及适用的厂商专用 compatible。对于使用 st,nor 的设备，还需提供必需的 st,mem-type 属性。

    • 在适用的情况下，将 ospi-max-frequency 或 qspi-max-frequency 重命名为 mspi-max-frequency，将 spi-bus-width 重命名为 mspi-io-mode，将 data-rate 重命名为 mspi-data-rate。MSPI 模式和数据速率属性接受 "MSPI_IO_MODE_OCTAL" 和 "MSPI_DATA_RATE_DUAL" 这样的字符串值，而不是旧的数值常量。

    • 在适用的情况下，为所选协议配置存储器的命令操作码、命令长度、空周期和寻址模式。旧的 four-byte-opcodes 属性不属于 MSPI NOR 绑定；请改用新绑定的寻址和命令配置。

    • 保留应用程序覆盖文件和 chosen 节点所引用的 Flash 区域和分区标签，并保留相应的内存映射。更新引用旧节点名称或控制器专用属性的覆盖文件。

    • 对于内存映射配置，请启用 CONFIG_MSPI_MEMMAP 并配置设备的 memmap-config 属性。

  • st,stm32-adc 绑定已重构，以反映 ADC 硬件拓扑。父节点现在表示 ADC 公共块（common block），它持有时钟以及连接到它的所有 ADC 实例共享的设置，而新的 child-binding 表示 ADC 实例本身。

    现有的 &adcN 节点标签仍然指代 ADC 实例，这些实例现在是标签为 &adcN_common 的公共块节点的子节点，其中 N 列出共享该块的实例（例如 &adc1_common、&adc12_common 或 &adc123_common）。除实例节点外，还必须启用公共块节点。

    &adc1 {

           <&rcc STM32_SRC_SYSCLK ADC_SEL(3)>;
  clock-names = "adcx", "adc_ker";
  st,adc-clock-source = "ASYNC";
  st,adc-prescaler = <4>;
  vref-mv = <3000>;
  pinctrl-0 = <&adc1_in1_pa0>;
  pinctrl-names = "default";
  status = "okay";
};

    &adc12_common {
  clocks = <&rcc STM32_CLOCK(AHB2, 13)>,
           <&rcc STM32_SRC_SYSCLK ADC_SEL(3)>;
  clock-names = "adcx", "adc_ker";
  st,adc-clock-source = "ASYNC";
  st,adc-prescaler = <4>;
  vref-mv = <3000>;
  status = "okay";
};

&adc1 {
  pinctrl-0 = <&adc1_in1_pa0>;
  pinctrl-names = "default";
  status = "okay";
};

    px0 是占位符，应替换为实际的引脚名称（例如 pa1）。

    STM32H5Ex/STM32H5Fx 产品线的 SoC 不受此更改影响，因为它们自加入 Zephyr 以来一直使用新名称。

存储

  • flash_sector 的 fs_off 成员的类型已从 off_t 改为 ptrdiff_t。这样所有平台和工具链都会使用本机寄存器宽度，而不会随 C 库继承的 POSIX off_t 类型而变化。Picolibc 1.8.12 总是将 off_t 定义为 64 位整数，即使在 32 位平台上也是如此；使用该 C 库时，此更改实际上让该结构体恢复到以前的布局。对于较旧的 Picolibc 版本以及所有其他受支持的 C 库，ptrdiff_t 与 off_t 使用相同的底层 C 类型；此更改旨在使 fs_off 使用的底层 C 类型在 Picolibc 更新前后保持不变。

Syscon

  • syscon API 函数 syscon_read_reg() 和 syscon_write_reg() 的寄存器偏移参数现在使用 uint32_t 而不是 uint16_t，从而支持更大的寄存器偏移。显式为寄存器参数声明 uint16_t 变量的代码，或实现 syscon 驱动 API 函数的代码，可能需要更新。

定时器

  • sys_clock_set_timeout()、sys_clock_announce() 和 sys_clock_announce_locked() 的节拍数参数现在使用无符号的 uint32_t，而不是有符号的 int32_t。树外系统定时器驱动必须相应地更新其 sys_clock_set_timeout() 定义，否则构建会因类型冲突错误而失败。内核现在还会将请求的超时限制在 SYS_CLOCK_MAX_WAIT 以内，并且不再向驱动传递 K_TICKS_FOREVER，因此这类驱动不再需要按 sys_clock_announce() 的范围限制请求值，也不再需要特殊处理 K_TICKS_FOREVER；只需继续遵守其自身硬件周期计数的限制（GitHub #111022）。

  • sys_clock_set_timeout() 的 bool idle 参数已弃用。内核现在调用新的 sys_clock_idle_enter() 钩子，而不是以 idle=true 调用 sys_clock_set_timeout()。为保持向后兼容，sys_clock_idle_enter() 的默认实现会以 idle=true 调用 sys_clock_set_timeout() 来模拟旧行为，因此仍然检查 idle 的定时器驱动无需修改即可继续工作。这类驱动应当更新为实现 sys_clock_idle_enter()，并将其特定于 idle 的处理移到该函数中。该参数将在未来的版本中移除（GitHub #115844）。

  • 启用 CONFIG_SYSTEM_CLOCK_SLOPPY_IDLE 时，内核在没有待处理超时的情况下，现在会调用新的 sys_clock_no_timeout() 钩子，而不是以 ticks=K_TICKS_FOREVER 调用 sys_clock_set_timeout()。为保持向后兼容，sys_clock_no_timeout() 的默认实现会以 ticks=UINT32_MAX（数值上与前者相同）调用 sys_clock_set_timeout()，因此将该值视为“无截止时间”信号的驱动无需修改即可继续工作，无论它们是停止时钟还是设置最大等待时间。这类驱动应当更新为实现 sys_clock_no_timeout()。

    注意这两个新钩子之间的分工。在 CPU 仍在运行时屏蔽唤醒应放在 sys_clock_no_timeout() 中，并且该函数必须保证 sys_clock_cycle_get_32() 仍能正常工作。停止时基则应在 sys_clock_idle_enter() 收到 SYS_CLOCK_IDLE_FOREVER 时进行。确切语义请参阅 系统定时器驱动文档（GitHub #115844）。

  • 无节拍系统定时器驱动不应再自行处理节拍。实现头文件 drivers/timer/system_timer_generic.h 现在负责以前每个驱动都要手工重新实现、而且常常有细微错误的计数逻辑：周期到节拍的转换、announce 基准、按节拍对齐的截止时间计算以及计数器范围限制，包括窄位宽计数器的回绕处理。驱动只需提供少量周期域原语，即读取周期计数器和设置绝对比较值，并包含一次该头文件，该头文件会生成 sys_clock_set_timeout()、sys_clock_elapsed() 以及 sys_clock_cycle_get_32() / sys_clock_cycle_get_64()（GitHub #115844）。

  • 启用 SYSTEM_TIMER_LPM_COMPANION_COUNTER 时，会在构建时检查由 通用 chosen 节点 zephyr,system-timer-companion 选择的低功耗伴随（Low-Power Companion）计数器，该计数器必须能够用作唤醒源。如果这类节点尚未包含 wakeup-source 属性，应当添加该属性，以表明它们可以用作唤醒源。（GitHub #117274）

    这样，初始化在没有主机的构建中也会运行，而在这种构建中 setup() 从未被调用。有主机时，初始化在调用 bt_enable() 的线程中、在该函数返回之前运行，即使传入了就绪回调也是如此；而在这种情况下 setup() 是在系统工作队列中运行的。这一点适用于所有曾实现 setup() 的树内驱动，因为它们都已完成转换。

  • HCI 驱动的 bt_hci_driver_api.open 回调不再有 recv 参数；改由公共 HCI 驱动层代码将其作为公共数据结构体的一部分进行管理。新增了 bt_hci_recv() API，供驱动将数据传递给上层（例如 Bluetooth 主机协议栈）。对于需要获取 recv() 返回的任何错误的驱动（大多数驱动不需要），还新增了 bt_hci_recv_err() API，在出错的情况下由调用者负责释放缓冲区的引用。

  • CONFIG_BT_HCI_SET_PUBLIC_ADDR 不再选择 CONFIG_BT_HCI_SETUP。在其 setup() 实现中应用公共地址的树外 HCI 驱动，现在必须自行选择 CONFIG_BT_HCI_SETUP；否则 bt_hci_driver_api 中不存在 setup 成员，该回调也不会被调用。现在从传输层打开时起，就可以通过 bt_hci_get_public_addr() 获取该地址，因此驱动也可以改为在 open() 期间应用它。

  • HCI 驱动 API 现在记录了其生命周期约定。对于其使用者：不能针对同一设备并发调用 bt_hci_open()、bt_hci_close() 和 bt_hci_send()，bt_hci_send() 只在传输层已打开时有效，并且不会在接收回调中调用 bt_hci_close()。对于驱动：open() 失败后传输层保持关闭，且之后不会调用 close()；close() 失败后传输层保持打开；close() 成功后不再调用接收回调；除 setup() 以外的驱动操作不使用主机的 HCI 命令 API。树外 HCI 驱动以及直接调用 HCI 驱动 API 的树外代码，可能需要修改以遵守这些规则。

  • H:4 厂商扩展改为在 bt_h4_vnd_open()（声明于 include/zephyr/drivers/bluetooth/h4.h）中配置其控制器，而不是在 bt_h4_vnd_setup() 和 setup() 操作中配置；H:4 驱动会在其 open() 末尾调用该函数，并传入用于该扩展命令的 lockstep 辅助对象。该扩展选择 CONFIG_BT_H4_VND_OPEN 来代替 CONFIG_BT_HCI_SETUP，并使用 bt_hci_get_public_addr() 读取公共地址，而不是从 setup 参数中获取。对于仍然选择 CONFIG_BT_HCI_SETUP 的扩展，bt_h4_vnd_setup() 仍会通过 setup() 操作被调用。

Bluetooth 主机（Host）

  • 当连接参数更新失败时（即 LE Connection Update Complete 事件报告非零状态），bt_conn_cb 中的 le_param_updated 回调不再被调用。以前该回调会被无条件调用，报告未改变的连接参数且没有任何错误指示，因此无法与成功的更新区分开。需要在应用程序发起的参数更新被拒绝时收到通知的应用程序，应当启用 CONFIG_BT_USER_CONN_PARAM_REJECTED 并实现新的 le_param_update_rejected 回调。

  • CONFIG_BT_RECV_CONTEXT Kconfig choice 及其选项 CONFIG_BT_RECV_WORKQ_SYS 和 CONFIG_BT_RECV_WORKQ_BT 已被移除。主机现在无条件地在专用的 Bluetooth RX 工作队列上处理低优先级 HCI 数据包（即以前 CONFIG_BT_RECV_WORKQ_BT 的行为）。为节省 RAM（例如在 nRF51 上）而选择了 CONFIG_BT_RECV_WORKQ_SYS 的应用程序必须去掉该选项；现在总会创建专用的 RX 线程。请根据应用程序启用的主机功能调整 CONFIG_BT_RX_STACK_SIZE（RX 线程栈）。由于低优先级 RX 不再在系统工作队列上运行，应用程序或许可以减小 CONFIG_SYSTEM_WORKQUEUE_STACK_SIZE，但这两个栈大小都与具体应用程序相关，应当通过栈使用量测量进行验证。

  • 启用 CONFIG_BT_GATT_AUTO_READ_CENTRAL_ADDR_RES 时（在可能的情况下默认启用），主机会在创建绑定时读取一次已绑定对端的 Central Address Resolution 特征；并且当对已知不支持地址解析的对端使用 BT_LE_ADV_OPT_DIR_ADDR_RPA 时，bt_le_adv_start()、bt_le_ext_adv_create() 和 bt_le_ext_adv_update_param() 现在会失败并返回 -ENOTSUP。这样的对端无法解析目标地址，因此永远不会响应该广播。需要提前得知结果的应用程序可以通过 bt_le_bond_addr_res_support() 读取相同的结果，并改为向这些对端的身份地址发送定向广播。禁用该选项可恢复以前的行为。

  • 部分 Bluetooth 主机工作项现在在专用的 Bluetooth RX 工作队列而不是系统工作队列上运行。因此，由这些工作项触发的应用程序回调会在 Bluetooth RX 线程中运行。这包括连接拆除和延迟的连接工作（例如 disconnected() 连接回调和 SMP 配对超时），以及 ATT/GATT、L2CAP、AVDTP 和 HFP AG 中的超时和完成路径。依赖这些回调在系统工作队列中运行的应用程序应当检查其同步机制和回调栈需求。详情请参阅 PR GitHub #93033。

  • CONFIG_BT_AUTO_PHY_UPDATE 已被移除。请改用按角色区分的 BT_AUTO_PHY_CENTRAL 和 BT_AUTO_PHY_PERIPHERAL choice。=n 不能简单地转换为删除该选项：central 的 choice 默认值为 CONFIG_BT_AUTO_PHY_CENTRAL_2M，因此必须将两个角色都显式设置为 _NONE。

  • 已弃用的 CONFIG_BT_CONN_TX_MAX Kconfig 选项已被移除。它自 Zephyr 4.2 起就已弃用，带回调的待发送 TX 缓冲区数量始终跟随 CONFIG_BT_BUF_ACL_TX_COUNT。

  • 由于 SID 只对扩展广播集有效，对于传统广播集，bt_le_ext_adv_info.sid 现在会被设置为 BT_GAP_SID_INVALID。应用程序不应期望 bt_le_adv_param.sid 会应用于传统广播集。

  • bt_le_ext_adv_info.sid 现在反映传给 bt_le_ext_adv_update_param() 的 SID。以前即使控制器已应用新值，它仍保留 bt_le_ext_adv_create() 中的值。

  • bt_addr_le_to_str() 现在使用单字符类型前缀格式化 LE 地址，P: 表示公共地址，R: 表示随机地址，后面直接跟地址，例如 R:11:22:33:44:55:66。不再生成以前的 11:22:33:44:55:66 (random) 形式；带有额外 HCI 层级位的地址类型（例如 BT_ADDR_LE_RANDOM_ID）会按其基本类型格式化，而不是显示为 (random-id) 或原始十六进制值。通过解析 Zephyr 日志或 shell 输出来提取地址的代码必须更新。BT_ADDR_LE_STR_LEN 也相应地从 30 缩小为 20。

  • bt_addr_le_from_str() 不再接受单独的地址类型字符串。它只接受 bt_addr_le_to_str() 生成的带 P:/R: 前缀的格式；不再支持以前的 "XX:XX:XX:XX:XX:XX" + "public"/"random" 形式。因此，所有接受 LE 地址的 Bluetooth shell 命令（例如 bt connect、bt disconnect、bt clear、bt fal-add、bt per-adv-sync-create、gatt resubscribe 和 bap_broadcast_assistant add_src）都改为接受单个 P:XX:XX:XX:XX:XX:XX 或 R:XX:XX:XX:XX:XX:XX 参数，而不是地址后跟单独的类型参数。

网络

  • HTTP 客户端响应回调（http_response_cb_t）现在可能会针对一次接收的缓冲区被调用多次，每个正文片段调用一次，例如对分块（chunked）响应的每个块调用一次。假定每次接收只调用一次回调的应用程序，必须追加处理传给它的每个片段。

  • CONFIG_NET_TEST_PROTOCOL 已被移除，它是一个 JSON 控制通道，允许树外的 TTCN-3 测试套件驱动 TCP 协议栈并读取其内部状态；同时被移除的还有 samples/net/sockets/tcp 示例，它是该选项唯一的被测系统。树内没有任何地方启用该选项，其背后的代码已有数年无法编译。使用它的测试套件也已被其作者归档。

    启用该选项还会关闭初始序列号随机化，并使 net_tcp_connect() 不等待连接建立就返回，因此启用了它的构建与未启用它的构建行为不同。

    没有替代选项，因为替代方案并不是一个选项：tests/net/conformance 下的一致性测试改为通过网络驱动未经修改的构建，其中包括一个覆盖相同范围的 TCP 测试套件。请参阅 使用 TTCN-3 进行协议一致性测试。

  • 嵌套在 dns_resolve_context 中的 struct dns_server 类型已重命名为 struct dns_server_info。C++ 类成员不能与其所在类同名，因此旧的标签导致无法在 C++ 中包含 <zephyr/net/dns_resolve.h>。没有任何字段被重命名，因此 ctx->servers[i].dns_server_addr 之类的访问不受影响；只有直接使用该类型名称的代码（例如在 CONTAINER_OF() 调用中）需要更新。

    这些选项控制各协议族的单播路由表，这些路由表用于静态路由管理、网络 shell 路由命令，以及为本地发出的流量（例如发往 VPN 的数据包）进行主机侧路由选择。这些选项本身并不启用接口之间的数据包转发。

  • Kconfig 选项 CONFIG_NET_IPV4_ROUTING 和 CONFIG_NET_IPV6_ROUTING 已重命名为 CONFIG_NET_IPV4_FORWARDING 和 CONFIG_NET_IPV6_FORWARDING。

    重命名后的选项明确表示接口之间的 IP 转发。只需要路由表查找或静态路由的应用程序应当启用 CONFIG_NET_IPV4_ROUTE 或 CONFIG_NET_IPV6_ROUTE，并保持转发禁用。充当路由器的应用程序应当同时启用路由表选项和相应的转发选项。

  • LLMNR 支持已弃用。Kconfig 选项 CONFIG_LLMNR_RESOLVER 和 CONFIG_LLMNR_RESPONDER 将在未来的版本中移除（最早为 4.7）。Microsoft 正在淘汰 LLMNR（RFC 4795），现代 Windows 默认禁用它。依赖本地名称解析的应用程序应当迁移到 mDNS（CONFIG_MDNS_RESOLVER / CONFIG_MDNS_RESPONDER）。

  • 以下 MQTT-SN 传输函数现在接受 mqtt_sn_transport，而不是 mqtt_sn_client：

    • mqtt_sn_transport.recvfrom

    • mqtt_sn_transport.poll

库

环形缓冲区

环形缓冲区 API 已重新设计，以减小 ring_buf 的大小并提高记账路径的效率。为适应这些变化，零拷贝的 claim/finish API（ring_buf_put_claim() / ring_buf_put_finish() 及其对应的 get 函数）已被不可叠加调用的 ring_buf_put_ptr() 和 ring_buf_get_ptr() 取代。

旧的 claim/finish API 仍然可用，但仅在启用 CONFIG_RING_BUFFER 时可用。新代码应当直接使用 _ptr API。

启用 CONFIG_RING_BUFFER 会选用旧版环形缓冲区头文件，这也会恢复默认头文件中没有的其他已弃用符号：整个 item API（ring_buf_item_init()、ring_buf_item_put()、ring_buf_item_get()、ring_buf_item_space_get()、RING_BUF_ITEM_DECLARE* 和 RING_BUF_ITEM_SIZEOF）以及 ring_buf_internal_reset()。仍在使用其中任何一个的树外代码会编译失败，且没有其他提示；在将代码迁移到 sys_ringq 和 _ptr API 期间，启用该选项即可恢复这些符号。

在默认（精简）构建中，ring_buf_get() 不再接受 NULL 目标来丢弃数据；只有启用 CONFIG_RING_BUFFER 时才允许传入 NULL。要在没有目标缓冲区的情况下丢弃数据，请使用 ring_buf_consume() 直接推进读索引，例如 ring_buf_consume(rb, MIN(count, ring_buf_size_get(rb)))。

先试探性写入再取消 和 回填（在提交之前修改先前写入的头部）等高级用法，现在依赖 ring_buf_put_ptr() 和 ring_buf_get_ptr() 末尾的 offset 参数。该偏移量是调用者在当前写（或读）索引之后已试探性预留的字节数，回绕由内部处理。通过传入递增的偏移量依次布置各个区域，此时实际的环形缓冲区保持不变，只有调用 ring_buf_commit()（或 ring_buf_consume()）时才推进索引。如果任何一步失败，只需不提交直接返回，这相当于以前的 ring_buf_put_finish(rb, 0) 取消操作。

例如，以下 claim/finish 代码：

int write_pkg(struct ring_buf *rb, const uint8_t *payload, size_t payload_size)
{
        struct hdr *h;
        uint8_t *ptr;
        uint32_t claim_size;

        claim_size = ring_buf_put_claim(rb, (uint8_t **)&h, sizeof(*h));
        if (claim_size < sizeof(*h)) {
                ring_buf_put_finish(rb, 0);
                return -ENOMEM;
        }

        claim_size = ring_buf_put_claim(rb, &ptr, payload_size);
        if (claim_size == 0) {
                ring_buf_put_finish(rb, 0);
                return -ENOMEM;
        }
        h->len = claim_size;
        /* ... write payload through ptr ... */
        ring_buf_put_finish(rb, sizeof(*h) + h->len);
        return h->len;
}

大致可转换为：

int write_pkg(struct ring_buf *rb, const uint8_t *payload, size_t payload_size)
{
        struct hdr *h;
        uint8_t *ptr;
        uint32_t claim_size;

        /* Reserve the header region without committing it. */
        if (ring_buf_put_ptr(rb, (uint8_t **)&h, 0) < sizeof(*h)) {
                return -ENOMEM;
        }

        /* Expose the region right after the header via a trailing offset. */
        claim_size = ring_buf_put_ptr(rb, &ptr, sizeof(*h));
        if (claim_size == 0) {
                /* Nothing was committed to rb, so the write is cancelled. */
                return -ENOMEM;
        }
        h->len = MIN(claim_size, payload_size);
        /* ... write payload through ptr ... */

        /* Publish header and payload atomically to the real buffer. */
        ring_buf_commit(rb, sizeof(*h) + h->len);
        return h->len;
}

  • 取消句柄的类型已从 struct rtio_sqe * 改为一个包含代号（generation）和池内索引的句柄，其类型定义为 rtio_sqe_handle_t。与原始指针不同，句柄可以被校验（边界 + 代号）。取消一个已经完成且其池槽位已被回收的提交，现在是安全的空操作，而不再是未定义行为。

  • rtio_sqe_cancel() 现在除句柄外还接受所属的 RTIO 上下文，以便根据该上下文的 SQE 池解析句柄：

    /* Before */

int rtio_sqe_cancel(struct rtio *r, rtio_sqe_handle_t handle);

  • rtio_sqe_cancel() 只标记其句柄所指的那个提交，绝不会涉及链或事务中的其余部分，因此要取消一条链或一个事务，就必须取消 rtio_sqe_copy_in_get_handles() 为其返回的每个句柄。取消仍然是尽力而为的：在成员被分派之前标记它确实可以阻止其执行，因为执行器在将每个成员交给其 iodev 的途中会检查该成员的状态；但如果某个成员的前驱在它被标记之前或期间完成，该成员可能已经在运行，并将运行到完成。

  • 子系统或驱动在提交后修改的运行时状态已从 rtio_sqe 移到所属的 rtio_iodev_sqe 中：内存池缓冲区绑定（以前回写到 sqe->rx.buf / sqe->rx.buf_len）、await 信号状态和延迟到期时间。iodev 不得在后续的完成步骤中重新读取 sqe->rx.buf 来找回绑定到内存池的缓冲区；再次调用 rtio_sqe_rx_buf() 会返回已绑定的缓冲区。对于内存池提交，该字段在运行时现在始终为 NULL，且没有任何编译期诊断。调用者提供的 RX 缓冲区不受影响。

    一个 Coccinelle 语义补丁可以重写这两处字段迁移：将 sqe.await.{ok,callback,userdata} 改为 rt.await.{ok,callback,userdata}，将 sqe.delay.expiry 改为 rt.delay_expiry：

    spatch --sp-file scripts/coccinelle/rtio_sqe_runtime_state.cocci \
       --macro-file scripts/coccinelle/macros.h --dir . --in-place

    内存池缓冲区无法机械地重写，因为将对 sqe.rx 的读取替换为 rtio_sqe_rx_buf() 调用时，需要驱动期望的缓冲区长度以及分配失败时的错误处理路径。MODE=report 会在自行绑定内存池缓冲区的文件中标出这些读取。通过裸 struct rtio_sqe * 访问已迁移的 await 和 delay 成员不再能够编译，需要通过 CONTAINER_OF 或传给该操作的 rtio_iodev_sqe 访问其外层封装结构体。

  • 大多数应用程序可以借助第二个 Coccinelle 语义补丁自动迁移，该补丁会修改句柄变量的类型，将 rtio_sqe_cancel(handle) 重写为 rtio_sqe_cancel(ctx, handle)（ctx 取自产生句柄的 rtio_sqe_copy_in_get_handles / sensor_stream / adc_stream 调用），并将对 RTIO_SQE_CANCELED 的读取重写为 rtio_iodev_sqe_is_canceled() 调用：

lvgl

  • LVGL 已从 v9.5 更新到 v9.6。LVGL 本身的变更请参阅 LVGL 迁移指南。

  • LVGL v9.6 弃用了 LV_COLOR_DEPTH choice，改用 LV_COLOR_FORMAT_DEFAULT choice，并且在 Zephyr 中 CONFIG_LV_COLOR_DEPTH_* 选项不再选择颜色格式。请将它们替换为 CONFIG_LV_COLOR_FORMAT_*，例如将 CONFIG_LV_COLOR_DEPTH_16=y 替换为 CONFIG_LV_COLOR_FORMAT_RGB565=y。

  • CONFIG_LV_ATTRIBUTE_MEM_ALIGN_SIZE 已被 CONFIG_LV_Z_ATTRIBUTE_MEM_ALIGN_SIZE 取代。

  • 开发板、扩展板和 SoC 不再在 Kconfig.defconfig 文件中设置 LVGL 选项，因为缺少 LVGL 模块时这些选项没有定义。它们改为设置 Zephyr 选项，由这些选项提供 LVGL 选项的默认值。树外开发板、扩展板和 SoC 需要进行以下替换：

    • 将 LV_COLOR_DEPTH choice 替换为 LV_Z_COLOR_FORMAT choice，例如将 LV_COLOR_DEPTH_16 替换为 LV_Z_COLOR_FORMAT_RGB565，

    • 将 LV_DPI_DEF 和 LV_DRAW_BUF_ALIGN 替换为 CONFIG_LV_Z_DPI_DEF 和 CONFIG_LV_Z_DRAW_BUF_ALIGN，

    • 将 LV_USE_DRAW_DMA2D 替换为 CONFIG_LV_Z_DRAW_DMA2D_DEFAULT，

    • 将 LV_USE_DRAW_DMA2D_INTERRUPT 和 LV_DRAW_DMA2D_HAL_INCLUDE 替换为 CONFIG_LV_Z_DRAW_DMA2D_INTERRUPT 和 CONFIG_LV_Z_DRAW_DMA2D_HAL_INCLUDE，

    • 将 LV_NEMA_USE_CACHE 和 LV_NEMA_CACHE_HAL_INCLUDE 替换为 CONFIG_LV_Z_NEMA_USE_CACHE 和 CONFIG_LV_Z_NEMA_CACHE_HAL_INCLUDE，

    • 将 LV_USE_NEMA_LIB choice 替换为某个 LV_Z_NEMA_LIB_* 选项，例如 CONFIG_LV_Z_NEMA_LIB_M7。

    LV_USE_NEMA_HAL choice 无需替换，因为 Zephyr 使用的自定义 HAL 就是 LVGL 的默认值。在 .conf 文件中设置 LVGL 选项的应用程序不受影响。

  • Zephyr LVGL 集成的日志级别不再跟随 LVGL 的日志级别，而是通过标准的 CONFIG_LV_Z_LOG_LEVEL choice（CONFIG_LV_Z_LOG_LEVEL_DBG 等）选择，默认值为 CONFIG_LOG_DEFAULT_LEVEL。LVGL 自身的日志仍通过 CONFIG_LV_USE_LOG 和 CONFIG_LV_LOG_LEVEL_* 配置。转发到 Zephyr 日志子系统的 LVGL 消息会同时按这两个级别过滤，因此要查看 LVGL 的 trace 消息，请设置 CONFIG_LV_Z_LOG_LEVEL_DBG=y。

  • CONFIG_LV_USE_SYSMON 不再隐含启用 CONFIG_CPU_LOAD。要让系统监视器报告 CPU 使用率，请启用 CONFIG_CPU_LOAD。

  • zephyr,lvgl-pointer-input 设备树绑定将 swap-xy、invert-x 和 invert-y 属性标记为 已弃用。用户应当改为在底层触摸输入控制器设备节点上添加对应的触摸屏属性 swapped-x-y、inverted-x 和 inverted-y，这些变换现在以该处的定义为准。

  • CONFIG_LV_Z_FULL_REFRESH 现在与 CONFIG_LV_Z_PARTIAL_REFRESH（默认）和 CONFIG_LV_Z_DIRECT_RENDERING 一起，属于 LV_Z_RENDERING_MODE Kconfig choice。在 .conf 片段中设置 CONFIG_LV_Z_FULL_REFRESH=y 仍然有效，但 CONFIG_LV_Z_FULL_REFRESH=n 会被悄悄忽略，因为不能通过这种方式取消选择 choice 成员。以前使用 CONFIG_LV_Z_FULL_REFRESH=n 来放弃默认全刷新的树外开发板或扩展板，必须改为在 Kconfig.defconfig 或 .defconfig 文件中覆盖该 choice 的默认值：

架构

  • 新增了一个架构原语 arch_cpu_irqs_are_enabled()。它返回调用 CPU 当前的中断使能状态而不修改它，与检查已保存键值的 arch_irq_unlocked() 互为补充。树外架构移植必须提供其实现。

  • CONFIG_XTENSA_MPU_ONLY_SOC_RANGES 已被移除。如果 SoC 或开发板需要覆盖默认的 MPU 区域表，请改为在 SoC 或开发板层覆盖 xtensa_mpu_ranges。

  • xtensa_soc_mpu_ranges[] 和 xtensa_soc_mpu_ranges_num 已被移除。如果 SoC 或开发板在启动时需要自己的内存区域，请改为覆盖 xtensa_mpu_ranges。

  • CONFIG_XTENSA_MPU_DEFAULT_MEM_TYPE 已被移除，因为内存类型现在通过 xtensa_mpu_mem_type_ranges[] 定义。

  • CONFIG_XTENSA_BACKTRACE_EXCEPTION_DUMP_HOOK 已被移除，因为回溯现在总是使用 EXCEPTION_DUMP 输出。

  • 使用 CONFIG_XTENSA_BACKTRACE 的 SoC 现在需要实现 xtensa_soc_stack_ptr_is_sane() 和 xtensa_soc_ptr_executable()。

  • ARMv7-M MPU 设备类型区域属性 REGION_PPB_ATTR、REGION_IO_ATTR 和 REGION_EXTMEM_ATTR 现在在所有 ARMv7-M 内核上都设置了 Execute-Never（XN=1）。在 ARMv7-M 上，从 Device/Strongly-ordered 内存执行代码在架构上属于 UNPREDICTABLE 行为，因此不会影响任何合理的用例。在 Cortex-M7 上，XN 属性还可以防止对这些区域的推测性取指，此类取指可能导致总线挂起或在外设空间产生读副作用（参见 Arm Cortex-M7 TRM 中的“Speculative accesses - Considerations for system design”）；仅靠内存类型无法防止这种取指。仍然从以这些属性映射的区域执行代码的树外开发板，必须改为定义自定义属性。

  • 新增的 CONFIG_ARM_MPU_CM7_UNMAPPED_REGION 选项使 Arm MPU 驱动将优先级最低的 MPU 区域（区域 0）配置为覆盖 4GB、Strongly-ordered、禁止访问且 Execute-Never 的兜底区域，从而实现 Arm Cortex-M7 勘误 1013783（SDEN-1068427）的规避方案，并防止 Cortex-M7 对未映射地址进行推测性访问。如果 Cortex-M7 开发板或 SoC 的静态 MPU 区域表显式覆盖了固件使用的所有内存，就可以启用该选项；此时静态区域从 MPU 区域 1 开始配置。mimxrt1180_evk 和 frdm_imxrt1186 的 cm7 目标默认启用该选项，取代了它们以前手工编写的 UNMAPPED MPU 区域表项，运行时行为完全相同。

  • CONFIG_SSE 和 CONFIG_SSE_FP_MATH 已被移除。请改用 CONFIG_X86_SSE 和 CONFIG_X86_SSE_FP_MATH。

  • CONFIG_PLATFORM_SPECIFIC_INIT 及其 z_arm_platform_init() 钩子已被移除。请启用 CONFIG_SOC_RESET_HOOK，并将钩子重命名为 soc_reset_hook()。新钩子在复位路径中运行得更晚，即在栈指针设置完成之后，并且从挂起到 RAM（suspend-to-RAM）恢复时会跳过该钩子。

  • RISC-V 专用的 CONFIG_EXTRA_EXCEPTION_INFO 已被移除。请改用 CONFIG_EXCEPTION_DEBUG。该选项在 Arm 和 SPARC 上保持不变。

  • arch_mem_map() 和 arch_mem_unmap() 的返回类型都已从 void 改为 int，以便在禁用断言时调用者可以根据错误码做出处理。如果启用了断言，目前基本保留以前使系统停机的行为。

视频
