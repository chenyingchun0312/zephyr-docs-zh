Zephyr 4.2.0

我们很高兴地宣布 Zephyr 4.2.0 版本正式发布。

本版本的主要改进包括：

初步支持 Renesas RX

现已支持 Renesas RX 架构，包括一个基于 QEMU 的 开发板目标。

USB 视频类驱动

USB 设备协议栈现已支持 USB 视频类（UVC），可以将摄像头设备和其他图像/视频源作为标准 USB 视频设备对外提供。请参阅 USB Video webcam 开始使用。

Twister 功耗测试框架（harness）

一个 新的 Twister harness 可以测量被测设备的功耗，并确保其保持在给定的容差范围内。

MQTT 5.0

网络协议栈现已完整支持 MQTT 5.0 协议。

经典蓝牙改进

经典蓝牙协议栈现已支持 免提规范（Hands-Free Profile）（HFP），涵盖音频网关（AG）和免提设备（HF）两种角色。

Zbus

随着 API 版本 v1.0.0 的发布，Zbus 库 升级为稳定状态。

扩展的开发板支持

本版本新增了对 96 款 新开发板 和 22 款 新扩展板 的支持。

将应用程序从 Zephyr v4.1.0 迁移到 Zephyr v4.2.0 时需要或建议进行的更改概述，请参阅单独的 迁移指南。

以下各节按组件详细列出了各项更改。

安全漏洞相关

本版本解决了以下 CVE：

  • CVE 2025-12890 蓝牙：外围设备：对畸形连接请求的处理不当

  • CVE 2025-27809 TLS 客户端可能在不知情的情况下跳过服务器认证

  • CVE 2025-27810 TLS 握手中可能存在认证绕过

  • CVE 2025-2962 dns_copy_qname 中的无限循环

  • CVE 2025-52496 AESNI 支持检测中的竞争条件

  • CVE 2025-52497 解析 PEM 加密材料时的堆缓冲区下溢读取

  • CVE 2025-49600 LMS 验证中未检查返回值导致签名绕过

  • CVE 2025-49601 mbedtls_lms_import_public_key() 中的越界读取

  • CVE 2025-49087 使用 PKCS#7 填充的分组密码解密中的时序侧信道

  • CVE 2025-48965 使用 mbedtls_asn1_store_named_data() 后的空指针解引用

  • CVE 2025-47917 mbedtls_x509_string_to_names() 中具有误导性的内存管理

  • CVE 2025-7403：禁止披露至 2025-09-05

更多详细信息请参阅：https://docs.zephyrproject.org/latest/security/vulnerabilities.html

API 变更

已移除的 API 和选项

  • 移除了已弃用的 net_buf_put() 和 net_buf_get() API 函数。

  • 移除了已弃用的 include/zephyr/net/buf.h 头文件。

  • 移除了 Twister 选项 --disable-unrecognized-section-test。相关测试已被移除，该选项的行为已成为默认行为。

  • 移除了已弃用的 kscan 子系统。

  • 移除了 meas,ms5837，由 meas,ms5837-30ba 和 meas,ms5837-02ba 取代。

  • 从 video_driver_api 中移除了 get_ctrl 驱动 API。

  • 移除了 CONFIG_I3C_USE_GROUP_ADDR 以及对 I3C 设备组地址的支持。

已弃用的 API 和选项

  • 调度器 Kconfig 选项 CONFIG_SCHED_DUMB 和 CONFIG_WAITQ_DUMB 已被重命名并弃用。请改用 CONFIG_SCHED_SIMPLE 和 CONFIG_WAITQ_SIMPLE。

  • 移除了 CONFIG_LWM2M_ENGINE_MESSAGE_HEADER_SIZE Kconfig 选项。所需的头部大小应计入消息大小，消息大小通过 CONFIG_LWM2M_COAP_MAX_MSG_SIZE 配置。需特别注意确保所用的 CoAP 块大小（CONFIG_LWM2M_COAP_BLOCK_SIZE）加上头部后能容纳在给定的消息大小内。此前预留的余量为 48 字节。

  • TLS 凭据类型 TLS_CREDENTIAL_SERVER_CERTIFICATE 已被重命名并弃用，请改用 TLS_CREDENTIAL_PUBLIC_CERTIFICATE。

  • 弃用了 arduino_uno_r4_minima 和 arduino_uno_r4_wifi 开发板目标，改用带有版本（arduino_uno_r4@minima 和 arduino_uno_r4@wifi）的新开发板 arduino_uno_r4。

  • esp32c6_devkitc 开发板目标已被弃用，并重命名为 esp32c6_devkitc/esp32c6/hpcore。

  • xiao_esp32c6 开发板目标已被弃用，并重命名为 xiao_esp32c6/esp32c6/hpcore。

  • 弃用了 CONFIG_HAWKBIT_DDI_NO_SECURITY Kconfig 选项，因为 hawkBit 服务器已在 0.8.0 版本中移除了对匿名认证的支持。

  • 弃用了 CONFIG_BT_CONN_TX_MAX Kconfig 选项。待发送 TX 缓冲区的数量现在与 CONFIG_BT_BUF_ACL_TX_COUNT Kconfig 选项保持一致。

  • 移除了 CONFIG_CRYPTO_TINYCRYPT_SHIM Kconfig 选项。该选项自 Zephyr 4.0 起已被弃用，并已建议用户迁移到其他加密后端。

  • 移除了 CONFIG_BT_MESH_USES_TINYCRYPT Kconfig 选项。该选项自 Zephyr 4.0 起已被弃用，并已建议用户改用 CONFIG_BT_MESH_USES_MBEDTLS_PSA 或 CONFIG_BT_MESH_USES_TFM_PSA。

本版本中的稳定 API 变更

  • net_mgmt 事件处理函数 net_mgmt_event_handler_t 和请求处理函数 net_mgmt_request_handler_t 的 API 签名已更改。事件值的类型由 uint32_t 改为 uint64_t。

其他值得注意的变更

  • 新增对 Armv8.1-M MPU 的 PXN（Privileged Execute Never，特权模式禁止执行）属性的支持。为此修改了 __ramfunc 和 __ram_text_reloc 的 MPU 属性：当使用 CONFIG_ARM_MPU_PXN 和 CONFIG_USERSPACE 编译时，会为这些区域设置 PXN 属性。这会改变从这些区域执行代码的行为，因为设置了 PXN 属性的区域无法在特权模式下执行。

  • 移除了对 Nucleo WBA52CG 开发板（nucleo_wba52cg）的支持，因为该产品已处于 NRND（Not Recommended for New Design，不推荐用于新设计）状态，且自 1.1.0 版本（2023 年 7 月）起 STM32CubeWBA 已不再支持它。建议改为迁移到 Nucleo WBA55CG（nucleo_wba55cg）。

  • 将 Mbed TLS 从 3.6.2 版本更新至 3.6.4 版本。3.6.3 和 3.6.4 的发布说明见下：

    • 3.6.3: https://github.com/Mbed-TLS/mbedtls/releases/tag/mbedtls-3.6.3

    • 3.6.4: https://github.com/Mbed-TLS/mbedtls/releases/tag/mbedtls-3.6.4

  • 将 TF-M 从 2.1.1 版本更新至 2.2.0 版本。其发布说明见：https://trustedfirmware-m.readthedocs.io/en/latest/releases/2.2.0.html

  • 更新了所有带有外部 I2C 连接器（Qwiic、Stemma、Grove 等）的开发板，使其使用 zephyr_i2c 设备树标签。这样就可以利用现有的 扩展板 构建系统功能（west build --shield），将任何带连接器的 I2C 模块连接到任何具有兼容 I2C 端口的开发板上，而不论具体的 I2C 连接器品牌如何。

  • 撤销了对 Nordic UART 驱动中接收器选项的弃用。此前已弃用使用额外 TIMER 外设对接收字节进行计数的接收器模式（例如 CONFIG_CONFIG_UART_0_NRF_HW_ASYNC）。然而事实证明，该模式是唯一能够在没有硬件流控的情况下可靠接收数据的模式，因此应保留在驱动中。
