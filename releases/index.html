版本发布

Zephyr 以源代码和构建脚本的形式分发，而不是二进制镜像。请使用 West（Zephyr 的元工具） 来 获取 特定版本的代码，完整的已打标签版本历史请参阅 GitHub repository。

当前及以往版本的技术文档可在 https://docs.zephyrproject.org/ 查阅（使用版本选择器选择所需版本）。

已停止维护的版本

已停止维护的版本不再维护，也不再接收安全修复。这些版本的发布说明和迁移指南可在 此处 查阅。

版本生命周期与维护

主要版本与维护版本

Zephyr 以 六个月为周期 发布主要版本，目标时间为每年的 4 月和 10 月。这一节奏既能定期提供经过充分测试的版本，又不会因更新过于频繁而给用户造成负担，同时也避开了各地区的主要节假日。

维护（小数点）版本不按固定计划发布，当主要版本分支上积累了足够多的重要修复时才会发布。每个小数点版本在发布前都要经过完整的 QA 周期。

长期支持与维护

稳定版本的支持期为 2 个发布周期（约 1 年），而 Zephyr 项目会为其中某些特定版本提供更长时间的支持，这些版本称为长期支持（LTS）版本。

Zephyr 每 2.5 到 3 年发布一个 长期支持（LTS） 版本，该版本从主干单独拉出分支，并在发布后独立维护约 5 年。

这为项目用户提供了更高的稳定性，也让用户有更充裕的时间升级到下一个 LTS 版本。

过渡到新的发布节奏

向新发布节奏的过渡将于 2026 年开始。Zephyr 4.4 计划于 2026 年 4 月发布，此后每六个月发布一个版本。

安全修复

Zephyr 中修复的每个安全问题都会向后移植（backport）或提交到以下版本：

  • 当前受支持的长期支持（LTS）版本。

  • 最近的两个版本。

更多信息请参阅 安全漏洞报告。

版本文档

每个版本都附带两份配套文档：

  • 发布说明汇总了发布周期内整个项目所做的变更。

  • 迁移指南介绍了将应用程序从一个主要版本迁移到下一个主要版本时需要处理的变更。

发布说明

发布说明列出了在该版本开发周期内对项目各个领域所做的变更。需要用户修改自己的应用程序以支持新版本的变更可以在发布说明中提及，但关于 需要修改什么 的细节应在该版本的迁移指南中详细说明。

发布周期结束后仍允许更新发布说明，但仅限于格式、排版错误修正，以及从维护版本分支向上合并说明内容，其唯一目的是使最新文档与项目中的变更保持一致。

迁移指南

Zephyr 为所有主要版本提供迁移指南，以帮助用户从上一个版本过渡。

如上一节所述，凡是需要用户采取行动（即修改源代码或配置文件）才能保持其应用程序现有行为的代码变更，都应写入迁移指南。这包括：

  • 破坏性 API 变更

  • 弃用

  • 影响用户的设备树或 Kconfig 变更（默认值变更、重命名等）

  • 具有实际影响的全局性变更（例如更改头文件包含路径，或默认改用另一个 C 标准库）

  • 其他任何可能影响现有应用程序编译或运行时行为的内容

迁移指南中的每个条目都必须简要说明该变更，并引用引入该变更的 PR（拉取请求），以便用户了解变更的背景。
