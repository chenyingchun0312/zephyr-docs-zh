术语表

API

（Application Program Interface，应用程序接口）用于构建应用软件的一组明确定义的例程和协议。

CPU 核（CPU core）

单个处理单元，拥有自己的程序计数器，按顺序执行程序指令。CPU 核属于某个 CPU 簇，一个簇可以包含一个或多个核。

CPU 簇（CPU cluster）

由一个或多个 CPU 核 组成的组，这些核在同一地址空间内以对称（SMP）配置执行同一个镜像。只有相同 架构 的 CPU 核 才能位于同一个簇中。同一个 SoC 中可以同时存在多个 CPU 簇（每个簇包含一个或多个核）。

IDT

（Interrupt Descriptor Table，中断描述符表）x86 架构用来实现中断向量表的一种数据结构。IDT 用于确定对中断和异常的正确响应。

ISR

（Interrupt Service Routine，中断服务例程）也称为中断处理程序。ISR 是一种回调函数，由硬件中断（或软件中断指令）触发执行，用于处理需要打断处理器上当前正在执行的代码的高优先级情况。

SoC

即 System on a chip （片上系统），是一种集成电路，至少包含一个 CPU 簇 （每个簇又至少包含一个 CPU 核），以及外设和存储器。

SoC 家族（SoC family）

一个或多个 SoC 或 SoC 系列，它们有足够多的共同点，因而被视为相关并归入同一个家族名称之下。

SoC 系列（SoC series）

若干个具有相似特性和功能的不同 SoC，厂商通常将它们一起命名和推广。

west

为 Zephyr 项目开发的多仓库元工具。请参见 West（Zephyr 的元工具）。

west 安装（west installation）

west 0.7 之前用来指代 west 工作区 的旧术语，现已废弃。

west 工作区（west workspace）

系统上的一个文件夹，其中包含 .west 子目录和一个 west 清单仓库。使用 west init 命令创建 west 工作区，即可将 Zephyr 源代码及其 west 项目 的源代码克隆到系统上。请参见 基础知识。

west 清单仓库（west manifest repository）

west 工作区 中包含 west 清单 的 Git 仓库。其位置由 manifest.path 配置选项 给出。请参见 基础知识。

west 清单（west manifest）

一个 YAML 文件，通常名为 west.yml，描述构成 west 工作区 的项目（即 Git 仓库）以及其他元数据。一般信息请参见 基础知识，详细信息请参见 West 清单。

west 项目（west project）

west 清单 中的每个条目，描述一个 Git 仓库；在使用相应的 west 清单仓库 时，west 会克隆并管理该仓库。注意，west 项目与 zephyr 模块 不同，尽管许多项目同时也是模块。更多信息请参见 项目。

XIP

（eXecute In Place，就地执行）一种直接从长期存储器中执行程序、而不是将程序复制到 RAM 中执行的方法，这样可以将可写存储器留给动态数据，而不是静态程序代码。

zephyr 模块（zephyr module）

包含 zephyr/module.yml 文件的 Git 仓库，Zephyr 构建系统利用该文件将模块的源代码和配置文件集成到常规的 Zephyr 构建中。Zephyr 模块可以是 west 项目，但并非必须如此。更多详细信息请参见 模块（外部项目）。

公共 API（public API）

在 include/zephyr 文件夹中定义、且未明确标记为私有的任何函数、结构体或宏。公共 API 供树内或树外的任何 软件组件 使用。不遵循 API 生命周期 一节所述规定，就不能修改公共 API，这意味着它们保证会长期保持稳定。

内核（kernel）

Zephyr 提供的、实现 Zephyr 内核的一组文件，包括其核心服务、设备驱动、网络协议栈等。

内部 API（internal API）

Zephyr 源代码树中任何位置定义的任何内部函数、结构体或宏。内部 API 旨在“扩展”Zephyr，只能在某些 软件组件 之间使用，这些组件通常位于树内，但在某些情况下也可能位于树外（例如添加树外的架构或驱动）。应用程序不得在其自身作用域之外调用内部 API。调用或实现 API 的上下文有明确定义。例如，以 arch_ 为前缀的函数供 Zephyr 内核调用架构特定的代码。内部 API 大多保持稳定，但其保证少于 公共 API。

变体（variant）

在 开发板限定符 的语境中，变体是指针对 SoC 与 CPU 簇 的某个组合的特定构建类型或构建配置。变体概念的常见用途包括：为支持可信执行环境（Trusted Execution Environment）的平台同时引入安全和非安全构建，或者选择构建中使用的 RAM 类型。

子系统（subsystem）

子系统是指操作系统中逻辑上相对独立、负责特定功能或提供特定服务的部分。

应用程序镜像（application image）

由其目标开发板加载并执行的二进制文件。每个应用程序镜像既包含应用程序的代码，也包含支持该应用程序所需的 Zephyr 内核代码。二者被编译为一个完全链接的单一二进制文件。应用程序镜像加载到开发板上后，便接管系统的控制权，对系统进行初始化，并作为系统唯一的应用程序运行。应用程序代码和内核代码都作为特权代码在同一个共享地址空间中执行。

应用程序（application）

用户提供的一组文件，Zephyr 构建系统使用这些文件为指定的开发板配置构建应用程序镜像。它可以包含应用程序特定的代码、内核配置设置以及至少一个 CMakeLists.txt 文件。应用程序的内核配置设置指示构建系统创建一个定制内核，以高效利用开发板的资源。如果应用程序不需要任何开发板特定的功能，有时可以为多种开发板配置（包括 CPU 架构不同的开发板）构建。

开发板名称（board name）

开发板 的人类可读名称。它以唯一且具有描述性的方式标识某个特定系统，但不包含为其实际构建 Zephyr 镜像可能需要的其他信息。更多详细信息请参见 开发板术语。

开发板版本（board revision）

可选的版本字符串，用于标识硬件系统的某个特定版本。当硬件系统引入细微变更时，它有助于避免重复编写开发板文件。更多信息请参见 多个开发板版本 和 为开发板版本构建。

开发板目标（board target）

可以提供给任一 Zephyr 构建工具的完整字符串，用于为某个特定硬件系统编译和链接镜像。该字符串唯一标识 开发板名称、开发板版本 和 开发板限定符 的组合。更多详细信息请参见 开发板术语。

开发板配置（board configuration）

一组内核配置选项，用于指定内核如何使用开发板上的设备。Zephyr 构建系统为其支持的每块开发板定义一个或多个开发板配置。如有需要，应用程序可以覆盖构建系统指定的内核配置设置。

开发板限定符（board qualifiers）

跟在 开发板名称 （以及可选的 开发板版本）之后、以正斜杠（/）分隔的一组附加标记，它们共同构成 开发板目标。目前可接受的限定符有 SoC、CPU 簇 和 变体。更多详细信息请参见 开发板术语。

开发板（board）

具有一组确定的设备和功能、能够加载并执行应用程序镜像的目标系统。它可以是实际的硬件系统，也可以是在 QEMU 下运行的仿真系统。一块开发板可以包含一个或多个 SoC。Zephyr 内核支持 多种开发板。

架构（architecture）

指令集架构（ISA）及其编程模型。

电源域（power domain）

电源域是一组设备的集合，这些设备的供电通过一次操作统一施加或断开。电源域由 device 表示。

电源门控（power gating）

电源门控通过关闭集成电路中未使用的区域来降低功耗。

私有 API（private API）

Zephyr 源代码树中任何位置定义的、仅供其所在 软件组件 内部使用的任何函数、结构体或宏。私有 API 可能随时更改，相应软件组件之外的代码不得使用。

空闲线程（idle thread）

在没有其他就绪线程可运行时运行的系统线程。

系统电源状态（system power state）

系统电源状态描述整个系统的功耗。系统电源状态由 pm_state 表示。

设备运行时电源管理（device runtime power management）

设备运行时电源管理（PM）是指设备独立于系统电源状态进行节能的能力。设备会记录自身的使用情况，并自动挂起或恢复。此功能通过 Kconfig 选项 CONFIG_PM_DEVICE_RUNTIME 启用。

软件组件（software component）

软件组件是 Zephyr 源代码中自包含、模块化且可替换的部分。驱动、子系统或应用程序都是 Zephyr 中软件组件的例子。
