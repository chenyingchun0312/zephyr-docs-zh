详细描述

连接回调结构体。

此结构体用于跟踪连接的状态，通过 bt_conn_cb_register() API 注册。允许注册多个此 bt_conn_cb 类型的实例，以应对应用程序中不同模块都关注连接状态的情况。若某个实例不关心某个回调，可将其设为 NULL，从而该实例不会使用该回调。

注解
这些回调在线程上下文中调用，绝不会在 ISR 中调用。回调是由协议栈内部上下文调用，还是由触发它的 API 调用同步调用，以及来自哪个上下文，不属于 API 的一部分，且可能随版本变化。参见 Callback execution contexts for the hazards of blocking in a callback and their mitigations.

◆ conn_rate_changed

void(*) bt_conn_cb::conn_rate_changed(struct bt_conn *conn, uint8_t status, const struct bt_conn_le_conn_rate_changed *params)

LE Connection Rate Changed 事件。

此回调通知应用程序连接的连接速率参数（包括连接间隔和子速率）可能已变化。

参数
conn连接对象。
status来自 LE Connection Rate Change 事件的 HCI 状态。可能的状态码：
  • 成功（0x00）
  • 未知连接标识符（0x02）
  • 命令不允许（0x0C）
  • 不支持的特性或参数值（0x11）
  • HCI 命令参数无效（0x12）
  • 不支持的远端特性（0x1A）
  • 不支持的链路层参数值（0x20）
params新的连接速率参数。若 status 不是 BT_HCI_ERR_SUCCESS，连接速率参数将为 NULL。

◆ connected

void(*) bt_conn_cb::connected(struct bt_conn *conn, uint8_t err)

已建立新连接。

此回调向应用程序通知新连接。若 err 参数非零，表示连接建立失败。

注解
若连接是由某个广播集建立的，则不能直接在该回调中重启该广播集，而应使用该广播集的已连接回调。
参数
conn新连接对象。
errHCI 错误。成功时为零，否则非零。

err can mean either of the following:

  • BT_HCI_ERR_UNKNOWN_CONN_ID 由以下方式启动的创建连接 bt_conn_le_create was canceled either by the user through bt_conn_disconnect or by the timeout in the host through bt_conn_le_create_param timeout parameter, which defaults to CONFIG_BT_CREATE_CONN_TIMEOUT seconds.
  • BT_HCI_ERR_ADV_TIMEOUT 由 bt_le_adv_start 启动的高占空比定向可连接广播者在超时内未能建立连接。

◆ disconnected

void(*) bt_conn_cb::disconnected(struct bt_conn *conn, uint8_t reason)

连接已断开。

此回调通知应用程序某个连接已断开。

调用此回调时，协议栈仍持有该连接对象的一个引用。若应用程序在此回调中尝试启动可连接广播者或创建新连接，可能因没有空闲的连接对象而失败。为避免此问题，建议改用 bt_conn_cb.recycled，它在连接对象真正被释放时通知应用程序。

参数
conn连接对象。
reason断开原因，取值见 BT_HCI_ERR_*。

◆ le_param_req

bool(*) bt_conn_cb::le_param_req(struct bt_conn *conn, struct bt_le_conn_param *param)

LE 连接参数更新请求。

此回调通知应用程序远端设备正在请求更新连接参数。应用程序通过返回 true 接受这些参数，或返回 false 拒绝。在接受之前，应用程序也可以调整参数以更好地满足自身需求。

为简单起见，建议应用程序只使用一个此类回调。但若注册多个，则需处理各回调可能不同的需求。每个回调收到的是先前回调返回的参数，即不一定与远端最初发送的参数相同。

若应用程序没有此回调，则默认接受这些参数。

参数
conn连接对象。
param建议的连接参数。
返回
接受这些参数则为 true，拒绝则为 false。

void(*) bt_conn_cb::le_param_update_rejected(struct bt_conn *conn, uint8_t hci_err)

LE 连接参数更新被对端拒绝。

此回调通知应用程序由 bt_conn_le_param_update 发起的连接参数更新请求被对端拒绝。

注解
仅在显式的 HCI 拒绝和 L2CAP 连接参数更新过程（CPUP）拒绝时调用。对同一事件与 le_param_updated 互斥。若远端不支持连接参数请求（CPR）过程且 L2CAP 回退被拒绝，hci_err 将为 BT_CONN_PARAM_REJECT_ERR_L2CAP_CPUP。
参数
conn连接对象。
hci_errCPR 被拒绝时的 HCI 错误码（BT_HCI_ERR_*），或 L2CAP 回退被拒绝时的 BT_CONN_PARAM_REJECT_ERR_L2CAP_CPUP。

◆ recycled

void(*) bt_conn_cb::recycled(void)

连接对象已归还到池中。

此回调通知应用程序或许可以分配连接对象了。但不作保证，先到先得。只有受 CONFIG_BT_MAX_CONN 配置的连接（即 BT_CONN_TYPE_LE 或 BT_CONN_TYPE_BR 类型的连接）会触发此回调。

同时连接的最大数量由 CONFIG_BT_MAX_CONN 配置。

无论是希望在系统完全处理完先前的连接之后再启动，还是应用程序出于任何原因启动连接失败并在等待合适的重试时机，都应监听此事件以启动新连接或可连接广播者。

void(*) bt_conn_cb::security_changed(struct bt_conn *conn, bt_security_t level, enum bt_security_err err)

此回调通知应用程序某个连接的安全状态已变化。
