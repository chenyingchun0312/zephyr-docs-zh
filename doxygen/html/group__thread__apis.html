◆ k_reschedule()

void k_reschedule ( void )

#include <zephyr/kernel.h>

调用调度器

此例程调用调度器，以在当前 CPU 上强制产生一个调度点。如果从线程内调用，调度器会立即被调用（前提是调用时中断未锁定）。如果从 ISR 内调用，调度器将在退出该 ISR 时被调用。

调用调度器使内核能立即确定下一个应执行的线程。与让出不同，如果有同等或更高优先级的线程可用，此例程不保证切换到它们。例如，如果当前线程是协作式线程，且存在一个仍更高优先级的就绪协作式线程，那么让出会切换到那个更高优先级的线程，而此例程不会。

大多数应用程序永远不会使用此例程。

◆ k_sched_lock()

void k_sched_lock ( void )

#include <zephyr/kernel.h>

锁定调度器。

此例程指示调度器将当前线程视为协作式线程，从而防止其被另一线程抢占。如果该线程随后执行了使其不再就绪的操作，它将按常规方式被上下文切换出去。当该线程再次成为当前线程时，其不可抢占状态将保持。

此例程可递归调用。

得益于巧妙的实现细节，对于非用户空间线程，调度器锁定极快（只是在 thread 结构体中递增/递减一个字节）。

注解

◆ k_thread_suspend()

void k_thread_suspend ( k_tid_t thread)

#include <zephyr/kernel.h>

挂起线程。

此例程阻止内核调度器将 thread 设为当前线程。对 thread 的所有其他内部操作仍会执行；例如，它正在等待的内核对象仍会交给它。线程挂起不影响该线程可能正在等待的任何超时（例如调用 k_sem_take() 或 k_sleep() 产生的超时）。因此，如果线程被挂起期间超时到期，它仍保持挂起，直到调用 k_thread_resume()。

当目标线程正在另一个 CPU 上活动时，调用者将阻塞，直到目标线程停止（挂起或终止）。但如果调用者处于中断上下文中，它将自旋等待那个在另一 CPU 上活动的目标线程停止。

如果 thread 已处于挂起状态，则此例程无效果。

参数
thread要挂起的线程 ID。

k_thread_timeslice_fn_t expired,

#include <zephyr/kernel.h>

设置线程时间片

与 k_sched_time_slice_set 类似，但当 CONFIG_TIMESLICE_PER_THREAD=y 时，为特定线程设置时间片。非零时，该时间片将优先于全局值。

当此类线程的时间片到期时，会在该线程被移出/重新加入运行队列之前调用所配置的回调。该回调将在中断上下文中发生，且可保证指定线程已被当前正在执行的 ISR 抢占。此类回调可以自由地执行诸如修改线程优先级或后续执行的时间片、挂起线程等操作……

注解
与较老的 API 不同，这里的时间片参数以节拍为单位，而不是毫秒。节拍一直是内部单位，而且并非所有平台都能在两者之间进行整数换算。
设置了非零时间片的线程将始终进行时间片调度，即使它们的优先级高于通过 k_sched_time_slice_set() 设置的最高时间片优先级。
时间片到期的回调通知必然在线程仍为“当前”时发生，因此它发生在此节拍上任何已注册超时之前。这有一个略显令人困惑的副作用：节拍时间（参见 k_uptime_get()）尚未反映已到期的节拍。希望在此回调中做细粒度计时决策的应用程序应使用周期 API，或 k_thread_runtime_stats_get() 之类的派生设施。
