详细描述

转换元素结构

媒体管道中所有转换元素的基类结构。转换元素处理来自其 sink pad 的数据，并将结果输出到其 source pad。

◆ decide_buffer_pool

int(*) mpipe_transform::decide_buffer_pool(struct mpipe_transform *self, struct mpipe_dispatch *query)

为下游决定缓冲区池

下游提议要么是整个池（查询的 pool 指针；其配置即为提议），要么是裸配置（查询的 pool_cfg）。对提出提议的池应用需求只能通过以下方式 mpipe_buffer_pool_set_config, which the pool may refuse - keep a fallback. An element deciding for its own pool rebuilds its config baseline here on every negotiation before absorbing the query's demands, so nothing accumulates across replays.

参数
self指向转换元素的指针
query缓冲区池查询（mpipe_dispatch）
返回
成功时为 0，失败时为负的 errno

◆ propose_buffer_pool

int(*) mpipe_transform::propose_buffer_pool(struct mpipe_transform *self, struct mpipe_dispatch *query)

向上游提议缓冲区池

转换元素可以提议其整个输入缓冲区池（设置查询的 pool 指针；池自身的配置即为提议），或提议一个裸配置（写入查询的 pool_cfg）。被提议池的操作随后将由上游元素调用。在提议之前请根据其要求重建池的配置：活动配置是上次协商的结果，原样提议它会使对端需求在多次重放中累积。

就地转换元素可以对输入和输出使用同一个池。当该池被向上游提议时，将 mpipe_transform::in_pool 指向它，并让 mpipe_transform::out_pool 保持 NULL，这样该池仅由上游配置和启动。

参数
self指向转换元素的指针
query缓冲区池查询（mpipe_dispatch）
返回
成功时为 0，失败时为负的 errno

int(*) mpipe_transform::transform_caps(struct mpipe_transform *self, enum mpipe_pad_direction direction, const struct mpipe_structure *in, uint32_t index, struct mpipe_structure *out)

产生能力跨该元素的一种变换

元素通常将单个输入能力映射到多个输出能力：一个能输出 N 种像素格式中任一种的解码器，一个具有 N 种可达格式的转换器。这些备选存在于 index 上而不是返回的集合中，因此协商逐个遍历它们，扇形展开从不被物化。

参数
self指向转换元素的指针
direction要将能力转换到的 pad 的方向（mpipe_pad_direction）
in对侧 pad 上要转换的能力
index要产生的变换的索引，从 0 开始
[out]out接收该变换的调用方存储
返回
out 持有变换时返回 0，失败时返回其他负 errno
返回值
-EAGAIN该索引不产生任何变换，但更靠后的索引可能会
-ENOENT已超过最后一个变换
