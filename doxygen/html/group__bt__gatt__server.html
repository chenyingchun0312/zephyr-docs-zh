◆ BT_GATT_CCC_MAX

#define BT_GATT_CCC_MAX   0

#include <zephyr/bluetooth/gatt.h>

BT_GATT_CCC_MAX 的定义取决于是否 CONFIG_BT_SETTINGS_CCC_LAZY_LOADING or CONFIG_BT_CONN is set.

CONFIG_BT_SETTINGS_CCC_LAZY_LOADING will set BT_GATT_CCC_MAX to CONFIG_BT_MAX_CONN CONFIG_BT_CONN will set BT_GATT_CCC_MAX to CONFIG_BT_MAX_PAIRED + CONFIG_BT_MAX_CONN If neither are set, BT_GATT_CCC_MAX is 0.

在单个 PDU 中发送多条通知。

GATT 服务器将发送单个 ATT_MULTIPLE_HANDLE_VALUE_NTF PDU，其中包含传给此 API 的所有通知。

所有 params 必须具有相同的 func 和 user_data\ （受实现限制）。但每个参数都会调用 func(user_data)。

对端的 GATT 客户端必须先写入本设备的客户端支持特征属性并设置多句柄值通知位，然后才能使用此 API。

◆ bt_gatt_service_register()

int bt_gatt_service_register ( struct bt_gatt_service * svc)

#include <zephyr/bluetooth/gatt.h>

注册 GATT 服务。

要注册 GATT 服务，应用程序可以使用 BT_GATT_PRIMARY_SERVICE、BT_GATT_CHARACTERISTIC、BT_GATT_DESCRIPTOR 等宏。

使用 CONFIG_BT_SETTINGS 时，所有需要加载绑定配置（即 CCC 值）的服务都必须在调用 settings_load 之前注册。

同时使用 CONFIG_BT_GATT_CACHING 和 CONFIG_BT_SETTINGS 时，所有需要纳入 GATT 数据库哈希计算的服务都应在调用 settings_load 之前添加。在 settings_load 之后注册的所有服务都会触发新的数据库哈希计算并存储新的哈希。

可以在两种情况下调用此函数：在调用 bt_init() 之前，或在调用 settings_load() 之后。不支持在中间阶段注册服务，此时会返回错误。

参数
svc包含可用属性的服务
返回
成功时为 0，出错时为负值。
-EAGAIN 表示 bt_init() 已被调用，但 settings_load() 尚未调用。
