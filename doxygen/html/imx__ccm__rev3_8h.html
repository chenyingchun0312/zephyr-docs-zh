每设备时钟根配置单元

如果外设希望自行拥有其时钟根的 mux/分频器设置（而不是继承由 SoC 时钟初始化编程的固定根），则在其 clocks 属性中添加第二个条目，并在 clock-names 中命名为 "source"，遵循 Zephyr 既有的时钟绑定惯例，即在门控之外再提供一个 "source-select" clocks 条目（clocks = <&ctlr GATE>, <&ctlr SRC SEL>;）。该条目是一个打包的 IMX_CCM_ROOT_CFG 单元。IP 驱动读取它，并按值原样作为 clock_control_configure() 的子系统参数传入（data 为 NULL）；rev3 控制器将其解包并发出一次 CLOCK_SetRootClock。

该单元必须能与传统的 IMX_CCM_CLK 门控单元区分开，因为共享驱动也会把门控单元传给 clock_control_configure()\ （即原有的容错调用）。门控单元用两个 16 位 id 填满全部 32 位；其高半字节是时钟根 id 的高半字节，对每个真实根（最大 id 217）均为 0，而仅对以下情况才为 0xF IMX_CCM_ROOT_NONE. A root-config cell uses the low 28 bits for its fields and stamps a fixed 0xA tag into the top nibble – a value a gate cell can never produce – so IMX_CCM_ROOT_CFG_IS() tells the two kinds apart by construction.

字段宽度：root 8 位（最大 id 217），mux 4 位（最大 3），div 8 位，snd_div 8 位，共 28 位，经确认对所有 RT2660 外设根都足够。分频值为 0 是非法的：HAL 编程的是 value - 1，因此 0 会以全 1 字段到达寄存器（最慢分频）。除以一是 1。

详细描述

适用于 NXP i.MX CCM rev3 的、与 SoC 无关的时钟说明符编码。

近期 i.MX RT 系列所用的 i.MX CCM 将外设时钟建模为两个独立的部分：

  • 一个 gate\ （LPCG），用于打开和关闭外设的总线时钟和功能时钟，以及
  • 一个 **clock root**，其 mux 和分频器设置决定外设实际收到的频率。

这两个标识符空间之间不存在算法上的关联，因此二者都必须传到时钟驱动。共享的 NXP 外设驱动读取单个时钟单元 – DT_INST_CLOCKS_CELL(n, name) – 并将该值同样传给 clock_control_on()、clock_control_get_rate() 和 clock_control_configure()，因此第二个设备树单元对它们是不可见的。因此两个标识符被打包进同一个单元：

clocks = <&ccm IMX_CCM_CLK(<gate-id>, <root-id>)>;

Packing two identifiers into one cell is how nxp,imx-ccm-rev2 already encodes its peripheral and instance numbers.

Use IMX_CCM_GATE_NONE for a peripheral that has no gate of its own, and IMX_CCM_ROOT_NONE for one with no dedicated clock root – asking such a peripheral for its rate yields -ENOTSUP rather than a fabricated number.

The identifier values themselves are SoC-specific and generated into the hal_nxp module beside the fsl_clock.h they are derived from, for example <nxp/imxrt/imxrt266x/clock/imx_ccm_rev3_rt266x.h>.
