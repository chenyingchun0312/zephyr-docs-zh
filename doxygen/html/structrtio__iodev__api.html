◆ cancel

void(*) rtio_iodev_api::cancel(const struct rtio_iodev *iodev, struct rtio *r, rtio_sqe_handle_t handle)

尝试主动取消此前提交的条目

可选。当非 NULL 时，会在 handle 所指定名称的提交被取消时调用，给 iodev 一个中止其仍拥有工作的机会（例如从内部队列中移除尚未开始的条目，或停止正在进行的传输）。如果该条目仍归 iodev 所有并被移除，iodev 负责完成它（通常是调用 rtio_iodev_sqe_err() 并传入 -ECANCELED）。如果该条目未被 iodev 拥有（或已不再被拥有），则必须为空操作。

提交以句柄而非指针形式传递，因为它不归调用方所有：在此代码运行之前的任何时刻，该条目都可能已完成且其池槽位被回收。实现用锁将自己的完成路径串行化，并在持锁期间用 rtio_iodev_sqe_from_handle() 解析句柄，这既能识别出已被回收的槽位（返回 NULL），又能防止该条目在钩子之下被完成。

钩子为 NULL 意味着取消是尽力而为的：已取消状态（参见 rtio_iodev_sqe_is_canceled()）仍会停止链式继续和重新入队，但已入队或正在进行的条目会运行到自然完成。

参数
iodev该提交被分派到的 iodev
r拥有该提交的 RTIO 上下文
handle正在被取消的提交的句柄
