◆ unicast_start_codec_configured

void(*) bt_cap_initiator_cb::unicast_start_codec_configured(void)

所有流均已完成编解码器配置

传给 bt_cap_initiator_unicast_audio_start() 的所有流都处于 BT_BAP_EP_STATE_CODEC_CONFIGURED state or higher, with the requested codec configuration.

仅当至少有一个配置编解码器操作被发送给 CAP 接受方时才调用，即如果所有流都已具有所请求的编解码器配置则不调用。

可在此回调中使用 bt_cap_unicast_group_reconfig() 重新配置单播组，因为 QoS 配置子过程尚未开始。仅当该单播组中没有任何流曾提前连接过时才可行，因为一旦 CIS 建立，单播组就无法重新配置。无法在此回调中启动新的 CAP 过程，因为当前过程仍在进行中。

◆ unicast_start_complete

void(*) bt_cap_initiator_cb::unicast_start_complete(int err, struct bt_conn *conn)

bt_cap_initiator_unicast_audio_start() 的回调。

参数
err
  • 0 if success.
  • 若无法执行子过程，则为 -ENOEXEC。
  • 若因内存不足无法执行子过程，则为 -ENOMEM。
  • 若请求被对端拒绝，则为 -EACCES。
  • 若因单播客户端已忙碌而无法执行子过程，则为 -EBUSY。
  • 若子过程包含无效参数，则为 -EINVAL。
  • 若发生意外的状态变化，则为 -EBADMSG。
  • 若因状态意外而无法执行子过程，则为 -EALREADY。
  • 若过程执行期间连接断开，则为 -ECONNRESET。
  • 若因连接问题无法执行子过程，则为 -ENOTCONN。
  • 若被 bt_cap_initiator_unicast_audio_cancel() 取消，则为 -ECANCELED。
conn发生错误的连接指针。若 err 为 0 或被 bt_cap_initiator_unicast_audio_cancel() 取消，则为 NULL

◆ unicast_start_connected

void(*) bt_cap_initiator_cb::unicast_start_connected(void)

所有流的 CIS 均已连接

传给 bt_cap_initiator_unicast_audio_start() 的所有流均已建立 CIS。

仅当至少有一个 CIS 是在该过程中建立的时才调用，即如果所有 CIS 均已建立则不调用。

◆ unicast_start_enabled

void(*) bt_cap_initiator_cb::unicast_start_enabled(void)

所有流均已启用

传给 bt_cap_initiator_unicast_audio_start() 的所有流都处于 BT_BAP_EP_STATE_ENABLING state or higher, with the requested metadata.

仅当至少有一个启用操作被发送给 CAP 接受方时才调用，即如果所有流都已用所请求的元数据启用则不调用。

◆ unicast_start_qos_configured

void(*) bt_cap_initiator_cb::unicast_start_qos_configured(void)

所有流均已完成 QoS 配置

传给 bt_cap_initiator_unicast_audio_start() 的所有流都处于 BT_BAP_EP_STATE_QOS_CONFIGURED state or higher, with the QoS configuration of the unicast group.

仅当至少有一个配置 QoS 操作被发送给 CAP 接受方时才调用，即如果所有流都已具有所请求的 QoS 配置则不调用。

◆ unicast_start_started

void(*) bt_cap_initiator_cb::unicast_start_started(void)

所有流均已启动

传给 bt_cap_initiator_unicast_audio_start() 的所有流都处于 BT_BAP_EP_STATE_STREAMING state.

仅当至少有一个接收端启动就绪（Receiver Start Ready）操作被发送给 CAP 接受方时才调用，即如果所有流都由 CAP 接受方启动则不调用。

void(*) bt_cap_initiator_cb::unicast_stop_disabled(void)

所有流均已禁用

传给 bt_cap_initiator_unicast_audio_stop() 的所有流都处于 BT_BAP_EP_STATE_DISABLING or BT_BAP_EP_STATE_QOS_CONFIGURED state.

仅当至少有一个禁用操作被发送给 CAP 接受方时才调用，即如果没有流被启用或处于流式传输状态则不调用。
