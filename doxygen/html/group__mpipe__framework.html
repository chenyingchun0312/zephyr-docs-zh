详细描述

对象模型、协商和运行时。

应用程序声明它需要的元素，将它们链接成图，并通过状态机驱动该图。框架负责在相邻元素之间协商数据格式、确定缓冲区配置，并将缓冲区从一个元素传递到下一个元素。

对象 is the base every type embeds; 元素 is what a graph is made of and Pad is where two elements meet; 能力结构 describes what crosses a link and 派发 carries the negotiation; 管道 runs the result.

No dynamic allocation

框架不分配任何内存。元素和管道是应用程序拥有的对象，缓冲区来自管道启动时确定大小的内存池，协商路径上的每种类型都是固定大小且按值保存的，因此运行数小时的流不可能使其从未触及的堆产生碎片。需要临时内存的元素在初始化时从应用程序获取，就像获取内存池和栈那样。协商在改变状态的线程上运行，该线程需要为其分配足够的栈。

Pointer parameters

除非指针参数自己的文档说明了 NULL 对它的含义（“或 NULL 表示重置为 ANY”、“或未使用时为 NULL”），否则指针参数不得为 NULL。在其他任何地方传入 NULL 都属于编程错误，而不是运行时状况：调用方交出的是它自己拥有的对象，因此没有什么可恢复的，也没有可报告的内容。这类情况由断言捕获，在关闭 CONFIG_ASSERT 后不产生任何开销。

值则不同。当参数携带的是数据而不是对象时（可能为空的能力、应用程序自选了值的属性），API 会校验它并返回负的 errno，因为管道可以报告该错误并继续运行。
