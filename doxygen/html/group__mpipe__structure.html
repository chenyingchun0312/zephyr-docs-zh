详细描述

描述一个媒体能力的固定大小容器。

mpipe_structure 持有一组字段，每个字段是一个 mpipe_caps_field 标识符配一个 mpipe_value。它是按值持有的固定大小类型，因此无需分配：字段占据两个平行数组的前几个槽位，一个数组给出字段名，另一个保存其值。

诸如以下视频能力 

video, format=VIDEO_PIX_FMT_RGB565, width=[16, 1280, 2], height=[16, 720, 2]

直接在调用方的存储中构建：

struct mpipe_structure s;
mpipe_structure_init_fields(&s, MPIPE_MEDIA_VIDEO,
MPIPE_CAPS_PIXEL_FORMAT, MPIPE_TYPE_UINT, VIDEO_PIX_FMT_RGB565,
MPIPE_CAPS_IMAGE_WIDTH, MPIPE_TYPE_UINT_RANGE, 16, 1280, 2,
MPIPE_CAPS_IMAGE_HEIGHT, MPIPE_TYPE_UINT_RANGE, 16, 720, 2,
MPIPE_CAPS_END);

A range is written [min, max, step], so the width above admits every multiple of 2 from 16 to 1280.

Two structures intersect when they have the same media type, carry at least one field identifier in common, and every field they do share has intersecting values. The result is the union of both: a shared field holds the intersected value, and a field only one side carries passes through unchanged. That last rule is what lets a constraint travel down a chain of elements that do not themselves care about it.

Pointers passed to this API must not be NULL unless the parameter is documented otherwise.

能力在构建时已知的元素可以把它们放在这里，而不必在运行时构建，并在枚举时通过普通的结构体赋值复制出来。

fields is a macro taking one argument, which it applies to each field as arg(field_id, value_initializer). Listing the fields once is what keeps the identifiers, the values and the count from disagreeing, which would silently drop a field. Defining more fields than CONFIG_MPIPE_STRUCTURE_MAX_FIELDS fails the build.

◆ mpipe_caps_field

enum mpipe_caps_field

#include <zephyr/mpipe/mpipe_structure.h>

Caps 字段标识符

能力结构 的字段是这些标识符之一与一个以下内容的配对 值容器. Each entry below names the value type that carries it. A capability offering a span rather than one setting uses the matching range type instead, MPIPE_TYPE_UINT_RANGE where the entry says MPIPE_TYPE_UINT, which is how a device advertises every width from 16 to 1280 rather than a single one. Negotiation then narrows the span, and fixation picks one value out of it. MPIPE_CAPS_PIXEL_FORMAT and MPIPE_CAPS_INTERLEAVED, for example, are the exceptions: neither has a meaningful range form, so both are always carried fixed.

caps 字段描述从 source pad 到 sink pad 跨越链接的数据，因此两端必须对它达成一致，而属性只配置单个元素（参见 mpipe_object）。只有当两个不同元素必须得到相同的值才能保证流正确时（如 MPIPE_CAPS_IMAGE_WIDTH），才应添加字段，并优先选择整个域都一致认可的字段：一个结构一次只能容纳 CONFIG_MPIPE_STRUCTURE_MAX_FIELDS 个字段。

在 MPIPE_CAPS_END 之前添加它，并像下面各条目那样记录其单位和值类型。

枚举值

像素格式，以 VIDEO_PIX_FMT_* fourcc 表示，MPIPE_TYPE_UINT

MPIPE_CAPS_IMAGE_WIDTH 

图像宽度（像素），MPIPE_TYPE_UINT

MPIPE_CAPS_IMAGE_HEIGHT 

图像高度（像素），MPIPE_TYPE_UINT

MPIPE_CAPS_SAMPLE_RATE 

采样频率（Hz，音频），MPIPE_TYPE_UINT

MPIPE_CAPS_BIT_WIDTH 

样本大小（位，音频），MPIPE_TYPE_UINT

MPIPE_CAPS_NUM_CHANNELS 

通道数（音频），MPIPE_TYPE_UINT

缓冲区中通道的布局（音频），MPIPE_TYPE_BOOLEAN：交错（LRLRLRLR）为 true，非交错（LLLLRRRR）为 false

一帧覆盖的时间，以微秒为单位，MPIPE_TYPE_UINT。音频和视频域都会使用它：对视频而言它是帧间隔，即帧率的倒数。

int mpipe_structure_intersect ( const struct mpipe_structure * struct1,

struct mpipe_structure * out )

#include <zephyr/mpipe/mpipe_structure.h>

将两个结构相交到调用方提供的存储中。

两个结构必须有相同的媒体类型，至少有一个共同的字段标识符，且它们共有的每个字段的值必须可相交。结果是两个输入的并集：双方都携带的字段持有相交后的值，只有一方携带的字段原样复制通过，这可能使结果持有的字段比任一输入都多。与 ANY 结构相交会得到另一方的副本。

out is written field by field, so it must not be one of the inputs.

参数
struct1指向第一个结构的指针。
struct2指向第二个结构的指针。
[out]out指向存放结果的存储的指针，出现 -EINVAL 时保持不变，任何其他失败时被清空。
返回值
0Success.
-ENOENT两个结构没有共同字段，或共有字段没有共同值
-EINVALout 与某个输入重叠，或媒体类型不同
-ENOSPC并集超出 CONFIG_MPIPE_STRUCTURE_MAX_FIELDS
