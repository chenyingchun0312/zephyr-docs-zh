详细描述

通用访问配置文件（GAP）

通用访问配置文件（GAP）定义了基本的 Bluetooth 操作，包括设备发现、配对和连接管理。Zephyr 的 GAP 实现同时支持经典 Bluetooth 和低功耗 Bluetooth（LE）功能，可承担广播者、观察者、外围设备和中心等角色。这些角色定义了设备在 Bluetooth 网络中进行广播、扫描和建立连接时的行为。

GAP 推荐的用户发起的可连接广播参数

此宏定义设置当应用程序可能正在等待设备被连接或发现时使用的推荐默认值。

GAP 建议广播者对用户发起的广播使用 BT_LE_ADV_CONN_FAST_1 设置的广播参数。这可能指用户与设备交互的任何时刻，例如按下专用的 Bluetooth 唤醒按钮，或介于两者之间的任何情况。具体解释由应用程序开发者决定。

这些参数设置考虑了以下模式：

  • 非定向可连接模式
  • 有限可发现模式并发送可连接非定向广播事件
  • 一般可发现模式并发送可连接非定向广播事件
  • 定向可连接模式并发送低占空比定向广播事件
注解
这些参数仅为建议值。例如，应用程序可能为省电而使用更长的间隔，这会牺牲响应性，并且应考虑仅在超时之后才以更长间隔进入低功耗状态。
这是有限可发现模式的推荐设置。

参见 Bluetooth 核心规范：

  • 6.0 第 3 卷第 C 部分附录 A“定时器与常量”，T_GAP(adv_fast_interval1)
  • 6.0 第 3 卷第 C 部分第 9.3.11 节“连接建立定时参数”

int bt_id_create ( bt_addr_le_t * addr,
uint8_t * irk )

#include <zephyr/bluetooth/bluetooth.h>

创建新的身份地址。

使用给定的地址和 IRK 创建新的身份地址。本函数可在调用 bt_enable 之前调用。但是，只有在 bt_enable 之后使用本 API，新的身份地址才会持久存储到 Flash 中。原因是持久设置会在 bt_enable 之后加载，因而可能与协议栈盲目覆盖 Flash 中所存内容产生潜在冲突。若提供了预定义地址，身份地址也不会写入 Flash，因为在这种情况下应用程序显然知道该地址的来源，并且能在每次上电时重复该过程，即在 Flash 中再存一份信息是多余的。

在 bt_enable 之前调用本函数时不支持生成随机静态地址或随机 IRK。

若应用程序希望由协议栈随机生成身份地址并存储到 Flash 中以便以后恢复，做法是先初始化协议栈（使用 bt_enable），然后调用 settings_load，之后再通过 bt_id_get 检查恢复了多少身份地址。若恢复的身份地址数量不足，应用程序可调用本函数创建新的身份地址。

注解
若启用了 CONFIG_BT_HCI_SET_PUBLIC_ADDR，首次调用可将公共地址设置为控制器的身份，但只能在 bt_enable 之前且不存在其他身份时进行。
