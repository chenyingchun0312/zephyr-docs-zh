◆ onoff_client_callback

typedef void(*) onoff_client_callback(struct onoff_manager *mgr, struct onoff_client *cli, uint32_t state, int res)

#include <zephyr/sys/onoff.h>

用于向开关服务客户端通知操作完成的签名。

这些函数可从任何上下文调用，包括内核前、ISR 或协作式、可抢占线程。兼容的函数必须支持 ISR 且不得睡眠。

参数
mgr发起该操作的管理器。若开关服务使用同步切换，则可以为 null。
cli传给发起该操作的函数的客户端结构体。
state完成时状态机的状态，受 ONOFF_STATE_MASK 限制。必须独立于 res 是否为负来检查 ONOFF_FLAG_ERROR，因为状态机错误可能表明除 onoff_reset() 之外的所有后续操作都将失败。
res操作的结果。期望值因服务而异，但操作成功时该值应为非负，操作失败时应为负。若 res 为负，则 state 中会置位 ONOFF_FLAG_ERROR；但若 res 为非负，state 中仍可能置位 ONOFF_FLAG_ERROR。

◆ onoff_monitor_callback

typedef void(*) onoff_monitor_callback(struct onoff_manager *mgr, struct onoff_monitor *mon, uint32_t state, int res)

#include <zephyr/sys/onoff.h>

用于向 onoff 服务的监视器通知错误或状态切换完成的签名。

这与 onoff_client_callback 类似，但提供所有切换的信息，而不只是与特定客户端相关联的切换。监视器回调在任何与状态变化相关联的完成通知之前被调用。

这些函数可从任何上下文调用，包括内核前、ISR 或协作式、可抢占线程。兼容的函数必须支持 ISR 且不得睡眠。

该回调可以注销自身，但不得注册或注销任何其他监视器。

参数
mgr切换已完成的那个管理器。
mon此通知所经由的监视器实例。
state完成时的状态机状态，受 ONOFF_STATE_MASK 限制。可能观察到所有有效状态。
res操作的结果。期望值因服务和状态而异，但操作成功时该值应为非负，操作失败时应为负。

◆ onoff_transition_fn

typedef void(*) onoff_transition_fn(struct onoff_manager *mgr, onoff_notify_fn notify)

#include <zephyr/sys/onoff.h>

服务实现用来执行切换的签名。

服务定义使用两个必需的此类型函数指针来获知需要切换，以及第三个可选的函数指针，用于在服务处于错误状态时重置服务。

start 函数仅从关闭状态调用。

stop 函数仅从开启状态调用。

reset 函数（若支持）仅在 onoff_has_error() 返回 true 时调用。

注解
所有切换函数都必须支持 ISR。
参数
mgr请求了切换的管理器。
notify切换完成时要调用的函数。若切换是同步的，实现必须在切换函数返回前调用 notify。否则实现必须保存此参数，并在切换完成时调用它。

◆ onoff_cancel()

int onoff_cancel ( struct onoff_manager * mgr,
struct onoff_client * cli )

#include <zephyr/sys/onoff.h>

尝试取消正在进行的客户端操作。

客户端可能已发起操作，但需要在操作完成前关闭。例如，已发出请求而该需求已不复存在。

取消仅支持 onoff_request() 和 onoff_reset() 操作，且为同步操作。请注意，任何代表客户端发起的切换都会继续进行到完成：可能被消除的只是切换完成的通知。若切换到开启完成时没有活动请求，管理器将发起切换到关闭。

被取消的操作不会产生客户端通知。

参数
mgr要取消其操作的管理器。
cli指向与被取消操作发出时相同的客户端状态的指针。
返回值
>=0若取消成功，则为取消时观察到的状态机状态。取消成功后，*cli 的所有权交还客户端。
-EINVAL若参数无效。
-EALREADY若在处理取消时 cli 不是未完成通知的记录。这通常表明该操作和客户端通知已经完成。

◆ onoff_cancel_or_release()

int onoff_cancel_or_release ( struct onoff_manager * mgr,
struct onoff_client * cli )
inlinestatic

#include <zephyr/sys/onoff.h>

安全取消请求的辅助函数。

某些应用程序可能希望在异步事件（例如连接到 USB 总线）上发出请求，并在配对事件（例如与 USB 总线断开连接）上释放。若不使用 onoff_monitor 并小心避免竞态条件，应用程序无法准确判断正在进行的请求是否仍处于待处理状态。

此函数是一个辅助函数，它尝试取消操作，并在因请求已完成而导致取消失败时发出释放。这会同步确保客户端数据的所有权交还客户端，以便用于未来的请求。

参数
mgr要取消其操作的管理器。
cli指向与调用 onoff_request() 时相同的客户端状态的指针。若这是与 onoff_reset() 请求相关联的客户端数据指针，则行为未定义。
返回值
ONOFF_STATE_TO_ON若取消发生在切换完成之前。
ONOFF_STATE_ON若取消发生在切换完成之后。
-EINVAL若参数无效。
<0onoff_release() 产生的其他错误。

测试开关服务是否已记录错误。

此函数可用于确定服务是否已记录错误。错误可通过调用 onoff_reset() 清除。

这是一个不加锁的便捷函数，仅当确知没有其他进程会调用使服务在错误与非错误状态之间切换的操作时才适合使用。

◆ onoff_reset()

int onoff_reset ( struct onoff_manager * mgr,

#include <zephyr/sys/onoff.h>

清除开关服务上的错误并将其重置为关闭状态。

仅当服务处于 onoff_has_error() 所指示的错误状态时才能重置。

返回值指示发起重置资源操作的成功或失败。若操作发起成功，重置操作本身的结果将通过所配置的客户端通知方式提供，可能在此调用返回之前就已提供。多个客户端可能请求重置；完成时它们都会被通知。

注意，即使实际重置失败，对此函数的调用也可能成功。请始终检查操作的完成结果。

注解
由于状态切换的条件，所有未完成的异步操作在错误发生时都已被告知该错误。因此无需担心重置完成后会残留悬空请求。
参数
mgr要重置的管理器。
cli指向客户端状态的指针，其中包含重置完成时如何通知客户端的说明。若 cli 引用与未完成服务操作相关联的对象，则行为未定义。
返回值
>=0若重置成功，则为重置时观察到的状态机状态。
-ENOTSUP若服务不支持重置。
-EINVAL若参数无效。
-EALREADY若服务没有已记录的错误。

◆ onoff_sync_finalize()

int onoff_sync_finalize ( struct onoff_sync_service * srv,
k_spinlock_key_t key,
struct onoff_client * cli,
int res,
bool on )

#include <zephyr/sys/onoff.h>

处理同步服务中切换的完成并释放锁。

此函数根据 res 和 on 参数更新服务状态，然后释放锁。若 cli 不为 null，则使用 res 完成客户端通知。

若加锁时服务处于错误状态，且终结时 res 为非负，则在完成终结前将计数重置为零。

参数
srv指向同步服务状态的指针
key前一次调用 onoff_sync_lock() 返回的键。
cli指向用于返回完成信息的 onoff 客户端的指针。若传入空指针，则只更新服务的状态。为了与配合管理器 API 使用的回调行为兼容，当 on 为 false 时 cli 必须为 null（管理器在关闭设备时不支持回调）。
res切换的结果。负值使服务进入错误状态。非负值按 on 的指定递增或递减引用计数。
on仅当 res 为非负时，若 on 为 true，服务引用计数将递增；若 on 为 false，则递减。
返回
若服务处于或进入错误状态则为负，否则为释放锁时的活动请求数量。
