◆ video_closest_frmival()

int video_closest_frmival ( const struct device * dev,
struct video_frmival_enum * match )

在视频设备中查找与某个帧间隔值最接近的匹配

要计算最接近的匹配，请为 match 填充以下字段：

  • 将 match->format 设为感兴趣的 video_format。
  • 将 match->type 设为 VIDEO_FRMIVAL_TYPE_DISCRETE。
  • 将 match->discrete 设为所需的帧间隔。

结果将载入 match，并设置以下字段：

  • 将 match->discrete 设为最接近的帧间隔的值。
  • 将 match->index 设为最接近的帧间隔的索引。
参数
dev要查询的视频设备。
match带有查询条件并被载入结果的帧间隔枚举器。
返回值
0If successful.

◆ video_get_csi_link_freq()

int64_t video_get_csi_link_freq ( const struct device * dev,
uint8_t bpp,
uint8_t lane_nb )

返回设备所通告的链路频率

对外提供 CSI 链路的设备应至少通告以下两个控制之一：

  • VIDEO_CID_LINK_FREQ
  • VIDEO_CID_PIXEL_RATE

首先该辅助函数会尝试读取 VIDEO_CID_LINK_FREQ，若不可用，则根据 VIDEO_CID_PIXEL_RATE 的值并考虑格式的每像素位数和通道数来估算链路频率。

参数
dev要查询的视频设备。
bpp设备所产生像素格式的每像素位数
lane_nb使用的 CSI-2 通道数

◆ video_query_ctrl()

int video_query_ctrl ( struct video_ctrl_query * cq)

查询某个控制的信息。

应用程序设置查询结构体的 id 字段，函数填充该结构体的其余部分。可以通过从 VIDEO_CID_BASE 开始、依次递增 id 直到 VIDEO_CID_LASTP1（不含）调用此函数来枚举基类控制（即 VIDEO_CID_BASE + x）。若该范围内的某个控制不受支持，函数可能返回 -ENOTSUP。应用程序也可以从 VIDEO_CID_PRIVATE_BASE 开始并递增 id，直到驱动返回 -ENOTSUP 来枚举私有控制。对于其他控制类则稍难。因此，枚举设备所支持的全部控制的最佳方式是用 VIDEO_CTRL_FLAG_NEXT_CTRL 进行迭代。

参数
cq指向控制查询结构体的指针。
返回值
0成功时。
-EINVAL控制 ID 无效。
-ENOTSUP控制 ID 不受支持。

将视频格式能力从 m2m 视频设备的一端转换到另一端。

该函数将 video_format_cap 从 m2m 视频设备的一端转换到另一端。它使应用程序能够在给定另一端单个输入能力的情况下，迭代获取设备一端的所有受支持能力。

应用程序将单个输入能力和单个 res_cap 的地址，连同 res_cap 的类型和用于迭代的索引（从 0 开始）一起传给该函数。驱动填充 res_cap 结构体并每次返回 0。应递增索引以获取下一个 res_cap，直到函数返回某个 errno（例如 -EINVAL）。例如：

struct video_format_cap cap = {.pixelformat = VIDEO_PIX_FMT_RGB565};
struct video_format_cap res_cap = {0};
uint8_t ind = 0;
while (video_transform_cap(dev, &cap, &res_cap, VIDEO_BUF_TYPE_OUTPUT, ind) == 0) {
// Process output_cap here
ind++;
}
