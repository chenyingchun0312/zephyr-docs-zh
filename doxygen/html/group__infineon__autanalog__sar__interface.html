注解
这些厂商函数不会与 adc_read() 串行化，不得在同一设备上进行 ADC 转换时并发调用。它们访问唯一的共享 SAR，与进行中的读取（包括异步 adc_read_async()）重叠的调用可能破坏转换或 FIR 配置。调用方负责确保没有正在进行的转换，例如从执行读取的同一线程中调用它们。

◆ adc_ifx_autanalog_sar_stream_stop()

int adc_ifx_autanalog_sar_stream_stop ( const struct device * dev)

#include <zephyr/drivers/adc/infineon_autanalog_sar.h>

停止活动的 RTIO ADC 流并拆除其软件状态。

将 SAR 序列器切回单次模式并停止自由运行（连续）SAR。它会清除流式状态，并以 -ECANCELED 终止进行中的 RTIO 提交（若有）。此函数返回后，SAR 处于空闲状态，共享序列器可供后续的 adc_read() 使用，并且可以用新的 adc_stream() 调用重新启动流式传输。

硬件 FIFO 保持原样：已捕获的样本会被保留，因此应用程序可以停止流式传输后再恢复而不丢失数据。单次 adc_read() 读取的是结果寄存器而非 FIFO，因此保留的样本不会影响它。

调用方必须先取消该流的多重采样 SQE 句柄（rtio_sqe_cancel()），再调用本函数，以便 RTIO 不会重新提交并重启该流。

参数
devADC 设备（infineon,autanalog-sar-adc 实例）。
返回值
0成功时。
-EALREADY当前没有活动流时。
-EBUSY最终转换后 SAR 未返回空闲状态时。
