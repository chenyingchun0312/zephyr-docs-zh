◆ lora_cad_mode

enum lora_cad_mode

#include <zephyr/drivers/lora.h>

信道活动检测模式

控制发送/接收操作是否在实际操作之前执行 CAD。

枚举值
LORA_CAD_MODE_NONE 

不执行 CAD（默认）

LORA_CAD_MODE_RX 

接收前 CAD：lora_recv() 先执行 CAD，若未检测到活动则立即返回 0。若需持续低功耗监听，建议改用 lora_recv_duty_cycle_async instead.

LORA_CAD_MODE_LBT 

先听后说：lora_send() 在发送前执行 CAD，若信道忙则返回 -EBUSY。

◆ lora_coding_rate

enum lora_coding_rate

#include <zephyr/drivers/lora.h>

LoRa 编码率

该枚举定义用于前向纠错（FEC）的 LoRa 编码率。

编码率表示为 4/x，分母越小（如 4/5）冗余越少，数据速率越高但鲁棒性越差。冗余越大（如 4/8）容错能力越强，但以数据速率为代价。

枚举值
CR_4_5 

编码率 4/5（4 个信息位、1 个纠错位）

CR_4_6 

编码率 4/6（4 个信息位、2 个纠错位）

CR_4_7 

编码率 4/7（4 个信息位、3 个纠错位）

CR_4_8 

编码率 4/8（4 个信息位、4 个纠错位）

LoRa 数据速率

该枚举表示 LoRa 信号的数据速率，以扩频因子（SF）表示。

扩频因子决定编码每个符号所用的 chirp 数量（每符号 2^SF 个 chip）。取值越大数据速率越低，但通信距离和鲁棒性越好。

◆ lora_energy_detect()

int lora_energy_detect ( const struct device * dev,
int16_t rssi_threshold,
k_timeout_t duration )

#include <zephyr/drivers/lora.h>

执行能量检测载波侦听

将射频置于接收模式并重复采样 RSSI，持续 duration. The channel is reported busy as soon as one sample reaches rssi_threshold, and clear if the window elapses without that happening.

与 lora_cad 不同，它会对信道上的任何能量作出反应，而不只针对 LoRa 前导码。侦听在调制解调器最近一次由 lora_config 或 lora_config_gfsk 设置的带宽上进行。

注解
这是阻塞式调用。
参数
devLoRa 设备
rssi_threshold判定信道忙的电平阈值，以 dBm 计
duration载波侦听窗口，不能为 K_NO_WAIT 或 K_FOREVER
返回
信道空闲时为 0
信道忙时为 1
duration 为 K_NO_WAIT 或 K_FOREVER 时为 -EINVAL
调制解调器正在使用中时为 -EBUSY
驱动既不支持 RSSI 也不支持异步接收时为 -ENOSYS
其他错误时为负值

射频在睡眠与监听 LoRa 前导码之间自动交替。该函数阻塞直至接收到有效数据包或操作超时，然后停止占空比循环。

启动接收占空比循环（radio 唤醒）

射频在睡眠与监听 LoRa 前导码之间自动交替。接收到有效数据包时会调用 cb。占空比循环会持续，直到以 cb = NULL 调用该函数将其取消。

发送方必须使用比（sleep_period + rx_period）更长的前导码，以保证被检测到。

cb接收到数据包时的回调。为 NULL 则取消。
user_data传递给回调的用户数据
返回
成功时为 0，出错时为负值
