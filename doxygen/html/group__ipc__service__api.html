◆ ipc_service_get_tx_buffer()

int ipc_service_get_tx_buffer ( struct ipc_ept * ept,
void ** data,
uint32_t * size,
k_timeout_t wait )

#include <zephyr/ipc/ipc_service.h>

获取一个空 TX 缓冲区，以便使用 ipc_service_send_nocopy 发送

可以调用此函数获取一个空 TX 缓冲区，使应用程序能直接将数据放入发送缓冲区，而无需从应用程序缓冲区复制。

应用程序有责任正确地用数据填充所分配的 TX 缓冲区，并向 ipc_service_send_nocopy 函数传递正确的参数，以实现数据无复制发送机制。

可以使用 size 参数请求特定大小的缓冲区：

  • 如果可容纳该大小，函数不返回错误并分配缓冲区
  • 如果请求的大小过大，函数返回 -ENOMEM，并且不分配缓冲区。
  • 如果请求的大小为 '0'，则按允许的最大大小分配缓冲区。

在所有情况下，返回时 size 参数都包含所返回缓冲区的最大大小。

当函数不返回错误时，缓冲区被视为已分配，并在两种条件下被释放：(1) 使用以下方式发送该缓冲区时 ipc_service_send_nocopy (and in this case the buffer is automatically released by the backend), (2) when using ipc_service_drop_tx_buffer on a buffer not sent.

参数
[in]ept通过 ipc_service_register_endpoint 注册的端点。
[out]data指向该空 TX 缓冲区的指针。
[in,out]size用于存储所请求 TX 缓冲区大小的指针。如果函数返回 -ENOMEM，此参数返回允许的最大大小。
[in]wait等待可用 TX 缓冲区超时。
返回值
-EIO当没有注册后端，或后端缺少 send 钩子时。
-EINVAL当实例或端点无效时。
-ENOENT当端点未注册到该实例时。
-ENOTSUP当后端不支持该操作或超时时。
-ENOBUFS当没有可用的 TX 缓冲区时。
-EALREADY当已有缓冲区被占用且尚未释放时。
-ENOMEM当请求的大小过大时（此时 size 参数包含允许的最大大小）。
0成功时。
other取决于后端实现的 errno 错误码。

◆ ipc_service_hold_rx_buffer()

int ipc_service_hold_rx_buffer ( struct ipc_ept * ept,
void * data )

#include <zephyr/ipc/ipc_service.h>

保留 RX 缓冲区，以便在接收回调之外使用。

调用此函数可防止接收缓冲区被释放回 shmem 缓冲区池。当用户不希望在回调内部复制消息时，可以在接收回调中调用此函数。

处理完消息后，应用程序必须使用 ipc_service_release_rx_buffer 函数释放缓冲区。

参数
[in]ept通过 ipc_service_register_endpoint 注册的端点。
[in]data指向要保留的 RX 缓冲区的指针。
返回值
-EIO当没有注册后端，或后端缺少 release 钩子时。
-EINVAL当实例或端点无效时。
-ENOENT当端点未注册到该实例时。
-EALREADY当缓冲区数据已被保留时。
-ENOTSUP当后端不支持此操作时。
0成功时。
other取决于后端实现的 errno 错误码。

◆ ipc_service_send_critical()

int ipc_service_send_critical ( struct ipc_ept * ept,
const void * data,
size_t len )

#include <zephyr/ipc/ipc_service.h>

绕过正常状态检查发送高优先级消息。

此函数使用后端在特殊的快速路径上发送高优先级消息，该路径跳过正常的状态和繁忙检查。它适用于崩溃报告、致命错误或紧急关机信号等关键系统通知，这些通知即使在 IPC 通道被认为繁忙或阻塞时也必须送达。

警告：此函数只应用于关键系统通知。误用可能导致数据损坏或系统不稳定。后端必须支持此操作。

参数
[in]ept通过 ipc_service_register_endpoint 注册的端点。
[in]data指向要发送的关键消息缓冲区的指针。
[in]len要发送的字节数。
返回值
-EIO当没有注册后端，或后端缺少 send_critical 钩子时。
-EINVAL当实例或端点无效时。
-ENOENT当端点未注册到该实例时。
-EBADMSG当数据无效时（例如数据格式无效、长度超过后端限制……）。
-ENOTSUP当后端不支持该操作时。
-ENOMEM当连关键路径缓冲区也耗尽时。
bytes已发送的字节数。
other取决于后端实现的 errno 错误码。

◆ ipc_service_send_nocopy()

int ipc_service_send_nocopy ( struct ipc_ept * ept,
const void * data,
size_t len )

#include <zephyr/ipc/ipc_service.h>

使用给定的 IPC 端点发送由 ipc_service_get_tx_buffer 预留的 TX 缓冲区中的数据。

这等同于 ipc_service_send，但此处的 TX 缓冲区是通过 ipc_service_get_tx_buffer 获得的。

应用程序必须负责使用 ipc_service_get_tx_buffer 获取 TX 缓冲区，并用数据填充该 TX 缓冲区。

调用 ipc_service_send_nocopy 函数后，TX 缓冲区不再归发送任务所有，除非函数失败并返回错误，否则不得再访问它。

如果此函数返回错误，可以使用 ipc_service_drop_tx_buffer 丢弃该 TX 缓冲区。

参数
[in]ept通过 ipc_service_register_endpoint 注册的端点。
[in]data指向待发送缓冲区的指针，该缓冲区通过 ipc_service_get_tx_buffer 获得。
[in]len要发送的字节数。
返回值
-EIO当没有注册后端，或后端缺少 send 钩子时。
-EINVAL当实例或端点无效时。
-ENOENT当端点未注册到该实例时。
-EBADMSG当数据无效时（例如数据格式无效、长度无效……）
-EBUSY当实例繁忙时。
bytes已发送的字节数。
other取决于后端实现的 errno 错误码。
