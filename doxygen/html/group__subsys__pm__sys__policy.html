◆ pm_policy_event_register()

void pm_policy_event_register ( struct pm_policy_event * evt,
int64_t uptime_ticks )

#include <zephyr/pm/policy.h>

注册事件。

在电源管理策略的上下文中，事件被定义为将在未来已知时间唤醒系统的任何来源。通过注册此类事件，策略管理器将能够判断是否值得进入某些电源状态。

事件以运行时间节拍跟踪，策略在计算距下次唤醒的时间时使用最早（最近）的事件时间。

同一个 evt 在任一时刻最多只能注册一次。重复注册已注册的事件等同于调用 pm_policy_event_update()。

被唤醒后，CPU 应保持唤醒状态，直到事件被处理完毕，这通过 pm_policy_event_unregister() 或使用 pm_policy_event_update() 将该事件移到将来来表示。

参数
evtEvent.
uptime_ticks事件将发生的时间，以运行时间节拍表示。
参见
pm_policy_event_unregister()

◆ pm_policy_next_custom_ticks()

int64_t pm_policy_next_custom_ticks ( void )

#include <zephyr/pm/policy.h>

为 PM 策略获取自定义下一事件的节拍数。

此可选钩子允许提供一个额外的“下一事件”节拍值，该值源自未通过 pm_policy_next_event_ticks() 建模的专有或硬件特定来源。

与 pm_policy_next_event_ticks() 一样，返回值在做出休眠决策之前会被饱和到 SYS_CLOCK_MAX_WAIT，因此钩子可以报告任意远的事件，而无需针对 32 位上限做特殊处理。

注意
Available only when the following Kconfig option is enabled: CONFIG_PM_CUSTOM_TICKS_HOOK.
返回
如果下一个自定义事件在将来，则为正的节拍数。
返回值
0下一个自定义事件是当前或已过去。
-1没有待处理的自定义事件。

◆ pm_policy_next_event_ticks()

int64_t pm_policy_next_event_ticks ( void )

#include <zephyr/pm/policy.h>

返回距下一个事件的节拍数

返回以运行时间节拍表示的相对超时时间，直到最早（最近）的已注册事件。

返回值遵循以下规则：

  • 如果至少注册了一个事件且其排定时间在将来，则返回距该事件的节拍数。
  • 如果最早的事件当前到期或已过去，则返回 0。
  • 如果没有注册任何事件，则返回 -1。

返回的节拍数不受休眠决策所使用的 32 位上限约束：pm_system_suspend() 会在把它传给 pm_policy_next_state() 之前将其饱和到 SYS_CLOCK_MAX_WAIT。因此，比该上限更远的事件与恰好位于该上限的事件会选择相同的状态，且永远不会被截断。

返回
如果下一个已注册事件在将来，则为正的节拍数。
返回值
0下一个已注册事件是当前或已过去。
-1没有注册任何事件。

◆ pm_policy_state_lock_get()

void pm_policy_state_lock_get ( enum pm_state state,
uint8_t substate_id )

#include <zephyr/pm/policy.h>

递增电源状态锁计数器。

首次调用 pm_policy_state_lock_get() 时不会允许某个电源状态。后续调用只会递增引用计数，因此可以安全地并发使用此 API。当 pm_policy_state_lock_put() 的调用次数与 pm_policy_state_lock_get() 相同时，该状态将重新被允许。

请注意，PM_STATE_ACTIVE 状态始终被允许，因此以 PM_STATE_ACTIVE 调用此 API 不会产生任何效果。

参数
state电源状态。
substate_id电源子状态 ID。使用 PM_ALL_SUBSTATES 可影响给定电源状态下的所有子状态。
