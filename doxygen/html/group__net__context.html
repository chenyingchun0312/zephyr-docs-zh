◆ net_context_setup_pools

#define net_context_setup_pools ( context,
tx_slab,
data_pool )

#include <zephyr/net/net_context.h>

为上下文发送操作设置自定义网络缓冲区池

设置 IP 协议栈在向网络发送数据时用于为上下文分配网络缓冲区的自定义网络缓冲区池。使用专用缓冲区有助于使给定上下文上的发送操作更可靠，例如不会因其他网络上下文上的操作而出现缓冲区饥饿。缓冲区池按上下文设置，但多个上下文可以共享相同的缓冲区。注意，不支持按上下文自定义接收数据包池。

参数
context将使用给定 net_buf 池的上下文。
tx_slab指向将向调用方返回 TX 池的函数的指针。发送数据到网络时使用 TX 池。每个发送的网络数据包对应一个 TX net_pkt。
data_pool指向将向调用方返回 DATA 池的函数的指针。DATA 池用于存储发送到网络的数据。

◆ net_context_connect_cb_t

typedef void(*) net_context_connect_cb_t(struct net_context *context, int status, void *user_data)

#include <zephyr/net/net_context.h>

连接回调。

连接回调在连接正在建立之后被调用。对于 TCP 连接，此回调由 RX 线程调用，因此这里使用的是其栈和执行上下文。回调在 TCP 连接建立之后或连接失败时被调用。请保持回调中的处理尽量简短，以减少处理数据包时的阻塞时间。对于 UDP 连接，此回调由 net_context_connect() 函数立即调用。UDP 是无连接协议，因此可以认为连接会立即建立。

参数
context要使用的上下文。
status连接建立的状态。如果连接成功建立则为 0，如果出错则小于 0。
user_data在 net_context_connect() 调用中给出的用户数据。

◆ net_context_recv_cb_t

typedef void(*) net_context_recv_cb_t(struct net_context *context, struct net_pkt *pkt, union net_ip_header *ip_hdr, union net_proto_header *proto_hdr, int status, void *user_data)

#include <zephyr/net/net_context.h>

网络数据接收回调。

recv 回调在收到网络数据包之后被调用。此回调由 RX 线程调用，因此这里使用的是其栈和执行上下文。请保持回调中的处理尽量简短，以减少处理数据包时的阻塞时间。

参数
context要使用的上下文。
pkt收到的网络缓冲区。如果 pkt 不为 NULL，则回调将拥有该缓冲区，并且需要在处理完毕后尽快对 pkt 进行 unref。在 EOF 时，pkt 将为 NULL。
ip_hdr指向相关 IP（v4 或 v6）头部的指针。
proto_hdr指向相关协议（udp 或 tcp）头部的指针。
status如果有数据或连接处于 EOF，则该值设为 0；如果接收数据出错则小于 0，此时 pkt 参数将设为 NULL。
user_data在 net_recv() 调用中给出的用户数据。

更新上下文的 TCP 接收窗口。

此函数应由不在其接收回调中完整处理传入数据、而是将其排队的应用程序使用。在这种情况下，接收回调应按排队数据的大小减小窗口（用负值调用此函数），而将数据出队的函数则用与出队大小对应的正值调用。例如，如果接收回调收到数据大小为 256 的数据包并将其排队，则应使用 -256 的增量调用此函数。如果某个函数取出 10 字节的排队数据，则应使用 10 的增量调用它。

参数
context要使用的 TCP 网络上下文。

返回
成功时为 0，出错时 < 0
