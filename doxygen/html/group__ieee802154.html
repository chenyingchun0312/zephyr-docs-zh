IEEE 802.15.4 原生与 OpenThread 的 L2、配置、管理和驱动 API

自从
1.0
版本
0.8.0

IEEE 802.15.4 与 Thread 子系统包括 OpenThread L2 子系统、原生 IEEE 802.15.4 L2 子系统（"Soft" MAC）、一个大多与厂商和协议无关的驱动 API（由 OpenThread 与原生 L2 协议栈共享，即 "Hard" MAC 和 PHY），以及用于配置该子系统的若干 API（shell、网络管理、Kconfig、设备树等）。

OpenThread 子系统 API 将外部的 OpenThread 协议栈集成到 Zephyr 中。它建立在 Zephyr 原生 IEEE 802.15.4 驱动 API 之上。

原生 IEEE 802.15.4 子系统 API 在不同层次上提供，面向多类使用者：

  • shell（最终用户、应用程序开发者）：
    • 一组 IEEE 802.15.4 shell 命令（参见 shell> IEEE 802.15.4 与 Thread API help）
  • 应用程序 API（应用程序开发者）：
    • 用于节点之间实际点对点、多播和广播数据交换的 IPv6、DGRAM 和 RAW 套接字，包括连接特定的配置（示例即将推出，目前可参见 https://github.com/linux-wpan/wpan-tools/tree/master/examples，它启发了我们的 API，因此具有类似的套接字 API），
    • Kconfig 与设备树配置选项（网络配置库扩展、子系统范围的 MAC 和 PHY Kconfig/DT 选项、驱动/厂商特定的 Kconfig/DT 选项，注意带有 IEEE802154/ieee802154 前缀的选项），
    • 网络管理：在 MAC（L2）和 PHY（L1）层对 IEEE 802.15.4 协议栈进行运行时配置（参见 ieee802154_mgmt），
  • L2 集成（子系统贡献者）：
    • 参见 IEEE 802.15.4 L2
    • 实现 Zephyr 内部的 L2 层套接字与网络上下文抽象（上下文/套接字操作，参见 net_l2），
    • 对接口结构的协议特定扩展（参见 net_if）
    • 对网络报文结构的协议特定扩展（参见 net_pkt），
  • OpenThread 与原生 IEEE 802.15.4 共享一个通用的 驱动 API\ （驱动维护者/贡献者）：
    • 参见 IEEE 802.15.4 驱动
    • 所有驱动都需实现的基本的、主要位于 PHY 层的驱动 API，
    • 若干 "hard MAC"（硬件/固件卸载）扩展点，用于协议中对性能关键或对时序敏感的部分
  • 生成于 , 为 Zephyr API 参考使用 1.18.0
