◆ counter_set_guard_period()

int counter_set_guard_period ( const struct device * dev,
uint32_t ticks,
uint32_t flags )

#include <zephyr/drivers/counter.h>

以计数器定时计数为单位设置保护期。

当设置接近当前计数值的绝对闹钟值时，存在一种风险：在驱动成功激活闹钟之前，计数器已经越过该绝对值。若这一点未被察觉，那么闹钟只有在定时器回绕并在一个完整定时器周期后再次到达该绝对值时才会到期。对于 32 位定时器，这可能要等很长时间。设置足够大的保护期有助于驱动无歧义地检测是否已经太晚。

保护期应等于驱动在调用驱动 API 之后实际激活闹钟最多需要的定时计数数。若驱动发现计数器刚刚越过给定绝对定时计数值但仍足够接近而落在保护期内，它会认为已经“太晚”，即预期的到期时间已经过去。根据 COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE 标志，驱动在这种情况下会忽略该闹钟或立即使其到期。

然而，若计数器已越过给定绝对定时计数值但处于保护期之外，则驱动会认为这是有意为之，并让计数器回绕到零或从零开始再到期。

更准确地说：

  • 向上计数时（参见 COUNTER_CONFIG_INFO_COUNT_UP），若计数器越过给定绝对定时计数值的幅度小于 guard_period 个定时计数，则闹钟被判定为“太晚”并拒绝：(now - target) % top_value < guard_period。否则接受该闹钟（target 仍在未来，或已过去足够远，被视为有意的未来回绕）。
  • 向下计数时，若满足 (target - now) % top_value < guard_period，则闹钟“太晚”。否则接受该闹钟。

示例：

  • 向上计数，now = 4950，顶部值 = 5000，保护期 = 100：太晚区间：(4950 - target) % 5000 < 100，即 target 在 [4851, 4950]；接受区间：target 在 [0, 4850] 或 [4951, 4999]
  • 向下计数，now = 50，顶部值 = 5000，保护期 = 100：太晚区间：(target - 50) % 5000 < 100，即 target 在 [50, 149]；接受区间：target 在 [0, 49] 或 [150, 4999]

若只需要短的闹钟周期，可以将保护期设得很高（例如计数器顶部值的一半），这样可以极大地降低计数器意外回绕的可能性。

初始化时保护期设为 0（无保护）。

uint64_t ticks,
uint32_t flags )

#include <zephyr/drivers/counter.h>

以计数器定时计数为单位设置 64 位保护期。

当设置接近当前计数值的绝对闹钟值时，存在一种风险：在驱动成功激活闹钟之前，计数器已经越过该绝对值。若这一点未被察觉，那么闹钟只有在定时器回绕并在一个完整定时器周期后再次到达该绝对值时才会到期。对于 32 位定时器，这可能要等很长时间。设置足够大的保护期有助于驱动无歧义地检测是否已经太晚。

保护期应等于驱动在调用驱动 API 之后实际激活闹钟最多需要的定时计数数。若驱动发现计数器刚刚越过给定绝对定时计数值但仍足够接近而落在保护期内，它会认为已经“太晚”，即预期的到期时间已经过去。根据 COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE 标志，驱动在这种情况下会忽略该闹钟或立即使其到期。

然而，若计数器已越过给定绝对定时计数值但处于保护期之外，则驱动会认为这是有意为之，并让计数器回绕到零或从零开始再到期。

更准确地说：

  • 向上计数时（参见 COUNTER_CONFIG_INFO_COUNT_UP），若计数器越过给定绝对定时计数值的幅度小于 guard_period 个定时计数，则闹钟被判定为“太晚”并拒绝：(now - target) % top_value < guard_period。否则接受该闹钟（target 仍在未来，或已过去足够远，被视为有意的未来回绕）。
  • 向下计数时，若满足 (target - now) % top_value < guard_period，则闹钟“太晚”。否则接受该闹钟。

示例：

  • 向上计数，now = 4950，顶部值 = 5000，保护期 = 100：太晚区间：(4950 - target) % 5000 < 100，即 target 在 [4851, 4950]；接受区间：target 在 [0, 4850] 或 [4951, 4999]
  • 向下计数，now = 50，顶部值 = 5000，保护期 = 100：太晚区间：(target - 50) % 5000 < 100，即 target 在 [50, 149]；接受区间：target 在 [0, 49] 或 [150, 4999]

若只需要短的闹钟周期，可以将保护期设得很高（例如计数器顶部值的一半），这样可以极大地降低计数器意外回绕的可能性。

初始化时保护期设为 0（无保护）。

flagsSee COUNTER_GUARD_PERIOD_FLAGS.

◆ counter_set_top_value()

int counter_set_top_value ( const struct device * dev,
const struct counter_top_cfg * cfg )

#include <zephyr/drivers/counter.h>

设置计数器顶部值。

该函数设置顶部值，并可选地根据计数方向将计数器复位为 0 或顶部值。回绕时，计数器可以复位，并会周期性调用可选回调。只有在没有活动通道闹钟时才能更改顶部值。

COUNTER_TOP_CFG_DONT_RESET prevents counter reset. When counter is running while top value is updated, it is possible that counter progresses outside the new top value. In that case, error is returned and optionally driver can reset the counter (see COUNTER_TOP_CFG_RESET_WHEN_LATE).

警告
启用 CONFIG_COUNTER_64BITS_TICKS 时，该函数设置最大顶部值的低 32 位。若预计会超过 32 位，请使用 counter_set_top_value_64() 设置完整的 64 位值。
参数
dev指向该驱动实例设备结构的指针。
cfg配置。不可为 NULL。
返回值
0成功时。
-ENOTSUP请求不受支持（例如顶部值无法更改，或更新顶部值期间计数器不能/必须不复位）。
-EBUSY有任何闹钟处于活动状态。
-ETIME设置了 COUNTER_TOP_CFG_DONT_RESET，且新的顶部值小于当前计数值（计数器向上计数）。
