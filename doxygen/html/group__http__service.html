定义静态 HTTP 资源

静态 HTTP 资源是在系统初始化之前就已知的资源。相对地，动态资源可能在系统初始化时被发现。动态资源也可能在运行时由系统内部或外部产生的事件插入或移除。

注解
_resource 是不含关联协议、主机或 URL 参数的 URL。例如 http://www.foo.com/bar/baz.html#param1=value1 对应的资源为 /bar/baz.html。它通常被称为 URL 的“路径”。每个 (service, resource) 对都应唯一。_resource 必须非 NULL。
参数
_name资源名称。
_service关联服务的名称。
_resource标识该资源的类路径字符串。
_detail与该资源关联的实现特定详细信息。

定义带静态资源的 HTTP 服务。

注解
_host 参数用于指定 IPv4 或 IPv6 格式的 IP 地址、完全限定的主机名或虚拟主机。如果留为 NULL，则监听端口将监听所有地址。
_port 参数必须非 NULL。它指向一个用于指定该服务所用端口号的位置。若指定的端口号为零，则将使用临时端口号，实际分配的端口号会被写回该内存。对于临时端口号，_port 所指向的内存必须可写。
参数
_name服务的名称。
_host与该服务关联的 IP 地址或主机名。
[in,out]_port指向与该服务关联的端口的指针。
_concurrent最大并发客户端数量。（最大 CONFIG_HTTP_SERVER_MAX_CLIENTS）
_backlog最大排队连接数量。（最小 1）
_detail用户定义的、与该服务关联的详细信息。
_res_fallback当没有其他资源匹配路径时提供的回退资源
_config指向 http_service_config 结构体的指针（可为 NULL，表示默认行为）

typedef int(*) http_socket_create_fn(const struct http_service_desc *svc, int af, int proto)

#include <zephyr/net/http/service.h>

自定义套接字创建函数类型

允许按用户需求定制 HTTP 服务。例如，可用它创建带自定义选项的套接字，或为特定服务创建不同类型的套接字。

参数
svc正在为其创建套接字的 HTTP 服务描述。
af要创建的套接字的地址族（例如 AF_INET 或 AF_INET6）。
proto要创建的套接字的协议（例如 IPPROTO_TCP）。
返回
成功时返回有效的套接字文件描述符，失败时返回负的错误码。
