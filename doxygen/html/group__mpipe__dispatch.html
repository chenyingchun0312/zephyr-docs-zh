详细描述

元素之间交换的查询和事件。

当元素发送的不是数据时，它通过 pad 链接交给对端的东西就是派发。派发是以下两者之一：

  • 一个 **查询**，传给 mpipe_pad_query()：对端就地作答，因此询问方从该派发中读回答案；
  • 一个 **事件**，传给 mpipe_pad_send_event()：由对端据以动作并转发的单向通告。

一个固定大小的结构承载这两种内容，因为协商不得分配任何内存。派发也不是 mpipe_message：消息沿总线向上到达应用程序，而派发跨越两个元素之间的 pad 链接传递。

结构本身并不指明它是两者中的哪一种。类型指明派发的内容，而传给它的函数决定它是询问还是通告：

| 类型 | 作为查询 | 作为事件 | | :— | :— | :— | | CAPS | 给定此过滤器，你能接受什么？ | 这是格式，请应用它 | | BUFFER_POOL | 你需要什么缓冲区？ | - | | EOS | - | 流已结束 |
