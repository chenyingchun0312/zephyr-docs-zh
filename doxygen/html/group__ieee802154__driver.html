详细描述

IEEE 802.15.4 驱动 API

自从
1.0
版本
0.8.0

此 API 为原生 IEEE 802.15.4 L2 和 OpenThread 协议栈提供厂商特定硬件与固件的通用表示。**应用程序开发者绝不应直接使用此 API。** 它仅对驱动维护者有意义。

IEEE 802.15.4 驱动 API 由两个独立部分组成：

  • 所有驱动都需实现的基本的、主要位于 PHY 层的驱动 API，
  • 若干可选的 MAC 层扩展点，用于将 MAC 层中对性能关键或对时序敏感的方面卸载到驱动的硬件或固件（"hard" MAC）。

实现基本驱动 API 可确保与原生 L2 协议栈集成，并提供对 OpenThread 的基本支持。视硬件而定，可能需要卸载到厂商特定的硬件或固件特性，才能完全符合 Thread 协议或 IEEE 802.15.4 子协议（例如足够快的 ACK 包、TSCH 或 CSL 子协议中定时 TX/RX 的精确时序）。

是否需要实现 MAC 层卸载扩展点，由各驱动维护者决定。上层应尽可能提供 "soft" MAC 回退。

注解
所有章节、表格和插图引用均指 IEEE 802.15.4-2020 标准。

IEEE802154_CONFIG_RX_SLOT 

设置或取消无线接收窗口（RX 时隙）。可用于任何调度式接收，例如：Zigbee GP 设备、CSL、TSCH 等。

RX 时隙的 start 和 duration 参数相对于网络子系统的本地时钟。若 RX 时隙的 start 参数为 -1，则应立即取消任何之前配置的 RX 时隙。若 start 参数为任何过去的值（包括 0）或 duration 参数为零，则接收机应始终保持关闭，直到该 RX 时隙被移除或重新配置为指向将来的启动时间。若在上一 RX 时隙仍被调度时配置 RX 时隙，则应取消上一时隙并改为调度新时隙。

驱动处于 "DOWN" 状态时也可编程 RX 时隙。若在调用 start() 时存在任何过去或将来的 RX 时隙，则接口应被置为 "UP" 状态，但接收机不应启动。

驱动应自行异步地、自动地在 RX 时隙前后启动/停止接收机。驱动应在 RX 时隙开始前刚刚恢复供电，并在时隙结束后再次挂起，除非另有已编程事件迫使驱动不挂起。驱动应在 RX 时隙前切换到所编程的信道，并在时隙结束后切回用 set_channel() 设置的信道。若 RX 时隙的启动时间到来时驱动接口处于 "DOWN" 状态，则不应观察该 RX 时隙，且接收机应保持关闭。

若配置 RX 时隙时驱动处于 "UP" 状态，则驱动应立即关闭接收机，并将驱动置于尽可能低的省电模式（可以是异步的），直到 RX 时隙开始。若删除 RX 时隙时驱动处于 "UP" 状态，则驱动应立即启用接收机。此种情况下，接收机必须在 configure() 操作返回前准备好接收报文。

此行为意味着，设置 RX 时隙会隐式将 MAC PIB 属性 macRxOnWhenIdle（参见第 8.4.3.1 节、表 8-94）置为 "false"，而删除 RX 时隙会隐式将 macRxOnWhenIdle 置为 "true"。

注解
需要 IEEE802154_HW_RXTIME 能力，且在任意接口工作状态下均可用。

IEEE802154_CONFIG_CSL_PERIOD 

将设备启用或禁用为 CSL 接收器，并配置其 CSL 周期。

以 10 个符号周期为单位配置 CSL 周期。大于零的值在驱动支持 CSL 时启用 CSL，设备随后开始作为 CSL 接收器工作。将此值设为零会禁用设备上的 CSL。若驱动不支持 CSL，配置调用应返回 -ENOTSUP。

参见第 7.4.2.3 节以及第 8.4.3.6 节、表 8-104、macCslPeriod。

注解
容易混淆的是，标准将 CSL 接收器称为 "CSL 协调器"（即 "协调 CSL 协议时序"，参见第 6.12.2.2 节），尽管通常 CSL 协调器并非 IEEE 802.15.4 FFD 协调器或 PAN 协调器，而只是一个简单的 RFD 终端设备（对比第 5.1、5.3、5.5 和 6.1 节所述的设备角色）。为避免混淆，我们更愿意将 CSL 协调器（通常是 RFD 终端设备）称为 "CSL 接收器"，将 CSL 对等设备（通常是 FFD 协调器或 PAN 协调器）称为 "CSL 发送器"。另请注意，目前我们尚不支持第 6.12.2.4.4 节所规定的使用 CSL 唤醒帧的非同步传输。

为将 CSL 接收器时序卸载到驱动，上层应按以下方式组合若干配置选项：

  1. 使用一次 IEEE802154_CONFIG_ENH_ACK_HEADER_IE，并配合一个合适的预填充 CSL IE，其中 CSL 相位设为任意值或保持未初始化。CSL 相位应由驱动在运行时按下面第 2 点即时注入。添加短地址和扩展地址会告知驱动应向哪个特定 CSL 接收器注入 CSL IE。若未给出任何地址，则一旦启用 CSL，CSL IE 就会被注入到所有增强 ACK 帧中。此配置应在通过设置大于零的 CSL 周期启用 CSL 之前完成。

  2. 配置 IEEE802154_CONFIG_EXPECTED_RX_TIME，紧接着配置 IEEE802154_CONFIG_CSL_PERIOD。为防止竞态条件，上层应确保在这两次调用期间及之间接收机未被启用（例如通过先前配置的 RX 时隙），也不应同时发送帧。

    预期 RX 时间应指向一个理想定时 RX 帧的 SFD 结束处，该帧位于任意过去或将来的 CSL 信道采样中，即其 "SFD 结束" 恰好在该 CSL 信道采样内的本地预测时刻到达。

    驱动应按以下方式从给定的预期 RX 时间推导 CSL 锚点和 CSL 相位： 

    cslAnchorPointNs = 上一个预期 RX 时间
                   + PHY 特定的 PHR 时长（纳秒）

startOfMhrNs = 含 CSL IE 的帧的 MHR 起始，相对于本地网络时钟

cslPhase = (startOfMhrNs - cslAnchorPointNs) / (10 * PHY 特定符号周期（纳秒）) % cslPeriod

    驱动应设置第 1 点中所配置 IE 的 CSL 相位，并在目的地址符合该 IE 地址过滤器时，将该 IE 即时注入到发出的增强 ACK 帧中。

  3. 定期使用 IEEE802154_CONFIG_RX_SLOT，在每个 CSL 信道采样开始时间之前足够早地调度它。CSL 信道采样的时长应按标准规定考虑相对于 CSL 发送器的时钟漂移和调度不确定性，以保证合法 RX 帧的至少完整 SHR 落在该信道采样内。

    + N * (cslPeriod * 10 * PHY 特定符号周期（纳秒）)

IEEE802154_CONFIG_EXPECTED_RX_TIME 

配置预期 RX 帧到达的时间点。

配置以纳秒为分辨率的时间点，相对于网络子系统的本地时钟，即假定本地与远端网络时钟完全同步且天线间距离为零时，RX 帧的 SFD 结束（等价地其 SHR 结束、PHR 起始，或对于具有 RDEV 或 ERDEV 能力的 PHY 则为 RMARKER）预期到达本端天线的时刻。

此参数可用于将对时序敏感的 TDMA（例如 TSCH、含 DSME 的信标使能 PAN）、低功耗（例如 CSL、RIT）或测距（TDoA）协议的部分时序计算卸载给驱动。在这些协议中，介质访问受到严格控制，因此帧的预期到达时间可以在明确的时间窗内预测。此特性通常会与 IEEE802154_CONFIG_RX_SLOT 结合使用，尽管这不是硬性要求。

"预期 RX 时间" 的含义可能因协议上下文而略有不同：

  • CSL 相位（即到下一次预期 CSL 传输的时间）或锚点时间（即任意 "CSL 相位为零" 的时间点）应通过将 PHY 头部时长加到预期 RX 时间上来计算 CSL 协议所需的 "MHR 起始"（"MAC 的第一个符号"，参见第 6.12.2.1 节）来推导，对比 IEEE802154_CONFIG_CSL_PERIOD。
  • 在 TSCH 中，预期 RX 时间可设为 macTsRxOffset + macTsRxWait / 2。此时时间校正应按预期 RX 时间减去实际到达时间戳计算，参见第 6.5.4.3 节。
  • 在测距应用中，可在驱动内部将实际 RMARKER 时间戳与假定的、测距帧被发送时的同步时间进行比较，从而计算到达时间差（TDOA），参见 IEEE 802.15.4z。

对于周期性协议（例如 CSL 信道采样、单个 PAN 的周期性信标、周期性测距 "blink"），可以给出过去或将来任意时刻的单个时间戳，并通过加上或减去 RX 周期的倍数来推导其他预期时间戳。例如参见此 API 中的 CSL 文档。

此外，驱动可用此参数通过推导与同一时钟远端表示相关的同步时刻（如同 PTP 中那样），来校正其对分布式网络时钟的本地表示。

注解
在任意接口工作状态下均可用。

IEEE802154_CONFIG_ENH_ACK_HEADER_IE 

添加一个头部信息元素（IE），当给定的目的地址过滤器匹配时，将其注入到驱动生成的增强 ACK 帧中。

实现 IEEE802154_HW_RX_TX_ACK 能力的驱动会自行生成 ACK 帧。设置此配置将要求驱动在按标准适当生成增强 ACK 帧时注入给定的预配置头部 IE。其他所有帧类型的 IE 应由 L2 提供。

在以下情况下，驱动应返回 -ENOTSUP：

  • 不支持 IEEE802154_HW_RX_TX_ACK，
  • 不支持头部 IE 注入，
  • 无法即时注入给定 IE 元素 ID 所需的运行时字段（参见下面的列表）。

由于需要即时注入时序信息，因此需要被拒绝，或需由驱动显式支持并解析的增强 ACK 头部 IE（括号中为元素 ID）包括：

  • CSL IE (0x1a)
  • 会合时间 IE (0x1d)
  • 时间校正 IE (0x1e)

接受此配置选项的驱动应针对每个发出的增强 ACK 帧检查已配置的 IE 列表，根据元素 ID 选择适用于所接收帧的 IE，即时注入任何所需的运行时信息，并将选中的 IE 包含到增强 ACK 帧的 MAC 头中。

支持增强 ACK 头部 IE 注入的驱动应按标准要求自行注入头部终止 IE。

L2 可给出目的短地址和扩展地址，以过滤包含给定 IE 的设备。将短地址设为广播地址、扩展地址设为 NULL，会将给定 IE 注入到所有 ACK 帧中，除非对任一给定目的设备还存在更具体的过滤器（回退配置）。L2 应确保两个地址字段要么都设为有效的设备地址，要么都不设置。

此配置类型可多次调用，每次使用不同的元素 ID 和/或地址。驱动应存储所有已配置的 IE/地址组合，或者在无法再存储配置时返回 -ENOMEM。

配置具有先前已配置元素 ID 和地址过滤器的头部 IE 应覆盖之前的配置。这意味着不支持重复相同的头部 IE/地址组合。

以头部 IE 的长度字段设为零来配置已存在的元素 ID/地址过滤器组合，应移除该配置。若未给出地址，则应移除回退配置。

以头部 IE 指针设为 NULL 来为某地址过滤器配置头部 IE，应移除该地址过滤器的所有头部 IE。若未给出地址，则应移除所有头部 IE 配置（包括但不限于回退配置）。

若被删除的任何配置此前并不存在，则应忽略该调用。每当长度字段设为零时，驱动不得访问内容字段。

L2 应通过合并地址过滤器并移除不再需要的配置，尽量减小驱动内保存 IE 配置所需的空间。

注解
需要 IEEE802154_HW_RX_TX_ACK 能力，且在任意接口工作状态下均可用。目前我们仅支持头部 IE，但将来可能会改变。

IEEE802154_CONFIG_RX_ON_WHEN_IDLE 

启用/禁用 RxOnWhenIdle MAC PIB 属性（表 8-94）。

由于 IEEE 802.15.4 规范中没有关于 "空闲期" 定义的明确指导，此实现期待驱动在以下场景中使用 RxOnWhenIdle 属性来确定下一个无线状态（false --> 关闭，true --> 接收）：

  • 常规帧接收任务结束时，前提是：
    • 该帧接收无错误并通过了过滤，且不是伪 ACK。
    • 未请求 ACK，或由于内部条件无法发送 ACK。
  • 帧发送结束或 ACK 帧发送结束时，且所发送的帧未请求 ACK。
  • 所请求 ACK 的接收操作因以下原因结束：
    • ACK 超时到期。
    • 收到无效的 ACK 或非 ACK 帧。
    • 收到正确的 ACK，除非所发送的帧是数据请求命令且所收到 ACK 上的帧待处理位为 true。在这种情况下，无线平台实现宜保持接收机开启，直到确定的超时触发空闲期开始。
  • 独立 CCA 任务结束。
  • CSMA/CA 过程中结果为忙的 CCA 操作结束。
  • 能量检测任务结束。
  • 调度的无线接收窗口结束（参见 IEEE802154_CONFIG_RX_SLOT）。

  • 2006 版标准有一个只读的 phyChannelsSupported PHY PIB 属性，用位图表示信道页/编号组合。随着信道数量增加到超出位图所能表示的范围，该属性在后来的标准版本中被移除。这就是为什么决定用信道页和范围的组合来表示支持的信道。
  • 在 2020 版标准中，明确定义了 13 个信道页，但原则上最多可支持 32 个页。这在 2006 版标准中是硬性要求。在后来的标准中，这隐含于字段规范中，例如 MAC PIB 属性 macChannelPage（第 8.4.3.4 节、表 8-100）或 SRM 协议中使用的信道页字段（参见第 8.2.26.5 节）。
  • ASK PHY（信道页一）在 2015 版标准中被弃用。2020 版标准对信道页一是消失还是现在应解释为 O-QPSK 有些模棱两可（参见第 10.1.3.3 节）。在 Zephyr 中通过弃用信道页一来解决这种模棱两可。
  • 对于某些 PHY，标准没有明确规定信道页，即 GFSK、RS-GFSK、CMB 和 TASK PHY。这些都比较新，只要没有驱动想实现它们，就不在我们的列表中。
警告
这些位编号并非随意指定，而是代表标准所定义的信道页编号。因此不要更改位编号。

返回

警告
