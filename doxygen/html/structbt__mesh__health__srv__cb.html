◆ attn_on

void(*) bt_mesh_health_srv_cb::attn_on(const struct bt_mesh_model *model)

开始关注该设备。

关注状态用于将元素地址映射到物理设备。调用此回调时，设备应开始某种旨在引起关注的物理动作，例如闪烁、蜂鸣、振动或移动。如果设备上有多个健康服务器实例，关注状态还应有助于识别服务器所在的具体元素。

关注行为应持续到 attn_off 回调被调用为止。

参数
model要启动其关注状态的健康服务器模型。

◆ fault_get_cur

int(*) bt_mesh_health_srv_cb::fault_get_cur(const struct bt_mesh_model *model, uint8_t *test_id, uint16_t *company_id, uint8_t *faults, uint8_t *fault_count)

用于获取当前故障的回调。

故障值既可以由规范定义，也可以由厂商定义。厂商特定的故障应结合随附的公司 ID 来解释。规范定义的故障可以为任何公司 ID 报告，同一故障可能出现在多个公司 ID 下。

所有故障都应至少关联一个公司 ID，代表设备厂商或其他使用了其厂商特定故障值的厂商。

如果有多个公司 ID 存在活动故障，则每次只返回与其中一个关联的故障。要为多个公司 ID 报告故障，请在各次调用中交替报告不同的公司 ID。

参数
model要获取其故障的健康服务器模型实例。
test_id测试 ID 响应缓冲区。
company_id公司 ID 响应缓冲区。
faults要填充当前故障的数组。
fault_count故障数组可容纳的故障数量。应更新以反映已复制到数组中的故障数量。
返回
成功时返回 0，否则返回（负的）错误码。

int(*) bt_mesh_health_srv_cb::fault_get_reg(const struct bt_mesh_model *model, uint16_t company_id, uint8_t *test_id, uint8_t *faults, uint8_t *fault_count)

用于获取所有已注册故障的回调。

已注册故障是指自上次调用 fault_clear 以来的所有过去和当前故障。只应报告与给定公司 ID 关联的故障。

故障值既可以由规范定义，也可以由厂商定义。厂商特定的故障应结合随附的公司 ID 来解释。规范定义的故障可以为任何公司 ID 报告，同一故障可能出现在多个公司 ID 下。

参数
model要获取其故障的健康服务器模型实例。
company_id要获取其故障的公司 ID。
test_id测试 ID 响应缓冲区。
faults要填充已注册故障的数组。
fault_count故障数组可容纳的故障数量。应更新以反映已复制到数组中的故障数量。
返回
成功时返回 0，否则返回（负的）错误码。

◆ fault_test

int(*) bt_mesh_health_srv_cb::fault_test(const struct bt_mesh_model *model, uint8_t test_id, uint16_t company_id)

Run a self-test.

健康服务器可为每个公司 ID 支持最多 256 个自检。所有测试 ID 的行为都是厂商特定的，应结合随附的公司 ID 来解释。测试失败应导致故障数组发生变化。

参数
model要为其运行测试的健康服务器模型实例。
test_id要运行的测试 ID。
company_id要为其运行测试的公司 ID。
返回
如果测试执行成功启动则返回 0，否则返回（负的）错误码。注意，如果测试执行没有启动，故障数组不会回报给客户端。
