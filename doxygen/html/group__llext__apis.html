◆ arch_elf_relocate()

int arch_elf_relocate ( struct llext_loader * ldr,
struct llext * ext,
elf_rela_t * rel,
const elf_shdr_t * shdr )

#include <zephyr/llext/llext.h>

架构特定的操作码更新函数

ELF 文件包含描述一系列 _relocations_（重定位）的段，这些是给定某些符号数据（例如段、函数或对象）的实际位置后如何重写操作码的指令。这些重定位是架构特定的，每个支持 LLEXT 的架构都必须实现此函数。参数 sym_base_addr、sym_name 可从 sym 参数计算得出，但为了效率这些参数被冗余提供。

参数
[in]ldr扩展加载器
[in]ext正在重定位的扩展所引用的
[in]relELF 提供的重定位数据
[in]shdr当前正在定位的 ELF 段的头
返回值
0成功
-ENOTSUP不支持的重定位
-ENOEXEC无效的重定位

◆ llext_bootstrap()

void llext_bootstrap ( struct llext * ext,
llext_entry_fn_t entry_fn,
void * user_data )

#include <zephyr/llext/llext.h>

启动、执行并拆除扩展。

在当前线程上下文中调用扩展自身的设置函数、一个附加入口点以及扩展的清理函数。

这是 llext_bringup 和 llext_teardown 的便捷封装，符合 k_thread_entry_t 的签名，因此可以通过 k_thread_create 直接作为新的用户线程或内核线程启动。

参数
[in]ext要执行的扩展。在 k_thread_create 中作为 p1 传入。
[in]entry_fn执行扩展设置后线程的主入口点。在 k_thread_create 中作为 p2 传入。
[in]user_data传给 entry_fn 的参数。在以下调用中作为 p3 传入 k_thread_create.

◆ llext_relink_dependency()

int llext_relink_dependency ( struct llext * ext,
unsigned int n_ext )

#include <zephyr/llext/llext.h>

重新链接依赖项以准备挂起

对于挂起-恢复用例，当 LLEXT 上下文应保存在非易失缓冲区中时，用户可以保存大多数 LLEXT 支持数据，但必须使用 llext_restore() 重新分配对象，这还需要恢复依赖指针。为确保依赖保存和恢复一致进行，我们也为前者提供了一个辅助函数。

警告
这是实验性 API 的一部分，将来会发生变化！其可用性取决于 CONFIG_LLEXT_EXPERIMENTAL，该选项默认为禁用。
参数
[in]ext扩展数组
[in]n_ext扩展数量
返回值
0成功
-ENOENT未找到某些依赖项

◆ llext_restore()

int llext_restore ( struct llext ** ext,
struct llext_loader ** ldr,
unsigned int n_ext )

#include <zephyr/llext/llext.h>

从已保存数据恢复 LLEXT 上下文

在挂起期间，用户已保存所有扩展和加载器描述符及相关对象，并调用了 llext_relink_dependency() 以准备依赖指针。恢复时必须使用 llext_alloc_metadata() 重新分配所有对象，因此用户需要 LLEXT 核心的支持才能完成此操作。此函数以保存的扩展和加载器副本的指针数组为参数，重新分配所有对象，同时将它们添加到全局扩展列表。同时，它会将依赖指针重新链接到新分配的扩展。

警告
这是实验性 API 的一部分，将来会发生变化！其可用性取决于 CONFIG_LLEXT_EXPERIMENTAL，该选项默认为禁用。
参数
[in,out]ext扩展指针数组——替换为重新分配的副本
[in,out]ldr用于恢复段映射的加载器指针数组
[in]n_ext扩展数量
返回值
0成功
-ENOMEM没有内存
-EINVAL存储的依赖项超出范围
-EFAULT内部算法错误
