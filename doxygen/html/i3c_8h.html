总线特性寄存器（BCR）

  • BCR[7:6]：设备角色
    • 0：I3C 目标
    • 1：支持 I3C 控制器
    • 2：保留
    • 3：保留。
  • BCR[5]：高级能力
    • 0：不支持可选的高级能力。
    • 1：支持可选的高级能力，可通过 GETCAPS CCC 查看。
  • BCR[4]：虚拟目标支持
    • 0：不是虚拟目标。
    • 1：是虚拟目标。
  • BCR[3]：支持离线
    • 0：将始终响应 I3C 命令。
    • 1：不会始终响应 I3C 命令。
  • BCR[2]：IBI 负载
    • 0：接受的 IBI 之后没有数据字节。
    • 1：接受的 IBI 之后有一个数据字节（MDB，强制数据字节）。其后还可能跟随其他数据字节。
  • BCR[1]：支持 IBI 请求
    • 0：不支持
    • 1：支持
  • BCR[0]：最大数据速率限制
    • 0：无限制
    • 1：限制通过 GETMXDS CCC 获取。

传统虚拟寄存器（LVR）

传统虚拟寄存器（LVR）

  • LVR[7:5]：I2C 设备索引：
    • 0：I2C 设备具有 50 ns 尖峰滤波器，不受 SCL 上高频的影响。
    • 1：I2C 设备没有 50 ns 尖峰滤波器，但可在 SCL 上高频工作。
    • 2：I2C 设备没有 50 ns 尖峰滤波器，且不能在 SCL 上高频工作。
  • LVR[4]：I2C 模式指示：
    • 0：FM+ 模式
    • 1：FM 模式
  • LVR[3:0]: Reserved.

◆ i3c_dev_list_daa_addr_helper()

int i3c_dev_list_daa_addr_helper ( const struct device * dev,
uint64_t pid,
bool must_match,
bool assigned_okay,
struct i3c_device_desc ** target,
uint8_t * addr )

在 ENTDAA 期间查找可用地址的辅助函数。

该辅助函数用于在动态地址分配期间查找可用地址。给定 PID（pid），它会在设备列表中搜索匹配的设备描述符。若该设备描述符指明了首选地址（即设备树中的 assigned-address、i3c_device_desc::init_dynamic_addr），则在该地址仍可用时返回该首选地址；若不可用，则返回另一个空闲地址。

若 must_match 为 true，则 PID（pid）必须与设备列表中的某个设备匹配。

若 must_match 为 false，则返回任意地址。当并非所有设备都在设备树中描述时这很有用；否则由于没有可分配的地址，DAA 过程将无法进行。

若 assigned_okay 为 true，则返回已分配给该设备的相同地址（i3c_device_desc::dynamic_addr）。若尚未分配地址，则其行为如同 assigned_okay 为 false。这适用于给同一设备分配相同地址（例如设备从挂起状态恢复后的热加入）。

若 assigned_okay 为 false，则该设备不能已经分配了地址（即 i3c_device_desc::dynamic_addr 不为零）。这主要用于初始 DAA 期间。

注意
Available only when the following Kconfig option is enabled: CONFIG_I3C_CONTROLLER.
参数
[in]dev指向控制器设备驱动实例的指针。
[in]pid待分配地址设备的预置 ID。
[in]must_match为 true 时 PID 必须与设备列表中的设备匹配，否则为 false。
[in]assigned_okay为 true 时允许返回已分配给与 PID（pid）匹配的目标的地址。
[out]target若设备描述符与传入的 PID（pid）匹配，则存储该描述符的指针。
[out]addr要分配给目标设备的地址。
返回值
