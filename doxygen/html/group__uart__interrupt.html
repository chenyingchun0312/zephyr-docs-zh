◆ uart_fifo_fill()

int uart_fifo_fill ( const struct device * dev,
const uint8_t * tx_data,
int size )
inlinestatic

#include <zephyr/drivers/uart.h>

用数据填充 FIFO。

此函数应在 uart_irq_tx_ready() 返回 true 时从 UART 中断处理程序（ISR）中调用。不在 ISR 中调用此函数的结果未定义（取决于硬件）。同样，如果 uart_irq_tx_ready() 返回 true 而不在 ISR 中调用此函数，可能导致未定义行为，例如无限中断循环。必须检查此函数的返回值，因为不同硬件的 FIFO 深度不同（通常只有 1）。

参数
devUART 设备实例。
tx_data要发送的数据。
size要发送的字节数。
返回
已发送的字节数。
返回值
-ENOSYS不支持此函数。
-ENOTSUPAPI 未启用。

◆ uart_irq_rx_ready()

int uart_irq_rx_ready ( const struct device * dev)
inlinestatic

#include <zephyr/drivers/uart.h>

检查 UART RX 缓冲区是否有已接收的字符

检查 UART RX 缓冲区是否至少有一个待处理字符（即 uart_fifo_read() 将成功并返回非零值）。此函数必须在 UART 中断处理程序中调用，否则其结果未定义。在中断处理程序中调用此函数之前，每次处理程序调用都必须先调用一次 uart_irq_update()。此函数返回的条件是电平触发还是边沿触发并未规定（即此函数是在 RX FIFO 非空时返回 true，还是在自上次调用以来收到了新字符时返回 true）。关于其影响，请参见 uart_fifo_read() 的说明。

参数
devUART 设备实例。
返回值
1已接收的字符已就绪。
0已接收的字符尚未就绪。
-ENOSYS此函数未实现。
-ENOTSUPAPI 未启用。

◆ uart_irq_tx_complete()

int uart_irq_tx_complete ( const struct device * dev)
inlinestatic

#include <zephyr/drivers/uart.h>

检查 UART TX 块是否已完成传输

检查 UART TX 块中缓冲的所有待发数据是否已完全发送且 TX 块空闲。当此条件为真时，UART 设备（或整个系统）可以断电。注意，此函数 不 适用于检查 UART TX 是否能接收更多数据，那应使用 uart_irq_tx_ready()。此函数必须在 UART 中断处理程序中调用，否则其结果未定义。在中断处理程序中调用此函数之前，每次处理程序调用都必须先调用一次 uart_irq_update()。

参数
devUART 设备实例。
返回值
1没有剩余需要发送的内容。
0传输未完成。
-ENOSYS此函数未实现。
-ENOTSUPAPI 未启用。

◆ uart_irq_update()

void uart_irq_update ( const struct device * dev)
inlinestatic

#include <zephyr/drivers/uart.h>

开始在 ISR 中处理中断。

此函数应在 ISR 中最先调用。只有在此之后才允许调用 uart_irq_rx_ready()、uart_irq_tx_ready()、uart_irq_tx_complete() 和 uart_irq_is_pending()。

此函数的目的是：

  • 对于在读取寄存器时自动确认中断状态的设备，缓存该寄存器的值（随后 rx_ready 等使用此缓存值）。
  • 对于需要显式确认中断的设备，确认任何待处理的中断，并同样缓存原始值。
  • 对于隐式确认的设备，此函数将不被实现。但 ISR 必须执行确认中断所需的操作（通常是在 rx_ready 时调用 uart_fifo_read()，在 tx_ready 时调用 uart_fifo_fill()）。
参数
devUART 设备实例。
