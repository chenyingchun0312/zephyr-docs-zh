◆ nrf_clock_control_cancel_or_release()

int nrf_clock_control_cancel_or_release ( const struct device * dev,
const struct nrf_clock_spec * spec,
struct onoff_client * cli )
inlinestatic

#include <zephyr/drivers/clock_control/nrf_clock_control.h>

安全地取消预留请求。

客户端可能已发出预留请求，但需要在请求完成之前关闭。本函数尝试取消该请求；若因请求已完成而取消失败，则发出一次释放。这会同步确保所有权数据回到客户端，从而可用于后续请求。

参数
dev指向时钟设备结构的指针。
spec与预留请求中使用的完全相同的时钟属性规范。
cli指向与被取消操作发出时相同的客户端状态的指针。
返回值
ONOFF_STATE_TO_ON若取消发生在切换完成之前。
ONOFF_STATE_ON若取消发生在切换完成之后。
-EINVAL若参数无效。
negativeonoff_release() 产生的其他错误。

void nrf_clock_control_hfxo_release ( void )

从零延迟中断上下文释放 HFXO。

该函数针对零延迟中断上下文中的使用做了优化。

对本函数的调用必须与之前的 nrf_clock_control_hfxo_request() 调用配对，因为它使用基本的引用计数来确保在没有未完成请求时释放 HFXO。

◆ nrf_clock_control_hfxo_request()

void nrf_clock_control_hfxo_request ( void )

#include <zephyr/drivers/clock_control/nrf_clock_control.h>

从零延迟中断上下文请求 HFXO。

该函数针对零延迟中断上下文做了优化。它在 HFXO 就绪时不给出通知，因此每个使用者都必须足够早地发出请求，以确保 HFXO 的爬升过程按时完成。

该函数使用引用计数，因此调用方必须确保每个 nrf_clock_control_hfxo_request() 调用都有对应的 nrf_clock_control_hfxo_release() 调用。

◆ nrf_clock_control_request()

int nrf_clock_control_request ( const struct device * dev,
const struct nrf_clock_spec * spec,
struct onoff_client * cli )
inlinestatic

#include <zephyr/drivers/clock_control/nrf_clock_control.h>

请求预留以使用具有指定属性的给定时钟。

返回值表示发起“请求使时钟可用”这一操作是否成功。若操作发起成功，该请求操作的结果会通过配置的客户端通知方式提供，可能在本调用返回之前就提供。

注意，即使实际请求失败，对此函数的调用也可能成功。请始终检查操作的完成结果。

参数
dev指向时钟设备结构的指针。
spec可接受的最小属性规范，例如时钟所需的频率、准确度和精度。值 0 表示“默认”，在此方面没有严格要求时可代替给定属性传入。若对所有属性都没有特定要求，此参数可为 NULL。
cli指向客户端状态的指针，该状态给出关于同步期望的指示以及请求完成时如何通知客户端。若客户端传入的指针对象关联的服务操作尚未完成，则行为未定义。
返回值
non-negative若成功，为处理该请求时与时钟机制关联的 onoff 服务的观测状态（参见 onoff_request()）。
-EIO若服务已记录错误。
-EINVAL若函数参数无效或无法提供所要求的时钟属性（例如所请求的准确度不可用）。
-EAGAIN若引用计数将溢出。
