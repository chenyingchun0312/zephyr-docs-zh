详细描述

包含其他元素的元素。

bin 本身就是一个 mpipe_element，因此从外部可以把整个图当作一个元素处理。它的职责是容纳子元素，并以安全的顺序将状态变化转发给它们。

该顺序并非它们被添加的顺序。bin 按链接对子元素做拓扑排序：当转换向上时，从 sink 向 source 遍历，这样下游元素在有任何数据推入之前就已就绪；当转换向下时，从 source 向 sink 遍历，这样不会有元素继续向已被拆除的元素产出数据。 CONFIG_MPIPE_BIN_MAX_CHILDREN bounds the arrays that sort uses.

bin 还拥有其子元素用于报告的消息通道，图中的深层故障正是通过它到达应用程序。参见 mpipe_message。

向 bin 添加元素

将给定元素添加到 bin。

一个元素只能添加到一个 bin。元素 id 在 bin 内必须唯一。

该函数接受可变数量的元素，以 NULL 终止。

添加元素不会改动其 pad，因此元素可以在链接之前或之后添加。在被拒绝元素之前的元素保持已添加状态。

参数
bin指向要添加元素的 Bin 的指针
element要添加的第一个 元素
...其他 mpipe_element 指针，以 NULL 终止
返回值
0Success.
-EBUSY某个元素已在一个 bin 中
-EEXIST某个元素的 id 与 bin 中已有元素相同
-ENOSPCbin 已容纳 CONFIG_MPIPE_BIN_MAX_CHILDREN 个元素

Bin 状态变化函数

通过以适当顺序将状态变化传播给所有子元素来处理 bin 的状态变化。bin 管理拓扑关系并确保状态变化的正确顺序。

返回
成功时返回 0，否则返回拒绝的子元素的 errno
返回值
-ENOSPCbin 容纳的子元素超出容量
-EINVAL子元素无法排序

在 bin 的总线上安装校验器和用户数据。

mpipe_bin_init brings the channel up with no validator, since a bin has no opinion on the messages passing through it. An element wrapping a bin (a pipeline, say) uses this to install its own.

只有这两个字段会在通道自身的锁保护下改变。已附加的观察者保持附加状态，也可以在本次调用之前或之后附加。

参数
bin指向 Bin 的指针。
bus_validator要安装的消息校验器，NULL 表示不做校验。
user_data与总线关联的用户数据，可通过 zbus_chan_user_data() 从校验器/观察者获取；未使用时为 NULL。
返回
成功时为 0，失败时为负的 errno
