◆ bt_mesh_blob_cli_caps_get()

int bt_mesh_blob_cli_caps_get ( struct bt_mesh_blob_cli * cli,
const struct bt_mesh_blob_cli_inputs * inputs )

#include <zephyr/bluetooth/mesh/blob_cli.h>

获取一组目标节点的传输能力。

查询所有目标节点的可用性和能力，生成目标节点的累积传输能力集合，并通过 bt_mesh_blob_cli_cb::caps 回调返回。

获取能力可能需要数秒，具体取决于目标节点数量和 Mesh 网络性能。该过程结束通过 bt_mesh_blob_cli_cb::caps 回调指示。

此过程不是必需的，但强烈建议作为传输的准备步骤，以最大化性能和成功概率。

参数
cliBLOB 传输客户端实例。
inputs静态分配的 BLOB 传输客户端传输输入。
返回
成功时返回 0，否则返回（负的）错误码。

◆ bt_mesh_blob_cli_send()

int bt_mesh_blob_cli_send ( struct bt_mesh_blob_cli * cli,
const struct bt_mesh_blob_cli_inputs * inputs,
const struct bt_mesh_blob_xfer * xfer,
const struct bt_mesh_blob_io * io )

#include <zephyr/bluetooth/mesh/blob_cli.h>

执行 BLOB 传输。

开始向目标节点发送传输。只有具备以下条件的目标节点 status of BT_MESH_BLOB_SUCCESS will be considered.

传输将持续进行，直到所有目标节点都被移除，或者完整 BLOB 已发送完毕。

BLOB 传输可能需要数分钟，具体取决于目标节点数量、BLOB 大小和 Mesh 网络性能。传输结束通过 bt_mesh_blob_cli_cb::end 回调指示。

客户端一次只支持一个传输。

参数
cliBLOB 传输客户端实例。
inputs静态分配的 BLOB 传输客户端传输输入。
xfer静态分配的传输参数。
io要从中读取传输的 BLOB 流。
返回
成功时返回 0，否则返回（负的）错误码。

◆ bt_mesh_blob_cli_set_chunk_interval_ms()

void bt_mesh_blob_cli_set_chunk_interval_ms ( struct bt_mesh_blob_cli * cli,
uint32_t interval_ms )

#include <zephyr/bluetooth/mesh/blob_cli.h>

设置分块发送间隔（毫秒）

此函数是可选的，可用于定义 BLOB 客户端模型中分块的发送速度。如果没有附加延迟，例如 Bluetooth Mesh DFU 可能因不断发送下一个分块而造成网络阻塞，特别是当分块被发送到组地址或多个单播地址时。

注解
：较大的间隔可能导致超时。相应地增大 timeout_base 可以规避此问题。
参数
cliBLOB 传输客户端实例。
interval_ms发送每个分块前的延迟（毫秒）。
