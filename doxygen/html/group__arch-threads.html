每个线程栈对象开头的保留空间

在线程栈对象最低地址处为架构或平台数据（例如 MPU 栈保护区域）保留的字节数。此空间不能用作线程栈缓冲区，也不计入用户请求的栈大小。

可选定义，默认为 0。

◆ ARCH_THREAD_STACK_SIZE_ADJUST

#define ARCH_THREAD_STACK_SIZE_ADJUST ( size)

#include <zephyr/arch/arch_interface.h>

将栈缓冲区大小向上取整以满足对齐约束

将所请求的栈缓冲区大小调整为底层缓冲区的真实大小，即可用于线程栈上下文和线程局部存储的区域。

此处传入的大小值不包括为平台数据保留的存储。

返回值要么是所提供的同一大小（如果已正确对齐），要么是向上取整以满足对齐约束后的值。此处进行的计算 必须 是幂等的。

可选定义。如果未定义，栈缓冲区大小将：

  • 在启用了用户模式、且架构的 MPU 要求如此对齐时，向上取整到下一个 2 的幂
  • 向上取整到 ARCH_STACK_PTR_ALIGN
参数
size所请求的栈缓冲区大小
返回
调整后的栈对象大小
参见
Z_THREAD_STACK_SIZE_ADJUST

处理设置新线程的架构特定逻辑

栈和架构特定的线程状态变量必须设置妥当，使得之后尝试切换到该线程时能够成功，并以所请求的线程和参数作为其参数进入 z_thread_entry。

在此函数实现的某个时刻，必须用线程栈对象中可用栈缓冲区的真实边界调用 z_setup_new_thread()。

所提供的栈指针保证已按 CPU 和 ABI 的要求正确对齐。栈指针与栈缓冲区边界之间可能保留有空间，用于初始栈指针随机化和线程本地存储。

调用此函数时，thread->base 中的字段将被初始化。

◆ arch_switch()

void arch_switch ( void * switch_to,
void ** switched_from )
inlinestatic

#include <kernel/include/kernel_arch_interface.h>

协作式上下文切换原语

arch_switch() 的行为应是切换到第一个参数传入的新上下文，并将指向当前上下文的指针保存到第二个参数传入的地址中。

切换句柄的实际类型和解释由架构规定。它就是 arch_new_thread() 中新创建线程的 "switch_handle" 字段所存储的同一数据结构，并作为 z_get_next_switch_handle() 的 "interrupted" 参数传给内核。

请注意，在 SMP 系统中，内核将通过第二个指针的存储作为同步点，以检测线程上下文何时已完全保存（这样另一个 CPU 就能知道何时可以安全切换）。此存储必须在所有相关状态保存完毕之后进行，并且必须包含所需的任何内存屏障或缓存管理代码，以确保另一个 CPU 能正确看到结果。

arch_switch() 最简单的实现通常是将状态压入线程栈，并将得到的栈指针用作切换句柄。有些架构则可能决定改用指向线程结构体的指针作为 "switch handle" 类型。这些架构可以合法地假定 arch_switch() 的第二个参数是 struct thread_base 的 switch_handle 字段的地址，并可对该值使用偏移量来找到线程结构体的其他部分。例如，arch_switch() 的（C 伪代码）实现可能如下所示：

void arch_switch(void *switch_to, void **switched_from) { struct k_thread *new = switch_to; struct k_thread *old = CONTAINER_OF(switched_from, struct k_thread, switch_handle);

// 保存旧上下文... *switched_from = old; // 恢复新上下文... }

请注意，如上所述，内核会管理 switch_handle 字段以实现同步。因此架构代码不能假定它在其他任何时刻具有某个特定的值。特别是，不得从第二个参数传入的地址读取该字段。

参数
switch_to即将切入的线程的 switch handle
switched_from指向即将切出的线程的 switch handle 存储位置的指针，该位置必须被更新。
