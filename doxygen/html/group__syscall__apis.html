运行时检查用户线程对某内存区域是否具有读和/或写权限

检查如果 CPU 处于用户模式，当前运行的线程是否可读和/或可写该特定内存区域。这可防止用户空间让内核读取和/或修改该线程无权访问的内存，或传入解引用后会令内核崩溃/缺页的无效指针。

参数
ptr要检查的内存区域
size内存区域的大小
write该线程是否应能写入此内存，而不仅仅是读取
返回
成功时为 false，失败时为 true
注解
这是内部 API。除非你在扩展 Zephyr 树中的功能，否则不要使用它。

与 K_SYSCALL_OBJ() 相同，但额外拒绝动态分配的内核对象。在系统调用处理程序中，若把对象指针存储在内核于系统调用返回后会解引用的位置，应使用此宏而不是 K_SYSCALL_OBJ()。动态分配的对象在检查之后的任何时刻都可能被用户模式释放——通过调用 k_object_release()，或仅仅终止最后一个持有该对象权限的线程——从而使保留的指针悬空，并在内存被复用时可能指向无关对象。

运行时检查设备对象是否属于特定驱动程序类型

检查传入的驱动程序对象是否已初始化、调用者是否具有正确的权限，以及它是否属于指定的驱动程序子系统。此外，所有设备都存储一个驱动程序 API 的结构体指针。如果它与所提供的值不匹配，检查将失败。

这提供了一种简便方法来判断设备对象不仅属于特定子系统，而且属于特定的设备驱动程序实现。对于定义仅由某一个驱动程序实现的子系统外系统调用很有用。

参数
_device不受信任的设备指针
_dtype所提供设备指针的预期内核对象类型
_api预期的驱动 API 结构体内存地址

注解

inlinestatic

在 z_vrfy 函数内部，我们总是知道自己正在处理从用户上下文调用的系统调用。

◆ k_object_is_dynamic()

bool k_object_is_dynamic ( const void * obj)
inlinestatic

#include <zephyr/internal/syscall_handler.h>

检查内核对象是否为动态分配

动态分配的内核对象其生命周期由权限位掩码决定：一旦最后一个持有其权限的线程释放该权限或终止，对象就会被释放，其内存随后可被无关的内核对象复用。内核自身持有的指针不会在该位掩码中体现，因此不会使对象保持存活。

因此，任何在调用本身结束后仍保留内核对象指针的系统调用都必须拒绝动态分配的对象，因为注册时校验对象并不能说明之后解引用所保留指针时该对象是否仍然有效。

参数
obj内核对象的地址
返回
如果对象存在且为动态分配则为 true
注解
这是内部 API。除非你在扩展 Zephyr 树中的功能，否则不要使用它。
