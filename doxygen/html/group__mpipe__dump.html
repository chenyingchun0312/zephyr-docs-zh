详细描述

渲染 bin 的拓扑以及每个 pad 上协商的能力。

将 bin 渲染为 Graphviz 图：每个元素及其状态、作为端口的 pad、每个 pad 所链接的对端，以及该 pad 最终确定的能力。协商过程是日志最难呈现的部分，因此这个工具适合回答“每条链路达成了什么”以及“哪个 pad 仍未链接”。

目标端输出文本，由主机端排版。没有文件系统的开发板会把文本输出到控制台，再从串口抓取记录中截出该图：

sed -n '/^digraph/,/^}/p' capture.log > pipe.dot
dot -Tpng pipe.dot -o pipe.png

An element whose pads are not all linked is drawn with a red border, and one nothing reaches simply stands alone in the layout, so a broken graph shows itself without a separate report.

The graph is rendered as it is now: an element that removed itself once negotiated, as a caps filter does, appears detached during a run and linked again after it.

Nothing here allocates, and the walk holds no lock: a dump taken while the pipeline is changing state is a snapshot that may catch a pad mid-update. Dump from a settled state to read a settled answer.

◆ mpipe_dump_print_t

typedef void(*) mpipe_dump_print_t(void *ctx, const char *str)

#include <zephyr/mpipe/utils/mpipe_dump.h>

转储的输出回调。

转储每次渲染一行并交给回调，因此它自己不需要缓冲区，可以写到调用者希望的任意位置：shell 实例、控制台，或供测试随后断言的缓冲区。

参数
ctx传给转储的上下文，原样回传。
str一行已渲染的内容，以 NUL 结尾；如果该处有换行，则带换行符。

◆ mpipe_dump_caps()

int mpipe_dump_caps ( const struct mpipe_structure * caps,
mpipe_dump_print_t print,
void * ctx )

#include <zephyr/mpipe/utils/mpipe_dump.h>

将单个能力渲染为一行。

将其写为 <video, format=RGBP, width=640, height=480>，范围写为 [min, max, step]，不约束任何内容的能力写为 <any> 或 <empty>。每个能力都以相同方式界定，因此可以从其后还带有其他文本的行中挑出某一个。结尾不带换行符，以便调用者自行放置。

参数
caps要渲染的能力。
print写入位置；为 NULL 时使用 printk() 写入控制台。
ctx原样传给 print。
返回值
0Success.
