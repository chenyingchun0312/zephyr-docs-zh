构造 SCMI 消息头

根据组成消息头的各个字段构造 SCMI 消息头。生成的 32 位消息头布局如下：

  • 位 [7:0] 消息 ID
  • 位 [9:8] 消息类型（参见 scmi_message_type）
  • 位 [17:10] 协议 ID
  • 位 [27:18] 消息令牌
参数
id消息 ID
type消息类型
proto协议 ID
token消息令牌

◆ scmi_protocol_event_callback

typedef void(*) scmi_protocol_event_callback(struct scmi_protocol *proto, uint32_t msg_id)

#include <zephyr/drivers/firmware/scmi/protocol.h>

由 SCMI 核心调用的、按协议的通知回调。

在各 SCMI 协议的静态注册阶段定义事件特定信息。收到 P2A 通知/中断时，SCMI 核心会解码消息并将其分派给相应协议的回调。

参数
proto指向收到该通知的 SCMI 协议实例的指针。
msg_id协议特定的消息 ID。

◆ scmi_send_message()

int scmi_send_message ( struct scmi_protocol * proto,
struct scmi_message * msg,
struct scmi_message * reply,
bool use_polling )

#include <zephyr/drivers/firmware/scmi/protocol.h>

发送 SCMI 消息并等待其回复

阻塞函数，用于通过给定通道发送 SCMI 消息并等待其回复

参数
proto指向 SCMI 协议的指针
msg指向要发送的 SCMI 消息的指针
reply指向用于写入回复的 SCMI 消息的指针
use_polling指定 scmi 平台与代理交互所使用的通信机制。
  • true：轮询模式——平台主动检查消息状态以判断是否已处理
  • false：中断模式——平台依靠 SCMI 中断检测消息何时被处理。
返回
成功时为 0，失败时为负的 errno 值。
