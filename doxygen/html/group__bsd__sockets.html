◆ zsock_get_context_object()

void * zsock_get_context_object ( int sock)

#include <zephyr/net/socket.h>

获取文件描述符关联的网络上下文

启用 CONFIG_USERSPACE 时，内核对象权限系统必须作用于套接字文件描述符。打开套接字时，默认只有调用者拥有权限，其他线程访问将失败，除非已专门为其授予权限。

这是通过给实现套接字文件描述符底层对象的数据结构定义打上 __net_socket 标记来实现的。指向这些实例的所有指针都会被内核识别为类型 K_OBJ_NET_SOCKET 的内核对象。

此 API 面向需要把特定文件描述符关联对象的访问权授予其他线程的线程。返回的指针表示底层的 K_OBJ_NET_SOCKET，可传给 k_object_access_grant() 之类的 API。

在 Linux 这类具有“线程运行于共享虚拟地址空间中的进程”概念的系统里，这种管理是不必要的，因为文件描述符的作用域是在进程级别实现的。

然而在 Zephyr 中，文件描述符的作用域是全局的，而基于 MPU 的系统由于缺少内存虚拟化硬件，无法实现类进程模型。它们改用离散的对象权限和内存域来定义线程的访问范围。

用户线程无法直接访问返回的对象，若尝试访问其内存将触发错误；该指针只能用于进行权限分配调用，这类调用完全遵循设备驱动和 IPC 等其他内核对象的规则。

参数
sock文件描述符
返回
指向关联网络套接字对象的指针，若文件描述符无效或调用者没有访问权限则为 NULL

◆ zsock_send_all()

int zsock_send_all ( int sock,
const void * buf,
size_t len,
int flags,
k_timeout_t timeout,
size_t * sent_len )

#include <zephyr/net/socket.h>

向任意网络地址发送数据。该函数会尝试发送所请求的全部数据，必要时阻塞。用户可通过套接字发送超时限制该函数的耗时。

关于各参数的规范性描述，参见 POSIX.1-2017 文档 http://pubs.opengroup.org/onlinepubs/9699919799/functions/sendto.html。该函数与 zsock_send() 的不同之处在于它会尝试发送所请求的全部数据，必要时阻塞，直到所有数据发送完毕或发生超时。注意，这仅适用于 TCP 这类流式套接字。若超时设为 K_NO_WAIT，该函数将在首次发送尝试后返回，可能发送的数据少于请求量。

参数
sock套接字文件描述符
buf指向要发送的数据缓冲区的指针
len要发送的数据长度
flags发送数据的套接字标志
timeout等待数据发送完毕的最长时间
sent_len指向用于存储实际发送字节数的变量的指针。若调用方不需要该信息，可设为 NULL。
返回
成功时为 0，失败时为 -errno
