#include <zephyr/bluetooth/audio/bap.h>

从周期广播同步创建广播接收端

应仅在确认该周期广播同步来自广播源后再执行此操作。

需要将所创建的广播接收端传给 bt_bap_broadcast_sink_sync()，以便同步到广播音频。

如果成功，将用所创建的广播接收端对象调用 bt_bap_broadcast_sink_cb.pa_synced()。

参数
pa_sync指向周期广播同步对象的指针。
broadcast_id24 位广播 ID。
[out]sink指向所创建广播接收端的指针。
返回
成功时为 0，出错时为 errno 值。

◆ bt_bap_broadcast_sink_delete()

#include <zephyr/bluetooth/audio/bap.h>

释放广播接收端

在 pa_synced 回调之后分配的广播接收端可用此函数删除。如果该接收端已同步到任何广播音频流，则必须先使用 bt_bap_stream_stop 停止这些流。

参数
sink指向要删除的接收端对象的指针。
返回
成功时为 0，出错时为负值。

◆ bt_bap_broadcast_sink_register_cb()

int bt_bap_broadcast_sink_register_cb ( struct bt_bap_broadcast_sink_cb * cb)

#include <zephyr/bluetooth/audio/bap.h>

注册广播接收端回调

可以注册多个回调结构体，但单个结构体只能注册一次。多次注册同一回调属于未定义行为，可能破坏协议栈。

参数
cb广播接收端回调结构体。
返回值
0成功时
-EINVAL若 cb 为 NULL
-EALREADY如果 cb 已注册

停止音频广播接收端。

停止音频广播接收端。广播接收端将停止接收 BIGInfo，且不再能流传输音频数据。

返回
成功时为零，否则为（负的）错误码。

uint32_t indexes_bitfield,
struct bt_bap_stream * streams[],

#include <zephyr/bluetooth/audio/bap.h>

同步到广播方的音频

参数
sink来自 base_recv 回调的接收端对象指针。
indexes_bitfield要同步到的 BIS 索引位字段。例如要同步到 BIS 索引 1 和 2，此值应为 BIT(1U) | BIT(2U)。
streams用于接收端的流对象指针。如果要同步多个 BIS 索引，则应提供多个流。
broadcast_code16 字节的广播码。如果广播已加密则必须提供（参见 bt_bap_broadcast_sink_cb.syncable）。如果该值为字符串或不足 16 字节，则剩余字节应填 0。 
                      示例：字符串 "Broadcast Code" 应为 [42 72 6F 61 64 63 61 73 74 20 43 6F 64 65 00 00]
返回
成功时为 0，出错时为负值。
