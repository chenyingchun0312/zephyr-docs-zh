SDP PDU 中的数据表示（BT SDP 规范第 339、340 页）

这些是放入 PDU 缓冲区的确切数据类型+长度描述符值。

数据类型（前 5 位）+ 长度描述符（后 3 位）共 8 位。长度描述符对于从 PDU 中提取正确字节数的数据值至关重要。

对于大多数基本类型，数据类型+长度描述符是直接的。但对于构造类型和字符串，数据的长度位于 8 位（数据类型+长度）描述符之后的接下来 "n" 个字节中。"n" 具体是多少由长度描述符的 3 位指定。

TextString 和 URLString 的长度可以是 2^{8, 16, 32} 字节，DataSequence 和 DataSequenceAlternates 的长度也可以是 2^{8, 16, 32}。这些长度在 API 中是事后计算的，事先并不知道。

对于 BT_SDP_UINT128、BT_SDP_INT128 和 BT_SDP_UUID128 类型，数据的字节序应为小端。例如，SPP UUID128：00001101-0000-1000-8000-00805F9B34FB 将表示为 {0xFB, 0x34, 0x9B, 0x5F, 0x80, 0x00, 0x00, 0x80, 0x00, 0x10, 0x00, 0x00, 0x01, 0x11, 0x00, 0x00}。对于 UUID 128，使用 BT_SDP_ARRAY_UUID_128 声明数组。

typedef uint8_t(*) bt_sdp_discover_func_t(struct bt_conn *conn, struct bt_sdp_client_result *result, const struct bt_sdp_discover_params *params)

#include <zephyr/bluetooth/classic/sdp.h>

回调类型，向用户报告远端存在给定 UUID 的已解析结果，且用户可使用结果记录缓冲区做进一步检查。

此类型的函数由用户提供给 bt_sdp_discover_params 对象。对于给定 UUID 的每个有效记录发现完成时都会调用它。如果 UUID 解析没有返回记录，则向用户传入 NULL。否则用户可获取有效记录，随后内部提示 'next record' 被置为 false，表示该 UUID 解析完成，或者调用方可将该提示置为 true，表示给定 UUID 还有下一条记录可用。返回的函数值让用户可以控制是否继续读取后续解析出的记录。如果用户因当前记录数据已满足需求而不再读取给定 UUID 的更多已解析记录，应返回 BT_SDP_DISCOVER_UUID_STOP。否则返回值表示允许更多子调用迭代。

参数
conn标识与所查询远端连接的连接对象。
result指向根据给定发现参数所驱动的响应而收集的逻辑未解析 SDP 记录的对象。
params发现参数。
返回
BT_SDP_DISCOVER_UUID_STOP 表示无需再读取下一条记录数据并继续给定 UUID 的发现。通过返回
BT_SDP_DISCOVER_UUID_CONTINUE，用户允许继续该发现。
