宏定义说明

◆ ARCH_EXCEPT

#define ARCH_EXCEPT ( reason_p)

#include <zephyr/arch/arch_interface.h>

产生一个由软件引发的致命错误。

如果调用者运行在用户模式下，则只能引发 K_ERR_KERNEL_OOPS 或 K_ERR_STACK_CHK_FAIL。

理想情况下，这应产生一个软件陷阱，其异常上下文指明调用时的状态。陷阱发生时的通用寄存器状态不应被调用上下文的操作所破坏。

参数
reason_p该致命错误的 K_ERR_ 作用域原因码。

#include <zephyr/arch/arch_interface.h>

用于静态连接中断的架构特定钩子

在构建时静态填充中断表，使得 isr is invoked with arg as its argument when interrupt irq fires, with interrupt priority pri and architecture-specific configuration flags. All arguments must be usable in a constant expression context.

pri中断优先级
isr中断服务例程
arg传给 ISR 的参数
flags架构特定的 IRQ 配置标志

◆ ARCH_ISR_DIRECT_DECLARE

#define ARCH_ISR_DIRECT_DECLARE ( name)

#include <zephyr/arch/arch_interface.h>

用于声明直接中断服务例程的架构特定钩子

声明一个适合用 ARCH_IRQ_DIRECT_CONNECT() 安装的函数 name，并包裹随后的函数体，使 ARCH_ISR_DIRECT_HEADER() 和 ARCH_ISR_DIRECT_FOOTER() 在其前后运行，并应用任何架构特定的 ISR 前导/收尾（例如中断属性）。被包裹的函数体在中断退出时可能执行上下文切换时返回非零值。

参数
name要声明的直接中断服务例程的名称
参见
ISR_DIRECT_DECLARE()

◆ ARCH_ISR_DIRECT_FOOTER

#define ARCH_ISR_DIRECT_FOOTER ( swap)

#include <zephyr/arch/arch_interface.h>

直接中断退出时的架构特定簿记

ARCH_ISR_DIRECT_HEADER() 的对应操作：撤销中断入口簿记，并在 swap 非零时检查中断退出时是否需要进行上下文切换并为其做好安排。通过 ISR_DIRECT_FOOTER() 在每个直接 ISR 末尾调用。

参数
swap如果退出时可能执行上下文切换则为非零
参见
ISR_DIRECT_FOOTER()

◆ arch_cpu_irqs_are_enabled()

bool arch_cpu_irqs_are_enabled ( void )
inlinestatic

#include <zephyr/arch/arch_interface.h>

探测当前 CPU 的总体中断控制器锁定状态而不修改它。

与检查已保存键的 arch_irq_unlocked() 不同，此函数报告调用 CPU 总体中断使能状态的瞬时值。

返回
如果调用 CPU 当前使能了中断，则为 true。

◆ arch_irq_disable()

void arch_irq_disable ( unsigned int irq)

#include <zephyr/arch/arch_interface.h>

禁用指定的中断线

注解
：此调用返回之后、到调用 arch_irq_enable() 之前到达的中断，其行为是未定义的。硬件不要求锁存并递送此类中断，尽管在某些架构上这可能有效。其他架构将直接丢失此类中断且永远不会递送。许多驱动和子系统无法容忍这种丢弃的中断，因此由应用层负责确保行为仍然正确。
