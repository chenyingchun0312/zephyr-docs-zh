◆ esp_wifi_mesh_event

enum esp_wifi_mesh_event

#include <zephyr/drivers/wifi/esp_wifi/esp_wifi_mesh.h>

投递给应用回调的 Wi-Fi mesh 事件。

它们将底层厂商 mesh 事件抽象为稳定的 Zephyr 原生事件集，使应用程序不依赖厂商 mesh 头文件。

枚举值
ESP_WIFI_MESH_EVENT_STARTED 

mesh 栈已启动。

ESP_WIFI_MESH_EVENT_STOPPED 

mesh 栈已停止。

ESP_WIFI_MESH_EVENT_PARENT_CONNECTED 

此节点已连接到父节点（参见 info 中的 is_root）。

ESP_WIFI_MESH_EVENT_PARENT_DISCONNECTED 

此节点失去了父节点。

ESP_WIFI_MESH_EVENT_CHILD_CONNECTED 

子节点已连接到此节点。

ESP_WIFI_MESH_EVENT_CHILD_DISCONNECTED 

子节点已从此节点断开。

ESP_WIFI_MESH_EVENT_NO_PARENT_FOUND 

上次扫描期间未找到父节点。

ESP_WIFI_MESH_EVENT_FIND_NETWORK 

节点开始寻找要加入的网络。

ESP_WIFI_MESH_EVENT_ROUTING_TABLE_CHANGE 

路由表已变化（参见 info 中的 routing_table_size）。

ESP_WIFI_MESH_EVENT_LAYER_CHANGE 

此节点的 mesh 层级（树深度）已变化（参见 info 中的 layer）。

ESP_WIFI_MESH_EVENT_TODS_REACHABLE 

根节点的外部网络（toDS）路径变为可达。

ESP_WIFI_MESH_EVENT_TODS_UNREACHABLE 

根节点的外部网络（toDS）路径变为不可达。

◆ esp_wifi_mesh_bind_sta_rx()

void esp_wifi_mesh_bind_sta_rx ( void )

#include <zephyr/drivers/wifi/esp_wifi/esp_wifi_mesh.h>

将根节点 station 的上行帧投递到 station 接口。

mesh 栈会安装自己的 station 接收回调。在根节点上，station 还承载到路由器的上行链路，因此此函数为该接口恢复驱动的接收路径。节点成为 mesh 根节点后调用一次。

◆ esp_wifi_mesh_event_cb_register()

void esp_wifi_mesh_event_cb_register ( esp_wifi_mesh_event_cb_t cb)

#include <zephyr/drivers/wifi/esp_wifi/esp_wifi_mesh.h>

注册应用 mesh 事件回调。

该回调运行在共享的 Wi-Fi 事件任务上，不得阻塞。其栈大小由 CONFIG_ESP32_WIFI_EVENT_TASK_STACK_SIZE 决定；繁重的工作（启动 IP 栈、DHCP、NAT）应放到应用程序自己的线程上，或为事件任务栈设置足够大小。仅支持一个回调；重复注册会替换先前的回调。

参数
cb发生 mesh 事件时要调用的回调；为 NULL 时取消注册。

◆ esp_wifi_mesh_send()

int esp_wifi_mesh_send ( const uint8_t * data,
size_t len )

#include <zephyr/drivers/wifi/esp_wifi/esp_wifi_mesh.h>

通过 mesh 发送数据缓冲区。

在非根节点上，缓冲区被向上路由到根节点。在根节点上，它会被发送到路由表中的每个节点。这是供不使用 IP-over-mesh 接口的应用消息使用的便捷路径。

注解
在启用 CONFIG_WIFI_ESP32_MESH_IP 时不可用。IP 接口与本原始路径都会读取同一个 mesh 接收队列且没有解复用，帧会在两个读者之间不确定地分配。在接收路径能够按帧协议标签解复用之前，两者保持互斥。
参数
data要发送的缓冲区。
len要发送的字节数。
返回值
0成功时（在根节点上则为部分成功）。
-EIOmesh 发送出错时。

◆ esp_wifi_mesh_start()

int esp_wifi_mesh_start ( void )

#include <zephyr/drivers/wifi/esp_wifi/esp_wifi_mesh.h>

启动 Wi-Fi mesh 栈。

执行完整的 mesh 启动流程：将 Wi-Fi 置于 AP+STA 模式，依据当前配置（参见 esp_wifi_mesh_set_config()/esp_wifi_mesh_get_config()）以及 mesh 调优 Kconfig 选项初始化并配置 mesh 栈，禁用省电功能，然后启动 mesh。

节点角色取决于 WIFI_ESP32_MESH_ROLE 选项：auto 角色执行自组织选举（需要路由器）；WIFI_ESP32_MESH_FORCE_ROOT 将本节点指定为固定根节点并停止其自组织父节点搜索；WIFI_ESP32_MESH_FORCE_CHILD 阻止节点成为根节点。

需要路由器。树围绕根节点与路由器的关联形成，子节点通过自组织父节点搜索自动接入。完全无路由器的 mesh（根本没有路由器）需要为每个子节点指定显式父节点，而本驱动不做这件事，因此在无路由器时子节点不会接入固定根节点。

注解
mesh 是启动时模式，不支持运行时拆除。一旦启动，它将在节点整个生命周期内常驻；没有停止或反初始化入口，运行期间普通 station/softAP 的 wifi_mgmt 操作（connect、disconnect、ap_enable、scan）都会被拒绝。
返回值
0成功时。
-EINVAL使用 auto 角色但未提供路由器 SSID 时。
-EIO发生 mesh 栈错误时。
