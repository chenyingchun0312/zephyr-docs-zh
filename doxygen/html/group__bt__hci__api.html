枚举值
BT_HCI_QUIRK_NO_RESET 
BT_HCI_QUIRK_NO_AUTO_DLE 
BT_HCI_QUIRK_NO_FLOW_CONTROL 

控制器向主机报告支持控制器到主机的流控命令，但不接受这些命令。主机将该特性视为不支持。

BT_HCI_QUIRK_NO_ADV_TERM_ON_DIR_TIMEOUT 

高占空比广播超时时不产生 LE Advertising Set Terminated 事件。

控制器仅通过连接完成事件来报告用扩展广播命令启用的高占空比可连接定向广播的超时。Core Spec v6.3 Vol 4 Part E 7.8.56 允许该事件、LE Advertising Set Terminated 事件或两者，而主机无法判断控制器发送了哪一个。启用该特殊行为后，它在连接完成事件处结束广播集。永不要为同时发送 LE Advertising Set Terminated 的控制器设置它；主机收到一个时会记录警告。

连接完成事件不指明任何广播集，因此在某个此类集已启用时，主机会以 -EBUSY 拒绝启动第二个此类集，向该集的发送回调报告 0 个已完成事件，并把应用程序重新开始广播时仍在排队的事件当作新广播的结束事件。

◆ bt_hci_close()

int bt_hci_close ( const struct device * dev)
inlinestatic

#include <zephyr/drivers/bluetooth.h>

关闭 HCI 传输。

关闭 HCI 传输。成功时，该函数在传输关闭之前不得返回：此后驱动不再调用 recv 回调，并且可以用 bt_hci_open() 再次打开传输。函数失败时，传输仍处于打开状态，可像之前一样使用。

在 bt_hci_send() 调用进行期间，不得调用该函数；在另一次对该函数的调用或对 bt_hci_open() 的调用进行期间也不得调用；并且它运行期间不得调用 bt_hci_send()。不得从 recv 回调中调用它，这样驱动可以自由地停止其传递数据的线程。它可能阻塞，并从线程上下文调用。

传输必须处于打开状态，参见 bt_hci_send()。

参数
devHCI 设备
返回
成功时为 0，失败时为负的 POSIX 错误号。
返回值
-ENOSYS驱动不支持关闭传输。

◆ bt_hci_get_public_addr()

const bt_addr_t * bt_hci_get_public_addr ( const struct device * dev)

#include <zephyr/drivers/bluetooth.h>

获取驱动要配置的公共身份地址。

返回用 bt_hci_set_public_addr() 存储的地址，供驱动在打开传输时写入控制器。它不会查询控制器。

“无地址”是 BT_ADDR_ANY 而非 BT_ADDR_NONE，尽管后者的名称暗示相反。 BT_ADDR_ANY 是其中的地址部分。 BT_ADDR_LE_ANY, with which the Host marks an identity that has no address, and it is what the setup() op receives in bt_hci_setup_params::public_addr when there is no public identity, so a driver has one check whichever way it gets the address. It is also the all-zero address, so driver data that has never been written already reads as "no address". This function cannot fail, so the driver compares the address it returns with BT_ADDR_ANY, using bt_addr_eq(), before it uses it.

注意
Available only when the following Kconfig option is enabled: CONFIG_BT_HCI_SET_PUBLIC_ADDR.
参数
devHCI 设备
返回
要配置的地址，永不为 NULL，在下一次为该设备调用 bt_hci_set_public_addr() 之前保持有效。它与该地址比较相等。 BT_ADDR_ANY when no public address has been set, or it has been cleared.

◆ bt_hci_open()

int bt_hci_open ( const struct device * dev,
bt_hci_recv_t recv )
inlinestatic

#include <zephyr/drivers/bluetooth.h>

打开 HCI 传输。

打开 HCI 传输以供操作。该函数在传输准备好操作之前不得返回，这意味着此后可以安全地开始调用 send() 处理函数。它可能阻塞，并从线程上下文调用。

当该函数失败时，传输处于关闭状态：驱动已停止该调用所启动的工作，不再调用 recv 回调，且不会为它调用 bt_hci_close()。例外是 -EALREADY：当传输已打开时，该函数不调用驱动即返回该值，并使传输保持打开。

已用 bt_hci_close() 关闭的传输可以再次打开。在另一次对该函数的调用或对 bt_hci_close() 的调用进行期间，不得调用该函数。

参数
devHCI 设备
recv这是一个回调，HCI 驱动通过它向主机提供来自控制器的数据。该回调应在线程上下文中调用，并且可能在 bt_hci_open() 返回之前就被调用。
返回
成功时为 0，失败时为负的 POSIX 错误号。
返回值
-EALREADYHCI 传输已打开。

◆ bt_hci_recv_err()

int bt_hci_recv_err ( const struct device * dev,
struct net_buf * buf )
inlinestatic

#include <zephyr/drivers/bluetooth.h>

从驱动传递 HCI 数据包。

HCI 驱动调用该函数，将从控制器接收的数据传递给主机。缓冲区包含原始 HCI 数据包，其中包括按 H:4 格式编码的数据包类型前缀。

若函数返回 0（成功），则 buf 的引用已移交给上层（例如主机协议栈）。出错时，调用方（HCI 驱动）仍拥有该引用，并负责最终对其调用 net_buf_unref。

参数
devHCI 设备
buf包含从控制器接收的数据的缓冲区。
返回
成功时为 0，失败时为负的 POSIX 错误号。
返回值
-ENOTCONNHCI 传输未打开。

◆ bt_hci_send()

int bt_hci_send ( const struct device * dev,
struct net_buf * buf )
inlinestatic

#include <zephyr/drivers/bluetooth.h>

向控制器发送 HCI 缓冲区。

向控制器发送 HCI 数据包。数据包类型以 H:4（即 UART 传输编码）作为实际负载的前缀编码。这意味着使用 H:4 作为原生编码的 HCI 驱动无需对数据包类型做任何特殊处理。

若函数返回 0（成功），则 buf 的引用已移交给 HCI 驱动。出错时，调用方仍拥有该引用，并负责最终对其调用 net_buf_unref。

传输必须处于打开状态：只能在这 bt_hci_open() 成功返回之后调用该函数，既不能在 bt_hci_close() 调用进行期间调用，也不能在其成功之后调用。没有对此的查询接口：传输的唯一使用者从自己的调用中得知该状态。对未打开的传输调用该函数是调用方的错误，结果未定义，驱动无需检测。此外，在另一次对该函数的调用进行期间不得调用该函数。

注解
该函数只能从协作式线程调用。
参数
devHCI 设备
buf包含要发送给控制器数据的缓冲区。
返回
成功时为 0，失败时为负的 POSIX 错误号。

#include <zephyr/drivers/bluetooth.h>

为控制器设置公共身份地址。

存储驱动应在控制器中配置的公共地址。

当应用程序已用 bt_id_create() 创建公共身份时，Bluetooth Host 会在 bt_hci_open() 之前调用该函数。仅控制器的应用程序同样可以在打开传输之前调用它。

驱动用 bt_hci_get_public_addr() 读取该地址，并在打开传输时或在其 setup() 实现中应用它。

注意

devHCI 设备
addr公共地址，或用 BT_ADDR_ANY 清除先前设置的地址。 BT_ADDR_NONE does not clear it, see bt_hci_get_public_addr().
