◆ arch_mem_map()

int arch_mem_map ( void * virt,
uintptr_t phys,
size_t size,
uint32_t flags )

#include <kernel/include/kernel_arch_interface.h>

将物理内存映射到虚拟地址空间

这是将页映射到地址空间的底层接口。提供未对齐的地址/大小时行为未定义，这些值假定已按 CONFIG_MMU_PAGE_SIZE 对齐。

内核核心负责虚拟地址空间的所有管理；当调用此函数时，我们已确切知道该映射将建立在哪里。如果页表中已为该虚拟内存区域安装了映射，这些映射将被覆盖。

如果目标架构支持多种页大小，目前只会使用最小的页大小。

此操作从不会访问内存范围本身。

此 API 必须可在 ISR 或异常处理程序中安全调用。对此 API 的调用假定是串行化的，实际上所有使用都来自负责虚拟内存管理的 kernel/mm.c。

架构应为整个地址空间预先分配页表，该空间由 CONFIG_KERNEL_VM_BASE 和 CONFIG_KERNEL_VM_SIZE 定义。此操作不应需要为分页结构进行任何形式的分配。

参数校验应通过断言完成。

此 API 属于仍在开发中的基础设施，可能会发生变化。

参数
virt要映射的目标虚拟地址，需页对齐
phys要映射的源物理地址，需页对齐
size所映射内存区域的大小，单位为字节，需页对齐
flags缓存、访问和控制标志，参见 K_MAP_* 宏
返回值
0成功时
-EINVAL传入无效参数时
-ENOTSUP目标架构不支持 flags 中所请求的缓存/属性组合时
-ENOMEM底层页表无法更新时
-errno针对其他失败模式，架构特定的实现可能返回其他负错误码。

◆ arch_mem_page_in()

void arch_mem_page_in ( void * addr,
uintptr_t phys )

#include <kernel/include/kernel_arch_interface.h>

为已换入的数据页更新所有页表

此函数：

  • 将指定的虚拟数据页地址映射到所提供的物理页帧地址，使后续内存访问按预期工作。访问和缓存属性不受影响。
  • 清除对 "accessed" 和 "dirty" 状态的任何记录。

如果使用了多个页表，则必须更新所有页表。此函数在中断锁定的情况下被调用。

对已经换入的数据页调用此函数属于未定义行为。

此 API 属于仍在开发中的基础设施，可能会发生变化。

◆ arch_mem_page_out()

void arch_mem_page_out ( void * addr,
uintptr_t location )

#include <kernel/include/kernel_arch_interface.h>

为已换出的数据页更新所有页表

此函数：

  • 将数据页虚拟地址设置为在被访问时触发故障，该故障可与访问违例或未映射的页区分开。
  • 保存所提供的 location 值，以便在缺页处理程序中为该数据页取回。
  • location 值的语义在此未定义，但该值将始终页对齐。它可能为 0。

如果使用了多个页表，则必须更新所有页表。此函数在中断锁定的情况下被调用。

对已经换出的数据页调用此函数属于未定义行为。

此 API 属于仍在开发中的基础设施，可能会发生变化。

◆ arch_mem_scratch()

void arch_mem_scratch ( uintptr_t phys)

#include <kernel/include/kernel_arch_interface.h>

为临时映射更新当前页表

将物理页帧地址映射到特殊的虚拟地址 K_MEM_SCRATCH_PAGE，并具有管理员模式的读/写权限，使得此函数返回时，调用上下文可以从 K_MEM_SCRATCH_PAGE 地址读/写该页帧的内容。

此映射只需在当前页表集合上完成，因为它仅在短时间内由调用者独占使用。此函数在中断锁定的情况下被调用。

此 API 属于仍在开发中的基础设施，可能会发生变化。

◆ arch_mem_unmap()

int arch_mem_unmap ( void * addr,
size_t size )

#include <kernel/include/kernel_arch_interface.h>

移除指定虚拟地址范围的映射

这是从地址空间取消映射页的底层接口。完成后，相关页表项将被更新，就像该内存范围从未建立过映射一样。不需要保留任何先前的上下文。此函数必须更新所有活动页表中的映射。

提供未对齐的地址/大小时行为未定义，这些值假定已按 CONFIG_MMU_PAGE_SIZE 对齐。

提供的地址范围尚未映射时，行为未定义。

此函数不应需要为分页结构分配内存，也无需释放任何分页结构。因所有包含项都已取消映射而变空的页表可以保留在原处。

实现必须按需使 TLB 失效。

此 API 属于仍在开发中的基础设施，可能会发生变化。

参数
addr要取消映射的起始虚拟地址，需页对齐
size区域大小，需页对齐
返回值
0成功时
-EINVAL传入无效参数时
-errno针对其他失败模式，架构特定的实现可能返回其他负错误码。

◆ arch_page_info_get()

uintptr_t arch_page_info_get ( void * addr,
uintptr_t * location,
bool clear_accessed )

#include <kernel/include/kernel_arch_interface.h>

从页表检索页特性

架构负责维护数据页的 "accessed" 和 "dirty" 状态，以支持标记淘汰算法。这既可由硬件直接支持，也可通过修改保护策略以在读写时产生故障来模拟。在所有情况下，架构都必须以某种方式维护此信息。

对于给定虚拟地址，如果该页已映射且未换出，则报告系统中所有活动页表内相关项的 accessed 与 dirty 状态的逻辑或。

如果 clear_accessed 为 true，则 ARCH_DATA_PAGE_ACCESSED 标志将被复位。此函数将报告其先前状态。如果使用了多个页表，此函数会清除所有页表中的 accessed 状态。

此函数在中断锁定的情况下被调用，以免所报告的信息在据此做出决策期间变得陈旧。

返回值中可能还设置了其他位，调用者必须忽略它们。

对非 ARCH_DATA_PAGE_LOADED 的数据页清除 accessed 状态属于未定义行为。

仅当设置了 ARCH_DATA_PAGE_LOADED 时，返回值中的 ARCH_DATA_PAGE_DIRTY 和 ARCH_DATA_PAGE_ACCESSED 位才有意义，否则请忽略它们。

仅当未设置 ARCH_DATA_PAGE_LOADED 时，返回值中的 ARCH_DATA_PAGE_NOT_MAPPED 位才有意义，否则请忽略它。

除非另有说明，虚拟数据页在所有页表中的映射相同。对此规则的例外数据页（如 scratch 页）调用此函数属于未定义行为。

此 API 属于仍在开发中的基础设施，可能会发生变化。

参数
addr要在页表中查找的虚拟地址
[out]location若非 NULL，则根据 ARCH_DATA_PAGE_LOADED 状态更新为物理页帧地址或后备存储位置。若为 ARCH_DATA_PAGE_NOT_MAPPED，则不修改此项。
clear_accessed是否清除 ARCH_DATA_PAGE_ACCESSED 状态
返回值
Value其中设置了 ARCH_DATA_PAGE_* 各位以反映数据页配置

◆ arch_page_location_get()

enum arch_page_location arch_page_location_get ( void * addr,
uintptr_t * location )

#include <kernel/include/kernel_arch_interface.h>

获取特定地址处页的位置信息

此函数只需查询当前页表集合，因为其报告的信息在使用多个页表时必须对所有页表通用。如果有多个活动页表，无需遍历全部。这可能允许某些类型的优化（例如 x86 上的反向页表映射）。

此函数在中断锁定的情况下被调用，以免所报告的信息在据此做出决策期间变得陈旧。

除非另有说明，虚拟数据页在所有页表中的映射相同。对此规则的例外数据页（如 scratch 页）调用此函数属于未定义行为。只需检查当前安装的页表并返回其中的信息。

参数
addr触发缺页的虚拟数据页地址
[out]location在 ARCH_PAGE_LOCATION_PAGED_OUT 情况下，为用于取回数据页的后备存储位置值；在 ARCH_PAGE_LOCATION_PAGED_IN 情况下，为该页所映射到的物理地址。
返回值
ARCH_PAGE_LOCATION_PAGED_OUT该页已被换出到后备存储。
ARCH_PAGE_LOCATION_PAGED_IN该数据页驻留在内存中。
ARCH_PAGE_LOCATION_BAD该页未映射，或因其他原因发生了无效访问

◆ arch_page_phys_get()

int arch_page_phys_get ( void * virt,
uintptr_t * phys )

#include <zephyr/arch/arch_interface.h>

获取映射到某个虚拟地址的物理地址。

该查询基于调用者当前活动的页表来回答。只有调用者上下文中活动的映射才会被可靠地报告：映射不属于该上下文的虚拟地址（例如属于当前未激活的内存域的内存，或诸如暂存页之类的按上下文数据页）可能被报告为未映射，或解析出不同的结果。对此类地址调用此函数会导致未定义行为。

从实现角度看，只需查询当前已安装的页表，无需遍历系统中的其他页表：通过此 API 合法查询的任何内容在所有页表中的映射都相同。

参数
virt页对齐的虚拟地址
[out]phys映射的物理地址（如果仅检查虚拟地址是否已映射，则可以为 NULL）
返回值
0如果找到映射且其有效
-EFAULT如果虚拟地址未映射

◆ arch_reserved_pages_update()

void arch_reserved_pages_update ( void )

#include <kernel/include/kernel_arch_interface.h>

用保留页更新页帧数据库

系统 RAM 中的某些页帧可能不可用。一个典型例子是类 PC 系统第一个兆字节中的保留区域。

此函数的实现应在 k_mem_page_frames 中将所有相关项标记为 K_PAGE_FRAME_RESERVED。此函数在系统早期初始化时、持有 mm_lock 的情况下被调用。
