详细描述

HID 主机应用程序提供的回调。

通过 bt_hid_host_register() 注册，以接收来自已连接 HID 设备的事件。

一次只能有一个控制通道事务未完成（HID 规范 v1.1.2 第 3.2.1 节）；在响应到达之前，后续请求将返回 -EBUSY。每个请求都有自己的结果回调，该回调报告设备提供的 HANDSHAKE 结果码，因此只有在设备作答时才会被调用。对于始终未得到应答的事务，按 HID 规范 v1.1.2 第 5.2.6 节视为连接已丢失：HID 关联被拆除，并改为调用 disconnected 回调。由于同时最多只有一个未完成的事务，应用程序在发出请求后若看到 disconnected，即可知道该请求已丢失。

void(*) bt_hid_host_cb::get_report(struct bt_hid_host *hid, uint8_t result_code, uint8_t type, struct net_buf *buf)

GET_REPORT result.

对每个 GET_REPORT 事务调用，无论设备是用 DATA 消息作答还是用 HANDSHAKE 拒绝请求（HID 规范 v1.1.2 第 3.2.1.1 节），因此结果在一处处理。

载荷按接收原样交付，在使用 Report ID 时以该 ID 开头。

参数
hidHID 主机实例。
result_codeBT_HID_HS_RSP_SUCCESS，或设备回复的 BT_HID_HS_RSP_ERR_* 错误码。
type报告类型（INPUT/OUTPUT/FEATURE），在以下情况下未定义 result_code is not BT_HID_HS_RSP_SUCCESS.
buf报告载荷（所有权仍归协议栈），未收到 DATA 消息时为 NULL。

◆ vc_unplug

void(*) bt_hid_host_cb::vc_unplug(struct bt_hid_host *hid)

从设备收到虚拟线缆拔出。

远程 HID 设备已发送 VIRTUAL_CABLE_UNPLUG 控制消息，协议栈将断开 HID 关联。HID 规范 v1.1.2 第 3.1.2.2.3 节还要求销毁绑定；这留给应用程序处理，因为 bt_br_unpair() 会丢弃整个 ACL，从而影响任何同址的配置。

拔出到达时仍处于未完成状态的控制事务会被丢弃，因此其结果回调永远不会被调用：按第 3.1.2.2.3 节，接收方会丢弃任何待处理的控制传输。等待此类应答的应用程序必须将本回调视为该事务的结果。

参数
hidHID 主机实例。
