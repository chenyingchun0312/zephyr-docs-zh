详细描述

MUX 控制器接口

多路复用器（信号路由）控制器的通用设备模型。其设备树模型源自 Linux，但本子系统有意不提供共享线路仲裁：没有 mux_control_select()/deselect()，也没有针对单个控制的并发锁。假定一条控制线只有一个所有者；并发消费者同时驱动同一条线路时不受保护。

#include <zephyr/drivers/mux.h>

值:
Z_MUX_STATE_DEFINE_BY_IDX(node_id, idx)

由 mux-states 条目定义 mux_state 对象。

为寻址单元、内嵌的 mux_control, and the mux_state. The leading cells of the specifier become the addressing portion (mux_state.control->cells); the trailing cell becomes mux_state.state.

必须在文件作用域内调用。每个 idx 只应定义一次，以免产生重复存储。

设备树片段示例（一个假想的多通道后端）： 

mux0: mux-controller@... {
        compatible = "vendor,demux";
        #mux-control-cells = <1>;
        #mux-state-cells   = <2>;
        ...
};

n: node { // <控制器通道状态> mux-states = <&mux0 5 2>, <&mux0 7 3>; };

用法示例： 

MUX_STATE_DT_SPEC_DEFINE_BY_IDX(DT_NODELABEL(n), 0);

const struct mux_state *s0 = MUX_STATE_DT_GET_BY_IDX(DT_NODELABEL(n), 0);
// s0->control->cells[0] == 5, s0->state == 2

◆ mux_control_disconnect()

int mux_control_disconnect ( const struct device * dev,
const struct mux_control * control )

#include <zephyr/drivers/mux.h>

物理断开 MUX 控制线。

将被寻址的控制线驱动到其断开/关闭状态，此时不路由任何输入。如何达到该状态取决于后端：可能是一个专用的使能门，它会锁存此前选择的路由以便重新连接（例如使能引脚），也可能是开关阵列的全断开状态（所有底层开关断开）。之后的 mux_control_set() 会重新连接该线路并施加所请求的路由；没有单独的重新连接操作。

受影响的正是被寻址控制线所覆盖的路由单元，与后端设备树绑定中的建模一致。将每个通道建模为独立控制线的后端只断开被寻址的通道；将整个设备建模为单条控制线（#mux-control-cells = 0）的后端会断开整个设备。

可选操作。无法达到断开状态的后端（例如始终驱动某个模式、没有使能线的普通 GPIO 选择总线）会将 disconnect 操作留为 NULL，此时该函数返回 -ENOSYS。

参数
devMUX 控制器设备。
control要断开的控制线的寻址。
返回值
0成功时。
-ENOSYS驱动未实现该操作，或该实例不具备断开能力时返回。
-EINVAL寻址超出范围时返回。
-errno失败时为其他负的 errno。
