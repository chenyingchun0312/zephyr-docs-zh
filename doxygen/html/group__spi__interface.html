SPI 双工模式 @{

部分控制器支持半双工传输，此时使用三线连接。默认采用全双工。

#define SPI_FULL_DUPLEX   (0U << 11)
#define SPI_HALF_DUPLEX   (1U << 11)

SPI 帧格式 @{

提供两种帧格式：Motorola 和 TI。主要区别在于 CS 线的行为。Motorola 格式下 CS 线在整个传输过程中保持有效。TI 格式下 CS 线仅在实际传输前一个串行时钟周期内有效，因此在传输期间无效，传输随时钟结束一并结束。由于 Motorola 格式最为常用，默认采用该帧格式。

#define SPI_FRAME_FORMAT_MOTOROLA   (0U << 15)
#define SPI_FRAME_FORMAT_TI   (1U << 15)

◆ SPI_CS_ACTIVE_HIGH

#define SPI_CS_ACTIVE_HIGH   BIT(14)

#include <zephyr/drivers/spi.h>

片选有效状态配置

若设置此标志，CS 为高有效。若未设置此标志，CS 为低有效。

默认是低有效（未设置），因为这对 SPI 外设来说最常见。

并非所有控制器都能原生处理这一点，此时仍可通过 spi_cs_control 用 GPIO 以软件方式控制 CS

标识谁“锁定”设备的识别信息是传给事务 API 的 spi_config 指针，因此应复用同一个配置来执行另一个事务或释放锁。

注意：此同步函数用于释放对 SPI 设备和/或 CS 线的锁定，前提是且仅是给定的 config 参数是最后一次使用的参数（在上述任何函数中），并且其 operation 位字段中设置了 SPI_LOCK_ON 位和/或 SPI_HOLD_ON_CS 位。如果调用者需要在连续事务中一直占用 SPI 设备，和/或需要设备保持选中状态，则可以使用此函数。通常这两个位会一起使用，这样设备会被锁定并保持到需要另一次操作或使用本函数将其释放为止。

参数
dev驱动实例的设备结构体指针
config指向有效 spi_config 结构体实例的指针。
返回
成功时为 0，失败时为负的 errno 值。

int spi_transceive ( const struct device * dev,
const struct spi_config * config,
const struct spi_buf_set * tx_bufs,
const struct spi_buf_set * rx_bufs )

#include <zephyr/drivers/spi.h>

从 SPI 驱动程序读/写指定数量的数据。

注解
此函数是同步的。
在控制器模式下，片选线会在所提供 buf 集中所有缓冲区的整个传输期间保持有效。只有所有缓冲区都传输完毕后，CS 才会被取消有效。
在外设模式下，数据传输在控制器使 CS 有效并提供时钟时发生。函数将等待控制器完成传输后才返回。CS 由控制器控制，因此在整个传输期间可能不会持续保持有效。
参数
dev驱动实例的设备结构体指针
config指向有效 spi_config 结构体实例的指针。可通过指针比较来检测与之前操作的变化。
tx_bufs待发送数据的来源缓冲区数组，如果没有则为 NULL。
rx_bufs待读取数据写入的目标缓冲区数组，如果没有则为 NULL。
返回
外设模式下接收的帧数；控制器模式下成功时为 0，失败时为负的 errno 值。
返回值
-ENOTSUP设备硬件或驱动程序软件不支持该 spi 配置。
-EINVALspi_config 的某个参数无效。
