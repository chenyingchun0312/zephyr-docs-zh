枚举类型说明

◆ pm_state

enum pm_state

#include <zephyr/pm/state.h>

Power management state

枚举值
PM_STATE_ACTIVE 

运行活动状态

系统完全上电并处于活动状态。

注解
此状态对应 ACPI G0/S0 状态
PM_STATE_RUNTIME_IDLE 

运行空闲状态

运行空闲是一种系统休眠状态，其中所有核心进入尽可能深的空闲状态并等待中断，对设备没有要求，使其保持原有状态。

注解
此状态对应 ACPI S0ix 状态
PM_STATE_SUSPEND_TO_IDLE 

挂起到空闲状态

系统经过正常的平台挂起流程，将所有核心置于尽可能深的空闲状态，并 可能 将外设置于低功耗状态。不会丢失任何运行状态（即 CPU 核心不会丢失执行上下文），因此系统可以很容易地回到原来的位置。

注解
此状态对应 ACPI S1 状态
PM_STATE_STANDBY 

待机状态

除了将外设置于低功耗状态外，所有非启动 CPU 都会断电。相比挂起到空闲，它应能节省更多能量，但恢复延迟通常大于该状态。不过在单处理器系统上，它应与挂起到空闲是相同的状态。

注解
此状态对应 ACPI S2 状态
PM_STATE_SUSPEND_TO_RAM 

挂起到 RAM 状态

此状态通过尽可能多地关闭系统电源来显著节省能量，其中内存应置于自刷新模式以保持其内容。设备和 CPU 的状态被保存并保留在内存中，可能需要 ROM 中的一些引导代码来从该状态恢复系统。

注解
此状态对应 ACPI S3 状态
PM_STATE_SUSPEND_TO_DISK 

挂起到磁盘状态

此状态通过尽可能多地关闭系统电源（包括内存）来显著节省能量。内存内容被写入磁盘或其他非易失性存储，恢复时借助引导代码将其读回内存，使系统恢复到进入挂起到磁盘时的同一执行点。

注解
此状态对应 ACPI S4 状态
PM_STATE_SOFT_OFF 

软关机状态

此状态消耗极少的功率，但需要很长的延迟才能回到运行活动状态。系统（CPU 和内存）的内容不会被保留，因此系统将像从初始上电和内核启动一样重新启动。

注解
此状态对应 ACPI G2/S5 状态
PM_STATE_COUNT 

电源管理状态的数量（内部使用）
