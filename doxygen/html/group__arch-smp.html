◆ arch_cpu_start()

void arch_cpu_start ( int cpu_num,
k_thread_stack_t * stack,
int sz,
arch_cpustart_t fn,
void * arg )

#include <zephyr/arch/arch_interface.h>

在支持多处理器的系统上启动带编号的 CPU

此函数启动并初始化指定的 CPU。启动时主线程运行在 CPU 零上，其他处理器按顺序编号。从此函数返回时，可认为该 CPU 已开始运行，并将进入所提供的函数。其中断将被初始化但处于禁用状态，因此使用所提供键调用 irq_unlock() 即可使能它们。

通常，在 SMP 模式下，此函数由内核初始化调用，不应作为用户 API 使用。但此处定义它，是为了满足那些希望 Zephyr 运行在一个核心上、而使用其他核心进行特定于设计的处理的特殊用途应用。

参数
cpu_numCPU 的整数编号
stack该 CPU 的栈内存
sz栈缓冲区大小，以字节为单位
fn要在该 CPU 上开始运行的函数。
arg传给“fn”的无类型参数

◆ arch_proc_id()

uint32_t arch_proc_id ( void )
inlinestatic

#include <zephyr/arch/arch_interface.h>

处理器硬件 ID

大多数多处理器架构都有一个与当前 CPU 关联的低级唯一 ID 值，可以在内核上下文中快速高效地取回。注意，虽然 CPU 的编号保证唯一，但这些值是由平台定义的。特别是，它们不保证与 Zephyr 自己的顺序 CPU ID 一致（尽管在某些平台上确实一致）。

注解
此 API 存在固有的竞态：系统可能在使用该值之前抢占当前线程并将其迁移到另一个 CPU。若要安全使用，需要确保迁移不可能发生（例如代码处于中断上下文、持有自旋锁，或因 k_cpu_mask 状态而无法迁移）。
返回
当前正在执行 CPU 的唯一 ID
