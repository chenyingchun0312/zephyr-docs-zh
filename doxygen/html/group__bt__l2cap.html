ECRED L2CAP 信令 PDU 中的最大信道数量

目前，这是以下 PDU 中引用的最大信道数量：

  • L2CAP_CREDIT_BASED_CONNECTION_REQ
  • L2CAP_CREDIT_BASED_RECONFIGURE_REQ
警告
该共同点是在这些 PDU 之间推断出来的。Bluetooth 规范将它们视为彼此独立的数字，并不保证未来潜在的 ECRED L2CAP 信令 PDU 具有相同的上限。

◆ bt_l2cap_br_server_register()

int bt_l2cap_br_server_register ( struct bt_l2cap_server * server)

#include <zephyr/bluetooth/l2cap.h>

在面向 BR/EDR 的连接上注册 L2CAP 服务器。

为某个 PSM 注册 L2CAP 服务器，每个新连接都通过 accept() 回调进行授权，若成功则该回调应分配供新连接使用的信道结构。

对于固定的、由 SIG 分配的 PSM（范围为 0x0001-0x0eff），应在调用此 API 之前将 PSM 赋给 server->psm。对于动态 PSM（范围为 0x1000-0xffff），server->psm 可以预先设为给定值（但不推荐），也可以留为 0，此时返回时会为其分配一个新值。对于动态分配的值，期望通过 SDP 记录公开，L2CAP 客户端正是以此发现如何连接到该服务器。

参数
server服务器结构。
返回
成功时为 0，出错时为负值。

◆ bt_l2cap_chan_connect()

int bt_l2cap_chan_connect ( struct bt_conn * conn,
struct bt_l2cap_chan * chan,
uint16_t psm )

#include <zephyr/bluetooth/l2cap.h>

连接 L2CAP 信道

按 PSM 连接 L2CAP 信道，连接完成后将调用信道的 connected() 回调。若连接被拒绝，则改为调用 disconnected() 回调。作为第二个参数传入的信道对象（通过其地址）不应在应用程序中作为独立对象实例化。应用程序应创建传输专用的 L2CAP 对象，即 LE 的 bt_l2cap_le_chan 类型和/或 BR/EDR 的 bt_l2cap_br_chan 类型，然后将作为这两种传输专用对象成员的 bt_l2cap_chan 类型对象的位置（地址）传给此 API。

注解

◆ bt_l2cap_chan_send()

int bt_l2cap_chan_send ( struct bt_l2cap_chan * chan,
struct net_buf * buf )

#include <zephyr/bluetooth/l2cap.h>

向 L2CAP 信道发送数据

将缓冲区中的数据发送到信道。对于动态信道：若没有可用信用额度，则会排队该 buf，并在从对端收到信用额度时发送。

不支持网络缓冲区分片（即 buf->frags）。

在 BR/EDR 连接或固定 L2CAP 信道上发送 L2CAP 数据时，应用程序发送的是 L2CAP PDU。应用程序在发送前必须在缓冲区中预留 BT_L2CAP_CHAN_SEND_RESERVE 个字节。应用程序应使用 BT_L2CAP_BUF_SIZE() 辅助函数为外出缓冲池正确设置缓冲区大小。

在动态 L2CAP 信道上发送 L2CAP 数据时，应用程序发送的是 L2CAP SDU。应用程序应预留 BT_L2CAP_SDU_CHAN_SEND_RESERVE bytes in the buffer before sending. The application can use the BT_L2CAP_SDU_BUF_SIZE() helper to correctly size the buffer to account for the reserved headroom.

将 L2CAP SDU 分段为 L2CAP PDU 时，协议栈会首先尝试从信道的 alloc_seg 回调分配缓冲区，若失败则回退到协议栈的全局缓冲池（其大小 CONFIG_BT_L2CAP_TX_BUF_COUNT).

警告
此函数会覆盖缓冲区的 user_data。不要在其中存放任何内容。一旦调用了此函数，即视为 user_data 的所有权已转移给协议栈。
注解
成功时缓冲区的所有权转移给协议栈；出错时调用方保留缓冲区的所有权。
警告
若缓冲区所属的池定义了销毁回调，则当 HCI 驱动释放缓冲区时，该回调可能从 ISR 上下文调用。因此销毁回调不得调用任何在 ISR 上下文中不安全的同步原语，例如阻塞调用或锁定调度器。
参数
chan要向其发送数据的信道。详情请参见 bt_l2cap_chan_connect。
buf包含数据的缓冲区。
返回
成功时为 0，出错时为负值。
若 buf 或 chan 为 NULL，则为 -EINVAL。
若 chan 既不是基于 BR/EDR 也不是基于 LE，则为 -EINVAL。
若缓冲区没有预留足够字节容纳头部，则为 -EINVAL。
若缓冲区的引用计数 != 1，则为 -EINVAL
若 buf 大于 chan 的 MTU，则为 -EMSGSIZE。
若底层连接已断开，则为 -ENOTCONN。
若 L2CAP 信道已断开，则为 -ESHUTDOWN。
若 chan 为 BR/EDR，则为来自下层的其他错误。
