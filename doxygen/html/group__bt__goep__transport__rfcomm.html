◆ bt_goep_transport_rfcomm_connect()

int bt_goep_transport_rfcomm_connect ( struct bt_conn * conn,
struct bt_goep * goep,
uint8_t channel )

#include <zephyr/bluetooth/classic/goep.h>

通过 RFCOMM 连接 GOEP 传输

通过 RFCOMM 连接 GOEP 传输，连接完成后，回调 bt_goep_transport_ops::connected is called. If the connection is rejected, bt_goep_transport_ops::disconnected callback is called instead. The GOEP object is passed (over an address of it) as second parameter, application should create transport dedicated GOEP object 通用对象交换配置文件（GOEP）. Then pass to this API the location (address). Before calling the API, bt_goep::transport_ops should be initialized with valid address of type bt_goep_transport_ops object. The RFCOMM channel is passed as third parameter. It is the RFCOMM channel of RFCOMM server discovered from the peer device.

bt_obex::rx 的 mtu 字段值将被忽略，取而代之的是根据 CONFIG_BT_GOEP_RFCOMM_MTU 计算出的值。

警告
调用方负责将 GOEP 对象的父对象清零。
注解
accept 回调必须按如下方式初始化返回的 GOEP 实例：
  • 将 bt_goep::transport_ops 设置为有效的操作表。
  • bt_goep::v1 字段应传入所指向的 bt_goep_transport_v1 instance must remain valid (address stable) for the entire lifetime of the transport connection. And bt_goep::v2 should be set to NULL.
  • 初始化版本专属对象中的反向指针 bt_goep_transport_v1::goep to point at the parent 通用对象交换配置文件（GOEP）. The version-specific object must remain valid for the lifetime of the transport.
参数
conn连接对象。
goepGOEP object.
channel要连接的 RFCOMM 通道。
返回
成功时为 0，出错时为负值。

◆ bt_goep_transport_rfcomm_server_register()

int bt_goep_transport_rfcomm_server_register ( struct bt_goep_transport_rfcomm_server * server)

#include <zephyr/bluetooth/classic/goep.h>

注册 GOEP RFCOMM 服务端。

为 RFCOMM 通道 bt_rfcomm_server::channel 注册 GOEP 服务端，每个新连接都通过 bt_goep_transport_rfcomm_server::accept 回调进行授权，成功时应分配供新 GOEP 连接使用的 GOEP 结构 bt_goep。

bt_rfcomm_server::channel may be pre-set to a given value (not recommended however). Or be left as 0, in which case the channel will be auto-allocated by RFCOMM.

参数
server服务器结构。
返回
成功时为 0，出错时为负值。
