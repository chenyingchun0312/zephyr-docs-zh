◆ arch_buffer_validate()

int arch_buffer_validate ( const void * addr,
size_t size,
int write )

#include <zephyr/arch/arch_interface.h>

检查内存区域的权限

在给定内存区域的情况下，返回当前内存管理硬件配置是否允许用户线程读/写该区域。用于系统调用校验来自用户空间的缓冲区。

注意：如果整个缓冲区区域并非用户可访问，则保证此函数绝不会返回校验成功。

如果整个缓冲区的用户访问权限由单个已使能的内存管理区域强制执行，则保证此函数能正确校验所提供缓冲区的权限。

在某些架构上，如果所提供的缓冲区跨越多个已使能的内存管理区域（即使所有这些区域都允许用户访问），校验也将总是返回失败。

警告
大小为零（0）的缓冲区会导致未定义行为。
参数
addr缓冲区的起始地址
size缓冲区的大小
write如果非零，则额外检查该区域是否可写。否则，仅检查该内存是否可读。
返回
如果权限不匹配则为非零。

◆ arch_cohere_stacks()

void arch_cohere_stacks ( struct k_thread * old_thread,
void * old_switch_handle,
struct k_thread * new_thread )
inlinestatic

#include <zephyr/arch/arch_interface.h>

在上下文切换之前确保缓存一致性

当 CONFIG_KERNEL_COHERENCE 为 true 时需要。在缓存不一致的多处理器架构上，出于性能考虑，线程栈默认是被缓存的。因此必须在上下文切换时适当地刷新它们。规则如下：

  1. 旧栈中包含活动数据的区域（一般是当前栈指针与栈内存顶部之间的字节）必须刷新到底层存储，以便运行同一线程的新 CPU 能看到正确的数据。这必须在为线程结构中的 switch_handle 字段赋值（该赋值标志着上下文切换完成）之前发生。
  2. 要从新栈读取的任何数据区域（一般与保存时的活动区域相同）应在数据缓存中失效（且务必不要刷新！）。这是因为自本 CPU 挂起该线程以来，另一个 CPU 可能已运行过该线程或将其重新初始化，缓存中存在的任何数据都将是过期的。
注解
当已选定新线程运行时，内核将在中断退出期间调用此函数，也会在进入 arch_switch() 以执行由代码驱动的上下文切换之前立即调用它。在后一种情况下，很可能在此函数返回之后、切换完成之前还会有更多数据写入 old_thread 栈区域。在许多架构上，仅在此处简单地刷新是不够的，很可能需要与 arch_switch() 的实现协同。
参数
old_thread在允许在其他 CPU 上运行之前需要被刷新的旧线程。
old_switch_handle要存入 old_thread 的切换句柄（在缓存被刷新之前它不会有效，因此目前尚不存在）。如果在 z_swap() 内部，则此值为 NULL（因为 arch_switch() 尚未保存它）。
new_thread在本地运行之前需要被失效的新线程。

◆ arch_syscall_invoke0()

uintptr_t arch_syscall_invoke0 ( uintptr_t call_id)
inlinestatic

#include <zephyr/arch/arch_interface.h>

调用带 0 个参数的系统调用。

出于安全考虑，从超级用户模式返回用户模式时，除返回值外不得保留任何通用寄存器状态。

从用户模式提升到超级用户模式时，要求所有参数都存储在寄存器中。

系统调用的处理在单独的内核栈上进行。从分发表调用系统调用编组器时应使能中断。处理系统调用时可能发生线程抢占。

调用 ID 是不可信的，必须做边界检查，因为该值用于索引系统调用分发表，该表包含指向具体系统调用代码的函数指针。

参数
call_id系统调用 ID
返回
系统调用的返回值。void 系统调用在此处返回 0。

FUNC_NORETURN void arch_syscall_oops ( void * ssf)

#include <zephyr/arch/arch_interface.h>

引发一个看似来自特定位置的内核 oops

通常，k_oops() 会生成一个看似来自 k_oops() 自身调用点的异常。

然而，在校验系统调用的参数时，如果出现问题，我们希望该 oops 看似来自调用系统调用的位置，而不是位于校验函数内部。

参数
ssf系统调用栈帧指针。它作为参数传给 _k_syscall_handler_t 函数，其内容完全与架构相关。

◆ arch_user_mode_enter()

FUNC_NORETURN void arch_user_mode_enter ( k_thread_entry_t user_entry,
void * p1,
void * p2,
void * p3 )

#include <zephyr/arch/arch_interface.h>

执行从超级用户模式到用户模式的单向转换。

此函数的实现必须执行以下操作：

  • 将线程的栈指针重置为合适的初始值。由于这是单向操作，我们不需要任何先前的上下文。
  • 设置供 CPU 在权限提升期间使用的任何内核栈区域
  • 使 CPU 进入其等效的用户模式
  • 在用户模式下将所有提供的参数传给 arch_new_thread() 并转移执行。
参数
user_entry开始以用户线程身份执行的入口点
p1传给用户线程的第 1 个参数
p2传给用户线程的第 2 个参数
p3传给用户线程的第 3 个参数

安全地获取可能无效的字符串的长度

此函数不得触发错误，而是必须将 -1 写入 err 参数。除此之外，此函数的行为应与 libc strnlen() 完全一致。成功时 err should be set to 0.

err要写入的错误值
返回
字符串的长度（不计 NULL 字节），最多到 maxsize

◆ arch_virt_region_align()

size_t arch_virt_region_align ( uintptr_t phys,
size_t size )

#include <zephyr/arch/arch_interface.h>

获取最优的虚拟区域对齐，以优化 MMU 表布局

某些 MMU 硬件要求区域对齐到某种中间块对齐，以减少表的使用量。此调用返回最优的虚拟地址对齐，以便在随后的 MMU 映射调用中实现此类优化。

参数
[in]phys要映射区域的物理地址，需按 CONFIG_MMU_PAGE_SIZE 对齐
[in]size要映射区域的大小，需按 CONFIG_MMU_PAGE_SIZE 对齐
返回
要应用到此区域虚拟地址上的对齐
