#include <zephyr/bluetooth/audio/csip.h>

bt_csip_set_coordinator_ordered_access() 的回调

若传给 bt_csip_set_coordinator_ordered_access() 的任何集成员处于锁定状态，则以 locked 为 true 调用此回调，member 为被锁定的成员，并且有序访问过程被取消。同样，若发生任何错误，该过程也会中止。

参数

err错误值。成功时为 0，失败时为 GATT 错误或 ERRNO。
locked锁是被锁定还是被释放。
member若 locked 为 true，则为被锁定的成员，否则为 NULL。

◆ bt_csip_set_coordinator_size_changed_cb

typedef void(*) bt_csip_set_coordinator_size_changed_cb(struct bt_conn *conn, const struct bt_csip_set_coordinator_csis_inst *inst)

#include <zephyr/bluetooth/audio/csip.h>

所连接设备的某个集大小发生变化时的回调。

由于一个集中的所有设备应具有相同的集大小值。每个已连接设备可能通过通知发送相同的新大小，前提是远端设备支持集大小通知。

集中的每个设备等级也可能随之变化，因此建议调用 bt_csip_set_coordinator_discover() 重新发现并读取各设备上集的特性值。

参数
conn指向远端设备的指针。
inst发生变化的协调集标识服务实例。新大小存放在 inst->info.size 中。

◆ bt_csip_set_coordinator_ordered_access()

int bt_csip_set_coordinator_ordered_access ( const struct bt_csip_set_coordinator_set_member * members[],
uint8_t count,
const struct bt_csip_set_coordinator_set_info * set_info,
bt_csip_set_coordinator_ordered_access_t cb )

#include <zephyr/bluetooth/audio/csip.h>

作为客户端以有序方式访问协调集设备

此函数会读取所有设备的锁状态，若所有设备都处于未锁定状态，则以与 members 相同的成员调用 cb，但成员按等级（若存在）排序。此过程完成后或发生错误后， bt_csip_set_coordinator_cb::ordered_access will be called.

仅当所有成员都具有锁定特征，且全部 rank = 0 或等级互不相同时，此过程才可工作。

若有任何成员处于锁定状态，过程将被取消。

只能对已绑定的成员执行此操作。

参数
members要访问的集成员数组。
countmembers 中的集成员数量。
set_info指向特定 set_info 结构体的指针，因为一个成员可能属于多个集。
cb要为每个成员调用的回调函数。

为服务实例设置新的大小和等级

此函数可用于动态更改服务实例的大小和等级。需要注意的是，一个集中的多个设备不能具有相同等级，这需要由该函数的调用者保证。同样，重要的是集中所有设备同时更新大小。设备的等级不能单独修改，只有当 size 与当前集大小不同才能设置新等级。

若启用了 CONFIG_BT_CSIP_SET_MEMBER_SIZE_NOTIFIABLE，这还会向所有已连接或已绑定的客户端发送通知。

在启用 CONFIG_BT_CSIP_SET_MEMBER_SIZE_SUPPORT 或 CONFIG_BT_CSIP_SET_MEMBER_RANK_SUPPORT is enabled. The disabled parameter (i.e. rank or size) will not be set.

参数
svc_inst服务实例。
size新的集大小。
rank新的等级。
返回值
-EINVALsvc_inst 为 NULL，size 小于 1，或对于可锁定的 svc_inst，rank 小于 1 或大于 size。
-EALREADYsize 已设置。
0Success.
