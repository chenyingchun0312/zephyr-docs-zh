详细描述

HID 应用程序提供的回调

应用程序应通过 bt_hid_device_register() 注册一个此回调表实例，以接收来自 HID 主机的事件和请求。只需提供应用程序所需的回调；未实现的回调应设为 NULL。

◆ get_report

int(*) bt_hid_device_cb::get_report(struct bt_hid_device *hid, uint8_t type, bool size_present, struct net_buf *req, struct net_buf *rsp)

Get_Report 请求回调

当主机发送 GET_REPORT 请求时同步调用。此回调是必需的（按 HID 规范 v1.1.2 必须支持 GET_REPORT），并且必须在注册时提供。

应用程序在回调内通过以下方式作出应答：将报告载荷追加到 rsp（如果报告描述符声明了 Report ID，还包括 Report ID 字节）并返回 0。随后协议栈会在前面加上 HIDP DATA 报头并发送响应。

如果尚无可用数据，返回 -EAGAIN；协议栈将回复 NOT_READY 握手，主机可重试（HID 规范 v1.1.2 第 3.2.1.1 节）。其他任何负 errno 都会触发相应的握手错误响应。

req contains the remaining GET_REPORT parameters after the HIDP header: an optional Report ID (present per the report descriptor) followed, when size_present is true, by a 2-byte little-endian BufferSize (the maximum response length the host expects). When size_present is false no BufferSize is present.

参数
hidHID 设备对象。
type报告类型（参见 BT_HID_REPORT_TYPE_*）。
size_present如果请求的 Size 位已设置则为 true，表示 req 中在可选的 Report ID 之后还有一个 2 字节的 BufferSize。
req其余请求参数（所有权仍归协议栈）。
rsp要用报告载荷填充的响应缓冲区（所有权仍归协议栈；返回 0 时由协议栈发送）。
返回
如果 rsp 已填入响应则为 0，若要以 NOT_READY 回复则为 -EAGAIN，其他负 errno 表示握手错误。

Set_Protocol 请求回调

当主机发送 SET_PROTOCOL 请求时调用。如果支持该协议模式，应用程序应返回 0；如果不支持，则返回负 errno。驱动会根据返回值更新内部协议模式标志并发送相应的 HANDSHAKE 响应。

参数
hidHID 设备对象。
protocol请求的协议模式（BT_HID_PROTOCOL_BOOT_MODE 或 BT_HID_PROTOCOL_REPORT_MODE）。
返回
如果接受该协议模式则为 0，否则为负 errno。

int(*) bt_hid_device_cb::set_report(struct bt_hid_device *hid, uint8_t type, struct net_buf *buf)

Set_Report 请求回调

此回调提供 HID 主机发送的报告数据。此回调是必需的（按 HID 规范 v1.1.2 必须支持 SET_REPORT），并且必须在注册时提供。

缓冲区包含按原样接收的原始 Report Data Payload，如果在描述符中声明了 Report ID 字节，也包含该字节。返回 0 表示接受该报告。返回负的 errno 以触发相应的握手错误响应。

参数
hidHID 设备对象。
type报告类型（参见 BT_HID_REPORT_TYPE_*）。
buf报告载荷缓冲区（所有权仍归协议栈）。
返回
成功时为 0，失败时为负的 errno。

◆ suspend

void(*) bt_hid_device_cb::suspend(struct bt_hid_device *hid, bool suspended)

挂起或退出挂起通知回调

SUSPEND 和 EXIT_SUSPEND 是由 HID 主机拥有的单向 HID_CONTROL 消息。此回调只是将收到的每条此类消息转发给应用程序；设备自身不维护任何挂起状态机。根据 HID 配置，检测到本地用户活动的挂起设备会通过重新连接唤醒主机，之后主机（可选地）发出 EXIT_SUSPEND。请注意 EXIT_SUSPEND 不是必需的，因此应用程序不能依赖它退出挂起状态。

由于消息是原样转发的，该回调可能在主机每次发送 SUSPEND/EXIT_SUSPEND 时触发，包括重复的消息。如果应用程序需要在重新连接之间保持幂等或按对端的挂起行为（例如 HID DRE/BV-09-C），则需自行跟踪，并以从 ACL 连接获得的对端标识作为键。

参数
hidHID 设备对象。
suspended进入挂起时为 true，退出挂起时为 false。

◆ vc_unplug

void(*) bt_hid_device_cb::vc_unplug(struct bt_hid_device *hid)

虚拟线缆拔出（Virtual Cable Unplug）通知回调

当 HID 主机发送 VIRTUAL_CABLE_UNPLUG HID_CONTROL 消息时调用。按 HID 规范 v1.1.2 第 3.1.2.2.3 节，接收方应销毁为对端存储的所有绑定和虚拟线缆信息。

协议栈会代应用程序拆除 INTR 和 CTRL 通道，但不会清除绑定：清除绑定需要丢弃链路密钥（并视情况丢弃 ACL），这可能影响共享同一 ACL 的其他配置。因此，应用程序负责在适当时机清除绑定信息，例如：

struct bt_conn *conn = bt_hid_device_get_conn(hid);
if (conn != NULL) {
bt_br_unpair(bt_conn_get_dst_br(conn));
bt_conn_unref(conn);
}
