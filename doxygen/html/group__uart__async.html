◆ uart_event_type

enum uart_event_type

#include <zephyr/drivers/uart.h>

UART_ASYNC_API 中传给回调的事件类型

接收：

  1. 要开始接收，必须使用第一个缓冲区调用 uart_rx_enable
  2. 当开始接收到当前缓冲区时，会生成 #UART_RX_BUF_REQUEST，用户可对此做出如下响应：
    • 使用 uart_rx_buf_rsp 提供第二个缓冲区，当第一个缓冲区填满时，接收将自动切换到第二个缓冲区。
    • 忽略该事件，这样当前缓冲区填满后会生成 UART_RX_RDY 事件并停止接收。
  3. 如果接收到了一些数据并发生超时，将生成 UART_RX_RDY 事件。同一缓冲区中可能出现多次。RX 超时从最后接收的字节开始计算，即如果没有收到数据，就不会有超时事件。
  4. 当驱动程序不再使用当前缓冲区时，会生成 UART_RX_BUF_RELEASED 事件。它会紧跟在 UART_RX_RDY 事件之后。取决于实现，缓冲区可能在被完全或部分填满时释放。
  5. 如果提供了第二个缓冲区，它将成为当前缓冲区，然后从第 2 步重新开始。如果未指定第二个缓冲区，则停止接收并生成 UART_RX_DISABLED 事件。之后可重复整个过程。

在接收期间的任何时候都可能发生 UART_RX_STOPPED 事件。如果接收到了任何数据，将生成 UART_RX_RDY 事件。随后会为当前传给驱动程序的每个缓冲区生成 UART_RX_BUF_RELEASED 事件，最后生成 UART_RX_DISABLED 事件。

可使用 uart_rx_disable 禁用接收；调用该函数后，如果接收到了任何数据，将生成 UART_RX_RDY 事件。随后会为当前传给驱动程序的每个缓冲区生成 UART_RX_BUF_RELEASED 事件，最后发生 UART_RX_DISABLED 事件。

发送：

  1. 发送由 uart_tx 函数开始。
  2. 如果整个缓冲区已发送完毕，则生成 #UART_TX_DONE。如果发生超时，则生成 #UART_TX_ABORTED。

可使用 uart_tx_abort 中止发送，调用该函数后会生成 UART_TX_ABORTED 事件。

枚举值
UART_TX_DONE 

整个 TX 缓冲区已发送完毕。

UART_TX_ABORTED 

由于超时或调用 uart_tx_abort 而中止了发送

启用流控时，TX 传输有可能无法在分配的时间内完成。部分数据可能已被传输，相关信息可在事件数据中找到。

UART_RX_RDY 

接收到的数据已就绪可供处理。

在以下情况下会生成此事件：

  • 发生 RX 超时，且数据已存储在提供的缓冲区中。同一缓冲区中可能出现多次。
  • 提供的缓冲区已满时。
  • 调用 uart_rx_disable() 之后。
  • 由于外部事件（#UART_RX_STOPPED）而停止之后。
UART_RX_BUF_REQUEST 

驱动程序请求下一个缓冲区以实现连续接收。

当开始接收到新缓冲区时会触发此事件，即此时应提供下一个缓冲区以实现无缝切换。为实现连续可靠的接收，用户应通过 uart_rx_buf_rsp 函数响应此事件提供另一个 RX 缓冲区

如果在当前缓冲区填满之前未调用 uart_rx_buf_rsp，接收将停止。

UART_RX_BUF_RELEASED 

缓冲区不再被 UART 驱动程序使用。

UART_RX_DISABLED 

RX 已禁用，可重新启用。

当接收器已停止、被禁用或已完成其操作，且可以使用 uart_rx_enable 再次启用时，会生成此事件

UART_RX_STOPPED 

RX 由于外部事件而停止。

原因为 uart_rx_stop_reason 之一。

size_t len )
inlinestatic

#include <zephyr/drivers/uart.h>

响应 UART_RX_BUF_REQUEST 事件提供接收缓冲区。

提供指向 RX 缓冲区的指针，它将在当前缓冲区填满时使用。

注解
提供驱动程序已在使用中的缓冲区会导致未定义行为。缓冲区在由驱动程序释放后才可复用。

devUART 设备实例。
buf指向接收缓冲区的指针。
len缓冲区长度。
返回
成功时为 0，失败时为负的 errno 值。
返回值
-ENOTSUPAPI 未启用。
-EBUSY下一个缓冲区已设置。
-EACCES接收器已被禁用（函数调用得太晚？）。

◆ uart_rx_disable()

int uart_rx_disable ( const struct device * dev)

#include <zephyr/drivers/uart.h>

禁用 RX

将为每个已安排的缓冲区生成 UART_RX_BUF_RELEASED 事件，之后会生成 UART_RX_DISABLED 事件。此外，如果存在任何待处理的已接收数据，这些数据的 UART_RX_RDY 事件将在 UART_RX_BUF_RELEASED 事件之前生成。

参数
devUART 设备实例。
返回
成功时为 0，失败时为负的 errno 值。
返回值
-ENOTSUPAPI 未启用。
-EFAULT没有活动的接收。

◆ uart_rx_enable()

int uart_rx_enable ( const struct device * dev,
uint8_t * buf,
size_t len,
int32_t timeout )

#include <zephyr/drivers/uart.h>

开始通过 UART 接收数据。

函数将给定缓冲区设为接收的第一个缓冲区并立即返回。之后会以 UART_RX_RDY 或 UART_RX_BUF_REQUEST 事件调用通过 uart_callback_set 设置的事件处理函数。

参数
devUART 设备实例。
buf指向接收缓冲区的指针。
len缓冲区长度。
timeout接收到至少一个字节后的空闲时间，超过该时间会触发 UART_RX_RDY 事件。单位为微秒。 SYS_FOREVER_US disables timeout. See uart_event_type for details.
返回
成功时为 0，失败时为负的 errno 值。
返回值
-ENOTSUPAPI 未启用。
-EBUSYRX 已在进行中。
