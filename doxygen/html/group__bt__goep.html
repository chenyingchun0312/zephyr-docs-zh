◆ bt_goep_transport_state

enum bt_goep_transport_state

#include <zephyr/bluetooth/classic/goep.h>

GOEP 传输的生命周期状态。

仅由内部 API 使用，用于根据运行上下文将 GOEP 设置为适当的传输状态。

GOEP 传输在以下情况下进入 BT_GOEP_TRANSPORT_CONNECTING 状态： bt_goep_transport_l2cap_connect, bt_goep_transport_rfcomm_connect or upon returning from bt_goep_transport_rfcomm_server::accept and bt_goep_transport_l2cap_server::accept.

当 GOEP 传输离开 BT_GOEP_TRANSPORT_CONNECTING 状态并进入 BT_GOEP_TRANSPORT_CONNECTED 时，会调用 bt_goep_transport_ops::connected。

当 GOEP 传输从其他状态进入 BT_GOEP_TRANSPORT_DISCONNECTED 时， bt_goep_transport_ops::disconnected is called.

枚举值
BT_GOEP_TRANSPORT_DISCONNECTED 

GOEP 已断开

BT_GOEP_TRANSPORT_CONNECTING 

GOEP 处于连接中状态

BT_GOEP_TRANSPORT_CONNECTED 

GOEP 已就绪，可在其上承载上层流量

BT_GOEP_TRANSPORT_DISCONNECTING 

GOEP 处于断开中状态

◆ bt_goep_create_pdu()

struct net_buf * bt_goep_create_pdu ( struct bt_goep * goep,
struct net_buf_pool * pool )

#include <zephyr/bluetooth/classic/goep.h>

在为 GOEP 预留头部空间后从给定池中分配缓冲区

对于基于 RFCOMM 的 GOEP 连接，预留的头部空间包括 OBEX、RFCOMM、L2CAP 和 ACL 报头。对于基于 L2CAP 的 GOEP 连接，预留的头部空间包括 OBEX、L2CAP 和 ACL 报头。
