Driver Operations Bluetooth HCI driver operations

This is the driver API structure any Bluetooth HCI driver needs to define. It contains function pointers to the operations the driver implements, as well as any other driver-specific constant data.

Members marked with REQ MUST be set by the driver, whereas those marked with OPT are optional.

参见
DEVICE_DT_INST_DEFINE()
DEVICE_DT_DEFINE()
DEVICE_API()

这些操作服务于该 API 的所有使用者，Bluetooth Host 只是其中之一：仅控制器的应用程序或测试以相同方式打开、关闭和发送。因此，除 setup() 之外，它们不使用 Host 的 HCI 命令 API（bt_hci_cmd_alloc()、bt_hci_cmd_send()、bt_hci_cmd_send_sync()）。分配器 the buffer API, bt_hci_recv() and bt_hci_recv_err() are what a driver delivers its data with, and not meant by that. A driver that has HCI commands of its own to exchange with its controller does so over its own transport, for which the Bluetooth HCI 数据包辅助函数 and the Bluetooth HCI lockstep 命令辅助函数 exist, and only inside open() and close(), while the transport is not in the hands of its user.

对于同一设备，bt_hci_open()、bt_hci_close() 和 bt_hci_send() 不能并发调用：在另一个调用或同一函数的另一次调用进行期间，不得调用其中任何一个。一个传输只有一个使用者，即打开它的那一方，也就是 Bluetooth Host，或在不含 Host 的构建中的应用程序。该使用者一次只发起一个调用，并遵守这三个函数所记载的限制，驱动无需防御其他情况。
