详细描述

通用音频配置文件（CAP）

自从
3.2
版本
0.8.0

通用音频配置文件（Common Audio Profile，CAP）提供在单个设备或设备组上启动、更新和停止单播与广播音频流的过程，这些过程基于基本音频配置文件（Basic Audio Profile，BAP）。该配置文件还提供在设备组上控制音量和设备输入的过程，这些过程基于音量控制配置文件（VCP）与麦克风控制配置文件（MICP）。该规范还引用了通用音频服务（Common Audio Service，CAS）。

◆ bt_cap_commander_cancel()

int bt_cap_commander_cancel ( void )

#include <zephyr/bluetooth/audio/cap.h>

取消当前任何通用音频配置文件指挥者过程

这会阻止当前过程继续执行，从而可以运行新的通用音频配置文件过程。

如果现有过程耗时超出预期，建议执行此操作，这可能表示通用音频配置文件接受方缺少响应。

此操作不会向当前过程涉及的任何通用音频配置文件接受方发送请求，因此调用之后仍可能收到这些接受方的通知。因此建议仅在过程已停滞时使用，或在调用之后等待一小段时间再启动新的通用音频配置文件过程，以避免收到已取消过程的通知。等待时长取决于连接间隔、前一个过程中的设备数量以及通用音频配置文件接受方的行为。

此操作会调用该过程的各个回调，其中连接指针置为 NULL，err 值置为 -ECANCELED。

使用 bt_cap_initiator_unicast_audio_cancel() 取消任何 CAP 发起方过程。使用 bt_cap_handover_cancel() 取消任何 CAP 移交过程。

返回值
0成功时
-EALREADY若没有活动过程
-EOPNOTSUPP有过程处于活动状态，但它不是指挥者过程。

◆ bt_cap_commander_discover()

int bt_cap_commander_discover ( struct bt_conn * conn)

#include <zephyr/bluetooth/audio/cap.h>

发现远端设备上的音频支持。

这会在远端设备上发现通用音频服务（CAS），以确认远端设备是否支持通用音频配置文件。

注解
此函数需要启用 CONFIG_BT_CAP_COMMANDER。如果 CONFIG_BT_CAP_INITIATOR is also enabled, it does not matter if bt_cap_commander_discover() or bt_cap_initiator_unicast_discover() is used.
参数
conn与远端服务器的连接。
返回值
0成功
-EINVALconn 为 NULL
-ENOTCONNconn 未连接
-ENOMEM无法为请求分配内存
-EBUSY已在为 conn 执行发现
