◆ ipm_complete()

void ipm_complete ( const struct device * ipmdev)

#include <zephyr/drivers/ipm.h>

通知异步命令完成

某些 IPM 后端能够异步投递命令。回调将在中断上下文中被调用，但消息（包括提供的数据指针）会保持“活动”且未确认状态，直到后续代码（大概在线程模式下）调用 ipm_complete()。

显然，在不支持异步的驱动上该函数是空操作。

参数
ipmdev驱动实例指针。

◆ ipm_send()

int ipm_send ( const struct device * ipmdev,
int wait,
uint32_t id,
const void * data,
int size )

#include <zephyr/drivers/ipm.h>

尝试通过 IPM 设备发送消息。

消息在远端中断处理程序执行完毕后即被视为已消费。若远端存在延迟处理，或者外发消息必须排队并等待事件/信号量，可由高层驱动实现这些机制。

可发送的数据量以及 ID 的最大值都有约束。请使用 ipm_max_data_size_get 和 ipm_max_id_val_get 例程来确定这些约束。

size 参数仅在发送端用于确定要放入消息寄存器的数据量，不会传递给接收端。读回的数据量由上层协议规定。

参数
ipmdev驱动实例
wait若非零，则一直忙等待直到远端消费该消息。消息在远端中断处理程序执行完毕后即被视为已消费。若远端存在延迟处理，或者希望将外发消息排队并等待事件/信号量，可以在高层驱动中实现这些机制
id消息标识符。其取值受以下限制 ipm_max_data_size_get since many boards only allow for a subset of bits in a 32-bit register to store the ID.
data指向消息中所发送数据的指针。
size数据大小。
返回值
-EBUSY远端尚未读取上次发送的数据时返回。
-EMSGSIZE驱动不支持所给数据大小时返回。
-EINVAL存在错误参数时返回，例如：ID 值过大，或该设备不是出站 IPM 通道。
0成功时。
