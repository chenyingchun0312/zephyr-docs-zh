详细描述

数字音频接口的接口。

自从
3.1
版本
0.9.0

DAI API 为标准的 I2S（SSP）及其常见变体提供支持，也支持 DMIC、HDA 和 SDW 后端。该 API 有一个带专用数据参数的配置函数，用于设备/厂商特定配置。此外还有可选的时间戳函数，用于获取设备特定的音频时钟时间。

◆ dai_trigger_cmd

enum dai_trigger_cmd

#include <zephyr/drivers/dai.h>

触发命令

枚举值
DAI_TRIGGER_START 

开始数据的发送/接收。

若设置了 DAI_DIR_TX，则必须通过 dai_write() 函数排队一些数据以供发送。该触发只能在 READY 状态下使用，并将接口状态改为 RUNNING。

DAI_TRIGGER_PRE_START 

可选——在数据发送/接收之前预先启动。

允许 DAI 和下游编解码器通过启动下游 PLL/FLL 锁定所需的时钟，为音频 Tx/Rx 做好准备。

DAI_TRIGGER_STOP 

停止数据的发送/接收。

在当前内存块结束时停止数据的发送/接收。该触发只能在 RUNNING 状态下使用，并首先将接口状态改为 STOPPING。当当前 TX/RX 块发送/接收完毕时，状态改为 READY。后续的 START 触发将从停止处继续发送/接收。

DAI_TRIGGER_PAUSE 

暂停数据的发送/接收。

在当前内存块结束时暂停数据的发送/接收。行为取决于具体实现，但通常该状态不会完全停止时钟或传输。DAI 可能发送 0（静音），但不从外部消费数据。

DAI_TRIGGER_POST_STOP 

可选——在数据发送/接收之后停止。

允许 DAI 和下游编解码器在音频 Tx/Rx 之后通过停止下游音频完成所需的时钟来干净地关闭。

DAI_TRIGGER_DRAIN 

清空发送队列。

发送发送队列中的所有数据并停止发送。若将该触发应用于 RX 队列，则效果与 DAI_TRIGGER_STOP 相同。该触发只能在 RUNNING 状态下使用，并首先将接口状态改为 STOPPING。当所有 TX 块发送完毕时，状态改为 READY。

DAI_TRIGGER_DROP 

丢弃发送/接收队列。

立即停止发送/接收并丢弃相应队列的内容。该触发可在除 NOT_READY 之外的任何状态下使用，并将接口状态改为 READY。

DAI_TRIGGER_PREPARE 

在发生欠载/溢出错误后准备队列。

该触发只能在 ERROR 状态下使用，并将接口状态改为 READY。

DAI_TRIGGER_RESET 

复位

该触发释放资源并使驱动回到初始状态。

DAI_TRIGGER_COPY 

复制

该触发为数据复制做准备。

#include <zephyr/drivers/dai.h>

DAI 驱动的配置操作。

dir 参数指定将通过 cfg 参数所提供的数据来配置发送（TX）还是接收（RX）方向。

该函数只能在 NOT_READY 或 READY 状态下调用。若执行成功，函数会将接口状态改为 READY。

若调用该函数时参数 cfg->rate 设为 0，则接口状态将被改为 NOT_READY。

参数
dev指向该驱动实例设备结构的指针。
cfg包含配置参数的结构体的指针。
bespoke_cfg包含专用配置的结构体的指针。
size专用配置的大小。
返回值
0If successful.
-EINVAL无效参数。
-ENOSYS不支持 DAI_DIR_BOTH 值。

◆ dai_config_update()

int dai_config_update ( const struct device * dev,
const void * bespoke_cfg,
size_t size )

#include <zephyr/drivers/dai.h>

在运行时更新 DAI 配置。

该函数在运行时更新 DAI 接口的配置。它允许设置 DAI 实现特定的专用配置参数，从而能够在完整配置数据块的常规流程之外进行更新。专用配置的细节因每个 DAI 实现而异。仅当 DAI 处于 READY 状态时才应调用该函数，以确保配置更新在数据传输或接收开始之前生效。

参数
dev指向该驱动实例设备结构的指针。
bespoke_cfg包含专用配置参数的缓冲区的指针。
sizebespoke_cfg 缓冲区的大小，以字节为单位。
返回值
0If successful.
-ENOSYS若未实现配置更新操作。
<0失败时为负的 errno 错误码。
