◆ bt_audio_codec_cfg_get_frame_blocks_per_sdu()

int bt_audio_codec_cfg_get_frame_blocks_per_sdu ( const struct bt_audio_codec_cfg * codec_cfg,
bool fallback_to_default )

#include <zephyr/bluetooth/audio/audio.h>

从 Bluetooth 编解码器配置中提取每个 SDU 中的音频帧块数

总 SDU 大小为 octets_per_frame * frame_blocks_per_sdu * 声道数。

如果不存在此值，应使用默认值 1。

帧块是表示同一时间段但不同声道数据的一个或多个帧。如果流有两个音频声道且此值为 2，则 SDU 中将有四个帧。

参数
codec_cfg要从中提取数据的编解码器配置。
fallback_to_default若为 true，当 codec_cfg.id 为 BT_HCI_CODING_FORMAT_LC3 且未找到该类型时，此函数将返回默认值 1。
返回值
frame_blocks_per_sdu每个 SDU 中编解码器帧块的数量。
-EINVAL参数无效
-ENODATA未找到数据
-EBADMSG找到的值的长度或取值无效

◆ bt_audio_codec_cfg_get_octets_per_frame()

int bt_audio_codec_cfg_get_octets_per_frame ( const struct bt_audio_codec_cfg * codec_cfg)

#include <zephyr/bluetooth/audio/audio.h>

从 Bluetooth 编解码器配置中提取帧大小（字节）

总 SDU 大小为 octets_per_frame * blocks_per_sdu。

Bluetooth 规范未明确说明此值：规范并未规定编解码器只能使用该 SDU 大小。像 LC3 这样的编解码器支持可变比特率（按 SDU），因此编码器可能被允许将帧大小减小到该值以下。因此建议使用实际收到的 SDU 大小除以 blocks_per_sdu，而不要依赖此 octets_per_sdu 值保持不变。

参数
codec_cfg要从中提取数据的编解码器配置。
返回值
frame_length帧长度，单位为字节
-EINVAL参数无效
-ENODATA未找到数据
-EBADMSG找到的值的长度或取值无效
