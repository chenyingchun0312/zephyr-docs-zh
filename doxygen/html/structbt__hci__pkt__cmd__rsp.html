详细描述

解码后的 HCI 命令响应。

由 bt_hci_pkt_pull_cmd_complete()、bt_hci_pkt_pull_cmd_status() 和 bt_hci_pkt_parse_cmd_rsp() 从 HCI_Command_Complete 或 HCI_Command_Status 事件中填充。

结构体成员变量说明

◆ ncmd

uint8_t bt_hci_pkt_cmd_rsp::ncmd

Num_HCI_Command_Packets.

控制器还可接受的后续 HCI 命令数据包数量。

◆ opcode

uint16_t bt_hci_pkt_cmd_rsp::opcode

该事件所响应的命令的操作码。

BT_OP_NOP when the event responds to no command and only updates the number of command packets the controller accepts.

◆ rp

const uint8_t* bt_hci_pkt_cmd_rsp::rp

命令的返回参数。

指向解码后的事件内部，并以状态开始，作为 bt_hci_rp_* structures do. HCI_Command_Status carries no return parameters: rp_len is then 0 and rp points just past the event parameters, so that a zero-length copy stays well defined.

◆ rp_len

size_t bt_hci_pkt_cmd_rsp::rp_len

rp 的长度，单位为字节。

◆ status

uint8_t bt_hci_pkt_cmd_rsp::status

状态码（BT_HCI_ERR_*）。

对于 HCI_Command_Complete，这是第一个返回参数。仅当 opcode 不是 BT_OP_NOP 时才有意义：该事件不响应任何命令且不携带状态，此时该字段为 BT_HCI_ERR_SUCCESS. Match opcode before acting on it. When an HCI_Command_Complete for a command lacks the status its return parameters start with, reported as -ENODATA by the decoders, the field is BT_HCI_ERR_UNSPECIFIED.
