◆ coap_client_payload_cb_t

typedef int(*) coap_client_payload_cb_t(size_t offset, const uint8_t **payload, size_t *len, bool *last_block, void *user_data)

#include <zephyr/net/coap_client.h>

为 CoAP 请求提供有效载荷的回调。

为 CoAP 客户端请求提供有效载荷的可选回调。若在以下位置设置 coap_client_request, the CoAP client library will call this callback when preparing a PUT/POST request.

调用时，库会向应用程序提供该传输的当前有效载荷偏移和有效载荷块大小。应用程序则设置有效载荷指针、有效载荷大小，以及是否预期还有更多数据块的信息。在首次回调调用时将 last_block 参数设为 false 会触发块传输上传。库会持续调用该回调，直到 last_block parameter is set to true.

注解
若使用块传输，应用程序应提供完整的有效载荷块。只有最后一块（即在 last_block 被设为 true 时）可以短于所请求的块大小。
参数
offset有效载荷相对于块传输起始位置的偏移。
payload指向包含有效载荷块的缓冲区的指针。
len输入时为请求的（最大）块大小，输出时为实际有效载荷长度。
last_block指向表示是否预期还有更多有效载荷块的标志的指针。
user_data用户提供的上下文。
返回
成功时为零，返回负的错误码以中止上传。

◆ coap_client_response_cb_t

typedef void(*) coap_client_response_cb_t(const struct coap_client_response_data *data, void *user_data)

#include <zephyr/net/coap_client.h>

CoAP 请求的回调。

此回调针对 CoAP 客户端请求的响应被调用。它用于指示错误、来自服务器的响应码，或交付有效载荷。块传输会导致此回调按有效载荷偏移递增顺序被多次调用，且 payload 参数所指向的缓冲区中只有部分内容。

对于组播请求，回调会针对每个作出响应的服务器各调用一次，并带有 source set to the unicast source address of that server. When the collection window expires, the callback is invoked one final time with source set to NULL to signal that no further responses will be delivered for this request.

参数
dataCoAP 响应数据。
user_data用户提供的上下文。

取消匹配的请求。

此函数取消所有与给定请求匹配的 CoAP 客户端请求。若提供了 method、path、callback 和 user_data，则基于它们进行匹配。任何设为 NULL 的字段都被视为通配符。

◆ coap_client_deregister_observe()

int coap_client_deregister_observe ( struct coap_client * client,
struct coap_client_request * req )

#include <zephyr/net/coap_client.h>

注销匹配的 CoAP 观察订阅。

按 RFC 7641, section-3.6，使用与原始观察请求相同的令牌，发送 Observe 选项设为 1（注销）的 GET。CON/NON 类型与原始请求一致。

对于可确认请求，该操作是异步的：重传由库处理，注销被确认后会以服务器的最终响应调用响应回调。

对于不可确认请求，注销只发送一次并立即释放请求；响应回调会以 -ECANCELED 被调用。

匹配规则与 coap_client_cancel_request 相同。

参数
client指向 CoAP 客户端实例的指针。
req指向要为其匹配注销的 CoAP 客户端请求的指针。
返回
成功时返回 0，否则返回负的错误码。

发送 CoAP 请求

该操作通过后台线程异步处理。若套接字未连接到目的地址，用户必须提供目的地址，否则该地址应设为 NULL。一旦以 last block 为 true 调用了回调，套接字即可关闭或用于另一次查询。

注解
若使用块传输，req 参数中提供的 payload 指针必须在整个事务期间保持有效（即直到最后一块或报告错误）。库在发送连续的有效载荷块时需要访问该有效载荷指针。
应用程序不得为同一目标资源注册多于一个观察（RFC 7641, section-3.1）。请使用 coap_client_reregister_observe() 刷新正在进行的观察。
参数
client客户端实例。
sock已打开的套接字文件描述符。
addr请求的目的地址；若套接字已连接则为 NULL。
reqCoAP 请求结构
params指向传输参数结构体的指针，NULL 表示使用默认值。
返回值
0请求已启动。
-EINVAL参数或请求无效。
-EAGAIN没有空闲的请求槽位。
-EALREADY另一个套接字上有正在进行的请求。
-ENOTSUP不支持的地址族。
<0构建或发送请求失败时的其他负错误码。

◆ coap_client_reregister_observe()

int coap_client_reregister_observe ( struct coap_client * client,
struct coap_client_request * req )

#include <zephyr/net/coap_client.h>

刷新（重新注册）正在进行的 CoAP 观察。

以 Observe 选项设为 0（注册）、相同的令牌和与原始请求相同的选项，重新发送该观察的 GET（RFC 7641 重新注册）。这会刷新服务器的观察条目——例如在 Max-Age 或服务器侧空闲超时到期之前——而不会创建第二个观察。服务器以当前资源状态作答，并通过现有的观察回调交付。除非该应答不是带 Observe 选项的 2.xx 响应（那会结束观察，RFC 7641 第 3.2 和 4.1 节），否则观察会继续。

构建或发送刷新失败时观察保持完好（后续的刷新仍可能成功），错误会被返回且不会调用回调。服务器未确认的可确认刷新会像其他可确认请求一样被重传，一旦重试耗尽，就以 -ETIMEDOUT 报告给回调并结束观察。

参数
client指向客户端实例的指针。
req指向标识该观察的指针，按与注册时 coap_client_req() 相同的字段（method、path、cb、user_data）匹配。
返回值
0Success.
-ENOENT没有正在进行的观察匹配 req，例如因为它已因超时、服务器的 Reset 或结束它的服务器响应而终止。
-EBUSY该观察上仍有请求在等待其响应，例如注册本身、先前的可确认刷新或正在获取的块传输通知，或者该函数是从该观察的响应回调中调用的。请稍后重试。
<0构建或发送请求失败时的其他负错误码。
