详细描述

与异步操作的通知相关联的状态。

此类型的对象由客户端分配，客户端必须使用初始化函数（例如 sys_notify_init_signal()）来配置它们。通常该结构体是服务特定客户端结构体的成员，例如 onoff_client。

当指向该对象的指针被传给文档声明会接管该对象的服务函数（例如 onoff_service_request()）时，包含该对象的控制权转移给服务提供者。在服务提供者控制该对象期间，客户端不得更改任何对象字段。控制权交还客户端的情形：

  • 若对服务 API 的调用返回错误；
  • 当操作完成被发布时。这可能发生在对服务 API 的调用返回之前。

从技术上讲，操作完成是在 flags 字段被更新以使 sys_notify_fetch_result() 返回成功时发布的。这会发生在信号被发布或回调被调用之前。注意，尽管管理器在此之后不再引用 sys_notify 对象，包含该对象的对象可能持有会在回调中被引用的状态。在使用回调的情况下，直到回调被调用控制权才交还客户端。（明确允许在回调中复用。）

在控制权交还客户端后，必须为下一次操作重新初始化该通知对象。

此结构体的内容对客户端而言不是公共 API：所有配置和检查都应使用 sys_notify_init_callback() 和 sys_notify_fetch_result() 之类的函数完成。不过，使用此结构体的服务可以直接访问某些字段。
