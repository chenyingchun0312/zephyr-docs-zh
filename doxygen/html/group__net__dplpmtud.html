详细描述

自从
4.5
版本
0.1.0

适用于 UDP 传输的通用数据报分片层路径 MTU 发现（:rfc:8899）。协议栈负责每个目的地的搜索状态（已验证的 PLPMTU、探测大小、重试计数器）。每个传输负责构造探测报文、以不分片方式发送，并通过其丢失恢复路径进行确认。

典型集成方式：

  1. 连接建立时调用 net_dplpmtud_init_path()。
  2. 使用 net_dplpmtud_get_path_mtu() 确定对外发送数据报的大小。
  3. 当 net_dplpmtud_get_path_probe_size() 返回大于零的值且 net_dplpmtud_path_probe_in_flight() 为 false 时，以该大小发送一个启用了 IP_DONTFRAG / IPV6_DONTFRAG 的探测数据报。
  4. 在发送探测报文之前调用 net_dplpmtud_on_path_probe_sent()，然后调用 net_dplpmtud_on_path_probe_acked() 或 net_dplpmtud_on_path_probe_lost()。

通过 PMTU 目的地缓存进行的 ICMP Packet Too Big（PTB）更新会被自动应用。已验证的探测结果会写回该缓存，供其他协议栈使用者使用。

QUIC 在内部使用此 API；参见 :ref:quic_dplpmtud。

◆ net_dplpmtud_reopen_path_search()

void net_dplpmtud_reopen_path_search ( struct net_dplpmtud_path * path)

#include <zephyr/net/dplpmtud.h>

重新启动某个路径的 PLPMTU 搜索。

将搜索重置为从基础 PLPMTU 重新开始，直到该条目的当前上限，并清除任何失效的在途探测状态，从而使新（重新）启动的探测程序从头重新验证该路径。

每个目的地的 DPLPMTUD 状态是共享的，且其生命周期长于单个传输/套接字。之前的运行可能使其处于不再产生任何探测的终态：要么搜索已完成（已验证的 PLPMTU 已达上限），要么在反复探测丢失且无响应者后崩溃。在这两种情况下，单纯重新启用都不会发送探测，因此重新连接到某个目的地的传输在重新启用探测时应调用此函数。

参数
path已初始化的路径句柄
