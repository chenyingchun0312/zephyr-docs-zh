typedef uint32_t k_ticks_t

#include <zephyr/sys/clock.h>

超时 API 中使用的 tick 精度

此类型定义 k_timeout_t 对象中超时值所用的字长，因而也就定义了最大超时长度（或等价地，最小 tick 时长）的上界。注意这不影响系统 uptime 计数器的宽度，它始终是以 tick 计的 64 位计数。

◆ sys_clock_getrtoffset()

void sys_clock_getrtoffset ( struct timespec * tp)

#include <zephyr/sys/clock.h>

获取 SYS_CLOCK_REALTIME 相对于 SYS_CLOCK_MONOTONIC 的偏移量

“墙上时钟”（即 SYS_CLOCK_REALTIME）取决于系统设置的基准时间。基准时间可能因多种原因被更新，例如硬件实时时钟（RTC）初始化、网络时间协议（NTP）同步，或应用程序手动调整。

此函数以 timespec 对象的形式获取当前的时移，用于 SYS_CLOCK_REALTIME, with respect to SYS_CLOCK_MONOTONIC, and writes it to the provided memory location pointed-to by tp.

注解
若 tp 为 NULL，此函数可能触发断言。
参数
tp指向写入时间的存储位置的指针。

◆ sys_clock_nanosleep()

int sys_clock_nanosleep ( int clock_id,
int flags,
const struct timespec * rqtp,
struct timespec * rmtp )

#include <zephyr/sys/clock.h>

相对于指定时钟休眠指定的时长。

此函数会使调用线程休眠，直到

  • 由 rqtp 指定的绝对时间（若 flags 包含 SYS_TIMER_ABSTIME），或
  • 由 rqtp 指定的相对时间（若 flags 不包含 SYS_TIMER_ABSTIME).

clock_id 的可接受取值包括

  • SYS_CLOCK_REALTIME
  • SYS_CLOCK_MONOTONIC

若 rmtp 不为 NULL，且线程在 rqtp 指定的时间之前被唤醒，则剩余时间会写入 rmtp。若线程已休眠至少 rqtp 指定的时间，则 rmtp 会被设为零。

参数
clock_id用于休眠所依据的时钟。
flags用于修改休眠操作行为的标志。
rqtp指向所请求休眠时间的指针。
rmtp指向用于复制剩余时间（若有）的存储位置的指针。
返回值
0成功时。
-EINVAL当 clock_id 无效，当 rqtp 包含超出 [0, 999999999] 范围的纳秒值，或当 rqtp 包含负值时。

◆ sys_timepoint_calc()

k_timepoint_t sys_timepoint_calc ( k_timeout_t timeout)

#include <zephyr/sys/clock.h>

计算时间点值

返回与某个超时对象到期相对应的时间点（相对于未加锁的 “now” ！）。正确使用时，应在用户传入新超时值的同时同步调用一次。不应反复用它来调整超时（为此请使用 sys_timepoint_timeout()）。

参数
timeout相对于当前时间的超时值（也可以是 K_FOREVER 或 K_NO_WAIT）。
返回
与给定超时相对应的时间点值

到给定时间点的剩余时间

返回当前时间与所提供时间点之间的超时区间。若该时间点现已过去，或它是用 K_NO_WAIT 创建的，则返回 K_NO_WAIT。若它是用 K_FOREVER 创建的，则返回 K_FOREVER。

参数

返回
相应的超时值。
