枚举值
IEEE802154_OPENTHREAD_ATTR_T_RECCA 

属性：连续执行的相邻 CCA 之间的最大时间。

这是为以下内容提到的 T_recca 参数对应的属性 IEEE802154_OPENTHREAD_TX_MODE_TXTIME_MULTIPLE_CCA. Time is expressed in microseconds.

IEEE802154_OPENTHREAD_ATTR_T_CCATX 

属性：检测到 CCA 信道空闲到 SHR 在本端天线开始的时刻之间的最大时间。

这是为以下内容提到的 T_ccatx 参数对应的属性 IEEE802154_OPENTHREAD_TX_MODE_TXTIME_MULTIPLE_CCA. Time is expressed in microseconds.

◆ ieee802154_openthread_config_type

enum ieee802154_openthread_config_type

ieee802154 驱动 OpenThread 特定的配置类型。此类型扩展 ieee802154_config_type。

枚举值
IEEE802154_OPENTHREAD_CONFIG_MAX_EXTRA_CCA_ATTEMPTS 

允许为以以下模式请求的发送配置额外 CCA： IEEE802154_OPENTHREAD_TX_MODE_TXTIME_MULTIPLE_CCA.

Requires IEEE802154_OPENTHREAD_HW_MULTIPLE_CCA capability.

IEEE802154_OPENTHREAD_CONFIG_CST_PERIOD 

配置设备的 CST 周期。

当驱动即将发送包含 CST Period IE 的帧时，驱动应根据此配置参数的值，将 CST Period 值注入 CST Period IE。

需要 IEEE802154_OPENTHREAD_HW_CST 能力。

IEEE802154_OPENTHREAD_CONFIG_EXPECTED_TX_TIME 

配置预期发送 TX 帧的时间点。

当驱动即将发送包含 CST Phase IE 的帧时，驱动应根据此配置参数的值、发送时间以及 CST 周期值，将 CST Phase IE 值注入 CST Phase IE。

此参数配置以纳秒为分辨率的时刻，相对于网络子系统的本地时钟，即假定 TX 帧的 SFD 结束（等价地其 SHR 结束、PHR 起始）预期在本端天线上发送的时刻。

需要 IEEE802154_OPENTHREAD_HW_CST 能力。

◆ ieee802154_openthread_hw_caps

enum ieee802154_openthread_hw_caps

ieee802154 驱动的 OpenThread 特定能力。此类型扩展 ieee802154_hw_caps。

枚举值
IEEE802154_OPENTHREAD_HW_MULTIPLE_CCA 

以 IEEE802154_OPENTHREAD_TX_MODE_TXTIME_MULTIPLE_CCA 模式发送的能力。

IEEE802154_OPENTHREAD_HW_CST 

支持 CST 相关特性的能力。

CST 相关特性由 "Specification changes for Thread-in-Mobile" 草案第 1 版（2024 年 7 月 11 日）描述。CST 允许发送带有 CST Phase 和 CST Period IE 的帧，如 Thread-in-Mobile 规范变更第 4.6.6.1 章所述。上层实现（OpenThread）负责准备待发送的帧，并在其中为 CST Phase 和 CST Period 预留占位符。驱动实现负责根据配置参数为 CST Phase IE 和 CST Period IE 注入正确的值 IEEE802154_OPENTHREAD_CONFIG_CST_PERIOD and IEEE802154_OPENTHREAD_CONFIG_EXPECTED_TX_TIME.

注解
CST 发送在设计上与 CSL 接收非常相似。在 CSL 接收中，接收方向对端告知其能够接收的时刻。在 CST 发送中，发送方向对端告知下一次发送将要发生的时刻。

◆ ieee802154_openthread_tx_mode

enum ieee802154_openthread_tx_mode

TX 模式

枚举值
IEEE802154_OPENTHREAD_TX_MODE_TXTIME_MULTIPLE_CCA 

IEEE802154_OPENTHREAD_TX_MODE_TXTIME_MULTIPLE_CCA 模式允许在连续执行最多 1 + max_extra_cca_attempts 次 CCA 后信道报告空闲时发送已调度的报文。

此模式是非标准的实验性 OpenThread 特性。它允许在特定时间窗内发送报文。最早发送时间的指定方式与其他 TXTIME 模式相同：当第一次 CCA 报告信道空闲时，报文 PHR 的第一个符号应在调度的 TX 时间戳所表示的时刻（下文称为 T_tx）出现在本端天线上。

若第一次 CCA 报告信道忙，则将额外执行最多 max_extra_cca_attempts 次 CCA，直到其中一次报告信道空闲并发出报文，或达到最大尝试次数（此时发送失败）。

这些额外 CCA 的时序取决于驱动的能力，驱动在 T_recca 和 T_ccatx 驱动属性中报告它们（参见 IEEE802154_OPENTHREAD_ATTR_T_RECCA 和 IEEE802154_OPENTHREAD_ATTR_T_CCATX). Based on these attributes the upper layer can calculate the latest point in time (T_txmax) that the first symbol of the scheduled packet's PHR SHALL be present at the local antenna:

T_maxtxdelay = max_extra_cca_attempts * (aCcaTime + T_recca) - T_recca + T_ccatx T_txmax = T_tx + T_maxtxdelay

aCcaTime 的定义参见 IEEE 802.15.4-2020 第 11.3 节、表 11-1。

实现此 TX 模式的驱动宜使 T_recca 和 T_ccatx 尽可能短。T_ccatx 应小于或等于 aTurnaroundTime，如 ibid. 第 11.3 节、表 11-1 所定义。

CCA 应按 phyCcaMode PHY PIB 属性所定义的方式执行（参见 ibid. 第 11.3 节、表 11-2）。

需要 IEEE802154_OPENTHREAD_HW_MULTIPLE_CCA 能力。

注解
IEEE802154_HW_SELECTIVE_TXCHANNEL 能力的适用方式与以下相同 IEEE802154_TX_MODE_TXTIME_CCA.
