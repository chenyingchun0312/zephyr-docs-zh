详细描述

RFCOMM DLC 操作结构。

该对象在 DLC 生命周期内必须保持有效且不变。

注解
这些回调在线程上下文中调用，绝不会在 ISR 中调用。回调是由协议栈内部上下文调用，还是由触发它的 API 调用同步调用，以及来自哪个上下文，不属于 API 的一部分，且可能随版本变化。参见 Callback execution contexts for the hazards of blocking in a callback and their mitigations.

◆ recv

int(*) bt_rfcomm_dlc_ops::recv(struct bt_rfcomm_dlc *dlc, struct net_buf *buf)

DLC 接收回调

在 DLC 上收到数据时调用。

如果处理 buf 需要无法立即完成的工作（例如将数据传给另一个线程或工作队列），请返回 -EINPROGRESS 以延迟完成。此时回调不得阻塞。随后协议栈会暂不发放 RX 流控信用（CFC），或在非 CFC 情况下置 FC=1，直到对每个未完成的缓冲区调用 bt_rfcomm_dlc_recv_complete。

当返回 -EINPROGRESS 时，应用程序取得 buf 引用的所有权，并最终必须恰好调用一次 bt_rfcomm_dlc_recv_complete，传回同一个 buf 指针。此次移交前后无需调用 net_buf_ref 或 net_buf_unref。

警告
必须在本回调返回之后，从线程上下文调用 bt_rfcomm_dlc_recv_complete。在 recv 回调内部（返回之前）调用它会使进行中计数器下溢，并导致 bt_rfcomm_dlc_recv_complete 以 -EINVAL 失败。
参数
dlc正在接收数据的 DLC。
buf包含传入数据的缓冲区。
返回值
0数据已同步完全消耗；协议栈保留 buf 的所有权。
-EINPROGRESS数据处理被延迟；应用程序现在拥有 buf，必须在处理完成后调用一次 bt_rfcomm_dlc_recv_complete。
返回
其他负错误码；协议栈将主动断开该 DLC。
