◆ bt_gatt_discover_func_t

typedef uint8_t(*) bt_gatt_discover_func_t(struct bt_conn *conn, const struct bt_gatt_attr *attr, struct bt_gatt_discover_params *params)

#include <zephyr/bluetooth/gatt.h>

发现属性回调函数。

参数
conn连接对象。
attr找到属性，若未找到则为 NULL。
params给出的发现参数。

若发现过程已完成，则会以 attr 设置为 NULL 调用此回调。若通过返回 BT_GATT_ITER_STOP 停止过程，则不会发生这种情况。

属性对象及其 UUID 和值对象都是临时的，必须复制才能缓存其信息。

注解
bt_gatt_attr 作为参数传给 bt_gatt_discover 函数，但它并不是此类型的正规对象。bt_gatt_attr::perm 以及 bt_gatt_attr.read() 和 bt_gatt_attr.write() 方法都不可用，将指针传给 GATT 服务器 API 也不可靠。该属性中只有以下字段包含有效信息：
  • uuid 表示属性类型的 UUID。
  • handle 远程数据库中的句柄。
  • user_data 属性的值，前提是发现类型对应的 ATT 操作提供该信息。否则为 NULL。见下文。

attr->user_data 的实际类型由 params 决定。注意发现过程不会改变 params->type 和 params->uuid 字段。

params->type params->uuid Type of attr->user_data
BT_GATT_DISCOVER_PRIMARY any bt_gatt_service_val
BT_GATT_DISCOVER_SECONDARY any bt_gatt_service_val
BT_GATT_DISCOVER_INCLUDE any bt_gatt_include
BT_GATT_DISCOVER_CHARACTERISTIC any bt_gatt_chrc
BT_GATT_DISCOVER_STD_CHAR_DESC BT_UUID_GATT_CEP bt_gatt_cep
BT_GATT_DISCOVER_STD_CHAR_DESC BT_UUID_GATT_CCC bt_gatt_ccc
BT_GATT_DISCOVER_STD_CHAR_DESC BT_UUID_GATT_SCC bt_gatt_scc
BT_GATT_DISCOVER_STD_CHAR_DESC BT_UUID_GATT_CPF bt_gatt_cpf
BT_GATT_DISCOVER_DESCRIPTOR any NULL
BT_GATT_DISCOVER_ATTRIBUTE any NULL

还请考虑使用按类型读取而不是发现是否更方便。参见 bt_gatt_read，其 bt_gatt_read_params::handle_count 设置为 0.

返回
BT_GATT_ITER_CONTINUE 表示继续发现过程。
BT_GATT_ITER_STOP 表示停止发现过程。

◆ bt_gatt_sub_flag

enum bt_gatt_sub_flag

#include <zephyr/bluetooth/gatt.h>

订阅标志

枚举值
BT_GATT_SUBSCRIBE_FLAG_VOLATILE 

持久化标志

若置位，表示该订阅不会保存在 GATT 服务器一侧。因此断开连接时该订阅会自动从客户端的订阅列表中移除，客户端重新连接后必须重新发起订阅。

BT_GATT_SUBSCRIBE_FLAG_NO_RESUB 

不重新订阅标志

默认情况下，当未设置 BT_GATT_SUBSCRIBE_FLAG_VOLATILE 时，客户端重新连接后订阅会自动续订，这是针对不持久保存订阅的 GATT 服务器的权宜做法。

此标志将禁用自动重新订阅。若应用层已知 GATT 服务器会记住先前连接的订阅并希望避免续订订阅，则该标志很有用。

BT_GATT_SUBSCRIBE_FLAG_WRITE_PENDING 

写挂起标志

若置位，表示写操作正在挂起，等待远程端响应。

注解
仅供内部使用。
BT_GATT_SUBSCRIBE_FLAG_SENT 

已发送标志

若置位，表示已在当前连接中发送过订阅请求（CCC 写入）。

用于避免在以下情况下多次发送订阅请求 CONFIG_BT_GATT_AUTO_RESUBSCRIBE quirk is enabled.

注解
仅供内部使用。
BT_GATT_SUBSCRIBE_NUM_FLAGS

◆ bt_gatt_discover()

int bt_gatt_discover ( struct bt_conn * conn,
struct bt_gatt_discover_params * params )

#include <zephyr/bluetooth/gatt.h>

GATT 发现函数

客户端使用此过程发现服务器上的属性。

主服务发现：该过程可发现主服务，方式为“发现所有主服务”或“按服务 UUID 发现主服务”。被包含服务发现：该过程可发现指定范围内的所有被包含服务。特征发现：该过程可发现指定句柄范围内的所有特征，以及发现具有指定 UUID 的特征。描述符发现：该过程可发现指定范围内的所有特征描述符。

对每个找到的属性都会调用回调，回调随后可决定是继续发现还是停止。

响应在回调 params->func 中返回。该回调在线程上下文中运行，绝不会在 ISR 中运行；参见 Callback execution contexts . params must remain valid until start of callback where iter attr is NULL or callback will return BT_GATT_ITER_STOP.

参数
conn连接对象。
params发现参数。
返回值
0请求已成功排队。解决时将调用 params->func。
-ENOMEMATT 请求队列已满，阻塞会导致死锁。请先让待处理的请求完成再重试，或从单独的线程调用此函数以获得阻塞行为。队列大小由 CONFIG_BT_ATT_TX_COUNT 控制。

int bt_gatt_exchange_mtu ( struct bt_conn * conn,
struct bt_gatt_exchange_params * params )

#include <zephyr/bluetooth/gatt.h>

交换 MTU

该客户端过程可为每个连接执行一次，用于将 MTU 设置为缓冲区所能容纳的最大可能大小。

由于响应在回调 params->func 中返回，例如 bt_gatt_get_mtu can be invoked in the mtu_exchange-callback to read out the new negotiated ATT connection MTU. The callback runs in a thread context, never in an ISR; see Callback execution contexts . params must remain valid until start of callback.

参数
conn连接对象。
params交换 MTU 参数。
返回值
0请求已成功排队。解决时将调用 params->func。
-ENOMEMATT 请求队列已满，阻塞会导致死锁。请先让待处理的请求完成再重试，或从单独的线程调用此函数以获得阻塞行为。队列大小由 CONFIG_BT_ATT_TX_COUNT 控制。
-EALREADYMTU 交换过程已执行过。

◆ bt_gatt_read()

int bt_gatt_read ( struct bt_conn * conn,
struct bt_gatt_read_params * params )

#include <zephyr/bluetooth/gatt.h>

按句柄读取属性值

此过程读取属性值并将其返回给回调。

按 UUID 读取属性时，回调可能被调用多次，具体取决于给定 UUID 存在多少个实例，每个实例对应的 start_handle 都会更新。

要执行 GATT 长读过程，请先进行特征值读取（将 offset 设为 0、handle_count 设为 1），然后返回 BT_GATT_ITER_CONTINUE from the callback. This is equivalent to calling bt_gatt_read again, but with the correct offset to continue the read. This may be repeated until the procedure is complete, which is signaled by the callback being called with data set to NULL.

注意，返回 BT_GATT_ITER_CONTINUE 实际上是启动新的 ATT 操作，因此可能无法分配资源。但所有 API 错误都会按服务器返回 BT_ATT_ERR_UNLIKELY 的方式报告，无法区分这种情况与服务器本身返回 BT_ATT_ERR_UNLIKELY 响应。

注意，从回调返回 BT_GATT_ITER_CONTINUE 的效果取决于读取操作的类型。

响应在回调 params->func 中返回。该回调在线程上下文中运行，绝不会在 ISR 中运行；参见 Callback execution contexts . params must remain valid until start of callback. If the received data length is invalid, the callback params->func will called with the error BT_ATT_ERR_INVALID_PDU.

参数
conn连接对象。
params读取参数。
返回值
0请求已成功排队。解决时将调用 params->func。
-ENOMEMATT 请求队列已满，阻塞会导致死锁。请先让待处理的请求完成再重试，或从单独的线程调用此函数以获得阻塞行为。队列大小由 CONFIG_BT_ATT_TX_COUNT 控制。

◆ bt_gatt_subscribe()

int bt_gatt_subscribe ( struct bt_conn * conn,
struct bt_gatt_subscribe_params * params )

#include <zephyr/bluetooth/gatt.h>

订阅属性值通知

此过程使用客户端特征配置句柄订阅值通知。收到通知时会调用订阅值回调以返回通知值，随后可以决定是否直接从该回调中取消订阅。若通过此方法移除订阅，则不会调用数据为 NULL 的通知回调。

响应在回调 params->subscribe 中返回，通知则在 params->notify. Both callbacks run in a thread context, never in an ISR; see Callback execution contexts .

注解
通知是异步的，因此 params 在订阅期间必须保持有效，且在活动期间不能复用于其他订阅。
参数
conn连接对象。
params订阅参数。
返回值
0请求已成功排队。解决时将调用 params->write。
-ENOMEMATT 请求队列已满，阻塞会导致死锁。请先让待处理的请求完成再重试，或从单独的线程调用此函数以获得阻塞行为。队列大小由 CONFIG_BT_ATT_TX_COUNT 控制。
-EALREADY若已存在使用 params 的订阅。
-EBUSY若 params.ccc_handle 为 0、已启用 CONFIG_BT_GATT_AUTO_DISCOVER_CCC 且 params 的发现已在进行中。

#include <zephyr/bluetooth/gatt.h>

带回调的按句柄无响应写入属性值。

此函数的工作方式与 bt_gatt_write_without_response 相同，另外在发送写入后会调用回调函数。

该回调在线程上下文中运行，绝不会在 ISR 中运行；参见 Callback execution contexts . When called from the System Workqueue context this API will not wait for resources for the callback but instead return an error.

参数
conn连接对象。
handle属性句柄。
data要写入的数据。
length数据长度。
sign是否对数据签名。
func发送完成回调。
user_data要传回回调的用户数据。
返回值
0请求已成功排队。
-ENOMEMATT 请求队列已满，阻塞会导致死锁。请先让待处理的请求完成再重试，或从单独的线程调用此函数以获得阻塞行为。队列大小由 CONFIG_BT_ATT_TX_COUNT 控制。
