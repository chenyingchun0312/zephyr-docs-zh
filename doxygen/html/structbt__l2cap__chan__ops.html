详细描述

L2CAP 信道操作结构。

该对象在信道的生命周期内必须保持有效且不变。

注解
这些回调在线程上下文中调用，绝不会在 ISR 中调用。回调是由协议栈内部上下文调用，还是由触发它的 API 调用同步调用，以及来自哪个上下文，不属于 API 的一部分，且可能随版本变化。参见 Callback execution contexts for the hazards of blocking in a callback and their mitigations.

struct net_buf *(*) bt_l2cap_chan_ops::alloc_buf(struct bt_l2cap_chan *chan)

信道 alloc_buf 回调

若提供此回调，信道将使用它分配缓冲区以存放传入数据。需要分片的信道必须设置此回调。若应用程序未设置回调，则 L2CAP SDU MTU 将被截断为 BT_L2CAP_SDU_RX_MTU。

注解
协议栈将接收到的分段数量存放在缓冲区用户数据的前两个字节中。此回调返回的缓冲区其用户数据大小必须至少为 sizeof(uint16_t).
参数
chan请求缓冲区的信道。
返回
分配的缓冲区。

struct net_buf *(*) bt_l2cap_chan_ops::alloc_seg(struct bt_l2cap_chan *chan)

信道 alloc_seg 回调

若提供此回调，信道将使用它分配缓冲区以存放分段。这避免了用可能小得多的 PDU 浪费大的 SDU 缓冲区。若提供了此回调，它必须返回有效的缓冲区。

参数
chan请求缓冲区的信道。
返回
分配的缓冲区。

◆ encrypt_change

void(*) bt_l2cap_chan_ops::encrypt_change(struct bt_l2cap_chan *chan, uint8_t hci_status)

信道加密变更回调

若提供此回调，则安全级别改变（间接完成链路加密）或认证过程失败时都会调用它。在这两种情况下，安全发起方和响应方都会获得由本地主机控制器相关的加密和认证事件传递的最终状态（HCI 状态）。

参数
chan加密状态发生变化的信道。
hci_status因信道安全要求而执行的安全过程的 HCI 状态。该值由 HCI 层填充，成功时为 0，安全/认证失败时非零（参考 HCI 错误码）。

int(*) bt_l2cap_chan_ops::recv(struct bt_l2cap_chan *chan, struct net_buf *buf)

信道接收回调

参数
chan正在接收数据的信道。
buf包含传入数据的缓冲区。
注解
此回调是必需的，除非 CONFIG_BT_L2CAP_SEG_RECV is enabled and seg_recv is supplied.

若应用程序返回 -EINPROGRESS，则应用程序取得 buf 中引用的所有权。（即该指针值可以直接传给 bt_l2cap_chan_recv_complete，而无需调用 net_buf_ref 或 net_buf_unref。）

返回
成功时为 0，出错时为负值。
-EINPROGRESS 表示用户必须在数据处理完成后通过调用以下函数进行确认 bt_l2cap_chan_recv_complete passing back the buffer received with its original user_data which contains the number of segments/credits used by the packet.

◆ seg_recv

void(*) bt_l2cap_chan_ops::seg_recv(struct bt_l2cap_chan *chan, size_t sdu_len, off_t seg_offset, struct net_buf_simple *seg)

直接处理 L2CAP 分段

这是 bt_l2cap_chan_ops::recv 的替代方案。两者不能同时使用。

对每个收到的分段立即调用此项。

与 bt_l2cap_chan_ops::recv 不同，流控是显式的。每次调用此处理函数时，对端都已永久消耗一个信用额度。请使用 bt_l2cap_chan_give_credits 提供信用额度。

SDU 的开始由 seg_offset == 0 标记。SDU 的结束由 seg_offset + seg->len == sdu_len 标记。

协议栈保证：

  • 发送方拥有信用额度。
  • SDU 长度不超过 MTU。
  • 分段长度不超过 MPS。

此外，L2CAP 协议还保证：

  • 分段按顺序到达。
  • SDU 不能交错，也不能中途放弃。
注解
使用此替代 API 时，由应用程序负责设置 RX MTU 和 MPS。MPS 不得超过 BT_L2CAP_RX_MTU。
参数
chan接收信道。
sdu_len该分段所属 SDU 的字节长度。
seg_offset该分段在 SDU 中的字节偏移。
seg分段载荷。
