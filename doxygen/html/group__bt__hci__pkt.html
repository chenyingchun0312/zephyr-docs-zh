详细描述

Bluetooth HCI 数据包辅助函数

自从
4.5
版本
0.1.0

用于封装 HCI 命令数据包以及解析携带命令响应的 HCI 事件的无状态辅助函数，它们作用于 net_buf_simple 缓冲区和数据包字节。它们既不依赖 Bluetooth Host 也不依赖 HCI 驱动接口，可用于任何构建类型：Host、HCI 驱动（例如通过驱动自身的传输执行厂商特定的控制器初始化，参见 hci_lockstep.h）以及仅含控制器的应用。

注解
这些并不是通用的应用 API，尽管该头文件位于应用可见的 include 目录中：预期使用者是 HCI 驱动和 Bluetooth 协议栈内部。需要在 Host 运行时发送 HCI 命令的应用应使用 hci.h 中更高层的 bt_hci_cmd_alloc()、bt_hci_cmd_send() 和 bt_hci_cmd_send_sync() API，它们与 Host 的命令流控相配合。

数据包采用 Zephyr 中通行的形式处理：HCI 数据包指示符（BT_HCI_H4_CMD、BT_HCI_H4_EVT 等）为第一个字节，随后是数据包头和参数。参数由调用方使用 packed 的 bt_hci_cp_* 和 bt_hci_rp_* 结构以及 net_buf_simple API 进行编码和解码，与 Bluetooth Host 中完全一致。

为 HCI 命令数据包定义缓冲区。

定义并初始化一个 net_buf_simple，其存储可容纳携带最多 _max_param_len 个参数字节的 HCI 命令数据包。缓冲区初始为空，并为 bt_hci_pkt_push_cmd_hdr() 预留了头部空间：参数通过 net_buf_simple API 添加，之后再将命令头压入到参数之前。

要将缓冲区复用于另一条命令，或在其他存储上准备缓冲区，请使用 bt_hci_pkt_reset_cmd()。

参数
_namenet_buf_simple 对象的名称。
_max_param_len缓冲区可容纳的最大参数字节数。

int bt_hci_pkt_parse_cmd_rsp ( const uint8_t * pkt,
size_t len,

#include <zephyr/bluetooth/hci_pkt.h>

从完整的 HCI 数据包中解析 HCI 命令响应。

检查一个完整的 HCI 数据包（从其数据包指示符开始），当它是 HCI_Command_Complete 或 HCI_Command_Status 事件时进行解码，并将命令的返回参数留在 bt_hci_pkt_cmd_rsp::rp 中。超出事件头中给出长度的字节会被忽略，且数据包不会被修改，因此任何收到的数据包都可就地检查。

参数
pkt完整的 HCI 数据包。
lenpkt 的长度，单位为字节。
rsp解码后的响应。
返回值
0该数据包是命令响应。
-ENODATA该数据包是某条命令的 HCI_Command_Complete，但该命令不携带任何返回参数，甚至连状态也没有；rsp 的 status 被填充为 BT_HCI_ERR_UNSPECIFIED。
-ENOMSG该数据包不是命令响应；rsp 保持不变。
-EINVAL该数据包是格式错误的 HCI 事件；rsp 保持不变。

压入 HCI 命令数据包的数据包指示符和命令头。

将 BT_HCI_H4_CMD 以及包含 opcode 的 HCI 命令头添加到 buf 内容之前，buf 必须存放命令参数（若有）。命令头中的参数长度由 buf 的长度得出，随后缓冲区即包含完整的命令数据包。

参数
buf存放命令参数的缓冲区，至少包含 BT_HCI_PKT_CMD_HDR_SIZE bytes of headroom, as set up by BT_HCI_PKT_CMD_DEFINE() or bt_hci_pkt_reset_cmd().
opcodeHCI 命令操作码。
返回值
0成功；buf 中存放完整的命令数据包。
-EINVALbuf 的头部空间不足以容纳该前缀。

清空 buf 并为 bt_hci_pkt_push_cmd_hdr() 预留头部空间，从而可以用 net_buf_simple API 添加命令参数。用它来复用 BT_HCI_PKT_CMD_DEFINE() 定义的缓冲区，或准备一个在调用方提供的存储上初始化的 net_buf_simple（例如使用 net_buf_simple_init_with_data()）。该存储至少必须容纳 BT_HCI_PKT_CMD_HDR_SIZE bytes.
