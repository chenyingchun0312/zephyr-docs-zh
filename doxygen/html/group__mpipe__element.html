详细描述

构建管道的基本单元。

元素是一个处理步骤：它产生缓冲区、消费缓冲区，或将一些缓冲区转换为另一些。它暴露 Pad 连接器，链接两个元素就是把一个元素的 source pad 链接到另一个元素的 sink pad。元素做什么是它自己的事；框架对它的要求是回答查询、处理事件并遵循状态机。

States

元素处于三种状态之一，并一次一步地在相邻状态之间移动： 

READY <-> PAUSED <-> PLAYING

READY 表示已构造并已链接，但尚未持有协商出的格式和缓冲区。工作发生在 READY 到 PAUSED 的转换中：source 在整个图上驱动能力协商，随后缓冲区池查询确定由谁提供缓冲区以及提供多少个，然后各池启动。PAUSED 到 PLAYING 让数据流动。反向过程则相反，PAUSED 到 READY 会丢弃已协商的能力，以便下次运行时重新协商。

转换完成时返回 0，元素拒绝时返回负的 errno；-EINPROGRESS 保留给异步完成的转换。拒绝某次转换的元素保持原位；已经移动的元素不会被回滚，这是有意为之——这样图能准确显示哪个元素在哪个转换中拒绝。

Specializing an element

mpipe_src、 mpipe_sink、转换元素 中的基类， 解析器 and Bin implement the protocol; a concrete element embeds one of them as its first member, calls that base's init with its own id, and overrides only the hooks it cares about. Chaining to the base change_state is mandatory - that is what performs the reset and the pool teardown every element is expected to do.

为管道转储命名一个元素。

每个元素的 init 函数都会按其类型为其元素命名，因此转储读起来 vid_transform rather than an address. Call this afterwards to give one instance a distinct name, which is what tells two elements of the same type apart in a dump.

ret = mpipe_queue_init(&queue, QUEUE_ID);
mpipe_element_set_name(&queue.transform.element, "video_queue");
