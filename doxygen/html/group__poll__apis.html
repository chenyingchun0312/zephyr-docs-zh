◆ k_poll()

int k_poll ( struct k_poll_event * events,
int num_events,
k_timeout_t timeout )

#include <zephyr/kernel.h>

等待一个或多个轮询事件发生

此例程允许线程并发等待多个轮询事件中的一个或多个发生。这类事件可以是内核对象（如信号量）变为可用，也可以是轮询信号事件。

当事件通知某个内核对象可用时，该内核对象并不会被“交给”调用 k_poll() 的线程：它只是表明在 k_poll() 调用生效期间该对象曾可用。此外，所有以常规方式（即在该对象上等待）尝试获取对象的线程，其优先级都高于轮询该对象的线程。这意味着轮询线程在对象变为可用且其等待队列为空之前，永远不会获得该对象上的轮询事件。因此，当被轮询的对象只有一个线程（即轮询线程）尝试获取时，k_poll() 调用会更有效。

当 k_poll() 返回 0 时，调用者应遍历传给 k_poll() 的所有事件，检查 state 字段是否为期望的值，并采取相应的操作。

在再次用于另一次 k_poll() 调用之前，用户必须将 state 字段重置为 K_POLL_STATE_NOT_READY。

从用户模式调用时，需要从调用者的资源池中进行临时内存分配。

参数
events要轮询的事件数组。
num_events数组中的事件数量。
timeout等待事件就绪的时间，或特殊值 K_NO_WAIT 和 K_FOREVER 之一。
返回值
0一个或多个事件已就绪。
-EAGAIN等待时间超时。
-EINTR轮询已被中断，例如通过 k_queue_cancel_wait()。所有输出事件仍然被设置且有效，被取消的事件将被设为 K_POLL_STATE_CANCELLED。换句话说，-EINTR 状态意味着至少有一个输出事件为 K_POLL_STATE_CANCELLED。
-ENOMEM线程资源池内存不足（仅用户模式）
-EINVAL参数错误（仅用户模式）

◆ k_poll_signal_raise()

int k_poll_signal_raise ( struct k_poll_signal * sig,
int result )

#include <zephyr/kernel.h>

向轮询信号对象发送信号。

此例程使一个轮询信号就绪，该信号本质上是 K_POLL_TYPE_SIGNAL 类型的轮询事件。如果有线程正在轮询该事件，该线程将被置为可运行。可以指定 result 值。

轮询信号包含一个 'signaled' 字段，当它被 k_poll_signal_raise() 置位后，会一直保持置位，直到用户通过 k_poll_signal_reset() 将其设回 0。因此用户必须将其重置后再传给 k_poll()，否则 k_poll() 会认为它已被发送信号并立即返回。

注解
即使轮询线程的超时已经到期、因而未直接收到轮询通知，结果仍会被存储且 'signaled' 字段仍会被置位。下一次 k_poll() 将检测到这次错过的触发。
参数
sig轮询信号。
result要存入信号 result 字段的值。
返回值
0信号已成功递送。
