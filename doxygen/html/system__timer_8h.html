宏定义说明

◆ SYS_CLOCK_IDLE_FOREVER

#define SYS_CLOCK_IDLE_FOREVER   UINT32_MAX

表示“无需唤醒 CPU”的节拍数

在无预期唤醒时传给 sys_clock_idle_enter()。它大于 SYS_CLOCK_MAX_WAIT（内核所请求的最长等待时间），因此不会被误认为该值。此处不能使用 K_TICKS_FOREVER：在 CONFIG_TIMEOUT_64BIT 下它是 (int64_t)-1，未启用时则是 UINT32_MAX，因此将无符号节拍数与它比较在两种配置下含义不同。

◆ sys_clock_announce_locked()

void sys_clock_announce_locked ( uint32_t ticks,
k_spinlock_key_t key )

向内核通告时间进度

通知内核自上次调用 sys_clock_announce() 以来（首次调用则自系统启动以来）已流逝指定数量的节拍。定时器驱动应尽可能接近节拍边界地发出这些通告（受硬件和延迟限制）。

调用方必须已持有通过 sys_clock_lock() 获取的系统时钟锁。该键会被消费：此函数返回时锁即被释放。

对于需要在内核节拍统计的同时原子地更新驱动内部状态（例如周期计数器基准）的定时器 ISR，这是首选的接口。用法示例参见 sys_clock_lock()。

参数
ticks已流逝时间，单位为节拍
key从 sys_clock_lock() 获取的锁键。

◆ sys_clock_cycle_get_32()

uint32_t sys_clock_cycle_get_32 ( void )

硬件周期计数器

定时器驱动通常既负责节拍通告，也负责系统周期计数器。为实现周期计数器，通常会从架构层（

参见
arch_k_cycle_get_32()）调用此函数，但面向用户的 API 属于架构层而非驱动。其频率必须与 CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC 匹配。
注解
如果计数器时钟足够快，使其整个范围能在几秒内回绕（即 CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC 大于 50Mhz），则建议同时实现 sys_clock_cycle_get_64()。
返回
当前周期时间。它应在整个 32 位空间内单调递增，并在 0xffffffff 处回绕。精度低于 32 位的定时器硬件应合成为一个 32 位计数。

◆ sys_clock_cycle_get_64()

uint64_t sys_clock_cycle_get_64 ( void )

64 位硬件周期计数器

与 sys_clock_cycle_get_32() 类似，但返回 64 位值。并非所有硬件都有 64 位计数器。仅在设置了 CONFIG_TIMER_HAS_64BIT_CYCLE_COUNTER 时才需要实现此函数。

注解
如果计数器时钟足够快，使 sys_clock_cycle_get_32() 的整个范围能在几秒内回绕（即 CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC 大于 50Mhz），则建议实现此 API。
返回
当前周期时间。它应在整个 64 位空间内单调递增，并在 2^64-1 处回绕。精度较低的定时器硬件通常不期望实现此 API。

◆ sys_clock_idle_enter()

void sys_clock_idle_enter ( uint32_t ticks)

通知定时器驱动 CPU 即将进入低功耗空闲。

当 CPU 即将睡眠时，从电源管理空闲路径调用。将工作移交给低功耗唤醒定时器或以其他方式为睡眠重新配置自身的驱动在此处完成。sys_clock_idle_exit() 在退出时撤销该操作。没有低功耗处理的驱动无需实现此钩子。

该钩子是可选的。若未实现，调用 sys_clock_set_timeout() 时会将其已弃用的 idle 参数设为 true，这样以该参数为依据实现低功耗处理的驱动仍可正常工作。该参数一并移除时，使用电源管理功能的平台应已自行实现 sys_clock_idle_enter()。

参数
ticks距下一次预期唤醒的节拍数；若无需唤醒 CPU 且允许运行时间统计发生漂移，则为 SYS_CLOCK_IDLE_FOREVER，此时驱动可停止其时基。只有发起调用的 CPU 进入空闲：时基在多个 CPU 间共享的驱动必须确保只有最后一个进入空闲的 CPU 才停止时钟。
注解
调用时已持有系统时钟锁。

◆ sys_clock_idle_exit()

void sys_clock_idle_exit ( void )

定时器空闲退出通知

它通知定时器驱动系统正在退出空闲状态，并允许驱动执行所需簿记，以恢复定时器运行并计算已流逝的节拍。

注解
旧式定时器驱动还借此机会回调 sys_clock_announce()，向内核通知已到期的节拍。为兼容性这是允许的，但不推荐。内核会自行处理。

◆ sys_clock_lock()

k_spinlock_key_t sys_clock_lock ( void )

锁定系统时钟。

获取保护节拍统计和超时队列的内核定时器锁。定时器驱动应在其 ISR 开头调用此函数，并将返回的键传给 sys_clock_announce_locked()，由后者消费该键。sys_clock_announce_locked() 返回时释放该锁。

内核调用驱动提供的 sys_clock_set_timeout()、sys_clock_elapsed()、sys_clock_no_timeout() 和 sys_clock_idle_enter() 函数时，总是已持有该锁。

定时器 ISR 中的用法示例：

static void timer_isr(const void *arg)
{
k_spinlock_key_t key = sys_clock_lock();
// Update driver-private state (e.g. cycle counter baseline)
uint64_t now = read_hw_counter();
uint32_t dticks = (now - last_cycle) / CYC_PER_TICK;
last_cycle += (uint64_t)dticks * CYC_PER_TICK;
// Reprogram comparator if needed ...
// Announce ticks — key ownership transfers to announce.
sys_clock_announce_locked(dticks, key);
}

◆ sys_clock_no_timeout()

void sys_clock_no_timeout ( void )

通知定时器驱动没有待处理的超时。

当超时队列为空且使能了 CONFIG_SYSTEM_CLOCK_SLOPPY_IDLE 时，内核会用此函数代替 sys_clock_set_timeout() 进行调用。不会马上有节拍通告，系统也不关心精确的运行时间保持，因此驱动可以做些节省资源的事：屏蔽唤醒、编程硬件所能承载的最长间隔，或两者兼施。下次调用 sys_clock_set_timeout() 时恢复正常运行。

CPU 仍在运行，因此 sys_clock_cycle_get_32() 和 sys_clock_cycle_get_64() 必须继续计数：线程仍可能调用 k_cycle_get_32() 或 k_busy_wait()。若驱动的周期计数器由它将要停止的定时器驱动，则只能屏蔽中断。若周期计数器位于不同的时钟或电源域，则可以做得更多。停止时基应放在 sys_clock_idle_enter() 中。

与 sys_clock_disable() 不同，这不是拆除操作。

注解
调用时已持有系统时钟锁。

该钩子是可选的。若未实现，则以它所能表达的最长等待 UINT32_MAX 个节拍来调用 sys_clock_set_timeout()。此值在数值上等于此处原来的 K_TICKS_FOREVER，因此未迁移且仍以该值判断的驱动会像以往一样停止其时钟。

◆ sys_clock_set_timeout()

void sys_clock_set_timeout ( uint32_t ticks,
bool idle )

设置系统时钟超时

通知系统时钟驱动：下一次需要调用 sys_clock_announce() 之前不会超过从当前时刻起的指定节拍数。注意允许对 sys_clock_announce() 的虚假调用（即每个节拍都通告并将此函数实现为空操作是合法的），要求是在指定到期时刻之前的一个节拍内至少发生一次节拍通告（也就是说，传入 ticks==1 表示“通告下一个节拍”，此约定是为了与旧用法保持一致）。同样，ticks 值为零也是合法的：它只是表示内核希望尽快进行下一次节拍通告。

任何节拍数都没有自身含义。驱动按请求配置，并将值钳制到硬件所能承载的范围，然后通告实际经过的节拍。

过去驱动从节拍值推断的两种条件现在有各自的入口：sys_clock_no_timeout() 表示“没有待处理的超时”，sys_clock_idle_enter() 表示“CPU 即将进入睡眠”。

关于 SMP 的最后一点说明：对 sys_clock_set_timeout() 的调用可能在任意 CPU 上发起，并反映全局期望的下一个超时。由此产生的对 sys_clock_announce() 的调用必须由驱动正确串行化，以确保给定节拍在整个系统中只被通告一次。内核不会（实际上也无法）通过把超时“分配”给特定 CPU 来尝试串行化。

注解
内核调用此函数时已持有系统时钟锁。
参数
ticks超时时间，单位为节拍
idle已弃用；内核调用此函数时它始终为 false：空闲进入通过 sys_clock_idle_enter() 通知，其回退路径在此处传入 true。计划在未来的版本中移除；新代码必须忽略它。

◆ sys_clock_unlock()

void sys_clock_unlock ( k_spinlock_key_t key)

解锁系统时钟。

释放先前通过 sys_clock_lock() 获取的内核定时器锁。为有特殊需求的驱动而提供；大多数驱动应使用 sys_clock_announce_locked()，它会自动处理解锁。
