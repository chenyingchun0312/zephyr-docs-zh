类型定义说明

◆ net_time_t

typedef int64_t net_time_t

#include <zephyr/net/net_time.h>

任何出现 net_time_t 的地方都指定一种概念：纳秒分辨率的标量时间跨度，即相对于某个本地网络运行时间参考时钟的未来（正）或过去（负）相对时间或绝对时间戳；该参考时钟在运行期间不回绕，并且在某种明确定义的意义上与所有本地网络接口（有时甚至与同一网络上的远程接口）共用。

该类型是实验性的。目前其用途仅限于网络子系统内的时间表示。

定时的网络协议（PTP、TDMA 等）通常要求多个本地或远程接口在明确定义的容差范围内共享同一套经过时间的概念。因此，网络运行时间不同于由单个硬件计数器外设表示的时间：它需要在多个频率、准确度和精度各不相同的硬件外设中表示。为了协同工作，这些硬件计数器必须相对于共同的本地或远程网络参考时间信号进行“同步（syntonize）”或“驯服（discipline）”（即频率和相位锁定）。请注意，虽然同步的时钟共享相同的频率和相位，但它们通常并不共享相同的纪元（零点）。

这也解释了为什么网络时间如果表示为某个特定硬件计数器的周期值，就永远不会“精确”，而只能相对于给定网络协议所要求的容差（分辨率、漂移、抖动）达到“足够好”。所有参与定时网络协议的计数器外设都必须满足这些容差。

请尽可能使用具体的周期/节拍计数器值而不是 net_time_t，尤其是当涉及内核系统时钟或任何单个计数器外设的值时。

net_time_t 无法表示以任意纪元为基准的通用时钟，因为它只覆盖大约 +/-290 年。它也不能用于表示更复杂时间刻度下的时间（例如包含闰秒、时间调整、复杂日历或时区）。在这些情况下，你可以使用 timespec (C11, POSIX.1-2001), timeval (POSIX.1-2001) or broken down time as in tm (C90). The advantage of net_time_t over these structured time representations is lower memory footprint, faster and simpler scalar arithmetic and easier conversion from/to low-level hardware counter values. Also net_time_t can be used in the network stack as well as in applications while POSIX concepts cannot. Converting net_time_t from/to structured time representations is possible in a limited way but - except for timespec - requires concepts that must be implemented by higher-level APIs. Utility functions converting from/to timespec will be provided as part of the net_time_t API as and when needed.

如果你想在网络应用程序中表示更粗粒度的标量时间，可使用 time_t（C99、POSIX.1-2001），它规定以秒为单位表示，或使用 suseconds_t（POSIX.1-2001）以获得微秒分辨率。内核的 k_ticks_t 和周期（cycles）值（两者都是 Zephyr 特有的）分辨率未作规定，但可用于表示内核定时器值并实现高分辨率自旋。

如果你需要更细粒度的时间分辨率，可以查看（g）PTP 概念，参见 net_ptp_extended_time。

我们不在网络协议栈中直接使用 int64_t 表示纳秒分辨率的标量时间，原因在于过去已经证明，使用通用类型的字段往往不会被正确使用（例如使用了错误的分辨率，或用它们表示定义不充分、同步语义不清的时间概念）。

任何暴露或使用 net_time_t 值的 API 都应确保遵守所规定的契约，包括所有协议特定的容差，因此客户端可以依赖该类型的通用语义。这使得来自不同硬件外设乃至不同网络节点的时间在明确定义的范围内可比，因此 net_time_t 是定时网络协议理想的中间构件。
