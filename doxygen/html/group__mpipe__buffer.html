详细描述

承载数据的是什么，以及由谁提供。

数据以 Zephyr 的 net_buf 缓冲区形式传递。mpipe 添加了一个 mpipe_buffer_meta in the buffer's user data - the pool it came from, how many bytes are valid, a timestamp, and the driver-owned buffer it wraps where there is one. That last field is what makes the path zero-copy: a frame a camera wrote reaches the display without being moved.

缓冲区来自 mpipe_buffer_pool，绝不来自堆。池是建立在某个后备存储之上的小型 vtable，因此插件可以分发驱动已拥有的缓冲区，而不是它们的副本，并且框架通过辅助函数驱动它，而不是直接调用钩子。

Settling who provides the buffers

格式确定后，会通过图执行一次查询以确定缓冲区配置——数量、大小、对齐方式以及使用哪个池。该查询向下游传播到 sink，并在返回途中写入提议，因此元素在做出决定之前总能拿到下游的提议。

提议要么是整个池，要么是按值传递的裸配置。这一区别对所有权很重要：需求只能通过 mpipe_buffer_pool_set_config 到达提议元素仍拥有的池，池的所有者可以自行裁剪或拒绝它。任何人都不得直接写入其他池的配置字段，而启动某个池的人正是停止它的人。

池携带的两个配置 req_config 和 config 使一次运行中协商出的需求不会遗留到下一次；请参见下面的字段。

#include <zephyr/mpipe/mpipe_buffer.h>

将协商得到的配置应用于缓冲区池

这是通过缓冲区池查询协商出的配置到达池的唯一途径：调用方交出该值，由池的所有者校验。元素绝不能写入它并不拥有的池的 mpipe_buffer_pool::config 字段。

若有 mpipe_buffer_pool::set_config 实现，则由池决定：它可以接受、裁剪或拒绝该配置。若没有该实现，则按给定值原样复制配置。

参数
pool指向缓冲区池的指针
cfg要应用的协商配置
返回值
0成功，池的配置反映了所接受的值。
-EBUSY池已启动；请先停止它再重新配置。
返回
池的 set_config 为拒绝而返回的任何负 errno。

◆ mpipe_buffer_pool_set_req_config()

int mpipe_buffer_pool_set_req_config ( struct mpipe_buffer_pool * pool,
const struct mpipe_buffer_pool_config * cfg )

#include <zephyr/mpipe/mpipe_buffer.h>

声明缓冲区池自身的固有要求

池的所有者在设置时调用一次，说明无论以后要求其承载什么，对该池都成立的要求：硬件的最小缓冲区数量、分配器强制的对齐、应用程序固定的尺寸。协商从不写入它，因此它始终作为每次运行的起点下限保留下来——框架在拆除时用它恢复 mpipe_buffer_pool::config，而把需求合并到自己拥有的池中的元素无需自行记住任何内容。

mpipe_buffer_pool::config is set to the same values, so the first run starts from the requirement like every run after it.

参数
pool指向缓冲区池的指针
cfg池的要求
返回值
0成功
-EBUSY池已启动；请先停止它再重新声明其要求
