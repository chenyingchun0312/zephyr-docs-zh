◆ k_work_cancel()

int k_work_cancel ( struct k_work * work)
isr-ok

#include <zephyr/kernel.h>

取消工作项。

此函数尝试通过将待处理（不可延迟的）工作项从工作队列中移除，以阻止其被处理。如果该项正在被处理，则工作项将继续被处理，但在取消完成之前的重新提交会被拒绝。

如果此函数返回零，则取消已完成；否则仍有某物（可能是工作队列线程）在引用该项。

另请参阅 k_work_cancel_sync()。

参数
work指向工作项的指针。
返回
k_work_busy_get() 状态，表示在此调用执行的所有取消步骤完成后该项的状态。

◆ k_work_cancel_delayable()

int k_work_cancel_delayable ( struct k_work_delayable * dwork)
isr-ok

#include <zephyr/kernel.h>

取消可延迟工作。

类似于 k_work_cancel()，但针对可延迟工作。如果该工作已调度或已提交，则将其取消。此函数不等待取消完成。

注解
此函数返回时该工作可能仍在运行。使用 k_work_flush_delayable() 或 k_work_cancel_delayable_sync() 以确保它不在运行。
取消可延迟工作不会阻止重新调度它，但会阻止提交它，直到取消完成。
参数
dwork指向可延迟工作项的指针。
返回
k_work_delayable_busy_get() 状态，表示在此调用执行的所有取消步骤完成后该项的状态。

◆ k_work_cancel_delayable_sync()

bool k_work_cancel_delayable_sync ( struct k_work_delayable * dwork,
struct k_work_sync * sync )

#include <zephyr/kernel.h>

取消可延迟工作并等待。

与 k_work_cancel_delayable() 类似，但会等待该工作变为空闲。

注解
取消可延迟工作不会阻止重新调度它，但会阻止提交它，直到取消完成。
注意调用者与工作队列线程的相对优先级。如果此函数进入睡眠，则它将不会返回，直到工作队列线程完成那些允许此线程恢复的任务。
如果从正在运行 dwork 的工作队列中对此函数传入 dwork 调用，则行为未定义。
参数
dwork指向可延迟工作项的指针。
sync指向一个不透明项的指针，该项包含与待处理取消操作相关的状态。该对象必须在调用返回前保持存在，并且从调用线程和工作队列线程均可访问。在此操作完成之前，该对象不得用于任何其他 flush 或 cancel 操作。在启用了 CONFIG_KERNEL_COHERENCE 的架构上，该对象必须分配在一致性内存中。
返回值
true如果工作未空闲（调用不得不等待正在运行的处理函数取消完成，或已调度、已提交的操作被取消）；
false否则

◆ k_work_cancel_sync()

bool k_work_cancel_sync ( struct k_work * work,
struct k_work_sync * sync )

#include <zephyr/kernel.h>

取消工作项并等待其完成。

与 k_work_cancel() 相同，但不返回，直到取消完成。线程可以在 k_work_cancel() 之后调用此函数，以与先前的取消操作同步。

返回时工作结构将处于空闲状态，除非在取消完成后有某物提交了它。

注解
注意调用者与工作队列线程的相对优先级。如果此函数进入睡眠，则它将不会返回，直到工作队列线程完成那些允许此线程恢复的任务。
如果从正在运行 work 的工作队列中对此函数传入 work 调用，则行为未定义。
参数
work指向工作项的指针。
sync指向一个不透明项的指针，该项包含与待处理取消操作相关的状态。该对象必须在调用返回前保持存在，并且从调用线程和工作队列线程均可访问。在此操作完成之前，该对象不得用于任何其他 flush 或 cancel 操作。在启用了 CONFIG_KERNEL_COHERENCE 的架构上，该对象必须分配在一致性内存中。
返回值
true如果工作曾处于待处理状态（调用不得不等待正在运行的处理函数取消完成，或已调度、已提交的操作被取消）；
false否则

◆ k_work_flush()

bool k_work_flush ( struct k_work * work,
struct k_work_sync * sync )

#include <zephyr/kernel.h>

等待最后一次提交的实例完成。

等待期间可能发生重新提交，包括（从处理函数内部发起的）链式提交。

注解
注意调用者与工作队列线程的相对优先级。如果此函数进入睡眠，则它将不会返回，直到工作队列线程完成那些允许此线程恢复的任务。
如果从正在运行 work 的工作队列中对此函数传入 work 调用，则行为未定义。
参数
work指向工作项的指针。
sync指向一个不透明项的指针，该项包含与待处理取消操作相关的状态。该对象必须在调用返回前保持存在，并且从调用线程和工作队列线程均可访问。在此操作完成之前，该对象不得用于任何其他 flush 或 cancel 操作。在启用了 CONFIG_KERNEL_COHERENCE 的架构上，该对象必须分配在一致性内存中。
返回值
true如果调用不得不等待完成
false如果工作已处于空闲状态
