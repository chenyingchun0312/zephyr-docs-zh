◆ anonymous enum

anonymous enum

#include <zephyr/fs/fs.h>

用于唯一标识文件系统类型的枚举。

Zephyr 支持树内文件系统和外部文件系统。两者都需要唯一标识符，用于注册文件系统实现并将挂载点与文件系统类型关联。此匿名枚举为树内文件系统定义全局标识符。

外部文件系统应使用以 FS_TYPE_EXTERNAL_BASE 开头的唯一标识符进行注册。如果应用程序使用多个文件系统实现，确保这些标识符唯一是使用外部文件系统的应用程序的责任。

◆ fs_mount()

int fs_mount ( struct fs_mount_t * mp)

#include <zephyr/fs/fs.h>

挂载文件系统

执行挂载文件系统所需的步骤，例如调用文件系统特定的挂载函数，并将挂载点添加到已挂载文件系统列表。

注解
ELM FAT 驱动程序的当前实现仅允许以下挂载点："/RAM:","/NAND:","/CF:","/SD:","/SD2:","/USB:","/USB2:","/USB3:"，或由单个数字组成的挂载点，例如 "/0:"、"/1:" 等。
参数
mp指向 fs_mount_t 结构体的指针。如果挂载操作失败，所引用的对象不会被更改。如果挂载操作成功，fs 基础设施会捕获该引用，在成功对同一指针调用 fs_unmount 之前，应用程序不得更改结构体内容。
返回值
0成功时返回；
-ENOENT当文件系统类型尚未注册时；
-ENOTSUP当底层文件系统驱动程序不支持时；当设置了 FS_MOUNT_FLAG_USE_DISK_ACCESS 但驱动程序不支持它时。
-EBUSY当 mp 已挂载、当另一个文件系统已挂载在 mp->mnt_point、或当 mp->fs_data 已被另一个挂载点使用时；
-EROFS如果系统需要格式化但已设置 FS_MOUNT_FLAG_READ_ONLY 时；
<0出错时为另一个负的 errno 代码。

◆ fs_normalize_path()

int fs_normalize_path ( const char * path,
char * buf,
size_t len )

#include <zephyr/fs/fs.h>

规范化路径

生成 path 的规范化形式：重复和末尾的路径分隔符会被合并，"." 和 ".." 分量按文本方式解析。此过程不查询挂载表，因此 path 不必指定已挂载的文件系统；并且 Zephyr 不支持符号链接，因此不会进行链接解析。

".." 会相对于前一个分量解析，而会爬到开头 "/" 之上的 ".." 则解析为 "/"，这与 POSIX 系统上的行为相同。需要将路径保持在特定子树内的调用者应对照该子树检查规范化结果。

path and buf may be the same buffer, to normalize a path in place. When they are different buffers, they must not overlap.

出错时 buf 的内容未作规定。这对原地操作的情况很重要：被拒绝的路径会使调用者自己的缓冲区被修改。

参数
path要规范化的绝对路径
buf用于接收以 null 结尾的规范化路径的缓冲区
lenbuf 的大小，以字节为单位
返回值
0成功时返回；
-EINVAL当 path 不是绝对路径，或 buf 为 NULL，或 len 为零时；
-ENAMETOOLONG当 buf 太小，无法容纳规范化路径，或无法容纳在解析某个 ".." 之前生成的任何前缀时；
<0出错时为另一个负的 errno 代码。

打开或创建文件

打开（或可能创建）文件，并将一个流与它关联。成功打开的文件在不再使用时应用 fs_close() 关闭。

flags can be 0 or a binary combination of one or more of the following identifiers:

  • FS_O_READ 以只读方式打开
  • FS_O_WRITE 以只写方式打开
  • FS_O_RDWR 以读写方式打开（FS_O_READ | FS_O_WRITE）
  • FS_O_CREATE 如果文件不存在则创建它
  • FS_O_APPEND 在每次写入前移动到文件末尾
  • FS_O_TRUNC 截断文件
警告
如果 flags 设为 0，则函数会打开文件（如果它存在且可访问），但你对它没有读/写权限。
参数
zfp指向一个 已初始化 的文件对象
file_name要打开的文件名
flags模式标志
返回值
0成功时返回；
-EBUSY当 zfp 已被使用时；
-EINVAL当给定的文件名无效时；
-EROFS当以写入方式打开只读文件，或试图在以 FS_MOUNT_FLAG_READ_ONLY 标志挂载的系统上创建文件时；
-ENOENT当该路径下的文件不存在时；
-ENOTSUP当底层文件系统驱动程序未实现时；
-EACCES当试图截断文件却未以写入方式打开它时。
<0其他负的 errno 代码，具体取决于文件系统后端。

返回值
