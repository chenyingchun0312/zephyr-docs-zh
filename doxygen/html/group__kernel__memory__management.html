区域将被固定在内存中，永不换出

一旦映射调用返回，此类内存保证不会因换出或写时复制而产生缺页。物理页框将按需预取并固定。

◆ K_MEM_MAP_UNINIT

#define K_MEM_MAP_UNINIT   BIT(16)

#include <zephyr/kernel/mm.h>

映射的区域不保证被清零。

这可以提高性能。关联的页框可能包含不确定的数据、零，甚至敏感信息。

这不能与 K_MEM_PERM_USER 一起使用，因为任何情况下这样做都不安全。

◆ K_MEM_MAP_UNPAGED

#define K_MEM_MAP_UNPAGED   BIT(18)

#include <zephyr/kernel/mm.h>

区域将被换出，即不映射到内存中

这是供内核代码使用，而不是供应用程序代码使用。

相应的内存地址范围将被设置，因此最初不会分配实际内存。分配将在访问该范围内的地址时通过按需分页进行。这与 K_MEM_MAP_LOCK 不兼容。

指定此标志时，arch_mem_map() 的 phys 参数被解释为后备存储位置值，而不是物理地址。在这方面与 arch_mem_page_out() 非常相似。定义了两个特殊位置值：ARCH_UNPAGED_ANON_ZERO 和 ARCH_UNPAGED_ANON_UNINIT。它们分别用于清零页和未初始化页的匿名内存映射。

size_t k_mem_free_get ( void )

#include <zephyr/kernel/mm.h>

返回可用的空闲内存量

返回的值将反映有多少空闲 RAM 页框可用。如果启用了按需分页，仍有可能分配更多。

如果同时发生内存映射或页入，此函数报告的信息可能立即失效。

返回
空闲物理 RAM，单位为字节

◆ k_mem_map()

void * k_mem_map ( size_t size,
uint32_t flags )
inlinestatic

#include <zephyr/kernel/mm.h>

将匿名内存映射到 Zephyr 的地址空间

此函数实际上增加了 Zephyr 可用的数据空间。内核将选择一个基础虚拟地址并将其返回给调用方。内存将根据提供的 flags 参数为所有上下文设置访问权限。

如果需要以任何方式管理用户线程访问控制，请不要在此处启用 K_MEM_PERM_USER 标志；而应在建立映射后使用内存域 API 管理该区域的权限。在此处设置 K_MEM_PERM_USER 会允许所有用户线程访问此内存，这通常不可取。

除非使用 K_MEM_MAP_UNINIT，否则返回的内存将被清零。

映射的区域不保证在物理内存中连续。物理连续的缓冲区应在构建时静态分配并固定。

以此方式映射的页具有写回缓存设置。

返回的虚拟内存指针将按页对齐。size 参数以及用于重映射的任何基地址都必须按页对齐。

请注意，分配范围包括紧邻所请求区域之前和之后的两个保护页。分配的总大小将是所请求的大小加上这两个保护页的大小。

许多 K_MEM_MAP_* 标志已被实现用于改变此函数的行为，详情见这些标志的文档。

参数
size内存映射的大小。必须按页对齐。
flagsK_MEM_PERM_*、K_MEM_MAP_* 控制标志。
返回
映射的内存位置；如果虚拟地址空间不足、物理内存不足以建立映射，或分页结构内存不足，则为 NULL。

◆ k_mem_unmap()

void k_mem_unmap ( void * addr,
size_t size )
inlinestatic

#include <zephyr/kernel/mm.h>

取消映射已映射的内存

这会移除所提供按页对齐区域的内存映射。关联的页框将被释放，内核可以重新使用关联的虚拟地址区域。任何已换出的数据页都可能被丢弃。

对原本未映射的区域调用此函数属于未定义行为。

参数
addr按页对齐的内存区域基础虚拟地址
size按页对齐的内存区域大小
