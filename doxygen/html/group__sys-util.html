对一组 COND_CODE_1 风格的用例求值。

每个用例由一个标志和一个值组成，均放在圆括号内。参数从左到右依次处理，直到某个标志展开为字面量 1，此时展开对应的值。若没有标志展开为 1，则使用最后一个参数（也必须放在圆括号内）作为默认值。也支持只提供默认参数。

示例： 

int foo = COND_CASE_1(CONFIG_SOME_BOOL, (handle_a()),
                      CONFIG_SOME_OTHER_BOOL, (handle_b()),
                      (handle_default()));

默认值之前最多支持 16 个标志/值对。

参数
...标志/值对，后跟默认值。每个值都必须放在圆括号内，以避免逗号处理问题。

这一技巧最早在 Linux 中作为 config_enabled() 宏提出。它的作用是将可能定义为“1”或根本未定义的宏值转换为字面表达式，从而可由 C 编译器而非仅预处理器处理。它常与 CONFIG_FOO 宏一起使用，该宏可能通过 Kconfig 定义为 1，或保持未定义。

也就是说，它的工作方式类似于 #if defined(CONFIG_FOO)，只是其展开结果是 C 表达式。因此，许多 #ifdef 用法都可以替换为如下等价写法： 

if (IS_ENABLED(CONFIG_FOO)) {
        do_something_with_foo
}

这更简洁，因为即使 CONFIG_FOO 未定义，编译器也能为 do_something_with_foo 产生错误和警告。

注意：不建议在 #if 语句中使用 IS_ENABLED，因为与普通的 #if defined() 相比它没有任何好处

参数
config_macro要检查的宏
返回
若 config_macro 定义为 1 则为 1，否则为 0（包括 config_macro 未定义的情况）
