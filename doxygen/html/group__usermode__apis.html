授予静态线程对一组内核对象的访问权限

对于用 K_THREAD_DEFINE() 声明的线程，授予该线程对一组内核对象的访问权限。这些对象无需处于已初始化状态。在线程于早期启动序列中被初始化时会授予这些权限。

第一个参数之后的所有参数都必须是内核对象的指针。

参数
name_传给 K_THREAD_DEFINE() 的线程名称

◆ k_object_access_all_grant()

void k_object_access_all_grant ( const void * object)

#include <zephyr/sys/kobject.h>

授予所有当前和未来线程对某个对象的访问权限

若调用方来自监管模式，或调用方来自用户模式且对该对象有足够权限，则该对象将被授予系统中 所有 当前和未来线程的访问权限，实际上成为一个公共内核对象。

在运行不受信任代码的系统上应避免使用此 API，因为这类代码可能推导出内核对象的地址并对其执行不期望的操作。

无法撤销单个线程对公共对象的权限；对象一旦成为公共的，任何线程都可以使用它。可使用 k_object_access_revoke_others() 还原对象的公共访问状态。

参数
object内核对象的地址

◆ k_object_access_revoke_others()

void k_object_access_revoke_others ( const void * object)

#include <zephyr/sys/kobject.h>

撤销所有其他线程对内核对象的访问权限

用户线程可以把它有权访问的对象（包括它自己创建的线程）授予其他线程访问。因此在许多情况下，仅从指定线程撤销访问权限并不够。此 API 会撤销除当前线程之外所有其他线程的访问权限，从而不留下任何有权限的用户线程。

这还会还原公共访问状态，该状态之前可能已由 k_object_access_all_grant() 授予某个对象。

注意此函数只能由内核线程使用。因此，保留调用线程的访问权限在权限层面几乎没有影响，但我们希望保留一个所有者，以便明确此函数从不会释放动态对象——通常动态对象在不再有任何所有者时就会被释放。

参数
object内核对象的地址

void * k_object_alloc ( enum k_objects otype)

#include <zephyr/sys/kobject.h>

分配指定类型的内核对象

这会在运行时实例化指定类型的内核对象并返回指向它的指针。该对象将以未初始化状态返回，同时授予调用线程对其的权限。对象的内存将从调用线程的资源池中分配。

注解
仅在选中 CONFIG_DYNAMIC_OBJECTS 时此函数才可用。
线程栈对象必须使用 k_object_alloc_size()，因为栈的大小可能不同。
参数
otype请求的内核对象类型
返回
指向所分配内核对象的指针，若内存不可用则为 NULL

分配指定类型且给定大小的内核对象

这会在运行时实例化指定类型的内核对象并返回指向它的指针。该对象将以未初始化状态返回，同时授予调用线程对其的权限。对象的内存将从调用线程的资源池中分配。
