初始化“直接”中断处理程序。

此例程为某个 IRQ 初始化中断处理程序。随后必须先通过 irq_enable() 使能该 IRQ，中断处理程序才会开始处理中断。

这些 ISR 面向性能关键的中断处理，不经过通用中断处理代码。它们的实现方式必须保证可以直接放入向量表中是安全的。对于用 C 编写的 ISR，ISR_DIRECT_DECLARE() 宏会自动完成这一点。对于用汇编编写的 ISR，则完全由开发者确保采取正确的步骤。

与普通的 Zephyr 中断相比，此类中断目前有一些限制：

  • 不向 ISR 传递任何参数。
  • 不进行栈切换，ISR 将在被中断上下文的栈上运行，除非架构在硬件中自动完成栈切换。
  • 中断锁定状态与硬件在 ISR 运行时所设置的一致。在进入 ISR 时中断处于锁定状态的架构上，中断将保持锁定。
  • 调度决策现在是可选的，由使用 ISR_DIRECT_DECLARE() 宏实现的 ISR 的返回值控制
  • 调用操作系统以退出电源管理空闲状态现在是可选的。普通中断总是在 ISR 运行之前执行此操作，而现在何时执行由 ISR_DIRECT_PM() 宏的放置位置控制，或完全省略。
警告
尽管此例程在运行时调用，其所有参数必须能在构建时由编译器计算出来。
注解
所有使用 IRQ_ZERO_LATENCY 标志配置的 IRQ 都必须声明为直接中断。
参数
irq_pIRQ 线号。
priority_p中断优先级。
isr_p中断服务例程的地址。
flags_p架构特定的 IRQ 配置标志。

◆ irq_lock

#define irq_lock ( )

#include <zephyr/irq.h>

值:
z_smp_global_lock()

锁定中断。

此例程禁用 CPU 上的所有中断。它返回一个无符号整数“锁定键”，这是架构相关的指示，表示调用之前中断是否已锁定。该锁定键必须传给 irq_unlock() 才能重新使能中断。

注解
此例程还必须充当内存屏障，以确保自旋锁的单处理器实现正确。

此例程可递归调用，只要调用者跟踪好每个生成的锁定键。通过按获取时的相反顺序将各个键传给 irq_unlock() 来重新使能中断。（也就是说，每次 irq_lock() 调用都必须由相应的 irq_unlock() 调用平衡。）

此例程只能从管理员模式调用。某些架构（例如 ARM）在从用户模式调用时会静默失败，而不是产生异常。

ISR 和线程都可以调用此例程。

警告
只要对 irq_lock() 的所有递归调用尚未由相应的 irq_unlock() 调用平衡，调用者就“持有中断锁”。在发生上下文切换时“持有中断锁”是非法的。
锁定键绝不应被用于手动重新使能中断，或检查、操作 CPU 中断位的内容。
返回
架构相关的锁定键，表示调用之前的“中断禁用状态”。

用于声明直接中断服务例程的辅助宏。

这会以正确的方式声明该函数，并自动包含 ISR_DIRECT_FOOTER() 和 ISR_DIRECT_HEADER() 宏。如果可能需要做出调度决策，该函数应返回非零状态。有关调度决策的更多细节，参见 ISR_DIRECT_FOOTER()。

对于同时支持“常规”和“快速”中断类型、且这两种中断类型要求 ISR 以不同汇编方式处理寄存器的架构，这始终会为“快速”中断类型生成代码。

警告
服务于使用 IRQ_ZERO_LATENCY 标志配置的 IRQ 的任何 ISR，在此宏中都必须始终返回 0。

用法示例： 

ISR_DIRECT_DECLARE(my_isr) { bool done = do_stuff(); ISR_DIRECT_PM(); // 出于延迟考虑，在 do_stuff() 之后执行 if (!done) { return 0; // 无需检查是否必须调用 z_swap() }

        k_sem_give(some_sem);
        return 1;
 }
参数
nameISR 的符号名

退出 ISR 主体之前的通用任务

此宏必须位于所有直接中断的末尾，执行诸如 EOI 之类最少的架构特定任务。它没有返回值。

在普通中断中，中断结束时会有一次检查，以在当前线程可抢占且内核就绪队列缓存中存在另一个可运行线程时调用 z_swap() 逻辑。这现在是可选的，由 check_reschedule 参数控制。如果不确定，请设为非零。在软件中完成栈切换和嵌套中断跟踪的系统上，仅在这是非嵌套中断时才应调用 z_swap()。

参数
check_reschedule若非零，则额外调用调度逻辑

◆ k_is_preempt_thread()

int k_is_preempt_thread ( void )
isr-ok

#include <zephyr/kernel.h>

判断代码是否在抢占式线程中运行。

此例程允许调用者根据自己是否可能被另一线程抢占来定制其行为。如果满足以下所有条件，该例程返回 'true' 值：

  • 代码在线程中运行，而不是在 ISR 中。
  • 该线程的优先级处于抢占式范围内。
  • 该线程尚未锁定调度器。
返回
如果由 ISR 或协作式线程调用则为 0。
如果由抢占式线程调用则为非零。
