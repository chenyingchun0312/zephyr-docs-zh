RFCOMM 开销长度

RFCOMM 的开销长度包括最大报头长度、FCS 长度和 credits 长度。

对于 credits 大小字段，在支持 CFC 的情况下，应从最大帧长度中扣除 credits 占用的空间。这样可避免在包含 credits 字段时 SDU 长度超过最大帧长度。

◆ bt_rfcomm_dlc_recv_complete()

int bt_rfcomm_dlc_recv_complete ( struct bt_rfcomm_dlc * dlc,
struct net_buf * buf )

#include <zephyr/bluetooth/classic/rfcomm.h>

完成接收 RFCOMM 通道数据

对每次返回的 bt_rfcomm_dlc_ops::recv 调用，必须恰好调用一次 -EINPROGRESS. Pass back the same buf pointer that was received in that callback; no additional net_buf_ref or net_buf_unref calls are needed.

注解
此函数只能从线程上下文调用，绝不能从 ISR 调用。
此函数只能在 bt_rfcomm_dlc_ops::recv 返回之后调用。在 recv 回调内部（返回之前）调用它会使进行中计数器下溢，并使此函数返回 -EINVAL。

当此函数返回时，无论返回值如何，协议栈都会释放其对 buf 的引用，除非 dlc 或 buf 为 NULL（此时会立即返回 -EINVAL，并且 buf is not touched).

成功调用后的流控行为：

  • CFC 会话：协议栈现在可以向远端发送额外的 RX 信用，允许其发送更多帧。
  • 非 CFC 会话：仅当所有进行中的缓冲区都完成时，才会向远端发送带 FC=0（恢复）的 MSC 命令。
参数
dlc指向正在完成接收操作的 RFCOMM DLC 的指针。
buf当 bt_rfcomm_dlc_ops::recv 返回时传给它的缓冲区 -EINPROGRESS.
返回
成功时为 0，出错时为负值。
返回值
-EINVALdlc 或 buf 为 NULL、DLC 的 CFC 状态未知，或进行中计数器将要下溢（完成次数多于进行中的调用次数）。
-ENOTCONN该 DLC 没有关联的会话，或未处于已连接状态。

◆ bt_rfcomm_send_rls_cmd()

int bt_rfcomm_send_rls_cmd ( struct bt_rfcomm_dlc * dlc,
uint8_t line_status )

#include <zephyr/bluetooth/classic/rfcomm.h>

发送远程线路状态命令

将带有特定 rls 值 line_status 的远程线路状态发送给 RFCOMM DLC。对于 line_status，BIT(4-7) 为保留位，必须设置为 0。BIT(0-3) 表示线路状态。如果 BIT(0) 为 0，表示未发生错误。如果 BIT(0) 为 1，则由 BIT(1-3) 按以下取值指示错误： BT_RFCOMM_RLS_ERR_OVERRUN_ERROR - Received character overwrote an unread character. BT_RFCOMM_RLS_ERR_PARITY_ERROR - Received character's parity was incorrect. BT_RFCOMM_RLS_ERR_FRAMING_ERROR - a character did not terminate with a stop bit.

line_status can be created using BT_RFCOMM_RLS_NO_ERR and BT_RFCOMM_RLS_ERR macros.

参数
dlc指向 RFCOMM DLC 的指针
line_status线路状态值
返回
成功时为 0，失败时为负的错误码
