用给定的自旋锁守护一个代码块，在执行该代码块之前自动获取锁。锁将在到达代码块末尾时、或在通过以下方式离开代码块时释放 K_SPINLOCK_BREAK.

用法示例：

K_SPINLOCK(&mylock) {
...execute statements with the lock held...
if (some_condition) {
...release the lock and leave the guarded section prematurely:
K_SPINLOCK_BREAK;
}
...execute statements with the lock held...
}

Behind the scenes this pattern expands to a for-loop whose body is executed exactly once:

for (k_spinlock_key_t key = k_spin_lock(&mylock); ...; k_spin_unlock(&mylock, key)) {
...
}
警告
The code block must execute to its end or be left by calling K_SPINLOCK_BREAK. Otherwise, e.g. if exiting the block with a break, goto or return statement, the spinlock will not be released on exit.
注解
In user mode the spinlock must be placed in memory accessible to the application, see K_APP_DMEM and K_APP_BMEM macros for details.
参数
lckSpinlock used to guard the enclosed code block.

自旋锁键类型

此类型定义了自旋锁实现所使用的“键”值，用于在调用 k_spin_lock() 时保存系统中断状态。它应被传给匹配的 k_spin_unlock()。

此类型是不透明的，应用程序代码不应检查它。

锁定自旋锁

此例程锁定指定的自旋锁，并返回一个键句柄，表示解锁时所需的中断状态。返回后，调用线程在其当前 CPU 上保证不会被挂起或中断，直到它调用 k_spin_unlock()。该实现保证互斥：同一时刻只有一个 CPU 上的一个线程从 k_spin_lock() 返回。其他 CPU 若尝试获取已被另一 CPU 持有的锁，将进入由实现定义的忙等循环（“自旋”），直到锁被释放。

不同的自旋锁可以嵌套。在持有一个锁的同时锁定另一个（未锁定的）自旋锁是合法的。然而自旋锁不是递归的：尝试获取 CPU 已持有的自旋锁会导致死锁。

在只有一个 CPU 的情况下，k_spin_lock() 的行为仍与上述规定一致，尽管显然不会发生自旋。在单处理器上下文中，实现可以自由优化，使加锁简化为屏蔽中断的操作。

警告
在发生上下文切换时持有自旋锁是非法的。
参数
l指向要锁定的自旋锁的指针
返回
一个键值，在释放锁时必须传给 k_spin_unlock()。

解锁自旋锁

此函数释放由 k_spin_lock() 获取的锁。调用此函数后，任何 CPU 都能获取该锁。如果其他 CPU 当前正在 k_spin_lock() 中自旋等待该锁，它们中恰好一个会在持有锁的情况下同步返回。

自旋锁必须正确嵌套。对 k_spin_unlock() 的调用必须针对最近使用 k_spin_lock() 锁定的锁对象，并使用其返回的键值。试图解锁嵌套错误的锁、解锁未被持有的锁，或传入并非由 k_spin_lock() 返回的键参数，都是非法的。当设置了 CONFIG_SPIN_VALIDATE 时，框架可以检测出其中部分错误。

参数
l指向要释放的自旋锁的指针
key获取此锁时由 k_spin_lock() 返回的值
