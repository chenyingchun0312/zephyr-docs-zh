◆ sys_notify_generic_callback

typedef void(*) sys_notify_generic_callback()

#include <zephyr/sys/notify.h>

用于通过回调通知结果完成的通用签名。

具有此角色的函数可从任何上下文调用，包括内核前、ISR 或协作式、可抢占线程。兼容的函数必须支持 ISR 且不得睡眠。

通常应传给此类函数的参数包括：

  • 指向特定客户端请求结构体的指针，即包含 sys_notify 结构体的那个请求。
  • 操作的结果，既可传给 sys_notify_finalize()，也可稍后用 sys_notify_fetch_result() 提取。期望值因服务而异，但操作成功时该值应为非负，操作失败时应为负。

◆ sys_notify_init_callback()

void sys_notify_init_callback ( struct sys_notify * notify,
sys_notify_generic_callback handler )
inlinestatic

#include <zephyr/sys/notify.h>

为回调通知初始化通知对象。

使用此初始化的客户端将通过所提供的回调获知操作的完成。注意，回调可能依具体服务而从不同上下文调用；参见 sys_notify_generic_callback。

操作完成后，必须重新初始化客户端对象才能再次使用。

参数
notify指向通知配置对象的指针。
handler用于通知的函数指针。

◆ sys_notify_uses_callback()

bool sys_notify_uses_callback ( const struct sys_notify * notify)
inlinestatic

#include <zephyr/sys/notify.h>

检测某个特定通知是否使用回调。

通用处理程序不捕获回调所期望的签名，转换为服务特定回调必须由服务提供。此检查允许抽象服务在自身不提供转换函数时拒绝回调通知请求。

返回
当且仅当通知使用回调时为 true。

◆ sys_notify_validate()

int sys_notify_validate ( struct sys_notify * notify)

#include <zephyr/sys/notify.h>

校验并初始化通知结构体。

这应在任何服务特定的配置校验开始时调用。它确保基本的异步通知配置一致，并清除结果。

注意此函数不校验扩展位（由 sys_notify_init_callback() 等异步通知 API 初始化函数清零）。由于只针对方法设置测试 flags 的方法位，它可能无法识别出传入的是未初始化的结构体。为降低接受未初始化操作的可能性，对包含 sys_notify 实例的结构体进行服务校验时应确认扩展位按预期置位或清零。

返回值
0在成功校验并重新初始化时
-EINVAL若配置无效。
