详细描述

用于显示驱动的 RGB 到调色板抖动辅助函数。

这些辅助函数让原生写路径使用 PIXEL_FORMAT_I_4 的驱动也能接受所配置的 RGB 输入格式。该辅助函数将每个 RGB 写缓冲区转换为打包的 PIXEL_FORMAT_I_4 using the driver's color palette before the native write code runs.

驱动在四个位置使用该辅助函数：

  • 在驱动的数据中加入 display_color_dither_state 成员，以嵌入每实例状态。
  • 使用 DISPLAY_COLOR_DITHER_DEFINE 定义并初始化后备存储，并 DISPLAY_COLOR_DITHER_INIT.
  • 在 display_driver_api.write() 操作开始时调用 display_color_dither_prepare。
  • 在驱动的 display_driver_api.get_capabilities() 操作中填好显示能力之后，调用 display_color_dither_patch_caps。
  • 在 display_driver_api.set_pixel_format() 中调用 display_color_dither_set_input_format

典型集成方式：

#include <zephyr/drivers/display/color_dither.h>
struct foo_data {
struct display_color_dither_state color_dither;
// ... other fields for driver state ...
};
static int foo_write(const struct device *dev,
const uint16_t x, const uint16_t y,
const struct display_buffer_descriptor *desc,
const void *buf)
{
struct display_buffer_descriptor scratch;
struct foo_data *data = dev->data;
int ret = display_color_dither_prepare(dev, &data->color_dither, &desc, &buf,
&scratch);
if (ret < 0) {
return ret;
}
// ...existing I_4-only body, unchanged...
}
static void foo_get_capabilities(const struct device *dev, struct display_capabilities *caps)
{
struct foo_data *data = dev->data;
// ... existing population of caps (advertising I_4, plus maybe other formats) ...
display_color_dither_patch_caps(&data->color_dither, caps);
}
static int foo_set_pixel_format(const struct device *dev,
enum display_pixel_format pf)
{
struct foo_data *data = dev->data;
// Let the color dithering helper know which input format to expect.
return display_color_dither_set_input_format(&data->color_dither, pf);
}
// In the driver instance definition, define backing storage before data:
#define FOO_DEFINE(inst) \
DISPLAY_COLOR_DITHER_DEFINE(inst); \
static struct foo_data foo_data_##inst = { \
.color_dither = DISPLAY_COLOR_DITHER_INIT(inst), \
}; \
DEVICE_DT_INST_DEFINE(inst, ...);

对每个可使用该辅助函数的驱动实例使用一次。它会分配转换缓冲区和可选的误差扩散行。缓冲区尺寸来自该实例的 width 和 height 设备树属性。

将辅助函数管理的 RGB 格式添加到显示能力。

在驱动的 display_driver_api.get_capabilities() 操作末尾调用，此时驱动已填好其原生能力和调色板。

这会将由 Kconfig 启用的 RGB 格式添加到 display_capabilities::supported_pixel_formats 中的受支持像素格式列表。

当辅助函数正在主动转换时，它还会在 display_capabilities::current_pixel_format 中报告由辅助函数管理的输入格式。

注意
Available only when the following Kconfig option is enabled: CONFIG_DISPLAY_COLOR_DITHER.
参数
state嵌入在驱动数据中的颜色抖动状态。
caps要修补的能力。

int display_color_dither_prepare ( const struct device * dev,

struct display_buffer_descriptor * scratch )

#include <zephyr/drivers/display/color_dither.h>

为 PIXEL_FORMAT_I_4 原生路径准备写缓冲区。

在驱动的 display_driver_api.write() 操作开始时调用。

若 state->input_format 是 RGB 输入格式，则此函数将 buf 转换为打包的 PIXEL_FORMAT_I_4 and updates desc and buf to point at the converted data.

若 state->input_format 为 PIXEL_FORMAT_I_4，或状态中没有转换缓冲区，则输入保持不变。

注意
Available only when the following Kconfig option is enabled: CONFIG_DISPLAY_COLOR_DITHER.
参数
dev显示设备。用于读取驱动的调色板。
state嵌入在驱动数据中的颜色抖动状态。
desc写回调描述符指针的地址。
buf写回调缓冲区指针的地址。
scratch由调用方拥有的暂存描述符存储。
返回值
0写操作可以继续。
-EINVAL输入描述符对所选格式无效。
-ENOMEM转换缓冲区太小。
-ENOTSUP无法转换所选格式或调色板。

◆ display_color_dither_set_input_format()

int display_color_dither_set_input_format ( struct display_color_dither_state * state,
enum display_pixel_format pf )

#include <zephyr/drivers/display/color_dither.h>

选择辅助函数输入像素格式。

在驱动的 display_driver_api.set_pixel_format() 操作中调用。

pf 值为 PIXEL_FORMAT_I_4 时选择驱动的原生 I_4 写路径，不做辅助函数转换。

pf 为已配置的 RGB 格式时指示辅助函数将输入转换为打包的 PIXEL_FORMAT_I_4 before the driver's native write path runs.

注意
Available only when the following Kconfig option is enabled: CONFIG_DISPLAY_COLOR_DITHER.
参数
state嵌入在驱动数据中的颜色抖动状态。
pf调用方请求的像素格式。
返回值
0成功，包括不经辅助函数转换的原生 PIXEL_FORMAT_I_4。
-ENOTSUP辅助函数被禁用、state 没有转换缓冲区，或 pf 不支持 RGB 到 I_4 的转换。
