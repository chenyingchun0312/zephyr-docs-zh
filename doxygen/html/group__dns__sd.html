为 DNS 服务发现注册服务

此宏应用于高级用例。两个简单的用例是需要自定义 _domain 或自定义（非标准）_proto 时。

另一个用例是端口号未预先分配。这可能有多方面原因，但最常见的用例是使用临时端口，即服务使用端口号 0 进行绑定。在这种情况下，Zephyr（与其他 OS 一样）会直接选择一个未使用的端口。使用临时端口时，将 _port 赋值为 net_sockaddr_in::sin_port field of an IPv4 net_sockaddr_in, or to the net_sockaddr_in6::sin6_port field of an IPv6 net_sockaddr_in6.

可以使用 _id 变量引用该服务。

参数
_idDNS-SD 服务记录的变量名
_instance服务实例的名称，例如 "My HTTP Server"
_service服务的名称，例如 "_http"
_proto服务使用的协议，为 "_tcp" 或 "_udp"
_domain服务的域，例如 "local"
_textDNS TXT 记录的信息
_port指向该服务将使用的端口号的指针

为 DNS 服务发现注册 TCP 服务

此宏可用于通过 DNS-SD 通告服务。

可以使用 id 变量引用该服务。

示例（带 TXT）：

#include <zephyr/net/dns_sd.h>
static const char bar_txt[] = {
"\x06" "path=/"
"\x0f" "this=is the way"
"\x0e" "foo or=foo not"
"\x17" "this=has\0embedded\0nulls"
"\x04" "true"
};
DNS_SD_REGISTER_TCP_SERVICE(bar, CONFIG_NET_HOSTNAME,
"_bar", "local", bar_txt, 4242);

TXT records begin with a single length byte (hex-encoded) and contain key=value pairs. Thus, the length of the key-value pair must not exceed 255 bytes. Care must be taken to ensure that the encoded length value is correct.

For additional rules on TXT encoding, see RFC 6763, section-6.

bool dns_sd_is_service_type_enumeration ( const struct dns_sd_rec * rec)

#include <zephyr/net/dns_sd.h>

检查 rec 是否为 DNS-SD 服务类型枚举

DNS-SD 服务类型枚举供网络工具使用，用于获取属于特定主机、特定域的所有 mDNS 通告服务的列表。

例如，对于域 '.local'，等效查询为 '_services._dns-sd._udp.local'。

目前仅支持 '.local' 域。

参见
RFC 6763, section-9
参数
rec所涉及的记录
返回
若 rec 是 DNS-SD 服务类型枚举则为 true
