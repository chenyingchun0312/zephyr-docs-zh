◆ PM_DEVICE_ISR_SAFE

#define PM_DEVICE_ISR_SAFE   1

#include <zephyr/pm/device.h>

指示设备的运行时 PM API 可以从任意上下文调用的标志。

如果设备定义使用了 PM_DEVICE_ISR_SAFE 标志，则表示 PM 动作是同步的，可以从任意上下文执行。此方式适用于挂起和恢复耗时较短的场景，因为它会在临界区中执行。此模式占用较少的资源（RAM 少约 80 字节），并允许从任意上下文（包括中断）使用设备运行时 PM。

◆ pm_device_action

enum pm_device_action

#include <zephyr/pm/device.h>

设备 PM 动作。

枚举值
PM_DEVICE_ACTION_SUSPEND 

Suspend.

PM_DEVICE_ACTION_RESUME 

Resume.

PM_DEVICE_ACTION_TURN_OFF 

关闭。

仅由电源域触发的动作。

此动作作为通知发送给设备，告知其电源域即将断电。此动作完成后，设备必须已禁用 IRQ、释放资源，并完全做好断电准备。

电源域实际断电的时机取决于平台，可能立即发生、被推迟，或作为系统级电源转换的一部分处理。此动作仅表示设备应做好可能断电的准备。

PM_DEVICE_ACTION_TURN_ON 

开启。

仅由电源域触发的动作。

此动作作为通知发送给设备，告知其电源域已上电。

◆ pm_device_state

enum pm_device_state

#include <zephyr/pm/device.h>

设备电源状态。

枚举值
PM_DEVICE_STATE_ACTIVE 

设备硬件已上电，且系统需要该设备。

此状态下应启用该设备。此状态下可以调用任何设备驱动 API。

PM_DEVICE_STATE_SUSPENDED 

设备硬件已上电，但系统不需要该设备。

设备应进入其最低内部电源状态，通常称为 "disabled" 或 "stopped"。

如果某个设备被指定为此设备的电源域，且该设备不再被系统需要，则此设备将转换到 PM_DEVICE_STATE_OFF 状态，随后电源域设备将转换到 PM_DEVICE_STATE_SUSPENDED state.

某设备驱动可在此状态下反初始化。设备驱动反初始化后，我们隐式转入 PM_DEVICE_STATE_OFF state as the device hardware may lose power, with no device driver to respond to the corresponding PM_DEVICE_ACTION_TURN_OFF action.

注解
此状态不是“低功耗”/“部分可操作”状态，那些状态通过设备驱动特定的 API 配置，且仅在设备处于 PM_DEVICE_STATE_ACTIVE 状态时才适用。
PM_DEVICE_STATE_SUSPENDING 

设备硬件已上电，但由于系统不再需要该设备，它已被排定为挂起。

此状态用于将设备的挂起委托给 PM 子系统，并可选地采用驻留时间以避免不必要的挂起/恢复循环，它源于对以下函数的调用 pm_device_runtime_put_async. The device will be unscheduled in case the device becomes needed by the system.

此状态下不得进行任何设备驱动 API 调用。

注解
即此状态对设备驱动是不透明的（无 pm_device_action is called as this state is entered) and is used solely by PM_DEVICE_RUNTIME.
PM_DEVICE_STATE_OFF 

设备硬件未上电。这是设备驱动初始化时所处的初始状态。

当设备驱动被初始化时，我们并不知道设备的状态。因此，PM_DEVICE_ACTION_TURN_ON 动作应能将设备从任意内部状态转换到 PM_DEVICE_STATE_SUSPENDED, since no guarantees can be made across resets. This is typically achieved through toggling a reset pin or triggering a software reset through a register write before performing any additional configuration needed to meet the requirements of PM_DEVICE_STATE_SUSPENDED. For devices where this is not possible, the device driver must presume the device is in either the PM_DEVICE_STATE_OFF or PM_DEVICE_STATE_SUSPENDED state at time of initialization, as these are the states within which device drivers may be deinitialized.

如果某个设备被指定为此设备的电源域，且该设备被系统需要，则电源域设备将转换到 PM_DEVICE_STATE_ACTIVE 状态，随后此设备将转换到 PM_DEVICE_STATE_SUSPENDED state.

◆ pm_device_driver_init()

int pm_device_driver_init ( const struct device * dev,
pm_device_action_cb_t action_cb )

#include <zephyr/pm/device.h>

将设备驱动移入其初始设备电源状态。

此函数使用设备驱动的内部 PM 钩子，将设备从 OFF 状态移到系统期望的初始电源状态。

系统期望的初始电源状态为：

  • 如果 CONFIG_PM_DEVICE=n，或（CONFIG_PM_DEVICE=y 且 CONFIG_PM_DEVICE_RUNTIME=n），或（CONFIG_PM_DEVICE_RUNTIME=y 且 !pm_device_runtime_is_enabled(dev)），则为 ACTIVE。
  • 如果 CONFIG_PM_DEVICE_RUNTIME=y 且设备的父电源域为 ACTIVE，则为 SUSPENDED。
  • 如果 CONFIG_PM_DEVICE_RUNTIME=y 且设备的父电源域为 SUSPENDED，则为 OFF。
注解
此函数必须在驱动 init 函数的末尾调用。
参数
dev设备实例。
action_cb设备 PM 控制回调函数。
返回
成功时为 0，失败时为负的 errno 值。

◆ pm_device_init_off()

void pm_device_init_off ( const struct device * dev)
inlinestatic

#include <zephyr/pm/device.h>

将设备状态初始化为 #PM_DEVICE_STATE_OFF。

默认情况下设备状态被初始化为 #PM_DEVICE_STATE_ACTIVE。通常这是合理的，因为设备初始化函数会恢复并配置设备，使其处于可工作状态。然而启用电源域后，设备可能连接到可开关的电源，此时它在启动时不会上电。因此可以用此函数通知 PM 子系统设备处于 PM_DEVICE_STATE_OFF 而非默认状态。
