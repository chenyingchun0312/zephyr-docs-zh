详细描述

沿 pad 链接传递的查询或事件。

派发沿一次同步遍历传递，因此它引用寿命长于该遍历的存储，而不是内嵌其所携带全部内容的副本。它使用指定初始化器声明，没有 init 函数——零是每个字段的中性值：

struct mpipe_dispatch query = {
.type = MPIPE_DISPATCH_CAPS,
.caps = &caps_storage,
};

结构体成员变量说明

◆ caps

struct mpipe_structure* mpipe_dispatch::caps

所携带的能力，派发未携带任何能力时为 NULL。

创建者将其指向自己在整个遍历期间拥有的存储；其他每个元素通过它读取，并通过复制到其中作答，绝不能重新指向它。

| 值 | 在查询中（输入/输出存储） | 在事件中（通告） | | :— | :— | :— | | 一个能力 | 用于作答的过滤器 | 已确定的格式 | | ANY | 无约束：用你支持的全部作答 | 绝不发送 | | NULL | 调用方错误：无处作答 | 没有任何可通告的内容 |

查询函数可以不加检查地解引用它：未携带存储的 caps 查询会在任何查询函数被调用之前由 mpipe_pad_query() 以 -EINVAL 拒绝。事件处理函数必须检查，因为 NULL 是事件可以合法携带的内容。

未携带任何内容的 caps 事件是触发器而不是通告：不知道格式的源（例如文件源）仍会发送一个，而第一个知道格式的元素会将其填入并向下游通告。
