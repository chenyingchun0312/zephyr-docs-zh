Producer/consumer

Browse source code on GitHub

概述

设想一个“示例驱动”，它从某个未知来源获取输入数据，并产生携带指向这些数据的指针的中断。应用程序需要对这些数据进行一些处理，然后将处理后的数据写回驱动。

本示例的目标是演示：

  • 多个逻辑应用程序，各自拥有自己的内存域

  • 创建 sys_heap 并将其分配给内存分区

  • 使用 k_queue_alloc_append() 等需要配置线程资源池的 API

  • 管理内核对象和驱动的权限

  • 展示如何定义应用程序专用的系统调用

  • 展示 ISR 与应用程序之间的 IPC（使用 k_msgq）以及应用程序之间的 IPC（使用 k_queue）

  • 展示如何创建应用程序专用的系统调用

在本示例中，应用程序 A 负责与驱动通信、缓冲输入数据，并在应用程序 B 处理完数据后将其写回。

应用程序 B 只负责处理数据。假设这些数据不可信且可能是恶意的，因此应用程序 B 与其他所有部分隔离在沙箱中，只有两个队列用于发送和接收数据项。

控制循环如下：

  • 示例驱动产生中断，并以固定大小的数据负载调用其关联的回调函数。

  • 应用程序 A 的回调函数在特权模式（supervisor mode）下将数据负载放入消息队列。

  • 应用程序 A 的监控线程在用户模式下等待消息队列中的数据。唤醒后，它将数据负载复制到从共享内存池分配的缓冲区中，并将该数据加入应用程序 B 所监控的 k_queue。

  • 应用程序 B 的处理线程等待队列中的新数据项，然后原地处理数据，处理完成后将处理后的数据放入另一个队列，以便写回驱动。

  • 应用程序 A 的回写线程监控输出数据队列中包含已处理数据的新数据项。每取得一项，就将数据写回驱动并释放缓冲区。

本示例还以 magic_cookie() 函数的形式演示了应用程序定义的系统调用。
