NXP MCX suspend-to-RAM

Browse source code on GitHub

概述

本示例在 NXP MCXA 和 MCXN SoC 上测试 PM_STATE_SUSPEND_TO_RAM，该状态映射到 SoC 的深度掉电（Deep Power Down）模式。CORE 电源域被关断，芯片通过复位例程唤醒；随后 pm_s2ram 恢复路径直接返回挂起调用处，不会重新运行内核或 CPU 初始化，因此在这两个系列上，恢复过程对应用程序都是透明的（原地恢复）。

一个替身应用程序线程模拟真实的工作负载：它完成工作后阻塞等待下一个事件，对深度掉电一无所知。线程将 SoC 挂起到 RAM，唤醒后在其阻塞处透明地恢复执行。每次挂起前递增的计数器在周期结束后依然保留，因此打印出的值证明了 RAM 内容被保持。

该线程重复 CONFIG_SAMPLE_APP_TEST_CYCLES 个周期（默认 10 个）后停止，并打印最后一行 Completed N suspend-to-RAM cycles，供测试工具确认每次唤醒都已发生。无需任何控制台输入。运行结束后 SoC 保持唤醒状态（所有电源管理状态都被锁定，因此只有在示例明确要求时才会挂起）。

唤醒源通过 WUC（唤醒控制器） 子系统配置，可在构建时选择：

  • CONFIG_SAMPLE_S2RAM_WAKEUP_TIMER（默认）通过计数器告警 API 设置 LPTMR0，并将其作为 WUU 内部模块唤醒源路由到内核。工作线程阻塞在 k_sleep() 中，因此周期会自动重复。

  • CONFIG_SAMPLE_S2RAM_WAKEUP_BUTTON 在 WUU 外部引脚发生电平跳变时恢复（即开发板的 wakeup-button，SW2）。深度掉电会复位 GPIO，因此恢复时没有可捕获的 GPIO 边沿，按键只会被 WUU 锁存。因此示例将挂起到 RAM 的恢复本身视为唤醒信号（未设置其他唤醒源），由一个电源管理通知器检测到后释放工作线程。按下 SW2 推进每个周期。

备注

在 MCXN SoC 上，只有 SRAMA（前 32 KB，由 VBAT RAM LDO 保持）能在深度掉电中保留，因此整个需保持的工作集必须放在 SRAMA 中，并且 zephyr,sram 必须指向它。在 MCXA SoC 上，所有 SRAM 都由 SPC SRAM 保持 LDO 保持，因此没有位置限制。

构建与运行

west build -b frdm_mcxa156 samples/boards/nxp/mcxn_a/s2ram
west flash

示例输出

frdm_mcxa156 suspend-to-RAM demo
Retained S2RAM cycle counter: 0
Entering suspend-to-RAM (cycle 1/10); wake in 3 s
Resumed from suspend-to-RAM; retained counter is 1
Entering suspend-to-RAM (cycle 2/10); wake in 3 s
Resumed from suspend-to-RAM; retained counter is 2
...
Entering suspend-to-RAM (cycle 10/10); wake in 3 s
Resumed from suspend-to-RAM; retained counter is 10
Completed 10 suspend-to-RAM cycles

使用 CONFIG_SAMPLE_S2RAM_WAKEUP_BUTTON 时，每个周期改为等待按下 SW2：

frdm_mcxn236 suspend-to-RAM demo
Retained S2RAM cycle counter: 0
Entering suspend-to-RAM (cycle 1/10); press SW2 to wake
Resumed from suspend-to-RAM; retained counter is 1
Entering suspend-to-RAM (cycle 2/10); press SW2 to wake
Resumed from suspend-to-RAM; retained counter is 2
...
