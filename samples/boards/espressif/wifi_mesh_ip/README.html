Wi-Fi Mesh IP

Browse source code on GitHub

概述

本示例在自组织的 Wi-Fi mesh 上承载 IP，使单播 IPv4 套接字无需修改即可在每个节点上运行（mesh 传输不承载的内容见 Limitations）。它基于 Wi-Fi Mesh 示例构建：各节点组成相同的自组织 mesh（AP 与 station 组合模式，按路由器可达性选举根节点），本示例在 mesh 传输之上增加了一个 IP 层。

Wi-Fi 驱动（CONFIG_WIFI_ESP32_MESH_IP）提供了一个小型以太网接口，将 Zephyr 网络协议栈桥接到 mesh：发出的数据包通过 mesh 发送 API 发送，收到的 mesh 帧交给协议栈处理。所有 IP 层功能都由 Zephyr 原生子系统实现。

根节点在 mesh 接口上为子节点提供 DHCP 服务（子网 192.168.4.0/24），并通过 NAT 将其流量伪装后从 station 接口发出。子节点通过 mesh 从根节点获取地址（例如 192.168.4.2），并安装一条指向根节点的默认路由。根节点的 station 从路由器获得自己的上行租约后，子节点即可通过根节点的 NAT 访问外部网络。

mesh 传输无法承载子节点用于解析根网关的 ARP 广播，因此根节点会周期性地发送免费 ARP（gratuitous ARP），由 mesh 分发给每个子节点。因此，新加入的子节点可能需要等待最多 CONFIG_NET_ARP_GRATUITOUS_INTERVAL 秒，收到下一个免费 ARP 后其上行链路才能解析网关，外部流量才开始流动。

限制

IP-over-mesh 传输仅支持单播 IPv4。以下是 mesh 传输本身的特性而非缺陷，但它们决定了能在其上运行什么：

  • 不支持组播。mesh 没有组播原语，因此 IPv4 组播以及 IPv6 邻居发现、mDNS 和基于组播的服务发现都无法穿越 mesh。

  • 广播通过向每个已知节点各发送一次单播来模拟（基于路由表，复杂度为 O(N)），仅用于上述免费 ARP 网关变通方案，无法扩展到一般的广播流量。

  • 仅支持 IPv4。寻址、DHCP 和根节点 NAT 都基于 IPv4，没有 IPv6 路径。

  • MTU 较小且不支持分片。mesh 接口的 MTU 小于普通以太网链路，大于 mesh 载荷的帧会被拒绝而不是分片，因此必须遵守路径 MTU。

简而言之，未经修改的单播 IPv4（TCP 和 UDP）可以跨 mesh 工作；任何依赖组播、广播或 IPv6 的功能都不行。

要求

  • 至少两块受支持的 ESP32 开发板（esp32、esp32s2、esp32s3、esp32c3、esp32c5、esp32c6）。ESP32-C2 和 ESP32-H2 不提供 mesh 库。

  • 一台可访问互联网的 2.4 GHz 路由器。根节点关联该路由器，并将子节点的流量中继到外部网络。

内存

配置按根节点的需求确定大小，因为根节点承担的最多：既要为直接子节点提供 Wi-Fi 缓冲池，又要承担子网的 DHCP 服务器、NAT 和路由状态。由于任何节点都可能被选为根节点，所有开发板都烧录同一个镜像。

在 RAM 预算较小、容纳不下的 SoC 上（如 ESP32 和 ESP32-S2），请减小 mesh 扇出和 Wi-Fi 缓冲池（参见 boards/ 下的开发板文件）。这样配置的节点作为叶子节点运行。

设置 CONFIG_NET_DHCPV4_SERVER=n 和 CONFIG_NET_IPV4_NAT=n 会完全去掉根节点中继功能，并释放其所需的内存。这样的节点永远无法为 mesh 子网提供服务，因此只能在确保另一个节点成为根节点的场合构建它；如果它被选为根节点，会报告错误。

构建与运行

west build -b esp32c6_devkitc/esp32c6/hpcore samples/boards/espressif/wifi_mesh_ip
west flash

在运行时于 src/main.c 中通过 esp_wifi_mesh_set_config() 配置 mesh 信道和路由器凭据（参见 esp_wifi_mesh.h）。路由器凭据默认为占位值 myssid/mypassword，必须设置为实际使用的路由器；保留占位值的节点找不到该网络，会一直搜索父节点。将信道设置为路由器所用的信道。将同一镜像烧录到每块开发板。

由于根节点选举由路由器可达性驱动，所有都在路由器范围内的开发板会各自成为根节点；只有超出路由器范围时，节点才会作为子节点加入 mesh。在所有开发板都靠近路由器的台架测试中，请使用 CONFIG_WIFI_ESP32_MESH_FORCE_CHILD=y 构建预定的子节点，使它们接入选出的根节点，而不是各自成为根节点。

示例输出

根节点建立其上行链路和 NAT，子节点通过 mesh 获取地址：

<inf> wifi_mesh_ip: Wi-Fi mesh starting (router SSID "myssid")
<inf> wifi_mesh_ip: parent connected, layer 1 (root)
<inf> wifi_mesh_ip: mesh root IP: gateway 192.168.4.1, DHCP + NAT up
<inf> wifi_mesh_ip: child connected
<inf> wifi_mesh_ip: root external network reachable
<inf> wifi_mesh_ip: child got IP 192.168.4.2 over mesh

子节点获得地址后，在子节点的 shell 中 ping 一台公共主机，确认它能通过根节点的 NAT 访问外部网络：

uart:~$ net ping 1.1.1.1
