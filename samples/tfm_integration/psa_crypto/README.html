TF-M PSA crypto

Browse source code on GitHub

概述

本 TF-M 集成示例演示如何在 Zephyr 中使用 PSA 加密 API 进行加密运算和生成设备证书签名请求。此外，本示例还演示了 PSA Certified Level 1 产品中 RTOS 供应商要求所涵盖的部分 TF-M 功能，例如配置数据的安全存储，以及用于设备验证的初始证明（initial attestation）。

安全处理环境使用 Trusted Firmware（TF-M）平台安全架构（PSA）API，Zephyr 运行在非安全处理环境中。

它使用 IPC 模式 进行通信，即插入一种 IPC 机制来处理安全 TF-M API 的调用和响应。

本示例以单线程或多线程应用程序的形式将测试信息打印到控制台。

关键文件

psa_crypto.c

演示哈希、签名/验证流程：

  • 生成/导入持久密钥：secp256r1（用途：ecdsa-with-SHA256）

  • 根据上述私钥数据显示公钥

  • 计算负载数据的 SHA256 哈希值

  • 使用持久密钥对哈希值签名

  • 使用公钥验证签名

  • 销毁密钥

还演示了设备证书签名请求（CSR）流程：

  • 生成/导入持久密钥：secp256r1（用途：ecdsa-with-SHA256）

  • 在设备 CSR 中设置主题名称

  • 生成 PEM 格式的设备 CSR

  • 将设备 CSR 编码为 JSON

导入还是生成持久密钥取决于配置选项 PSA_IMPORT_KEY。启用 PSA_IMPORT_KEY 时，如果设置了 PRIVATE_KEY_STATIC，则密钥数据为静态数据；如果设置了 PRIVATE_KEY_RANDOM，则使用 psa_generate_random 生成密钥数据。

psa_attestation.c

演示如何从 TF-M 安全处理环境（SPE）请求初始证明令牌（IAT）。

构建与运行

本项目将启动状态和信息输出到控制台。可以在 ARM Cortex M33 目标开发板或 QEMU 上构建并执行。

本示例只能在 Linux 或 macOS 开发系统上构建（不支持 Windows），已在以下环境中测试：

  • macOS Mojave，使用 QEMU 4.2.0 和 gcc-arm-none-eabi-7-2018-q2-update

  • macOS Mojave，使用 gcc-arm-none-eabi-7-2018-q2-update

  • Ubuntu 18.04，使用 Zephyr SDK 0.11.2

TF-M BL2 日志

在 prj.conf 中添加以下内容，即可查看 TF-M BL2 的日志：

CONFIG_TFM_BL2=y
CONFIG_TFM_CMAKE_BUILD_TYPE_DEBUG=y

On MPS2+ AN521:

  1. 使用非安全配置构建 Zephyr（-DBOARD=mps2/an521/cpu0/ns）。

    使用 west

    cd <ZEPHYR_ROOT>
west build -p -b mps2/an521/cpu0/ns samples/tfm_integration/psa_crypto

    使用 cmake 和 ninja

    cd <ZEPHYR_ROOT>/samples/tfm_integration/psa_crypto/
rm -rf build
mkdir build && cd build
cmake -GNinja -DBOARD=mps2/an521/cpu0/ns ..
ninja

    使用 cmake 和 make

    cd <ZEPHYR_ROOT>/samples/tfm_integration/psa_crypto/
rm -rf build
mkdir build && cd build
cmake -DBOARD=mps2/an521/cpu0/ns ..
make

  2. 将应用程序二进制文件（mcuboot.bin 和 tfm_sign.bin）复制到 <MPS2 device name>/SOFTWARE/。

  3. 编辑（例如使用 vim）<MPS2 device name>/MB/HBI0263C/AN521/images.txt 文件，按如下所示进行更新：

    TITLE: Versatile Express Images Configuration File

[IMAGES]
TOTALIMAGES: 2 ;Number of Images (Max: 32)

IMAGE0ADDRESS: 0x10000000
IMAGE0FILE: \SOFTWARE\mcuboot.bin  ; BL2 bootloader

IMAGE1ADDRESS: 0x10080000
IMAGE1FILE: \SOFTWARE\tfm_sign.bin ; TF-M with application binary blob

  4. 保存文件，退出编辑器，然后复位 MPS2+ 开发板。

On QEMU:

使用非安全配置（-DBOARD=mps2/an521/cpu0/ns）构建 Zephyr，并通过 run 命令在 qemu 中运行。

使用 west

cd <ZEPHYR_ROOT>
west build -p -b mps2/an521/cpu0/ns samples/tfm_integration/psa_crypto -t run

使用 cmake 和 ninja

cd <ZEPHYR_ROOT>/samples/tfm_integration/psa_crypto/
rm -rf build
mkdir build && cd build
cmake -GNinja -DBOARD=mps2/an521/cpu0/ns ..
ninja run

使用 cmake 和 make

cd <ZEPHYR_ROOT>/samples/tfm_integration/psa_crypto/
rm -rf build
mkdir build && cd build
cmake -DBOARD=mps2/an521/cpu0/ns ..
make run

On LPCxpresso55S69:

使用非安全配置构建 Zephyr：

$ west build -p -b lpcxpresso55s69_ns samples/tfm_integration/psa_crypto/ --

确保开发板已配置为使用 LPC-Link2 J-Link 板载调试探针，因为这不是开发板出厂时自带的调试接口；

接下来需要按如下方式使用 J-Link 手动烧录生成的镜像（tfm_merged.bin）：

JLinkExe -device lpc55s69 -if swd -speed 2000 -autoconnect 1
J-Link>r
J-Link>erase
J-Link>loadfile build/tfm_merged.bin

复位并擦除开发板会解锁开发板，这在开发板处于未知状态、无法烧录时很有用。

烧录镜像后，需要手动复位开发板才能运行这段代码。

在 nRF5340 和 nRF9160 上：

使用非安全配置构建 Zephyr（-DBOARD=nrf5340dk/nrf5340/cpuapp/ns 或 -DBOARD=nrf9160dk/nrf9160/ns）。

例如，对于 nRF9160，使用 cmake 和 ninja

cd <ZEPHYR_ROOT>/samples/tfm_integration/psa_crypto/
rm -rf build
mkdir build && cd build
cmake -GNinja -DBOARD=nrf9160dk/nrf9160/ns ..

如果构建时启用了 BL2（MCUboot 引导加载程序），请手动烧录 MCUboot 引导加载程序镜像二进制文件（bl2.hex）。

例如，在 nRF9160 上使用 nrfjprog：

nrfjprog -f NRF91 --program tfm/bin/bl2.hex --sectorerase

最后，烧录合并后的 TF-M + Zephyr 二进制文件。

例如，对于 nRF9160

west flash

On BL5340:

使用非安全配置构建 Zephyr（-DBOARD=bl5340_dvk/nrf5340/cpuapp/ns）。

使用 cmake 和 ninja 的示例

cd <ZEPHYR_ROOT>/samples/tfm_integration/psa_crypto/
rm -rf build
mkdir build && cd build
cmake -GNinja -DBOARD=bl5340_dvk/nrf5340/cpuapp/ns ..

烧录合并后的 TF-M + Zephyr 二进制文件。

使用 west 的示例

west flash --hex-file tfm_merged.hex
