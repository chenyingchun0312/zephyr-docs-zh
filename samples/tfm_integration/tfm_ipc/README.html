TF-M IPC

Browse source code on GitHub

概述

这是一个简单的 TF-M 集成示例，可用于受支持的 ARMv8-M 开发板。

它使用 IPC 模式 进行通信，即通过 IPC 机制调用安全镜像中的 TF-M API；与之相对的是 库模式，该模式绕过 IPC 机制，改为直接调用。

Zephyr 使用 Trusted Firmware（TF-M）平台安全架构（PSA）API 在安全配置中运行本示例，Zephyr 本身则运行在非安全配置中。

本示例以单线程或多线程应用程序的形式将测试信息打印到控制台。

本示例会在 5 秒后重启，以演示在 TF-M 下的重启。由于非安全应用程序不允许直接执行重启，sys_reboot 调用会被转发给 TF-M。

构建与运行

本项目将测试状态和信息输出到控制台。可以在 MPS2+ AN521 和 ST Nucleo L552ZE Q 上构建并执行。

On MPS2+ AN521:

  1. 使用非安全配置构建 Zephyr（-DBOARD=mps2/an521/cpu0/ns）。

    cd $ZEPHYR_ROOT/samples/tfm_integration/tfm_ipc/
mkdir build
cd build
cmake -DBOARD=mps2/an521/cpu0/ns ..
make

也可以按如下方式使用 west：

$ west build -p -b mps2/an521/cpu0/ns zephyr/samples/tfm_integration/tfm_ipc

  1. 将应用程序二进制文件（mcuboot.bin 和 tfm_sign.bin）复制到 <MPS2 device name>/SOFTWARE/。

  2. 打开 <MPS2 device name>/MB/HBI0263C/AN521/images.txt，按如下方式编辑 AN521/images.txt 文件：

    TITLE: Versatile Express Images Configuration File

[IMAGES]
TOTALIMAGES: 2 ;Number of Images (Max: 32)

IMAGE0ADDRESS: 0x10000000
IMAGE0FILE: \SOFTWARE\mcuboot.bin  ; BL2 bootloader

IMAGE1ADDRESS: 0x10080000
IMAGE1FILE: \SOFTWARE\tfm_sign.bin ; TF-M with application binary blob

  3. 复位 MPS2+ 开发板。

如果运行 cmake 时出现以下错误：

CMake Error at cmake/Common/FindGNUARM.cmake:121 (message):
arm-none-eabi-gcc can not be found.  Either put arm-none-eabi-gcc on the
PATH or set GNUARM_PATH properly.

可能需要编辑 tfm_ipc 项目文件夹中的 CMakeLists.txt 文件，更新 -DGNUARM_PATH=/opt/toolchain/arm-none-eabi 路径。

On QEMU:

MPS2+ AN521 目标（mps2/an521/cpu0/ns）基于双核 ARM Cortex-M33 配置。如果手头没有受支持的 ARMv8-M 开发板，也可以通过 QEMU 使用该目标运行 TF-M 测试。

在上述常规构建流程中，还会生成一个可通过 qemu-system-arm 运行的二进制文件。可按如下方式执行该二进制文件：

qemu-system-arm -M mps2-an521 -device loader,file=build/zephyr/tfm_merged.hex -serial stdio

也可以在 west 构建过程中运行该二进制文件，方法是在构建命令末尾追加 -t run 参数；如果使用 ninja 或 make，则添加 run 命令：

$ west build -b mps2/an521/cpu0/ns zephyr/samples/tfm_integration/tfm_ipc -t run

或者在构建完成后运行：

$ ninja run

在 ST Nucleo L552ZE Q 或 STM32L562E-DK Discovery 上：

本示例已在 Ubuntu 18.04 上使用 Zephyr SDK 0.11.3 测试。

使用非安全配置构建 Zephyr：

示例：为 Nucleo L552ZE Q 构建非安全配置

$ west build -b nucleo_l552ze_q/stm32l552xx/ns samples/tfm_integration/tfm_ipc/

示例：为 STM32L562E-DK Discovery 构建非安全配置

$ west build -b stm32l562e_dk/stm32l562xx/ns samples/tfm_integration/tfm_ipc/

用于初始化设备的脚本位于 build/tfm 文件夹中：

  • regression.sh：设置平台选项字节配置并擦除平台。

按以下顺序运行这些脚本以烧录开发板：

$ ./build/tfm/api_ns/regression.sh
$ west flash

备注

注意，PATH 变量中必须能找到 arm-none-eabi-gcc，并且运行 regression.sh 需要 STM32_Programmer_CLI（参见 https://www.st.com/en/development-tools/stm32cubeprog.html）。如果运行这些脚本时仍有问题，请查看 Nucleo L552ZE Q 或 STM32L562E-DK Discovery 文档中的“编程与调试”一节。

On LPCxpresso55S69:

使用非安全配置构建 Zephyr：

$ west build -p -b lpcxpresso55s69_ns samples/tfm_integration/tfm_ipc/ --

确保开发板已配置为使用 LPC-Link2 J-Link 板载调试探针，因为这不是开发板出厂时自带的调试接口；

接下来需要按如下方式使用 J-Link 手动烧录生成的镜像（tfm_merged.bin）：

JLinkExe -device lpc55s69 -if swd -speed 2000 -autoconnect 1
J-Link>r
J-Link>erase
J-Link>loadfile build/zephyr/tfm_merged.bin

复位并擦除开发板会解锁开发板，这在开发板处于未知状态、无法烧录时很有用。

烧录镜像后，需要手动复位开发板才能运行这段代码。

在 nRF5340 和 nRF9160 上：

使用非安全配置构建 Zephyr（-DBOARD=nrf5340dk/nrf5340/cpuapp/ns 或 -DBOARD=nrf9160dk/nrf9160/ns）。

例如，对于 nRF9160，使用 cmake 和 ninja

cd <ZEPHYR_ROOT>/samples/tfm_integration/tfm_ipc/
rm -rf build
mkdir build && cd build
cmake -GNinja -DBOARD=nrf9160dk/nrf9160/ns ..

如果构建时启用了 BL2（MCUboot 引导加载程序），请手动烧录 MCUboot 引导加载程序镜像二进制文件（bl2.hex）。

例如，在 nRF9160 上使用 nrfjprog：

nrfjprog -f NRF91 --program tfm/bin/bl2.hex --sectorerase

最后，烧录合并后的 TF-M + Zephyr 二进制文件。

例如，对于 nRF9160

west flash

On BL5340:

使用非安全配置构建 Zephyr（-DBOARD=bl5340_dvk/nrf5340/cpuapp/ns）。

使用 cmake 和 ninja 的示例

cd <ZEPHYR_ROOT>/samples/tfm_integration/tfm_ipc/
rm -rf build
mkdir build && cd build
cmake -GNinja -DBOARD=bl5340_dvk/nrf5340/cpuapp/ns ..

烧录合并后的 TF-M + Zephyr 二进制文件。

使用 west 的示例

west flash --hex-file zephyr/tfm_merged.hex

On FRDM-MCXN947:

使用非安全配置构建 Zephyr：

$ west build -p -b frdm_mcxn947/mcxn947/cpu0/ns samples/tfm_integration/tfm_ipc/

确保开发板已配置为使用 LPC-Link2 J-Link 板载调试探针，因为出厂开发板默认提供的调试接口并不是它；

构建完成后，使用 J-Link 调试探针将生成的镜像（tfm_merged.bin）手动烧录到目标，如下所示：

JLinkExe -device MCXN947_M33_0 -if swd -speed 4000 -autoconnect 1
J-Link>r
J-Link>erase
J-Link>loadfile build/zephyr/tfm_merged.bin

先复位再完全擦除设备，可以确保设备解锁并恢复到已知状态。如果开发板处于未知状态或受保护状态而无法烧录，这一步尤其有用。

镜像烧录成功后，手动复位开发板，开始执行新烧录的固件。
