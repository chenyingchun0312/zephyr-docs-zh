Linkable loadable extensions shell module

Browse source code on GitHub

概述

本示例提供对 可链接可加载扩展（LLEXT） 系统的 shell 访问，可以在 shell 中管理可加载的代码扩展。

要求

一块具有受支持的 LLEXT 架构和支持 shell 的控制台的开发板。下面的例子以 ARMv7 目标进行说明；在任何支持 LLEXT 的架构上流程都相同，只是工具链前缀和生成的十六进制载荷不同。

构建

以下命令构建主 shell 应用程序：

west build -b robokit1 samples/subsys/llext/shell_loader

备注

可能需要禁用内存保护才能使示例正常工作（例如 ARM 上的 CONFIG_ARM_MPU=n，Xtensa 上的 CONFIG_XTENSA_MMU=n / CONFIG_XTENSA_MPU=n，RISC-V 上的 CONFIG_RISCV_PMP=n）。类似标志的完整列表请参阅 tests/subsys/llext/no_mem_protection.conf。

本示例还包含一个非常基础的扩展的源代码 samples/subsys/llext/shell_loader/hello_world.c，可用于测试 LLEXT 功能。

可以像下面这样使用 Zephyr 构建系统将其编译为 build/hello_world.llext：

$ ninja -C build -vvv hello_world_ext

在安装了 Zephyr SDK 且 PATH 中有对应工具链的主机上，也可以直接生成同样的目标文件。请选择与目标匹配的工具链前缀，例如 ARM 使用 arm-zephyr-eabi-，Xtensa 使用 xtensa-<soc>_zephyr-elf-，RISC-V 使用 riscv64-zephyr-elf-：

$ <toolchain-prefix>gcc -mlong-calls -c -o build/hello_world.llext samples/subsys/llext/shell_loader/hello_world.c

备注

扩展必须针对每种目标架构重新构建：为 ARM 编译的扩展无法在 Xtensa 或 RISC-V 上加载，反之亦然。加载器会接受该十六进制字符串，但调用扩展时 CPU 会触发陷阱，因为指令流对它来说是陌生的。

备注

默认情况下，LLEXT 只导入扩展通过 EXPORT_SYMBOL 宏显式导出的符号。使用该宏进行编译需要完整的 Zephyr 构建系统，或者至少需要 LLEXT EDK。

为了避免这种复杂性，本示例通过 Kconfig 选项 CONFIG_LLEXT_IMPORT_ALL_GLOBALS 将 Zephyr 配置为使用扩展 ELF 文件中定义的所有全局符号。对于大型扩展不建议这样做，因为内存占用会明显增加。

可以使用常用的 binutils 工具检查编译后的扩展，查看符号、节（section）和重定位信息。然后借助其他工具，将其转换为可供 llext load_hex shell 命令使用的十六进制字符串。下面的示例输出由 ARM 工具链生成；在其他架构上，重定位类型和指令列表会有所不同，但步骤完全相同：

运行

开发板启动后，会出现 shell 提示符。所有与 LLEXT 系统相关的命令都是 llext 的子命令，可以通过 llext help 查看：

uart:~$ llext help
llext - Loadable extension commands
Subcommands:
  list          :List loaded extensions and their size in memory
  load_hex      :Load an elf file encoded in hex directly from the shell input.
                 Syntax:
                 <ext_name> <ext_hex_string>
  unload        :Unload an extension by name. Syntax:
                 <ext_name>
  list_symbols  :List extension symbols. Syntax:
                 <ext_name>
  call_fn       :Call extension function with prototype void fn(void). Syntax:
                 <ext_name> <function_name>

uart:~$ llext call_fn hello_world hello_world
hello world

加载多个扩展

每次调用 load_hex 都会分配独立的 ELF 缓冲区，并以扩展名称跟踪该缓冲区。对该名称调用 unload 时缓冲区会被释放，因此可以同时加载多个扩展并分别调用：

uart:~$ llext load_hex hello_world <hex>
uart:~$ llext load_hex worker <hex>
uart:~$ llext list
| Name             | Size         |
|      hello_world |          ... |
|           worker |          ... |
uart:~$ llext call_fn hello_world hello_world
uart:~$ llext call_fn worker run
uart:~$ llext unload worker

可同时加载的扩展数量受 subsys/llext/shell.c 中 LLEXT_SHELL_MAX_LOADED 槽位数量的限制（默认为 4 个）。如需同时加载更多扩展，请在该处调整。
