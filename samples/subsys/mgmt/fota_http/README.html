Firmware Over-the-Air over HTTP

Browse source code on GitHub

概述

本示例展示如何使用 基于 HTTP 的固件空中升级 库从任意普通 HTTP 服务器更新设备。设备通过 HTTP GET 请求获取已签名的镜像，将其以流方式写入 MCUboot 当前未运行的那个槽位，然后请求引导加载程序启动该镜像。不需要更新服务器或设备管理协议，一个由 Web 服务器提供的目录就足够了。

本示例启用了 fota shell 命令，因此整个流程都可以在控制台中操作。

要求

  • 一块具有网络接口、并采用包含两个应用程序槽位的 MCUboot 分区布局的开发板。

  • 一台开发板可以访问的 HTTP 服务器。

本示例使用 sysbuild 构建，以便 MCUboot 与应用程序一起构建和烧录。引导加载程序配置为 swap-using-offset 模式，以便可以测试回滚路径；overwrite-only 模式不支持回滚。

警告

镜像使用 MCUboot 仓库中附带的 MCUboot 开发密钥签名，任何人都可以用它签名镜像。在实际设备上使用之前，请在 MCUboot 配置中将 CONFIG_MCUBOOT_SIGNATURE_KEY_FILE 设置为你自己的密钥。

构建与运行

使用 sysbuild 构建并烧录本示例。为镜像指定一个版本号，以便在控制台上区分两次构建：

west build -b esp32c5_devkitc/esp32c5/hpcore --sysbuild samples/subsys/mgmt/fota_http -- -DCONFIG_MCUBOOT_IMGTOOL_SIGN_VERSION=\"1.0.0\"
west flash

构建另一个版本号不同的镜像。开发板将下载这个镜像，因此请保留其构建目录：

west build -b esp32c5_devkitc/esp32c5/hpcore --sysbuild -d build/build-v2 samples/subsys/mgmt/fota_http -- -DCONFIG_MCUBOOT_IMGTOOL_SIGN_VERSION=\"2.0.0\"

在主机上提供已签名镜像的下载服务。任何 HTTP 服务器都可以，例如：

cd build-v2/fota_http/zephyr && python3 -m http.server 8000 --bind 0.0.0.0

MCUboot 只接受 zephyr.signed.bin，不接受 zephyr.bin。

对于带 Wi-Fi 的开发板，请先连接网络：

uart:~$ wifi connect -s <ssid> -p <passphrase> -k <key_mgmt>

带以太网的开发板在启动时通过 DHCP 获取地址。

下载镜像，请求交换并重启：

uart:~$ fota download http://<host-ip>:8000/zephyr.signed.bin
uart:~$ fota apply
uart:~$ kernel reboot cold

重启后，控制台显示版本 2.0.0 的镜像作为测试镜像运行。如果不进行确认，下次重启时 MCUboot 会回滚到版本 1.0.0。要保留该镜像，请进行确认：

uart:~$ fota status
uart:~$ fota confirm

fota apply permanent 变体会跳过测试启动，并立即确认镜像。

自动下载

设置 CONFIG_SAMPLE_FOTA_HTTP_AUTO_URL 后，示例会自行开始下载，而不是等待 shell 命令。它注册了连接管理器的 L4 已连接事件，因此接口一获得地址就开始下载，然后调用 fota_http_download_async()，并打印库线程报告的进度：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/fota_http -- -DCONFIG_SAMPLE_FOTA_HTTP_AUTO_URL=\"http://<host-ip>:8000/zephyr.signed.bin\"

对于带 Wi-Fi 的开发板，wifi connect 成功后才开始下载。镜像只会被存储，仍需执行 fota apply 才能启动它。如果正在运行的镜像仍是测试镜像，则跳过下载，因为此时次槽位中保存的是 MCUboot 回滚所用的镜像；如果次槽位中已经包含正在运行的版本，也会跳过下载。使用 resume.conf 片段构建时，因复位而中断的传输会在下次启动后从上次保存的偏移量继续。

恢复下载

使用 resume.conf Kconfig 片段构建，可将下载偏移量保存在 settings 中。断电或网络出错后，带上 resume 关键字再次执行下载，传输会通过 HTTP Range 请求继续：

uart:~$ fota download http://<host-ip>:8000/zephyr.signed.bin resume

不支持 Range 请求的服务器会返回完整文件，下载将从零开始。

TLS

使用 tls.conf Kconfig 片段构建可以接受 https URL。示例将 src/ca_cert.pem 中的 PEM 证书注册为受信任的 CA；构建时会将其转换为 C 数组，并由 src/main.c 包含。这是一个针对 localhost 和 127.0.0.1 的自签名证书，仅用于测试该代码路径。在提供真实镜像之前，请将其替换为你的服务器证书，或为该证书签名的 CA 证书。

要在测试台上尝试，请为主机地址生成一个自签名证书，并用 server.pem 覆盖 src/ca_cert.pem：

openssl req -x509 -newkey rsa:2048 -nodes -keyout server.key \
  -out server.pem -days 365 -subj "/CN=<host-ip>" \
  -addext "subjectAltName=IP:<host-ip>"

然后在主机上通过 https 提供构建目录：

import http.server, ssl
httpd = http.server.HTTPServer(("0.0.0.0", 8443),
                               http.server.SimpleHTTPRequestHandler)
ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
ctx.load_cert_chain("server.pem", "server.key")
httpd.socket = ctx.wrap_socket(httpd.socket, server_side=True)
httpd.serve_forever()

证书也可以在运行时配置，而不必构建进镜像中。覆盖配置为此启用了 TLS 凭据 shell：

uart:~$ cred add 1 CA DEFAULT strt <PEM certificate>

只有启用 CONFIG_MBEDTLS_HAVE_TIME_DATE 时才会检查证书的有效日期，这要求设备在第一次下载之前具有正确的实时时钟。
