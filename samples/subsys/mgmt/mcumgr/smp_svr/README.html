SMP server

Browse source code on GitHub

概述

本示例应用程序实现了一个简单管理协议（Simple Management Protocol，SMP）服务器。SMP 是与 MCUmgr 管理协议配合使用的一种基本传输编码。有关 MCUmgr 和 SMP 的更多信息，请参阅 设备管理。

本示例应用程序默认支持以下 MCUmgr 传输方式：

  • Shell

  • 蓝牙

  • UDP

smp_svr 启用了对以下命令组的支持：

  • fs_mgmt

  • img_mgmt

  • os_mgmt

  • stat_mgmt

  • shell_mgmt

注意事项

  • img_mgmt 需要 MCUboot 引导加载程序才能正常工作。有关设备固件升级子系统和 MCUboot 的更多信息，请参阅 MCUboot。

前提条件

使用工具

要远程与设备上的管理子系统交互，需要使用相应的工具。可用作 Zephyr MCUmgr SMP 服务器客户端的各种工具列在管理子系统文档的 工具/库 页面中。

构建 BLE 控制器

备注

本节仅适用于 Linux 用户

如果想尝试使用低功耗蓝牙（BLE）进行空中设备固件升级（DFU），但没有内置或可插拔的 BLE 无线模块，可以按照 将控制器与 BlueZ 配合使用 中的说明自行构建一个并使用。

构建示例应用程序

以下步骤介绍如何在 Zephyr 中构建并运行包含 MCUboot 的 smp_svr 示例。smp_svr 示例有多种变体。

构建 Bluetooth 示例：

west build -b nrf52dk/nrf52832 --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="bt.conf"

构建支持文件系统和 shell 管理的串口示例：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="serial.conf;fs.conf;shell-mgmt.conf"

备注

原始 UART 支持通过 UART 设备直接发送原始 MCUmgr 数据包，而不使用基于控制台的 SMP 协议。这些是二进制数据，因此如果同一 UART 上启用了 shell 等功能，就不能使用该方式。

构建支持文件系统管理的原始 UART（串口）示例：

west build -b nrf52840dk/nrf52840 --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="raw-serial.conf;fs.conf"

构建使用 USB CDC_ACM 后端的串口示例：

west build -b nrf52840dk/nrf52840 --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="cdc.conf" -DEXTRA_DTC_OVERLAY_FILE="usb.overlay"

备注

如果使用 CDC 覆盖文件构建示例并打算进行测试，请确保连接到开发板上直接连到 MCU 的那个 USB 端口。

构建 shell 示例：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="shell.conf"

SMP 的 UDP 传输同时支持 IPv4 和 IPv6。本示例同时启用了 IPv4 和 IPv6，但二者可以分别启用和禁用。

构建 UDP 示例：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="udp.conf"

构建使用 802154 Sub-GHz 网络的 UDP 示例：

west build -b beagleconnect_freedom --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="overlay-udp.conf;802154-subg.conf"

构建使用 DTLS 的 UDP 示例：

west build -b bl5340_dvk/nrf5340/cpuapp --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="udp-dtls.conf"

烧录示例镜像

原始应用程序将为 slot-0 构建，Flash 分区的详细信息请参阅 Flash 映射（Flash map）。烧录 MCUboot 和示例应用程序：

west flash

示例镜像：hello world!

smp_svr 应用程序已经可以运行。只需复位开发板，然后使用所选工具的 echo 功能测试该应用程序：该功能会向远端目标设备发送一个字符串，并让其将字符串回显回来。

J-Link 虚拟 MSD 交互说明

在带有同时支持 CDC 和 MSC（虚拟大容量存储设备，也称为拖放）功能的 J-Link OB 的开发板上（例如 Nordic nrf52840dk），由于 J-Link 固件中 USB 端点的配置方式限制了最大数据包大小，MSD 功能可能导致通过 CDC UART 端口发送的 mcumgr 命令无法工作（最可能发生在使用镜像管理命令更新固件时）。可以通过在 J-Link 设备上禁用 MSD 功能解决此问题，禁用方法请参阅 禁用大容量存储设备功能 中的说明。

设备固件升级（DFU）

SMP 服务器已经在开发板上运行，并且可以使用客户端与之通信，现在可以测试通常所说的“OTA DFU”，即空中设备固件升级（Over-The-Air Device Firmware Upgrade）。该功能适用于 BT 和 UDP 两种方式。

DFU 过程的一般步骤如下：

  • 使用 sysbuild 构建启用 MCUboot 的应用程序，请参阅 构建示例应用程序

  • 使用 MCUmgr 客户端上传已签名的镜像

  • 使用 MCUmgr 客户端列出设备上的镜像

  • 使用 MCUmgr 客户端将上传的镜像标记为待测试

  • 使用 MCUmgr 客户端远程复位设备

  • 使用 MCUmgr 客户端确认上传的镜像（可选）

直接上传镜像以及镜像到 MCUboot 槽位的映射

目前 MCUmgr 的直接上传支持 4 个目标镜像，其中前两个分别映射到 MCUboot 的主槽位（slot-0）和次槽位（slot-1）。

为清楚起见，下表列出 DTS 标签、槽位与 <image> 之间的对应关系：

槽位

-n <image>

"image-0"

slot-0

1

"image-1"

slot-1

0, 1

"image-2"

2

"image-3"

3

备注

slot info 命令可用于查看所有槽位的信息，并获取更新该槽位时使用的上传 image ID，详情请参阅 槽位信息。

上传已签名的镜像

要上传已签名的镜像，请参阅所选工具的文档，选择要上传的新固件文件并开始上传。

备注

上传过程开始时，目标设备可能会先擦除镜像槽位，在某些目标上这需要几十秒。

列出镜像

现在可以使用所选工具获取远端目标设备上现有镜像（slot-0 和 slot-1）的列表，该工具应会打印每个现有镜像的状态和哈希值。

测试镜像

为了让 MCUboot 交换镜像，需要先测试该镜像，确保它能够启动，具体请参阅所选工具中的说明。重启时，MCUboot 会交换到新镜像。

备注

有些工具可以在无需上传镜像的情况下列出镜像的哈希值。也可以对已签名的更新文件使用 imgtool 的 dumpinfo 命令列出镜像哈希值，不过输出为 C 十六进制数组格式，例如：

远程复位

可以远程复位设备，以观察（借助控制台输出）MCUboot 如何交换镜像，具体请查阅所选工具的文档。复位时，MCUboot 会交换 slot-0 和 slot-1。

确认新镜像

新镜像现在已加载到 slot-0 中，但除非确认该镜像，否则下次复位时它会被交换回 slot-1。请使用所选工具确认该镜像。

备注

如果尝试发送与 slot-0 中已烧录镜像完全相同的镜像，由于两个槽位的哈希值相同，该过程将无法成功完成。

从文件系统下载文件/向文件系统上传文件

SMP 服务器支持从设备上的 文件系统 下载文件或向其上传文件，这在文件存储于非易失性存储器中时很有用，例如使用 FS 日志后端时。使用 sysbuild 构建并烧录 smp_svr，然后使用所选工具从文件系统下载文件。必须知道并使用文件在设备上的完整路径。
