USB Mass Storage

Browse source code on GitHub

概述

本示例应用程序演示如何使用 Zephyr 项目的 USB 大容量存储驱动。这个非常简单的驱动会将带有 RAM 或 FLASH 的开发板枚举为 USB 磁盘。

要求

本项目需要 USB 设备驱动，以及 96KiB RAM 或一个 Flash 设备。

构建与运行

本示例可以为多种开发板构建，并通过 Zephyr 项目源码树中 samples/subsys/usb/mass/boards 下的覆盖文件进行定制。可以通过 -D 命令行开关传入 Kconfig 配置，在基于 RAM 和基于 FLASH 的磁盘及文件系统之间进行选择。

不带文件系统的 RAM 磁盘示例

默认配置选择不带任何文件系统的基于 RAM 的磁盘。该示例只需为 RAM 磁盘额外提供 96KiB RAM，用于测试 USB 大容量存储类的实现。

west build -b reel_board samples/subsys/usb/mass -- -DEXTRA_DTC_OVERLAY_FILE="ramdisk.overlay"

FAT FS 示例

如果可用 RAM 超过 96KiB，可以在 RAM 磁盘上使用 FAT 文件系统。

west build -b reel_board samples/subsys/usb/mass -- -DEXTRA_DTC_OVERLAY_FILE="ramdisk.overlay" -DCONFIG_APP_MSC_STORAGE_RAM=y

另外，当存储分区足够大时，也可以在 SoC 内部 Flash 上使用 FAT 文件系统。

west build -b frdm_k64f samples/subsys/usb/mass -- -DEXTRA_DTC_OVERLAY_FILE="flashdisk.overlay" -DCONFIG_APP_MSC_STORAGE_FLASH_FATFS=y -DCONFIG_DISK_DRIVER_SDMMC=n

SoC 上的内部 Flash 存储分区对 FAT 文件系统来说可能太小。不过，如果开发板带有外部 Flash 设备，就可以将其用于 FAT 文件系统。本示例包含几个用于配置外部 Flash 设备的开发板覆盖文件。例如，有一个针对 Adafruit Feather nRF52840 Express 的覆盖文件，可以使用一块外部 16 MiBy QSPI Flash 芯片，并在其上建立 2 MiBy 的 FAT 分区。

west build -b adafruit_feather_nrf52840_sense samples/subsys/usb/mass -- -DCONFIG_APP_MSC_STORAGE_FLASH_FATFS=y

构建示例应用程序镜像并将其烧录到开发板后，将开发板插入主机设备，例如运行 Linux 的 PC。开发板会被检测到，Linux journalctl 命令的输出如下：

SD 卡示例

本示例需要 SD 卡支持（参见 磁盘访问），以及一张格式化为 FAT 文件系统的 SD 卡。

如果有带 SD 卡控制器的开发板，可以按如下方式构建本示例：

west build -b mimxrt1050_evk samples/subsys/usb/mass -- -DCONFIG_APP_MSC_STORAGE_SDCARD=y

如果开发板不支持 SD 卡控制器，但可以（例如通过扩展板）将 SD 卡连接到 SPI，可以按如下方式构建本示例：

west build -b nrf52840dk/nrf52840 --shield waveshare_epaper_gdeh0154a07 samples/subsys/usb/mass -- -DCONFIG_APP_MSC_STORAGE_SDCARD=y

根据存储介质的大小，文件系统可能需要一段时间才能完成卡的初始化，并通过 USB 提供访问。还需要注意，通过 SPI 的传输速度非常慢。

LittleFS 示例

本示例可以为任何定义了存储分区的开发板构建。

west build -b reel_board samples/subsys/usb/mass -- -DEXTRA_DTC_OVERLAY_FILE="flashdisk.overlay" -DCONFIG_APP_MSC_STORAGE_FLASH_LITTLEFS=y

如果需要更多存储空间，可以将开发板配置为使用外部 Flash 设备，做法与 FAT 文件系统示例相同。在本例中，nRF52840DK 开发板被配置为使用一块外部 64 MiB QSPI Flash 芯片，并在其上建立一个 128 KiBy 的 littlefs 分区，该分区与 LittleFS filesystem 示例生成的分区兼容。

west build -b nrf52840dk/nrf52840 samples/subsys/usb/mass -- -DCONFIG_APP_MSC_STORAGE_FLASH_LITTLEFS=y

构建示例应用程序镜像并将其烧录到开发板后，将开发板的两个 USB 连接器（调试口和 nRF USB）连接到一台运行支持 littlefs-FUSE 的操作系统的主机。控制台输出类似如下（文件系统内容会有所不同）：

[00:00:00.009,063] <inf> littlefs: FS at MX25R64:0x0 is 16 0x1000-byte blocks with 512 cye
[00:00:00.009,063] <inf> littlefs: sizes: rd 16 ; pr 16 ; ca 64 ; la 32

有关在 Linux 或 FreeBSD 系统上挂载 littlefs 文件系统的信息，请参阅下文的“littlefs 用法”一节。

littlefs 用法

许多系统都能自动挂载基于 FAT 的文件系统，而在 Linux 或 FreeBSD 系统上挂载 littlefs 文件系统，则可以借助 littlefs-FUSE 工具完成。

首先从系统日志中确定本地设备名称，例如：

Apr 25 08:10:25 tirzah kernel: [570310.921039] scsi 17:0:0:0: Direct-Access     ZEPHYR   ZEPHYR USB DISK  0.01 PQ: 0 ANSI: 0 CCS
Apr 25 08:10:25 tirzah kernel: [570310.921550] sd 17:0:0:0: Attached scsi generic sg4 type 0
Apr 25 08:10:25 tirzah kernel: [570310.922277] sd 17:0:0:0: [sdd] 256 512-byte logical blocks: (131 kB/128 KiB)
Apr 25 08:10:25 tirzah kernel: [570310.922696] sd 17:0:0:0: [sdd] Write Protect is off

这表明与该 USB 驱动器关联的块设备为 /dev/sdd：

tirzah[447]$ ll /dev/sdd
brw-rw---- 1 root disk 8, 48 Apr 25 08:10 /dev/sdd

可以使用以下命令将其作为文件系统挂载：

sudo chmod a+rw /dev/sdd   # required to allow user access
mkdir /tmp/lfs
lfs \
       --read_size=16 \
       --prog_size=16 \
       --block_size=4096 \
       --block_count=32 \
       --cache_size=64 \
       --lookahead_size=32 \
       /dev/sdd /tmp/lfs

会产生类似如下的输出（磁盘内容会有所不同）：

tirzah[467]$ ls -l /tmp/lfs
total 0
-rwxrwxrwx 0 root root   8 Dec 31  1969 hi
-rwxrwxrwx 0 root root 128 Dec 31  1969 linux
-rwxrwxrwx 0 root root   5 Dec 31  1969 newfile

lfs 是一个挂载命令，在拔出 USB 驱动器之前请务必先卸载该设备：

umount /tmp/lfs

littlefs 参数选择

请注意，上例中传给 lfs 的参数 必须 与初始化文件系统时使用的相应参数完全一致。所需的参数可以从 Zephyr 的挂载日志消息中看到：

[00:00:00.009,002] <inf> littlefs: LittleFS version 2.2, disk version 2.0
[00:00:00.009,063] <inf> littlefs: FS at MX25R64:0x0 is 16 0x1000-byte blocks with 512 cye
[00:00:00.009,063] <inf> littlefs: sizes: rd 16 ; pr 16 ; ca 64 ; la 32

  • --read_size 对应 rd 大小，值为 16；

  • --prog_size 对应 pr 大小，值为 16；

  • --block_size 来自 0x1000-byte blocks，值为 4096（0x1000）；

  • --block_count 来自 16 0x1000-byte blocks，值为 16；

  • --cache_size 来自 ca 大小，值为 64；

  • --lookahead_size 来自 la 大小，值为 32

如果 Zephyr 与 Linux 两侧指定的任何参数不一致，文件系统将无法正确挂载。
