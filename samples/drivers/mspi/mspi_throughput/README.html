MSPI throughput performance test

Browse source code on GitHub

概述

本示例通过测量不同缓冲区大小和数据包配置下的传输速率来演示 MSPI 吞吐量性能测试。示例执行一系列测试，以确定实现最大吞吐量和效率的最佳 MSPI 传输参数。

示例测试内容：* 多种缓冲区大小：4、16、64、256、1024、1500 和 2304 字节 * 多种数据包数量：每次传输 1、4 和 16 个数据包 * 总传输大小：每个测试用例 32 KB * 性能指标：吞吐量（MB/s）、效率（%）、CPU 负载（%）和延迟。

注意：延迟是根据效率损失计算出的估计值，不会打印在汇总表中，而是打印在每个测试用例的详细结果中。

本示例同时支持 DMA 和 CPU 驱动的轮询模式。启用 CONFIG_CPU_LOAD 时，会使用 CPU 负载 子系统报告 CPU 负载（百分比）（支持 Cortex-M、RISC-V 和 Cortex-A；仅限单核）。

目标与后续工作

当前示例测量的是 控制器端 的吞吐量和效率，便于了解驱动在不同数据包大小和数量下的表现，并比较 DMA 与 FIFO 以及 CPU 利用率。无论另一端是什么（Flash、从设备或主机），这都有助于评估任何 MSPI 控制器的特性。

将来，示例可能会扩展为让两个 SoC 同时运行它（一个处于控制器模式，一个处于外设模式），并使用一个简单的协议来测量完整链路的吞吐量。这项工作依赖于明确定义的协议和 MSPI 外设支持。

配置

本示例的配置如下：

MSPI 设备参数（时钟频率、I/O 模式、数据速率、字节序、命令/地址长度等）通过 MSPI_DEVICE_CONFIG_DT() 从目标设备节点的设备树中获取。具体取值请参阅开发板覆盖文件。

每个测试用例的总传输大小由 Kconfig 选项 CONFIG_SAMPLE_MSPI_THROUGHPUT_TOTAL_TRANSFER_SIZE 设置（默认：32 KB）。

硬件设置

本示例需要一个开发板覆盖文件，将别名 dev0 定义为指向 MSPI 目标设备节点（例如控制器下 reg = <0> 的虚拟设备或外设）。示例将 dev0 所在的总线作为控制器，并使用 MSPI_DEVICE_ID_DT(DT_ALIAS(dev0)) 作为设备索引和片选。

构建与运行

west build -b nrf7120dk_nrf7120_cpuapp samples/drivers/mspi/mspi_throughput
west build -t Test
west build -t MSPI
west build -t throughput

输出包括：* BufSize：每次传输使用的缓冲区大小（字节） * PktCnt：每次传输的数据包数 * Time：总传输时间，单位为微秒（CPU 周期） * Throughput：测得的吞吐量，单位为 MB/s * Efficiency：达到理想吞吐量的百分比 * CPU Load：CPU 利用率百分比（启用 CONFIG_CPU_LOAD 时）

汇总报告会指出达到最高吞吐量的配置。

性能分析

示例计算以下几项性能指标：

  • 吞吐量：实际数据传输速率，单位为 MB/s，由传输的总字节数（包括命令和地址开销）除以传输时间得出。

  • 效率：达到理想吞吐量的百分比。对于四线（quad）模式，理想吞吐量按 (clock_frequency * 4) / 8 计算，即 4 条数据线、每字节 8 位。

  • CPU 负载：启用 CONFIG_CPU_LOAD 时，示例使用 CPU 负载子系统测量传输期间的利用率（在支持的平台上与架构无关）。

  • 估计延迟：根据效率损失计算出的每个缓冲区的开销，有助于确定最佳缓冲区大小。

本示例有助于确定：* 获得最大吞吐量的最佳缓冲区大小 * 数据包批量处理对性能的影响 * 不同传输配置的 CPU 开销
