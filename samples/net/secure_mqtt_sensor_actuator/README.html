Secure MQTT Sensor/Actuator

Browse source code on GitHub

概述

此示例演示一个物联网传感器/执行器设备的实现。该应用程序使用 MQTT 协议将传感器数据安全地发送到远程 MQTT 代理，同时响应通过 MQTT 收到的命令。

功能：

  • 通过 DHCPv4 租约建立网络连接

  • 与 MQTT 代理建立安全的 MQTT 连接（使用 TLS 1.2）

  • 按用户定义的间隔，以 JSON 格式将温度传感器数据发布到 MQTT 代理

  • 订阅 MQTT 代理上用户定义的主题

  • 响应通过网络收到的命令（LED 控制）

  • 处理 MQTT 连接、重连和保活（keep-alive）

  • 网络状态 LED

要求

  • 具备网络功能的开发板（已在 adi_eval_adin1110ebz 上测试）

  • Eclipse Mosquitto MQTT 代理

  • DHCP 服务器

  • 开发板与 Mosquitto 代理之间的网络连接

构建与运行

此应用程序依赖开发板与 MQTT 代理之间的网络连接。该代理可以位于本地（例如主机 PC 上），也可以使用公开可用的 MQTT 代理 <https://test.mosquitto.org/>。为了快速试用/测试，提供了一个使用静态 IP 地址、无安全保护地连接到本地 MQTT 代理的配置。

硬件设置

如果使用以太网，请将开发板连接到 MQTT 代理。这可以是主机 PC（对于本地托管的 Mosquitto 代理），也可以是互联网路由器（用于连接公共 Mosquitto 代理）。如有需要，将温度传感器连接到开发板。

软件设置

温度传感器应在设备树中设置别名 ambient-temp0。如果开发板没有板载温度传感器，可以外接一个，并使用开发板覆盖文件添加该传感器和别名：

/ {
        aliases {
                        ambient-temp0 = &adt7420;
                };
        };
};

也可以使用其他类型的传感器，只需将其添加到设备树中，并修改 SENSOR_CHAN in device.c 以匹配所需的传感器类型。

有以下几种方式配置该应用程序：

prj.conf

默认配置：安全 MQTT，动态 IP 地址（DHCP）

overlay-static.conf

安全 MQTT，静态 IP 地址

overlay-static-insecure.conf

非安全 MQTT，静态 IP 地址

Default Config:

使用默认配置时，应用程序会通过 DHCP 获取 IP 地址，并尝试使用 TLS 1.2 安全地连接到 MQTT 代理。

  • 开发板要连接的 MQTT 代理由 CONFIG_NET_SAMPLE_MQTT_BROKER_HOSTNAME 指定。默认设置为 test.mosquitto.org。

  • 使用 TLS 安全连接时，需要在应用程序中包含代理的 CA 证书。

  • 从 https://test.mosquitto.org 下载 DER 或 PEM 格式的 CA 证书

  • 在 tls_config/cert.h 中，将 ca_certificate[] 设置为证书的内容。

  • 将开发板连接到互联网路由器后，它应该会通过 DHCP 自动获得一个 IPv4 地址。

  • 随后，应用程序会尝试连接到公共 Mosquitto 代理并开始发布数据。

  • 也可以安全地连接到本地托管的 MQTT 代理。这需要预置证书。CA 证书应按上文所述包含在构建中。应配置 CONFIG_NET_SAMPLE_MQTT_BROKER_HOSTNAME 以匹配本地代理的主机名/IP 地址。根据所使用的 CA 证书，可能还需要启用额外的 MbedTLS 配置选项。这可以通过 Kconfig 或自定义的 MbedTLS 配置文件完成（参见 modules/mbedtls/Kconfig）。有关在本地为 Mosquitto 设置 TLS 支持的更多信息，请参阅 https://mosquitto.org/man/mosquitto-tls-7.html 。

  • 可以在主机 PC 上安装 DHCP 服务器来为开发板分配 IP，例如 dnsmasq（Linux）或 DHCP Server for Windows（Windows）。

  • 使用默认配置构建示例：

west build -b adi_eval_adin1110ebz samples/net/secure_mqtt_sensor_actuator

Static IP Config:

使用 Kconfig 覆盖文件 overlay-static.conf 禁用 DHCP 并使用静态 IP 地址配置。设备、网关和 DNS 服务器的 IP 地址应根据本地网络配置进行设置。

west build -b adi_eval_adin1110ebz samples/net/secure_mqtt_sensor_actuator -- -DCONF_FILE="prj.conf overlay-static.conf"

Static IP/Unsecure MQTT Config:

使用 Kconfig 覆盖文件 overlay-static-insecure.conf 禁用 TLS 和 DHCP。此配置需要连接到本地托管的 Mosquitto MQTT 代理。

  • 在 overlay-static-insecure.conf 中设置开发板和 Mosquitto 代理的 IP 地址（即主机 PC 上以太网端口的 IP 地址）。这两个地址应位于同一子网，例如 192.0.2.1 和 192.0.2.2。

  • 在主机 PC 上安装 Mosquitto。

  • 创建一个名为 unsecure.conf 的文件，内容如下：

listener 1883 0.0.0.0
allow_anonymous true

  • 使用该配置文件启动 Mosquitto 代理：

$ sudo mosquitto -v -c unsecure.conf

  • 使用快速测试配置构建示例：

west build -b adi_eval_adin1110ebz samples/net/secure_mqtt_sensor_actuator -- -DCONF_FILE="prj.conf overlay-static-insecure.conf"

使用示例

  • 开发板与 Mosquitto 代理建立 MQTT 连接后，网络 LED 会点亮，开发板开始以 CONFIG_NET_SAMPLE_MQTT_PUBLISH_INTERVAL 确定的固定间隔发布 JSON 格式的传感器读数。

  • 使用 Mosquitto 订阅开发板发送的传感器数据：

$ mosquitto_sub -d -h <test.mosquitto.org/local broker IP> -t zephyr_sample/sensor

  • 应用程序会订阅由 CONFIG_NET_SAMPLE_MQTT_SUB_TOPIC_CMD 确定的主题。如果开发板在此主题上收到受支持的命令字符串，就会执行相应的命令处理函数。支持的命令（在 device.c 中定义）：

    • led_on：点亮开发板 LED

    • led_off：熄灭开发板 LED

  • 使用 Mosquitto 向 MQTT 代理发布这些命令：

$ mosquitto_pub -d -h <test.mosquitto.org/local broker IP> --cafile <path/to/ca.crt> -t zephyr_sample/command -m "led_on"

  • MQTT 发布和订阅所使用的服务质量（QoS）级别可以通过 Kconfig 配置。
