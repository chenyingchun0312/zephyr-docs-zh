MQTT publisher

Browse source code on GitHub

概述

MQTT（MQ Telemetry Transport）是一种轻量级的发布/订阅消息协议，针对小型传感器和移动设备进行了优化。

Zephyr MQTT Publisher 示例应用程序是一个 MQTT 客户端，用于向 MQTT 代理（broker）发送 MQTT PUBLISH 消息。该示例支持 v3.1.1（默认）和 v5.0 版本的 MQTT 客户端。

有关 MQTT v3.1.1 和 v5.0 的更多信息，请分别参阅 MQTT v3.1.1 spec 和 MQTT v5.0 spec。

此示例应用程序的源代码位于：samples/net/mqtt_publisher。

要求

  • Linux 主机

  • Freedom 开发板（FRDM-K64F）

  • Mosquitto 服务器：任何支持 MQTT v3.1.1 的版本。此示例已使用 mosquitto 1.3.4 测试。

  • Mosquitto 订阅者

  • 用于测试的局域网（以太网）

构建与运行

目前，此示例应用程序仅支持静态 IP 地址。打开 src/config.h 文件，根据局域网环境设置 IP 地址。也可以在 prj.conf 文件中设置 IP 地址。

src/config.h 文件中还包含一些可以修改的变量：

MQTT 代理 TCP 端口：

#define SERVER_PORT             1883

应用程序休眠时间：

#define APP_SLEEP_MSECS         500

最大连接尝试次数：

#define APP_CONNECT_TRIES       10

MQTT 客户端标识符：

#define MQTT_CLIENTID           "zephyr_publisher"

此示例应用程序支持 IBM Bluemix Watson 主题格式，将 APP_BLUEMIX_TOPIC 的默认值由 0 改为 1 即可启用：

#define APP_BLUEMIX_TOPIC       1

Bluemix 主题可以包含设备类型、设备标识符、事件类型和消息格式等参数。此应用程序使用以下宏来指定这些值：

#define BLUEMIX_DEVTYPE         "sensor"
#define BLUEMIX_DEVID           "carbon"
#define BLUEMIX_EVENT           "status"
#define BLUEMIX_FORMAT          "json"

MQTT PUBLISH 的最大迭代次数在 Kconfig 中定义：

CONFIG_NET_SAMPLE_APP_MAX_ITERATIONS=5

在 Linux 主机上打开一个终端窗口，找到此示例应用程序的源代码（即 samples/net/mqtt_publisher），然后输入：

west build -b frdm_k64f samples/net/mqtt_publisher
west flash

如果开发板通过局域网直接连接到 Linux 主机，请配置网络接口：

$ IFACE=eth0 # Change this to the interface to which the LAN cable is connected

$ IPV4_ADDR_1="192.0.2.2/24"
$ IPV4_ROUTE_1="192.0.2.0/24"

$ sudo ip address add $IPV4_ADDR_1 dev $IFACE
$ sudo ip route add $IPV4_ROUTE_1 dev $IFACE
$ sudo ip link set dev $IFACE up

可以运行 sudo ip addr flush dev $IFACE 来撤销上述步骤。

备注

对于 mosquitto 2.0 及更高版本，请确保在 mosquitto 配置文件 mosquitto.conf 中添加以下内容，以允许未认证访问：

listener 1883
allow_anonymous true
bind_interface eth0

打开另一个终端窗口并输入：

$ sudo mosquitto -v -p 1883             # For mosquitto < 2.0
$ sudo mosquitto -v -c mosquitto.conf   # For mosquitto >= 2.0

打开另一个终端窗口并输入：

$ mosquitto_sub -t sensors

MQTT v5.0 支持

可以将示例配置为使用 MQTT v5.0 而不是 MQTT v3.1.1。要在示例中启用 MQTT v5.0，请使用 -DEXTRA_CONF_FILE=overlay-mqtt-5.conf 参数进行构建。该示例应能与任何支持 MQTT v5.0 的代理配合使用，不过专门针对 mosquitto 2.0.21 版本进行过测试。此时服务器端的配置与 MQTT v3.1.1 相同。

当示例配置为 MQTT v5.0 模式时，会使用主题别名功能。也就是说，如果代理报告支持主题别名，客户端会为默认的 sensors 主题注册一个主题别名，并在后续的 MQTT Publish 消息中使用它。可以观察到（例如使用 Wireshark），实际主题只出现在第一条 Publish 消息中，之后的所有 Publish 消息都更小，因为它们只包含主题别名属性。

使用 TLS 安全连接

虽然可以搭建本地的安全 MQTT 服务器并修改示例以连接到它，但这需要用户自行创建证书并在服务器上进行配置。

另一种方式是使用 公开可用的 Mosquitto MQTT 服务器/代理，按照以下步骤即可快速、方便地试用启用 TLS 的示例：

  • 从 https://test.mosquitto.org 下载 DER 格式的服务器 CA 证书文件

  • 在 src/test_certs.h 中，用证书内容设置 ca_certificate[]（如果平台启用了套接字卸载功能且 CONFIG_TLS_CREDENTIAL_FILENAMES 设置为 y，则将其设置为证书文件名）。

  • 在 src/config.h 中，将 SERVER_ADDR 设置为要连接的 IP 地址，即 test.mosquitto.org 的 IP 地址 "37.187.106.16"

  • 在 src/main.c 中，将 TLS_SNI_HOSTNAME 设置为 "test.mosquitto.org"，以匹配所下载证书中的通用名称（CN）。

  • 运行 west build 或 cmake 时指定 -DEXTRA_CONF_FILE=overlay-tls.conf 来构建示例（如果平台使用卸载功能，请参阅下面的 TLS 卸载一节）。

  • 将二进制文件烧录到设备上以运行示例：

$ west flash

TLS 卸载

对于支持此功能的开发板，在运行 west build 或 cmake 时指定 -DEXTRA_CONF_FILE=overlay-tls-offload.conf 即可使用 TLS 卸载。

使用此覆盖文件可以在不引入 mbedtls 的情况下启用 TLS。

SOCKS5 代理支持

也可以通过 SOCKS5 代理连接到 MQTT 代理。要启用此功能，请在运行 west build 或 cmake 时使用 -DEXTRA_CONF_FILE=overlay-socks5.conf。

默认情况下，为便于测试，代理服务器应与 MQTT 代理运行在同一主机上。

可以使用 ssh 启动代理服务器。使用以下命令在主机上以默认端口运行：

$ ssh -N -D 0.0.0.0:1080 localhost

要连接到与 MQTT 代理 IP 不同或使用不同端口号的代理服务器，请修改以下值：

#define SOCKS5_PROXY_ADDR    SERVER_ADDR
#define SOCKS5_PROXY_PORT    1080

MQTT 日志后端

可以将示例配置为使用 MQTT 日志后端，从而将应用程序的日志消息发布到 MQTT 代理。此功能与主示例应用程序使用同一个 MQTT 客户端实例。

MQTT 日志后端使用 log_backend_mqtt_client_set() API 注册一个用于发布日志消息的 MQTT 客户端。该后端只使用客户端的 mqtt_publish() 函数，不管理客户端的连接生命周期，这仍由应用程序负责。

要在示例中启用 MQTT 日志后端，请使用 -DEXTRA_CONF_FILE=overlay-log-backend-mqtt.conf 参数进行构建。

可用的主要配置选项：

  • CONFIG_LOG_BACKEND_MQTT_TOPIC_DEFAULT：发布日志的主题（默认值："zephyr/logs"）

  • CONFIG_LOG_BACKEND_MQTT_QOS：日志消息的 QoS 级别（默认值：0）

  • CONFIG_LOG_BACKEND_MQTT_RETAIN：是否保留日志消息（默认：禁用）

  • CONFIG_LOG_BACKEND_MQTT_MAX_MSG_SIZE：日志消息的最大长度（默认值：256 字节）

在 cc3220sf_launchxl 上运行

cc3220sf_launchxl 上的卸载功能还提供 DHCP 服务，因此该示例在此开发板上使用动态 IP 地址。

默认情况下，示例设置为连接到 config.h 中 SERVER_ADDR 所指定地址的代理。如果代理使用 TLS 保护，用户应启用 TLS 卸载，使用 TI Uniflash 将 DER 格式的服务器证书颁发机构文件上传到设备文件系统，并将其命名为 "ca_cert.der"。

此外，main.c 中的 TLS_SNI_HOSTNAME 应定义为与证书文件中的通用名称（CN）一致，TLS 域名验证才能成功。

请参阅 CC3220SF LaunchXL 中关于配网（Provisioning）和快速连接（Fast Connect）的说明。

Secure Socket Offload 一节介绍了如何将证书写入 Flash。

然后按上述方法进行测试。
