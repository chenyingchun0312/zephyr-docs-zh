gPTP

Browse source code on GitHub

概述

Zephyr 的 gPTP 示例应用程序会启用 gPTP 支持，注册 gPTP 相位不连续回调，启用流量类别支持（TX 多队列），并设置 VLAN（如果启用）。同时还启用了 net-shell，以便用户监视 gPTP 功能。

本示例应用程序的源代码位于：samples/net/ethernet/gptp。

要求

关于可用于调试的通用主机连接，详情请参阅 使用 native_sim 开发板联网。

构建与运行

运行本示例的一个好方法是按照 使用 native_sim 开发板联网 中的说明在 native_sim 开发板中运行这个 gPTP 应用程序，或者在 NXP FRDM-K64F、Nucleo-H743-ZI、Nucleo-H745ZI-Q、Nucleo-F767ZI 或 Atmel SAM-E70 Xplained 等嵌入式设备上运行。注意，只有带以太网口且支持为收发的以太网帧采集时间戳的开发板才支持 gPTP。

按照以下步骤构建 gPTP 示例应用程序：

west build -b <board to use> samples/net/ethernet/gptp

net-shell 命令“net gptp”会打印 gPTP 的总体信息。对于端口 1，命令“net gptp 1”会打印端口 1 的统计等详细信息。注意，执行 shell 命令可能会影响收发 gPTP 数据包的时序，grandmaster 可能会将设备标记为不具备 AS 能力并将其禁用。

设置 Linux 主机

如果网络中需要 VLAN 支持，samples/net/ethernet/vlan/vlan-setup-linux.sh 提供了一个可在 Linux 主机上执行的脚本。它在 Linux 主机上创建两个 VLAN，并创建到 Zephyr 的路由。如果使用 native_sim 开发板，net-setup.sh 会通过以下命令自动完成 VLAN 设置：

./net-setup.sh -c zeth-vlan.conf

https://github.com/AVnu 上的 OpenAVNU 仓库包含一个 gPTP 守护进程，可以在 Linux 主机上运行，充当 IEEE 801.1AS 网络的 grandmaster。注意，OpenAVNU 无法与 native_sim 开发板配合使用，因为该开发板只支持软件时间戳，而 OpenAVNU 只支持硬件时间戳。关于如何在 native_sim 开发板上运行 linuxptp 守护进程，请参阅本章末尾的说明。

获取 OpenAvnu/gPTP 项目源代码

git clone git@github.com:AVnu/gptp.git

下载源代码后，在 Linux 中按如下方式编译：

mkdir build
cd build
cmake ..
make
cp ../gptp_cfg.ini .

编辑 gptp_cfg.ini 文件，将 neighborPropDelayThresh 设置为 10000，因为在 FRDM-K64F 上运行 gPTP 时，默认值 800 太低。

然后使用正确的网络接口和配置文件运行该守护进程。

sudo ./gptp enp0s25 -F gptp_cfg.ini

注意，这里的示例网络接口 enp0s25 是连接到 Zephyr 设备的网络接口的名称。

如果一切配置正确，你应该会看到 gptp 输出如下消息：

INFO     : GPTP [13:01:14:837] gPTP starting

INFO     : GPTP [13:01:14:838] announceReceiptTimeout: 3
INFO     : GPTP [13:01:14:838] syncReceiptTimeout: 3
INFO     : GPTP [13:01:14:838] LINKSPEED_100MB - PHY delay
                    TX: 1044 | RX: 2133
INFO     : GPTP [13:01:14:838] LINKSPEED_1G - PHY delay
                    TX: 184 | RX: 382
INFO     : GPTP [13:01:14:838] neighborPropDelayThresh: 10000
INFO     : GPTP [13:01:14:838] syncReceiptThreshold: 8
ERROR    : GPTP [13:01:14:838] Using clock device: /dev/ptp0
STATUS   : GPTP [13:01:14:838] Starting PDelay
STATUS   : GPTP [13:01:14:838] Link Speed: 1000000 kb/sec
STATUS   : GPTP [13:01:14:871] AsCapable: Enabled
STATUS   : GPTP [13:01:16:497] New Grandmaster "3C:97:0E:FF:FE:23:F2:32" (previous "00:00:00:00:00:00:00:00")

如果 Zephyr 与 gptp 守护进程正常同步，会打印以下内容：

STATUS   : GPTP [13:01:25:965] AsCapable: Enabled

默认情况下，Zephyr 中的 gPTP 不会向控制台打印任何 gPTP 调试消息。可以在配置文件中设置 CONFIG_NET_GPTP_LOG_LEVEL_DBG 启用调试打印。

对于 native_sim 开发板，请使用 linuxptp 项目，因为它支持软件时间戳。

获取 linuxptp 项目源代码

git clone git://git.code.sf.net/p/linuxptp/code

编译 ptp4l 守护进程并按如下方式启动：

sudo ./ptp4l -2 -f gPTP-zephyr.cfg -i zeth -m -q -l 6 -S

以 default.cfg 为基础，将其复制为 gPTP-zephyr.cfg，并根据需要修改。

多端口设置

如果将 CONFIG_NET_GPTP_NUM_PORTS 设置为大于 1，gPTP 示例会创建多个 TSN 端口。目前只有 native_sim 开发板支持该配置。设备树中定义的 zephyr,native-tap 接口数量必须与 CONFIG_NET_GPTP_NUM_PORTS 一致。对于两个端口，请使用 overlay-multiport.conf 和 overlay-multiport.overlay 构建，它们会添加第二个 TAP 接口：

west build -b native_sim samples/net/ethernet/gptp -- -DEXTRA_CONF_FILE=overlay-multiport.conf -DEXTRA_DTC_OVERLAY_FILE=overlay-multiport.overlay

需要在 net-tools 中启用这些端口。如果端口数设置为 2，请执行以下命令在主机端创建网络接口：

sudo ./net-setup.sh -c zeth0-gptp.conf -i zeth0 start
sudo ./net-setup.sh -c zeth1-gptp.conf -i zeth1 start

之后即可为两个接口启动 ptp4l 守护进程。启动 ptp4l 守护进程时请使用两个终端。注意，必须使用 ptp4l，因为 OpenAVNU 无法使用 native_sim 中提供的软件时钟。

cd <ptp4l directory>
sudo ./ptp4l -2 -f gPTP-zephyr.cfg -m -q -l 6 -S -i zeth0
sudo ./ptp4l -2 -f gPTP-zephyr.cfg -m -q -l 6 -S -i zeth1

编译 Zephyr 应用程序。

west build -b native_sim samples/net/ethernet/gptp

构建好 Zephyr 镜像后，可以按如下方式启动它：

build/zephyr/zephyr.exe -attach_uart

静态时间接收者（timeReceiver）设置

在按照 IEEE 802.1AS 汽车配置文件（automotive profile）构建的网络中，网桥只发送 Sync 和 Follow_Up 消息，不发送 Announce 消息，因此默认协议栈永远不会选出时间接收者端口。请使用 samples/net/ethernet/gptp/overlay-static-time-receiver.conf 覆盖配置构建本示例，将端口固定为时间接收者角色：

west build -b <board to use> samples/net/ethernet/gptp -- -DCONF_FILE="prj.conf overlay-static-time-receiver.conf"

可以与 linuxptp 配合测试：将 ptp4l 作为不发送 Announce 消息的 grandmaster 运行，例如使用基于 linuxptp 自带的 automotive-master.cfg 文件的配置。
