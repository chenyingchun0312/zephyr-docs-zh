HTTP Server

Browse source code on GitHub

概述

此示例应用程序演示 HTTP 服务器 库的用法。该库提供高层函数，用于简化和抽象服务器的实现。服务器支持 HTTP/1.1 协议，并可升级到 HTTP/2，也支持无需升级的原生 HTTP/2 协议。如果启用了 CONFIG_QUIC 配置选项，服务器还会支持 HTTP/3 协议。默认情况下，HTTP/1.1 会话可以升级到 HTTP/3，也可以无需升级直接使用 HTTP/3。net-shell 命令 net http services 可以显示每个已配置的 HTTP 服务支持哪些 HTTP 协议。

要求

QEMU Networking

构建并运行服务器

samples/net/sockets/http_server 目录中提供了适用于各种设置的配置文件：

prj.conf

这是标准的默认配置。

ieee802154-overlay.conf

添加此覆盖配置可启用 IEEE 802.15.4 支持。

overlay-usbd.conf

添加此覆盖配置可通过 USB 网络进行连接。

overlay-tls.conf

添加此覆盖配置可构建 HTTPS 版本。

overlay-dhcpv4.conf

此覆盖文件启用 DHCPv4 客户端功能。

构建并运行 HTTP 服务器应用程序：

$ west build -p auto -b <board_to_use> -t run samples/net/sockets/http_server

对于 HTTPS 版本：

$ west build -p auto -b <board_to_use> -t run --test samples/net/sockets/http_server/sample.net.sockets.https.server

服务器启动后，可以从主机使用 HTTP/1.1 或 HTTP/2 协议向服务器发出请求。

With HTTP/1.1:

  • 使用浏览器：http://192.0.2.1/

  • 使用 curl：curl -v --compressed http://192.0.2.1/

  • 使用 ab（Apache Bench）：ab -n10 http://192.0.2.1/

With HTTP/2:

  • 使用 nghttp 客户端：nghttp -v --no-dep http://192.0.2.1/

  • 使用 curl：curl --http2 -v --compressed http://192.0.2.1/

  • 使用 h2load：h2load -n10 http://192.0.2.1/

Web 浏览器对 HTTP/2 协议采用更严格的安全设置。因此，要在 Web 浏览器中使用 HTTP/2，必须在上述 HTTPS 构建的基础上启用 ALPN（在 west build 命令中添加 -DCONFIG_NET_SAMPLE_HTTPS_USE_ALPN）。此外，服务器证书必须由浏览器信任的 CA 证书签名。

最好的做法是生成自己的 CA 证书：

$ west build -b <board_to_use> -t sample_ca_cert samples/net/sockets/http_server

生成一个由该 CA 证书签名的服务器证书：

$ west build -t sample_server_cert samples/net/sockets/http_server

然后使用新生成的服务器证书和密钥构建应用程序：

$ west build samples/net/sockets/http_server

应将该 CA 证书添加到浏览器的受信任机构列表中，才能使用 HTTP/2。如果使用 Firefox，可能还需要将设置 network.http.http2.enforce-tls-profile 改为 false，因为在使用 HTTP/2 时，Firefox 似乎会将使用由其未知机构签发的 CA 证书视为安全错误。

服务器定制

服务器示例包含若干可根据需求定制的参数。可配置参数如下：

  • CONFIG_NET_SAMPLE_HTTP_SERVER_SERVICE_PORT：配置服务端口。

  • CONFIG_HTTP_SERVER_MAX_CLIENTS：定义服务器可同时处理的 HTTP/2 客户端的最大数量。

  • CONFIG_HTTP_SERVER_MAX_STREAMS：指定每个客户端可建立的 HTTP/2 流的最大数量。

  • CONFIG_HTTP_SERVER_CLIENT_BUFFER_SIZE：定义为每个客户端分配的缓冲区大小。这限制了所支持的单个 HTTP 头部的最大长度。

  • CONFIG_HTTP_SERVER_MAX_URL_LENGTH：指定服务器可处理的 HTTP URL 的最大长度。

  • CONFIG_NET_SAMPLE_WEBSOCKET_SERVICE：启用 Websocket 服务端点。这样 Websocket 客户端就可以连接到 / 端点，客户端发送的所有数据都会被回显回去。

要定制这些选项，可以运行 west build -t menuconfig，它提供交互式配置界面。然后从顶层菜单导航到：-> Subsystems and OS Services -> Networking -> Network Protocols。

Websocket 连接

可以使用类似下面这样的简单 Websocket 客户端应用程序来测试 Websocket 连接。

import websocket

websocket.enableTrace(True)
ws = websocket.WebSocket()
ws.connect("ws://192.0.2.1/ws_echo")
ws.send("Hello, Server")
print(ws.recv())
while True:
  line = input("> ")
  if line == "quit":
    break
  ws.send(line)
  print(ws.recv())
ws.close()

通过 USB 测试

下面通过一个实际例子，介绍如何在真实设备上通过连接到 Linux 主机 PC 的 USB 来测试 HTTP(S) 服务器。这里以 NRF52840 开发板为例。

首先，构建启用 HTTPS 服务的示例并烧录到开发板：

# From the root of the zephyr repository
west build -b nrf52840dk/nrf52840 samples/net/sockets/http_server/ -- -DCONFIG_NET_SAMPLE_HTTPS_SERVICE=y -DEXTRA_CONF_FILE=overlay-netusb.conf

然后将 USB 线连接到主机 PC 并执行：

$ ip link show

以获取 Linux 为 USB 以太网接口分配的设备名。下文假设该名称为 eth-device。

现在需要为该接口配置 IP 和路由：

$ sudo ip addr add 192.0.2.2/24 dev eth-device
$ sudo ip route add 192.0.2.0/24 dev eth-device

其中：

  • 我们为该接口选择了一个 IP 地址，即 192.0.2.2/24，它与服务器的地址（即 CONFIG_NET_CONFIG_MY_IPV4_ADDR）不同，但位于 /24 掩码定义的允许 IP 范围内。

  • 我们假设 192.168.0.x 范围不与主机系统中的其他地址和路由冲突。如果存在冲突，则应修改所有 IP 地址（示例、主机 IP 接口、证书）。

完成后，应该就可以使用 curl 测试 HTTP 和 HTTPS：

$ curl -v --compressed http://192.0.2.1
$ curl -v --compressed https://192.0.2.1

备注

要成功建立 HTTPS 连接，请务必更新 Linux 主机系统的 CA 证书，将 samples/net/sockets/http_server/src/certs/ca_cert.pem 添加到已知 CA 列表中。

性能分析

CPU 使用率分析

可以使用 perf 的 stat 命令，收集运行在 native_sim 开发板中的服务器的 CPU 使用率统计信息：

$ sudo perf stat -p <pid_of_server>

随后 perf stat 会开始监视服务器。可以让它持续运行，同时向服务器发送请求。收集到足够的数据后，停止 perf stat，它会打印性能统计摘要。

热点分析

可以结合使用 perf record 和 perf report，找出代码中占用 CPU 时间最多的函数：

$ sudo perf record -g -p <pid_of_server> -o perf.data

在服务器承受负载（例如使用 ApacheBench 工具）运行一段时间后，停止记录并使用以下命令分析数据：

$ sudo perf report -i perf.data

生成包含性能分析数据的 perf.data 文件后，可以使用 FlameGraph 工具将其可视化。这对于识别开销最大的代码路径、查看应用程序在哪些地方花费时间最多特别有用。

为此，需要将 perf.data 转换为 FlameGraph 能够识别的格式：

$ sudo perf script | ~/FlameGraph/stackcollapse-perf.pl > out.perf-folded

然后生成 FlameGraph：

$ ~/FlameGraph/flamegraph.pl out.perf-folded > flamegraph.svg

可以使用 Web 浏览器查看 flamegraph.svg。
