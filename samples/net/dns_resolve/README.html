DNS resolve

Browse source code on GitHub

概述

本应用程序为设备设置 IP 地址，然后根据用户对系统的配置尝试解析各种主机名。

  • 如果启用了 IPv4，则解析 www.zephyrproject.org 的 A 记录。

  • 如果启用了 IPv6，则解析 www.zephyrproject.org 的 AAAA 记录。

  • 如果启用了 mDNS，则解析 zephyr.local 名称。

要求

  • 与主机系统联网

  • screen 终端仿真器或同类工具。

  • 对于大多数没有以太网的开发板，需要 ENC28J60 以太网模块。

  • dnsmasq 应用程序。本示例使用的 dnsmasq 版本为：

dnsmasq -v
Dnsmasq version 2.76  Copyright (c) 2000-2016 Simon Kelley

构建与运行

网络配置

打开你的平台对应的项目配置文件，例如 prj_frdm_k64f.conf 是 FRDM-K64F 开发板的配置文件。

本示例应用程序同时支持静态 IP 地址和 DHCPv4 IP 地址。静态 IP 地址在项目配置文件中指定，例如：

CONFIG_NET_CONFIG_MY_IPV6_ADDR="2001:db8::1"
CONFIG_NET_CONFIG_PEER_IPV6_ADDR="2001:db8::2"

分别是运行 Zephyr 的 DNS 客户端和 DNS 服务器的 IPv6 地址。

DNS 服务器

可以使用 dnsmasq 工具进行测试。在 Zephyr 项目的默认安装中，示例 dnsmasq 启动脚本位于 net-tools 项目中，也可以从 https://github.com/zephyrproject-rtos/net-tools 下载。

打开一个终端窗口并输入：

$ cd net-tools
$ sudo ./dnsmasq.sh

本示例的默认项目配置使用 Google 公共 DNS 服务器。要使用本地 dnsmasq 服务器，请编辑相应的 'prj.conf' 文件并更新 DNS 服务器地址。例如，如果使用常见的测试用 IP 地址，请将其更新为以下值：

CONFIG_DNS_SERVER1="192.0.2.2:5353"
CONFIG_DNS_SERVER2="[2001:db8::2]:5353"

备注

DNS 默认使用端口 53，但 net-tools 提供的 dnsmasq.conf 文件使用端口 5353，以便无需超级用户权限即可运行该守护进程。

如果 dnsmasq 启动失败并出现如下错误：

dnsmasq: failed to create listening socket for port 5353: Address already in use

打开一个终端窗口并输入：

$ killall -s KILL dnsmasq

请再次尝试启动 dnsmasq 应用程序。

要测试 mDNS，请使用 net-tools 项目中的 Avahi 脚本：

$ cd net-tools
$ ./avahi-daemon.sh

LLMNR 响应器

如果希望 Zephyr 响应 Windows 主机发送的 LLMNR DNS 请求，可以设置以下配置选项：

CONFIG_NET_HOSTNAME_ENABLE=y
CONFIG_NET_HOSTNAME="zephyr-device"
CONFIG_DNS_RESOLVER=y
CONFIG_LLMNR_RESPONDER=y

Zephyr 主机需要分配一个主机名，才能响应 DNS 查询。注意，主机名中不应包含点号。

QEMU x86

要使用 QEMU 进行测试，请按照 使用 QEMU 联网 指南操作。

FRDM K64F

打开一个终端窗口并输入：

west build -b frdm_k64f samples/net/dns_resolve
west flash

关于该开发板的更多信息，请参阅 Freedom-K64F 开发板文档。

打开一个终端窗口并输入：

$ screen /dev/ttyACM0 115200

使用 'dmesg' 找到正确的 USB 设备。

二进制文件加载到 FRDM 开发板后，按下 RESET 按键。

Wi-Fi

可以通过 Wi-Fi 代码片段（snippet） 在本示例中启用 IPv4 Wi-Fi 支持。
