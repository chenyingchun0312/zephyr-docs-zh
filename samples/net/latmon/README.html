Latmon Client

Browse source code on GitHub

概述

本项目提供用于测量被测系统（SUT）对 GPIO 事件最坏情况响应时间的工具，包括：

  • Latmon:

    运行在基于 Zephyr 的开发板上，生成并监视 GPIO 事件，同时收集指标

  • Latmus:

    运行在 SUT 上，响应输入 GPIO 事件的下降沿，显示延迟指标并生成直方图数据。

本项目是开源计划 EVL Project - Latmus GPIO Response Time 的一部分。

主程序用于在基于 Zephyr 的系统上利用 GPIO 引脚监视延迟。它在一个 GPIO 引脚上产生脉冲信号，并测量（运行 Latmus 的）SUT 对其作出响应所需的时间。

SUT 必须运行 Latmus，以采集通过网络上报的延迟指标和直方图信息。程序使用 LED 指示不同状态，例如 DHCP 绑定（红色）、等待 Latmus 连接（蓝色）和采样（绿色）。

为什么不直接使用定时器？

定时器测试会遗漏 GPIO 信号、硬件和中断处理等外部因素。Latmon 和 Latmus 模拟真实场景，采集端到端的延迟指标，从而确保准确评估整个系统的实时响应能力。

  • Real-Time Thread Testing:

    评估用户空间线程如何处理外部中断。

  • End-to-End Latency Measurement:

    采集来自硬件、驱动和用户空间线程的延时。

  • Versatile Platform Support:

    适用于 EVL、PREEMPT_RT 和其他平台。

代码结构

Latmon 示例应用程序分为两个主要组件：

  • Application Logic (samples/net/latmon/src/main.c):

    该文件包含 Latmon 的应用逻辑。它初始化网络，提供测量机制，并控制指示不同状态的 LED。

  • Library (subsys/net/lib/latmon/latmon.c):

    该文件提供通过 Latmus 进行延迟监视的可复用函数和抽象，包括上报延迟指标和直方图数据的核心逻辑。

要求

  • Zephyr-Compatible Board:

    一块支持外部 GPIO 并带有 IPv4 网络接口的开发板（例如 FRDM-K64F）。

  • System under Test:

    一个带有外部 GPIO 引脚、运行 Latmus 服务并带有 IPv4 网络接口的系统。

  • Network Connection:

    一个用于分配 IP 的 DHCP 服务器。

  • Physical Connection:

    用 GPIO 导线将 Zephyr 开发板连接到 SUT，并将两个系统都接入网络。

设置与使用

  • Flash Latmon onto the Zephyr board:

    应用程序会连接到网络并等待来自 SUT 的连接。应用程序使用 DHCP 获取 IPv4 地址。

  • Connect GPIO pins for transmit (Zephyr to SUT) and receive (SUT to Zephyr)

    在 FRDM-K64F 上，示例代码使用 Arduino 排针 J2，其中 pin 20 用于向 SUT 发送脉冲，pin 18 用于接收 SUT 的确认信号。

  • Run Latmus on the SUT

    使用 Latmus 请求相应的选项。例如，用户可以用 -p 选项修改采样周期，或者用 -g 选项生成供后期处理的直方图数据，

  • Monitor results from the SUT

    Latmus 会报告延迟数据，并在请求时生成直方图数据文件。

  • Calibrating the Latmus latencies: CONFIG_LATMON_LOOPBACK_CALIBRATION:

    用户可以将 GPIO 引脚以回环方式连接（发送脚接确认脚），并在启用 CONFIG_LATMON_LOOPBACK_CALIBRATION 的情况下构建 Latmon 示例应用程序。在这种配置下连接 Latmus 时，Latmus 会提供一个校准值，可用于调整最终的延迟数据。

示例

在主机上，构建 Latmon 示例并将其烧录到 Zephyr FRDM-K64F 开发板：

user@host:~$ west build -b frdm_k64f samples/net/latmon
user@host:~$ west flash

在运行 Linux 的 SUT 上，latmus 必须 跟踪信号的下降沿：

root@target:~$ latmus -I gpiochip2,23,falling-edge -O gpiochip2,21 -z -g"histogram" "broadcast"

完成后，在主机上从 SUT 取回直方图文件，并使用 gnuplot 生成图表（PNG 文件）：

user@host:~$ gnuplot plot_data.gp

对于名为 histogram 的文件，plot_data.gp 脚本应如下所示：

set terminal pngcairo size 800,600
set output 'plot.png'
set title "Data Plot"
set xlabel "Latency (usec)"
set ylabel "Sample Count"
set grid
set style data linespoints
plot 'histogram' using 1:2 with linespoints title "Data Points"
