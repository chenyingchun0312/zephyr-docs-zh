Object cores

Browse source code on GitHub

概述

对象核心（object core）是一种内核调试设施，工具可以借助它找到给定类型的每个内核对象（无论是静态定义的还是在运行时初始化的），并读取该对象类型提供的统计信息。追踪子系统中的对象跟踪（CONFIG_TRACING_OBJECT_TRACKING）也基于同一设施实现。

本示例逐一介绍该设施的各个方面：

  • 对象清单：每种类型的对象各有多少个，以及有多少个因位于栈存储中（skipped）或因注册表已满（dropped）而被拒绝注册。只有当 dropped 为零时，清单才是完整的；一旦非零，就存在任何遍历都报告不到的对象。如果某种类型的内核代码未链接进镜像，则报告为不存在。

  • 静态对象和运行时对象：用 K_SEM_DEFINE 创建的信号量无需任何调用就会被报告，而位于普通存储中的信号量在 k_sem_init() 将其注册后才会被报告。

  • 临时对象：在函数内部声明的信号量不会被注册，因为其存储随函数结束而失效，信号量类型会将其计为已跳过（skipped）。

  • 线程：线程从创建起直到被中止都会被报告。

  • 已释放的内存：嵌入在堆分配结构体中的互斥量，在该结构体被释放后就不再被报告。

  • 显式注销：k_obj_core_unlink() 会立即将对象从遍历中移除。

  • 统计信息：启用 CONFIG_OBJ_CORE_STATS 后，每个线程的运行时统计信息、内存块（slab）的使用情况以及所有 CPU 消耗的周期数都通过同一个 API k_obj_core_stats_query() 读取。

构建与运行

本应用程序可以按如下方式在 QEMU 上构建并运行：

west build -b qemu_x86 samples/kernel/object_cores
west build -t run

要为其他开发板构建，请将上面的 qemu_x86 改为该开发板的名称。在 native_sim 上，线程运行在主机栈上，因此本示例启用了 CONFIG_ARCH_POSIX_UPDATE_STACK_INFO，让内核能够识别位于栈存储中的对象。

对象跟踪

tests.yaml 中的 sample.kernel.object_cores.tracking 配置构建同一个程序，但使用 CONFIG_TRACING 和 CONFIG_TRACING_OBJECT_TRACKING，而不是 prj.conf 中的 CONFIG_OBJ_CORE：

west build -b qemu_x86 samples/kernel/object_cores -T sample.kernel.object_cores.tracking -t run

对象跟踪会选中对象核心框架，因此程序无需修改即可运行，第一行会注明框架是如何启用的。
