Memory Protection Unit (MPU)

Browse source code on GitHub

概述

本应用程序提供一组选项，用于检查 MPU 配置是否能正确防范以下安全问题：

  • 读取内存映射中保留的地址。

  • 写入启动 Flash/ROM。

  • 运行位于 SRAM 中的代码。

如果 MPU 配置正确，所选的每个选项最终都会触发 MPU 故障。

构建与运行

本项目可以按如下方式构建并运行：

west build -b v2m_beetle samples/arch/mpu/mpu_test
west flash

要构建单线程版本，请使用提供的单线程配置文件 prj_single.conf：

west build -b v2m_beetle samples/arch/mpu/mpu_test -- -DCONF_FILE=prj_single.conf
west build -t run

要构建允许写入 Flash 设备的版本，请编辑 prj.conf，并按照其中注释的说明启用相应配置。

示例输出

在 ARMv7 或 ARMv8 CPU 上运行上述命令时，每条命令的输出可能如下所示。

<err> os:  xpsr:  0x21000000

<err> os:  xpsr:  0x61000000
<err> os: Faulting instruction address (r15/pc): 0x000003b2

uart:~$ mpu run
<err> os: ***** MPU FAULT *****
<err> os:   Instruction Access Violation
<err> os: r0/a1:  0x00009a5c  r1/a2:  0x00000001  r2/a3:  0x20001aa8

<err> os: Faulting instruction address (r15/pc): 0x20000000
<err> os: >>> ZEPHYR FATAL ERROR 0: CPU exception on CPU 0
<err> os: Current thread: 0x20000708 (shell_uart)
<err> os: Halting system

在 ARMv6 CPU（具体为 Cortex-M0+）上运行此测试时，输出会有所不同，因为 ARMv6 将 MPU 故障作为通用硬故障（hard fault）处理。此外，运行 mpu run 命令时，Zephyr 的 AArch32 硬故障处理程序会尝试从异常栈帧中解引用程序计数器，导致第二次故障，并使处理器静默进入锁定（lockup）状态。

要专门验证 mpu run 测试是否正确运行，可以：

  • 使用 west debug 在 gdb 下启动 MPU 测试

  • 通过 UART 执行 mpu run

  • 然后按 Ctrl-C 中断 gdb，并在 gdb 中运行 l 显示程序计数器。

程序计数器应显示为 0xfffffffe，表示处于锁定状态。

uart:~$ mpu read
<err> os: ***** HARD FAULT *****
<err> os: r0/a1:  0x0800a54c  r1/a2:  0x00000008  r2/a3:  0x08003
<err> os: r3/a4:  0x24000000 r12/ip:  0x00000040 r14/lr:  0x0800d
<err> os:  xpsr:  0x01000000
<err> os: Faulting instruction address (r15/pc): 0x08000486
<err> os: >>> ZEPHYR FATAL ERROR 0: CPU exception on CPU 0
<err> os: Current thread: 0x200006a8 (shell_uart)
<err> os: Halting system

<err> os: r0/a1:  0x00000000  r1/a2:  0x0000000e  r2/a3:  0x0000e
