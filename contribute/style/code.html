C 代码及通用风格指南

编码风格会在所有新增或修改的代码上强制执行，但不要求贡献者修正他们未修改的现有代码的风格。

对于指南没有给出明确指导、或允许多种有效写法的风格问题，贡献者应遵循代码树中现有代码的风格，并优先参考“邻近”的代码（先看同一函数，再看同一文件，然后是子系统，依此类推）。

总体上遵循 Linux kernel coding style，但有以下例外和说明：

  • 制表符宽度为 8 个字符。

  • 代码和变量使用 snake case。

  • 行长度不超过 100 列。在文档中，URL 引用所在的较长行是允许的例外。

  • 每个 if、else、do、while、for 和 switch 的主体都要加花括号，即使是单行代码块也不例外。

  • 必要时，使用空格而不是制表符来对齐声明后面的注释。

  • 使用 C89 风格的单行注释 /*  */。不允许使用 C99 风格的单行注释 //。

  • 需要出现在文档中的 doxygen 注释使用 /**  */。

  • 避免使用二进制字面量（以 0b 开头的常量）。

  • 避免在代码中使用非 ASCII 符号，除非这样能显著提高清晰度；任何情况下都不要使用 emoji。

  • 在代码注释中正确使用名词的大小写（例如写 UART 而不是 uart，写 CMake 而不是 cmake）。
