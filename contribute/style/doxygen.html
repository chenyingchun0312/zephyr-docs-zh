Doxygen 风格指南

Zephyr 项目使用 Doxygen 从源代码注释生成 API 文档。本指南定义了以一致方式编写 Zephyr 公共 API 文档的约定。

所有 Doxygen commands 都可以使用，即使它们没有在本文档中明确出现。

要在本地构建和预览 Zephyr 的 Doxygen 文档，请参阅 文档生成。

通用规则

所有 公共头文件及其中的公共 API 符号（函数、结构体、枚举、联合体、typedef、宏和全局变量）：

  • 必须有完整的文档（例外情况参见 隐藏内部细节）

  • 必须至少属于一个 Doxygen 组（参见 组）

为公共 API 编写文档时，必须使用以下语法：

  • 使用 /** 开始块注释，使用 */ 结束块注释。

  • 与符号位于同一行的尾随注释使用 /**<。

  • Doxygen 命令使用 @（而不是 \）（例如使用 @param 而不是 \param）。

  • @brief 命令是可选的。如果不使用，第一个句子（以句点结尾）会被视为简要描述。

仅供内部使用的结构必须在公共文档中隐藏，具体方法见 隐藏内部细节。

需要记录的内容

对于任何接受、返回或存储值的 API 元素（函数参数、返回值、结构体/联合体成员、枚举值、typedef 和宏），在适用时，其文档必须描述以下各项：

语义

该元素代表什么，以及调用者/使用者应如何理解它。不要重复标识符名称或 C 类型。

示例：

  • 避免：@param timeout Timeout value in ms.

  • 推荐：@param timeout Maximum time to wait before returning, in milliseconds.

有效值

接受哪些值，以及这些值如何解释。指定以下一项或多项：

  • 范围：最小值/最大值（例如，类型为 uint8_t，但只有 0–100 有效）。

  • 离散集合：仅允许部分值时，列出允许的值。

  • 枚举：该值是否必须是给定枚举的有效成员（以及是允许所有枚举项还是只允许其中一部分）。

  • 标志/位掩码：哪些位有效，以及是否允许组合。

  • 可空性：指针值是否允许为 NULL，以及这种情况的含义。

单位

当值表示某个量时，指明其单位和参照基准（例如毫秒还是节拍、赫兹、字节）。适用时使用 SI 单位符号，并在数字和单位符号之间加一个空格（例如 10 ms）。

表示方式

任何不明显的编码或缩放方式（例如定点数的比例、Q 格式、拆分的整数和小数字段、字节序要求）。

所有权和生命周期

对于指针/缓冲区，说明由谁分配/释放，以及内存必须保持有效的时长。相关时注明所需的大小/对齐。

写作风格

简要描述应使用祈使语气（动词短语），而不是第三人称叙述。这样可以使 API 摘要保持一致、便于浏览。

  • 避免："Transmits data through a pipe."、"This function gets the device state."。

  • 推荐："Transmit data through a pipe."、"Get the device state."、"Initialize the subsystem."。

参数和成员的描述可以是不完整的句子，但应保持描述性，并避免重复参数/成员的名称。

组

组将相关符号组织成层级结构，帮助用户浏览 API。

  • 每个组只用 @defgroup 定义一次。

    • 所给的标题应是简短且具有描述性的组名。由于组本身就是将各种接口/API 归集在一起，标题中 不要 使用 "API" 或 "Interface"（或这些词的任何变体），否则会显得多余。

    • 组的简要描述不应只是换种说法复述其标题。

  • 组名使用 snake_case。

  • 使用 @ingroup 指定组所属的父组。

示例：

/**
 * @defgroup mqtt_socket MQTT Client library
 * @ingroup networking
 * @since 1.14
 * @version 0.8.0
 * @{
 */

 /* documented contents of the MQTT header file */

 /** @} */

备注

一个组可以属于多个父组，因此可以有多条 @ingroup 命令。例如，设备驱动模拟器通常同时出现在 "Emulator Interfaces" 和 "Device drivers" 两个组中。示例参见 i2c_emul_interface。

重要

没有父组的组会成为 API 概览 的顶层条目，而顶层分类被有意控制得很少。务必使用 @ingroup 为新组指定父组。

顶层条目的允许列表位于 doc/_doxygen/toplevel_groups.txt，并由 scripts/ci/doxygen_toplevel_groups.py 强制检查。添加新的顶层条目需要文档维护者批准。

API 版本管理

在组定义（@defgroup）上使用 @since 和 @version 记录 API 的历史和成熟度：

  • @since 表示引入该 API 的 Zephyr 版本（例如 @since 3.7）

  • @version 表示当前的 API 版本，遵循语义化版本规范

版本号反映了 API 概览 中所定义的 API 成熟度。

示例：

以下示例中的 API 在 Zephyr 1.14 中引入，当前版本为 0.8.0（不稳定）。
/**
 * @defgroup mqtt_socket MQTT Client library
 * @ingroup networking
 * @since 1.14
 * @version 0.8.0
 * @{
 */

 /* documented contents of the MQTT header file */

 /** @} */

文件

每个公共头文件的顶部都必须有一个 @file 块，位于 SPDX 许可证和版权声明之后。

@file 块也必须属于某个 Doxygen 组，通常是同一头文件中定义的组。这样，按文件浏览的用户可以方便地跳转到相关的组。

/**
 * @file
 * @brief Public API for the GPIO driver.
 * @ingroup gpio_interface
 */

类型定义

为 struct、enum、union 和 typedef 定义编写简要描述。

同时也要为每个成员（结构体字段、枚举值等）编写文档。当只提供简要描述且能放在一行内时，建议使用 /**< 尾随注释风格。

完整记录的枚举、结构体和 typedef 示例。
/** @brief Parity modes */
enum uart_config_parity {
     UART_CFG_PARITY_NONE,   /**< No parity */
     UART_CFG_PARITY_ODD,    /**< Odd parity */
     UART_CFG_PARITY_EVEN,   /**< Even parity */
     UART_CFG_PARITY_MARK,   /**< Mark parity */
     UART_CFG_PARITY_SPACE,  /**< Space parity */
};

/**
 * GPIO pin configuration.
 *
 * Specifies direction, pull resistor, and interrupt settings.
 */
struct gpio_config {
    uint32_t flags;    /**< Pin configuration flags. */
    gpio_pin_t pin;    /**< Pin number within the port. */
};

/**
 * @brief Identifies a set of pins associated with a port.
 *
 * The pin with index n is present in the set if and only if the bit
 * identified by (1U << n) is set.
 */
typedef uint32_t gpio_port_pins_t;

函数

参数

  • 按声明顺序使用 @param 记录参数

  • 对于函数会写入的指针，使用 @param[out]。

  • 对于函数既读取又写入的指针，使用 @param[in,out]。

  • 对于 const 指针和标量（隐含为仅输入），可以省略方向说明符。

返回值

  • 一般性描述（例如布尔值或计算得到的值）使用 @return <description>。

  • 具体的离散返回值（通常是错误码）使用 @retval <value> <description>，并从成功的情况开始（如适用）。<value> 必须作为第一个单词给出，后面跟描述（例如写 @retval -EINVAL Invalid arguments，而不是 @retval -EINVAL if invalid arguments）。

    备注

    由于同一个离散值可能因多种原因被返回，允许在多条 @retval 语句中使用相同的值。

示例：

完整记录的函数示例。
/**
 * @brief Write data to the TX queue from a provided buffer
 *
 * @param dev Pointer to the device structure for the driver instance.
 * @param buf Pointer to a buffer containing the data to transmit.
 * @param size Number of bytes to write. This value has to be equal or smaller
 *        than the size of the channel's TX memory block configuration.
 *
 * @retval 0 on success.
 * @retval -EIO The interface is not in READY or RUNNING state.
 * @retval -EBUSY Returned without waiting.
 * @retval -EAGAIN Waiting period timed out.
 * @retval -ENOMEM No memory in TX slab queue.
 * @retval -EINVAL Size parameter larger than TX queue memory block.
 */
int i2s_buf_write(const struct device *dev, void *buf, size_t size);

/**
 * @brief Add an application callback.
 *
 * @param port Pointer to the device structure for the driver instance.
 * @param callback A valid application's callback structure pointer.
 *
 * @return 0 on success, negative errno value on failure.
 * @retval -ENOSYS Driver does not implement the operation.
 */
int gpio_add_callback(const struct device *port, struct gpio_callback *callback);

/**
 * @brief Helper function for converting struct sensor_value to float.
 *
 * @param val A pointer to a sensor_value struct.
 * @return The converted value.
 */
static inline float sensor_value_to_float(const struct sensor_value *val)
{
    return (float)val->val1 + (float)val->val2 / 1000000;
}

宏

对于类函数宏，像函数一样记录其参数。

完整记录的类函数宏示例。
/**
 * @brief Get a node's (only) register block size
 *
 * Equivalent to DT_REG_SIZE_BY_IDX(node_id, 0).
 *
 * @param node_id node identifier
 * @return node's only register block's size
 */
#define DT_REG_SIZE(node_id) DT_REG_SIZE_BY_IDX(node_id, 0)

引用主文档

API 文档可以使用下述命令引用基于 Sphinx 的主文档中的内容。在生成的 API 文档页面中，这些引用会渲染为指回主文档相应页面的超链接。

@kconfig{<option>}

通过完整名称（包括 CONFIG_ 前缀）引用 Kconfig 选项。它是 kconfig:option 角色在 Doxygen 中的对应命令。

示例：@kconfig{CONFIG_GPIO}

@kconfig_regex{<regex>}

引用与某个正则表达式匹配的所有 Kconfig 选项，生成一个指向 Kconfig 搜索页面并预先填好该模式的链接。它是 kconfig:option-regex 角色在 Doxygen 中的对应命令。由于逗号在 Doxygen 命令中有特殊含义，必须用反斜杠转义。

示例：@kconfig_regex{CONFIG_SECURE_STORAGE_ITS_.*_CUSTOM}

@dtcompatible{<compatible>}

通过 compatible 字符串引用设备树绑定。它是 dtcompatible 角色在 Doxygen 中的对应命令。由于逗号在 Doxygen 命令中有特殊含义，必须用反斜杠转义。

示例：@dtcompatible{zephyr\,input-longpress}

@rstref{<target>} 或 @rstref{<text> <target>}

通过引用标签（或文档名）引用任意文档页面或章节，类似于 Sphinx 的 ref 角色。未提供自定义文字时，使用被引用页面或章节的标题作为链接文字。

示例：@rstref{zephyr_licensing} 或 @rstref{the licensing page <zephyr_licensing>}

构建文档时会检查这些引用：引用不存在的 Kconfig 选项、绑定或标签会导致文档构建警告。

备注

单独构建 Doxygen 文档（即不包含其余文档）时，这些命令会展开为纯文本。更多详情请参阅 文档生成。

引用 IETF RFC

@rfc{<number>} 或 @rfc{<number>,<anchor>}

通过编号引用 IETF RFC，并可选择指向其中的某个锚点。它是 rfc 角色在 Doxygen 中的对应命令，会渲染为指向 IETF Datatracker 上该 RFC 的超链接。

锚点会原样传递，因此可以指向 Datatracker 为该 RFC 定义的任何锚点，例如 section-3.1、appendix-B.1.2、figure-2 或 table-1。具体存在哪些锚点取决于 RFC 本身：只有从 XML 源文件渲染的 RFC 才会为图和表设置锚点。

逗号后面不要加空白字符：Doxygen 会将其保留为参数的一部分，最终出现在 URL 片段中。渲染出的链接文字看起来仍然正确，因此只有在点击链接时才会发现锚点失效。

示例：@rfc{7519}、@rfc{8613,section-3.1} 或 @rfc{8613,appendix-B.1.2}

隐藏内部细节

使用 @cond INTERNAL_HIDDEN / @endcond 在生成的文档中隐藏内部细节。

仍然可以选择为这些内部符号编写文档，为内部使用者提供有用的参考。

/** Timer structure.
 *
 * Opaque type for a timer object. All the fields in this structure are internal and should not
 * be accessed outside of kernel code.
 */
struct k_timer {
    /** @cond INTERNAL_HIDDEN */

    /* ... internal members ... */

    /** @endcond */
};

驱动后端 API

驱动子系统向应用程序公开公共 API，并向驱动实现者公开“后端”API。

虽然后端 API 并不打算由应用程序直接使用，但它仍然是子系统与驱动实现者之间的公共约定，因此必须有完善的文档。它通常包括驱动操作结构体、定义每个操作签名的 typedef，以及在某些情况下对驱动实现有用的其他辅助类型或宏。

后端 API 的 Doxygen 组

使用 @def_driverbackendgroup 创建一个子组，作为主 API 组的子级，包含与后端 API 相关的所有符号。该命令接受两个参数：后端 API 的可读名称（通常与父组相同）和父组标识符。

/**
 * @def_driverbackendgroup{Haptics,haptics_interface}
 * @{
 */

/* callback typedefs, driver ops struct, helpers ... */

/** @} */

驱动操作 typedef

为每个驱动操作定义一个 typedef。详细描述可以引用对应的公共 API 函数，因为两者的签名通常相似。

/**
 * @brief Set the haptic device to stop output.
 * See haptics_stop_output() for argument description.
 */
typedef int (*haptics_stop_output_t)(const struct device *dev);

驱动操作结构体

使用 @driver_ops{Name} 标注该结构体（其中 Name 与传给 @def_driverbackendgroup 的名称一致）。对每个成员，使用 @driver_ops_mandatory 或 @driver_ops_optional 表明驱动是否必须实现它，并使用 @copybrief 继承公共 API 函数的简要描述：

/**
 * @driver_ops{Haptics}
 */
__subsystem struct haptics_driver_api {
    /**
     * @driver_ops_mandatory @copybrief haptics_start_output
     */
    haptics_start_output_t start_output;
    /**
     * @driver_ops_mandatory @copybrief haptics_stop_output
     */
    haptics_stop_output_t stop_output;
    /**
     * @driver_ops_optional @copybrief haptics_register_error_callback
     */
    haptics_register_error_callback_t register_error_callback;
};

条件编译代码

为确保条件编译的代码出现在文档中，可以使用以下任一方法：

  1. 将控制该代码的 Kconfig 宏（CONFIG_...）添加到 doc/zephyr.doxyfile.in 中的 PREDEFINED 列表。这样在生成文档时，这段代码对 Doxygen 可见。

  2. 或者，也可以依靠 __DOXYGEN__ 宏使条件编译的代码对 Doxygen 可见，因为该宏由 Doxygen 自动定义。

struct coap_packet {
    uint8_t *data;  /**< User allocated buffer. */
#if defined(CONFIG_COAP_KEEP_USER_DATA) || defined(__DOXYGEN__)
    /**
     * Application-specific user data.
     * @kconfig_dep{CONFIG_COAP_KEEP_USER_DATA}
     */
    void *user_data;
#endif
};

Kconfig 依赖

@kconfig_dep 命令可用于记录某个 API 符号对用户可用所需的 Kconfig 选项。该命令可以带一个、两个或三个 Kconfig 选项。

例如，在某个 API 符号的 Doxygen 文档中添加 @kconfig_dep{CONFIG_PM,CONFIG_SMP}，生成的文档中就会包含一条注释，内容为："Available only when the following Kconfig options are enabled: CONFIG_PM, CONFIG_SMP."（仅在启用以下 Kconfig 选项时可用）。

在 coap_packet 的文档中可以看到 @kconfig_dep 的用法示例。
