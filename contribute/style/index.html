风格工具

Checkpatch

使用 Linux 内核中以 GPL 许可的工具 checkpatch 检查编码风格是否合规。

备注

checkpatch 目前无法在 Windows 上运行。

Checkpatch 位于 scripts 目录中。要在提交代码时调用它，请将文件 $ZEPHYR_BASE/.git/hooks/pre-commit 设为可执行，并编辑其内容为：

#!/bin/sh
set -e exec
exec git diff --cached | ${ZEPHYR_BASE}/scripts/checkpatch.pl -

如果不想在每次提交时都运行 checkpatch，也可以只在推送到 zephyr 仓库之前运行它。为此，请将文件 $ZEPHYR_BASE/.git/hooks/pre-push 设为可执行，并编辑其内容为：

#!/bin/sh
remote="$1"
url="$2"

z40=0000000000000000000000000000000000000000

echo "Run push hook"

while read local_ref local_sha remote_ref remote_sha
do
    args="$remote $url $local_ref $local_sha $remote_ref $remote_sha"
    exec ${ZEPHYR_BASE}/scripts/series-push-hook.sh $args
done

exit 0

如果想忽略 checkpatch 的判定结果，在报告了问题的情况下仍推送分支，可以在 git push 命令中添加 --no-verify 选项。

运行 checkpatch 的另一种方式是使用 check_compliance.py 脚本，它还会执行其他与风格和合规性相关的检查。

clang-format

clang-format 工具 配合仓库中提供的 .clang-format 配置文件，可以快速地将大量新源代码重新格式化为符合 Coding Style Guidelines 标准的代码。clang-format 已很好地集成到大多数编辑器中，也可以像下面这样手动运行：

clang-format -i my_source_file.c

clang-format 是 LLVM 的一部分，可以从该项目的 发布页面 下载。注意，如果你是 Linux 用户，你所用发行版的软件仓库中很可能提供了 clang-format 软件包。

当 Coding Style Guidelines 与代码格式化工具生成的格式存在差异时，以 Coding Style Guidelines 为准。如果格式化工具与指南之间存在歧义，可由维护者决定采用哪种风格。

dts-linter

dts-linter 可以快速地将大量设备树文件重新格式化为符合 Coding Style Guidelines 标准的格式。也可以像下面这样手动运行：

针对单个文件

npx --ignore-scripts --prefix ./scripts/ci dts-linter --format --file board.dts --file board_pinctrl.dtsi --patchFile diff.patch
git apply diff.patch

可以省略 --file，此时会格式化执行该命令的目录下的所有文件。也可以传入 --cwd 来设置工具查找文件的基础目录。该选项还用于使补丁文件中的路径成为相对路径。

也可以使用以下命令就地修复：

npx --ignore-scripts --prefix ./scripts/ci dts-linter --formatFixAll

编辑器集成

  • VS Code：从 VS Code Marketplace 或 Open VSIX 安装该扩展

  • 其他支持 LSP 客户端的编辑器：使用 devicetree-language-server devicetree-language-server

请务必遵循 设备树风格指南 的要求来正确配置编辑器。
