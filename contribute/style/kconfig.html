Kconfig 风格指南

本文档为在 Zephyr 项目中编写 Kconfig 文件提供风格指南。遵循这些指南可以确保整个代码库的一致性和可读性，使开发者更容易理解和维护配置选项。

以下各节给出了相关指南，并通过示例说明正确的 Kconfig 格式和命名约定。

基本格式规则

编写 Kconfig 文件时，请遵循以下基本格式规则：

  • 行长度：每行不超过 100 列。

  • 缩进：使用制表符缩进，但 help 条目的文本例外，它应缩进一个制表符再加两个空格。

  • 间距：选项声明之间留一个空行。

  • 注释：注释格式应为 # Comment，而不是 #Comment。

  • 条件块：在每个顶层 if 和 endif 语句的前后各插入一个空行。

  • 文件末尾：文件以恰好一个换行符结束。

关于 select 等语句的使用指导，请参阅 Kconfig 技巧与最佳实践 了解更多信息。

这些格式规则由 CI 中的 KconfigFormat 合规性检查强制执行。可以使用 scripts/kconfig/kconfig_style.py 脚本在本地检查 Kconfig 文件，它会报告所有风格问题（对于目录，会递归查找其中的 Kconfig 文件）：

./scripts/kconfig/kconfig_style.py path/to/Kconfig
./scripts/kconfig/kconfig_style.py drivers/sensor/

符号命名和结构

以下示例演示了正确的 Kconfig 符号命名和结构：

# Symbol to enable/disable the feature ("enabling symbol")
config ADC_AD405X
	bool "AD405X ADC driver"
	depends on DT_HAS_ADI_AD4052_ADC_ENABLED || DT_HAS_ADI_AD4050_ADC_ENABLED
	select SPI
	default y
	help
	  Enable ADC driver for AD405X.

# Symbol to enable/disable the feature ("enabling symbol")
menuconfig ADC_AD4114
	bool "AD4114 ADC driver"
	depends on DT_HAS_ADI_AD4114_ADC_ENABLED
	select SPI
	default y
	help
	  Enable the AD4114 ADC driver.

if ADC_AD4114

# Symbol to configure the behavior of the feature ("config symbol")
config ADC_AD4114_ACQUISITION_THREAD_STACK_SIZE
	int "Stack size for the data acquisition thread"
	default 512
	help
	  Size of the stack used for the internal data acquisition
	  thread.

# Symbol to configure the behavior of the feature ("config symbol")
config ADC_AD4114_ACQUISITION_THREAD_PRIO
	int "Priority for the data acquisition thread"
	default 0
	help
	  Priority level for the internal ADC data acquisition thread.

endif # ADC_AD4114

命名约定

  • 一般来说，与同一组件相关的符号应与其他符号区分开。这通常可以通过使用共同前缀来实现。该前缀可以是一个简单的关键字；对于驱动等情况，也可以由多个关键字组成，以便更加精确。

  • 共同前缀通常表示该符号所属的子系统或组件。

  • 启用符号的名称应由关键字组成，按从最一般到最具体的范围给出符号的上下文（例如 Driver Type -> Driver Name）。

  • 启用符号的提示文本应采用与符号名称本身相同的逻辑，但关键字顺序相反。

    • 遵循这种风格可以更方便地在界面中搜索符号，因为可以按范围关键字进行过滤。

  • 当启用符号依赖于某个设备树节点时，可以考虑依赖 自动创建的 DT_HAS_<node>_ENABLED 符号。

  • 基于设备树节点的 compatible 构建复杂表达式时，请使用 自动定义的 DT_COMPAT_VND_DEVICE，而不要手动定义一个值等于 vnd,device 的变量。

按子目录划分的具体格式：

  • 驱动（/drivers）：符号使用 {Driver Type}_{Driver Name} 格式，提示文本使用 {Driver Name} {Driver Type} driver 格式。

  • 传感器（/drivers/sensors）：符号使用 SENSOR_{Sensor Name} 格式，提示文本使用 {Sensor Name} {Sensor Type} sensor driver 格式。

  • 架构（/arch）：许多符号在各架构之间共享。创建新符号之前，请检查其他架构中是否已存在类似的符号。

  • 示例（/samples）：符号使用 SAMPLE_ 前缀，以免与外部模块冲突。

  • 测试（/tests）：符号使用 TEST_ 前缀，以免与外部模块冲突。

  • 开发板（/boards）：符号使用 BOARD_ 前缀。

  • SoC（/soc）：为符号选用最合适的基础前缀：如果涉及某个 SoC 厂商的多个系列，使用 SOC_VENDOR_{SoC vendor}_；如果涉及整个 SoC 系列（family），使用 SOC_FAMILY_{SoC family}_；如果涉及整个 SoC 子系列（series），使用 SOC_SERIES_{SoC series}_；如果涉及某个特定 SoC，使用 SOC_{SoC}_。关于这些术语的详细说明及其必须来自何处，请参阅 SoC 移植指南。这样可以避免与其他厂商和外部模块冲突。

示例

备注

为简洁起见，以下示例只显示符号行和提示文本行。

驱动示例：

config ADC_AD405X
	bool "AD405X ADC driver"

config CAN_MAX32
	bool "MAX32 CAN driver"

config I2C_EMUL
	bool "I2C emulator driver"

传感器示例：

config SENSOR_BMP581
	bool "BMP581 barometric pressure sensor driver"

config SENSOR_TMP007
	bool "TMP007 infrared thermopile sensor driver"

config SENSOR_LM75
	bool "LM75 temperature sensor driver"

示例程序示例：

config SAMPLE_LOCK
	bool "Locking feature"

config SAMPLE_TEMPERATURE_READINGS
	bool "Fetch readings from temperature sensor"

测试示例：

config TEST_ITERATIONS
	int "Number of times test should run"
	default 3

SoC 示例：

# This assumes the following soc.yml file for the vendor "hotel":
# family:
#   - name: alpha
#     series:
#       - name: foxtrot
#         socs:
#           - name: charlie

config SOC_VENDOR_HOTEL_FLASH_PREFETCH
	bool "Flash prefetch"

config SOC_FAMILY_ALPHA_JTAG_LOCK
	bool "Lock JTAG access"

config SOC_SERIES_FOXTROT_EMULATE_POWER_OFF
	bool "Emulate power off mode"

config SOC_CHARLIE_IMAGE_HEADER
	bool "Include image header"

配置符号的组织

当某个功能使用配置符号来配置其行为时：

  • 使用 menuconfig 而不是 config 来定义启用该功能的符号（即使该配置符号没有提示文本）。

  • 将这些配置符号包含在一个 if 语句中，以声明它们对启用符号的依赖（这样会在界面中自动将这些符号归到启用符号之下）。

  • 为配置符号加上启用符号的名称作为前缀，以提供范围和上下文。

  • 在配置符号的提示文本中，描述该符号配置的内容，不要重复范围关键字，因为界面中的分组已经提供了这一上下文。

文件组织

组织 Kconfig 文件时：

  • 将 Kconfig 文件放在它所配置的源文件附近。

  • 处理较大的 Kconfig 文件时（例如包含许多配置符号），可以考虑将其中（部分）符号归入一个单独的文件，并使用 source 指令导入，以提高可读性。
