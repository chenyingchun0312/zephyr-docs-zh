修改其他开发者所做的贡献

场景

我们鼓励 Zephyr 贡献者和协作者以评审者的身份参与 PR（拉取请求），以便补丁能在原始 PR 中获得批准并合并到 Zephyr 的主分支。PR 的作者负责在评审过程中修订自己的原始提交。

然而，有时贡献者可能需要修改其他 Zephyr 贡献者所提交的 PR 中的补丁。例如以下情况：

  • 开发者将其他贡献者提交的提交 cherry-pick 到自己的 PR 中，以便：

    • 整合某个停滞 PR 中的有用内容，或者

    • 作为更大补丁的一部分，将这些内容合并到项目的主分支

  • 开发者向其他贡献者打开的分支或 PR 推送，以便：

    • 协助更新 PR，使补丁能合并到项目的主分支

    • 推动停滞的 PR 完成，使其能够被合并

公认的规则

打算 cherry-pick 并可能修改其他贡献者所发送补丁的开发者应当：

  • 在自己的 PR 中说明为何要 cherry-pick 这些补丁，而不是协助在原始 PR 中合并这些补丁，并且

  • 邀请这些补丁的原作者参与自己 PR 的评审。

打算向其他 Zephyr 贡献者的分支或 PR 强制推送（force-push）的开发者，应在该 PR 中说明推送及修改现有补丁的原因（例如说明这样做是为了在 PR 作者无法完成时推动 PR 评审完成）。

备注

开发者应尽量将上述做法限于被认定为 停滞 的 PR。关于如何认定 PR 已停滞，请阅读 开发流程和工具

如果对原始补丁做了实质性修改，开发者可以：

  • （首选）联系原作者，请其确认可以在保留原始 sign-off 行和作者身份的情况下合并修改后的补丁，或者

  • 将修改后的补丁作为 自己 的工作提交（即使用 自己 的 sign-off 行和作者身份）。在这种情况下，开发者应在提交信息中注明所提交工作基于的原始来源（例如注明原始 PR 编号）。

备注

如果贡献者不希望其他 Zephyr 开发者在其原始分支或 PR 中修订自己的补丁，应取消勾选 “Allow Edits By Maintainers" 复选框。
