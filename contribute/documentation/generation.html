文档生成

本文介绍如何在本地系统上生成 Zephyr 项目的文档，所用的文档源文件与生成在线文档（https://docs.zephyrproject.org）所用的相同。

文档概述

Zephyr 项目的内容使用 reStructuredText 标记语言（文件扩展名为 .rst）及 Sphinx 扩展编写，并由 Sphinx 处理，生成格式化的独立网站。开发者既可以直接查看 .rst 标记文件的原始内容，也可以生成 HTML 内容，在自己工作站上用网页浏览器直接查看。同样的 .rst 内容也会输入到 Zephyr 项目公开网站的文档区（使用不同的主题）。

关于 reStructuredText 和 Sphinx 的详细信息，可以在各自的网站上查阅。

项目文档包含以下内容：

  • 用于生成 https://docs.zephyrproject.org 网站上文档的 reStructuredText 源文件。大多数 reStructuredText 源文件位于 /doc 目录中，其余的则存放在代码源码树中相应组件的附近（例如 /samples 和 /boards）

  • 由 Doxygen 生成的材料，用于创建所有 API 相关文档，这些文档同样发布在 https://docs.zephyrproject.org

  • 根据源码树中的 Kconfig 文件，由脚本生成的内核配置选项材料

reStructuredText 文件由 Sphinx 文档系统处理，并使用 Doxygen 生成的 API 材料。在本地生成文档还需要其他工具，详见以下各节。

安装文档处理工具

我们的文档处理流程已在以下环境中测试通过：

  • Doxygen 1.17.0 版

  • Graphviz 2.43

  • Latexmk 4.83 版

  • 仓库文件 doc/requirements.txt 中列出的所有 Python 依赖项

要安装文档工具，请先按照 入门指南 中的说明安装 Zephyr，然后按下文所述安装仅在生成文档时才需要的其他工具：

所有 Linux 发行版都需要安装构建文档所需的 Python 依赖项：

pip install -U -r ~/zephyrproject/zephyr/doc/requirements.txt

在 Ubuntu Linux 上：

sudo apt-get install --no-install-recommends doxygen graphviz librsvg2-bin \
texlive-latex-base texlive-latex-extra latexmk texlive-fonts-recommended imagemagick

在 Fedora Linux 上：

sudo dnf install doxygen graphviz texlive-latex latexmk \
texlive-collection-fontsrecommended librsvg2-tools ImageMagick

在 Clear Linux 上：

sudo swupd bundle-add texlive graphviz ImageMagick

在 Arch Linux 上：

sudo pacman -S graphviz doxygen librsvg texlive-core texlive-bin \
texlive-latexextra texlive-fontsextra imagemagick

安装构建文档所需的 Python 依赖项：

pip install -U -r ~/zephyrproject/zephyr/doc/requirements.txt

使用 brew 和 tlmgr 安装这些工具：

brew install doxygen graphviz mactex librsvg imagemagick
tlmgr install latexmk
tlmgr install collection-fontsrecommended

安装构建文档所需的 Python 依赖项：

pip install -U -r %HOMEPATH$\zephyrproject\zephyr\doc\requirements.txt

以 管理员 身份打开 cmd.exe 窗口，运行以下命令：

choco install doxygen.install graphviz strawberryperl miktex rsvg-convert imagemagick

备注

在 Windows 上，Sphinx 可执行文件 sphinx-build.exe 位于 Python 安装路径下的 Scripts 文件夹中。根据 Python 的安装方式，可能需要将该文件夹添加到 PATH 环境变量中。如有需要，请按照 Windows Python Path 中的说明添加。

文档展示主题

Sphinx 支持通过主题轻松定制生成文档的外观。替换主题文件后重新执行 make html，输出的布局和样式就会改变。read-the-docs 主题已在入门指南的 获取 Zephyr 并安装 Python 依赖项 步骤中安装。

运行文档处理工具

在克隆的 Zephyr 项目 git 仓库中，/doc 目录包含所有 .rst 源文件、辅助工具以及用于在本地生成 Zephyr 项目技术文档的 Makefile。假设本地 Zephyr 项目副本位于主目录下的 zephyr 文件夹中，在本地生成 HTML 内容的命令如下：

# On Linux/macOS
cd ~/zephyrproject/zephyr/doc
# On Windows
cd %userprofile%\zephyrproject\zephyr\doc

# Use cmake to configure a Ninja-based build system:
cmake -GNinja -B_build .

# Enter the build directory
cd _build

# To generate HTML output, run ninja on the generated build system:
ninja html
# If you modify or add .rst files, run ninja again:
ninja html

# To generate PDF output, run ninja on the generated build system:
ninja pdf

警告

文档构建系统会在构建目录中为生成文档所用的每个 .rst 文件创建副本，同时复制这些 .rst 文件所引用的依赖文件。

这意味着 Sphinx 的警告和错误指向的是这些 副本，而不是 Zephyr 中受版本控制的原始文件。注意不要误改错误信息中提到的文件副本，因为这些修改不会被保存。

根据开发系统的不同，收集并生成 HTML 内容最多需要 15 分钟。完成后，可以用浏览器打开 doc/_build/html/index.html 查看 HTML 输出；如果生成了 PDF，该文件位于 doc/_build/latex/zephyr.pdf。

如果想从头构建文档，只需删除构建文件夹的内容，然后重新运行 cmake 和 ninja。

备注

如果在文档中添加或删除了文件，需要重新运行 CMake。

在 Unix 平台上，可以使用便捷的 doc/Makefile 直接在该目录下构建文档：

cd ~/zephyrproject/zephyr/doc

# To generate HTML output
make html

# To generate PDF output
make pdf

开发者模式文档构建

在对文档进行重大修改和测试时，我们提供了一个选项，可以临时用占位内容替代自动生成的设备树绑定文档，从而加快文档构建过程。

要启用此模式，请在调用 cmake 时设置以下选项:

-DDT_TURBO_MODE=1

另一个通常耗时较长的步骤是为每块开发板生成所支持功能的列表。可以在调用 cmake 时设置以下选项来禁用该步骤:

-DHW_FEATURES_TURBO_MODE=1

使用以下目标调用 make，可以在不包含上述两项功能的情况下构建文档:

cd ~/zephyrproject/zephyr/doc

# To generate HTML output without detailed Devicetree bindings documentation
# and supported features index
make html-fast

在编写叙述性页面时，如需更快地迭代，还可以使用其他 SKIP_* 选项跳过整类自动生成的内容：

SKIP_DOXYGEN

跳过运行 Doxygen 和构建 C API 参考。

SKIP_KCONFIG

跳过生成 Kconfig 选项参考及其搜索页面。

SKIP_EXTERNAL_CONTENT

跳过复制在 doc/ 文件夹之外维护的开发板、示例和代码片段页面（即 boards、samples 和 snippets 文件夹中的内容）。

每个选项都可以单独启用:

make html SKIP_DOXYGEN=1

make html-minimal 目标在 html-fast 的基础上组合了以上所有选项，是预览叙述性页面修改的最快方式:

make html-minimal

警告

被跳过的生成器原本会生成的内容将被替换为占位内容，指向这些内容的交叉引用会显示为纯文本，相关警告也会被抑制。因此，使用任何 SKIP_* 选项的构建只适合本地预览：它不能用于验证交叉引用，其输出也不得发布。

在编写特定厂商开发板的文档时，还可以将所支持功能列表的生成限制在部分开发板厂商范围内。可以在调用 cmake 时设置以下选项来实现:

-DHW_FEATURES_VENDOR_FILTER=vendor1,vendor2

此选项也可以与 make 包装脚本一起使用:

cd ~/zephyrproject/zephyr/doc

# To generate HTML output with supported features limited to a subset of vendors
make html HW_FEATURES_VENDOR_FILTER=vendor1,vendor2

在本地查看生成的文档

可以用 Python 在本地托管生成的 HTML 文档，以便用网页浏览器查看：

$ python3 -m http.server -d _build/html

备注

WSL2 用户可能需要显式地将地址绑定到 127.0.0.1，才能从宿主机访问：

$ python3 -m http.server -d _build/html --bind 127.0.0.1

另外，也可以使用 make html-live（或 make html-live-fast、make html-live-minimal）命令构建文档。该命令会构建文档、在本地托管，并监视文档目录的变化。检测到变化时，它会自动重新构建文档并刷新托管的文件。

单独构建 Doxygen 文档

doxygen 构建目标可用于只构建 Doxygen（API）文档，这比构建完整的文档集快得多:

cd ~/zephyrproject/zephyr/doc
make doxygen

输出位于 _build/doxygen/html。

doxygen-xml 目标构建相同的文档，但只启用 XML 输出，输出位于 _build/doxygen-xml/xml。

在常规文档构建中，Doxygen 注释中指向主文档的引用（例如 @kconfig{}、@dtcompatible{} 或 @rstref{}，参见 引用主文档）会自动解析为超链接。在单独的 Doxygen 构建中，由于其余文档不可用，这些引用会保留为纯文本。

将外部 Doxygen 项目链接到 Zephyr

基于 Zephyr 功能构建、并希望在 Doxygen 中（通过 @ref）引用 Zephyr 文档的外部项目，可以使用导出于 zephyr.tag 的标签文件

下载后，可以在自定义的 doxyfile.in 中按如下方式使用该标签文件:

TAGFILES = "/path/to/zephyr.tag=https://docs.zephyrproject.org/latest/doxygen/html/"

更多信息请参阅 Doxygen External Documentation。
