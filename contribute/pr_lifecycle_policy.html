PR（拉取请求）生命周期政策

本政策使处于打开状态的 PR 列表集中于正在积极推进、并且有现实合并途径的贡献。

目标

  • 让处于打开状态的 PR 对贡献者和维护者而言保持在可管理的范围内。

  • 将评审精力优先投入到正在推进的修改上。

  • 为草稿 PR 和不活跃的 PR 提供明确的期望。

适用范围

本政策适用于仓库中的所有 PR，包括草稿 PR。

定义

活跃 PR

有实质性进展的 PR，例如有新提交、对评审的回复，或针对所要求修改的更新。

草稿 PR

为进行中的工作及获取早期反馈而打开的 PR。

停滞 PR

在不活跃期限内没有实质性活动的 PR。

因不活跃而关闭的 PR

因不活跃、已被取代或没有明确合并途径而关闭的 PR。

对草稿 PR 的期望

  • 草稿 PR 应包含清晰的问题陈述、当前状态和已知的欠缺之处。

  • 草稿 PR 应在 30 天内转为待评审（ready-for-review）状态。

  • 如果草稿 PR 连续 30 天不活跃，可能会被标记为 stale（停滞），并发布一条提醒。

  • 如果在停滞通知发出后再过 7 天仍没有实质性进展，该 PR 可能会被关闭。

对待评审 PR 的期望

  • 作者应在 21 天内回复评审反馈。

  • 如果待评审 PR 连续 30 天没有实质性活动，可能会被标记为 stale（停滞）。

  • 如果在停滞通知发出后 7 天内没有实质性更新，该 PR 可能会被关闭。

  • 如果阻塞性反馈超过 45 天仍未解决，且没有提供具体计划，该 PR 可能会被关闭。

哪些算作实质性活动

实质性活动的例子包括：

  • 处理评审反馈的新提交。

  • 具体的技术回复和后续更新。

  • 对 PR 做出实质改变的重大修订更新。

通常不算作实质性活动的例子包括：

  • 没有任何技术更新、仅用于催促的评论。

  • 没有实质性修改的简单变基（rebase）。

例外情况

以下 PR 可以免于因不活跃而被自动关闭：

  • 安全关键的修复。

  • 发布阻塞项（release blocker）。

  • 明确在等待外部依赖、并关联了跟踪条目的 PR。

获得豁免的 PR 仍需至少每 30 天更新一次状态。

被取代的 PR

当工作被另一个 PR 取代时：

  • 将旧 PR 以“已被取代”为由关闭。

  • 链接到取而代之的 PR。

  • 添加一条简短的总结评论以保留上下文。

重新打开因不活跃而关闭的 PR

因不活跃而关闭 PR 是一项管理措施，目的是让打开的 PR 列表保持在可管理的范围内。这并不代表拒绝该贡献。

在以下情况下，因不活跃而关闭的 PR 可以重新打开：

  • 作者发布了更新后的计划。

  • 之前的阻塞性反馈已得到处理。

  • 维护者确认评审可以继续。

鼓励贡献者在能够提供实质性更新时随时重新打开 PR。

职责

贡献者应当：

  • 保持 PR 描述为最新。

  • 及时回复评审评论。

  • 草稿 PR 一旦可以评审，就将其转为待评审（ready-for-review）状态。

更多指导请参阅 贡献者行为期望 文档。

维护者应当：

  • 一致地做出标记停滞和关闭的决定。

  • 提供明确的阻塞性反馈。

  • 关闭时给出明确的理由和重新打开的途径。

更多指导请参阅 维护者职责 文档。
