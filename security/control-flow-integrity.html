控制流完整性

控制流完整性（Control Flow Integrity，CFI）是一种信息安全特性，它确保程序的控制流沿预先定义的路径执行，防止攻击者将执行流转向恶意代码。CFI 在防御控制流劫持攻击方面尤其有用，例如面向返回编程（ROP）和面向跳转编程（JOP）。

CFI 在运行时验证程序的控制流，确保函数调用和返回都指向合法目标。通常通过对代码插桩来实现：插入的检查会验证控制流是否遵循程序控制流图所定义的预期路径。

前向边与返回边

在 CFI 中，控制流边可以分为两类：

  1. 前向边：表示控制从一个函数流向另一个函数，例如函数调用。通常会验证前向边，以确保调用目标是程序中的合法函数。

  2. 返回边：表示从函数返回到调用者。验证返回边是为了确保返回地址合法，并且对应一个有效的调用点。

前向边可以通过编译器插桩来支持，插入的检查会验证函数调用的目标是否有效。返回边可以通过维护影子栈（shadow stack）或其他机制来支持，以确保返回地址合法。

Zephyr 支持维护影子栈，可通过 CONFIG_HW_SHADOW_STACK 启用。启用后，内核会使用 K_THREAD_HW_SHADOW_STACK_DEFINE 等宏，配合其他与线程栈相关的宏，为线程使用的影子栈提供存储区域。通常，应用程序只需启用 CONFIG_HW_SHADOW_STACK（以及相关选项，例如 CONFIG_HW_SHADOW_STACK_PERCENTAGE_SIZE 和 CONFIG_HW_SHADOW_STACK_MIN_SIZE）即可启用影子栈支持，之后内核会自动管理每个线程的影子栈。

实现细节

K_THREAD_HW_SHADOW_STACK* 系列宏只对影子栈参数做最基本的设置，然后调用特定于架构的 ARCH_THREAD_HW_SHADOW_STACK* 宏完成实际设置。

硬件支持

CFI 虽然可以用软件实现，但硬件支持可以大幅提升其效果和性能。目前，Zephyr 支持 Intel 控制流强制技术（Control-flow Enforcement Technology，CET），它为 CFI 提供基于硬件的支持。

Intel CET

Intel 控制流强制技术（CET）是一组硬件特性，通过为 CFI 提供支持来增强应用程序的信息安全。CET 包含两个主要组件：

  1. 影子栈（Shadow Stack）：该特性为返回地址单独维护一个栈，确保返回地址无法被篡改。函数返回时，返回地址从影子栈中弹出，并与常规栈中的返回地址进行比较，从而为防御控制流劫持多提供一层保护。

  2. 间接分支跟踪（Indirect Branch Tracking，IBT）：该特性跟踪间接分支（例如函数指针），确保它们只跳转到代码中的有效位置，防止攻击者通过 ROP 等技术将执行流重定向到任意代码。

这两个特性分别提供返回边和前向边的验证。在受支持的硬件上，可以使用 CONFIG_HW_SHADOW_STACK Kconfig 选项在 Zephyr 中启用影子栈支持。要启用 IBT，请使用 CONFIG_X86_CET_IBT。

由于 IBT 实际上由编译器实现，因此需要工具链支持。目前，可以使用 Zephyr SDK 的 x86 工具链构建支持 IBT 的应用程序。但是，该工具链中的预编译产物（例如 libc 和 libgcc）没有启用 IBT。因此，对于 libc，需要将其作为模块构建，例如使用 CONFIG_PICOLIBC_USE_MODULE。对于其他部分，则需要使用定制的工具链。

Intel CET 的限制

目前，在后台自动创建的影子栈位于全局命名空间中。因此，不能 重复使用线程栈名称，即使在不同的编译单元之间也不行。

ARM 指针认证与分支目标识别

ARM 平台通过指针认证（Pointer Authentication，PAC）和分支目标识别（Branch Target Identification，BTI）提供基于硬件的 CFI 特性，Cortex-M 和 ARM64（Cortex-A/R）架构均支持这些特性：

  1. 指针认证（PAC）：使用密码学签名对返回地址和其他指针进行签名。返回地址压入栈时，会使用每个线程独有的密钥对其签名。返回之前会验证签名，以确保返回地址未被篡改。这可以防御面向返回编程（ROP）攻击。ARMv8.1-M Mainline（Cortex-M）以及 ARMv8.3-A 及更高版本（ARM64）支持该特性。

  2. 分支目标识别（BTI）：使用特殊的 BTI 着陆点（landing pad）指令标记合法的间接分支目标。处理器会验证间接分支只落在以 BTI 指令标记的有效目标上。这可以防御面向跳转编程（JOP）攻击。ARMv8.1-M Mainline（Cortex-M）以及 ARMv8.5-A 及更高版本（ARM64）支持该特性。

这两个特性分别提供返回边和前向边的验证。PAC 和 BTI 可以通过 ARM_PACBTI 菜单启用。可用选项包括 CONFIG_ARM_PACBTI_STANDARD（同时启用 PAC 和 BTI）、CONFIG_ARM_PACBTI_PACRET（仅 PAC）、CONFIG_ARM_PACBTI_BTI（仅 BTI）以及其他变体。这两个特性既可以单独使用，也可以组合使用，以实现全面的控制流完整性。

与 x86 CET IBT 一样，这些特性需要编译器支持以及对 C 库进行相应的插桩。PAC 要求函数使用相应的签名和验证指令，而 BTI 要求所有合法的分支目标都包含 BTI 着陆点指令。工具链自带的预编译 C 库通常缺少这种插桩。

要支持 BTI，C 库必须使用 -mbranch-protection 标志编译，以便在所有函数中加入 BTI 着陆点。因此，使用任何启用 BTI 的选项时，只能使用 CONFIG_MINIMAL_LIBC，或通过 CONFIG_PICOLIBC_USE_MODULE 作为模块构建的 picolibc。BTI 不支持工具链自带的 Newlib。

PAC 的要求没有那么严格，因为它主要影响函数的序言和尾声；但为了获得最佳的信息安全效果，建议构建支持 PAC 的 C 库。
