CVE 2020-10019

Zephyr USB DFU 中的缓冲区溢出漏洞允许通过 USB 连接的主机造成可能的远程代码执行。

此问题已在 v1.14.2、v2.2.0 和 v2.1.1 版本中修复。

  • PR23460 fix for 1.14.x

  • PR23457 fix for 2.1.x

  • PR23190 fix in 2.2.0

CVE 2020-10021

USB 大容量存储在大小未对齐时存在越界写

USB 大容量存储（Mass Storage）的 memoryWrite 处理函数在大小未对齐时存在越界写。

参见 NCC-ZEP-024、NCC-ZEP-025、NCC-ZEP-026

此问题已在 v1.14.2 和 v2.2.0 版本中修复。

  • PR23240 fix for v2.2.0

CVE 2020-10022

UpdateHub 模块将可变长度的哈希字符串复制到固定大小的数组中

从 UpdateHub 服务器接收到的格式错误的 JSON 载荷可能在 Zephyr OS 中引发内存损坏。最好的情况下会导致拒绝服务，最坏的情况下会导致代码执行。

参见 NCC-ZEP-016

此问题已通过以下针对 main 分支、v2.1.0 派生分支和 v2.2.0 派生分支的 PR 修复。

  • Zephyr project bug tracker ZEPSEC-28

  • PR24154 fix for main

  • PR24065 fix for branch from v2.1.0

  • PR24066 fix for branch from v2.2.0

CVE 2020-10059

UpdateHub 模块显式禁用了 TLS 验证

UpdateHub 模块禁用了 DTLS 对端检查，因此可能遭受中间人攻击。由于固件镜像要求具备有效签名，这一风险有所缓解。但是，不进行对端检查时使用 DTLS 没有任何意义。

参见 NCC-ZEP-018

此问题已通过一个针对 Zephyr main 分支的 PR 修复。

CVE 2020-10060

UpdateHub 可能解引用未初始化的指针

在 updatehub_probe 中，JSON 解析完成后，紧接着在两个不同的位置访问了输出结构体中的 objects[1]。如果 JSON 中的元素少于两个，此访问将引用未初始化的栈内存。这可能导致崩溃、拒绝服务，或可能导致信息泄露。

建议在修复发布之前禁用 updatehub。

参见 NCC-ZEP-030

此问题已通过一个针对 Zephyr main 分支的 PR 修复。

  • Zephyr project bug tracker ZEPSEC-37

  • PR27865 fix on main (to be fixed in v2.4.0)

  • PR27865 fix for v2.3.0

  • PR27865 fix for v2.2.0

  • PR27865 fix for v2.1.0

CVE 2020-10062

MQTT 中的数据包长度解码错误

CVE：Zephyr 项目 MQTT 数据包长度解码器中的差一错误（off-by-one）可能导致内存损坏，并可能导致远程代码执行。NCC-ZEP-031

MQTT 数据包头部的长度字段可以是 1 到 4 个字节。代码中的差一错误可能导致它被解释为 5 个字节，从而引起整数溢出，导致内存损坏。

此问题已在 main 分支中修复，将包含在 v2.3 中。

  • Zephyr project bug tracker ZEPSEC-84

  • commit 11b7a37d for v2.3

  • NCC-ZEP report (NCC-ZEP-031)

CVE 2020-13603

mempool 中可能存在溢出

  • Zephyr 另外提供了预构建的 'malloc' 包装函数。

  • 'malloc' 函数是 'sys_mem_pool_alloc' 函数的包装

  • sys_mem_pool_alloc 以不安全的方式分配 'size + WB_UP(sizeof(struct sys_mem_pool_block))' 大小的内存。

  • 请求非常大的 size 值会导致内部整数回绕。

  • 整数回绕导致只分配了很小的内存，但分配却返回成功。

  • 例如：调用 malloc(0xffffffff) 会成功分配 7 个字节。

  • 这会导致堆溢出。

  • Zephyr project bug tracker ZEPSEC-111

  • PR31796 fix for v2.4

  • PR32808 fix for v1.4
