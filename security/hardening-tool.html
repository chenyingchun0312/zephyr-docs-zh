加固工具

产品发布之前，务必确保软件尽可能安全。这个过程称为“加固”（hardening），即增强系统的信息安全，使其免受潜在威胁和漏洞的影响。

从宏观上看，加固 Zephyr 应用程序可以分为两个方面：

  1. 禁用可能导致信息安全漏洞的特性和编译标志（例如，确保没有使用“实验性”特性，禁用通常用于调试目的的特性，例如断言、Shell 等）。

  2. 启用有助于提高信息安全的可选特性（例如栈哨兵、硬件栈保护等）。其中一些特性可能依赖于硬件。

为了简化这一过程，Zephyr 提供了一个 加固工具，它根据 加固数据库 分析应用程序的配置；加固数据库是由 Zephyr 信息安全工作组（Security Working Group）整理的一组建议。该工具检查构建目标中的 Kconfig 选项，针对信息安全相关的选项给出有针对性的调整建议，并说明每条建议背后的理由。

用法

使用 west：

# From the root of the zephyr repository
west build -b reel_board samples/hello_world
west build -t hardenconfig

使用 CMake 和 ninja：

# From the root of the zephyr repository
# Use cmake to configure a Ninja-based buildsystem:
cmake -Bbuild -GNinja -DBOARD=reel_board samples/hello_world

# Now run the build tool on the generated build system:
ninja -Cbuild hardenconfig

除了基于数据库的检查之外，该工具还会标记所有已启用、且在 Kconfig 中本身被标记为实验性、已弃用或不安全的选项（即 select 了 CONFIG_EXPERIMENTAL、CONFIG_DEPRECATED 或 CONFIG_NOT_SECURE 的选项）。

配置档（profile）

建议按 配置档 分组。代码树中提供了两个配置档：

base

每个量产构建都应满足的基线加固要求：启用可用的内存保护和漏洞利用缓解特性，并禁用本质上不安全的选项。

strict（默认）

包含 base 中的全部内容，此外还要求移除会扩大攻击面或泄露内部状态的调试、跟踪和可观测性特性（日志、Shell、断言等）。有些产品确实有理由保留其中一部分特性；如果你的情况如此，请改用 base 配置档进行检查：

west build -t hardenconfig -- -DHARDENCONFIG_PROFILE=base

配置选项

该工具通过 CMake 缓存变量（如上所示，在 west build 命令行中的 -- 之后传入）或同名的环境变量进行控制：

选项

作用

HARDENCONFIG_PROFILE

用于检查的加固配置档。默认值：strict。

HARDENCONFIG_SHOW_ALL

设置后，除了未通过的选项外，还会列出通过的选项和不适用的选项。

HARDENCONFIG_STRICT

设置后，只要有任何检查未通过，就以非零代码退出。可用于将 CI 流水线或发布流程的放行条件设为加固报告无问题。

HARDENCONFIG_JSON

文件路径，结果会额外以 JSON 格式写入该文件，供脚本和仪表板使用。

HARDENCONFIG_EXTRA_SOURCES

以分号分隔的附加加固数据库文件列表（见下文）。

加固数据库

数据库采用分布式组织，每条规则都与它所加固的代码放在一起，并由该代码的维护者审查：

  • scripts/kconfig/hardening.yaml：中心文件，由信息安全工作组负责。它定义加固 配置档，以及针对顶层 Kconfig 文件中所定义符号的规则。

  • 放在相关 Kconfig 文件旁边的 hardening.yaml 片段（例如 subsys/bluetooth/hardening.yaml 或 arch/x86/hardening.yaml），其中只包含规则。工具会在 arch/、boards/、drivers/、kernel/、lib/、modules/、share/、soc/ 和 subsys/ 下自动发现这些片段。在两个文件中定义同一个符号会报错，在片段中定义配置档也会报错。

所有文件都使用相同的 JSON 模式（schema）scripts/schemas/hardening-schema.yaml。每条规则以其所适用的 Kconfig 符号为键，推荐一个确切的值或一个整数约束：

rules:
  BOOT_BANNER:
    value: n
    rationale: |
      The boot banner prints the exact Zephyr version to the console,
      letting anyone with console access fingerprint the firmware and
      match it against known vulnerabilities for that release.
    references: [CWE-200]

  STACK_POINTER_RANDOM:
    min: 100
    rationale: |
      Randomizing each thread's initial stack pointer makes stack
      addresses unpredictable. The offset is taken out of the thread's
      own stack, which keeps the recommended value small.
    references: [CWE-121]

贡献一条新规则，就是将其添加到相关 Kconfig 文件旁边的 hardening.yaml 片段中（如果该子系统还没有片段，则新建一个），并且必须提供 rationale，这一要求由模式强制执行。持续集成还会验证：每个文件都能被解析并符合模式；每条规则都引用一个已存在的 Kconfig 符号，且其值与该符号的类型一致；没有规则被重复定义；没有文件看起来像是命名错误的片段。这样，条目就不会在无人察觉的情况下过时或加载失败。

rationale 是报告展示给读者的内容，会被折行显示在一个较窄的列中，而且通常是读者唯一的判断依据。请用一两句话、以现在时态、以该特性为主语，说明该选项在信息安全方面的后果：

value: n

说明启用该选项所造成的暴露面，以及在相关时说明谁能够接触到它：“详细的调制解调器日志会转储与调制解调器交换的全部数据，其中可能包括 APN 设置、PIN 码和服务器地址等凭据。”

value: y

说明它所抵御的攻击，或者不启用它会带来什么后果，选择读起来更清楚的一种写法。

value: 0、min 和 max

说明其他值会输出什么或无法防止什么，以及边界值本身起什么作用。

不要：

  • 说明该选项应该用在哪里。产品是否应当接受该后果由配置档决定；应写“……泄露内部传输状态和地址”，而不是“……只应用于开发构建”。

  • 声称一个不采取进一步操作就无法完全实现的效果。例如，某个选项可以启用生成去除符号信息（stripped）的二进制文件，但确保部署的正是该文件则是用户的责任。

  • 复述报告中已经显示的某一列。在“0 会完全禁用随机化；建议至少使用 100 字节的随机偏移”中，后半句就是“推荐值”（Recommended）列的内容。

  • 重复另一条规则的措辞。可能在同一份报告中同时未通过的两条规则，读起来应当有足够的差别，让读者能够区分它们。

如果某个选项只有在另一条至少覆盖相同配置档的 n 规则已被违反时才能启用，就不要为它添加 n 规则。例如，一旦 CONFIG_SHELL 本身被标记，再为某个 Shell 命令模块添加规则就是多余的，CI 会拒绝这样的规则。而为一个仅仅 select 了某个被标记选项的选项添加规则则不算多余：它指出了用户实际需要修改的地方。

规则不带适用条件：某条建议是否适用于给定目标，已经在 Kconfig 本身中体现（依赖关系、硬件支持），而且该工具会将不适用于当前目标的选项报告为不适用，而不是报告为未通过。

在代码树之外扩展数据库

产品团队可以通过 HARDENCONFIG_EXTRA_SOURCES 在代码树内数据库之上叠加自己的建议。每个附加文件都使用相同的模式，可以定义新的配置档（可选择扩展代码树内的配置档）和新的规则，也可以覆盖代码树内的规则。重新定义已有的配置档会被拒绝，因此无论产品在其上叠加什么内容，代码树内的配置档始终保持本文所记录的含义：

profiles:
  acme-production:
    extends: strict
    description: ACME product security policy.

rules:
  MY_VENDOR_DEBUG_INTERFACE:
    value: n
    profiles: [acme-production]
    rationale: |
      The vendor debug interface bypasses the product's authentication.

west build -t hardenconfig -- \
  -DHARDENCONFIG_EXTRA_SOURCES=/path/to/acme-hardening.yaml \
  -DHARDENCONFIG_PROFILE=acme-production
