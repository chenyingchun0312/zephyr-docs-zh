应用程序版本管理

Zephyr 为应用程序提供了一套版本管理系统，它基于 Zephyr 自身的版本管理系统构建。应用程序可以借此定义一个版本文件，并让应用程序（或模块）代码包含自动生成的文件并访问其中的信息，就像访问内核版本一样。这些版本信息可在多个范围内使用，包括：

  • 代码（C/C++）

  • Kconfig

  • CMake

  • Shell

这使它成为一套非常灵活的应用程序生命周期管理系统。此外，在构建面向受支持的引导加载程序（例如 MCUboot）的应用程序时，也可以使用它，自动用正确的应用程序版本对镜像签名，无需任何手动签名步骤。

VERSION 文件

应用程序版本信息按应用程序分别设置在名为 VERSION 的文件中，该文件必须放在应用程序的根目录，即 CMakeLists.txt 文件所在的位置。这是一个简单的文本文件，包含各个版本信息字段，每个字段占一行。基本的 VERSION 文件结构如下：

VERSION_MAJOR =
VERSION_MINOR =
PATCHLEVEL =
VERSION_TWEAK =
EXTRAVERSION =

下面介绍每个字段及其支持的值。Zephyr 将每个数值字段的值限制为一个字节（注意，根据版本的用途，可能还有进一步的限制，例如引导加载程序可能只支持其中部分字段，或者可能限制字段的最大值）：

使用 CMake 配置应用程序时，版本文件会被自动处理，并且每次版本变更时都会自动检查，因此修改此文件后无需手动重新运行 CMake。

以下各节的示例基于如下 VERSION 文件：

VERSION_MAJOR = 1
VERSION_MINOR = 2
PATCHLEVEL = 3
VERSION_TWEAK = 4
EXTRAVERSION = unstable.5

应用程序构建版本

应用程序构建版本 是一个独立的、更具动态性的概念，与 VERSION 文件中描述的版本不同：它用于表示构建时应用程序源代码的当前状态，从源代码版本控制元数据中提取。

默认情况下，如果应用程序位于 Git 仓库中，其内容由在应用程序目录中运行命令 git describe --abbrev=12 --always 的输出生成。生成的字符串包含最近的标签、自该标签以来的提交数以及缩写的提交哈希。

将 APP_BUILD_VERSION 直接设置为所需的字符串值，即可覆盖这一默认行为。可以在应用程序的 CMakeLists.txt 文件中设置，也可以在调用 CMake 时在命令行上设置，例如通过 cmake -DAPP_BUILD_VERSION="v3.3.0-18-g2c85d92" ..。

在支持 MCUboot 的应用程序中使用

只要目标应用程序配置为支持 MCUboot 并生成了签名镜像，就无需对其做任何额外配置，版本信息会自动包含在镜像数据中。

配置了 shell 接口时，可以使用以下命令获取应用程序版本信息：

app build-version

APP_BUILD_VERSION
