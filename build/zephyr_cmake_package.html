Zephyr CMake 包

Zephyr CMake package 为创建基于 Zephyr 的应用程序提供了一种便捷的方式。

备注

应用程序类型 一节介绍了本页中使用的应用程序类型。

Zephyr CMake 包确保 CMake 能自动选择一个 Zephyr 安装来构建应用程序，无论它是 Zephyr 仓库应用程序、Zephyr 工作区应用程序 还是 Zephyr 独立应用程序。

开发基于 Zephyr 的应用程序时，开发者只需在应用程序的 CMakeLists.txt 文件开头写上 find_package(Zephyr)。

要使用 Zephyr CMake 包，必须先将其导出到 CMake user package registry。这意味着在 CMake 用户包注册表中创建一个指向当前 Zephyr 安装的引用。

在 Linux 中，CMake 用户包注册表位于：

~/.cmake/packages/Zephyr

在 macOS 中，CMake 用户包注册表位于：

~/.cmake/packages/Zephyr

在 Windows 中，CMake 用户包注册表位于：

HKEY_CURRENT_USER\Software\Kitware\CMake\Packages\Zephyr

Zephyr CMake 包使 CMake 能够自动找到 Zephyr 根目录（Zephyr base）。必须导出一个或多个 Zephyr 安装。在开发或测试 Zephyr 独立应用程序、使用厂商分支的 Zephyr 工作区应用程序等场景下，导出多个 Zephyr 安装可能会很有用。

导出 Zephyr CMake 包（使用 west）

如果使用 west 安装 Zephyr，建议使用 west zephyr-export 导出 Zephyr。

导出 Zephyr CMake 包（不使用 west）

使用以下命令将 Zephyr CMake 包导出到 CMake 用户包注册表：

cmake -P <PATH-TO-ZEPHYR>/share/zephyr-package/cmake/zephyr_export.cmake

这会将当前的 Zephyr 导出到 CMake 用户包注册表。

Zephyr 根目录环境设置

Zephyr CMake 包的查找功能允许通过环境变量显式指定 Zephyr 根目录。

为此，请使用以下 find_package() 语法：

find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})

该语法指示 CMake 先使用 Zephyr 根目录环境设置 ZEPHYR_BASE 查找 Zephyr，然后再使用常规的查找路径。

Zephyr CMake 包的查找顺序

如果查找时不使用 Zephyr 根目录环境设置，则会使用符合以下条件的 Zephyr 安装：

  • Zephyr 仓库应用程序会使用它所在的那个 Zephyr。例如：

    <projects>/zephyr-workspace/zephyr
└── samples
    └── hello_world

    在这个例子中，hello_world 将使用 <projects>/zephyr-workspace/zephyr。

  • Zephyr 工作区应用程序会使用位于同一工作区中的 Zephyr。例如：

    <projects>/zephyr-workspace
├── zephyr
├── ...
└── my_applications
     └── my_first_app

    在这个例子中，my_first_app 将使用 <projects>/zephyr-workspace/zephyr，因为这个 Zephyr 与该 Zephyr 工作区应用程序位于同一工作区中。

备注

如果工作区是使用 west 安装的，Zephyr 工作区的根目录与 west topdir 相同

  • Zephyr 独立应用程序会使用在 CMake 用户包注册表中注册的 Zephyr。例如：

    <projects>/zephyr-workspace-1
└── zephyr                       (Not exported to CMake)

<projects>/zephyr-workspace-2
└── zephyr                       (Exported to CMake)

<home>/app
├── CMakeLists.txt
├── prj.conf
└── src
    └── main.c

    在这个例子中，只有 <projects>/zephyr-workspace-2/zephyr 被导出到 CMake 包注册表，因此 Zephyr 独立应用程序 <home>/app 将使用这个 Zephyr。

    如果用户想用 <projects>/zephyr-workspace-1/zephyr 测试该应用程序，可以使用 Zephyr 根目录环境设置，即在运行 CMake 之前设置 ZEPHYR_BASE=<projects>/zephyr-workspace-1/zephyr。

    备注

    首次调用 CMake 时选定的 Zephyr 包会用于之后的所有构建。要更换 Zephyr 包，例如要使用 Zephyr 根目录环境设置测试应用程序，必须先进行一次全新构建（参见 重新构建应用程序）。

Zephyr CMake 包版本

编写应用程序时，可以指定构建该应用程序必须使用的 Zephyr 版本号 x.y.z。

指定版本对 Zephyr 独立应用程序尤其有用，因为它可以确保应用程序使用不低于某个最低版本的 Zephyr 构建。

当系统中有多个 Zephyr 安装时，它还能帮助 CMake 选择正确的 Zephyr 进行构建。

例如：

find_package(Zephyr 2.2.0)
project(app)

这会要求 app 至少使用 Zephyr 2.2.0 构建。CMake 会搜索所有已导出的候选项，以找到符合该版本条件的 Zephyr 安装。

因此可以同时存在多个 Zephyr 安装，并让 CMake 根据所提供的版本号自动在它们之间进行选择，详见 CMake package version。

例如：

<projects>/zephyr-workspace-2.a
└── zephyr                       (Exported to CMake)

<projects>/zephyr-workspace-2.b
└── zephyr                       (Exported to CMake)

<home>/app
├── CMakeLists.txt
├── prj.conf
└── src
    └── main.c

在这种情况下，系统中安装了两个已发布的 Zephyr 版本，各自位于自己的工作区中。工作区 2.a 和 2.b 与 Zephyr 版本相对应。

要确保 app 至少使用 2.a 版本构建，可以使用以下 find_package 语法：

find_package(Zephyr 2.a)
project(app)

注意，2.a 和 2.b 都满足这一要求。

如果需要，CMake 还支持关键字 EXACT，以确保使用确切的版本。在这种情况下，应用程序的 CMakeLists.txt 可以这样写：

find_package(Zephyr 2.a EXACT)
project(app)

如果找不到满足所需版本的 Zephyr，例如应用程序指定了

find_package(Zephyr 2.z)
project(app)

则会打印类似下面的错误：

Could not find a configuration file for package "Zephyr" that is compatible
with requested version "2.z".

The following configuration files were considered but not accepted:

  <projects>/zephyr-workspace-2.a/zephyr/share/zephyr-package/cmake/ZephyrConfig.cmake, version: 2.a.0
  <projects>/zephyr-workspace-2.b/zephyr/share/zephyr-package/cmake/ZephyrConfig.cmake, version: 2.b.0

备注

为 Zephyr 仓库应用程序和 Zephyr 工作区应用程序指定版本号也有好处。在这些情况下指定版本，可以确保只有当 Zephyr 仓库或工作区匹配时，应用程序才会被构建。这有助于避免在工作区只更新了一部分时意外进行构建。

多个 Zephyr 安装（Zephyr 工作区）

有时需要试用新的 Zephyr 版本，同时保持工作区中现有的 Zephyr 不变。

或者在同一工作区中同时拥有上游 Zephyr、厂商专用 Zephyr 和自定义 Zephyr。

例如：

<projects>/zephyr-workspace
├── zephyr
├── zephyr-vendor
├── zephyr-custom
├── ...
└── my_applications
     └── my_first_app

在这种布局下，find_package(Zephyr) 按以下优先顺序选择要使用的 Zephyr：

  • 项目名称：zephyr

  • 将 Zephyr 项目按字典序排序后的第一个项目，在本例中为：

    • zephyr-custom

    • zephyr-vendor

这意味着 my_first_app 将使用 <projects>/zephyr-workspace/zephyr。

可以在应用程序中指定 Zephyr 优先列表。

Zephyr 优先列表可以这样指定：

set(ZEPHYR_PREFER "zephyr-custom" "zephyr-vendor")
find_package(Zephyr)

project(my_first_app)

ZEPHYR_PREFER 是一个列表，可以包含多个 Zephyr。如果列表中指定的某个 Zephyr 在系统中找不到，它会被直接忽略，find_package(Zephyr) 会继续查找下一个候选项。

这样就可以临时创建一个新的 Zephyr 发布版本进行测试，而不影响当前的 Zephyr。测试完成后，直接删除 zephyr-test 目录即可。这样的 CMakeLists.txt 可能如下所示：

set(ZEPHYR_PREFER "zephyr-test")
find_package(Zephyr)

project(my_first_app)

Zephyr 构建配置 CMake 包

有两个 Zephyr 构建配置包，可以用更通用的方式控制 Zephyr 中的构建设置。这两个包是：

  • ZephyrBuildConfiguration：适用于工作区中的所有 Zephyr 应用程序

  • ZephyrAppConfiguration：只适用于当前正在构建的应用程序

它们类似于可用于设置 环境变量 的每用户 .zephyrrc 文件，但设置的是 CMake 变量。它们还可以通过项目仓库在所有用户之间自动共享构建配置，并支持更高级的用例，例如加载额外的 CMake 样板代码。

Zephyr 构建配置 CMake 包会在 Zephyr 样板代码中加载，时机是在初始属性和 ZEPHYR_BASE 定义之后、CMake 代码执行之前。先包含 ZephyrBuildConfiguration，再包含 ZephyrAppConfiguration。这意味着如有需要，应用程序专用包可以覆盖工作区设置。这样，Zephyr 构建配置 CMake 包就可以设置或扩展以下属性：DTS_ROOT、BOARD_ROOT、TOOLCHAIN_ROOT / 其他工具链设置、固定的覆盖文件，以及任何其他可控制的属性。它还允许包含额外的样板代码。

要提供 ZephyrBuildConfiguration 或 ZephyrAppConfiguration，请分别创建 ZephyrBuildConfig.cmake 和/或 ZephyrAppConfig.cmake，并将它们放在适当的位置。CMake 的 find_package 机制会按以下步骤查找这些文件。其他默认的 CMake 包查找路径和提示均被禁用，并且这些包没有实现版本检查。这也意味着这些包不能安装到 CMake 包注册表中。查找步骤如下：

  1. 如果设置了 ZephyrBuildConfiguration_ROOT（或相应的 ZephyrAppConfiguration_ROOT），则在该前缀路径中查找。如果找到匹配的文件，就执行该文件。如果没有找到匹配的文件，转到第 2 步。

  2. 在 ${ZEPHYR_BASE}/../*（或相应的 ${APPLICATION_SOURCE_DIR}）中查找。如果找到匹配的文件，就执行该文件。如果没有找到匹配的文件，则终止查找。

建议将这些文件放在第 2 步中的默认路径下，但借助 <PackageName>_ROOT 变量，也可以灵活地将它们放在任何位置。这对独立应用程序尤其必要，因为对于独立应用程序，ZephyrBuildConfiguration 的默认路径通常不起作用。在这种情况下，可以 在 find_package(Zephyr ...) 之前 设置 <PackageName>_ROOT 变量，方式可以是 CMake 命令行、环境变量，或通过 -C 命令行选项指定的 CMake 缓存初始化文件。

备注

<PackageName>_ROOT 变量以及默认路径都只是查找路径的前缀。这些前缀会与额外的路径后缀组合，共同构成实际的查找路径。任何符合 CMake package search procedure 的组合都是有效的，都能正常工作。

如果想完全禁用对这些包的查找，可以使用 CMake 的特殊变量 CMAKE_DISABLE_FIND_PACKAGE_<PackageName>。只需将 CMAKE_DISABLE_FIND_PACKAGE_ZephyrBuildConfiguration 或 CMAKE_DISABLE_FIND_PACKAGE_ZephyrAppConfiguration 设置为 TRUE 即可禁用相应的包。

目录结构示例如下：

<projects>/zephyr-workspace
├── zephyr
├── ...
├── manifest repo (can be named anything)
│    └── cmake/ZephyrBuildConfig.cmake
├── ...
└── zephyr application
     └── share/zephyrapp-package/cmake/ZephyrAppConfig.cmake

下面是一个 ZephyrBuildConfig.cmake 示例。

# ZephyrBuildConfig.cmake sample code

# To ensure final path is absolute and does not contain ../.. in variable.
get_filename_component(APPLICATION_PROJECT_DIR
                       ${CMAKE_CURRENT_LIST_DIR}/../../..
                       ABSOLUTE
)

# Add this project to list of board roots
list(APPEND BOARD_ROOT ${APPLICATION_PROJECT_DIR})

# Default to GNU Arm Embedded toolchain if no toolchain is set
if(NOT ENV{ZEPHYR_TOOLCHAIN_VARIANT})
    set(ZEPHYR_TOOLCHAIN_VARIANT gnuarmemb)
    find_program(GNU_ARM_GCC arm-none-eabi-gcc)
    if(NOT ${GNU_ARM_GCC} STREQUAL GNU_ARM_GCC-NOTFOUND)
        # The toolchain root is located above the path to the compiler.
        get_filename_component(GNUARMEMB_TOOLCHAIN_PATH ${GNU_ARM_GCC}/../.. ABSOLUTE)
    endif()
endif()

Zephyr CMake 包源代码

share/zephyr-package/cmake 中的 Zephyr CMake 包源代码包含供 CMake find_package 函数使用的 CMake 配置包。

其中还包含将 Zephyr 导出为 CMake 配置包的代码。

下面概述该目录中的文件：

ZephyrConfigVersion.cmake

Zephyr 包版本文件。CMake 调用此文件来判断该安装是否满足用户调用 find_package(Zephyr ...) 时指定的要求。它还负责检测仅限 Zephyr 仓库或工作区的安装。

ZephyrConfig.cmake

Zephyr 包文件。对于满足用户调用 find_package(Zephyr ...) 时所指定要求的包，CMake 会调用此文件。该文件负责引入样板代码。

zephyr_package_search.cmake

用于检测 Zephyr 仓库和工作区候选项的公共文件。ZephyrConfigVersion.cmake 和 ZephyrConfig.cmake 使用它作为公共代码。

zephyr_export.cmake

参见 导出 Zephyr CMake 包（不使用 west）。
