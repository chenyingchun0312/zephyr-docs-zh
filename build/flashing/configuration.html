烧录配置

Zephyr 支持为烧录运行器（runner，由 west flash 调用）设置配置，用于定制烧录开发板时各命令的使用方式。该配置用于 Sysbuild（系统构建） 项目，可以为一组开发板目标配置命令的执行时机。例如：多核 SoC 可能希望 --erase 参数在该 SoC 的所有核中只使用一次，这样可以避免在一次 west flash 调用中执行多次擦除任务，否则可能会错误地清除正在烧录的其他镜像所使用的存储器。

优先级

烧录配置是唯一的，只会从一个位置读取。该配置可以位于以下文件中，按优先级从高到低排列：

  • soc.yml（位于 SoC 目录中）

  • board.yml（位于开发板目录中）

配置

在 yml 文件中通过 runners 映射来应用配置，该映射只包含一个 run_once 子项，其中是一个命令映射，命令的写法与传给烧录运行器时相同（例如 --reset），每个命令后跟一个列表，指定该命令的各项设置（这些设置按烧录运行器以及限定符/开发板分组）。命令通过 runners 列表值指定其适用的运行器：如果适用于所有运行器，可以写 all；否则必须使用运行器专用名称列出其适用的每个运行器。开发板目标组通过 groups 键指定，其值是一个开发板目标集合的列表。开发板目标采用正则表达式匹配：对于 soc.yml 文件，每组开发板目标必须放在 qualifiers 键中（只允许对开发板限定符进行正则表达式匹配，这些条目中必须省略开发板名称）；对于 board.yml 文件，每组开发板目标必须放在 boards 键中，这些列表包含构成单个组的匹配项。最后一个参数 run 可以设为 first，表示该命令在每组开发板目标的第一个镜像烧录过程中执行一次；或设为 last，表示该命令在每组开发板目标的最后一个镜像烧录时执行一次。

下面是一个 soc.yml 的烧录配置示例。在该示例中，对于使用 nRF5340 SoC 应用核或网络核的任何开发板目标，--recover 命令只会使用一次，并且只有在相应核的所有镜像都烧录完成后，才会复位网络核或应用核。

runners:
  run_once:
    '--recover':
      - run: first
        runners:
          - nrfjprog
        groups:
          - qualifiers:
              - nrf5340/cpunet
              - nrf5340/cpuapp
              - nrf5340/cpuapp/ns
    '--reset':
      - run: last
        runners:
          - nrfjprog
          - jlink
        groups:
          - qualifiers:
              - nrf5340/cpunet
          - qualifiers:
              - nrf5340/cpuapp
              - nrf5340/cpuapp/ns
      # Made up non-real world example to show how to specify different options for different
      # flash runners
      - run: first
        runners:
          - some_other_runner
        groups:
          - qualifiers:
              - nrf5340/cpunet
          - qualifiers:
              - nrf5340/cpuapp
              - nrf5340/cpuapp/ns

用法

烧录非 sysbuild 应用程序时，烧录运行器支持的命令可以照常使用，不会应用“只执行一次”配置。烧录包含多个镜像的 sysbuild 项目时，会应用烧录运行器的“只执行一次”配置。

例如，为 nrf5340dk 构建 SMP server 示例，该构建会将 MCUboot 作为第二个镜像包含进来：

cmake -GNinja -Sshare/sysbuild/ -Bbuild -DBOARD=nrf5340dk/nrf5340/cpuapp -DAPP_DIR=samples/subsys/mgmt/mcumgr/smp_svr
cmake --build build

构建完成后，连接 nrf5340dk，可以使用以下命令将两个应用程序烧录到开发板上，并且只会在烧录第一个镜像时执行一次设备恢复操作：

west flash --recover

如果在没有该烧录配置的情况下运行上述命令，恢复过程会执行两次，设备将无法启动。
