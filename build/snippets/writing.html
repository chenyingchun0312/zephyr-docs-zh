基础知识

代码片段使用名为 snippet.yml 的 YAML 文件定义。

snippet.yml 文件包含代码片段的名称以及其他构建系统设置，如下所示：

name: snippet-name
# ... build system settings go here ...

构建系统设置放在文件中的其他键里，详见本页后文。

只要设置出现在相同的键下，就可以组合使用。例如，可以像这样组合代码片段专用的设备树覆盖文件和 .conf 文件：

name: foo
append:
  EXTRA_DTC_OVERLAY_FILE: foo.overlay
  EXTRA_CONF_FILE: foo.conf

此外，代码片段也可以像下面这样应用于 sysbuild 配置：

name: foo
append:
  SB_EXTRA_CONF_FILE: sb.conf
  EXTRA_CONF_FILE: app.conf

命名空间

在代码片段中编写设备树覆盖文件时，为节点标签、节点名称等取名时请使用 snippet_<name> 或 snippet-<name> 作为命名空间前缀，以避免命名空间冲突。

例如，如果代码片段名为 foo-bar，请这样编写设备树覆盖文件：

chosen {
        zephyr,baz = &snippet_foo_bar_dev;
};

snippet_foo_bar_dev: device@12345678 {
        /* ... */
};

代码片段的存放位置

构建系统会在以下位置查找代码片段：

  1. 在 CMake 变量 SNIPPET_ROOT 所配置的目录中。其中始终包括 zephyr 仓库（因此 snippets/ 始终是代码片段的来源之一）。

    可以在 CMake 阶段手动添加其他目录。

    该变量是一个以空白或分号分隔的目录列表，这些目录中可以包含代码片段定义。

    对于列表中的每个目录，如果其中存在名为 snippets/ 的子目录，构建系统就会在该子目录下查找 snippet.yml 文件。

    例如，如果 SNIPPET_ROOT 设置为 /foo;/bar，构建系统会在以下子目录下查找 snippet.yml 文件：

    • /foo/snippets/

    • /bar/snippets/

    snippet.yml 文件可以嵌套在这些位置下的任意层级。

  2. 在任何其 module.yml 文件提供了 snippet_root 设置的 模块 中。

    例如，在名为 baz 的 zephyr 模块中，可以在 module.yml 文件里添加：

    settings:
  snippet_root: .

    这样，baz/snippets 中的所有 snippet.yml 文件都会被构建系统自动发现，就像 baz 的路径出现在 SNIPPET_ROOT 中一样。

处理顺序

代码片段按照它们在 SNIPPET 变量中列出的顺序处理；如果使用 west，则按照 -S 参数的顺序处理。

要在 foo 之后应用 bar：

cmake -Sapp -Bbuild -DSNIPPET="foo;bar" [...]
cmake --build build

使用 west 也可以达到同样的效果：

west build -S foo -S bar [...] app

当多个代码片段设置了同一项配置时，最终配置中采用的是最后处理的代码片段所设置的值。

例如，在上面的示例中，如果 foo 设置了 CONFIG_FOO=1，而 bar 设置了 CONFIG_FOO=2，那么由于 bar 在 foo 之后处理，最终配置将是 CONFIG_FOO=2。

这一原则同时适用于 Kconfig 片段（.conf 文件）和设备树覆盖文件（.overlay 文件）。

设备树覆盖文件（.overlay）

下面的 snippet.yml 将 foo.overlay 添加到构建中：

name: foo
append:
  EXTRA_DTC_OVERLAY_FILE: foo.overlay

foo.overlay 的路径相对于包含 snippet.yml 的目录。也可以以列表形式提供多个 .overlay 文件：

name: foo
append:
  EXTRA_DTC_OVERLAY_FILE:
    - foo.overlay
    - bar.overlay

.conf 文件

下面的 snippet.yml 将 foo.conf 添加到构建中：

name: foo
append:
  EXTRA_CONF_FILE: foo.conf

foo.conf 的路径相对于包含 snippet.yml 的目录。也可以以列表形式提供多个 .conf 文件。

Sysbuild .conf 文件

下面的 snippet.yml 将 foo.conf 添加到 sysbuild 配置中：

name: foo
append:
  SB_EXTRA_CONF_FILE: foo.conf

foo.conf 的路径相对于包含 snippet.yml 的目录。也可以以列表形式提供多个 sysbuild .conf 文件。

DTS_EXTRA_CPPFLAGS

下面的 snippet.yml 向构建中添加 DTS_EXTRA_CPPFLAGS CMake 缓存变量：

name: foo
append:
  DTS_EXTRA_CPPFLAGS: -DMY_DTS_CONFIGURE

添加这些标志可以控制设备树文件的内容。

开发板专用设置

可以编写只适用于某些开发板的设置。

这里介绍的设置是在适用于所有开发板的代码片段设置 之外额外 应用的。（这类似于：一个同时具有 prj.conf 和 boards/foo.conf 文件的应用程序，在为开发板 foo 构建时，会在构建中同时使用这两个 .conf 文件，而不是只使用 boards/foo.conf。）

按名称

name: ...
boards:
  bar: # settings for board "bar" go here
    append:
      EXTRA_DTC_OVERLAY_FILE: bar.overlay
  baz: # settings for board "baz" go here
    append:
      EXTRA_DTC_OVERLAY_FILE: baz.overlay

上面的示例在为开发板 bar 构建时使用 bar.overlay，在为 baz 构建时使用 baz.overlay。

按正则表达式

可以用斜杠（/）将开发板名称括起来，从而用 CMake syntax 的正则表达式匹配名称。正则表达式必须匹配完整的开发板名称。

例如：

name: foo
boards:
  /my_vendor_.*/:
    append:
      EXTRA_DTC_OVERLAY_FILE: my_vendor.overlay

上面的示例在为开发板 my_vendor_board1 或 my_vendor_board2 构建时使用设备树覆盖文件 my_vendor.overlay。为 another_vendor_board 或 x_my_vendor_board 构建时则不会使用该覆盖文件。

开发板版本

还支持针对开发板版本的专用配置，它会在通用文件之后应用：

name: foo
boards:
  bar:
    append:
      # Base file will be applied first
      EXTRA_DTC_OVERLAY_FILE: first.overlay
    revisions:
      "0.7.0":
        append:
          # Will be applied on top of common board file
          EXTRA_DTC_OVERLAY_FILE: extra_0_7_0.overlay

上面的示例会对 bar 开发板的所有版本使用 first.overlay，并且在为 bar 开发板的 0.7.0 版本（bar@0.7.0）构建时，还会包含 extra_0_7_0.overlay。
