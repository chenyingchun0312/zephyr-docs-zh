sysbuild_extensions

Sysbuild 的 CMake 扩展命令。

此模块定义用于描述 sysbuild 配置的命令：哪些镜像参与构建、如何配置这些镜像，以及它们的配置和烧录顺序。

下文记录的命令可在任何参与 sysbuild 构建的应用程序或 Zephyr 模块的 sysbuild.cmake 文件中使用。

此处未记录的命令由 sysbuild 自身使用，可能会在不事先通知的情况下被移除、重命名或改作他用。

  • 为镜像设置 Kconfig 值

sysbuild_get(<variable> IMAGE <image> [VAR <image-variable>] <KCONFIG|CACHE>)

从镜像中读取 CMake 缓存变量或 Kconfig 设置。

只有在镜像完成配置后，sysbuild 才能读取该镜像，例如在 sysbuild 模块 的 CMake 后置钩子中读取。

如果提供了 VAR，则查找作为参数给出的名称；如果未提供 VAR，则提供的 <variable> 名称既用于查找，也用于返回值。

结果将通过 <variable> 返回。

<variable>

用于返回值的变量。如果未提供 VAR，它也用作查找的变量名。

IMAGE <image>

要从中读取变量的镜像名称。

VAR <image-variable>

要查找的变量名称。

KCONFIG

表示应获取 Kconfig 设置的标志。

CACHE

表示应获取 CMake 缓存变量的标志。

用法示例：

# Look up PROJECT_NAME from the CMake cache of `my_sample` and return it
# in the local variable `PROJECT_NAME`.
sysbuild_get(PROJECT_NAME IMAGE my_sample CACHE)

# Same lookup, but returned in `my_sample_PROJECT_NAME`.
sysbuild_get(my_sample_PROJECT_NAME IMAGE my_sample VAR PROJECT_NAME CACHE)

# Look up the Kconfig setting CONFIG_FOO of `my_sample`.
sysbuild_get(my_sample_CONFIG_FOO IMAGE my_sample VAR CONFIG_FOO KCONFIG)
ExternalZephyrProject_Add(APPLICATION <name> SOURCE_DIR <dir> [BOARD <board> [BOARD_REVISION <revision>]] [APP_TYPE <MAIN|BOOTLOADER|FIRMWARE_LOADER>] [BUILD_ONLY <bool>] )

将一个基于 Zephyr 的构建系统纳入多镜像构建系统。

APPLICATION <name>

应用程序名称。该名称也会用作应用程序的构建目录名。

SOURCE_DIR <dir>

应用程序的源目录。

BOARD <board>

构建该应用程序时使用 <board>，而不是用户定义的 BOARD。

BOARD_REVISION <revision>

为该应用程序使用 <board> 的 <revision> 版本。仅在同时提供 BOARD 时有效。

APP_TYPE <MAIN|BOOTLOADER|FIRMWARE_LOADER>

应用程序类型。

MAIN 表示此应用程序是主应用程序，除多镜像构建标志外，用户定义的设置会原样传递给它。例如，-DCONF_FILE=<files> 会不加修改地传递给主应用程序。

BOOTLOADER 表示此应用程序是引导加载程序。

FIRMWARE_LOADER 表示此应用程序是 MCUboot 的固件加载器镜像。

BUILD_ONLY <bool>

将该应用程序标记为仅构建。如果 <bool> 求值为真，则此应用程序不参与烧录和调试。

完整示例参见 向 sysbuild 添加 Zephyr 应用程序。

ExternalZephyrVariantProject_Add(APPLICATION <name> SOURCE_APP <name> [SNIPPET <snippet>] [EXTRA_DTC_OVERLAY_FILE <file>] [EXTRA_CONF_FILE <file>] [BUILD_ONLY <bool>] )

将现有的基于 Zephyr 的构建系统复制一份并按指定修改纳入多镜像构建系统。

此命令不会创建 ExternalZephyrProject_Add() 所添加的额外构建目标，例如 <app>_menuconfig。

备注

必须为变体镜像添加 CONF_FILE、EXTRA_CONF_FILE、EXTRA_DTC_OVERLAY_FILE 或 SNIPPET，否则该镜像无效，配置镜像时会产生致命错误。

APPLICATION <name>

应用程序名称。该名称也会用作应用程序的构建目录名。

SOURCE_APP <name>

用作复制来源的现有镜像名称。

SNIPPET <snippet>

要为变体镜像应用的默认代码片段列表。

EXTRA_DTC_OVERLAY_FILE <file>

要为变体镜像应用的默认额外设备树覆盖文件列表。

EXTRA_CONF_FILE <file>

要为变体镜像应用的默认额外 Kconfig 片段列表。

BUILD_ONLY <bool>

将该应用程序标记为仅构建。如果 <bool> 求值为真，则此应用程序不参与烧录和调试。

sysbuild_cache_set(VAR <variable> [APPEND [REMOVE_DUPLICATES]] <value>)

设置一个 sysbuild 缓存变量，之后各镜像都可以访问它。

结果将通过 <variable> 返回。

VAR <variable>

CMake 缓存中的变量名称。

APPEND

如果指定，则将提供的数据以列表形式追加到现有值之后。

REMOVE_DUPLICATES

如果指定，则在存入缓存之前移除列表中的重复项。

<value>

要设置或更新的值。

用法示例：

# Add `battery` to the `ATTRIBUTES` list in the CMake cache, removing
# any duplicates from the list.
sysbuild_cache_set(VAR ATTRIBUTES APPEND REMOVE_DUPLICATES battery)

为镜像设置 Kconfig 值

以下命令会向 <image> 添加一行 Kconfig 片段。sysbuild.cmake 文件应通过这些命令来配置其添加的镜像。

收集到的片段会作为强制输入配置传递给镜像，因此最后应用，并优先于镜像自身的 Kconfig 片段。关于它们与 SB_CONFIG_ 选项的关系，参见 Kconfig 命名空间。

set_config_bool(<image> <setting> <value>)

如果 <value> 求值为真，则将布尔型 Kconfig 选项设为 y，否则设为 n。

set_config_string(<image> <setting> <value>)

将字符串型 Kconfig 选项设为 <value>。

set_config_int(<image> <setting> <value>)

将 int 或 hex 型 Kconfig 选项设为 <value>。

用法示例：

set_config_bool(${DEFAULT_IMAGE} CONFIG_BOOTLOADER_MCUBOOT y)
set_config_string(${DEFAULT_IMAGE} CONFIG_MCUBOOT_SIGNATURE_KEY_FILE "${keyfile}")
set_config_int(mcuboot CONFIG_LOG_MAX_LEVEL 2)
sysbuild_add_subdirectory(<source_dir> [<binary_dir>])

添加一个子目录，并递归处理其添加的 sysbuild 镜像。

此命令扩展了 add_subdirectory，会对通过 <source_dir> 添加的 sysbuild 镜像进行额外的递归处理。

退出 <source_dir> 后，此命令会遍历到目前为止添加的每个镜像，如果找到其 sysbuild.cmake 文件，则用 include() 包含该文件。如果在此阶段又添加了更多镜像，它们的 sysbuild.cmake 文件也会被包含，依此类推，直到所有预期的镜像都已添加后才返回。

sysbuild_add_dependencies(<CONFIGURE | FLASH> <image> [<image-dependency> ...])

在配置顺序或烧录顺序上，使一个镜像依赖于其他镜像。

每个名为 <image-dependency> 的镜像都会排在名为 <image> 的镜像之前。

CONFIGURE

添加 CMake 配置依赖，决定各镜像的配置顺序。

FLASH

添加烧录依赖，决定所有镜像在 domains.yaml 中出现的顺序。

完整示例参见 在 Zephyr 应用程序之间添加依赖。

sysbuild_images_order(<variable> <CONFIGURE | FLASH> IMAGES <images>)

对提供的 <images> 进行排序，以满足通过 sysbuild_add_dependencies() 指定的依赖关系。

结果将通过 <variable> 返回。
