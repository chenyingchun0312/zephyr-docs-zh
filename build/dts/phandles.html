phandle

设备树中的 phandle 概念与 C 语言中的指针非常相似。可以使用 phandle 引用设备树中的节点，就像在 C 中使用指针引用结构体一样。

获取 phandle

获取设备树节点 phandle 的常用方法是通过它的某个节点标签。例如，对于下面的设备树：

/ {
        lbl_a: node-1 {};
        lbl_b: lbl_c: node-2 {};
};

可以这样写出以下节点的 phandle：

  • /node-1 写作 &lbl_a

  • /node-2 写作 &lbl_b 或 &lbl_c

注意，设备树的 &nodelabel 语法与 C 语言的“取地址”语法很相似。

使用 phandle

备注

本节中的“类型”指设备树绑定文档的 属性 中所列的类型名称之一。

以下是使用 phandle 的主要方式。

单个节点：phandle 类型

可以使用 phandle 从 node-a 引用 node-b，其中 node-b 与 node-a 存在某种关联。

一个常见的例子是：node-a 表示某个产生中断的硬件，node-b 表示接收该中断的中断控制器。这种情况下，可以这样写：

node_b: node-b {
        interrupt-controller;
};

node-a {
        interrupt-parent = <&node_b>;
};

这里使用设备树规范中定义的标准 interrupt-parent 属性来表达两个节点之间的关系。

这类属性的类型为 phandle。

零个或多个节点：phandles 类型

可以使用 phandle 构成一个引用其他节点的数组。

一个常见的例子出现在 引脚控制 中。pinctrl-0、pinctrl-1 等引脚控制属性可以包含多个 phandle，每个 phandle 都“指向”一个包含该硬件外设引脚配置相关信息的节点。下面是在单个属性中使用六个 phandle 的示例：

pinctrl-0 = <&quadspi_clk_pe10 &quadspi_ncs_pe11
             &quadspi_bk1_io0_pe12 &quadspi_bk1_io1_pe13
             &quadspi_bk1_io2_pe14 &quadspi_bk1_io3_pe15>;

这类属性的类型为 phandles。

零个或多个带元数据的节点：phandle-array 类型

可以使用 phandle 引用并配置由其他节点“拥有”的一个或多个资源。

这是最复杂的情况。下一节将给出示例和更多细节。

这类属性的类型为 phandle-array。

phandle-array 属性

这类属性通常用于指定由另一个节点拥有的资源，以及关于该资源的附加元数据。

概要说明

这种类型的属性通常写成本例中 phandle-array-prop 的形式：

node {
        phandle-array-prop = <&foo 1 2>, <&bar 3>, <&baz 4 5>;
};

也就是说，属性值写作以逗号分隔的一系列“组”，每个“组”写在尖括号（< ... >）内。每个“组”都以一个 phandle（&foo、&bar、&baz）开头。每个“组”中跟在 phandle 后面的值称为 说明符（specifier）。上例中有三个说明符：

  1. 1 2

  2. 3

  3. 4 5

每个“组”中的 phandle 用于“指向”控制目标资源的硬件，说明符则描述资源本身以及其他必要的元数据。

本节其余部分介绍一个常见示例。后续各节进一步说明在实践中如何使用 phandle-array 属性的规则。

phandle-array 示例：GPIO

phandle-array 属性最常见的用途，或许是指定开发板上另一块芯片所连接的 SoC 上的一个或多个 GPIO。因此，这里重点讨论这一用途。不过，设备树中还有 许多其他用途 也是用 phandle-array 属性处理的。

例如，考虑一块外部芯片，其中断引脚连接到 SoC 上的某个 GPIO。通常需要把该 GPIO 的信息（GPIO 控制器和引脚号）提供给该芯片的 设备驱动。通常还需要向驱动提供该 GPIO 的其他元数据，例如它是低电平有效还是高电平有效、为了与设备通信应启用 SoC 内部哪种上拉/下拉电阻等。

在设备树中，会有一个节点表示控制一组引脚的 GPIO 控制器。这反映了 GPIO IP 模块在硬件中的通常设计方式。因此，设备树中没有单独的节点表示某个 GPIO 引脚，也无法用单个 phandle 来表示它。

而是应该使用 phandle-array 属性，如下所示：

my-external-ic {
        irq-gpios = <&gpioX pin flags>;
};

在本例中，irq-gpios 是一个值中只有一个“组”的 phandle-array 属性。&gpioX 是控制该引脚的 GPIO 控制器节点的 phandle，pin 是引脚号（0、1、2……），flags 是描述引脚元数据的位掩码（例如 (GPIO_ACTIVE_LOW | GPIO_PULL_UP)）。更多细节请参见 include/zephyr/dt-bindings/gpio/gpio.h。

然后，处理 my-external-ic 节点的设备驱动就可以使用 irq-gpios 属性的值，按照该芯片在你的开发板上的使用方式为其设置中断处理。这样就可以在设备树中配置设备驱动，而无需修改驱动源代码。

这类属性也可以包含多个值：

my-other-external-ic {
        handshake-gpios = <&gpioX pinX flagsX>, <&gpioY pinY flagsY>;
};

上例指定了两个引脚：

  • phandle 为 &gpioX 的 GPIO 控制器上的 pinX，标志为 flagsX

  • &gpioY 上的 pinY，标志为 flagsY

你可能想知道“引脚和标志”这一约定是如何建立和强制执行的。要回答这个问题，我们需要先介绍一个称为说明符空间的概念，然后再介绍设备树绑定的一些相关信息。

说明符空间

说明符空间（specifier space）是一种让节点描述应如何在 phandle-array 属性中使用它们的方式。

我们先从抽象、高层的角度描述说明符空间在 DTS 文件中如何工作，然后给出一个具体示例，并提供进一步阅读的参考资料，说明在实践中如何通过 DTS 文件和绑定文件实现这一切。

概要说明

如上所述，phandle-array 属性是由若干“组”构成的序列，每组由一个 phandle 及其后的若干单元组成：

node {
        phandle-array-prop = <&foo 1 2>, <&bar 3>;
};

跟在每个 phandle 后面的单元称为 说明符（specifier）。本例中有两个说明符：

  1. 1 2：两个单元

  2. 3：一个单元

每个 phandle-array 属性都有一个关联的 说明符空间。这听起来很复杂，但实际上它只是一种以硬件相关的方式为每个 phandle 后面的单元赋予含义的方法。每个说明符空间都有一个唯一的名称。常用硬件有一些“标准”名称，但你也可以创建自己的名称。

设备树节点使用 #SPACE_NAME-cells 属性，按名称编码说明符中必须出现的单元个数。例如，假设 phandle-array-prop 的说明符空间名为 baz，那么 foo 和 bar 节点就需要具有如下 #baz-cells 属性：

foo: node@1000 {
        #baz-cells = <2>;
};

bar: node@2000 {
        #baz-cells = <1>;
};

如果没有 #baz-cells 属性，设备树工具就无法校验 phandle-array-prop 中每个说明符的单元个数。

这种灵活性使你能够在单个设备树属性中写下一组硬件资源，即使不同节点描述每个资源所需的元数据量可能各不相同。

同一个节点在不同的说明符空间中也可以有不同的单元个数。例如：

foo: node@1000 {
        #baz-cells = <2>;
        #bob-cells = <1>;
};

这样，如果 phandle-array-prop-2 的说明符空间为 bob，就可以这样写：

node {
        phandle-array-prop = <&foo 1 2>, <&bar 3>;
        phandle-array-prop-2 = <&foo 4>;
};

这种灵活性使一个节点可以同时管理多种不同类型的资源。该节点使用不同的 #SPACE_NAME-cells 属性描述每类资源所需的元数据量（即每种情况下需要多少个单元）。

说明符空间示例：gpio

通过上面的示例，你已经了解了一种说明符空间的工作方式：在“gpio”空间中，说明符几乎总是有两个单元：

  1. 引脚号

  2. 与该引脚相关的标志位掩码

因此，实践中见到的几乎所有 GPIO 控制器节点都类似下面这样：

gpioX: gpio-controller@deadbeef {
        gpio-controller;
        #gpio-cells = <2>;
};

将属性与说明符空间关联

前面我们介绍了：

  • 每个 phandle-array 属性都有一个关联的说明符空间

  • 说明符空间通过名称标识

  • 设备树节点使用 #SPECIFIER_NAME-cells 属性配置说明符中必须出现的单元个数

本节说明 phandle-array 属性如何获得其说明符空间。

概要说明

一般来说，名为 foos 的 phandle-array 属性隐式地具有说明符空间 foo。例如：

properties:
  dmas:
    type: phandle-array
  pwms:
    type: phandle-array

dmas 属性的说明符空间为“dma”，pwms 属性的说明符空间为 pwm。

特殊情况：GPIO 和 IO 通道

*-gpios 和 *-io-channels 属性有特殊处理，例如 foo-gpios 和 bar-io-channels 分别解析为 #gpio-cells 和 #io-channel-cells，而不是 #foo-gpio-cells 和 #bar-io-channel-cells。

手动指定空间

可以为任何 phandle-array 属性手动指定说明符空间。参见 specifier-space。

为说明符中的单元命名

编写绑定时，应为硬件所支持的每个说明符空间中的单元命名。具体做法请参见 说明符单元名称（*-cells）。

这样，C 代码就可以使用如下设备树 API，按名称查询说明符中单元的信息并获取其值：

  • DT_PHA_BY_IDX

  • DT_PHA_BY_NAME

许多硬件专用 API 在内部都使用了这一特性和这些宏。下面是一些示例：

  • DT_GPIO_PIN_BY_IDX

  • DT_PWMS_CHANNEL_BY_IDX

  • DT_DMAS_CELL_BY_NAME

  • DT_IO_CHANNELS_INPUT_BY_IDX

  • DT_CLOCKS_CELL_BY_NAME
