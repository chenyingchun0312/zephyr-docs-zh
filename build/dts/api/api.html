设备树 API

本页是 <zephyr/devicetree.h> API 的参考页面。该 API 基于宏。使用这些宏不会影响调度，它们可以在任何调用上下文中以及文件作用域中使用。

其中一些宏（以 DT_INST_ 开头的那些）要求在使用前定义一个名为 DT_DRV_COMPAT 的特殊宏，下文会单独讨论。这些宏通常用于 设备驱动 中，不过只要足够小心，也可以在驱动之外使用。

通用 API

本节中的 API 可以在任何地方使用，不需要定义 DT_DRV_COMPAT。

节点标识符及辅助宏

节点标识符（node identifier）是在 C 预处理阶段引用设备树节点的一种方式。虽然节点标识符不是 C 值，但可以借助它们以 C 右值的形式访问设备树数据，例如使用 属性访问 API。

根节点 / 的节点标识符为 DT_ROOT。可以使用 DT_PATH、DT_NODELABEL、DT_ALIAS 和 DT_INST 为其他设备树节点创建节点标识符。

还有 DT_PARENT 和 DT_CHILD 宏，可分别用于为给定节点的父节点或某个特定子节点创建节点标识符。

以下宏用于创建或操作节点标识符。

devicetree-generic-id

属性访问

以下通用宏可用于访问节点属性。访问 ranges 属性、reg 属性 和 interrupts 属性 有专门的 API。

即使节点被禁用，只要它有匹配的绑定，仍可以使用这些宏读取属性值。

devicetree-generic-prop

ranges 属性

访问 ranges 属性时，请使用这些 API，而不是 属性访问。由于该属性的语义由设备树规范定义，这些宏甚至可以用于没有匹配绑定的节点。不过，当节点的绑定表明它是 PCIe 总线节点时，这些宏具有 PCI Bus Binding to: IEEE Std 1275-1994 Standard for Boot (Initialization Configuration) Firmware 中定义的特殊语义。

devicetree-ranges-prop

reg 属性

访问 reg 属性时，请使用这些 API，而不是 属性访问。由于该属性的语义由设备树规范定义，这些宏甚至可以用于没有匹配绑定的节点。

devicetree-reg-prop

interrupts 属性

访问 interrupts 属性时，请使用这些 API，而不是 属性访问。

由于该属性的语义由设备树规范定义，其中一些宏甚至可以用于没有匹配绑定的节点。但这不适用于以单元名作为参数的宏。

devicetree-interrupts-prop

遍历宏

DT_FOREACH_ANCESTOR 宏用于遍历设备树节点的祖先节点。此外，DT_FOREACH_CHILD 宏用于遍历设备树节点的子节点。

还有一些专用的遍历宏，例如 DT_INST_FOREACH_STATUS_OKAY，但它们要求在使用前定义 DT_DRV_COMPAT。

devicetree-generic-foreach

节点间依赖关系

devicetree.h API 对跟踪节点之间的依赖关系提供了一定支持。依赖跟踪基于设备树节点之间的二元“依赖于”关系，该关系定义为以下“直接依赖于”关系的 传递闭包：

  • 每个非根节点都直接依赖于其父节点

  • 节点直接依赖于其属性通过 phandle 引用的任何节点，这可以通过节点绑定中的 dependency-mode 加以更改

  • 如果节点具有 interrupts 属性，则它直接依赖于其 interrupt-parent

  • 父节点继承其子节点的所有依赖关系

设备树的 依赖顺序（dependency ordering）是其节点组成的一个列表，其中每个节点 n 都排在所有依赖于 n 的节点之前。节点的 依赖序号（dependency ordinal）就是它在该列表中从零开始的索引。因此，对于依赖序号分别为 d1 和 d2 的两个不同设备树节点 n1 和 n2，有：

  • d1 != d2

  • 如果 n1 依赖于 n2，则 d1 > d2

  • d1 > d2 并不 一定意味着 n1 依赖于 n2

Zephyr 构建系统会为最终设备树选择一种依赖顺序，并为每个节点分配一个依赖序号。可以使用以下宏访问与依赖相关的信息。具体选择的依赖顺序属于实现细节，但循环依赖会被检测出来并导致错误，因此使用这些宏时可以放心地假设不存在循环依赖。

也有基于实例编号的便捷宏，参见 DT_INST_DEP_ORD 及其后的文档。

devicetree-dep-ord

总线辅助宏

Zephyr 的设备树绑定语言支持 bus: 键，绑定可以借此声明具有给定 compatible 的节点描述的是系统总线。这种情况下，其子节点被视为位于该类型的总线上，可以使用以下 API。

devicetree-generic-bus

基于实例的 API

建议在设备驱动中使用这些 API。使用时，请将 DT_DRV_COMPAT 定义为设备驱动所支持 compatible 的小写加下划线形式。下面是一个设备树片段示例：

serial@40001000 {
        compatible = "vnd,serial";
        status = "okay";
        current-speed = <115200>;
};

使用示例，假设 serial@40001000 是唯一一个已启用且 compatible 为 vnd,serial 的节点：

#define DT_DRV_COMPAT vnd_serial
DT_DRV_INST(0)                  // node identifier for serial@40001000
DT_INST_PROP(0, current_speed)  // 115200

警告

对实例编号做假设时要小心。API 所提供的保证请参见 DT_INST。

如上所示，DT_INST_* API 是按实例编号访问节点的便捷方式。它们几乎都是基于某个 通用 API 定义的。去掉宏名中的 INST_ 即可找到等效的通用 API。例如，DT_INST_PROP(inst, prop) 等效于 DT_PROP(DT_DRV_INST(inst), prop)。同理，DT_INST_REG_ADDR(inst) 等效于 DT_REG_ADDR(DT_DRV_INST(inst))，依此类推。也有一些例外：DT_ANY_INST_ON_BUS_STATUS_OKAY 和 DT_INST_FOREACH_STATUS_OKAY 是专用辅助宏，没有直接对应的通用等效宏。

由于 DT_DRV_INST() 要求定义 DT_DRV_COMPAT，在未定义该宏的情况下使用其中任何一个宏都是错误的。

注意，还有一些针对特定硬件的辅助宏，它们在 硬件专用 API 中介绍。

Pinctrl（引脚控制）

这些宏用于按名称或索引访问引脚控制属性。

设备树节点可以具有指定引脚控制（有时也称为引脚复用）设置的属性。这些设置通过节点中的 pinctrl-<index> 属性表示，其中 <index> 的值是从 0 开始的连续整数。还可以使用 pinctrl-names 属性为它们命名。

示例如下：

node {
    ...
    pinctrl-0 = <&foo &bar ...>;
    pinctrl-1 = <&baz ...>;
    pinctrl-names = "default", "sleep";
};

上例中，pinctrl-0 的名称为 "default"，pinctrl-1 的名称为 "sleep"。pinctrl-<index> 属性的值包含 phandle。属性中的 &foo、&bar 等 phandle 指向的节点内容因平台而异，它们描述该节点的一种引脚配置。

devicetree-pinctrl

Zephyr 特有的 chosen 节点

下表列出了一些常用的 Zephyr 特有 chosen 节点。

有时，chosen 节点的 label 属性会被用来设置某个 Kconfig 选项的默认值，该选项进而配置一个硬件相关的设备。这通常是为了向后兼容，因为该 Kconfig 选项早于 Zephyr 对设备树的支持。在其他情况下，没有对应的 Kconfig 选项，而是在源代码中直接使用设备树节点来选择设备。
