上游绑定的规则

本节包含编写打算提交到上游 Zephyr 项目的绑定时应遵循的一般规则。（对于不打算贡献给 Zephyr 项目的绑定，不必遵循这些规则，但遵循它们是个好主意。）

Zephyr 设备树维护者做出的决定优先于本节内容。不过，如果出现这种情况，请告知他们，以便他们更新本页，你也可以自己提交补丁。

始终先检查是否已有绑定

Zephyr 的目标是实现设备树的 与其他操作系统的源码兼容性。因此，如果权威来源中已有适用于你的设备的绑定，编写 Zephyr 绑定时应尽量沿用其属性，并且必须说明任何 Zephyr 特有差异的理由。

特别是在以下情况下适用此规则：

  • 主线 Linux 内核中已有绑定。现有绑定请参见 Linus's tree 中的 Documentation/devicetree/bindings，更多信息请参见 Linux devicetree documentation。

  • 你的硬件厂商在 Linux 内核之外提供了官方绑定。

一般规则

为 Zephyr 编写设备树绑定时，应尽可能遵循 design guidelines laid out by Linux。

文件名

匹配某个 compatible 的绑定，其文件名必须基于该 compatible。

  • 例如，compatible 为 vnd,foo 的绑定必须命名为 vnd,foo.yaml。

  • 如果绑定是特定于总线的，可以在文件名后附加总线名称。例如，如果绑定 YAML 中有 on-bus: bar，可以将文件命名为 vnd,foo-bar.yaml。

建议即要求

提交绑定时，default 中的所有建议都是要求。

特别是，如果使用 default: 功能，必须在属性的描述中说明该值的理由。

描述

属性的 description: 字符串只有两种可接受的写法。

如果描述很短，可以使用这种风格：

description: my short string

如果描述很长或跨越多行，必须使用这种风格：

title: I'm sure you need a short title.

description: |
  My very long string
  goes here.
  Look at all these lines!

这种 | 风格可防止 YAML 解析器删除多行描述中的换行符，从而使这些长字符串在 devicetree_binding_index 中正确显示。

如果绑定属性的用法较为复杂，可以用示例给出一个最小节点，例如：

description: ...

properties:
 ...

examples:
  - |
    leds {
      compatible = "gpio-leds";

      uled: led {
      gpios = <&gpioe 12 GPIO_ACTIVE_HIGH>;
      };
    };

命名约定

属性名中不要使用大写字母（A 到 Z）或下划线（_）。使用小写字母（a 到 z）代替大写字母，使用短横线（-）代替下划线。（此规则唯一的例外是你在沿用 Linux 等处已有的成熟绑定。）

厂商前缀规则

以下一般规则适用于 compatible 属性中的厂商前缀。

  • 如果你的设备由特定厂商制造，其 compatible 应带有厂商前缀。

    如果你的绑定描述的硬件来自 dts/bindings/vendor-prefixes.txt 列表中的知名厂商，必须使用该厂商前缀。

  • 如果你的设备不是由特定硬件厂商制造的，不要 自创厂商前缀。厂商前缀不是 compatible 属性的必需部分，除非指代真实的厂商，否则 compatible 中不应包含厂商前缀。此规则有一些例外，但强烈不建议这样做。

  • 除非同时包含新前缀的使用者，否则不要向 Zephyr 的 dts/bindings/vendor-prefixes.txt 文件提交新增内容。这意味着至少要有一个使用该厂商前缀的绑定和一个设备树，并且最好还包含一个处理该 compatible 的设备驱动。

    对于自定义绑定，可以在 DTS_ROOT 中的任意目录下添加自定义的 dts/bindings/vendor-prefixes.txt 文件。设备树工具会识别这些前缀，在你自己的绑定或设备树中使用它们时不会产生警告或错误。

  • 我们有时会将 Zephyr 的 vendor-prefixes.txt 文件与 Linux 内核中的对应文件同步，此过程不受上一条规则的限制。

  • 如果你的绑定描述的是一类抽象硬件，由 Zephyr 特有的驱动处理这些节点，通常最好使用 zephyr 作为厂商前缀。示例请参见 dt_vendor_zephyr。

默认值规则

只要在设备树绑定中使用了 default:，该属性的 description: 就 必须 解释 为什么 选择该值，以及在哪些条件下需要提供不同的值。此外，如果更改一个属性需要同时更改另一个属性才能形成一致的配置，则应将这些属性设为必需。

无需记录默认值本身，devicetree_binding_index 的输出中已经包含该值。

如果绑定中的值对于特定开发板或硬件配置可能不正确，使用 default: 就存在风险。例如，在充电 IC 绑定中为所连接电池的容量设置默认值，很可能是不正确的。对于这类属性，最好将其设为 required: true，强制用户做出明确选择。

驱动开发者应自行判断某个值能否安全地设置默认值。适合设置默认值的候选包括：

  • 只在特殊条件下（例如中间插入了其他硬件）才会不同的延时

  • 具有标准初始配置的设备（例如 USB 音频耳机）的配置

  • 与厂商规定的上电复位值一致的默认值（前提是它们与其他属性无关）

status、#address-cells 和 #size-cells 的默认值不能在绑定中定义。这些属性的默认行为已在设备树规范 §2.3.4 和 §2.3.5 中定义。

按照这些规则编写描述的示例：

properties:
  cs-interval:
    type: int
    default: 0
    description: |
      Minimum interval between chip select deassertion and assertion.
      The default corresponds to the reset value of the register field.
  hold-time-ms:
    type: int
    default: 20
    description: |
      Amount of time to hold the power enable GPIO asserted before
      initiating communication. The default was recommended in the
      manufacturer datasheet, and would only change under very
      cold temperatures.

一些 不应 采用的写法示例及其原因：

properties:
  # Description doesn't mention anything about the default
  foo:
    type: int
    default: 1
    description: number of foos

  # Description mentions the default value instead of why it
  # was chosen
  bar:
    type: int
    default: 2
    description: bar size; default is 2

  # Explanation of the default value is in a comment instead
  # of the description. This won't be shown in the bindings index.
  baz:
    type: int
    # This is the recommended value chosen by the manufacturer.
    default: 2
    description: baz time in milliseconds

zephyr, 前缀

在以下情况下，必须为属性名添加此前缀：

  • 对与上游 Linux 共享的绑定所做的 Zephyr 特有扩展。例如 ADC 通道属性 zephyr,vref-mv，它是 dts/bindings/adc/adc-controller.yaml 中定义的 ADC 控制器的通用属性。该通道绑定部分与类似的 Linux 绑定共享，Zephyr 特有的扩展用此前缀加以标记。

  • 特定于 Zephyr 设备驱动的配置值。例如 ti,bq274xx 绑定中的 zephyr,lazy-load 属性。虽然设备树总体上是一种硬件描述和配置语言，但它是 Zephyr 中为单个 struct device 配置驱动行为的唯一机制。因此，作为折中，我们确实允许在 Zephyr 设备树绑定中进行一些软件配置，只要它们使用此前缀来表明其为 Zephyr 特有。

为 Zephyr 特有的设备树 compatible 命名时，可以使用 zephyr, 前缀，例如 zephyr,ipc-openamp-static-vrings。这种情况下，允许但不要求为绑定中定义的属性添加 zephyr, 前缀。
