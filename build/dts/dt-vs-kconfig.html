设备树与 Kconfig 的对比

除设备树外，Zephyr 还使用 Kconfig 语言来配置源代码。对于某个具体用途应该使用设备树还是 Kconfig，有时会令人困惑。本节可以帮助你决定使用哪一个。

简而言之：

  • 使用设备树描述 硬件 及其 启动时配置，例如开发板上的外设、启动时的时钟频率、中断线等。

  • 使用 Kconfig 配置要编译进最终镜像的 软件支持，例如是否添加网络支持、应用程序需要哪些驱动等。

换言之，设备树主要处理硬件，而 Kconfig 主要处理软件。

例如，考虑一块开发板，其 SoC 包含 2 个 UART（即串口）实例。

  • 开发板具有这些 UART 硬件 这一事实，由设备树中的两个 UART 节点描述。这些节点提供 UART 类型（通过 compatible 属性）以及某些设置，例如硬件外设寄存器在内存中的地址范围（通过 reg 属性）。

  • 此外，UART 的 启动时配置 也由设备树描述，例如 RX IRQ 线的优先级和 UART 波特率。这些配置可能可以在运行时修改，但其启动时配置是在设备树中描述的。

  • 从应用程序代码的角度看，这两个 UART 可以互换，使用哪一个都没有影响，这只是开发板设计的问题。这属于纯粹的 硬件配置，应使用设备树完成。

  • 是否在构建中包含 UART 的 软件支持 由 Kconfig 控制。不需要使用 UART 的应用程序可以通过 Kconfig 从构建中移除驱动源代码，即使开发板的设备树中仍然包含 UART 节点。

再举一个例子，考虑一个带有 2.4GHz 多协议无线电的设备，它同时支持低功耗蓝牙（Bluetooth Low Energy）和 802.15.4 无线技术。

  • 应使用设备树描述无线电 硬件 的存在、它与哪个或哪些驱动兼容等。

  • 无线电的 启动时配置，例如以 dBm 为单位的发射功率，也应使用设备树指定。

  • 在应用程序中，使用不同的协议会启用不同的代码，但使用的是同一硬件。这属于 软件配置 的范畴。

  • 应由 Kconfig 决定为该无线电构建哪些 软件功能，例如选择 BLE 或 802.15.4 协议栈。

再举一个例子，以前用于启用某个驱动（该驱动本身由 Kconfig 启用）特定实例的 Kconfig 选项已被移除。现在通过在相应硬件实例上使用设备树的 status 关键字来逐个选择设备。

这些规则也有 例外：

  • 由于 Kconfig 无法灵活地控制某些与实例相关的驱动配置参数（例如内部缓冲区的大小），这些选项可以在设备树中定义。不过，为了表明它们是 Zephyr 驱动特有的，而不是硬件描述或配置，这些属性应加上 zephyr, 前缀，例如通用以太网设备树属性中的 zephyr,random-mac-address。

  • 设备树的 chosen 关键字，它允许用户选择某个硬件设备的特定实例用于特定用途，例如选择某个 UART 作为系统控制台。

由设备树自动生成的 Kconfig 符号

在设备树处理步骤中，CMake 会运行 scripts/dts/gen_driver_kconfig_dts.py，该脚本扫描所有 DTS 根目录（包括 dts/bindings），并将 Kconfig.dts 写入构建的 KCONFIG_BINARY_DIR（例如 <build>/zephyr，在使用 Sysbuild（系统构建） 时为 <build>/<image>/zephyr）。对于绑定中出现的每个 compatible = "vendor,chip"，生成的文件包含：

DT_COMPAT_VENDOR_CHIP := vendor,chip

config DT_HAS_VENDOR_CHIP_ENABLED
        def_bool $(dt_compat_enabled,$(DT_COMPAT_VENDOR_CHIP))

该赋值使 compatible 字面字符串可供 自定义 Kconfig 预处理器函数 中介绍的预处理函数使用，这样 Kconfig 文件就可以调用 $(dt_compat_on_bus,$(DT_COMPAT_<compatible>),i2c) 之类的辅助函数。创建符号名时，-、, 和 @ 等字符会被转换为下划线。

Kconfig 运行后，该隐藏的布尔符号会成为 CONFIG_DT_HAS_<compatible>_ENABLED。其值反映当前设备树中是否至少有一个具有该 compatible 且 status 为 okay 的节点。用于启用驱动的符号几乎都应设为 default y，并带有 depends on CONFIG_DT_HAS_<compatible>_ENABLED，例如：

config SENSOR_VENDOR_CHIP
        bool "Vendor Chip sensor"
        default y
        depends on DT_HAS_VENDOR_CHIP_ENABLED

由于这些符号是自动生成的，只需添加一个带有 compatible 属性的新绑定，相应的 DT_HAS_<compatible>_ENABLED 和 DT_COMPAT_<compatible> 结构即可在 Kconfig 中使用。
