输入和输出文件

本节更详细地介绍 范围与用途 中图示的输入和输出文件。

输入文件

设备树输入文件有四种类型：

  • 源文件（.dts）

  • 包含文件（.dtsi）

  • 覆盖文件（.overlay）

  • 绑定（.yaml）

zephyr 目录中的设备树文件如下所示：

boards/<ARCH>/<BOARD>/<BOARD>.dts
dts/common/skeleton.dtsi
dts/<ARCH>/.../<SOC>.dtsi
dts/bindings/.../binding.yaml

一般来说，每个受支持的开发板都有一个描述其硬件的 BOARD.dts 文件。例如，reel_board 对应 boards/phytec/reel_board/reel_board.dts。

BOARD.dts 包含一个或多个 .dtsi 文件。这些 .dtsi 文件描述运行 Zephyr 的 CPU 或片上系统（SoC），可能还会包含其他 .dtsi 文件。它们也可以描述多个开发板共有的其他通用硬件特性。除这些包含文件外，BOARD.dts 还描述该开发板特有的硬件。

dts/common 目录包含 skeleton.dtsi，这是用于定义完整设备树的最小包含文件。各架构专用的子目录（dts/<ARCH>）包含扩展 skeleton.dtsi 的 CPU 或 SoC .dtsi 文件。

所有设备树文件都会经过 C 预处理器处理以展开宏引用。虽然 DTS 有 /include/ "<filename>" 语法，但通常使用 #include <filename> 指令进行包含。

可以使用 覆盖文件（overlay）扩展或修改 BOARD.dts。覆盖文件也是 DTS 文件，.overlay 扩展名只是一种用来明确其用途的约定。覆盖文件可以针对不同用途调整基础设备树：

  • Zephyr 应用程序可以使用覆盖文件启用默认禁用的外设、为特定应用程序用途选择开发板上的某个传感器等。结合 配置系统（Kconfig），这使得无需修改源代码即可重新配置内核和设备驱动。

  • 定义 扩展板 时也会使用覆盖文件。

构建系统会自动获取存放在特定位置的 .overlay 文件。也可以通过 DTC_OVERLAY_FILE CMake 变量显式列出要包含的覆盖文件。详情请参见 设置设备树覆盖文件。

构建系统通过拼接的方式合并 BOARD.dts 和所有 .overlay 文件，覆盖文件放在最后。这依赖于 DTS 语法允许合并设备树中重叠的节点定义这一特性。其工作方式的示例请参见 示例：FRDM-K64F 和 Hexiwear K64（该示例针对的是 .dtsi 文件，但覆盖文件的原理相同）。将 .overlay 文件的内容放在最后，使它们能够覆盖 BOARD.dts 中的内容。

设备树绑定（即 YAML 文件）本质上起粘合作用。它们描述设备树源文件、包含文件和覆盖文件的内容，使构建系统能够生成可供设备驱动和应用程序使用的 C 宏。dts/bindings 目录中存放着绑定。

脚本和工具

以下位于 scripts/dts/ 中的库和脚本根据输入文件生成输出文件。它们的源代码中有详尽的文档。

dtlib.py

一个底层 DTS 解析库。

edtlib.py

构建在 dtlib 之上的库，使用绑定来解释属性，并提供更高层次的设备树视图。它使用 dtlib 进行 DTS 解析。

gen_defines.py

使用 edtlib 根据设备树和绑定生成 C 预处理器宏的脚本。

此外，如果系统中安装了标准的 dtc（设备树编译器）工具，还会对最终的设备树运行该工具。这样做只是为了捕获错误或警告，其输出并不使用。开发板可能需要向 dtc 传递额外的标志，例如用于屏蔽警告。开发板目录中可以包含一个名为 pre_dt_board.cmake 的文件来配置这些额外标志，如下所示：

list(APPEND EXTRA_DTC_FLAGS "-Wno-simple_bus_reg")

扩展板目录中可以包含一个名为 pre_dt_shield.cmake 的文件，其功能与前面提到的 pre_dt_board.cmake 相同。

输出文件

这些文件生成在应用程序的构建目录中。

警告

不要直接包含这些头文件。正确做法请参见 从 C/C++ 访问设备树。

<build>/zephyr/zephyr.dts.pre

经过预处理的 DTS 源文件。这是一个中间输出文件，作为 gen_defines.py 的输入，用于生成 zephyr.dts 和 devicetree_generated.h。

<build>/zephyr/include/generated/zephyr/devicetree_generated.h

生成的宏以及描述设备树的附加注释。由 devicetree.h 包含。

<build>/zephyr/zephyr.dts

最终合并后的设备树。该文件由 gen_defines.py 输出，有助于调试各种问题。如果安装了设备树编译器 dtc，还会对该文件运行设备树编译器，以捕获其他警告或错误。
