Kconfig 扩展

Zephyr 使用 Kconfig 的 Kconfiglib 实现，其中包含一些 Kconfig 扩展：

  • 使用 configdefault 可以为已有符号应用默认值，而不会 削弱 这些符号的依赖关系。

    config FOO
    bool "FOO"
    depends on BAR

configdefault FOO
    default y if FIZZ

    上面的语句等价于：

    config FOO
    bool "Foo"
    default y if FIZZ
    depends on BAR

    configdefault 符号只能包含 default 字段，不能包含其他字段，但可以包在 if 语句中。下面两段语句是等价的：

    configdefault FOO
    default y if BAR

if BAR
configdefault FOO
    default y
endif # BAR

  • source 语句中的环境变量会被直接展开，这意味着无需定义带有 option env="ENV_VAR" 的“中转”符号。

    备注

    从 Linux 4.18 起，C 语言工具也已移除 option env。

    引用环境变量的推荐语法是 $(FOO)，而不是 $FOO。这使用的是新的 Kconfig 预处理器。展开环境变量的 $FOO 语法仅为向后兼容而保留支持。

  • source 语句支持通配模式，并会包含每个匹配的文件。模式必须至少匹配一个文件。

    请看下面的示例：

    source "foo/bar/*/Kconfig"

    如果模式 foo/bar/*/Kconfig 匹配到文件 foo/bar/baz/Kconfig 和 foo/bar/qaz/Kconfig，则上面的语句等价于下面两条 source 语句：

    source "foo/bar/baz/Kconfig"
source "foo/bar/qaz/Kconfig"

    如果没有文件匹配该模式，则会产生错误。

    可接受的通配模式与 Python glob 模块相同。

    如果允许模式不匹配任何文件（或允许普通文件名对应的文件不存在），可以使用单独的 osource（可选 source）语句。如果没有文件匹配，osource 不执行任何操作。

    备注

    source 和 osource 类似于 Make 中的 include 和 -include。

  • rsource 语句用于包含以相对路径指定的文件。该路径相对于包含该 rsource 语句的 Kconfig 文件所在的目录。

    例如，假设 foo/Kconfig 是顶层 Kconfig 文件，而 foo/bar/Kconfig 包含以下语句：

    source "qaz/Kconfig1"
rsource "qaz/Kconfig2"

    这会包含 foo/qaz/Kconfig1 和 foo/bar/qaz/Kconfig2 两个文件。

    rsource 可用于创建可以自由移动的 Kconfig“子树”。

    rsource 同样支持通配模式。

    rsource 的一个缺点是，它可能使人更难弄清某个文件是在哪里被包含的，因此请仅在需要时使用。

  • orsource 语句结合了 osource 和 rsource 的功能。

    例如，下面的语句会包含当前目录中的 Kconfig1 和 Kconfig2（如果它们存在）：

    orsource "Kconfig[12]"

  • 还提供了 def_int、def_hex 和 def_string 关键字，类似于 def_bool。它们在设置类型的同时添加一个 default。

  • 可以使用 choice <symbol> 语法将符号名称关联到 choice 组。这类 choice 称为 命名 choice，可以在其初始定义以外的地方修改。例如，下面的语句定义了命名 choice FOOBAR：

    choice FOOBAR
        prompt "Example choice"
        default BAR

config FOO
        bool "Foo"

config BAR
        bool "Bar"

endchoice

    然后可以使用下面的语句（例如在 Kconfig.defconfig 文件中）覆盖 choice FOOBAR 的默认选项：

    # Note how "prompt" is not present here
choice FOOBAR
    default FOO
endchoice

    备注

    命名 choice 功能源自 Linux，但从内核 6.9 版本起 Linux 已不再支持该功能，因此它已成为 Kconfiglib 的语言扩展。
