追溯配置值的来源

保存到 zephyr/.config 的合并配置，是将用户配置文件应用于整个 Kconfig 文件树后得到的结果。这个过程可能很难跟踪，尤其是当不可见符号被树中任意位置隐式选中时。为此，可以使用 traceconfig 目标在构建目录中生成一个文件，详细说明每个符号是如何得到其最终值的。

照常构建 Zephyr 项目后，可以使用以下任一命令生成 Kconfig 追溯报告：

west build -t traceconfig

ninja traceconfig

备注

生成的信息只有在干净构建时才有用，否则 .config 文件会把所有设置“固定”为特定的值（如 卡住的符号 中所述）。因此，建议在生成追溯报告之前执行一次 全新构建。

输出位于构建目录下的 zephyr/kconfig-trace.md 文件中。最好在 IDE 中查看此文件，以利用 Markdown 元素（表格、高亮、可点击的链接），不过即使直接用任意文本编辑器打开，也很容易看懂。

报告分为三个部分：

  1. 可见符号

  2. 不可见符号

  3. 未设置的符号

第 1 和第 2 部分以表格形式列出每个符号的类型、名称和当前值。第四列说明使该值生效的语句类型，可能是以下之一：

  • assigned：从配置文件中读取到 CONFIG_xxx=y 形式的显式赋值；

  • default：没有用户赋值，但从 Kconfig 树中读取到适用的默认值；

  • selected 或 implied：另一个符号的 select 或 imply 语句使该符号被设置。

第五列说明来源语句的位置。对于前两种语句，给出确切位置（文件名和行号）；对于后两种情况，则给出导致该符号被设置的表达式。

最后，第 3 部分只是列出所有未定义的符号。由于这些符号从未通过上述任何方式获得值，因此没有附加信息。
