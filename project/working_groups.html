TSC 工作组

概述

TSC 可自行决定设立工作组或小组委员会，作为专注于特定技术领域、计划或任务的团队。

成员资格

工作组成员资格

  • 每个工作组（WG）应在与 TSC 协商后，自行确定其成员资格。

  • 每个工作组都应有一支积极参与其活动和决策过程的成员团队。

  • 工作组成员资格应 向所有 Zephyr 项目 协作者 开放；但工作组可以施加限制，例如限制来自同一家公司的参与人数。

  • 所有 TSC 成员都有资格以成员身份加入工作组，这是 TSC 成员职责的一部分。

  • 最少成员人数可能因任务的复杂程度以及有效完成任务所需的专业知识广度而异。

  • 工作组应力求至少有五到七名成员，以确保观点的多样性、协作和连续性。

  • Zephyr 项目中每个工作组的结构都应以确保有效性、生产力和包容性为目标进行设计，而工作组的最佳规模可能因其具体背景和活动范围而有所不同。

  • 工作组会议和讨论向所有项目 贡献者 开放。

工作组主席/联席主席

每个工作组可以选举一名主席，并可选地选举一名联席主席，负责主持会议并在 TSC 面前代表该工作组。

工作组主席/联席主席选举

  • 主席和联席主席应由工作组成员选举产生

  • 工作组的任何成员都有权自荐担任主席/联席主席。

  • 主席/联席主席的任期为一年

  • 如果主席/联席主席在任期结束前辞职，应举行投票选举新的主席/联席主席。

工作组投票资格

  • 主席或联席主席的选举投票向工作组成员开放。

  • 每家公司只能有 1 名工作组成员参与选举投票。

  • 主席和联席主席应为工作组成员。

工作组选举确认

  • 当选的主席（和/或联席主席）需提交 TSC 确认。

  • TSC 决定接受选举结果，或要求重新投票。

咨询性质

  • 工作组本质上是咨询性质的，向各项目和 TSC 提供建议。

  • 工作组以大致共识为基础运作。如果工作组无法就提供何种建议达成共识，工作组主席应将该问题提交给 TSC 或相关委员会（安全委员会和信息安全委员会），由其进行正式投票；或者告知项目该工作组无法达成共识。

  • 工作组应跟踪讨论情况，记录所做的任何投票、决定或建议，并与社区和 TSC 分享结果。

  • 工作组会议和线下讨论应记录在一份独立文档中，并附上所有支撑细节，例如出席情况、法定人数、待执行的行动和后续步骤。

  • 工作组内做出的决定不具约束力，只有在将决定和结果通报给 TSC 之后才被视为获得批准。

  • 在通报或报告任何结果后 1 周内，如果 TSC 没有提出任何异议，工作组的决定即被视为已确认并获得批准。

TSC 工作组生命周期

创建 TSC 工作组

要创建 TSC 工作组，TSC 成员应（通过 TSC 邮件列表）向 TSC 提交一份提案，提案至少应包含以下内容：

  • TSC 工作组名称。

  • TSC 工作组目的

  • TSC 工作组预期交付成果

  • TSC 工作组的初始参与者，其中至少有一名 TSC 成员担任发起人（sponsor）。

  • 可选：TSC 工作组的完成定义

更新 TSC 工作组

TSC 可以通过 TSC 决议修改 TSC 工作组。如需申请此类修改，应向 TSC 邮件列表提出请求。

结束 TSC 工作组

TSC 依照 TSC 决策程序决定终止 TSC 工作组。提交的终止 TSC 工作组请求应包含：

  • TSC 工作组名称

  • TSC 工作组交付成果

  • 终止 TSC 工作组的理由
