功能跟踪

要向 Zephyr 项目提议新内容：

  1. 首先搜索现有的 issue，看看该领域是否已有相关工作。

  2. 如果没有，可以随时创建一个类型合适（Enhancement、RFC/Proposal 等）的 新 issue

如果你想讨论或参与某个现有 issue 的实现，应联系该 issue 的指定负责人。

备注

以前，项目使用 GitHub 标签 来跟踪与功能相关的工作。你可能会看到带有“Feature”或“Enhancement”等标签的 issue。

这些标签已不再用于新 issue，新 issue 应改为设置合适的类型。例如，应创建类型为 Enhancement 的 issue，而不是给新 issue 添加 Enhancement 标签。

路线图与发布计划

项目路线图和发布计划都是项目的重要工具，但二者用途截然不同，不应混淆。项目路线图传达项目战略的高层概览，而发布计划是一份战术性文档，用于记录和跟踪计划在后续版本中实现的功能。

  • 项目路线图传达的是“为什么”；发布计划详述的是“做什么”

  • 发布计划只跨越几个月；产品路线图则可能涵盖一年或更长时间

项目路线图

项目路线图应是对项目战略目标和预期的高层次、可视化的总结。

如果制定得当，路线图会因多方面原因成为一个有价值的工具。它可以帮助项目以有说服力的方式向现有和新的利益相关方展示其计划，有助于吸引新成员；它还可以作为团队和社区在整个项目开发过程中随时参考的资料，以确保仍在按计划执行。

因此，路线图应只包含战略层面的细节、主要的项目主题、史诗（epic）和目标。

发布计划

当项目路线图的高层战略被转化为可执行的计划，即落实到需要进入某个特定版本或里程碑的具体功能、改进和修复时，就需要发布计划。

发布计划传达的是项目下一个版本（或接下来几个版本）计划纳入的功能和改进。因此它更像是一份项目计划，把宏大的构想拆分成社区和项目主要利益相关方能够逐步推进的小项目。
