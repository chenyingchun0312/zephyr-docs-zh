Zephyr 项目定义了一套开发流程：使用 GitHub Issues 跟踪功能、改进和缺陷报告，并使用 GitHub Pull Requests （PR）提交和审查变更。Zephyr 社区成员共同审查这些 Issue 和 PR，通过定期发布来管理 Zephyr 的功能增强和质量改进，具体见 发布流程。

只有要求社区和贡献者及时进行审查、反馈和回复（无论是针对初次提交，还是针对后续的问题和澄清），我们才能应对大量的 Issue 和 PR。请阅读项目的 开发流程与工具 以及 审查时间线 的具体说明，以了解项目为活跃开发者社区制定的目标和准则。

TSC 项目角色 详细描述了 Zephyr 项目中的各个角色，以及它们在开发流程中对应的权限。

术语

  • mainline（主线）：开发核心功能和核心特性的主代码树。

  • subsystem/feature branch（子系统/功能分支）：同一仓库中的一个分支。在本文中，引用不在同一仓库中、但作为共享相同历史的仓库副本的分支时，我们也使用“分支”一词。

  • upstream（上游）：源代码所基于的父分支。也就是你拉取代码和推送代码的分支，即你的上游。

  • LTS：长期支持（Long Term Support）
