构建扩展

LLEXT 子系统允许创建可加载到正在运行的 Zephyr 应用程序中的扩展。构建这些扩展时，能够使用 Zephyr 主应用程序所用的头文件和编译器标志往往非常有用。

实现这一点最简单的途径是使用 Zephyr 原生 CMake 功能，将扩展作为 Zephyr 应用程序的一部分来构建。这样一次构建就能同时得到 Zephyr 主应用程序和扩展，而且它们都会自动使用相同的参数构建。

在某些情况下，引入完整的 Zephyr 构建系统可能不可行或不方便；例如扩展可能使用不同的编译器套件构建，或者完全属于另一个项目。在这种情况下，扩展开发者需要导出 Zephyr 主应用程序所用的头文件和编译器标志。这可以借助 LLEXT 扩展开发套件 完成。

使用 Zephyr CMake 功能

Zephyr 构建系统提供了一组功能，可用于将扩展作为 Zephyr 应用程序的一部分来构建。这是构建扩展最简单的方式，只需在应用程序的构建系统中添加极少的内容。

构建扩展

可以在应用程序的 CMakeLists.txt 中调用 add_llext_target() 函数来定义扩展，并提供目标名称、输出文件和源文件。用法与标准 CMake 函数 add_custom_target 类似：

add_llext_target(
    <target_name>
    OUTPUT <ext_file.llext>
    SOURCES <src1> [<src2>...]
)

其中：

  • <target_name> 是最终 CMake 目标的名称，构建该目标将生成 LLEXT 二进制文件；

  • <ext_file.llext> 是包含打包后扩展的输出文件的名称；

  • <src1> [<src2>...] 是为创建扩展而编译的源文件列表。

扩展构建过程的具体步骤取决于当前选择的 ELF 目标文件格式。

<target_name> 定义了以下自定义属性，可以使用 CMake 函数 get_target_property() 获取：

lib_target

源文件编译和/或链接步骤的目标名称。

lib_output

编译和/或链接步骤生成的二进制文件。

pkg_input

用作打包步骤输入的文件。

pkg_output

最终的扩展文件名。

调整构建过程

以下 CMake 函数可用于在扩展构建过程中精细地调整构建系统的行为。下面每个函数都以 LLEXT 目标名称作为第一个参数，除此之外，其功能与 Zephyr 中常用的 target_* 版本等效。

  • llext_compile_definitions()

  • llext_compile_features()

  • llext_compile_options()

  • llext_include_directories()

  • llext_link_options()

自定义构建步骤

可以使用 CMake 函数 add_llext_command 添加在扩展构建过程中执行的自定义构建步骤。该命令将在指定的构建步骤运行，并可以引用目标的属性来获取与构建相关的细节。

函数签名如下：

add_llext_command(
    TARGET <target_name>
    [PRE_BUILD | POST_BUILD | POST_PKG]
    COMMAND <command> [args...]
)

各构建步骤如下：

PRE_BUILD

如果架构使用动态库，则在链接扩展代码之前执行。此步骤可以访问 lib_target 及其自身的属性。

POST_BUILD

在扩展代码构建完成之后、将其打包为 .llext 文件之前执行。此步骤应读取 lib_output 的内容，创建 pkg_input 文件。

POST_PKG

在扩展输出文件创建之后执行。该命令可以对最终的 llext 文件 pkg_output 进行操作。

COMMAND 之后的所有内容都会原样传给 add_custom_command()（包括多条命令和其他选项）。

LLEXT 扩展开发套件（EDK）

在 Zephyr 主构建系统之外将扩展作为独立项目构建时，必须能够使用 Zephyr 主应用程序所用的同一套生成头文件和编译器标志，因为它们直接影响 Zephyr 头文件的解释方式以及扩展的整体编译方式。

为此，可以让 Zephyr 根据 Zephyr 主应用程序的构建产物生成一个扩展开发套件（Extension Development Kit，EDK），方法是运行以下使用 llext-edk 目标的命令：

west build -t llext-edk

生成的 EDK 位于构建目录中的 zephyr 目录下。它是一个 tar 包，包含构建扩展所需的头文件和编译标志。扩展开发者随后可以在自己的构建系统中包含这些头文件并使用这些编译标志来构建扩展。

EDK 定义文件

EDK 包含若干便捷文件，启用后，这些文件定义一组变量，其中包含项目所需的编译标志以及其他与构建相关的信息。这些信息目前以下列格式导出：

  • Makefile.cflags，用于基于 Makefile 的项目；

  • cmake.cflags，用于基于 CMake 的项目。

头文件路径和标志都以 EDK 根目录为前缀。对于 CMake 项目，该目录会自动从 CMAKE_CURRENT_LIST_DIR 获取；其他格式则引用 LLEXT_EDK_INSTALL_DIR 变量，用户必须在包含生成的文件之前将其设置为 EDK 的安装路径。

备注

变量名中的 LLEXT_EDK 前缀可以通过 CONFIG_LLEXT_EDK_NAME 选项更改。

编译标志

构建扩展所需的完整标志列表由 LLEXT_CFLAGS 提供。此外还提供了一组更细粒度的标志，可用于不同的用例，例如为单元测试构建模拟（mock）对象：

LLEXT_INCLUDE_CFLAGS

将包含非自动生成头文件的目录添加到编译器头文件搜索路径中的编译器标志。

LLEXT_GENERATED_INCLUDE_CFLAGS

将包含自动生成头文件的目录添加到编译器头文件搜索路径中的编译器标志。

LLEXT_ALL_INCLUDE_CFLAGS

将构建中用到的所有头文件目录添加到编译器头文件搜索路径中的编译器标志。它是 LLEXT_INCLUDE_CFLAGS 与 LLEXT_GENERATED_INCLUDE_CFLAGS 的组合。

LLEXT_GENERATED_IMACROS_CFLAGS

用于必须通过 -imacros 包含到构建中的自动生成头文件的编译器标志。

LLEXT_BASE_CFLAGS

控制目标 CPU 代码生成的其他编译器标志。上述列表均不包含这些标志。

LLEXT_CFLAGS

构建扩展所需的全部标志。它是 LLEXT_ALL_INCLUDE_CFLAGS、LLEXT_GENERATED_IMACROS_CFLAGS 与 LLEXT_BASE_CFLAGS 的组合。

目标信息

EDK 包含标识当前 Zephyr 构建目标的信息。目前定义了以下变量，它们与 Zephyr 构建系统中可用的信息一致：

LLEXT_EDK_BOARD_NAME

Zephyr 构建中使用的开发板名称。

LLEXT_EDK_BOARD_QUALIFIERS

Zephyr 构建中使用的开发板限定符（如果提供）。

LLEXT_EDK_BOARD_REVISION

Zephyr 构建中使用的开发板版本（如果提供）。

LLEXT_EDK_BOARD_TARGET

Zephyr 构建中使用的完全限定的开发板目标。

备注

变量名中的 LLEXT_EDK 前缀可以通过 CONFIG_LLEXT_EDK_NAME 选项更改。

LLEXT EDK Kconfig 选项

可以使用以下 Kconfig 选项配置 LLEXT EDK：

CONFIG_LLEXT_EDK_NAME

生成的 EDK tar 包的名称。它还用作 EDK 文件中所定义的若干变量的前缀。

CONFIG_LLEXT_EDK_USERSPACE_ONLY

如果设置该选项，EDK 将包含不含系统调用路由到内核代码的头文件。这在构建只在用户模式下运行的扩展时很有用。
