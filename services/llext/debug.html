调试扩展

调试扩展是一项复杂的任务。按照定义，扩展代码不是与 Zephyr 应用程序一起构建的，因此最终的 Zephyr ELF 文件不包含扩展代码的符号。此外，扩展在运行时由 llext_load() 动态重定位，因此即使有这些符号，调试器也无法知道扩展代码中各符号的最终位置。

在这种情况下，正确设置调试会话需要几个手动步骤。以下各节将介绍如何使用 Zephyr SDK 和 west 提供的调试功能完成这些步骤，不过这些说明也可以套用到任何基于 GDB 的调试环境。

扩展调试流程

  1. 确保项目已设置为显示详细的 LLEXT 调试输出（已设置 CONFIG_LOG 和 CONFIG_LLEXT_LOG_LEVEL_DBG）。

  2. 构建 Zephyr 应用程序和扩展。

    对于当前构建中包含的每个目标 name，会在构建根目录的 llext 子目录中生成两个文件：

    name_ext_debug.elf

    包含完整调试信息的中间 ELF 文件。

    name.llext

    最终的扩展二进制文件，经过剥离，只保留加载到 Zephyr 应用程序所必需的数据。

    根据目标架构和构建配置的不同，还可能存在其他文件。

  3. 启动 Zephyr 主应用程序的调试会话。文档的 调试 一节对此有说明；在受支持的开发板上，只需运行 west debug（可能需要附加一些参数）即可。

  4. 在代码中 llext_load() 函数之后设置一个断点，然后让程序运行。这会将扩展加载到内存中并对其重定位。输出日志中会有一行 gdb add-symbol-file flags:，其后是若干以 -s 开头的行。

  5. 在 GDB 控制台中输入以下命令以加载该扩展的符号：

    add-symbol-file <path-to-debug.elf> <load-addresses>

    其中 <path-to-debug.elf> 是第 2 步中确定的带调试信息 ELF 文件的完整路径，<load-addresses> 是从上一步日志中收集的所有 -s 行，以空格分隔。

  6. 现在调试器已经可以使用扩展的符号。你可以像平常一样设置断点、查看变量和单步执行代码。

如果应用程序加载了多个扩展，可以对每个扩展重复第 4-6 步。

符号查找问题

警告

加载的符号几乎肯定会被主应用程序中的其他符号遮蔽；例如，它们可能位于 ELF 缓冲区或 LLEXT 堆的内存区域内。

在这种情况下，GDB 会选择第一个已知的符号，因此会将地址关联到类似 elf_buffer+0x123 的位置，而不是预期的 ext_fn。这会进一步干扰源码级单步执行或查看局部变量之类的高层操作，因为在那种上下文中这些操作毫无意义。

下面几段讨论了解决此问题的两种可能方案。

丢弃所有 Zephyr 符号

最简单的办法是在第 5 步之前不带参数调用 add-symbol-file，从 GDB 中丢弃 Zephyr 应用程序的所有符号。但这样一来，调试会话就只能专注于 llext，因为有关 Zephyr 应用程序的所有信息都会丢失。例如，调试器可能无法正确跟踪扩展代码之外的栈回溯。

可以在同一个会话中多次使用这一技巧，按需在主程序和扩展的符号表之间切换，但这很快就会变得繁琐。

编辑 ELF 文件

这种方法更复杂，但能带来更流畅的调试体验。其思路是编辑 Zephyr 主 ELF 文件，删除与待调试扩展重叠的符号信息，这样在加载扩展符号时，GDB 就不会产生任何歧义。这可以通过带 -N <symbol> 选项的 objcopy 来完成。

不过，找出引起冲突的符号是一个反复试错的过程，因为可能存在许多不同的层次；例如，ELF 缓冲区本身可能包含在数据段的某个符号中。幸运的是，由于对于给定项目这个列表不太可能变化，这些信息可以多次重复使用。

调试会话示例

本示例演示如何在基于 ARM Cortex-M3 的模拟 mps2/an385 开发板上调试 tests/subsys/llext 项目中的 detached_fn 扩展（具体为 writable 用例）。

备注

以下日志是使用 Zephyr 4.1 版本和 Zephyr SDK 0.17.0 版本获得的。不过，即使使用相同的版本，每次运行的具体地址仍可能不同。请调整下面的命令，使其与你自己会话的结果相符。

编辑 ELF 文件

在这种替代方法中，对 Zephyr ELF 文件的修补必须在终端 1 上构建 Zephyr 二进制文件并启动模拟器之后、在终端 2 上启动 GDB 客户端之前进行。

上面的调试会话已经确定 test_detached_ext（保存 ELF 文件的 char 数组）是引起冲突的符号，因此第一轮先将其删除。多次执行相同的步骤后，还可以发现 __data_start 和 __data_region_start 也与所关注的内存区域重叠。

以下命令将从 Zephyr ELF 文件中删除所有这些符号，然后在修改后的文件上启动调试会话：

终端 2（GDB 客户端）
zephyr$ export LLEXT_SDK_INSTALL_DIR=/opt/zephyr-sdk-0.17.0
zephyr$ ${LLEXT_SDK_INSTALL_DIR}/arm-zephyr-eabi/bin/arm-zephyr-eabi-objcopy -N test_detached_ext -N __data_start -N __data_region_start build/zephyr/zephyr.elf build/zephyr/zephyr-edit.elf
zephyr$ ${LLEXT_SDK_INSTALL_DIR}/arm-zephyr-eabi/bin/arm-zephyr-eabi-gdb build/zephyr/zephyr-edit.elf
GNU gdb (Zephyr SDK 0.17.0) 12.1
[...]
Reading symbols from build/zephyr/zephyr-edit.elf...
(gdb)
