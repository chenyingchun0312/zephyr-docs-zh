状态机框架

概述

状态机框架（State Machine Framework，SMF）是一个与应用无关的框架，为开发者提供了一种将状态机集成到应用程序中的简便方法。启用 CONFIG_SMF 选项即可将该框架加入任何项目。

创建状态

一个状态由三个函数表示：一个函数实现 Entry（进入）动作，另一个实现 Run（运行）动作，最后一个实现 Exit（退出）动作。进入和退出函数的原型为 void funct(void *obj)，运行动作的原型为 enum smf_state_result funct(void *obj)，其中 obj 参数是一个用户定义的结构体，其第一个成员是状态机上下文 smf_ctx。例如:

struct user_object {
   struct smf_ctx ctx;
   /* All User Defined Data Follows */
};

smf_ctx 成员必须位于首位，因为状态机框架的函数会使用 SMF_CTX 宏将用户定义的对象强制转换为 smf_ctx 类型。

例如，你可以使用 SMF_CTX(&user_obj)，而不必写 (struct smf_ctx *)&user_obj。

默认情况下，状态不能有祖先状态，因此得到的是扁平状态机。要创建层次状态机，必须启用 CONFIG_SMF_ANCESTOR_SUPPORT 选项。

运行动作的返回值 smf_state_result 决定状态机是把事件传播给父状态的运行动作（SMF_EVENT_PROPAGATE），还是事件已由该运行动作处理（SMF_EVENT_HANDLED）。扁平状态机没有父动作，因此返回码会被忽略；建议返回 SMF_EVENT_HANDLED。

调用 smf_set_state() 会阻止调用父状态的运行动作，即使返回了 SMF_EVENT_PROPAGATE 也是如此。

默认情况下，层次状态机不支持在进入超状态时初始转换到子状态。要启用这一功能，必须启用 CONFIG_SMF_INITIAL_TRANSITION 选项。

可以使用以下宏方便地创建状态：

  • SMF_CREATE_STATE 创建一个状态

创建状态机

状态机通过定义一张以枚举为索引的状态表来创建。例如，下面创建了三个扁平状态:

enum demo_state { S0, S1, S2 };

const struct smf_state demo_states[] = {
   [S0] = SMF_CREATE_STATE(s0_entry, s0_run, s0_exit, NULL, NULL),
   [S1] = SMF_CREATE_STATE(s1_entry, s1_run, s1_exit, NULL, NULL),
   [S2] = SMF_CREATE_STATE(s2_entry, s2_run, s2_exit, NULL, NULL)
};

下面的示例创建了三个层次状态:

enum demo_state { S0, S1, S2 };

const struct smf_state demo_states[] = {
   [S0] = SMF_CREATE_STATE(s0_entry, s0_run, s0_exit, parent_s0, NULL),
   [S1] = SMF_CREATE_STATE(s1_entry, s1_run, s1_exit, parent_s12, NULL),
   [S2] = SMF_CREATE_STATE(s2_entry, s2_run, s2_exit, parent_s12, NULL)
};

下面的示例创建了三个层次状态，并带有从父状态 S0 到子状态 S2 的初始转换:

enum demo_state { S0, S1, S2 };

/* Forward declaration of state table */
const struct smf_state demo_states[];

const struct smf_state demo_states[] = {
   [S0] = SMF_CREATE_STATE(s0_entry, s0_run, s0_exit, NULL, demo_states[S2]),
   [S1] = SMF_CREATE_STATE(s1_entry, s1_run, s1_exit, demo_states[S0], NULL),
   [S2] = SMF_CREATE_STATE(s2_entry, s2_run, s2_exit, demo_states[S0], NULL)
};

要设置初始状态，应调用 smf_set_initial() 函数。

要从一个状态转换到另一个状态，使用 smf_set_state() 函数。

备注

如果未设置 CONFIG_SMF_INITIAL_TRANSITION，则不应向 smf_set_initial() 和 smf_set_state() 函数传入父状态，因为父状态不知道要转换到哪个子状态。如果定义了到子状态的初始转换，则可以转换到父状态。一个结构良好的 HSM 应为所有父状态定义初始转换。

备注

状态机运行期间，只应在 Entry 或 Run 函数中调用 smf_set_state()。在 Exit 函数中调用 smf_set_state() 会在日志中产生一条警告，并且不会发生转换。

执行状态机

要运行状态机，应以某种与应用程序相关的方式调用 smf_run_state() 函数。如果 smf_run_state 返回非零值，应用程序应停止调用它。

终止状态机

要终止状态机，应调用 smf_set_terminate() 函数。它可以在进入、运行或退出动作中调用。该函数接受一个用户定义的非零值，该值将由 smf_run_state() 函数返回。

获取当前状态

叶状态：在层次状态机中，叶状态（leaf state） 是不包含任何子状态的状态。它代表层次结构中粒度最细的状态，无法再进一步分解。

执行状态：执行状态（executing state） 是指状态机当前正在执行其进入、运行或退出动作的状态。根据当前操作的不同，它可能是父状态，也可能是叶状态。

要获取当前的叶状态，应调用 smf_get_current_leaf_state() 函数。例如:

const struct smf_state *leaf_state = smf_get_current_leaf_state(SMF_CTX(&s_obj));

备注

如果未启用 CONFIG_SMF_INITIAL_TRANSITION，或者父状态的初始状态未定义，请始终将状态设为叶状态。否则，状态机可能直接进入父状态，此时 smf_get_current_leaf_state() 可能返回父状态而不是叶状态。请确保为所有父状态正确配置初始转换，以免得到结构不良的层次状态机。

要获取当前正在执行其进入、运行或退出动作的状态，请使用 smf_get_current_executing_state() 函数。

UML 状态机

SMF 在转换方面遵循 UML 层次状态机规则，即转换时不执行最近公共祖先的进入和退出动作，除非该转换是自转换。

UML 状态机规范见 UML 规范第 14 章，可在此获取：https://www.omg.org/spec/UML/

SMF 在以下方面不同于 UML 规则：

  1. 在源状态的上下文中执行与转换关联的动作，而不是在执行退出动作之后执行。

  2. 只允许到自身的外部转换，不允许到子状态的外部转换。从超状态到子状态的转换被视为局部转换。

  3. 禁止在退出动作中使用 smf_set_state() 进行转换。

除初始伪状态外，SMF 也不提供任何其他伪状态。终止伪状态可以通过在一个“terminate”状态的进入动作中调用 smf_set_terminate() 来建模。正交区域通过为每个区域调用 smf_run_state() 来建模。

状态机示例

扁平状态机示例

本示例使用 SMF 将下面的状态图转换为代码，其中初始状态为 S0。

代码:

#include <zephyr/smf.h>

/* Forward declaration of state table */
static const struct smf_state demo_states[];

/* List of demo states */
enum demo_state { S0, S1, S2 };

/* User defined object */
struct s_object {
        /* This must be first */
        struct smf_ctx ctx;

        /* Other state specific data add here */
} s_obj;

/* State S0 */
static void s0_entry(void *o)
{
        /* Do something */
}
static enum smf_state_result s0_run(void *o)
{
        smf_set_state(SMF_CTX(&s_obj), &demo_states[S1]);
        return SMF_EVENT_HANDLED;
}
static void s0_exit(void *o)
{
        /* Do something */
}

/* State S1 */
static enum smf_state_result s1_run(void *o)
{
        smf_set_state(SMF_CTX(&s_obj), &demo_states[S2]);
        return SMF_EVENT_HANDLED;
}
static void s1_exit(void *o)
{
        /* Do something */
}

/* State S2 */
static void s2_entry(void *o)
{
        /* Do something */
}
static enum smf_state_result s2_run(void *o)
{
        smf_set_state(SMF_CTX(&s_obj), &demo_states[S0]);
        return SMF_EVENT_HANDLED;
}

/* Populate state table */
static const struct smf_state demo_states[] = {
        [S0] = SMF_CREATE_STATE(s0_entry, s0_run, s0_exit, NULL, NULL),
        /* State S1 does not have an entry action */
        [S1] = SMF_CREATE_STATE(NULL, s1_run, s1_exit, NULL, NULL),
        /* State S2 does not have an exit action */
        [S2] = SMF_CREATE_STATE(s2_entry, s2_run, NULL, NULL, NULL),
};

int main(void)
{
        int32_t ret;

        /* Set initial state */
        smf_set_initial(SMF_CTX(&s_obj), &demo_states[S0]);

        /* Run the state machine */
        while(1) {
                /* State machine terminates if a non-zero value is returned */
                ret = smf_run_state(SMF_CTX(&s_obj));
                if (ret) {
                        /* handle return code and terminate state machine */
                        break;
                }
                k_msleep(1000);
        }
}

层次状态机示例

本示例使用 SMF 将下面的状态图转换为代码，其中 S0 和 S1 共享一个父状态，S0 为初始状态。

代码:

#include <zephyr/smf.h>

/* Forward declaration of state table */
static const struct smf_state demo_states[];

/* List of demo states */
enum demo_state { PARENT, S0, S1, S2 };

/* User defined object */
struct s_object {
        /* This must be first */
        struct smf_ctx ctx;

        /* Other state specific data add here */
} s_obj;

/* Parent State */
static void parent_entry(void *o)
{
        /* Do something */
}
static void parent_exit(void *o)
{
        /* Do something */
}

/* State S0 */
static enum smf_state_result s0_run(void *o)
{
        smf_set_state(SMF_CTX(&s_obj), &demo_states[S1]);
        return SMF_EVENT_HANDLED;
}

/* State S1 */
static enum smf_state_result s1_run(void *o)
{
        smf_set_state(SMF_CTX(&s_obj), &demo_states[S2]);
        return SMF_EVENT_HANDLED;
}

/* State S2 */
static enum smf_state_result s2_run(void *o)
{
        smf_set_state(SMF_CTX(&s_obj), &demo_states[S0]);
        return SMF_EVENT_HANDLED;
}

/* Populate state table */
static const struct smf_state demo_states[] = {
        /* Parent state does not have a run action */
        [PARENT] = SMF_CREATE_STATE(parent_entry, NULL, parent_exit, NULL, NULL),
        /* Child states do not have entry or exit actions */
        [S0] = SMF_CREATE_STATE(NULL, s0_run, NULL, &demo_states[PARENT], NULL),
        [S1] = SMF_CREATE_STATE(NULL, s1_run, NULL, &demo_states[PARENT], NULL),
        /* State S2 do not have entry or exit actions and no parent */
        [S2] = SMF_CREATE_STATE(NULL, s2_run, NULL, NULL, NULL),
};

int main(void)
{
        int32_t ret;

        /* Set initial state */
        smf_set_initial(SMF_CTX(&s_obj), &demo_states[S0]);

        /* Run the state machine */
        while(1) {
                /* State machine terminates if a non-zero value is returned */
                ret = smf_run_state(SMF_CTX(&s_obj));
                if (ret) {
                        /* handle return code and terminate state machine */
                        break;
                }
                k_msleep(1000);
        }
}

设计层次状态机时，应考虑以下几点：

  • 祖先状态的进入动作在兄弟状态的进入动作之前执行。例如，parent_entry 函数在 s0_entry 函数之前被调用。

  • 在具有共同祖先的兄弟状态之间转换时，不会重新执行祖先状态的进入动作，也不会执行其退出动作。例如，从 S0 转换到 S1 时，既不会调用 parent_entry 函数，也不会调用 parent_exit 函数。

  • 祖先状态的退出动作在当前状态的退出动作之后执行。例如，s1_exit 函数在 parent_exit 函数之前被调用。

  • 只有当 child_run 函数既没有调用 smf_set_state()，也没有返回 SMF_EVENT_HANDLED 时，parent_run 函数才会执行。

  • 在未启用 CONFIG_SMF_INITIAL_TRANSITION，或父状态的初始状态未定义时，请确保状态总是转换到叶状态，以免得到结构不良的层次状态机。

事件驱动的状态机示例

事件并不是状态机框架的显式组成部分，但可以使用 Zephyr 事件 实现事件驱动的状态机。

代码:

#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>
#include <zephyr/smf.h>

#define SW0_NODE        DT_ALIAS(sw0)

/* List of events */
#define EVENT_BTN_PRESS BIT(0)

static const struct gpio_dt_spec button =
        GPIO_DT_SPEC_GET_OR(SW0_NODE, gpios, {0});

static struct gpio_callback button_cb_data;

/* Forward declaration of state table */
static const struct smf_state demo_states[];

/* List of demo states */
enum demo_state { S0, S1 };

/* User defined object */
struct s_object {
        /* This must be first */
        struct smf_ctx ctx;

        /* Events */
        struct k_event smf_event;
        int32_t events;

        /* Other state specific data add here */
} s_obj;

/* State S0 */
static void s0_entry(void *o)
{
        printk("STATE0\n");
}

static enum smf_state_result s0_run(void *o)
{
        struct s_object *s = (struct s_object *)o;

        /* Change states on Button Press Event */
        if (s->events & EVENT_BTN_PRESS) {
                smf_set_state(SMF_CTX(&s_obj), &demo_states[S1]);
        }
        return SMF_EVENT_HANDLED;
}

/* State S1 */
static void s1_entry(void *o)
{
        printk("STATE1\n");
}

static enum smf_state_result s1_run(void *o)
{
        struct s_object *s = (struct s_object *)o;

        /* Change states on Button Press Event */
        if (s->events & EVENT_BTN_PRESS) {
                smf_set_state(SMF_CTX(&s_obj), &demo_states[S0]);
        }
        return SMF_EVENT_HANDLED;
}

/* Populate state table */
static const struct smf_state demo_states[] = {
        [S0] = SMF_CREATE_STATE(s0_entry, s0_run, NULL, NULL, NULL),
        [S1] = SMF_CREATE_STATE(s1_entry, s1_run, NULL, NULL, NULL),
};

void button_pressed(const struct device *dev,
                struct gpio_callback *cb, uint32_t pins)
{
        /* Generate Button Press Event */
        k_event_post(&s_obj.smf_event, EVENT_BTN_PRESS);
}

int main(void)
{
        int ret;

        if (!gpio_is_ready_dt(&button)) {
                printk("Error: button device %s is not ready\n",
                        button.port->name);
                return;
        }

        ret = gpio_pin_configure_dt(&button, GPIO_INPUT);
        if (ret != 0) {
                printk("Error %d: failed to configure %s pin %d\n",
                        ret, button.port->name, button.pin);
                return;
        }

        ret = gpio_pin_interrupt_configure_dt(&button,
                GPIO_INT_EDGE_TO_ACTIVE);
        if (ret != 0) {
                printk("Error %d: failed to configure interrupt on %s pin %d\n",
                        ret, button.port->name, button.pin);
                return;
        }

        gpio_init_callback(&button_cb_data, button_pressed, BIT(button.pin));
        gpio_add_callback(button.port, &button_cb_data);

        /* Initialize the event */
        k_event_init(&s_obj.smf_event);

        /* Set initial state */
        smf_set_initial(SMF_CTX(&s_obj), &demo_states[S0]);

        /* Run the state machine */
        while(1) {
                /* Block until an event is detected */
                s_obj.events = k_event_wait(&s_obj.smf_event,
                                EVENT_BTN_PRESS, true, K_FOREVER);

                /* State machine terminates if a non-zero value is returned */
                ret = smf_run_state(SMF_CTX(&s_obj));
                if (ret) {
                        /* handle return code and terminate state machine */
                        break;
                }
        }
}

带初始转换和自转换的状态机示例

测试插桩

SMF 提供了可选的插桩钩子，用于在测试期间观察状态机的行为。要启用它们，请设置 CONFIG_SMF_INSTRUMENTATION。

启用后，可以通过 smf_set_hooks() 在状态机上下文中注册三个钩子回调：

  • on_action —— 在每个进入、运行或退出动作执行之前调用。

  • on_transition —— 在当前状态指针更新之后、新状态的进入动作执行之前调用。

  • on_error —— 在检测到无效操作时调用（例如转换目标为 NULL，或在退出动作中尝试转换）。

重要

smf_set_hooks() 必须在 smf_set_initial() 之后 调用，因为 smf_set_initial() 会把钩子指针重置为 NULL。因此，在 smf_set_initial() 期间执行的进入动作（即初始状态及其祖先状态的进入动作）不会 被钩子捕获。

示例:

#include <zephyr/smf.h>

static void on_action(struct smf_ctx *ctx,
                      const struct smf_state *state,
                      smf_action_type action_type)
{
        /* Log or record the action */
}

static void on_transition(struct smf_ctx *ctx,
                          const struct smf_state *source,
                          const struct smf_state *dest)
{
        /* Log or record the transition */
}

static const struct smf_hooks hooks = {
        .on_action = on_action,
        .on_transition = on_transition,
        /* .on_error = NULL — any member may be NULL */
};

void test_example(void)
{
        struct s_object s_obj;

        /* Set the initial state first */
        smf_set_initial(SMF_CTX(&s_obj), &demo_states[S0]);

        /* Install hooks after init — initial entry actions are not captured */
        smf_set_hooks(SMF_CTX(&s_obj), &hooks);

        /* Run the state machine — hooks fire on every action and transition */
        while (!smf_run_state(SMF_CTX(&s_obj))) {
                /* ... */
        }
}

未设置 CONFIG_SMF_INSTRUMENTATION 时，所有插桩代码都不会被编译进来，运行时开销为零。
