概述

连接管理器是一组可选的 Zephyr 功能，旨在让应用程序监视和控制连接（即对支持 IP 的网络的访问），而尽量少地关心底层网络技术的细节。

借助连接管理器，应用程序可以使用一套抽象 API 来控制网络关联并监视互联网访问，避免编写过多与特定技术相关的样板代码。

这使得应用程序有可能用同一套代码支持多种截然不同的连接技术（例如 Wi-Fi 和 LTE）。

应用程序还可以使用连接管理器以通用方式同时管理和使用多种连接技术。

结构

连接管理器分为以下两个子系统：

  • 连接监视（头文件 include/zephyr/net/conn_mgr_monitoring.h）监视所有可用的 Zephyr 网络接口（iface），并在获得或失去 IP 连接时触发 网络管理 事件。

  • 连接控制（头文件 include/zephyr/net/conn_mgr_connectivity.h）提供用于控制接口网络关联的抽象 API。

连接监视

连接监视会跟踪所有可用的接口（无论它们是否支持 连接控制），记录它们在各种 运行状态 之间的转换，以及获得或失去所分配 IP 地址的情况。

每个可用接口在满足以下条件时被视为就绪：

  • 接口处于 admin-up 状态

    • 这表示已指示该接口进入 oper-up 状态（可供使用）。这通过调用 net_if_up() 完成。

  • 接口处于 oper-up 状态

    • 这表示该接口已完全可供使用：它已上线，并且在适用的情况下已与网络关联。

    • 详情参见 网络接口状态管理。

  • 接口至少分配了一个 IP 地址

    • IPv4 和 IPv6 地址均可。只要分配了其中一种或两种地址，即满足此条件。

    • 关于接口 IP 地址分配的详情，参见 网络接口。

  • 接口未被忽略

    • 被忽略的接口始终被视为未就绪。

    • 详情参见 忽略接口。

备注

通常，接口状态和 IP 地址分配由接口的 L2 实现 或所绑定的 连接实现 更新。

详情参见 实现接口状态上报。

一旦上述任一条件不再满足，就绪的接口即不再就绪。

当至少有一个接口就绪时，会触发 NET_EVENT_L4_CONNECTED 网络管理 事件，此时称 IP 连接已就绪。

此后，只要始终至少有一个就绪的接口，各接口变为就绪或未就绪都不会触发额外的事件。

当不再有任何就绪的接口时，会触发 NET_EVENT_L4_DISCONNECTED 网络管理 事件，此时称 IP 连接未就绪。

备注

连接管理器还会触发以下更具体的 CONNECTED / DISCONNECTED 事件：

  • NET_EVENT_L4_IPV4_CONNECTED

  • NET_EVENT_L4_IPV4_DISCONNECTED

  • NET_EVENT_L4_IPV6_CONNECTED

  • NET_EVENT_L4_IPV6_DISCONNECTED

这些事件与 NET_EVENT_L4_CONNECTED 和 NET_EVENT_L4_DISCONNECTED 类似，但分别跟踪支持 IPv4 和支持 IPv6 的接口是否就绪。

用法

启用 Kconfig 选项 CONFIG_NET_CONNECTION_MANAGER 即可启用连接监视。

要接收连接更新，请为 NET_EVENT_L4_CONNECTED 和 NET_EVENT_L4_DISCONNECTED 网络管理 事件创建并注册监听器：

/* Callback struct where the callback will be stored */
struct net_mgmt_event_callback l4_callback;

/* Callback handler */
static void l4_event_handler(struct net_mgmt_event_callback *cb,
                             uint32_t event, struct net_if *iface)
{
        if (event == NET_EVENT_L4_CONNECTED) {
                LOG_INF("Network connectivity gained!");
        } else if (event == NET_EVENT_L4_DISCONNECTED) {
                LOG_INF("Network connectivity lost!");
        }

        /* Otherwise, it's some other event type we didn't register for. */
}

/* Call this before Connection Manager monitoring initializes */
static void my_application_setup(void)
{
        /* Configure the callback struct to respond to (at least) the L4_CONNECTED
         * and L4_DISCONNECTED events.
         *
         *
         * Note that the callback may also be triggered for events other than those specified here!
         * (See the net_mgmt documentation)
         */
        net_mgmt_init_event_callback(
                &l4_callback, l4_event_handler,
                NET_EVENT_L4_CONNECTED | NET_EVENT_L4_DISCONNECTED
        );

        /* Register the callback */
        net_mgmt_add_event_callback(&l4_callback);
}

也可以使用 NET_MGMT_REGISTER_EVENT_HANDLER 在编译时而不是运行时注册回调处理程序。这样可以确保回调在连接管理器监视初始化之前完成注册。

static void l4_event_handler(uint64_t event, struct net_if *iface, void *info,
                             size_t info_length, void *user_data)
{
        if (event == NET_EVENT_L4_CONNECTED) {
                LOG_INF("Network connectivity gained!");
        } else if (event == NET_EVENT_L4_DISCONNECTED) {
                LOG_INF("Network connectivity lost!");
        }

        /* Otherwise, it's some other event type we didn't register for. */
}

NET_MGMT_REGISTER_EVENT_HANDLER(l4_callback, l4_event_handler,
                                NET_EVENT_L4_CONNECTED | NET_EVENT_L4_DISCONNECTED, NULL);

关于监听 net_mgmt 事件的更多信息，参见 监听网络事件。

备注

为避免错过最初的连接事件，应在连接管理器监视初始化之前注册监听器。确保做到这一点的方法参见 避免错过通知。

避免错过通知

连接监视可能在初始化后立即触发事件。

如果应用程序在连接监视初始化之后才注册事件监听器，就可能错过第一批事件，从而在首次获得网络连接时得不到通知。

如果需要考虑这一点，应用程序应在连接监视初始化之前 注册事件监听器。

连接监视使用 SYS_INIT APPLICATION 初始化级别进行初始化，其优先级由 Kconfig 选项 CONFIG_NET_CONNECTION_MANAGER_MONITOR_PRIORITY 指定。

可以使用优先级早于该值的 SYS_INIT（例如优先级 0）在该初始化之前注册回调：

static int my_application_setup(void)
{
        /* Register callbacks here */
        return 0;
}

SYS_INIT(my_application_setup, APPLICATION, 0);

如果这样做不可行，也可以随时调用 conn_mgr_mon_resend_status()，请求连接监视重新发送最新的连接事件：

static void my_late_application_setup(void)
{
  /* Register callbacks here */

  /* Once done, request that events be re-triggered */
  conn_mgr_mon_resend_status();
}

忽略接口

应用程序可以调用 conn_mgr_ignore_iface() 并传入要忽略的接口，请求连接管理器忽略该接口。

也可以调用 conn_mgr_ignore_l2() 忽略整个 L2 实现。

其效果相当于逐个忽略所有使用该 L2 实现 的接口。

接口被忽略期间，无论其实际状态如何，连接管理器都会将其视为尚未准备好承载网络流量。

例如，如果应用程序配置了一个或多个无法（或出于某种原因不应）用于访问外部互联网的接口，这一功能会很有用。

批量便捷函数 可以选择跳过被忽略的接口。

详情参见 conn_mgr_ignore_iface() 和 conn_mgr_watch_iface()。

连接控制

许多网络接口需要先完成网络关联过程才能使用。

对于这类接口，连接控制提供了通用 API，用于请求网络关联（conn_mgr_if_connect()）和解除关联（conn_mgr_if_disconnect()）。网络接口通过 将自身绑定到连接实现 来支持该 API。

使用该 API，应用程序只需极少的特定技术样板代码即可与网络关联。

连接控制还提供以下附加功能：

  • 关联过程中标准化的 持久性和超时 行为。

  • 用于同时控制所有可用接口的管理状态和网络关联的 批量函数。

  • 可选的 便捷自动化功能，用于常见的连接操作。

基本操作

以下各节概述连接管理器连接控制的基本操作。

绑定

在使用连接管理器命令接口进行关联或解除关联之前，必须先将接口绑定到一个 连接实现。绑定由接口的提供方而不是应用程序执行（参见 将接口绑定到实现），可以将其视为接口声明的扩展。

接口绑定后，传递给它的所有连接命令（例如 conn_mgr_if_connect() 或 conn_mgr_if_disconnect()）都会被路由到连接实现中相应的实现函数。

备注

为避免行为不一致，所有连接实现都必须遵循 实现指南。

连接

绑定的接口处于 admin-up 状态后（参见 网络接口状态管理），可以调用 conn_mgr_if_connect() 使其与网络关联。

如果关联成功，连接实现会将该接口标记为 operational-up（参见 网络接口状态管理）。

如果关联发生不可恢复的失败，会触发 致命错误事件。

可以为此过程配置可选的 超时。

备注

conn_mgr_if_connect() 函数刻意设计得极简，不接受任何配置。每个连接实现都应提供某种方式，预先配置或自动配置所需的关联设置或凭据。详情参见 允许预先配置连接。

连接丢失

如果连接因外部因素丢失，连接实现会将该接口标记为 operational-down。

随后，根据是否设置了 持久性，该接口可能会尝试重新连接。

手动断开连接

应用程序也可以调用 conn_mgr_if_disconnect()，请求主动放弃连接。

这种情况下，连接实现会使接口与其网络解除关联，并将接口标记为 operational-down（参见 网络接口状态管理）。无论是否启用了持久性，都不会发起新的连接尝试。

超时和持久性

连接管理器要求所有连接实现都支持以下标准关键功能：

  • 连接超时

  • 连接持久性

这些功能描述了接口在连接和断开事件期间应有的行为。可以为每个接口分别设置。

备注

这两项功能需要由连接实现按下文所述正确、准确地实现。从连接实现角度的更多详情参见 实现超时和持久性。

连接管理器还实现了以下可选功能：

  • 接口空闲超时

备注

要实现空闲超时，对连接实现的唯一要求是在每次使用接口时调用 conn_mgr_if_used()。

连接超时

在接口上调用 conn_mgr_if_connect() 时，会开始一次连接尝试。

除非为接口指定了超时（使用 conn_mgr_if_set_timeout()），连接尝试会无限期地持续，直到成功为止。

如果指定了超时，而在连接成功之前超时已到，则会放弃该连接尝试。发生这种情况时，会引发 超时事件。

接口空闲超时

连接管理器允许用户为接口设置不活动超时（conn_mgr_if_set_idle_timeout()）。连接建立后，如果接口在配置的秒数内没有任何活动，就会自动断开连接。发生这种情况时，会引发 空闲超时事件。就 连接持久性 而言，空闲超时被视为非主动的连接丢失。

连接持久性

每个接口还有一个连接持久性设置，可以通过 conn_mgr_binding_set_flag() 设置 CONN_MGR_IF_PERSISTENT 标志来启用或禁用。

该设置指定接口应如何处理非主动的连接丢失。

如果启用了持久性，任何非主动的连接丢失都会发起新的连接尝试，并在适用时使用新的超时。

否则，接口不会尝试重新连接。

备注

持久性不影响连接尝试的行为，只有超时设置会影响。

例如，如果接口上的一次连接尝试超时，即使该接口设置了持久性，也不会尝试重新连接。

反之，如果没有指定超时，即使接口未设置持久性，它也会一直尝试连接，直到成功为止。

对应的实现指南参见 连接尝试期间的持久性。

控制事件

连接控制会触发 网络管理 事件，将重要的状态变化通知应用程序。

对应的连接实现指南参见 触发连接控制事件。

致命错误

当接口遇到无法恢复的错误时（这意味着之后任何关联尝试都必然失败，应放弃所有此类尝试），会引发 NET_EVENT_CONN_IF_FATAL_ERROR 事件。

该事件的处理程序会收到指向发生致命错误的接口的指针。各个连接实现还可以传递一个应用程序特定的数据指针。

超时

当 接口关联 尝试 超时 时，会引发 NET_EVENT_CONN_IF_TIMEOUT 事件。

该事件的处理程序会收到指向关联尝试超时的接口的指针。

空闲超时

当接口被视为 不活动 时，会引发 NET_EVENT_CONN_IF_IDLE_TIMEOUT 事件。

该事件的处理程序会收到指向关联尝试超时的接口的指针。

监听控制事件

可以按如下方式监听控制事件：

/* Declare a net_mgmt callback struct to store the callback */
struct net_mgmt_event_callback my_conn_evt_callback;

/* Declare a handler to receive control events */
static void my_conn_evt_handler(struct net_mgmt_event_callback *cb,
                                uint32_t event, struct net_if *iface)
{
        if (event == NET_EVENT_CONN_IF_TIMEOUT) {
                /* Timeout occurred, handle it */
        } else if (event == NET_EVENT_CONN_IF_FATAL_ERROR) {
                /* Fatal error occurred, handle it */
        }

        /* Otherwise, it's some other event type we didn't register for. */
}

int main()
{
        /* Configure the callback struct to respond to (at least) the CONN_IF_TIMEOUT
         * and CONN_IF_FATAL_ERROR events.
         *
         * Note that the callback may also be triggered for events other than those specified here!
         * (See the net_mgmt documentation)
         */

        net_mgmt_init_event_callback(
                &conn_mgr_conn_callback, conn_mgr_conn_handler,
                    NET_EVENT_CONN_IF_TIMEOUT | NET_EVENT_CONN_IF_FATAL_ERROR
        );

        /* Register the callback */
        net_mgmt_add_event_callback(&conn_mgr_conn_callback);
        return 0;
}

关于监听 net_mgmt 事件的更多信息，参见 监听网络事件。

自动化行为

有一些与连接相关的操作会（至少在默认情况下）自动为用户执行。

自动 admin-up

在 Zephyr 中，接口在初始化期间会自动进入 admin-up 状态（关于接口状态的详情参见 网络接口状态管理）。

应用程序可以使用 net_if_flag_set() 设置 NET_IF_NO_AUTO_START 接口标志来禁用此行为。

自动连接

默认情况下，连接管理器会自动连接任何进入 admin-up 状态的 已绑定 接口。

应用程序可以使用 conn_mgr_if_set_flag() 设置 CONN_MGR_IF_NO_AUTO_CONNECT 连接标志来禁用此行为。

自动 admin-down

默认情况下，如果已绑定的接口放弃了关联，连接管理器会自动使其进入 admin-down 状态。

应用程序可以禁用 Kconfig 选项 CONFIG_NET_CONNECTION_MANAGER_AUTO_IF_DOWN，对所有接口禁用此行为；也可以使用 conn_mgr_if_set_flag() 设置 CONN_MGR_IF_NO_AUTO_DOWN 连接标志，对单个接口禁用此行为。
