与主机系统联网

开发网络软件时，通常需要与主机系统（例如 Linux 台式计算机）连接并交换数据。根据开发所用的开发板，可以选择以下方式：

  • QEMU 使用 SLIP（串行线路网际协议，Serial Line Internet Protocol）。

    • 此方式下，IP 数据包通过串口在 Zephyr 与主机系统之间交换。这是传输数据的传统方式，速度也相当慢，因此仅在必要时使用。详情参见 使用 QEMU 联网。

  • QEMU 使用内置以太网驱动。

    • 此方式下，IP 数据包通过 QEMU 内置的以太网驱动在 Zephyr 与主机系统之间交换。并非所有 QEMU 开发板都支持内置以太网，因此某些情况下可能需要使用 SLIP 方式连接主机。详情参见 使用 QEMU 以太网联网。

  • QEMU 使用 SLIRP（QEMU 用户网络）。

    • QEMU 用户网络基于 “slirp” 实现，它在 QEMU 内部提供完整的 TCP/IP 协议栈，并用该协议栈实现一个经过 NAT 的虚拟网络。由于该支持内置于 QEMU 中，它可以用于任何模型，并且与 TAP 不同，不需要主机上的管理员权限。不过它存在若干限制，包括性能方面的限制，因此实用价值较低。详情参见 使用 QEMU 用户网络联网。

  • Arm FVP（用户模式网络）。

    • 用户模式网络模拟了一个内置的 IP 路由器和 DHCP 服务器，并在客户机与主机之间路由 TCP 和 UDP 流量。它使用主机的用户模式套接字层与其他主机通信。这样无需管理员权限，也无需在运行模型的主机上安装额外的驱动，就能使用大量 IP 网络服务。详情参见 使用 Arm FVP 用户模式联网。

  • native_sim 开发板。

    • Zephyr 实例可以作为主机系统中的用户空间进程运行。这是调试 Zephyr 系统最方便的方式，因为可以将主机调试器直接附加到正在运行的 Zephyr 实例上。这需要 Zephyr 中有一个与主机系统对接的适配驱动。可以使用两种网络驱动：TAP 虚拟以太网驱动和卸载式套接字（offloaded sockets）驱动。详情参见 使用 native_sim 开发板联网。

  • USB 设备联网。

    • 此方式下，Zephyr 实例运行在真实开发板上，通过 USB 与主机系统连接。详情参见 USB 设备联网。

  • 将多个 Zephyr 实例连接在一起。

    • 如果有多个 Zephyr 实例（QEMU 或 native_sim 实例），并希望在它们之间建立连接，详情参见 多个 Zephyr 实例之间联网。

  • 在两个 QEMU 之间模拟 IEEE 802.15.4 网络。

    • 此方式下运行两个 Zephyr 实例，它们之间通过 UART 运行 IEEE 802.15.4 链路层。详情参见 使用 QEMU 和 IEEE 802.15.4 联网。

  • 使用 native_sim 模拟以太网桥网络。

    • 此方式下运行一个 Zephyr 实例，并通过 Kconfig 选项 CONFIG_NET_ETHERNET_BRIDGE 启用以太网桥。主机上有两个网络接口 zeth0 和 zeth1，网络数据包在这两个接口之间桥接。详情参见 native_sim 开发板上的以太网桥。
