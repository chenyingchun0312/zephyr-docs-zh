本页介绍如何在（Linux）主机与运行在 QEMU 虚拟机（为 qemu_x86、qemu_cortex_m3 等 Zephyr 目标构建）中的 Zephyr 应用程序之间建立虚拟网络。某些虚拟 ARM 开发板（例如 qemu_cortex_a53）只支持一个 UART，此时建议使用 QEMU 以太网，详情参见 使用 QEMU 以太网联网。

本例在 QEMU 中运行 Zephyr 源码中的 Echo server (advanced) 示例应用程序。QEMU 实例通过串口连接到 Linux 主机，Zephyr 应用程序与 Linux 之间使用 SLIP（经过一串虚拟连接）传输数据。

前提条件

在 Linux 主机上找到 Zephyr net-tools 项目。它位于 Zephyr 标准安装的 tools/net-tools 目录下，也可以从其独立的 git 仓库单独安装：

sudo apt install -y socat libpcap-dev
git clone https://github.com/zephyrproject-rtos/net-tools
cd net-tools
make

备注

如果出现关于 AX_CHECK_COMPILE_FLAG 的错误，请在 Debian/Ubuntu 上安装 autoconf-archive 软件包。

基本设置

执行以下步骤至少需要 4 个终端窗口：

  • 终端 #1 是常用的 Zephyr 开发终端，已初始化 Zephyr 环境。

  • 终端 #2、#3 和 #4 的当前目录为 net-tools（cd net-tools）

第 1 步 - 创建辅助套接字

在启动带网络模拟的 QEMU 之前，应先创建用于模拟的 Unix 套接字。

在终端 #2 中输入：

./loop-socat.sh

第 2 步 - 启动 TAP 设备路由守护进程

在终端 #3 中输入：

sudo ./loop-slip-tap.sh

对于需要 DNS 的应用程序，此时可能需要重启主机的 DNS 服务器，参见 设置 Zephyr 并在主机上配置 NAT/伪装以访问互联网。

第 3 步 - 在 QEMU 中启动应用程序

构建并启动 echo_server 示例应用程序。

在终端 #1 中输入：

west build -b qemu_x86 samples/net/sockets/echo_server
west build -t run

如果 QEMU 报告 unix:/tmp/slip.sock 相关的错误，说明漏掉了上面的第 1 步。

第 4 步 - 在主机上运行应用程序

现在可以在终端 #4 中运行各种工具，与 QEMU 中运行的应用程序通信。

可以先用 ping 测试：

ping 192.0.2.1
ping6 2001:db8::1

可以使用 netcat（“nc”）工具通过 UDP 连接：

echo foobar | nc -6 -u 2001:db8::1 4242
foobar

echo foobar | nc -u 192.0.2.1 4242
foobar

如果 echo_server 编译时启用了 TCP 支持（echo_server 示例现在默认启用，即 CONFIG_NET_TCP=y）：

echo foobar | nc -6 -q2 2001:db8::1 4242
foobar

备注

按 Ctrl+C 退出。

也可以使用 telnet 命令完成上述操作。

第 5 步 - 停止辅助守护进程

使用 QEMU 完成网络测试后，应停止在开始步骤中启动的所有守护进程或辅助程序，以避免可能的网络或路由问题，例如本地网络接口中的地址冲突。例如，从 QEMU 网络测试切换到真实硬件时，或者要让主机笔记本电脑恢复正常使用 Wi-Fi 时，应停止它们。

要停止这些守护进程，请在相应的终端窗口中按 Ctrl+C（需要同时停止 loop-slip-tap.sh 和 loop-socat.sh）。

按 CTRL+A x 退出 QEMU。

设置 Zephyr 并在主机上配置 NAT/伪装以访问互联网

要从 Zephyr 应用程序访问互联网，可能需要在主机上做一些额外设置。假设开发板连接到开发主机，该设置对运行在 QEMU 中和真实硬件上的应用程序都适用。如果开发板连接到专用路由器，则不需要这些设置。

要从 Zephyr 应用程序通过 IPv4 访问互联网，应通过 DHCP 设置网关或手动配置网关。对于使用 “Settings” 功能（启用了配置选项 CONFIG_NET_CONFIG_SETTINGS）的应用程序，将 CONFIG_NET_CONFIG_MY_IPV4_GW 选项设置为网关的 IP 地址。对于不使用 “Settings” 功能的应用程序，在运行时调用 net_if_ipv4_set_gw() 设置网关。例如：CONFIG_NET_CONFIG_MY_IPV4_GW="192.0.2.2"

要从运行在 QEMU 中的自定义应用程序访问互联网，应为 QEMU 的源地址设置 NAT（伪装）。假设使用 192.0.2.1，且 Zephyr 网络接口为 zeth，应以 root 身份运行以下命令：

iptables -t nat -A POSTROUTING -j MASQUERADE -s 192.0.2.1/24
iptables -I FORWARD 1 -i zeth -j ACCEPT
iptables -I FORWARD 1 -o zeth -m state --state RELATED,ESTABLISHED -j ACCEPT

此外，应在主机上启用 IPv4 转发，并且可能需要检查其他防火墙（iptables）规则是否会干扰伪装。要启用 IPv4 转发，应以 root 身份运行以下命令：

sysctl -w net.ipv4.ip_forward=1

某些应用程序可能还需要 DNS 服务器。许多 Zephyr 提供的示例默认假定主机（IP 192.0.2.2）上有可用的 DNS 服务器，现代 Linux 发行版通常至少会运行一个 DNS 代理。使用 QEMU 时，可能需要重启主机的 DNS，使其能够处理新建 TAP 接口上的请求。例如，在基于 Debian 的系统上：

service dnsmasq restart

除了依赖主机的 DNS 服务器，也可以使用网络中的 DNS 服务器。例如，8.8.8.8 是一个公共 DNS 服务器。可以使用 CONFIG_DNS_SERVER1 选项进行配置。

两个 QEMU 虚拟机之间的网络连接

与上面介绍的虚拟机到主机的设置不同，虚拟机到虚拟机的设置是自动完成的。对于支持此模式的示例应用程序（例如 echo_server 和 echo_client 示例），需要两个已设置好 Zephyr 开发环境的终端窗口。

终端 #1：

west build -b qemu_x86 -o server samples/net/sockets/echo_server

这会启动 QEMU，并等待客户端 QEMU 连接。

终端 #2：

west build -b qemu_x86 -o client samples/net/sockets/echo_client

这会启动第二个 QEMU 实例，此时应能在两个实例中看到收发数据的日志。

运行同一示例的多个 QEMU 虚拟机

如果想运行同一个 Zephyr 示例应用程序的多个实例，且这些实例之间不需要相互通信，请使用 QEMU_INSTANCE 参数。

为所需数量的实例手动启动 socat 和 tunslip6（而不是使用 loop-xxx.sh 脚本）。可参考以下示例，将 MAIN 或 OTHER 替换为实际值。

终端 #1：

socat PTY,link=/tmp/slip.devMAIN UNIX-LISTEN:/tmp/slip.sockMAIN &
sudo $ZEPHYR_BASE/../tools/net-tools/tunslip6 -t tapMAIN -T -s /tmp/slip.devMAIN 2001:db8::1/64 &
# Now run Zephyr
make -Cbuild run QEMU_INSTANCE=MAIN

终端 #2：

socat PTY,link=/tmp/slip.devOTHER UNIX-LISTEN:/tmp/slip.sockOTHER &
sudo $ZEPHYR_BASE/../tools/net-tools/tunslip6 -t tapOTHER -T -s /tmp/slip.devOTHER 2001:db8::1/64 &
make -Cbuild run QEMU_INSTANCE=OTHER
