使用 QEMU 用户网络联网

  • 简介

  • 在 Zephyr 中使用 SLIRP

  • 限制

本页面面向希望在 Zephyr 中使用 QEMU SLIRP 的读者，作为入门参考。

简介

SLIRP 是一种网络后端，它在 QEMU 内部提供完整的 TCP/IP 协议栈，并用该协议栈实现一个经过 NAT 的虚拟网络。由于不依赖主机，SLIRP 设置起来很简单。

默认情况下，QEMU 使用 10.0.2.X/24 网络，并在 10.0.2.2 运行网关。所有发往主机网络的流量都必须经过该网关，网关会根据 QEMU 命令行参数过滤数据包。该网关同时充当所有 GOS 的 DHCP 服务器，从 10.0.2.15 开始为它们自动分配 IP 地址。

关于用户网络的更多信息，请参阅：https://wiki.qemu.org/Documentation/Networking#User_Networking_.28SLIRP.29

在 Zephyr 中使用 SLIRP

要在 Zephyr 中使用 SLIRP，用户需要设置 Kconfig 选项以启用用户网络。

CONFIG_NET_QEMU_USER=y

启用该配置选项后，所有 QEMU 启动都会使用 SLIRP。在默认配置下，Zephyr 只启用用户网络，而不向其传递任何参数。这意味着客户机只能与 QEMU 网关通信，所有发往主机的数据都会被 QEMU 丢弃。

一般来说，QEMU 用户网络可以接受很多参数，包括：

  • 主机/客户机端口转发信息。要在客户机和主机之间建立通信通道，必须提供此信息。

  • 要使用的网络信息。如果用户不想使用默认的 10.0.2.X 网络，此信息会很有用。

  • 让 QEMU 在用户定义的 IP 地址上启动 DHCP 服务器。

  • ID 及其他信息。

由于这些信息因使用场景而异，很难给出适用于所有场景的合适默认值。因此，Zephyr 的实现把这项工作交给用户，期望用户根据需求提供参数。为此提供了一个可由用户填写的 Kconfig 字符串选项。

CONFIG_NET_QEMU_USER_EXTRA_ARGS="net=192.168.0.0/24,hostfwd=tcp::8080-:8080"

该选项会原样附加到 QEMU 命令行。因此，该命令行的任何问题都只会由 QEMU 报告。这个示例的作用如下：

  • 让 QEMU 使用 192.168.0.0/24 网络，而不是默认网络。

  • 启用转发：将主机 8080 端口收到的所有 TCP 数据转发到客户机的 8080 端口，反之亦然。

限制

如果除了从客户机访问网页之外，用户没有其他特定的网络需求，用户网络（slirp）是不错的选择。但它有以下几个限制：

  • 开销很大，因此性能较差。

  • 无法从主机或外部网络直接访问客户机。

  • 一般情况下 ICMP 流量无法工作（因此无法在客户机中使用 ping）。

  • 由于端口映射需要在启动 qemu 之前定义，使用动态生成端口的客户端无法与外部网络通信。

  • SLIRP 实现中有一个缺陷，会过滤掉客户机发出的所有 IPv6 数据包。详情参见 https://bugs.launchpad.net/qemu/+bug/1724590。因此，IPv6 无法在用户网络下工作。
