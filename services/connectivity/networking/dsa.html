分布式交换架构（DSA）

分布式交换架构（Distributed Switch Architecture，DSA）并不是新事物，它在 Linux 中作为成熟的子系统已有多年。本文跳过背景、术语及相关知识的介绍，用户可以在 Linux DSA documentation 中找到这些内容。

DSA 交换机 TX/RX 流程

DSA 交换机的 TX/RX 流程如下。

主机接口

主机接口网络设备使用常规的、未经修改的以太网驱动，作为 DSA 管道端口（conduit port），处理器通过它管理交换机。

交换机接口

交换机接口在 Zephyr 中同样以标准以太网接口的形式呈现。与管道端口相连的接口作为 CPU 端口，其余供用户使用的接口作为用户端口。

交换机标签协议

交换机标签协议通常是厂商特定的。它们都包含以下信息：

  • 标识以太网帧来自哪个端口或应发送到哪个端口

  • 说明该帧被转发到管理接口的原因

并在数据包上打标签，为其添加交换机帧头。但也存在无标签的情况，这取决于厂商。

网络协议栈处理流程

为了让 DSA 子系统通过管道端口处理以太网交换机特定的标签协议：

对于 RX 路径，在 subsys/net/ip/net_core.c 中 net_recv_data() 的开头调用 dsa_recv()，先进行去标签和接口重定向处理。

对于 TX 路径，交换机接口注册为标准以太网设备，并以 dsa_xmit() 作为 ethernet_api->send。dsa_xmit() 负责打标签并重定向到管道端口。

DSA 设备驱动支持

DSA 核心驱动与 MDIO、PHY 和设备树等子系统和驱动交互，以支持通用的 DSA 设置和工作流程，因此设备驱动的支持工作要简单得多。

对于设备树，交换机描述应遵循 dts/bindings/dsa/dsa.yaml。

对于设备驱动，只需准备 dsa_api、私有数据（如有）和 dsa_port_config，并可使用相应的宏函数。下面是 i.MX NETC 的示例。

  • DSA_SWITCH_INST_INIT

  • DSA_PORT_INST_INIT

#define DSA_NETC_PORT_INST_INIT(port, n)                                                    \
        COND_CODE_1(DT_NUM_PINCTRL_STATES(port),                                            \
                        (PINCTRL_DT_DEFINE(port);), (EMPTY))                                \
        struct dsa_netc_port_config dsa_netc_##n##_##port##_config = {                      \
                .pincfg = COND_CODE_1(DT_NUM_PINCTRL_STATES(port),                          \
                                (PINCTRL_DT_DEV_CONFIG_GET(port)), NULL),                   \
                .phy_mode = NETC_PHY_MODE(port),                                            \
        };                                                                                  \
        struct dsa_port_config dsa_##n##_##port##_config = {                                \
                .mcfg = NET_ETH_MAC_DT_CONFIG_INIT(port),                                   \
                .port_idx = DT_REG_ADDR(port),                                              \
                .phy_dev = DEVICE_DT_GET_OR_NULL(DT_PHANDLE(port, phy_handle)),             \
                .phy_mode = DT_PROP_OR(port, phy_connection_type, ""),                      \
                .ethernet_connection = DEVICE_DT_GET_OR_NULL(DT_PHANDLE(port, ethernet)),   \
                .prv_config = &dsa_netc_##n##_##port##_config,                              \
        };                                                                                  \
        DSA_PORT_INST_INIT(port, n, &dsa_##n##_##port##_config)

#define DSA_NETC_DEVICE(n)                                                                  \
        AT_NONCACHEABLE_SECTION_ALIGN(static netc_cmd_bd_t dsa_netc_##n##_cmd_bd[8],        \
                                      NETC_BD_ALIGN);                                       \
        static struct dsa_netc_data dsa_netc_data_##n = {                                   \
                .cmd_bd = dsa_netc_##n##_cmd_bd,                                            \
        };                                                                                  \
        DSA_SWITCH_INST_INIT(n, &dsa_netc_api, &dsa_netc_data_##n, DSA_NETC_PORT_INST_INIT);

使用 DSA 设置时的常见陷阱

以下内容摘自 Linux DSA 文档，同样适用于 Zephyr。尽管管道端口和 CPU 端口在 Zephyr 中以以太网设备的形式呈现，但它们不能被直接使用。

备注

一旦管道网络设备被配置为使用 DSA（dev->dsa_ptr 变为非 NULL），并且其后的交换机需要标签协议，该网络接口就只能专门用作管道接口。直接通过该接口发送数据包（例如打开使用该接口的套接字）不会经过交换机标签协议的发送函数，因此另一端期望带标签的以太网交换机通常会丢弃该帧。

待办工作

与 Linux 相比，Zephyr DSA 还有大量功能有待支持或基于其实现。但基本上应当支持网桥层。之后 DSA 就可以为用户提供两种使用交换机端口的模式。

  • 独立模式：所有用户端口作为常规以太网设备工作，不进行交换。

  • 网桥模式：启用交换模式，将用户端口加入虚拟网桥设备。可以为网桥分配 IP 地址。
