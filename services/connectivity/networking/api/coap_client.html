CoAP 客户端

  • 概述

    • 基于 TCP 的 CoAP

  • 使用示例

  • API 参考

概述

CoAP 客户端库允许应用程序发送 CoAP 请求并解析 CoAP 响应。可以通过 Kconfig 选项 CONFIG_COAP_CLIENT 启用该库。应用程序通过一个回调获知响应，该回调在请求中提供给 API。CoAP 客户端负责通过套接字进行通信。由于 CoAP 客户端不会创建它所使用的套接字，因此由应用程序负责创建套接字。支持普通 UDP 套接字和 DTLS 套接字。

基于 TCP 的 CoAP

还支持 RFC 8323 中规定的基于可靠传输（TCP/TLS）的 CoAP。可通过 CONFIG_COAP_CLIENT_TCP 启用。TCP 客户端在内部管理连接建立、CSM（能力与设置消息）交换以及信令（Ping/Pong、Release、Abort）。与 UDP 客户端不同，应用程序不创建套接字，而是使用服务器地址调用 coap_client_tcp_connect()。用法示例请参见 CoAP TCP Client。

使用示例

下面是 CoAP 客户端初始化和发送请求的示例：

static struct coap_client client;
struct coap_client_request req = { 0 };

coap_client_init(&client, NULL);

req.method = COAP_METHOD_GET;
req.confirmable = true;
strcpy(req.path, "test");
req.fmt = COAP_CONTENT_FORMAT_TEXT_PLAIN;
req.cb = response_cb;
req.payload = NULL;
req.len = 0;

/* Sock is a file descriptor referencing a socket, address is the net_sockaddr struct for the
 * destination address of the request or NULL if the socket is already connected.
 */
ret = coap_client_req(&client, sock, &address, &req, -1);

在发送任何请求之前，需要先初始化 CoAP 客户端。初始化之后，应用程序就可以发送 CoAP 请求并等待响应。目前，单个 CoAP 客户端一次只能发送一个请求。可以有多个 CoAP 客户端。

回调中提供的回调函数会在以下情况下被调用：

  • 请求收到了响应

  • 请求由于某种原因失败

回调中包含一个标志 last_block，表示响应中是否还有更多数据，即当前响应是分块传输的一部分。当 last_block 为 true 时，响应已结束，客户端从回调返回后即可处理下一个请求。

如果服务器响应了请求，该库会通过请求结构体中注册的响应回调把响应提供给应用程序。由于响应可能是分块传输，且客户端对每个分块调用一次回调，应用程序应当处理所有分块才能完成对响应的处理。

在分块传输期间，客户端会按照 RFC 7959 的要求比较所收分块的 ETag 选项。如果资源表示在传输过程中发生变化，传输会被中止，并以 result_code 设为 -EBADMSG 调用回调。RFC 的最低要求只是比较服务器提供的 ETag，本实现更为严格：当 ETag 选项在分块之间出现或消失时，传输也会被中止，因为这种带标签与不带标签分块的混合无法校验。应用程序应丢弃已收到的部分数据，并可重试该请求。

下面是一个非常简单的响应处理函数示例：

void response_cb(const struct coap_client_response_data *data, void *user_data)
{
    if (data->result_code >= 0) {
            LOG_INF("CoAP response from server %d", data->result_code);
            if (data->last_block) {
                    LOG_INF("Last packet received");
            }
    } else {
            LOG_ERR("Error in sending request %d", data->result_code);
    }
}

应用程序也可以向请求中添加 CoAP 选项。下面的示例中，应用程序在初始请求中添加了 Block2 选项，针对一个预计大到需要分块传输的资源，向服务器建议最大块大小（参见 RFC 7959 图 3：带提前协商的分块 GET）。

static struct coap_client client;
struct coap_client_request req = { 0 };

coap_client_init(&client, NULL);

req.method = COAP_METHOD_GET;
req.confirmable = true;
strcpy(req.path, "test");
req.fmt = COAP_CONTENT_FORMAT_TEXT_PLAIN;
req.cb = response_cb;
req.options[0] = coap_client_option_initial_block2();
req.num_options = 1;
req.payload = NULL;
req.len = 0;

ret = coap_client_req(&client, sock, &address, &req, -1);

应用程序也可以选择注册一个负载回调，而不是为 CoAP 上传提供负载指针。这种情况下，CoAP 客户端库会在准备 PUT/POST 请求时调用该回调，使应用程序可以分块提供负载，而不必提供一个包含完整负载的连续缓冲区。一个提供 Lorem Ipsum 字符串内容的示例回调如下：

static int lorem_ipsum_cb(size_t offset, const uint8_t **payload, size_t *len,
                          bool *last_block, void *user_data)
{
    size_t data_left;

    if (offset > LOREM_IPSUM_STRLEN) {
        return -EINVAL;
    }

    *payload = LOREM_IPSUM + offset;

    data_left = LOREM_IPSUM_STRLEN - offset;
    if (data_left <= *len) {
        *len = data_left;
        *last_block = true;
    } else {
        *last_block = false;
    }

    return 0;
}

然后就可以为 PUT/POST 请求注册该回调，而不是提供负载指针：

struct coap_client_request req = { 0 };

req.method = COAP_METHOD_PUT;
req.confirmable = true;
strcpy(req.path, "lorem-ipsum");
req.fmt = COAP_CONTENT_FORMAT_TEXT_PLAIN;
req.cb = response_cb;
req.payload_cb = lorem_ipsum_cb,

ret = coap_client_req(&client, sock, &address, &req, -1);
