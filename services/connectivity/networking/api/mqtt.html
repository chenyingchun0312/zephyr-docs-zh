MQTT

  • 使用示例

  • 通过 TLS 使用 MQTT

  • API 参考

概述

MQTT（消息队列遥测传输，Message Queuing Telemetry Transport）是一种运行在 TCP/IP 协议栈之上的应用层协议。它是一种用于机器间通信的轻量级发布/订阅消息传输协议。关于该协议本身的更多信息，请参见 https://mqtt.org/。

Zephyr 提供了一个基于 BSD 套接字 API 构建的 MQTT 客户端库。可以通过 Kconfig 选项 CONFIG_MQTT_LIB 启用该库，它可以按客户端单独配置，支持 MQTT 3.1.0、3.1.1 和 5.0 版本。Zephyr 的 MQTT 实现既可以使用通过 TCP 通信的普通套接字，也可以使用通过 TLS 通信的安全套接字。关于 Zephyr 套接字的更多信息，请参见 BSD 套接字。

MQTT 客户端需要连接到一个 MQTT 服务器。这种服务器称为 MQTT 代理（Broker），负责管理客户端订阅并分发客户端发布的消息。MQTT 代理有很多实现，Eclipse Mosquitto 就是其中之一。关于 Eclipse Mosquitto 项目的更多信息，请参见 https://mosquitto.org/。

使用示例

要创建 MQTT 客户端，需要定义一个客户端上下文结构体和缓冲区：

/* Buffers for MQTT client. */
static uint8_t rx_buffer[256];
static uint8_t tx_buffer[256];

/* MQTT client context */
static struct mqtt_client client_ctx;

应用程序中可以创建多个 MQTT 客户端实例并独立管理。此外，还需要一个保存 MQTT 代理地址信息的结构体。该结构体在 MQTT 客户端的整个生命周期内都必须可访问，并且可以在多个 MQTT 客户端之间共享：

/* MQTT Broker address information. */
static struct net_sockaddr_storage broker;

MQTT 客户端库会通过一个专门处理相应事件的回调函数，把 MQTT 事件通知给应用程序：

void mqtt_evt_handler(struct mqtt_client *client,
                      const struct mqtt_evt *evt)
{
   switch (evt->type) {
      /* Handle events here. */
   }
}

可能的事件列表请参见 API 参考。

客户端上下文结构体在使用前需要进行初始化和设置。下面是 TCP 传输的配置示例：

mqtt_client_init(&client_ctx);

/* MQTT client configuration */
client_ctx.broker = &broker;
client_ctx.evt_cb = mqtt_evt_handler;
client_ctx.client_id.utf8 = (uint8_t *)"zephyr_mqtt_client";
client_ctx.client_id.size = sizeof("zephyr_mqtt_client") - 1;
client_ctx.password = NULL;
client_ctx.user_name = NULL;
client_ctx.protocol_version = MQTT_VERSION_3_1_1;
client_ctx.transport.type = MQTT_TRANSPORT_NON_SECURE;

/* MQTT buffers configuration */
client_ctx.rx_buf = rx_buffer;
client_ctx.rx_buf_size = sizeof(rx_buffer);
client_ctx.tx_buf = tx_buffer;
client_ctx.tx_buf_size = sizeof(tx_buffer);

完成配置后，MQTT 客户端就可以连接到 MQTT 代理。调用 mqtt_connect 函数，它会创建相应的套接字，建立 TCP/TLS 连接，并发送 MQTT CONNECT 消息。收到通知时，应用程序应调用 mqtt_input 函数处理收到的响应。注意，mqtt_input 是非阻塞函数，因此应用程序应使用套接字 poll 等待响应。如果连接成功，会通过回调函数向应用程序通知 MQTT_EVT_CONNACK。

rc = mqtt_connect(&client_ctx);
if (rc != 0) {
   return rc;
}

fds[0].fd = client_ctx.transport.tcp.sock;
fds[0].events = ZSOCK_POLLIN;
poll(fds, 1, 5000);

mqtt_input(&client_ctx);

if (!connected) {
   mqtt_abort(&client_ctx);
}

在上面的代码片段中，MQTT 回调函数应在连接成功时设置 connected 标志。如果连接在 MQTT 层失败或发生超时，连接会被中止，底层套接字也会被关闭。

连接建立后，应用程序需要定期调用 mqtt_input 和 mqtt_live 函数，以处理传入数据并维持连接。如果收到 MQTT 消息，MQTT 回调函数会被调用，并通知相应的事件。

可以通过调用 mqtt_disconnect 函数关闭连接。

Zephyr 提供了使用 MQTT 客户端 API 的示例代码。更多信息请参见 MQTT publisher。

通过 TLS 使用 MQTT

通过选择安全传输类型（MQTT_TRANSPORT_SECURE）并提供一些额外的配置信息，可以在 TLS 传输上使用 Zephyr MQTT 库进行安全通信：

client_ctx.transport.type = MQTT_TRANSPORT_SECURE;

struct mqtt_sec_config *tls_config = &client_ctx.transport.tls.config;

tls_config->peer_verify = TLS_PEER_VERIFY_REQUIRED;
tls_config->cipher_list = NULL;
tls_config->sec_tag_list = m_sec_tags;
tls_config->sec_tag_count = ARRAY_SIZE(m_sec_tags);
tls_config->hostname = MQTT_BROKER_HOSTNAME;
tls_config->set_native_tls = true;

在这段示例代码中，m_sec_tags 数组保存了一个标签列表，这些标签引用 MQTT 库进行身份验证时应使用的 TLS 凭据。我们没有指定 cipher_list，以允许使用系统中所有可用的密码套件。我们把 hostname 字段设为代理的主机名，这是服务器身份验证所必需的。最后，通过设置 peer_verify 字段强制进行对端证书验证。

注意，m_sec_tags 数组引用的 TLS 凭据必须先在系统中注册。关于如何注册，请参阅 安全套接字文档。

最后，可以选择设置 set_native_tls 以启用原生 TLS 支持，而不是把 TLS 操作卸载到卸载式套接字。

示例应用程序 MQTT publisher 中也有在 MQTT 中使用 TLS 的示例。
