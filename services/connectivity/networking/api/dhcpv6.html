DHCPv6

  • 概述

  • 前缀委派

  • 限制

  • API 参考

概述

IPv6 动态主机配置协议（DHCP）是基于 IPv6 的网络中使用的一种网络管理协议。DHCPv6 服务器为网络中的每个设备动态分配 IPv6 地址和其他网络配置参数，使它们能够与其他 IP 网络通信。关于 DHCPv6 工作原理的详细介绍，请参见这篇 DHCPv6 维基百科文章。

Zephyr 同时支持 DHCPv6 客户端和服务器功能，包括 RFC 8415 中规定的 IPv6 前缀委派（IA_PD）。

前缀委派

DHCPv6 客户端可以充当 请求路由器：除了请求非临时地址（IA_NA）外，还可以通过设置 net_dhcpv6_params.request_prefix 请求委派前缀（IA_PD）。委派前缀会安装到发出请求的接口上。

要让节点成为完整的请求路由器，将前缀再委派给一条或多条下游链路，请在 net_dhcpv6_params.downstream_ifaces 中列出下游（LAN）接口索引，并把 net_dhcpv6_params.downstream_count 设为条目数。每个下游接口会分配到从委派前缀中划分出的一个不同的 /64（第 N 个接口获得第 N 个 /64），随后通过路由器通告（Router Advertisement）在该接口上通告，使下游主机可以使用 SLAAC 自动配置地址。该数组最多容纳 CONFIG_NET_DHCPV6_MAX_DOWNSTREAM 个条目；net_dhcpv6_params.downstream_count 为 0 表示委派前缀只安装在发出请求的接口上。此功能需要 CONFIG_NET_IPV6_ND_RA_TX（路由器通告发送 / 路由器角色）；若要在上游和下游接口之间转发流量，还需要 CONFIG_NET_IPV6_FORWARDING。

委派前缀必须足够短，才能为每个下游接口容纳一个不同的 /64，也就是说，长度为 L 的委派前缀最多可服务 2^(64 - L) 条下游链路。因此，恰好为 /64 的委派只能服务一条链路，而比 /64 更长的委派则完全无法再委派。无法分配到不同 /64 的下游接口会被跳过，并给出警告。

DHCPv6 服务器（CONFIG_NET_DHCPV6_SERVER）实现 委派路由器 角色，从配置的地址池中分发地址和委派前缀。关于两种角色的完整示例，请参见 DHCPv6 prefix delegation。

限制

该实现有意省略了 RFC 8415 和 RFC 4861 允许简化的几项内容：

  • 客户端停止时发送的 Release（CONFIG_NET_DHCPV6_SEND_RELEASE_ON_STOP）是尽力而为的，只发送一次，不会像 RFC 8415 Section 18.2.7 中描述的那样重传 REL_MAX_RC 次。未被释放的租约会在过期后由服务器回收。

  • 非请求的路由器通告按 CONFIG_NET_IPV6_ND_RA_TX_INTERVAL 配置的固定间隔发送，而不是在 MinRtrAdvInterval 与 MaxRtrAdvInterval 之间的随机间隔发送；接口承担路由器角色时，也不会发送 MAX_INITIAL_RTR_ADVERTISEMENTS 次初始突发通告。被请求的通告会按 RFC 4861 Section 6.2.6 的要求进行速率限制和随机延迟。

  • 服务器通过改变所配置地址池基址中的单个字节来分配地址和前缀，因此地址池最多只有 CONFIG_NET_DHCPV6_SERVER_MAX_LEASES 个条目，且 IA_PD 地址池的前缀长度必须按字节对齐。
