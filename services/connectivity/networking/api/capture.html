网络数据包捕获

  • 概述

  • Cooked 模式捕获

  • 使用示例

  • API 参考

概述

net_capture API 允许用户监视 Zephyr 某个网络接口上的网络流量，并把这些流量发送到外部系统进行分析。监视既可以通过 net-shell 手动设置，也可以通过 net_capture API 自动设置。

Cooked 模式捕获

如果启用并配置了捕获功能，系统会自动捕获指定网络接口的网络流量。如果想在不涉及网络接口的情况下捕获网络数据，则需要使用 cooked 模式捕获 API。

在 cooked 模式捕获中，可以捕获任意网络数据包，且不需要涉及网络接口。例如，可以捕获 PPP 中的底层 HDLC 数据包，因为在使用常规的基于网络接口的捕获时，HDLC L2 层数据会被剥离。CANBUS 或 Bluetooth 网络数据也可以被捕获，不过目前网络协议栈还不支持捕获这些数据。

Cooked 模式捕获的工作方式如下：

  • 创建一个 any 网络接口。它充当接收端，cooked 模式捕获 API 会把捕获到的数据包写入该接口。

  • 在这个 any 接口之上挂接一个 cooked 虚拟网络接口。

  • 必须使用网络接口配置 API 将 cooked 接口配置为捕获特定的 L2 数据包类型。

  • 使用 cooked 模式捕获 API 时，调用者必须指定所捕获数据的第 2 层协议类型。这样，cooked 模式捕获 API 在收到此类 L2 数据包时就能确定要捕获什么。

  • 随后对网络数据包捕获基础设施进行设置，把 cooked 接口标记为被捕获的网络接口。cooked 接口经由 any 接口收到的数据包会自动放入捕获 IP 隧道，并发送到远程主机进行分析。

例如，在捕获示例应用程序中会创建以下网络接口：

Interface any (0x808ab3c) (Dummy) [1]
================================
Virtual interfaces attached to this : 2
Device    : NET_ANY (0x80849a4)

Interface cooked (0x808ac94) (Virtual) [2]
==================================
Virtual name : Cooked mode capture
Attached  : 1 (Dummy / 0x808ab3c)
Device    : NET_COOKED (0x808497c)

Interface eth0 (0x808adec) (Ethernet) [3]
===================================
Virtual interfaces attached to this : 4
Device    : zeth0 (0x80849b8)
IPv6 unicast addresses (max 4):
     fe80::5eff:fe00:53e6 autoconf preferred infinite
     2001:db8::1 manual preferred infinite
IPv4 unicast addresses (max 2):
     192.0.2.1/255.255.255.0 overridable preferred infinite

Interface net0 (0x808af44) (Virtual) [4]
==================================
Virtual name : Capture tunnel
Attached  : 3 (Ethernet / 0x808adec)
Device    : IP_TUNNEL0 (0x8084990)
IPv6 unicast addresses (max 4):
     2001:db8:200::1 manual preferred infinite
     fe80::efed:6dff:fef2:b1df autoconf preferred infinite
     fe80::56da:1eff:fe5e:bc02 autoconf preferred infinite

在本例中，192.0.2.2 是终结隧道的主机的外部端点地址。Zephyr 使用该地址选择隧道所用的内部接口，本例中为接口 3。

接口 2 是运行在接口 1 之上的虚拟接口。捕获 API 把 cooked 捕获数据包写入接收端接口 1。由于接口 2 与第一个接口相连，数据包会传播到接口 2。net-shell 命令 net capture enable 2 会使发送到接口 2 的数据包被写入捕获接口 4，捕获接口 4 再对数据包进行封装，并通过以太网接口 3 以隧道方式发送给对端。

如果修改了示例文件 samples/net/capture/overlay-tunnel.conf 中的地址，上述 IP 地址可能会随之改变。
