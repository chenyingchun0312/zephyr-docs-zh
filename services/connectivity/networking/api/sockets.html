概述

Zephyr 实现了 BSD 套接字 API（POSIX 标准的一部分）的一个子集。借助该 API，可以沿用已有的编程经验，并将现有的简单网络应用程序移植到 Zephyr。

以下是指导 Zephyr 实现 BSD 套接字兼容 API 的主要要求和理念：

  • 开销最小，这与其他 Zephyr 子系统的要求类似。

  • 默认带有命名空间，以避免与 close() 等常见名称冲突，这些名称可能属于 libc 或其他 POSIX 兼容库。如果通过 CONFIG_POSIX_API 启用，还会提供 POSIX 兼容的 API。

BSD 套接字兼容 API 通过 CONFIG_NET_SOCKETS 配置选项启用，并实现以下操作：socket()、close()、recv()、recvfrom()、send()、sendto()、connect()、bind()、listen()、accept()、fcntl() （用于设置非阻塞模式）、getsockopt()、setsockopt()、poll()、select()、getaddrinfo()、getnameinfo()。

基于上述命名空间要求，这些操作默认以带 zsock_ 前缀的函数形式提供，例如 zsock_socket() 和 zsock_close()。如果定义了配置选项 CONFIG_POSIX_API，所有函数还会以不带前缀的别名形式提供。其中包括 close() 和 fcntl() 等函数（它们可能与 libc 或其他库中的函数冲突，例如文件系统库）。

上述设计要求带来的另一个结果是，Zephyr API 会尽可能积极地利用 POSIX API 的短读/短写特性（以尽量降低复杂度和开销）。POSIX 允许 recv() 和 send() 等调用实际处理（接收或发送）的数据少于用户请求的数据量（对于 SOCK_STREAM 类型的套接字）。例如，调用 recv(sock, 1000, 0) 可能返回 100，表示只读取了 100 字节（短读），应用程序需要重试调用以接收剩余的 900 字节。

BSD 套接字 API 使用文件描述符表示套接字。文件描述符是从零开始连续分配的小整数，由套接字、文件、特殊设备（如 stdin/stdout）等共享。内部有一张表，将文件描述符映射到内部对象指针。即使未启用 POSIX 子系统的其余部分（文件系统、stdin/stdout），BSD 套接字 API 也会使用文件描述符表。

安全套接字

Zephyr 提供了标准 POSIX 套接字 API 的扩展，允许创建和配置使用 TLS 协议类型的套接字，以便进行安全通信。其实现所用的安全功能由 Mbed TLS 库提供。安全套接字实现允许通过标准套接字调用使用 TLS 和 DTLS 两种协议。支持的安全协议版本请参见 net_ip_protocol_secure 类型。

要启用安全套接字，请设置 CONFIG_NET_SOCKETS_SOCKOPT_TLS 选项。要启用 DTLS 支持，请使用 CONFIG_NET_SOCKETS_ENABLE_DTLS 选项。

TLS 凭据子系统

TLS 凭据必须先在系统中注册，然后才能用于安全套接字。更多信息请参见 tls_credential_add()。

当某个 TLS 凭据在系统中注册时，会为其分配一个 sec_tag_t 类型的数值，称为标签（tag）。之后在通过套接字选项配置安全套接字时，可以用这个值来引用该凭据。

系统中可以注册以下类型的 TLS 凭据：

  • TLS_CREDENTIAL_CA_CERTIFICATE

  • TLS_CREDENTIAL_PUBLIC_CERTIFICATE

  • TLS_CREDENTIAL_PRIVATE_KEY

  • TLS_CREDENTIAL_PSK

  • TLS_CREDENTIAL_PSK_ID

注册 CA 证书（由 ca_certificate 数组提供）的示例如下：

ret = tls_credential_add(CA_CERTIFICATE_TAG, TLS_CREDENTIAL_CA_CERTIFICATE,
                         ca_certificate, sizeof(ca_certificate));

默认支持 DER 格式的证书。可以在 Mbed TLS 设置中启用 PEM 支持。

创建安全套接字

可以通过指定安全协议类型来创建安全套接字，例如：

sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TLS_1_2);

创建安全套接字时指定的协议版本表示 TLS 会话所使用的最低 TLS 版本。

创建之后，可以通过套接字选项对其进行配置。例如，可以设置 CA 证书和主机名：

sec_tag_t sec_tag_opt[] = {
        CA_CERTIFICATE_TAG,
};

ret = setsockopt(sock, SOL_TLS, TLS_SEC_TAG_LIST,
                 sec_tag_opt, sizeof(sec_tag_opt));

char host[] = "google.com";

ret = setsockopt(sock, SOL_TLS, TLS_HOSTNAME, host, sizeof(host));

配置完成后，该套接字就可以像普通 TCP 套接字一样使用。

备注

由于 mbed TLS 内部的数据缓冲以及 mbedtls_ssl_write() 函数的要求，当非阻塞的 zsock_send() 返回 EAGAIN 时，后续的 zsock_send() 调用应包含与原调用相同的数据。

Zephyr 中有多个示例使用安全套接字进行通信。示例用法请参见 echo-server 示例应用程序 或 HTTP GET 示例应用程序 等。

套接字卸载

Zephyr 允许注册自定义的套接字实现（称为卸载套接字）。这使得提供外部 IP 协议栈并公开类似套接字 API 的设备能够无缝集成。

可以通过 CONFIG_NET_SOCKETS_OFFLOAD 选项启用套接字卸载。要注册新套接字实现的网络驱动应使用 NET_SOCKET_OFFLOAD_REGISTER 宏。该宏接受以下参数：

  • socket_name

    套接字实现的任意名称。

  • prio

    套接字实现的优先级。优先级越高，创建新套接字时越早处理该实现。数值越小表示优先级越高。

  • _family

    卸载套接字所实现的套接字地址族。AF_UNSPEC 表示任意地址族。

  • _is_supported

    一个过滤函数，用于检查卸载套接字实现是否支持特定的套接字地址族、类型和协议。

  • _handler

    一个与 socket() API 兼容的函数，用于创建卸载套接字。

每个卸载套接字实现还应实现 socket_op_vtable 结构体中规定的一组套接字 API。

注册用于创建套接字的函数应使用 zvfs_reserve_fd() 函数分配一个新的文件描述符。特定卸载套接字实现在创建时所需的其他操作，都应在分配文件描述符之后进行。最后一步，如果卸载套接字创建成功，应使用 zvfs_finalize_typed_fd() 或 zvfs_finalize_fd() 函数完成文件描述符的设置。该完成函数可以为卸载套接字注册一个实现套接字 API 的 socket_op_vtable 结构体，以及一个可选的套接字上下文数据指针。

最后，在初始化卸载网络接口时，应使用 net_if_socket_offload_set() 函数表明该接口是卸载接口。该函数会在网络接口上注册用于创建卸载套接字的函数（与 NET_SOCKET_OFFLOAD_REGISTER 中提供的函数相同）。

卸载套接字的创建

当应用程序使用 socket() 函数创建新套接字时，网络协议栈会遍历所有已注册的套接字实现（原生实现和卸载实现）。优先级较高的套接字实现会先被处理。对于每个已注册的套接字实现，先检查地址族，如果匹配（或该套接字注册为 AF_UNSPEC），则调用相应的 _is_supported 函数检查其余的套接字参数。第一个满足套接字要求的实现（即 _is_supported 返回 true）将通过其 _handler 函数创建新套接字。

由上可见套接字优先级的重要性。如果多个套接字实现支持同一组套接字地址族/类型/协议，则由系统最先处理的实现创建套接字。因此，应为作为系统默认的实现赋予最高优先级。

原生套接字实现的套接字优先级通过 Kconfig 配置。使用 CONFIG_NET_SOCKETS_TLS_PRIORITY 设置原生 TLS 套接字的优先级，使用 CONFIG_NET_SOCKETS_PRIORITY_DEFAULT 设置其余原生套接字的优先级。

处理多个卸载接口

由于 socket() 函数无法指定套接字应使用哪个网络接口，当存在多个支持同类套接字的卸载套接字实现时，就无法选择特定的实现。当系统中同时存在原生套接字和卸载套接字时，也会出现同样的问题。

为解决这一问题，引入了一种特殊的套接字实现（称为套接字分派器）。该模块的唯一作用是将套接字的创建推迟到对套接字执行第一个操作时。这样就可以使用 SO_BINDTODEVICE 套接字选项，将套接字绑定到特定的网络接口（从而绑定到特定的卸载套接字实现）。套接字分派器可通过 CONFIG_NET_SOCKETS_OFFLOAD_DISPATCHER Kconfig 选项启用。

启用后，应用程序可以使用 setsockopt() 函数指定要使用的网络接口：

/* A "dispatcher" socket is created */
sock = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP);

struct ifreq ifreq = {
   .ifr_name = "SimpleLink"
};

/* The socket is "dispatched" to a particular network interface
 * (offloaded or not).
 */
setsockopt(sock, SOL_SOCKET, SO_BINDTODEVICE, &ifreq, sizeof(ifreq));

同样，如果原生套接字和卸载套接字都支持 TLS，可以使用 TLS_NATIVE 套接字选项指明应创建原生 TLS 套接字。然后可以将底层套接字绑定到特定的网络接口：

/* A "dispatcher" socket is created */
sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TLS_1_2);

int tls_native = 1;

/* The socket is "dispatched" to a native TLS socket implmeentation.
 * The underlying socket is a "dispatcher" socket now.
 */
setsockopt(sock, SOL_TLS, TLS_NATIVE, &tls_native, sizeof(tls_native));

struct ifreq ifreq = {
   .ifr_name = "SimpleLink"
};

/* The underlying socket is "dispatched" to a particular network interface
 * (offloaded or not).
 */
setsockopt(sock, SOL_SOCKET, SO_BINDTODEVICE, &ifreq, sizeof(ifreq));

如果套接字上未使用 SO_BINDTODEVICE 套接字选项，则会在第一次调用套接字 API 时，根据默认优先级和过滤规则分派该套接字。
