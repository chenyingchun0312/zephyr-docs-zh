网络超时

  • 概述

  • 用法

  • API 参考

概述

Zephyr 的网络基础设施主要使用毫秒分辨率的运行时间（uptime）时钟来跟踪超时，截止时间和持续时间都用 32 位无符号值表示。32 位的值会在 49 天 17 小时 2 分 47.296 秒后回绕。

超时处理经常受到延迟的影响，因此检查超时的时刻可能比超时本应到期的时刻晚一些。要在不对最大延迟做任意假设的情况下正确处理这一点，可直接表示的最大延迟必须是一个 31 位非负数（INT32_MAX），它会在 24 天 20 小时 31 分 23.648 秒后溢出。

大多数网络超时都短于延迟回绕时间，但少数协议允许以秒为单位、用 32 位无符号值表示的延迟，这相当于 42 位的毫秒计数。

net_timeout API 提供了一种通用的超时机制，用于正确跟踪这类长时间超时的剩余时间。

用法

该 API 最简单的用法是：

  1. 使用 net_timeout_set() 配置网络超时。

  2. 使用 net_timeout_evaluate() 确定距离超时发生还有多长时间，并安排在该延迟之后触发超时。

  3. 超时回调被调用时，再次使用 net_timeout_evaluate() 判断超时是否已经完成，还是仍有剩余时间。如果仍有剩余时间，则重新安排回调。

  4. 超时运行期间，可使用 net_timeout_remaining() 获取距离超时到期的秒数。这可用于显式更新超时，做法是取消所有挂起的回调，然后用新的超时值从第 1 步重新开始。

net_timeout 包含一个 sys_snode_t，使多个超时实例可以聚合在一起，共享同一个内核定时器元素。应用程序必须对所有实例调用 net_timeout_evaluate()，以确定下一个将要发生的超时事件。

net_timeout_deadline() 可用于重建超时的全精度截止时间。它主要用于测试，但在某些应用程序中也可能有用，因为它能以毫秒分辨率计算剩余时间。
