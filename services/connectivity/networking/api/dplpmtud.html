数据报 PLPMTUD API

  • 概述

  • 配置

  • 使用模型

  • API 参考

概述

Zephyr 提供了一个基于 RFC 8899 的通用 数据报分组层路径 MTU 发现（DPLPMTUD）实现。它面向基于 UDP 的传输（QUIC、基于 UDP 的 CoAP、自定义协议），这些传输需要在不依赖本地 IP 分片的情况下，发现数据报负载最大可以有多大。

该子系统的职责划分如下：

通用协议栈（subsys/net/ip/dplpmtud.c）

  • 按目的地维护的搜索状态：已验证的 PLPMTU、探测大小、重试次数、上下界

  • 在基础 PLPMTU（1200 字节）与路径上限之间进行二分查找

  • 与现有的 PMTU 目的地缓存集成（输入 ICMP PTB，输出已验证的大小）

  • 当 PMTU 缓存报告的 MTU 低于基础 PLPMTU 时进行黑洞处理

传输层使用者

  • 按 net_dplpmtud_get_path_probe_size() 返回的大小构造探测数据报

  • 在启用禁止分片的情况下发送探测（参见 IPv4 和 IPv6 套接字选项 以及 ZSOCK_IP_DONTFRAG / ZSOCK_IPV6_DONTFRAG）

  • 把传输层的确认/丢失映射到 net_dplpmtud_on_path_probe_acked() 和 net_dplpmtud_on_path_probe_lost()

QUIC 是树内第一个使用者。其他传输可以使用同一 API，而无需重复实现 RFC 8899 状态机。

配置

按地址族启用 DPLPMTUD：

  • IPv4：CONFIG_NET_IPV4_PMTU 和 CONFIG_NET_IPV4_PMTU_DPLPMTUD

  • IPv6：CONFIG_NET_IPV6_PMTU 和 CONFIG_NET_IPV6_PMTU_DPLPMTUD

两个地址族都还需要 CONFIG_NET_UDP。启用任一地址族选项时，都会选中总选项 CONFIG_NET_PMTU_DPLPMTUD。

基于 ICMP 的 PMTU 缩减（Packet Too Big）仍可通过 CONFIG_NET_IPV4_PMTU_PTB 和 CONFIG_NET_IPV6_PMTU_PTB 使用。DPLPMTUD 是对 PTB 的补充，在路径允许时会主动探测更大的大小。

可同时跟踪的路径数量分别与 CONFIG_NET_IPV4_PMTU_DESTINATION_CACHE_ENTRIES 和 CONFIG_NET_IPV6_PMTU_DESTINATION_CACHE_ENTRIES 一致。

使用模型

为每个远程目的地初始化一个 net_dplpmtud_path（或在连接的整个生命周期内重用该句柄）：

struct net_dplpmtud_path path;
uint16_t max_plpmtu = 1452U; /* transport / peer limit, or 0 if uncapped */
int mtu;
int probe;
int ret;

ret = net_dplpmtud_init_path(&path, &remote_addr, max_plpmtu);
if (ret < 0) {
    /* handle error */
}

mtu = net_dplpmtud_get_path_mtu(&path);
if (mtu < 0) {
    mtu = NET_DPLPMTUD_BASE_PLPMTU;
}

/* Application data must fit in @a mtu bytes (transport framing excluded). */

探测生命周期：

  1. 调用 net_dplpmtud_get_path_probe_size()。返回值为 0 表示不需要探测。路径必须已经初始化；获取函数不会创建缓存条目。

  2. 如果 net_dplpmtud_path_probe_in_flight() 为 false，则构造并发送该大小的探测数据报，并设置禁止分片（通过套接字选项，或 zsock_sendmsg() 中的逐数据报控制消息）。

  3. 调用 net_dplpmtud_on_path_probe_sent() 在通用状态机中预留该探测，然后发送探测数据报。

  4. 如果发送失败，调用 net_dplpmtud_on_path_probe_lost()，使核心状态与传输层状态保持一致。

  5. 在传输层确认后，调用 net_dplpmtud_on_path_probe_acked() 或 net_dplpmtud_on_path_probe_lost()。

当传输层获知新的上限时（例如 QUIC 的 max_udp_payload_size 传输参数），调用 net_dplpmtud_set_path_max_plpmtu() 进行更新。

如果传输层独立于 ICMP 检测到黑洞，调用 net_dplpmtud_note_path_blackhole()。低于基础 PLPMTU 的 PTB 更新会通过 PMTU 缓存自动应用。
