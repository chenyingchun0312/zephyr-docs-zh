Wi-Fi 管理

概述

Wi-Fi 管理 API 用于管理 Wi-Fi 网络。它支持以下模式：

  • IEEE802.11 站点（STA）

  • IEEE802.11 接入点（AP）

  • IEEE802.11 P2P（Wi-Fi Direct）

仅支持个人模式安全，包括以下类型：

  • 开放（Open）

  • OWE

  • WEP

  • WPA2-PSK

  • WPA2-PSK-256

  • WPA3-SAE

Wi-Fi 管理 API 在 wifi_mgmt 模块中实现，是网络 L2 协议栈的一部分。目前支持两类 Wi-Fi 驱动：

  • 网络卸载或套接字卸载驱动

  • 原生 L2 以太网驱动

编译的功能

为了支持只需要部分 Wi-Fi 功能的应用程序，可以使用 CONFIG_WIFI_USAGE_MODE 提示驱动限制需要编译进来的功能。可用的用法提示如下：

  • CONFIG_WIFI_USAGE_MODE_STA （连接到接入点）

  • CONFIG_WIFI_USAGE_MODE_AP （作为接入点）

  • CONFIG_WIFI_USAGE_MODE_STA_AP （既作为接入点，又连接到接入点）

  • CONFIG_WIFI_USAGE_MODE_SCAN_ONLY （仅扫描接入点 SSID）

备注

是否支持所请求的用法模式取决于硬件。

Wi-Fi shell

Wi-Fi shell 提供了一组命令，可通过交互界面测试和探索 Wi-Fi 管理 API，而无需专门的应用程序。启用 CONFIG_NET_L2_WIFI_SHELL 选项即可添加 wifi 命令。

主要的 Wi-Fi shell 子命令包括：

Wi-Fi shell 子命令

子命令

说明

scan

扫描 Wi-Fi 网络。

connect

连接到 Wi-Fi 网络。

disconnect

断开与 Wi-Fi 网络的连接。

status

显示 Wi-Fi 接口状态。

使用 wifi --help 列出所有可用的子命令，使用 wifi <subcommand> --help 查看特定命令的帮助。启用 Wi-Fi shell 的示例应用程序请参见 Wi-Fi shell。

警告

默认情况下，Wi-Fi shell 的 scan 命令不限制扫描结果数量。由于 UART shell 后端较慢，打印全部扫描结果可能导致网络管理事件被丢弃。为避免该警告，必要时可调整 CONFIG_NET_MGMT_EVENT_QUEUE_TIMEOUT 或 CONFIG_NET_MGMT_EVENT_QUEUE_SIZE。

支持 Wi-Fi PSA 加密的构建

要启用支持 PSA 加密 API 的 Wi-Fi 构建，需要设置 CONFIG_WIFI_NM_WPA_SUPPLICANT_CRYPTO_ALT 和 CONFIG_WIFI_NM_WPA_SUPPLICANT_CRYPTO_MBEDTLS_PSA。

Wi-Fi 功能与加密的对应关系

关于 Wi-Fi 功能（WPA3-SAE、DPP、SAE-PK、WPA2-PSK、企业版 EAP 等）与加密原语（大数运算、ECDH、TLS、哈希、AES）的对应关系，以及哪些使用 传统加密、哪些使用 PSA 加密，请参见专门的子页面：

Wi-Fi 企业版测试：X.509 证书管理

Wi-Fi 企业版安全需要使用 X.509 证书，支持两种安装证书的方法：

编译时证书

PEM 格式的测试证书已提交到仓库的 samples/net/wifi/test_certs 中，在构建过程中，这些证书会被转换为一个 C 头文件，供 Wi-Fi shell 模块包含。

如果要使用自己的证书，可以在同一目录中用自己的证书替换现有证书。

$ export WIFI_TEST_CERTS_DIR=samples/net/wifi/test_certs/rsa3k
$ cp client.pem $WIFI_TEST_CERTS_DIR
$ cp client-key.pem $WIFI_TEST_CERTS_DIR
$ cp ca.pem $WIFI_TEST_CERTS_DIR
$ cp client2.pem $WIFI_TEST_CERTS_DIR
$ cp client-key2.pem $WIFI_TEST_CERTS_DIR
$ cp ca2.pem $WIFI_TEST_CERTS_DIR
$ west build -p -b <board> samples/net/wifi -S wifi-enterprise

对于 RSA 2048 位证书，请使用 rsa2k_no_des。

$ export WIFI_TEST_CERTS_DIR=samples/net/wifi/test_certs/rsa2k_no_des

也可以设置 WIFI_TEST_CERTS_DIR 环境变量，使其指向包含你的证书的目录。

$ west build -p -b <board> samples/net/wifi -S wifi-enterprise -- -DWIFI_TEST_CERTS_DIR=<path_to_your_certificates>

运行时证书

Wi-Fi shell 模块使用 TLS 凭据子系统来存储和管理证书。可以在运行时使用 shell 命令添加证书，详细信息请参见 TLS 凭据 Shell。示例或应用程序需要启用 CONFIG_WIFI_SHELL_RUNTIME_CERTIFICATES 选项才能使用此功能。

为方便安装证书，提供了一个辅助脚本，用法见下文。

$ ./scripts/utils/wifi_ent_cert_installer.py -p samples/net/wifi/test_certs/rsa2k_no_des

该脚本会通过 UART 并使用 TLS 凭据 shell 命令，将证书安装到设备中的 TLS 凭据存储中。

要使用企业版安全发起 Wi-Fi 连接，请根据 EAP 方法使用以下命令之一：

  • EAP-TLS

    uart:~$ wifi connect -s <SSID> -c <channel> -k 7 -w 2 -a <Anonymous identity> --key1-pwd <Password EAP phase1> --key2-pwd <Password EAP phase2>

  • EAP-TTLS-MSCHAPV2

    uart:~$ wifi connect -s <SSID> -c <channel> -k 14 -K <Private key Password> --eap-id1 <Client Identity> --eap-pwd1 <Client Password> -a <Anonymous identity>

  • EAP-PEAP-MSCHAPV2

    uart:~$ wifi connect -s <SSID> -c <channel> -k 12 -K <Private key Password> --eap-id1 <Client Identity> --eap-pwd1 <Client Password> -a <Anonymous identity>

同一目录中还提供了用于测试的服务器证书。可以使用任意 AAA 服务器进行测试，例如 FreeRADIUS 或 hostapd。

服务器证书域名验证

通过使用 Common Name （CN）字段验证从服务器收到的 X.509 证书中的域名，来验证认证服务器的身份。

  • 精确域名匹配 — 验证证书的 CN 与指定域名完全一致。

  • 域名后缀匹配 — 允许 CN 以指定域名后缀结尾的证书。

要使用带服务器证书验证的企业版安全发起 Wi-Fi 连接，请根据所需的验证模式使用以下命令之一：

  • 精确域名匹配

    wifi connect -s <SSID> -c <channel> -k 12 -K <Private key Password> -e <Domain match>

  • 域名后缀匹配

    wifi connect -s <SSID> -c <channel> -k 12 -K <Private key Password> -x <Domain suffix name>

EAP 方法的证书要求

不同的 EAP 方法对客户端证书的要求各不相同，概述如下：

  • EAP-TLS - 客户端上需要客户端证书（及其私钥）和 CA 证书。

    客户端使用其证书向服务器认证自身。

  • EAP-TTLS-MSCHAPV2 - 客户端上只需要 CA 证书。

    客户端在 TLS 隧道内使用用户名和密码 <MSCHAPV2> 向服务器认证。不需要客户端证书。

  • EAP-PEAP-MSCHAPV2 - 客户端上只需要 CA 证书。

    与 TTLS 类似，客户端在 TLS 隧道内使用用户名和密码 <MSCHAPV2>，不需要客户端证书。

备注

这些证书仅用于测试，不应在生产环境中使用。它们是使用 FreeRADIUS raddb 脚本生成的。

备注

使用 TLS 凭据子系统时，默认选择易失性后端，即 CONFIG_TLS_CREDENTIALS_BACKEND_VOLATILE。使用易失性后端时，证书存储在 RAM 中，重启后会丢失，因此重启后需要重新安装证书。作为替代方案，可以使用 PS（受保护存储）后端，即 CONFIG_TLS_CREDENTIALS_BACKEND_PROTECTED_STORAGE，将证书存储在非易失性存储中。

如何使用 FreeRADIUS 生成测试证书

samples/net/wifi/test_certs/rsa2k_no_des 中的测试证书是使用 FreeRADIUS raddb/certs 脚本 生成的。可以按以下步骤生成自己的测试证书：

  1. 前提条件 - 安装 OpenSSL 和 GNU Make。- 下载 FreeRADIUS raddb/certs 目录。

  2. 编辑 Makefile 在 raddb/certs 目录中编辑 Makefile，为生成服务器和客户端密钥的 OpenSSL 命令添加 -nodes。这样可以确保私钥不受密码保护（Zephyr Wi-Fi shell 不支持私钥密码）：

    $(OPENSSL) req -new -out server.csr -keyout server.key -nodes -config ./server.cnf
$(OPENSSL) req -new -out client.csr -keyout client.key -nodes -config ./client.cnf

  3. （可选）编辑 .cnf 文件 根据你的环境需要定制 server.cnf 和 client.cnf。

  4. 生成证书 在 raddb/certs 目录中运行以下命令：

    make destroycerts
make server
make client

  5. 为 Zephyr 重命名文件 与 Zephyr 示例中使用的文件名保持一致：

    FreeRADIUS 输出

    Zephyr 示例中的名称

    ca.pem server.key server.pem client.key client.pem

    ca.pem server-key.pem server.pem client-key.pem client.pem

  6. 复制文件 将重命名后的文件放到 Zephyr 项目的证书目录中（例如 samples/net/wifi/test_certs/rsa2k_no_des）。请使用 AES（PBES2）而不是 DES 加密私钥；可参考现有的 rsa2k_no_des 密钥。

备注

这些证书仅用于测试，不应在生产环境中使用。

Wi-Fi P2P（Wi-Fi Direct）

Wi-Fi P2P 即 Wi-Fi Direct，它使设备无需传统接入点即可彼此直接通信。该功能对于设备到设备的通信场景特别有用。

要启用 Wi-Fi P2P 支持并进行构建：

$ west build -p -b <board> samples/net/wifi/shell -- -DCONFIG_WIFI_NM_WPA_SUPPLICANT_P2P=y

Wi-Fi NAN（邻居感知网络）

Wi-Fi NAN（邻居感知网络，Neighbor Awareness Networking），也称为 Wi-Fi Aware，使设备无需传统接入点或互联网连接，即可发现服务并与附近的设备通信。该功能采用发布-订阅模型，设备可以发布服务，或者订阅以发现附近对等设备提供的服务。

要启用 Wi-Fi NAN 支持并进行构建：

$ west build -p -b <board> samples/net/wifi/shell -- -DCONFIG_WIFI_NM_WPA_SUPPLICANT_NAN=y
