DNS 解析

  • 概述

  • 网络管理事件

  • 使用示例

  • API 参考

概述

DNS 解析器按照 RFC 1035 实现了一个基本的 DNS 解析器。支持的 DNS 应答类型为 IPv4/IPv6 地址和 CNAME。

如果收到 CNAME，DNS 解析器会再创建一个 DNS 查询。额外查询的数量由 Kconfig 变量 CONFIG_DNS_RESOLVER_ADDITIONAL_QUERIES 控制。

可以通过设置 Kconfig 选项 CONFIG_MDNS_RESOLVER 启用组播 DNS（mDNS）客户端解析器支持。关于 mDNS 的更多细节，请参见 RFC 6762。

可以通过设置 Kconfig 变量 CONFIG_LLMNR_RESOLVER 启用链路本地组播名称解析（LLMNR）客户端解析器支持。关于 LLMNR 的更多细节，请参见 RFC 4795。

关于 DNS 配置变量的更多信息，请参见 subsys/net/lib/dns/Kconfig。DNS 解析器 API 位于 include/zephyr/net/dns_resolve.h。

RFC 6763 中描述的基于 DNS 的服务发现查询可以通过 dns_resolve_service() API 完成。返回的服务描述会传给用户提供的回调，API 会把地址族设为 AF_LOCAL，表示该值不是 IPv4 或 IPv6 地址，而是服务描述。

示例：

#include <zephyr/net/dns_resolve.h>

#define MAX_STR_LEN CONFIG_DNS_RESOLVER_MAX_NAME_LEN

static void dns_result_cb(enum dns_resolve_status status,
                          struct dns_addrinfo *info,
                          void *user_data)
{
     if (status == DNS_EAI_CANCELED) {
             /* dns: Timeout while resolving name */
             return;
     }

     if (status == DNS_EAI_INPROGRESS && info) {
             char str[MAX_STR_LEN + 1];

             if (info->ai_family == NET_AF_INET) {
                     net_addr_ntop(NET_AF_INET,
                                   &net_sin(&info->ai_addr)->sin_addr,
                                   str, NET_IPV4_ADDR_LEN);
             } else if (info->ai_family == NET_AF_INET6) {
                     net_addr_ntop(NET_AF_INET6,
                                   &net_sin6(&info->ai_addr)->sin6_addr,
                                   str, NET_IPV6_ADDR_LEN);
             } else if (info->ai_family == AF_LOCAL) {
                     /* service discovery */
                     memset(str, 0, MAX_STR_LEN);
                     memcpy(str, info->ai_canonname,
                            MIN(info->ai_addrlen, MAX_STR_LEN));
             } else {
                     strncpy(str, "Invalid proto family", MAX_STR_LEN + 1);
             }

             str[MAX_STR_LEN] = '\0';

             printk("dns: %s\n", str);
             return;
     }

     if (status == DNS_EAI_ALLDONE) {
             printk("dns: All results received\n");
             return;
     }

     if (status == DNS_EAI_FAIL) {
             printk("dns: No such name found.\n");
             return;
     }

     printk("dns: Unhandled status %d received (errno %d)\n", status, errno);
}

#define DNS_TIMEOUT (MSEC_PER_SEC * 5) /* in ms */

static void discover_service(void)
{
     int ret = dns_resolve_service(dns_resolve_get_default(),
                                   "_http._tcp.dns-sd.org",
                                   NULL, dns_result_cb,
                                   NULL, DNS_TIMEOUT);
     ...
}

由于服务发现查询可能返回很长的字符串，数据包也可能很大，可能需要调整以下 Kconfig 选项：

  • CONFIG_DNS_RESOLVER_MAX_ANSWER_SIZE。该选项指定应答的最大大小，典型值可以是 1024。该选项的默认大小为 512 字节。

  • CONFIG_DNS_RESOLVER_MAX_NAME_LEN。该选项指定返回名称的最大长度。该值取决于预期的数据大小，典型值可能是 128 字节。

网络管理事件

DNS 解析器会产生以下 NET_MGMT_EVENT 事件：

  • NET_EVENT_DNS_SERVER_ADD：向解析器添加了一个 DNS 服务器槽位。每个槽位产生一次，事件负载为发起该操作的接口。

  • NET_EVENT_DNS_SERVER_DEL：移除了一个 DNS 服务器槽位，事件负载为发起该操作的接口。

  • NET_EVENT_DNS_SERVERS_RECONFIGURED：通过 dns_resolve_reconfigure() 或 dns_resolve_reconfigure_with_interfaces() 刷新了 DNS 服务器配置。每次调用成功都会产生该事件，无论各个服务器槽位是否真的发生变化，其 iface 为 NULL（系统级事件）。

ADD 和 DEL 是 增量 事件：当调用 dns_resolve_reconfigure() 时传入的服务器集合与现有集合相同，ADD 和 DEL 都不会触发。解析器有意抑制这两个事件，以避免在 DHCP offer 重传和 IPv6 RA 时取消正在进行的查询。如果使用者需要在网络事件之后获得“DNS 配置再次就绪”的判断条件（例如，PPP iface 重新建立后，在每个电源管理恢复周期都会通过 IPCP 推送相同的 DNS 服务器），应监听 NET_EVENT_DNS_SERVERS_RECONFIGURED，而不是 NET_EVENT_DNS_SERVER_ADD。
