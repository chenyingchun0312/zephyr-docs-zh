概述

Model Context Protocol（MCP，模型上下文协议）是一项开放标准，用于把 AI 应用程序连接到外部数据源和工具。它定义了一种在 MCP 客户端（AI 代理）与 MCP 服务器（能力提供方）之间基于 JSON-RPC 的通信协议。

Zephyr MCP 服务器库实现了 MCP 规范（版本 2025-11-25）中的服务器角色。它允许联网的 Zephyr 设备公开工具，供 AI 代理通过 HTTP 发现和调用。该库构建在现有的 Zephyr 子系统之上：使用 HTTP 服务器库进行传输，使用 JSON 库进行序列化。

备注

该库被标记为 实验性。目前只实现了带文本响应的工具服务。更多内容类型、会话管理、SSE 流式传输、授权及其他服务等功能计划在未来版本中提供。

架构

应用程序

注册工具并实现其回调。工具执行结果通过 mcp_server_submit_tool_message() 提交回核心。

MCP 服务器核心

实现 MCP 协议状态机。管理客户端连接、工具注册表、执行跟踪以及一个可配置的工作线程池。一个健康监视线程负责执行超时控制并触发取消。

JSON 处理

使用 Zephyr JSON 库序列化发出的响应，并反序列化收到的 JSON-RPC 请求。

传输层

对网络协议进行抽象。自带的 HTTP 传输使用 Zephyr HTTP 服务器库。另有一个模拟传输可用于单元测试。

HTTP 传输与异步响应

Zephyr 的 HTTP 服务器在单个线程中运行，对所有连接一次只处理一个请求。资源回调必须返回，服务器才能处理来自任意客户端的下一个请求。由于工具执行所需的时间可能超过阻塞整个服务器所能接受的时长，MCP HTTP 传输实现了一种从轮询回退到 SSE 的机制：

  1. 收到 POST 请求时，传输在内部轮询工具响应，最长 CONFIG_MCP_HTTP_TIMEOUT_MS（每隔 CONFIG_MCP_HTTP_POLL_INTERVAL_MS 检查一次）。

  2. 如果在此时间窗口内响应已就绪，则直接以 application/json 返回。

  3. 如果超时到期，传输切换到 SSE 模式：返回一个只包含事件 ID（没有数据）的 text/event-stream 响应。这会告知客户端响应尚未完成，客户端应开始用周期性的 GET 请求进行轮询（间隔由 CONFIG_MCP_HTTP_SSE_RETRY_MS 控制）。

  4. 随后客户端发出带有 Last-Event-Id 头部的周期性 GET 请求。如果结果已就绪，服务器发送响应并结束 SSE 流。如果结果尚未就绪，服务器会再次发送重试响应。

备注

这并不是完整的 SSE 流式传输。该机制只为未能在初始 HTTP 超时内完成的请求投递延迟响应。在此阶段不支持服务器发起的通知和流式工具输出。

配置

通过 CONFIG_MCP_SERVER 启用该库。传输通过 CONFIG_MCP_TRANSPORT_HTTP（默认）或 CONFIG_MCP_TRANSPORT_MOCK（仅用于测试）选择。

最小的 prj.conf：

CONFIG_NETWORKING=y
CONFIG_NET_TCP=y
CONFIG_HTTP_SERVER=y
CONFIG_MCP_SERVER=y
CONFIG_MCP_TRANSPORT_HTTP=y

主要配置组：

可扩展性

CONFIG_MCP_MAX_CLIENTS、CONFIG_MCP_MAX_CLIENT_REQUESTS、CONFIG_MCP_MAX_TOOLS、CONFIG_MCP_REQUEST_WORKERS

超时

CONFIG_MCP_TOOL_EXEC_TIMEOUT_MS、CONFIG_MCP_TOOL_IDLE_TIMEOUT_MS、CONFIG_MCP_TOOL_CANCEL_TIMEOUT_MS、CONFIG_MCP_CLIENT_TIMEOUT_MS、CONFIG_MCP_HTTP_TIMEOUT_MS

内存分配

CONFIG_MCP_ALLOC_SLAB（默认）使用预先分配的内存块（slab）提供确定性、无碎片的分配。CONFIG_MCP_ALLOC_HEAP 使用 k_malloc/k_free 按需分配，代价是可能产生碎片。

用法

服务器设置

#include <zephyr/net/mcp/mcp_server.h>
#include <zephyr/net/mcp/mcp_server_http.h>

static mcp_server_ctx_t server;

int main(void)
{
    server = mcp_server_init();
    mcp_server_http_init(server);

    /* Register tools here */

    mcp_server_start(server);
    mcp_server_http_start(server);
    return 0;
}

工具注册

static int my_tool_cb(enum mcp_tool_event_type event,
                      const char *arguments,
                      const char *execution_token)
{
    if (event == MCP_TOOL_CANCEL_REQUEST) {
        struct mcp_tool_message ack = {
            .type = MCP_USR_TOOL_CANCEL_ACK,
        };

        mcp_server_submit_tool_message(server, &ack, execution_token);

        /* Handle cancellation here */
    }

    struct mcp_tool_message resp = {
        .type = MCP_USR_TOOL_RESPONSE,
        .data = "Tool execution result",
        .length = strlen("Tool execution result"),
        .is_error = false,
    };
    return mcp_server_submit_tool_message(server, &resp, execution_token);
}

static const struct mcp_tool_record my_tool = {
    .metadata = {
        .name = "my_tool",
        .input_schema = "{\"type\":\"object\",\"properties\":{}}",
    },
    .callback = my_tool_cb,
};

mcp_server_add_tool(server, &my_tool);

.data 字段接受纯文本字符串。服务器会自动把它包装成符合 MCP 规范的 "text" 内容项。最大长度为 CONFIG_MCP_TOOL_RESULT_MAX_LEN。

工具回调模式

阻塞式

运行时间短的工具直接在工作线程中执行，并在返回之前调用 mcp_server_submit_tool_message()。工作线程栈大小为 CONFIG_MCP_REQUEST_WORKER_STACK_SIZE。

异步式

长时间运行的工具应创建一个专用线程，立即从回调返回，之后使用所提供的执行令牌提交响应。周期性的 ping（MCP_USR_TOOL_PING）可以防止健康监视器取消空闲的执行。

取消

当健康监视器或客户端请求取消时，会以 MCP_TOOL_CANCEL_REQUEST 调用回调。工具应停止工作并提交 MCP_USR_TOOL_CANCEL_ACK。

工具移除

可以在运行时通过 mcp_server_remove_tool() 移除工具。如果该工具正在执行，调用会返回 -EBUSY，请稍后重试。

限制

以下 MCP 功能尚未实现：

  • 资源（resources）、提示（prompts）、采样（sampling）、根（roots）和会话管理

  • 服务器发起的通知和流式工具输出

  • 图像和嵌入资源内容类型（仅支持 "text"）

  • 完整的 SSE 传输（仅支持延迟响应投递）

测试

单元测试位于 tests/net/lib/mcp/ 下。它们使用模拟传输（CONFIG_MCP_TRANSPORT_MOCK），在没有网络协议栈的情况下测试协议逻辑。
