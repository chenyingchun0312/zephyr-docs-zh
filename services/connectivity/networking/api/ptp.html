概述

PTP 是一种在应用层实现的网络协议，用于同步计算机网络中的时钟，精度可达亚微秒级。该协议栈支持 IEEE 1588-2019 standard （《IEEE 网络化测量与控制系统精确时钟同步协议标准》）中定义的协议和过程。PTP 有多种配置文件（profile），可以在 L2（以太网）或 L3（UDP/IPv4 或 UDP/IPv6）之上实现。其精度通过对协议数据包进行硬件时间戳来实现。

Zephyr 的 PTP 协议栈实现包含以下部分：

  • 处理传入消息和事件的 PTP 协议栈线程

  • 与 ptp_clock 驱动的集成

  • 在系统初始化期间执行的 PTP 协议栈初始化

该实现会自动创建 PTP 端口（每个 PTP 端口对应一个唯一的接口）。

网络传输模式

网络传输模式通过 PTP_NETWORK_MODE Kconfig 选择项选择：

  • 多播模式（CONFIG_PTP_NETWORK_MODE_MULTICAST，默认）是标准的 PTP 模式，所有 PTP 消息都发送到默认的多播地址。这意味着每个节点都会收到所有其他节点的 Delay_Req 和 Delay_Resp 消息对，从而增加网络上的流量。在只有少量时间接收方（timeReceiver）的小型网络中，这通常不成问题。

  • 混合模式（CONFIG_PTP_NETWORK_MODE_HYBRID）仍将 Announce、Sync 和 Follow_Up 消息发送到默认的多播地址，但时间接收方会以单播方式将其 Delay_Req 消息直接发送到当前时间发送方（timeTransmitter）的协议地址（IP 地址；对于 IEEE 802.3 传输则为 MAC 地址），时间发送方再以单播 Delay_Resp 应答发出请求的时间接收方。这降低了网络上的 PTP 流量，在扩展到拥有大量时间接收方的大型网络时，这一点可能很重要。混合模式只要求网络支持从时间发送方到时间接收方的多播传输。该模式与 linuxptp 的 hybrid_e2e 选项以及 sfptpd 的 hybrid 网络模式兼容；不支持单播协商。

    如果时间发送方连续 CONFIG_PTP_HYBRID_FALLBACK_ATTEMPTS 次未应答单播 Delay_Req 消息，PTP 端口会记录一条错误，退回到多播延迟测量，并保持多播方式，直到选出新的时间发送方。可以通过 CONFIG_PTP_NETWORK_MODE_HYBRID_NO_FALLBACK 禁用这种回退，此时端口会始终发送单播 Delay_Req 消息。

    混合模式要求使用端到端延迟机制（CONFIG_PTP_DELAY_MECHANISM_E2E），并且在所有传输协议（UDP IPv4、UDP IPv6 和 IEEE 802.3）上都受支持。

时间戳说明

当 RX 硬件时间戳不可用或无效时，同步会退而在接收处理过程中读取 PHC 时间。这可能会因帧到达与读取 PHC 之间的软件处理延迟（数据包路径和调度）而引入额外的抖动。

对于没有真正由驱动提供 RX 硬件时间戳的 L2 AF_PACKET 路径，这种行为是预期之中的。

对于 IEEE 802.3 传输，Sync 以两步模式发送，Follow_Up 根据 TX 时间戳回调生成。如果 TX 时间戳缺失或延迟，协议栈会记录一条警告并跳过该 Sync 序列的 Follow_Up，然后在后续间隔中继续正常发送 Sync（尽力而为的行为）。

可以通过 CONFIG_PTP_DELAY_MECHANISM_P2P 选择点对点延迟测量。首个受支持的 P2P 模式是两步式 Pdelay_Req / Pdelay_Resp / Pdelay_Resp_Follow_Up。一步式 Pdelay_Resp 样本会被拒绝并记录日志，留待以后实现。

支持的硬件

虽然协议栈本身与硬件无关，但必须在以太网驱动中启用以太网帧时间戳支持。

支持的开发板：

  • Nucleo H563ZI

  • Nucleo H743ZI

  • Nucleo H745ZI-Q

  • Nucleo F767ZI

  • FRDM-MCXN947

  • Native simulator - native_sim （仅可用于简单测试，由于没有硬件时钟，功能有限）

启用协议栈

必须在 prj.conf 文件中启用以下配置选项。

  • CONFIG_PTP
