网络数据包过滤

  • 概述

  • 示例

  • API 参考

概述

网络数据包过滤功能提供了构建自定义规则的基础设施，用于接受和/或拒绝数据包的发送和接收。它还允许修改传入网络数据包的优先级。这可用于构建基本的防火墙、控制网络流量等。

必须设置 CONFIG_NET_PKT_FILTER 才能启用相关 API。

发送路径和接收路径都可以有一个过滤规则列表。每条规则由一组条件和一个数据包处理结果组成。每个数据包都要接受规则所附条件的检验。当某条规则的所有条件都为真时，数据包的处理结果立即按该规则的规定确定，不再考虑其余规则。如果有一个条件为假，则考虑列表中的下一条规则。

数据包处理结果可以是 NET_OK （接受数据包）、NET_DROP （丢弃数据包）或 NET_CONTINUE （动态修改其优先级）。

当处理结果为 NET_CONTINUE 时，优先级会被更新，但最终结果尚未确定，处理将继续进行。如果多条规则的所有条件都为真，则数据包获得最后考虑的那条规则的优先级。

规则由 npf_rule 对象表示。可以使用 npf_insert_rule()、npf_append_rule() 和 npf_remove_rule() 将其插入、追加到 npf_rule_list 对象所包含的规则列表中，或从中移除。

网络协议栈的不同层有不同的规则集。有些规则应用于以太网等 L2 层，有些应用于处理 IPv4 或 IPv6 协议的 L3 层。local_in 规则用于匹配运行在 IPv4 或 IPv6 之上的传入协议类型，例如 UDP 或 TCP 数据包。各层的规则支持可由下文提到的相关 Kconfig 选项控制。

  • npf_send_rules 是应用于 L2 层传出数据包的规则列表

  • npf_recv_rules 是应用于 L2 层传入数据包的规则列表

  • npf_ipv4_recv_rules 是应用于传入 IPv4 数据包的规则列表。可通过 CONFIG_NET_PKT_FILTER_IPV4_HOOK 选项启用或禁用。

  • npf_ipv6_recv_rules 是应用于传入 IPv6 数据包的规则列表。可通过 CONFIG_NET_PKT_FILTER_IPV6_HOOK 选项启用或禁用。

  • npf_local_in_recv_rules 是应用于传入 UDP 或 TCP 数据包的规则列表。可通过 CONFIG_NET_PKT_FILTER_LOCAL_IN_HOOK 选项启用或禁用。

如果过滤规则列表为空，则默认结果为 NET_OK。如果一个非空规则列表一直执行到末尾，则默认结果为 NET_DROP。不过，建议始终以显式的默认终止规则（npf_default_ok 或 npf_default_drop）结束非空规则列表。

规则条件由 npf_test 表示。当某个条件需要额外的测试数据时，可以将该结构体嵌入到一个更大的结构体中。此类条件的测试函数负责根据传入的 npf_test 结构体指针获取外层结构体。

include/zephyr/net/net_pkt_filter.h 中提供了一些便捷宏，用于为各种条件静态定义条件实例；还提供了 NPF_RULE() 和 NPF_PRIORITY()，用于创建立即给出处理结果或修改优先级的规则实例。

关于如何创建和管理数据包过滤器，另请参见 Network packet filter 示例。网络 shell 提供了 net filter 命令，可在运行时查看已安装的规则。

示例

下面是一个用法示例：

static NPF_SIZE_MAX(maxsize_200, 200);
static NPF_ETH_TYPE_MATCH(ip_packet, NET_ETH_PTYPE_IP);

static NPF_RULE(small_ip_pkt, NET_OK, ip_packet, maxsize_200);

void install_my_filter(void)
{
    npf_insert_recv_rule(&npf_default_drop);
    npf_insert_recv_rule(&small_ip_pkt);
}

上述规则会接受 200 字节及以下的 IP 数据包，并丢弃其他所有数据包。

实现相同结果的另一种（效率较低的）方式是：

static NPF_SIZE_MIN(minsize_201, 201);
static NPF_ETH_TYPE_UNMATCH(not_ip_packet, NET_ETH_PTYPE_IP);

static NPF_RULE(reject_big_pkts, NET_DROP, minsize_201);
static NPF_RULE(reject_non_ip, NET_DROP, not_ip_packet);

void install_my_filter(void) {
    npf_append_recv_rule(&reject_big_pkts);
    npf_append_recv_rule(&reject_non_ip);
    npf_append_recv_rule(&npf_default_ok);
}

此示例为不同的网络流量分配优先级。它为 ptp 数据包分配网络控制优先级（NET_PRIORITY_NC），为第 6 版互联网协议流量分配关键应用优先级（NET_PRIORITY_CA），为第 4 版互联网协议流量分配卓越努力优先级（NET_PRIORITY_EE），并为 lldp 和 arp 分配最低的后台优先级（NET_PRIORITY_BK）。

只有在项目配置 CONFIG_NET_TC_RX_COUNT 中启用了多个流量类别队列时，优先级规则才真正有用。数据包优先级到流量类别队列的映射遵循 802.1Q 标准，并取决于 CONFIG_NET_TC_RX_COUNT。

static NPF_ETH_TYPE_MATCH(is_arp, NET_ETH_PTYPE_ARP);
static NPF_ETH_TYPE_MATCH(is_lldp, NET_ETH_PTYPE_LLDP);
static NPF_ETH_TYPE_MATCH(is_ptp, NET_ETH_PTYPE_PTP);
static NPF_ETH_TYPE_MATCH(is_ipv4, NET_ETH_PTYPE_IP);
static NPF_ETH_TYPE_MATCH(is_ipv6, NET_ETH_PTYPE_IPV6);

static NPF_PRIORITY(priority_bk, NET_PRIORITY_BK, is_arp, is_lldp);
static NPF_PRIORITY(priority_ee, NET_PRIORITY_EE, is_ipv4);
static NPF_PRIORITY(priority_ca, NET_PRIORITY_CA, is_ipv6);
static NPF_PRIORITY(priority_nc, NET_PRIORITY_NC, is_ptp);

void install_my_filter(void) {
    npf_append_recv_rule(&priority_bk);
    npf_append_recv_rule(&priority_ee);
    npf_append_recv_rule(&priority_ca);
    npf_append_recv_rule(&priority_nc);
    npf_append_recv_rule(&npf_default_ok);
}
