TLS 凭据 Shell

TLS 凭据 shell 提供了一个命令行界面，用于管理已安装的 TLS 凭据。

命令

缓冲凭据（buf）

将数据逐步缓冲到凭据缓冲区中，以便随后使用 添加凭据（add） 命令添加。

或者：

  • 清空凭据缓冲区。

  • 将凭据直接加载到凭据缓冲区，以 Ctrl + c 结束。

用法

要将 <DATA> 追加到凭据缓冲区，请使用：

cred buf <DATA>

根据需要多次使用该命令，将完整的凭据加载到凭据缓冲区中，然后使用 添加凭据（add） 命令存储它。

要将 <DATA> 直接加载到凭据缓冲区，请使用：

cred buf load
<DATA>
Ctrl + c

要清空凭据缓冲区，请使用：

cred buf clear

参数

参数

说明

<DATA>

要追加到凭据缓冲区的文本数据。可以是文本，也可以是 base64 编码的二进制数据。详细信息请参见 添加凭据（add） 和 存储/获取格式。

添加凭据（add）

将一个 TLS 凭据添加到 TLS 凭据存储中。

凭据内容可以在调用 cred add 时直接提供，否则将从凭据缓冲区中获取。

用法

要使用凭据缓冲区中的数据添加 TLS 凭据，请使用：

cred add <SECTAG> <TYPE> <BACKEND> <FORMAT>

要使用同一命令中提供的数据添加 TLS 凭据，请使用：

cred add <SECTAG> <TYPE> <BACKEND> <FORMAT> <DATA>

参数

参数

说明

<SECTAG>

新凭据要使用的 sectag。可以是任意非负整数。

<TYPE>

要添加的凭据类型。有效值请参见 凭据类型。

<BACKEND>

保留参数。必须始终为 DEFAULT （不区分大小写）。

<FORMAT>

指定所提供凭据的存储格式。有效值请参见 存储/获取格式。

<DATA>

如果提供了此参数，它将用作凭据数据，而不使用凭据缓冲区中的任何数据。可以是文本，也可以是 base64 编码的二进制数据。

删除凭据（del）

从凭据存储中删除指定的凭据。

用法

要删除与指定 sectag 和凭据类型匹配的凭据（如果存在），请使用：

cred del <SECTAG> <TYPE>

参数

参数

说明

<SECTAG>

要删除的凭据的 sectag。可以是任意非负整数。

<TYPE>

要删除的凭据类型。有效值请参见 凭据类型。

获取凭据内容（get）

获取并打印指定凭据的内容。

用法

要获取并打印与指定 sectag 和凭据类型匹配的凭据（如果存在），请使用：

cred get <SECTAG> <TYPE> <FORMAT>

参数

参数

说明

<SECTAG>

要获取的凭据的 sectag。可以是任意非负整数。

<TYPE>

要获取的凭据类型。有效值请参见 凭据类型。

<FORMAT>

指定所获取凭据的输出格式。有效值请参见 存储/获取格式。

列出凭据（list）

列出凭据存储中的 TLS 凭据。

用法

要列出所有可用的凭据，请使用：

cred list

要列出具有指定 sectag 的所有凭据，请使用：

cred list <SECTAG>

要列出具有指定凭据类型的所有凭据，请使用：

cred list any <TYPE>

要列出具有指定凭据类型和 sectag 的所有凭据，请使用：

cred list <SECTAG> <TYPE>

参数

参数

说明

<SECTAG>

可选。如果提供，则只列出具有此 sectag 的凭据。传入 any 或省略此参数表示允许任意 sectag。否则，可以是任意非负整数。

<TYPE>

可选。如果提供，则只列出具有此凭据类型的凭据。传入 any 或省略此参数表示允许任意凭据类型。否则，有效值请参见 凭据类型。

输出

该命令以下列（符合 CSV 规范的）格式输出所有匹配的凭据：

<SECTAG>,<TYPE>,<DIGEST>,<STATUS>

其中：

符号

值

<SECTAG>

所列凭据的 sectag。一个非负整数。

<TYPE>

所列凭据的凭据类型简码（详细信息请参见 凭据类型）。

<DIGEST>

表示凭据内容的字符串摘要。该摘要的具体性质可能因凭据存储后端而异，但目前所有后端都使用原始凭据内容的 base64 编码 SHA256 哈希（因此，本质上相同但存储格式不同的凭据会有不同的摘要）。

<STATUS>

状态码，表示为所列凭据生成摘要是否成功。成功时为 0，否则为特定于存储后端的负错误码。状态不为零的行将以错误格式打印。

列表打印完毕后，会以如下形式打印所找到凭据的最终汇总：

<N> credentials found.

其中 <N> 是找到的凭据数量，如果未找到任何凭据则为零。

凭据类型

可以使用以下关键字（不区分大小写）指定凭据类型：

关键字

含义

CA_CERT, CA

受信任的 CA 证书。

SERVER_CERT, SELF_CERT, CLIENT_CERT, CLIENT, SELF, SERV

自身证书或服务器证书。

PRIVATE_KEY, PK

私钥。

PRE_SHARED_KEY, PSK

预共享密钥。

PRE_SHARED_KEY_ID, PSK_ID

预共享密钥的 ID。

存储/获取格式

tls_credentials 模块将存储的凭据视为任意二进制缓冲区。

为方便起见，TLS 凭据 shell 提供了四种格式，用于通过 shell 提供并在之后获取这些缓冲区。

这些格式及其（不区分大小写的）关键字如下：

关键字

含义

存储时的行为（cred add）

获取时的行为（cred get）

BIN

shell 将凭据作为 base64 处理，存储时不带 NULL 终止符。

输入 shell 的数据会先从 base64 解码为原始二进制，然后再存储。不追加终止符。

存储的数据会先编码为 base64，然后再打印。

BINT

shell 将凭据作为 base64 处理，存储时带 NULL 终止符。

输入 shell 的数据会从 base64 解码为原始二进制，并在存储前追加一个 NULL 终止符。

先从存储的数据中去掉 NULL 终止符，再将数据编码为 base64 并打印。

STR

shell 将凭据作为字面字符串处理，存储时不带 NULL 终止符。

输入 shell 的文本数据会按原样存储，不带 NULL 终止符。

存储的数据以文本形式打印。不可打印的字符会打印为 ?

STRT

shell 将凭据作为字面字符串处理，存储时带 NULL 终止符。

输入 shell 的文本数据会按原样存储，并带 NULL 终止符。

先从存储的数据中去掉 NULL 终止符，再将数据以文本形式打印。不可打印的字符会打印为 ?

BIN 格式可用于安装任何类型的凭据，因为 base64 可以编码任何可能的二进制缓冲区。其余三种格式是为特殊用例提供的便利。

例如：

  • 要安装可打印的预共享密钥，可使用 STR 直接输入 PSK，无需先进行编码。这可以确保存储时不带 NULL 终止符。

  • 要安装 DER 格式的 X.509 证书（或其他原始二进制凭据，例如不可打印的 PSK），请将二进制数据进行 base64 编码，并使用 BIN 格式。

  • 要安装 PEM 格式的 X.509 证书或证书链，请对完整的 PEM 字符串（包括换行符和 ----BEGIN X ---- / ----END X---- 标记）进行 base64 编码，然后使用 BINT 格式，以确保存储的字符串以 NULL 结尾。之所以需要这样做，是因为 Zephyr 的 shell 不支持多行字符串；否则，可以直接使用 STRT 格式而无需 base64 编码。如果手动将 NULL 终止符编码进 base64 数据中，也可以改用 BIN。
