网络管理

概述

网络管理 API 使应用程序以及网络层代码本身能够调用 IP 协议栈中任意层级上定义的网络例程，或接收相关网络事件的通知。例如，应用程序代码可以使用这些 API 请求在基于 Wi-Fi 或 Bluetooth 的网络接口上执行扫描，或者请求在网络接口 IP 地址变化时得到通知。

网络管理 API 的实现旨在节省内存，它在构建时剔除未使用的管理例程的代码。它没有为网络管理过程使用各自独立、静态定义的 API，而是通过 NET_MGMT_REGISTER_REQUEST_HANDLER 宏注册已定义的过程处理函数。过程请求统一通过 net_mgmt() 这一个 API 发起，由它调用对应请求的已注册处理函数。

当前实现处于实验阶段，在未来的版本中可能会有变化和改进。

请求已定义的过程

所有网络管理请求的形式都是 net_mgmt(mgmt_request, ...)。mgmt_request 参数是一个位掩码，指明目标协议栈层、是否涉及 net_if 对象，以及所请求的具体管理过程。可用的过程请求取决于协议栈中实现了哪些内容。

为避免额外开销，所有 net_mgmt() 调用都是直接调用。虽然这在未来的版本中可能会改变，但不会影响该函数的使用者。

监听网络事件

要接收网络事件通知，可以注册一个回调函数，并指定一组事件，用于筛选何时调用该回调。对于一对层和代码，回调必须是唯一的，而命令部分则是一个事件掩码。

运行时有两个函数可用：net_mgmt_add_event_callback() 用于注册回调函数，net_mgmt_del_event_callback() 用于注销回调。辅助函数 net_mgmt_init_event_callback() 可用于简化回调结构体的初始化。

此外，还可以使用 NET_MGMT_REGISTER_EVENT_HANDLER 在编译时注册回调处理函数。

当发生的事件与某个回调的事件集匹配时，会以实际的事件代码调用相应的回调函数。因此，如有需要，可以由同一个回调函数处理不同的事件。

警告

对于层和层代码相同的事件，事件集筛选可能出现误报。回调处理函数 必须 将（作为参数传入的）事件代码与其要处理的具体网络事件进行核对，无论 传给 net_mgmt_init_event_callback() 的事件集中包含多少个事件。

注意，要接收来自多个层的事件，必须注册多个监听器，每个被监听的层对应一个。回调处理函数可以在不同层的事件之间共享。

（对于层和层代码相同的事件，可能会出现误报。）

示例如下。

/*
 * Set of events to handle.
 * See e.g. include/zephyr/net/net_event.h for some NET_EVENT_xxx values.
 */
#define EVENT_IFACE_SET (NET_EVENT_IF_xxx | NET_EVENT_IF_yyy)
#define EVENT_IPV4_SET (NET_EVENT_IPV4_xxx | NET_EVENT_IPV4_yyy)

struct net_mgmt_event_callback iface_callback;
struct net_mgmt_event_callback ipv4_callback;

void callback_handler(struct net_mgmt_event_callback *cb,
                      uint64_t mgmt_event,
                      struct net_if *iface)
{
        if (mgmt_event == NET_EVENT_IF_xxx) {
                /* Handle NET_EVENT_IF_xxx */
        } else if (mgmt_event == NET_EVENT_IF_yyy) {
                /* Handle NET_EVENT_IF_yyy */
        } else if (mgmt_event == NET_EVENT_IPV4_xxx) {
                /* Handle NET_EVENT_IPV4_xxx */
        } else if (mgmt_event == NET_EVENT_IPV4_yyy) {
                /* Handle NET_EVENT_IPV4_yyy */
        } else {
                /* Spurious (false positive) invocation. */
        }
}

void register_cb(void)
{
        net_mgmt_init_event_callback(&iface_callback, callback_handler,
                                     EVENT_IFACE_SET);
        net_mgmt_init_event_callback(&ipv4_callback, callback_handler,
                                     EVENT_IPV4_SET);
        net_mgmt_add_event_callback(&iface_callback);
        net_mgmt_add_event_callback(&ipv4_callback);
}

或者以类似方式使用 NET_MGMT_REGISTER_EVENT_HANDLER。

备注

只有启用了 CONFIG_NET_MGMT_EVENT_INFO 时，info 和 info_length 参数才可用；否则它们分别为 NULL 和零。

/*
 * Set of events to handle.
 */
#define EVENT_IFACE_SET (NET_EVENT_IF_xxx | NET_EVENT_IF_yyy)
#define EVENT_IPV4_SET (NET_EVENT_IPV4_xxx | NET_EVENT_IPV4_yyy)

static void event_handler(uint64_t mgmt_event, struct net_if *iface,
                          void *info, size_t info_length,
                          void *user_data)
{
        if (mgmt_event == NET_EVENT_IF_xxx) {
                /* Handle NET_EVENT_IF_xxx */
        } else if (mgmt_event == NET_EVENT_IF_yyy) {
                /* Handle NET_EVENT_IF_yyy */
        } else if (mgmt_event == NET_EVENT_IPV4_xxx) {
                /* Handle NET_EVENT_IPV4_xxx */
        } else if (mgmt_event == NET_EVENT_IPV4_yyy) {
                /* Handle NET_EVENT_IPV4_yyy */
        } else {
                /* Spurious (false positive) invocation. */
        }
}

NET_MGMT_REGISTER_EVENT_HANDLER(iface_event_handler, EVENT_IFACE_SET,
                                event_handler, NULL);
NET_MGMT_REGISTER_EVENT_HANDLER(ipv4_event_handler, EVENT_IPV4_SET,
                                event_handler, NULL);

可监听的通用核心事件请参见 include/zephyr/net/net_event.h。

定义网络管理过程

可以定义一个处理函数并以相应的 mgmt_request 代码注册它，从而提供特定于自己协议栈实现的额外管理过程。

管理请求代码根据目标层定义在相应的位置；如果目标层是 l2，还取决于具体的技术。例如，所有 IP 层管理请求代码都位于 include/zephyr/net/net_event.h 头文件中。而对于 L2 技术，比如以太网，则位于 include/zephyr/net/ethernet.h 中

按照以下签名定义处理函数：

static int your_handler(uint64_t mgmt_event, struct net_if *iface,
                        void *data, size_t len);

然后以相应的 mgmt_request 代码注册它：

NET_MGMT_REGISTER_REQUEST_HANDLER(<mgmt_request code>, your_handler);

之后即可通过以下方式调用这个新的管理过程：

net_mgmt(<mgmt_request code>, ...);

发出网络事件信号

可以使用 net_mgmt_event_notify() 函数并提供网络事件代码来发出特定网络事件的信号。详细信息请参见 include/zephyr/net/net_mgmt.h。与管理请求代码一样，事件代码也可以在特定 L2 技术的管理头文件中找到，例如，如果要监听 802.15.4 L2 技术的事件，应查看 include/zephyr/net/ieee802154_mgmt.h。
