MQTT-SN

  • 概述

  • 使用示例

  • 与标准的差异

概述

MQTT-SN 是知名的 MQTT 协议的一个变体，请参见 MQTT。

与 MQTT 不同，MQTT-SN 不需要 TCP 传输，而是被设计为可以在任何基于消息的传输上使用。它最初主要是针对 ZigBee 设计的，但 Bluetooth、UDP 甚至 UART 等其他传输同样可以使用。

Zephyr 提供了一个基于 BSD 套接字 API 构建的 MQTT-SN 客户端库。可以通过 Kconfig 选项 CONFIG_MQTT_SN_LIB 启用该库，它可以按客户端单独配置，支持 MQTT-SN 1.2 版。Zephyr 的 MQTT-SN 实现可以与任何基于消息的传输配合使用，并且已内置了对 UDP 的支持。

MQTT-SN 客户端需要连接到一个 MQTT-SN 网关。这些网关负责在 MQTT-SN 和 MQTT 之间进行转换。Eclipse Paho 项目提供了一个 MQTT-SN 网关实现，此外也有其他实现可用。https://www.eclipse.org/paho/index.php?page=components/mqtt-sn-transparent-gateway/index.php

MQTT-SN 规范 v1.2 可在此处找到：https://www.oasis-open.org/committees/download.php/66091/MQTT-SN_spec_v1.2.pdf

使用示例

要创建 MQTT-SN 客户端，需要定义一个客户端上下文结构体和缓冲区：

/* Buffers for MQTT client. */
static uint8_t rx_buffer[256];
static uint8_t tx_buffer[256];

/* MQTT-SN client context */
static struct mqtt_sn_client client;

应用程序中可以创建多个 MQTT-SN 客户端实例并独立管理。此外，还需要一个用于传输的结构体。该库已经自带了一个 UDP 的示例实现。

/* MQTT Broker address information. */
static struct mqtt_sn_transport tp;

MQTT-SN 库会通过回调把特定事件通知给客户端。

static void evt_cb(struct mqtt_sn_client *client,
                   const struct mqtt_sn_evt *evt)
{
   switch(evt->type) {
   {
      /* Handle events here. */
   }
}

可能的事件列表请参见 API 参考。

客户端上下文结构体在使用前需要进行初始化和设置。下面是 UDP 传输的配置示例：

struct mqtt_sn_data client_id = MQTT_SN_DATA_STRING_LITERAL("ZEPHYR");
struct net_sockaddr_in gateway = {0};

uint8_t tx_buf[256];
uint8_t rx_buf[256];

mqtt_sn_transport_udp_init(&tp, (struct net_sockaddr*)&gateway, sizeof((gateway)));

mqtt_sn_client_init(&client, &client_id, &tp.tp, evt_cb, tx_buf, sizeof(tx_buf), rx_buf, sizeof(rx_buf));

完成配置后，必须定义要连接的网关的网络地址。MQTT-SN 协议提供了通过通告或搜索机制发现网关的功能。用户至少应执行以下步骤之一，为该库定义一个网关：

  • 调用 mqtt_sn_add_gw() 函数手动定义网关地址。

  • 等待 MQTT_SN_EVT_ADVERTISE。

  • 调用 mqtt_sn_search() 函数并等待 MQTT_SN_EVT_GWINFO 回调。务必定期调用 mqtt_sn_input() 函数以处理传入的消息。

mqtt_sn_search() 函数调用示例：

err = mqtt_sn_search(&mqtt_client, 1);
k_sleep(K_SECONDS(10));
err = mqtt_sn_input(&mqtt_client);
__ASSERT(err == 0, "mqtt_sn_search() failed %d", err);

定义或找到网关地址后，MQTT-SN 客户端就可以连接到网关。调用 mqtt_sn_connect() 函数，它会发送一条 CONNECT MQTT-SN 消息。应用程序应定期调用 mqtt_sn_input() 函数处理收到的响应。如果应用程序知道没有收到任何数据（例如使用 Bluetooth 时），则不必调用 mqtt_sn_input()。注意，如果传输结构体包含一个与 poll() 兼容的函数指针，那么 mqtt_sn_input() 是非阻塞函数。如果连接成功，会通过回调函数向应用程序通知 MQTT_SN_EVT_CONNECTED。

err = mqtt_sn_connect(&client, false, true);
__ASSERT(err == 0, "mqtt_sn_connect() failed %d", err);

while (1) {
        mqtt_sn_input(&client);
        if (connected) {
                mqtt_sn_publish(&client, MQTT_SN_QOS_0, &topic_p, false, &pubdata);
        }
        k_sleep(K_MSEC(500));
}

在上面的代码片段中，先连接网关，再发布消息。如果连接在 MQTT 层失败或发生超时，连接会被中止并返回错误。

连接建立后，应用程序需要定期调用 mqtt_input() 函数处理传入数据。而连接的维持则通过一个 k_work 工作项自动完成。如果收到 MQTT 消息，MQTT 回调函数会被调用，并通知相应的事件。

可以通过调用 mqtt_sn_disconnect() 函数关闭连接，但这对传输没有影响。如果想关闭传输（例如套接字），请调用 mqtt_sn_client_deinit()，它也会对传输进行反初始化。

Zephyr 提供了使用 MQTT-SN 客户端 API 的示例代码。更多信息请参见 MQTT-SN publisher。
