通用精确时间协议（gPTP）

概述

该 gPTP 协议栈支持 IEEE 802.1AS-2011 standard（桥接局域网中时间敏感应用的定时与同步）中定义的协议和过程。

支持的特性

该协议栈处理 IEEE 802.1AS-2011 standard 中定义的通信和状态机。支持该标准附录 A 中为全双工点对点链路端点定义的强制性要求。

原则上，该协议栈能够处理多个网络接口（在标准中也称为“端口”）上的通信，从而充当 802.1AS 网桥。不过，这种工作模式尚未在 Zephyr OS 上验证过。

在遵循 IEEE 802.1AS 汽车配置文件（不交换 Announce 消息）的网络中，该协议栈还可以作为静态配置的时间接收方运行。参见下文的 Static timeReceiver operation。

支持的硬件

虽然协议栈本身与硬件无关，但必须在以太网驱动中启用以太网帧时间戳支持。

支持的开发板：

  • FRDM-K64F

  • Nucleo H743ZI

  • Nucleo H745ZI-Q

  • Nucleo F767ZI

  • SAM E70(B) Xplained

  • Native simulator - native_sim（仅可用于简单测试，由于缺少硬件时钟，功能有限）

  • QEMU Emulation for X86（仿真环境，由于缺少硬件时钟，功能有限）

启用协议栈

必须在 prj.conf 文件中启用以下配置选项。

  • CONFIG_NET_GPTP

Static timeReceiver operation

按照 IEEE 802.1AS 汽车配置文件（AVnu《Automotive Ethernet AVB Functional and Interoperability Specification》）构建的网络使用静态端口角色，而不是最佳主时钟算法（BMCA）。此类网络中的网桥会发送 Sync 和 Follow_Up 消息，但不发送 Announce 消息，并且不需要在其 timeTransmitter 端口上应答 Pdelay 请求。默认的协议栈无法与这样的网桥同步：没有收到 Announce 消息，端口就永远无法进入时间接收方（“slave”）角色。

启用 CONFIG_NET_GPTP_STATIC_TIME_RECEIVER 会把节点配置为静态配置的时间接收方：绕过 BMCA 和所有 Announce 处理，每个端口都固定为时间接收方角色，强制设置 asCapable，使同步不依赖于 Pdelay 测量，本地时钟仅根据收到的 Sync 和 Follow_Up 消息进行校准。即使设置了 CONFIG_NET_GPTP_GM_CAPABLE，节点也永远不会成为主时钟（grandmaster），也永远不会发送 Sync 或 Announce 消息。这与 linuxptp ptp4l 的汽车时间接收方配置相对应（BMCA "noop"、clientOnly、inhibit_announce、asCapable "true"、ignore_source_id）。在标准中，以这种方式禁用 BMCA 对应于 IEEE 802.1AS-2020 的外部端口配置（第 10.3.14 条，源自 IEEE 1588-2019 第 17.6.2 条）。

应用程序接口

可以使用标准第 9 节中定义的以下应用程序接口：

  • ClockSourceTime 接口（gptp_clk_src_time_invoke()）

  • ClockTargetPhaseDiscontinuity 接口（gptp_register_phase_dis_cb()）

  • ClockTargetEventCapture 接口（gptp_event_capture()）

测试

该协议栈已使用 OpenAVnu gPTP 和 Linux ptp4l 守护进程进行过非正式测试。可以使用 Zephyr 源码发行版中的 gPTP 示例应用程序 进行测试。
