HTTP 客户端

  • 概述

  • 使用示例

  • API 参考

概述

HTTP 客户端库可用于发送 HTTP 请求并解析 HTTP 响应。该库通过套接字 API 通信，但不会自行创建套接字。可以通过 Kconfig 选项 CONFIG_HTTP_CLIENT 启用该库。

应用程序必须负责创建套接字并将其传给该库。因此，根据应用程序的需要，该库既可以通过普通 TCP 套接字（HTTP）通信，也可以通过 TLS 套接字（HTTPS）通信。

使用示例

HTTP 客户端库的 API 只有一个函数。

下面是一个正确创建的请求结构体示例：

struct http_request req = { 0 };
static uint8_t recv_buf[512];

req.method = HTTP_GET;
req.url = "/";
req.host = "localhost";
req.protocol = "HTTP/1.1";
req.response = response_cb;
req.recv_buf = recv_buf;
req.recv_buf_len = sizeof(recv_buf);

/* sock is a file descriptor referencing a socket that has been connected
 * to the HTTP server.
 */
ret = http_client_req(sock, &req, 5000, NULL);

如果服务器响应了请求，该库会通过请求结构体中注册的响应回调把响应提供给应用程序。由于该库可能分块提供响应，应用程序必须能够处理这些分块。

除了包含响应数据的结构体外，回调函数还会告知该库是否还期望接收更多数据。

下面是一个非常简单的响应处理函数示例：

static int response_cb(struct http_response *rsp,
                       enum http_final_call final_data,
                       void *user_data)
{
    if (final_data == HTTP_DATA_MORE) {
        LOG_INF("Partial data received (%zd bytes)", rsp->data_len);
    } else if (final_data == HTTP_DATA_FINAL) {
        LOG_INF("All the data received (%zd bytes)", rsp->data_len);
    }

    LOG_INF("Response status %s", rsp->http_status);

    return 0;
}

关于该库用法的更多信息，请参见 HTTP 客户端示例应用程序。
