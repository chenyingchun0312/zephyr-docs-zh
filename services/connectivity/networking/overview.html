支持的功能

网络 IP 协议栈是模块化的，在构建时进行配置。只启用应用程序需要的功能可以最大限度减少内存占用；几乎所有功能都可以禁用。

  • IPv6（RFC 8200），以下子功能可在构建时配置：

    • 同时有效的单播和组播地址的数量。

    • 静态地址或 SLAAC（无状态地址自动配置，Stateless Address Autoconfiguration，RFC 4862）。

    • 多个前缀，最多可达可配置的上限。

    • 可选的邻居缓存，大小可配置。

    • 邻居发现（RFC 4861）和组播侦听者发现 v2（RFC 3810），默认启用。

    • 用于 IEEE 802.15.4 网络的 6LoWPAN 报头压缩（RFC 4944）。

    • DHCPv6（RFC 8415）客户端和服务器，包括前缀委派。参见 DHCPv6。

    • 从路由器通告中获取 DNS 服务器地址（RDNSS，RFC 8106）。

    • 隐私扩展（RFC 8981）。

    • 分片和路径 MTU 发现（RFC 8201）。

    • 组播路由和转发。

  • IPv4（RFC 791），例如用于以太网、Wi-Fi 和蜂窝网络。IEEE 802.15.4 仅支持 IPv6。

    • DHCPv4（RFC 2131）客户端和服务器。参见 DHCPv4。

    • 静态地址，默认启用。

    • 链路本地地址自动配置（RFC 3927）和地址冲突检测（RFC 5227）。示例：IPv4 autoconf client。

    • IGMPv2（RFC 2236）和 IGMPv3（RFC 3376）。

    • 分片和路径 MTU 发现（RFC 1191）。

    • NAT（网络地址转换，Network Address Translation）：接口之间的 SNAT 和 DNAT，支持连接跟踪以及类似 iptables 的规则，用于跨子网过滤和转发数据包。

  • 双栈。 可以同时使用 IPv6 和 IPv4。

  • UDP（RFC 768），用于发送数据报和监听端口，并支持 UDP 选项（RFC 9868）。为基于 UDP 的协议提供数据报分组层路径 MTU 发现（DPLPMTUD，RFC 8899），并通过 UDP 选项（RFC 9869）为普通 UDP 套接字提供该功能。参见 DPLPMTUD。

  • TCP（RFC 9293），支持客户端和服务器，套接字数量可在构建时配置。通过 CONFIG_NET_TCP_SACK 支持对接收数据的选择性确认（RFC 2018）。

  • QUIC（RFC 9000），集成 TLS 1.3（RFC 9001）。参见 QUIC。示例：Echo client (QUIC)、Echo server (QUIC)。

  • BSD 套接字 API，BSD 套接字 API 的一个子集：阻塞和非阻塞的数据报（UDP）和流（TCP）套接字，以及数据包套接字（AF_PACKET）。

  • 安全套接字 API，为套接字 API 提供 TLS 和 DTLS，基于 Mbed TLS 实现。参见 安全套接字。

  • MQTT（ISO/IEC PRF 20922）3.1.1 和 5.0 版本。示例：MQTT publisher。

  • MQTT-SN 1.2 版本。示例：MQTT-SN publisher。

  • CoAP（RFC 7252），支持块传输（RFC 7959）、资源观察（RFC 7641）、OSCORE（RFC 8613），客户端还支持基于 TCP 和 TLS 的 CoAP（RFC 8323）。示例：CoAP client、CoAP service。

  • LwM2M OMA 轻量级机器对机器协议（LwM2M specification 1.0.2，以及通过 Kconfig 选项启用的 LwM2M specification 1.1.1）：引导（Bootstrap）、客户端注册、设备管理与服务启用以及信息上报接口，必需的核心对象和若干 IPSO 智能对象。示例：LwM2M client。

  • HTTP 客户端 支持 HTTP/1.1（RFC 2616），服务器 支持 HTTP/1.1、HTTP/2（RFC 9113）和 HTTP/3（RFC 9114）。示例：HTTP Client、HTTP Server。

  • Websocket（RFC 6455）客户端，以及 HTTP 服务器中的 Websocket 升级。示例：WebSocket Client。

  • DNS（RFC 1035）解析器，支持 IPv4（A）和 IPv6（AAAA）记录、组播 DNS（mDNS，RFC 6762）、DNS 服务发现（DNS-SD，RFC 6763）以及已弃用的 LLMNR（RFC 4795）。mDNS 响应器负责应答查询并通告 DNS-SD 服务。示例：mDNS responder。

  • 网络管理 API，用于接收来自网络协议栈的事件，例如添加了 IP 地址或接口启用时。

  • Wi-Fi 管理 API，用于管理 Wi-Fi 接口，例如扫描和连接网络。

  • Wi-Fi 网络管理器 API，供向 Wi-Fi 协议栈注册并实现 Wi-Fi 管理 API 的网络管理器使用。

  • 多种网络技术，例如以太网、Wi-Fi 和 IEEE 802.15.4，可以在 Kconfig 中同时启用。它们之间不进行自动路由；应用程序将数据发送到自己选择的接口。

  • 最少复制的缓冲区管理。 协议栈在发送路径上避免复制应用程序数据。

  • 虚拟局域网（VLAN）将物理以太网网络划分为多个逻辑网络。参见 VLAN。

  • 流量分类，为发送和接收的数据包划分优先级。参见 流量分类。

  • 时间敏感网络，支持 gPTP（广义精确时间协议，generalized Precision Time Protocol）和 PTP（IEEE 1588）。参见 gPTP 和 PTP。

  • SNTP（RFC 5905）客户端和服务器。参见 SNTP。示例：SNTP client、SNTP server。

  • SOCKS5 代理（RFC 1928）。

  • TFTP（RFC 1350）客户端。示例：TFTP client。

  • FTP（RFC 959）客户端。参见 FTP 客户端。示例：FTP client shell sample。

  • SSH SSH-2（RFC 4251 至 RFC 4254）服务器和客户端。会话通道承载 shell、exec 和 subsystem 请求，并可通过 SSH 使用 Zephyr shell。示例：SSH server and client。

  • WireGuard VPN（WireGuard protocol）。示例：Wireguard VPN。

  • RTP 实时传输协议（Real-time Transport Protocol，RFC 3550）。示例：RTP。

  • MIDI2 MIDI 2.0 UDP 网络传输。示例：MIDI2 network transport。

  • OCPP 开放充电桩协议（Open Charge Point Protocol）。示例：OCPP charge point。

  • Prometheus 指标服务器。示例：Prometheus Sample。

  • MCP 模型上下文协议（Model Context Protocol）服务器，对外提供设备工具，供 AI 代理通过 HTTP 发现和调用。参见 MCP 服务器。示例：MCP Server Hello World。

  • 数据包过滤和捕获。 使用规则过滤发送和接收的数据包，并将流量捕获到远程主机进行分析。参见 数据包过滤 和 网络数据包捕获。

  • 网络 shell，用于查看网络状态、启用或禁用功能，以及运行 ping 或 DNS 查询等命令。参见 网络 shell。

  • zperf 网络性能和带宽测量工具，包括客户端和服务器，兼容 iPerf v2 和 iperf3。示例：zperf: Network Traffic Generator。

支持的网络技术（链路层）：

  • IEEE 802.15.4

  • 以太网，IEEE 802.3

  • Wi-Fi，IEEE 802.11

  • 蜂窝网络 / PPP（RFC 1661）

  • Thread（示例：OpenThread）

  • 用于 SocketCAN 的 CAN 总线

  • SLIP（串行线路上的 IP），用于将 QEMU 目标作为以太网接口连接到主机，使主机应用程序能够与 Zephyr 交换数据。

源码树结构

网络协议栈源码树的组织结构如下：

subsys/net/

各种可选的网络协议栈组件，例如连接管理器、数据包过滤代码和主机名处理，位于此处。

subsys/net/ip/

网络协议栈的核心代码位于此处。

subsys/net/l2

IP 协议栈的第 2 层代码位于此处，包括对以太网、IEEE 802.15.4 和 Wi-Fi 的通用支持。

subsys/net/lib/

应用层协议（DNS、MQTT 等）及其他协议栈组件（BSD 套接字等）。

include/zephyr/net/

公共 API 头文件。应用程序要使用 IP 网络功能，需要包含这些头文件。

samples/net/

网络示例代码。这是入门网络应用程序开发的良好参考。

tests/net/

测试应用程序。这些应用程序用于验证 IP 协议栈的功能，但并不是示例代码的最佳来源（请改为参考 samples/net/）。
