一次运行的过程如下：Twister 构建并启动被测系统，测试框架使用 Titan 构建 TTCN-3 测试套件，测试套件通过 tap 接口与正在运行的应用程序通信，最后 Titan 的判定结果成为测试结果。

运行所需的条件

  • Titan 安装，并将 TTCN3_DIR 指向它。参见 安装 Titan。

  • 第三方 TTCN-3 模块，使用 ttcn3/fetch-modules.sh 获取一次即可。这些模块按固定的提交克隆，不属于 net-tools 仓库。

  • net-tools 检出副本，west 工作区中已经有了：它在 west.yml 的 tools 组中，而该组未被过滤掉。

  • make，因为 Titan 用它来构建测试套件。

  • zeth 接口，对于在 IP 层以下工作的测试套件则为 zethL2。参见 设置网络接口。

  • root 权限，用于无法避免使用特权端口或数据包套接字的测试套件。

  • expect，用于通过 Titan 主控制器运行的测试套件。

测试套件 列出了各测试套件分别需要其中哪些条件，scripts/net/run-conformance-tests.sh --list 也会打印相同的信息。

测试框架会在设置了 NET_TOOLS_BASE 时到该位置查找 net-tools，否则先在相对于 ZEPHYR_BASE 的 ../tools/net-tools/ttcn3 查找，再到上一级目录查找。所有这些都会在构建之前检查，缺少任何一项都会跳过测试并给出原因，而不是让测试失败。

安装 Titan

大多数发行版都打包了 Titan，持续集成安装的就是它：

sudo apt install --no-install-recommends eclipse-titan expect
export TTCN3_DIR=/usr

打包的版本落后于测试套件所依赖的协议模块，因此如果测试套件编译失败，请改为从源码构建最新的 Titan。

从源码构建 Titan

net-tools/docker/Dockerfile.ttcn3 会将 Titan 构建到 /opt/titan 中，可作为手动构建的参考，既可以作为容器使用，也可以作为操作步骤照做。这是一个本地选项，持续集成并不使用它。

手动构建 Titan 时有两点必须做对。Titan 通过其源码树中的 Makefile.personal 进行配置，而不是通过 configure 脚本，其中的 TTCN3_DIR 是安装前缀。另外，make install 必须串行执行：运行时库的某些部分包含由另一部分生成的头文件，并行 make 会在这一竞争中出错。

使用脚本运行测试套件

scripts/net/run-conformance-tests.sh 用一条命令完成后两节所述的工作，是运行测试套件最简单的方式：它会查找 net-tools，在缺少模块时获取模块，创建所选测试套件需要的接口，在所选测试套件需要 root 时以 sudo 重新运行自身，运行一次 Twister，然后再拆除这些接口。

export TTCN3_DIR=/usr
./scripts/net/run-conformance-tests.sh

指定测试套件名称时只运行这些测试套件，这是在处理某一个测试套件时保持非特权运行的快捷方式：

./scripts/net/run-conformance-tests.sh mdns dns

--list 显示各测试套件及其所需条件，--keep 保留接口供下次运行使用，--start 和 --stop 只执行对应的那一半操作。--help 列出其余选项以及检测到的目录。

由于特权运行会以 root 身份创建文件，脚本在退出前会把 Twister 输出目录和测试套件构建目录的所有权交还给调用它的用户。

设置网络接口

测试套件使用两个 tap 接口，因为在 IP 层以下工作的测试套件不能与会自行应答的主机共用一条链路。

zeth：共享接口

供通过套接字工作的测试套件使用，此时测试器只是链路上的另一台主机：

cd $ZEPHYR_BASE/../tools/net-tools
sudo ./net-setup.sh --config zeth.conf start

主机持有 192.0.2.2/24 和 2001:db8::2；Zephyr 在 192.0.2.1 和 2001:db8::1 上应答。将 start 替换为 stop 即可拆除该接口。

zethL2：无地址接口

供在 IP 层以下工作的测试套件使用：

sudo ./net-setup.sh --config zeth-l2.conf --iface zethL2 start

该接口特意不分配 IP 地址。除非另行设置，Linux 会为它在任何接口上持有的任何地址应答地址解析和邻居发现，而来自主机的应答与来自 Zephyr 的应答无法区分。测试器使用原始帧通信，因此不需要自己的地址。

该配置设置了三个 sysctl 来阻止主机参与：arp_ignore=8 使其不为任何本地地址应答地址解析，arp_announce=2 使其从不使用该接口未持有的地址应答，disable_ipv6=1 使其不发送邻居通告或路由器请求。

zethL2 这个名称不能随意更改，参见 测试网络。

使用 Twister 运行测试套件

获取一次第三方模块。该脚本可以安全地重复运行：

cd $ZEPHYR_BASE/../tools/net-tools
./ttcn3/fetch-modules.sh

然后运行测试：

export TTCN3_DIR=/usr
cd $ZEPHYR_BASE
./scripts/twister -p native_sim --enable-slow -T tests/net/conformance

必须使用 --enable-slow：这些测试套件将自身标记为慢速，因为完整运行需要几十分钟。native_sim 是它们唯一允许的平台。

通过测试标识符 net.conformance.<suite> 选择单个测试套件：

./scripts/twister -p native_sim --enable-slow -T tests/net/conformance \
    -s net.conformance.mdns

它们还带有 net 和 conformance 标签，因此 --tag conformance 会选中所有测试套件。

以 root 身份运行

有些测试套件必须以 root 身份运行。DHCP 规定使用 67 和 68 端口，且无法改用其他端口，因此测试器无法避免绑定特权端口；而从链路上读取帧需要数据包套接字。如果运行时权限不足，这些测试会自行跳过。

请使用 sudo -E，以便保留 TTCN3_DIR 及其余环境变量。一次运行要么全部以特权运行，要么全部不以特权运行，两者不能混合的原因参见 测试框架。

为什么运行是串行的

每个被测系统都在同一接口上以同一地址应答，因此同一时间只能运行一个一致性测试。它们会对接口加排他锁并互相等待，这意味着无论给 Twister 分配多少个作业，运行整个目录时都是串行的。

手动运行测试套件

Twister 很方便，但每轮运行都较慢。在编写或调试测试套件时，可以自己分别运行这两部分。

启动被测系统并让其保持运行：

cd $ZEPHYR_BASE
west build -p -b native_sim -d ../build/mdns tests/net/conformance/mdns
../build/mdns/zephyr/zephyr.exe

构建测试套件并针对被测系统运行：

cd $ZEPHYR_BASE/../tools/net-tools/ttcn3
./build.sh mdns
cd suites/mdns/build
./mdns ../mdns.cfg

如果测试套件的测试用例会创建并行测试组件，请改为通过主控制器启动：

ttcn3_start ./coap ../coap.cfg

指定测试用例名称即可运行单个测试用例：

./mdns ../mdns.cfg MDNS_Suite.tc_a_query

地址、接口和超时都来自测试套件配置文件的 [MODULE_PARAMETERS] 部分，因此只需编辑一个文件而无需修改测试套件，就能将运行转移到另一条链路上。

有一件事测试框架会做，而手动运行时需要自己完成：将 Titan 的库目录加入 LD_LIBRARY_PATH。

解读结果

Titan 运行结束时会给出每种判定结果的数量以及本次运行的判定结果：

Verdict statistics: 0 none (0.00 %), 7 pass (100.00 %), 0 inconc (0.00 %), 0 fail (0.00 %), 0 error (0.00 %).
Test execution summary: 7 test cases were executed. Overall verdict: pass

inconc 表示测试用例无法得出结论，通常是因为它所依赖的某件事没有发生。这不算通过。error 表示测试套件本身出错，而不是被测系统出错。

证据位于两个地方。Titan 会为每个测试套件在构建目录中写入一份日志，文件名取自配置文件中的 LogFile 设置。Twister 会在其输出目录下写入 twister_harness.log，其中以 INFO 级别包含测试套件的全部输出。

测试套件被跳过时

测试套件所需的一切都会在构建之前检查，缺少任何一项都会跳过测试，而不是让测试失败。原因按检查顺序列出如下：

原因

处理方法

TTCN3_DIR is unset

安装 Titan 并导出 TTCN3_DIR，参见 安装 Titan

make is not installed

安装 make；Titan 使用生成的 makefile 构建测试套件

no TTCN-3 suites under ...

未找到 net-tools；请设置 NET_TOOLS_BASE

... has no <suite> suite

net-tools 检出副本早于该测试套件；请更新它

third party modules are missing

运行 ttcn3/fetch-modules.sh

the <iface> interface does not exist

使用 net-setup.sh 创建该接口，参见 设置网络接口

ttcn3_start is not in TTCN3_DIR/bin

安装 expect 以及附带主控制器的 Titan

has to be run as root

使用 sudo -E 重新运行，或使用脚本

在环境中设置 NET_CONFORMANCE_REQUIRED，可将上述每种情况都变为失败。这适用于以测试套件为目的的运行，例如每晚作业：在这种运行中，没有运行的测试不能被当作运行过的测试而通过。

故障排除

测试套件无法编译

几乎都是因为打包的 Titan 落后于测试套件所依赖的协议模块。请从源码构建 Titan。

测试套件收不到任何数据并超时

检查应用程序和测试套件是否在同一接口上：在 IP 层以下工作的测试套件需要 zethL2，而应用程序构建时必须带有指定同一接口的 host-interface 属性，测试在 boards/native_sim.overlay 中设置了该属性。如果链路上是主机而不是 Zephyr 在应答，说明 zethL2 的 sysctl 设置未生效；可以用 sysctl net.ipv4.conf.zethL2.arp_ignore 确认。

运行挂起或被中断

一次运行外层嵌套了四个超时，哪个超时触发就说明问题出在哪里：等待应用程序就绪行的 30 秒、构建测试套件的 1800 秒、运行测试套件的 600 秒，以及整个 Twister 测试的 900 秒。超时的测试套件会连同其整个进程组一起被终止，因此不会遗留主控制器进程。

遗留状态

使用 net-setup.sh 和 stop 拆除接口。测试获取的锁是临时目录中名为 zephyr-net-conformance-<euid>.lock 的文件；进程退出时锁会被释放，因此残留的锁文件不会造成影响。
