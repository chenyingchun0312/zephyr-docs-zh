Bluetooth：通用音频规范（Common Audio Profile）Shell

本文档介绍如何运行通用音频规范的功能。

CAP 接受者（Acceptor）

接受者通常是资源受限的设备，例如头戴式耳机、入耳式耳机或助听器。如果接受者与一个或多个其他 CAP 接受者组成一组，它可以初始化一个协调集识别服务（Coordinated Set Identification Service）实例。

使用 CAP 接受者

初始化 Bluetooth 协议栈（bt init）后，可以调用 cap_acceptor init 注册接受者，该命令会注册 CAS 和 CSIS 服务以及回调。

cap_acceptor --help
cap_acceptor - Bluetooth CAP acceptor shell commands
Subcommands:
  init          :Initialize the service and register callbacks [size <int>]
                 [rank <int>] [not-lockable] [sirk <data>]
  lock          :Lock the set
  release       :Release the set [force]
  sirk          :Set the currently used SIRK <sirk>
  get_info      :Get CSIS info
  sirk_rsp      :Set the response used in SIRK requests <accept, accept_enc,
                 reject, oob>

除了初始化 CAS 和 CSIS 之外，还有一些命令用于锁定和释放 CSIS 实例，以及打印和修改对 CSIS 的 SIRK 的访问。

设置新的 SIRK

该命令可以修改当前使用的 SIRK。要在空中广播新的 RSI，必须再次调用 bt adv-data 或 bt advertise 来设置新的广播数据。如果启用了 CONFIG_BT_CSIP_SET_MEMBER_SIRK_NOTIFIABLE，还会通知已连接的客户端。

uart:~$ cap_acceptor sirk 00112233445566778899aabbccddeeff
SIRK updated

获取当前 SIRK

该命令可以获取当前使用的 SIRK。

uart:~$ cap_acceptor get_info
Info for 0x2003b0c8
        SIRK
00000000: 20 37 0a 00 95 c4 04 20  00 00 00 00 f1 79 09 00 | 7.....  .....y..|
        Set size: 2
        Rank: 1
        Lockable: true
        Locked: false

CAP 发起者（Initiator）

发起者通常是资源丰富的设备，例如手机或 PC。发起者可以发现 CAP 接受者的 CAS 服务和可选的 CSIS 服务。读取 CSIS 服务可以获得同一协调集中其他 CAP 接受者的信息。发起者可以在一组设备（临时组合的或协调集）上执行流控制过程，从而能够方便地一次在多个设备上建立多个流。

使用 CAP 发起者

初始化 Bluetooth 协议栈（bt init）后，发起者可以调用（cap_initiator discover）发现 CAS 以及可选包含的 CSIS 实例。CAP 发起者还支持作为广播音频的源。

uart:~$ cap_initiator --help

  unicast_update    : Unicast Update <all | stream [stream [stream...]]>

  unicast_cancel    : Unicast cancel current procedure

  ac_6_ii           : Unicast audio configuration 6(ii)

在执行任何流操作之前，设备还必须执行 bap discover 操作，以发现 ASE 和 PAC 记录。还需要调用 bap init 命令。

对于要在组中使用的每个设备，都应执行上述两条命令。要使用多个设备，只需连接更多设备，然后使用 bt select 选择要在其上执行命令的设备。

连接所有设备并调用各自的发现命令后，可以使用 cap_initiator unicast_start 命令让一个或多个流进入 streaming 状态。

uart:~$ cap_initiator unicast_start sinks 1 sources 0 conns all
Setting up 1 sinks and 0 sources on each (2) conn
Starting 1 streams
Unicast start completed

要停止所有已启动的流，可以使用 cap_initiator unicast_stop 命令。

uart:~$ cap_initiator unicast_stop all
Unicast stop completed

进行广播时

要以 CAP 发起者身份启动广播，需要完成以下几个步骤：

  1. 创建并配置带周期性广播的扩展广播集

  2. 创建并配置广播源

  3. 设置扩展广播数据和周期性广播数据

以下命令将使用 16_2_1 预设（由 BAP 定义）设置一个 CAP 广播源：

bt init
bap init
bt adv-create nconn-nscan ext-adv
bt per-adv-param
bap preset broadcast 16_2_1
cap_initiator ac_12
bt adv-data dev-name discov
bt per-adv-data
cap_initiator broadcast_start
bt adv-start
bt per-adv on

广播源由 cap_initiator ac_12、cap_initiator ac_13 和 cap_initiator ac_14 命令创建，这些命令按照 BAP 中定义的音频配置来配置广播源。之后可以使用 cap_initiator broadcast_stop 停止广播源，或使用 cap_initiator broadcast_delete 删除广播源。

广播源的元数据可以随时更新，包括正在传输流时。要更新元数据，可以使用 cap_initiator broadcast_update 命令。该命令接受一个数据数组，唯一的要求（除了数据有效之外）是必须设置流上下文（streaming context）。例如，要将流上下文设置为媒体，可以按如下方式使用该命令

cap_initiator broadcast_update 03020400
CAP Broadcast source updated with new metadata. Update the advertised base via `bt per-adv-data`
bt per-adv-data

之后应使用 bt per-adv-data 命令更新所广播的 BASE 中的数据。数据必须为小端格式，因此在上面的示例中，元数据 03020400 设置的元数据条目以 03 为长度，02 为类型（流上下文），0400 为值 BT_AUDIO_CONTEXT_TYPE_MEDIA（其数值为 0x）。

CAP 指挥者（Commander）

指挥者通常与 CAP 发起者位于同一设备上，或者位于单独的资源丰富的移动设备上，例如手机或智能手表。指挥者可以发现 CAP 接受者的 CAS 服务和可选的 CSIS 服务。读取 CSIS 服务可以获得同一协调集中其他 CAP 接受者的信息。指挥者可以向 CAP 接受者提供广播源的信息，或协调采集与渲染信息，例如静音或音量状态。

使用 CAP 指挥者

初始化 Bluetooth 协议栈（bt init）后，指挥者可以调用（cap_commander discover）发现 CAS 以及可选包含的 CSIS 实例。

cap_commander --help

Subcommands:
  discover                  :Discover CAS
  cancel                    :CAP commander cancel current procedure
  change_volume             :Change volume on all connections <volume>
  change_volume_mute        :Change volume mute state on all connections <mute>
  change_volume_offset      :Change volume offset per connection <volume_offset
                             [volume_offset [...]]>
  change_microphone_mute    :Change microphone mute state on all connections <mute>
  change_microphone_gain    :Change microphone gain per connection <gain

在执行任何流操作之前，设备还必须执行 bap discover 操作，以发现 ASE 和 PAC 记录。还需要调用 bap init 命令。

CAP 切换（Handover）

切换过程允许用户在单播流和广播流之间切换。由于广播流始终是单向的，这些过程仅适用于音频方向从发起者到接受者的流（sink 流）。

使用 CAP 切换过程

初始化 Bluetooth 协议栈（bt init）、连接一个或多个远端 CAP 接受者设备并建立音频流后，即可使用切换过程在单播和广播之间切换。在使用任何切换过程之前，必须先执行并完成 bap discover、cap_initiator discover 和 bap_broadcast_assistant discover 命令。

cap_handover --help
cap_handover - Bluetooth CAP handover shell commands
Subcommands:
  unicast_to_broadcast  : Handover current unicast group to broadcast (unicast
                        group will be deleted) [enc <broadcast_code>] [preset <preset_name>]
  broadcast_to_unicast  : Handover current broadcast source to unicast
                        (broadcast source will be deleted)
                        [conns <count>|all] [preset <preset_name>]

从单播切换到广播

该命令将一个或多个单播流从单播切换到广播。

uart:~$ bt init
uart:~$ bap init
uart:~$ bt connect <addr>

# Discover necessary services
uart:~$ bap discover
uart:~$ cap_initiator discover
uart:~$ bap_broadcast_assistant discover

# Setup unicast audio e.g. using the ac_1
uart:~$ cap_initiator ac_1

# Create a non-connectable and non-scannable extended advertising set for broadcast
uart:~$ bt adv-create nconn-nscan ext-adv
uart:~$ bt per-adv-param

# Perform the handover and update the advertising data to contain the broadcast ID
uart:~$ cap_handover unicast_to_broadcast
uart:~$ bt adv-data dev-name discov
uart:~$ bt per-adv-data

# Enable periodic advertising (extended advertising is enabled as part of handover)
uart:~$ bt per-adv on

从广播切换到单播

该命令将一个或多个单播流从广播切换到单播。

uart:~$ bt init
uart:~$ bap init
uart:~$ bt connect <addr>

# Discover necessary services
uart:~$ bap discover
uart:~$ cap_initiator discover
uart:~$ bap_broadcast_assistant discover

# Create a non-connectable and non-scannable extended advertising set for broadcast
uart:~$ bt adv-create nconn-nscan ext-adv
uart:~$ bt per-adv-param

# Setup broadcast audio e.g. using the ac_12
uart:~$ cap_initiator ac_12
uart:~$ cap_initiator broadcast_start

# Set advertising data and enable advertising
uart:~$ bt adv-data dev-name discov
uart:~$ bt per-adv-data
uart:~$ bt per-adv on
uart:~$ bt adv-start

# Wait for broadcast sink to self-scan, or use broadcast reception to instruct sink to sync

# Perform the handover
uart:~$ cap_handover broadcast_to_unicast

# Terminate the advertiser (optional)
uart:~$ bt adv-stop
uart:~$ bt per-adv off
uart:~$ bt adv-delete
