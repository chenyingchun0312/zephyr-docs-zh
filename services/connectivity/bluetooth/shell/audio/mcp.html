Bluetooth：媒体控制规范（Media Control Profile）Shell

本文档介绍如何使用 Shell，以客户端和服务器两种身份运行媒体控制功能。

媒体控制服务器由两部分组成：一是媒体播放器（mpl），包含处理媒体的逻辑；二是媒体控制服务（mcs），作为播放器基于 GATT 的接口。媒体控制客户端只有一部分，即基于 GATT 的客户端（mcc）。

媒体控制服务器可以包含对象传输服务（ots），媒体控制客户端可以包含对象传输客户端（otc）。包含这些部分时，可以使用更丰富的功能。

媒体控制服务器和客户端都（仅）实现了通用媒体控制服务（Generic Media Control Service），不使用任何底层的媒体控制服务。

注意，在以下示例中，许多情况下删除了调试输出，较长的输出也可能被缩短，以使示例更简短清晰。

另请注意，本文档并未列出所有 Shell 命令，只展示了其中部分命令的示例。可以在 mcc Shell 和 mpl Shell 中输入 mcc 或 mpl 并按 TAB 键来浏览命令集。执行 mcc <command> help 或 mpl <command> help 可以查看每条命令的帮助文本。

概述

媒体播放器有一个 名称（name） 和一个 图标（icon），供用户识别播放器。

媒体播放器的内容按曲目和分组组织。一个媒体播放器有若干分组。一个分组包含曲目和其他分组。（在本实现中，分组只包含曲目，不包含其他分组。）曲目可以划分为片段。

处于活动状态的播放器会有一个 当前曲目（current track），即正在播放的曲目（如果播放器正在播放）。当前曲目有 标题（title）、时长（duration）（以百分之一秒为单位）和 位置（position），即播放器在曲目中的当前位置。

此外还有 当前分组（current group）（当前曲目所在的分组）、父分组（parent group）（当前分组的父分组）和 下一曲目（next track）。

媒体播放器处于某种 状态（state），即播放、暂停、搜寻（seeking）或非活动之一。播放时，以给定的 播放速度（playback speed） 回放，曲目按照 播放顺序（playing order） 播放，该顺序是 所支持的播放顺序（playing orders supported） 之一。曲目变更通过 曲目已变更（track changed） 特征的通知来指示。搜寻（快进或快退）时，曲目位置按照 搜寻速度（seeking speed） 移动。

支持的操作码（opcodes supported） 指明了播放器支持通过写入 媒体控制点（media control point） 执行哪些操作。另外还有一个 搜索控制点（search control point），允许按各种条件搜索分组和曲目，结果在 搜索结果（search results） 中返回。

最后，内容控制 ID（content control ID） 用于将媒体播放器与音频流关联起来。

媒体控制客户端（MCP）

媒体控制客户端用于控制媒体控制服务器并从中获取信息。控制通过写入两个控制点之一或写入其他可写特征来完成。获取信息通过读取特征，或配置服务器发送通知来完成。

使用媒体控制客户端

使用前，必须通过命令 mcc init 初始化媒体控制客户端。

要与对端建立连接，必须使用 bt 命令：先执行 bt init，再执行 bt advertise on（如果服务器正在广播，则执行 bt connect）。

媒体控制客户端连接到媒体控制服务器后，客户端可以通过命令 mcc discover_mcs 发现服务器的通用媒体控制服务。该命令会保存服务的句柄，并（可选，但默认如此）订阅所有通知。

发现完成后，媒体控制客户端可以读写特征，包括媒体控制点和搜索控制点。

写入特征，以曲目位置为例：

曲目位置是播放器在当前曲目中“所处”的位置。读取曲目位置，通过写入来更改它，再读取一次进行确认。

uart:~$ mcc read_track_position
Track Position: 0

uart:~$ mcc set_track_position 500
Track Position: 500

uart:~$ mcc read_track_position
Track Position: 500

通过控制点控制播放器：

写入控制点可以让客户端请求服务器执行播放、暂停、快进、切换曲目、切换分组等操作。某些操作（例如跳转到曲目）需要参数。目前，控制点 Shell 命令以原始操作码值作为输入。这些操作码值可以在 mpl.h 头文件中找到。

搜索

搜索控制点以一系列搜索控制项作为输入，每一项由长度、类型（例如曲目名称或艺术家名称）和参数（要搜索的曲目名称或艺术家名称）组成。如果搜索成功，搜索结果会存储在对象传输服务的一个对象中。搜索结果对象的 ID 可以从搜索结果对象 ID 特征中读取。然后可以像上面下载当前分组对象一样下载搜索结果对象。（注意，在执行搜索之前，搜索结果对象 ID 为空。）

本实现中，搜索功能接口和服务器端搜索控制点参数解析均可正常工作。但 实际搜索是伪造的，无论搜索什么，都返回相同的结果。

搜索有两条命令。一条（mcc set_scp_raw）允许以字符串形式输入搜索控制点参数（搜索控制项序列）。另一条（mcc set_scp_ioptest）执行预设的 IOP 测试搜索，并以 IOP 搜索控制点测试的轮次编号作为参数。

搜索之前，搜索结果对象 ID 为空

uart:~$ mcc read_search_results_obj_id
Search Results Object ID: 0x000000000000
<dbg> bt_mcc.mcc_read_search_results_obj_id_cb: Zero-length Search Results Object ID

运行与 IOP 测试第四轮对应的搜索：

该命令及参数生成的搜索控制点参数包含一个搜索控制项。长度字段（第一个八位组）为 16（0x10）（不包括长度字段本身的长度）。类型字段（第二个八位组）为 0x04（搜索分组名称）。参数（要搜索的分组名称）为“TSPX_Group_Name”。

uart:~$ mcc set_scp_ioptest 4

00000010: 65                                               |e                |
Search control point notification result code: 1
Search Results Object ID: 0x000000000107
Search Control Point set

搜索成功后，搜索结果对象 ID 有了值：

uart:~$ mcc read_search_results_obj_id
Search Results Object ID: 0x000000000107

媒体控制服务（MCS）

媒体控制服务（mcs）及其关联的媒体播放器（mpl）通常位于能够提供媒体内容访问和服务的设备上，例如 PC 和智能手机。

如上所述，媒体播放器（mpl）包含播放器逻辑，而媒体控制服务（mcs）提供基于 GATT 的接口。这样分离是为了让媒体播放器在没有基于 GATT 的接口时也能使用。

使用媒体控制服务和媒体播放器

媒体控制服务和媒体播放器一般由媒体控制客户端进行远程控制。

使用前，必须通过命令 mpl init 初始化媒体控制客户端。

与客户端一样，使用 bt 命令进行连接：先执行 bt init，再执行 bt connect <address> <address type>（如果服务器正在广播，则执行 bt advertise on）。

使用示例

设置

uart:~$ bt init
Bluetooth initialized

uart:~$ mpl init
[Large amounts of debug output]

uart:~$ bt connect R:F9:33:3B:67:D2:A7
Connection pending
Connected: R:F9:33:3B:67:D2:A7

连接后

控制由客户端执行。

服务器会输出与客户端执行的各种操作相关的调试信息。

示例：强制发送曲目时长的通知（伪造值）：
