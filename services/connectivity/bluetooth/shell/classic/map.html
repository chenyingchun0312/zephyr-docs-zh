Bluetooth：MAP Shell 命令

本文档介绍如何运行经典 Bluetooth 的 MAP（消息访问规范，Message Access Profile）Shell 功能。map 命令提供了经典 Bluetooth MAP 的 Shell 命令。

命令

主命令

map 命令：

uart:~$ map
map - Bluetooth MAP shell commands
Subcommands:
  add_header  : Adding header sets
  mce         : MCE commands
  mse         : MSE commands

MCE 命令

map mce 命令：

uart:~$ map mce
mce - MCE commands
Subcommands:
  mas  : MCE MAS commands
  mns  : MCE MNS commands

map mce mas 命令：

附加信息

RFCOMM 与 L2CAP 传输对比

RFCOMM 传输

对于 GET 或 PUT 操作，必须多次调用同一条 Shell 命令，直到完整的消息传送完毕。

使用 SRM 的 L2CAP 传输

启用 SRM（单响应模式，Single Response Mode）时，GET 请求无需重复发送，服务器会发送所有响应数据包。对于 PUT 操作，客户端无需等待中间响应即可发送所有请求数据包，服务器在收到最后一个 PUT 请求后发送单个响应。

使用 SRM 和 SRMP 的 L2CAP 传输

同时启用 SRM 和 SRMP（单响应模式参数，Single Response Mode Parameter）时，需要持续发送 GET 请求和 PUT 响应，直到 SRMP 被禁用。

SRM（单响应模式）

SRM 在 L2CAP 传输（GOEP v2.0）上自动启用。

GET 操作

为 GET 操作启用 SRM 时：

  • 客户端发送单个 GET 请求。

  • 服务器发送多个响应数据包，无需等待额外的请求。

  • srmp 参数可用于控制流程（等待下一个请求）。

PUT 操作

为 PUT 操作启用 SRM 时：

  • 客户端发送多个 PUT 请求，无需等待额外的响应。

  • 服务器在收到最后一个 PUT 请求时发送单个 PUT 响应。

  • srmp 参数可用于控制流程（等待下一个响应）。

多实例支持

MAP Shell 支持多个 MAS 实例：

  • MCE 可以同时连接到多个 MSE MAS 实例

  • MSE 可以注册多个具有不同实例 ID 的 MAS 实例

  • 使用 select 命令在实例之间切换

uart:~$ map mce mas select 0
Selected MCE MAS instance_id 0 as default
uart:~$
