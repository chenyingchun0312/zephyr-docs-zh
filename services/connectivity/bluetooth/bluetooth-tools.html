移动应用程序

利用现有的移动应用程序与运行 Zephyr 的硬件交互通常很有用，这样无需编写额外代码或准备额外硬件即可测试功能。

推荐用于与 Zephyr 交互的移动应用程序有：

  • Android：

    • nRF Connect for Android

    • nRF Mesh for Android

    • LightBlue for Android

  • iOS：

    • nRF Connect for iOS

    • nRF Mesh for iOS

    • LightBlue for iOS

在 Zephyr 中使用 BlueZ

Linux Bluetooth 协议栈 BlueZ 附带一组非常有用的工具，可用于调试 Zephyr 的 Bluetooth 主机和控制器并与之交互。要使用这些工具，需要确保运行的是较新版本的 Linux 内核和 BlueZ：

  • Linux 内核 4.10+

  • BlueZ 4.45+

此外，你的 Linux 发行版可能默认未附带某些 BlueZ 工具。如果需要从头构建 BlueZ 以更新到较新版本或获取其全部工具，可以按照以下步骤操作：

git clone git://git.kernel.org/pub/scm/bluetooth/bluez.git
cd bluez
./bootstrap-configure --disable-android --disable-midi
make

之后可以在 tools/ 文件夹中找到 btattach、btmgt 和 btproxy，在 monitor/ 文件夹中找到 btmon。

你需要启用 BlueZ 的实验性功能，才能使用其最新的 Bluetooth 功能。为此，请编辑文件 /lib/systemd/system/bluetooth.service，确保在守护进程的执行启动行中包含 -E 选项：

ExecStart=/usr/libexec/bluetooth/bluetoothd -E

最后，重新加载并重启守护进程：

sudo systemctl daemon-reload
sudo systemctl restart bluetooth

在 QEMU 或 native_sim 上运行

可以使用 QEMU 模拟器 或 native_sim 运行 Bluetooth 应用程序。

无论哪种情况，都需要将 Bluetooth 控制器从宿主操作系统（Linux）导出给模拟器。为此需要用到 在 Zephyr 中使用 BlueZ 一节中介绍的一些工具。

使用宿主系统的 Bluetooth 控制器

宿主操作系统的 Bluetooth 控制器按以下方式连接：

  • 通过 UNIX 套接字连接到 QEMU 的第二条串行线路。该套接字借助 QEMU 选项 -serial unix:/tmp/bt-server-bredr 使用。只要应用程序启用了 Bluetooth 支持，该选项就会自动通过 QEMU_EXTRA_FLAGS 传递给 QEMU。

  • 通过向 native_sim 可执行文件传递命令行选项 --bt-dev=hci0，连接到 native_sim 的 BT 用户通道驱动

在宿主端，BlueZ 允许通过所谓的用户通道（user channel）导出其 Bluetooth 控制器，供 QEMU 和 native_sim 使用。

备注

只有使用 QEMU 时才需要运行 btproxy。native_sim 会自动处理 UNIX 套接字代理

如果使用 QEMU，为了让控制器可用，还需要使用 btproxy 额外执行一步：

  1. 确保 Bluetooth 控制器处于关闭（down）状态

  2. 使用 btproxy 工具打开监听的 UNIX 套接字，输入：

    sudo tools/btproxy -u -i 0
Listening on /tmp/bt-server-bredr

    你可能需要将 -i 0 替换为要代理的控制器的索引。

    如果运行 QEMU 时看到 Received unknown host packet type 0x00，请在 btproxy 命令行中添加 -z，以忽略启动时传输的空字节。

硬件连接好并可以使用后，就可以继续构建并运行示例：

  • 从 samples/bluetooth 中选择一个 Bluetooth 示例应用程序。

  • 要在 QEMU 中运行 Bluetooth 应用程序，请输入：

    west build -b qemu_x86 samples/bluetooth/<sample>
west build -t run

    此时运行 QEMU，其第二条串行线路会连接到 bt-server-bredr UNIX 套接字，使应用程序能够访问 Bluetooth 控制器。

  • 要在 native_sim 中运行 Bluetooth 应用程序，首先构建它：

    west build -b native_sim samples/bluetooth/<sample>

    然后使用以下命令运行:

    $ sudo ./build/zephyr/zephyr.exe --bt-dev=hci0

使用基于 Zephyr 的 Bluetooth 控制器

根据你可用的硬件，在构建单模、基于 Zephyr 的 Bluetooth 控制器时可以在两种传输方式之间选择：

  • UART：使用 HCI UART 示例，并按照 将控制器与 QEMU 或 native_sim 配合使用 中的说明操作。

  • USB：使用 HCI USB 示例，然后将其视为宿主系统的 Bluetooth 控制器（见上一节）

HCI 跟踪

在连接了外部控制器的计算机上运行主机时，能够以 主机控制器接口（Host Controller Interface） 日志的格式查看两者之间交互的完整日志非常有用。要查看这些日志，可以使用 BlueZ 内置的 btmon 工具：

$ btmon

输出如下所示:

= Open Index: 00:00:00:00:00:00                                              0.274500

      Reset (0x03|0x0003) ncmd 1
      Status: Success (0x00)

嵌入式 HCI 跟踪

当主机和控制器都运行在实际的集成电路上时，默认情况下控制台上只会显示普通日志消息，无法获取主机与控制器之间的 HCI 流量。不过，有一种特殊的 Bluetooth 日志模式，可以让控制台改用二进制协议，将普通日志消息和 HCI 流量交织在一起输出。

构建应用程序之前，设置以下 Kconfig 选项以启用该协议：

CONFIG_BT_DEBUG_MONITOR_UART=y
CONFIG_UART_CONSOLE=n

  • 设置 CONFIG_BT_DEBUG_MONITOR_UART 会启用该格式

  • 清除 CONFIG_UART_CONSOLE 会使该 UART 不能用作系统控制台，例如不能用于 printk 和 boot banner

可选地，在监视器 UART 驱动支持中断 API 的开发板上，设置 CONFIG_BT_DEBUG_MONITOR_UART_INTERRUPT_DRIVEN 会将完整的监视器记录排入队列，并从 UART 中断处理程序中发送，而不是在发送每个字节时阻塞。放不进缓冲区的记录会被丢弃，并在下一条监视器记录中报告。缓冲区大小可通过 CONFIG_BT_DEBUG_MONITOR_UART_BUFFER_SIZE 调整。

要解码此时发送到控制台 UART 的二进制协议，需要使用 BlueZ 中的 btmon 工具：

$ btmon --tty <console TTY> --tty-speed 115200

如果没有可用的 UART（或者你仍然希望获得非二进制日志），可以改为设置 CONFIG_BT_DEBUG_MONITOR_RTT，它将使用 Segger RTT。例如，要连接序列号为 683578642 的 nRF52840DK：

$ btmon --jlink nRF52840_xxAA,683578642

在虚拟控制器和 native_sim 上运行

除物理 Bluetooth 控制器外，还可以使用虚拟控制器。这种控制器可以通过 HCI TCP 服务器连接，该 TCP 服务器必须支持 HCI H4 协议。与物理控制器方案相比，虚拟控制器可以在没有物理 Bluetooth 控制器的情况下测试运行在 native 开发板上的 Zephyr 应用程序。

虚拟控制器的主要用例是在不需要 Bluetooth 硬件的情况下进行 Bluetooth 连接测试。这样就可以与 Bluetooth 网关或移动应用程序等外部应用程序一起，自动化地进行 Bluetooth 集成测试。

为了演示这一功能，下面给出一个与虚拟控制器交互的示例。这里使用 Google 的实验性 Python 模块 Bumble，因为它可以创建 TCP Bluetooth 虚拟控制器并与 Zephyr Bluetooth 主机连接。要安装 Bumble，请按照 Bumble Getting Started Guide 操作。

备注

如果你的 Zephyr 应用程序需要使用 HCI LE Set 扩展命令，请安装 Bumble 的 controller-extended-advertising 分支。

Android 模拟器

你可以将 Bluetooth Zephyr 应用程序连接到 Android Emulator 来测试虚拟控制器。

要将应用程序连接到 Android 模拟器，请按以下步骤操作：

  1. 构建 Zephyr 应用程序，并禁用 HCI ACL 流控（即 CONFIG_BT_HCI_ACL_FLOW_CONTROL=n），因为 Android 的虚拟控制器目前不支持该功能。

  2. 安装 33.1.4.0 或更高版本的 Android 模拟器。最简单的方法是安装最新版本的 Android Studio Preview。

  3. 使用 Android Device Manager 创建一个新的 Android 虚拟设备（AVD）。该 AVD 应至少使用 SDK API 34。

  4. 按如下方式通过终端运行 Android 模拟器：

    emulator avd YOUR_AVD -packet-streamer-endpoint default

  5. 使用 Bumble 的 hci-bridge 工具，在 Zephyr 应用程序和 Android 模拟器的虚拟控制器之间创建 Bluetooth 桥接。

    bumble-hci-bridge tcp-server:_:1234 android-netsim

    该命令会在本地主机 IP 地址 127.0.0.1 和端口号 1234 上创建一个 TCP 服务器桥接。

  6. 运行 Zephyr 应用程序，并连接到上一步创建的 TCP 服务器。

    ./zephyr.exe --bt-dev=127.0.0.1:1234

完成这些步骤后，Android 模拟器就可以通过经 Bumble 桥接的虚拟 Bluetooth 控制器访问 Zephyr 应用程序。你可以在 AVD 中打开 Bluetooth 设置并扫描你的 Zephyr 应用程序设备，以验证 Zephyr 应用程序能够通过 Bluetooth 通信。为此，可以构建 Bluetooth 外设示例，例如 Heart-rate Monitor (Peripheral) 或 DIS Peripheral。

在 BlueZ 中使用基于 Zephyr 的控制器

如果要使用 BlueZ 的 Bluetooth 主机测试基于 Zephyr 的 Bluetooth 控制器，需要用到 在 Zephyr 中使用 BlueZ 一节中介绍的一些工具。安装这些工具后，就可以用它们与基于 Zephyr 的控制器交互：

sudo tools/btmgmt --index 0
[hci0]# auto-power
[hci0]# find -l

你可能需要将 --index 0 替换为要管理的控制器的索引。有关 btmgmt 的更多信息，请参阅其手册页。
