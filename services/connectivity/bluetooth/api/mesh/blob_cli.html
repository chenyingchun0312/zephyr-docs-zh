BLOB 传输客户端

二进制大对象（Binary Large Object，BLOB）传输客户端是 BLOB 传输的发送方。它支持以推送 BLOB 传输模式（Push BLOB Transfer Mode）和拉取 BLOB 传输模式（Pull BLOB Transfer Mode）向任意数量的目标节点发送任意大小的 BLOB。

用法

初始化

BLOB 传输客户端在某个元素上实例化，并带有一组事件处理回调：

static const struct bt_mesh_blob_cli_cb blob_cb = {
      /* Callbacks */
};

static struct bt_mesh_blob_cli blob_cli = {
      .cb = &blob_cb,
};

static const struct bt_mesh_model models[] = {
      BT_MESH_MODEL_BLOB_CLI(&blob_cli),
};

传输上下文

传输能力获取过程和 BLOB 传输都使用一个 bt_mesh_blob_cli_inputs 实例来确定如何执行传输。在用于某个过程之前，BLOB 传输客户端输入结构体至少必须初始化目标列表、应用密钥（AppKey）和生存时间（TTL）值：

static struct bt_mesh_blob_target targets[3] = {
        { .addr = 0x0001 },
        { .addr = 0x0002 },
        { .addr = 0x0003 },
};
static struct bt_mesh_blob_cli_inputs inputs = {
        .app_idx = MY_APP_IDX,
        .ttl = BT_MESH_TTL_DEFAULT,
};

sys_slist_init(&inputs.targets);
sys_slist_append(&inputs.targets, &targets[0].n);
sys_slist_append(&inputs.targets, &targets[1].n);
sys_slist_append(&inputs.targets, &targets[2].n);

注意，参与传输的所有 BLOB 传输服务器都必须绑定到所选的应用密钥。

组地址

应用程序还可以在上下文结构体中指定一个组地址。如果组地址不是 BT_MESH_ADDR_UNASSIGNED，传输中的消息将发送到该组地址，而不是逐个发送给每个目标节点。Mesh 管理者必须确保所有具有 BLOB 传输服务器模型的目标节点都订阅了该组地址。

使用组地址传输 BLOB 通常可以提高传输速度，因为 BLOB 传输客户端会同时向所有目标节点发送每条消息。但是，在 Bluetooth Mesh 中，向组地址发送大型分段消息通常不如向单播地址发送可靠，因为组没有传输层确认机制。这可能导致每个块结束时的恢复期更长，并增加丢失目标节点的风险。通常只有在目标节点列表很长时，使用组地址进行 BLOB 传输才会划算；而每种寻址策略的效果会因不同的部署环境和块片大小而有很大差异。

传输超时

如果某个目标节点未能在 BLOB 传输客户端的时间限制内响应一条需确认消息，该目标节点将被移出传输。应用程序可以通过上下文结构体为 BLOB 传输客户端提供额外时间来降低这种情况发生的概率。在 20 秒的基础时间之外，额外时间可以按 10 秒的增量设置，最长 182 小时。等待时间会随传输的 TTL 自动缩放。

注意，BLOB 传输客户端只在以下情况下才会推进传输：

  • 所有目标节点都已响应。

  • 某个节点已从目标节点列表中移除。

  • BLOB 传输客户端超时。

增加等待时间会增加此延迟。

BLOB 传输能力获取

通常建议在开始传输之前先获取 BLOB 传输能力。该过程会根据所有目标节点的情况，以能让所有目标节点都参与传输的最宽松参数集填充传输能力。任何未能响应或以不兼容的传输参数响应的目标节点都将被移除。

目标节点按照其在目标节点列表中的顺序确定优先级。如果发现某个目标节点与之前的任一目标节点不兼容（例如报告的块大小范围没有重叠），它将被移除。丢失的目标节点将通过 lost_target 回调报告。

过程结束时会通过 caps 回调发出通知，得到的能力可用于确定 BLOB 传输所需的块大小和块片大小。

BLOB 传输

调用 bt_mesh_blob_cli_send() 函数即可启动 BLOB 传输，该函数除了需要前述的传输输入之外，还需要一组传输参数和一个 BLOB 流实例。传输参数包括 64 位 BLOB ID、BLOB 大小、传输模式、以对数形式表示的块大小以及块片大小。BLOB ID 由应用程序定义，但必须与启动 BLOB 传输服务器时所用的 BLOB ID 一致。

传输会一直运行，直到至少对一个目标节点成功完成，或者被取消。传输结束时会通过 end 回调通知应用程序。丢失的目标节点将通过 lost_target 回调报告。
