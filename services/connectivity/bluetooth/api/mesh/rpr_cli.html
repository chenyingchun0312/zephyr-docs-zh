远程配网客户端

远程配网客户端（Remote Provisioning Client）模型是 Bluetooth Mesh 规范定义的一个基础模型。它通过 CONFIG_BT_MESH_RPR_CLI 选项启用。

远程配网客户端模型是在 Bluetooth Mesh 协议规范 1.1 版中引入的。该模型通过与支持 远程配网服务器 模型的 Mesh 节点交互，提供将设备远程配网到 Mesh 网络中的功能，以及执行节点配网协议接口（Node Provisioning Protocol Interface）过程的功能。

远程配网客户端模型使用包含目标远程配网服务器模型实例的节点的设备密钥（DevKey），与远程配网服务器模型通信。

如果存在，远程配网客户端模型必须在主元素上实例化。

扫描

扫描过程用于扫描位于远程配网服务器附近的未配网设备。远程配网客户端通过调用 bt_mesh_rpr_scan_start() 启动扫描过程：

static void rpr_scan_report(struct bt_mesh_rpr_cli *cli,
            const struct bt_mesh_rpr_node *srv,
            struct bt_mesh_rpr_unprov *unprov,
            struct net_buf_simple *adv_data)
{

}

struct bt_mesh_rpr_cli rpr_cli = {
   .scan_report = rpr_scan_report,
};

const struct bt_mesh_rpr_node srv = {
   .addr = 0x0004,
   .net_idx = 0,
   .ttl = BT_MESH_TTL_DEFAULT,
};

struct bt_mesh_rpr_scan_status status;
uint8_t *uuid = NULL;
uint8_t timeout = 10;
uint8_t max_devs = 3;

bt_mesh_rpr_scan_start(&rpr_cli, &srv, uuid, timeout, max_devs, &status);

上面的示例展示了在目标远程配网服务器节点上启动扫描过程的伪代码。该过程会启动一次时长为十秒的多设备扫描，生成的扫描报告最多包含三个未配网设备。如果指定了 UUID 参数，该过程将只扫描具有对应 UUID 的设备。过程完成后，服务器会发送扫描报告，由客户端的 bt_mesh_rpr_cli.scan_report 回调处理。

此外，远程配网客户端模型还支持通过 bt_mesh_rpr_scan_start_ext() 进行扩展扫描。扩展扫描是对常规扫描的补充，允许远程配网服务器报告某个特定设备的附加数据。如果未配网设备支持，远程配网服务器将使用主动扫描向该设备请求扫描响应。

配网

远程配网客户端通过调用 bt_mesh_provision_remote() 启动配网过程：

struct bt_mesh_rpr_cli rpr_cli;

const struct bt_mesh_rpr_node srv = {
   .addr = 0x0004,
   .net_idx = 0,
   .ttl = BT_MESH_TTL_DEFAULT,
};

uint8_t uuid[16] = { 0xaa };
uint16_t addr = 0x0006;
uint16_t net_idx = 0;

bt_mesh_provision_remote(&rpr_cli, &srv, uuid, net_idx, addr);

上面的示例展示了通过远程配网服务器节点对设备进行远程配网的伪代码。该过程将尝试为具有对应 UUID 的设备配网，使用索引为零的网络密钥（NetKey），并将地址 0x0006 分配给其主元素。

备注

在远程配网期间，触发的 bt_mesh_prov 回调与普通配网相同。更多细节请参阅 配网 一节。

重新配网

除了扫描和配网功能之外，远程配网客户端还提供了在支持 远程配网服务器 模型的设备上重新配置节点地址、设备密钥和组成数据（Composition Data）的手段。这是通过节点配网协议接口（NPPI）实现的，它支持以下三种过程：

  • 设备密钥刷新（Device Key Refresh）过程：用于更改目标节点的设备密钥，而无需重新配置该节点。

  • 节点地址刷新（Node Address Refresh）过程：用于更改节点的设备密钥和单播地址。

  • 节点组成刷新（Node Composition Refresh）过程：用于更改节点的设备密钥，以及添加或删除节点的模型或功能。

这三种 NPPI 过程都可以通过调用 bt_mesh_reprovision_remote() 发起：

struct bt_mesh_rpr_cli rpr_cli;
struct bt_mesh_rpr_node srv = {
   .addr = 0x0006,
   .net_idx = 0,
   .ttl = BT_MESH_TTL_DEFAULT,
};

bool composition_changed = false;
uint16_t new_addr = 0x0009;

bt_mesh_reprovision_remote(&rpr_cli, &srv, new_addr, composition_changed);

上面的示例展示了在目标节点上触发节点地址刷新过程的伪代码。具体执行哪种过程不是直接选择的，而是由传入的其他参数决定。在本例中，目标节点当前的单播地址是 0x0006，而新地址被设置为 0x0009。如果两个地址相同，并且 composition_changed 标志设为 true，这段代码将改为触发节点组成刷新过程。如果两个地址相同，并且 composition_changed 标志设为 false，这段代码将触发设备密钥刷新过程。
