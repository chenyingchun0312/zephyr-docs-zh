Bluetooth Mesh Shell

Bluetooth Mesh shell 子系统为 Shell 模块提供了一组 Bluetooth Mesh shell 命令。借助它，无需编写应用程序即可通过交互式界面测试和探索 Bluetooth Mesh API。

Bluetooth Mesh shell 界面可以访问大部分 Bluetooth Mesh 功能，包括配网、配置和消息发送。

前提条件

Bluetooth Mesh shell 子系统依赖应用程序来创建组成数据（Composition Data）并完成 Mesh 初始化。

应用程序

使用 Bluetooth Mesh shell 子系统最简便的方式是通过 tests/bluetooth/mesh_shell 下的 Bluetooth Mesh shell 应用程序。关于如何连接 Bluetooth Mesh shell 应用程序并与之交互，请参阅 Shell。

基本用法

Bluetooth Mesh shell 子系统只添加一个 mesh 命令，其下包含一组子命令。每次设备启动后，都必须先调用 mesh init，然后才能调用其他 Bluetooth Mesh shell 命令:

uart:~$ mesh init

这样做是为了确保所有可用的日志都会输出到 shell 中。

配网

Mesh 节点必须经过配网才能成为网络的一部分。只有设备首次启动时才需要配网，因为设备在重启后会记住其配网数据。

为设备配网最简单的方式是自配网。为此，用户需要使用默认网络密钥和地址 0x0001 为设备配网，执行:

uart:~$ mesh prov local 0 0x0001

由于所有 Mesh 节点的默认网络密钥取值都相同，只要为各设备分配互不重叠的单播地址，就可以在多台设备上这样操作。另一种方式是将设备配网到已有网络中：可以通过 mesh prov pb-adv on 或 mesh prov pb-gatt on 启用未配网信标（unprovisioned beacon）。外部配网器（provisioner）接收到这些信标后，即可将该节点配网到自己的网络中。

Mesh 节点加入网络后，可以通过以下通用配置命令控制其发送参数：

  • 要设置目标地址，调用 mesh target dst <Addr>。

  • 要设置网络密钥索引，调用 mesh target net <NetKeyIdx>。

  • 要设置应用密钥索引，调用 mesh target app <AppKeyIdx>。

默认情况下，发送参数被设置为使用配网时的地址和网络密钥发送消息。

配置

将目标地址设置为本地单播地址（即上面 mesh prov local 命令中的 0x0001）后，就可以通过任意 模型 命令进行自配置。

第一步最好先读出节点自身的组成数据:

uart:~$ mesh models cfg get-comp

该命令会打印节点的组成数据，其中包括其模型 ID 列表。

接下来，由于设备默认没有任何应用密钥，最好先添加一个:

uart:~$ mesh models cfg appkey add 0 0

消息发送

添加应用密钥（见上文）后，Mesh 节点的发送参数便全部有效，Bluetooth Mesh shell 可以通过网络发送原始 Mesh 消息。

例如，要发送一条 Generic OnOff Set 消息，调用:

uart:~$ mesh test net-send 82020100

备注

模型消息中所有多字节字段均采用小端序，操作码（opcode）除外。

消息将发送到当前目标地址，并使用当前的网络密钥索引和应用密钥索引。由于目标地址默认指向本地单播地址，设备只会向自己发送数据包。要将目标地址改为 All Nodes 广播地址，调用:

uart:~$ mesh target dst 0xffff

将目标地址设置为 0xffff 后，网络中配置了相同网络密钥和应用密钥的其他 Mesh 节点都会接收并处理我们发送的消息。

备注

要修改设备的配置，在执行任何配置命令之前，必须先把目标地址改回本地单播地址。

在开发过程中，发送原始 Mesh 数据包是测试模型消息处理函数实现的好方法，因为无需实现发送端模型。默认情况下，用这种方式只能测试模型消息的接收，因为 Bluetooth Mesh shell 只包含基础模型（foundation model）。要在 Mesh 节点中接收数据包，必须在 subsys/bluetooth/mesh/shell.c 的组成数据中添加一个带有效操作码处理函数列表的模型，并在处理回调中把收到的消息打印到 shell。

Bluetooth Mesh shell 实现了大量命令。部分命令接受参数，这些参数以括号形式写在命令名之后，例如 mesh lpn set <value: off, on>。必选参数用尖括号标记（例如 <NetKeyIdx>），可选参数用方括号标记（例如 [DstAddr]）。

备注

部分命令依赖于在应用程序编译期配置中启用的特定功能。并非所有功能都默认启用。在 shell 中不带任何参数调用 mesh，即可显示可用的 Bluetooth Mesh shell 命令列表。

通用配置

mesh init

初始化 Mesh shell。必须先运行此命令，才能运行其他任何 Mesh 命令。

mesh reset-local

将本地 Mesh 节点重置为初始的未配网状态。如果存在配置数据库（CDB），此命令也会将其清除。

目标

目标（target）命令用于查看和设置 shell 使用的目标地址、网络索引和应用索引。这些参数会被配网、配置客户端等多个命令使用。

mesh target dst [DstAddr]

获取或设置消息目标地址。目标地址决定通过 shell 发送的 Mesh 数据包发往何处，但对 shell 控制范围之外的模块没有影响。

  • DstAddr：如果提供，则设置新的 16 位 Mesh 目标地址；如果省略，则打印当前目标地址。

mesh target net [NetKeyIdx]

获取或设置消息网络索引。网络索引决定使用哪个网络密钥加密通过 shell 发送的 Mesh 数据包，但对 shell 控制范围之外的模块没有影响。该网络密钥必须已经添加到设备中，可以通过配网添加，也可以由配置客户端添加。

  • NetKeyIdx：如果提供，则设置新的网络索引；如果省略，则打印当前网络索引。

mesh target app [AppKeyIdx]

获取或设置消息应用索引。应用索引决定使用哪个应用密钥加密通过 shell 发送的 Mesh 数据包，但对 shell 控制范围之外的模块没有影响。该应用密钥必须已由配置客户端添加到设备中，并且必须绑定到当前网络索引。

  • AppKeyIdx：如果提供，则设置新的应用索引；如果省略，则打印当前应用索引。

低功耗节点

mesh lpn set <Val(off, on)>

启用或禁用低功耗（Low Power）运行。启用后，设备会关闭无线电并开始轮询好友节点。

  • Val：设置是否启用低功耗运行。

mesh lpn poll

向好友节点执行一次轮询，以接收所有待处理的消息。仅在启用 LPN 时可用。

测试

mesh test net-send <HexString>

使用当前目标地址、网络索引和应用索引发送一条原始 Mesh 消息。消息操作码必须手动编码。

  • HexString：待发送消息的原始十六进制表示。

mesh test iv-update

强制执行一次 IV 更新。

mesh test iv-update-test <Val(off, on)>

设置 IV 更新测试模式。在测试模式下，会绕过 IV 更新的时序要求。

  • Val：启用或禁用 IV 更新测试模式。

mesh test rpl-clear

清空重放保护列表，强制节点忘记所有已收到的消息。

警告

清空重放保护列表会破坏 Mesh 节点的安全机制，使其容易受到消息重放攻击。切勿在实际部署中执行此操作。

健康服务器测试

mesh test health-srv add-fault <FaultID>

为 Linux Foundation 公司 ID 注册一个新的健康服务器故障。

  • FaultID：要注册的故障 ID（0x0001 到 0xFFFF）

mesh test health-srv del-fault [FaultID]

删除为 Linux Foundation 公司 ID 注册的健康服务器故障。

  • FaultID：如果提供，则删除指定的故障 ID；如果省略，则清除所有已注册的故障。

配网

要允许设备广播可连接的未配网信标，必须启用 CONFIG_BT_MESH_PROVISIONEE 配置选项以及 CONFIG_BT_MESH_PB_GATT 选项。

mesh prov pb-gatt <Val(off, on)>

开始或停止广播可连接的未配网信标。通过可连接的未配网信标，附近基于 GATT 的配网器可以发现该 Mesh 节点，并通过 GATT 承载为其配网。

  • Val：启用或禁用通过 GATT 配网

要允许设备广播未配网信标，必须启用 CONFIG_BT_MESH_PROVISIONEE 配置选项以及 CONFIG_BT_MESH_PB_ADV 选项。

mesh prov pb-adv <Val(off, on)>

开始或停止广播未配网信标。通过未配网信标，附近基于广播的配网器可以发现该 Mesh 节点，并通过广播承载为其配网。

  • Val：启用或禁用通过广播配网

要允许设备为其他设备配网，必须启用 CONFIG_BT_MESH_PROVISIONER 和 CONFIG_BT_MESH_PB_ADV 配置选项。

mesh prov remote-adv <UUID(1-16 hex)> <NetKeyIdx> <Addr> <AttDur(s)>

将附近的设备配网到 Mesh 中。Mesh 节点开始扫描具有指定 UUID 的未配网信标。找到后，该未配网设备会以指定的单播地址加入 Mesh 网络，并获得 NetKeyIdx 所指示的网络密钥。

  • UUID：未配网设备的 UUID。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。

  • NetKeyIdx：要下发给设备的网络密钥的索引。

  • Addr：分配给未配网设备的第一个单播地址。设备占用的地址数量与其元素数量相同，并且这些地址都必须可用。

  • AttDur：未配网设备进行自我标识（identify）的持续时间（秒），前提是设备支持该功能。详见 注意状态。

要允许设备通过 GATT 为其他设备配网，必须启用 CONFIG_BT_MESH_PROVISIONER 和 CONFIG_BT_MESH_PB_GATT_CLIENT 配置选项。

mesh prov remote-gatt <UUID(1-16 hex)> <NetKeyIdx> <Addr> <AttDur(s)>

将附近的设备配网到 Mesh 中。Mesh 节点开始扫描具有指定 UUID 的 PB-GATT 可连接广播。找到后，该未配网设备会以指定的单播地址加入 Mesh 网络，并获得 NetKeyIdx 所指示的网络密钥。

  • UUID：未配网设备的 UUID。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。

  • NetKeyIdx：要下发给设备的网络密钥的索引。

  • Addr：分配给未配网设备的第一个单播地址。设备占用的地址数量与其元素数量相同，并且这些地址都必须可用。

  • AttDur：未配网设备进行自我标识（identify）的持续时间（秒），前提是设备支持该功能。详见 注意状态。

mesh prov uuid [UUID(1-16 hex)]

获取或设置 Mesh 节点的 UUID，该 UUID 用于未配网信标中。

  • UUID：如果提供，则为新的 128 位 UUID 值。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则打印当前 UUID。要启用此命令，必须启用 CONFIG_BT_MESH_SHELL_PROV_CTX_INSTANCE 选项。

mesh prov input-num <Number>

输入数字形式的 OOB 认证值。仅在配网期间 shell 提示输入时有效。输入的数字必须与配网另一方显示的数字一致。

  • Number：十进制认证数字。

mesh prov input-str <String>

输入字母数字形式的 OOB 认证值。仅在配网期间 shell 提示输入时有效。输入的字符串必须与配网另一方显示的字符串一致。

  • String：不加引号的字母数字认证字符串。

mesh prov static-oob [Val(1-32 hex)]

设置或清除静态 OOB 认证值。静态 OOB 认证值必须在配网开始前设置才会生效。配网双方的静态 OOB 值必须相同。要启用此命令，必须启用 CONFIG_BT_MESH_SHELL_PROV_CTX_INSTANCE 选项。

  • Val：如果提供，则表示新的静态 OOB 十六进制值。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则清除静态 OOB 值。

mesh prov local <NetKeyIdx> <Addr> [IVI]

为 Mesh 节点自身配网。如果启用了配置数据库，则必须先创建网络密钥；否则使用默认密钥值。

  • NetKeyIdx：配网所用网络密钥的索引。

  • Addr：分配给设备的第一个单播地址。设备占用的地址数量与其元素数量相同，并且这些地址都必须可用。

  • IVI：表示当前网络的 IV 索引。省略时默认为 0。

mesh prov beacon-listen <Val(off, on)>

启用或禁用打印收到的未配网信标。配网器设备可借此检测附近的未配网设备并为其配网。要启用此命令，必须启用 CONFIG_BT_MESH_SHELL_PROV_CTX_INSTANCE 选项。

  • Val：是否启用未配网信标打印。

mesh prov remote-pub-key <PubKey>

提供设备公钥。

  • PubKey - 大端序的设备公钥。

mesh prov auth-method input <Action> <Size>

在配网器设备上，指示未配网设备使用指定的输入 OOB（Input OOB）认证动作。

  • Action - 输入动作。允许的取值：

    • 0 - 无输入动作。

    • 1 - 按压（Push）动作。

    • 2 - 旋转（Twist）动作。

    • 4 - 输入数字动作。

    • 8 - 输入字符串动作。

  • Size - 认证值长度。

mesh prov auth-method output <Action> <Size>

在配网器设备上，指示未配网设备使用指定的输出 OOB（Output OOB）认证动作。

  • Action - 输出动作。允许的取值：

    • 0 - 无输出动作。

    • 1 - 闪烁（Blink）动作。

    • 2 - 振动（Vibrate）动作。

    • 4 - 显示数字动作。

    • 8 - 显示字符串动作。

  • Size - 认证值长度。

mesh prov auth-method static <Val(1-16 hex)>

在配网器设备上，指示未配网设备使用静态 OOB 认证，并在配网时使用给定的静态认证值。

  • Val - 静态 OOB 值。如果提供的十六进制字符串短于 32 字节，则填充数组中最高的 N 个字节，其余部分补零。

mesh prov auth-method none

在配网器设备上，为新设备配网时不使用任何认证。这是默认行为。

代理

代理服务器（Proxy Server）模块是可选的 Mesh 子系统，可通过 CONFIG_BT_MESH_GATT_PROXY 配置选项启用。

mesh proxy identity-enable

启用代理节点身份（Proxy Node Identity）信标，使代理设备可以明确地连接到本设备。该信标会持续 60 秒，之后节点恢复发送普通的代理信标。

代理客户端（Proxy Client）模块是可选的 Mesh 子系统，可通过 CONFIG_BT_MESH_PROXY_CLIENT 配置选项启用。

mesh proxy connect <NetKeyIdx>

自动连接附近的代理服务器以接入 Mesh。

  • NetKeyIdx：用于连接的网络密钥的索引。

mesh proxy disconnect <NetKeyIdx>

断开现有的代理连接。

  • NetKeyIdx：要断开连接的网络密钥的索引。

mesh proxy solicit <NetKeyIdx>

开始对某个子网进行代理征求（Proxy Solicitation）。可通过 CONFIG_BT_MESH_PROXY_SOLICITATION 配置选项启用对此功能的支持。

  • NetKeyIdx：发送征求 PDU（Solicitation PDU）所针对的网络密钥的索引。

模型

配置客户端

配置客户端（Configuration Client）模型是可选的 Mesh 子系统，可通过 CONFIG_BT_MESH_CFG_CLI 配置选项启用。它作为 mesh models 子命令列表中一个单独的模块（mesh models cfg）实现。只要启用了上述 shell 配置选项，并且应用程序的模型组成中包含配置客户端模型，该模块即可作用于配置客户端模型的任一实例。此 shell 模块可用于配置节点自身以及 Mesh 网络中的其他节点。

配置客户端使用 mesh target dst 和 mesh target net 设置的通用消息参数来指定目标节点。在启用了 CONFIG_BT_MESH_SHELL_PROV_CTX_INSTANCE 选项且 shell 配网上下文已初始化的前提下，Bluetooth Mesh shell 节点完成配网后，配置客户端模型默认以自身为目标。同样，当 Bluetooth Mesh shell 为另一个节点配网后，配置客户端模型会以该新节点为目标。在大多数常见用例中，配置客户端需要依赖配网功能和配置数据库才能完整运行。配置客户端总是使用与目标地址绑定的设备密钥（Device key）发送消息，因此它只能配置自身以及由它配网的 Mesh 节点。以下步骤示例说明了如何设置设备以开始使用配置客户端命令：

  • 初始化客户端节点（mesh init）。

  • 创建 CDB（mesh cdb create）。

  • 为本地设备配网（mesh prov local）。

  • 此时 shell 模块应以自身为目标。

  • 查看本地节点的组成数据（mesh models cfg get-comp）。

  • 使用配置客户端命令按需配置本地节点。

  • 为其他设备配网（mesh prov beacon-listen）（mesh prov remote-adv）（mesh prov remote-gatt）。

  • 此时 shell 模块应以新添加的节点为目标。

  • 查看新配网的节点及其地址（mesh cdb show）。

  • 查看目标设备的组成数据（mesh models cfg get-comp）。

  • 使用配置客户端命令按需配置该节点。

健康客户端

健康客户端（Health Client）模型是可选的 Mesh 子系统，可通过 CONFIG_BT_MESH_HEALTH_CLI 配置选项启用。它作为 mesh models 子命令列表中一个单独的模块（mesh models health）实现。只要启用了上述 shell 配置选项，并且应用程序的模型组成中包含一个或多个健康客户端模型，该模块即可作用于健康客户端模型的任一实例。此 shell 模块可用于触发 Mesh 网络中各设备上健康客户端与健康服务器之间的交互。

默认情况下，使用健康客户端命令时，该模块会选择模型组成中的第一个健康客户端实例。要选择特定的健康客户端实例，用户可以使用 mesh models health instance set 和 mesh models health instance get-all 命令。

健康客户端可以使用 mesh target dst、mesh target net 和 mesh target app 设置的通用消息参数来指定目标节点。如果 shell 的目标地址设为零，则目标健康客户端会尝试使用其已配置的发布参数发布消息。

远程配网客户端

远程配网客户端（Remote Provisioning Client）是可选的 Bluetooth Mesh 模型，通过 CONFIG_BT_MESH_RPR_CLI 配置选项启用。远程配网客户端模型借助远程配网服务器模型，支持将设备远程配网到 Mesh 网络中。

开始扫描未配网设备。

  • Timeout：扫描超时（秒），至少为 1 秒。

  • UUID：要扫描的设备 UUID。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则报告所有设备。

  • Timeout：扫描超时（秒）。有效取值范围为 BT_MESH_RPR_EXT_SCAN_TIME_MIN 到 BT_MESH_RPR_EXT_SCAN_TIME_MAX。

  • UUID：要进行扩展扫描的设备 UUID。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。

  • ADType：要包含在扫描报告中的 AD 类型列表。必须包含 1 到 CONFIG_BT_MESH_RPR_AD_TYPES_MAX 个条目。

mesh models rpr scan-srv [<ADType> ... ]

开始对远程配网服务器进行扩展扫描。

  • ADType：要包含在扫描报告中的 AD 类型列表。必须包含 1 到 CONFIG_BT_MESH_RPR_AD_TYPES_MAX 个条目。

mesh models rpr scan-caps

获取远程配网服务器的扫描能力。

mesh models rpr scan-get

获取远程配网服务器当前的扫描状态。

mesh models rpr scan-stop

停止远程配网服务器上正在进行的扫描。

mesh models rpr link-get

获取远程配网服务器当前的链路状态。

mesh models rpr link-close

关闭远程配网服务器上所有已打开的链路。

mesh models rpr provision-remote <UUID(1-16 hex)> <NetKeyIdx> <Addr>

使用 PB-Remote 配网承载为 Mesh 节点配网。

  • UUID：未配网节点的 UUID。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。

  • NetKeyIdx：要下发给未配网节点的网络密钥索引。

  • Addr：分配给远端设备的地址。如果 addr 为 0，则选择可用的最小地址。

mesh models rpr reprovision-remote <Addr> [<CompChanged(false, true)>]

使用 PB-Remote 配网承载为 Mesh 节点重新配网。

  • Addr：分配给远端设备的地址。如果 addr 为 0，则选择可用的最小地址。

  • CompChanged：目标节点已表明其组成数据发生了变化。默认为 false。

mesh models rpr instance-set <ElemIdx>

在使用其他远程配网客户端模型命令时，使用指定元素上的远程配网客户端模型实例。

  • ElemIdx：在其上查找所要使用的远程配网客户端模型实例的元素。

mesh models rpr instance-get-all

桥接配置客户端

桥接配置客户端（Bridge Configuration Client）模型是可选的 Bluetooth Mesh 模型，可通过 CONFIG_BT_MESH_BRG_CFG_CLI 配置选项启用。该模型用于配置 Mesh 节点的子网桥接功能。

mesh models brg get

获取当前的子网桥接（Subnet Bridge）状态。

mesh models brg set <State(disable, enable)>

设置子网桥接状态。

  • State：禁用或启用子网桥接功能。

mesh models brg table-size-get

获取桥接表（Bridging Table）的当前大小。

mesh models brg table-add <Directions> <NetIdx1> <NetIdx2> <Addr1> <Addr2>

向桥接表中添加一个条目。

  • Directions：桥接流量允许的方向。有效取值为：

    • 0x01：仅允许桥接以 Addr1 为源地址、以 Addr2 为目标地址的消息。

    • 0x02：允许双向桥接。

  • NetIdx1：第一个子网的 NetKey 索引。

  • NetIdx2：第二个子网的 NetKey 索引。

  • Addr1：第一个子网中节点的地址。

  • Addr2：第二个子网中节点的地址。

mesh models brg table-remove <NetIdx1> <NetIdx2> <Addr1> <Addr2>

从桥接表中移除一个条目。

  • NetIdx1：第一个子网的 NetKey 索引。

  • NetIdx2：第二个子网的 NetKey 索引。

  • Addr1：第一个子网中节点的地址。

  • Addr2：第二个子网中节点的地址。

mesh models brg subnets-get <Filter> <NetIdx> <StartIdx>

获取从桥接表中提取的、经过过滤的 NetKey 索引对集合。

  • Filter：报告从桥接表中提取的 NetKey 索引对时所应用的过滤条件。允许的取值：

    • 0x00：报告所有索引对。

    • 0x01：报告第一个子网的 NetKey 索引与 NetIdx 匹配的索引对。

    • 0x02：报告第二个子网的 NetKey 索引与 NetIdx 匹配的索引对。

    • 0x03：报告其中一个 NetKey 索引与 NetIdx 匹配的索引对。

  • NetIdx：任一子网的 NetKey 索引。

  • StartIdx：读取的起始偏移量，以 NetKey 索引对为单位。

mesh models brg table-get <NetIdx1> <NetIdx2> <StartIdx>

获取桥接表各条目的地址列表及允许的流量方向。

  • NetIdx1：第一个子网的 NetKey 索引。

  • NetIdx2：第二个子网的 NetKey 索引。

  • StartIdx：读取的起始偏移量，以桥接表状态条目为单位。

配置数据库

配置数据库（Configuration database）是可选的 Mesh 子系统，可通过 CONFIG_BT_MESH_CDB 配置选项启用。配置数据库仅在配网器设备上可用，可用于存储有关 Mesh 网络的全部信息。为避免冲突，网络中应只有一个 Mesh 节点启用配置数据库。该节点即配置者（Configurator），负责向网络中添加新节点并对其进行配置。

mesh cdb create [NetKey(1-16 hex)]

创建配置数据库。

  • NetKey：可选，主网络密钥（NetKeyIndex=0）的网络密钥值。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则使用默认密钥值。

mesh cdb clear

清除配置数据库中的所有数据。

mesh cdb show

显示配置数据库中的所有数据。

mesh cdb node-add <UUID(1-16 hex)> <Addr> <ElemCnt> <NetKeyIdx> [DevKey(1-16 hex)]

手动将一个 Mesh 节点添加到配置数据库中。注意，如果已启用并创建了配置数据库，通过 mesh provision 和 mesh provision-adv 配网的设备会被自动添加。

  • UUID：节点的 128 位十六进制 UUID。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。

  • Addr：节点的单播地址；设为 0 则自动选择可用的最小地址。

  • ElemCnt：节点上的元素数量。

  • NetKeyIdx：节点配网时使用的网络密钥。

  • DevKey：可选，设备的 128 位设备密钥值。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则生成一个随机值。

mesh cdb node-del <Addr>

从配置数据库中删除一个 Mesh 节点。如有可能，应先使用 mesh reset 重置该节点，再将其从配置数据库中删除，以避免出现意外行为以及对网络的不受控访问。

  • Addr：要删除的节点的地址。

mesh cdb subnet-add <NetKeyIdx> [<NetKey(1-16 hex)>]

向配置数据库添加一个网络密钥。之后可以将该网络密钥下发给网络中的 Mesh 节点。注意，将密钥添加到配置数据库并不会自动把它加入本地节点的已知网络密钥列表。

  • NetKeyIdx：要添加的网络密钥的密钥索引。

  • NetKey：可选，128 位网络密钥值。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则生成一个随机值。

mesh cdb subnet-del <NetKeyIdx>

从配置数据库中删除一个网络密钥。

  • NetKeyIdx：要删除的网络密钥的密钥索引。

mesh cdb app-key-add <NetKeyIdx> <AppKeyIdx> [<AppKey(1-16 hex)>]

向配置数据库添加一个应用密钥。之后可以将该应用密钥下发给网络中的 Mesh 节点。注意，将密钥添加到配置数据库并不会自动把它加入本地节点的已知应用密钥列表。

  • NetKeyIdx：应用密钥所绑定的网络密钥索引。

  • AppKeyIdx：要添加的应用密钥的密钥索引。

  • AppKey：可选，128 位应用密钥值。如果提供的十六进制字符串短于 16 字节，则填充数组中最高的 N 个字节，其余部分补零。如果省略，则生成一个随机值。

mesh cdb app-key-del <AppKeyIdx>

从配置数据库中删除一个应用密钥。

  • AppKeyIdx：要删除的应用密钥的密钥索引。
