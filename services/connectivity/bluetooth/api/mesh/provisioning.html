配网

配网（provisioning）是将设备加入 Mesh 网络的过程。它需要两台分别担任以下角色的设备：

  • 配网器（provisioner） 代表网络所有者，负责将新节点加入 Mesh 网络。

  • 被配网设备（provisionee） 是通过配网过程加入网络的设备。在配网过程开始之前，被配网设备是一台 未配网设备（unprovisioned device）。

Zephyr Bluetooth Mesh 协议栈中的配网模块在被配网设备角色下同时支持广播（Advertising）配网承载和 GATT 配网承载，在配网器角色下支持广播配网承载。

配网过程

所有 Bluetooth Mesh 节点都必须先完成配网，才能加入 Bluetooth Mesh 网络。配网 API 提供了设备成为已配网 Mesh 节点所需的全部功能。配网过程分为五个步骤：

  • 发送信标

  • 邀请

  • 公钥交换

  • 认证

  • 配网数据传输

发送信标

要启动配网过程，未配网设备必须首先开始广播未配网信标（Unprovisioned Beacon）。这使附近的配网器能够发现它，并发起配网。要表明设备需要配网，请调用 bt_mesh_prov_enable()。设备会开始广播未配网信标，其中包含设备 UUID 和 OOB information 字段，二者由传给 bt_mesh_init() 的 prov 参数指定。此外，还可以指定一个统一资源标识符（URI），它可以向配网器指明某些带外（Out Of Band）信息的位置，例如设备的公钥或认证值数据库。URI 在一个单独的信标中广播，并在未配网信标中包含 URI 哈希，从而将二者关联起来。

统一资源标识符

统一资源标识符（URI）应遵循 Bluetooth 核心规范补充文档（Bluetooth Core Specification Supplement）中规定的格式。URI 必须以 URI 方案（scheme）开头，该方案编码为单个 utf-8 码点；或者以特殊的 none 方案开头，该方案编码为 0x01。可用的方案列在 Bluetooth 网站 上。

已编码 URI 的示例：

URI

http://example.com

https://www.zephyrproject.org/

配网邀请

配网器通过发送配网邀请（Provisioning invitation）来发起配网过程。如果可用，该邀请会提示被配网设备使用健康服务器的 注意状态 引起用户注意。

未配网设备会自动响应邀请，提供其能力列表，包括所支持的带外认证方法和算法。

公钥交换

在配网过程开始之前，配网器和未配网设备会以带内（in-band）或带外（OOB）方式交换公钥。

带内公钥交换是配网过程的一部分，未配网设备和配网器总是支持这种方式。

如果应用程序希望支持通过 OOB 交换公钥，就需要向 Mesh 协议栈提供公钥和私钥。未配网设备会在其能力中体现这一点。配网器通过任何可用的 OOB 机制获取公钥（例如，设备可以广播一个包含公钥的数据包，或者将公钥编码在印于设备包装上的二维码中）。注意，即使未配网设备已经指定了用于带外交换的公钥，如果配网器无法通过 OOB 机制获取公钥，它也可以选择以带内方式交换公钥。在这种情况下，Mesh 协议栈会为每次配网过程生成一个新的密钥对。

要在未配网设备一侧启用对 OOB 公钥的支持，需要启用 CONFIG_BT_MESH_PROV_OOB_PUBLIC_KEY。应用程序必须在配网过程开始之前，通过初始化 bt_mesh_prov.public_key_be 和 bt_mesh_prov.private_key_be 指针来提供公钥和私钥。密钥需要以大端字节序提供。

要提供通过 OOB 获取的设备公钥，请在配网器一侧调用 bt_mesh_prov_remote_pub_key_set()。

认证

完成初始交换后，配网器会选择一种带外（OOB）认证方法。这让用户可以确认配网器所连接的设备确实是其想要配网的设备，而不是恶意的第三方。

配网 API 为被配网设备支持以下认证方法：

  • 静态 OOB（Static OOB）： 设备在生产时被分配一个认证值，配网器可以通过某种应用程序特定的方式查询该值。为了使用 BTM_ECDH_P256_HMAC_SHA256_AES_CCM 算法进行安全配网，静态 OOB 值应包含超过 128 位的熵，以提供足够的抗攻击安全性。

  • 输入 OOB（Input OOB）： 由用户输入认证值。可用的输入动作列在 bt_mesh_input_action_t 中。

  • 输出 OOB（Output OOB）： 向用户显示认证值。可用的输出动作列在 bt_mesh_output_action_t 中。

应用程序必须在 bt_mesh_prov 中为所支持的认证方法提供回调，并在 bt_mesh_prov.output_actions 和 bt_mesh_prov.input_actions 中启用所支持的动作。

选择输出 OOB 动作时，应在调用输出回调时向用户显示认证值，并一直保持显示，直到 bt_mesh_prov.input_complete 或 bt_mesh_prov.complete 回调被调用。如果动作是 blink、beep 或 vibrate，应在间隔三秒或更长时间后重复该序列。

选择输入 OOB 动作时，应在应用程序收到 bt_mesh_prov.input 回调时提示用户。用户的输入应通过 bt_mesh_input_string() 或 bt_mesh_input_numeric() 反馈给配网 API。如果在 60 秒内没有记录到用户输入，配网过程将被中止。

如果被配网设备要求强制使用 OOB 认证，则必须使用 BT_MESH_ECDH_P256_HMAC_SHA256_AES_CCM 算法。

数据传输

设备成功通过认证后，配网器会传输以下配网数据：

  • 单播地址

  • 一个网络密钥（NetKey）

  • IV 索引

  • 网络标志

    • 密钥刷新（Key refresh）

    • IV 更新（IV update）

此外，还会为节点生成一个设备密钥（DevKey）。所有这些数据都由 Mesh 协议栈存储，然后调用配网的 bt_mesh_prov.complete 回调。

配网安全

根据所选的公钥交换机制和认证方法，配网过程可能是安全的，也可能是不安全的。

2021 年 5 月 24 日，ANSSI 披露 了 Bluetooth Mesh 配网协议中的一组漏洞，展示了闪烁（Blink）、振动（Vibrate）、按压（Push）、旋转（Twist）以及输入/输出数字等 OOB 方法所提供的低熵如何可能被用于冒充攻击和中间人（MITM）攻击。作为回应，由于 AuthValue 可能被实时暴力破解，Bluetooth SIG 在 Bluetooth Mesh Profile 规范 v1.0.1 的 勘误 16350 中将这些 OOB 方法重新归类为不安全。为确保配网安全，应用程序应使用静态 OOB 值和 OOB 公钥传输。
