核心

核心部分提供管理 Bluetooth Mesh 总体状态的功能。

低功耗节点

低功耗节点（LPN）角色允许电池供电的设备作为叶节点加入 Mesh 网络。LPN 通过一个好友节点与 Mesh 网络交互，好友节点负责转发所有发往该 LPN 的消息。LPN 通过保持射频关闭来节省电量，只在发送消息或向好友节点轮询是否有待接收消息时才唤醒。

射频控制和轮询由 Mesh 协议栈自动管理，但 LPN API 允许应用程序随时通过 bt_mesh_lpn_poll() 触发轮询。LPN 的运行参数，包括轮询间隔、轮询事件时序以及对好友节点的要求，由 CONFIG_BT_MESH_LOW_POWER 选项及相关配置选项控制。

在使用 LPN 功能并启用日志时，强烈建议只使用 CONFIG_LOG_MODE_DEFERRED 选项。延迟模式以外的日志模式可能会在处理日志消息时造成意外延迟，进而影响接收延迟（receive delay）和接收窗口（receive window）的调度。同样的限制也适用于 CONFIG_BT_MESH_FRIEND 选项。

重放保护列表

重放保护列表（Replay Protection List，RPL）用于保存最近从 Mesh 网络中各元素收到的序列号，以防范重放攻击。

为了让节点在重启后仍能防范重放攻击，节点需要在断电之前将整个 RPL 存入持久化存储。根据 Mesh 网络中流量的多少，存储最近见到的序列号可能会使 Flash 或早或晚地磨损。为缓解这一问题，可以使用 CONFIG_BT_MESH_RPL_STORE_TIMEOUT。该选项会推迟将 RPL 条目存入持久化存储。

不过，该选项并不能完全解决问题，因为节点可能在存储 RPL 的定时器触发之前就断电了。为确保消息无法被重放，节点可以随时（或在断电前足够早的时候）调用 bt_mesh_rpl_pending_store()，发起对待存储 RPL 条目的存储。在这种情况下，由节点自行决定要存储哪些 RPL 条目。

将 CONFIG_BT_MESH_RPL_STORE_TIMEOUT 设置为 -1 可以完全关闭该定时器，这有助于大幅减少 Flash 磨损。这样一来，存储 RPL 的责任就转移给了用户应用程序，并要求从调用该 API 起直到所有 RPL 条目都写入 Flash 为止，有足够的后备电源。

在 CONFIG_BT_MESH_RPL_STORE_TIMEOUT 与调用 bt_mesh_rpl_pending_store() 之间找到合适的平衡，可以降低安全漏洞和 Flash 磨损的风险。

持久化存储

Mesh 协议栈使用 设置子系统 持久化存储设备配置。当协议栈配置发生变化且需要持久化存储时，协议栈会调度一个工作项。从调度工作项到将其提交到工作队列之间的延迟由 CONFIG_BT_MESH_STORE_TIMEOUT 选项定义。一旦数据存储已被调度，在该工作项被处理之前就不能重新调度。某些情况例外，如下所述。

当需要存储 IV 索引、序列号、CDB 配置或重放保护列表重置时，工作项会被立即提交到工作队列，不经过延迟。如果该工作项之前已被调度，它会被重新调度为无延迟。

重放保护列表和征求重放保护列表由一个单独的工作项存储，其调度延迟由 CONFIG_BT_MESH_RPL_STORE_TIMEOUT 定义。其他类型的待处理存储不会缩短这一延迟。如果该选项设置为 -1，重放保护列表将与协议栈的其余配置一起存储。

工作项运行时，协议栈会存储该工作项负责的所有待处理配置。

工作项执行上下文

CONFIG_BT_MESH_SETTINGS_WORKQ 选项配置执行工作项的上下文。该选项默认启用，此时协议栈会使用一个专用的协作式线程来处理工作项。这样，在存储协议栈配置期间，协议栈仍可以处理其他收发消息，以及提交到系统工作队列的其他工作项。

禁用该选项时，工作项会被提交到系统工作队列。这意味着在存储协议栈配置所需的时间内，系统工作队列会被阻塞。不建议禁用该选项，因为这会使设备在相当长的一段时间内无响应。

广播标识

所有 Mesh 协议栈承载层都使用 BT_ID_DEFAULT 本地标识广播数据。该值在 Mesh 协议栈实现中预先设定。当低功耗蓝牙（Bluetooth® Low Energy，LE）和 Bluetooth Mesh 共存于同一设备时，应用程序应在开始通信之前，为 Bluetooth LE 用途分配并配置另一个本地标识。
