子网桥接

Bluetooth Mesh 协议规范 1.1 版引入了 Bluetooth Mesh 子网桥接（Subnet Bridge）功能。该功能允许 Mesh 网络使用子网进行区域隔离，同时又允许不同的相邻子网中的特定设备之间进行通信，而不会损害安全性。

借助 Bluetooth Mesh 子网桥接功能，网络中选定的节点可以充当子网桥，通过在相邻子网的节点之间中继消息来实现受控的通信。

子网桥接功能包括两个模型：

  • 桥接配置服务器

  • 桥接配置客户端

桥接配置服务器模型是支持子网桥接功能所必需的。桥接配置客户端模型是可选的，它允许节点配置其他节点上的子网桥接。这些模型定义了配置和管理子网桥接功能所需的状态、消息和行为。

子网桥接功能的配置和管理通过桥接配置服务器模型和客户端模型完成。实现了桥接配置客户端模型的节点可以充当子网桥接功能的 配置管理者（Configuration Manager）。

概念

为了更好地理解子网桥接功能及其能力，需要先了解几个概念。

子网

子网是 Mesh 网络中共享同一网络密钥（NetKey）的一组节点，这使它们能够在网络层安全地通信。每个子网独立运行，节点只在该组内交换消息。一个节点可以同时属于多个子网。

子网桥节点

子网桥节点是 Bluetooth Mesh 网络中属于多个子网并启用了子网桥接功能的节点。只有这样的节点才能执行子网桥接。子网桥节点连接各个子网，并通过在子网组之间中继消息来实现它们之间的通信。

子网桥节点有一个基于主 NetKey 的主子网，负责处理 IV 更新过程并将更新传播到其他子网。在其上中继消息的次级子网称为 被桥接子网（bridged subnet）。

桥接表

桥接表包含该节点所桥接子网的条目，由桥接配置服务器模型管理。

桥接表中的最大条目数由 CONFIG_BT_MESH_BRG_TABLE_ITEMS_MAX 选项定义，默认值为最小值 16，最大可能的大小为 255。

启用或禁用子网桥接功能

桥接配置客户端（或配置管理者）可以使用 bt_mesh_brg_cfg_cli_set() 函数，向目标节点上的桥接配置服务器模型发送 Subnet Bridge Set 消息，从而在该节点上启用或禁用子网桥接功能。

添加或移除子网

桥接配置客户端可以调用 bt_mesh_brg_cfg_cli_table_add() 或 bt_mesh_brg_cfg_cli_table_remove() 函数，向目标节点上的桥接配置服务器模型发送 Bridging Table Add 或 Bridging Table Remove 消息，从而在桥接表中添加或移除条目。

子网桥接状态

子网桥接具有以下状态：

  • 子网桥接（Subnet Bridge）：该状态表示节点上的子网桥接功能是启用还是禁用。桥接配置客户端可以使用 bt_mesh_brg_cfg_cli_get() 函数向桥接配置服务器发送 Subnet Bridge Get 消息来获取此信息。

  • 桥接表（Bridging Table）：该状态保存桥接表。客户端可以使用 bt_mesh_brg_cfg_cli_table_get() 函数向目标节点发送 Bridging Table Get 消息，请求桥接表中的条目列表。

    客户端可以调用 bt_mesh_brg_cfg_cli_subnets_get() 函数向目标服务器发送 Bridged Subnets Get 消息，获取子网桥当前所桥接的子网列表。

  • 桥接表大小（Bridging Table Size）：该状态报告桥接表可以存储的最大条目数。客户端可以使用 bt_mesh_brg_cfg_cli_table_size_get() 函数发送 Bridging Table Size Get 消息来获取此信息。这是一个只读状态。

子网桥接与重放保护

子网桥接功能实现了子网之间的消息中继，需要有效的重放保护来确保网络安全。需要考虑的关键事项如下所述。

中继缓冲区注意事项

当子网桥在子网之间中继消息时，消息从中继缓冲池中分配。中继缓冲区的数量可以通过 CONFIG_BT_MESH_RELAY_BUF_COUNT Kconfig 选项配置。

启用 CONFIG_BT_MESH_ADV_EXT 时，消息将使用中继广播集（advertising set）发送。广播集的数量可以通过 CONFIG_BT_MESH_RELAY_ADV_SETS Kconfig 选项配置。

即使中继功能 CONFIG_BT_MESH_RELAY 被禁用，中继缓冲池和广播集也都可以使用。

重放保护与桥接表

子网桥节点必须对发往被桥接子网的所有访问（Access）消息和传输控制（Transport Control）消息实施重放保护。

重放保护列表（RPL）与桥接表协同工作以确保安全：

  • 子网桥会为每个被授权向被桥接子网发送消息的源地址存储最新的 IVISeq。

  • IVISeq 小于或等于已存储值的消息会被丢弃，而有效消息在被中继之前会更新已存储的 IVISeq。

为确保正常运行，RPL 与桥接表保持同步非常重要，因为每条被桥接的消息在中继之前都必须经过重放保护机制。

备注

RPL 的大小应当随桥接表一起扩展。随着被桥接子网数量的增加，需要跟踪的源地址和 IVISeq 值也会增多，因此需要更大的 RPL 才能保持有效的重放保护。

子网桥接与定向转发

Bluetooth Mesh 定向转发（Mesh Directed Forwarding，MDF）通过优化中继路径，实现跨子网节点之间的高效路由。虽然 MDF 可以通过处理路径发现和转发来增强子网桥接，但当前实现尚不支持此功能。
