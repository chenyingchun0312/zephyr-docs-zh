固件更新服务器

固件更新服务器（Firmware Update Server）模型实现了 设备固件更新（DFU） 子系统的目标节点（Target node）功能。它扩展了 BLOB 传输服务器，并用其从分发者（Distributor）节点接收固件镜像二进制文件。

固件更新服务器模型与其扩展的 BLOB 传输服务器模型一起，实现了通过 Mesh 网络接收固件更新所需的全部功能，但不提供存储、应用或验证镜像的任何功能。

固件镜像

固件更新服务器维护设备上所有可更新固件镜像的列表。完整列表应通过 BT_MESH_DFU_SRV_INIT 中的 _imgs 参数传给服务器，并且必须在 Bluetooth Mesh 子系统启动之前填充完毕。镜像列表中的每个固件镜像都必须能够独立更新，并且应当有自己的固件 ID。

例如，一个带有可升级引导加载程序、一个应用程序以及一个具有固件更新能力的外设芯片的设备，可以在固件镜像列表中有三个条目，每个条目都有各自独立的固件 ID。

接收传输

固件更新服务器模型使用同一元素上的 BLOB 传输服务器模型来传输二进制镜像。固件更新服务器、BLOB 传输服务器和应用程序之间的交互如下所述：

传输检查

传输检查是应用程序可以对传入的固件镜像元数据执行的一项可选的传输前检查。固件更新服务器通过调用 check 回调来执行传输检查。

传输检查的结果是一个通过/失败的返回状态以及预期的 bt_mesh_dfu_effect。DFU 影响（effect）返回参数会被回传给分发者，并且应当指明固件更新将对设备的 Mesh 状态产生什么影响。

组成数据和模型元数据

如果传输会导致设备更改其组成数据（Composition Data）或变为未配网状态，应当通过元数据检查的 effect 参数告知。

当传输会导致组成数据发生变化，并且支持 远程配网服务器 时，新固件镜像的组成数据将由组成数据页 128、129 和 130 表示。新固件镜像的模型元数据将由模型元数据页 128 表示。在使用 远程配网客户端 通过节点配网协议接口（Node Provisioning Protocol Interface，NPPI）过程对设备重新配网之前，组成数据页 0、1 和 2 以及模型元数据页 0 将表示旧固件镜像的组成数据和模型元数据。

在引导进入组成数据和模型元数据已更新的固件之前，应用程序必须调用 bt_mesh_comp_change_prepare() 和 bt_mesh_models_metadata_change_prepare() 函数，以存储现有的组成数据页和模型元数据页。之后，旧的组成数据将被加载到组成数据页 0、1 和 2 中，而新固件中的组成数据将被加载到组成数据页 128、129 和 130 中。旧镜像的模型元数据将被加载到模型元数据页 0 中，新镜像的模型元数据将被加载到模型元数据页 128 中。

限制：

  • 在应用新固件镜像之后，无法在更改设备组成数据的同时，让设备保持已配网状态并以旧固件继续工作。

启动

启动（Start）过程让应用程序为即将到来的传输做好准备。它包含正在更新哪个镜像的信息以及更新元数据。

固件更新服务器的 start 回调必须返回一个指向 BLOB 写入器的指针，BLOB 传输服务器将把 BLOB 发送给该写入器。

BLOB 传输

在设置阶段之后，固件更新服务器让 BLOB 传输服务器为即将到来的传输做好准备。整个固件镜像被传输到 BLOB 传输服务器，后者再将镜像交给为其指定的 BLOB 写入器。

BLOB 传输结束时，固件更新服务器会调用其 end 回调。

镜像验证

BLOB 传输完成后，应用程序应当尽其所能地验证镜像，以确保镜像已可以应用。镜像验证通过后，应用程序调用 bt_mesh_dfu_srv_verified()。

如果镜像无法通过验证，应用程序调用 bt_mesh_dfu_srv_rejected()。

应用镜像

最后，如果镜像已通过验证，分发者可以指示固件更新服务器应用此次传输。这会通过 apply 回调通知应用程序。应用程序应当切换镜像，并开始运行新固件。固件镜像表应当更新，以反映已更新镜像的新固件 ID。

当传输针对的是 Mesh 应用程序本身时，设备可能需要在切换过程中重启。这次重启可以在 apply 回调内部执行，也可以异步完成。使用新固件启动后，应当在启动 Bluetooth Mesh 子系统之前更新固件镜像表。

分发者会读取固件镜像表，以确认传输已成功应用。如果元数据检查表明设备将变为未配网状态，则目标节点无需响应此检查。
