代理

代理（Proxy）功能允许手机等传统设备通过 GATT 接入 Bluetooth Mesh 网络。只有设置了 CONFIG_BT_MESH_GATT_PROXY 选项时，代理功能才会被编译进来。代理功能的状态由 配置服务器 控制，其初始值可以通过 bt_mesh_cfg_srv.gatt_proxy 设置。

启用了代理功能的节点可以使用网络标识（Network Identity）和节点标识（Node Identity）进行广播，这由 配置客户端 控制。

GATT 代理状态表示是否支持代理功能。

私有代理

同时支持代理功能和 私有信标服务器 模型的节点可以使用私有网络标识（Private Network Identity）和私有节点标识（Private Node Identity）类型进行广播，这由 私有信标客户端 控制。通过使用这组标识类型进行广播，节点允许传统设备通过 GATT 连接到网络，同时保护网络的隐私。

私有 GATT 代理状态表示是否支持私有代理功能。

代理征求

如果某个节点上的 GATT 代理状态和私有 GATT 代理状态都被禁用，传统设备将无法连接到该节点。不过，对于支持 按需私有代理服务器 的节点，可以在不启用私有 GATT 代理状态的情况下，通过征求（solicit）使其发送可连接的广播事件。要征求节点，传统设备可以调用 bt_mesh_proxy_solicit() 函数发送一个征求 PDU。要启用此功能，编译设备时必须设置 CONFIG_BT_MESH_PROXY_SOLICITATION 选项。

征求 PDU 是非 Mesh、不可连接、无定向的广播消息，其中包含代理征求（Proxy Solicitation）UUID，并使用传统设备想要连接的子网的网络密钥（NetKey）加密。该 PDU 包含传统设备的源地址和一个序列号。序列号由传统设备维护，每发送一个新的征求 PDU 就递增一次。

每个支持接收征求 PDU 的节点都维护自己的征求重放保护列表（SRPL）。SRPL 通过存储节点已处理的有效征求 PDU 的征求序列号（SSEQ）和征求源（SSRC）对，保护征求机制免受重放攻击。从更新 SRPL 到将变更存入持久化存储之间的延迟由 CONFIG_BT_MESH_RPL_STORE_TIMEOUT 定义。

征求 PDU RPL 配置模型，即 征求 PDU RPL 配置客户端 和 征求 PDU RPL 配置服务器，提供保存和清除 SRPL 条目的功能。支持征求 PDU RPL 配置客户端模型的节点可以调用 bt_mesh_sol_pdu_rpl_clear() 函数清除目标节点上 SRPL 的一部分。征求 PDU RPL 配置客户端与服务器之间的通信使用应用密钥（AppKey）加密，因此征求 PDU RPL 配置客户端可以在网络中的任何设备上实例化。

节点收到征求 PDU 并成功完成认证后，将开始以私有网络标识类型发送可连接广播。广播的持续时间可以由按需私有代理客户端模型配置。
