分段与重组（SAR）

分段与重组（SAR）提供了一种在 Mesh 网络中处理较大的上层传输层消息的方法，目的是提高 Bluetooth Mesh 的吞吐量。分段与重组机制由下层传输层使用。

下层传输层定义了如何将上层传输层 PDU 分段并重组为多个下层传输 PDU（Lower Transport PDU），并将它们发送到对端设备的下层传输层。如果上层传输 PDU（Upper Transport PDU）能够放入单个下层传输 PDU，则以单个下层传输 PDU 发送。对于无法放入单个下层传输 PDU 的较长数据包，下层传输层会进行分段，将上层传输 PDU 拆分为多个分段。

接收设备上的下层传输层会将各分段重组为单个上层传输 PDU，然后再将其向上传递给协议栈。分段消息的送达会由接收节点的下层传输层进行确认，而未分段消息的送达则不会被确认。不过，当需要下层传输层进行确认时，能够放入一个下层传输 PDU 的上层传输 PDU 也可以作为单分段的分段消息发送。设置 send rel 标志（参见 bt_mesh_msg_ctx）即可使用可靠消息传输，并对单分段的分段消息进行确认。

传输层借助其 SAR 机制最多可以传输 32 个分段，消息（PDU）最大为 384 个八位组（octet）。要为 Bluetooth Mesh 协议栈配置消息大小，请使用以下 Kconfig 选项：

  • CONFIG_BT_MESH_RX_SEG_MAX：设置传入消息中的最大分段数。

  • CONFIG_BT_MESH_TX_SEG_MAX：设置传出消息中的最大分段数。

Kconfig 选项 CONFIG_BT_MESH_TX_SEG_MSG_COUNT 和 CONFIG_BT_MESH_RX_SEG_MSG_COUNT 定义了可以同时处理多少条传出和传入的分段消息。当有多条分段消息发往同一目的地时，这些消息会被排队并逐条发送。

传入和传出的分段消息共用同一个池来分配其分段。该池的大小通过 CONFIG_BT_MESH_SEG_BUFS Kconfig 选项配置。传入和传出消息都在事务开始时分配分段。传出的分段消息在每个分段被接收方确认后就逐个释放该分段，而传入消息要等到整条消息接收完毕后才释放分段。定义缓冲区大小时请注意这一点。

SAR 不会给每个分段的访问层负载带来额外开销。

分段与重组（SAR）配置模型

从 Bluetooth Mesh 协议规范 1.1 版开始，可以使用 SAR 配置模型通过 Mesh 网络配置 SAR 行为，例如间隔、定时器和重传计数器：

  • SAR 配置客户端

  • SAR 配置服务器

无论节点上是否存在 SAR 配置服务器，以下 SAR 行为都适用。

各分段的发送之间间隔一个分段发送间隔（参见 SAR Segment Interval Step 状态）。分段与重组可用的其他可配置时间间隔和延迟有：

  • 单播重传之间的间隔（参见 SAR Unicast Retransmissions Interval Step 和 SAR Unicast Retransmissions Interval Increment 状态）。

  • 多播重传之间的间隔（参见 SAR Multicast Retransmissions Interval Step 状态）。

  • 分段接收间隔（参见 SAR Receiver Segment Interval Step 状态）。

  • 确认延迟增量（参见 SAR Acknowledgment Delay Increment 状态）。

当最后一个被标记为未确认的分段发送完毕后，下层传输层会启动一个重传定时器。SAR 单播重传定时器的初始值取决于消息 TTL 字段的值。如果 TTL 字段的值大于 0，定时器的初始值按以下公式设置：

\[unicast~retransmissions~interval~step + unicast~retransmissions~interval~increment \times (TTL - 1)\]

如果 TTL 字段的值为 0，定时器的初始值设置为单播重传间隔步长。

SAR 多播重传定时器的初始值设置为多播重传间隔。

当下层传输层收到一个消息分段时，会启动一个 SAR 丢弃定时器。丢弃定时器表示下层传输层在丢弃该分段所属的分段消息之前要等待多长时间。SAR 丢弃定时器的初始值是 SAR Discard Timeout 状态所指示的丢弃超时值。

SAR 确认定时器保存的是为某个已接收分段发送分段确认（Segment Acknowledgment）消息之前的时间。SAR 确认定时器的初始值按以下公式计算：

\[min(SegN + 0.5 , acknowledgment~delay~increment) \times segment~reception~interval\]

SegN 字段的值表示上层传输 PDU 被分成的分段总数。

与 SAR 行为相关的计数器有四个：

  • 两个单播重传计数（参见 SAR Unicast Retransmissions Count 状态和 SAR Unicast Retransmissions Without Progress Count 状态）

  • 多播重传计数（参见 SAR Multicast Retransmissions Count 状态）

  • 确认重传计数（参见 SAR Acknowledgment Retransmissions Count 状态）

如果本次传输中的分段数高于 SAR Segments Threshold 状态的值，分段确认消息将按照 SAR Acknowledgment Retransmissions Count 状态的值进行重传。

SAR 状态

与分段与重组相关的状态有两种：

  • SAR 发送器（SAR Transmitter）状态

  • SAR 接收器（SAR Receiver）状态

SAR 发送器状态是一个复合状态，用于控制分段消息的发送次数和时序。它包括以下状态：

  • SAR Segment Interval Step

  • SAR Unicast Retransmissions Count

  • SAR Unicast Retransmissions Without Progress Count

  • SAR Unicast Retransmissions Interval Step

  • SAR Unicast Retransmissions Interval Increment

  • SAR Multicast Retransmissions Count

  • SAR Multicast Retransmissions Interval Step

SAR 接收器状态是一个复合状态，用于控制分段确认（Segment Acknowledgment）消息的发送次数和时序，以及分段消息重组的丢弃。它包括以下状态：

  • SAR Segments Threshold

  • SAR Discard Timeout

  • SAR Acknowledgment Delay Increment

  • SAR Acknowledgment Retransmissions Count

  • SAR Receiver Segment Interval Step

SAR Segment Interval Step

SAR 分段间隔步长（SAR Segment Interval Step）状态保存的值用于控制分段消息中各分段发送之间的间隔。该间隔以毫秒为单位。

使用 CONFIG_BT_MESH_SAR_TX_SEG_INT_STEP Kconfig 选项设置默认值。随后按以下公式计算分段发送间隔：

\[(\mathtt{CONFIG\_BT\_MESH\_SAR\_TX\_SEG\_INT\_STEP} + 1) \times 10~\text{ms}\]

SAR Unicast Retransmissions Count

SAR 单播重传计数（SAR Unicast Retransmissions Count）保存的值定义了向单播目的地发送的分段消息的最大重传次数。使用 CONFIG_BT_MESH_SAR_TX_UNICAST_RETRANS_COUNT Kconfig 选项设置此状态的默认值。

SAR Unicast Retransmissions Without Progress Count

该状态保存的值定义了在超时期间未收到确认，或收到的确认中只包含已确认过的分段时，向单播地址发送的分段消息的最大重传次数。使用 Kconfig 选项 CONFIG_BT_MESH_SAR_TX_UNICAST_RETRANS_WITHOUT_PROG_COUNT 设置最大重传次数。

SAR Unicast Retransmissions Interval Step

该状态的值控制间隔步长，该步长用于延迟向单播地址发送的分段消息中未确认分段的重传。间隔步长以毫秒为单位。

使用 CONFIG_BT_MESH_SAR_TX_UNICAST_RETRANS_INT_STEP Kconfig 选项设置默认值。随后用该值按以下公式计算间隔步长：

\[(\mathtt{CONFIG\_BT\_MESH\_SAR\_TX\_UNICAST\_RETRANS\_INT\_STEP} + 1) \times 25~\text{ms}\]

SAR Unicast Retransmissions Interval Increment

SAR 单播重传间隔增量（SAR Unicast Retransmissions Interval Increment）保存的值控制间隔增量，该增量用于延迟向单播地址发送的分段消息中未确认分段的重传。增量以毫秒为单位。

使用 Kconfig 选项 CONFIG_BT_MESH_SAR_TX_UNICAST_RETRANS_INT_INC 设置默认值。该 Kconfig 选项的值按以下公式用于计算增量：

\[(\mathtt{CONFIG\_BT\_MESH\_SAR\_TX\_UNICAST\_RETRANS\_INT\_INC} + 1) \times 25~\text{ms}\]

SAR Multicast Retransmissions Count

该状态保存的值控制向多播地址发送的分段消息的总重传次数。使用 Kconfig 选项 CONFIG_BT_MESH_SAR_TX_MULTICAST_RETRANS_COUNT 设置总重传次数。

SAR Multicast Retransmissions Interval Step

该状态保存的值控制向多播地址发送的分段消息中所有分段的重传之间的间隔。该间隔以毫秒为单位。

使用 Kconfig 选项 CONFIG_BT_MESH_SAR_TX_MULTICAST_RETRANS_INT 设置默认值，并按以下公式用该值计算间隔：

\[(\mathtt{CONFIG\_BT\_MESH\_SAR\_TX\_MULTICAST\_RETRANS\_INT} + 1) \times 25~\text{ms}\]

SAR Discard Timeout

该状态的值定义了下层传输层在收到分段消息的分段后、丢弃该分段消息之前等待的时间（以秒为单位）。使用 Kconfig 选项 CONFIG_BT_MESH_SAR_RX_DISCARD_TIMEOUT 设置默认值。丢弃超时按以下公式计算：

\[(\mathtt{CONFIG\_BT\_MESH\_SAR\_RX\_DISCARD\_TIMEOUT} + 1) \times 5~\text{seconds}\]

SAR Acknowledgment Delay Increment

该状态保存的值控制某个间隔的延迟增量，该间隔用于在收到新分段后延迟确认消息的发送。增量以分段数为单位。

使用 Kconfig 选项 CONFIG_BT_MESH_SAR_RX_ACK_DELAY_INC 设置默认值。增量值的计算结果为 \(\verb|CONFIG_BT_MESH_SAR_RX_ACK_DELAY_INC| + 1.5\)。

SAR Segments Threshold

SAR 分段阈值（SAR Segments Threshold）状态保存的值定义了一个以分段消息的分段数计的阈值，用于确认消息的重传。使用 Kconfig 选项 CONFIG_BT_MESH_SAR_RX_SEG_THRESHOLD 设置该阈值。

当分段消息的分段数高于此阈值时，协议栈会将每条确认消息额外重传若干次，次数由 CONFIG_BT_MESH_SAR_RX_ACK_RETRANS_COUNT 的值给出。

SAR Acknowledgment Retransmissions Count

SAR 确认重传计数（SAR Acknowledgment Retransmissions Count）状态控制下层传输层发送的分段确认消息的重传次数。它给出当分段消息的分段数高于 CONFIG_BT_MESH_SAR_RX_SEG_THRESHOLD 值时，协议栈额外发送的确认消息的总重传次数。

使用 Kconfig 选项 CONFIG_BT_MESH_SAR_RX_ACK_RETRANS_COUNT 设置此状态的默认值。分段确认消息的最大发送次数为 \(\verb|CONFIG_BT_MESH_SAR_RX_ACK_RETRANS_COUNT| + 1\)。

SAR Receiver Segment Interval Step

SAR 接收器分段间隔步长（SAR Receiver Segment Interval Step）定义了分段接收间隔步长，该步长用于在收到新分段后延迟确认消息的发送。该间隔以毫秒为单位。

使用 Kconfig 选项 CONFIG_BT_MESH_SAR_RX_SEG_INT_STEP 设置默认值，并按以下公式计算间隔：

\[(\mathtt{CONFIG\_BT\_MESH\_SAR\_RX\_SEG\_INT\_STEP} + 1) \times 10~\text{ms}\]
