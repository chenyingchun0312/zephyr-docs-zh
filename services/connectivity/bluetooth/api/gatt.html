通用属性配置文件（GATT）

GATT 层管理服务数据库，提供用于注册服务和声明属性的 API。

GATT 客户端向 GATT 服务器发起命令和请求，并可接收服务器发送的响应、指示（indication）和通知（notification）。它通过配置选项 CONFIG_BT_GATT_CLIENT 启用

GATT 服务器接收来自 GATT 客户端的命令和请求，并向客户端发送响应、指示和通知。

服务可以通过 bt_gatt_service_register() API 注册，该 API 接收一个 bt_gatt_service 结构体，其中提供该服务所含属性的列表。可以使用辅助宏 BT_GATT_SERVICE() 声明服务。

属性可以使用 bt_gatt_attr 结构体声明，也可以使用以下辅助宏之一声明：

BT_GATT_PRIMARY_SERVICE

声明一个首要服务（Primary Service）。

BT_GATT_SECONDARY_SERVICE

声明一个次要服务（Secondary Service）。

BT_GATT_INCLUDE_SERVICE

声明一个包含服务（Include Service）。

BT_GATT_CHARACTERISTIC

声明一个特征（Characteristic）。

BT_GATT_DESCRIPTOR

声明一个描述符（Descriptor）。

BT_GATT_ATTRIBUTE

声明一个属性（Attribute）。

BT_GATT_CCC

声明一个客户端特征配置（Client Characteristic Configuration）。

BT_GATT_CEP

声明一个特征扩展属性（Characteristic Extended Properties）。

BT_GATT_CUD

声明一个特征用户格式（Characteristic User Format）。

每个属性都包含一个描述其类型的 uuid、一个 read 回调、一个 write 回调以及一组权限。如果属性权限不允许相应的操作，读回调和写回调都可以设为 NULL。

备注

GATT 不支持 32 位 UUID。当 UUID 包含在 ATT PDU 中时，所有 32 位 UUID 都应转换为 128 位 UUID。

备注

属性的 read 和 write 回调直接在 RX 线程中调用，因此不建议在其中长时间阻塞。

属性值的变化可以通过 bt_gatt_notify() API 通知；另外还有 bt_gatt_notify_cb()，如果需要确切知道数据在空中发送完成的时刻，可以向它传入一个回调。指示由 bt_gatt_indicate() API 支持。

发现过程可以使用 bt_gatt_discover() API 发起，该 API 接收一个描述发现类型的 bt_gatt_discover_params 结构体。这些参数还起到过滤器的作用：设置 uuid 字段时只会发现匹配的属性；相反，将其设为 NULL 则会发现所有属性。

备注

不支持缓存已发现的属性。

读取过程由 bt_gatt_read() API 支持，该 API 以 bt_gatt_read_params 结构体作为参数。参数中可以设置一个或多个属性，但设置多个句柄需要启用选项 CONFIG_BT_GATT_READ_MULTIPLE

写入过程由 bt_gatt_write() API 支持，该 API 以 bt_gatt_write_params 结构体作为参数。如果写操作不需要响应，可以使用 bt_gatt_write_without_response() 或 bt_gatt_write_without_response_cb() API，后者的工作方式与 bt_gatt_notify_cb() 类似。

可以使用 bt_gatt_subscribe() API 发起对通知和指示的订阅，该 API 以 bt_gatt_subscribe_params 作为参数。支持对同一属性进行多个订阅，因此同一属性可能会触发多个 notify 回调。可以使用 bt_gatt_unsubscribe() API 移除订阅。

备注

移除订阅时，会以数据为 NULL 的方式调用 notify 回调。
