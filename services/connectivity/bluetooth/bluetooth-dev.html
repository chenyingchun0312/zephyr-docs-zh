线程安全

除非 API 函数的文档中另有说明，调用 Bluetooth API 应当是线程安全的。确保所有 API 调用都满足这一点的工作仍在持续进行，但本段正式说明了总体目标。欢迎提交推动子系统朝这一目标发展的缺陷报告和 PR（拉取请求）。

硬件环境搭建

本节介绍使用 Zephyr 构建和调试 Bluetooth 应用程序时可选的方案。你可以根据手头的硬件、自身需求以及偏好的开发方式，选择适合的环境搭建方案。

有以下 3 种可能的环境搭建方案：

  1. 嵌入式

  2. 外部控制器

    • QEMU 主机

    • native_sim 主机

  3. 使用 BabbleSim 仿真的 nRF5x

嵌入式

这种方案中，所有软件都直接运行在应用程序所面向的嵌入式平台上。所有 配置 和 构建类型 均受支持，但如果使用双芯片配置，或者 SoC 中有多个核且每个核运行不同的构建类型（例如一个运行主机，另一个运行控制器），则可能需要多次构建 Zephyr。

要使用这种方案开始开发，请按照 入门指南 操作，选择一块支持 Bluetooth 的开发板（如果使用双芯片方案则选择多块），然后 运行应用程序。

即使没有物理传输，也有办法获取主机与控制器之间的 HCI 流量。具体说明请参阅 嵌入式 HCI 跟踪。

Linux 上的主机搭配外部控制器

备注

目前仅适用于 GNU/Linux

这种方案依赖于“双芯片” 配置，由以下设备组成：

  1. 在 QEMU 模拟器或 Zephyr 的 native_sim 原生移植上运行的 仅主机 应用程序

  2. 一个控制器，可以是以下类型之一：

    • 市售的控制器

    • Zephyr 的 仅控制器 构建

    • 虚拟控制器

警告

某些外部控制器无法接受 Zephyr 默认设置的主机到控制器流控参数（Qualcomm），或者不会从控制器向主机发送任何数据（Realtek）。如果你看到类似下面的消息:

<wrn> bt_hci_core: opcode 0x0c33 status 0x12

（在启动所选示例时出现；运行示例前请确保已在 prj.conf 中启用 CONFIG_LOG），或者没有数据从控制器流向主机，则需要禁用主机到控制器的流控。为此，请在 prj.conf 中设置 CONFIG_BT_HCI_ACL_FLOW_CONTROL=n。

QEMU

你可以在 QEMU 模拟器 上运行 Zephyr 主机，并让它与物理的外部 Bluetooth 控制器交互。

有关在这种方案中构建和运行应用程序的完整说明，请参阅 在 QEMU 或 native_sim 上运行。

native_sim

备注

目前仅适用于 GNU/Linux

native_sim 目标会将你的 Zephyr 应用程序与 Zephyr 内核以及少量硬件模拟一起构建为原生 Linux 可执行文件。

该可执行文件是一个普通的 Linux 程序，可以像其他程序一样调试和插桩，并与物理或虚拟的外部控制器通信。请参阅：

  • 物理控制器：在 QEMU 或 native_sim 上运行

  • 虚拟控制器：在虚拟控制器和 native_sim 上运行

使用 BabbleSim 仿真的 nRF5x

备注

目前仅适用于 GNU/Linux

nrf52_bsim 和 nrf5340bsim 开发板是仿真目标开发板，它们模拟了 nRF52/53 SoC 的必要外设，以便开发和测试 Bluetooth LE 应用程序。这些开发板使用：

  • BabbleSim 仿真 nRF5x 调制解调器和无线电环境。

  • POSIX 架构和原生仿真器来模拟处理器，并在你的主机上原生运行。

  • nrf5x 硬件模型

与 native_sim 目标一样，构建结果是一个普通的 Linux 可执行文件。有关如何使用一个或多个设备运行仿真的更多信息，请参阅 这些开发板的文档。

使用 nrf52_bsim 时，通常进行 组合构建，但也可以在一个仿真设备中使用 HCI UART 示例之一构建控制器，在另一个仿真设备中使用 H4 驱动（而非集成控制器）构建主机。

使用 nrf5340bsim 时，可以选择将控制器和主机都构建在其网络核上；也可以让网络核只运行控制器，应用核运行主机和你的应用程序，并通过 IPC 进行 HCI 传输。

初始化

Bluetooth 子系统使用 bt_enable() 函数初始化。调用者应检查返回码中的错误，确保该函数执行成功。如果向 bt_enable() 传入函数指针，初始化将异步进行，并通过给定的函数通知完成。

Bluetooth 应用程序示例

下面展示了一个简单的 Bluetooth 信标（beacon）应用程序。该应用程序初始化 Bluetooth 子系统并启用不可连接广播，实际上充当一个 Bluetooth Low Energy 广播者（broadcaster）。

 1
 2/*
 3 * Set Advertisement data. Based on the Eddystone specification:
 4 * https://github.com/google/eddystone/blob/master/protocol-specification.md
 5 * https://github.com/google/eddystone/tree/master/eddystone-url
 6 */
 7static const struct bt_data ad[] = {
 8	BT_DATA_BYTES(BT_DATA_FLAGS, BT_LE_AD_NO_BREDR),
 9	BT_DATA_BYTES(BT_DATA_UUID16_ALL, 0xaa, 0xfe),
10	BT_DATA_BYTES(BT_DATA_SVC_DATA16,
11		      0xaa, 0xfe, /* Eddystone UUID */
12		      0x10, /* Eddystone-URL frame type */
13		      0x00, /* Calibrated Tx power at 0m */
14		      0x00, /* URL Scheme Prefix http://www. */
15		      'z', 'e', 'p', 'h', 'y', 'r',
16		      'p', 'r', 'o', 'j', 'e', 'c', 't',
17		      0x08) /* .org */
18};
19
20/* Set Scan Response data */
21static const struct bt_data sd[] = {
22	BT_DATA(BT_DATA_NAME_COMPLETE, DEVICE_NAME, DEVICE_NAME_LEN),
23};
24
25static void bt_ready(int err)
26{
27	bt_addr_le_t addr = {0};
28	size_t count = 1;
29
30	if (err) {
31		printk("Bluetooth init failed (err %d)\n", err);
32		return;
33	}
34
35	printk("Bluetooth initialized\n");
36
37	/* Start advertising */
38	err = bt_le_adv_start(BT_LE_ADV_NCONN_IDENTITY, ad, ARRAY_SIZE(ad),
39			      sd, ARRAY_SIZE(sd));
40	if (err) {
41		printk("Advertising failed to start (err %d)\n", err);
42		return;
43	}
44
45
46	/* For connectable advertising you would use
47	 * bt_le_oob_get_local().  For non-connectable non-identity
48	 * advertising an non-resolvable private address is used;
49	 * there is no API to retrieve that.
50	 */
51
52	bt_id_get(&addr, &count);
53
54	printk("Beacon started, advertising as %s\n", bt_addr_le_str(&addr));
55}
56
57int main(void)
58{
59	int err;
60
61	printk("Starting Beacon Demo\n");
62
63	/* Initialize the Bluetooth Subsystem */
64	err = bt_enable(bt_ready);
65	if (err) {
66		printk("Bluetooth init failed (err %d)\n", err);
67	}
68	return 0;
69}

该信标示例使用的关键 API 是用于初始化 Bluetooth 的 bt_enable()，以及用于开始广播特定广播数据和扫描响应数据组合的 bt_le_adv_start()。
