空中升级（OTA）

概述

空中升级（Over-the-Air，OTA）是一种通过网络连接向远程设备分发固件更新的方法。虽然名称暗示使用无线连接，但通过有线连接（例如以太网）接收的更新通常也称为 OTA 更新。这种方式需要服务器基础设施来托管固件二进制文件，并实现一种在有可用更新时发出通知的方法。安全性是 OTA 更新需要关注的问题；固件二进制文件在升级之前应经过加密签名和验证。

设备固件升级 一节讨论了使用 MCUboot 升级 Zephyr 固件。同样的方法也可以用于 OTA。先将二进制文件下载到一个空闲的代码分区（通常名为 slot1_partition），然后通过 MCUboot 流程进行升级。

OTA 示例

Golioth

Golioth 是一个包含 OTA 更新功能的物联网管理平台。设备被配置为监视 Golioth Cloud 上可用的固件版本。有新版本可用时，设备会下载并烧录该二进制文件。在这一实现中，云端与设备之间的连接使用 TLS/DTLS 加密保护，已签名的固件二进制文件在升级前由 MCUboot 进行确认。

  1. 可在 Golioth Firmware SDK repository 中找到一个可用的示例

  2. Golioth OTA documentation 包含有关版本管理流程的完整信息

纯 HTTP 下载

基于 HTTP 的固件空中升级 库从任意 HTTP 服务器获取已签名的镜像，将其写入次槽位（secondary slot）并请求交换。不需要管理协议或专用的更新服务器。MCUboot 会在升级前验证镜像签名。

Zephyr 的 Management 部分中包含一个 Firmware Over-the-Air over HTTP 示例。

Eclipse hawkBit™

Eclipse hawkBit™ 是一个更新服务器框架，它通过轮询 REST API 来检测固件更新。检测到新的更新时，会下载并安装二进制文件。可以使用 MCUboot 在升级固件之前验证签名。

Zephyr 的 Management 部分中包含一个 Eclipse hawkBit Direct Device Integration API 示例。

UpdateHub

UpdateHub 是一个用于远程更新嵌入式设备的平台。更新可以手动触发，也可以通过轮询进行监视。检测到新的更新时，会下载并安装二进制文件。可以使用 MCUboot 在升级固件之前验证签名。

Zephyr 的 Management 部分中包含一个 UpdateHub embedded Firmware Over-The-Air (FOTA) update 示例。

SMP 服务器

简单管理协议（Simple Management Protocol，SMP）服务器可用于通过低功耗蓝牙（LE）或 UDP 更新固件。MCUmgr 用于将已签名的固件二进制文件发送到远程设备，并在升级前由 MCUboot 进行验证。

Zephyr 的 Management 部分中包含一个 SMP server 示例。

轻量级 M2M（LwM2M）

轻量级 M2M（LwM2M） 协议通过 CONFIG_LWM2M_FIRMWARE_UPDATE_OBJ_SUPPORT 支持固件更新。设备使用 DTLS 安全地连接到 LwM2M 服务器。提供了一个 LwM2M client 示例，但它没有演示固件更新功能。

mender-mcu

mender-mcu 通过与 Zephyr 集成，在资源受限的设备上实现可靠的固件更新。它实现了一个 Update Module 接口，并提供一个默认的 Update Module，该模块与 MCUboot 集成以提供 A/B 更新。这使得微控制器单元（MCU）能够执行原子性的、故障安全的 OTA 更新，并在失败时自动回滚。

有关集成细节和示例，请参阅 mender-mcu。

Memfault 以及由 Memfault 提供支持的 nRF Cloud

Memfault 是一个包含 OTA 管理功能的物联网可观测性平台。设备定期向 Memfault 的服务签到以检查 OTA 更新，有可用更新时，下载并安装该二进制文件。

有关整体集成细节和示例，请参阅 memfault-firmware-sdk。
