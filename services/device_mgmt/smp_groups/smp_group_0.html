1

3

5

回显命令

回显命令通过发回收到的字符串作为响应。

回显请求

回显请求头部字段：

OP

Group ID

Command ID

0 或 2

0

0

请求的 CBOR 数据：

{
    (str)"d" : (str)
}

其中：

"d"

由回显服务回复的字符串。

回显响应

回显响应头部字段：

OP

Group ID

Command ID

说明

1

0

0

当请求的 OP 为 0 时

3

0

0

当请求的 OP 为 2 时

成功响应的 CBOR 数据：

{
    (str)"r"        : (str)
}

出错时，CBOR 数据采用以下形式：

{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

{
    (str)"rc"       : (int)
}

其中：

"r"

回复的回显字符串。

"err" -> "group"

基于组的错误码所属的 mcumgr_group_t 组。仅在使用 SMP 版本 2 且返回错误时出现。

"err" -> "rc"

包含基于组的错误码的索引。仅在使用 SMP 版本 2 且该值非零（出错）时出现。

"rc"

mcumgr_err_t，仅在使用 SMP 版本 1 且该值非零（出错）时，或在使用 SMP 版本 2 时出现 SMP 错误的情况下出现。

任务统计信息响应头部字段：

OP

Group ID

Command ID

1

0

2

成功响应的 CBOR 数据：

{
    (str)"tasks" : {
        (str)<task_name> : {
            (str)"prio"         : (uint)
            (str)"tid"          : (uint)
            (str)"state"        : (uint)
            (str)"stkuse"       : (uint)
            (str)"stksiz"       : (uint)

出错时，CBOR 数据采用以下形式：

        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

    (str)"rc"       : (int)
}

其中：

<task_name>

标识任务的字符串。

"prio"

任务优先级。

"tid"

数字形式的任务 ID。

"state"

数字形式的任务状态。

"stkuse"

任务/线程的栈使用量。

"stksiz"

任务/线程的栈大小。

"cswcnt"

任务/线程的上下文切换次数。

"runtime"

任务/线程以“节拍”（tick）为单位的运行时间。

"last_checkin"

Zephyr 将其设为 0。

"next_checkin"

Zephyr 将其设为 0。

"err" -> "group"

基于组的错误码所属的 mcumgr_group_t 组。仅在使用 SMP 版本 2 且返回错误时出现。

"err" -> "rc"

包含基于组的错误码的索引。仅在使用 SMP 版本 2 且该值非零（出错）时出现。

"rc"

mcumgr_err_t，仅在使用 SMP 版本 1 且该值非零（出错）时，或在使用 SMP 版本 2 时出现 SMP 错误的情况下出现。

备注

"stkuse" 和 "stksiz" 的单位取决于系统，在 Zephyr 中是 4 字节字的数量。

系统复位

执行系统复位。设备应在复位之前发出响应，以便 SMP 客户端能够得知该命令已被接受。默认情况下，该命令在任何情况下都会被接受；但如果启用了 CONFIG_MCUMGR_GRP_OS_RESET_HOOK 并且应用程序注册了回调，则在发出该命令时会调用该回调，可以借此在模块重启之前执行必要的清理操作，或者直接以错误响应拒绝复位请求。有关此功能的详细信息，请参阅 MCUmgr 回调。

系统复位请求

系统复位请求头部字段：

OP

Group ID

Command ID

2

0

5

通常该命令发送一个空的 CBOR 映射作为数据；但如果之前的复位尝试以等于 MGMT_ERR_EBUSY 的 "rc" 作为响应，则可以发送以下映射来强制复位：

{
    (opt)"force"       : (int)
    (opt)"boot_mode"   : (uint)
}

其中：

"force"

如果值 > 0，则强制复位；值为 0 时可省略。

"boot_mode"

为镜像或应用程序模式/选择指定启动模式，需要启用 CONFIG_MCUMGR_GRP_OS_RESET_BOOT_MODE。

操作系统/应用程序信息

用于获取正在运行镜像的信息，功能类似于 Linux 的 uname 命令，可以返回内核名称、内核版本、构建日期/时间、处理器类型以及应用程序定义的详细信息等。可以通过 CONFIG_MCUMGR_GRP_OS_INFO 启用此功能。

操作系统/应用程序信息请求

操作系统/应用程序信息请求头部字段：

OP

Group ID

Command ID

0

0

7

请求的 CBOR 数据：

{
    (str,opt)"format"      : (str)
}

其中：

"format"

返回响应的格式说明符，各字段按其自然的升序索引顺序追加，而不是按命令收到的字符顺序。格式说明符：
* s 内核名称
* n 节点名称
* r 内核发行版本
* v 内核版本
* b 构建日期和时间（需要 CONFIG_MCUMGR_GRP_OS_INFO_BUILD_DATE_TIME）
* m 机器
* p 处理器
* i 硬件平台
* o 操作系统
* a 所有字段（以上所有选项的简写）
如果未提供此选项，则使用 s 内核名称选项。

引导加载程序信息：MCUboot

当 MCUboot 是应用程序的引导加载程序时，对空请求的响应为：

{
    (str)"bootloader"      : (str)"MCUboot"
}

目前 "MCUboot" 支持查询工作模式：

{
    (str)"query"           : (str)"mode"
}

对 "mode" 的响应为：

{
    (str)"mode"                     : (int)
    (str,opt)"no-downgrade"         : (bool)
}

其中 "mode" 为以下值之一：

-1

MCUboot 模式未知。

0

MCUboot 处于单应用程序模式。

1

MCUboot 处于使用暂存分区的交换（swap using scratch）模式。

2

MCUboot 处于覆盖（仅升级）模式。

3

MCUboot 处于不使用暂存分区的交换模式。

4

MCUboot 处于不带回退的 DirectXIP 模式。

5

MCUboot 处于带回退的 DirectXIP 模式。

6

MCUboot 处于 RAM 加载器模式。

no-downgrade 字段是一个标志，为 true 时总会发送，表示 MCUboot 启用了降级防护；降级防护是指，如果上传的镜像版本低于当前运行的应用程序，MCUboot 将不会使用它进行更新。

在这种配置下，MCUmgr 可能会拒绝版本较低的镜像。
