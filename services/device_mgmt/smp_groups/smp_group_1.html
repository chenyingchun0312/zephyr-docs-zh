槽位信息

Zephyr 中“槽位”（slot）与“镜像”（image）的概念

“槽位”和“镜像”的定义来自 mcuboot：一个“镜像”由两个“槽位”组成，分别称为“主”（primary）槽位和“次”（secondary）槽位；应用程序应从“主槽位”运行，更新应上传到“次槽位”；mcuboot 负责在启动时交换槽位。这意味着一对槽位专用于一个可升级的应用程序。在 Zephyr 中这有点令人困惑，因为 DTS 会使用 "slot0_partition" 和 "slot1_partition" 作为专用于单个应用程序的 fixed-partitions 或 zephyr,mapped-partition 的标签，却又分别将它们命名为 "image-0" 和 "image-1"。

目前 Zephyr 最多支持两个镜像，此时的映射关系如下：

镜像

槽位标签

槽位名称

1

"slot0_partition" "slot1_partition"

"image-0" "image-1"

2

"slot2_partition" "slot3_partition"

"image-2" "image-3"

备注

下面的响应定义中包含一个标记为可选（opt）的 "image" 字段：当目标应用程序不支持多个镜像时，响应中可能不出现该字段。当应用程序支持多个应用程序镜像时，该字段是必需的，以便识别所列出的是哪个镜像的信息。

响应只包含有效镜像的信息，如果某个镜像无法被识别为有效，就直接跳过。

成功响应的 CBOR 数据：

{
    (str)"images" : [
        {
            (str,opt)"image"        : (uint)
            (str)"slot"             : (uint)
            (str)"version"          : (str)
            (str,opt*)"hash"        : (byte str)
            (str,opt)"bootable"     : (bool)
            (str,opt)"pending"      : (bool)
            (str,opt)"confirmed"    : (bool)
            (str,opt)"active"       : (bool)
            (str,opt)"permanent"    : (bool)
        }
        ...
    ]
    (str,opt)"splitStatus" : (int)
}

出错时，CBOR 数据采用以下形式：

{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

{
    (str)"rc"       : (int)
    (str,opt)"rsn"  : (str)
}

其中：

"image"

半可选的镜像编号；当运行中的应用程序只支持一个镜像时，不需要该字段。

"slot"

"image" 内的槽位编号；每个镜像有两个槽位：主槽位（正在运行的槽位）= 0，次槽位（用于 DFU 双 bank 用途）= 1。

"version"

表示镜像版本的字符串，由 imgtool 设置。

"hash"

镜像头部和镜像体的 SHA256 哈希值。注意，它与整个文件的 SHA256 不同，而是 MCUboot TLV 区中包含数据哈希值的字段，用于签名验证。该字段是可选的，但仅在使用 MCUboot 串口恢复功能且只有一对镜像槽位时才是可选的；在这种配置下，可以禁用 Kconfig 选项 CONFIG_BOOT_SERIAL_IMG_GRP_HASH 来移除对哈希值的支持。应用程序中的 MCUmgr 必须支持发送哈希值。

备注

请参阅下文链接的 MCUboot 镜像格式文档中的 IMAGE_TLV_SHA256。

"bootable"

如果镜像设置了可启动标志，则为 true；为 false 时可以不出现该字段。

"pending"

如果镜像被设置为在下次交换时使用，则为 true；为 false 时可以不出现该字段。

"confirmed"

如果镜像已被确认，则为 true；为 false 时可以不出现该字段。

"active"

如果镜像是当前活动的应用程序，则为 true；为 false 时可以不出现该字段。

"permanent"

如果镜像在下次启动后将保留在主槽位中，则为 true；为 false 时可以不出现该字段。

"splitStatus"

表示拆分镜像的加载器是否与应用程序部分兼容；Zephyr 未使用该字段。

"err" -> "group"

基于组的错误码所属的 mcumgr_group_t 组。仅在使用 SMP 版本 2 且返回错误时出现。

"err" -> "rc"

包含基于组的错误码的索引。仅在使用 SMP 版本 2 且该值非零（出错）时出现。

"rc"

mcumgr_err_t，仅在使用 SMP 版本 1 且该值非零（出错）时，或在使用 SMP 版本 2 时出现 SMP 错误的情况下出现。

"rsn"

可选字符串，用于说明出错原因；当 rc 为 MGMT_ERR_EUNKNOWN 时尤其有用。

备注

有关镜像/槽位工作方式的更多信息，请参阅 MCUBoot 文档 https://docs.mcuboot.com/design.html#image-slots 。有关 MCUboot 镜像格式的信息，请参阅 MCUboot 文档 https://docs.mcuboot.com/design.html#image-format

请求的 CBOR 数据：

{
    (str,opt)"hash"     : (byte str)
    (str)"confirm"      : (bool)
}

如果 "confirm" 为 false 或未提供，则具有该 "hash" 的镜像将被设置为测试状态，即不会被标记为永久，硬复位后将把先前的应用程序恢复到主槽位。当 "confirm" 为 true 时，"hash" 是可选的，因为会假定当前运行的应用程序就是确认的目标。

镜像上传

镜像上传命令用于更新应用程序镜像。

镜像上传请求

所上传镜像的每个数据块都会发送一个镜像上传请求，直到完整的镜像上传到设备为止。

镜像上传请求头部字段：

OP

Group ID

Command ID

2

1

1

请求的 CBOR 数据：

{
    (str,opt)"image"    : (uint)
    (str,opt)"len"      : (uint)
    (str)"off"          : (uint)
    (str,opt)"sha"      : (byte str)
    (str)"data"         : (byte str)
    (str,opt)"upgrade"  : (bool)
}

其中：

"image"

可选的镜像编号，可以完全不出现在请求中，此时假定为 0。仅当 "off" 为 0 时才应出现。

"len"

可选的镜像长度。当 "off" 为 0 时必须出现。

"off"

请求所携带镜像数据块的偏移量。

"sha"

上传内容的 SHA256 哈希值；用于标识一个上传会话（例如使 MCUmgr 能够继续中断的会话），以及用于镜像验证。它必须是所上传整个镜像的完整 SHA256 哈希值；如果无法获得哈希值，则不包含该字段（此时上传会话续传和镜像验证功能将不可用）。仅当 "off" 为 0 时才应出现。

"data"

要写入到所提供偏移量处的镜像数据。

"upgrade"

可选标志，表示只允许升级，因此如果上传软件的版本不高于设备上已有的版本，镜像上传将被拒绝。Zephyr 默认比较主版本号、次版本号和修订号（x.y.z），如果设置了 CONFIG_MCUMGR_GRP_IMG_VERSION_CMP_USE_BUILD_NUMBER，还会比较构建号。仅当 "off" 为 0 时才应出现。

备注

没有表示 "data" 所携带数据块大小的字段，因为该信息已嵌入在 "data" 字段本身之中。

备注

服务器可能会以 "off" 为 0 响应一次上传，这种情况可能发生在另一个传输上（或完全在 MCUmgr 之外）开始了上传、设备已重启或数据包丢失时。发生这种情况时，客户端必须重新发送它在最初第一个数据包中发送的所有必需字段和可选字段，以便服务器重建上传状态。如果不包含这些原始字段，上传将无法继续。

MCUmgr 库使用 "sha" 字段标记正在进行的更新会话，以便在会话中断时能够继续，同时也用于上传验证。如果库收到 "off" 等于零的请求，它会检查其状态中存储的 "sha"，如果匹配，就会向更新客户端应用程序回复其应继续的偏移量。如果无法获得该哈希值（例如因为文件是以流的方式传输的），则不得提供该字段，此时镜像验证和上传会话续传功能将不可用。
