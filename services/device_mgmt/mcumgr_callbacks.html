MCUmgr 回调

概述

MCUmgr 有一套可定制的回调/通知系统，允许应用程序（和模块）代码接收其关心的 MCUmgr 事件的回调，并对其作出响应，或者向调用函数返回一个状态码，从而控制是否允许该操作。fs_mgmt 组就是一个例子：可以对文件访问进行把关，回调使应用程序能够检查请求的路径，允许或拒绝对该文件的访问，也可以将提供的路径改写为另一个路径，以支持透明的文件重定向。

实现

启用

可以使用 CONFIG_MCUMGR_MGMT_NOTIFICATION_HOOKS 启用基础的回调/通知系统，它会将注册和通知系统编译进代码中。默认情况下这不会提供任何回调，因为构建所支持的回调还必须通过启用所需回调对应的 Kconfig 选项来选择（详情请参阅 事件）。然后，可以声明一个类型定义为 mgmt_cb 的回调函数，将其放入 mgmt_callback 结构体中，并调用 mgmt_callback_register() 为所需事件注册。处理程序按注册顺序被调用。

启用该系统后，可以在应用程序代码中按如下方式设置和定义一个基本的处理程序：

#include <zephyr/kernel.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>

struct mgmt_callback my_callback;

enum mgmt_cb_return my_function(uint32_t event, enum mgmt_cb_return prev_status,
                                int32_t *rc, uint16_t *group, bool *abort_more,
                                void *data, size_t data_size)
{
    if (event == MGMT_EVT_OP_CMD_DONE) {
        /* This is the event we registered for */
    }

    /* Return OK status code to continue with acceptance to underlying handler */
    return MGMT_CB_OK;
}

int main()
{
    my_callback.callback = my_function;
    my_callback.event_id = MGMT_EVT_OP_CMD_DONE;
    mgmt_callback_register(&my_callback);
}

这段代码为 MGMT_EVT_OP_CMD_DONE 事件注册了一个处理程序，该处理程序会在 MCUmgr 命令处理完毕并生成输出之后被调用。注意，要接收此回调，需要启用 CONFIG_MCUMGR_SMP_COMMAND_STATUS_HOOKS。

可以设置多个回调，让它们使用同一个函数作为公共回调；也可以通过为每个组各注册一次，为每个事件使用许多不同的函数；还可以使用某个 MGMT_EVT_OP_*_ALL 事件启用整个组的所有通知；或者使用 MGMT_EVT_OP_ALL 为所有通知设置处理程序。设置处理程序时，只能组合同一组中的事件。例如，可以通过一次注册调用设置 5 个 img_mgmt 回调，但如果还要为 os_mgmt 设置回调，则必须单独注册。之所以有这一限制，是因为组 ID 是递增的数值，而事件 ID 是位掩码值。

例如，以下注册是允许的，它在一次注册中用单个回调函数注册了 3 个 SMP 事件：

my_callback.callback = my_function;
my_callback.event_id = (MGMT_EVT_OP_CMD_RECV |
                        MGMT_EVT_OP_CMD_STATUS |
                        MGMT_EVT_OP_CMD_DONE);
mgmt_callback_register(&my_callback);

以下代码是不允许的，会导致未定义的行为，因为它将 IMG 管理组与 OS 管理组混在一起，而组不是位掩码值，只有事件才是：

my_callback.callback = my_function;
my_callback.event_id = (MGMT_EVT_OP_IMG_MGMT_DFU_STARTED |
                        MGMT_EVT_OP_OS_MGMT_RESET);
mgmt_callback_register(&my_callback);

事件

可以通过启用相应的 Kconfig 选项来选择事件：

  • CONFIG_MCUMGR_SMP_COMMAND_STATUS_HOOKS

    MCUmgr 命令状态（MGMT_EVT_OP_CMD_RECV、MGMT_EVT_OP_CMD_STATUS、MGMT_EVT_OP_CMD_DONE）

  • CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK

    fs_mgmt 文件访问（MGMT_EVT_OP_FS_MGMT_FILE_ACCESS）

  • CONFIG_MCUMGR_GRP_IMG_UPLOAD_CHECK_HOOK

    img_mgmt 上传检查（MGMT_EVT_OP_IMG_MGMT_DFU_CHUNK）

  • CONFIG_MCUMGR_GRP_IMG_STATUS_HOOKS

    img_mgmt 上传状态（MGMT_EVT_OP_IMG_MGMT_DFU_STOPPED、MGMT_EVT_OP_IMG_MGMT_DFU_STARTED、MGMT_EVT_OP_IMG_MGMT_DFU_PENDING、MGMT_EVT_OP_IMG_MGMT_DFU_CONFIRMED）

  • CONFIG_MCUMGR_GRP_OS_RESET_HOOK

    os_mgmt 复位检查（MGMT_EVT_OP_OS_MGMT_RESET）

  • CONFIG_MCUMGR_GRP_SETTINGS_ACCESS_HOOK

    settings_mgmt 访问（MGMT_EVT_OP_SETTINGS_MGMT_ACCESS）

动作

有些回调需要返回一个状态，以允许或禁止某项操作，例如 fs_mgmt 访问钩子可以允许或拒绝对文件的访问。对于这类处理程序，第一个由处理程序返回的非 OK 错误码会被返回给 MCUmgr 客户端。

选择性拒绝文件访问的示例：

#include <zephyr/kernel.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>
#include <string.h>

struct mgmt_callback my_callback;

enum mgmt_cb_return my_function(uint32_t event, enum mgmt_cb_return prev_status,
                                int32_t *rc, uint16_t *group, bool *abort_more,
                                void *data, size_t data_size)
{
    /* Only run this handler if a previous handler has not failed */
    if (event == MGMT_EVT_OP_FS_MGMT_FILE_ACCESS && prev_status == MGMT_CB_OK) {
        struct fs_mgmt_file_access *fs_data = (struct fs_mgmt_file_access *)data;

        /* Check if this is an upload and deny access if it is, otherwise check
         * the path and deny if is matches a name
         */
        if (fs_data->access == FS_MGMT_FILE_ACCESS_WRITE) {
            /* Return an access denied error code to the client and abort calling
             * further handlers
             */
            *abort_more = true;
            *rc = MGMT_ERR_EACCESSDENIED;

            return MGMT_CB_ERROR_RC;
        } else if (strcmp(fs_data->filename, "/lfs1/false_deny.txt") == 0) {
            /* Return a no entry error code to the client, call additional handlers
             * (which will have failed set to true)
             */
            *rc = MGMT_ERR_ENOENT;

            return MGMT_CB_ERROR_RC;
        }
    }

    /* Return OK status code to continue with acceptance to underlying handler */
    return MGMT_CB_OK;
}

int main()
{
    my_callback.callback = my_function;
    my_callback.event_id = MGMT_EVT_OP_FS_MGMT_FILE_ACCESS;
    mgmt_callback_register(&my_callback);
}

这段代码为 MGMT_EVT_OP_FS_MGMT_FILE_ACCESS 事件注册了一个处理程序，该处理程序会在收到 fs_mgmt 文件读/写命令之后被调用，以检查是否应允许访问该文件。注意，要接收此回调，需要启用 CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK。可以返回两种类型的错误：一种是将 rc 参数设置为 mcumgr_err_t 错误码并返回 MGMT_CB_ERROR_RC；另一种是设置组错误码（随 MCUmgr 协议版本 2 引入），即将 group 值设置为该组、将 rc 值设置为组错误码，并返回 MGMT_CB_ERROR_ERR。

MCUmgr 命令回调用法/添加新的事件类型

要为 MCUmgr 命令添加回调，可以用事件 ID 调用 mgmt_callback_notify()，并可选地传入一个要传给回调的数据结构体（处理程序可以修改它）。如果不需要回传数据，可以改用 NULL，并将数据大小设为 0。

MCUmgr 命令处理程序示例：

#include <zephyr/kernel.h>
#include <zcbor_common.h>
#include <zcbor_encode.h>
#include <zephyr/mgmt/mcumgr/smp/smp.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>

#define MGMT_EVT_GRP_USER_ONE MGMT_EVT_GRP_USER_CUSTOM_START

enum user_one_group_events {
    /** Callback on first post, data is test_struct. */
    MGMT_EVT_OP_USER_ONE_FIRST  = MGMT_DEF_EVT_OP_ID(MGMT_EVT_GRP_USER_ONE, 0),

    /** Callback on second post, data is test_struct. */
    MGMT_EVT_OP_USER_ONE_SECOND = MGMT_DEF_EVT_OP_ID(MGMT_EVT_GRP_USER_ONE, 1),

    /** Used to enable all user_one events. */
    MGMT_EVT_OP_USER_ONE_ALL    = MGMT_DEF_EVT_OP_ALL(MGMT_EVT_GRP_USER_ONE),
};

struct test_struct {
    uint8_t some_value;
};

static int test_command(struct mgmt_ctxt *ctxt)
{
    int rc;
    int err_rc;
    uint16_t err_group;
    zcbor_state_t *zse = ctxt->cnbe->zs;
    bool ok;
    struct test_struct test_data = {
        .some_value = 8,
    };

    rc = mgmt_callback_notify(MGMT_EVT_OP_USER_ONE_FIRST, &test_data,
                              sizeof(test_data), &err_rc, &err_group);

    if (rc != MGMT_CB_OK) {
        /* A handler returned a failure code */
        if (rc == MGMT_CB_ERROR_RC) {
            /* The failure code is the RC value */
            return err_rc;
        }

        /* The failure is a group and ID error value */
        ok = smp_add_cmd_err(zse, err_group, (uint16_t)err_rc);
        goto end;
    }

    /* All handlers returned success codes */
    ok = zcbor_tstr_put_lit(zse, "output_value") &&
         zcbor_int32_put(zse, 1234);

end:
    rc = (ok ? MGMT_ERR_EOK : MGMT_ERR_EMSGSIZE);

    return rc;
}

如果回调不需要响应，可以直接调用该函数并将其返回值强制转换为 void。

迁移

如果现有代码使用的是 Zephyr 3.2 或更早版本中的旧回调系统，则需要将其迁移到新系统。迁移代码时，需要将以下回调注册函数改为使用 mgmt_callback_register() 注册回调（注意，除了进行这些迁移之外，还需要设置 CONFIG_MCUMGR_MGMT_NOTIFICATION_HOOKS 以启用新的通知系统）：

  • mgmt_evt

    使用 MGMT_EVT_OP_CMD_RECV、MGMT_EVT_OP_CMD_STATUS 或 MGMT_EVT_OP_CMD_DONE 直接替换同名事件，提供的数据为 mgmt_evt_op_cmd_arg。需要设置 CONFIG_MCUMGR_SMP_COMMAND_STATUS_HOOKS。

  • fs_mgmt_register_evt_cb

    使用 MGMT_EVT_OP_FS_MGMT_FILE_ACCESS，提供的数据为 fs_mgmt_file_access。不再通过返回 true 允许操作或返回 false 拒绝操作，而是需要返回一个 MCUmgr 结果码：MGMT_ERR_EOK 表示允许该操作，任何其他返回码都会禁止该操作并将该返回码返回给客户端（访问被拒绝的错误可以使用 MGMT_ERR_EACCESSDENIED）。需要设置 CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK。

  • img_mgmt_register_callbacks

    如果使用过 dfu_started_cb，则改用 MGMT_EVT_OP_IMG_MGMT_DFU_STARTED；如果使用过 dfu_stopped_cb，则改用 MGMT_EVT_OP_IMG_MGMT_DFU_STOPPED；如果使用过 dfu_pending_cb，则改用 MGMT_EVT_OP_IMG_MGMT_DFU_PENDING；如果使用过 dfu_confirmed_cb，则改用 MGMT_EVT_OP_IMG_MGMT_DFU_CONFIRMED。这些回调没有返回状态。需要设置 CONFIG_MCUMGR_GRP_IMG_STATUS_HOOKS。

  • img_mgmt_set_upload_cb

    使用 MGMT_EVT_OP_IMG_MGMT_DFU_CHUNK，提供的数据为 img_mgmt_upload_check。不再通过返回 true 允许操作或返回 false 拒绝操作，而是需要返回一个 MCUmgr 结果码：MGMT_ERR_EOK 表示允许该操作，任何其他返回码都会禁止该操作并将该返回码返回给客户端（访问被拒绝的错误可以使用 MGMT_ERR_EACCESSDENIED）。需要设置 CONFIG_MCUMGR_GRP_IMG_UPLOAD_CHECK_HOOK。

  • os_mgmt_register_reset_evt_cb

    使用 MGMT_EVT_OP_OS_MGMT_RESET。不再通过返回 true 允许操作或返回 false 拒绝操作，而是需要返回一个 MCUmgr 结果码：MGMT_ERR_EOK 表示允许该操作，任何其他返回码都会禁止该操作并将该返回码返回给客户端（访问被拒绝的错误可以使用 MGMT_ERR_EACCESSDENIED）。需要设置 CONFIG_MCUMGR_GRP_OS_RESET_HOOK。
