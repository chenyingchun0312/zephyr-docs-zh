SMP 协议规范

本文描述简单管理协议（Simple Management Protocol，SMP），MCUmgr 使用该协议向设备传递请求并接收设备的响应。

SMP 是一种应用层协议。底层传输层不在本文档的讨论范围之内。

备注

此处的 SMP 指 MCUmgr 的 SMP（Simple Management Protocol，简单管理协议），与蓝牙中的 SMP（Security Manager Protocol，安全管理协议）无关，不过 MCUmgr 有一个用于蓝牙的 SMP 传输。

帧：封装

每个帧由头部和数据组成。如果底层传输层支持分片，头部中的 Data Length 字段可用于重组。当字段长度超过一个字节时，帧采用“大端”（网络字节序）编码，格式如下：

备注

原始规范规定 SMP 应支持接收“小端”和“大端”两种帧，但实际上 MCUmgr 库被硬编码为始终将“网络”侧视为“大端”。

数据是可选的，当 Data Length 为零时不存在数据。数据的编码取决于组/ID 的目标。

各字段及其含义说明如下：

字段

描述

Res

保留的未使用字段，必须始终设为 0。

Ver（版本）

表示所使用的协议版本。设为 0b01 表示使用较新的 SMP 传输，其错误码更详细，并在映射（map）中返回；否则保持为 0b00，表示使用旧版 SMP 协议。版本 0b10 和 0b11 保留供将来使用，不应使用。

OP

mcumgr_op_t，决定是向设备写入信息还是向设备请求信息，以及数据包包含的是发往 SMP 服务器的请求还是来自 SMP 服务器的响应。

Flags

保留给标志使用；目前尚未定义任何标志，该字段应设为 0

Data Length

Data 字段的长度

Group ID

mcumgr_group_t，详情请参阅 管理 Group ID。

Sequence Num

帧序列号。每个请求帧的序列号加一。响应的 Sequence Num 应与请求中的相同。

Command ID

Group 内的命令。

Data

大小为 Data Length 的数据载荷。它是可选的，因为 Data Length 可以设为零，这表示头部之后没有数据。

备注

Data 的内容取决于 OP、Group ID 和 Command ID 的值。

除用户组（64 及以上）之外，上述各组的载荷始终采用 CBOR 编码。64 及以上的组可以自行定义数据通信方案。

最小响应

无论发出什么命令，只要请求的另一端存在 SMP 客户端，就应发出响应，其中包含头部，后跟一个 CBOR 映射容器。只有在没有 SMP 服务或设备无响应时，才允许不发出响应。

最小响应 SMP 数据

最小响应为：

{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

{
    (str)"rc"       : (int)
}

其中：

"err" -> "group"

基于组的错误码所属的 mcumgr_group_t 组。仅在使用 SMP 版本 2 且返回错误时出现。

"err" -> "rc"

包含基于组的错误码的索引。仅在使用 SMP 版本 2 且该值非零（出错）时出现。

"rc"

mcumgr_err_t，仅在使用 SMP 版本 1 且该值非零（出错）时，或在使用 SMP 版本 2 时出现 SMP 错误的情况下出现。

注意，命令执行成功时会返回一个空映射（只有在出错时才会返回 rc/err），因此如果只返回了空映射，或者响应中不含这些字段，就可以认为请求已成功。对于 SMP 版本 2，与 SMP 本身相关、不特定于某个组的错误仍会以 rc 错误的形式返回，因此 SMP 版本 2 客户端必须能够处理这两种类型的错误。
