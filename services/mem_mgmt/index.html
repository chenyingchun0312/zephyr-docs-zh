内存属性

在设备树中，可以使用 zephyr,memory-attr 属性为内存区域标记属性。之后可以借助提供的辅助库，在运行时获取该属性及相关的内存区域。

可在该属性中指定的通用属性集合，其定义和说明见 include/zephyr/dt-bindings/memory-attr/memory-attr.h。

例如，要在设备树中将某个内存区域标记为非易失、可缓存、乱序：

mem: memory@10000000 {
    compatible = "mmio-sram";
    reg = <0x10000000 0x1000>;
    zephyr,memory-attr = <(DT_MEM_NON_VOLATILE | DT_MEM_CACHEABLE | DT_MEM_OOO)>;
};

备注

使用 zephyr,memory-attr 并不会真正创建任何内存区域。如果需要根据设备树中定义的内存区域创建实际的段，可以使用兼容属性 zephyr,memory-region，它会（仅在架构支持时）生成一个新的链接器段和区域。

zephyr,memory-attr 属性还可用于设置架构特定和软件特定的自定义属性，以便在运行时解释。这一点的用途之一是根据设备树中定义的内存区域创建 MPU 区域，例如：

mem: memory@10000000 {
    compatible = "mmio-sram";
    reg = <0x10000000 0x1000>;
    zephyr,memory-region = "NOCACHE_REGION";
    zephyr,memory-attr = <DT_MEM_ARM_MPU_RAM_NOCACHE>;
};

有关 MPU 用法的更多细节，请参阅 include/zephyr/dt-bindings/memory-attr/memory-attr-arm.h 以及 Arm Cortex-M 开发者指南 中的 内存映射和 MPU 注意事项。有关 Zephyr 如何处理缓存，另请参阅 缓存基础。

处理和管理带属性标记的内存区域的常规且推荐的方式，是启用 CONFIG_MEM_ATTR 来使用提供的 mem-attr 辅助库。启用此选项后，内存区域及其属性的列表会被编译进一个用户可访问的数组，并提供一组函数，用于查询、探测内存区域和属性并据此进行操作（详见下一节）。

备注

zephyr,memory-attr 属性只是对相关内存区域能力的描述，并不会对内存进行任何实际设置。希望利用这些信息完成某些工作（例如根据该属性创建 MPU 区域）的用户、代码或子系统，必须使用提供的 mem-attr 库或常规的设备树辅助工具来执行所需的工作或设置。但请注意，在某些架构（如 ARM 和 ARM64）上，MPU 驱动会利用这些信息在启动时正确初始化缓存。参见 CONFIG_ARM_MPU、CONFIG_RISCV_PMP 等。

tests/subsys/mem_mgmt/mem_attr/ 中提供了 mem-attr 库及其用法的测试。

内存属性堆分配器

可以利用内存属性 zephyr,memory-attr 定义并创建一组内存堆，用户可以从中分配具有特定属性或能力的内存。

设置 CONFIG_MEM_ATTR_HEAP 后，凡是标记了 include/zephyr/dt-bindings/memory-attr/memory-attr-sw.h 中所列某个内存属性的区域，都会被加入一个内存堆池，用于动态分配具有特定属性的内存缓冲区。

以下是部分可用属性（并非完整列表）：

DT_MEM_SW_ALLOC_CACHE
DT_MEM_SW_ALLOC_NON_CACHE
DT_MEM_SW_ALLOC_DMA

例如，可以定义多个具有不同属性的内存区域，并使用相应的属性表明可以从这些区域动态分配内存：

mem_cacheable: memory@10000000 {
    compatible = "mmio-sram";
    reg = <0x10000000 0x1000>;
    zephyr,memory-attr = <(DT_MEM_CACHEABLE | DT_MEM_SW_ALLOC_CACHE)>;
};

mem_non_cacheable: memory@20000000 {
    compatible = "mmio-sram";
    reg = <0x20000000 0x1000>;
    zephyr,memory-attr = <(DT_MEM_NON_CACHEABLE | ATTR_SW_ALLOC_NON_CACHE)>;
};

mem_cacheable_big: memory@30000000 {
    compatible = "mmio-sram";
    reg = <0x30000000 0x10000>;
    zephyr,memory-attr = <(DT_MEM_CACHEABLE | DT_MEM_OOO | DT_MEM_SW_ALLOC_CACHE)>;
};

mem_cacheable_dma: memory@40000000 {
    compatible = "mmio-sram";
    reg = <0x40000000 0x10000>;
    zephyr,memory-attr = <(DT_MEM_CACHEABLE      | DT_MEM_DMA |
                           DT_MEM_SW_ALLOC_CACHE | DT_MEM_SW_ALLOC_DMA)>;
};

然后，用户可以使用提供的函数从这些区域中动态划分内存，库会根据提供的属性和大小，从正确的堆中分配内存：

// Init the pool
mem_attr_heap_pool_init();

// Allocate 0x100 bytes of cacheable memory from `mem_cacheable`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_CACHE, 0x100);

// Allocate 0x200 bytes of non-cacheable memory aligned to 32 bytes
// from `mem_non_cacheable`
block = mem_attr_heap_aligned_alloc(ATTR_SW_ALLOC_NON_CACHE, 0x100, 32);

// Allocate 0x100 bytes of cacheable and dma-able memory from `mem_cacheable_dma`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_CACHE | DT_MEM_SW_ALLOC_DMA, 0x100);

当多个区域标记了相同的属性时，内存的分配方式如下：

  1. 从 zephyr,memory-attr 属性包含所请求属性（一个或多个）的区域中分配。

  2. 在第 1 点所述的区域中，如果最小的区域还有足够的未分配空间满足请求的大小，则从该区域分配

  3. 如果空间不足，则从下一个能够容纳所请求大小的更大区域中分配

以下示例展示了第 3 点：

// This memory is allocated from `mem_non_cacheable`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_NON_CACHE, 0x100);

// This memory is allocated from `mem_cacheable_big`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_CACHE, 0x5000);

备注

该框架假定用于创建堆的内存区域可被代码使用，并且在初始化时可用。用户必须在调用 mem_attr_heap_pool_init() 之前负责初始化和设置该内存区域。

这意味着该区域必须在 MPU / MMU 方面正确配置（如有需要），并且能够在其上创建实际的堆，例如利用 zephyr,memory-region 属性创建合适的链接器段来容纳该堆。
