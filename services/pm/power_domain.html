电源域

简介

Zephyr 电源域抽象旨在支持将由同一电源供电的设备分组，并以通用的方式通知它们电源状态的变化。使用设备 A 的应用程序代码无需知道设备 B 位于同一电源域中、也应被配置为低功耗状态。

电源域在 Zephyr 中是可选的，要启用此功能，必须设置 CONFIG_PM_DEVICE_POWER_DOMAIN 选项。

当电源域自身开启或关闭时，电源域负责通知所有使用它的设备，分别以 PM_DEVICE_ACTION_TURN_ON 或 PM_DEVICE_ACTION_TURN_OFF 调用它们的电源管理回调。该工作流程如下图所示。

内部电源域

SoC 中的大多数设备都有独立的电源控制，可以开启或关闭以降低功耗。但仍有相当多的静态漏电流无法仅靠设备电源管理来控制。为解决这个问题，SoC 通常被划分为若干区域，把通常一起使用的设备分为一组，这样就可以将未使用的区域完全断电，以消除这种漏电。这些区域称为“电源域”，它们可以构成层次结构，也可以嵌套。

外部电源域

SoC 外部的设备可以由 SoC 主电源以外的电源供电。这些外部电源通常是开关、稳压器或专用电源 IC。多个设备可以由同一电源供电，这样的设备分组通常称为“电源域”。

将设备置于电源域中有多种原因，包括让在低功耗模式下功耗较高的设备在不使用时可以完全关闭。

实现指南

首先，充当电源域的设备需要声明兼容 power-domain。以 电源域工作流程 为例，以下代码定义了一个名为 gpio_domain 的域。

gpio_domain: gpio_domain@4 {
        compatible = "power-domain";
        ...
};

电源域需要实现电源管理动作回调，电源管理子系统使用该回调来开启和关闭设备。

static int mydomain_pm_action(const struct device *dev,
                           enum pm_device_action action)
{
    switch (action) {
    case PM_DEVICE_ACTION_RESUME:
        /* resume the domain */
        ...
        /* notify children domain is now powered */
        pm_device_children_action_run(dev, PM_DEVICE_ACTION_TURN_ON, NULL);
        break;
    case PM_DEVICE_ACTION_SUSPEND:
        /* notify children domain is going down */
        pm_device_children_action_run(dev, PM_DEVICE_ACTION_TURN_OFF, NULL);
        /* suspend the domain */
        ...
        break;
    case PM_DEVICE_ACTION_TURN_ON:
        /* turn on the domain (e.g. setup control pins to disabled) */
        ...
        break;
    case PM_DEVICE_ACTION_TURN_OFF:
        /* turn off the domain (e.g. reset control pins to default state) */
        ...
        break;
    default:
        return -ENOTSUP;
    }

    return 0;
}

属于该设备的设备可以通过在节点的 power-domain 属性中引用它来声明。下面的示例声明了设备 gpio0 和 gpio1，它们属于域 gpio_domain`。

&gpio0 {
        compatible = "zephyr,gpio-emul";
        gpio-controller;
        power-domains = <&gpio_domain>;
};

&gpio1 {
        compatible = "zephyr,gpio-emul";
        gpio-controller;
        power-domains = <&gpio_domain>;
};

域的状态发生变化时，该域下的所有设备都会收到通知。这些通知作为动作发送到设备的电源管理动作回调中，设备可以借此完成所需的额外工作。不过，也可以放心地忽略它们。

static int mydev_pm_action(const struct device *dev,
                           enum pm_device_action *action)
{
    switch (action) {
    case PM_DEVICE_ACTION_SUSPEND:
        /* suspend the device */
        ...
        break;
    case PM_DEVICE_ACTION_RESUME:
        /* resume the device */
        ...
        break;
    case PM_DEVICE_ACTION_TURN_ON:
        /* configure the device into low power mode */
        ...
        break;
    case PM_DEVICE_ACTION_TURN_OFF:
        /* prepare the device for power down */
        ...
        break;
    default:
        return -ENOTSUP;
    }

    return 0;
}

备注

如果依赖某个域的设备被用作“唤醒”源，则由驱动或应用程序负责将该域也设为“唤醒”源。
