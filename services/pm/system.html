系统电源管理

简介

当内核没有可调度的任务时，会进入空闲状态。启用 CONFIG_PM 后，内核可以请求电源管理子系统把空闲的系统置于某个受支持的电源状态。内核请求一段希望挂起的时间，然后电源管理子系统根据所配置的电源管理策略决定要转换到的合适电源状态。

设置唤醒事件是应用程序的责任。唤醒事件通常是由 SoC 外设模块触发的中断，例如 SysTick、RTC、计数器或 GPIO。请记住，根据 SoC 和所涉及的电源模式，并非所有外设都处于活动状态，因此某些唤醒源可能无法在所有电源模式下使用。

空闲线程在调用 pm_system_suspend() 之前锁定中断，并持有原始的架构中断键（interrupt key）。如果电源管理子系统进入了低功耗状态，电源管理的恢复记账工作会在中断仍处于锁定状态时运行。默认情况下，先恢复由系统管理的设备，然后依次执行 pm_state_exit_post_ops()、电源管理退出通知以及系统时钟的空闲退出记账。如果低功耗状态停止了定时器，设备恢复回调就不能依赖基于定时器的 k_busy_wait()。这些记账工作完成且 pm_system_suspend() 返回后，空闲线程恢复原始的中断键。

备注

默认关闭的实验性选项 CONFIG_PM_EARLY_SYSTEM_TIMER_RESUME 会把顺序改为：pm_state_exit_post_ops()、系统时钟空闲退出记账、设备恢复，然后是电源管理退出通知。这样可以在设备恢复回调中使用基于定时器的 k_busy_wait()，但需要针对具体平台进行验证。SoC 的 post-ops 不得依赖已恢复的设备，定时器空闲退出也不得依赖仍处于挂起状态的设备。定时器空闲退出还可能在设备恢复之前调用 k_timer 的到期函数。

未选择 CONFIG_PM_STATE_SET_IRQ_UNLOCKED 的架构和 SoC 会在低功耗指令前后紧接着使用架构钩子，这样低功耗指令仍能感知唤醒事件，而不会先分派唤醒源的 ISR。在这种模式下，pm_state_set() 和 pm_state_exit_post_ops() 只能用于 SoC 特定的硬件工作，不能用作最终取消中断屏蔽的位置。

上述顺序保证只适用于 arch_irq_lock() 能够屏蔽的中断。零延迟中断不在此顺序之内。参见 零延迟中断。

电源状态

电源管理子系统定义了一组状态，每个状态由其功耗和上下文保留情况来描述。

电源状态集合由 pm_state 定义。一般来说，功耗越低的状态（在枚举中的索引越大）节能效果越好，唤醒延迟也越长。

电源管理策略

电源管理子系统支持以下电源管理策略：

  • 基于驻留时间

  • 由应用程序定义

策略管理器是电源管理子系统中负责决定系统应转换到哪个电源状态的组件。策略管理器只能在为平台定义的状态之间进行选择。根据策略的不同，决策还可能受到其他约束，包括禁止某些电源状态的锁，或各种最小和最大延迟值。

有关状态定义的更多详情，请参阅 zephyr,power-state 绑定文档。

驻留时间

在驻留时间策略下，系统将进入节能效果最好的电源状态，约束条件是最小驻留时间值（参见 zephyr,power-state）与退出该模式的延迟之和必须小于或等于内核调度的系统空闲时长。

因此核心逻辑可以概括为以下表达式：

if (time_to_next_scheduled_event >= (state.min_residency_us + state.exit_latency)) {
   return state
}

应用程序

应用程序通过实现 pm_policy_next_state() 函数来定义电源管理策略。在这种策略下，应用程序可以根据距下一次调度超时的剩余时间，自由决定系统应转换到哪个电源状态。

定义了自己策略的应用程序示例见 tests/subsys/pm/power_mgmt/。

自定义节拍钩子

除了内核节拍到期时间和电源管理策略事件列表之外，应用程序和 SoC 特定代码可能还需要从专有或硬件特定的数据源推导下一次唤醒时间。例如硬件寄存器、仅以二进制形式提供的第三方模块，或不便建模为标准电源管理策略事件的复杂/遗留数据结构。

启用 CONFIG_PM_CUSTOM_TICKS_HOOK 后，电源管理核心会在 pm_system_suspend() 期间调用可选函数 pm_policy_next_custom_ticks()。该钩子返回距下一个自定义事件的节拍数；如果不需要考虑自定义事件，则返回 K_TICKS_FOREVER。

然后电源管理核心在以下各项中选择最早的到期时间：

  • 内核节拍到期时间，

  • 电源管理策略事件列表的节拍数（来自 pm_policy_next_event_ticks()），

  • 自定义节拍值（来自 pm_policy_next_custom_ticks()）。

这一机制使开发板和应用程序无需修改电源管理事件列表基础设施，即可将额外的定时源纳入系统电源管理决策。

策略与电源状态

电源管理子系统允许不同的 Zephyr 组件和应用程序配置策略管理器，阻止系统转换到某些电源状态。设备在后台执行任务时可以借此防止系统进入会丢失上下文的特定状态。参见 pm_policy_state_lock_get()。
