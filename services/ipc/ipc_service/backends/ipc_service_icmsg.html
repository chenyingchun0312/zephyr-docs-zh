ICMsg 后端

核间消息（inter core messaging，ICMsg）后端是较重的 RPMsg 静态 vring 后端的轻量替代方案。它以很小的内存占用提供最精简的特性集。ICMsg 后端构建在 单生产者单消费者数据包缓冲区 之上。

概述

ICMsg 后端使用共享内存和 MBOX 设备交换数据。共享内存用于存储数据，MBOX 设备用于发出数据已写入的信号。

该后端支持在单个实例上注册单个端点。如果应用程序需要多个通信通道，必须定义多个实例，每个实例拥有自己专用的端点。

配置

该后端通过 Kconfig 和设备树进行配置。配置后端时，请执行以下操作：

  • 如果至少有一个核在共享内存上使用数据缓存，请设置 dcache-alignment 值。该值必须取通信双方的无效化（invalidation）大小或回写（write-back）大小中的最大值。如果通信双方都没有在共享内存上使用数据缓存，可以跳过此项。

  • 定义两个存储区域，并将它们分配给实例的 tx-region 和 rx-region。确保用于数据交换的存储区域是唯一的（不与任何其他区域重叠），并且两个域（或 CPU）都可以访问。

  • 定义 MBOX 设备，用于发送信号，通知另一个域（或 CPU）数据已写入。确保另一个域（或 CPU）能够接收该信号。

小心

务必为 dcache-alignment 设置正确的值。错误的值起初可能不会表现出任何迹象，从而给人一切正常的错觉，但不稳定的行为迟早会出现。

请参阅以下其中一个实例的配置示例：

reserved-memory {
   tx: memory@20070000 {
      reg = <0x20070000 0x0800>;
   };

   rx: memory@20078000 {
      reg = <0x20078000 0x0800>;
   };
};

   ipc {
      ipc0: ipc0 {
         compatible = "zephyr,ipc-icmsg";
         dcache-alignment = <32>;
         tx-region = <&tx>;
         rx-region = <&rx>;
         mboxes = <&mbox 0>, <&mbox 1>;
         mbox-names = "tx", "rx";
         status = "okay";
      };
   };
};

必须为通信的另一方（域或 CPU）提供类似的配置，但必须交换 MBOX 通道和存储区域（tx-region 和 rx-region）。

绑定

注册端点时，通过 IPC 实例连接的每个域（或 CPU）上会发生以下过程：

  1. 域（或 CPU）将一个魔数写入共享内存中自己的 tx-region。

  2. 然后它向另一个域或 CPU 发送信号，通知数据已写入。向另一个域或 CPU 发送信号的操作会按超时间隔重复进行。

  3. 收到来自另一个域或 CPU 的信号后，从 rx-region 读取魔数。如果魔数正确，绑定过程即完成，后端通过调用 ipc_service_cb.bound 回调通知应用程序。

示例

  • IPC service: icmsg backend

详细协议规范

ICMsg 使用两个共享内存区域和两个 MBOX 通道。一对区域和通道用于在一个方向上传输消息，另一对与之对称，用于在相反方向上传输消息。因此，下面的规范只针对其中一对进行说明，另一对完全相同。

ICMsg 每个实例只提供一个端点。

共享内存区域的组织

如果启用了数据缓存，提供给 ICMsg 的共享内存区域必须按照缓存要求对齐。如果未启用缓存，则要求按 4 字节对齐。

共享内存区域完全由单个 FIFO 使用。它包含读索引和写索引，后面是数据缓冲区。详细结构见下表：

这是一个使用循环缓冲区的普通 FIFO：

  • 索引（rd_idx 和 wr_idx）到达 data 缓冲区末尾时会回绕。

  • 如果 rd_idx == wr_idx，则 FIFO 为空。

  • FIFO 的容量比 data 缓冲区长度少一个字节。

数据包

数据包通过上一节所述的 FIFO 发送。如果数据包位于 FIFO 缓冲区末尾，可以回绕。

0‑3

数据包的发送过程如下：

  1. 检查数据包能否放入缓冲区。

  2. 将数据包从 wr_idx 开始写入 data FIFO 缓冲区，必要时回绕。

  3. 写入 wr_idx 的新值。

  4. 通过 MBOX 通道通知接收方。

初始化

初始化顺序如下：

  1. 将 wr_idx 和 rd_idx 设为零。

  2. 向 FIFO 推送一个包含魔数数据 45 6d 31 6c 31 4b 30 72 6e 33 6c 69 34 的数据包。此时还不使用 MBOX。

  3. 初始化 MBOX。

  4. 以一定的间隔（例如 1 ms）通过 MBOX 通道重复发送通知。

  5. 等待包含魔数数据的传入数据包。它将通过另一对（共享内存区域和 MBOX）到达。

  6. 停止重复发送 MBOX 通知。

此后，ICMsg 即完成绑定，可以开始传输数据包。
