CPU 频率调节

  • CPU 频率调节策略
  • CPU 频率温度上限

概述

Zephyr 中的 CPU 频率调节子系统提供了一个框架，让 SoC 能够根据所监测的指标和性能状态（P-state）策略算法动态调整处理器频率。

设计目标

CPU 频率调节子系统旨在提供一个框架，让任何策略算法都能与任何 P-state 驱动配合使用，并让每个策略可以利用一个或多个指标来确定最佳 CPU 频率。该子系统应足够灵活，允许 SoC 厂商定义自定义的 P-state、阈值和指标。

P-state 策略

P-state 策略是一种算法，它根据所使用的指标以及为每个 P-state 定义的阈值来确定 CPU 的最佳 P-state。策略可以使用一个或多个指标，根据期望的系统统计数据确定最佳 CPU 频率。

标准策略列表请参阅 策略。

指标

P-state 策略应包含一个或多个作为决策依据的指标。指标的例子包括 CPU 负载百分比、SoC 温度等。

有关指标的使用示例，请参阅 on_demand 策略。

温度上限

可选的 CPU 频率温度上限 根据温度触发点限制当前策略所允许的最高性能 P-state。它是一个约束层，而不是 P-state 策略，用于减少过多的发热并保护 SoC 免受热应力损害。

P-state 驱动

支持 CPU 频率调节子系统的 SoC 必须实现一个 P-state 驱动，其中实现 cpu_freq_pstate_set()，该函数在被调用时将传入的 p_state 应用到 CPU。

SoC 还必须在设备树中通过一个兼容 zephyr,pstate 的节点提供可用的 P-state。SoC 也可以定义自己的 P-state 绑定，在 zephyr,pstate 的基础上扩展额外的属性，供 SoC 的 P-state 驱动使用。

使用注意事项

CPU 频率调节子系统设计为可在 UP 和 SMP 系统上工作。在 SMP 系统上，默认假定所有 CPU 以相同的频率运行。因此，只要有一个 CPU 进行 P-state 转换，所有其他 CPU 也会进行相同的 P-state 转换。SoC 可以通过启用 CONFIG_CPU_FREQ_PER_CPU_SCALING 配置选项覆盖这一行为，让每个 CPU 独立设置时钟频率。

支持 CPU 频率调节的 SoC 必须遵守 Zephyr 的要求：系统定时器频率在程序的整个生命周期内保持稳定。更多信息请参阅 内核计时。

CPU 频率调节子系统作为 k_timer 的处理函数运行，这意味着它在中断上下文（IRQ）中运行。SoC 的 P-state 驱动必须确保其 cpu_freq_pstate_set() 实现在 IRQ 上下文中是安全的。如果 P-state 转换无法在 IRQ 上下文中于合理时间内完成，建议 SoC 的 P-state 驱动将其任务实现为工作队列项。
