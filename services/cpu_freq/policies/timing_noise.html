时序噪声 CPU 频率调节策略

概述

时序噪声（timing noise）策略是一种周期性随机选择性能状态（P-state）的 CPU 频率调节策略。其目的是通过让 CPU 时钟抖动来注入时序变化，从而干扰那些假定频率稳定的简单周期计数或挂钟时间测量。

这是一种随机化的 P-state 策略，并不是通用的侧信道防护措施。

主要防护措施

经过侧信道泄漏审查的恒定时间和恒定控制流实现，仍然是抵御时序攻击的主要防护措施。该策略不能替代这些做法，最多只能让某一类测量变得更复杂。

攻击者模型

该策略考虑的攻击者具有以下特点：

  • 通过周期计数器、挂钟定时器或类似的软件可见时间戳观察相对执行时间

  • 依赖稳定的 CPU 频率，使指令数量或数据相关路径上的微小差异在多次试验中仍可区分

随机选择 P-state 并不能挫败这类攻击。只要样本足够多，攻击者通常可以通过求平均消除噪声。该策略只是让这些测量变得不那么方便、不那么可重复。

使用场景

当应用程序希望在本身已经安全可靠的软件之上额外增加时序变化，作为第二层防护时，该策略可能有用。应把它视为干扰某些分析的手段，而不是独立的安全解决方案。

它不适合以下场景：

  • 需要确定性执行时间的硬实时系统

  • 时序可预测性是安全论证一部分的安全相关系统

  • 无法容忍意外的低速 P-state 的延迟敏感型负载

  • 严格限定功耗预算的设计，因为频繁的 P-state 变化可能增加平均功耗

配置

启用 CPU 频率子系统并选择时序噪声策略：

CONFIG_CPU_FREQ=y
CONFIG_CPU_FREQ_POLICY_TIMING_NOISE=y

该策略使用标准的 CPU 频率子系统更新间隔，通过以下选项配置：

CONFIG_CPU_FREQ_INTERVAL_MS=<interval>

更新间隔越小，时序变化越大，但频率转换的次数也越多。

随机数生成

该策略使用 sys_rand32_get() 选择性能状态。在具有硬件熵源的平台上，选择 CONFIG_CPU_FREQ_POLICY_TIMING_NOISE 会启用熵驱动。如果有 TRNG 可用，最好通过该驱动获取随机数：

CONFIG_ENTROPY_DEVICE_RANDOM_GENERATOR=y

限制

  • 它不能消除时序侧信道

  • 它无法弥补本质上不安全的软件

  • 它可能降低整体系统性能

  • 由于频繁变化性能状态，它可能增加功耗

  • 面对执意攻击或具备完善测量手段的攻击者，它不提供任何保证

有关时序噪声策略的示例，请参阅 CPU frequency scaling timing noise sample 示例。
