TF-M 构建系统

构建有效的 _ns 开发板目标时，TF-M 会在后台构建，并与 Zephyr 非安全应用程序链接。大多数情况下无需了解 TF-M 的构建系统，以下命令会构建一对 TF-M 和 Zephyr 镜像，并在 qemu 中运行，无需任何额外步骤：

$ west build -p auto -b mps2/an521/cpu0/ns samples/tfm_integration/psa_protected_storage/ -t run

不过，由于需要理解和使用构建输出，并在部署之前处理安全镜像和非安全镜像的签名，这里介绍该构建过程的输出及其中的某些关键步骤。

TF-M 构建生成的镜像

TF-M 构建系统会生成以下可执行文件：

  • tfm_s - TF-M 安全固件

  • tfm_ns - TF-M 非安全应用程序（仅用于回归测试）。

  • bl2 - TF-M MCUboot（如已启用）

对于每个文件，都会生成 .bin、.hex、.elf 和 .axf 文件。

TF-M 构建系统还会生成 tfm_s 和 tfm_ns 的签名版本，以及一个将两者合并的文件：

  • tfm_s_signed

  • tfm_ns_signed

  • tfm_s_ns_signed

对于这些文件，只会生成 .bin 文件。

除了运行 TF-M 回归测试套件的情况外，TF-M 非安全应用程序都会被舍弃，改用 Zephyr 非安全应用程序。

Zephyr 构建系统通常会自行对 tfm_s 和 Zephyr 非安全应用程序签名。详见下文。

'tfm' 目标包含所有这些路径的属性。例如，下面的写法会解析为 <path>/tfm_s.hex：

$<TARGET_PROPERTY:tfm,TFM_S_HEX_FILE>

所有属性的概况请参阅 tfm 模块中的顶层 CMakeLists.txt 文件。

镜像签名

当 CONFIG_TFM_BL2 设置为 y 时，TF-M 使用安全引导加载程序（BL2），固件镜像必须使用私钥签名。更新期间，引导加载程序会使用对应的公钥验证固件镜像，该公钥存储在安全引导加载程序的固件镜像中。

默认情况下，使用 <tfm-dir>/bl2/ext/mcuboot/root-rsa-3072.pem 对安全镜像签名，使用 <tfm-dir>/bl2/ext/mcuboot/root-rsa-3072_1.pem 对非安全镜像签名。可以（并且 应该）通过 CONFIG_TFM_KEY_FILE_S 和 CONFIG_TFM_KEY_FILE_NS 配置标志覆盖这些默认的 .pem 密钥。

为满足 PSA Certified Level 1 的要求，必须用新的密钥对替换默认的 .pem 文件！

要生成新的公钥/私钥对，请运行以下命令：

$ imgtool keygen -k root-rsa-3072_s.pem -t rsa-3072
$ imgtool keygen -k root-rsa-3072_ns.pem -t rsa-3072

然后可以将新的 .pem 文件放在其他位置（例如 Zephyr 应用程序文件夹中），并在 prj.conf 文件中通过 CONFIG_TFM_KEY_FILE_S 和 CONFIG_TFM_KEY_FILE_NS 配置标志引用它们。

警告

务必将私钥文件保存在安全、可靠的位置！如果丢失该密钥文件，将无法再为以后的固件镜像签名，也无法再更新已部署在现场的设备！

内置签名脚本运行后，会生成一个 tfm_merged.hex （以及 tfm_merged.bin）文件，其中包含全部三个二进制文件：bl2、tfm_s 和 zephyr 应用程序。之后可以将这些文件烧录到开发板，或在 QEMU 中运行。

自定义 CMake 参数

构建带有 TF-M 的 Zephyr 应用程序时，可能需要控制传给 TF-M 构建的 CMake 参数。

Zephyr TF-M 构建提供了若干 Kconfig 选项来控制构建，但并未涵盖 TF-M 构建系统支持的所有 CMake 参数。

可以使用 zephyr_property_target 上的 TFM_CMAKE_OPTIONS 属性向 TF-M 构建系统传递自定义 CMake 参数。

要将 CMake 参数 -DFOO=bar 传给 TF-M 构建系统，请在 CMakeLists.txt 文件中加入以下 CMake 代码片段。

set_property(TARGET zephyr_property_target
             APPEND PROPERTY TFM_CMAKE_OPTIONS
             -DFOO=bar
)

备注

TFM_CMAKE_OPTIONS 是一个列表，因此可以追加多个选项。此外还支持 CMake 生成器表达式，例如 $<1:-DFOO=bar>

由于 TFM_CMAKE_OPTIONS 是列表参数，它在传给 TF-M 构建系统之前会被展开。因此，带有列表参数的选项必须正确转义，以免被当作列表展开。

set_property(TARGET zephyr_property_target
             APPEND PROPERTY TFM_CMAKE_OPTIONS
             -DFOO="bar\\\;baz"
)

资源占用与内存使用

构建系统提供了一些目标，用于查看和分析生成镜像的 RAM 和 ROM 使用情况。这些工具作用于最终镜像，给出 RAM 和 ROM 中所用符号和代码的大小信息。有关这些工具的更多信息，请参阅：资源占用与内存使用

使用 tfm_ram_report 获取 TF-M 安全固件（tfm_s）的 RAM 报告。

使用 west：

# From the root of the zephyr repository
west build -b mps2/an521/cpu0/ns samples/hello_world
west build -t tfm_ram_report

使用 CMake 和 ninja：

# From the root of the zephyr repository
# Use cmake to configure a Ninja-based buildsystem:
cmake -Bbuild -GNinja -DBOARD=mps2/an521/cpu0/ns samples/hello_world

# Now run the build tool on the generated build system:
ninja -Cbuild tfm_ram_report

使用 tfm_rom_report 获取 TF-M 安全固件（tfm_s）的 ROM 报告。

使用 west：

# From the root of the zephyr repository
west build -b mps2/an521/cpu0/ns samples/hello_world
west build -t tfm_rom_report

使用 CMake 和 ninja：

# From the root of the zephyr repository
# Use cmake to configure a Ninja-based buildsystem:
cmake -Bbuild -GNinja -DBOARD=mps2/an521/cpu0/ns samples/hello_world

# Now run the build tool on the generated build system:
ninja -Cbuild tfm_rom_report

使用 bl2_ram_report 获取 TF-M MCUboot（如已启用）的 RAM 报告。
