插桩

概述

插桩（instrumentation）子系统为 Zephyr 应用程序提供由编译器管理的运行时系统插桩能力。它让开发者只需很少的手动插桩工作，就能跟踪函数调用、观察上下文切换并剖析应用程序性能。

跟踪 子系统提供感知 RTOS 的跟踪功能和结构化的事件 API，而插桩子系统则利用编译器的插桩钩子，在更低的层次上工作。这种方法几乎可以捕获任何函数的进入和退出事件，而无需在代码中手动添加跟踪调用。

跟踪与插桩的比较

何时使用跟踪：当你需要感知 RTOS 的事件跟踪（例如线程切换、信号量操作等）并希望尽量降低开销时，选择跟踪子系统。

何时使用插桩：当你需要函数级执行的详细视图，以便更好地理解代码流程，或在不添加手动跟踪点的情况下找出性能瓶颈时，选择插桩。

插桩子系统依赖编译器对自动函数插桩的支持。启用后，编译器会在应用程序中每个函数（显式标记为 __no_instrumentation__ 的函数除外）的入口和出口处自动插入对特殊插桩处理函数的调用。目前只支持带 -finstrument-functions 编译选项的 GCC。

该子系统在 RAM 初始化之后自动初始化，并使用触发/停止函数来控制何时进行记录。默认的触发函数和停止函数都设为 main()（可通过 Kconfig 配置），也就是说插桩会捕获从 main() 开始到其返回的整个执行过程。

记录的数据存储在 RAM 中，主机可以通过一个提供一组简单命令的 UART 后端访问这些数据。scripts/instrumentation/zaru.py 脚本可以通过高层命令行界面执行这些命令，并便于以适合进一步分析（例如使用 Perfetto）的格式获取数据。

工作模式

插桩子系统支持两种模式，可以单独启用，也可以同时启用：

调用图模式（跟踪）

在调用图模式（通过 CONFIG_INSTRUMENTATION_MODE_CALLGRAPH 启用）下，子系统把函数的进入和退出事件连同时间戳和上下文信息记录到内存缓冲区中。这可以用于：

  • 重建完整的函数调用图

  • 观察线程上下文切换

  • 分析执行流程和时序关系

跟踪缓冲区可以工作在环形缓冲区模式（默认，覆盖旧条目）或固定缓冲区模式（满时停止）。缓冲区大小可通过 CONFIG_INSTRUMENTATION_MODE_CALLGRAPH_TRACE_BUFFER_SIZE 配置。

统计模式（性能剖析）

在统计模式（通过 CONFIG_INSTRUMENTATION_MODE_STATISTICAL 启用）下，子系统为触发点和停止点之间执行的每个不同函数累计时间统计。它提供每个函数的总执行时间，有助于找出性能瓶颈。子系统最多跟踪 CONFIG_INSTRUMENTATION_MODE_STATISTICAL_MAX_NUM_FUNC 个不同函数。

统计模式的输出示例（开销最大的前 10 个函数）。更多详情请参阅 zaru.py 用法。

配置

使用以下方式启用插桩：

CONFIG_INSTRUMENTATION=y
CONFIG_INSTRUMENTATION_MODE_CALLGRAPH=y    # For tracing
CONFIG_INSTRUMENTATION_MODE_STATISTICAL=y  # For profiling

插桩子系统通过 UART 控制台与目标设备通信。请确保 zephyr_console chosen 节点指向所需的 UART 控制器。

保留内存 可以让触发/停止函数的地址在重启后保留。此功能是可选的，通过 CONFIG_INSTRUMENTATION_DYNAMIC_TRIGGER Kconfig 选项启用。启用后，设备树中必须指定一个保留内存区域：

/ {
    sram@2003FC00 {
        compatible = "zephyr,memory-region", "mmio-sram";
        reg = <0x2003FC00 DT_SIZE_K(1)>;
        zephyr,memory-region = "RetainedMem";

        retainedmem {
            compatible = "zephyr,retained-ram";
            status = "okay";

            instrumentation_triggers: retention@0 {
                compatible = "zephyr,retention";
                status = "okay";
                reg = <0x0 0x10>;
            };
        };
    };
};

/* Adjust main SRAM to exclude retained region */
&sram0 {
    reg = <0x20000000 DT_SIZE_K(255)>;
};

完整的配置示例请参阅 Instrumentation 示例。其他选项包括缓冲区大小、触发函数以及函数/文件排除列表（参见以 CONFIG_INSTRUMENTATION_* 开头的 Kconfig 选项）。

zaru.py 用法

zaru.py 命令行工具（位于 scripts/instrumentation/zaru.py）提供了一个通过 UART 控制插桩并从目标提取数据的接口。

该工具提供以下几个命令：

  • status：检查目标设备是否支持

    • 调用图（跟踪）模式

    • 统计（性能剖析）模式

    • 动态配置触发/停止函数

  • trace：捕获并显示函数调用跟踪。

  • profile：捕获并显示函数性能剖析数据。

  • reboot：重启目标设备。

运行 zaru.py <command> --help 可以获取各命令的帮助。

默认情况下，zaru.py 尝试使用 /dev/ttyACM0 连接目标设备。可以使用 --serial 选项指定其他串口：

$ ./scripts/instrumentation/zaru.py --serial /dev/ttyACM1 status

--build-dir 选项用于指定 Zephyr 构建目录，需要它来找到用于符号解析的 ELF 文件。如果未提供，zaru.py 会尝试自动查找。

详细的使用说明请参阅 Instrumentation 示例文档。

限制与注意事项

编译器支持

插桩子系统需要支持 -finstrument-functions 的 GCC，不支持其他编译器。

栈大小要求

插桩会给每次函数调用增加开销，从而增加栈的使用量。你可能需要增大线程栈大小，以容纳插桩处理函数和嵌套函数调用所需的额外空间。

执行开销

所有函数调用都会产生插桩开销。由于增加了插桩调用，代码体积会增大，性能也会受到影响。

初始化限制

在 RAM 初始化之前运行的代码（例如早期启动函数）不会被捕获，因为它们在插桩子系统初始化之前运行。

为降低开销，请使用触发/停止函数只对感兴趣的代码区域插桩，并通过 CONFIG_INSTRUMENTATION_EXCLUDE_FUNCTION_LIST 和 CONFIG_INSTRUMENTATION_EXCLUDE_FILE_LIST 排除对性能要求高的函数。
