设置（Settings）

设置子系统为模块提供了一种存储每台设备的持久配置和运行时状态的方式。它在一套通用 API 之后提供了多种存储实现，分别基于 FCB、NVS、ZMS 或文件系统。这些不同的实现使应用程序开发者可以灵活地选择合适的存储介质，甚至可以在需求变化时更换它。该子系统被 Zephyr 的多个组件使用，也可以同时被用户应用程序使用。

设置项以键值对字符串的形式存储。按照惯例，键可以按定义该键的包和子树来组织，例如键 id/serial 定义了包 id 的 serial 配置元素。

子系统提供了一些便捷例程，用于在键值与字符串类型之间进行转换。

有关设置子系统的示例，请参阅 Settings API 示例。

备注

自 Zephyr 4.1 版本起，推荐用于非文件系统存储的后端是 NVS 和 ZMS。

处理程序

子树的设置处理程序（handler）实现一组处理函数。动态处理程序通过调用 settings_register() 注册，静态处理程序通过调用 SETTINGS_STATIC_HANDLER_DEFINE() 定义。

h_get

通过运行时后端使用 settings_runtime_get() 按名称请求某个设置元素的值时，会调用此函数。

h_set

使用 settings_load() 从持久存储加载值时，或通过运行时后端使用 settings_runtime_set() 时，会调用此函数。

h_commit

在设置全部加载完成后调用此函数。有时你并不希望单个设置值立即生效，例如当多个设置相互依赖时。

h_export

调用此函数以写出所有当前设置。当 settings_save() 尝试保存设置或将其传输到任何用户实现的后端时，就会发生这种调用。

设置处理程序还有一个提交优先级 cprio，用于确定 h_commit 调用的先后顺序。例如，当某个子系统初始化了一项其他 h_commit 调用所依赖的服务时，这会很有用。

设置处理程序的 h_commit 例程默认以 cprio = 0 初始化。要以不同的优先级初始化设置处理程序，动态处理程序可调用 settings_register_with_cprio()，静态处理程序可调用 SETTINGS_STATIC_HANDLER_DEFINE_WITH_CPRIO()。指定的 cprio 值是一个整数，数值越小表示优先级越高。

后端

后端负责为设置处理程序加载和保存数据，并实现一组处理函数。可以加载数据的后端通过调用 settings_src_register() 注册，可以保存数据的后端通过调用 settings_dst_register() 注册（一个后端可以同时注册两者）。当前实现允许多个源后端，但只允许一个目标后端。

csi_load

使用 settings_load() 从持久存储加载值时，会调用此函数。

csi_load_one

使用 settings_load_one() 从持久存储只加载一项时，会调用此函数。

csi_get_val_len

使用 settings_get_val_len() 从持久存储获取某个值的长度时，会调用此函数。

csi_save

使用 settings_save_one() 将单个设置保存到持久存储时，会调用此函数。

csi_save_start

使用 settings_save() 或 settings_save_subtree() 开始保存所有当前设置时，会调用此函数。

csi_save_end

使用 settings_save() 或 settings_save_subtree() 保存完所有当前设置后，会调用此函数。

Zephyr 存储后端

Zephyr 提供以下存储后端：

  • Flash 循环缓冲区（CONFIG_SETTINGS_FCB）。

  • 文件系统中的文件（CONFIG_SETTINGS_FILE）。

  • 非易失性存储（CONFIG_SETTINGS_NVS）。

  • Zephyr 存储器存储（Zephyr Memory Storage，CONFIG_SETTINGS_ZMS）。

可以为设置声明多个源；调用 settings_load() 时，会从所有这些源恢复设置。

写入设置的目标只能有一个；调用 settings_save() 或 settings_save_one() 时，数据就存储在这里。

FCB 读取目标通过 settings_fcb_src() 注册，写入目标通过 settings_fcb_dst() 注册。settings_fcb_src() 有一个附带作用：它会初始化 FCB 区域，因此必须在调用 settings_fcb_dst() 之前调用它。文件读取目标通过 settings_file_src() 注册，写入目标通过 settings_file_dst() 注册。

非易失性存储读取目标通过 settings_nvs_src() 注册，写入目标通过 settings_nvs_dst() 注册。

Zephyr 存储器存储（ZMS）读取目标通过 settings_zms_src() 注册，写入目标通过 settings_zms_dst() 注册。

ZMS 后端的特别之处在于，它在将设置键存入持久存储之前会使用哈希函数对其进行哈希。这种实现意味着，如果存储了大量不同的键，键的哈希值之间可能会发生冲突。具体数量取决于所选的哈希函数。

ZMS 后端最多可以处理 \(2^n\) 次冲突，其中 n 由（CONFIG_SETTINGS_ZMS_MAX_COLLISIONS_BITS）定义。

存储位置

FCB、非易失性存储（NVS）和 ZMS 后端默认查找标签为 "storage" 的固定分区。可以通过设置设备树中 chosen 节点的 zephyr,settings-partition 属性来选择其他分区。

文件后端用于存储设置的文件路径通过选项 CONFIG_SETTINGS_FILE_PATH 选择。

从持久存储加载数据

调用 settings_load() 时，会使用 h_set 实现将设置数据从存储加载到易失性存储器中。所有数据加载完成后，会调用 h_commit 处理程序，通知应用程序已成功获取设置。

另外，调用 settings_load_one() 只会加载一个设置条目，并将其存储到提供的缓冲区中。

如果只需要获取设置条目所关联值的长度，可以调用 settings_get_val_len()。例如，动态分配数据缓冲区的应用程序需要在通过 settings_load_one() 读取数据之前获取数据大小，就会用到它。

从技术上讲，FCB 和文件后端可能会存储实体的一些历史记录。这意味着最新的数据实体存储在所有已有的旧数据实体之后。从 Zephyr 2.1 开始，后端必须过滤掉所有旧实体，只用最新的实体调用回调。

将数据存储到持久存储

调用 settings_save_one() 时，会使用后端实现将设置数据存储到存储介质中。调用 settings_save() 时，会使用 h_export 实现，通过 settings_save_one() 在一次操作中存储不同的数据。只有当某个键需要由 settings_save() 调用来存储时，才需要 h_export 覆盖该键。

对于 FCB 和文件后端，只有当存储请求的数据改变了键的当前值时，才会实际存储，因此应用程序无需检查值是否发生了变化。这种存储机制意味着存储中可能包含对同一个键的多次赋值，而只有最后一次才是该键的当前值。

垃圾回收

当存储已满（FCB）或占用空间过多（文件）时，后端会删除非最新的键值对记录以及不必要的键删除记录。

安全域设置

目前，设置子系统不提供在同一实例中同时存储安全配置和非安全配置的方案。建议安全域使用自己的设置实例；如有需要（视具体情况而定），可以通过专用接口向非安全域提供数据。

示例：设备配置

这是一个简单的示例，其中设置处理程序只实现了 h_set 和 h_export。h_set 在从存储中恢复值时（或初始设置时）被调用，h_export 则借助 storage_func() 将值写入存储。用户也可以实现其他导出功能，例如写入 shell 控制台。

#define DEFAULT_FOO_VAL_VALUE 1

static int8 foo_val = DEFAULT_FOO_VAL_VALUE;

static int foo_settings_set(const char *name, size_t len,
                            settings_read_cb read_cb, void *cb_arg)
{
    const char *next;
    int rc;

    if (settings_name_steq(name, "bar", &next) && !next) {
        if (len != sizeof(foo_val)) {
            return -EINVAL;
        }

        rc = read_cb(cb_arg, &foo_val, sizeof(foo_val));
        if (rc >= 0) {
            /* key-value pair was properly read.
             * rc contains value length.
             */
            return 0;
        }
        /* read-out error */
        return rc;
    }

    return -ENOENT;
}

static int foo_settings_export(int (*storage_func)(const char *name,
                                                   const void *value,
                                                   size_t val_len))
{
    return storage_func("foo/bar", &foo_val, sizeof(foo_val));
}

struct settings_handler my_conf = {
    .name = "foo",
    .h_set = foo_settings_set,
    .h_export = foo_settings_export
};

示例：持久化运行时状态

这是一个演示如何持久化运行时状态的简单示例。本例只定义了 h_set，它在从持久存储恢复值时使用。

在本例中，main 函数递增 foo_val，然后持久化最新的数值。系统重启后，应用程序在初始化时调用 settings_load()，foo_val 会从重启前的值继续递增计数。

#include <zephyr/kernel.h>
#include <zephyr/sys/reboot.h>
#include <zephyr/settings/settings.h>
#include <zephyr/sys/printk.h>
#include <inttypes.h>

#define DEFAULT_FOO_VAL_VALUE 0

static uint8_t foo_val = DEFAULT_FOO_VAL_VALUE;

static int foo_settings_set(const char *name, size_t len,
                            settings_read_cb read_cb, void *cb_arg)
{
    const char *next;
    int rc;

    if (settings_name_steq(name, "bar", &next) && !next) {
        if (len != sizeof(foo_val)) {
            return -EINVAL;
        }

        rc = read_cb(cb_arg, &foo_val, sizeof(foo_val));
        if (rc >= 0) {
            return 0;
        }

        return rc;
    }


    return -ENOENT;
}

struct settings_handler my_conf = {
    .name = "foo",
    .h_set = foo_settings_set
};

int main(void)
{
    settings_subsys_init();
    settings_register(&my_conf);
    settings_load();

    foo_val++;
    settings_save_one("foo/bar", &foo_val, sizeof(foo_val));

    printk("foo: %d\n", foo_val);

    k_msleep(1000);
    sys_reboot(SYS_REBOOT_COLD);
}

示例：自定义后端实现

这是一个演示如何注册简单自定义后端处理程序（CONFIG_SETTINGS_CUSTOM）的简单示例。

static int settings_custom_load(struct settings_store *cs,
                                const struct settings_load_arg *arg)
{
    //...
}

static int settings_custom_save(struct settings_store *cs, const char *name,
                                const char *value, size_t val_len)
{
    //...
}

/* custom backend interface */
static struct settings_store_itf settings_custom_itf = {
    .csi_load = settings_custom_load,
    .csi_save = settings_custom_save,
};

/* custom backend node */
static struct settings_store settings_custom_store = {
    .cs_itf = &settings_custom_itf
};

int settings_backend_init(void)
{
    /* register custom backend */
    settings_dst_register(&settings_custom_store);
    settings_src_register(&settings_custom_store);
    return 0;
}
