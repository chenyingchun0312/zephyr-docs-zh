引导加载程序信息

引导加载程序信息（简称 blinfo）子系统是 保留系统（Retention System） 的扩展，用于读取引导加载程序共享的数据，并允许应用程序查询这些数据。它还有一项可选功能：整理从引导加载程序获取的信息，并以 blinfo/ 为前缀将其存储到 设置（Settings） 中。

设备树设置

要使用引导加载程序信息子系统，需要创建一个以保留数据区为父节点的保留区域，通常使用不初始化（non-init）RAM 来实现。请参阅下面的示例（本指南中的示例基于 nRF52840 DK 开发板及其存储布局）：

/ {
        sram@2003FC00 {
                compatible = "zephyr,memory-region", "mmio-sram";
                reg = <0x2003FC00 DT_SIZE_K(1)>;
                zephyr,memory-region = "RetainedMem";
                status = "okay";

                retainedmem {
                        compatible = "zephyr,retained-ram";
                        status = "okay";
                        #address-cells = <1>;
                        #size-cells = <1>;

                        boot_info0: boot_info@0 {
                                compatible = "zephyr,retention";
                                status = "okay";
                                reg = <0x0 0x100>;
                        };
                };
        };

        chosen {
                zephyr,bootloader-info = &boot_info0;
        };
};


/* Reduce SRAM0 usage by 1KB to account for non-init area */
&sram0 {
        reg = <0x20000000 DT_SIZE_K(255)>;
};

注意，必须在引导加载程序（MCUboot）和应用程序中同时应用此配置才能使用该功能。它可以与其他保留系统 API（例如 启动模式）组合使用。

MCUboot 设置

应用上述设备树配置后，需要将 MCUboot 配置为把共享数据存储在该区域中，为此需要设置以下 Kconfig 选项：

  • CONFIG_RETAINED_MEM：启用保留内存驱动

  • CONFIG_RETENTION：启用保留系统

  • CONFIG_BOOT_SHARE_DATA：启用共享数据

  • CONFIG_BOOT_SHARE_DATA_BOOTINFO：启用启动信息共享数据类型

  • CONFIG_BOOT_SHARE_BACKEND_RETENTION：使用 retention/blinfo 子系统存储共享数据

应用程序设置

应用程序必须启用以下基本 Kconfig 选项，引导加载程序信息子系统才能工作：

  • CONFIG_RETAINED_MEM

  • CONFIG_RETENTION

  • CONFIG_RETENTION_BOOTLOADER_INFO

  • CONFIG_RETENTION_BOOTLOADER_INFO_TYPE_MCUBOOT

使用引导加载程序信息子系统需要包含以下头文件：

#include <zephyr/retention/blinfo.h>

默认只提供查找函数 blinfo_lookup()，应用程序可以调用它来查询引导加载程序的信息。该函数由 CONFIG_RETENTION_BOOTLOADER_INFO_OUTPUT_FUNCTION 默认启用；不过，应用程序也可以选择改用设置存储功能。在这种模式下，可以通过设置键查询引导加载程序信息，此模式需要启用以下 Kconfig 选项：

  • CONFIG_SETTINGS

  • CONFIG_SETTINGS_RUNTIME

  • CONFIG_RETENTION_BOOTLOADER_INFO_OUTPUT_SETTINGS

这样就可以通过 settings_runtime_get() 函数使用以下键查询信息：

  • blinfo/mode：MCUboot 所配置的模式（enum mcuboot_mode 值）

  • blinfo/signature_type：MCUboot 所配置的签名类型（enum mcuboot_signature_type 值）

  • blinfo/recovery：MCUboot 中启用的恢复类型（enum mcuboot_recovery_mode 值）

  • blinfo/running_slot：当前运行的槽位，在 direct-XIP 模式下可用于确定更新时应使用哪个槽位

  • blinfo/bootloader_version：引导加载程序的版本（struct image_version 对象）

  • blinfo/max_application_size：可加载的应用程序的最大大小（以字节为单位）

除了前面的头文件之外，此模式还需要包含以下头文件：

#include <bootutil/boot_status.h>
#include <bootutil/image.h>
#include <zephyr/mcuboot_version.h>
#include <zephyr/settings/settings.h>
