保留系统（Retention System）

保留系统提供了一组 API，允许应用程序读写在设备通电期间能保留数据的存储区域或设备。这样，即使设备重启，也可以在不同应用程序之间或单个应用程序内部共享信息而不丢失状态信息。所存储的数据不应在断电时（或某些设备的某些低功耗模式下）保留，也不应存储到 Flash、EEPROM API 或电池供电 RAM 之类的非易失性存储中。

保留系统构建在保留数据（retained data）驱动之上，并在其基础上增加了额外的软件层功能以确保数据有效。可选地，可以使用一个魔数头部来检查保留数据存储区的开头是否包含该特定值，还可以在数据末尾附加一个可选的存储数据校验和（大小为 1、2 或 4 字节）。此外，保留系统 API 允许将保留数据区划分为多个不同的区域。例如，一个 64 字节的保留数据区可以划分为：4 字节用于启动模式，16 字节用于时间戳，44 字节用于最后一条日志消息。所有这些区域都可以独立访问或更新。前缀和校验和可以通过设备树按实例设置。

设备树设置

要使用保留系统，必须为所用开发板设置一个保留数据驱动。Zephyr 提供了一个可用的驱动，它会把一部分 RAM 用作不初始化（non-init）区域来实现这一目的。然后，保留系统作为该设备的子节点被初始化一次或多次。注意，需要相应减小存储区域的大小，以扣除这部分预留的 RAM。请参阅下面的示例（本指南中的示例基于 nRF52840 DK 开发板及其存储布局）：

/ {
        sram@2003FC00 {
                compatible = "zephyr,memory-region", "mmio-sram";
                reg = <0x2003FC00 DT_SIZE_K(1)>;
                zephyr,memory-region = "RetainedMem";
                status = "okay";

                retainedmem {
                        compatible = "zephyr,retained-ram";
                        status = "okay";
                        #address-cells = <1>;
                        #size-cells = <1>;

                        /* This creates a 256-byte partition */
                        retention0: retention@0 {
                                compatible = "zephyr,retention";
                                status = "okay";

                                /* The total size of this area is 256
                                 * bytes which includes the prefix and
                                 * checksum, this means that the usable
                                 * data storage area is 256 - 3 = 253
                                 * bytes
                                 */
                                reg = <0x0 0x100>;

                                /* This is the prefix which must appear
                                 * at the front of the data
                                 */
                                prefix = [08 04];

                                /* This uses a 1-byte checksum */
                                checksum = <1>;
                        };

                        /* This creates a 768-byte partition */
                        retention1: retention@100 {
                                compatible = "zephyr,retention";
                                status = "okay";

                                /* Start position must be after the end
                                 * of the previous partition. The total
                                 * size of this area is 768 bytes which
                                 * includes the prefix and checksum,
                                 * this means that the usable data
                                 * storage area is 768 - 6 = 762 bytes
                                 */
                                reg = <0x100 0x300>;

                                /* This is the prefix which must appear
                                 * at the front of the data
                                 */
                                prefix = [00 11 55 88 fa bc];

                                /* If omitted, there will be no
                                 * checksum
                                 */
                        };
                };
        };
};

/* Reduce SRAM0 usage by 1KB to account for non-init area */
&sram0 {
        reg = <0x20000000 DT_SIZE_K(255)>;
};

随后即可使用数据保留 API 访问这些保留区域（需先通过 CONFIG_RETENTION 启用，而它要求启用 CONFIG_RETAINED_MEM），获取设备的方法如下：

#include <zephyr/device.h>
#include <zephyr/retention/retention.h>

const struct device *retention0 = DEVICE_DT_GET(DT_NODELABEL(retention0));
const struct device *retention1 = DEVICE_DT_GET(DT_NODELABEL(retention1));

调用写入函数时，会在该区域上设置魔数头部和校验和（如果已启用），并从此时起将该区域标记为有效。

互斥量保护

当应用程序在编译时启用了多线程支持，保留区域的互斥量保护默认启用。这意味着不同线程可以安全地调用保留函数，而不会与其他线程的并发调用冲突，但也意味着不能在 ISR 中使用保留函数。可以通过启用 CONFIG_RETENTION_MUTEX_FORCE_DISABLE 在所有保留区域上全局禁用互斥量保护，此时由用户负责确保函数调用之间不会相互冲突。注意，要使用该选项，还必须通过启用 CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE 禁用保留驱动的互斥量支持。

启动模式

保留子系统附带了一个启动模式接口，可用于在设备重启时动态改变应用程序的状态，或以最少的功能集运行另一个应用程序（例如，无需按键即可从主应用程序进入 mcuboot 的串口恢复功能）。

要使用启动模式功能，设备树中必须存在一个专门用于启动模式选择的数据保留条目（用户区数据大小只需一个字节），并将该区域分配给 zephyr,boot-mode chosen 节点。请参阅下面的示例：

/ {
        sram@2003FFFF {
                compatible = "zephyr,memory-region", "mmio-sram";
                reg = <0x2003FFFF 0x1>;
                zephyr,memory-region = "RetainedMem";
                status = "okay";

                retainedmem {
                        compatible = "zephyr,retained-ram";
                        status = "okay";
                        #address-cells = <1>;
                        #size-cells = <1>;

                        retention0: retention@0 {
                                compatible = "zephyr,retention";
                                status = "okay";
                                reg = <0x0 0x1>;
                        };
                };
        };

        chosen {
                zephyr,boot-mode = &retention0;
        };
};

/* Reduce SRAM0 usage by 1 byte to account for non-init area */
&sram0 {
        reg = <0x20000000 0x3FFFF>;
};

可以通过 CONFIG_RETENTION_BOOT_MODE 启用启动模式接口，然后使用启动模式函数访问它。如果使用带串口恢复功能的 mcuboot，可以在构建时启用 CONFIG_MCUBOOT_SERIAL 和 CONFIG_BOOT_SERIAL_BOOT_MODE，这样就可以通过以下方式直接重启进入串口恢复模式：

#include <zephyr/retention/bootmode.h>
#include <zephyr/sys/reboot.h>

bootmode_set(BOOT_MODE_TYPE_BOOTLOADER);
sys_reboot(0);
