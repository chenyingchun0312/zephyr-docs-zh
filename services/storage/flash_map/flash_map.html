Flash 映射（Flash map）

<zephyr/storage/flash_map.h> API 允许通过 flash_area 结构体访问设备 Flash 分区的信息。

每个 flash_area 描述一个 Flash 分区。该 API 提供对“Flash 映射”的访问，其中包含预定义的 Flash 区域，可通过全局唯一的 ID 号访问。该映射由 DTS 文件中兼容 "fixed-partitions" 和 "zephyr,mapped-partition" 的条目生成。用户也可以在运行时创建 flash_area 对象，用于应用程序特定的用途。

本文档在指代单个 "fixed-partitions" 或 "zephyr,mapped-partition" 实体时使用“Flash 区域”一词。

flash_area 包含一个指向 device 的指针，可借助它通过 Flash API 直接访问该区域所在的 Flash 设备。每个 Flash 区域由其所在的设备、相对设备起始处的偏移量以及在设备上的大小来描述。flash_area_open() 函数还使用一个额外的标识符参数在 Flash 映射中查找 Flash 区域。

flash_map.h API 提供了操作 flash_area 的函数，主要例子是 flash_area_read() 和 flash_area_write()。这些函数基本上是对 Flash API 的封装，额外增加了偏移量和大小检查，从而将 Flash 操作限制在预定义的区域内。

大多数 <zephyr/storage/flash_map.h> API 函数需要一个 flash_area 对象指针，用来描述它们将要操作的 Flash 区域。获取这种指针有两种方法：

  • 使用 flash_area_open() 获取；

  • 定义一个 flash_area 类型的对象，这需要提供一个有效的 device 对象指针，以及该区域在 Flash 设备内的偏移量和大小。

flash_area_open() 使用数字标识符在 Flash 映射中搜索 flash_area 对象，如果找到，则返回指向表示给定 ID 区域的对象的指针。Flash 区域的 ID 号可以使用 PARTITION_ID() 从 "fixed-partitions" 或 "zephyr,mapped-partition" DTS 节点标签获得；这些标签按下文所述从设备树中获得。

与设备树的关系

flash_map.h API 使用由 设备树 API 生成的数据，特别是其中的 固定 Flash 分区和映射 Flash 分区。此外，Zephyr 还有一些分区约定，用于通过 MCUboot 引导加载程序进行 设备固件升级，以及定义可供 文件系统 或其他非易失性 存储 使用的分区。

下面是一个设备树片段示例，它为 MCUboot 和一个存储分区都使用了固定 Flash 分区。为清晰起见，省略了部分细节。

/ {
	soc {
		flashctrl: flash-controller@deadbeef {
			flash0: flash@0 {
				compatible = "soc-nv-flash";
				reg = <0x0 0x100000>;
				ranges = <0x0 0x0 0x100000>;

				partitions {
					#address-cells = <1>;
					#size-cells = <1>;
					ranges;

					boot_partition: partition@0 {
						compatible = "zephyr.mapped-partition";
						reg = <0x0 0x10000>;
						read-only;
					};

					storage_partition: partition@1e000 {
						compatible = "zephyr.mapped-partition";
						reg = <0x1e000 0x2000>;
					};

					slot0_partition: partition@20000 {
						compatible = "zephyr.mapped-partition";
						reg = <0x20000 0x60000>;
					};

					slot1_partition: partition@80000 {
						compatible = "zephyr.mapped-partition";
						reg = <0x80000 0x60000>;
					};

					scratch_partition: partition@e0000 {
						compatible = "zephyr.mapped-partition";
						reg = <0xe0000 0x20000>;
					};
				};
			};
		};
	};
};

分区偏移量应相对于该分区所属 Flash 存储器的起始地址来表示。

boot_partition、slot0_partition、slot1_partition 和 scratch_partition 节点标签是为 MCUboot 定义的，不过并非所有 MCUboot 配置都要求定义全部这些标签。详情请参阅 MCUboot documentation。

storage_partition 节点定义为供文件系统或其他非易失性存储 API 使用。

将 DTS 节点标签传给 PARTITION_ID() 即可获得数字形式的 Flash 区域 ID；例如，要获得 slot0_partition 的 ID 号，用户可调用 PARTITION_ID(slot0_partition)。

所有 PARTITION_* 宏都以 DTS 节点标签作为分区标识符。

如果 Flash 区域已在 DTS 文件中定义，用户无需通过 flash_map_open() 获取 flash_area 对象指针，即可获得该区域的大小、偏移量或设备信息。只要知道某个区域的 DTS 节点标签，用户就可以分别使用 PARTITION_OFFSET()、PARTITION_SIZE() 或 PARTITION_DEVICE() 直接从 DTS 节点定义中获取这些信息。例如，要获取 storage_partition 的偏移量，只需调用 PARTITION_OFFSET(storage_partition)。

下面的示例展示了如何使用 flash_area_open() 和 DTS 节点标签获取 flash_area 对象指针：

const struct flash_area *my_area;
int err = flash_area_open(PARTITION_ID(slot0_partition), &my_area);

if (err != 0) {
     handle_the_error(err);
} else {
     flash_area_read(my_area, ...);
}
