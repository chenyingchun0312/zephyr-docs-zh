磁盘访问

概述

磁盘访问 API 提供对存储设备的访问。

初始化磁盘

由于许多磁盘设备（例如 SD 卡）支持热插拔，磁盘访问 API 提供了用于初始化和反初始化磁盘的 IOCTL，如下所示：

  • DISK_IOCTL_CTRL_INIT：初始化磁盘。必须先调用它，才能在磁盘设备上执行其他 I/O 操作。等效于调用旧版函数 disk_access_init()。

  • DISK_IOCTL_CTRL_DEINIT：反初始化磁盘。发出此 IOCTL 后，必须先发出 DISK_IOCTL_CTRL_INIT，才能再用该磁盘执行其他 I/O 操作。

初始化/反初始化 IOCTL 调用是成对计数的，因此只有在发出的反初始化 IOCTL 数量与初始化 IOCTL 数量相等时，磁盘才会被反初始化。

也可以向 DISK_IOCTL_CTRL_DEINIT IOCTL 传入一个指向值为 true 的布尔变量的指针作为参数，从而强制反初始化磁盘。这是一项不安全的操作，各磁盘驱动的处理方式可能不同，但它总是返回表示成功的值。

注意，反初始化磁盘是一项底层操作。通常应将反初始化和初始化调用交给文件系统实现处理，用户应用程序不需要手动反初始化磁盘，而是可以调用 fs_unmount()。

SD 卡支持

Zephyr 支持部分 SD 卡控制器，也支持通过 SPI 连接 SD 卡。这些驱动使用磁盘驱动接口，文件系统可以通过磁盘访问 API 访问 SD 卡。标准容量和高容量 SD 卡均受支持。

备注

FAT 文件系统不具备掉电安全性，因此如果断电，或者在未卸载文件系统的情况下拔出存储卡，文件系统可能会损坏。

SD 存储卡子系统

Zephyr 通过磁盘驱动 API 或 SDMMC 子系统支持 SD 存储卡。该子系统可以通过磁盘驱动 API 透明地使用，也支持对存储卡进行直接的块级访问。SDMMC 子系统与 SD 主机控制器 API 交互，以便与所连接的 SD 卡通信。

通过 SPI 支持 SD 卡

下面的设备树片段示例展示了如何在 spi1 接口上添加 SD 卡节点。该示例使用引脚 PA27 作为片选，并在 SD 卡初始化完成后以 24 MHz 运行 SPI 总线：

&spi1 {
        status = "okay";
        cs-gpios = <&porta 27 GPIO_ACTIVE_LOW>;

        sdhc0: sdhc@0 {
                compatible = "zephyr,sdhc-spi-slot";
                reg = <0>;
                status = "okay";
                mmc {
                    compatible = "zephyr,sdmmc-disk";
                    disk-name = "SD";
                    status = "okay";
                };
                spi-max-frequency = <24000000>;
        };
};

开发板启动时，文件系统驱动会自动检测并初始化 SD 卡。

要读写文件和目录，请参阅 include/zephyr/fs/fs.h 中的 文件系统，例如 fs_open()、fs_read() 和 fs_write()。

eMMC 设备支持

Zephyr 还支持通过磁盘访问 API 使用 eMMC 设备。由于 MMC 总线与 SD 总线有很多相似之处，Zephyr 中的 MMC 是基于 SD 子系统实现的。MMC 控制器同样使用 SDHC 设备驱动 API。

支持基于 Flash 分区的模拟块设备

Zephyr 的 flashdisk 驱动可以将 Flash 存储器分区用作块设备。flashdisk 实例在设备树中定义：

/ {
    msc_disk0 {
        compatible = "zephyr,flash-disk";
        partition = <&storage_partition>;
        disk-name = "NAND";
        cache-size = <4096>;
    };
};

zephyr,flash-disk 节点中指定的缓存大小应等于底层分区的最小可擦除块大小。
