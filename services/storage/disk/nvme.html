NVMe

NVMe 是 PCIe 总线上用于暴露存储设备的标准化逻辑设备接口。

Zephyr 支持 NVMe 控制器和磁盘。磁盘可以通过其暴露的 磁盘访问 API 访问，从而可以通过 文件系统 API 使用。

驱动设计

该驱动分为 3 个主要部分：

  • NVMe 控制器：drivers/disk/nvme/nvme_controller.c

  • NVMe 命令：drivers/disk/nvme/nvme_cmd.c

  • NVMe 命名空间：drivers/disk/nvme/nvme_namespace.c

其中，NVMe 控制器是设备驱动的根，设备驱动实例就是针对它创建的。注意，DTS 描述的也仅仅是 NVMe 控制器，而不包括它的任何命名空间（磁盘）。NVMe 命令是与控制器及其暴露的命名空间进行通信的通用逻辑。最后，NVMe 命名空间部分专门处理实际的命名空间，进而使应用程序能够通过磁盘访问 API（drivers/disk/nvme/nvme_disk.c）访问每个命名空间。

如果控制器暴露了不止 1 个命名空间（磁盘），可以通过调整配置选项 CONFIG_NVME_MAX_NAMESPACES（见下文）来增加内置支持的命名空间数量。

每个暴露的磁盘通过其相关的 disk_info 结构体以名称区分，该名称继承自对应的命名空间。因此，磁盘名称遵循 NVMe 的命名方式 nvme<k>n<n>，其中 k 是控制器编号，n 是命名空间编号。大多数情况下，如果系统中只插入了一块 NVMe 磁盘，看到的暴露磁盘就是 'nvme0n0'。

NVMe 配置

DTS

任何暴露 NVMe 磁盘的开发板都应提供一个 DTS 覆盖文件，以便在 Zephyr 中使用该磁盘

#include <zephyr/dt-bindings/pcie/pcie.h>
/ {
    pcie0 {
        nvme0: nvme0 {
            compatible = "nvme-controller";
            vendor-id = <VENDOR_ID>;
            device-id = <DEVICE_ID>;
            status = "okay";
        };
    };
};

其中 VENDOR_ID 和 DEVICE_ID 取自所暴露的 NVMe 控制器。

选项

  • CONFIG_NVME

注意，NVME 要求目标平台支持 PCIe 多向量 MSI-X 才能工作。

  • CONFIG_NVME_MAX_NAMESPACES

用户须知

NVMe 规范要求数据缓冲区位于双字（4 字节）对齐的地址上。对于在用户进程之下管理虚拟内存和动态分配的高级操作系统来说，这不是问题；但在 Zephyr 中，一旦缓冲区地址直接映射到物理内存，这就可能成为问题。

因此，目前需要由用户确保传给 disk_access_read() 和 disk_access_write() 的缓冲区地址是双字对齐的。
