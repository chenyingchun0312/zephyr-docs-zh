VirtIO 块设备

VirtIO 是一种向客户机（通常运行在 QEMU 等虚拟机监控程序之下）暴露虚拟设备的标准化接口。virtio,blk 驱动将 VirtIO 块设备呈现为 Zephyr 磁盘：可以通过 磁盘访问 API 访问它，进而通过 文件系统 API 使用它。

该驱动与传输方式无关，无需修改即可在 Zephyr 支持的两种 VirtIO 传输方式 PCI 和 MMIO 上运行（参见 VirtIO）。每个已启用的 virtio,blk 设备树节点都会创建一个实例。

驱动设计

该驱动位于 drivers/disk/virtio_blk.c，构建在通用 VirtIO API 之上。virtio,blk 节点是 VirtIO 传输设备（DT_INST_PARENT）的子节点，因此同一份代码无需修改即可服务于 PCI 或 MMIO 设备。

单个进行中的请求

disk_access 读写 API 是同步阻塞的。驱动还使用互斥量对调用者进行串行化，因此每个设备同一时刻只有一个进行中的请求：驱动将单个描述符链添加到请求 virtqueue，通知设备，然后阻塞在一个信号量上，由完成回调在中断上下文中释放该信号量。

由于没有请求流水线，整个 virtqueue 都用于单个请求的分散-聚集（scatter-gather）链。面向用户的可调参数是每个请求的最大数据段数（CONFIG_DISK_VIRTIO_BLK_MAX_SEGMENTS）；驱动将 MAX_SEGMENTS + 2 向上取整到 2 的幂作为 virtqueue 的大小，为请求头和状态字节留出空间。

块大小

VirtIO 块协议始终以固定的 512 字节扇区对设备寻址，并以该单位报告设备容量。暴露给 disk_access 的逻辑块大小可能与之不同：

  • 当设备提供 VIRTIO_BLK_F_BLK_SIZE 时，驱动会协商该特性并暴露设备通告的 blk_size。

  • 否则回退为 CONFIG_DISK_VIRTIO_BLK_SECTOR_SIZE。

所有寻址在内部都会转换为 512 字节的 VirtIO 扇区。块大小必须是 512 的倍数；在启用 CONFIG_MMU 时，块大小不得超过 MMU 页大小；不支持的值会在初始化时被拒绝。

零拷贝传输

调用者的缓冲区会直接交给设备，而不使用中转缓冲区（bounce buffer）。在启用 CONFIG_MMU 时，缓冲区可能位于内核的线性 RAM 映射之外（例如 f_mkfs() 传下来的线程栈工作区），并且不一定在物理上连续。驱动使用 arch_page_phys_get() 逐页遍历这类缓冲区，将物理上相邻的部分合并为分散-聚集段；当一次传输的碎片程度超出段数限额时，会将其拆分为多个设备请求。

特性协商

除了 VIRTIO_BLK_F_BLK_SIZE 之外，驱动还会协商：

  • VIRTIO_BLK_F_RO：只读设备会被报告为 DISK_STATUS_WR_PROTECT，写请求会以 -EROFS 被拒绝。

  • VIRTIO_BLK_F_FLUSH：DISK_IOCTL_CTRL_SYNC 会向设备发出刷新命令。如果设备没有提供 FLUSH，则不存在需要刷新的回写缓存，因此该 ioctl 会作为成功的空操作返回，而不是报错。

状态字节不为 OK 的已完成请求会被记录日志并映射为 errno：不支持的请求映射为 -ENOTSUP，I/O 错误映射为 -EIO。

VirtIO 块设备配置

DTS

virtio,blk 节点放在其 VirtIO 传输父节点之下，并且需要一个供 disk_access API 使用的 disk-name。使用 PCI 传输时：

#include <zephyr/dt-bindings/pcie/pcie.h>

/ {
    pcie0 {
        virtio-blk-pci {
            compatible = "virtio,pci";
            vendor-id = <0x1af4>;
            device-id = <0x1001>;
            interrupts = <0xb 0x0 0x0>;
            interrupt-parent = <&intc>;
            status = "okay";

            virtio_blk: virtio-blk {
                compatible = "virtio,blk";
                disk-name = "VIRTIOBLK0";
                status = "okay";
            };
        };
    };
};

使用 MMIO 传输时，该节点是已有 virtio,mmio 总线的子节点：

&virtio_mmio4 {
    status = "okay";

    virtio_blk: virtio-blk {
        compatible = "virtio,blk";
        disk-name = "VIRTIOBLK0";
        status = "okay";
    };
};

选项

  • CONFIG_DISK_DRIVER_VIRTIO_BLK

  • CONFIG_DISK_VIRTIO_BLK_MAX_SEGMENTS

  • CONFIG_DISK_VIRTIO_BLK_SECTOR_SIZE

QEMU 选项

在 QEMU 开发板上启用 CONFIG_DISK_DRIVER_VIRTIO_BLK 时，模拟层会创建一个原始后备镜像，并将其挂接到模拟的 virtio-blk 设备上。PCI 传输由通用的 QEMU 模拟代码挂接；qemu_cortex_a53 开发板则将一个 MMIO virtio-blk-device 挂接到 virtio-mmio-bus.4。

  • CONFIG_QEMU_VIRTIO_BLK_LOGICAL_BLOCK_SIZE

  • CONFIG_QEMU_VIRTIO_BLK_DISK_SIZE

限制

  • 同一时刻只有一个进行中的请求。这符合 disk_access 的同步约定，因此不会降低该使用方的吞吐量，但驱动不提供请求流水线。

  • 与 Zephyr VirtIO 子系统的其余部分一样，该驱动假定 DMA 是一致性的，不会对描述符、环或数据缓冲区执行任何缓存维护操作。

  • 在 MMU 下，逻辑块大小不能超过 MMU 页大小。
