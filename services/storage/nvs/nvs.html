非易失性存储（NVS）

以 id-数据对形式表示的元素，使用以 FIFO 方式管理的循环缓冲区存储在 Flash 中。Flash 区域被划分为多个扇区。元素会被追加到一个扇区中，直到该扇区的存储空间耗尽，然后准备（擦除）Flash 区域中的一个新扇区以供使用。在擦除扇区之前，会检查使用中的扇区里是否存在相应的标识符-数据对，如果不存在，则复制该 id-数据对。

id 是一个 16 位无符号数。NVS 确保对于每个已使用的 id，Flash 中始终至少存储有一个 id-数据对。

NVS 支持存储二进制数据块（blob）、字符串、整数、长整数，以及它们的任意组合。

每个元素在 Flash 中存储为元数据（8 字节）和数据。元数据写入一个从 NVS 扇区末尾开始的表中，数据则从扇区开头起依次写入。元数据包括：id、数据在扇区中的偏移量、数据长度、part（未使用）以及一个 CRC。该 CRC 仅针对元数据计算，只用于确保写入已完成。元素的实际数据可以由另一个（可选的）CRC-32 保护。使用 CONFIG_NVS_DATA_CRC 配置项可启用数据部分的 CRC。

备注

仅在读取元素的全部数据时才会检查数据 CRC。部分读取时不会检查数据 CRC，因为它存储在元素数据区的末尾。

备注

在原先不带数据 CRC 的已有 NVS 内容上启用数据 CRC 功能，会使所有现有数据失效。

向 NVS 写入数据时，总是先写入数据，再写入元数据。在初始化期间，已写入 Flash 但没有元数据的数据会被忽略。

在初始化期间，NVS 会校验存储在 Flash 中的数据，如果遇到错误，会忽略元数据缺失或不正确的所有数据。

NVS 在向 Flash 写入数据之前会检查 id-数据对。如果 id-数据对未发生变化，则不会对 Flash 执行写入。

为了防止 Flash 区域被频繁擦除，保留足够的空闲空间非常重要。NVS 有一种保护机制，可避免在空闲空间有限时陷入无休止的 Flash 页擦除循环。检测到这种循环时，NVS 会返回没有更多可用空间。

对于 NVS，文件系统的声明方式如下：

static struct nvs_fs fs = {
.flash_device = NVS_FLASH_DEVICE,
.sector_size = NVS_SECTOR_SIZE,
.sector_count = NVS_SECTOR_COUNT,
.offset = NVS_STORAGE_OFFSET,
};

其中

  • NVS_FLASH_DEVICE 是对将要使用的 Flash 设备的引用，该设备必须处于可用状态。

  • NVS_SECTOR_SIZE 是扇区大小，它必须是 Flash 擦除页大小的倍数，并且是 2 的幂。

  • NVS_SECTOR_COUNT 是扇区数量，至少为 2，始终会保留一个扇区为空，以便复制现有数据。

  • NVS_STORAGE_OFFSET 是存储区在 Flash 中的偏移量。

Flash 磨损

向 Flash 写入数据时，研究 Flash 磨损非常重要。Flash 的寿命有限，由 Flash 可被擦除的次数决定。Flash 每次擦除一页，页大小由硬件决定。例如，nRF51822 设备的页大小为 1024 字节，每页大约可以擦除 20,000 次。

计算预期设备寿命

假设我们使用一个 4 字节的状态变量，它每分钟变化一次，并且需要在重启后恢复。NVS 定义的 sector_size 等于页大小（1024 字节），并定义了 2 个扇区。

每次写入该状态变量需要 12 字节的 Flash 存储空间：8 字节用于元数据，4 字节用于数据。存储数据时，第一个扇区将在 1024/12 = 85.33 分钟后写满。再过 85.33 分钟，第二个扇区也会写满。此时，由于只使用了两个扇区，第一个扇区将被重新用于存储，它会在系统运行 171 分钟后被擦除。按预期设备寿命为 20,000 次写入计算，两个扇区每 171 分钟写入一轮，设备大约可以使用 171 * 20,000 分钟，即约 6.5 年。

更一般地，设

  • NS 为每分钟的存储请求次数，

  • DS 为数据大小（字节），

  • SECTOR_SIZE 为扇区大小（字节），

  • PAGE_ERASES 为页可被擦除的次数，

则预期设备寿命（以分钟为单位）可按如下公式计算:

SECTOR_COUNT * SECTOR_SIZE * PAGE_ERASES / (NS * (DS+8)) minutes

从这个公式也可以清楚地看出，如果预期寿命太短该怎么办：增大 SECTOR_COUNT 或 SECTOR_SIZE。

Flash 写入块大小迁移

在 DFU 过程中，NVS 所使用的 Flash 驱动可能会改变其支持的最小写入块大小。只要物理 ATE 大小不变，NVS 在 Flash 中的镜像就保持兼容。特别地，允许在 1、2、4、8 字节写入块大小之间迁移。

故障排除

使用 NVS 时出现 MPU 故障，或返回 -ETIMEDOUT 错误

NVS 可以使用 SoC 的内部 Flash。启用 MPU 时，Flash 驱动需要对 Flash 存储器具有 MPU RWX 访问权限，这通过 CONFIG_MPU_ALLOW_FLASH_WRITE 配置。如果禁用此选项，当 NVS 应用程序访问 SoC 内部 Flash 且它是唯一运行的线程时，就会发生 MPU 故障。在多线程应用程序中，其他线程可能会截获该故障，此时 NVS API 会返回 -ETIMEDOUT 错误。
