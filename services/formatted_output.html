格式化输出

应用程序以及 Zephyr 本身都需要一套基础设施，把数值格式化成便于用户阅读的形式。标准 C99 库的 *printf() 功能可以满足流式输出设备或内存缓冲区的这一需求，但在嵌入式系统中，设备可能不接受流式数据，也可能没有足够的内存来存放格式化后的输出。

过去，Zephyr 内部 API 同时为 printk() 和 Zephyr 内部的最小 libc 提供这一功能，但使用的是各自独立的内部接口。日志、跟踪、shell 以及其他应用程序会根据构建选项，使用这些 API 或标准 libc 例程。

cbprintf() 公共 API 用于转换 C99 格式字符串和参数，通过回调机制逐个字符地产生输出。它取代了原来的内部函数，并支持几乎所有 C99 格式说明符。Zephyr 中现有对 s*printf() C 库函数的使用可以改为 snprintfcb()，以避免引入 libc 实现。

若干 Kconfig 选项控制启用哪些功能，从而可以在一定程度上控制功能和内存占用：

  • CONFIG_CBPRINTF_FULL_INTEGRAL 或 CONFIG_CBPRINTF_REDUCED_INTEGRAL

  • CONFIG_CBPRINTF_FP_SUPPORT

  • CONFIG_CBPRINTF_FP_A_SUPPORT

  • CONFIG_CBPRINTF_FP_ALWAYS_A

  • CONFIG_CBPRINTF_N_SPECIFIER

CONFIG_CBPRINTF_LIBC_SUBSTS 可用于提供一组函数，它们的行为与标准 libc 函数相同，但使用所选的 cbprintf 格式化器，而不是从 libc 中再引入另一个格式化器。

此外，可以使用 CONFIG_CBPRINTF_NANO 退回到在加入此功能之前 printk() 所用的格式化器，它非常节省空间，但功能有限。

Cbprintf 打包

通常，调用 printf 系列函数时会同步格式化字符串。但在某些情况下，推迟格式化更有利。这时必须捕获状态（格式字符串和参数）。这种状态构成一个自包含的包（package），其中包含格式字符串和参数。此外，包中还可以包含属于格式化内容的字符串（格式字符串或任意 %s 参数）的副本。包的主要内容类似于 va_list 栈帧，因此可以使用标准格式化函数来处理包。由于包中包含按 va_list 帧处理的数据，必须严格保持对齐。由于需要填充，包的大小取决于对齐方式。复制包时，应复制到与原始位置对齐方式相同的内存块中。

包有以下几种变体：

  • 自包含 ——非只读字符串追加到包中。只要能访问只读字符串所在的位置，就可以从这种包格式化出字符串。包中可以包含只读字符串在包内位置的信息，利用这些信息可以把包转换为完全自包含的包。

  • 完全自包含 ——所有字符串都追加到包中。无需任何外部数据即可从这种包格式化出字符串。

  • 临时 ——只存储参数。包中包含指向非只读字符串的指针在包内所处位置的信息，还可以选择性地包含只读字符串的位置信息。只要非只读字符串仍然有效且只读字符串可访问，就可以从这种包格式化出字符串。另外，也可以把包转换为 自包含 包；如果包中含有只读字符串的位置信息，还可以转换为 完全自包含 包。

可以通过两种方法创建包：

  • 运行时——使用 cbprintf_package() 或 cbvprintf_package()。这种方法扫描格式字符串，并根据检测到的格式说明符构建包。

  • 静态——由预处理器在编译时检测参数类型，通过对给定内存的简单赋值来创建包。这种方法比运行时方法快得多（超过 15 倍），但有一个重要限制：使用 char 指针时，它无法区分 %p 和 %s。它把所有（unsigned）char 指针都当作 %s，因此会尝试把字符串追加到包中。在把 临时 包转换为 自包含 包时，使用 CBPRINTF_PACKAGE_CONVERT_PTR_CHECK 标志可以正确处理这种情况。但这需要访问格式字符串，而这并不总是可行，因此建议把用于 %p 的 char 指针强制转换为 void *。当 char 指针与 %p 一起使用时，以 CBPRINTF_PACKAGE_CONVERT_PTR_CHECK 标志调用 cbprintf_package_convert() 会产生一条日志警告。

若干 Kconfig 选项控制打包的行为：

  • CONFIG_CBPRINTF_PACKAGE_LONGDOUBLE

  • CONFIG_CBPRINTF_STATIC_PACKAGE_CHECK_ALIGNMENT

Cbprintf 包转换

可以把包转换为包含更多信息的变体，例如把 临时 包转换为 自包含 包。如果创建包时使用了 CBPRINTF_PACKAGE_ADD_RO_STR_POS 标志，则可以转换为 完全自包含 包。

cbprintf_package_copy() 用于计算新包所需的空间，以及复制并转换包。

Cbprintf 包格式

包的格式中包含与平台相关的填充。包由头部开始，头部包含包的大小（不含追加的字符串）和追加字符串的数量。其后是参数，参数中包含对齐填充，类似于 va_list 栈帧。再往后是与字符串所用的、未追加到包中的字符指针参数相关的数据（这些字符串之后可能由 cbprinf_package_convert() 追加）。最后，包中可以选择性地包含追加的字符串。每个字符串带有 1 字节的头部，其中包含存放地址参数的位置的索引。打包时地址被设置为 null，在格式化字符串之前再更新为指向该字符串在包中的当前位置。由于每次复制包时地址都会改变，更新地址参数必须在格式化字符串之前进行。

警告

如果同时选择了 CONFIG_MINIMAL_LIBC 和 CONFIG_CBPRINTF_NANO，则使用 printf 或 snprintf 等 C 标准库函数进行格式化会受到限制。其中包括不支持 %n 说明符、大多数格式标志、精度控制和浮点数。

限制与建议

  • 建议把与 %p 格式说明符一起使用的字符指针强制转换为其他指针类型（例如 void *）。如果无法访问格式字符串，则只能使用静态打包，此时会追加所有检测到的字符串，用于 %p 的字符指针也会被当作字符串指针。从意外的位置复制数据可能造成严重后果（例如内存故障或安全违规）。
