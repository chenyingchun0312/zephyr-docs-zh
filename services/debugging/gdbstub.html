GDB stub

  • 概述

  • 功能

  • 启用 GDB Stub

    • 使用串口后端

  • 调试

    • 使用串口后端

  • 示例

概述

gdbstub 功能提供了 GDB 远程串行协议（Remote Serial Protocol，RSP）的实现，让你可以使用 GDB 远程调试 Zephyr。

该协议支持不同的连接类型：串口、UDP/IP 和 TCP/IP。Zephyr 目前只支持串口设备通信。

GDB 程序充当客户端，而 Zephyr gdbstub 充当服务器。启用此功能后，gdb_init() 启动 gdbstub 服务后 Zephyr 会停止执行，等待 GDB 连接。建立连接后，就可以与 Zephyr 进行同步交互。注意，目前无法向目标异步发送命令。

功能

支持以下功能：

  • 添加和删除断点

  • 让目标继续运行和单步执行

  • 打印回溯

  • 读写通用寄存器

  • 读写内存

启用 GDB Stub

可以通过 CONFIG_GDBSTUB 选项启用 GDB stub。

使用串口后端

可以通过 CONFIG_GDBSTUB_SERIAL_BACKEND 选项启用 GDB stub 的串口后端。

由于串口后端使用 UART 设备收发 GDB 命令，

  • 如果开发板上有空闲的 UART 设备，请将 chosen 节点的 zephyr,gdbstub-uart 属性设为该空闲 UART 设备，这样 printk() 和日志消息就不会打印到 GDB 所用的同一个 UART 设备上。

  • 对于只有一个 UART 设备的开发板，如果 printk() 和日志也使用同一个 UART 设备输出，则必须禁用它们。GDB 相关的消息可能与日志消息交错，从而产生意想不到的后果。通常可以通过禁用 CONFIG_PRINTK 和 CONFIG_LOG 来实现。

调试

使用串口后端

  1. 在启用 GDB stub 和串口后端的情况下构建。

  2. 将构建好的镜像烧录到开发板上并复位开发板。

    • 此时执行应暂停在 gdb_init() 处。

  3. 在开发机上运行 GDB 并连接到 GDB stub。

    target remote <serial device>

    例如，

    target remote /dev/ttyUSB1

  4. 可以使用 GDB 命令开始调试。

示例

测试应用程序 tests/subsys/debug/gdbstub 中的测试用例 debug.gdbstub.breakpoints 演示了如何使用 Zephyr GDB stub。该测试还有一个用例连接到 QEMU 的 GDB stub 实现（使用自定义端口 tcp:1235），作为验证测试脚本本身的参照。

在 ZEPHYR_BASE 目录下使用以下命令运行测试：

west twister -p qemu_x86 -T tests/subsys/debug/gdbstub

测试应能成功运行。下面我们一步一步地做类似的操作，从 GDB 用户的角度演示 Zephyr GDB stub 是如何工作的。

在下面的代码片段中，请使用你自己的相应目录代替 <SDK install directory>、<build_directory>、<ZEPHYR_BASE>。

  1. 打开两个终端窗口。

  2. 在第一个终端中，构建并运行测试应用程序：

    # From the root of the zephyr repository
west build -b qemu_x86 tests/subsys/debug/gdbstub -- '-DCONFIG_QEMU_EXTRA_FLAGS="-serial tcp:localhost:5678,server"'
west build -t run

    注意，这里设置了 CONFIG_QEMU_EXTRA_FLAGS，将 QEMU 串口控制台端口定向到 localhost 的 TCP 端口 5678，以等待我们在后续步骤中通过 GDB remote 命令发起的连接。

  3. 在第二个终端中启动 GDB：

    <SDK install directory>/x86_64-zephyr-elf/bin/x86_64-zephyr-elf-gdb

    1. 告诉 GDB 在哪里查找构建好的 ELF 文件：

      (gdb) symbol-file <build directory>/zephyr/zephyr.elf

      GDB 的响应：

      Reading symbols from <build directory>/zephyr/zephyr.elf...

    2. 让 GDB 连接到 Zephyr gdbstub 串口后端，该后端之前已通过 QEMU 的 -serial 重定向作为服务器暴露在 TCP 端口上。

      (gdb) target remote localhost:5678

      GDB 的响应：

      Remote debugging using localhost:5678
arch_gdb_init () at <ZEPHYR_BASE>/arch/x86/core/ia32/gdbstub.c:252
252     }

      GDB 还会显示代码执行停止的位置。本例中停在 arch/x86/core/ia32/gdbstub.c 的第 252 行。

    3. 使用 bt 或 backtrace 命令显示栈帧回溯。

      (gdb) bt
#0  arch_gdb_init () at <ZEPHYR_BASE>/arch/x86/core/ia32/gdbstub.c:252
#1  0x00104140 in gdb_init () at <ZEPHYR_BASE>/zephyr/subsys/debug/gdbstub.c:852
#2  0x00109c13 in z_sys_init_run_level (level=INIT_LEVEL_PRE_KERNEL_2) at <ZEPHYR_BASE>/kernel/init.c:360
#3  0x00109e73 in z_cstart () at <ZEPHYR_BASE>/kernel/init.c:630
#4  0x00104422 in z_prep_c (arg=0x1245bc <x86_cpu_boot_arg>) at <ZEPHYR_BASE>/arch/x86/core/prep_c.c:80
#5  0x001000c9 in __csSet () at <ZEPHYR_BASE>/arch/x86/core/ia32/crt0.S:290
#6  0x001245bc in uart_dev ()
#7  0x00134988 in z_interrupt_stacks ()
#8  0x00000000 in ?? ()

    4. 使用 list 命令显示代码执行停止处及其附近的源代码。

      (gdb) list
247             __asm__ volatile ("int3");
248
249     #ifdef CONFIG_GDBSTUB_TRACE
250             printk("gdbstub:%s GDB is connected\n", __func__);
251     #endif
252     }
253
254     /* Hook current IDT. */
255     _EXCEPTION_CONNECT_NOCODE(z_gdb_debug_isr, IV_DEBUG, 3);
256     _EXCEPTION_CONNECT_NOCODE(z_gdb_break_isr, IV_BREAKPOINT, 3);

    5. 使用 s 或 step 命令单步执行程序，直到到达另一行源代码。此时它已执行完 arch_gdb_init()，并在 gdb_init() 中继续执行。

      (gdb) s
gdb_init () at <ZEPHYR_BASE>/subsys/debug/gdbstub.c:857
857     return 0;

      (gdb) list
852             arch_gdb_init();
853
854     #ifdef CONFIG_GDBSTUB_TRACE
855             printk("gdbstub:%s exit\n", __func__);
856     #endif
857             return 0;
858     }
859
860     #ifdef CONFIG_XTENSA
861     /*

    6. 使用 br 或 break 命令设置断点。本例在 main() 处设置断点，然后使用 c（或 continue）命令让代码继续执行而不加干预。

      (gdb) break main
Breakpoint 1 at 0x10064d: file <ZEPHYR_BASE>/tests/subsys/debug/gdbstub/src/main.c, line 27.

      (gdb) continue
Continuing.

      代码执行到 main() 时会停止，并返回 GDB 提示符。

      Breakpoint 1, main () at <ZEPHYR_BASE>/tests/subsys/debug/gdbstub/src/main.c:27
27              printk("%s():enter\n", __func__);

      现在 GDB 停在 main() 的开头：

      (gdb) list
22
23      int main(void)
24      {
25              int ret;
26
27              printk("%s():enter\n", __func__);
28              ret = test();
29              printk("ret=%d\n", ret);
30              return 0;
31      }

    7. 可以使用 p 或 print 命令查看 ret 的值。

      (gdb) p ret
$1 = 1273788

      由于 ret 尚未初始化，它包含某个随机值。

    8. 如果此时使用单步（s 或 step），执行会跳过 test() 的内部继续进行。要查看 test() 内部的代码执行，可以为 test() 设置断点，或者直接使用 si（或 stepi）执行一条机器指令，其副作用是进入该函数。GDB 命令 finish 可用于在不加干预的情况下继续执行，直到函数返回。

      (gdb) finish
Run till exit from #0  test () at <ZEPHYR_BASE>/tests/subsys/debug/gdbstub/src/main.c:17
0x00100667 in main () at <ZEPHYR_BASE>/tests/subsys/debug/gdbstub/src/main.c:28
28              ret = test();
Value returned is $2 = 30

    9. 再次查看 ret，它应当包含 test() 的返回值。有时像本例这样，要再执行一次 step 才会完成赋值。这是因为赋值代码在函数返回之后才执行。赋值代码由工具链生成为机器指令，在查看对应的 C 源文件时是看不到的。

      (gdb) p ret
$3 = 1273788
(gdb) step
29              printk("ret=%d\n", ret);
(gdb) p ret
$4 = 30

    10. 如果此时执行 continue，代码会一直执行下去，因为没有断点可以再次停止执行。目前无法在 GDB 中通过 Ctrl-C 中断执行，因为 Zephyr gdbstub 尚不支持该功能。请切换到运行着 Zephyr 镜像的 QEMU 所在的第一个控制台，使用 Ctrl+a x 手动停止它。当 Twister 执行同一个测试时，它会自动负责停止 QEMU 实例。
