Zyclictest

zyclictest 模块用于估计实时线程的最坏情况延迟。它可以测量从硬件中断到中断服务例程、再到 Zephyr 线程所经历的时间。

该模块及其名称的灵感来自 Linux 上的 cyclictest 程序，因此它是 Zephyr 版的 cyclictest。

其思路是使用定时器中断作为中断源，因为我们确切地知道它发生的时间点。在中断服务例程中获取当前时间，并计算它与定时器中断编程时间之间的差值。

此外，还有一个线程同样与定时器同步，并测量其与编程的定时器时间之间的差值。

这两个时间都会存入一个数组，作为测量结束时打印的直方图的数据源。

这种测量以一定的间隔时间循环进行。

如果想知道优先级为 <p> 的任务的最坏情况延迟，需要让应用程序处于运行状态。在其运行时，以至少比被测应用程序线程低一级的优先级数值启动 zyclictest。例如，如果应用程序中我们关心的线程优先级为 -10，则需要以 -11 或更小的优先级启动 zyclictest。

另一个重要参数是间隔时间。间隔不应小于测得的最坏情况延迟。因此，建议将间隔设为至少是预期或测得的最坏情况延迟的两倍。

如果测量结束时显示有溢出，则意味着在直方图的范围内不存在确定的最坏情况延迟。

为了得到有意义的输出，建议将 CONFIG_SYS_CLOCK_TICKS_PER_SEC 设为至少 1000000，这意味着最小分辨率为 1 微秒。还需要无节拍（tickless）内核（CONFIG_TICKLESS_KERNEL:）。

工作模式

zyclictest 可以以自由运行方式启动，不设固定的循环次数。这是默认方式。停止时会打印到目前为止的结果。

在循环模式（使用 -l <loops> 选项启动）下，zyclictest 运行预先设定的循环次数。达到循环次数后，shell 上会显示一条表示测试结束的消息。不过也可以使用 zyclictest stop -c 提前取消测试。

配置

使用以下选项配置该模块。

  • CONFIG_ZYCLICTEST_SHELL：启用 shell 命令。

用法

zyclictest start [options]
-i <interval>

间隔，单位为微秒

-l <loops>

使用预设循环次数的循环模式

-p <prio>

设置线程的优先级

zyclictest stop [options]
-c

提前取消循环模式

-q

静默模式，打印摘要但不打印直方图数据

示例

在本例中，我们想知道一个由中断唤醒、以协作式任务运行、优先级为 -10 的线程的最坏情况延迟。我们预期延迟小于 200 us。我们使用自由运行模式。

1. Start the zyclictest thread with an interval of 400 us (double of expected worst case latency) and a priority of -11 (one digit higher than the application thread):

zyclictest start -i 400 -p -11

  1. 执行需要测试的操作……

  2. 停止测量：

    zyclictest stop

    zyclictest 的输出：

    Count: 547329
                   IRQ  Thread
Max-Latency:        21      27
Errors:              0       0
Overflow:            0       0
Histogram:
[...]
 23                  0  547306
 24                  0       2
 25                  0       5
 26                  0       5
 27                  0       2
 28                  0       0
[...]

  3. 解读结果：

    没有错误也没有溢出，这意味着测量结果可用。测试中共有 547329 个循环。中断的最坏情况延迟为 21 us，线程为 27 us。
