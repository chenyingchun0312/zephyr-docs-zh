PSA Crypto

概述

PSA（Platform Security Architecture，平台安全架构）Crypto API 为密码学运算和密钥存储提供了一套可移植的编程接口，适用于各种各样的硬件。它的设计既易于使用，又能访问现代密码学所必需的底层原语。

它由 Arm 创建和维护。Arm 将 PSA 开发为一个全面的安全框架，以满足联网设备日益增长的安全需求。

在 Zephyr 中，PSA Crypto API 基于 Mbed TLS 实现，Mbed TLS 是一个提供底层密码学函数的开源密码学库。

设计目标

该接口适用于种类繁多的设备：从使用内置密钥处理数据的专用密码处理器，到运行定制应用程序代码的受限设备（如微控制器），再到多应用程序设备（如服务器）。它遵循密码敏捷性（cryptographic agility）原则。

算法灵活性

PSA Crypto API 支持多种密码学算法，开发者可以根据需要在不同的密码学方法之间切换。随着新算法的出现和现有算法的过时，这种灵活性对于保持安全性至关重要。

密钥管理

PSA Crypto API 包含完善的密钥管理功能，支持以安全、灵活的方式创建、存储和使用密钥。它使用不透明的密钥标识符，因此可以方便地替换和更新密钥，而不会暴露密钥材料。

与实现无关

PSA Crypto API 对底层密码学库进行了抽象，这意味着可以更换具体实现而不影响应用程序代码。这种抽象使得可以根据需要使用不同的密码学库或硬件加速器，从而支持密码敏捷性。

面向未来

通过遵循密码敏捷性原则，PSA Crypto 确保应用程序能够迅速适应新的密码学标准和实践，从而增强长期的安全性和合规性。

应用示例

网络安全（TLS）

该 API 提供了建立 TLS 连接所需的全部密码学原语。

安全存储

该 API 提供与存储加密（基于块或基于文件）相关的全部原语，主加密密钥保存在密钥库中。

网络凭据

该 API 提供密钥库内的网络凭据管理，例如用于基于 X.509 的身份认证，或企业网络中的预共享密钥。

设备配对

该 API 支持密钥协商协议，这类协议常用于通过无线信道安全地配对设备。例如，NFC 令牌或蓝牙设备在首次使用时进行配对，可能就会用到密钥协商协议。

安全启动

该 API 提供在安全启动或可信启动过程中验证固件完整性和真实性所用的原语。

证明（Attestation）

该 API 提供证明活动中使用的原语。证明是指设备使用设备私钥对一个字节数组签名，并将结果返回给调用者的能力。证明有多种用例，从证明设备状态，到生成密钥对并证明该密钥对是在安全密钥库内生成的。该 API 提供了证明中常用的算法。

工厂预配（Factory Provisioning）

大多数物联网设备会在工厂预配过程中，或在部署到现场之后，获得唯一身份。该 API 提供了向设备写入代表该身份的密钥所需的接口。

使用注意事项

始终检查错误

PSA Crypto API 中的大多数函数都可能返回错误。所有可能失败的函数，其返回类型都是 psa_status_t。少数函数不会失败，因此返回 void 或其他类型。

如果发生错误，除非另有说明，输出参数的内容是未定义的，不得使用。

一些常见的错误原因包括：

  • 在密钥的存储和处理与应用程序处于不同环境的实现中，所有需要访问密码学处理环境的函数都可能因两个环境之间的通信错误而失败。

  • 如果算法由硬件加速器实现，而该加速器在逻辑上独立于应用处理器，那么即使应用处理器仍在正常运行，加速器也可能发生故障。

  • 大多数函数都可能因资源不足而失败。不过，有些实现会保证某些函数始终有足够的内存。

  • 所有访问持久密钥的函数都可能因存储故障而失败。

  • 所有需要随机性的函数都可能因熵不足而失败。建议实现在执行 psa_crypto_init() 期间为随机数生成器提供足够的熵作为种子。不过，有些安全标准要求定期从硬件随机数生成器重新获取种子，而这一过程可能失败。

共享内存与并发

有些环境允许应用程序多线程运行，有些则不允许。在某些环境中，应用程序可以与不同的安全上下文共享内存。在多线程应用程序或共享内存的环境中，必须谨慎编写应用程序，以避免数据损坏或泄露。本规范要求应用程序遵守一定的约束。

一般而言，对于任一给定对象，PSA Crypto API 允许一个写入者，或者任意数量的同时读取者。换言之，如果两个或更多调用并发访问同一个对象，只有当所有调用都只读取该对象而不修改它时，行为才是明确定义的。读访问包括通过输入参数读取内存，以及通过使用密钥读取密钥库内容。更多细节请参阅 并发调用

如果应用程序与另一个安全上下文共享内存，它可以将共享内存块作为输入缓冲区或输出缓冲区传递，但不能作为非缓冲区参数传递。更多细节请参阅 参数的稳定性。

使用后清理

为了在系统被攻破时将影响降到最低，建议应用程序在不再使用敏感数据时将其从内存中擦除。这样，只有当前正在使用的数据可能泄露，过去的数据不会受到危害。

擦除敏感数据包括：

  • 清除栈上或堆上的临时缓冲区。

  • 中止不会完成的操作。

  • 销毁不再使用的密钥。
