随机数生成

概述

随机数 API 子系统同时提供密码学安全和非密码学安全的随机数生成 API。使用哪种随机数 API 取决于对随机数的密码学要求。非密码学 API 返回随机值的速度快得多，因此只要不需要密码学安全的随机值，就应优先使用它们。

  • 对于非密码学用途，例如随机化延迟、打乱数据或一般的随机化，请使用 sys_rand_get() 及相关函数。这些函数速度更快，但不适合安全应用。

  • 对于密码学用途，例如生成加密密钥、nonce、初始化向量，或任何必须让攻击者无法预测的数据，请使用 sys_csrand_get()。

警告

切勿将非密码学随机数函数（sys_rand_get()、sys_rand8_get()、sys_rand16_get()、sys_rand32_get()、sys_rand64_get()）用于安全敏感的操作。这些函数不提供密码学安全的随机数。

随机数 API 声明在 include/zephyr/random/random.h 中。sys_rand_get() 和 sys_csrand_get() 是系统调用，启用 CONFIG_USERSPACE 后可从用户模式线程调用。

API 用法

非密码学随机数

以下函数提供非密码学安全的随机数：

  • sys_rand_get() - 用随机字节填充缓冲区

  • sys_rand8_get() - 获取一个 8 位随机值

  • sys_rand16_get() - 获取一个 16 位随机值

  • sys_rand32_get() - 获取一个 32 位随机值

  • sys_rand64_get() - 获取一个 64 位随机值

用法示例：

#include <zephyr/random/random.h>

void example_random_usage(void)
{
    uint8_t buffer[16];
    uint32_t random_value;

    /* Fill buffer with random bytes */
    sys_rand_get(buffer, sizeof(buffer));

    /* Get a single random 32-bit value */
    random_value = sys_rand32_get();
}

密码学安全的随机数

对于密码学用途，请使用 sys_csrand_get()：

#include <zephyr/random/random.h>

int generate_encryption_key(uint8_t *key, size_t key_len)
{
    int ret;

    ret = sys_csrand_get(key, key_len);
    if (ret != 0) {
        /* Handle error - entropy source may have failed */
        return ret;
    }

    return 0;
}

备注

sys_csrand_get() 成功时返回 0，熵源出错时返回 -EIO。生成密码学材料时务必检查返回值。

Kconfig 选项

所有配置选项都位于 subsys/random/Kconfig 中。

通用选项

CONFIG_TEST_RANDOM_GENERATOR

用于测试。此选项允许使用非随机的数字生成器，并允许随机数 API 返回并非真正随机的值。它应由测试、示例等应用程序级配置选择，切勿用于生产环境。

警告

此选项仅用于在缺少硬件熵支持的平台上进行测试。启用此选项时生成的随机数是可预测的，不适合任何安全敏感的用途。

非密码学随机数生成器的选择

Kconfig choice RNG_GENERATOR_CHOICE 选择 sys_rand_get() 背后所用的生成器。要在开发板或 SoC 配置文件中覆盖默认值：

choice RNG_GENERATOR_CHOICE
        default XOSHIRO_RANDOM_GENERATOR
endchoice

可用的生成器：

CONFIG_ENTROPY_DEVICE_RANDOM_GENERATOR

直接使用硬件熵驱动生成随机数。它提供高质量的随机数，但可能比伪随机方案慢。当硬件熵源的性能足以满足应用程序的需求时，请选择此选项。

CONFIG_XOSHIRO_RANDOM_GENERATOR

使用 Xoshiro128++ 伪随机数生成器，其种子来自硬件熵源。这是一种快速的通用 PRNG，具有 128 位状态，可通过所有标准随机性测试。

对于大多数需要快速非密码学随机数的应用程序，推荐选择此项。

CONFIG_ARM64_RANDOM_GENERATOR

在支持的平台上，使用 ARM64 FEAT_RNG 扩展中的 RNDR 指令。指令失败时的重试行为可通过 CONFIG_ARM64_RANDOM_GENERATOR_MAX_RETRIES 和 CONFIG_ARM64_RANDOM_GENERATOR_RETRY_WAIT_USEC 调整。

CONFIG_TIMER_RANDOM_GENERATOR

使用系统定时器生成伪随机数。该生成器产生的值是可预测的，仅用于 在没有硬件熵支持的平台上 进行测试。其初始状态可通过 CONFIG_TIMER_RANDOM_INITIAL_STATE 设置。

需要启用 CONFIG_TEST_RANDOM_GENERATOR。

密码学安全随机数生成器的选择

Kconfig choice CSPRNG_GENERATOR_CHOICE 选择密码学安全随机数生成所用的来源。

要在开发板或 SoC 配置文件中覆盖默认值：

choice CSPRNG_GENERATOR_CHOICE
        default PSA_CSPRNG_GENERATOR
endchoice

可用的生成器：

CONFIG_HARDWARE_DEVICE_CS_GENERATOR

直接使用硬件熵驱动作为密码学安全随机数的来源。当硬件随机数生成器已通过密码学用途的认证或验证时，请选择此项。

CONFIG_PSA_CSPRNG_GENERATOR

使用 PSA Crypto API 的安全随机数生成功能，在可用时它可能会进一步使用硬件熵源。它需要 CONFIG_PSA_CRYPTO，即构建中必须包含 Mbed TLS 或 TF-M 等 PSA Crypto 提供者。

CONFIG_TEST_CSPRNG_GENERATOR

将对 sys_csrand_get() 的调用转交给 sys_rand_get()。这样就可以在没有硬件熵支持的平台上测试需要 CSPRNG 的库。

需要启用 CONFIG_TEST_RANDOM_GENERATOR。

警告

此选项 不提供任何密码学安全性。仅用于测试。

如果应用程序只在平台确实能够提供时才需要密码学安全的随机数，可以启用 CONFIG_CSPRNG_NEEDED，然后检查 CONFIG_CSPRNG_ENABLED；只有构建中包含适合生成密码学安全随机数的熵驱动时，后者才会被设置。

设备树配置

随机数子系统使用 zephyr,entropy chosen 节点来确定硬件熵设备：

/ {
    chosen {
        zephyr,entropy = &rng;
    };
};

如果平台带有硬件随机数生成器，请确保开发板的设备树正确指定了该 chosen 节点。熵驱动 API 请参见 熵。如果平台没有熵驱动，则只能使用测试生成器，且需要启用 CONFIG_TEST_RANDOM_GENERATOR。
