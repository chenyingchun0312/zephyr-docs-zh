任务看门狗

概述

许多微控制器都带有硬件看门狗定时器外设。其作用是在软件出现严重故障时触发某种动作（通常是系统复位）。看门狗定时器初始化后，必须定期重启（即“喂狗”），以防其超时。如果软件卡死、无法再喂狗，就会触发纠正动作，使系统恢复正常运行。

在多个任务并行运行的实时操作系统中，单个看门狗实例可能已不够用，因为它只能用于一个任务。这个基于内核定时器的软件看门狗提供了一种监视多个线程或任务（称为看门狗通道）的方法。

如果任务看门狗本身或调度器出现故障，可以选择使用现有的硬件看门狗作为后备。

任务看门狗以内核定时器作为后端。如果配置得当，正常运行期间定时器 ISR 实际上永远不会被调用，因为每次喂狗调用都会不断更新定时器。

目前无法拥有多个任务看门狗实例。不过，任务看门狗 API 可以全局访问，因此在固件中添加或删除通道时无需传递上下文或设备指针。

最大通道数通过 Kconfig 预先定义，应调整为与应用程序所需的通道数完全一致。

配置选项

相关配置选项位于 subsys/task_wdt/Kconfig。

  • CONFIG_TASK_WDT

  • CONFIG_TASK_WDT_CHANNELS

  • CONFIG_TASK_WDT_HW_FALLBACK

  • CONFIG_TASK_WDT_MIN_TIMEOUT

  • CONFIG_TASK_WDT_HW_FALLBACK_DELAY
