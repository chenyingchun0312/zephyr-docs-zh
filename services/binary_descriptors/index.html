二进制描述符

二进制描述符是存储二进制可执行文件相关信息的常量数据对象。与“普通”常量不同，二进制描述符被链接到二进制文件中的已知偏移处，因此其他程序（例如同一设备上运行的另一个镜像或主机工具）也能访问它们。适合作为二进制描述符的常量举例：内核版本、应用程序版本、构建时间、编译器版本、环境变量、编译主机名等。

二进制描述符通过 DEFINE_BINDESC_* 宏创建。例如：

#include <zephyr/bindesc.h>

BINDESC_STR_DEFINE(my_string, 2, "Hello world!"); // Unique ID is 2

之后可以这样访问 my_string：

printk("my_string: %s\n", BINDESC_GET_STR(my_string));

也可以通过 west bindesc 获取：

$ west bindesc custom_search STR 2 build/zephyr/zephyr.bin
"Hello world!"

内部实现

二进制描述符以 TLV（标签、长度、值）头部的形式实现，并链接到二进制镜像中的已知偏移处。该偏移因架构而异，但一般会将描述符链接到尽量靠近镜像开头的位置。在镜像必须以向量表开头的架构（如 ARM）上，描述符紧接在向量表之后链接，复位向量指向位于描述符之后的 text 段开头。在镜像必须以可执行代码开头的架构（如 x86）上，会在镜像开头插入一条跳转指令以跳过二进制描述符，描述符紧跟在这条跳转指令之后。

每个标签是一个 16 位无符号整数，其中最高的半字节（4 位）表示类型（目前为 uint、string 或 bytes），其余部分为 ID。每个描述符的 ID 全局唯一。例如，应用程序版本字符串的 ID 为 0x800，字符串类型用 0x1 表示，因此应用程序版本的标签为 0x1800。长度是一个 16 位数，等于数据的字节数。数据即描述符的实际值。所有二进制描述符中的数字（魔数、标签、uint）在内存中都按 SoC 原生的字节序排列。west bindesc 默认假定为小端序，因此如果镜像属于大端序 SoC，应向该工具传入相应的标志。

二进制描述符头部以魔数 0xb9863e5a7ea46046 开始，其后是各个 TLV，最后以 DESCRIPTORS_END （0xffff）标签结束。标签总是按 32 位对齐。如果前一个描述符的值长度未对齐，会填充零以确保当前标签对齐。

综上，上面的示例在（小端序 SoC 的）内存中如下所示：

 46 60 a4 7e 5a 3e 86 b9 02 10  0d 00  48 65 6c 6c 6f 20 77 6f 72 6c 64 21 00 00 00 00 ff ff 00 00
|         magic         | tag |length| H  e  l  l  o     w  o  r  l  d  !    |   pad  |    end    |

用法

二进制描述符总是通过 BINDESC_*_DEFINE 宏创建。如上例所示，可以用任意 ID 从任意字符串或整数生成描述符。不过，建议遵循 include/zephyr/bindesc.h 中定义的标准标签，这样有以下好处：

  1. west bindesc 工具能够识别描述符的含义，并打印有意义的标签

  2. 可以确保来自不同来源的各个应用程序之间保持一致

  3. 使描述符的生成可以合入上游（参见标准描述符）

要定义使用标准标签的描述符，只需使用 bindesc.h 中包含的标签：

#include <zephyr/bindesc.h>

BINDESC_STR_DEFINE(app_version, BINDESC_ID_APP_VERSION_STRING, "1.2.3");

标准描述符

有些描述符实现起来很简单，因此可以在上游 Zephyr 中以标准方式实现，然后通过 Kconfig 启用，而不必让每个用户重新实现。这些描述符包括构建时间、内核版本和主机信息。例如，要以字符串形式添加构建日期和时间，应启用以下配置：

# Enable binary descriptors
CONFIG_BINDESC=y

# Enable definition of binary descriptors
CONFIG_BINDESC_DEFINE=y

# Enable default build time binary descriptors
CONFIG_BINDESC_DEFINE_BUILD_TIME=y
CONFIG_BINDESC_BUILD_DATE_TIME_STRING=y

为避免与用户定义的描述符冲突，标准描述符被分配在 0x800-0xfff 范围内，0x000-0x7ff 则留给用户。更多信息请阅读这些 Kconfig 符号的 help 部分。按照惯例，每个 Kconfig 符号对应一个二进制描述符，其名称为该 Kconfig 名称（去掉 CONFIG_BINDESC_）的小写形式。例如，CONFIG_BINDESC_KERNEL_VERSION_STRING 会创建一个描述符，可通过 BINDESC_GET_STR(kernel_version_string) 访问。

读取描述符

也可以在应用程序中读取和解析二进制描述符。无论是镜像读取自身的描述符，还是读取另一个镜像的描述符，这都很有用。可以通过以下三种后端之一进行读取：

  1. RAM：假定描述符已被复制到 RAM 中（例如由引导加载程序复制），则可以从其所在的缓冲区读取。

  2. 内存映射 Flash：如果待读取镜像所在的 Flash 可以通过程序的地址空间访问，则可以直接从 Flash 读取。此选项占用的 RAM 最少，但在 Flash 未做内存映射时无法使用；出于安全考虑，也不建议用它读取引导加载程序的描述符。

  3. Flash：使用一个内部缓冲区，通过 Flash API 逐个读取描述符，并在描述符位于缓冲区中时交给用户。

要启用描述符读取功能，请启用 CONFIG_BINDESC_READ。三种后端分别由以下 Kconfig 符号启用：CONFIG_BINDESC_READ_RAM、CONFIG_BINDESC_READ_MEMORY_MAPPED_FLASH 和 CONFIG_BINDESC_READ_FLASH。

要读取描述符，首先应初始化一个描述符句柄：

struct bindesc_handle handle;

/* Assume buffer holds a copy of the descriptors */
bindesc_open_ram(&handle, buffer);

只有 bindesc_open_* 系列函数与所用的后端有关，其余 API 与数据所在位置无关。句柄初始化后，即可与其余 API 一起使用：

char *version;
bindesc_find_str(&handle, BINDESC_ID_KERNEL_VERSION_STRING, &version);
printk("Kernel version: %s\n", version);

west bindesc 工具

west 能够从给定的可执行镜像中解析并显示二进制描述符。

更多信息请参阅 west bindesc --help 或 文档。
