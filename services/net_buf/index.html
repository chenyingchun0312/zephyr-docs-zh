概述

网络缓冲区是网络协议栈（以及蓝牙协议栈）传递数据的核心概念。其 API 定义在 include/zephyr/net_buf.h 中。

缓冲区布局

缓冲区的数据保存在一块存储空间中，其大小在分配缓冲区时确定。数据不必从存储空间的开头开始：数据之前可以有空闲空间，称为头部空间（headroom）；数据之后也可以有空闲空间，称为尾部空间（tailroom）。

缓冲区的以下四个字段描述了这种布局：

data

指向数据的起始位置。

len

data 指针之后的数据长度。

size

存储空间的大小，包括头部空间和尾部空间。

__buf

存储空间的起始位置。不要直接访问，请改用 data 指针。

net_buf_headroom() 返回头部空间，net_buf_tailroom() 返回尾部空间，net_buf_tail() 返回 data + len，即下一个添加到缓冲区的字节所在的位置。可容纳更多数据的剩余空间是尾部空间，而不是 size 减去 len，因为 size 也包含了头部空间。

创建缓冲区

net_buf 从缓冲池中分配，缓冲池需要先使用对应池类型的宏来定义（参见 Pool Types）。net_buf_simple 不需要缓冲池（参见 Simple Buffers）。固定大小缓冲区的缓冲池按如下方式定义：

NET_BUF_POOL_FIXED_DEFINE(pool_name, buf_count, buf_size, user_data_size, NULL);

缓冲池是一个静态变量，因此如果需要将其导出给其他模块，需要另外定义一个指针。

定义缓冲池之后，可以按如下方式从中分配缓冲区：

buf = net_buf_alloc(&pool_name, timeout);

缓冲池及其缓冲区没有显式的初始化函数，初始化是在调用 net_buf_alloc() 时隐式完成的。

如果需要在缓冲区中为稍后添加到前面的协议头预留空间，可以按如下方式预留头部空间：

net_buf_reserve(buf, headroom);

除了实际的协议数据和通用解析上下文之外，网络缓冲区还可以包含协议特定的上下文，称为用户数据。用户数据的大小是缓冲池的属性：池中每个缓冲区都有 user_data_size 字节的用户数据，可通过 net_buf_user_data() 获取。

缓冲池定义的最后一个参数是一个可选的销毁回调。当缓冲区的最后一个引用被释放时，会调用该回调，而不是将缓冲区归还缓冲池；该回调最终必须调用 net_buf_destroy() 来归还缓冲区。

缓冲区原生支持通过 k_fifo 内核对象传递。使用 k_fifo_put() 和 k_fifo_get() 可以在线程之间传递缓冲区。

缓冲区还可以通过其 node 字段保存在 sys_slist_t 中。net_buf_slist_put() 和 net_buf_slist_get() 会在自旋锁保护下追加和移除缓冲区，因此只要对链表的每次访问都通过这两个函数进行，该链表就可以在线程和中断处理程序之间共享。对于这样的链表，请使用它们，而不是 sys_slist_append() 和 sys_slist_get()。一个缓冲区只有一个 node 字段，因此无论它有多少个引用，同一时刻只能位于一个 FIFO 或链表中。

缓冲池类型

缓冲池类型决定其缓冲区数据的来源：

缓冲池

数据存储

数据分配

NET_BUF_POOL_FIXED_DEFINE

一个静态数组，每个缓冲区对应一块 data_size 字节的数据块。

总是分配整个数据块。从不等待。

NET_BUF_POOL_VAR_DEFINE

一个 data_size 字节的堆，由池中的缓冲区共享。

按每个缓冲区请求的大小分配。等待堆内存，直到分配超时到期。

NET_BUF_POOL_VAR_ALIGN_DEFINE

与 NET_BUF_POOL_VAR_DEFINE 相同。

与 NET_BUF_POOL_VAR_DEFINE 相同，但数据起始位置按 align 对齐，分配大小向上取整为其倍数。请求少于 align 字节的分配会失败，除非请求的数据大小为零。

NET_BUF_POOL_HEAP_DEFINE

系统堆，通过 k_malloc() 分配。需要 CONFIG_HEAP_MEM_POOL_SIZE。

按每个缓冲区请求的大小分配。从不等待：堆耗尽时立即失败。

在所有缓冲池类型中，缓冲区本身都来自一个包含 buf_count 个条目的固定数组，分配时会等待空闲缓冲区，直到超时到期。之后再在同一超时的剩余时间内分配数据。因此，即使使用 K_FOREVER，从堆缓冲池分配也可能返回 NULL。每次从可变缓冲池或堆缓冲池分配时，还会占用堆中的若干字节用于记录管理信息，确定可变缓冲池的堆大小时必须考虑这部分开销。

net_buf_alloc() 按其缓冲池的固定数据大小分配缓冲区，适用于固定缓冲池：从可变缓冲池或堆缓冲池分配时，它返回的缓冲区没有数据存储空间。对于这两类缓冲池，请使用 net_buf_alloc_len()。net_buf_alloc_with_data() 适用于所有缓冲池类型：此时缓冲区使用调用者提供的存储空间，缓冲池不为其分配数据。缓冲区初始时以全部存储空间作为其数据，因此没有尾部空间；释放缓冲区也不会释放该存储空间，调用者必须在缓冲区存在期间保证该存储空间有效。

分配超时

分配的超时是指分配操作等待空闲缓冲区（对于可变缓冲池，还包括等待数据内存）的最长时间。中断处理程序不能等待，必须使用 K_NO_WAIT。

如果一个缓冲池的缓冲区只能由某个线程释放（直接释放，或通过该线程自己处理的工作释放），那么该线程以 K_FOREVER 在这个缓冲池上等待时将永远不会被唤醒。在这种上下文中请使用有限的超时，并处理返回 NULL 的情况。

每种操作针对每种数据类型都有一个函数，例如 Add 操作：

net_buf_add_mem()

复制一块内存区域。

net_buf_add_u8()

net_buf_add_le16(), net_buf_add_be16()

以小端序或大端序添加一个 16 位值。24、32、40、48 和 64 位也都有这两种字节序的版本。

Push、Pull 和 Remove 也有同样的一组函数，分别命名为 net_buf_push_*()、net_buf_pull_*() 和 net_buf_remove_*()。Pull 和 Remove 的定宽版本会返回拉出或移除的值。net_buf_add()、net_buf_push() 和 net_buf_pull() 只将边界移动一定长度而不复制任何数据，并返回指向缓冲区内部的指针：

struct foo_hdr *hdr = net_buf_push(buf, sizeof(*hdr));

hdr->opcode = FOO_OP_WRITE;
hdr->len = sys_cpu_to_le16(len);

简单缓冲区

net_buf 构建在 net_buf_simple 之上，后者只有缓冲区布局中的四个字段。net_buf 增加的是缓冲区在不同上下文之间传递所需的内容：引用计数、缓冲区归还的目标缓冲池、用于 FIFO 和链表的链接、分片链以及用户数据。

对于某个函数或对象独自使用的缓冲区（例如在栈上编码的一条短消息），net_buf_simple 就足够了。NET_BUF_SIMPLE_DEFINE 定义一个这样的缓冲区及其存储空间，NET_BUF_SIMPLE_DEFINE_STATIC 则定义一个静态的。add、remove、push 和 pull 系列函数都有对应的 net_buf_simple_ 版本：

NET_BUF_SIMPLE_DEFINE(msg, 8);

net_buf_simple_add_u8(&msg, opcode);
net_buf_simple_add_le16(&msg, handle);

解析器在把缓冲区交给会从中拉出数据的代码之前，可以先用 net_buf_simple_save() 保存数据的位置，之后再用 net_buf_simple_restore() 恢复到该位置：

NET_BUF_SIMPLE_DEFINE(msg, 32);
struct net_buf_simple_state state;

net_buf_simple_add_mem(&msg, data, len);

net_buf_simple_save(&msg, &state);
err = parse_header(&msg);
net_buf_simple_restore(&msg, &state);

保存的状态是数据的位置，而不是数据的内容：期间写入缓冲区的数据不会被撤销。

分片

无法放入单个缓冲区的数据，或由多个片段拼接而成的数据，保存在通过 frags 字段链接起来的缓冲区链中。链中的第一个缓冲区称为链头。

链中的每个缓冲区都有自己的头部空间和尾部空间，其 len 只计算自身的数据。net_buf_frags_len() 返回整条链中数据的长度。

net_buf_frag_add() 将一个分片添加到链的末尾，net_buf_frag_insert() 在给定缓冲区之后插入一个分片，net_buf_frag_del() 移除一个分片并释放链对它的引用。链中缓冲区的所有权归属见 Ownership。

有些函数作用于整条链的数据：net_buf_linearize() 将链中的数据复制到一个连续的缓冲区，net_buf_append_bytes() 将数据添加到链的末尾并按需分配更多分片，net_buf_data_match() 将数据与链的内容进行比较。它们返回的长度都可能小于请求的长度。net_buf_skip() 从链的开头移除数据，释放被清空的分片，并返回链的剩余部分。

所有权

与 net_buf_simple 不同，net_buf 采用引用计数。新分配的缓冲区有一个引用，当最后一个引用被释放时，缓冲区归还其缓冲池。每个引用恰好有一个所有者。所有者要么将引用转移给新的所有者（例如 FIFO、链表或接管缓冲区所有权的函数），要么释放它。转移之后，原所有者不得再使用该缓冲区，除非它持有通过 net_buf_ref() 获取的另一个属于自己的引用。

有两个辅助函数作用于持有引用的指针，使原所有者得到的是 NULL，而不是指向一个已不再拥有的缓冲区的指针。net_buf_take() 将引用从该指针中移出，net_buf_drop() 则释放该引用。net_buf_drop() 适用于在释放之后仍然存在的指针（例如结构体成员），或可能已经是 NULL 的指针。对于在离开作用域时持有引用的局部指针，只需调用 net_buf_unref()。

分片链通过其链头拥有。链中的每个缓冲区都拥有对下一个分片的一个引用，并在自身被释放时释放该引用，因此释放链头的最后一个引用时，会沿着链依次释放，直到遇到第一个仍被其他地方引用的分片。net_buf_frag_insert() 会接管所传入分片的所有权；链头不为 NULL 时，net_buf_frag_add() 也是如此。链头为 NULL 时，net_buf_frag_add() 返回带有一个新引用的分片，调用者保留自己的引用。

被传入缓冲区的函数或回调会以下列方式之一处理该引用，其文档应说明属于哪一种：

借用

函数可以在返回之前使用该缓冲区，但既不能保留也不能转移它。要保留借用的缓冲区，函数需先用 net_buf_ref() 获取一个自己的引用。

接管所有权

无论以何种方式返回（包括出错时），引用都会转移给该函数。

成功时接管所有权

只有函数执行成功时引用才会转移。出错时，缓冲区仍归调用者所有。

将缓冲区放入 FIFO 或链表会把引用转移给该队列。接收方甚至可能在 k_fifo_put() 返回之前就处理并释放该缓冲区，例如有更高优先级的线程正在等待该 FIFO 时。请在同一个表达式中用 net_buf_take() 转移引用：

k_fifo_put(&tx_queue, net_buf_take(&buf));

即使 buf 在调用之后立即离开作用域，也要这样做：普通指针参数看起来与仅被借用的参数无异，而 net_buf_take() 能在调用处表明引用发生了转移。

将 net_buf_take(&buf) 作为参数传递，只适用于总是接管所有权的调用，例如 k_fifo_put()、net_buf_slist_put() 和 net_buf_frag_insert()。当向一个仅在成功时接管所有权的函数传入普通指针时，无论结果如何，调用者的指针都保持不变，只有返回值能说明缓冲区是否仍归自己所有。

因此，新编写的接管所有权的函数应接受一个指向调用者缓冲区指针的指针，并在接管时用 net_buf_take() 移出引用。这样，调用者的指针恰好在所有权转移时变为 NULL，并且无论结果如何，调用之后使用 net_buf_drop() 都是正确的：

int foo_send(struct foo *foo, struct net_buf **buf)
{
    if (!foo->ready) {
        return -EAGAIN;
    }

    k_fifo_put(&foo->tx_queue, net_buf_take(buf));

    return 0;
}

err = foo_send(foo, &buf);
if (err != 0) {
    LOG_WRN("Not sent (err %d)", err);
}

/* Releases the buffer only if foo_send() did not take it */
net_buf_drop(&buf);

将现有函数改为这种形式会破坏其调用者，因此最好在该函数本来就要重写时再进行。

调试

CONFIG_NET_BUF_LOG

启用该库的日志。在警告或更高的日志级别下，当使用 K_FOREVER 的分配不得不等待缓冲区时，会输出一条警告，提示可能存在 Allocation Timeouts 中描述的死锁。

CONFIG_NET_BUF_POOL_USAGE

跟踪每个缓冲池中空闲缓冲区的数量以及同时使用的最大数量，分别由 net_buf_get_available() 和 net_buf_get_max_used() 返回。这有助于确定缓冲池的大小。

CONFIG_NET_BUF_HARDENING

为 add、remove、push 和 pull 系列函数添加不依赖断言（断言默认禁用）的检查。被拒绝的操作并不总是会向调用者报告。net_buf_is_valid() 可按需检查缓冲区是否一致且仍被引用。

常见错误

所有权

在错误路径上没有释放的缓冲区会从其缓冲池中丢失，缓冲池要到很久以后才会耗尽，而且出问题的地方与原因相距甚远。被释放两次的缓冲区可能在另一个所有者仍在使用时就归还给了缓冲池。请遵循 Ownership 中的规则：每个引用只有一个所有者；转移给队列或总是接管所有权的函数时，用 net_buf_take() 编写；保存起来的引用用 net_buf_drop() 释放。

两个线程操作同一个缓冲区

缓冲池能防止并发的分配和释放，但缓冲区的字段不受保护：两个线程不得同时修改同一个缓冲区的 data、len 或 frags。请通过队列将缓冲区从一个线程传给另一个线程，或者让每个线程各持一个引用，并保持缓冲区不变。拉出数据也会修改缓冲区：解析共享缓冲区的线程应从自己的 net_buf_simple 中拉出数据，该结构体通过 net_buf_simple_clone() 设置，指向相同的数据。

头部空间和尾部空间

net_buf_push() 需要头部空间，这部分空间由 net_buf_reserve() 在添加任何数据之前预留；net_buf_add() 需要尾部空间：可容纳更多数据的剩余空间是 net_buf_tailroom()，而不是 size。只有断言（默认禁用）或 CONFIG_NET_BUF_HARDENING 才会检查这两种空间是否耗尽。push 或 pull 还会移动 data 指针，因此之前保存的该指针副本随后就会失效，而且不会有任何检查。

缓冲池大小

如果多个相互独立的数据流（例如发送和接收）共享一个缓冲池，其中一个数据流可能会让另一个数据流得不到缓冲区。请为每个数据流使用单独的缓冲池，并根据同时使用的缓冲区数量确定其大小，该数量可用 CONFIG_NET_BUF_POOL_USAGE 测量（参见 Debugging）。

用户数据

持有缓冲区的每一层都可以读写其用户数据，用户数据随缓冲区一起转手。除非接收方 API 有相应说明，否则不要假定缓冲区传递后用户数据会被保留。只有一个模块需要的状态，可以改为保存在缓冲池旁边的一个数组中，用 net_buf_id() 作为索引。
