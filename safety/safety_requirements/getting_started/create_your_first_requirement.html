创建你的第一个 Zephyr RTOS 需求

仓库概述

Zephyr 的需求使用 StrictDoc 在 reqmgmt 仓库中管理。该仓库包括：

  • docs/：包含 StrictDoc 格式的需求文档

  • tools/：实用脚本和配置

  • strictdoc.toml：StrictDoc 的项目配置

  • tasks.py：使用 Invoke 的任务自动化脚本

第 1 步：创建或编辑需求文件

进入仓库中的 docs/ 文件夹。

文件夹概述

docs/ 文件夹包含所有以 StrictDoc 格式编写的需求文档。

docs/ 文件夹包含两个子文件夹，组织方式如下：

  • system_requirements/ 包含高层系统需求，描述 Zephyr RTOS 的总体目标、约束条件和预期行为。

    • system_requirements.sgra 包含 GRAMMAR（语法），定义需求的形式化结构

    • index.sdoc 包含实际的需求陈述

  • software_requirements/ 包含组件级需求。该文件夹中的每个文件对应一个特定的子系统或模块。

    • software_requirements.sgra 包含所有软件需求的 GRAMMAR（语法）

    • 一组 .sdoc 片段文件，它们共同汇编成一份完整的软件需求文档，例如

      • interrupts.sdoc

      • queues.sdoc

      • semaphore.sdoc

      • threads.sdoc

这些文件是模块化的，使贡献者能够独立处理系统的特定领域。你可以编辑现有的 .sdoc 文件，也可以创建新文件。下面是一个基本的需求块示例：

[REQUIREMENT]
UID: ZEP-SRS-17-1
STATUS: Draft
TYPE: Functional
COMPONENT: File System
TITLE: Create file
STATEMENT: >>>
Zephyr shall provide file create capabilities for files on the file system.
<<<

将 UID 设为 TBD，以便 StrictDoc 在后续步骤中自动生成。

第 2 步：保存文件

将文件保存在 docs/ 文件夹下的系统需求或软件需求子文件夹中。如果创建新文件，请为其起一个有意义的名称，通常以其内容所针对的组件或功能命名。

第 3 步：自动分配 UID

在仓库根目录下运行以下命令：

strictdoc manage auto-uid .

该命令将：

  • 遍历项目目录

  • 查找带有 UID: TBD 的需求

  • 为每个需求分配一个唯一标识符

第 4 步：验证 UID 分配

再次打开该文件，你现在应该会看到类似下面的内容：

UID: ZEP-SRS-17-2
STATUS: Draft
TYPE: Functional
COMPONENT: File System
TITLE: Create file
STATEMENT: >>>
Zephyr shall provide file create capabilities for files on the file system.
<<<

注意：UID 格式可以在 strictdoc.toml 中配置。

可选：生成 HTML 文档

要构建 HTML 版本的需求文档：

strictdoc export .

这将在 output/ 文件夹中生成可浏览的文档。

可选：启动 Web 编辑器

要以交互方式浏览和编辑需求：

strictdoc server .

这会启动一个用于编辑和审查需求的本地 Web 界面。

小结

  • 在 docs/ 中创建或编辑一个带有 UID: TBD 的需求

  • 运行 strictdoc manage auto-uid . 来分配 UID

  • 可选择生成 HTML 文档或启动 Web 编辑器

StrictDoc 帮助 Zephyr 在各个平台上维护结构化、可追溯且可编辑的需求。
